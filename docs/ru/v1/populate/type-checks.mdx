Тип поля зависит от того, вызвали ли вы `populate`: до вызова в `author` лежит идентификатор `Ref<User>`, после — документ пользователя или `null`, если пользователя успели удалить. Это удобно, пока запрос и код, который его использует, находятся рядом. Как только документ передаётся в другую функцию, тип нужно как-то донести туда же, а если документ пришёл из места, где вы не знаете, загружена ли связь, нужна проверка. На этой странице показаны способы: назвать тип загруженного результата, описать функцию для документа в любом состоянии ([`AnyPopulationDoc`](../reference/populate/populate-types.mdx#anypopulationdoc) и [`isPopulated`](../reference/populate/populate-types.mdx#ispopulated)), потребовать загрузку методом [`$assertPopulated`](../reference/documents/document-api.mdx#assertpopulated), проверить её во время работы через [`$populated`](../reference/documents/document-api.mdx#populated) и обработать `null` ([`isPresent`](../reference/populate/populate-types.mdx#ispresent) и опция [`required`](../reference/populate/populate.mdx#required)).

## Что предполагается

Примеры используют клиент и модели блога из руководства [Показать связанные данные](./basics.mdx): у поста есть `author`, `tags`, а у комментария — `post` и `author`. В базе два пользователя (Alice и Bob), пост «Hello» Alice с тегами `db` и `ts` и комментарий `c1` к нему.

## Быстрый путь

Если функции нужен документ именно с загруженной связью, опишите её параметр типом результата загрузки. Если функция должна принять документ в любом состоянии, опишите параметр типом `AnyPopulationDoc` и спросите у `isPopulated`. Если связь могла загрузить другой код, а вам нужно её потребовать, вызовите `$assertPopulated`.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
import { type AnyPopulationDoc, type HydratedDoc, isPopulated } from "@venloc/typemo";

// вариант 1: тип берётся из функции, которая загружает
const loadPost = () => Posts.findOne({ title: "Hello" }).populate("author").orFail();
type LoadedPost = Awaited<ReturnType<typeof loadPost>>;
const authorOf = (post: LoadedPost) => post.author?.name;

// вариант 2: функция принимает пост в любом состоянии
const signature = (post: AnyPopulationDoc<Post>): string =>
  isPopulated(post, "author") ? `— ${post.author?.name}` : "—";

// вариант 3: связь загрузила другая функция, а здесь её требуют
const warmUp = async (post: HydratedDoc<Post>) => {
  await post.$populate("author");
};
const post = await Posts.findOne({ title: "Hello" }).orFail();
await warmUp(post);
const authorName = post.$assertPopulated("author").author?.name;

console.log(authorOf(await loadPost()), signature(await loadPost()), signature(post), authorName);
// → "Alice" "— Alice" "— Alice" "Alice"
```

Остальная страница разбирает каждый способ и то, что делать с пропавшей ссылкой.

## Передать загруженный документ в другую функцию

Ситуация: функция форматирует пост для письма и использует имя автора. Ей нужен пост, у которого `author` загружен, и компилятор должен не пропускать пост без этого. Самый надёжный способ назвать такой тип — вывести его из функции, которая загружает: тогда тип не может разойтись с запросом.

```ts twoslash title="blog/posts.service.ts"

@Schema({ collection: "users" })
class User extends Entity {

}
@Schema({ collection: "tags" })

  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
export const loadPost = (title: string) => Posts.findOne({ title }).populate("author").orFail();
export type LoadedPost = Awaited<ReturnType<typeof loadPost>>;

export const subject = (post: LoadedPost) => `${post.title} by ${post.author?.name ?? "аноним"}`;

console.log(subject(await loadPost("Hello")));
// → "Hello by Alice"
```

Тип `LoadedPost` — это документ поста, в котором `author` заменён загруженным пользователем или `null`. `?.` и запасное значение нужны потому, что автора могли удалить уже после записи поста; как убрать `null` из типа, если пропавшая ссылка для вас ошибка, рассказано [ниже](#что-делать-с-null). Если передать в `subject` пост без populate, компилятор остановит вызов. Обратите внимание на код ошибки: он `TS2379`, а не `TS2345`, потому что проект собирается с `exactOptionalPropertyTypes`.

Ошибка `TS2379` разворачивается до причины: `Types of property 'author' are incompatible. Type 'Ref<User>' is not assignable to type 'HydratedDoc<User> | null'`. Так забытая загрузка ловится там, где документ передан, а не там, где его прочитали.

Обратное тоже верно, и это важно для общих функций: документ с загруженной связью — другой тип, он **не присваивается** параметру `HydratedDoc<Post>` (компилятор: `Type 'HydratedDoc<User> | null' is not assignable to type 'Ref<User>'`). Функция, объявленная с параметром `HydratedDoc<Post>`, принимает только документы без загруженных связей. Поэтому код, который должен работать и с загруженными, и с незагруженными документами, описывают не полным типом документа, а типом для любого состояния: он описан в следующем разделе.

## Принять документ в любом состоянии

Ситуация: функция формирует подпись к посту. Если автор загружен, в подписи его имя, иначе подпись пустая; вызывают её и с постом, прочитанным как есть, и с постом, у которого уже загружен автор или теги. [`AnyPopulationDoc<Post>`](../reference/populate/populate-types.mdx#anypopulationdoc) — тип для такой функции: к нему присваиваются и обычный пост, и пост с populate по любым путям. Ссылки в нём читаются осторожно (`Ref<User> | AnyPopulationDoc<User> | null`), а [`isPopulated`](../reference/populate/populate-types.mdx#ispopulated) во время работы выясняет, загружена ли связь, и сужает тип.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
import { type AnyPopulationDoc, isPopulated } from "@venloc/typemo";

export const signature = (post: AnyPopulationDoc<Post>): string =>
  isPopulated(post, "author") ? `— ${post.author?.name ?? "аноним"}` : "—";

const bare = await Posts.findOne({ title: "Hello" }).orFail();
const loaded = await Posts.findOne({ title: "Hello" }).populate("author").orFail();
console.log(signature(bare), signature(loaded));
// → "—" "— Alice"
```

Одна функция приняла оба поста. Внутри ветки `true` компилятор знает, что `post.author` загружен: поле имеет тип `AnyPopulationDoc<User> | null`. Ветка `false` не обязана быть пустой: в ней пост читается как «автор не загружен или неизвестен».

Проверка смотрит на то, что есть на самом деле, а не на тип переменной. Если связь загрузил другой код уже после того, как вы получили документ, `isPopulated` это увидит:

`isPopulated` принимает только документ, объявленный как `AnyPopulationDoc`: обычный `HydratedDoc<Post>` говорит, что ссылки в нём идентификаторы, спрашивать у него нечего. Параметр функции решает это само: оба вида документов к нему присваиваются, как в примерах выше.

Для массива ссылок сужение оставляет в элементах `| null`:

```ts twoslash

}
@Schema({ collection: "comments" })

  @Prop(() => String, { required: true }) text!: string;

import { type AnyPopulationDoc, isPopulated, isPresent } from "@venloc/typemo";

  if (!isPopulated(post, "tags")) return [];
  return post.tags.filter(isPresent).map((tag) => tag.label);
};

const post = await Posts.findOne({ title: "Hello" }).populate("tags").orFail();
console.log(labels(post));
// → ["db", "ts"]
```

Элемент массива после `isPopulated` остаётся `AnyPopulationDoc<Tag> | null`, хотя без [`retainNullValues`](../reference/populate/populate.mdx#retainnullvalues) `null` в нём не бывает: форма не знает, с какими опциями шёл запрос. `.filter(isPresent)` убирает `null` из типа. Вложенную связь (`isPopulated(post.author, "posts")`) проверяют вторым вызовом на загруженном документе. Подробнее об устройстве типа и обо всех формах связей — в справочнике [Типы populate](../reference/populate/populate-types.mdx#ispopulated).

У формы есть границы. Документ, загруженный с `select`, который убрал обязательные поля, с `transform` или с `justOne` над массивом ссылок, к `AnyPopulationDoc` не присваивается: в нём нет того, что форма обещает. Для такого документа параметр функции описывают типом результата запроса, как в разделе выше. Методы записи и загрузки (`$set`, `$populate`, `$depopulate`) у формы отсутствуют: они зависят от состояния, которого форма не знает.

## Что делать с null

Ситуация: вы загрузили автора, а он удалён. Единичная ссылка после populate — документ или `null`, и без проверки к `post.author.name` обратиться нельзя. Способов три, и какой выбрать, зависит от того, что значит пропавший автор для вашего кода.

Если `null` допустим (подпись «аноним»), сужайте через `?.` и `??` или через [`isPresent`](../reference/populate/populate-types.mdx#ispresent): охранник убирает `null` и `undefined` из типа и работает с любой формой — документом, lean и plain.

```ts twoslash

}
@Schema({ collection: "posts" })

  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;

// ---cut---

## Потребовать загрузку: $assertPopulated

Ситуация: связь мог загрузить код, за которым тип не уследил: хук, вспомогательная функция, которая вызвала `$populate` у документа. Вам нужно и подтвердить это, и получить точный тип. [`$assertPopulated`](../reference/documents/document-api.mdx#assertpopulated) проверяет во время работы, что путь загружен, и сужает тип возвращаемого значения. Ничего не загружает: если путь не загружен, бросает ошибку.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
import type { HydratedDoc } from "@venloc/typemo";

// код читателя: загружает автора как побочный эффект
const warmUp = async (post: HydratedDoc<Post>) => {
  await post.$populate("author");
};

const post = await Posts.findOne({ title: "Hello" }).orFail();
await warmUp(post);
const loaded = post.$assertPopulated("author");
console.log(loaded.author?.name);
// → "Alice"
```

Метод возвращает тот же документ, но с типом, в котором путь загружен, поэтому пользуйтесь возвращённым значением: тип самой переменной `post` от вызова не меняется. Пустой результат тоже считается загруженным: если у поста нет тегов и массив после populate пуст, `$assertPopulated("tags")` проходит, потому что populate выполнялся. Так же проходит и пропавшая единичная ссылка: её значение `null`, поэтому поле в возвращённом типе остаётся `HydratedDoc<User> | null`. Если путь не загружен, вы получаете ошибку до того, как обратитесь к полю:

```text
QueryError: $assertPopulated: "author" of Post is not populated — populate it first
```

Несколько путей проверяются одним вызовом: метод принимает тот же список путей и объектов, что и [`$populate`](./document-populate.mdx), например `post.$assertPopulated(["author", "tags"])`. Ошибка называет первый незагруженный путь из списка. У объекта с вложенным `populate` проверяется и вложенный путь: `{ path: "author", populate: "company" }` требует, чтобы был загружен и `author`, и `author.company`.

Для вложенного пути проверяется вся цепочка: `post.author` у комментария проходит, только если загружены и `post`, и `author` у найденных постов; если загружен один `post`, метод сообщит `QueryError: $assertPopulated: "post.author" of Comment is not populated — populate it first`. Тем же методом можно передать объект: `{ path: "tags", select: { label: 1 } }`, чтобы тип учёл выбранные поля.

Метод становится подтверждением: вы говорите компилятору «здесь уже загружено» и получаете проверку во время работы. Если связь не загружена, вы узнаете об этом сразу, а не по `undefined` в середине шаблона письма. Если же функции нужен не один документ, а возможность принять любой, есть [`isPopulated`](../reference/populate/populate-types.mdx#ispopulated): он не бросает ошибку, а выбирает ветку.

## Проверить загрузку без ошибки: $populated

Если ошибка вам не нужна, а нужно ветвление, спросите [`$populated`](../reference/documents/document-api.mdx#populated): для загруженного пути он вернёт исходные идентификаторы, для незагруженного — `undefined`.

## Как выглядят типы загруженных полей

Документ с загруженной связью называется [`HydratedDocWith`](../reference/values/form-types.mdx#hydrateddocwith): первым аргументом стоит класс, вторым — загруженные поля в том виде, в каком они читаются. Для поста с автором это `HydratedDocWith<Post, { author: HydratedDoc<User> | null }>`. Остальные поля такие же, как у `HydratedDoc<Post>`, и в подсказке не повторяются. Внутри типа загруженное поле описано через [`PopulatedField<Value, Original>`](../reference/populate/populate-types.mdx#populatedfield): он хранит и значение после загрузки, и исходный тип. В подсказках его не видно, но он объясняет две вещи. Метод [`$depopulate`](../reference/documents/document-api.mdx#depopulate) знает, к какому типу вернуть поле (`Ref<User>`): это [`Depopulated`](../reference/populate/populate-types.mdx#depopulated). А [`$set`](../reference/documents/document-api.mdx#set) загруженного поля принимает идентификаторы, а не документы.

```ts twoslash

Подсказка для самого документа называет класс и загруженное поле: `HydratedDocWith<Post, { author: HydratedDoc<User> | null }>`. После `$depopulate()` всех загруженных полей документ снова читается как `HydratedDoc<Post>`.

## Как выбрать способ

Задайте себе вопрос: **кто знает, что связь загружена?** Если это код, который сам сделал запрос, назовите тип из его результата: проверка бесплатна и выполняется компилятором. Если функция должна принять документ в любом состоянии, опишите параметр как `AnyPopulationDoc` и спросите `isPopulated`: ветка выбирается по тому, что есть на самом деле. Если связь могла загрузить другой код, а вам нужен конкретный `HydratedDoc`, потребуйте загрузку `$assertPopulated`: вы платите проверкой во время работы, зато нарушение видно сразу и с понятным текстом. Если вам нужно ветвление без сужения типа, спросите `$populated`. Отдельный вопрос про `null`: пропавшая ссылка допустима — `isPresent`, не допустима — `required: true`.

## Когда это не нужно

Если вы читаете в виде plain или lean и грузите связь в том же запросе, отдельная проверка не нужна: тип результата уже точный, а из функции его можно вывести так же, как для документа. Если функция сама вызывает `$populate`, проверять нечего: возвращённое значение уже с нужным типом. А если ссылка у вас не нужна как документ вовсе (достаточно `_id`), populate и проверки вокруг него лишние.

## Частые ошибки

### `$assertPopulated` не изменил тип переменной

Вы вызвали `post.$assertPopulated("author")` и продолжаете обращаться к `post.author?.name`. Компилятор: `Property 'name' does not exist on type 'Ref<User>'`. Метод сужает тип возвращаемого значения, а не переменной: запишите результат (`const loaded = post.$assertPopulated("author")`) и работайте с ним.

### Автор «возможно null»

```

Компилятор проверяет путь так же, как в `.populate`: `Invalid populate path "nope": unknown field "nope"`. Ошибка во время работы для строки без пути — `QueryError: $assertPopulated: a populate path or { path }`.

## Полный пример

```ts twoslash title="blog/mail.ts"
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
import { type AnyPopulationDoc, type HydratedDoc, isPopulated, isPresent } from "@venloc/typemo";

// тип загруженного поста берётся из функции, которая его загружает
export const loadPost = (title: string) => Posts.findOne({ title }).populate("author").orFail();
export type LoadedPost = Awaited<ReturnType<typeof loadPost>>;

export const subject = (post: LoadedPost) =>
  `${post.title} by ${isPresent(post.author) ? post.author.name : "аноним"}`;

// пост в любом состоянии: подпись, если автор загружен
export const footer = (post: AnyPopulationDoc<Post>): string =>
  isPopulated(post, "author") ? `— ${post.author?.name ?? "аноним"}` : "";

// связь загрузил другой код; здесь её требуют и получают точный тип
export const signature = async (post: HydratedDoc<Post>) => {
  await post.$populate("author");
  const loaded = post.$assertPopulated("author");
  return `— ${loaded.author?.name ?? "аноним"}`;
};

// ветвление без ошибки (после `signature` автор у `bare` уже загружен)
export const isReady = (post: HydratedDoc<Post>) => post.$populated("author") !== undefined;

const post = await loadPost("Hello");
const bare = await Posts.findOne({ title: "Hello" }).orFail();
console.log(subject(post), footer(bare), await signature(bare), isReady(bare));
// → "Hello by Alice" "" "— Alice" true
```
