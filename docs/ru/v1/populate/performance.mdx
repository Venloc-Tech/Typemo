Populate удобен тем, что прячет лишние запросы, и именно поэтому его легко сделать дорогим. Каждый путь — отдельный запрос к базе, каждый загруженный документ занимает память приложения. А виртуальное поле с тысячами комментариев на пост превращает список из десяти постов в десять тысяч документов.

Ускорить populate можно четырьмя способами.

- Брать меньше полей.
- Не загружать то, что нужно только посчитать.
- Ограничивать число документов на владельца.
- Когда данные нужны для расчёта, переходить на агрегацию со стадией [`$lookup`](../reference/aggregation/stages.mdx#lookup).

## Что понадобится

Клиент и модели блога из руководства [Показать связанные данные](./basics.mdx). В базе два пользователя и три поста — «Hello» и «Second» у Alice, «Bob's» у Bob. Комментариев три — `c1` и `c2` к «Hello», `c3` к «Second».

## Быстрый путь

Три самых частых приёма — выбрать только нужные поля, посчитать вместо загрузки и ограничить число документов на владельца.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
// только имя автора
const named = await Posts.find({ title: "Hello" })
  .populate({ path: "author", select: { name: 1, _id: 0 } })
  .plain();
console.log(named[0]?.author);
// → { name: "Alice" }

// число комментариев вместо самих комментариев
const counted = await Posts.find({ title: "Hello" }).populate("commentCount").plain();
console.log(counted[0]?.commentCount);
// → 2

// не больше одного комментария на пост
const limited = await Posts.find({ title: "Hello" }).populate({ path: "comments", perDocumentLimit: 1 }).plain();
console.log(limited[0]?.comments.length);
// → 1
```

## Брать только нужные поля

Для списка постов нужно имя автора, а в документе пользователя ещё профиль, настройки и длинная биография. По умолчанию populate загрузит всё это. Опция [`select`](../reference/populate/populate.mdx#select) — та же проекция, что в обычных запросах. База отдаёт только выбранные поля, и в приложение уходит меньше данных.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";

  @Prop(() => Number, { required: true }) views!: number;

  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
```

Выигрыш растёт вместе с размером связанных документов. У пользователя с тремя полями разницы почти нет, а у документа с картинками в двоичных полях она огромная. Тип результата сужается вместе с проекцией, и если вы выбрали только имя, прочитать почту компилятор не даст.

## Считать, а не загружать

В списке постов нужно показать «комментариев: 2», а сами комментарии не нужны. Виртуальное поле со счётчиком (`count: true` в [`@Virtual`](../reference/schemas/virtual.mdx)) заставляет Typemo посчитать документы на стороне базы одной агрегацией, а не загружать их и пересчитывать в приложении.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
const posts = await Posts.find().sort({ title: 1 }).populate("commentCount").plain();
console.log(posts.map((post) => [post.title, post.commentCount]));
// → [["Bob's", 0], ["Hello", 2], ["Second", 1]]
```

В [событиях операций](../observability/events.mdx) видно, что для счётчика уходит одна агрегация, `aggregate:Comment@commentCount`, а не `find`.

Счётчик не принимает `select`, `sort`, лимиты, `justOne`, `transform`, `required`, `clone` и вложенный populate. Результат — число, и ни одна из этих опций не имела бы смысла. Typemo ответит ошибкой вроде `QueryError: populate "commentCount": a count virtual takes no select (it gives a number)`. А вот `match` разрешён, и тогда считаются только подходящие документы.

## Ограничить число документов на владельца

В списке у каждого поста показывают последний комментарий, а комментариев тысячи. Опция [`perDocumentLimit`](../reference/populate/populate.mdx#perdocumentlimit), или `options.limit`, что одно и то же, ограничивает число документов на каждый пост. Для виртуальных полей на нескольких постах Typemo превращает это в одну агрегацию с `$lookup` и `$limit` на каждый пост. Нужное отбирает сама база, и лишнее в приложение не попадает.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
const posts = await Posts.find({ title: { $in: ["Hello", "Second"] } })
  .sort({ title: 1 })
  .populate({ path: "comments", perDocumentLimit: 1, options: {} })
  .plain();
console.log(posts.map((post) => post.comments.map((comment) => comment.text)));
// → [["c1"], ["c3"]]
```

Лимит действует на каждый пост отдельно — «не больше одного на пост», а не «один всего». Задать его дважды нельзя. `options.limit` вместе с `perDocumentLimit` даёт ошибку `QueryError: populate "comments": "options.limit" and "perDocumentLimit" are the same per-document limit; give one`.

## Индекс для виртуальных полей

Виртуальное поле `comments` ищет комментарии по полю `post`. Если индекса по этому полю нет, при каждом populate база просматривает всю коллекцию комментариев. Поле, по которому идёт поиск, нужно проиндексировать в модели-цели. Ссылки (`ref`) и так пользуются индексом `_id`, а у `foreignField` виртуального поля индекса нет, пока вы его не объявите.

```ts twoslash title="blog/models.ts"
import { Entity, Prop, Schema, Types, type Ref } from "@venloc/typemo";

@Schema({ collection: "posts" })
export class Post extends Entity {
  @Prop(() => String, { required: true })
  title!: string;
}

@Schema({ collection: "comments" })
export class Comment extends Entity {
  @Prop(() => String, { required: true })
  text!: string;

  @Prop(() => Types.ObjectId, { ref: () => Post, required: true, index: true }) // [!code highlight]
  post!: Ref<Post>;
}
```

Индексы создаются при синхронизации ([`Model.syncIndexes`](../reference/collections/model-indexes.mdx#modelsyncindexes)). Когда её запускать, объясняет руководство [Синхронизация индексов](../collections/index-sync.mdx).

## Не загружать в цикле

Вы читаете список постов, а потом в цикле вызываете [`$populate`](../reference/documents/document-api.mdx#populate) для каждого. Это N дополнительных запросов вместо одного, ведь каждый вызов — отдельный обмен с базой. Если связь нужна всему списку, загрузите её в запросе. `.populate` соберёт идентификаторы со всех постов и найдёт документы одним запросом.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
// медленно: по запросу на пост
const slow = await Posts.find().sort({ title: 1 });
for (const post of slow) await post.$populate("author");

// быстро: один запрос на все посты
const fast = await Posts.find().sort({ title: 1 }).populate("author");
console.log(fast.map((post) => post.author?.name));
// → ["Bob", "Alice", "Alice"]
```

## Когда лучше $lookup

Populate работает после чтения. Сначала он находит основные документы, потом связанные и склеивает их уже в приложении. Поэтому отбирать основные документы по связанным полям и считать по связанным данным на стороне базы он не умеет. Для этого нужна агрегация с [`$lookup`](../reference/aggregation/stages.mdx#lookup). База сама подтягивает документы, а следующие стадии фильтруют, группируют и считают.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
const rows = await Posts.aggregate((pipeline) =>
  pipeline
    .lookup({ from: Comment, localField: "_id", foreignField: "post", as: "comments" })
    .project({ title: 1, comments: 1 }),
).plain();
console.log(rows.map((row) => [row.title, row.comments.length]).sort());
// → [["Bob's", 0], ["Hello", 2], ["Second", 1]]
```

Агрегация возвращает строки, а не документы модели, то есть простые значения. Populate же читает целевую модель обычным запросом, и её скрытые поля и мягкое удаление продолжают действовать. В результате `.plain()` скрытое поле цели не появится, а мягко удалённый документ не найдётся. Подробнее об агрегациях — в руководстве [Соединения](../aggregation/joins.mdx).

## Как выбрать

Спросите себя, что вы делаете со связанными данными — показываете или считаете.

- **Показываете** — populate с `select` и лимитом.
- **Только считаете** — счётчик, `count: true`.
- **Отбираете основные документы по связанным или группируете** — `$lookup`.

Если связанные данные нужны не всем строкам списка, а только выбранной, загрузите их отдельным запросом, когда пользователь её откроет.

## Когда это не нужно

Если список маленький, скажем десяток постов, и связанные документы невелики, оптимизировать нечего. Два запроса почти не отличаются от одного. Беритесь за оптимизацию, когда в [событиях операций](../observability/events.mdx) видно много подзапросов или большие результаты, а не заранее.

## Если что-то пошло не так

**Список замедлился после добавления виртуального поля.** Обычно на `foreignField` нет индекса или вы загружаете все документы там, где хватило бы счётчика или лимита. Загляните в события. Подзапрос `find:Comment@comments` без индекса просматривает всю коллекцию. Добавьте `index: true` к полю цели, а где нужно — `perDocumentLimit` или `count: true`.

**Документов загружено больше, чем ожидалось.** `options.limit` действует на каждого владельца отдельно, а не на весь результат. Чтобы ограничить размер всего списка, ограничьте основной запрос через `.limit`, а не populate.

## Полный пример

```ts twoslash title="blog/reports.service.ts"
// список для главной: имя автора и число комментариев, без лишних данных
export const listForHome = async () => {
  const posts = await Posts.find()
    .sort({ title: 1 })
    .populate([{ path: "author", select: { name: 1 } }, "commentCount"])
    .plain();
  return posts.map((post) => ({ title: post.title, author: post.author?.name, comments: post.commentCount }));
};

// страница поста: последний комментарий вместо всех
export const readPost = async (title: string) => {
  const post = await Posts.findOne({ title })
    .populate({ path: "comments", options: { sort: { text: -1 }, limit: 1 } })
    .orFail()
    .plain();
  return post.comments.map((comment) => comment.text);
};
```
