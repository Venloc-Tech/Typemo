Populate удобен, потому что скрывает лишние запросы, но именно поэтому его легко сделать дорогим. Каждый путь — это отдельный запрос к базе, каждый загруженный документ занимает память приложения, а виртуальное поле с тысячами комментариев на пост превращает список из десяти постов в десять тысяч документов. Ускорить populate можно четырьмя способами: брать меньше полей, не загружать то, что нужно только посчитать, ограничивать число документов на владельца и, когда данные нужны для расчёта, переходить на агрегацию со стадией [`$lookup`](../reference/aggregation/stages.mdx#lookup).

## Что предполагается

Примеры используют клиент и модели блога из руководства [Показать связанные данные](./basics.mdx). В базе два пользователя, три поста («Hello» и «Second» Alice, «Bob's» Bob) и три комментария: `c1` и `c2` к «Hello», `c3` к «Second».

## Быстрый путь

Три самых частых приёма: выбрать только нужные поля, посчитать вместо загрузки, ограничить число документов на владельца.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
// только имя автора
const named = await Posts.find({ title: "Hello" })
  .populate({ path: "author", select: { name: 1, _id: 0 } })
  .plain();
console.log(named[0]?.author);
// → { name: "Alice" }

// число комментариев вместо самих комментариев
const counted = await Posts.find({ title: "Hello" }).populate("commentCount").plain();
console.log(counted[0]?.commentCount);
// → 2

// не больше одного комментария на пост
const limited = await Posts.find({ title: "Hello" }).populate({ path: "comments", perDocumentLimit: 1 }).plain();
console.log(limited[0]?.comments.length);
// → 1
```

## Брать только нужные поля

Ситуация: для списка постов нужно имя автора, а у пользователя в документе профиль, настройки, длинная биография. По умолчанию populate загрузит всё. Опция [`select`](../reference/populate/populate.mdx#select) — та же проекция, что и в обычных запросах: база отдаёт только выбранные поля, и в приложение уходит меньше данных.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;

  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })

  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];

  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;

```

Выигрыш растёт вместе с размером связанных документов: у пользователя с тремя полями разницы почти нет, а у документа с картинками в двоичных полях она огромная. Тип результата сужается вместе с проекцией, поэтому при выборе только имени компилятор не позволит прочитать почту.

## Считать, а не загружать

Ситуация: в списке постов нужно показать «комментариев: 2», а сами комментарии не нужны. Виртуальное поле со счётчиком (`count: true` в [`@Virtual`](../reference/schemas/virtual.mdx)) заставляет Typemo посчитать документы на стороне базы одной агрегацией, а не загрузить их и пересчитать в приложении.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
const posts = await Posts.find().sort({ title: 1 }).populate("commentCount").plain();
console.log(posts.map((post) => [post.title, post.commentCount]));
// → [["Bob's", 0], ["Hello", 2], ["Second", 1]]
```

В [событиях операций](../observability/events.mdx) видно, что для счётчика уходит одна агрегация (`aggregate:Comment@commentCount`), а не `find`. Счётчик не принимает `select`, `sort`, лимиты, `justOne`, `transform`, `required`, `clone` и вложенный populate: результат — число, и любая из этих опций была бы бессмысленной, поэтому Typemo отвечает ошибкой (`QueryError: populate "commentCount": a count virtual takes no select (it gives a number)`). Опция `match` разрешена: считаются только подходящие документы.

## Ограничить число документов на владельца

Ситуация: на странице списка у каждого поста показывают последний комментарий, а комментариев тысячи. Опция [`perDocumentLimit`](../reference/populate/populate.mdx#perdocumentlimit) (или `options.limit`, это одно и то же) ограничивает число документов на каждый пост. Для виртуальных полей на нескольких постах Typemo превращает это в один запрос-агрегацию с `$lookup` и `$limit` на каждый пост, то есть база сама отбирает нужное, и приложение не получает лишнего.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
const posts = await Posts.find({ title: { $in: ["Hello", "Second"] } })
  .sort({ title: 1 })
  .populate({ path: "comments", perDocumentLimit: 1, options: {} })
  .plain();
console.log(posts.map((post) => post.comments.map((comment) => comment.text)));
// → [["c1"], ["c3"]]
```

Лимит действует на каждый пост отдельно: «не больше одного на пост», а не «один всего». Лимит не задаётся дважды: `options.limit` вместе с `perDocumentLimit` — ошибка `QueryError: populate "comments": "options.limit" and "perDocumentLimit" are the same per-document limit; give one`.

## Индекс для виртуальных полей

Ситуация: виртуальное поле `comments` ищет комментарии по полю `post`. Если по этому полю нет индекса, для каждого populate база просматривает всю коллекцию комментариев. Поле, по которому ищут, нужно проиндексировать в модели-цели: для ссылок (`ref`) и так используется индекс `_id`, а вот `foreignField` виртуального поля индекса не имеет, пока вы его не объявили.

```ts twoslash title="blog/models.ts"
import { Entity, Prop, Schema, Types, type Ref } from "@venloc/typemo";

@Schema({ collection: "posts" })
export class Post extends Entity {
  @Prop(() => String, { required: true })
  title!: string;
}

@Schema({ collection: "comments" })
export class Comment extends Entity {
  @Prop(() => String, { required: true })
  text!: string;

  @Prop(() => Types.ObjectId, { ref: () => Post, required: true, index: true }) // [!code highlight]
  post!: Ref<Post>;
}
```

Индексы создаются при синхронизации ([`Model.syncIndexes`](../reference/collections/model-indexes.mdx#modelsyncindexes)); руководство [Синхронизация индексов](../collections/index-sync.mdx) объясняет, когда её запускать.

## Не загружать в цикле

Ситуация: вы читаете список постов, а в цикле вызываете [`$populate`](../reference/documents/document-api.mdx#populate) для каждого. Это N дополнительных запросов вместо одного: каждый вызов — отдельный обмен с базой. Если связь нужна всему списку, загрузите её в запросе: `.populate` соберёт идентификаторы всех постов и найдёт документы одним запросом.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
// медленно: по запросу на пост
const slow = await Posts.find().sort({ title: 1 });
for (const post of slow) await post.$populate("author");

// быстро: один запрос на все посты
const fast = await Posts.find().sort({ title: 1 }).populate("author");
console.log(fast.map((post) => post.author?.name));
// → ["Bob", "Alice", "Alice"]
```

## Когда лучше $lookup

Populate работает после чтения: он сначала находит основные документы, потом связанные и склеивает их в приложении. Значит, он не умеет фильтровать основные документы по связанным полям и считать по связанным данным на стороне базы. Тогда нужна агрегация с [`$lookup`](../reference/aggregation/stages.mdx#lookup): база присоединяет документы сама, а следующие стадии могут фильтровать, группировать и считать.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
const rows = await Posts.aggregate((pipeline) =>
  pipeline
    .lookup({ from: Comment, localField: "_id", foreignField: "post", as: "comments" })
    .project({ title: 1, comments: 1 }),
).plain();
console.log(rows.map((row) => [row.title, row.comments.length]).sort());
// → [["Bob's", 0], ["Hello", 2], ["Second", 1]]
```

Результат агрегации — строки, а не документы модели: вместо гидратированных документов вы получаете простые значения. Populate, напротив, читает целевую модель обычным запросом, и её скрытые поля и мягкое удаление действуют (в plain скрытое поле цели не попадает в результат, документ, удалённый мягким удалением, не находится). Подробнее об агрегациях — в руководстве [Соединения](../aggregation/joins.mdx).

## Как выбрать

Задайте себе один вопрос: **что вы делаете со связанными данными: показываете или считаете?** Показываете — populate с `select` и лимитом. Только считаете — счётчик (`count: true`). Фильтруете основные документы по связанным или группируете — `$lookup`. Если связанные данные нужны не всем строкам списка, а только выбранной, загрузите их отдельным запросом по действию пользователя.

## Когда это не нужно

Если список маленький (десяток постов) и связанные документы небольшие, оптимизировать нечего: два запроса почти не отличаются от одного. Начинайте оптимизацию, когда вы видите в [событиях операций](../observability/events.mdx) много подзапросов или большие результаты, а не заранее.

## Частые ошибки

### Список стал медленным после добавления виртуального поля

Причина обычно в отсутствии индекса на `foreignField` или в том, что вы загружаете все документы, тогда как нужен счётчик или лимит. Проверьте события: подзапрос `find:Comment@comments` без индекса просматривает коллекцию. Добавьте `index: true` к полю цели и `perDocumentLimit` или `count: true` там, где нужно.

### Загруженных документов больше, чем ожидалось

Лимит `options.limit` действует на каждого владельца отдельно, а не на весь результат. Чтобы ограничить общий размер списка, ограничьте основной запрос (`.limit`), а не populate.

## Полный пример

```ts twoslash title="blog/reports.service.ts"

}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;

  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);

// список для главной: имя автора и число комментариев, без лишних данных
export const listForHome = async () => {
  const posts = await Posts.find()
    .sort({ title: 1 })
    .populate([{ path: "author", select: { name: 1 } }, "commentCount"])
    .plain();
  return posts.map((post) => ({ title: post.title, author: post.author?.name, comments: post.commentCount }));
};

// страница поста: последний комментарий вместо всех
export const readPost = async (title: string) => {
  const post = await Posts.findOne({ title })
    .populate({ path: "comments", options: { sort: { text: -1 }, limit: 1 } })
    .orFail()
    .plain();
  return post.comments.map((comment) => comment.text);
};
```
