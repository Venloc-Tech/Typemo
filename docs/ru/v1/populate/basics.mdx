Чтобы показать пост с именем автора, а не с непонятным идентификатором, вызовите [`.populate`](../reference/populate/populate.mdx#populate). Он прочитает связанные документы и подставит их на место идентификаторов. В MongoDB документы хранятся отдельно и ссылаются друг на друга по `_id`, а сервер при чтении сам их не соединяет. Без populate вам пришлось бы собрать идентификаторы, сделать второй запрос и разложить результат по местам. Typemo делает это одним вызовом и, что важнее, меняет тип результата. Компилятор знает, что в `author` теперь пользователь, а не идентификатор, или `null`, если пользователя удалили.

Если ссылки между документами вам в новинку, хватит одной идеи. Поле, объявленное как `Ref<User>`, хранит `_id` документа пользователя, а `.populate("author")` подставляет вместо него самого пользователя. Ссылки описываются в схеме, об этом рассказывает руководство [Ссылки на другие модели](../schemas/references.mdx).

## Что понадобится

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модели блога — пользователь, тег, пост и комментарий. Модель растёт по ходу страницы, а целиком показана в справочнике [`.populate`](../reference/populate/populate.mdx). Данные в базе такие.

- Два пользователя — Alice и Bob.
- Два тега — `db` и `ts`.
- Три поста. «Hello» и «Second» написала Alice, «Bob's» — Bob. У «Hello» теги `db` и `ts`, у «Second» тег `ts`, у «Bob's» тегов нет.

Идентификаторы в результатах сокращены до `"…"`. Начнём с двух моделей, где пост хранит идентификатор автора.

```ts twoslash title="blog/models.ts"
import { Entity, Prop, Schema, Types, type Ref } from "@venloc/typemo";

@Schema({ collection: "users" })
export class User extends Entity {
  @Prop(() => String, { required: true })
  name!: string;

  @Prop(() => String)
  email?: string;
}

@Schema({ collection: "posts" })
export class Post extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Types.ObjectId, { ref: () => User, required: true })
  author!: Ref<User>;
}
```

## Быстрый путь

Вот три самых частых вызова. Каждый принимает путь поля со ссылкой, и в результате тот же пост, только в `author` вместо идентификатора лежит пользователь. `?.` в примерах нужен из-за `null` — если автора удалили, поле станет `null`, об этом ниже.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
// одна ссылка
const post = await Posts.findOne({ title: "Hello" }).populate("author").orFail().plain();
console.log(post.author?.name);
// → "Alice"

// только нужные поля связанного документа
const slim = await Posts.findOne({ title: "Hello" })
  .populate({ path: "author", select: { name: 1, _id: 0 } })
  .orFail()
  .plain();
console.log(slim.author);
// → { name: "Alice" }

// несколько связей за раз
const full = await Posts.findOne({ title: "Hello" }).populate(["author", "tags"]).orFail().plain();
console.log(full.author?.name, full.tags.map((tag) => tag.label));
// → "Alice" ["db", "ts"]
```

Ниже разберём каждый случай на живых задачах — список постов с авторами, выбор полей, связи «один ко многим», тип результата и число запросов.

## Показать автора в списке постов

На главной странице блога нужен список постов с именами авторов. Пост хранит только `author`, то есть идентификатор, и без populate имя взять неоткуда.

```ts twoslash title="blog/posts.service.ts"

  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;

console.log(await listPosts());
// → [{ title: "Bob's", author: "Bob" }, { title: "Hello", author: "Alice" }, { title: "Second", author: "Alice" }]
```

Typemo прочитал три поста, собрал из них идентификаторы авторов — Bob и Alice, каждого по разу, — одним запросом прочитал этих пользователей и разложил по постам. Число запросов от числа постов не зависит. Их два и при трёх постах, и при тысяче.

Посмотрите на тип. После `.populate("author")` поле `author` уже не `Ref<User>`, а объект пользователя или `null`, поэтому к имени обращаются через `?.`. Автора могли удалить уже после того, как пост был записан, подробнее — в разделе [Что вернётся и какой тип](#что-вернётся-и-какой-тип).

Уберите `.populate`, и тип подскажет разницу. Без него `post.author` — идентификатор, и `post.author.name` не скомпилируется.

## Выбрать только нужные поля связанного документа

Из автора нужно только имя. Почту показывать не стоит, да и тянуть её незачем. Опция [`select`](../reference/populate/populate.mdx#select) работает как обычная проекция, только для связанных документов.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
const post = await Posts.findOne({ title: "Hello" })
  .populate({ path: "author", select: { name: 1 } })
  .orFail()
  .plain();
console.log(post.author);
// → { _id: "…", name: "Alice" }
```

`_id` остаётся, пока вы явно его не исключите, — проекция везде в Typemo работает одинаково. Тип поля сужается вместе с выбором, и к `post.author?.email` компилятор не пустит, этого поля в результате нет. А ещё выбор полей уменьшает объём данных, которые база отдаёт приложению, и на больших связанных документах это заметно. Подробнее — в руководстве [Производительность populate](./performance.mdx).

Каждый путь — это отдельный запрос к своей модели, так что три пути дадут три дополнительных запроса. Пути можно и цеплять вызовами `.populate("author").populate("tags")`, результат будет тот же. Но повторный вызов для того же пути не добавляется к прежнему, а заменяет его. Выигрывает последний.

## Обратная связь через виртуальное поле

Нужны комментарии поста. Но пост не хранит их идентификаторы, а наоборот, каждый комментарий хранит ссылку на пост. Такую обратную связь описывает **виртуальное поле**. В базу оно ничего не пишет, а при populate находит комментарии по полю `post`. Опишем его в модели поста.

```ts twoslash title="blog/models.ts"
import { Entity, Prop, Schema, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";

@Schema({ collection: "users" })
export class User extends Entity {
  @Prop(() => String, { required: true })
  name!: string;

  @Prop(() => String)
  email?: string;
}

@Schema({ collection: "posts" })
export class Post extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Types.ObjectId, { ref: () => User, required: true })
  author!: Ref<User>;

  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) // [!code ++]
  comments?: VirtualRef<Comment>; // [!code ++]
}

@Schema({ collection: "comments" })
export class Comment extends Entity {
  @Prop(() => String, { required: true })
  text!: string;

  @Prop(() => Types.ObjectId, { ref: () => Post, required: true })
  post!: Ref<Post>;
}
```

`localField` — поле поста, чьё значение ищем (`_id`), а `foreignField` — поле комментария, где оно должно лежать (`post`). Подробнее о виртуальных полях — в руководстве [Виртуальные поля](../schemas/virtuals.mdx). Загружается виртуальное поле так же, как ссылка.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;

@Schema({ collection: "tags" })

  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}

```

У поста без комментариев виртуальное поле — пустой массив, а не отсутствие значения. После populate виртуальное поле есть всегда. Если нужно только число комментариев, объявите виртуальное поле со счётчиком (`count: true`). Тогда [`populate`](../reference/populate/populate.mdx#populate) попросит базу посчитать документы, а не загружать их. Остальные виды связей — вложенные, через карты и полиморфные — разобраны в руководстве [Сложные связи](./complex-relations.mdx).

## Что вернётся и какой тип

Ссылка, которая не нашла документ, ведёт себя по форме поля. Единичная ссылка становится `null`, а из массива элемент просто исчезает, и остальные сохраняют порядок. Так бывает, если документ удалили или скрыли мягким удалением.

Поэтому тип единичной ссылки после populate всегда допускает `null` — `HydratedDoc<User> | null` у документа и `{ … } | null` в результатах `.lean()` и `.plain()`. Схема этого не исключит. `required: true` у `@Prop` требует, чтобы идентификатор лежал в посте, но не обещает, что пользователь с таким идентификатором существует.

```ts twoslash
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
const [bobPost, hello] = await Posts.find({ title: { $in: ["Bob's", "Hello"] } })
  .sort({ title: 1 })
  .populate({ path: "tags", match: { label: "ts" } })
  .plain();
console.log(bobPost?.tags.length, hello?.tags.map((tag) => tag.label));
// → 0 ["ts"]
```

Опция [`match`](../reference/populate/populate.mdx#match) оставила из тегов только `ts`, и у «Hello» пропала ссылка на `db`. Что окажется в поле, зависит от вида результата. У документа это документ модели-цели со всеми методами, и такой массив доступен только для чтения. В результатах [`.lean()`](../reference/query/reading.mdx#lean) и [`.plain()`](../reference/query/reading.mdx#plain) — простые объекты. Разницу видно по `_id`. В `.lean()` это `ObjectId`, в `.plain()` — строка.

Как быть со сменой типа, если документ уходит в вашу функцию, рассказано в руководстве [Проверка типа](./type-checks.mdx). А менять и сохранять загруженные документы нужно осторожно, об этом — в [Populate у документа](./document-populate.mdx).

## Сколько запросов уходит в базу

Один путь — это один дополнительный запрос к модели-цели, сколько бы документов вы ни прочитали. Подзапросы видны в [событиях операций](../observability/events.mdx). У каждого заполнен `populatePath`, а родителем указан основной запрос. Вот события для `Posts.find().populate(["author", "tags", "comments"])`.

```text
find:Post
find:User@author
find:Tag@tags
find:Comment@comments
```

Запросы к разным моделям идут параллельно, а внутри транзакции — по очереди. Начаться раньше основного запроса они не могут. Только когда посты прочитаны, становится известно, какие идентификаторы искать. Если основной запрос ничего не нашёл, дополнительных запросов не будет вовсе.

## Как выбрать

Спросите себя, что вы будете делать со связанными данными.

- **Показать вместе с основными, а лежат они в других коллекциях** — берите populate.
- **Нужен один связанный документ, а основной уже есть** — обычный [`findById`](../reference/query/reading.mdx#modelfindbyid) короче и понятнее.
- **Считать по связанным данным** — сумма, среднее, группировка, — **или отбирать основные документы по связанным полям**. Нужна агрегация со стадией [`$lookup`](../reference/aggregation/stages.mdx#lookup). Populate загружает документы уже после основного запроса, и отбирать по ним основной запрос не может.

## Когда populate не нужен

Если связанные данные пользователю не показываются, а нужны только для проверки вроде «существует ли автор», загружать их незачем. Хватит [`exists`](../reference/query/reading.mdx#modelexists). Если ссылка нужна только как идентификатор, например для адреса `/users/<id>`, populate тоже лишний. И если нужно найти пост по полю автора, скажем все посты авторов из Москвы, populate не поможет — он работает после чтения основных документов.

## Если что-то пошло не так

**Вместо автора идентификатор.** `.populate` вызван не на том поле или не вызван совсем. В результате `.plain()` там строка, в `.lean()` и в документе — `ObjectId`. Тип подскажет — `post.author.name` не скомпилируется с ошибкой `Property 'name' does not exist on type 'string'`. Вызовите `.populate("author")`.

**Путь — не ссылка.** Например, populate по обычному полю.


Компилятор ответит `TS2345: Argument of type '"title"' is not assignable to parameter of type 'PopulateObject | "Invalid populate path \"title\": \"title\" is not a reference"'`. Если путь пришёл из данных, во время работы придёт `QueryError: populate "title": "title" is neither a reference nor an embedded document`. Populate работает только с полями, помеченными `ref`, и с виртуальными полями. Укажите поле со ссылкой, например `author` или `tags`.

**Автор оказался `null`.** Ссылка указывает на документ, которого нет или который скрыт мягким удалением. Populate ошибку не бросает, а ставит `null`, и тип это допускает, поэтому `post.author.name` не скомпилируется (`TS18047: 'post.author' is possibly 'null'`). Если такая ссылка нормальна, проверяйте её через `?.` или [`isPresent`](../reference/populate/populate-types.mdx#ispresent). Если она означает испорченные данные, попросите [`required: true`](../reference/populate/populate.mdx#required). Тогда пропавший документ бросит `DocumentNotFoundError`, а `null` уйдёт из типа результата.

## Полный пример

```ts twoslash title="blog/posts.service.ts"
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
// список для главной: автор и теги, без лишних полей
export const listPosts = async () => {
  const posts = await Posts.find()
    .sort({ title: 1 })
    .populate([
      { path: "author", select: { name: 1 } },
      { path: "tags", select: { label: 1 } },
    ])
    .plain();
  return posts.map((post) => ({
    title: post.title,
    author: post.author?.name,
    tags: post.tags.map((tag) => tag.label),
  }));
};

// страница поста: автор и комментарии с их авторами
export const readPost = async (title: string) => {
  const post = await Posts.findOne({ title })
    .populate(["author", { path: "comments", populate: { path: "author", select: { name: 1 } } }])
    .orFail()
    .plain();
  return {
    title: post.title,
    author: post.author?.name,
    comments: post.comments.map((comment) => `${comment.author?.name}: ${comment.text}`),
  };
};

console.log(await listPosts());
// → [{ title: "Bob's", author: "Bob", tags: [] }, { title: "Hello", author: "Alice", tags: ["db", "ts"] }, { title: "Second", author: "Alice", tags: ["ts"] }]
console.log(await readPost("Hello"));
// → { title: "Hello", author: "Alice", comments: ["Bob: c1", "Alice: c2"] }
```

<Callout type="migration">

В Typemo `limit` и `skip` в `populate` действуют на каждый исходный документ отдельно и точно — `limit: 2` значит «не больше двух документов на пост». Повторный вызов `.populate` для того же пути заменяет прежний, а неизвестный путь или неизвестная опция — ошибки, а не тихий пропуск.
