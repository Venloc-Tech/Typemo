**Представление** (view) — это готовая выборка. MongoDB хранит её как конвейер над другой коллекцией и пересчитывает при каждом чтении. Например, «только открытые счета», «заказы без персональных данных» или «сводка по клиентам». Приложение читает представление как обычную коллекцию, а условия выборки записаны в одном месте, в базе, и не повторяются в каждом запросе.

В Typemo представление описывает `TypedView`. Оно задаётся классом, и чтение получает те же типы, что у модели.

Если вы ещё не работали с агрегациями, начните с руководства [Первая агрегация](../aggregation/first-aggregation.mdx). Конвейер представления собирается тем же строителем.

## Что понадобится [#prerequisites]

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и счета. В коллекции `accounts` три документа.

- Main — владелец alice, баланс 120, открыт.
- Old — alice, 0, закрыт.
- Savings — bob, 500, открыт.

```ts twoslash title="accounts/account.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => Number, { required: true })
  balance!: number;

  @Prop(() => Boolean, { required: true })
  closed!: boolean;
}
```

## Быстрый путь [#quick-start]

Опишите класс строки представления, определите представление через [`TypedView.define`](../reference/collections/typed-view.mdx#typed-view.define), создайте его в базе через [`ensure`](../reference/collections/typed-view.mdx#typed-view.ensure) и читайте.

```ts twoslash
import { Entity, Prop, Schema, TypedView, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => Boolean, { required: true }) closed!: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const connection = client.connection;
// ---cut---
@Schema({ collection: "open_accounts" })
class OpenAccount extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}

const openAccounts = TypedView.define(connection, OpenAccount, {
  on: Account,
  pipeline: (p) => p.match({ closed: false }).project({ title: 1, owner: 1, balance: 1 }),
});
await openAccounts.ensure();
console.log(await openAccounts.countDocuments());
// → 2
```

Ниже разберём каждый шаг на задачах.

## Описать представление [#define-view]

Нужна выборка, которую приложение читает в нескольких местах. Класс представления пишется как обычная сущность. Его `collection` — это имя представления, а поля — то, что лежит в строке. Конвейер сверяется с классом при компиляции, и если он не выдаёт какое-то поле класса, компилятор на это укажет.

```ts twoslash title="accounts/open-account.ts"
import { Entity, Prop, Schema, TypedView, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => Boolean, { required: true }) closed!: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const connection = client.connection;
// ---cut---
@Schema({ collection: "open_accounts" })
export class OpenAccount extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => Number, { required: true })
  balance!: number;
}

export const openAccounts = TypedView.define(connection, OpenAccount, {
  on: Account,
  pipeline: (p) => p.match({ closed: false }).project({ title: 1, owner: 1, balance: 1 }),
});
```

`define` в базе ничего не создаёт, он только запоминает определение. Если `project` в конвейере пропустит `owner` или `balance`, компилятор отклонит определение и скажет, каких полей класса нет в результате. У конвейера есть ограничения — нельзя `$out` и `$merge`, а источник не должен использовать `dbName`. Подробнее в справочнике по [`TypedView.define`](../reference/collections/typed-view.mdx#typed-view.define).

## Создать представление в базе [#create-view]

Определение есть, а в базе представления ещё нет. Создать его можно двумя способами. [`connection.init`](../reference/connection/connection.mdx#connection.init) и [`connection.syncAll`](../reference/connection/connection.mdx#connection.sync-all) создают все определённые представления вместе с коллекциями. А для одного представления вызовите [`ensure`](../reference/collections/typed-view.mdx#typed-view.ensure).

```ts twoslash
import { Entity, Prop, Schema, TypedView, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => Boolean, { required: true }) closed!: boolean;
}
@Schema({ collection: "open_accounts" })
class OpenAccount extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const connection = client.connection;
const openAccounts = TypedView.define(connection, OpenAccount, {
  on: Account,
  pipeline: (p) => p.match({ closed: false }).project({ title: 1, owner: 1, balance: 1 }),
});
// ---cut---
console.log((await openAccounts.ensure()).result);
// → "created"
console.log((await openAccounts.ensure()).result);
// → "unchanged"
```

Повторный вызов безопасен. Второй `ensure` увидел, что представление уже совпадает с определением, и ничего не сделал. Обычную коллекцию и индексы для класса представления синхронизация не создаёт, [`connection.syncAll`](../reference/connection/connection.mdx#connection.sync-all) обрабатывает его именно как представление.

Пока представление не создано, чтение из него бросает [`ConfigurationError`](../reference/errors/configuration-errors.mdx#configuration-error). Сервер на такое чтение ответил бы пустым результатом, будто строк просто нет, и забытое создание никто бы не заметил. Поэтому первая операция с представлением проверяет, что оно есть.

```text
ConfigurationError: OpenAccount.find: the view "open_accounts" does not exist in the database "app" (the server would read it as empty); create it first: await connection.init(), or await view.ensure()
```

Найденное представление Typemo запоминает и больше не проверяет. Подробности и границы этого правила — в справочнике по [`TypedView`](../reference/collections/typed-view.mdx#missing-view).

## Читать строки [#read-rows]

Приложению нужны открытые счета владельца. У `TypedView` есть [`find`](../reference/collections/typed-view.mdx#typed-view.find), [`findOne`](../reference/collections/typed-view.mdx#typed-view.find-one), [`countDocuments`](../reference/collections/typed-view.mdx#typed-view.count-documents), [`distinct`](../reference/collections/typed-view.mdx#typed-view.distinct) и [`aggregate`](../reference/collections/typed-view.mdx#typed-view.aggregate). Фильтры проверяются по полям класса представления.

```ts twoslash title="accounts/accounts.service.ts"
import { Entity, Prop, Schema, TypedView, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => Boolean, { required: true }) closed!: boolean;
}
@Schema({ collection: "open_accounts" })
class OpenAccount extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const connection = client.connection;
const openAccounts = TypedView.define(connection, OpenAccount, {
  on: Account,
  pipeline: (p) => p.match({ closed: false }).project({ title: 1, owner: 1, balance: 1 }),
});
await openAccounts.ensure();
// ---cut---
export const listOpenAccounts = async (owner: string) => openAccounts.find({ owner }).sort({ balance: -1 });

const rows = await listOpenAccounts("alice");
//    ^?
console.log(rows.map((row) => [row.title, row.balance]));
// → [["Main", 120]]
```

Строки приходят обычными объектами с полями класса, как результат `.lean()`, а не документами, которые можно изменить и сохранить. Так и задумано. В представление нельзя писать, поэтому у него нет `create`, `save` и похожих методов, и их вызов не скомпилируется. Закрытого счёта `Old` в результате нет, условие `closed: false` уже применил сервер.

## Не показывать секретные поля [#hide-secrets]

Допустим, у счёта есть скрытое поле вроде `pin`, и представление не должно его выдавать. Typemo сам ставит в начало сохранённого конвейера удаление скрытых полей источника ([`hidden`](../reference/schemas/prop.mdx#hidden)). Строки представления этого поля не содержат, даже если ваш конвейер о нём ничего не знает.

Это видно по определению. У источника с полем `pin` первой стадией стоит `{ $unset: ["pin"] }`. Подробности в справочнике по [`TypedView.define`](../reference/collections/typed-view.mdx#stored-pipeline).

## Обновить определение [#update-definition]

Вы изменили конвейер, а в базе осталось старое определение. По умолчанию [`ensure`](../reference/collections/typed-view.mdx#typed-view.ensure) менять существующее представление отказывается и бросает [`CollectionOptionsError`](../reference/errors/configuration-errors.mdx#collection-options-error). Работающее представление не должно поменяться случайно.

```text
CollectionOptionsError: collection "open_accounts": the view exists with another definition (source or pipeline): run ensure({ update: true }) to change it
```

Чтобы посмотреть различие, вызовите `ensure({ dryRun: true })`. В отчёте будет `result: "updated"` и различие с `option: "pipeline"`. Чтобы применить его, вызовите `ensure({ update: true })`, а при [`connection.syncAll`](../reference/connection/connection.mdx#connection.sync-all) то же делает опция `update: true`. Оба вызова проверены на сервере.

Правило сортировки представления так не поменять. Представление придётся удалить через [`drop`](../reference/collections/typed-view.mdx#typed-view.drop) и создать заново.

## Как выбрать [#how-to-choose]

Спросите себя, **должен ли результат быть всегда свежим и как часто его читают**.

- **Результат отражает текущее состояние, а читают его умеренно** — берите представление. Оно ничего не хранит и никогда не устаревает.
- **Выборка тяжёлая, читают её часто, и небольшая задержка допустима** — сохраните результат как [материализованное представление](./materialized-views.mdx). Чтение будет быстрым, а обновлять результат вы будете сами.

## Когда это не нужно [#when-not-to-use]

Если выборка нужна в одном месте, хватит обычного [`find`](../reference/query/reading.mdx#model.find) с фильтром. Представление — это ещё один объект в базе, за которым надо следить. Если данные нужно менять через выборку, представление не подойдёт, оно только для чтения. А для разового отчёта берите [агрегацию](../aggregation/first-aggregation.mdx).

## Если что-то пошло не так [#troubleshooting]

**`ConfigurationError` — представления нет.** В тексте есть `the view "open_accounts" does not exist`. Представление определено, но на сервере не создано. Вызовите [`ensure`](../reference/collections/typed-view.mdx#typed-view.ensure) при запуске или [`connection.init`](../reference/connection/connection.mdx#connection.init).

**Представление пустое.** Чтение вернуло `[]`, хотя в источнике данные есть. Сначала проверьте условие `match` в конвейере, возможно, оно ничего не пропускает. Бывает и так, что представление создали и читали, а потом кто-то удалил его в обход Typemo. Сервер тогда отвечает пустым результатом, а повторной проверки существования нет, так что вызовите [`ensure`](../reference/collections/typed-view.mdx#typed-view.ensure) и создайте его заново.

**Компилятор не принимает конвейер.** Определение не компилируется, и ошибка называет поля. Конвейер выдаёт не все поля класса или типы не совпадают. Добавьте недостающие поля в `project` или уберите их из класса.

**`already defined on this connection`.** На подключении уже есть представление с таким именем, но другим определением — `ConfigurationError: view "open_accounts" is already defined on this connection with another definition`. Определяйте каждое представление один раз в отдельном файле и импортируйте оттуда. Повторное определение с тем же конвейером ошибкой не считается.

**Под именем представления лежит коллекция.** [`ensure`](../reference/collections/typed-view.mdx#typed-view.ensure) работать откажется (`exists as a collection, not a view: drop it or rename the view`), [`drop`](../reference/collections/typed-view.mdx#typed-view.drop) её не удалит (`is a collection, not a view: drop() only drops views`), а чтение бросит `ConfigurationError` (`"open_accounts" is a collection, not the view; drop it or rename the view, then create the view`). Переименуйте представление или удалите коллекцию вручную.

## Полный пример [#full-example]

Здесь представление и сервис, который его читает. При запуске представление создаётся вместе со всем остальным.

```ts twoslash title="accounts/open-accounts.ts"
import { Entity, Prop, Schema, TypedView, TypemoClient } from "@venloc/typemo";

@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => Number, { required: true })
  balance!: number;

  @Prop(() => Boolean, { required: true })
  closed!: boolean;
}

@Schema({ collection: "open_accounts" })
class OpenAccount extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => Number, { required: true })
  balance!: number;
}

const main = async () => {
  const client = await TypemoClient.connect("mongodb://localhost:27017/app", { name: "main" });
  const connection = client.connection;
  connection.model(Account);

  // определение: конвейер сверяется с классом OpenAccount
  const openAccounts = TypedView.define(connection, OpenAccount, {
    on: Account,
    pipeline: (p) => p.match({ closed: false }).project({ title: 1, owner: 1, balance: 1 }),
  });

  // запуск: создаёт коллекции, индексы и представления
  await connection.init();

  // чтение: обычные объекты со всеми полями класса
  const rows = await openAccounts.find({ owner: "alice" });
  console.log(rows.length);

  await client.close();
};

await main();
```

<Callout type="migration">

В Mongoose представление создают через `createCollection` с `viewOn` и `pipeline`, а модель поверх него остаётся обычной, с методами записи, которые сервер отвергнет. В Typemo у [`TypedView`](../reference/collections/typed-view.mdx) только методы чтения, а конвейер сверяется с классом строки при компиляции. Расхождение определения с базой — ошибка, а не тихий пропуск.

</Callout>
