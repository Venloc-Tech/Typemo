**Проекция** говорит базе, какие поля документа вернуть. Её задаёт [`.select`](../reference/query/reading.mdx#select), и пользы от неё две. Во-первых, по сети идёт меньше данных — списку статей для меню незачем тащить тексты и комментарии. Во-вторых, тип результата сужается вместе с выбором, и компилятор не даст обратиться к полю, которое вы не загрузили.

Если вы впервые работаете с MongoDB, запомните главное. Проекция бывает либо **включением** («верни только эти поля»), либо **исключением** («верни всё, кроме этих»). Смешивать их база не позволяет, и Typemo скажет об этом ошибкой ещё до отправки запроса.

## Что понадобится [#prerequisites]

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель статьи блога. В ней есть текст, счётчик, массив тегов, массив вложенных комментариев и скрытое поле.

```ts twoslash title="articles/article.ts"
import { Entity, type Hidden, Prop, Schema } from "@venloc/typemo";

@Schema()
export class Comment {
  @Prop(() => String, { required: true })
  author!: string;

  @Prop(() => String, { required: true })
  text!: string;

  @Prop(() => Number, { required: true })
  likes!: number;
}

@Schema({ collection: "articles" })
export class Article extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => String, { required: true })
  body!: string;

  @Prop(() => Number, { required: true })
  views!: number;

  @Prop(() => [String])
  tags!: string[];

  @Prop(() => [Comment])
  comments!: Comment[];

  @Prop(() => String, { hidden: true })
  editorNote?: Hidden<string>;
}
```

В коллекции одна статья `Intro`. У неё 120 просмотров, теги `news`, `typemo` и `mongo` и три комментария — `bob` с 3 отметками, `eve` с 0 и `dan` с 9. Ещё у неё есть заметка редактора `check facts`. Поле `editorNote` скрыто, об этом раздел [Прочитать скрытое поле](#read-hidden-field). Результаты в комментариях `// →` получены на этой статье, идентификаторы сокращены до `"…"`.

## Быстрый путь [#quick-start]

У проекции три формы — включить поля, исключить поля и убрать `_id`.

```ts twoslash
import { Entity, type Hidden, Prop, type Selected, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.db().model(Article);
// ---cut---
const included = await Articles.findOne({ title: "Intro" }).select({ title: 1, views: 1 }).plain().orFail();
//    ^?
// → { _id: "…", title: "Intro", views: 120 }

const excluded = await Articles.findOne({ title: "Intro" }).select({ body: 0, comments: 0 }).plain().orFail();
// → { _id: "…", title: "Intro", views: 120, tags: ["news", "typemo", "mongo"] }

const noId = await Articles.findOne({ title: "Intro" }).select({ title: 1, _id: 0 }).plain().orFail();
// → { title: "Intro" }
```

Ниже разберём каждую форму на настоящих задачах. Полное описание метода — в справочнике [Чтение](../reference/query/reading.mdx#select).

## Вернуть только нужные поля [#select-fields]

Если вы знаете, какие поля нужны, перечислите их со значением `1`. Вернутся эти поля и `_id`, а остальное база даже не отправит по сети. Это самая частая форма — список для страницы, выпадающее меню, карточка в поиске.

```ts twoslash title="articles/articles.service.ts"
import { Entity, type Hidden, Prop, type Selected, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.db().model(Article);
// ---cut---
export const listTitles = () =>
  Articles.find().sort({ views: -1 }).limit(20).select({ title: 1, views: 1 }).plain();

const titles = await listTitles();
//    ^?
```

Тип результата сужен до выбранных полей. У элементов есть `_id`, `title` и `views`, а `body` и `tags` нет, и обратиться к ним не выйдет. Так работают и документ, и результаты `.lean()` и `.plain()`. [`.select`](../reference/query/reading.mdx#select) не зависит от того, в каком виде вы получаете результат, и порядок вызовов не важен.

```ts twoslash
// @errors: 2339
import { Entity, type Hidden, Prop, type Selected, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.db().model(Article);
// ---cut---
const titles = await Articles.find().select({ title: 1 }).plain();
titles[0]?.body;
```

`_id` возвращается всегда, пока вы его не исключите. Это удобно, ведь по `_id` клиент потом запросит конкретную запись.

## Вернуть всё, кроме нескольких полей [#exclude-fields]

Если нужны почти все поля, а лишние тяжёлые, перечислите лишние со значением `0`. Вернётся всё остальное. Так в списке легко спрятать текст статьи и комментарии, не выписывая все прочие поля.

```ts twoslash
import { Entity, type Hidden, Prop, type Selected, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.db().model(Article);
// ---cut---
const rows = await Articles.find().select({ body: 0, comments: 0 }).plain();
//    ^?
// → [{ _id: "…", title: "Intro", views: 120, tags: ["news", "typemo", "mongo"] }]
```

У исключения есть минус. Поле, которое вы добавите в модель позже, само попадёт в такой ответ. Поэтому в ответах наружу перечисляйте нужное, а исключение оставьте внутреннему коду.

## Убрать `_id` [#remove-id]

`_id` — единственное поле, которое можно исключить внутри включения. Это пригодится, например, для выгрузки в таблицу, где идентификатор не нужен.

```ts twoslash
import { Entity, type Hidden, Prop, type Selected, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.db().model(Article);
// ---cut---
const names = await Articles.find().select({ title: 1, _id: 0 }).plain();
//    ^?
// → [{ title: "Intro" }]
```

## Прочитать скрытое поле [#read-hidden-field]

Поля с опцией [`hidden`](../reference/schemas/prop.mdx#hidden) и типом `Hidden<T>` Typemo не читает из базы, пока вы о них не попросите. Заметке редактора нечего делать в памяти приложения, когда она не нужна. Поэтому обычное чтение статьи заметку не вернёт.

```ts twoslash
import { Entity, type Hidden, Prop, type Selected, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.db().model(Article);
// ---cut---
const lean = await Articles.findOne({ title: "Intro" }).lean().orFail();
console.log("editorNote" in lean);
// → false
```

Чтобы прочитать скрытое поле, поставьте перед его именем `+`. Знак `+` не превращает выбор во включение. Вы получите все обычные поля и вдобавок скрытое.

```ts twoslash
import { Entity, type Hidden, Prop, type Selected, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.db().model(Article);
// ---cut---
const article = await Articles.findOne({ title: "Intro" }).select({ "+editorNote": true }).lean().orFail();
console.log(article.editorNote);
// → "check facts"
```

Если назвать скрытое поле в обычном включении (`{ title: 1, editorNote: 1 }`), оно тоже прочитается. Только в ответе тогда будут лишь эти два поля и `_id`.

Прочитать поле ещё не значит отдать его клиенту. В результат `.plain()` и в `$toPlain()` загруженное скрытое поле не попадёт, пока вы отдельно не скажете `{ hidden: true }`. Так проверка автора, ради которой кто-то добавил `+editorNote` в общий запрос, не обернётся утечкой. Подробнее в руководстве [Чтение данных](./reading-data.mdx#hide-secrets).

## Взять часть массива [#array-slice]

Массив можно вернуть не целиком, а частью — первые элементы, последние или диапазон. Для этого вместо флага передайте [`$slice`](../reference/query/reading.mdx#select). Число `n` возвращает первые `n` элементов, `-n` — последние `n`, а пара `[пропустить, взять]` — диапазон.

```ts twoslash
import { Entity, type Hidden, Prop, type Selected, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.db().model(Article);
// ---cut---
const first = await Articles.findOne({ title: "Intro" }).select({ title: 1, comments: { $slice: 2 } }).plain().orFail();
// → { _id: "…", title: "Intro", comments: [ { author: "bob", … }, { author: "eve", … } ] }

const last = await Articles.findOne({ title: "Intro" }).select({ title: 1, tags: { $slice: -1 } }).plain().orFail();
// → { _id: "…", title: "Intro", tags: ["mongo"] }

const middle = await Articles.findOne({ title: "Intro" }).select({ title: 1, tags: { $slice: [1, 1] } }).plain().orFail();
// → { _id: "…", title: "Intro", tags: ["typemo"] }
```

Это нужно, например, для списка, где у каждой статьи видны два последних комментария. Остальные десятки тысяч не поедут по сети.

`$slice` не превращает проекцию во включение. Напишите только `select({ comments: { $slice: 1 } })`, и вернутся **все** остальные поля статьи и один комментарий, потому что срез меняет только сам массив. Если нужны лишь некоторые поля, перечислите их рядом, как в примерах выше.

## Взять один подходящий элемент массива [#first-matching-element]

Проекция [`$elemMatch`](../reference/query/reading.mdx#select) возвращает из массива первый элемент, подходящий под условие, а не весь массив. Она выручает, когда нужен ровно один вложенный документ.

```ts twoslash
import { Entity, type Hidden, Prop, type Selected, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.db().model(Article);
// ---cut---
const article = await Articles.findOne({ title: "Intro" })
  .select({ title: 1, comments: { $elemMatch: { author: "eve" } } })
  .plain()
  .orFail();
// → { _id: "…", title: "Intro", comments: [ { author: "eve", text: "hm", likes: 0 } ] }
```

В отличие от `$slice`, `$elemMatch` включает поле. Остальные поля статьи, которые вы не назвали, не вернутся. Если подходящих элементов нет, массив в результате пустой. Не путайте эту проекцию с одноимённым оператором фильтра. Проекция выбирает, что вернуть, а [оператор фильтра](../reference/query/filter-operators.mdx#elem-match) — какие документы найти.

## Выбрать поля вложенных документов [#select-nested-fields]

Поля вложенных документов выбираются через точку. В массиве вложенных документов проекция применяется к каждому элементу.

```ts twoslash
import { Entity, type Hidden, Prop, type Selected, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}

// ---cut---
const authors = await Articles.findOne({ title: "Intro" }).select({ "comments.author": 1 }).plain().orFail();
// → { _id: "…", comments: [ { author: "bob" }, { author: "eve" }, { author: "dan" } ] }
```

## Собрать проекцию по частям [#build-projection]

Если вызвать `.select` несколько раз, выборы складываются. Это удобно, когда запрос собирается в разных местах кода. Базовый запрос выбирает общие поля, а вызывающий код добавляет свои.

```ts twoslash
import { Entity, type Hidden, Prop, type Selected, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.db().model(Article);
// ---cut---
const base = Articles.find().select({ title: 1 });

const withViews = await base.select({ views: 1 }).plain();
//    ^?
// → [{ _id: "…", title: "Intro", views: 120 }]
```

Складываются только выборы одной формы. Включение вместе с исключением — ошибка, о ней в разделе [Если что-то пошло не так](#troubleshooting). Один и тот же ключ дважды тоже не выбрать. `select({ title: 1 }).select({ title: 1 })` бросает `QueryError` с текстом `projection: "title" is selected twice`, чтобы бесполезный повторный вызов не прошёл незаметно.

## Проекция, которая приходит извне [#external-projection]

До сих пор проекция была литералом, и компилятор видел каждый её ключ. Но бывает, что поля выбирает не ваш код. Функция получает проекцию параметром, или клиент API сам просит `?fields=title,views`. Ключей тогда компилятор не знает.

[`.select`](../reference/query/reading.mdx#select) принимает такую проекцию без приведений типов и обходов. Подойдёт значение объявленного типа [`Projection<Article>`](../reference/values/query-types.mdx#projection) или словарь `Record<string, 0 | 1>`.

```ts twoslash title="articles/articles.service.ts"
import { Entity, type Hidden, Prop, type Projection, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.db().model(Article);
// ---cut---
export const pick = (id: string, fields: Projection<Article>) =>
  Articles.findById(id).select(fields).plain().orFail();

const intro = await Articles.findOne({ title: "Intro" }).plain().orFail();
const card = await pick(intro._id, { title: 1, views: 1 });
//    ^?
// → { _id: "…", title: "Intro", views: 120 }
declare const fields: Record<string, 0 | 1>;
const doc = await Articles.findOne({ title: "Intro" }).select(fields).orFail();
//    ^?
```

Компилятор не знает, какие ключи окажутся в `fields`, поэтому описывает результат самым широким образом. Это все поля модели, и каждое необязательно. Необязательными становятся только поля верхнего уровня, вложенные документы остаются такими, как в модели. Документ без `.plain()` редактор покажет как `HydratedDoc<Partial<Article>>`, то есть класс модели со всеми полями необязательными.

Тот же широкий результат получится, даже если проекция имеет тип `any`. В типе результата останутся поля модели, а не `any`. А то, что литерал проверил бы при компиляции, проверяется при запуске, ещё до базы. Неизвестный путь даёт `StrictModeError`, а включение вместе с исключением — `QueryError`, как описано в разделе [Если что-то пошло не так](#troubleshooting).

### Поля, которые выбирает клиент [#client-selected-fields]

Если набор полей строится из данных запроса, оберните его в [`untrusted(fields, "projection")`](../reference/policies/soft-delete-and-untrusted.mdx#untrusted). Функция вернёт ту же проекцию, но откажется принимать ключи, которые начинаются с `$` или `+`. Через `$` клиент превратил бы проекцию в вычисляемое выражение, а через `+` прочитал бы скрытое поле вроде заметки редактора.

```ts twoslash title="articles/articles.controller.ts"
import { Entity, type Hidden, Prop, Schema, TypemoClient, untrusted } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.db().model(Article);
// ---cut---
// код читателя: разбор ?fields=title,views в словарь { title: 1, views: 1 }
declare const __parseFields__: (raw: string) => Record<string, 0 | 1>;

export const listArticles = (rawFields: string) =>
  Articles.find().select(untrusted(__parseFields__(rawFields), "projection")).plain();

const rows = await listArticles("title,views");
//    ^?
// → [{ _id: "…", title: "Intro", views: 120 }]
```

Если клиент прислал запрещённый ключ, запрос не построится.

```text
StrictModeError: untrusted value: "+editorNote" at "+editorNote" — a "+path" key inside data from outside would select a Hidden field; validate the input and build the projection yourself [sanitize]
```

`untrusted` — только дополнительная страховка, а не проверка ввода. Какие поля вы готовы отдать, он не знает. Сверяйте поля клиента со списком разрешённых и собирайте проекцию сами, в примере выше это делает ваша функция `__parseFields__`. Без второго аргумента `untrusted` пишет в тексте ошибки про фильтр, с `"projection"` — про проекцию.

## Описать форму ответа [#define-response-shape]

У типа результата можно дать имя. Когда функция сервиса возвращает выборку, тип пишут в сигнатуре, чтобы обработчик и клиентская часть знали форму ответа. Переписывать поля вручную не нужно. Тип [`Selected`](../reference/query/contracts.mdx#selected) описывает строку результата `.plain()` по модели и списку полей.

```ts twoslash title="articles/articles.service.ts"
import { Entity, type Hidden, Prop, type Selected, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.db().model(Article);
// ---cut---
export type ArticlePreview = Selected<Article, "title" | "views">;
//          ^?

export const previewArticle = (idFromUrl: string): Promise<ArticlePreview> =>
  Articles.findById(idFromUrl).select({ title: 1, views: 1 }).plain().orFail();
```

`async` функции не нужен. Строитель запроса сам ведёт себя как `Promise`, и его можно вернуть прямо из функции с типом `Promise`. `_id` входит в `Selected` по умолчанию, а `"-_id"` среди полей его убирает.

Если выборка и объявленный тип разойдутся, компилятор скажет сразу. Скажем, вы убрали `views` из проекции, а в типе оставили.

```ts twoslash
// @errors: 2322
```

Чтобы такая проверка работала не только при компиляции, но и на настоящих данных, берите [`.expect`](../reference/query/contracts.mdx#expect) и [`.parse`](../reference/query/contracts.mdx#parse). О них руководство [Проверка формы ответа](./contracts.mdx).

## Как выбрать [#how-to-choose]

Спросите себя, **что нужно, а не что лишнее**.

- **Вы знаете, какие поля нужны** — перечислите их. Ответ не разрастётся, когда в модель добавят поле.
- **Нужны почти все поля, а два-три тяжёлых мешают** — исключите их.
- **Нужно скрытое поле** — читайте через `+` и только там, где без него никак, например при проверке пароля.
- **Нужна часть массива** — `$slice`, а один элемент — `$elemMatch`.
- **Поля выбирает клиент** — принимайте их словарём и оборачивайте в `untrusted(fields, "projection")`.

## Когда это не нужно [#when-not-to-use]

Если нужно только число документов или проверка, что документ есть, читать поля не нужно. Для этого есть [`countDocuments`](../reference/query/reading.mdx#model.count-documents) и [`exists`](../reference/query/reading.mdx#model.exists).

Если поле нужно спрятать от клиента совсем, а не просто не читать, объявите его скрытым в модели. Проекция бережёт от лишней работы, а не от утечки. А если значение нужно показать частично, например номер карты с последними четырьмя цифрами, берите [`.mask`](../reference/query/masks.mdx#mask), об этом руководство [Маски ответа](./response-masks.mdx).

## Если что-то пошло не так [#troubleshooting]

**Включение и исключение вместе.** Вы выбрали одни поля и исключили другие. Компилятор такой код не пропустит.

```ts twoslash
// @errors: 2345
import { Entity, type Hidden, Prop, type Selected, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.db().model(Article);
// ---cut---
Articles.find().select({ title: 1, body: 0 });
```

Если проекция собралась во время работы, [`.select`](../reference/query/reading.mdx#select) сразу при вызове бросит [`QueryError`](../reference/errors/query-errors.mdx#query-error).

```text
QueryError: projection: cannot mix inclusion (title) and exclusion (body); the server refuses it
```

MongoDB такую проекцию не примет — непонятно, что делать с полями, которые не названы. Исключение одно, `_id`. Выберите одну форму, либо `{ title: 1 }`, либо `{ body: 0 }`.

**Опечатка в имени поля.** Компилятор не пропустит поле, которого нет в модели. Его ошибка одинакова на любой модели и называет поле — `unknown field "nope"` в свойстве `"projection error"`. Во время работы Typemo бросит `StrictModeError`.

```ts twoslash
// @errors: 2345
import { Entity, type Hidden, Prop, type Selected, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.db().model(Article);
// ---cut---
Articles.find().select({ nope: 1 });
```

```text
StrictModeError: projection: "nope" is not a field of Article [unknown-path]
```

Опечатка не должна превращаться в ответ, где нужного поля просто нет. Typemo сообщает о ней сразу, до обращения к базе. Так же проверяется имя скрытого поля. `select({ "+nope": true })` не компилируется, а в коде без типов даёт ту же ошибку при запуске.

Ключ `+имя` у поля, которое не скрыто, тоже ошибка, например `select({ "+title": true })`. Он нужен только скрытым полям и здесь ничего бы не изменил. Запрос останавливается с `StrictModeError` и отдельной причиной [`not-hidden`](../reference/policies/violations.mdx#not-hidden) — `projection: "+title" adds a Hidden field back, and "title" is not Hidden; select it without the "+" [not-hidden]`. Поле при этом существует, поэтому причина отличается от `unknown-path`, и обработчик может объяснить клиенту, что не так.

**Поля нет в выборке.** Вы выбрали `title`, а в коде обратились к `body`. Это ошибка компиляции, а не `undefined` в продакшене, потому что в типе результата нет поля, которого не было в проекции. Пример есть в разделе [Вернуть только нужные поля](#select-fields).

**Скрытое поле не попало в ответ.** Вы добавили `+editorNote` и вызвали `.plain()`, а поля в ответе нет. Так и задумано — скрытое поле нужно прочитать через `+` и отдельно разрешить его отдать. Если оно правда нужно во внутреннем сервисе, вызовите `.plain({ hidden: true })`.

## Полный пример [#full-example]

Сервис статей со всеми сценариями страницы.

```ts twoslash title="articles/articles.service.ts"
import { Entity, type Hidden, Prop, type Selected, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Comment {
  @Prop(() => String, { required: true }) author!: string;
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Number, { required: true }) likes!: number;
}
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Comment]) comments!: Comment[];
  @Prop(() => String, { hidden: true }) editorNote?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.db().model(Article);
// ---cut---
// список для страницы: только нужные поля, два последних комментария
export const listArticles = () =>
  Articles.find()
    .sort({ views: -1 })
    .limit(20)
    .select({ title: 1, views: 1, comments: { $slice: -2 } })
    .plain();

// карточка статьи с описанным типом ответа
export type ArticlePreview = Selected<Article, "title" | "views">;
export const previewArticle = (idFromUrl: string): Promise<ArticlePreview> =>
  Articles.findById(idFromUrl).select({ title: 1, views: 1 }).plain().orFail();

// выгрузка без идентификатора
export const exportTitles = () => Articles.find().select({ title: 1, _id: 0 }).plain();

// внутренний сервис: заметка редактора нужна, отдаём её явно
export const forEditors = (idFromUrl: string) =>
  Articles.findById(idFromUrl).select({ "+editorNote": true }).plain({ hidden: true }).orFail();
```

<Callout type="migration">

В Mongoose `select` принимает и строку (`"title -body"`), и объект, а скрытые поля (`select: false`) читаются через `"+field"`. В Typemo проекция бывает только объектом, типы результата следуют за выбором, а скрытое поле читается через ключ `"+field"`.

Включение вместе с исключением в Mongoose можно было записать так, что побеждало последнее слово. В Typemo это ошибка. Типы Mongoose про скрытые поля не знали, а здесь таких полей нет в типе, пока вы их не запросили.

</Callout>
