Список, который видит пользователь, почти всегда нужно упорядочить и разбить на страницы. Для этого есть четыре инструмента.

- [`.sort`](../reference/query/reading.mdx#sort) задаёт порядок.
- [`.limit`](../reference/query/reading.mdx#limit) задаёт размер страницы.
- [`.skip`](../reference/query/reading.mdx#skip) говорит, сколько записей пропустить.
- [`countDocuments`](../reference/query/reading.mdx#model.count-documents) считает общее число записей для «страница 2 из 5».

Если вы впервые работаете с MongoDB, запомните два правила. Без сортировки база возвращает документы в каком угодно порядке, и от запроса к запросу он может меняться. А если у нескольких документов совпало значение, по которому вы сортируете, их порядок между собой тоже не определён, пока вы не добавите ещё один ключ.

## Что понадобится [#prerequisites]

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель поста с названием и числом просмотров.

```ts twoslash title="posts/post.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "posts" })
export class Post extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Number, { required: true })
  views!: number;
}
```

В коллекции семь постов, созданных в алфавитном порядке. У `A` 50 просмотров, у `B` и `C` по 40, у `D` 30, у `E` 20, у `F` и `G` по 10. В комментариях `// →` перечислены названия постов в порядке ответа.

## Быстрый путь [#quick-start]

Отсортируем по убыванию просмотров, возьмём три поста и посчитаем все.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
// ---cut---
const top = await Posts.find().sort({ views: -1, _id: 1 }).limit(3).plain();
console.log(top.map((post) => post.title));
// → ["A", "B", "C"]

console.log(await Posts.countDocuments());
// → 7
```

Ниже разберём каждый шаг на настоящих задачах. Если список длинный или пользователь листает его бесконечно, вместо `.skip` вам понадобится [пагинация по ключу](./keyset-pagination.mdx).

## Отсортировать список [#sort-list]

Сортировка — это объект «поле → направление», где `1` значит по возрастанию, а `-1` по убыванию. Ключей может быть несколько, и их порядок важен. Второй ключ работает только внутри одинаковых значений первого.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
// ---cut---
const byTitle = await Posts.find().sort({ title: -1 }).limit(3).plain();
console.log(byTitle.map((post) => post.title));
// → ["G", "F", "E"]

const byViews = await Posts.find().sort({ views: -1, title: 1 }).plain();
console.log(byViews.map((post) => post.title));
// → ["A", "B", "C", "D", "E", "F", "G"]
```

Направление можно записать и словом — `"asc"`, `"desc"`, `"ascending"`, `"descending"`. Если порядок ключей должен быть очевиден при чтении кода, передайте список пар, например `.sort([["views", "desc"], ["title", "asc"]])`. На результат это не влияет.

Несколько вызовов `.sort` дописывают ключи в конец, а не заменяют прежние. Один и тот же ключ дважды не пройдёт ни в одном вызове, ни в разных. Typemo бросит [`QueryError`](../reference/errors/query-errors.mdx#query-error) с текстом `sort: "views" is sorted twice`, чтобы второй вызов не оказался тихо бесполезным.

Сортировка есть и у [`findOne`](../reference/query/reading.mdx#model.find-one). Там она решает, какой из подходящих документов считать первым.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
// ---cut---
const best = await Posts.findOne().sort({ views: -1, _id: 1 }).plain().orFail();
console.log(best.title);
// → "A"
```

## Сделать порядок стабильным [#stable-order]

У постов `B` и `C` по 40 просмотров. Если сортировать только по просмотрам, MongoDB вправе вернуть их в любом порядке, и от запроса к запросу он может меняться. Для списка на одной странице это не страшно. А при постраничном выводе пост из конца страницы 1 может снова оказаться в начале страницы 2.

Поэтому последним ключом всегда ставьте поле, значения которого у всех документов разные. Проще всего взять `_id`. Он уникален, и порядок становится полным.

```ts twoslash title="posts/posts.service.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
// ---cut---
export const topPosts = () =>
  Posts.find()
    .sort({ views: -1, _id: 1 })
    .limit(3)
    .plain();
```

Направление у `_id` может быть любым, лишь бы не менялось между запросами.

## Взять первые записи [#take-first]

[`.limit`](../reference/query/reading.mdx#limit) ограничивает число документов в ответе. Ставьте его всегда, когда список видит пользователь. В коллекции сегодня десять записей, а через год может стать миллион, и запрос без ограничения положит приложение.

В MongoDB `limit(0)` значит «без ограничения», а отрицательное число включает особый режим. Оба правила неочевидны, а ноль легко получить из пустого параметра запроса и нечаянно выгрузить всю коллекцию. Поэтому Typemo принимает только целые положительные числа и сразу при вызове бросает `QueryError`.

```text
QueryError: limit must be a positive integer, got 0 (number)
```

Значение печатается вместе с типом, так что строку из параметра URL видно сразу. `limit("3")` бросит `limit must be a positive integer, got "3" (string)`. Переведите такое значение в число сами, прежде чем передать в `.limit`.

Если ограничение не нужно, просто не вызывайте `.limit`. Метод есть только у [`find`](../reference/query/reading.mdx#model.find). У `findOne` он не компилируется, а в коде без типов даёт `QueryError` с текстом `limit applies to find() only, not findOne()`.

## Вывести страницу [#render-page]

Страница номер `page` при размере `perPage` — это пропуск всех предыдущих страниц и ограничение до одной. Пропуск делает [`.skip`](../reference/query/reading.mdx#skip).

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
// ---cut---
const page = 2;
const perPage = 3;

const items = await Posts.find()
  .sort({ views: -1, _id: 1 })
  .skip((page - 1) * perPage)
  .limit(perPage)
  .plain();
console.log(items.map((post) => post.title));
// → ["D", "E", "F"]
```

Страница 3 состоит из одного поста `G`. Страница за концом списка — это пустой массив, а не ошибка.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
// ---cut---
const last = await Posts.find().sort({ views: -1, _id: 1 }).skip(6).limit(3).plain();
console.log(last.map((post) => post.title));
// → ["G"]

const beyond = await Posts.find().sort({ views: -1, _id: 1 }).skip(60).limit(3).plain();
console.log(beyond.length);
// → 0
```

`.skip` принимает целое число не меньше нуля. Отрицательное или дробное даст `QueryError` с текстом `skip must be a non-negative integer, got -1 (number)`. Причина та же, что у `.limit`. Число часто приходит извне, и тихое приведение спрятало бы ошибку.

## Посчитать общее число [#total-count]

Чтобы показать «страница 2 из 3», нужно знать общее число записей. Его считает [`countDocuments`](../reference/query/reading.mdx#model.count-documents). Он принимает тот же фильтр, что и `find`, и возвращает число подходящих документов.

```ts twoslash title="posts/posts.service.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
// ---cut---
export const listPosts = async (page: number, perPage: number) => {
  const [items, total] = await Promise.all([
    Posts.find()
      .sort({ views: -1, _id: 1 })
      .skip((page - 1) * perPage)
      .limit(perPage)
      .plain(),
    Posts.countDocuments(),
  ]);
  return { items, total, pages: Math.ceil(total / perPage) };
};

const result = await listPosts(2, 3);
console.log(result.items.map((post) => post.title), result.total, result.pages);
// → ["D", "E", "F"] 7 3
```

Страница и число — это два отдельных запроса, и их удобно выполнить одновременно, как выше. Между ними данные могут измениться, так что число не будет точным снимком той же выборки. Для списка на экране это допустимо. Если нужно число по фильтру, передайте фильтр в оба запроса.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
// ---cut---
const popular = { views: { $gte: 30 } };

const total = await Posts.countDocuments(popular);
console.log(total);
// → 4
```

Для приблизительного числа документов во всей коллекции есть [`estimatedDocumentCount`](../reference/query/reading.mdx#model.estimated-document-count). Он берёт число из метаданных и работает быстро, но фильтр не принимает.

## Принять номер страницы из URL [#page-number-from-url]

Номер и размер страницы приходят из адреса строками, и верить им нельзя. `page=0` даст отрицательный `skip`, `perPage=0` даст `limit(0)`, а `perPage=100000` заставит базу отдать всё. Неверные числа Typemo не пропустит, но ввод лучше проверить раньше и подставить безопасные значения.

```ts twoslash title="posts/posts.service.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
// ---cut---
const MAX_PER_PAGE = 50;

export const listPostsFromQuery = (pageParam: string | undefined, perPageParam: string | undefined) => {
  const page = Math.max(1, Number.parseInt(pageParam ?? "1", 10) || 1);
  const perPage = Math.min(MAX_PER_PAGE, Math.max(1, Number.parseInt(perPageParam ?? "20", 10) || 20));

  return Posts.find()
    .sort({ views: -1, _id: 1 })
    .skip((page - 1) * perPage)
    .limit(perPage)
    .plain();
};
```

Верхний предел размера страницы нужен, чтобы не пользователь решал, сколько документов загрузит ваш сервер.

## Как выбрать [#how-to-choose]

Спросите себя, **нужно ли пользователю переходить на произвольную страницу**.

- **Да**, например в таблице администратора с номерами страниц, — берите `.skip` и `.limit` вместе с `countDocuments`.
- **Пользователь только листает вперёд**, как в ленте, — берите [пагинацию по ключу](./keyset-pagination.mdx). Она стоит одинаково на любой глубине и не повторяет записи, когда список меняется.

## Когда это не нужно [#when-not-to-use]

Чтобы пропустить `n` документов, MongoDB всё равно их читает, а потом отбрасывает. На первых страницах это незаметно. Но на тысячной странице по двадцать записей база прочитает двадцать тысяч документов ради двадцати.

К тому же, если между запросами страниц кто-то добавил запись, документы сдвинутся. Пользователь увидит одну запись дважды или пропустит другую. Для длинных списков и бесконечной прокрутки берите [`Model.keysetPage`](../reference/query/keyset.mdx#model.keyset-page).

Если нужно выгрузить все документы, а не показать страницу, не листайте их через `.skip`. Для этого есть [курсор](./large-results.mdx).

## Если что-то пошло не так [#troubleshooting]

**`limit(0)` не выгружает всё.** Размер страницы пришёл из параметра запроса и оказался нулём. В MongoDB это значило бы «без ограничения», а в Typemo это ошибка.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
// ---cut---
Posts.find().limit(0); // [!code error]
// QueryError: limit must be a positive integer, got 0 (number)
```

Проверьте и ограничьте размер страницы до вызова, как в разделе [Принять номер страницы из URL](#page-number-from-url).

**Запись показалась на двух страницах.** Вы сортировали только по `views`, а у постов `B` и `C` значения совпали. Порядок таких документов между собой не определён, и между запросами страниц они могли поменяться местами. Добавьте последним ключом `_id`, как в разделе [Сделать порядок стабильным](#stable-order).

**Сортировка по полю с опечаткой.** Несуществующее поле в сортировке компилятор не пропустит. Во время работы Typemo бросит `StrictModeError`.

```ts twoslash
// @errors: 2353
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
// ---cut---
Posts.find().sort({ nope: 1 });
```

```text
StrictModeError: sort: "nope" is not a field of Post [unknown-path]
```

Иначе сортировка по несуществующему полю молча оставила бы документы в произвольном порядке.

**`.skip` у `findOne` не компилируется.** `.skip` и `.limit` есть только у `find`. У `findOne` результат один, и пропускать нечего. Нужен «второй по счёту» — вызовите `find().skip(1).limit(1)`.

## Полный пример [#full-example]

Сервис постов отдаёт страницу вместе с общим числом и подставляет безопасные значения вместо параметров URL.

```ts twoslash title="posts/posts.service.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
// ---cut---
const MAX_PER_PAGE = 50;

// список постов страницами, с общим числом
export const listPosts = async (pageParam: string | undefined, perPageParam: string | undefined) => {
  const page = Math.max(1, Number.parseInt(pageParam ?? "1", 10) || 1);
  const perPage = Math.min(MAX_PER_PAGE, Math.max(1, Number.parseInt(perPageParam ?? "20", 10) || 20));

  const [items, total] = await Promise.all([
    // порядок полный: последним ключом идёт _id
    Posts.find()
      .sort({ views: -1, _id: 1 })
      .skip((page - 1) * perPage)
      .limit(perPage)
      .plain(),
    Posts.countDocuments(),
  ]);

  return { items, total, page, pages: Math.ceil(total / perPage) };
};

// самый популярный пост
export const topPost = () => Posts.findOne().sort({ views: -1, _id: 1 }).plain().orFail();
```

<Callout type="migration">

В Mongoose `limit(0)` значил «без ограничения», а `skip` и `limit` принимали любое число, даже строку или дробь, и молча его приводили. В Typemo `limit` принимает только целое положительное число, а `skip` — целое не меньше нуля, всё остальное даёт `QueryError`.

Повторный ключ сортировки тоже ошибка, а несколько вызовов `.sort` складываются. Строковую запись `sort("-views title")` Typemo не поддерживает, сортировка задаётся объектом или списком пар.

</Callout>
