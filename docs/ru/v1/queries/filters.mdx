**Фильтр** — это объект, который говорит базе, какие документы нужны, например `{ price: { $gte: 20 } }`. Ключ фильтра — поле модели. Значение — либо само значение поля, либо объект с **операторами**, то есть ключами на `$`, каждый из которых задаёт одно условие.

Typemo проверяет фильтр дважды. Пока вы пишете код, поля и типы видит компилятор. А перед отправкой запроса Typemo повторяет проверку, потому что настоящий фильтр часто собирается из данных, которых компилятор не видит.

Если вы впервые работаете с MongoDB, запомните главное. Об опечатке в имени поля база не скажет, она честно вернёт пустой результат. Typemo сообщит об этом ошибкой сразу, и почти вся страница о том, где именно это выручает.

## Что понадобится [#prerequisites]

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель товара. В ней есть числа, массив строк, необязательная дата, поле, которое может быть `null`, и массив вложенных документов.

```ts twoslash title="products/product.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema()
export class Variant {
  @Prop(() => String, { required: true })
  sku!: string;

  @Prop(() => Number, { required: true })
  qty!: number;
}

@Schema({ collection: "products" })
export class Product extends Entity {
  @Prop(() => String, { required: true })
  name!: string;

  @Prop(() => Number, { required: true })
  price!: number;

  @Prop(() => Number, { required: true })
  stock!: number;

  @Prop(() => [String])
  tags!: string[];

  @Prop(() => Date)
  released?: Date;

  @Prop(() => String, { nullable: true })
  note!: string | null;

  @Prop(() => [Variant])
  variants!: Variant[];
}
```

В коллекции три товара.

- `Keyboard` — цена 50, на складе 10, теги `office` и `usb`, вышел 10 января 2025, `note` равен `null`. Две вариации — `K-1` в количестве 4 и `K-2` в количестве 0.
- `Mouse` — цена 20, на складе 0, тег `usb`, вышел 1 июня 2025, `note` равен `"sale"`. Одна вариация `M-1`, 7 штук.
- `Monitor` — цена 300, на складе 3, тегов нет, даты выхода нет, `note` равен `null`, вариаций нет.

В комментариях `// →` перечислены имена найденных товаров по алфавиту.

## Быстрый путь [#quick-start]

Три самых частых условия — равенство, диапазон и «одно из значений». Короткая запись — само значение, длинная — объект с оператором.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
const equal = await Products.find({ name: "Mouse" }).plain();
// → Mouse

const range = await Products.find({ price: { $gte: 20, $lt: 300 } }).sort({ name: 1 }).plain();
// → Keyboard, Mouse

const oneOf = await Products.find({ name: { $in: ["Mouse", "Monitor"] } }).sort({ name: 1 }).plain();
// → Monitor, Mouse
```

Ниже разберём каждое условие на настоящих задачах. Все операторы с типами полей, к которым они применимы, перечислены в справочнике [Операторы фильтра](../reference/query/filter-operators.mdx).

## Сравнить значение [#compare-value]

Условие на одно поле можно записать двумя равнозначными способами. `{ price: 50 }` значит «`price` равно 50», это то же, что [`$eq`](../reference/query/filter-operators.mdx#eq). Для «больше» и «меньше» нужен объект операторов с [`$gt`, `$gte`, `$lt`, `$lte`](../reference/query/filter-operators.mdx#gt-gte-lt-lte). Несколько операторов в одном объекте работают вместе, как «и», так и записывается диапазон.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
const names = async (query: { plain(): PromiseLike<{ name: string }[]> }) =>
  (await query.plain()).map((product) => product.name);

console.log(await names(Products.find({ price: { $gte: 20, $lt: 300 } }).sort({ name: 1 })));
// → ["Keyboard", "Mouse"]

console.log(await names(Products.find({ released: { $gte: new Date("2025-03-01") } })));
// → ["Mouse"]
```

Значение в условии должно быть того же типа, что и поле, — число для числа, `Date` для даты. MongoDB сравнивает значения разных типов без ошибки, только результат никому не нужен. Строка `"30"` не больше и не меньше числа 30, она просто другого типа. Typemo остановит такой фильтр раньше базы, об этом раздел [Если что-то пошло не так](#troubleshooting).

С идентификаторами то же самое. В фильтре по `_id` можно передать строку, и Typemo сам превратит её в `ObjectId`. Строка, не похожая на идентификатор, даст [`CastError`](../reference/errors/data-errors.mdx#cast-error).

## Выбрать из набора значений [#one-of-values]

Когда подходит любое из нескольких значений, берите [`$in`](../reference/query/filter-operators.mdx#in). Когда не должно подходить ни одно — [`$nin`](../reference/query/filter-operators.mdx#nin). Это короткая замена длинной цепочке равенств, например чтобы выбрать товары по списку имён или заказы по списку идентификаторов.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
const picked = await Products.find({ name: { $in: ["Mouse", "Monitor"] } }).sort({ name: 1 }).plain();
// → ["Monitor", "Mouse"]

const rest = await Products.find({ name: { $nin: ["Mouse"] } }).sort({ name: 1 }).plain();
// → ["Keyboard", "Monitor"]
```

Операнд `$in` обязан быть массивом. Если такой фильтр пришёл во время работы, а не из вашего типизированного кода, Typemo бросит `CastError` с текстом `Cast to Array failed at path "price.$in" for 5 (number): $in takes an array [type]`.

## Соединить условия [#combine-conditions]

Несколько ключей в одном фильтре работают как «и». Товары дороже 10 и с ненулевым остатком — это просто два поля. Отдельный оператор нужен для «или» и для «ни одного из».

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
const both = await Products.find({ price: { $gt: 10 }, stock: { $gt: 0 } }).sort({ name: 1 }).plain();
// → ["Keyboard", "Monitor"]

const either = await Products.find({ $or: [{ price: { $lt: 30 } }, { stock: 3 }] })
  .sort({ name: 1 })
  .plain();
// → ["Monitor", "Mouse"]

const neither = await Products.find({ $nor: [{ price: { $lt: 30 } }, { stock: 3 }] }).plain();
// → ["Keyboard"]
```

[`$or`](../reference/query/filter-operators.mdx#or) требует, чтобы выполнилось хотя бы одно условие из списка, а [`$nor`](../reference/query/filter-operators.mdx#nor) — чтобы не выполнилось ни одно. [`$and`](../reference/query/filter-operators.mdx#and) нужен редко, разве что одно и то же поле или оператор надо повторить дважды.

[`$not`](../reference/query/filter-operators.mdx#not) переворачивает условие, но под него подходят и документы, у которых поля нет вовсе. `{ released: { $not: { $gt: date } } }` найдёт и `Keyboard`, и `Monitor`, у которого даты нет совсем. Если условие можно выразить обратным оператором, так и делайте — `$lte` вместо `$not` с `$gt`.

## Найти по массиву [#query-arrays]

Поле-массив принимает всё, что принимает его элемент. Условие выполняется, если ему подходит хотя бы один элемент. Так `{ tags: "usb" }` находит товары, в тегах которых есть `usb`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
const usb = await Products.find({ tags: "usb" }).sort({ name: 1 }).plain();
// → ["Keyboard", "Mouse"]

const both = await Products.find({ tags: { $all: ["usb", "office"] } }).plain();
// → ["Keyboard"]

const untagged = await Products.find({ tags: { $size: 0 } }).plain();
// → ["Monitor"]
```

[`$all`](../reference/query/filter-operators.mdx#all) требует, чтобы в массиве были все перечисленные значения, в любом порядке. [`$size`](../reference/query/filter-operators.mdx#size) проверяет точную длину. Условие вроде «не меньше трёх тегов» через него не записать, для такого храните длину в отдельном поле.

### Условие на один элемент массива вложенных документов [#elem-match-condition]

У `Keyboard` две вариации — `K-1` в количестве 4 и `K-2` в количестве 0. Нужен товар, у которого есть вариация `K-1` с нулевым остатком. Такой вариации нет, но запись с двумя ключами её «находит».

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
const wrong = await Products.find({ "variants.sku": "K-1", "variants.qty": 0 }).plain();
// → ["Keyboard"]

const right = await Products.find({ variants: { $elemMatch: { sku: "K-1", qty: 0 } } }).plain();
// → []
```

Условия по вложенным полям массива проверяются независимо. `sku` совпал у первого элемента, `qty` — у второго, и товар подошёл. [`$elemMatch`](../reference/query/filter-operators.mdx#elem-match) требует, чтобы **один и тот же** элемент выполнил все условия сразу. Нужны два условия про одну вложенную запись — берите его.

## Условие на вложенное поле [#nested-field-condition]

Поле вложенного документа записывается путём через точку, например `"variants.sku"`. Компилятор знает такие пути, подсказывает их в редакторе и не пропускает несуществующие.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
const found = await Products.find({ "variants.sku": "M-1" }).plain();
// → ["Mouse"]
```

Для массива вложенных документов условие по пути проверяет элементы по очереди, и хватает одного подходящего. Для условий «вместе на одном элементе» нужен [`$elemMatch`](#elem-match-condition), о нём рассказано выше.

## Найти документы без поля или со значением null [#missing-or-null]

В MongoDB «поля нет» и «в поле лежит `null`» — разные состояния, и фильтры для них разные. Документы без поля находит [`$exists`](../reference/query/filter-operators.mdx#exists) со значением `false`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
const unreleased = await Products.find({ released: { $exists: false } }).plain();
// → ["Monitor"]
```

Поле со значением `null` существует, поэтому `{ note: { $exists: true } }` вернёт все три товара. Чтобы найти именно `null`, сравните с `null` напрямую.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
const noNote = await Products.find({ note: null }).sort({ name: 1 }).plain();
// → ["Keyboard", "Monitor"]
```

Сравнивать с `null` можно только поля, которые могут быть `null`, здесь это `note`. Фильтр `{ released: null }` не скомпилируется. Иначе «поля нет» и «`null`» смешались бы в одном фильтре, и вы нашли бы не то, что искали.

## Найти по тексту [#text-search]

Условие по строке в виде регулярного выражения записывает [`$regex`](../reference/query/filter-operators.mdx#regex) — строкой-шаблоном или объектом `RegExp`. Флаги для строки-шаблона задаются в соседнем `$options`, а у `RegExp` пишутся в самом выражении.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
const byPattern = await Products.find({ name: { $regex: "^m", $options: "i" } }).sort({ name: 1 }).plain();
// → ["Monitor", "Mouse"]

const byRegExp = await Products.find({ name: /^Mo/ }).sort({ name: 1 }).plain();
// → ["Monitor", "Mouse"]
```

Если шаблон вводит пользователь, экранируйте его. Иначе специальные символы его строки станут частью выражения, и поиск по `.*` вернёт всю коллекцию.

```ts twoslash title="products/products.service.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
const escapeRegExp = (text: string) => text.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");

export const findByName = (text: string) =>
  Products.find({ name: { $regex: escapeRegExp(text), $options: "i" } }).plain();

console.log((await findByName(".*")).length, (await findByName("mo")).length);
// → 0 2
```

Поиск по началу строки (`^Mo`) может пойти по индексу, а поиск по середине читает все значения поля. Для настоящего полнотекстового поиска регулярные выражения не годятся, смотрите [Полнотекстовый и векторный поиск](./text-and-vector-search.mdx).

## Собрать фильтр из пользовательского ввода [#filter-from-input]

Чаще всего фильтр строится из параметров запроса. Клиент выбирает тег, минимальную цену или часть названия. Каждый параметр необязателен, поэтому фильтр собирается по частям, и в него попадают только заданные условия. Для этого удобен [`.where(filter)`](../reference/query/conditions.mdx#where-filter). Он добавляет условия к запросу и не заменяет уже добавленные.

```ts twoslash title="products/products.service.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
const escapeRegExp = (text: string) => text.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");

export const searchProducts = (params: { text?: string; minPrice?: number; tag?: string }) => {
  let query = Products.find().sort({ name: 1 });
  if (params.tag !== undefined) query = query.where({ tags: params.tag });
  if (params.minPrice !== undefined) query = query.where({ price: { $gte: params.minPrice } });
  if (params.text !== undefined) {
    query = query.where({ name: { $regex: escapeRegExp(params.text), $options: "i" } });
  }
  return query.plain();
};

console.log((await searchProducts({ tag: "usb", minPrice: 30 })).map((product) => product.name));
// → ["Keyboard"]
console.log((await searchProducts({})).length);
// → 3
```

Условия складываются через «и», а запрос без параметров возвращает все товары, ведь пустой фильтр при чтении разрешён. Обратите внимание, что в `where` попадают уже проверенные значения — число, строка, — а не сырой объект запроса.

Сырой объект от клиента может содержать операторы. Тело `{"name": {"$gt": ""}}` — вполне допустимое условие для строкового поля. Передайте его в `find` целиком, и оно выполнится и вернёт все товары.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
const body: unknown = JSON.parse('{"name":{"$gt":""}}');

// неправильно: клиент решает, какие операторы будут в фильтре
const all = await Products.find({ name: body as string }).plain();
console.log(all.length);
// → 3
```

Typemo ловит только явные нарушения — неизвестное поле, неизвестный оператор, `$where`, `undefined`, значение не того типа. Откуда пришёл `{ "$gt": "" }`, от клиента или из вашего кода, он знать не может. Поэтому проверяйте ввод — типы, формат, диапазон — и собирайте фильтр в своём коде, как выше.

Для дополнительной страховки оберните значение из запроса в [`untrusted`](../reference/policies/soft-delete-and-untrusted.mdx#untrusted). Эта функция отвергает любой ключ с `$` на любой глубине. Подробнее в руководстве [Недоверенный ввод](../policies/untrusted-input.mdx).

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
import { untrusted } from "@venloc/typemo";

const body: unknown = JSON.parse('{"$gt":""}');
await Products.find({ name: untrusted(body) as string });
// StrictModeError: untrusted value: "$gt" at "$gt" — an operator inside data from outside (query selector injection); validate the input and build the filter yourself [sanitize]
```

## Собрать фильтр по частям [#build-filter]

Условия по одному добавляет не только пользовательский ввод, но и обычный код. Одна функция ограничивает права, другая добавляет диапазон. Кроме `.where(filter)` у запроса есть цепочка на одном поле, [`.where("поле")`](../reference/query/conditions.mdx#where-path), с методами вроде `gte` и `lt`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
const query = Products.find().where("price").gte(20).lt(300).where("stock").gt(0);
console.log(query.filter());
// → { price: { $gte: 20, $lt: 300 }, stock: { $gt: 0 } }

console.log((await query.plain()).map((product) => product.name));
// → ["Keyboard"]
```

Когда границы диапазона приходят из разных мест, такая запись читается лучше вложенных объектов. К тому же цепочка сужает тип результата. После `.where("role").in([...])` компилятор знает, что поле `role` в результате принимает только эти значения. Подробности и остальные методы цепочки — в справочнике [Условия цепочкой](../reference/query/conditions.mdx).

## Как выбрать [#how-to-choose]

Спросите себя, **откуда берётся условие**.

- **Вы пишете его в коде, и оно не меняется** — пишите объектом. `{ price: { $gte: 20 } }` — самая короткая и ясная запись.
- **Условия добавляются по частям в разных местах**, особенно из необязательных параметров, — берите [`.where(filter)`](../reference/query/conditions.mdx#where-filter).
- **Важнее читаемость диапазона на одном поле или сужение типа результата** — [`.where("поле")`](../reference/query/conditions.mdx#where-path).

Если условие пришло от клиента целиком, не отдавайте его в запрос как фильтр. Разберите ввод и постройте фильтр сами.

## Когда это не нужно [#when-not-to-use]

Для одного документа по `_id` фильтр не нужен. Берите [`findById`](../reference/query/reading.mdx#model.find-by-id), он принимает и строку из адреса. Чтобы проверить, есть ли подходящий документ, есть [`exists`](../reference/query/reading.mdx#model.exists), а чтобы посчитать документы — [`countDocuments`](../reference/query/reading.mdx#model.count-documents). Для поиска по смыслу текста и по вектору фильтры не годятся, смотрите [Полнотекстовый и векторный поиск](./text-and-vector-search.mdx).

## Если что-то пошло не так [#troubleshooting]

**Строка вместо числа.** Число пришло из адреса запроса строкой, и вы передали его в фильтр как есть. Компилятор такой код не пропустит.

```ts twoslash
// @errors: 2322
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
Products.find({ price: "30" });
```

Если фильтр собрался во время работы, Typemo не отправит его в базу и бросит `CastError`.

```text
CastError: Cast to number failed at path "price" for "30" (string): expected a number [type]
```

MongoDB не считает строку `"30"` ни равной числу 30, ни больше его. Запрос вернул бы пустой результат без единой ошибки. Переведите значение в число сами через `Number(params.price)` и проверьте, что получилось не `NaN`.

**`undefined` в фильтре.** Необязательный параметр не пришёл, и в фильтр попало `{ price: undefined }`. Компилятор такой код не пропускает, а во время работы `find` бросает `QueryError`.

```text
QueryError: filter: undefined at "price" (use $exists: false / $unset; undefined is never a value)
```

Если бы Typemo молча считал `undefined` отсутствием условия, вы получили бы не тех пользователей, кого искали, а все документы. Добавляйте условие, только когда параметр задан, как в функции `searchProducts` выше. А документы без поля ищите явно — `{ price: { $exists: false } }`.

**Опечатка в имени поля.** Компилятор подчеркнёт неизвестное поле, а во время работы Typemo бросит `StrictModeError`.

```ts twoslash
// @errors: 2345
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
Products.find({ nope: 1 });
```

```text
StrictModeError: filter: "nope" is not a field of Product [unknown-path]
```

MongoDB вернула бы пустой массив, ведь поля `nope` нет ни у одного документа. Ошибку пришлось бы искать по странному поведению приложения.

Компилятор видит только ключи, написанные в коде или описанные в типе фильтра. Фильтр, собранный во время работы, например объект `Record<string, unknown>` (или `{ [key: string]: unknown }`) из разбора параметров, он принимает целиком, ведь ключей такого объекта не знает. Так ведут себя `find`, `findOne`, `countDocuments`, `exists` и записи с фильтром — `updateOne`, `updateMany`, `deleteOne`, `deleteMany`, `findOneAnd*`.

В таком фильтре опечатка в ключе и значение не того типа найдутся только при запуске запроса, теми же `StrictModeError` и `CastError`. До базы запрос при этом всё равно не дойдёт. Чтобы компилятор помогал и здесь, собирайте фильтр частями через [`.where(filter)`](../reference/query/conditions.mdx#where-filter) и литералы, как в разделе [Собрать фильтр из пользовательского ввода](#filter-from-input).

**Два условия про один элемент проверяются на разных элементах.** Условия по вложенным полям массива вернули товар, у которого нет ни одной подходящей вариации. Почему так и как исправить, рассказано выше. Возьмите [`$elemMatch`](../reference/query/filter-operators.mdx#elem-match), чтобы условия проверялись на одном и том же элементе.

**Оператор не подходит к типу поля.** Регулярное выражение по числу смысла не имеет, и `Products.find({ price: { $regex: "5" } })` не скомпилируется. Во время работы Typemo бросит `StrictModeError`.

```text
StrictModeError: $regex applies to strings only (at "price.$regex") [sanitize]
```

Так путаница типов всплывает раньше, чем даст неверный результат. Для каждого оператора в справочнике [Операторы фильтра](../reference/query/filter-operators.mdx) указано, к каким полям он применим.

## Полный пример [#full-example]

Сервис товаров умеет искать по параметрам запроса, находить товары с вариацией нужного количества и выводить список без даты выхода. Код, которого нет в Typemo и который пишете вы, помечен `__…__`.

```ts twoslash title="products/products.service.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.db().model(Product);
// ---cut---
import { CastError, StrictModeError } from "@venloc/typemo";

// код читателя: ошибка на границе приложения
class __BadRequest__ extends Error {}

const escapeRegExp = (text: string) => text.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");

// поиск по необязательным параметрам запроса
export const searchProducts = async (params: { text?: string; minPrice?: number; tag?: string }) => {
  let query = Products.find().sort({ name: 1 });
  if (params.tag !== undefined) query = query.where({ tags: params.tag });
  if (params.minPrice !== undefined) query = query.where({ price: { $gte: params.minPrice } });
  if (params.text !== undefined) {
    query = query.where({ name: { $regex: escapeRegExp(params.text), $options: "i" } });
  }
  try {
    return await query.plain();
  } catch (error) {
    // ошибки фильтра — это ошибки ввода клиента, а не сбой сервера
    if (error instanceof CastError || error instanceof StrictModeError) {
      throw new __BadRequest__("the search parameters are invalid");
    }
    throw error;
  }
};

// у вариации этого товара есть нужный остаток
export const withVariant = (sku: string, qty: number) =>
  Products.find({ variants: { $elemMatch: { sku, qty } } }).plain();

// товары без даты выхода
export const unreleased = () => Products.find({ released: { $exists: false } }).plain();
```

<Callout type="migration">

В Mongoose поле, которого нет в схеме, при `strictQuery` молча выбрасывалось из фильтра, а без него уходило в базу как есть. В Typemo неизвестное поле, неизвестный оператор, `undefined`, значение не того типа и `$where` — всегда ошибка.

Оператор из ввода клиента (`{ "$gt": "" }` вместо строки) Typemo сам не отвергнет, если он допустим для поля. Проверяйте ввод и при необходимости оборачивайте его в [`untrusted`](../reference/policies/soft-delete-and-untrusted.mdx#untrusted).

</Callout>
