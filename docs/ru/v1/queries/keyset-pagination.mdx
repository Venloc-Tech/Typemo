**Пагинация по ключу** отдаёт страницу как «строки после последней увиденной», а не как «пропусти N строк». Страница стоит одинаково на любой глубине. А записи, которые добавили или удалили между запросами, не повторяются и не теряются.

В Typemo для этого есть один метод, [`Model.keysetPage`](../reference/query/keyset.mdx#modelkeysetpage). Он возвращает страницу и **токен** — строку, которая помнит, где страница закончилась. По токену запрашивается следующая страница.

Если вы впервые работаете с MongoDB, держите в голове одну мысль. Чтобы пропустить `n` документов, база всё равно читает их и отбрасывает, поэтому глубокие страницы через [`.skip`](../reference/query/reading.mdx#skip) медленные. Пагинация по ключу просит у базы строки после конкретного значения, и индекс отвечает сразу.

## Что понадобится

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель поста. Поля подобраны так, чтобы были видны и годные для ключа (обязательные), и негодные (необязательное `draft`).

```ts twoslash title="posts/post.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "posts" })
export class Post extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Number, { required: true })
  views!: number;

  @Prop(() => Boolean)
  draft?: boolean;
}
```

В коллекции семь постов, созданных в алфавитном порядке. У `A` 50 просмотров, у `B` и `C` по 40, у `D` 30, у `E` 20, у `F` и `G` по 10. В комментариях `// →` перечислены названия постов в порядке страницы.

## Быстрый путь

Первая страница и следующая за ней.

```ts twoslash
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Boolean) draft?: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
declare class __BadRequest__ extends Error {}
// ---cut---
const first = await Posts.keysetPage({ sort: [["views", "desc"]], limit: 3 });
console.log(first.items.map((post) => post.title), first.hasMore);
// → ["A", "C", "B"] true

const second = await Posts.keysetPage({ sort: [["views", "desc"]], limit: 3, after: first.nextCursor });
console.log(second.items.map((post) => post.title), second.hasMore);
// → ["D", "E", "G"] true
```

Ниже разберём метод на настоящих задачах. Все опции и результат описаны в справочнике [Пагинация по ключу](../reference/query/keyset.mdx).

## Получить первую и следующую страницу

Сортировка передаётся списком пар `[поле, направление]`, а не объектом. Порядок ключей объекта в JavaScript не всегда совпадает с порядком записи, а здесь от порядка ключей зависит порядок страницы. Опция `limit` задаёт размер страницы. Первую страницу запрашивают без `after`, а для следующих `after` берут из `nextCursor` предыдущей.

Обратите внимание, что посты `B` и `C` с их 40 просмотрами стоят на странице как `C`, `B`. Typemo сам добавляет `_id` последним ключом сортировки с тем же направлением, что у предыдущего ключа. Порядок получается полным, у двух строк не бывает «одинаковой позиции», и граница страницы всегда однозначна. `desc` действует и на `_id`, поэтому более новый пост `C` идёт раньше `B`.

Страница — это объект из трёх полей.

- `items` — строки.
- `nextCursor` — токен следующей страницы или `null`.
- `hasMore` — есть ли следующая страница.

Последняя страница выглядит так.

```ts twoslash
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Boolean) draft?: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
declare class __BadRequest__ extends Error {}
// ---cut---
const last = await Posts.keysetPage({ sort: [["views", "desc"]], limit: 7 });
console.log(last.items.length, last.hasMore, last.nextCursor);
// → 7 false null
```

Чтобы понять, что список кончился, Typemo запрашивает на одну строку больше, чем `limit`. Поэтому и последняя страница ровно из `limit` строк сообщает, что дальше ничего нет, и лишний пустой запрос вам делать не придётся. Пустая выборка — не ошибка, она даёт `{ items: [], nextCursor: null, hasMore: false }`.

## Отдать страницу клиенту

Токен приходит от клиента и уходит к клиенту. Поэтому обычная функция сервиса принимает токен строкой, а возвращает страницу и следующий токен. Строки по умолчанию — это документы. Для ответа клиенту превратите каждую в [обычный объект](./reading-data.mdx#отдать-данные-клиенту) через [`$toPlain()`](../reference/documents/document-api.mdx#toplain).

```ts twoslash title="posts/posts.service.ts"
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Boolean) draft?: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
declare class __BadRequest__ extends Error {}
// ---cut---
export const listPosts = async (afterFromUrl: string | null) => {
  try {
    const page = await Posts.keysetPage({ sort: [["views", "desc"]], limit: 20, after: afterFromUrl });
    return { items: page.items.map((post) => post.$toPlain()), next: page.nextCursor };
  } catch (error) {
    if (error instanceof KeysetTokenError) throw new __BadRequest__("the page token is invalid");
    throw error;
  }
};
```

Клиент положит `next` в адрес следующего запроса и получит следующую страницу. Когда `next` станет `null`, он покажет, что список закончился.

Испорченный токен от клиента вызывает [`KeysetTokenError`](../reference/query/keyset.mdx#keysettokenerror). Это ошибка ввода, а не сбой сервера, и функция выше отвечает на неё как на неверный запрос. Typemo проверяет токен целиком, прежде чем строить по нему запрос, — длину и алфавит, структуру, совпадение ключей и направлений с вашей сортировкой и тип каждого значения. Обрезанный токен даёт такую ошибку.

```text
KeysetTokenError: keysetPage: invalid cursor — it cannot be read
```

Если методы документа вам не нужны, передайте `lean: true`. Строки придут как результат `.lean()`, с `ObjectId` и `bigint`, и для ответа клиенту их ещё придётся перевести.

## Листать бесконечно

При бесконечной прокрутке клиент запрашивает страницу и показывает её. Когда пользователь дошёл до конца, клиент запрашивает следующую с последним `next`. На сервере, например в фоновой задаче, которая обходит весь список, это цикл по токену.

```ts twoslash title="posts/export-posts.ts"
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Boolean) draft?: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
declare class __BadRequest__ extends Error {}
// ---cut---
const pageAfter = (after: string | null) =>
  Posts.keysetPage({ sort: [["views", "desc"]], limit: 3, after });

export const allTitles = async () => {
  let page = await pageAfter(null);
  const titles = page.items.map((post) => post.title);
  while (page.nextCursor !== null) {
    page = await pageAfter(page.nextCursor);
    titles.push(...page.items.map((post) => post.title));
  }
  return titles;
};

console.log(await allTitles());
// → ["A", "C", "B", "D", "E", "G", "F"]
```

Все семь постов выданы по одному разу, и каждый запрос стоил одинаково. А для выгрузки всей коллекции лучше подходит [курсор](./large-results.mdx). Он читает документы одним запросом и не гоняет токен туда-обратно.

## Листать список с фильтром

Опция `filter` задаёт, какие документы листать. Она проверяется так же, как фильтр в [`find`](../reference/query/reading.mdx#modelfind), и действует на **каждую** страницу. Поэтому токен не открывает доступа к документам вне фильтра. Подменив токен, клиент может сместить позицию, но чужих данных не увидит.

```ts twoslash
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Boolean) draft?: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
declare class __BadRequest__ extends Error {}
// ---cut---
const page = await Posts.keysetPage({
  filter: { views: { $lt: 40 } },
  sort: [["views", "desc"]],
  limit: 2,
});
console.log(page.items.map((post) => post.title));
// → ["D", "E"]
```

Фильтр и сортировка должны быть одинаковыми на всех страницах одного списка. Токен запоминает ключи и направления сортировки, так что с другой сортировкой он не сработает. Вы получите `KeysetTokenError` с текстом `keysetPage: invalid cursor — it was made for another sort`. А фильтр токен не запоминает. Если поменять его между страницами, позиция останется прежней, а набор документов будет другим.

## Проверить, что записи не теряются

Главное отличие от `.skip` видно, когда между запросами страниц в начало списка добавляют запись. Возьмём страницу из двух постов и добавим `Z` со 100 просмотрами, самый популярный.

```ts twoslash
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Boolean) draft?: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
declare class __BadRequest__ extends Error {}
// ---cut---
const first = await Posts.keysetPage({ sort: [["views", "desc"]], limit: 2 });
console.log(first.items.map((post) => post.title));
// → ["A", "C"]

await Posts.create({ title: "Z", views: 100 });

const second = await Posts.keysetPage({ sort: [["views", "desc"]], limit: 2, after: first.nextCursor });
console.log(second.items.map((post) => post.title));
// → ["B", "D"]
```

Токен помнит позицию, а не номер страницы, поэтому вторая страница продолжается с `B`. Ни одна запись не повторилась и не пропала.

Со `.skip(2)` всё иначе. Порядок тот же, просмотры по убыванию, затем `_id` по убыванию, и первая страница — `A` и `C`. Но после появления `Z` вторая страница по `.skip(2)` начинается с `C` и даёт `C` и `B`. Новая запись сдвинула остальные, и читатель увидит `C` дважды.

## Листать по времени создания или изменения

Лента «сначала новые» и список «недавно менявшиеся» сортируются по времени. Если модель наследует [`Timestamped`](../reference/schemas/base-classes.mdx#timestamped), поля `createdAt` и `updatedAt` годятся в ключ, хотя в схеме не помечены обязательными. Ядро заполняет их при каждой вставке, и пустых значений не бывает. Скажем, заметки `s1`…`s5` созданы по очереди.

```ts twoslash title="notes/notes.service.ts"
import { Entity, Prop, Schema, Timestamped, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "notes" })
class Note extends Timestamped(Entity) {
  @Prop(() => String, { required: true }) title!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Notes = client.db().model(Note);
// ---cut---
export const newestFirst = (after: string | null) =>
  Notes.keysetPage({ sort: [["createdAt", "desc"]], limit: 2, after });

const page = await newestFirst(null);
console.log(page.items.map((note) => note.title));
// → ["s5", "s4"]
```

Порядок по `updatedAt` подвижный. `updatedAt` меняется при любой записи, и только что изменённая заметка сразу прыгает в начало списка. Для ленты, которая не должна скакать под пальцем пользователя, листайте по `createdAt`. Если у заметок одинаковый `createdAt`, границу страницы определит `_id`, который Typemo ставит последним ключом, так что ничего не повторится и не пропадёт.

## Подписать токен

Токен не зашифрован. Это записанные в строку значения ключей последней строки страницы, и любой клиент может их прочитать и изменить. Пока фильтр запроса действует на каждую страницу, подделка не даёт доступа к чужим данным, а самое большее сдвигает позицию.

Если и сдвигать позицию клиенту нельзя, подпишите токены. Опция клиента `keysetSecret` с ключом не короче 32 байт превращает токен в `payload.подпись`, где подпись — HMAC-SHA256 от payload.

```ts twoslash title="db/client.ts"
import { TypemoClient } from "@venloc/typemo";

export const client = await TypemoClient.connect("mongodb://localhost:27017/blog", {
  keysetSecret: "__a-secret-of-at-least-32-bytes-long__",
});
```

Ключ в примере заведомо ненастоящий. Настоящий берите из секретов окружения, а не из кода.

Подпись проверяется до разбора токена, и сравнение занимает одно и то же время, сколько бы символов ни совпало. С включённой подписью Typemo отвергает неподписанный токен и изменённый токен. И наоборот, подписанный токен на клиенте без ключа тоже не пройдёт.

```text
KeysetTokenError: keysetPage: invalid cursor — it is not signed (the client signs its tokens: keysetSecret)
KeysetTokenError: keysetPage: invalid cursor — the signature is not valid
KeysetTokenError: keysetPage: invalid cursor — it is signed, but this client has no keysetSecret
```

Ключ можно сменить без разрыва. `keysetSecret` принимает и список, где первый ключ подписывает, а проверяет любой из списка. Так токены, выданные старым ключом, доживут до конца перехода.

## Как выбрать

Спросите себя, **нужен ли пользователю переход на произвольную страницу или общее число страниц**.

- **Нет, он листает вперёд**, как в ленте или журнале, — берите `keysetPage`. Страница стоит одинаково на любой глубине и не теряет записи.
- **Нужно «страница 17 из 40»** — берите [`.skip`](../reference/query/reading.mdx#skip) с [`.limit`](../reference/query/reading.mdx#limit) и [`countDocuments`](../reference/query/reading.mdx#modelcountdocuments), об этом страница [Сортировка и страницы](./sorting-and-pages.mdx). Только глубокие страницы будут медленнее, а записи, добавленные между запросами, сдвинут границы.

## Когда это не нужно

`keysetPage` листает только вперёд и не знает общего числа страниц. Перейти на страницу 17 или показать «страница 3 из 40» он не умеет.

Ключом могут быть только обязательные поля верхнего уровня без `null` и с порядком — числа, строки, даты, идентификаторы. Ещё подходят `_id`, а у моделей с `Timestamped` также `createdAt` и `updatedAt`. Если список нужно упорядочить по необязательному или вычисляемому значению, метод не подойдёт. Для вычисляемого порядка берите [агрегацию](../aggregation/first-aggregation.mdx), а чтобы обойти всю коллекцию, а не показать страницу, — [курсор](./large-results.mdx).

## Если что-то пошло не так

**Необязательное поле в ключе.** Вы решили сортировать по полю, которого в документе может не быть. У отсутствующего значения нет места в порядке, поэтому такое поле в ключ не годится. Компилятор его не пропустит, а во время работы Typemo бросит [`ConfigurationError`](../reference/errors/configuration-errors.mdx#configurationerror).

```ts twoslash
// @errors: 2322
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Boolean) draft?: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
declare class __BadRequest__ extends Error {}
// ---cut---
await Posts.keysetPage({ sort: [["draft", "asc"]], limit: 3 });
```

```text
ConfigurationError: keysetPage: sort "draft" of Post must be required and not nullable (a missing value cannot be a position)
```

Сделайте поле обязательным и уберите у него `null` или сортируйте по другому полю.

**Токен от другой сортировки.** Клиент прислал токен, выданный для сортировки по `views`, а вы теперь листаете по `title`. Typemo его отвергнет.

```text
KeysetTokenError: keysetPage: invalid cursor — it was made for another sort
```

Поменяв сортировку списка, начинайте с первой страницы без `after` и сбросьте токены на клиенте.

**`limit` равен нулю.** Размер страницы пришёл из параметра запроса и оказался нулём. Typemo бросит `QueryError`, как и [`.limit`](../reference/query/reading.mdx#limit).

```text
QueryError: keysetPage: limit must be a positive integer, got 0 (number)
```

Проверьте и ограничьте размер страницы до вызова, как в разделе [Принять номер страницы из URL](./sorting-and-pages.mdx#принять-номер-страницы-из-url).

**Токен потерялся между запросами.** Вы на каждом запросе вызываете `keysetPage` без `after` и получаете одну и ту же первую страницу. Токен `nextCursor` нужно отдать клиенту и получить обратно, ведь сами страницы между запросами ничего не помнят.

## Полный пример

Сервис ленты постов отдаёт страницу с токеном, а ошибку токена превращает в неверный запрос. Подпись включается в клиенте, как в разделе выше. Код, которого нет в Typemo и который пишете вы, помечен `__…__`.

```ts twoslash title="posts/posts.service.ts"
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Boolean) draft?: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
declare class __BadRequest__ extends Error {}
// ---cut---
// код читателя: __BadRequest__ — ошибка вашего приложения на границе

// одна страница ленты: самые просматриваемые сверху
export const feed = async (afterFromUrl: string | null) => {
  try {
    const page = await Posts.keysetPage({
      filter: { views: { $gt: 0 } },
      sort: [["views", "desc"]],
      limit: 20,
      after: afterFromUrl,
    });
    return {
      items: page.items.map((post) => post.$toPlain()),
      next: page.nextCursor, // null на последней странице
    };
  } catch (error) {
    // токен от клиента: испорченный, подделанный или от другой сортировки
    if (error instanceof KeysetTokenError) throw new __BadRequest__("the page token is invalid");
    throw error;
  }
};
```

<Callout type="migration">

В Mongoose встроенной пагинации по ключу нет. Обычно её пишут вручную через `$or` по ключам и сами склеивают токен. В Typemo для этого есть [`Model.keysetPage`](../reference/query/keyset.mdx#modelkeysetpage). `_id` добавляется последним ключом сам, токен проверяется целиком, а подпись включается одной опцией клиента.

</Callout>
