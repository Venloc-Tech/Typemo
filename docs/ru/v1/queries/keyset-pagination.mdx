**Пагинация по ключу** отдаёт страницу как «строки после последней увиденной», а не как «пропусти N строк». Страница стоит одинаково на любой глубине, а записи, которые добавили или удалили между запросами страниц, не повторяются и не теряются. В Typemo её делает один метод, [`Model.keysetPage`](../reference/query/keyset.mdx#modelkeysetpage): он возвращает страницу и **токен** — строку, которая запоминает, где страница закончилась, и по которой запрашивается следующая.

Если вы впервые работаете с MongoDB, вам нужна одна мысль: чтобы пропустить `n` документов, база всё равно их читает и отбрасывает, поэтому глубокие страницы через [`.skip`](../reference/query/reading.mdx#skip) медленные. Пагинация по ключу спрашивает у базы «дай строки после вот этого значения», и индекс отвечает сразу.

## Что предполагается

Примеры используют клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель поста. Её поля выбраны так, чтобы были видны и годящиеся в ключ (обязательные), и негодящиеся (необязательное `draft`):

```ts twoslash title="posts/post.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "posts" })
export class Post extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Number, { required: true })
  views!: number;

  @Prop(() => Boolean)
  draft?: boolean;
}
```

В коллекции семь постов, созданных в алфавитном порядке. Просмотры: `A` — 50, `B` и `C` — по 40, `D` — 30, `E` — 20, `F` и `G` — по 10. Результаты в комментариях `// →` — названия постов в порядке страницы.

## Быстрый путь

Первая страница и следующая за ней:

```ts twoslash
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Boolean) draft?: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
declare class __BadRequest__ extends Error {}
// ---cut---
const first = await Posts.keysetPage({ sort: [["views", "desc"]], limit: 3 });
console.log(first.items.map((post) => post.title), first.hasMore);
// → ["A", "C", "B"] true

const second = await Posts.keysetPage({ sort: [["views", "desc"]], limit: 3, after: first.nextCursor });
console.log(second.items.map((post) => post.title), second.hasMore);
// → ["D", "E", "G"] true
```

Остальная страница разбирает метод на реальных задачах. Все опции и результат описаны в справочнике [Пагинация по ключу](../reference/query/keyset.mdx).

## Получить первую и следующую страницу

Сортировка передаётся списком пар `[поле, направление]`, а не объектом: порядок ключей объекта в JavaScript не всегда совпадает с порядком записи, а здесь порядок ключей определяет порядок страницы. Опция `limit` — размер страницы. Первая страница запрашивается без `after`, а для следующих `after` берётся из поля `nextCursor` предыдущей.

Обратите внимание, что в порядке страницы посты `B` и `C` стоят как `C`, `B`: у них по 40 просмотров. Typemo сам добавляет `_id` последним ключом сортировки, с тем же направлением, что у предыдущего ключа. Поэтому порядок полный: у двух строк не бывает «одинаковой позиции», и граница страницы всегда однозначна. `desc` относится и к `_id`, значит, более новый пост `C` идёт раньше `B`.

Результат страницы — объект из трёх полей: `items` (строки), `nextCursor` (токен следующей страницы или `null`) и `hasMore` (есть ли следующая). Последняя страница выглядит так:

```ts twoslash
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Boolean) draft?: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
declare class __BadRequest__ extends Error {}
// ---cut---
const last = await Posts.keysetPage({ sort: [["views", "desc"]], limit: 7 });
console.log(last.items.length, last.hasMore, last.nextCursor);
// → 7 false null
```

Typemo определяет конец списка, запрашивая на одну строку больше, чем `limit`. Поэтому последняя страница с ровно `limit` строками тоже сообщает «дальше ничего нет», а вы не делаете лишний пустой запрос. Пустая выборка не ошибка: она даёт `{ items: [], nextCursor: null, hasMore: false }`.

## Отдать страницу клиенту

Токен приходит от клиента и уходит к клиенту, поэтому типичная функция сервиса принимает токен строкой, а возвращает страницу и следующий токен. Строки по умолчанию — документы; для ответа клиенту переведите каждый в [plain-вид](./reading-data.mdx#отдать-данные-клиенту) через [`$toPlain()`](../reference/documents/document-api.mdx#toplain):

```ts twoslash title="posts/posts.service.ts"
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Boolean) draft?: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
declare class __BadRequest__ extends Error {}
// ---cut---
export const listPosts = async (afterFromUrl: string | null) => {
  try {
    const page = await Posts.keysetPage({ sort: [["views", "desc"]], limit: 20, after: afterFromUrl });
    return { items: page.items.map((post) => post.$toPlain()), next: page.nextCursor };
  } catch (error) {
    if (error instanceof KeysetTokenError) throw new __BadRequest__("the page token is invalid");
    throw error;
  }
};
```

Клиент положит `next` в адрес следующего запроса и получит следующую страницу, а когда `next` станет `null`, покажет, что список закончился. Токен, который клиент прислал испорченным, вызывает [`KeysetTokenError`](../reference/query/keyset.mdx#keysettokenerror): это ошибка ввода, а не сбой сервера, и функция выше отвечает на неё как на неверный запрос. Typemo проверяет токен полностью до того, как строит по нему запрос: длину и алфавит, структуру, совпадение ключей и направлений с вашей сортировкой и тип каждого значения. Обрезанный токен выглядит так:

```text
KeysetTokenError: keysetPage: invalid cursor — it cannot be read
```

Если вам не нужны методы документа, передайте `lean: true`: строки будут lean-строками с `ObjectId` и `bigint`, которые для ответа клиенту ещё нужно перевести.

## Листать бесконечно

Для бесконечной прокрутки клиент запрашивает страницу, показывает её и, когда пользователь дошёл до конца, запрашивает следующую с последним `next`. В коде клиента на стороне сервера, например в фоновой задаче, обходящей весь список, это цикл по токену:

```ts twoslash title="posts/export-posts.ts"
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Boolean) draft?: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
declare class __BadRequest__ extends Error {}
// ---cut---
const pageAfter = (after: string | null) =>
  Posts.keysetPage({ sort: [["views", "desc"]], limit: 3, after });

export const allTitles = async () => {
  let page = await pageAfter(null);
  const titles = page.items.map((post) => post.title);
  while (page.nextCursor !== null) {
    page = await pageAfter(page.nextCursor);
    titles.push(...page.items.map((post) => post.title));
  }
  return titles;
};

console.log(await allTitles());
// → ["A", "C", "B", "D", "E", "G", "F"]
```

Все семь постов выданы по одному разу, каждый запрос стоил одинаково. Для выгрузки всей коллекции целиком лучше [курсор](./large-results.mdx): он читает документы одним запросом и не гоняет токен туда-обратно.

## Листать список с фильтром

Опция `filter` задаёт, какие документы листать. Она проверяется как фильтр в [`find`](../reference/query/reading.mdx#modelfind) и действует на **каждую** страницу, поэтому токен не открывает доступ к документам вне фильтра: клиент, подменивший токен, может сместить позицию, но не увидеть чужих данных.

```ts twoslash
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Boolean) draft?: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
declare class __BadRequest__ extends Error {}
// ---cut---
const page = await Posts.keysetPage({
  filter: { views: { $lt: 40 } },
  sort: [["views", "desc"]],
  limit: 2,
});
console.log(page.items.map((post) => post.title));
// → ["D", "E"]
```

Фильтр и сортировка на всех страницах одного списка должны быть одинаковыми. Токен запоминает ключи и направления сортировки, поэтому токен, выданный для одной сортировки, нельзя использовать с другой: `KeysetTokenError` с текстом `keysetPage: invalid cursor — it was made for another sort`. Фильтр токен не запоминает: если вы поменяли его между страницами, позиция останется прежней, а состав документов будет другим.

## Проверить, что записи не теряются

Главное отличие от `.skip` видно, когда между запросами страниц в начало списка добавляют запись. Возьмём страницу из двух постов и добавим пост `Z` с 100 просмотрами, самый популярный:

```ts twoslash
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Boolean) draft?: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
declare class __BadRequest__ extends Error {}
// ---cut---
const first = await Posts.keysetPage({ sort: [["views", "desc"]], limit: 2 });
console.log(first.items.map((post) => post.title));
// → ["A", "C"]

await Posts.create({ title: "Z", views: 100 });

const second = await Posts.keysetPage({ sort: [["views", "desc"]], limit: 2, after: first.nextCursor });
console.log(second.items.map((post) => post.title));
// → ["B", "D"]
```

Токен помнит позицию, а не номер страницы, поэтому вторая страница продолжается с `B`: ни одна запись не повторилась и не пропала. Со страницей на `.skip(2)` всё иначе. При том же порядке («просмотры по убыванию, затем `_id` по убыванию») первая страница — `A` и `C`, а после появления `Z` вторая страница по `.skip(2)` начнётся с `C`, и запуск вернул `C` и `B`: новая запись сдвинула остальные, и читатель увидит `C` дважды.

## Листать по времени создания или изменения

Лента «сначала новые» и список «недавно менявшиеся» сортируются по времени. Если модель унаследована от [`Timestamped`](../reference/schemas/base-classes.mdx#timestamped), поля `createdAt` и `updatedAt` годятся в ключ, хотя в схеме они не помечены обязательными: ядро заполняет их при каждой вставке, и отсутствующих значений нет. Допустим, заметки `s1`…`s5` созданы по очереди:

```ts twoslash title="notes/notes.service.ts"
import { Entity, Prop, Schema, Timestamped, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "notes" })
class Note extends Timestamped(Entity) {
  @Prop(() => String, { required: true }) title!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Notes = client.db().model(Note);
// ---cut---
export const newestFirst = (after: string | null) =>
  Notes.keysetPage({ sort: [["createdAt", "desc"]], limit: 2, after });

const page = await newestFirst(null);
console.log(page.items.map((note) => note.title));
// → ["s5", "s4"]
```

Порядок по `updatedAt` подвижный: `updatedAt` меняется при любой записи, и только что изменённая заметка сразу оказывается в начале списка. Для ленты, которая не должна прыгать под пальцем пользователя, листайте по `createdAt`. Если заметки создали с одним и тем же `createdAt`, границу страницы определяет `_id`, который Typemo добавляет последним ключом: ничего не повторяется и не пропадает.

## Подписать токен

Токен не зашифрован: это записанные в строку значения ключей последней строки страницы, и любой клиент может их прочитать и изменить. Пока фильтр запроса действует на каждую страницу, подделанный токен не даёт доступа к чужим данным, максимум сдвигает позицию. Если сдвигать позицию клиенту нельзя, подпишите токены: опция клиента `keysetSecret` (ключ не короче 32 байт) превращает токен в `payload.подпись`, где подпись — HMAC-SHA256 от payload.

```ts twoslash title="db/client.ts"
import { TypemoClient } from "@venloc/typemo";

export const client = await TypemoClient.connect("mongodb://localhost:27017/blog", {
  keysetSecret: "__a-secret-of-at-least-32-bytes-long__",
});
```

Ключ в примере явно ненастоящий: настоящий читайте из секретов окружения, а не из кода. Подпись проверяется прежде, чем токен разбирается, и сравнение занимает одно и то же время независимо от того, сколько символов совпало. С включённой подписью Typemo отвергает неподписанный токен, изменённый токен и, наоборот, подписанный токен на клиенте без ключа:

```text
KeysetTokenError: keysetPage: invalid cursor — it is not signed (the client signs its tokens: keysetSecret)
KeysetTokenError: keysetPage: invalid cursor — the signature is not valid
KeysetTokenError: keysetPage: invalid cursor — it is signed, but this client has no keysetSecret
```

Ключ можно менять без разрыва: `keysetSecret` принимает и список, где первый ключ подписывает, а любой из списка проверяет. Так токены, выданные старым ключом, проживут до конца перехода.

## Как выбрать

Задайте себе один вопрос: **нужен ли пользователю переход на произвольную страницу или общее число страниц?** Если нет, то есть он листает вперёд, как в ленте или журнале, берите `keysetPage`: страница стоит одинаково на любой глубине и не теряет записи. Если нужны «страница 17 из 40», берите [`.skip`](../reference/query/reading.mdx#skip) с [`.limit`](../reference/query/reading.mdx#limit) и [`countDocuments`](../reference/query/reading.mdx#modelcountdocuments), см. [Сортировка и страницы](./sorting-and-pages.mdx): цена в том, что глубокие страницы медленнее, а записи, добавленные между запросами, сдвигают границы.

## Когда это не нужно

`keysetPage` листает только вперёд и не знает общего числа страниц: перейти на страницу 17 или показать «страница 3 из 40» он не может. Ключом могут быть только обязательные необнуляемые поля верхнего уровня с порядком (числа, строки, даты, идентификаторы), `_id`, а у моделей с `Timestamped` ещё `createdAt` и `updatedAt`. Если список нужно упорядочить по необязательному или вычисляемому значению, метод не подойдёт: для вычисляемого порядка используйте [агрегацию](../aggregation/first-aggregation.mdx). Если нужно обойти всю коллекцию, а не показать страницу, используйте [курсор](./large-results.mdx).

## Частые ошибки

### Необязательное поле в ключе

Вы решили сортировать по полю, которого в документе может не быть. У отсутствующего значения нет места в порядке, поэтому такое поле не годится в ключ. Компилятор его не пропускает, а во время работы Typemo бросает [`ConfigurationError`](../reference/errors/configuration-errors.mdx#configurationerror):

```ts twoslash
// @errors: 2322
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Boolean) draft?: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
declare class __BadRequest__ extends Error {}
// ---cut---
await Posts.keysetPage({ sort: [["draft", "asc"]], limit: 3 });
```

```text
ConfigurationError: keysetPage: sort "draft" of Post must be required and not nullable (a missing value cannot be a position)
```

Сделайте поле обязательным и необнуляемым или сортируйте по другому полю.

### Токен от другой сортировки

Клиент прислал токен, выданный для сортировки по `views`, а вы теперь листаете по `title`. Typemo отвергает его:

```text
KeysetTokenError: keysetPage: invalid cursor — it was made for another sort
```

Меняя сортировку списка, начинайте с первой страницы и без `after`: сбросьте токены на клиенте.

### `limit` равен нулю

Размер страницы пришёл из параметра запроса и оказался нулём. Typemo бросает `QueryError`, как и [`.limit`](../reference/query/reading.mdx#limit):

```text
QueryError: keysetPage: limit must be a positive integer, got 0 (number)
```

Ограничьте и проверьте размер страницы до вызова, как в разделе [Принять номер страницы из URL](./sorting-and-pages.mdx#принять-номер-страницы-из-url).

### Токен потерялся между запросами

Вы вызвали `keysetPage` без `after` на каждом запросе и получаете одну и ту же первую страницу. Токен `nextCursor` нужно отдать клиенту и получить обратно: сами страницы состояния между запросами не хранят.

## Полный пример

Сервис ленты постов: страница с токеном (подпись включается в клиенте, как в разделе выше), ошибку токена сервис превращает в неверный запрос. Код читателя, которого нет в Typemo, помечен `__…__`.

```ts twoslash title="posts/posts.service.ts"
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Boolean) draft?: boolean;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Posts = client.db().model(Post);
declare class __BadRequest__ extends Error {}
// ---cut---
// код читателя: __BadRequest__ — ошибка вашего приложения на границе

// одна страница ленты: самые просматриваемые сверху
export const feed = async (afterFromUrl: string | null) => {
  try {
    const page = await Posts.keysetPage({
      filter: { views: { $gt: 0 } },
      sort: [["views", "desc"]],
      limit: 20,
      after: afterFromUrl,
    });
    return {
      items: page.items.map((post) => post.$toPlain()),
      next: page.nextCursor, // null на последней странице
    };
  } catch (error) {
    // токен от клиента: испорченный, подделанный или от другой сортировки
    if (error instanceof KeysetTokenError) throw new __BadRequest__("the page token is invalid");
    throw error;
  }
};
```

<Callout type="migration">

В Mongoose нет встроенной пагинации по ключу: обычно её пишут вручную через `$or` по ключам и склеивают токен самостоятельно. В Typemo это [`Model.keysetPage`](../reference/query/keyset.mdx#modelkeysetpage): `_id` добавляется последним ключом сам, токен проверяется полностью, а подпись включается одной опцией клиента.

</Callout>
