Чтобы форма ответа не менялась незаметно, опишите её **контрактом**, то есть типом, который вы пишете сами. Потом попросите Typemo сверить с ним то, что запрос действительно возвращает. Это нужно там, где форма ответа — договорённость с другим кодом. Например, тело ответа API, сообщение в очередь или вход для другого сервиса. Добавили поле в модель или поменяли выбор полей в запросе — о расхождении скажет сверка при компиляции, а не клиент, который получил лишнее поле или потерял нужное.

Проверка бывает двух видов, и задачи у них разные.

- **При компиляции** работают [`.expect`](../reference/query/contracts.mdx#expect) и [`Contract.check`](../reference/query/contracts.mdx#contractcheck). Они сравнивают тип результата с вашим описанием и ничего не стоят во время работы.
- **Во время работы** работает [`.parse`](../reference/query/contracts.mdx#parse). Он прогоняет каждую строку через схему проверки данных.

Второй вид нужен, потому что тип обещает форму, а база хранит то, что в неё записали. А записать могли старая версия приложения, разовый скрипт или кто-то через драйвер.

## Что понадобится

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель счёта из файла `accounts/account.ts`. В ней есть необязательная заметка и скрытый `pin`, на них видны особые случаи.

```ts twoslash title="accounts/account.ts"
import { Entity, type Hidden, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Number, { required: true })
  balance!: number;

  @Prop(() => String)
  note?: string;

  @Prop(() => String, { hidden: true })
  pin?: Hidden<string>;
}
```

В коллекции три счёта.

- Alice — `Main`, баланс 100.
- Bob — `Savings`, баланс 250.
- Carol — её запись старый скрипт сделал прямо в базу с балансом-строкой `"n/a"`.

## Быстрый путь

Есть три способа для трёх ситуаций. Контракт для строки результата запроса проверяется при компиляции через [`.expect`](../reference/query/contracts.mdx#expect) и описание [`Selected`](../reference/query/contracts.mdx#selected) — «поля этой модели в результате `.plain()`».

```ts twoslash
import { Entity, type Hidden, Prop, Schema, type Selected, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => String) note?: string;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
type BalanceRow = Selected<Account, "owner" | "balance">;

const rows = await Accounts.find({ owner: { $ne: "carol" } })
  .select({ owner: 1, balance: 1 })
  .sort({ owner: 1 })
  .plain()
  .expect<BalanceRow>();
console.log(rows.map((row) => [row.owner, row.balance]));
// → [["alice", 100], ["bob", 250]]
```

Данные во время работы проверяет [`.parse`](../reference/query/contracts.mdx#parse) со схемой, а готовый документ при компиляции — [`Contract.check`](../reference/query/contracts.mdx#contractcheck). Ниже разберём всё на задачах.

## Зафиксировать форму ответа при компиляции

Допустим, обработчик отдаёт клиенту список счетов с владельцем и балансом. Вы выбираете два поля через [`.select`](../reference/query/reading.mdx#select), превращаете результат в обычные объекты через [`.plain()`](../reference/query/reading.mdx#plain) и добавляете `.expect<Форма>()`.

Форма записывается как `Selected<Модель, "поле" | "поле">`. Это тип строки результата `.plain()` с этими полями. `_id` входит в него по умолчанию, в результате `.plain()` это строка, а `"-_id"` среди полей его убирает.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, type Selected, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => String) note?: string;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
// ---cut---
type BalanceRow = Selected<Account, "owner" | "balance">;
//   ^?

type BalanceRowWithoutId = Selected<Account, "owner" | "balance" | "-_id">;
//   ^?
```

`.expect` сверяет **точно** — те же поля, та же необязательность, те же `null`. Если всё совпало, запрос возвращается как был, и тип результата не меняется. Во время работы метод ничего не делает, так что его можно оставить в коде насовсем.

### Что ловит проверка

Проверка ловит три вида расхождений, и все видны при компиляции. Первый — выбраны не все поля контракта.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, type Selected, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => String) note?: string;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
type BalanceRow = Selected<Account, "owner" | "balance">;
// ---cut---
// @errors: 2684
await Accounts.find().select({ owner: 1 }).plain().expect<BalanceRow>();
// компилятор: … is not assignable to method's 'this' of type '{ readonly missing: "balance"; }'
```

`missing` значит, что поле есть в контракте, но его нет в результате. Обратный случай — выбрано лишнее поле.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, type Selected, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => String) note?: string;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
type BalanceRow = Selected<Account, "owner" | "balance">;
// ---cut---
// @errors: 2684
await Accounts.find().select({ owner: 1, balance: 1, note: 1 }).plain().expect<BalanceRow>();
// компилятор: … is not assignable to method's 'this' of type '{ readonly extra: "note"; }'
```

`extra` значит, что поле есть в результате, но его нет в контракте. Лишнее поле здесь всегда ошибка, хотя обычная проверка типов TypeScript объект с лишним полем пропустила бы. Контракт для того и нужен, чтобы поле не ушло в ответ незамеченным, например чужая заметка к клиенту.

Третий вид — `mismatch`. Поле есть и там, и там, но отличается тип, `null` или необязательность.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => String) note?: string;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
type BalanceRow = { _id: string; owner: string; balance: string };

// @errors: 2684
await Accounts.find().select({ owner: 1, balance: 1 }).plain().expect<BalanceRow>();
// компилятор: … is not assignable to method's 'this' of type '{ readonly mismatch: "balance"; }'
```

Сообщение называет поле, на котором расхождение. Пути вложенных полей пишутся через точку, элементы массива — как `[]`, а сам результат — как `(root)`.

## Сверить готовый документ или JSON

`.expect` есть только у запросов. Бывает, что документ у вас уже есть, например после `findOne` или `create`, а клиенту вы отдаёте его `$toJSON()`. Тогда сверяйте значение через [`Contract.check`](../reference/query/contracts.mdx#contractcheck). Она принимает любое значение и возвращает его же с типом контракта.

Две пары скобок в вызове не случайны. Первые задают ожидаемый тип, вторые принимают значение, и его тип TypeScript выводит сам.

```ts twoslash title="accounts/accounts.api.ts"
import { Contract, Entity, type Hidden, Prop, Schema, type SelectedJson, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => String) note?: string;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
type AccountJson = SelectedJson<Account, "owner" | "title" | "balance" | "note">;

export const getAccountJson = async (owner: string) => {
  const account = await Accounts.findOne({ owner }).orFail();
  const json = Contract.check<AccountJson>()(account.$toJSON());
  //    ^?
  return json;
};
```

Скрытый `pin` в контракте не назван, и проверка проходит, ведь `$toJSON()` его не отдаёт. А уберите из описания `title` и `note`, и проверка вас остановит. Документ отдаёт больше, чем обещает контракт.

```ts twoslash
import { Contract, Entity, type Hidden, Prop, Schema, type SelectedJson, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => String) note?: string;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
const account = await Accounts.findOne({ owner: "alice" }).orFail();
// ---cut---
type Narrow = SelectedJson<Account, "owner" | "balance">;

// @errors: 2379
Contract.check<Narrow>()(account.$toJSON());
// компилятор: … Property 'extra' is missing in type … but required in type '{ readonly extra: "title" | "note"; }'
```

## Какое описание взять

Три типа описания различаются тем, в каком виде они показывают значения, ровно как виды результата запроса.

- [`Selected`](../reference/query/contracts.mdx#selected) описывает результат `.plain()` и `$toPlain()`. Идентификаторы — строки, геттеры-виртуальные поля на месте.
- [`SelectedLean`](../reference/query/contracts.mdx#selectedlean) описывает результат `.lean()`. Значения такие, какими их отдал драйвер, `_id` — `ObjectId`, 64-битные числа — `bigint`.
- [`SelectedJson`](../reference/query/contracts.mdx#selectedjson) описывает то, что возвращает `$toJSON()`. Идентификаторы, даты и 64-битные числа — строки.

Берите тот, в каком виде вы отдаёте данные. Ответ идёт клиенту через JSON — сверяйте с `SelectedJson`. Внутри приложения работаете с `.lean()` — с `SelectedLean`.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, type SelectedLean, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => String) note?: string;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
type LeanRow = SelectedLean<Account, "owner" | "balance" | "-_id">;

const rows = await Accounts.find({ owner: "alice" })
  .select({ owner: 1, balance: 1, _id: 0 })
  .lean()
  .expect<LeanRow>();
console.log(rows);
// → [{ owner: "alice", balance: 100 }]
```

Если поле заполняется через `populate` или это вложенный документ, форма зависит от запроса. Её нужно задать третьим параметром `Selected`, переопределением — `Selected<Post, "title" | "author", { author: Selected<User, "name" | "-_id"> }>`. Подробности в справочнике [Контракты](../reference/query/contracts.mdx#selected).

## Проверить данные из базы во время работы

Тип обещает форму, а база хранит то, что в неё записали. Скажем, старый скрипт сохранил баланс Carol строкой `"n/a"`. Сверка при компиляции этого не увидит, для неё баланс — просто число по типу модели. Чтобы поймать такую запись до того, как она уйдёт клиенту, передайте схему в [`.parse`](../reference/query/contracts.mdx#parse).

Подойдёт любая схема по стандарту **Standard Schema**, то есть объект с полем `"~standard"`. Так устроены схемы популярных библиотек проверки данных, и их можно передавать без обёрток. Ниже своя схема на несколько строк, чтобы не зависеть от библиотеки. Она пропускает строку, только если владелец — строка, а баланс — число.

```ts twoslash title="accounts/balance-row.ts"
export const balanceRow = {
  "~standard": {
    version: 1 as const,
    vendor: "app",
    validate: (value: unknown) => {
      const row = value as { owner?: unknown; balance?: unknown };
      if (typeof row.owner !== "string") return { issues: [{ message: "owner must be a string", path: ["owner"] }] };
      if (typeof row.balance !== "number") return { issues: [{ message: "balance must be a number", path: ["balance"] }] };
      return { value: { owner: row.owner, balance: row.balance } };
    },
    types: undefined as unknown as { input: unknown; output: { owner: string; balance: number } },
  },
};
```

Перед проверкой результат нужно превратить в обычные объекты, `.parse` работает у `.lean()` и `.plain()`. Если все строки верны, вы получите то, что вернула схема. Она умеет не только проверять, но и преобразовывать строки.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => String) note?: string;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
const balanceRow = {
  "~standard": {
    version: 1 as const,
    vendor: "app",
    validate: (value: unknown) => {
      const row = value as { owner?: unknown; balance?: unknown };
      if (typeof row.owner !== "string") return { issues: [{ message: "owner must be a string", path: ["owner"] }] };
      if (typeof row.balance !== "number") return { issues: [{ message: "balance must be a number", path: ["balance"] }] };
      return { value: { owner: row.owner, balance: row.balance } };
    },
    types: undefined as unknown as { input: unknown; output: { owner: string; balance: number } },
  },
};
// ---cut---
const bob = await Accounts.find({ owner: "bob" }).plain().parse(balanceRow);
//    ^?
console.log(bob);
// → [{ owner: "bob", balance: 250 }]
```

Если же в результат попадает запись Carol, запрос падает с [`ValidationError`](../reference/errors/data-errors.mdx#validationerror). Ошибка одна на весь запрос и собирает замечания по всем строкам. Путь начинается с номера строки в результате, считая с нуля. Carol третья по владельцу, поэтому путь начинается с `2`.

```ts twoslash title="accounts/accounts.service.ts"
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => String) note?: string;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
const balanceRow = {
  "~standard": {
    version: 1 as const,
    vendor: "app",
    validate: (value: unknown) => {
      const row = value as { owner?: unknown; balance?: unknown };
      if (typeof row.owner !== "string") return { issues: [{ message: "owner must be a string", path: ["owner"] }] };
      if (typeof row.balance !== "number") return { issues: [{ message: "balance must be a number", path: ["balance"] }] };
      return { value: { owner: row.owner, balance: row.balance } };
    },
    types: undefined as unknown as { input: unknown; output: { owner: string; balance: number } },
  },
};
// ---cut---
try {
  await Accounts.find().sort({ owner: 1 }).plain().parse(balanceRow);
} catch (error) {
  console.log(String(error));
  // → 'ValidationError: Validation failed: "2.balance": row 2: balance must be a number [schema]'
}
```

Схемы в `.parse` проверяют **читаемые** данные, а схемы полей модели — **записываемые**. Само чтение строки не проверяет. Если в базе лежит значение не того типа, обычный `find` вернёт его как есть. Поэтому `.parse` ставят там, где данные пересекают границу доверия.

### Один документ и списки

У `findOne` результат — строка или `null`. Если ничего не нашлось, `null` так и останется `null`, и схема его не проверяет. Отсутствие документа — не нарушение формы.

```ts twoslash
      if (typeof row.balance !== "number") return { issues: [{ message: "balance must be a number", path: ["balance"] }] };

```

### Большие выборки

Если вы читаете список курсором ([`.cursor()`](../reference/query/cursor.mdx)), строки проверяются по ходу чтения. Первая неверная строка завершает чтение ошибкой `ValidationError` с номером строки в потоке, и курсор закрывается. Строки до ошибки вы уже успели обработать. Для потока это нормально, данные не потерялись.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => String) note?: string;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
const balanceRow = {
  "~standard": {
    version: 1 as const,
    vendor: "app",
    validate: (value: unknown) => {
      const row = value as { owner?: unknown; balance?: unknown };
      if (typeof row.owner !== "string") return { issues: [{ message: "owner must be a string", path: ["owner"] }] };
      if (typeof row.balance !== "number") return { issues: [{ message: "balance must be a number", path: ["balance"] }] };
      return { value: { owner: row.owner, balance: row.balance } };
    },
    types: undefined as unknown as { input: unknown; output: { owner: string; balance: number } },
  },
};
// ---cut---
const cursor = Accounts.find().sort({ owner: 1 }).plain().parse(balanceRow).cursor();
const seen: string[] = [];
try {
  for await (const row of cursor) seen.push(row.owner);
} catch (error) {
  console.log(seen, String(error));
  // → ["alice", "bob"] 'ValidationError: Validation failed: "2.balance": row 2: balance must be a number [schema]'
}
```

## Как выбрать

Спросите себя, **кому вы не доверяете — коду или данным**.

- **Коду.** Кто-то из команды поменяет модель или запрос, и ответ разойдётся с договорённостью. Берите `.expect` и `Contract.check`, они бесплатны и работают при компиляции.
- **Данным.** В базе может лежать не то, что обещает тип, — записанное старым приложением, импортом или руками. Нужен `.parse`.

На границе с внешним миром часто нужны оба. `.expect` закрепляет, что запрос выбирает нужные поля, а `.parse` проверяет, что значения этих полей годятся.

## Когда это не нужно

Если ответ не покидает приложение и запрос с потребителем оба ваши, отдельный контракт лишний. Тип результата и так известен компилятору, и вы видите его в подсказке редактора.

Не ставьте `.parse` на горячий путь чтения, если данным вы доверяете. Он разбирает каждую строку, а это время. И для документов `.expect` и `.parse` не работают. Контракт описывает данные, а документ — объект с методами, поэтому сверяйте результат его метода через `Contract.check`.

## Если что-то пошло не так

**`.expect` не компилируется на документе.** Вы вызвали `.expect` у запроса без `.plain()` или `.lean()`. Контракт описывает данные, а документ — объект с методами, и точно сравнивать с ним бессмысленно. Компилятор прямо говорит, что делать.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, type Selected, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => String) note?: string;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
type BalanceRow = Selected<Account, "owner" | "balance">;
// ---cut---
// неправильно: у документа нет контракта
// @errors: 2684
await Accounts.find().select({ owner: 1, balance: 1 }).expect<BalanceRow>();
// компилятор: … 'PathError<"expect<Shape>() checks rows: call .plain() or .lean() first (for a document, Contract.check its $toPlain())">'

// правильно: строки результата в plain-виде
await Accounts.find().select({ owner: 1, balance: 1 }).plain().expect<BalanceRow>();
```

**Контракт разошёлся из-за `_id`.** Вы описали форму как `{ owner: string; balance: number }`, а запрос вернул ещё и `_id`. `_id` в результате есть всегда, пока вы его не исключите через `.select({ owner: 1, balance: 1, _id: 0 })`. Либо добавьте его в контракт, либо возьмите `Selected<Account, "owner" | "balance">`, где он уже есть, а если исключаете — допишите `"-_id"`.

**Выбрали одно, описали другое — `extra` или `missing`.** Причина всегда в разнице между `.select` и контрактом, одно поменяли, а другое нет. Ошибка называет поле. Держите `.select` и контракт рядом и меняйте вместе. Удобнее всего строить `Selected` от того же списка полей.

**`.parse` до `.plain()`.** `.parse` проверяет данные, а документ — не данные. Поэтому вызов до `.lean()` или `.plain()` не компилируется, а в коде без типов бросает `QueryError`.

```text
QueryError: parse() validates rows: call .lean() or .plain() before .parse(schema)
```

Добавьте `.plain()` перед `.parse(схема)`.

## Полный пример

Здесь всё вместе — контракт запроса при компиляции, проверка данных во время работы и сверка документа. Код, которого нет в Typemo и который пишете вы, помечен `__…__`.

```ts twoslash title="accounts/accounts.api.ts"
import { Contract, Entity, type Hidden, Prop, Schema, type Selected, type SelectedJson, TypemoClient } from "@venloc/typemo";

@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Number, { required: true })
  balance!: number;

  @Prop(() => String)
  note?: string;

  @Prop(() => String, { hidden: true })
  pin?: Hidden<string>;
}

// код читателя: ошибка на границе приложения и схема проверки данных
class __BadData__ extends Error {}
declare const __balanceRow__: {
  "~standard": {
    version: 1;
    vendor: string;
    validate: (value: unknown) => { value: { owner: string; balance: number } } | { issues: { message: string; path: string[] }[] };
    types: { input: unknown; output: { owner: string; balance: number } };
  };
};

type BalanceRow = Selected<Account, "owner" | "balance">;
type AccountJson = SelectedJson<Account, "owner" | "title" | "balance" | "note">;

export const createApi = (client: TypemoClient) => {
  const Accounts = client.db().model(Account);

  // список: форма зафиксирована при компиляции
  const listBalances = () =>
    Accounts.find().select({ owner: 1, balance: 1 }).sort({ owner: 1 }).plain().expect<BalanceRow>();

  // список из ненадёжного источника: значения проверяются во время работы
  const listCheckedBalances = async () => {
    try {
      return await Accounts.find().sort({ owner: 1 }).plain().parse(__balanceRow__);
    } catch (error) {
      throw new __BadData__("account data is corrupted", { cause: error });
    }
  };

  // один счёт: документ превращается в JSON по контракту
  const getAccount = async (owner: string) => {
    const account = await Accounts.findOne({ owner }).orFail();
    return Contract.check<AccountJson>()(account.$toJSON());
  };

  return { listBalances, listCheckedBalances, getAccount };
};
```

<Callout type="migration">

В Mongoose форму результата `lean()` описывали вручную дженериком, и ничто не сверяло его с запросом, тип можно было написать любой. В Typemo форму сверяет компилятор. [`.expect`](../reference/query/contracts.mdx#expect) сравнивает описание с типом результата и сообщает о расхождении, а [`.parse`](../reference/query/contracts.mdx#parse) добавляет проверку во время работы схемой Standard Schema.

</Callout>
