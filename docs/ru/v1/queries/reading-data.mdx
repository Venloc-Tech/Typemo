Typemo возвращает прочитанные данные в трёх видах: **документ**, который можно изменить и сохранить, **lean-строка** с данными ровно как в базе и **plain-объект**, готовый для ответа клиенту. Вид вы выбираете одним вызовом в конце запроса.

Разница появляется из-за того, что MongoDB хранит данные в формате BSON. В нём есть типы, которых нет в JSON: идентификатор `ObjectId`, 64-битные целые числа, точные десятичные `Decimal128`. Внутри приложения с ними удобно работать, но клиенту их напрямую не отдать. Если вы впервые работаете с MongoDB, сначала прочитайте [Типы данных MongoDB](../concepts/bson-types.mdx): там это разобрано подробно.

## Что предполагается

Примеры используют клиент из руководства [Подключиться к базе](../connection/connect.mdx) и обычные функции сервиса, без веб-фреймворка: тот же код вызывается из обработчика любого фреймворка. Границу приложения, например ответ 404, показывают классы читателя `__NotFound__` и `__BadRequest__`. В коллекциях лежит клиент Alice и два её счёта: `Main` (баланс `9007199254741093`, теги `salary` и `vip`, метка `tier` со значением `gold`) и `Savings` (баланс `500`, без тегов). Результаты в комментариях `// →` получены на этих данных, идентификаторы сокращены до `"…"`.

## Быстрый путь

Начнём с модели банковского счёта. В ней два поля:

```ts twoslash title="models/account.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => BigInt, { required: true })
  balance!: bigint;
}
```

[`Entity`](../reference/schemas/base-classes.mdx#entity) добавляет модели поле `_id` типа `ObjectId`: это идентификатор, который MongoDB присваивает каждому документу. `BigInt` означает, что баланс хранится в базе 64-битным целым числом, а в коде это `bigint`.

Вот три способа прочитать один и тот же счёт. Наведите курсор на имена переменных, чтобы увидеть их типы:

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
// ---cut---
// 1. Документ: чтобы изменить и сохранить
const account = await Accounts.findOne({ title: "Main" }).orFail();

// 2. plain: чтобы отдать клиенту
const forClient = await Accounts.findOne({ title: "Main" }).plain().orFail();
//    ^?
// → { _id: "…", title: "Main", balance: "9007199254741093" }

// 3. lean: чтобы посчитать внутри приложения
const raw = await Accounts.findOne({ title: "Main" }).lean().orFail();
//    ^?
// → { _id: ObjectId("…"), title: "Main", balance: 9007199254741093n }
```

У `forClient` поля `_id` и `balance` — строки, а у `raw` — `ObjectId` и `bigint`. Типы выводятся из модели и из вызова в конце запроса, поэтому компилятор всегда знает, с каким видом данных вы работаете.

[`.orFail()`](../reference/query/reading.mdx#orfail) значит «если ничего не нашлось, брось ошибку». Без него [`findOne`](../reference/query/reading.mdx#modelfindone) может вернуть `null`, и TypeScript заставит вас обработать этот случай.

Остальная страница разбирает каждый вид на реальных задачах.

## Изменить запись

Если в конце запроса нет [`.plain()`](../reference/query/reading.mdx#plain) или [`.lean()`](../reference/query/reading.mdx#lean), вы получаете документ. Он выглядит как экземпляр вашего класса `Account`, но умеет больше: помнит, какие поля вы изменили, и умеет сохранить себя в базу.

```ts twoslash
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
const account = await Accounts.findOne({ title: "Main" }).orFail();

account.title = "Main account";

console.log(account.$isModified("title"), account.$isModified("balance"));
// → true false

await account.$save();
```

[`$save()`](../reference/documents/document-api.mdx#save) не перезаписывает документ в базе целиком. Typemo отправляет только изменённые поля, здесь это `{ $set: { title: "Main account" } }`. Поэтому если другой запрос в это же время изменил `balance` того же счёта, его изменение не пропадёт. Методы документа начинаются с `$`: [`$set()`](../reference/documents/document-api.mdx#set), [`$isModified()`](../reference/documents/document-api.mdx#ismodified), [`$toPlain()`](../reference/documents/document-api.mdx#toplain). Так их легко отличить от полей вашей модели.

Массивы и `Map` внутри документа тоже отслеживают изменения. Добавим счёту теги:

```ts twoslash title="models/account.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => BigInt, { required: true })
  balance!: bigint;

  @Prop(() => [String]) // [!code ++]
  tags!: string[]; // [!code ++]
}
```

```ts twoslash
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
const account = await Accounts.findOne({ title: "Savings" }).orFail();

account.tags.push("gold");
await account.$save();
// в базу уйдёт { $push: { tags: { $each: ["gold"] } } }, а не весь массив
```

Подробнее о том, как массивы превращаются в операции MongoDB, — в руководстве [Массивы и Map в документе](../documents/typed-collections.mdx).

Документ стоит дороже двух других видов: для каждой строки Typemo строит объект, коллекции и запоминает исходные значения. Если вы не собираетесь ничего менять, эта работа лишняя.

## Отдать данные клиенту

Клиент запрашивает счёт через API. Документ отдавать нельзя: у него есть методы и служебное состояние. lean-строка тоже не подходит: `JSON.stringify` не умеет сериализовать `bigint` и бросает ошибку, а `ObjectId` клиенту ни о чём не говорит.

Для этого есть [`.plain()`](../reference/query/reading.mdx#plain). Он читает данные из базы и переводит каждое значение в обычный вид JavaScript:

```ts twoslash
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
const account = await Accounts.findOne({ title: "Main" }).plain().orFail();
// → {
//     _id: "…",
//     title: "Main",
//     balance: "9007199254741093",
//     tags: ["salary", "vip"],
//     owner: "…",
//     labels: Map(1) { "tier" => "gold" },
//   }
```

`_id` стал строкой: это шестнадцатеричная запись `ObjectId`, которую клиент может показать, передать в адресе и прислать обратно. `balance` тоже стал строкой, и это важно. Обычный `number` в JavaScript хранит целые числа точно только до 2⁵³. Баланс `9007199254741093` больше этой границы: если отправить его числом, клиент получил бы `9007199254741092`, и никакой ошибки не было бы. Поэтому 64-битные числа в plain-виде всегда десятичная строка. Документ при этом не создаётся, так что `.plain()` почти так же быстр, как `.lean()`. Как в plain-виде выглядит каждый тип MongoDB, показано в справочнике [Формы значений](../reference/values/value-forms.mdx).

### Список счетов

Самый частый сценарий — список для страницы приложения. Он живёт в функции сервиса, которую вызывает обработчик запроса:

```ts twoslash title="accounts/accounts.service.ts"
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
export const listAccounts = () =>
  Accounts.find()
    .sort({ title: 1 })
    .limit(20)
    .select({ title: 1, balance: 1 })
    .plain();

console.log(await listAccounts());
// → [
//     { _id: "…", title: "Main", balance: "9007199254741093" },
//     { _id: "…", title: "Savings", balance: "500" },
//   ]
```

[`.select({ title: 1, balance: 1 })`](../reference/query/reading.mdx#select) просит базу вернуть только эти поля. Компилятор это знает: у элементов результата нет поля `tags`, и обратиться к нему не получится. `_id` MongoDB возвращает всегда, пока вы не исключите его явно через `_id: 0`. Про выбор полей подробно рассказано в руководстве [Выбор полей и тип результата](./projections.mdx), а про сортировку и ограничение списка — в руководстве [Сортировка и страницы](./sorting-and-pages.mdx).

Функция `listAccounts` не объявлена `async` и возвращает запрос, а не результат: строитель запроса сам ведёт себя как `Promise`, поэтому вызывающий код пишет `await listAccounts()`, а тип возврата можно объявить как `Promise<…>` без обёрток. Запрос уходит в базу только на `await`.

### Один счёт по id из URL

Клиент запрашивает `GET /accounts/6abcfa30531a3d0a555e2f5b`. Id приходит строкой, и [`findById`](../reference/query/reading.mdx#modelfindbyid) принимает её как есть: приводить строку к `ObjectId` самому не нужно.

```ts twoslash title="accounts/accounts.service.ts"
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
export const getAccount = async (idFromUrl: string) => {
  try {
    return await Accounts.findById(idFromUrl).orFail().plain();
  } catch (error) {
    if (error instanceof DocumentNotFoundError) throw new __NotFound__("account not found");
    if (error instanceof CastError) throw new __BadRequest__("the id is malformed");
    throw error;
  }
};
```

Ошибок здесь две, и обе относятся к вводу клиента, а не к сбою сервера. Если счёта с таким id нет, `.orFail()` бросает [`DocumentNotFoundError`](../reference/errors/query-errors.mdx#documentnotfounderror), и функция превращает её в «не найдено»:

```text
DocumentNotFoundError: Account.findById: no document matched the filter (orFail)
```

Если строка не похожа на идентификатор, запрос вообще не уходит в базу. Typemo проверяет формат сам и бросает [`CastError`](../reference/errors/data-errors.mdx#casterror):

```text
CastError: Cast to ObjectId failed at path "_id" for "abc" (string): not a 24-character hex string [format]
```

Свой разбор строки перед вызовом для этого не нужен: `CastError` — это готовый сигнал «id неверный», и функция выше отвечает на него ошибкой 400.

<Callout type="tip">

Чтобы не повторять `try/catch` в каждой функции, переводите `DocumentNotFoundError` и `CastError` в ответы один раз, там, где ваше приложение превращает ошибки в ответы.

</Callout>

### Вернуть запись после изменения

Клиент переименовывает счёт и ждёт в ответ обновлённую запись. Есть два способа, и оба возвращают одинаковый plain-объект.

Первый — изменить запись одним запросом к базе через [`findByIdAndUpdate`](../reference/writes/writes.mdx#findbyidandupdate):

```ts twoslash title="accounts/accounts.service.ts"
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
export const renameAccount = (idFromUrl: string, title: string) =>
  Accounts.findByIdAndUpdate(idFromUrl, { $set: { title } }, { returnDocument: "after" })
    .orFail()
    .plain();
```

`returnDocument: "after"` просит вернуть запись после изменения. Без этой опции вы получите состояние до изменения.

Второй — прочитать документ, изменить его и перевести в plain через [`$toPlain()`](../reference/documents/document-api.mdx#toplain):

```ts twoslash title="accounts/accounts.service.ts"
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
export const renameAccountWithChecks = async (idFromUrl: string, title: string) => {
  const account = await Accounts.findById(idFromUrl).orFail();
  account.title = title;
  await account.$save();
  return account.$toPlain();
};
```

`$toPlain()` у документа даёт тот же результат, что `.plain()` у запроса, но берёт данные из уже загруженного документа, а не из базы. Второй способ нужен, когда перед сохранением есть логика: проверки, вычисления, [хуки](../hooks/document-hooks.mdx). Если логики нет, первый способ проще и делает одно обращение к базе вместо двух.

### Принять значения от клиента обратно

Клиент получил `balance` строкой и может прислать её обратно. В [`create`](../reference/writes/writes.mdx#create), в обновлениях и в фильтрах переводить строку в `bigint` не нужно: Typemo принимает строку с целым числом везде, где ожидается 64-битное число. Так же строкой можно передать идентификатор.

```ts twoslash
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
const alice = await Customers.findOne({ email: "alice@example.com" }).orFail();

await Accounts.create({ title: "Bonus", balance: "9007199254740993", tags: [], owner: alice._id });

await Accounts.updateOne({ title: "Bonus" }, { $set: { balance: "500" } });

const rich = await Accounts.find({ balance: { $gte: "500" } }).plain();
console.log(rich.length);
// → 3
```

После создания `Bonus` в коллекции три счёта с балансом не меньше 500: `Main`, `Savings` и `Bonus`.

Тот же принцип действует в операторах, которые считают, — [`$inc`](../reference/writes/update-operators.mdx#inc), `$mul`, `$min` и `$max`. Поэтому сумму пополнения, пришедшую от клиента строкой, можно передать как есть:

```ts twoslash title="accounts/accounts.service.ts"
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
export const deposit = (idFromUrl: string, amount: `${bigint}`) =>
  Accounts.findByIdAndUpdate(idFromUrl, { $inc: { balance: amount } }, { returnDocument: "after" })
    .orFail()
    .plain();
```

Строка должна быть записана строго: `"500"`, `"-42"`, `"9223372036854775807"`. Всё, что можно прочитать двусмысленно, Typemo отклоняет с `CastError`, а не округляет:

```text
CastError: Cast to Long failed at path "$inc.balance" for "1.5" (string): a string must be a decimal integer (no sign +, leading zeros, -0, spaces, exponent or prefix) [format]
```

Так же отклоняются `"1e3"`, `"+1"`, `"01"`, `" 1"`, `"0x10"`, пустая строка и числа за пределами 64 бит: иначе сумма, набранная клиентом с опечаткой, тихо превратилась бы в другую.

### Не отдать секретные поля

Добавим модель клиента банка с хешем пароля:

```ts twoslash title="models/customer.ts"
import { Entity, type Hidden, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "customers" })
export class Customer extends Entity {
  @Prop(() => String, { required: true })
  name!: string;

  @Prop(() => String, { required: true })
  email!: string;

  @Prop(() => String, { hidden: true }) // [!code ++]
  passwordHash?: Hidden<string>; // [!code ++]
}
```

Опция [`hidden`](../reference/schemas/prop.mdx#hidden) вместе с типом `Hidden<string>` делает поле **скрытым**. Такое поле не читается из базы, пока его не попросят явно, и не попадает в plain-вид, даже если его прочитали.

При входе в систему хеш нужен, чтобы проверить пароль. Попросите его через `select` со знаком `+` перед именем поля:

```ts twoslash title="auth/auth.service.ts"
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
declare const __verifyPassword__: (password: string, hash: string | undefined) => Promise<boolean>;
declare class __Unauthorized__ extends Error {}

export const login = async (email: string, password: string) => {
  const customer = await Customers.findOne({ email })
    .select({ "+passwordHash": true })
    .orFail();

  if (!(await __verifyPassword__(password, customer.passwordHash))) {
    throw new __Unauthorized__("wrong password");
  }

  return customer.$toPlain();
};

console.log(await login("alice@example.com", "…"));
// → { _id: "…", name: "Alice", email: "alice@example.com" }
```

Хеш прочитан и проверен, но в ответ он не попал. Это проверяется не только во время работы: в типе результата `$toPlain()` поля `passwordHash` нет, и обращение к нему не скомпилируется:


Случайно вернуть хеш клиенту не получится. Если скрытое поле всё-таки нужно в plain-виде, например во внутреннем сервисе, скажите об этом явно:


У запроса опция та же: `.plain({ hidden: true })`. Подробнее о скрытых полях и о маскировке значений — в руководстве [Скрытые и чувствительные поля](../schemas/hidden-and-sensitive.mdx).

### Отдать связанные данные

Счёт принадлежит клиенту. Добавим в `Account` ссылку на владельца:


### Выгрузить много строк

Если строк тысячи, например для выгрузки в другую систему, не загружайте их в память все сразу. **Курсор** отдаёт строки по одной, по мере чтения из базы. Его возвращает [`.cursor()`](../reference/query/reading.mdx#cursor):

Каждая строка уже в plain-виде. Другие способы обработки больших выборок — в руководстве [Большие выборки](./large-results.mdx).

## Посчитать что-то внутри приложения

Для расчётов plain-вид неудобен: сложить строки `"9007199254741093"` и `"500"` как числа не получится. Для таких задач есть [`.lean()`](../reference/query/reading.mdx#lean): он возвращает данные ровно в том виде, в каком их отдала база, без перевода.

Посчитаем, сколько денег у клиента на всех счетах. К `Main` и `Savings` здесь добавился `Bonus` из предыдущего раздела, поэтому счетов три:

```ts twoslash title="accounts/accounts.service.ts"

  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");

const Customers = client.db().model(Customer);

declare class __BadRequest__ extends Error {}

  const rows = await Accounts.find({ owner: ownerId }).select({ balance: 1 }).lean();
  return rows.reduce((sum, row) => sum + row.balance, 0n);
};

const alice = await Customers.findOne({ email: "alice@example.com" }).plain().orFail();
console.log(await totalBalance(alice._id));
// → 9007199254742093n
```

`row.balance` здесь `bigint`, поэтому сложение точное, даже если сумма больше 2⁵³. Обратите внимание, что в фильтр владелец передан строкой: `ObjectId` из строки Typemo собирает сам.

Идентификаторы в lean-виде остаются объектами `ObjectId`. Сравнивайте их методом `equals`: оператор `===` сравнивает объекты по ссылке, а не по значению.

## Найти список и считать пустой результат ошибкой

Обычно пустой список — нормальный ответ: у клиента пока нет счетов. Но иногда отсутствие данных — сбой, например справочник не загрузился. Тогда добавьте `.orFail()` и к `find`: пустой список превратится в `DocumentNotFoundError`, а непустой вернётся как обычно.

```ts twoslash
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}

```

MongoDB в такой ситуации вернула бы пустой массив; ошибку вы бросаете сами, когда пустой результат для вас недопустим. У курсора это не работает: [`.cursor()`](../reference/query/reading.mdx#cursor) не знает заранее, что документов не будет, и на пустой выборке просто завершается без единой строки.

## Как выбрать

Задайте себе один вопрос: что будет с данными после чтения?

Если вы будете их **менять и сохранять** — берите документ. Только он отслеживает изменения и умеет [`$save()`](../reference/documents/document-api.mdx#save).

Если данные **уйдут за пределы приложения** — в HTTP-ответ, в очередь сообщений, в кеш, в лог — берите [`.plain()`](../reference/query/reading.mdx#plain). Он переводит BSON-типы в строки, не теряет точность больших чисел и не выпускает скрытые поля.

Если данные **нужны для расчёта внутри приложения** — сложить, сравнить, передать в другой запрос — берите [`.lean()`](../reference/query/reading.mdx#lean). Он самый быстрый и сохраняет точные типы.

Бывает, что вы прочитали документ, изменили его, а потом нужно вернуть его клиенту. Второй раз читать из базы не нужно: вызовите [`$toPlain()`](../reference/documents/document-api.mdx#toplain) у документа.

## Когда что не нужно

Документ не нужен, если вы только читаете: для списков, отчётов и ответов API он делает лишнюю работу. Вместо него возьмите [`.plain()`](../reference/query/reading.mdx#plain) или [`.lean()`](../reference/query/reading.mdx#lean).

`.plain()` не нужен, если данные остаются внутри приложения: строки вместо чисел только помешают расчётам. Здесь подойдёт [`.lean()`](../reference/query/reading.mdx#lean).

`.lean()` не нужен, если данные уходят клиенту. Вам придётся самим переводить `bigint` и `ObjectId`, и это легко сделать с ошибкой; для ответа используйте [`.plain()`](../reference/query/reading.mdx#plain).

Если нужно только узнать, есть ли документ, или получить число документов, читать их не нужно: для этого есть [`exists`](../reference/query/reading.mdx#modelexists) и [`countDocuments`](../reference/query/reading.mdx#modelcountdocuments).

## Частые ошибки

### `JSON.stringify` падает на `bigint`

Вы прочитали счета через `.lean()` и отдаёте их клиенту:

```ts twoslash
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
const rows = await Accounts.find().lean();
JSON.stringify(rows); // [!code error]
// TypeError: JSON.stringify cannot serialize BigInt.
```

В lean-виде 64-битные числа остаются `bigint`, а `JSON.stringify` их не умеет. Для ответа клиенту используйте `.plain()`: баланс станет строкой.

### Метки превратились в `{}`

```ts twoslash
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;

@Schema({ collection: "accounts" })

  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---

JSON.stringify(account); // [!code warning]
// → {"_id":"…","title":"Main","balance":"9007199254741093","tags":["salary","vip"],"owner":"…","labels":{}}
```

plain-вид — это данные JavaScript, а не JSON. `Map` в нём остаётся `Map`, а `JSON.stringify` превращает любую `Map` в пустой объект без ошибки. Если в модели есть `Map` и вы сериализуете результат сами, сериализуйте документ: `JSON.stringify(document)` вызывает [`$toJSON()`](../reference/documents/document-api.mdx#tojson), и `Map` становится объектом.

```ts twoslash
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
```

### `.mask()` не компилируется

```ts twoslash
// @errors: 2684
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;

@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
Accounts.find().mask({ title: "mask" });
```

Текст ошибки объясняет причину: `mask() masks rows: call .lean() or .plain() first — a hydrated document with masked values could be saved`. [Маски](./response-masks.mdx) скрывают часть значения в ответе, например оставляют от номера карты последние четыре цифры. Документ с замаскированными значениями можно было бы случайно сохранить, и маска записалась бы в базу вместо настоящих данных. Поэтому [`.mask()`](../reference/query/masks.mdx#mask) работает только с `.plain()` и `.lean()`.

### Баланс пришёл числом, а не строкой

Счёт `Imported` попал в коллекцию из старой системы, и импорт записал баланс обычным числом, а не 64-битным целым. Модель читает документ как есть: в `.plain()` баланс приходит числом `500`, хотя тип обещает строку, и код клиента, который ждёт строку, ломается без всякой ошибки на сервере. По умолчанию Typemo не сверяет прочитанные документы со схемой: всё, что записала модель, уже проверено при записи. Чтобы найти такой документ, включите строгое чтение вызовом [`.validateReads()`](../reference/query/options.mdx#validatereads):

```ts twoslash
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
try {
  await Accounts.findOne({ title: "Imported" }).validateReads().plain();
} catch (error) {
  if (error instanceof CastError) console.log(error.message);
}
// → Cast to Long failed at path "balance" for 500 (number): the stored value does not match the schema of Account (a document read from the database, checked by validateReads) [type]
```

Исправьте данные миграцией, а чтобы такие документы находились сразу, включите проверку для всего клиента опцией [`validateReads: "development"`](../reference/connection/typemo-client.mdx#validatereads): в разработке и тестах каждое чтение сверяется со схемой, а в продакшене проверка не тратит время.

## Полный пример

Сервис счетов, в котором собраны сценарии страницы. Код читателя, которого нет в Typemo, помечен `__…__`.

```ts twoslash title="accounts/accounts.service.ts"
// @filename: db.ts
import { Entity, type Hidden, Prop, type Ref, Schema, TypemoClient, Types } from "@venloc/typemo";
@Schema({ collection: "customers" })
export class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
export const Accounts = client.db().model(Account);
// @filename: accounts.service.ts
// ---cut---
import { CastError, DocumentNotFoundError } from "@venloc/typemo";
import { Accounts } from "./db";

// код читателя: ошибки на границе приложения
class __NotFound__ extends Error {}
class __BadRequest__ extends Error {}

// список для страницы
export const listAccounts = () =>
  Accounts.find().sort({ title: 1 }).limit(20).select({ title: 1, balance: 1 }).plain();

// один счёт вместе с владельцем
export const getAccount = async (idFromUrl: string) => {
  try {
    return await Accounts.findById(idFromUrl)
      .populate({ path: "owner", select: { name: 1, email: 1 } })
      .orFail()
      .plain();
  } catch (error) {
    if (error instanceof DocumentNotFoundError) throw new __NotFound__("account not found");
    if (error instanceof CastError) throw new __BadRequest__("the id is malformed");
    throw error;
  }
};

// переименовать и вернуть обновлённый счёт
export const renameAccount = (idFromUrl: string, title: string) =>
  Accounts.findByIdAndUpdate(idFromUrl, { $set: { title } }, { returnDocument: "after" })
    .orFail()
    .plain();

// пополнить: сумма приходит строкой
export const deposit = (idFromUrl: string, amount: `${bigint}`) =>
  Accounts.findByIdAndUpdate(idFromUrl, { $inc: { balance: amount } }, { returnDocument: "after" })
    .orFail()
    .plain();

// сумма по всем счетам клиента
export const totalBalance = async (ownerId: string) => {
  const rows = await Accounts.find({ owner: ownerId }).select({ balance: 1 }).lean();
  return rows.reduce((sum, row) => sum + row.balance, 0n).toString();
};
```

<Callout type="migration">

[`.lean()`](../reference/query/reading.mdx#lean) работает так же, как в Mongoose, но его тип учитывает `select` и `populate`: невыбранных полей в типе нет. `.plain()` в Mongoose нет: там для ответа обычно читают документ и вызывают `toJSON()`. `toObject()` и `toJSON()` в Typemo называются [`$toObject()`](../reference/documents/document-api.mdx#toobject) и [`$toJSON()`](../reference/documents/document-api.mdx#tojson). Скрытое поле убирается из plain- и JSON-вида, даже если его загрузили явно, и исчезает из типа. Строку вместо `ObjectId` принимают и `findById`, и фильтры, и обновления: приведение вручную не нужно.

</Callout>
