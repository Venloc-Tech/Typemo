Прочитанные данные Typemo отдаёт в одном из трёх видов. **Документ** можно изменить и сохранить. **Результат `.lean()`** — это данные ровно в том виде, в каком их отдал драйвер. **Результат `.plain()`** — обычные объекты, готовые для ответа клиенту. Нужный вид вы выбираете одним вызовом в конце запроса.

Откуда такая разница? MongoDB хранит данные в формате BSON, а в нём есть типы, которых нет в JSON. Это идентификатор `ObjectId`, 64-битные целые числа, точные десятичные `Decimal128`. Внутри приложения с ними работать удобно, а вот клиенту их напрямую не отдашь. Если вы впервые работаете с MongoDB, загляните сначала в [Типы данных MongoDB](../concepts/bson-types.mdx), там это разобрано подробно.

## Что понадобится [#prerequisites]

Клиент из руководства [Подключиться к базе](../connection/connect.mdx). Примеры написаны обычными функциями сервиса, без веб-фреймворка, и тот же код вызывается из обработчика любого фреймворка. Границу приложения вроде ответа 404 изображают ваши классы `__NotFound__` и `__BadRequest__`.

В коллекциях лежит клиент Alice и два её счёта.

- `Main` — баланс `9007199254741093`, теги `salary` и `vip`, метка `tier` со значением `gold`.
- `Savings` — баланс `500`, без тегов.

Результаты в комментариях `// →` получены на этих данных, идентификаторы сокращены до `"…"`.

## Быстрый путь [#quick-start]

Начнём с модели банковского счёта, в ней два поля.

```ts twoslash title="models/account.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => BigInt, { required: true })
  balance!: bigint;
}
```

[`Entity`](../reference/schemas/base-classes.mdx#entity) добавляет модели поле `_id` типа `ObjectId`. Это идентификатор, который MongoDB присваивает каждому документу. `BigInt` значит, что баланс хранится в базе 64-битным целым, а в коде это `bigint`.

Вот три способа прочитать один и тот же счёт. Наведите курсор на имена переменных, чтобы увидеть их типы.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
// ---cut---
// 1. Документ: чтобы изменить и сохранить
const account = await Accounts.findOne({ title: "Main" }).orFail();

// 2. plain: чтобы отдать клиенту
const forClient = await Accounts.findOne({ title: "Main" }).plain().orFail();
//    ^?
// → { _id: "…", title: "Main", balance: "9007199254741093" }

// 3. lean: чтобы посчитать внутри приложения
const raw = await Accounts.findOne({ title: "Main" }).lean().orFail();
//    ^?
// → { _id: ObjectId("…"), title: "Main", balance: 9007199254741093n }
```

У `forClient` поля `_id` и `balance` — строки, а у `raw` — `ObjectId` и `bigint`. Типы выводятся из модели и из вызова в конце запроса, так что компилятор всегда знает, с каким видом данных вы работаете.

[`.orFail()`](../reference/query/reading.mdx#or-fail) бросает ошибку, если ничего не нашлось. Без него [`findOne`](../reference/query/reading.mdx#model.find-one) может вернуть `null`, и TypeScript заставит вас обработать этот случай.

Ниже разберём каждый вид на настоящих задачах.

## Изменить запись [#update-record]

Если в конце запроса нет [`.plain()`](../reference/query/reading.mdx#plain) или [`.lean()`](../reference/query/reading.mdx#lean), вы получаете документ. Он выглядит как экземпляр вашего класса `Account`, но умеет больше. Он помнит, какие поля вы изменили, и умеет сохранить себя в базу.

```ts twoslash
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
const account = await Accounts.findOne({ title: "Main" }).orFail();

account.title = "Main account";

console.log(account.$isModified("title"), account.$isModified("balance"));
// → true false

await account.$save();
```

[`$save()`](../reference/documents/document-api.mdx#save) не перезаписывает документ в базе целиком. Typemo отправляет только изменённые поля, здесь это `{ $set: { title: "Main account" } }`. Если другой запрос в это же время поменял `balance` того же счёта, его изменение не пропадёт.

Методы документа начинаются с `$` — [`$set()`](../reference/documents/document-api.mdx#set), [`$isModified()`](../reference/documents/document-api.mdx#is-modified), [`$toPlain()`](../reference/documents/document-api.mdx#to-plain). Так их легко отличить от полей вашей модели.

Массивы и `Map` внутри документа тоже следят за изменениями. Добавим счёту теги.

```ts twoslash title="models/account.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => BigInt, { required: true })
  balance!: bigint;

  @Prop(() => [String]) // [!code ++]
  tags!: string[]; // [!code ++]
}
```

```ts twoslash
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
const account = await Accounts.findOne({ title: "Savings" }).orFail();

account.tags.push("gold");
await account.$save();
// в базу уйдёт { $push: { tags: { $each: ["gold"] } } }, а не весь массив
```

Как массивы превращаются в операции MongoDB, рассказано в руководстве [Массивы и Map в документе](../documents/typed-collections.mdx).

Документ обходится дороже двух других видов. Для каждой строки Typemo строит объект и коллекции и запоминает исходные значения. Если менять вы ничего не собираетесь, эта работа лишняя.

## Отдать данные клиенту [#send-to-client]

Клиент запрашивает счёт через API. Документ отдавать нельзя, у него есть методы и служебное состояние. Результат `.lean()` тоже не подходит. `JSON.stringify` не умеет сериализовать `bigint` и бросает ошибку, а `ObjectId` клиенту ни о чём не говорит.

Для этого есть [`.plain()`](../reference/query/reading.mdx#plain). Он читает данные из базы и переводит каждое значение в обычный вид JavaScript.

```ts twoslash
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
const account = await Accounts.findOne({ title: "Main" }).plain().orFail();
// → {
//     _id: "…",
//     title: "Main",
//     balance: "9007199254741093",
//     tags: ["salary", "vip"],
//     owner: "…",
//     labels: Map(1) { "tier" => "gold" },
//   }
```

`_id` стал строкой. Это шестнадцатеричная запись `ObjectId`, которую клиент может показать, передать в адресе и прислать обратно.

`balance` тоже стал строкой, и это важно. Обычный `number` в JavaScript хранит целые точно только до 2⁵³. Баланс `9007199254741093` больше этой границы. Отправь его числом, и клиент получил бы `9007199254741092` без всякой ошибки. Поэтому в результате `.plain()` 64-битные числа всегда десятичные строки.

Документ при этом не создаётся, так что `.plain()` почти так же быстр, как `.lean()`. Как каждый тип MongoDB выглядит в результате `.plain()`, показано в справочнике [Формы значений](../reference/values/value-forms.mdx).

### Список счетов [#account-list]

Самый частый случай — список для страницы приложения. Он живёт в функции сервиса, которую вызывает обработчик запроса.

```ts twoslash title="accounts/accounts.service.ts"
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
export const listAccounts = () =>
  Accounts.find()
    .sort({ title: 1 })
    .limit(20)
    .select({ title: 1, balance: 1 })
    .plain();

console.log(await listAccounts());
// → [
//     { _id: "…", title: "Main", balance: "9007199254741093" },
//     { _id: "…", title: "Savings", balance: "500" },
//   ]
```

[`.select({ title: 1, balance: 1 })`](../reference/query/reading.mdx#select) просит базу вернуть только эти поля. Компилятор об этом знает. У элементов результата нет поля `tags`, и обратиться к нему не выйдет. `_id` MongoDB возвращает всегда, пока вы явно не исключите его через `_id: 0`. Подробнее о выборе полей рассказано в руководстве [Выбор полей и тип результата](./projections.mdx), о сортировке и ограничении списка — в руководстве [Сортировка и страницы](./sorting-and-pages.mdx).

Заметьте, что `listAccounts` не объявлена `async` и возвращает запрос, а не результат. Строитель запроса сам ведёт себя как `Promise`. Вызывающий код пишет `await listAccounts()`, а тип возврата можно объявить как `Promise<…>` без обёрток. В базу запрос уходит только на `await`.

### Один счёт по id из URL [#account-by-id]

Клиент запрашивает `GET /accounts/6abcfa30531a3d0a555e2f5b`. Id приходит строкой, и [`findById`](../reference/query/reading.mdx#model.find-by-id) принимает её как есть. Приводить строку к `ObjectId` самому не нужно.

```ts twoslash title="accounts/accounts.service.ts"
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
export const getAccount = async (idFromUrl: string) => {
  try {
    return await Accounts.findById(idFromUrl).orFail().plain();
  } catch (error) {
    if (error instanceof DocumentNotFoundError) throw new __NotFound__("account not found");
    if (error instanceof CastError) throw new __BadRequest__("the id is malformed");
    throw error;
  }
};
```

Ошибок здесь две, и обе про ввод клиента, а не про сбой сервера. Если счёта с таким id нет, `.orFail()` бросит [`DocumentNotFoundError`](../reference/errors/query-errors.mdx#document-not-found-error), и функция превратит её в «не найдено».

```text
DocumentNotFoundError: Account.findById: no document matched the filter (orFail)
```

Если строка не похожа на идентификатор, запрос даже не уйдёт в базу. Typemo сам проверит формат и бросит [`CastError`](../reference/errors/data-errors.mdx#cast-error).

```text
CastError: Cast to ObjectId failed at path "_id" for "abc" (string): not a 24-character hex string [format]
```

Свой разбор строки перед вызовом не нужен. `CastError` — уже готовый сигнал «id неверный», и функция выше отвечает на него ошибкой 400.

<Callout type="tip">

Чтобы не повторять `try/catch` в каждой функции, переводите `DocumentNotFoundError` и `CastError` в ответы один раз — там, где ваше приложение превращает ошибки в ответы.

</Callout>

### Вернуть запись после изменения [#return-updated]

Клиент переименовывает счёт и ждёт в ответ обновлённую запись. Сделать это можно двумя способами, и оба вернут одинаковый результат `.plain()`.

Первый способ — изменить запись одним запросом к базе через [`findByIdAndUpdate`](../reference/writes/writes.mdx#find-by-id-and-update).

```ts twoslash title="accounts/accounts.service.ts"
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
export const renameAccount = (idFromUrl: string, title: string) =>
  Accounts.findByIdAndUpdate(idFromUrl, { $set: { title } }, { returnDocument: "after" })
    .orFail()
    .plain();
```

`returnDocument: "after"` просит вернуть запись после изменения. Без этой опции придёт состояние до изменения.

Второй способ — прочитать документ, изменить его и получить обычный объект через [`$toPlain()`](../reference/documents/document-api.mdx#to-plain).

```ts twoslash title="accounts/accounts.service.ts"
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
export const renameAccountWithChecks = async (idFromUrl: string, title: string) => {
  const account = await Accounts.findById(idFromUrl).orFail();
  account.title = title;
  await account.$save();
  return account.$toPlain();
};
```

`$toPlain()` у документа даёт то же, что `.plain()` у запроса, только берёт данные из уже загруженного документа, а не из базы. Второй способ нужен, когда перед сохранением есть логика — проверки, вычисления, [хуки](../hooks/document-hooks.mdx). Если логики нет, первый проще и обходится одним обращением к базе вместо двух.

### Принять значения от клиента обратно [#accept-client-values]

Клиент получил `balance` строкой и может прислать его обратно. В [`create`](../reference/writes/writes.mdx#create), в обновлениях и в фильтрах переводить строку в `bigint` не нужно. Typemo принимает строку с целым числом везде, где ждёт 64-битное число. Идентификатор тоже можно передать строкой.

```ts twoslash
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
const alice = await Customers.findOne({ email: "alice@example.com" }).orFail();

await Accounts.create({ title: "Bonus", balance: "9007199254740993", tags: [], owner: alice._id });

await Accounts.updateOne({ title: "Bonus" }, { $set: { balance: "500" } });

const rich = await Accounts.find({ balance: { $gte: "500" } }).plain();
console.log(rich.length);
// → 3
```

После создания `Bonus` в коллекции три счёта с балансом не меньше 500 — `Main`, `Savings` и `Bonus`.

То же работает в операторах, которые считают, — [`$inc`](../reference/writes/update-operators.mdx#inc), `$mul`, `$min` и `$max`. Так что сумму пополнения, пришедшую строкой, можно передать как есть.

```ts twoslash title="accounts/accounts.service.ts"
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
```

Строка должна быть записана строго, например `"500"`, `"-42"` или `"9223372036854775807"`. Всё, что можно прочитать двояко, Typemo отклоняет с `CastError`, а не округляет.

```text
CastError: Cast to Long failed at path "$inc.balance" for "1.5" (string): a string must be a decimal integer (no sign +, leading zeros, -0, spaces, exponent or prefix) [format]
```

Так же отклоняются `"1e3"`, `"+1"`, `"01"`, `" 1"`, `"0x10"`, пустая строка и числа за пределами 64 бит. Иначе сумма, набранная клиентом с опечаткой, тихо превратилась бы в другую.

### Не отдать секретные поля [#hide-secrets]

Добавим модель клиента банка с хешем пароля.


Опция [`hidden`](../reference/schemas/prop.mdx#hidden) вместе с типом `Hidden<string>` делает поле **скрытым**. Такое поле не читается из базы, пока его не попросят явно, и не попадает в результат `.plain()`, даже если его прочитали.

При входе в систему хеш нужен, чтобы проверить пароль. Попросите его через `select`, поставив `+` перед именем поля.

```ts twoslash title="auth/auth.service.ts"

@Schema({ collection: "accounts" })

  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;

}

    .select({ "+passwordHash": true })
```

Хеш прочитан и проверен, но в ответ не попал. И это проверяется не только во время работы. В типе результата `$toPlain()` поля `passwordHash` нет, так что обращение к нему не скомпилируется.

### Выгрузить много строк [#export-rows]

Если строк тысячи, например для выгрузки в другую систему, не грузите их в память разом. **Курсор** отдаёт строки по одной, по мере чтения из базы. Его возвращает [`.cursor()`](../reference/query/reading.mdx#cursor).

## Посчитать что-то внутри приложения [#compute-in-app]

Для расчётов результат `.plain()` неудобен. Сложить строки `"9007199254741093"` и `"500"` как числа не выйдет. Здесь нужен [`.lean()`](../reference/query/reading.mdx#lean). Он возвращает данные ровно такими, какими их отдала база, без перевода.

Посчитаем, сколько денег у клиента на всех счетах. К `Main` и `Savings` добавился `Bonus` из прошлого раздела, так что счетов три.


`row.balance` здесь `bigint`, и сумма точная, даже если она больше 2⁵³. Обратите внимание, что владелец передан в фильтр строкой. `ObjectId` из строки Typemo соберёт сам.

## Найти список и считать пустой результат ошибкой [#empty-list-as-error]

Обычно пустой список — нормальный ответ, у клиента просто пока нет счетов. Но иногда отсутствие данных — это сбой, например не загрузился справочник. Тогда добавьте `.orFail()` и к `find`. Пустой список превратится в `DocumentNotFoundError`, а непустой вернётся как обычно.

Сама MongoDB в такой ситуации вернула бы пустой массив, а ошибку вы включаете сами, когда пустой результат недопустим. С курсором это не работает. [`.cursor()`](../reference/query/reading.mdx#cursor) заранее не знает, что документов не будет, и на пустой выборке просто завершается без единой строки.

## Как выбрать [#how-to-choose]

Спросите себя, что будет с данными после чтения.

- **Вы будете их менять и сохранять** — берите документ. Только он следит за изменениями и умеет [`$save()`](../reference/documents/document-api.mdx#save).
- **Данные уйдут за пределы приложения** — в HTTP-ответ, очередь сообщений, кеш или лог. Берите [`.plain()`](../reference/query/reading.mdx#plain). Он переводит BSON-типы в строки, не теряет точность больших чисел и не выпускает скрытые поля.
- **Данные нужны для расчёта внутри приложения** — сложить, сравнить, передать в другой запрос. Берите [`.lean()`](../reference/query/reading.mdx#lean), он самый быстрый и сохраняет точные типы.

Бывает, что вы прочитали документ, изменили его и теперь его нужно вернуть клиенту. Второй раз читать из базы не нужно, вызовите у документа [`$toPlain()`](../reference/documents/document-api.mdx#to-plain).

## Когда что не нужно [#when-not-to-use]

Документ не нужен, если вы только читаете. Для списков, отчётов и ответов API он делает лишнюю работу, так что берите [`.plain()`](../reference/query/reading.mdx#plain) или [`.lean()`](../reference/query/reading.mdx#lean).

`.plain()` не нужен, если данные остаются внутри приложения. Строки вместо чисел только помешают расчётам, и здесь подойдёт [`.lean()`](../reference/query/reading.mdx#lean).

`.lean()` не нужен, если данные уходят клиенту. Переводить `bigint` и `ObjectId` придётся самим, а ошибиться в этом легко. Для ответа берите [`.plain()`](../reference/query/reading.mdx#plain).

Если нужно только узнать, есть ли документ, или посчитать документы, читать их не нужно. Для этого есть [`exists`](../reference/query/reading.mdx#model.exists) и [`countDocuments`](../reference/query/reading.mdx#model.count-documents).


Результат `.plain()` — это данные JavaScript, а не JSON. `Map` в нём остаётся `Map`, а `JSON.stringify` молча превращает любую `Map` в пустой объект. Если в модели есть `Map` и вы сериализуете результат сами, сериализуйте документ. `JSON.stringify(document)` вызывает [`$toJSON()`](../reference/documents/document-api.mdx#to-json), и `Map` становится объектом.

```ts twoslash
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
const account = await Accounts.findOne({ title: "Main" }).orFail();
JSON.stringify(account);
// → {"_id":"…","title":"Main","balance":"9007199254741093","tags":["salary","vip"],"owner":"…","labels":{"tier":"gold"}}
```

Если документ вам не нужен, превратите `Map` в объект сами — `Object.fromEntries(account.labels)`.

**`.mask()` не компилируется.**

```ts twoslash
// @errors: 2684
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");

declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
Accounts.find().mask({ title: "mask" });
```

Причину объясняет сам текст ошибки — `mask() masks rows: call .lean() or .plain() first — a hydrated document with masked values could be saved`. [Маски](./response-masks.mdx) прячут часть значения в ответе, например оставляют от номера карты последние четыре цифры. Документ с замаскированными значениями можно было бы случайно сохранить, и маска легла бы в базу вместо настоящих данных. Поэтому [`.mask()`](../reference/query/masks.mdx#mask) работает только с `.plain()` и `.lean()`.

**У результата `.plain()` нет `$save`.**

```ts twoslash
// @errors: 2339
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");

```

Результаты `.plain()` и `.lean()` — это данные, а не документ. Чтобы изменить запись, прочитайте её без `.plain()` или возьмите [`updateOne`](../reference/writes/writes.mdx#update-one) и [`findByIdAndUpdate`](../reference/writes/writes.mdx#find-by-id-and-update).

**Баланс пришёл числом, а не строкой.** Счёт `Imported` попал в коллекцию из старой системы, и импорт записал баланс обычным числом, а не 64-битным целым. Модель читает документ как есть. В `.plain()` баланс приходит числом `500`, хотя тип обещает строку, и клиентский код, который ждёт строку, ломается без всякой ошибки на сервере.

По умолчанию Typemo не сверяет прочитанные документы со схемой, ведь всё, что записала модель, проверено при записи. Чтобы найти такой документ, включите строгое чтение вызовом [`.validateReads()`](../reference/query/options.mdx#validate-reads).

```ts twoslash
import { CastError, DocumentNotFoundError, Entity, type Hidden, Prop, type Ref, Schema, Spec, Types, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
  @Prop(() => Spec.map(String)) labels?: Map<string, string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Customers = client.db().model(Customer);
declare class __NotFound__ extends Error {}
declare class __BadRequest__ extends Error {}
// ---cut---
try {
  await Accounts.findOne({ title: "Imported" }).validateReads().plain();
} catch (error) {
  if (error instanceof CastError) console.log(error.message);
}
// → Cast to Long failed at path "balance" for 500 (number): the stored value does not match the schema of Account (a document read from the database, checked by validateReads) [type]
```

Исправьте данные миграцией. А чтобы такие документы находились сразу, включите проверку для всего клиента опцией [`validateReads: "development"`](../reference/connection/typemo-client.mdx#validate-reads). Тогда в разработке и тестах каждое чтение сверяется со схемой, а в продакшене проверка не тратит время.

## Полный пример [#full-example]

Сервис счетов со всеми сценариями страницы. Код, которого нет в Typemo и который пишете вы, помечен `__…__`.

```ts twoslash title="accounts/accounts.service.ts"
// @filename: db.ts
import { Entity, type Hidden, Prop, type Ref, Schema, TypemoClient, Types } from "@venloc/typemo";
@Schema({ collection: "customers" })
export class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => Types.ObjectId, { ref: () => Customer, required: true }) owner!: Ref<Customer>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
export const Accounts = client.db().model(Account);
// @filename: accounts.service.ts
// ---cut---
import { CastError, DocumentNotFoundError } from "@venloc/typemo";
import { Accounts } from "./db";

// код читателя: ошибки на границе приложения
class __NotFound__ extends Error {}
class __BadRequest__ extends Error {}

// список для страницы
export const listAccounts = () =>
  Accounts.find().sort({ title: 1 }).limit(20).select({ title: 1, balance: 1 }).plain();

// один счёт вместе с владельцем
export const getAccount = async (idFromUrl: string) => {
  try {
    return await Accounts.findById(idFromUrl)
      .populate({ path: "owner", select: { name: 1, email: 1 } })
      .orFail()
      .plain();
  } catch (error) {
    if (error instanceof DocumentNotFoundError) throw new __NotFound__("account not found");
    if (error instanceof CastError) throw new __BadRequest__("the id is malformed");
    throw error;
  }
};

// переименовать и вернуть обновлённый счёт
export const renameAccount = (idFromUrl: string, title: string) =>
  Accounts.findByIdAndUpdate(idFromUrl, { $set: { title } }, { returnDocument: "after" })
    .orFail()
    .plain();

// пополнить: сумма приходит строкой
export const deposit = (idFromUrl: string, amount: `${bigint}`) =>
  Accounts.findByIdAndUpdate(idFromUrl, { $inc: { balance: amount } }, { returnDocument: "after" })
    .orFail()
    .plain();

// сумма по всем счетам клиента
export const totalBalance = async (ownerId: string) => {
  const rows = await Accounts.find({ owner: ownerId }).select({ balance: 1 }).lean();
  return rows.reduce((sum, row) => sum + row.balance, 0n).toString();
};
```

<Callout type="migration">

[`.lean()`](../reference/query/reading.mdx#lean) работает так же, как в Mongoose, но его тип учитывает `select` и `populate`, и невыбранных полей в типе нет. `.plain()` в Mongoose нет. Там для ответа обычно читают документ и вызывают `toJSON()`. `toObject()` и `toJSON()` в Typemo называются [`$toObject()`](../reference/documents/document-api.mdx#to-object) и [`$toJSON()`](../reference/documents/document-api.mdx#to-json).

Скрытое поле убирается из результата `.plain()` и из JSON, даже если его загрузили явно, и пропадает из типа. Строку вместо `ObjectId` принимают и `findById`, и фильтры, и обновления, так что приводить вручную ничего не нужно.

</Callout>
