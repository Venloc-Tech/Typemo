Обычный `await` сначала собирает **все** найденные документы в массив и только потом отдаёт его вам. Для списка на странице это нормально. А для выгрузки в другую систему, миграции или ночной пересборки отчёта плохо — документов десятки тысяч, и память кончится раньше, чем вы начнёте их обрабатывать.

Выход — **курсор**. Он отдаёт документы по одному, по мере чтения из базы, и держит в памяти только текущую порцию. Курсор возвращает [`.cursor()`](../reference/query/reading.mdx#cursor).

Если вы впервые работаете с MongoDB, запомните одно. База отдаёт результат порциями, и курсор — ваша сторона такого чтения. Пока он открыт, на сервере тоже заняты ресурсы, поэтому курсор нужно дочитать до конца или закрыть.

## Что понадобится [#prerequisites]

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель заказа. Код, которого нет в Typemo и который пишете вы, помечен `__…__`.

```ts twoslash title="orders/order.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "orders" })
export class Order extends Entity {
  @Prop(() => Number, { required: true })
  number!: number;

  @Prop(() => String, { required: true })
  status!: string;
}
```

В коллекции пять заказов с номерами от 1 до 5. Нечётные оплачены (`paid`), чётные новые (`new`). Во всех примерах заказы читаются по возрастанию номера, так что порядок в результатах понятен. Результаты в комментариях `// →` получены на этих данных.

## Быстрый путь [#quick-start]

Пройдите курсор циклом `for await`. Каждая строка приходит обычным объектом, как из `.plain()`, а в памяти живёт только текущая порция.

```ts twoslash
import { EachAsyncError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.db().model(Order);
declare const __sendToWarehouse__: (order: { number: number }) => Promise<void>;
declare const __insertMany__: (orders: { number: number }[]) => Promise<void>;
// ---cut---
for await (const order of Orders.find().sort({ number: 1 }).plain().cursor()) {
  console.log(order.number);
}
// → 1
//   2
//   3
//   4
//   5
```

Ниже разберём способы обработки на настоящих задачах. Методы курсора описаны в справочнике [Курсор](../reference/query/cursor.mdx).

## Выгрузить все документы [#export-all]

Чаще всего нужно прочитать всё и отправить в другую систему. Запрос строится как обычно, только в конце вместо `await` стоит [`.cursor()`](../reference/query/reading.mdx#cursor). Вид строк выбирает та же цепочка, что и всегда. Без `.plain()` и `.lean()` это документы, с ними — данные.

```ts twoslash title="export/export-orders.ts"
import { EachAsyncError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.db().model(Order);
declare const __sendToWarehouse__: (order: { number: number }) => Promise<void>;
declare const __insertMany__: (orders: { number: number }[]) => Promise<void>;
// ---cut---
export const exportOrders = async () => {
  for await (const order of Orders.find().sort({ number: 1 }).plain().cursor()) {
    //             ^?
    await __sendToWarehouse__(order);
  }
};
```

Сортировку задавайте всегда. Без неё порядок документов не определён, и выгрузку не повторить. Для больших выгрузок удобнее всего `_id`, он уникален и есть в каждом документе.

[`.skip`](../reference/query/reading.mdx#skip), [`.limit`](../reference/query/reading.mdx#limit) и [`.batchSize`](../reference/query/options.mdx#batch-size) работают и с курсором. Последний задаёт, сколько документов база отдаёт за один обмен. Размер порции должен быть целым положительным числом. `batchSize(0)` база поняла бы как «размер по умолчанию», поэтому Typemo отвечает `QueryError` (`batchSize must be a positive integer, got 0 (number)`, с пояснением про ноль). Порция по умолчанию получится, если просто не вызывать метод.

Цикл закрывает курсор сам — и когда дочитал, и когда вы вышли раньше через `break` или ошибку. После раннего выхода этот курсор больше не читается, иначе будет [`QueryError`](../reference/errors/query-errors.mdx#query-error).

```text
QueryError: the cursor is closed (close() or a left for-await); open a new one
```

Так задумано. Чтение курсора, который вы уже закрыли, значило бы, что код читает не те данные, что вы думаете, а тихий пустой результат спрятал бы ошибку. Чтобы прочитать данные снова, откройте новый курсор.

И перебирать через `for await` нужно именно курсор, а не сам запрос. Цикл по запросу вроде `for await (const order of Orders.find())` бросит `QueryError` с подсказкой, как надо.

```text
QueryError: find(): a query is not iterable with "for await"; iterate its cursor instead: for await (const doc of Model.find(filter).cursor())
```

## Обработать документы с параллельностью [#process-in-parallel]

Если на каждый документ нужно ждать сеть, например отправку в другую систему, цикл `for await` простаивает. Следующий документ ждёт, пока закончится предыдущий. [`.eachAsync`](../reference/query/cursor.mdx#each-async) вызывает вашу функцию для каждого документа и умеет держать несколько вызовов одновременно.

```ts twoslash
import { EachAsyncError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.db().model(Order);
declare const __sendToWarehouse__: (order: { number: number }) => Promise<void>;
declare const __insertMany__: (orders: { number: number }[]) => Promise<void>;
// ---cut---
await Orders.find().sort({ number: 1 }).plain().cursor().eachAsync(
  (order) => __sendToWarehouse__(order),
  { parallel: 3 },
);
```

С `parallel: 3` одновременно идёт не больше трёх вызовов. Читаются документы по-прежнему по одному, параллельно работает только ваша функция. Порядок завершения не гарантирован, заказ 3 может закончиться раньше заказа 2. Если порядок важен, оставьте `parallel` равным единице, это значение по умолчанию. В конце `.eachAsync` сам закрывает курсор, даже если функция бросила ошибку.

## Обработать документы порциями [#process-in-batches]

Бывает, что получателю удобнее принимать пачками, например при вставке в другую базу. Тогда опция `batchSize` собирает документы в массивы. Функция получает массив вместо одного документа и номер порции вместо номера документа.

```ts twoslash
import { EachAsyncError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.db().model(Order);
declare const __sendToWarehouse__: (order: { number: number }) => Promise<void>;
declare const __insertMany__: (orders: { number: number }[]) => Promise<void>;
// ---cut---
await Orders.find().sort({ number: 1 }).plain().cursor().eachAsync(
  async (orders, batchIndex) => {
    console.log(batchIndex, orders.map((order) => order.number));
    await __insertMany__(orders);
  },
  { batchSize: 2 },
);
// → 0 [1, 2]
//   1 [3, 4]
//   2 [5]
```

Последняя порция короче остальных, в примере в ней один заказ.

Не путайте эту опцию с [`.batchSize`](../reference/query/options.mdx#batch-size) запроса. Тот управляет тем, сколько документов база отдаёт за один обмен по сети. А `batchSize` у `.eachAsync` — тем, сколько документов ваша функция получает за вызов. Порции и параллельность сочетаются. `{ batchSize: 100, parallel: 4 }` обрабатывает по 100 документов, четыре порции одновременно.

## Преобразовать строки на лету [#transform-rows]

[`.map`](../reference/query/cursor.mdx#map) возвращает новый курсор, строки которого получены вашей функцией. Так документ можно привести к нужной форме до того, как его прочитает остальной код. А при необходимости собрать всё в массив поможет [`.toArray`](../reference/query/cursor.mdx#to-array).

```ts twoslash
import { EachAsyncError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.db().model(Order);
declare const __sendToWarehouse__: (order: { number: number }) => Promise<void>;
declare const __insertMany__: (orders: { number: number }[]) => Promise<void>;
// ---cut---
const numbers = Orders.find().sort({ number: 1 }).plain().cursor().map((order) => order.number * 10);
console.log(await numbers.toArray());
// → [10, 20, 30, 40, 50]
```

Исходный курсор и результат `.map` читают один и тот же поток. Строка, прочитанная через один из них, второму уже не достанется. Если нужны оба вида строк, преобразуйте строку внутри одного цикла, а не заводите два курсора.

## Изменять документы во время выгрузки [#update-while-exporting]

Если курсор читает документы, а не результат `.lean()`, каждую строку можно изменить и сохранить. Так устроены миграции — пройти по всем заказам с нужным статусом и поменять его.

```ts twoslash title="scripts/mark-sent.ts"
import { EachAsyncError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.db().model(Order);
declare const __sendToWarehouse__: (order: { number: number }) => Promise<void>;
declare const __insertMany__: (orders: { number: number }[]) => Promise<void>;
// ---cut---
let sent = 0;
for await (const order of Orders.find({ status: "new" }).sort({ number: 1 }).cursor()) {
  order.status = "sent";
  await order.$save();
  sent++;
}
console.log(sent);
// → 2
```

Каждая строка курсора — полноценный документ, и [`$save()`](../reference/documents/document-api.mdx#save) отправит в базу только изменённое поле. Но для больших объёмов один [`updateMany`](../reference/writes/writes.mdx#update-many) с тем же фильтром работает на порядки быстрее миллиона сохранений по одному. Берите курсор, только когда для каждого документа нужна своя логика.

## Возобновить выгрузку после сбоя [#resume-export]

Выгрузка, которая идёт часами, может упасть на середине — из-за сети, перезапуска процесса или ошибки получателя. Чтобы не начинать сначала, запоминайте `_id` последнего обработанного документа и начинайте следующий запуск с него. Для этого нужна сортировка по `_id`, только она делает «после этого документа» однозначным.

```ts twoslash title="export/export-orders.ts"
import { EachAsyncError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.db().model(Order);
declare const __sendToWarehouse__: (order: { number: number }) => Promise<void>;
declare const __insertMany__: (orders: { number: number }[]) => Promise<void>;
// ---cut---
import type { Filter } from "@venloc/typemo";

export const exportOrdersAfter = async (lastId: string | null) => {
  const filter: Filter<Order> = lastId === null ? {} : { _id: { $gt: lastId } };
  let last = lastId;

  for await (const order of Orders.find(filter).sort({ _id: 1 }).plain().cursor()) {
    await __sendToWarehouse__(order);
    last = order._id; // сохраните это значение там, где переживёт перезапуск
  }
  return last;
};
```

Строку вместо `ObjectId` фильтр принимает, как и везде, так что приводить идентификатор вручную не нужно. При следующем запуске передайте сохранённое значение, и выгрузка продолжится с первого необработанного документа.

Отправка должна быть **идемпотентной**. Если документ ушёл, а позицию сохранить не успели, при перезапуске он уйдёт ещё раз, и получатель должен спокойно принять дубль.

## Обработать ошибки в потоке [#stream-errors]

Ошибка внутри цикла `for await` прерывает цикл и закрывает курсор. Ошибка из функции в `.eachAsync` ведёт себя так же. Первая ошибка останавливает обработку, уже запущенные при `parallel` вызовы доработают, а сама ошибка выйдет наружу без обёртки.

```ts twoslash
import { EachAsyncError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.db().model(Order);
declare const __sendToWarehouse__: (order: { number: number }) => Promise<void>;
declare const __insertMany__: (orders: { number: number }[]) => Promise<void>;
// ---cut---
try {
  await Orders.find().sort({ number: 1 }).plain().cursor().eachAsync((order) => {
    if (order.number === 3) throw new Error("order 3 rejected");
  });
} catch (error) {
  console.log(String(error));
  // → "Error: order 3 rejected"
}
```

Заказы 4 и 5 так и не обработаны. Если нужно дойти до конца, несмотря на отдельные сбои, включите `continueOnError: true`. Тогда каждый документ получит свой вызов функции, а ошибки соберутся и в конце придут вместе как [`EachAsyncError`](../reference/query/cursor.mdx#each-async-error).

```ts twoslash
import { EachAsyncError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.db().model(Order);
declare const __sendToWarehouse__: (order: { number: number }) => Promise<void>;
declare const __insertMany__: (orders: { number: number }[]) => Promise<void>;
// ---cut---
try {
  await Orders.find().sort({ number: 1 }).plain().cursor().eachAsync(
    (order) => {
      if (order.number % 2 === 0) throw new Error(`order ${order.number} rejected`);
    },
    { continueOnError: true },
  );
} catch (error) {
  if (error instanceof EachAsyncError) {
    console.log(error.message);
    // → "eachAsync: 2 call(s) of the callback failed (continueOnError)"
    console.log(error.errors.map(String));
    // → ["Error: order 2 rejected", "Error: order 4 rejected"]
  }
}
```

Все ошибки функции лежат в поле `errors` в порядке документов, а первая доступна ещё и как `cause`. Режим выбирайте по цене сбоя. Если пропущенный документ делает всю выгрузку бессмысленной, оставьте режим по умолчанию. Если документы независимы, включите `continueOnError` и разберите список ошибок в конце.

## Как выбрать [#how-to-choose]

Спросите себя, **что нужно сделать с каждым документом**.

- **Прочитать по одному и что-то сделать** — берите `for await`. Это самый короткий и понятный вариант, и из него можно выйти через `break`.
- **Функция ждёт сеть, а порядок обработки не важен** — [`.eachAsync`](../reference/query/cursor.mdx#each-async) с `parallel`.
- **Получателю удобнее пачки** — добавьте `batchSize`.
- **Нужно преобразовать строки или собрать остаток в массив** — [`.map`](../reference/query/cursor.mdx#map) и [`.toArray`](../reference/query/cursor.mdx#to-array).
- **Нужно ручное управление**, например взять несколько первых документов и закрыть курсор, — [`.next`](../reference/query/cursor.mdx#next) и [`.close`](../reference/query/cursor.mdx#close).

## Когда это не нужно [#when-not-to-use]

Для списка на странице курсор не нужен. Там показывается ограниченное число записей, и хватит обычного `await` с [`.limit`](../reference/query/reading.mdx#limit). Для страниц, которые листает пользователь, есть [пагинация по ключу](./keyset-pagination.mdx) или [`.skip`](../reference/query/reading.mdx#skip).

Изменить или удалить документы по условию тоже можно без курсора. [`updateMany`](../reference/writes/writes.mdx#update-many) и [`deleteMany`](../reference/writes/writes.mdx#delete-many) сделают это одним запросом. А если нужны только числа по группам, суммы или количества, считайте их в базе через [агрегации](../aggregation/first-aggregation.mdx).

## Если что-то пошло не так [#troubleshooting]

**Курсор закрыт.** Вы вышли из цикла через `break`, а потом вызвали `.next()` на том же курсоре. К этому моменту он уже закрыт.

```ts twoslash
import { EachAsyncError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.db().model(Order);
declare const __sendToWarehouse__: (order: { number: number }) => Promise<void>;
declare const __insertMany__: (orders: { number: number }[]) => Promise<void>;
// ---cut---
const cursor = Orders.find().sort({ number: 1 }).plain().cursor();
for await (const order of cursor) {
  if (order.number === 2) break;
}
await cursor.next(); // [!code error]
// QueryError: the cursor is closed (close() or a left for-await); open a new one
```

Откройте новый курсор через `Orders.find().sort({ number: 1 }).plain().cursor()`. Закрытый курсор заново не открыть.

**Выгрузка съедает всю память.** Вы вызвали `await` вместо `.cursor()`, и все документы собрались в один массив. Для выгрузки замените его на `.cursor()` и обрабатывайте строки по одной.

```ts twoslash
import { EachAsyncError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.db().model(Order);
declare const __sendToWarehouse__: (order: { number: number }) => Promise<void>;
declare const __insertMany__: (orders: { number: number }[]) => Promise<void>;
// ---cut---
// неправильно: весь список в памяти
const everything = await Orders.find().plain();

// правильно: по одному документу
for await (const order of Orders.find().plain().cursor()) {
  await __sendToWarehouse__(order);
}
```

**Порядок обработки перепутался.** С `parallel` больше единицы вызовы завершаются в любом порядке. Если получатель ждёт заказы по возрастанию номера, оставьте `parallel` равным единице или отправляйте порциями через `batchSize`, внутри порции порядок сохраняется.

**`.orFail()` на курсоре ничего не делает.** [`.orFail()`](../reference/query/reading.mdx#or-fail) у курсора не бросает ошибку на пустой выборке. Курсор отдаёт документы порциями и заранее не знает, что их не будет. Пустая выборка просто завершает цикл без единой итерации, так что если для вас это сбой, проверьте счётчик после цикла.

## Полный пример [#full-example]

Скрипт выгрузки заказов. Он умеет продолжать с места сбоя, отправляет параллельно и порциями и собирает ошибки.

```ts twoslash title="export/export-orders.ts"
import { EachAsyncError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.db().model(Order);
declare const __sendToWarehouse__: (order: { number: number }) => Promise<void>;
declare const __insertMany__: (orders: { number: number }[]) => Promise<void>;
// ---cut---
// возобновляемая выгрузка: идентификатор последнего обработанного заказа
import type { Filter } from "@venloc/typemo";

export const exportOrders = async (lastId: string | null) => {
  const filter: Filter<Order> = lastId === null ? {} : { _id: { $gt: lastId } };
  let last = lastId;

  // порядок по _id: «после этого документа» однозначно
  const cursor = Orders.find(filter).sort({ _id: 1 }).plain().cursor();

  try {
    // порции по 100 штук, четыре порции одновременно; ошибки собираются
    await cursor.eachAsync(
      async (orders) => {
        await __insertMany__(orders);
        last = orders.at(-1)?._id ?? last;
      },
      { batchSize: 100, parallel: 4, continueOnError: true },
    );
  } catch (error) {
    if (error instanceof EachAsyncError) {
      console.log(`${error.errors.length} batches failed`);
    }
    throw error;
  }
  return last;
};
```

<Callout type="migration">

`.cursor()`, `for await` и `eachAsync` с `parallel`, `batchSize` и `continueOnError` знакомы вам по Mongoose. В Typemo есть три отличия.

- Перебирать через `for await` нужно результат [`.cursor()`](../reference/query/reading.mdx#cursor), а не сам запрос.
- После выхода из цикла курсор закрыт, и чтение бросает `QueryError`.
- Ошибки `eachAsync` с `continueOnError` приходят одним [`EachAsyncError`](../reference/query/cursor.mdx#each-async-error) со всеми ошибками функции.

</Callout>
