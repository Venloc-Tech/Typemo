Многого из Mongoose в Typemo нет, и не потому, что не дошли руки. Эти возможности неотделимы от неявного поведения — того самого «молча приведу», «молча отброшу», «молча пропущу». Ниже они перечислены, и для каждой названы причина и замена.

Если ищете конкретный метод, быстрее заглянуть в таблицы [Соответствия API](../reference/migration/api-mapping.mdx). Здесь разобраны случаи, где нужно не новое имя, а другой подход.

## Что понадобится

Примеры построены на блоге с пользователями и постами. `Posts` — модель поста, полученная у клиента через `client.db().model(Post)`.

## Быстрый путь

Вот пять отсутствий, с которыми сталкиваются почти все, и чем их заменить.

| В Mongoose | В Typemo |
|---|---|
| поле `Mixed`, `Object`, `{}` | вложенный класс или [`Spec.map`](../reference/schemas/types-and-spec.mdx#specmap) |
| `strict: false`, `strictQuery: false` | нет, неизвестное — ошибка |
| `select("a -b")`, `sort("-age")` | объект, например `select({ a: 1 })`, `sort({ age: -1 })` |
| `next()` и колбэки | асинхронные методы и исключения |
| `this` как `Query` в хуках | типизированный контекст с методом `.modify` |

Ниже разберём каждое.

## Поле произвольной формы, `Mixed`

Скажем, в документе лежит объект, форму которого схема заранее не знает, например настройки, которые пользователь задаёт сам. Mongoose примет любой объект, но изменения внутри него придётся отмечать вручную через `markModified`. Typemo откажет уже при объявлении модели.

```ts twoslash
import { Entity, Prop, Schema } from "@venloc/typemo";
// ---cut---
// @errors: 1240
@Schema({ collection: "settings" })
class Settings extends Entity {
  @Prop(() => Object)
  data!: unknown;
}
// во время работы при создании модели:
// ConfigurationError: Settings.data: Object (Mixed) is not supported: declare a @Schema class or Spec.map(X)
```

Mixed выключает всё, ради чего Typemo существует, — проверку значения, тип поля, обновления по вложенным путям и защиту от неизвестных ключей. Ни компилятор, ни база о таком поле ничего не знают, а изменения внутри объекта не видят ни `save`, ни `$getChanges`.

Замены две, и выбор зависит от того, известны ли ключи. Если известны, опишите вложенный класс с [`nested: true`](../reference/schemas/schema.mdx#nested). Если ключи произвольные, а значения одного типа, возьмите [`Spec.map`](../reference/schemas/types-and-spec.mdx#specmap) — карту со строковыми ключами и проверяемыми значениями.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
// ---cut---
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Spec.map(String)) preferences?: Map<string, string>;
}
const Users = client.db().model(User);
const user = await Users.create({ name: "Ann", preferences: new Map([["theme", "dark"]]) });
console.log(user.preferences?.get("theme"));
// → dark
```

Если нужен действительно произвольный JSON, храните его строкой и разбирайте сами. Или обратитесь к драйверу через [`client.unsafeDriver()`](../reference/connection/typemo-client.mdx#clientunsafedriver), но помните, что политики и проверки Typemo там не действуют.

## Отключить строгость через `strict: false`

Бывает, что часть кода пишет в документ поля, которых нет в схеме, а другая часть их читает. Опций `strict`, `strictQuery`, `strictPopulate`, `useNestedStrict` и `sanitizeFilter` в Typemo нет. Компилятор отвергает их в [`@Schema`](../reference/schemas/schema.mdx#schema) как неизвестные.

Из JavaScript без типов (или с `as never`) такой ключ тоже молча не пройдёт. Любой ключ не из списка опций при сборке модели даст [`ConfigurationError`](../reference/errors/configuration-errors.mdx#configurationerror) с перечнем допустимых опций, например `Account: @Schema has no "strict" option (the options are: collection, nested, ext, discriminatorKey, discriminators, timeseries, capped, collation, clustered, changeStreamPreAndPostImages, validator, autoIndex, autoCreate, readConcern, writeConcern, optimisticConcurrency, shardKey, tenant, softDelete, audit)`. У `toJSON` и `toObject` текст свой — он подсказывает передавать параметры сериализации в каждый вызов.

Строгость, которую можно выключить, перестаёт быть гарантией. Если библиотека то отбрасывает неизвестное поле, то пишет его, вам приходится помнить, в каком режиме вы сейчас. Если поля действительно есть в базе, но вашему коду не нужны, опишите их в классе. А данные, записанные другим приложением, остаются в документе нетронутыми. На верхнем уровне — при любом сохранении, в поддокументах — с вашего явного согласия, как описано в руководстве [Неизвестные поля](../documents/unknown-fields.mdx).

## Строки вместо объектов в `select` и `sort`

Mongoose принимает `select("name -password")`, `select("+passwordHash")` и `sort("-age name")`. Typemo принимает только объекты, потому что строку типами не проверить. Опечатку `"nmae"` компилятор заметит в объекте, но не в строке.

<Compare>

```ts
const posts = await MPost.find().select("title -views").sort("-views title");
```

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number) views?: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Posts = client.db().model(Post);
// ---cut---
const posts = await Posts.find().select({ title: 1 }).sort({ views: -1, title: 1 });
```

</Compare>

Направления `1` и `-1` можно писать и словами, `"asc"` и `"desc"`. Смешивать включение и исключение в одной проекции нельзя. Mongoose в таком случае тихо выбирал одно из двух, а Typemo бросает ошибку. Скрытое поле возвращается только явным `+` в проекции и только если поле объявлено как [`Hidden`](../reference/schemas/field-markers.mdx#hidden). Подробнее — в справочниках [`.select`](../reference/query/reading.mdx#select) и [`.sort`](../reference/query/reading.mdx#sort).

## Колбэки и `next()`

Колбэки у методов модели Mongoose убрал ещё в седьмой версии, а в девятой убрал и параметр `next` у `pre`-хуков. Если вы переходите с 9.x, то, скорее всего, уже пишете `async`-функции, и менять ничего не придётся. Если код ещё на старой версии, сначала переведите его на промисы внутри Mongoose. Регрессии так искать проще, чем при одновременной смене библиотеки.

В Typemo хук — это метод класса, ошибка — исключение, а чтобы пропустить операцию, запросный хук вызывает `this.skip`. Ни колбэков, ни `next`, ни события `error` нет.

## `this` в хуках

В хуке запроса Mongoose `this` — это `Query`. Через него можно переписать условие (`this.where`), добавить `populate`, поменять опции. Всё это происходит после проверок и в обход политик, поэтому в Typemo такого доступа нет. Здесь в хуке запроса `this` — типизированный контекст [`OperationHookContext`](../reference/hooks/operation-context.mdx#operationhookcontext). Значения операции в нём только читаются, а менять их можно методом [`.modify`](../reference/hooks/operation-context.mdx#modify), и результат снова проходит политики.

<Compare>

```ts
schema.pre("find", function () {
  this.where({ archived: false });
});
```

```ts twoslash
import { type Defaulted, Entity, Pre, Prop, Schema, type OperationHookContext } from "@venloc/typemo";
// ---cut---
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Boolean, { default: false }) archived!: Defaulted<boolean>;

  @Pre("query.find")
  onlyActive(this: OperationHookContext<Post, "query.find">): void {
    this.modify({ where: { archived: false } });
  }
}
```

</Compare>

В хуке документа `this` — сам документ, как и в Mongoose, только с `$`-методами. Подробнее — в руководствах [Выполнить код при сохранении документа](../hooks/document-hooks.mdx) и [Вмешаться в операцию](../hooks/operation-hooks.mdx).

## Регулярные выражения в событиях, `pre("save")` для всего

`schema.pre(/^find/, fn)` ловит сразу все события `find`, `findOne` и `findOneAnd*`. В Typemo список событий явный, это [`HOOK_EVENTS`](../reference/hooks/pre-post.mdx#hook_events), а один метод можно повесить на несколько событий несколькими декораторами. Так по имени события видно, что произойдёт, и регулярное выражение не подхватит новую операцию, о которой вы не знали.

## Сеттеры и порядок обработки значения

В Mongoose сеттеры выполняются в порядке, обратном регистрации, а `trim` и `lowercase` — такие же сеттеры. В Typemo порядок фиксирован. Сначала приведение типа, затем [`trim`](../reference/schemas/prop.mdx#trim), затем [`lowercase` или `uppercase`](../reference/schemas/prop.mdx#lowercase) и в конце ваш [`set`](../reference/schemas/prop.mdx#set). Значение `null` в nullable-поле сеттеры не видят, они работают только с настоящим значением.

## Плагины-функции и глобальное изменение схем

Плагин Mongoose — это функция, которая мутирует схему. Глобальные плагины применяются при создании каждой модели, кроме уже скомпилированных. Плагин Typemo — объект с методом `apply`, который работает с черновиком метаданных. Регистрация закрывается, как только успешно скомпилируется первая модель, и поздняя регистрация — это ошибка, а не тихий пропуск. Подробности — в руководстве [Плагины](../hooks/plugins.mdx).

Для типичных задач, ради которых в Mongoose писали плагины, есть встроенные механизмы. Мягкое удаление, тенанты и аудит включаются опциями [`@Schema`](../reference/schemas/schema.mdx#softdelete) и действуют на всех операциях, включая агрегацию. Плагины вроде `mongoose-delete` и `mongoose-history` при переходе становятся не нужны.

## Отладка запросов и `mongoose.set("debug")`

Глобального `debug` нет, вместо него есть подписчик на события. [`Typemo.instrument`](../reference/connection/typemo.mdx#typemoinstrument) получает начало и конец каждой операции, время, ошибку и команду. Подробнее — в руководстве [События операций](../observability/events.mdx).

## Код на JavaScript в запросах — `$where`, `$function`, `$accumulator`

Mongoose позволяет передать в запрос или конвейер код на JavaScript — условие `$where`, выражение `$function`, аккумулятор `$accumulator`. Typemo серверный JavaScript не выполняет. Такой код работает с правами базы, его не проверить по схеме, а внедрённый ввод становится исполняемым кодом.

Вызовы [`fn.function` и `fn.accumulator`](../reference/aggregation/accumulators.mdx#код-на-javascript) — это ошибки компиляции, и в их тексте названа замена. Оператор, переданный в обход типов, отклоняется ещё до отправки с `StrictModeError` (правило `sanitize`). Условие пишите операторами запроса или выражением [`$expr`](../queries/filters.mdx), значение группы — аккумуляторами `fn.sum`, `fn.push`, `fn.top`, а вычисления — операторами `fn.cond`, `fn.map`, `fn.reduce`.

## Когда это не нужно

Переносить всё подряд не обязательно. Бывают данные произвольной формы по своей природе — журнал событий с полями, которые задают клиенты, или слепок чужих ответов. Строгая модель для них невозможна, и Typemo принесёт больше трения, чем пользы. Оставьте такие коллекции на Mongoose или на драйвере, а остальные переносите на Typemo. Обе библиотеки работают с одной базой, как описано в руководстве [Пошаговая миграция](./step-by-step.mdx).

## Если что-то пошло не так

**Модель не создаётся с `Object (Mixed) is not supported`.** Поле объявлено как `@Prop(() => Object)` или как массив без типа элемента. Замените его вложенным классом или `Spec.map`, как показано выше.

**Опцию схемы не принимает компилятор.** Вы перенесли `@Schema({ strict: false })` или `toJSON`. Таких опций у декоратора нет намеренно. Компилятор их не пропустит, а код без типов получит `ConfigurationError` при сборке модели. Уберите их, а параметры сериализации передавайте при вызове [`$toJSON`](../reference/documents/document-api.mdx#tojson).
