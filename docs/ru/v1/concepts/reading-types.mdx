Половина того, что нужно знать о результате запроса, в Typemo живёт в типах. Какие поля есть у строки, что стало с `bigint`, пропало ли скрытое поле, может ли прийти `null` — всё это видно, если навести курсор на переменную. Запускать код не нужно. Ниже разберём, что вы увидите в подсказке, что значат её странные на вид части и как читать сообщение компилятора, когда запрос не компилируется.

Типы Typemo **выводятся из вашего класса**, их никто не пишет руками. Подсказка для целого документа при этом короткая. В ней имя класса, `HydratedDoc<Account>`, а если документ отличается от обычного чтения, ещё и список отличающихся полей. Результаты чтения и сериализации (`lean`, `plain`, `$toPlain()`, `$toObject()`, `$toJSON()`) редактор раскрывает до полей. Точный тип одного поля покажет курсор на этом свойстве.

Все подсказки ниже выдал настоящий компилятор на одной модели счёта. В ней есть скрытое поле `pin`, которого нет в обычных результатах (подробнее в справочнике [`Hidden`](../reference/schemas/field-markers.mdx#hidden)). На нём видно, как такое поле пропадает из типов.

```ts twoslash title="accounts/account.ts"
import { Entity, Prop, Schema, type Hidden } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => BigInt, { required: true })
  balance!: bigint;

  @Prop(() => Date)
  openedAt?: Date;

  @Prop(() => String, { hidden: true })
  pin?: Hidden<string>;
}
```

## Документ

**Документ** — это результат обычного чтения. У этого объекта модели есть методы `$save`, `$set` и отслеживание изменений. Его тип называется `HydratedDoc`, а в угловых скобках Typemo пишет данные модели. Наведите курсор на переменную с документом, а потом на его свойства.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, type Hidden, type Selected } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => Date) openedAt?: Date;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.connection.model(Account);
// ---cut---
const account = await Accounts.findOne({ owner: "ann" }).orFail();
//    ^?
const balance = account.balance;
//    ^?
const id = account._id;
//    ^?
```

У `account` подсказка `HydratedDoc<Account>` — документ модели `Account` в том виде, в каком его отдаёт обычное чтение. В нём все поля класса, кроме скрытых. `pin` по умолчанию в документ не входит, и `account.pin` не скомпилируется. Тот же `HydratedDoc<Account>` возвращают `new()` и `create()`, так что смело пишите его в сигнатуры функций, которые принимают прочитанный документ.

Свойства читаются как обычные значения — `account.balance` это `bigint`, `account._id` это `ObjectId`. Служебных пометок вроде «поле нельзя менять после создания» в подсказках нет. Они живут только в объявлении класса, а зачем нужны, рассказывает справочник [Маркерные типы полей](../reference/schemas/field-markers.mdx).

Если документ отличается от обычного чтения, подсказка называется `HydratedDocWith`, и вторым аргументом в ней идут только отличающиеся поля. Так бывает в трёх случаях.

- Связь загружена через populate — `HydratedDocWith<Post, { author: HydratedDoc<User> | null }>`.
- Скрытое поле запрошено знаком `+` (пример в разделе [Скрытые поля](#скрытые-поля)).
- Поле сужено условием `.where(…).in(…)`.

Остальные поля такие же, как в `HydratedDoc` того же класса. Как читать подсказку документа с populate, показывает руководство [Проверки типов при populate](../populate/type-checks.mdx).

Забыли [`.orFail()`](../reference/query/reading.mdx#orfail) — в подсказке появится `| null`, и компилятор потребует проверки. Результат `findOne` может оказаться пустым.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, type Hidden, type Selected } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => Date) openedAt?: Date;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.connection.model(Account);
// ---cut---
const account = await Accounts.findOne({ owner: "ann" });
//    ^?
```

## `.lean()` и `.plain()`

`.lean()` и `.plain()` возвращают результат без методов, одни данные. В результате `.lean()` значения такие, как их отдал драйвер (`ObjectId`, `bigint`). В `.plain()` типы MongoDB превращены в строки, чтобы данные можно было отдать клиенту. Разницу видно по свойствам.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, type Hidden, type Selected } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => Date) openedAt?: Date;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.connection.model(Account);
// ---cut---
const lean = await Accounts.findOne({ owner: "ann" }).orFail().lean();
//    ^?
const plain = await Accounts.findOne({ owner: "ann" }).orFail().plain();
const plainBalance = plain.balance;
//    ^?
const plainId = plain._id;
//    ^?
```

Тип `lean` раскрыт целиком, `_id` в нём `ObjectId`, а `balance` — `bigint`. В результате `.plain()` те же поля стали `` `${bigint}` `` и `string`. Строка `${bigint}` — это «десятичная запись целого числа», и методы записи принимают её обратно. Как выбрать между ними, объясняет руководство [Чтение данных](../queries/reading-data.mdx), а все типы форм собраны в справочнике [Типы форм](../reference/values/form-types.mdx).

Те же формы можно получить и из документа — через [`$toPlain()`](../reference/documents/document-api.mdx#toplain), [`$toObject()`](../reference/documents/document-api.mdx#toobject) и [`$toJSON()`](../reference/documents/document-api.mdx#tojson). Их подсказки раскрыты до полей, и скрытого поля в них нет.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, type Hidden } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => Date) openedAt?: Date;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.connection.model(Account);
// ---cut---
const account = await Accounts.findOne({ owner: "ann" }).orFail();
const toPlain = account.$toPlain();
//    ^?
const toObject = account.$toObject();
//    ^?
const toJson = account.$toJSON();
//    ^?
```

Посмотрите на поля. `$toPlain()` превращает `balance` в `` `${bigint}` ``, а `_id` в строку. `$toObject()` оставляет значения драйвера, `bigint` и `ObjectId`. А `$toJSON()` вдобавок делает из даты строку, потому что JSON не знает `Date`.

## Скрытые поля

Скрытое поле пропадает из типа результата, пока вы не попросите его явно знаком `+` в [`.select`](../reference/query/reading.mdx#select). Тогда оно появится в типе документа, но в ответ клиенту не попадёт, пока вы не разрешите это отдельно. Может ли поле оказаться в ответе, тип говорит ещё до запуска.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, type Hidden, type Selected } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => Date) openedAt?: Date;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.connection.model(Account);
// ---cut---
const account = await Accounts.findOne({ owner: "ann" }).select({ "+pin": true }).orFail();
//    ^?
const inDocument = account.pin;
//    ^?
const forInternalUse = account.$toPlain({ hidden: true }).pin;
//    ^?
// @errors: 2339
account.$toPlain().pin;
```

У документа подсказка `HydratedDocWith<Account, { pin?: string }>`. По сравнению с обычным чтением у него одно лишнее поле, и подсказка называет только его. И в документе, и в `$toPlain()` с `{ hidden: true }` поле читается как `string | undefined` — раз вы запросили его знаком `+`, это обычная строка. В обычном `$toPlain()` поля нет, и компилятор не даст к нему обратиться. Нет `pin` в типе — значит, случайно отправить его клиенту не выйдет. Как скрытые поля устроены целиком, рассказывает руководство [Чтение данных](../queries/reading-data.mdx#не-отдать-секретные-поля).

## Selected

Если выбрать часть полей через [`.select`](../reference/query/reading.mdx#select), тип строки сузится до этих полей и `_id`. Такую форму можно записать отдельным типом [`Selected`](../reference/query/contracts.mdx#selected) — «эти поля модели в виде результата `.plain()`». Он пригодится, чтобы описать результат в сигнатуре функции, и в подсказке раскрывается полностью.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, type Hidden, type Selected } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => Date) openedAt?: Date;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.connection.model(Account);
// ---cut---
type BalanceRow = Selected<Account, "owner" | "balance">;
declare const row: BalanceRow;
const shown = row;
//    ^?
const rows = await Accounts.find().select({ owner: 1, balance: 1 }).plain();
//    ^?
```

Тип, выведенный из запроса (`rows`), и тип, записанный руками (`BalanceRow`), совпадают по полям, отличается только порядок в подсказке. Если они разойдутся, [`.expect`](../reference/query/contracts.mdx#expect) скажет об этом ещё при компиляции.

## Когда не компилируется

Сообщения компилятора для Typemo бывают длинными, потому что типы вложены друг в друга. Читайте их с двух концов. Первая строка называет правило (`Property … does not exist`, `is possibly 'null'`), а последняя вложенная строка обычно называет причину. Вот пять типичных случаев с настоящим текстом компилятора.

**Метод документа у результата `.lean()`.** `.lean()` возвращает данные без методов, так что `$save` там нет. В сообщении раскрыт тип строки, и по нему видно, что методов в ней нет.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, type Hidden, type Selected } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => Date) openedAt?: Date;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.connection.model(Account);
// ---cut---
const lean = await Accounts.findOne({ owner: "ann" }).orFail().lean();
// @errors: 2339
await lean.$save();
```

Чтобы менять и сохранять, читайте документ, а не `.lean()`.

**Результат может быть `null`.** Если ничего не нашлось, `findOne` без `.orFail()` вернёт `null`, и компилятор заставит это учесть.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, type Hidden, type Selected } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => Date) openedAt?: Date;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.connection.model(Account);
// ---cut---
const account = await Accounts.findOne({ owner: "ann" });
// @errors: 18047
account.owner;
```

Добавьте `.orFail()`, если отсутствие документа для вас ошибка, или проверьте `null` сами.

**Неверный тип значения при записи.** Тут вся суть в последней строке сообщения. Первые строки говорят только, что ни один из двух вариантов `create` не подошёл, а причина написана в конце каждого варианта. Поле `balance` объявлено как `bigint`, поэтому на входе подойдёт `bigint` или его десятичная строка, а число нет.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, type Hidden, type Selected } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => Date) openedAt?: Date;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.connection.model(Account);
// ---cut---
// @errors: 2769
await Accounts.create({ owner: "ann", balance: 5 });
```

Исправьте на `balance: 5n` или `balance: "5"`.

**Поле, которого нет.** Неизвестное имя компилятор не пропустит ни в `.select`, ни в фильтре, ни в обновлении. В фильтре это `Object literal may only specify known properties` с подсказкой ближайшего имени. В `.select` сообщение одно и то же на любой модели. В нём есть пара `"projection error"` с причиной `unknown field "nope"`, то есть компилятор прямо называет неизвестное поле.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, type Hidden, type Selected } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => Date) openedAt?: Date;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.connection.model(Account);
// ---cut---
// @errors: 2345
await Accounts.find().select({ nope: 1 });
```

**Контракт результата не сходится.** `.expect` сравнивает ожидаемую форму строки с настоящей. Если они расходятся, сообщение перечисляет лишние поля (`extra`) и несовпадающие (`mismatch`).

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, type Hidden, type Selected } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => Date) openedAt?: Date;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.connection.model(Account);
// ---cut---
// @errors: 2684
await Accounts.find({ owner: "ann" }).plain().expect<{ owner: number }>();
```

Способ каждый раз один. Найдите в сообщении имя поля или метода, посмотрите, какой тип назван справа, наведите курсор на переменную и сравните. А если запрос компилируется, но падает при запуске, дело в данных, а не в типах. Правила строгости описаны на странице [Строгость](./strictness.mdx).
