**Typemo** — ODM для MongoDB на TypeScript. ODM (object-document mapper) описывает документы базы классами вашего языка и даёт методы для чтения и записи, которые понимают эти классы. Схему в Typemo задаёт класс с декораторами, а обмен с сервером идёт через официальный драйвер `mongodb`: собственного протокола у библиотеки нет.

Страница объясняет четыре решения, из которых состоит Typemo: типы выводятся из класса, строгость включена всегда, вместо тихого поведения библиотека бросает ошибку, а поддерживаются только последние версии инструментов. Заодно она честно называет границы: чего Typemo не умеет и что вам придётся проверить самим.

## Типы выводятся из класса

В Typemo нет отдельного интерфейса «как выглядит документ» рядом со схемой. Класс с декораторами описывает и схему для проверки данных во время работы, и типы для компилятора, поэтому они не могут разойтись. Допустим, счёт банка устроен так:

```ts twoslash title="accounts/account.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => BigInt, { required: true })
  balance!: bigint;

  @Prop(() => Date)
  openedAt?: Date;
}
```

Из этого класса компилятор выводит типы фильтров, обновлений, проекций и результатов. Вы получаете подсказки имён полей в редакторе, а результат каждого запроса имеет тип, который зависит от того, как вы его прочитали:

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => BigInt, { required: true }) balance!: bigint;
  @Prop(() => Date) openedAt?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.connection.model(Account);
// ---cut---
const rows = await Accounts.find({ owner: "ann" }).select({ owner: 1, balance: 1 }).plain();
const first = rows[0];
//    ^?
const lean = await Accounts.findOne({ owner: "ann" }).orFail().lean();
const leanBalance = lean.balance;
//    ^?
```

В первом запросе выбраны два поля и результат — plain-вид, поэтому в типе только они и `_id`, а `balance` стал строкой `${bigint}`, которую можно отдать клиенту. Во втором запросе результат — lean, и `balance` остаётся `bigint`. Тип следует за запросом: что вы выбрали и в какой форме прочитали, то и написано в типе. Как читать такие подсказки, объясняет страница [Как читать типы в редакторе](./reading-types.mdx), а почему форм несколько — страница [Типы данных MongoDB](./bson-types.mdx).

Схему можно описать классами двух видов декораторов. Ядро `@venloc/typemo` работает на legacy-декораторах (в `tsconfig` нужен только `experimentalDecorators`: типы полей ядро не читает из компилятора, а метаданные хранит само), а отдельный пакет `@venloc/typemo-decorators` даёт те же декораторы в стандарте TC39. Все опции и настройки живут в ядре, пакет декораторов только переключает синтаксис.

## Строгость по умолчанию

**Строгость** — правило «если запрос нельзя выполнить однозначно, это ошибка». Typemo отвергает неизвестные поля в фильтре, `undefined` вместо значения, пустой фильтр в удалении и значение не того типа. Это не режим, который можно выключить: ни опция, ни настройка не ослабляют правил, и запрос с ошибкой не уходит на сервер. Причина в том, что MongoDB сама принимает всё перечисленное. Опечатка в имени поля даёт пустой результат, а не ошибку, `undefined` уходит как `null`, а `deleteMany({})` удаляет всю коллекцию.

Строгость проверяется дважды: компилятор останавливает ошибку в редакторе, а проверка при запуске ловит то же самое в данных, которых компилятор не видел (тело запроса, файл, динамически собранный фильтр). Подробно со всеми примерами это описано на странице [Строгость](./strictness.mdx).

## Ошибка вместо тихого поведения

Строгость — частный случай общего принципа: когда библиотека может выбрать, промолчать или сообщить, она сообщает. Поэтому у Typemo есть собственная иерархия ошибок с полями, по которым можно ветвиться (`reason`, `path`), и оригинальная ошибка сервера лежит в `cause`. Например, сохранение, которое стёрло бы из базы поля, о которых схема не знает, бросает [`UnknownFieldsError`](../reference/errors/data-errors.mdx#unknownfieldserror), а не теряет их молча. То же относится к чтению: [`.orFail()`](../reference/query/reading.mdx#orfail) превращает «ничего не нашлось» в [`DocumentNotFoundError`](../reference/errors/query-errors.mdx#documentnotfounderror), а без него `findOne` честно возвращает `null`, и тип об этом предупреждает.

Цена у этого принципа есть, и её лучше знать заранее: код, который в другой библиотеке «просто работал» с опечаткой или с `undefined`, в Typemo падает. Вы платите неудобством в первый день, а взамен не находите повреждённые данные через месяц.

## Только последние версии

Typemo поддерживает последние версии инструментов и не несёт код ради старых. Проверено 26 сентября 2026 года и записано в файле `VERSIONS.md` репозитория: драйвер `mongodb` 7.6.0 и `bson` 7.3.3 (оба указаны как peerDependencies с `^`), TypeScript 6.0.3, Bun 1.4.0. Тесты идут на настоящей MongoDB: на предварительной версии 9.0.0-rc0 и на стабильной 8.3.11.

Практическое следствие для вас: обратной совместимости с прежними версиями драйвера или сервера нет, и для них ничего не проверялось. Если у вас старые версии, сначала обновите их. Зато в библиотеке нет веток «если драйвер старый», а поведение описано одной страницей, а не таблицей исключений.

## Чего в Typemo нет

Границы важны не меньше возможностей, поэтому перечислим то, чего вы не найдёте.

- Схемы без класса. Модель описывается только классом с декораторами; схемы объектом или JSON-описанием в ядре нет, а свойство `schema` модели только читает описание (страница [Схема во время работы](../schemas/runtime-schema.mdx)).
- Смягчения строгости. Нельзя разрешить неизвестные поля в фильтре или пустой фильтр в удалении опцией: для намеренного удаления всех документов есть явный `Filters.all`, описанный в руководстве [Пустые фильтры](../writes/empty-filters.mdx).
- Собственного протокола и собственного драйвера. Если вам нужна операция, которой у Typemo нет, вы получаете доступ к драйверу, как описано в [руководстве по доступу к драйверу](../connection/driver-access.mdx), но такие вызовы идут мимо политик и типов библиотеки.
- Совместимости с другими версиями и другими ODM. Typemo написан с нуля и не повторяет Mongoose; если вы пришли оттуда, внимательно читайте выноски «Если вы пришли из Mongoose».

Есть и практические оговорки. Типы выводятся из класса, а вывод нагружает компилятор, и это стоит учитывать в очень больших проектах. Тесты проекта выполняются в Bun, поэтому в другой среде исполнения проверьте свою сборку сами. Транзакции и подписки на изменения требуют реплика-сета, так устроена сама MongoDB.
