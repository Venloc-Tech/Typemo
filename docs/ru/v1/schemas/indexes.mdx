**Индекс** — это вспомогательная структура в базе. С ним документ по полю находится без просмотра всей коллекции, а часть индексов ещё и не даёт значению повториться. Typemo описывает индексы прямо в классе модели. Простые случаи — опциями поля, составные и особые — декоратором [`@Index`](../reference/schemas/index-decorators.mdx#index). Само описание в базе ничего не создаёт. Индексы появляются при [`connection.init()`](../reference/connection/connection.mdx#connection.init) или [`connection.syncAll()`](../reference/connection/connection.mdx#connection.sync-all).

Если индексы MongoDB для вас в новинку, запомните главное. Без индекса запрос читает всю коллекцию, а с индексом — только нужный кусок. Поэтому индексы ставят на поля, по которым ищут и сортируют, а уникальность — на поля, которые не должны повторяться.

## Что понадобится [#prerequisites]

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель банковского счёта из файла `accounts/account.ts`. По ходу страницы модель будет расти.

## Быстрый путь [#quick-start]

Уникальный номер счёта и индекс по владельцу задаются опциями [`@Prop`](../reference/schemas/prop.mdx#unique), а составной индекс — через [`@Index`](../reference/schemas/index-decorators.mdx#index).

```ts twoslash title="accounts/account.ts"
import { Entity, Index, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Index({ owner: 1, opened: -1 }) // [!code ++]
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) // [!code highlight]
  number!: string;
  @Prop(() => String, { index: true }) // [!code highlight]
  owner?: string;
  @Prop(() => Date)
  opened?: Date;
}

const Accounts = client.db().model(Account);
const report = await client.connection.init();
console.log(report.created);
// → ["collection accounts", "index accounts.number_1", "index accounts.owner_1", "index accounts.owner_1_opened_-1"]
```

Отчёт `init()` перечисляет всё, что создано, — сначала коллекцию, потом каждый индекс. Ниже разберём каждый вид индекса на реальных задачах.

## Один индекс на поле [#one-index-per-field]

Опция [`index`](../reference/schemas/prop.mdx#index) создаёт индекс по одному полю. `true` или `1` — по возрастанию, `-1` — по убыванию, `"hashed"` — хешированный. Чтобы увидеть, что Typemo собирается создать, не трогая базу, спросите описание схемы. [`Accounts.schema.describe()`](../reference/schemas/schema-info.mdx#describe) вернёт индексы в том виде, в каком они попадут на сервер.

```ts twoslash title="accounts/account.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { index: true }) owner?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
console.log(Accounts.schema.describe().indexes);
// → [{ keys: { owner: 1 }, options: {} }]
```

Имя индексу сервер даёт сам по ключам, здесь это `owner_1`. Индекс по `_id` объявлять нельзя, сервер и так строит его уникальным.

## Не пустить дубликат [#prevent-duplicates]

[`unique`](../reference/schemas/prop.mdx#unique) создаёт уникальный индекс. Сервер не даст записать второй документ с тем же значением, а Typemo превратит отказ в [`DuplicateKeyError`](../reference/errors/server-errors.mdx#duplicate-key-error). Опции нужно одно из трёх — `required: true`, `sparse: true` или частичный `@Index`.

Дело в устройстве MongoDB. Документ без поля индексируется как `null`, и второй такой документ нарушил бы уникальность. Typemo откажет сразу при описании модели, чтобы вы не наткнулись на это в продакшене.

```ts twoslash title="accounts/accounts.service.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) number!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
await client.connection.init();
// ---cut---
await Accounts.create({ number: "1" });
try {
  await Accounts.create({ number: "1" });
} catch (error) {
  console.log((error as Error).message);
}
// → duplicate key on number_1: { number: "1" } (code 11000 DuplicateKey)
```

Если поле необязательное и уникальным должно быть только заполненное значение, добавьте [`sparse: true`](../reference/schemas/prop.mdx#sparse). В индекс попадут только документы, где поле есть. На поле с `nullable: true` уникальность запрещена совсем. Значения `null` конфликтуют даже в разреженном индексе, и тут нужен частичный индекс из следующего раздела. Модель не соберётся — `Account.nick: "unique" on a nullable field — null values collide even in a sparse index; use a partial @Index`.

## Уникальность только для части документов [#partial-unique]

Почта должна быть уникальной среди действующих счетов, а у закрытых может повторяться. Для этого нужен **частичный индекс**. В него входят только документы, подходящие под условие `partialFilterExpression`. Условие сверяется с классом при компиляции, так что опечатка в имени поля не пройдёт.

```ts twoslash title="accounts/account.ts"
import { Entity, Index, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Index({ email: 1 }, { unique: true, partialFilterExpression: { active: true }, name: "email_active" }) // [!code highlight]
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String) email?: string;
  @Prop(() => Boolean) active?: boolean;
}

const Accounts = client.db().model(Account);
await client.connection.init();
await Accounts.create({ email: "a@x", active: true });
const inactive = await Accounts.create({ email: "a@x", active: false });
// закрытый счёт с той же почтой записался: индекс его не видит

try {
  await Accounts.create({ email: "a@x", active: true });
} catch (error) {
  console.log((error as Error).message);
}
// → duplicate key on email_active: { email: "a@x" } (code 11000 DuplicateKey)
```

## Автоматически удалять старые документы [#expire-documents]

[`expires`](../reference/schemas/prop.mdx#expires) на поле типа `Date` создаёт TTL-индекс. MongoDB сама удалит документ, когда с даты в поле пройдёт заданное число секунд. Так чистят сессии, коды подтверждения, временные счета. Сервер проверяет TTL примерно раз в минуту, так что документ исчезает не мгновенно. Для условий сложнее одного поля берите [`expireAfterSeconds`](../reference/schemas/index-decorators.mdx#expire-after-seconds) в `@Index`.

```ts twoslash title="accounts/session.ts"
import { Entity, Index, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "sessions" })
class Session extends Entity {
  @Prop(() => Date, { expires: 3600 }) // [!code highlight]
  lastSeen?: Date;
}

const Sessions = client.db().model(Session);
console.log(Sessions.schema.describe().indexes);
// → [{ keys: { lastSeen: 1 }, options: { expireAfterSeconds: 3600 } }]
```

## Полнотекстовый поиск [#full-text-search]

Текстовый индекс позволяет искать слова в строках. В коллекции он может быть **только один**, поэтому поля с [`text: true`](../reference/schemas/prop.mdx#text) собираются в один индекс. Если нужны веса полей или язык, опишите индекс через `@Index` с `weights`, а `text: true` на поля не ставьте. Сочетать их нельзя.

```ts twoslash title="accounts/account.ts"
import { Entity, Index, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Index({ title: "text", note: "text" }, { weights: { title: 5 }, name: "search" }) // [!code highlight]
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String) title?: string;
  @Prop(() => String) note?: string;
}
const Accounts = client.db().model(Account);
console.log(Accounts.schema.describe().indexes);
// → [{ keys: { title: "text", note: "text" }, options: { weights: { title: 5 }, name: "search" } }]
```

Как искать по такому индексу, рассказывает руководство [Текстовый и векторный поиск](../queries/text-and-vector-search.mdx). Сервер хранит ключи текстового индекса как `_fts` и `_ftsx` и не пишет в описание вес по умолчанию (1), если его не задали. Typemo учитывает это при сравнении с базой. Повторный `connection.init()` на модели с текстовым индексом ничего не создаёт и не падает, отчёт второго вызова пуст (`created` — `[]`, `inSync` — `true`).

## Гео, wildcard и поисковые индексы [#geo-wildcard-search-indexes]

Направление в `@Index` бывает не только `1` и `-1`, но и `"hashed"`, `"2dsphere"` и `"2d"`. Для геозапросов нужен `"2dsphere"` (руководство [Гео-запросы](../queries/geo.mdx)). Ключ вида `"$**"` или `"path.$**"` создаёт **wildcard-индекс** для полей, чьи имена заранее неизвестны. Какие пути он покрывает, ограничивает `wildcardProjection`.

Полнотекстовые и векторные индексы Atlas Search описываются отдельным декоратором [`@SearchIndex`](../reference/schemas/index-decorators.mdx#search-index) и создаются на сервере Atlas. На обычном `mongod` `connection.init()` с ними бросит [`SyncError`](../reference/errors/configuration-errors.mdx#sync-error), а среди сбоев будет ответ сервера `SearchNotEnabled` с кодом 31082. О синхронизации поисковых индексов читайте в руководстве [Поисковые индексы](../collections/search-indexes.mdx).

## Создать индексы в базе [#create-indexes]

Объявление индекса в классе ничего не создаёт — ни при создании модели, ни при первой записи. До вызова `init` индексов нет, а значит, и уникальность не работает. Вызывайте [`connection.init()`](../reference/connection/connection.mdx#connection.init) при старте. Он создаёт недостающее, то есть коллекцию и индексы, и ничего не удаляет и не меняет.

Если индекс на сервере объявлен не так, как в схеме, `init` бросит [`SyncError`](../reference/errors/configuration-errors.mdx#sync-error) со сбоем в `failures` и советом — `Conf: index "owner_1" exists on the server with other keys or options; init() never drops or changes an index — run syncIndexes()/syncAll() to replace it`. Названные методы индекс заменяют. Весь процесс описан в руководстве [Синхронизация индексов](../collections/index-sync.mdx).

## Как выбрать [#how-to-choose]

Спросите себя — **сколько полей в индексе и какие у него условия?**

- **Одно поле, никаких условий** — опция `index`, `unique` или `expires` прямо на поле. Описание лежит рядом с полем.
- **Несколько полей, `partialFilterExpression`, веса, коллация, `hidden`** — `@Index`.

Порядок ключей в составном индексе важен. Индекс `{ owner: 1, opened: -1 }` обслуживает запросы по `owner` и по `owner` вместе с `opened`, но не запросы только по `opened`.

## Когда это не нужно [#when-not-to-use]

Не индексируйте поля, по которым не ищете и не сортируете. Каждый индекс замедляет запись и занимает память. Маленьким коллекциям, которые целиком помещаются в память, индексы почти ничего не дают. А уникальность держите индексом, а не проверкой в коде. Две одновременные записи обе пройдут проверку, и остановить вторую сможет только индекс.

## Если что-то пошло не так [#troubleshooting]

**`unique` без `required`.** Опцию отвергают при создании модели. Документы без поля индексируются как `null`, и второй такой документ нарушил бы уникальность.

```text
ConfigurationError: Account.passport: "unique" on a field that is not required — every document without it is indexed as null and the second one fails (E11000); add required: true, sparse: true or use a partial @Index
```

Добавьте `required: true` или `sparse: true` либо используйте частичный `@Index`.

**Опечатка в имени поля индекса.** Пути в `@Index` сверяются с классом при компиляции, и `@Index({ ownr: 1 })` не скомпилируется. Компилятор скажет `@Index: "ownr" is not a field of the class`.

**Уникальность не работает.** Одно значение записалось дважды, потому что индексов нет. Либо при старте не вызвали `connection.init()`, либо коллекцию исключили опцией [`autoIndex`](../reference/schemas/schema.mdx#auto-index) — с `autoIndex: false` `init()` индексы этой модели не строит. Проверьте, что индексы на месте, через [`Accounts.listIndexes()`](../reference/collections/model-indexes.mdx#model.list-indexes).

## Полный пример [#full-example]

Всё вместе в одном файле — модель со всеми видами индексов и их создание при старте.

```ts twoslash title="accounts/account.ts"
import { Entity, Index, Prop, Schema, TypemoClient } from "@venloc/typemo";

@Index({ owner: 1, opened: -1 })
@Index({ email: 1 }, { unique: true, partialFilterExpression: { active: true }, name: "email_active" })
@Index({ closedAt: 1 }, { expireAfterSeconds: 60, name: "closed_ttl" })
@Schema({ collection: "accounts" })
class Account extends Entity {
  // номер: уникален и обязателен
  @Prop(() => String, { required: true, unique: true })
  number!: string;

  // владелец: часто ищем
  @Prop(() => String, { index: true })
  owner?: string;

  @Prop(() => Date) opened?: Date;
  @Prop(() => String) email?: string;
  @Prop(() => Boolean) active?: boolean;
  @Prop(() => Date) closedAt?: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
client.connection.model(Account);

// старт приложения: создаём недостающие индексы
const report = await client.connection.init();
console.log(report.created);
// → ["collection accounts", "index accounts.number_1", "index accounts.owner_1", "index accounts.owner_1_opened_-1", "index accounts.email_active", "index accounts.closed_ttl"]
```

<Callout type="migration">

В Mongoose индексы создаются сами при подключении (`autoIndex`), а `unique` на необязательном поле проходит молча. В Typemo индексы создаёт только явный `connection.init()` (или `syncAll()`), а `unique` без `required`, `sparse` или частичного индекса — ошибка уже при описании модели.

</Callout>
