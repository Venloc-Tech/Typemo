**Индекс** — вспомогательная структура в базе, которая позволяет находить документы по полю без просмотра всей коллекции; часть индексов ещё и гарантирует, что значение не повторится. Typemo описывает индексы прямо в классе модели: короткие случаи — опциями поля, составные и особые — декоратором [`@Index`](../reference/schemas/index-decorators.mdx#index). Само описание в базе ничего не создаёт: индексы появляются при [`connection.init()`](../reference/connection/connection.mdx#connectioninit) или [`connection.syncAll()`](../reference/connection/connection.mdx#connectionsyncall).

Если вы впервые работаете с индексами MongoDB, запомните одно: без индекса запрос читает всю коллекцию, а с индексом — только нужный кусок. Поэтому индексы объявляют для полей, по которым вы ищете и сортируете, а уникальность — для полей, которые не должны повторяться.

## Что предполагается

Примеры используют клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель банковского счёта из файла `accounts/account.ts`. Она растёт по ходу страницы.

## Быстрый путь

Уникальный номер счёта и индекс по владельцу — опциями [`@Prop`](../reference/schemas/prop.mdx#unique), составной индекс — [`@Index`](../reference/schemas/index-decorators.mdx#index):

```ts twoslash title="accounts/account.ts"
import { Entity, Index, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Index({ owner: 1, opened: -1 }) // [!code ++]
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) // [!code highlight]
  number!: string;
  @Prop(() => String, { index: true }) // [!code highlight]
  owner?: string;
  @Prop(() => Date)
  opened?: Date;
}

const Accounts = client.db().model(Account);
const report = await client.connection.init();
console.log(report.created);
// → ["collection accounts", "index accounts.number_1", "index accounts.owner_1", "index accounts.owner_1_opened_-1"]
```

Отчёт `init()` называет всё, что было создано: сначала коллекцию, потом каждый индекс. Остальная страница разбирает каждый вид индекса на реальных задачах.

## Один индекс на поле

Опция [`index`](../reference/schemas/prop.mdx#index) создаёт индекс по одному полю: `true` или `1` — по возрастанию, `-1` — по убыванию, `"hashed"` — хешированный. Чтобы посмотреть, что Typemo собирается создать, не обращаясь к базе, спросите описание схемы: [`Accounts.schema.describe()`](../reference/schemas/schema-info.mdx#describe) возвращает индексы в том виде, в каком они попадут на сервер.

```ts twoslash title="accounts/account.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { index: true }) owner?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
console.log(Accounts.schema.describe().indexes);
// → [{ keys: { owner: 1 }, options: {} }]
```

Имя индекса сервер выбирает сам по ключам: `owner_1`. Индекс по `_id` объявлять нельзя: сервер и так строит его уникальным.

## Не пустить дубликат

[`unique`](../reference/schemas/prop.mdx#unique) создаёт уникальный индекс: сервер не даст записать второй документ с тем же значением, а Typemo превратит отказ в [`DuplicateKeyError`](../reference/errors/server-errors.mdx#duplicatekeyerror). Опция требует одного из условий: `required: true`, `sparse: true` или частичного `@Index`. Причина в устройстве MongoDB: документ без поля индексируется как `null`, и второй такой документ нарушил бы уникальность. Typemo отказывает сразу при описании модели, чтобы вы не нашли это в проде.

```ts twoslash title="accounts/accounts.service.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) number!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
await client.connection.init();
// ---cut---
await Accounts.create({ number: "1" });
try {
  await Accounts.create({ number: "1" });
} catch (error) {
  console.log((error as Error).message);
}
// → duplicate key on number_1: { number: "1" } (code 11000 DuplicateKey)
```

Если поле необязательное и уникальным должно быть только заполненное значение, добавьте [`sparse: true`](../reference/schemas/prop.mdx#sparse): в индекс попадут только документы, у которых поле есть. Уникальность на поле с `nullable: true` запрещена совсем: значения `null` конфликтуют даже в разреженном индексе, здесь нужен частичный индекс (следующий раздел). Модель не соберётся: `Account.nick: "unique" on a nullable field — null values collide even in a sparse index; use a partial @Index`.

## Уникальность только для части документов

Электронная почта должна быть уникальной среди действующих счетов, а закрытые счета могут её повторять. Для этого нужен **частичный индекс**: он включает только документы, подходящие под условие `partialFilterExpression`. Условие сверяется с классом при компиляции, поэтому опечатка в имени поля не пройдёт.

```ts twoslash title="accounts/account.ts"
import { Entity, Index, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Index({ email: 1 }, { unique: true, partialFilterExpression: { active: true }, name: "email_active" }) // [!code highlight]
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String) email?: string;
  @Prop(() => Boolean) active?: boolean;
}

const Accounts = client.db().model(Account);
await client.connection.init();
await Accounts.create({ email: "a@x", active: true });
const inactive = await Accounts.create({ email: "a@x", active: false });
// закрытый счёт с той же почтой записался: индекс его не видит

try {
  await Accounts.create({ email: "a@x", active: true });
} catch (error) {
  console.log((error as Error).message);
}
// → duplicate key on email_active: { email: "a@x" } (code 11000 DuplicateKey)
```

## Автоматически удалять старые документы

[`expires`](../reference/schemas/prop.mdx#expires) на поле типа `Date` создаёт TTL-индекс: MongoDB сама удалит документ, когда со значения даты пройдёт заданное число секунд. Так чистят сессии, коды подтверждения, временные счета. Сервер проверяет TTL примерно раз в минуту, поэтому документ исчезает не мгновенно. Для условий сложнее одного поля используйте [`expireAfterSeconds`](../reference/schemas/index-decorators.mdx#expireafterseconds) в `@Index`.

```ts twoslash title="accounts/session.ts"
import { Entity, Index, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "sessions" })
class Session extends Entity {
  @Prop(() => Date, { expires: 3600 }) // [!code highlight]
  lastSeen?: Date;
}

const Sessions = client.db().model(Session);
console.log(Sessions.schema.describe().indexes);
// → [{ keys: { lastSeen: 1 }, options: { expireAfterSeconds: 3600 } }]
```

## Полнотекстовый поиск

Текстовый индекс позволяет искать слова в строках. В коллекции может быть **только один** текстовый индекс, поэтому поля с [`text: true`](../reference/schemas/prop.mdx#text) объединяются в один. Если нужны веса полей или язык, опишите индекс через `@Index` с `weights` и не ставьте `text: true` на полях: сочетать их нельзя.

```ts twoslash title="accounts/account.ts"
import { Entity, Index, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Index({ title: "text", note: "text" }, { weights: { title: 5 }, name: "search" }) // [!code highlight]
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String) title?: string;
  @Prop(() => String) note?: string;
}
const Accounts = client.db().model(Account);
console.log(Accounts.schema.describe().indexes);
// → [{ keys: { title: "text", note: "text" }, options: { weights: { title: 5 }, name: "search" } }]
```

Как искать по такому индексу, описано в руководстве [Текстовый и векторный поиск](../queries/text-and-vector-search.mdx). Сервер хранит ключи текстового индекса как `_fts` и `_ftsx`, а вес по умолчанию (1) не записывает в описание, если он не задан. Typemo учитывает это при сравнении с базой, поэтому повторный `connection.init()` на модели с текстовым индексом ничего не создаёт и не падает: отчёт второго вызова пуст (`created` — `[]`, `inSync` — `true`).

## Гео, wildcard и поисковые индексы

Направление в `@Index` может быть не только `1` и `-1`, но и `"hashed"`, `"2dsphere"` и `"2d"`: под геозапросы нужен `"2dsphere"` (руководство [Гео-запросы](../queries/geo.mdx)). Ключ вида `"$**"` или `"path.$**"` создаёт **wildcard-индекс** для полей с заранее неизвестными именами; какие пути он покрывает, ограничивает `wildcardProjection`. Полнотекстовые и векторные индексы Atlas Search описываются отдельным декоратором [`@SearchIndex`](../reference/schemas/index-decorators.mdx#searchindex) и создаются на сервере Atlas: на обычном `mongod` `connection.init()` с ними бросает [`SyncError`](../reference/errors/configuration-errors.mdx#syncerror), а среди сбоев — ответ сервера `SearchNotEnabled` с кодом 31082. О синхронизации поисковых индексов читайте в руководстве [Поисковые индексы](../collections/search-indexes.mdx).

## Создать индексы в базе

Объявление индекса в классе ничего не создаёт: ни при создании модели, ни при первой записи. Индексов до вызова `init` нет, значит, уникальность не работает. Вызывайте [`connection.init()`](../reference/connection/connection.mdx#connectioninit) при старте: он создаёт недостающее (коллекцию и индексы) и ничего не удаляет и не меняет. Если индекс на сервере объявлен иначе, чем в схеме, `init` бросает [`SyncError`](../reference/errors/configuration-errors.mdx#syncerror) со сбоем в `failures` и советом: `Conf: index "owner_1" exists on the server with other keys or options; init() never drops or changes an index — run syncIndexes()/syncAll() to replace it`. Эти методы заменяют индекс. Полностью процесс описан в руководстве [Синхронизация индексов](../collections/index-sync.mdx).

## Как выбрать

Задайте себе один вопрос: **сколько полей и какие условия у индекса?** Одно поле и никаких условий — опция `index`, `unique` или `expires` на поле: описание рядом с полем. Несколько полей в одном индексе, условие `partialFilterExpression`, веса, коллация, `hidden` — `@Index`. Порядок ключей составного индекса важен: индекс `{ owner: 1, opened: -1 }` обслуживает запросы по `owner` и по `owner` вместе с `opened`, но не запросы только по `opened`.

## Когда это не нужно

Не индексируйте поля, по которым вы не ищете и не сортируете: каждый индекс замедляет запись и занимает память. Для коротких коллекций, которые целиком помещаются в память, индексы почти ничего не дают. Ограничение уникальности лучше держать индексом, а не проверкой в коде: две одновременные записи пройдут проверку обе, и только индекс остановит вторую.

## Частые ошибки

### `unique` без `required`

Опция отвергается при создании модели: документы без поля индексируются как `null`, и второй такой документ нарушил бы уникальность.

```text
ConfigurationError: Account.passport: "unique" on a field that is not required — every document without it is indexed as null and the second one fails (E11000); add required: true, sparse: true or use a partial @Index
```

Добавьте `required: true`, `sparse: true` или используйте частичный `@Index`.

### Опечатка в имени поля индекса

Пути в `@Index` сверяются с классом при компиляции: `@Index({ ownr: 1 })` не скомпилируется. Компилятор сообщает `@Index: "ownr" is not a field of the class`.

### Уникальность не работает

Запись прошла дважды с одним значением: индексы не были созданы. Вы забыли вызвать `connection.init()` при старте либо исключили коллекцию опцией [`autoIndex`](../reference/schemas/schema.mdx#autoindex): с `autoIndex: false` `init()` индексы этой модели не строит. Проверьте, что индексы есть, через [`Accounts.listIndexes()`](../reference/collections/model-indexes.mdx#modellistindexes).

## Полный пример

Один файл собирает всё вместе: модель со всеми видами индексов и создание индексов при старте.

```ts twoslash title="accounts/account.ts"
import { Entity, Index, Prop, Schema, TypemoClient } from "@venloc/typemo";

@Index({ owner: 1, opened: -1 })
@Index({ email: 1 }, { unique: true, partialFilterExpression: { active: true }, name: "email_active" })
@Index({ closedAt: 1 }, { expireAfterSeconds: 60, name: "closed_ttl" })
@Schema({ collection: "accounts" })
class Account extends Entity {
  // номер: уникален и обязателен
  @Prop(() => String, { required: true, unique: true })
  number!: string;

  // владелец: часто ищем
  @Prop(() => String, { index: true })
  owner?: string;

  @Prop(() => Date) opened?: Date;
  @Prop(() => String) email?: string;
  @Prop(() => Boolean) active?: boolean;
  @Prop(() => Date) closedAt?: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
client.connection.model(Account);

// старт приложения: создаём недостающие индексы
const report = await client.connection.init();
console.log(report.created);
// → ["collection accounts", "index accounts.number_1", "index accounts.owner_1", "index accounts.owner_1_opened_-1", "index accounts.email_active", "index accounts.closed_ttl"]
```

<Callout type="migration">

В Mongoose индексы создаются сами при подключении (`autoIndex`), а `unique` на необязательном поле принимается молча. В Typemo индексы создаёт только явный `connection.init()` (или `syncAll()`), а `unique` без `required`, `sparse` или частичного индекса — ошибка при описании модели.

</Callout>
