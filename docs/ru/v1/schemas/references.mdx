Документы разных коллекций связывают **ссылкой**. Пост хранит не копию автора, а его `_id`. Тогда имя автора лежит в одном месте и меняется одной записью. В Typemo ссылка — обычное поле с типом идентификатора, к которому добавлены опция [`ref`](../reference/schemas/prop.mdx#ref) и маркерный тип [`Ref<M>`](../reference/schemas/field-markers.mdx#ref). Они говорят библиотеке и компилятору, на какую модель указывает поле. А ещё позволяют подтянуть документ автора запросом [`populate`](../reference/populate/populate.mdx#populate).

Хранится ссылка всегда **одинаково** — идентификатором. Сам документ автора внутри поста не лежит никогда. После `populate` он появляется только в результате чтения, а в базе остаётся идентификатор. Даже если при записи передать документ автора вместо идентификатора, в базу уйдёт его `_id`.

## Что понадобится

Модель, описанная по руководству [Описать модель](./define-model.mdx). Примеры строят блог с автором и его постами. Подробно о том, как подтягивать связи, рассказывает раздел [Связанные данные](../populate/basics.mdx).

## Быстрый путь

Поле-ссылку объявляют идентификатором с `ref` и типом `Ref<Author>`.

```ts twoslash title="blog/post.ts"
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
@Schema({ collection: "authors" })
class Author extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}

@Schema({ collection: "posts" })
export class Post extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Types.ObjectId, { ref: () => Author, required: true })
  author!: Ref<Author>;
}

const Authors = client.connection.model(Author);
const Posts = client.connection.model(Post);
const ann = await Authors.create({ name: "Ann" });
const post = await Posts.create({ title: "Hello", author: ann._id });
console.log(post.author.constructor.name);
// → ObjectId
```

`ref` — это **функция**, которая возвращает класс. Так модель, объявленная ниже по файлу или в другом модуле, успеет появиться к моменту сборки. Ниже разберём, что можно записать в поле и как получить связанный документ.

## Записать ссылку

Поле-ссылка принимает идентификатор в трёх видах.

- Значение `ObjectId`.
- Его строку из 24 шестнадцатеричных символов. Удобно, когда идентификатор пришёл из адреса запроса.
- Сам документ модели — документ, результат `.lean()` или экземпляр класса. Удобно, когда документ уже в руках и доставать `_id` незачем.

В базу во всех трёх случаях уходит идентификатор.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
@Schema({ collection: "authors" })
class Author extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Types.ObjectId, { ref: () => Author, required: true }) author!: Ref<Author>;
}
const Authors = client.connection.model(Author);
const Posts = client.connection.model(Post);
const ann = await Authors.create({ name: "Ann" });
// ---cut---
const byString = await Posts.create({ title: "p1", author: ann._id.toHexString() });
const byDocument = await Posts.create({ title: "p2", author: ann }); // [!code highlight]
console.log(byString.author.constructor.name, byDocument.author.constructor.name);
// → ObjectId ObjectId
try {
  await Posts.create({ title: "p3", author: "zz" });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to ObjectId failed at path "author" for "zz" (string): not a 24-character hex string [format]
```

То же самое в обновлениях (`$set: { author: ann }`), фильтрах (`find({ author: ann })`), массивах ссылок и значениях `Map` ссылок. Везде документ превращается в свой `_id`.

Обратите внимание, Typemo не проверяет, что документ с таким идентификатором **существует**. Ссылка на несуществующего автора запишется, ведь внешних ключей в MongoDB нет. Если это важно, проверьте существование сами перед записью или в транзакции.

## Получить связанный документ

[`populate`](../reference/populate/populate.mdx#populate) подставляет в результат документ вместо идентификатора. В базе значение при этом не меняется. Если документа с таким идентификатором нет, на месте ссылки окажется `null`.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
@Schema({ collection: "authors" })
class Author extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Types.ObjectId, { ref: () => Author, required: true }) author!: Ref<Author>;
}
const Authors = client.connection.model(Author);
const Posts = client.connection.model(Post);
const ann = await Authors.create({ name: "Ann" });
await Posts.create({ title: "Hello", author: ann._id });
await Posts.create({ title: "Orphan", author: new Types.ObjectId() });
// ---cut---
const post = await Posts.findOne({ title: "Hello" }).populate("author").orFail();
console.log(post.author?.name);
// → Ann
const orphan = await Posts.findOne({ title: "Orphan" }).populate("author").orFail();
console.log(orphan.author);
// → null
```

После `populate` меняется и тип поля. Компилятор знает, что там теперь документ автора, а не идентификатор. Как подтягивать несколько уровней и как это сказывается на скорости, описано в разделе [Связанные данные](../populate/basics.mdx).

## Ссылаться на разные модели

Бывает, что одно поле указывает на документы разных моделей. Скажем, комментарий относится либо к посту, либо к автору. Для этого есть два способа.

- [`refPath`](../reference/schemas/prop.mdx#refpath) — путь к полю **того же документа**, где лежит имя класса целевой модели.
- [`refModel`](../reference/schemas/prop.mdx#refmodel) — функция, которая сама выбирает класс.

Поле объявляют как `Ref<A | B>`, и обе модели должны быть получены на подключении.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
@Schema({ collection: "authors" })
class Author extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Schema({ collection: "bots" })
class Bot extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) kind!: string;
  @Prop(() => Types.ObjectId, { refPath: "kind", required: true }) // [!code highlight]
  target!: Ref<Author | Bot>;
}
const Authors = client.connection.model(Author);
const Bots = client.connection.model(Bot);
const Comments = client.connection.model(Comment);
const bot = await Bots.create({ name: "R2" });
await Comments.create({ kind: "Bot", target: bot._id });
// ---cut---
const comment = await Comments.findOne({ kind: "Bot" }).populate("target").orFail();
console.log((comment.target as { name?: string }).name);
// → R2
```

`ref`, `refPath` и `refModel` исключают друг друга. Две опции сразу дают `ConfigurationError` — `"ref", "refPath" and "refModel" are exclusive (one form of reference)`.

## Ссылка в массиве

Список ссылок — это массив идентификаторов, `@Prop(() => [Types.ObjectId], { ref: () => Author })` с типом `Ref<Author>[]`. Опция `ref` относится к каждому элементу, и `populate` заменит их все. Правила и проверки массивов описаны в руководстве [Массивы](./arrays.mdx).

## Ссылаться на модель со своим `_id`

Если `_id` целевой модели не `ObjectId`, его тип называют вторым параметром `Ref`, а первым аргументом `@Prop` идёт тот же тип. Например, `@Prop(() => String, { ref: () => Country }) country?: Ref<Country, string>` для страны со строковым кодом или `Ref<Session, UUID>[]` для массива `UUID`. Всё остальное, включая `populate`, работает так же. Такие модели описаны в руководстве [Свой тип _id](./custom-ids.mdx).

## Как выбрать

Спросите себя — **связанные данные читаются всегда вместе или по отдельности?**

- **Автор нужен почти в каждом ответе, данных у него немного, и они почти не меняются** — подумайте о [вложенном объекте](./nested-and-subdocuments.mdx). Копия избавит от второго запроса.
- **Данные общие, растут или меняются** — храните ссылку. Запись автора обновится в одном месте.
- **Нужен обратный путь, «все посты автора»** — список у автора не хранят, а описывают [виртуальную связь](./virtuals.mdx).

## Когда это не нужно

Целостности ссылка не гарантирует. MongoDB не удалит посты, когда удалён автор. Каскадное удаление и проверка существования — дело кода приложения или транзакции ([Транзакции](../transactions/transactions.mdx)). А идентификатору из внешней системы, по которому вы не собираетесь подтягивать документы, `ref` не нужен. Хватит поля типа `Types.ObjectId` или `String`.

## Если что-то пошло не так

**Идентификатор неверной формы.** `create({ author: "zz" })` даёт `CastError` с причиной `format` — `Cast to ObjectId failed at path "author" for "zz" (string): not a 24-character hex string [format]`. Библиотека не угадывает идентификатор и не шлёт в базу то, что идентификатором быть не может. Передайте `ObjectId`, его шестнадцатеричную строку или документ автора.

**`ref` и `Ref<M>` не согласованы.** Компилятор следит за парой и выдаёт одно из сообщений — `@Prop "author": "ref" is set, but the field type is not Ref<Model>`, `the field is Ref<Model>, add ref: () => Model` или `"ref" points to another model than the field's Ref<Model>`. Тип результата после `populate` выводится из `Ref<M>`, и расхождение дало бы неверные типы.

## Полный пример

В одном файле автор, пост со ссылкой и чтение с `populate`. Код, которого нет в Typemo, помечен `__…__`.

```ts twoslash title="blog/posts.service.ts"
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
// модели: пост ссылается на автора идентификатором
@Schema({ collection: "authors" })
class Author extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}

@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Types.ObjectId, { ref: () => Author, required: true }) author!: Ref<Author>;
}

// код читателя: ошибка на границе приложения
class __NotFound__ extends Error {}

// публикация: идентификатор автора приходит строкой из адреса
export const publish = async (authorId: string, title: string) => {
  const Posts = client.connection.model(Post);
  return Posts.create({ title, author: authorId });
};

// чтение: автор подтягивается запросом
export const readPost = async (title: string) => {
  const Posts = client.connection.model(Post);
  const post = await Posts.findOne({ title }).populate("author").orFail();
  if (post.author === null) throw new __NotFound__("author is missing");
  return { title: post.title, author: post.author.name };
};

const ann = await client.connection.model(Author).create({ name: "Ann" });
await publish(ann._id.toHexString(), "Hello");
console.log(await readPost("Hello"));
// → { title: "Hello", author: "Ann" }
```

<Callout type="migration">

В Mongoose `ref` задают строкой с именем модели. В Typemo `ref` — функция, которая возвращает класс. Документ в поле-ссылке, как и в Mongoose, превращается в свой `_id`, но хранится ссылка всегда одинаково, идентификатором. Пару `ref` и `Ref<M>` проверяет компилятор, поэтому тип поля после `populate` выводится точно.

</Callout>
