Документы разных коллекций связывают **ссылкой**: пост хранит не копию автора, а его `_id`. Так имя автора хранится в одном месте и меняется одной записью. В Typemo ссылка — обычное поле с типом идентификатора, к которому добавлена опция [`ref`](../reference/schemas/prop.mdx#ref) и маркерный тип [`Ref<M>`](../reference/schemas/field-markers.mdx#ref). Они говорят библиотеке и компилятору, на какую модель указывает поле, и открывают возможность заполнить связь: подтянуть документ автора запросом [`populate`](../reference/populate/populate.mdx#populate).

Ссылка всегда хранится в **одной форме** — идентификатором. Сам документ автора внутри поста никогда не лежит: после `populate` он появляется только в результате чтения, а в базе остаётся идентификатор. Если при записи передать документ автора вместо идентификатора, в базу всё равно уходит его `_id`.

## Что предполагается

Модель описана по руководству [Описать модель](./define-model.mdx). Примеры строят блог: автор и его посты. Заполнение связей подробно описывает раздел [Связанные данные](../populate/basics.mdx).

## Быстрый путь

Поле-ссылка объявляется идентификатором с `ref` и типом `Ref<Author>`:

```ts twoslash title="blog/post.ts"
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
@Schema({ collection: "authors" })
class Author extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}

@Schema({ collection: "posts" })
export class Post extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Types.ObjectId, { ref: () => Author, required: true })
  author!: Ref<Author>;
}

const Authors = client.connection.model(Author);
const Posts = client.connection.model(Post);
const ann = await Authors.create({ name: "Ann" });
const post = await Posts.create({ title: "Hello", author: ann._id });
console.log(post.author.constructor.name);
// → ObjectId
```

`ref` — **функция**, возвращающая класс: так модель, объявленная ниже по файлу или в другом модуле, успевает появиться к моменту сборки. Остальная страница разбирает, что можно записать в поле и как получить связанный документ.

## Записать ссылку

Поле-ссылка принимает идентификатор в трёх видах: значение `ObjectId`, его строку из 24 шестнадцатеричных символов и сам документ модели (гидратированный, `lean` или экземпляр класса). Строка удобна, когда идентификатор пришёл из адреса запроса, а документ — когда он уже в руках и незачем доставать `_id`. В базу во всех трёх случаях уходит идентификатор.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
@Schema({ collection: "authors" })
class Author extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Types.ObjectId, { ref: () => Author, required: true }) author!: Ref<Author>;
}
const Authors = client.connection.model(Author);
const Posts = client.connection.model(Post);
const ann = await Authors.create({ name: "Ann" });
// ---cut---
const byString = await Posts.create({ title: "p1", author: ann._id.toHexString() });
const byDocument = await Posts.create({ title: "p2", author: ann }); // [!code highlight]
console.log(byString.author.constructor.name, byDocument.author.constructor.name);
// → ObjectId ObjectId
try {
  await Posts.create({ title: "p3", author: "zz" });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to ObjectId failed at path "author" for "zz" (string): not a 24-character hex string [format]
```

То же верно для обновлений (`$set: { author: ann }`), фильтров (`find({ author: ann })`), массивов ссылок и значений `Map` ссылок: везде документ превращается в свой `_id`. Обратите внимание: Typemo не проверяет, что документ с таким идентификатором **существует**. Ссылка на несуществующего автора запишется, как в самой MongoDB, где нет внешних ключей. Если это важно, проверьте существование сами перед записью или в транзакции.

## Получить связанный документ

Запрос [`populate`](../reference/populate/populate.mdx#populate) заменяет идентификатор в результате документом. В базе значение при этом не меняется. Если документа по идентификатору нет, на месте ссылки будет `null`.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
@Schema({ collection: "authors" })
class Author extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Types.ObjectId, { ref: () => Author, required: true }) author!: Ref<Author>;
}
const Authors = client.connection.model(Author);
const Posts = client.connection.model(Post);
const ann = await Authors.create({ name: "Ann" });
await Posts.create({ title: "Hello", author: ann._id });
await Posts.create({ title: "Orphan", author: new Types.ObjectId() });
// ---cut---
const post = await Posts.findOne({ title: "Hello" }).populate("author").orFail();
console.log(post.author?.name);
// → Ann
const orphan = await Posts.findOne({ title: "Orphan" }).populate("author").orFail();
console.log(orphan.author);
// → null
```

Тип поля после `populate` меняется: компилятор знает, что там документ автора, а не идентификатор. Как заполнять несколько уровней и как это влияет на скорость, описано в разделе [Связанные данные](../populate/basics.mdx).

## Ссылаться на разные модели

Иногда одно поле может указывать на документы разных моделей: комментарий относится либо к посту, либо к автору. Для этого есть [`refPath`](../reference/schemas/prop.mdx#refpath) — путь к полю **того же документа**, где лежит имя класса целевой модели, и [`refModel`](../reference/schemas/prop.mdx#refmodel) — функция, которая сама выбирает класс. Поле объявляется как `Ref<A | B>`, а обе модели должны быть получены на подключении.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
@Schema({ collection: "authors" })
class Author extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Schema({ collection: "bots" })
class Bot extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) kind!: string;
  @Prop(() => Types.ObjectId, { refPath: "kind", required: true }) // [!code highlight]
  target!: Ref<Author | Bot>;
}
const Authors = client.connection.model(Author);
const Bots = client.connection.model(Bot);
const Comments = client.connection.model(Comment);
const bot = await Bots.create({ name: "R2" });
await Comments.create({ kind: "Bot", target: bot._id });
// ---cut---
const comment = await Comments.findOne({ kind: "Bot" }).populate("target").orFail();
console.log((comment.target as { name?: string }).name);
// → R2
```

`ref`, `refPath` и `refModel` взаимоисключающие: две из них сразу — `ConfigurationError`: `"ref", "refPath" and "refModel" are exclusive (one form of reference)`.

## Ссылка в массиве

Список ссылок — массив идентификаторов: `@Prop(() => [Types.ObjectId], { ref: () => Author })` с типом `Ref<Author>[]`. Опция `ref` относится к каждому элементу; `populate` заменит их все. Правила массива и его проверки описаны в руководстве [Массивы](./arrays.mdx).

## Ссылаться на модель со своим `_id`

Если у целевой модели `_id` не `ObjectId`, второй параметр `Ref` называет его тип, а первый аргумент `@Prop` — тот же тип: `@Prop(() => String, { ref: () => Country }) country?: Ref<Country, string>` для страны со строковым кодом или `Ref<Session, UUID>[]` для массива `UUID`. Всё остальное, включая `populate`, работает так же. Такие модели описаны в руководстве [Свой тип _id](./custom-ids.mdx).

## Как выбрать

Задайте себе один вопрос: **читаете ли вы связанные данные всегда вместе или по отдельности?** Если автор нужен почти в каждом ответе, а его данные небольшие и почти не меняются, рассмотрите [вложенный объект](./nested-and-subdocuments.mdx): копия избавит от второго запроса. Если данные общие, растут или меняются, храните ссылку: одна запись автора обновляется в одном месте. Если нужен обратный путь, «все посты автора», у автора не хранят список, а описывают [виртуальную связь](./virtuals.mdx).

## Когда это не нужно

Ссылка не гарантирует целостности: MongoDB не удалит посты, когда удалён автор. Для каскадных удалений и проверки существования нужен код приложения или транзакция ([Транзакции](../transactions/transactions.mdx)). Идентификатор из внешней системы, по которому вы не собираетесь подтягивать документы, `ref` не требует: достаточно поля типа `Types.ObjectId` или `String`.

## Частые ошибки

### Идентификатор неверной формы

`create({ author: "zz" })` — `CastError` с причиной `format`: `Cast to ObjectId failed at path "author" for "zz" (string): not a 24-character hex string [format]`. Библиотека не пытается угадать идентификатор и не отправляет в базу то, что им не является. Передайте `ObjectId`, его шестнадцатеричную строку или документ автора.

### `ref` и `Ref<M>` не согласованы

Компилятор следит за парой: `@Prop "author": "ref" is set, but the field type is not Ref<Model>`, `the field is Ref<Model>, add ref: () => Model` и `"ref" points to another model than the field's Ref<Model>`. Причина в том, что тип результата после `populate` выводится из `Ref<M>`, и расхождение дало бы неверные типы.

## Полный пример

Один файл собирает автора, пост со ссылкой и чтение с заполнением. Код читателя, которого нет в Typemo, помечен `__…__`.

```ts twoslash title="blog/posts.service.ts"
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
// модели: пост ссылается на автора идентификатором
@Schema({ collection: "authors" })
class Author extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}

@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Types.ObjectId, { ref: () => Author, required: true }) author!: Ref<Author>;
}

// код читателя: ошибка на границе приложения
class __NotFound__ extends Error {}

// публикация: идентификатор автора приходит строкой из адреса
export const publish = async (authorId: string, title: string) => {
  const Posts = client.connection.model(Post);
  return Posts.create({ title, author: authorId });
};

// чтение: автор подтягивается запросом
export const readPost = async (title: string) => {
  const Posts = client.connection.model(Post);
  const post = await Posts.findOne({ title }).populate("author").orFail();
  if (post.author === null) throw new __NotFound__("author is missing");
  return { title: post.title, author: post.author.name };
};

const ann = await client.connection.model(Author).create({ name: "Ann" });
await publish(ann._id.toHexString(), "Hello");
console.log(await readPost("Hello"));
// → { title: "Hello", author: "Ann" }
```

<Callout type="migration">

В Mongoose `ref` задают строкой с именем модели. В Typemo `ref` — функция, возвращающая класс. Документ в поле-ссылке, как и в Mongoose, превращается в свой `_id`, но хранится ссылка всегда одной формы, идентификатором. Пара `ref` и `Ref<M>` проверяется компилятором, поэтому тип поля после `populate` выводится точно.

</Callout>
