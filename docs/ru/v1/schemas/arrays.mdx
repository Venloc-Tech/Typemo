Массив в схеме объявляют квадратными скобками вокруг типа элемента. `[String]` — список строк, `[Line]` — список поддокументов, `[[Number]]` — список списков чисел. Опции типа элемента (`enum`, `min`, `match`) относятся к каждому элементу. А сам массив Typemo проверяет целиком. Значение обязано быть массивом, и каждый элемент проходит своё приведение и правила. В пути ошибки есть позиция элемента, так что сразу видно, какой подвёл.

Как менять массив в загруженном документе (`push`, `pull`, `set`), рассказывает руководство [Массивы и Map в документе](../documents/typed-collections.mdx). Здесь мы объявляем схему и смотрим, что делает сама библиотека при записи и поиске.

## Что понадобится

Модель, описанная по руководству [Описать модель](./define-model.mdx), и поддокументы из руководства [Вложенные объекты и поддокументы](./nested-and-subdocuments.mdx). Примеры строят заказ магазина с метками и строками.

## Быстрый путь

Массив значений — `[String]`, массив поддокументов — `[Line]`, где `Line` — класс с `@Schema`.

```ts twoslash title="orders/order.ts"
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 1 }) qty!: number;
}

@Schema({ collection: "orders" })
export class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => [String])
  tags!: string[];

  @Prop(() => [Line])
  lines!: Line[];
}

const Orders = client.connection.model(Order);
const order = await Orders.create({
  customer: "ann",
  tags: ["gift"],
  lines: [{ sku: "A1", qty: 2 }],
});
console.log(order.$toPlain().lines.length, order.tags.length);
// → 1 1
```

Каждая строка заказа получила свой `_id`, потому что `Line` наследует `Entity`. Ниже разберём правила для элементов, пустые массивы и поиск.

## Проверить элементы

Каждый элемент приводится к типу элемента, и ошибка называет его позицию. Если вместо массива пришло что-то другое, ошибка так и скажет, что нужен массив. Превращать строку в список из одного элемента библиотека не станет, такая «помощь» спрятала бы ошибку в данных.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 1 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
}
const Orders = client.connection.model(Order);
// ---cut---
try {
  await Orders.create({ customer: "ann", tags: ["a", 5 as never], lines: [] });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to string failed at path "tags.1" for 5 (number): expected a string [type]
try {
  await Orders.create({ customer: "ann", tags: "a" as never, lines: [] });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to Array<string> failed at path "tags" for "a" (string): expected an array [type]
try {
  await Orders.create({ customer: "ann", tags: [], lines: [{ sku: "A", qty: 0 }, { qty: 1 } as never] });
} catch (error) {
  console.log((error as Error).message);
}
// → Validation failed: "lines.0.qty": must be at least 1 [min]; "lines.1.sku": the field is required [required]
```

В путях `tags.1` и `lines.0.qty` есть индекс элемента, а у поддокументов — ещё и имя поля внутри. `null` в массиве строк — тоже ошибка, `Cast to string failed at path "tags.1" for null: null is not allowed on a path that is not nullable [null]`.

## Ограничить значения элементов

Опции элемента ставятся на массив и действуют на каждый элемент. Для `enum` элементы объявляют объединением значений, для чисел работают `min` и `max`.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => [String], { enum: ["new", "sale"] as const }) // [!code highlight]
  labels?: ("new" | "sale")[];

  @Prop(() => [Number], { min: 1 }) // [!code highlight]
  ratings?: number[];
}
const Products = client.connection.model(Product);
try {
  await Products.create({ labels: ["new", "hot" as never], ratings: [5, 0] });
} catch (error) {
  console.log((error as Error).message);
}
// → Validation failed: "labels.1": must be one of "new", "sale" [enum]; "ratings.1": must be at least 1 [min]
```

Ограничения на сам массив, вроде числа элементов или непустоты, опциями не задаются. Чтобы потребовать хотя бы один элемент, напишите проверку через [`validate`](./validation.mdx) на поле-массиве.

## Вложить массив в массив

Массив внутри массива объявляют вложенными скобками, `[[Number]]`. Глубина не ограничена. Каждый уровень проверяется отдельно, а ошибка указывает позицию на нужном уровне.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
@Schema({ collection: "boards" })
class Board extends Entity {
  @Prop(() => [[Number]]) // [!code highlight]
  cells?: number[][];
}
const Boards = client.connection.model(Board);
const board = await Boards.create({ cells: [[1, 2], [3]] });
console.log(board.$toPlain().cells);
// → [[1, 2], [3]]
try {
  await Boards.create({ cells: [[1], "x"] as never });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to Array<number> failed at path "cells.1" for "x" (string): expected an array [type]
```

## Пустой массив по умолчанию

Поле-массив без `required` и без `default` **само становится пустым**. `create`, `Model.new`, вставка через upsert и новый поддокумент кладут `[]`, если вы не передали значение. Так тип в классе (`tags!: string[]`) говорит правду — список есть всегда. Объявлять `default: () => []` или `Defaulted<string[]>` не нужно. Запрещать их никто не запрещает, свой `default` просто заменит пустой массив.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) // [!code highlight]
  tags!: string[];
}
const Orders = client.connection.model(Order);
const order = await Orders.create({ customer: "ann" });
console.log(order.tags.length);
// → 0
const plain = await Orders.findById(order._id).orFail().lean();
console.log(plain.tags);
// → []
```

`[]` лежит и в базе. Значение пишется вместе с документом, а не подставляется при чтении. В `CreateInput` массив необязателен, поэтому `Orders.create({ customer: "ann" })` компилируется без `tags`.

**Старые документы**, у которых в базе нет ключа массива, читаются по-разному. Документ модели даёт пустой массив, и следующий `$save` запишет его в базу. `lean()` отдаёт документ как он хранится, то есть без ключа.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
@Schema({ collection: "legacy_orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
}
const Orders = client.connection.model(Order);
// ---cut---
await client.unsafeDriver().db("shop").collection("legacy_orders").insertOne({ customer: "old" });

const doc = await Orders.findOne({ customer: "old" }).orFail();
console.log(doc.tags.length);
// → 0
const lean = await Orders.findOne({ customer: "old" }).orFail().lean();
console.log("tags" in lean);
// → false
```

Если массив нужно передавать всегда, объявите его `required: true`. Такое поле пустого массива по умолчанию не получает, и `create` без него бросит `ValidationError` (`Validation failed: "tags": the field is required [required]`). Пустой массив считается переданным значением. Непустоту `required` не проверяет, для неё нужна своя проверка [`validate`](./validation.mdx).

## Искать по элементам

Путь через массив пишется так же, как для вложенного объекта. `"lines.sku"` находит заказы, где хотя бы у одной строки такой `sku`. Значение по этому пути приводится по типу элемента. Добавить элемент можно и оператором обновления `$push`. Новый элемент проверяется по тем же правилам, а в пути ошибки перед индексом стоит `+`, ведь в базе этого элемента ещё нет.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 1 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
}
const Orders = client.connection.model(Order);
await Orders.create({ customer: "bob", tags: [], lines: [{ sku: "B", qty: 2 }] });
// ---cut---
const found = await Orders.find({ "lines.sku": "B" }).plain();
console.log(found.length);
// → 1
await Orders.updateOne({ customer: "bob" }, { $push: { tags: "vip" } });
console.log((await Orders.findOne({ customer: "bob" }).plain())?.tags);
// → ["vip"]
try {
  await Orders.updateOne({ customer: "bob" }, { $push: { lines: { sku: "Z", qty: 0 } } } as never);
} catch (error) {
  console.log((error as Error).message);
}
// → Validation failed: "lines.+0.qty": must be at least 1 [min]
```

## Как выбрать

Спросите себя — **нужно ли находить и менять отдельный элемент по идентификатору?**

- **Нет** (метки, оценки, адреса почты) — массив значений, `[String]` или `[Number]`.
- **Да** (строка заказа, комментарий) — массив поддокументов с `Entity`. У каждого элемента будет `_id`.
- **Элементов может стать очень много, или они живут своей жизнью** — вынесите их в отдельную коллекцию со ссылкой ([Ссылки на другие модели](./references.mdx)).

## Когда это не нужно

Набор значений, где важна уникальность, а порядок нет, тоже хранят массивом. Добавлять в него удобно методом `addToSet` при работе с [документом](../documents/typed-collections.mdx). Отдельного типа «множество» нет, и `Set` как тип поля не поддерживается. Словарь с заранее неизвестными ключами — это не массив, а [`Spec.map`](./maps.mdx). Кортеж фиксированной длины лучше описать вложенным объектом с именованными полями.

## Если что-то пошло не так

**Присваивание по индексу не компилируется.** `order.tags[0] = "x"` на загруженном документе компилятор остановит. По индексу не понять, что вы хотели сделать, а запись массива целиком затёрла бы чужие правки. Пользуйтесь методами коллекции (см. [Массивы и Map в документе](../documents/typed-collections.mdx)).

**Строка вместо массива.** `tags: "gift"` даёт `CastError`, а не список из одного элемента. Библиотека не угадывает намерения. Оберните значение сами — `tags: ["gift"]`.

**Ждали ошибку из-за отсутствующего массива.** Документ создан без `tags`, а ошибки нет, Typemo положил `[]`. Поле-массив без `required` необязательно, и пустой список для него — обычное начальное значение. Если список должен прийти от вызывающего кода, объявите поле с `required: true`. Если он должен быть непустым, добавьте проверку [`validate`](./validation.mdx).

## Полный пример

В одном файле заказ с метками, строками и вложенным массивом. Код, которого нет в Typemo, помечен `__…__`.

```ts twoslash title="orders/orders.service.ts"
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
// поддокумент: строка заказа со своим _id
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 1 }) qty!: number;
}

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String], { enum: ["gift", "urgent"] as const })
  tags!: ("gift" | "urgent")[];
  @Prop(() => [Line]) lines!: Line[];
}

// код читателя: ошибка на границе приложения
class __BadRequest__ extends Error {}

// создание заказа со строками
export const placeOrder = async (customer: string, lines: { sku: string; qty: number }[]) => {
  const Orders = client.connection.model(Order);
  try {
    return await Orders.create({ customer, lines });
  } catch (error) {
    throw new __BadRequest__((error as Error).message);
  }
};

// поиск заказов, где есть строка с товаром
export const ordersWith = async (sku: string) => {
  const Orders = client.connection.model(Order);
  return Orders.find({ "lines.sku": sku }).plain();
};

await placeOrder("cid", [{ sku: "F1", qty: 2 }]);
console.log((await ordersWith("F1")).length);
// → 1
```

<Callout type="migration">

В Mongoose непереданный массив становится пустым `[]`, и в Typemo так же, отдельный `default: () => []` не нужен. Обязательным массив делает опция `required: true`. Присваивание по индексу и запись в `length` у загруженного документа закрыты типами. Меняйте массив методами, тогда в базу уйдёт точная операция.

</Callout>
