Некоторые данные задаются один раз и больше не меняются. Страна, где открыт счёт, номер во внешней системе, дата создания. Если такое поле можно изменить, однажды его изменит случайное обновление или ошибка в коде. И вы не заметите, пока не разойдутся отчёты. Опция [`immutable: true`](../reference/schemas/prop.mdx#immutable) и тип [`Immutable<T>`](../reference/schemas/field-markers.mdx#immutable) закрывают эту дыру. Значение пишется при создании документа, а любая попытка его изменить — ошибка.

`_id` и `createdAt` устроены так же, их неизменяемость задаёт та же опция.

## Что понадобится

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель счёта из файла `accounts/account.ts`.

## Быстрый путь

Поле объявляется парой — опция `immutable: true` и тип `Immutable<T>`. Компилятор проверяет, что они идут вместе, и не пускает такое поле в оператор обновления.

```ts twoslash title="accounts/account.ts"
import { Entity, type Defaulted, type Immutable, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { immutable: true }) // [!code highlight]
  country?: Immutable<string>;
}

const Accounts = client.db().model(Account);
await Accounts.create({ country: "PL" });
// @errors: 2769
await Accounts.updateOne({ country: "PL" }, { $set: { country: "DE" } });
```

Ниже разберём, что именно запрещено и как обойти запрет там, где это законно.

## Что запрещено после создания

Запрещена любая запись, которая меняет неизменяемый путь, в том числе его удаление и замена родителя. Проверка идёт во время работы, так что через неё проходят и обновления, собранные без типов. Ошибка всегда одна — [`StrictModeError`](../reference/errors/data-errors.mdx#strictmodeerror) с причиной `immutable`, а в тексте указаны оператор и путь.

```ts twoslash title="accounts/accounts.service.ts"
import { Entity, type Defaulted, type Immutable, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { immutable: true }) country?: Immutable<string>;
  @Prop(() => Number, { default: 0 }) balance!: Defaulted<number>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const account = await Accounts.create({ country: "PL" });
try {
  await Accounts.updateOne({ _id: account._id }, { $set: { country: "DE" } } as never);
} catch (error) {
  console.log((error as Error).message);
}
// → $set.country: "country" is immutable; it is written only when the document is created ($setOnInsert on upsert) [immutable]
```

Тот же текст, только с другим оператором, дадут `$unset`, [`findOneAndUpdate`](../reference/writes/writes.mdx#findoneandupdate), `bulkWrite` и [`$save`](../reference/documents/document-api.mdx#save). Присваивание `account.country = "DE"` сразу ошибку не бросит, но сохранить такой документ не выйдет. Пути внутри поддокументов защищены так же. Замена целого поддокумента с неизменяемым полем тоже не пройдёт — `$set.address: "address.country" is immutable; …`.

Обычные поля того же документа меняются как всегда, `$inc` по `balance` проходит. Защита точечная и касается только помеченных путей.

## Записать значение при создании

Значение неизменяемого поля пишется, когда документ создаётся. Если документ создаёт обновление с `upsert`, передайте значение через `$setOnInsert`. Этот оператор срабатывает только при вставке, и неизменяемость им не нарушить. `$set` с `upsert` для такого поля даст ту же ошибку.

```ts twoslash title="accounts/accounts.service.ts"
import { Entity, type Defaulted, type Immutable, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { immutable: true }) country?: Immutable<string>;
  @Prop(() => Number, { default: 0 }) balance!: Defaulted<number>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
await Accounts.updateOne({ balance: 0 }, { $setOnInsert: { country: "FR" } }, { upsert: true });
// создан документ со country: "FR"; следующий upsert по нему country не тронет
```

## Заменить документ целиком

[`replaceOne`](../reference/writes/writes.mdx#replaceone) переписывает документ целиком. Поэтому про неизменяемое поле замена обязана сказать то же, что уже хранится. Если поле в документе есть — то же значение, если нет — ничего. Сохранённый документ знает только сервер, так что Typemo добавляет это условие в фильтр замены, и сервер сравнивает значения в той же операции.

Если замена расходится с документом, она не запишется.

- Другое значение — `a replacement of Account changes the immutable field "country"; the document was not replaced. Carry the stored value [immutable]`.
- Поле есть в документе, но его нет в замене — `without the immutable field "country" would drop it from the stored document`.
- Замена добавляет поле, которого в документе нет, — `sets the immutable field "country", which the stored document does not have`.

Необязательное неизменяемое поле, которого нет ни в замене, ни в документе, замене не мешает. Так же проверяются [`findOneAndReplace`](../reference/writes/writes.mdx#findoneandreplace) и `replaceOne` в `bulkWrite`. Подробности и `upsert` — в руководстве [Заменить документ](../writes/replace.mdx#замена-расходится-с-полем-immutable). А `_id` в замене запрещён всегда, даже прежний — `a replacement of Account carries "_id": a replacement keeps the stored _id and cannot change it; leave "_id" out and select the document by _id in the filter [immutable]`.

Обновление-конвейер ([`UpdatePipelines`](../reference/writes/pipeline-updates.mdx#updatepipelines)) проверяется так же строго. `set` неизменяемого поля даёт `StrictModeError` (`update.0.$set.country: "country" is immutable; …`). Стадию `replaceWith`, которая теряет такое поле, Typemo отвергнет и подскажет перенести поле как есть — `$replaceWith rewrites the whole document and would change or drop the immutable fields country; carry each unchanged (country: "$country") or use $set/$unset of the other fields [immutable]`.

## Как выбрать

Спросите себя — **может ли это значение когда-нибудь законно стать другим?**

- **Нет** (страна регистрации, внешний идентификатор) — `immutable`.
- **Меняется редко, но бывает** (адрес) — оставьте обычное поле, а историю изменений ведите [аудитом](../policies/audit.mdx).
- **Менять нельзя только определённым ролям** — это правило приложения, а не схемы.

## Когда это не нужно

`immutable` защищает от обновлений через Typemo. От прямой записи в базу и от операций драйвера через [`client.unsafeDriver`](../reference/connection/typemo-client.mdx#clientunsafedriver) он не спасёт, они обходят все политики. А для полей, которые вы иногда правите руками, запрет будет только мешать. Там лучше обычное поле и аудит.

## Если что-то пошло не так

**Опция без типа.** Опция и тип идут парой. Если поле объявлено обычным типом, компилятор ответит `@Prop "country": "immutable" is set, declare the field as Immutable<T>`. А на `Immutable<T>` без опции — `@Prop "country": the field is Immutable<T>, add immutable: true`. Так тип результата не расходится с поведением записи.

**Нужно исправить опечатку в неизменяемом поле.** Обновление отвергнуто, а значение надо поправить. Через модель это нельзя, и так задумано. Исправьте значение разовым скриптом через [`client.unsafeDriver`](../reference/connection/typemo-client.mdx#clientunsafedriver) или пересоздайте документ.

**Upsert падает на `$set`.** Если upsert должен создавать документ с неизменяемым полем, перенесите это поле из `$set` в `$setOnInsert`.

## Полный пример

```ts twoslash title="accounts/accounts.service.ts"
import { Entity, type Defaulted, type Immutable, Prop, Schema, TypemoClient } from "@venloc/typemo";

@Schema({ collection: "accounts" })
class Account extends Entity {
  // страна регистрации не меняется никогда
  @Prop(() => String, { immutable: true })
  country?: Immutable<string>;

  @Prop(() => Number, { default: 0 })
  balance!: Defaulted<number>;
}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);

// открытие: страна пишется при создании
export const open = async (country: string) => Accounts.create({ country });

// пополнение: обычное поле меняется свободно
export const deposit = async (id: Account["_id"], amount: number) =>
  Accounts.updateOne({ _id: id }, { $inc: { balance: amount } });
```
