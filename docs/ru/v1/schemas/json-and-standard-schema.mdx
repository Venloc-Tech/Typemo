Схема модели описывает данные один раз, а пригодиться может ещё в двух форматах.

- **JSON Schema** — формат, которым MongoDB проверяет документы на сервере. Из схемы строится валидатор коллекции, и сервер отвергает неверные документы, даже если их пишет другая программа.
- **Standard Schema** — общий интерфейс проверки значений, который понимают формы, роутеры API и другие библиотеки. Каждая модель — сама такой валидатор, так что вход можно проверять, ничего не зная о Typemo.

Работает и обратное. Запрос может проверить свои результаты чужой схемой.

## Что понадобится

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель пользователя из файла `users/user.ts`. У неё имя с проверками и роль из двух значений.

## Быстрый путь

Валидатор на сервере включает опция `validator: true`, а вход проверяет свойство модели `~standard`.

```ts twoslash title="users/signup.ts"
import { Entity, type Defaulted, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "users", validator: true })
class User extends Entity {
  @Prop(() => String, { required: true, trim: true, lowercase: true, minLength: 3 })
  name!: string;
  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" })
  role!: Defaulted<"user" | "admin">;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
await client.db().init(); // коллекция создаётся с серверным валидатором

const result = await Users["~standard"].validate({ name: " Zed " });
console.log(result);
// → { value: { _id: "…", name: "zed", role: "user" } }
```

Ниже разберём оба направления.

## Проверять на сервере

Опция [`validator`](../reference/schemas/schema.mdx#validator) строит из схемы `$jsonSchema` и отдаёт её серверу при создании коллекции. Валидатор — второй рубеж. Проверки Typemo остаются на месте, а сервер защищает данные от чужих программ и от записи в обход Typemo. Что получил сервер, можно посмотреть через драйвер, для этого нужен [`client.unsafeDriver`](../reference/connection/typemo-client.mdx#clientunsafedriver).

```ts twoslash title="users/inspect-validator.ts"
import { Entity, type Defaulted, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "users", validator: true })
class User extends Entity {
  @Prop(() => String, { required: true, trim: true, lowercase: true, minLength: 3 })
  name!: string;
  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" })
  role!: Defaulted<"user" | "admin">;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
await client.db().init();
const [info] = await client.unsafeDriver().db("app").listCollections({ name: "users" }, { nameOnly: false }).toArray();
console.log(JSON.stringify(info?.options?.validator));
// → {"$jsonSchema":{"bsonType":"object","properties":{"_id":{"bsonType":"objectId"},"name":{"bsonType":"string","minLength":3},"role":{"bsonType":"string","enum":["user","admin"]}},"required":["_id","name"],"additionalProperties":false}}
```

Правила построения видны в результате. Тип поля превращается в `bsonType`, `required` собирается из обязательных полей и `_id`, а `enum` и границы длины переносятся как есть. Строгость абсолютная — `additionalProperties: false` на каждом уровне, так что лишнее поле сервер отвергнет.

Свои функции `validate`, границы дат и правила ключей Map сервер выразить не может. Их проверяет только Typemo. Уровень и действие настраивают опции [`validationLevel`](../reference/schemas/schema.mdx#validationlevel) и [`validationAction`](../reference/schemas/schema.mdx#validationaction). Подробнее — в руководстве [Особые коллекции](./special-collections.mdx#валидатор-на-сервере).

Тот же документ можно получить в коде, не создавая коллекции. [`JsonSchemaGenerator.generate`](../reference/schemas/json-and-standard-schema.mdx#jsonschemageneratorgenerate) принимает модель (или её `schema`) и возвращает `$jsonSchema`. А [`JsonSchemaGenerator.validator`](../reference/schemas/json-and-standard-schema.mdx#jsonschemageneratorvalidator) возвращает всё, что уходит серверу, — валидатор, уровень и действие.

```ts twoslash title="users/inspect-validator.ts"
import { Entity, type Defaulted, JsonSchemaGenerator, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "users", validator: true })
class User extends Entity {
  @Prop(() => String, { required: true, trim: true, lowercase: true, minLength: 3 })
  name!: string;
  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" })
  role!: Defaulted<"user" | "admin">;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
console.log(JsonSchemaGenerator.generate(Users).required);
// → ["_id", "name"]
const { validationLevel, validationAction } = JsonSchemaGenerator.validator(Users);
console.log(validationLevel, validationAction);
// → strict error
```

## Проверить вход через Standard Schema модели

У модели есть свойство `~standard`. На входе то, что принимает `create`, на выходе приведённые данные. Проверка приводит типы, обрезает пробелы и переводит в нижний регистр по опциям поля, подставляет значения по умолчанию, запускает `required` и все `validate`. В ответ она возвращает либо значение, либо список проблем с путями.

```ts twoslash title="users/signup.ts"
import { Entity, type Defaulted, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "users", validator: true })
class User extends Entity {
  @Prop(() => String, { required: true, trim: true, lowercase: true, minLength: 3 })
  name!: string;
  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" })
  role!: Defaulted<"user" | "admin">;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
const good = await Users["~standard"].validate({ name: " Zed " });
// → { value: { _id: "…", name: "zed", role: "user" } }

const bad = await Users["~standard"].validate({ name: "a" });
console.log(bad);
// → { issues: [{ message: "must be at least 3 characters long", path: ["name"] }] }
```

`_id` ядро придумывает само, а служебных полей (меток времени, версии) проверка не требует. Вот какие проблемы она находит.

- Значение вне `enum` — `must be one of "user", "admin"` с путём `["role"]`.
- Лишнее поле — `not a field of User` с путём `["extra"]`.
- Вообще не объект — `Cast to User failed for 5 (number): expected an object [type]` с пустым путём.

В базу проверка не пишет, поэтому подходит для форм. Библиотека, которая читает Standard Schema, получит готовые тексты проблем.

`~standard` — часть общего интерфейса. `version` у него равен `1`, а `vendor` — `"typemo"`. Убедиться, что перед вами именно такой валидатор, поможет [`StandardSchema.isSchema`](../reference/schemas/json-and-standard-schema.mdx#standardschemaisschema). Тот же валидатор возвращает [`StandardSchema.of`](../reference/schemas/json-and-standard-schema.mdx#standardschemaof). Он принимает модель или её `schema`, и `StandardSchema.of(Users)` ведёт себя как `Users["~standard"]`.

## Проверить результат запроса чужой схемой

В обратную сторону работает [`.parse`](../reference/query/contracts.mdx#parse). Он проверяет каждую строку результата запроса любым валидатором Standard Schema — zod, valibot, arktype или своим, — не подключая его к ядру. Запрос должен читать через `.lean()` или `.plain()`. Проблемы всех строк собираются в одну [`ValidationError`](../reference/errors/data-errors.mdx#validationerror). Ниже валидатор написан вручную, чтобы пример не зависел от сторонних пакетов.

```ts twoslash title="users/report.ts"
import { Entity, type Defaulted, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "users", validator: true })
class User extends Entity {
  @Prop(() => String, { required: true, trim: true, lowercase: true, minLength: 3 })
  name!: string;
  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" })
  role!: Defaulted<"user" | "admin">;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
const nameRow = {
  "~standard": {
    version: 1 as const,
    vendor: "app",
    validate: (value: unknown) => {
      const row = value as { name?: unknown };
      if (typeof row.name !== "string") return { issues: [{ message: "name must be a string", path: ["name"] }] };
      return { value: { name: row.name } };
    },
    types: undefined as unknown as { input: unknown; output: { name: string } },
  },
};

await Users.create({ name: "zed" });
const rows = await Users.find().lean().parse(nameRow);
console.log(rows);
// → [{ name: "zed" }]
```

Подробно о контрактах — в руководстве [Контракты результата](../queries/contracts.mdx).

## Как выбрать

Спросите себя — **кто, кроме вашего приложения, может писать в коллекцию?**

- **Никто** — серверный валидатор лишний, проверок Typemo хватит.
- **Скрипты, другие сервисы, ручные правки** — включите `validator`.

Standard Schema нужен, когда проверять надо на границе приложения, в форме или обработчике, ещё до модели. А `.parse` — когда данные приходят из базы и вы хотите проверить их форму, например после миграции.

## Когда это не нужно

Не включайте `validator`, если схема часто меняется. Сервер будет отвергать документы, пока вы не обновите коллекцию. Не заменяйте проверки Typemo проверками сервера, ваших функций `validate` сервер не знает. И не вызывайте `~standard.validate` перед записью, `create` проверит данные сам.

## Если что-то пошло не так

**Генератору передали класс, а не модель.** `JsonSchemaGenerator.generate(User)` с самим классом `User` не сработает. Нужна модель, полученная от подключения, или её `schema`. Класс не пропустит компилятор, а в коде без типов придёт `ConfigurationError: JsonSchemaGenerator.generate: a model (connection.model(Entity)) or its schema (model.schema) is expected, got function`. Передайте `client.db().model(User)` или `Users.schema`.

**Сервер отверг запись, которую принял Typemo.** Сервер отвечает `Document failed validation`, если документ записан в обход Typemo, например через драйвер. Ради этого валидатор и нужен. Если же так отвергается запись самого приложения, схема на сервере отстала от класса. Обновите параметры коллекции по руководству [Создание коллекций](../collections/create.mdx#изменить-параметры-существующей-коллекции).

## Полный пример

```ts twoslash title="users/signup.ts"
import { Entity, type Defaulted, Prop, Schema, TypemoClient } from "@venloc/typemo";

@Schema({ collection: "users", validator: true })
class User extends Entity {
  @Prop(() => String, { required: true, trim: true, lowercase: true, minLength: 3 })
  name!: string;
  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" })
  role!: Defaulted<"user" | "admin">;
}

// код читателя: ошибка на границе приложения
class __BadRequest__ extends Error {}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);

// старт: коллекция создаётся вместе с серверным валидатором
await client.db().init();

// обработчик формы: проверяем вход и отдаём тексты проблем
export const signUp = async (input: unknown) => {
  const result = await Users["~standard"].validate(input);
  if (result.issues !== undefined) throw new __BadRequest__(result.issues.map((issue) => issue.message).join("; "));
  return Users.create({ name: (result.value as { name: string }).name });
};
```
