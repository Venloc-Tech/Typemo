Бывает, что сущности одного рода отличаются набором полей. Платёж может быть картой или переводом, у каждого свои данные, а отчёт нужен по всем сразу. Для этого в Typemo есть **наследование с дискриминаторами**. Наследники базового класса лежат в **одной коллекции** с базой и различаются значением специального поля — **ключа дискриминатора**. Читаете через базовую модель — получаете все документы, каждый экземпляром своего класса. Читаете через модель наследника — только его документы.

Если MongoDB для вас в новинку, хватит одного факта. Коллекция не требует одинаковых полей у всех документов, потому такая схема вообще и возможна. Typemo добавляет к этому строгость, ведь для каждого документа он знает, какому классу тот принадлежит.

## Что понадобится

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модели платежей из файла `payments/payment.ts`. Как настроить `tsconfig` для декораторов, описано в руководстве [Установка и настройка](../getting-started/installation.mdx).

## Быстрый путь

База получает обычный [`@Schema`](../reference/schemas/schema.mdx#schema). Наследник получает [`@Discriminator("значение")`](../reference/schemas/discriminator.mdx#discriminator) и объявление ключа с тем же литералом. Свой `@Schema` наследнику не нужен, он берёт опции базы.

```ts twoslash title="payments/payment.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type DiscriminatorValue } from "@venloc/typemo";
@Schema({ collection: "payments" })
class Payment extends Entity {
  @Prop(() => Number, { required: true }) amount!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Discriminator("card") // [!code highlight]
class CardPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"card">; // [!code highlight]
  @Prop(() => String, { required: true })
  last4!: string;
}

const CardPayments = client.db().model(CardPayment);
const payment = await CardPayments.create({ amount: 30, last4: "4242" });
console.log(payment.__t);
// → card
```

По умолчанию ключ называется `__t`. Typemo записывает его сам при создании документа, передавать его не нужно. Ниже разберём работу с такой иерархией на реальных задачах.

## Хранить разные виды в одной коллекции

В коллекции `payments` уже лежит карта из быстрого пути. Добавим второй вид, перевод по IBAN, и ещё один документ без вида, созданный через базовую модель. Вот как они выглядят в базе.

```ts twoslash title="payments/payment.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type DiscriminatorValue } from "@venloc/typemo";
@Schema({ collection: "payments" })
class Payment extends Entity {
  @Prop(() => Number, { required: true }) amount!: number;
}
@Discriminator("card")
class CardPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"card">;
  @Prop(() => String, { required: true }) last4!: string;
}
@Discriminator("transfer")
class TransferPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"transfer">;
  @Prop(() => String, { required: true }) iban!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Payments = client.db().model(Payment);
const CardPayments = client.db().model(CardPayment);
const TransferPayments = client.db().model(TransferPayment);
// ---cut---
await TransferPayments.create({ amount: 500, iban: "PL61 1090 1014 0000 0712 1981 2874" });
await Payments.create({ amount: 5 });
// в коллекции payments:
// → { amount: 30, last4: "4242", __t: "card" }
// → { amount: 500, iban: "PL61 …", __t: "transfer" }
// → { amount: 5 }
```

У наследника поля базы плюс свои, а обязательность и проверки работают как обычно. `CardPayments.create({ amount: 1 })` без `last4` бросит [`ValidationError`](../reference/errors/data-errors.mdx#validationerror) с текстом `Validation failed: "last4": the field is required [required]`.

Поле другого наследника компилятор не пропустит. А если обойти типы, его отвергнет приведение. `CardPayments.create({ amount: 1, last4: "1", iban: "…" })` бросит [`CastError`](../reference/errors/data-errors.mdx#casterror) `Cast to CardPayment failed at path "iban" for "…" (string): not a field of CardPayment [unknown-key]`. Документ с полями двух видов в базу не попадёт.

## Прочитать все документы и документы одного вида

Модель базы возвращает все документы коллекции, и каждый оказывается экземпляром своего класса. Модель наследника добавляет к запросу условие на ключ и видит только свои документы. Это заметно и по счётчикам, и по самому условию запроса.

```ts twoslash title="payments/payments.service.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type DiscriminatorValue } from "@venloc/typemo";
@Schema({ collection: "payments" })
class Payment extends Entity {
  @Prop(() => Number, { required: true }) amount!: number;
}
@Discriminator("card")
class CardPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"card">;
  @Prop(() => String, { required: true }) last4!: string;
}
@Discriminator("transfer")
class TransferPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"transfer">;
  @Prop(() => String, { required: true }) iban!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Payments = client.db().model(Payment);
const CardPayments = client.db().model(CardPayment);
const TransferPayments = client.db().model(TransferPayment);
// ---cut---
const all = await Payments.find().sort({ amount: 1 });
console.log(all.map((payment) => payment.constructor.name));
// → ["Payment", "CardPayment", "TransferPayment"]

console.log(await Payments.countDocuments(), await CardPayments.countDocuments());
// → 3 1
```

Условие модели наследника — обычный фильтр по ключу. `CardPayments.find()` уходит в базу как `{ __t: "card" }`. Так что добавляйте к запросу любые свои условия, они сложатся с условием на вид.

Модель базы тоже можно фильтровать по ключу, если база перечисляет наследников (раздел [Базовая модель знает наследников](#базовая-модель-знает-наследников)). Тогда ключ виден типу фильтра. Без списка компилятор отклонит `__t` как неизвестное поле. А документ без ключа остаётся базовым `Payment`. Ни одному наследнику он не принадлежит, и модель наследника его не увидит.

## Сузить тип до конкретного вида

Без дополнительных сведений модель базы знает только поля базы. Строка, прочитанная через неё, — это `amount` и `_id`, без `last4` и `iban`. Для документов модели подойдёт `instanceof`. Каждый документ — экземпляр класса своего вида, и проверка сужает тип.

```ts twoslash title="payments/payments.service.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type DiscriminatorValue } from "@venloc/typemo";
@Schema({ collection: "payments" })
class Payment extends Entity {
  @Prop(() => Number, { required: true }) amount!: number;
}
@Discriminator("card")
class CardPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"card">;
  @Prop(() => String, { required: true }) last4!: string;
}
@Discriminator("transfer")
class TransferPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"transfer">;
  @Prop(() => String, { required: true }) iban!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Payments = client.db().model(Payment);
const CardPayments = client.db().model(CardPayment);
const TransferPayments = client.db().model(TransferPayment);
// ---cut---
export const describeDocs = async (): Promise<string[]> => {
  const docs = await Payments.find();
  return docs.map((doc) => {
    if (doc instanceof CardPayment) return `card ${doc.last4}`;
    if (doc instanceof TransferPayment) return `transfer ${doc.iban}`;
    return "other";
  });
};
```

У результатов `.lean()` и `.plain()` и у JSON классов нет, это обычные объекты. Их различает ключ, а для этого базе нужно рассказать о наследниках. Об этом следующий раздел.

## Базовая модель знает наследников

Перечислите наследников в опции [`discriminators`](../reference/schemas/schema.mdx#опция-discriminators) базы и объявите ключ типом [`Discriminators<…>`](../reference/schemas/discriminator.mdx#discriminators). Тогда каждое чтение через модель базы вернёт объединение «документ базы без ключа или любой наследник». Проверка ключа сузит его до нужного вида, без приведения типов и без объединения руками. Так работают документы модели, результаты `.lean()` и `.plain()`, JSON и курсор.

```ts twoslash title="payments/payment.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type Discriminators, type DiscriminatorValue } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "payments", discriminators: () => [CardPayment, TransferPayment] }) // [!code highlight]
class Payment extends Entity {
  declare readonly __t?: Discriminators<CardPayment | TransferPayment>; // [!code highlight]
  @Prop(() => Number, { required: true })
  amount!: number;
}

@Discriminator("card")
class CardPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"card">;
  @Prop(() => String, { required: true })
  last4!: string;
}

@Discriminator("transfer")
class TransferPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"transfer">;
  @Prop(() => String, { required: true })
  iban!: string;
}

const Payments = client.db().model(Payment);
export const statement = async (): Promise<string[]> => {
  const rows = await Payments.find().sort({ amount: 1 }).plain();
  return rows.map((row) => {
    if (row.__t === "card") return `card ${row.last4}`;
    //                                         ^?
    if (row.__t === "transfer") return `transfer ${row.iban}`;
    return `payment ${row.amount}`;
  });
};
console.log(await statement());
// → ["payment 5", "card 4242", "transfer PL61 …"]
const transfers = await Payments.find({ __t: "transfer" }).plain();
console.log(transfers.length);
// → 1
```

Стрелка в списке нужна, потому что наследники объявлены ниже базы. Ключ в базе необязателен. У документа, созданного через базовую модель, вида нет, и в последней ветке `row.__t` равен `undefined`. Документы модели сужаются так же, `doc.__t === "card"` даёт поля карты, а `instanceof` по-прежнему работает.

Если ключ называется по-своему, меняются обе части — `discriminatorKey: "kind"` в опциях и `declare readonly kind?: Discriminators<…>` в классе. Декоратором `@Prop` это поле в базе не объявляют, ключ добавляет схема, как и `__t`.

Список сверяется с иерархией при сборке. Наследник не из списка, лишний класс или повтор дают `ConfigurationError`, а расхождение списка с типом ключа заметит компилятор. Тексты ошибок есть в справочнике [`@Schema`](../reference/schemas/schema.mdx#опция-discriminators).

## Создать документ вида через базовую модель

Модель базы принимает ключ в данных, если вы создаёте документ известного вида. Typemo выбирает класс по значению и возвращает экземпляр наследника. Незарегистрированное значение — ошибка, а не тихое создание базового документа.

```ts twoslash title="payments/payments.service.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type DiscriminatorValue } from "@venloc/typemo";
@Schema({ collection: "payments" })
class Payment extends Entity {
  @Prop(() => Number, { required: true }) amount!: number;
}
@Discriminator("card")
class CardPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"card">;
  @Prop(() => String, { required: true }) last4!: string;
}
@Discriminator("transfer")
class TransferPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"transfer">;
  @Prop(() => String, { required: true }) iban!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Payments = client.db().model(Payment);
const CardPayments = client.db().model(CardPayment);
const TransferPayments = client.db().model(TransferPayment);
// ---cut---
const created = await Payments.create({ amount: 30, __t: "card", last4: "1111" } as never);
console.log(created.constructor.name);
// → CardPayment

try {
  await Payments.create({ amount: 1, __t: "crypto" } as never);
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to Payment failed at path "__t" for "crypto" (string): "crypto" is not a discriminator value of Payment (known: card, transfer) [type]
```

`as never` здесь потому, что тип входа базовой модели не знает полей наследников. Надёжнее создавать документ через модель нужного вида, там поля проверяют типы.

## Изменить и удалить документы вида

Модели наследников действуют только на свои документы. Условие на ключ добавляется и в изменение, и в удаление. Если условие обновления подходит документу другого вида, оно ничего не найдёт и ничего не изменит.

```ts twoslash title="payments/payments.service.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type DiscriminatorValue } from "@venloc/typemo";
@Schema({ collection: "payments" })
class Payment extends Entity {
  @Prop(() => Number, { required: true }) amount!: number;
}
@Discriminator("card")
class CardPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"card">;
  @Prop(() => String, { required: true }) last4!: string;
}
@Discriminator("transfer")
class TransferPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"transfer">;
  @Prop(() => String, { required: true }) iban!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Payments = client.db().model(Payment);
const CardPayments = client.db().model(CardPayment);
const TransferPayments = client.db().model(TransferPayment);
// ---cut---
await TransferPayments.create({ amount: 500, iban: "PL61" });

const other = await CardPayments.updateOne({ amount: 500 }, { $set: { amount: 8 } });
console.log(other.matchedCount);
// → 0
```

Поле чужого вида модель наследника не пропустит вовсе. Фильтр `{ last4: "0000" }` в `TransferPayments` отклонит компилятор, а в обход типов во время работы будет [`StrictModeError`](../reference/errors/data-errors.mdx#strictmodeerror) `filter: "last4" is not a field of TransferPayment [unknown-path]`. Поэтому массовые операции через модель наследника безопаснее, чем через базовую. `TransferPayments.deleteMany({ … })` не заденет карточные платежи, даже если условие окажется слишком широким.

## Хранить разные варианты внутри массива

Дискриминатор пригодится не только для коллекций. Поле-массив может хранить вложенные объекты разных видов, например блоки страницы — текст и картинку. Базовый класс блока — вложенный объект без `_id`-коллекции, а ключ получает своё имя через `discriminatorKey`.

```ts twoslash title="pages/page.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type DiscriminatorValue } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ discriminatorKey: "kind" })
class Block {
  @Prop(() => String, { required: true }) kind!: string;
}

@Discriminator("text")
class TextBlock extends Block {
  declare readonly kind: DiscriminatorValue<"text">;
  @Prop(() => String, { required: true }) text!: string;
}

@Discriminator("image")
class ImageBlock extends Block {
  declare readonly kind: DiscriminatorValue<"image">;
  @Prop(() => String, { required: true }) url!: string;
}

@Schema({ collection: "pages" })
class Page extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => [Block]) blocks!: (TextBlock | ImageBlock)[]; // [!code highlight]
}

const Pages = client.db().model(Page);
await Pages.create({ title: "Intro", blocks: [{ kind: "text", text: "Hi" }, { kind: "image", url: "/a.png" }] });
const page = await Pages.findOne({ title: "Intro" }).plain().orFail();
// → { _id: "…", title: "Intro", blocks: [{ kind: "text", text: "Hi" }, { kind: "image", url: "/a.png" }] }
```

Каждый элемент проверяется по схеме своего вида.

- Поле другого вида отвергается. `blocks: [{ kind: "text", url: "u" }]` даёт `CastError` `Cast to document failed at path "blocks.0.url" for "u" (string): not a field of TextBlock [unknown-key]`.
- Неизвестное значение ключа — `Cast to document failed at path "blocks.0.kind" for "video" (string): "video" is not a discriminator value of Block (known: text, image) [discriminator]`.
- Обязательное поле своего вида проверяется как обычно. Блок `{ kind: "text" }` без текста даёт `Validation failed: "blocks.0.text": the field is required [required]`.

## Как выбрать

Спросите себя — **нужно ли читать эти сущности вместе?**

- **Отчёт, список или поиск идут по всем видам сразу, а поля видов различаются** — нужен дискриминатор. Один запрос, один индекс, одна коллекция.
- **Виды почти не пересекаются, читаются и пишутся отдельно, а общие поля можно и повторить** — проще две модели в двух коллекциях. У каждой свои индексы, ключ не нужен.
- **Виды различаются только значением одного поля, а набор полей одинаковый** — хватит обычного [`enum`](../reference/schemas/prop.mdx#enum) на поле, иерархия классов не нужна.

## Когда это не нужно

Повторно использовать код модели — не повод для дискриминатора. Общие поля можно вынести в базовый класс без `@Discriminator`, только тогда наследники станут разными моделями с разными коллекциями. А для поля, которое бывает то строкой, то числом, есть [`Spec.union`](../reference/schemas/types-and-spec.mdx#specunion), а не дискриминатор.

## Если что-то пошло не так

**Декоратор есть, а ключ не объявлен.** Без строки `declare readonly __t: DiscriminatorValue<"card">` класс не скомпилируется, компилятору не по чему отличать наследников. Ошибка подскажет, что добавить.

```ts twoslash
import { Discriminator, Entity, Schema } from "@venloc/typemo";
// ---cut---
// @errors: 1238
@Schema()
class Payment extends Entity {}

@Discriminator("card") // неправильно: нет объявления ключа
class CardPayment extends Payment {}
```

Добавьте `declare readonly __t: DiscriminatorValue<"card">` в класс (или ваш `discriminatorKey` вместо `__t`), и ошибка уйдёт.

**Свой `@Schema` на наследнике.** Опции коллекции принадлежат базе. Поставите `@Schema` на наследника — Typemo откажет при сборке модели, а не начнёт молча писать в другую коллекцию.

```text
ConfigurationError: TransferPayment: a discriminator uses its root's schema options; remove @Schema (root: Payment)
```

Уберите `@Schema` с наследника. Если виды должны лежать в разных коллекциях, это не наследники, а отдельные модели.

**Два наследника с одним значением.** Значения должны быть уникальны во всей иерархии. Повтор найдётся при сборке любой модели иерархии, а не только той, где он объявлен.

```text
ConfigurationError: Dup: discriminator value "card" is already used by Card in the hierarchy of Payment
```

Дайте наследникам разные значения.

**Наследника забыли в списке базы.** Если база перечисляет наследников, а новый класс в список не попал, сборка откажет и назовёт класс.

```text
ConfigurationError: Payment: the "discriminators" list does not match the hierarchy — registered but not listed: RefundPayment
```

Добавьте класс в `discriminators: () => [...]` базы. Повторённый или лишний класс ловится так же, тексты — в справочнике [`@Schema`](../reference/schemas/schema.mdx#опция-discriminators).

**Ключ не переписывается.** Присвоить ключ загруженному документу не даст компилятор, а обновление с ключом будет отклонено. Вид выбирается при создании и потом не меняется.

```text
StrictModeError: $set.__t: "__t" is immutable; it is written only when the document is created ($setOnInsert on upsert) [immutable]
```

Чтобы сменить вид, создайте документ нужного вида и удалите прежний.

## Полный пример

Всё вместе в одном файле — три вида платежей, отчёт по всем и работа с одним видом. Код, которого нет в Typemo, помечен `__…__`.

```ts twoslash title="payments/payments.service.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type Discriminators, type DiscriminatorValue } from "@venloc/typemo";

@Schema({ collection: "payments", discriminators: () => [CardPayment, TransferPayment] })
class Payment extends Entity {
  declare readonly __t?: Discriminators<CardPayment | TransferPayment>;
  @Prop(() => Number, { required: true }) amount!: number;
}

@Discriminator("card")
class CardPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"card">;
  @Prop(() => String, { required: true }) last4!: string;
}

@Discriminator("transfer")
class TransferPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"transfer">;
  @Prop(() => String, { required: true }) iban!: string;
}

// код читателя: ошибка на границе приложения
class __NotFound__ extends Error {}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Payments = client.db().model(Payment);
const CardPayments = client.db().model(CardPayment);
const TransferPayments = client.db().model(TransferPayment);

// запись: каждый вид создаётся своей моделью, ключ ставится сам
export const payByCard = async (amount: number, last4: string) => CardPayments.create({ amount, last4 });
export const payByTransfer = async (amount: number, iban: string) => TransferPayments.create({ amount, iban });

// отчёт по всем видам: база знает наследников, дальше сужение по ключу
export const statement = async () => {
  const rows = await Payments.find().sort({ amount: 1 }).plain();
  return rows.map((row) => {
    if (row.__t === "card") return `card ${row.last4}: ${row.amount}`;
    if (row.__t === "transfer") return `transfer ${row.iban}: ${row.amount}`;
    return `payment: ${row.amount}`;
  });
};

// работа с одним видом: модель наследника видит только свои документы
export const findCard = async (last4: string) => {
  const payment = await CardPayments.findOne({ last4 }).plain();
  if (payment === null) throw new __NotFound__(`no card payment ending ${last4}`);
  return payment;
};
```

<Callout type="migration">

В Mongoose дискриминатор создаётся вызовом `Base.discriminator("name", schema)`, а ключ хранится в `__t`. В Typemo наследник — обычный класс с `@Discriminator`. Тип его полей выводится из класса, а объявление `declare readonly __t` делает ключ частью типа. Незарегистрированное значение ключа — ошибка приведения, а не молчаливое создание базового документа. После создания ключ менять нельзя, а повтор значения в иерархии находится при сборке. Имя ключа, как и в Mongoose, задаёт опция `discriminatorKey`. А объединение наследников, которого в Mongoose нет, даёт опция `discriminators`.

</Callout>
