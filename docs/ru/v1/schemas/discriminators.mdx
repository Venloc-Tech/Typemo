Иногда сущности одного рода отличаются набором полей: платёж бывает картой или переводом, у каждого свои данные, а отчёт нужен по всем сразу. Для этого Typemo умеет **наследование с дискриминаторами**: наследники базового класса лежат в **одной коллекции** с базой, а различаются значением специального поля, **ключа дискриминатора**. Читая через базовую модель, вы получаете все документы, каждый экземпляром своего класса. Читая через модель наследника — только его документы.

Если вы впервые встречаете MongoDB, достаточно знать, что коллекции не требуют одинаковых полей у всех документов: именно поэтому такая схема вообще возможна. Typemo добавляет к этому строгость, потому что для каждого документа знает, какому классу он принадлежит.

## Что предполагается

Примеры используют клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модели платежей из файла `payments/payment.ts`. Настройка `tsconfig` для декораторов описана в руководстве [Установка и настройка](../getting-started/installation.mdx).

## Быстрый путь

База получает обычный [`@Schema`](../reference/schemas/schema.mdx#schema). Наследник получает [`@Discriminator("значение")`](../reference/schemas/discriminator.mdx#discriminator) и объявление ключа с тем же литералом. Собственный `@Schema` наследнику не нужен: он берёт опции базы.

```ts twoslash title="payments/payment.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type DiscriminatorValue } from "@venloc/typemo";
@Schema({ collection: "payments" })
class Payment extends Entity {
  @Prop(() => Number, { required: true }) amount!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Discriminator("card") // [!code highlight]
class CardPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"card">; // [!code highlight]
  @Prop(() => String, { required: true })
  last4!: string;
}

const CardPayments = client.db().model(CardPayment);
const payment = await CardPayments.create({ amount: 30, last4: "4242" });
console.log(payment.__t);
// → card
```

Ключ по умолчанию называется `__t`. Typemo записывает его сам при создании документа, поэтому передавать его не нужно. Остальная страница разбирает работу с такой иерархией на реальных задачах.

## Хранить разные виды в одной коллекции

В коллекции `payments` уже лежит карта из быстрого пути. Добавим второй вид, перевод по IBAN, и один документ без вида, созданный через базовую модель. Теперь в ней документы двух видов и один без вида. Так они выглядят в базе, полученные запуском:

```ts twoslash title="payments/payment.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type DiscriminatorValue } from "@venloc/typemo";
@Schema({ collection: "payments" })
class Payment extends Entity {
  @Prop(() => Number, { required: true }) amount!: number;
}
@Discriminator("card")
class CardPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"card">;
  @Prop(() => String, { required: true }) last4!: string;
}
@Discriminator("transfer")
class TransferPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"transfer">;
  @Prop(() => String, { required: true }) iban!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Payments = client.db().model(Payment);
const CardPayments = client.db().model(CardPayment);
const TransferPayments = client.db().model(TransferPayment);
// ---cut---
await TransferPayments.create({ amount: 500, iban: "PL61 1090 1014 0000 0712 1981 2874" });
await Payments.create({ amount: 5 });
// в коллекции payments:
// → { amount: 30, last4: "4242", __t: "card" }
// → { amount: 500, iban: "PL61 …", __t: "transfer" }
// → { amount: 5 }
```

Поля наследника — это поля базы плюс собственные, а обязательность и проверки работают как обычно: `CardPayments.create({ amount: 1 })` без `last4` бросает [`ValidationError`](../reference/errors/data-errors.mdx#validationerror) с текстом `Validation failed: "last4": the field is required [required]`. Поле другого наследника компилятор не пропустит, а если обойти типы, оно отвергается при приведении: `CardPayments.create({ amount: 1, last4: "1", iban: "…" })` бросает [`CastError`](../reference/errors/data-errors.mdx#casterror) `Cast to CardPayment failed at path "iban" for "…" (string): not a field of CardPayment [unknown-key]`. Так документ с полями двух видов не окажется в базе.

## Прочитать все документы и документы одного вида

Модель базы возвращает все документы коллекции, и каждый оказывается экземпляром своего класса. Модель наследника добавляет к запросу условие на ключ: она видит только свои документы. Это видно и в счётчиках, и в самом условии запроса.

```ts twoslash title="payments/payments.service.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type DiscriminatorValue } from "@venloc/typemo";
@Schema({ collection: "payments" })
class Payment extends Entity {
  @Prop(() => Number, { required: true }) amount!: number;
}
@Discriminator("card")
class CardPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"card">;
  @Prop(() => String, { required: true }) last4!: string;
}
@Discriminator("transfer")
class TransferPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"transfer">;
  @Prop(() => String, { required: true }) iban!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Payments = client.db().model(Payment);
const CardPayments = client.db().model(CardPayment);
const TransferPayments = client.db().model(TransferPayment);
// ---cut---
const all = await Payments.find().sort({ amount: 1 });
console.log(all.map((payment) => payment.constructor.name));
// → ["Payment", "CardPayment", "TransferPayment"]

console.log(await Payments.countDocuments(), await CardPayments.countDocuments());
// → 3 1
```

Условие модели наследника — это обычный фильтр по ключу: запрос `CardPayments.find()` уходит в базу как `{ __t: "card" }`. Поэтому к запросу можно добавить любые свои условия, и они сложатся с условием на вид.

Модель базы можно фильтровать и по ключу, если база перечисляет наследников (раздел [Базовая модель знает наследников](#базовая-модель-знает-наследников)): тогда ключ виден типу фильтра, а без списка компилятор отклонит `__t` как неизвестное поле. А документ без ключа остаётся базовым `Payment`: он не принадлежит ни одному наследнику, и модель наследника его не увидит.

## Сузить тип до конкретного вида

Без дополнительных сведений модель базы знает только поля базы: тип строки, прочитанной через неё, — это `amount` и `_id`, без `last4` и `iban`. Для гидратированных документов подойдёт `instanceof`: каждый документ — экземпляр класса своего вида, и проверка сужает тип.

```ts twoslash title="payments/payments.service.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type DiscriminatorValue } from "@venloc/typemo";
@Schema({ collection: "payments" })
class Payment extends Entity {
  @Prop(() => Number, { required: true }) amount!: number;
}
@Discriminator("card")
class CardPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"card">;
  @Prop(() => String, { required: true }) last4!: string;
}
@Discriminator("transfer")
class TransferPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"transfer">;
  @Prop(() => String, { required: true }) iban!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Payments = client.db().model(Payment);
const CardPayments = client.db().model(CardPayment);
const TransferPayments = client.db().model(TransferPayment);
// ---cut---
export const describeDocs = async (): Promise<string[]> => {
  const docs = await Payments.find();
  return docs.map((doc) => {
    if (doc instanceof CardPayment) return `card ${doc.last4}`;
    if (doc instanceof TransferPayment) return `transfer ${doc.iban}`;
    return "other";
  });
};
```

Для `lean`, `plain` и JSON классов нет, это обычные объекты. Их различает ключ, и для него базе нужно рассказать о наследниках, как в следующем разделе.

## Базовая модель знает наследников

Перечислите наследников в опции [`discriminators`](../reference/schemas/schema.mdx#опция-discriminators) базы и объявите ключ типом [`Discriminators<…>`](../reference/schemas/discriminator.mdx#discriminators): тогда каждое чтение через модель базы возвращает объединение «документ базы без ключа или любой наследник». Проверка ключа сужает объединение до нужного вида, без приведения типов и без ручного объединения. Так работают гидратированные документы, `lean`, `plain`, JSON и курсор.

```ts twoslash title="payments/payment.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type Discriminators, type DiscriminatorValue } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "payments", discriminators: () => [CardPayment, TransferPayment] }) // [!code highlight]
class Payment extends Entity {
  declare readonly __t?: Discriminators<CardPayment | TransferPayment>; // [!code highlight]
  @Prop(() => Number, { required: true })
  amount!: number;
}

@Discriminator("card")
class CardPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"card">;
  @Prop(() => String, { required: true })
  last4!: string;
}

@Discriminator("transfer")
class TransferPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"transfer">;
  @Prop(() => String, { required: true })
  iban!: string;
}

const Payments = client.db().model(Payment);
export const statement = async (): Promise<string[]> => {
  const rows = await Payments.find().sort({ amount: 1 }).plain();
  return rows.map((row) => {
    if (row.__t === "card") return `card ${row.last4}`;
    //                                         ^?
    if (row.__t === "transfer") return `transfer ${row.iban}`;
    return `payment ${row.amount}`;
  });
};
console.log(await statement());
// → ["payment 5", "card 4242", "transfer PL61 …"]
const transfers = await Payments.find({ __t: "transfer" }).plain();
console.log(transfers.length);
// → 1
```

Стрелка в списке нужна потому, что наследники объявлены ниже базы. Ключ в базе необязателен: документ, созданный через базовую модель, вида не имеет, и в последней ветке `row.__t` — `undefined`. Гидратированные документы сужаются так же: `doc.__t === "card"` даёт поля карты, а `instanceof` остаётся рабочим способом.

Со своим именем ключа меняются обе части: `discriminatorKey: "kind"` в опциях и `declare readonly kind?: Discriminators<…>` в классе. Поле при этом в базе не объявляется декоратором `@Prop`: ключ добавляет схема, как и `__t`.

Список сверяется с иерархией при сборке: наследник, которого в списке нет, лишний класс или повтор — `ConfigurationError`, а расхождение списка с типом ключа видит компилятор. Тексты ошибок — в справочнике [`@Schema`](../reference/schemas/schema.mdx#опция-discriminators).

## Создать документ вида через базовую модель

Модель базы принимает ключ в данных, если вы создаёте документ уже известного вида. Typemo выбирает класс по значению и возвращает экземпляр наследника. Значение, которого нет среди зарегистрированных, — ошибка, а не тихое создание базового документа.

```ts twoslash title="payments/payments.service.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type DiscriminatorValue } from "@venloc/typemo";
@Schema({ collection: "payments" })
class Payment extends Entity {
  @Prop(() => Number, { required: true }) amount!: number;
}
@Discriminator("card")
class CardPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"card">;
  @Prop(() => String, { required: true }) last4!: string;
}
@Discriminator("transfer")
class TransferPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"transfer">;
  @Prop(() => String, { required: true }) iban!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Payments = client.db().model(Payment);
const CardPayments = client.db().model(CardPayment);
const TransferPayments = client.db().model(TransferPayment);
// ---cut---
const created = await Payments.create({ amount: 30, __t: "card", last4: "1111" } as never);
console.log(created.constructor.name);
// → CardPayment

try {
  await Payments.create({ amount: 1, __t: "crypto" } as never);
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to Payment failed at path "__t" for "crypto" (string): "crypto" is not a discriminator value of Payment (known: card, transfer) [type]
```

Приведение `as never` нужно потому, что тип входа базовой модели не содержит полей наследников. Надёжнее создавать документ через модель нужного вида, где типы проверяют поля.

## Изменить и удалить документы вида

Модели наследников действуют только на свои документы: условие на ключ добавляется и в изменение, и в удаление. Обновление, чьё условие подходит документу другого вида, не находит ничего и ничего не меняет.

```ts twoslash title="payments/payments.service.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type DiscriminatorValue } from "@venloc/typemo";
@Schema({ collection: "payments" })
class Payment extends Entity {
  @Prop(() => Number, { required: true }) amount!: number;
}
@Discriminator("card")
class CardPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"card">;
  @Prop(() => String, { required: true }) last4!: string;
}
@Discriminator("transfer")
class TransferPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"transfer">;
  @Prop(() => String, { required: true }) iban!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Payments = client.db().model(Payment);
const CardPayments = client.db().model(CardPayment);
const TransferPayments = client.db().model(TransferPayment);
// ---cut---
await TransferPayments.create({ amount: 500, iban: "PL61" });

const other = await CardPayments.updateOne({ amount: 500 }, { $set: { amount: 8 } });
console.log(other.matchedCount);
// → 0
```

Поле чужого вида модель наследника не пропускает вовсе: фильтр `{ last4: "0000" }` в `TransferPayments` компилятор отклоняет, а если обойти типы, во время работы это [`StrictModeError`](../reference/errors/data-errors.mdx#strictmodeerror) `filter: "last4" is not a field of TransferPayment [unknown-path]`. Поэтому массовые операции с моделью наследника безопаснее, чем с базовой: `TransferPayments.deleteMany({ … })` не заденет карточные платежи, даже если условие окажется слишком широким.

## Хранить разные варианты внутри массива

Дискриминатор нужен и не только для коллекций. Поле-массив может хранить разные виды вложенных объектов: блоки страницы (текст, картинка). Базовый класс блока — вложенный объект без `_id`-коллекции, а ключ выбирается своим именем через `discriminatorKey`.

```ts twoslash title="pages/page.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type DiscriminatorValue } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ discriminatorKey: "kind" })
class Block {
  @Prop(() => String, { required: true }) kind!: string;
}

@Discriminator("text")
class TextBlock extends Block {
  declare readonly kind: DiscriminatorValue<"text">;
  @Prop(() => String, { required: true }) text!: string;
}

@Discriminator("image")
class ImageBlock extends Block {
  declare readonly kind: DiscriminatorValue<"image">;
  @Prop(() => String, { required: true }) url!: string;
}

@Schema({ collection: "pages" })
class Page extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => [Block]) blocks!: (TextBlock | ImageBlock)[]; // [!code highlight]
}

const Pages = client.db().model(Page);
await Pages.create({ title: "Intro", blocks: [{ kind: "text", text: "Hi" }, { kind: "image", url: "/a.png" }] });
const page = await Pages.findOne({ title: "Intro" }).plain().orFail();
// → { _id: "…", title: "Intro", blocks: [{ kind: "text", text: "Hi" }, { kind: "image", url: "/a.png" }] }
```

Каждый элемент проверяется по схеме своего вида. Поле другого вида отвергается: `blocks: [{ kind: "text", url: "u" }]` даёт `CastError` `Cast to document failed at path "blocks.0.url" for "u" (string): not a field of TextBlock [unknown-key]`, а неизвестное значение ключа — `Cast to document failed at path "blocks.0.kind" for "video" (string): "video" is not a discriminator value of Block (known: text, image) [discriminator]`. Обязательное поле своего вида проверяется как обычно: блок `{ kind: "text" }` без текста — `Validation failed: "blocks.0.text": the field is required [required]`.

## Как выбрать

Задайте себе один вопрос: **нужно ли читать эти сущности вместе?** Если отчёт, список или поиск идут по всем видам сразу, а поля видов различаются, нужен дискриминатор: один запрос, один индекс, одна коллекция. Если виды почти не пересекаются, читаются и пишутся отдельно, а общие поля можно повторить, проще две модели в двух коллекциях: у каждой свои индексы, а ключ не нужен. Если виды различаются только значением одного поля и набор полей одинаковый, вам нужен обычный [`enum`](../reference/schemas/prop.mdx#enum) на поле, а не иерархия классов.

## Когда это не нужно

Наследование ради повторного использования кода в модели — не повод: общие поля можно вынести в базовый класс без `@Discriminator`, но тогда наследники будут разными моделями с разными коллекциями. Для значения одного поля, которое бывает то строкой, то числом, есть [`Spec.union`](../reference/schemas/types-and-spec.mdx#specunion), а не дискриминатор.

## Частые ошибки

### Декоратор без объявления ключа

Без строки `declare readonly __t: DiscriminatorValue<"card">` класс не скомпилируется: компилятор не сможет отличить наследников. Ошибка называет, что добавить.

```ts twoslash
import { Discriminator, Entity, Schema } from "@venloc/typemo";
// ---cut---
// @errors: 1238
@Schema()
class Payment extends Entity {}

@Discriminator("card") // неправильно: нет объявления ключа
class CardPayment extends Payment {}
```

Добавьте `declare readonly __t: DiscriminatorValue<"card">` в класс (или ваше `discriminatorKey` вместо `__t`), и ошибка исчезнет.

### Свой `@Schema` на наследнике

Опции коллекции принадлежат базе. Если поставить `@Schema` на наследника, Typemo откажет при сборке модели, а не сохранит молча другую коллекцию:

```text
ConfigurationError: TransferPayment: a discriminator uses its root's schema options; remove @Schema (root: Payment)
```

Уберите `@Schema` с наследника. Если виды должны лежать в разных коллекциях, они не наследники, а отдельные модели.

### Два наследника с одним значением

Значения должны быть уникальными во всей иерархии. Повтор находится при сборке любой модели иерархии, а не только той, которой он принадлежит:

```text
ConfigurationError: Dup: discriminator value "card" is already used by Card in the hierarchy of Payment
```

Дайте наследникам разные значения.

### Наследник не записан в список базы

Если база перечисляет наследников, а новый класс в список не добавили, сборка отказывает и называет класс:

```text
ConfigurationError: Payment: the "discriminators" list does not match the hierarchy — registered but not listed: RefundPayment
```

Добавьте класс в `discriminators: () => [...]` базы. Повторённый или лишний класс ловится так же, тексты — в справочнике [`@Schema`](../reference/schemas/schema.mdx#опция-discriminators).

### Ключ нельзя переписать

Присваивание ключа загруженному документу не скомпилируется, а обновление с ключом отклоняется. Вид выбирается при создании и потом не меняется:

```text
StrictModeError: $set.__t: "__t" is immutable; it is written only when the document is created ($setOnInsert on upsert) [immutable]
```

Чтобы сменить вид, создайте документ нужного вида и удалите прежний.

## Полный пример

Один файл собирает всё вместе: три вида платежей, отчёт по всем и работа с одним видом. Код читателя, которого нет в Typemo, помечен `__…__`.

```ts twoslash title="payments/payments.service.ts"
import { Discriminator, Entity, Prop, Schema, TypemoClient, type Discriminators, type DiscriminatorValue } from "@venloc/typemo";

@Schema({ collection: "payments", discriminators: () => [CardPayment, TransferPayment] })
class Payment extends Entity {
  declare readonly __t?: Discriminators<CardPayment | TransferPayment>;
  @Prop(() => Number, { required: true }) amount!: number;
}

@Discriminator("card")
class CardPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"card">;
  @Prop(() => String, { required: true }) last4!: string;
}

@Discriminator("transfer")
class TransferPayment extends Payment {
  declare readonly __t: DiscriminatorValue<"transfer">;
  @Prop(() => String, { required: true }) iban!: string;
}

// код читателя: ошибка на границе приложения
class __NotFound__ extends Error {}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Payments = client.db().model(Payment);
const CardPayments = client.db().model(CardPayment);
const TransferPayments = client.db().model(TransferPayment);

// запись: каждый вид создаётся своей моделью, ключ ставится сам
export const payByCard = async (amount: number, last4: string) => CardPayments.create({ amount, last4 });
export const payByTransfer = async (amount: number, iban: string) => TransferPayments.create({ amount, iban });

// отчёт по всем видам: база знает наследников, дальше сужение по ключу
export const statement = async () => {
  const rows = await Payments.find().sort({ amount: 1 }).plain();
  return rows.map((row) => {
    if (row.__t === "card") return `card ${row.last4}: ${row.amount}`;
    if (row.__t === "transfer") return `transfer ${row.iban}: ${row.amount}`;
    return `payment: ${row.amount}`;
  });
};

// работа с одним видом: модель наследника видит только свои документы
export const findCard = async (last4: string) => {
  const payment = await CardPayments.findOne({ last4 }).plain();
  if (payment === null) throw new __NotFound__(`no card payment ending ${last4}`);
  return payment;
};
```

<Callout type="migration">

В Mongoose дискриминатор создаётся вызовом `Base.discriminator("name", schema)` и хранится ключ `__t`. В Typemo наследник — обычный класс с `@Discriminator`, тип его полей выводится из класса, а объявление `declare readonly __t` делает ключ частью типа. Значение ключа, которого нет среди зарегистрированных, — ошибка приведения, а не молчаливое создание базового документа. Значение ключа после создания менять нельзя, а повтор значения в иерархии находится при сборке. Имя ключа, как и в Mongoose, задаётся опцией `discriminatorKey`. Объединение наследников, которого в Mongoose нет, даёт опция `discriminators`.

</Callout>
