**Значение по умолчанию** — то, что Typemo записывает в поле сам, когда вы его не передали: роль `user` новому участнику, дата регистрации, начальный набор меток. Оно задаётся опцией [`default`](../reference/schemas/prop.mdx#default) и избавляет от того, чтобы повторять одно и то же значение в каждом вызове [`create`](../reference/writes/writes.mdx#create). Чтобы типы знали, что поле можно не передавать при создании и что после чтения оно всегда есть, поле объявляют особым типом [`Defaulted<T>`](../reference/schemas/field-markers.mdx#defaulted). Для массивов этот тип не нужен: поле-массив и так необязательно при создании.

Важно понимать, **когда** значение подставляется: при создании документа и при upsert, но не при обычном обновлении и не при чтении в lean- и plain-видах. Ниже это разобрано на примерах.

## Что предполагается

Модель описана по руководству [Описать модель](./define-model.mdx), а различие между отсутствием и `null` известно из руководства [Обязательные поля, null и отсутствие](./required-and-null.mdx). Примеры строят модель участника сообщества.

## Быстрый путь

`default` принимает значение или функцию без аргументов. Поле с ним объявляется как `Defaulted<T>`.

```ts twoslash title="community/member.ts"
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
@Schema({ collection: "members" })
export class Member extends Entity {
  @Prop(() => String, { required: true })
  name!: string;

  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" })
  role!: Defaulted<"user" | "admin">;
}

const Members = client.connection.model(Member);
const member = await Members.create({ name: "Ann" });
console.log(member.role);
// → user
```

`role` не передали, и он получил значение `user`. Передать его тоже можно: `create({ name: "Bob", role: "admin" })` сохранит `admin`. Остальная страница разбирает разные виды значений и ситуации, в которых оно подставляется.

## Подставить постоянное значение

Число, строка, `null` и другие простые значения указываются прямо. Поле по умолчанию остаётся обычным полем: значение сохраняется в базе как любое другое.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
@Schema({ collection: "members" })
class Member extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { default: 0 }) // [!code highlight]
  score!: Defaulted<number>;
  @Prop(() => String, { nullable: true, default: null }) // [!code highlight]
  note!: Defaulted<string | null>;
}
const Members = client.connection.model(Member);
const member = await Members.create({ name: "Ann" });
console.log(member.score, member.note);
// → 0 null
```

`default: null` разрешён только вместе с `nullable: true`: значение по умолчанию обязано быть таким, какое поле принимает, иначе документ нарушал бы собственную схему сразу после создания.

## Вычислять значение для каждого документа

Если значение должно отличаться у каждого документа, передайте функцию. Typemo вызывает её заново при каждом создании: `() => new Date()` даёт дату создания именно этого документа, а не дату загрузки модуля.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
@Schema({ collection: "members" })
class Member extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Date, { default: () => new Date() }) // [!code highlight]
  joined!: Defaulted<Date>;
  @Prop(() => [String], { default: () => ["new"] }) // [!code highlight]
  tags!: string[];
}
const Members = client.connection.model(Member);
const first = await Members.create({ name: "Ann" });
const second = await Members.create({ name: "Bob" });
first.tags.push("vip");
console.log(first.tags.length, second.tags.length);
// → 2 1
console.log(first.joined.getTime() === second.joined.getTime());
// → false
```

Массив, как и любое значение, вычисляется для каждого документа отдельно: изменение меток первого участника не затрагивает второго. Даже если вы напишете массив-литералом (`default: ["new"]`), Typemo скопирует его для каждого документа, поэтому общий изменяемый объект между документами не возникает. Тип поля-массива остаётся обычным `string[]`: `Defaulted<string[]>` разрешён, но не нужен, потому что без `default` массив тоже получает `[]` (разбор — в руководстве [Массивы](./arrays.mdx)).

## Когда значение подставляется

Значение подставляется при создании документа: через `create`, [`insertMany`](../reference/writes/writes.mdx#insertmany) и [`Model.new`](../reference/documents/model-document-methods.mdx#modelnew), а также при upsert, то есть когда обновление не нашло документа и создало его само. При upsert Typemo добавляет недостающие значения по умолчанию только к вставке, поэтому уже существующий документ не перезаписывается.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
@Schema({ collection: "members" })
class Member extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" }) role!: Defaulted<"user" | "admin">;
  @Prop(() => Number, { default: 0 }) score!: Defaulted<number>;
}
const Members = client.connection.model(Member);
// ---cut---
await Members.updateOne({ name: "Zed" }, { $set: { score: 5 } }, { upsert: true });
const zed = await Members.findOne({ name: "Zed" }).plain();
console.log(zed?.role, zed?.score);
// → user 5
```

Обновление вставило документ с `score: 5` и само дописало `role: "user"`. А вот обычное обновление существующего документа значения по умолчанию не подставляет: если в документе поля нет, оно останется без значения. Это разумно: `updateOne` меняет то, что вы просили, а не «достраивает» документ.

## Прочитать старый документ

Документы в базе могли появиться раньше, чем вы добавили `default`: либо до появления поля, либо другой программой. Для гидратированного документа значение по умолчанию подставляется при чтении, поэтому `member.role` не бывает `undefined`. Но lean- и plain-виды отдают то, что лежит в базе, как оно есть: они не создают документ и ничего не достраивают.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
@Schema({ collection: "members" })
class Member extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" }) role!: Defaulted<"user" | "admin">;
}
const Members = client.connection.model(Member);
// ---cut---
// документ, записанный до появления поля role
await client.unsafeDriver().db("shop").collection("members").insertOne({ name: "Old" });

const asDocument = await Members.findOne({ name: "Old" }).orFail();
console.log(asDocument.role);
// → user
const asPlain = await Members.findOne({ name: "Old" }).plain();
console.log(asPlain);
// → { _id: "…", name: "Old" }
```

Есть и обратная сторона: если загрузить такой документ, изменить в нём другое поле и сохранить, подставленные значения попадут в изменения и запишутся в базу (в проверке [`$getChanges()`](../reference/documents/document-api.mdx#getchanges) после `score = 4` оказались и `score`, и `role: "user"`, а у модели с массивом `tags` с `default` — и `tags`). Так же ведёт себя и массив без ключа: гидратированный документ читает его пустым, а `$save` записывает. Старые документы, которые вы не загружаете как документы, остаются без поля.

Значит, если вы добавили `default` к уже заполненной коллекции, а клиентам отдаёте plain-вид, старые документы придут без этого поля. Тип результата при этом обещает, что поле есть. Если это важно, заполните поле в базе разово, а не полагайтесь на подстановку при чтении.

## Не передавать `undefined` и `null` явно

Значение по умолчанию подставляется только тогда, когда поля **нет** в данных. Явный `undefined` не считается «нет»: как и везде в Typemo, это ошибка `CastError`. Явный `null` на поле без `nullable` — тоже ошибка, а не запрос значения по умолчанию.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
@Schema({ collection: "members" })
class Member extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { default: 0 }) score!: Defaulted<number>;
}
const Members = client.connection.model(Member);
// ---cut---
try {
  await Members.create({ name: "Ann", score: undefined } as never);
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to number failed at path "score" for undefined: undefined is never a value; omit the field instead [undefined]
const zero = await Members.create({ name: "Bob", score: 0 });
console.log(zero.score);
// → 0
```

Нуль, пустая строка и `false` — обычные значения и сохраняются как есть: по умолчанию подставляется только при отсутствии, а не при «ложных» значениях.

## Как выбрать

Задайте себе один вопрос: **может ли документ существовать без этого поля?** Если нет и значение известно заранее (роль, статус, счётчик), используйте `default` вместе с `Defaulted<T>`. Если значение должно прийти от пользователя, а подставленное было бы ложью (адрес, имя), используйте [`required`](./required-and-null.mdx). Если значение вычисляется из других полей и не должно храниться, это не `default`, а геттер: [Виртуальные поля](./virtuals.mdx).

## Когда это не нужно

`default` не заменяет `required`: он подставляет значение, но не запрещает явно передать другое допустимое. Метки времени создания и изменения не нужно делать через `default: () => new Date()`: для них есть базовые классы [`Timestamped`](../reference/schemas/base-classes.mdx#timestamped), см. [Метки времени и версии](./timestamps-and-versions.mdx). Идентификатор `_id` получает значение от [`Entity`](../reference/schemas/base-classes.mdx#entity) сам.

## Частые ошибки

### Значение по умолчанию не подходит полю

Модель не собирается: `default: "x"` на числовом поле бросает `ConfigurationError` при получении модели, а не при первой записи.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
@Schema({ collection: "members" })
class Member extends Entity {
  @Prop(() => Number, { default: "x" as never }) // неправильно: строка в числовом поле
  score!: Defaulted<number>;
}
try {
  client.connection.model(Member);
} catch (error) {
  console.log((error as Error).message);
}
// → Member.score: the "default" value is not a value of the field (got "x" (string)): expected a number [type]
```

Исправьте значение: оно должно быть значением того типа, который принимает поле, и пройти его проверки.

### `default` без `Defaulted<T>` и наоборот

Компилятор следит за парой: `@Prop "score": "default" is set, declare the field as Defaulted<T>` и `the field is Defaulted<T>, but "default" is missing`. Причина — `Defaulted<T>` определяет, что поле необязательно при создании: без пары типы обещали бы одно, а схема делала другое. Добавьте недостающую половину пары.

### Инициализатор в теле класса вместо `default`

`score: number = 0` в теле класса не задаёт значение по умолчанию схемы. Typemo отклоняет такое при сборке модели: `Member: field(s) "score" get a value from an initializer or the constructor; use the "default" option — service fields are filled by Typemo`. Перенесите значение в опцию `default`.

## Полный пример

Один файл собирает участника со всеми видами значений и показывает, что сохранилось. Код читателя, которого нет в Typemo, помечен `__…__`.

```ts twoslash title="community/members.service.ts"
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
// модель: постоянное значение, функция и массив (пустой сам)
@Schema({ collection: "members" })
class Member extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" }) role!: Defaulted<"user" | "admin">;
  @Prop(() => Number, { default: 0 }) score!: Defaulted<number>;
  @Prop(() => Date, { default: () => new Date() }) joined!: Defaulted<Date>;
  @Prop(() => [String]) tags!: string[];
}

// регистрация: передаём только имя
export const join = async (name: string) => {
  const Members = client.connection.model(Member);
  const member = await Members.create({ name });
  return member.$toPlain();
};

const dto = await join("Ann");
console.log(dto.role, dto.score, dto.tags, dto.joined instanceof Date);
// → user 0 [] true
```

<Callout type="migration">

Опция `default` знакома по Mongoose, но в Typemo к ней добавлен тип `Defaulted<T>`: он сообщает компилятору, что поле можно не передавать при создании, и компилятор проверяет пару `default` и `Defaulted<T>` в обе стороны. Массив без значения Typemo создаёт пустым сам, как Mongoose, поэтому `default: () => []` не нужен.

</Callout>
