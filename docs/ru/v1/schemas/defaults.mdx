**Значение по умолчанию** Typemo записывает в поле сам, если вы его не передали. Роль `user` новому участнику, дата регистрации, начальный набор меток. Задаётся оно опцией [`default`](../reference/schemas/prop.mdx#default), и повторять одно и то же значение в каждом [`create`](../reference/writes/writes.mdx#create) больше не нужно.

Поле с такой опцией объявляют особым типом [`Defaulted<T>`](../reference/schemas/field-markers.mdx#defaulted). Так типы узнают, что при создании поле можно не передавать, а после чтения оно есть всегда. Массивам этот тип не нужен, поле-массив и так необязательно при создании.

Главное — понимать, **когда** значение подставляется. При создании документа и при upsert — да. При обычном обновлении и при чтении через `.lean()` и `.plain()` — нет. Ниже всё это на примерах.

## Что понадобится [#prerequisites]

Модель, описанная по руководству [Описать модель](./define-model.mdx), и понимание разницы между отсутствием поля и `null` из руководства [Обязательные поля, null и отсутствие](./required-and-null.mdx). Примеры строят модель участника сообщества.

## Быстрый путь [#quick-start]

`default` принимает значение или функцию без аргументов. Поле с ним объявляется как `Defaulted<T>`.

```ts twoslash title="community/member.ts"
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
@Schema({ collection: "members" })
export class Member extends Entity {
  @Prop(() => String, { required: true })
  name!: string;

  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" })
  role!: Defaulted<"user" | "admin">;
}

const Members = client.connection.model(Member);
const member = await Members.create({ name: "Ann" });
console.log(member.role);
// → user
```

`role` не передали, и он получил значение `user`. Передать его, конечно, тоже можно, `create({ name: "Bob", role: "admin" })` сохранит `admin`. Ниже разберём разные виды значений и ситуации, когда они подставляются.

## Подставить постоянное значение [#constant-value]

Число, строку, `null` и другие простые значения пишут прямо. Поле со значением по умолчанию остаётся обычным полем и хранится в базе как любое другое.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
@Schema({ collection: "members" })
class Member extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { default: 0 }) // [!code highlight]
  score!: Defaulted<number>;
  @Prop(() => String, { nullable: true, default: null }) // [!code highlight]
  note!: Defaulted<string | null>;
}
const Members = client.connection.model(Member);
const member = await Members.create({ name: "Ann" });
console.log(member.score, member.note);
// → 0 null
```

`default: null` разрешён только вместе с `nullable: true`. Значение по умолчанию должно быть таким, какое поле принимает, иначе документ нарушал бы собственную схему сразу после создания.

## Вычислять значение для каждого документа [#computed-per-document]

Если у каждого документа значение своё, передайте функцию. Typemo вызывает её заново при каждом создании, так что `() => new Date()` даёт дату создания именно этого документа, а не дату загрузки модуля.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
@Schema({ collection: "members" })
class Member extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Date, { default: () => new Date() }) // [!code highlight]
  joined!: Defaulted<Date>;
  @Prop(() => [String], { default: () => ["new"] }) // [!code highlight]
  tags!: string[];
}
const Members = client.connection.model(Member);
const first = await Members.create({ name: "Ann" });
const second = await Members.create({ name: "Bob" });
first.tags.push("vip");
console.log(first.tags.length, second.tags.length);
// → 2 1
console.log(first.joined.getTime() === second.joined.getTime());
// → false
```

Массив, как и любое значение, вычисляется для каждого документа отдельно. Меняете метки первого участника — второго это не касается. Даже массив-литерал (`default: ["new"]`) Typemo копирует для каждого документа, так что общего изменяемого объекта между ними не появится. Тип поля-массива остаётся обычным `string[]`. `Defaulted<string[]>` разрешён, но не нужен, ведь и без `default` массив получает `[]` (подробнее в руководстве [Массивы](./arrays.mdx)).

## Когда значение подставляется [#when-default-applies]

Значение подставляется, когда документ создаётся.

- Через `create`, [`insertMany`](../reference/writes/writes.mdx#insert-many) и [`Model.new`](../reference/documents/model-document-methods.mdx#model.new).
- При upsert, то есть когда обновление не нашло документ и создало его само.

При upsert Typemo добавляет недостающие значения по умолчанию только к вставке, и существующий документ не перезаписывается.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
@Schema({ collection: "members" })
class Member extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" }) role!: Defaulted<"user" | "admin">;
  @Prop(() => Number, { default: 0 }) score!: Defaulted<number>;
}
const Members = client.connection.model(Member);
// ---cut---
await Members.updateOne({ name: "Zed" }, { $set: { score: 5 } }, { upsert: true });
const zed = await Members.findOne({ name: "Zed" }).plain();
console.log(zed?.role, zed?.score);
// → user 5
```

Обновление вставило документ с `score: 5` и само дописало `role: "user"`. А вот обычное обновление существующего документа значения по умолчанию не подставляет. Если поля в документе не было, его и не будет. Это разумно, ведь `updateOne` меняет то, что вы попросили, а не «достраивает» документ.

## Прочитать старый документ [#read-old-document]

Документы в базе могли появиться раньше, чем вы добавили `default`. До появления поля или вообще из другой программы. Документ модели при чтении получает значение по умолчанию, поэтому `member.role` не бывает `undefined`. А `.lean()` и `.plain()` отдают то, что лежит в базе, как есть. Документ они не создают и ничего не достраивают.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
@Schema({ collection: "members" })
class Member extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" }) role!: Defaulted<"user" | "admin">;
}
const Members = client.connection.model(Member);
// ---cut---
// документ, записанный до появления поля role
await client.unsafeDriver().db("shop").collection("members").insertOne({ name: "Old" });

const asDocument = await Members.findOne({ name: "Old" }).orFail();
console.log(asDocument.role);
// → user
const asPlain = await Members.findOne({ name: "Old" }).plain();
console.log(asPlain);
// → { _id: "…", name: "Old" }
```

У этого есть обратная сторона. Загрузите такой документ, измените в нём другое поле и сохраните — подставленные значения попадут в изменения и запишутся в базу. В [`$getChanges()`](../reference/documents/document-api.mdx#get-changes) после `score = 4` оказались и `score`, и `role: "user"`, а у модели с массивом `tags` с `default` — ещё и `tags`. Массив без ключа ведёт себя так же. Документ читает его пустым, а `$save` записывает. Старые документы, которые вы не загружаете как документы модели, так и остаются без поля.

Значит, если вы добавили `default` к уже заполненной коллекции, а клиентам отдаёте `.plain()`, старые документы придут без этого поля. Хотя тип результата обещает, что поле есть. Если это важно, заполните поле в базе разово и не надейтесь на подстановку при чтении.

## Не передавать `undefined` и `null` явно [#no-explicit-undefined]

Значение по умолчанию подставляется, только когда поля **нет** в данных. Явный `undefined` за «нет» не считается. Как и везде в Typemo, это ошибка `CastError`. Явный `null` на поле без `nullable` — тоже ошибка, а не просьба подставить значение по умолчанию.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
@Schema({ collection: "members" })
class Member extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { default: 0 }) score!: Defaulted<number>;
}
const Members = client.connection.model(Member);
// ---cut---
try {
  await Members.create({ name: "Ann", score: undefined } as never);
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to number failed at path "score" for undefined: undefined is never a value; omit the field instead [undefined]
const zero = await Members.create({ name: "Bob", score: 0 });
console.log(zero.score);
// → 0
```

Ноль, пустая строка и `false` — обычные значения и сохраняются как есть. Значение по умолчанию подставляется только при отсутствии поля, а не при «ложных» значениях.

## Как выбрать [#how-to-choose]

Спросите себя — **может ли документ существовать без этого поля?**

- **Нет, и значение известно заранее** (роль, статус, счётчик) — `default` вместе с `Defaulted<T>`.
- **Значение должно прийти от пользователя, а подставленное было бы враньём** (адрес, имя) — [`required`](./required-and-null.mdx).
- **Значение вычисляется из других полей и храниться не должно** — это не `default`, а геттер ([Виртуальные поля](./virtuals.mdx)).

## Когда это не нужно [#when-not-to-use]

`default` не заменяет `required`. Он подставляет значение, но не запрещает явно передать другое допустимое. Метки времени создания и изменения не нужно делать через `default: () => new Date()`. Для них есть базовые классы [`Timestamped`](../reference/schemas/base-classes.mdx#timestamped), см. [Метки времени и версии](./timestamps-and-versions.mdx). А `_id` получает значение от [`Entity`](../reference/schemas/base-classes.mdx#entity) сам.

## Если что-то пошло не так [#troubleshooting]

**Значение по умолчанию не подходит полю.** Модель не собирается. `default: "x"` на числовом поле бросает `ConfigurationError` при получении модели, а не при первой записи.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
@Schema({ collection: "members" })
class Member extends Entity {
  @Prop(() => Number, { default: "x" as never }) // неправильно: строка в числовом поле
  score!: Defaulted<number>;
}
try {
  client.connection.model(Member);
} catch (error) {
  console.log((error as Error).message);
}
// → Member.score: the "default" value is not a value of the field (got "x" (string)): expected a number [type]
```

Исправьте значение. Оно должно быть того типа, который принимает поле, и проходить его проверки.

**`default` без `Defaulted<T>` или наоборот.** Компилятор следит за парой и выдаёт `@Prop "score": "default" is set, declare the field as Defaulted<T>` или `the field is Defaulted<T>, but "default" is missing`. Именно `Defaulted<T>` говорит, что поле необязательно при создании. Без пары типы обещали бы одно, а схема делала бы другое. Добавьте недостающую половину.

**Инициализатор в теле класса вместо `default`.** `score: number = 0` в теле класса значение по умолчанию схемы не задаёт. Typemo отклонит это при сборке модели — `Member: field(s) "score" get a value from an initializer or the constructor; use the "default" option — service fields are filled by Typemo`. Перенесите значение в опцию `default`.

## Полный пример [#full-example]

В одном файле участник со всеми видами значений, и видно, что сохранилось. Код, которого нет в Typemo, помечен `__…__`.

```ts twoslash title="community/members.service.ts"
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Computed, type Defaulted, type Hidden, type Immutable, type Ref, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
// ---cut---
// модель: постоянное значение, функция и массив (пустой сам)
@Schema({ collection: "members" })
class Member extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" }) role!: Defaulted<"user" | "admin">;
  @Prop(() => Number, { default: 0 }) score!: Defaulted<number>;
  @Prop(() => Date, { default: () => new Date() }) joined!: Defaulted<Date>;
  @Prop(() => [String]) tags!: string[];
}

// регистрация: передаём только имя
export const join = async (name: string) => {
  const Members = client.connection.model(Member);
  const member = await Members.create({ name });
  return member.$toPlain();
};

const dto = await join("Ann");
console.log(dto.role, dto.score, dto.tags, dto.joined instanceof Date);
// → user 0 [] true
```

<Callout type="migration">

Опция `default` знакома по Mongoose, но в Typemo к ней добавлен тип `Defaulted<T>`. Он говорит компилятору, что при создании поле можно не передавать, и компилятор проверяет пару `default` и `Defaulted<T>` в обе стороны. Массив без значения Typemo, как и Mongoose, создаёт пустым сам, так что `default: () => []` не нужен.

</Callout>
