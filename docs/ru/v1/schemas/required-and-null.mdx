У поля документа в MongoDB три состояния. В нём лежит **значение**, в нём лежит **`null`** или его **нет вообще**. Для базы это три разных случая, и фильтры, индексы и проверки ведут себя в них по-разному. Typemo эти состояния молча не смешивает.

- Опция [`required`](../reference/schemas/prop.mdx#required) говорит, что поле обязано быть в документе.
- Опция [`nullable`](../reference/schemas/prop.mdx#nullable) разрешает `null`.
- `undefined` значением не считается никогда.

Без `nullable` обязательное поле не может быть и `null`. С `nullable` ключ обязателен, а `null` допустим.

Если MongoDB для вас в новинку, помните, что она хранит документы как есть. Не записали поле — его нет. А `null` — это записанное значение «пусто». Проверка `user.nickname == null` одно от другого не отличит, а база отличает.

## Что понадобится [#prerequisites]

Модель, описанная по руководству [Описать модель](./define-model.mdx). Примеры строят профиль пользователя сайта и добавляют в него поля по одному.

## Быстрый путь [#quick-start]

Три поля — три состояния. Обязательное, допускающее `null` и необязательное.

<Snippet id="schemas/required-and-null/quick-start" title="users/profile.ts" twoslash />

`bio` не передали, и в документе его нет. `nickname` передали как `null`, и он записан. Ниже разберём каждый случай.

## Сделать поле обязательным [#required-field]

С `required: true` документ без этого поля не сохранится, и `null` вместо значения на обычном поле тоже не пройдёт. Опция задаётся явно и не выводится из `?` в объявлении. `?` описывает тип в TypeScript, а обязательность — правило для данных, и решаются они отдельно. Так что `login!: string` с `required: true` — обязательное поле, а `bio?: string` без `required` — необязательное. Компилятор проверяет вызов `create`, и без обязательного поля код не скомпилируется.

<Snippet id="schemas/required-and-null/required-field" twoslash />

В коде без типов, например с данными из внешнего запроса, то же самое поймает библиотека во время работы. Она бросит [`ValidationError`](../reference/errors/data-errors.mdx#validation-error) с причиной `required`.

<Snippet id="schemas/required-and-null/required-field-2" twoslash />

## Разрешить null [#nullable]

Без `nullable` значение `null` на поле не пройдёт. Это не пустая строка и не отсутствие, а отдельное значение, и принять его молча за что-то другое значило бы гадать. `nullable: true` объявляет `null` законным значением поля. Тип поля при этом должен содержать `| null`, и компилятор проверяет это в обе стороны.

<Snippet id="schemas/required-and-null/nullable" twoslash />

Первый документ хранит `nickname: null`, а у второго этого поля нет. Разница видна и в самой базе, и в результатах запросов. [`.lean()`](../reference/query/reading.mdx#lean) отдаёт `null` для первого, а у второго ключа просто нет. Ошибка на `bio` — это [`CastError`](../reference/errors/data-errors.mdx#cast-error) с причиной `null`.

Забудете `| null` в типе или, наоборот, добавите его без `nullable: true` — компилятор скажет об этом. Сообщения такие — `@Prop "nickname": "nullable" is set, but the field type has no "| null"` и `@Prop "nickname": the field type has "| null", add nullable: true`.

## Требовать ключ и разрешить null [#required-nullable]

На одно поле можно поставить обе опции, `required: true` вместе с `nullable: true`. Тогда ключ в документе обязателен, а значением может быть и настоящее значение, и `null`. «Мы спросили, ответа нет» отличается от «не спросили». Тип поля содержит `| null`, а чтение отдаёт его без `undefined`.

<Snippet id="schemas/required-and-null/required-nullable" twoslash />

Без ключа документ не сохранится, а `$unset` такого поля запрещён, ведь он убрал бы обязательный ключ. Очистить значение можно записью `null`, `$set: { phone: null }` проходит. Присвоить `undefined` в загруженном документе тоже нельзя, будет та же ошибка `required`. На обычном `nullable`-поле это значило бы `$unset`.

## Почему `undefined` не значение [#why-undefined]

`undefined` — особое значение JavaScript, и MongoDB его не хранит. Драйвер в зависимости от настроек либо пропускает такое поле, либо пишет `null`. Typemo не полагается ни на то, ни на другое и сразу отвергает `undefined` в данных. Если поля нет, **просто не передавайте его**.

<Snippet id="schemas/required-and-null/why-undefined" twoslash />

Тогда `nickname: user.nick` при отсутствующем `user.nick` не превратится втихую в запись `null` или в потерянное поле.

## Проверить null и отсутствие в фильтре [#filter-null]

Фильтр `{ nickname: null }` находит в MongoDB документы, где поле равно `null`, **и** документы, где поля нет. Так работает сама база. Чтобы найти только документы без поля, используйте `$exists: false`.

<Snippet id="schemas/required-and-null/filter-null" twoslash />

Для поля без `nullable` фильтр `{ field: null }` смысла не имеет, и библиотека говорит об этом прямо — `Cast to string failed at path "bio" for null: null is not a value of this path (it is not nullable); an absent field is { $exists: false } [null]`. Пустого результата там, где вы ждали документы, не будет.

## Убрать значение при обновлении [#unset-on-update]

«Очистить» поле в обновлении можно тремя способами, и значат они разное.

- `$set` с `null` записывает `null`. Разрешён только для `nullable`.
- `$unset` убирает поле из документа. Для обязательных полей запрещён, иначе документ перестал бы соответствовать схеме.
- `$set` с `undefined` отвергается, как и в `create`.

<Snippet id="schemas/required-and-null/unset-on-update" twoslash />

В загруженном документе присвоить полю `undefined` значит «убрать поле». В изменениях появится `$unset`, а не запись `null`. Подробности — в руководстве [Изменить и сохранить документ](../documents/change-and-save.mdx).

## Как выбрать [#how-to-choose]

Спросите себя — **что должен значить пустой результат для того, кто читает данные?**

- **Данные пока неизвестны, и поле пусть просто отсутствует** — оставьте его необязательным, без `nullable`.
- **Мы точно знаем, что значения нет, и хотим это хранить** (например, пользователь явно отказался указывать телефон) — `nullable: true`.
- **Без значения документ теряет смысл** (логин, сумма, владелец) — `required: true`.
- **Ключ обязан быть, но значением может быть «нет»** (телефон, который пользователь явно не указал) — обе опции.

Проверить себя просто. Если понадобится отличать «не спросили» от «спросили, ответа нет», нужны оба состояния, а значит, и `nullable`.

## Когда это не нужно [#when-not-to-use]

Значение, которое подставляется само, если его не передали, обязательным делать не нужно. Для него есть [`default`](./defaults.mdx). Формат и границы значения — тоже не забота `required`, для этого есть [`min`, `max`, `match` и остальные опции](./validation.mdx). Пара `required: true` и `nullable: true` нужна, только когда отсутствие ключа недопустимо, а `null` что-то значит. Если отличать «не спросили» от «ответа нет» не нужно, хватит одной из опций.

## Если что-то пошло не так [#troubleshooting]

**Обязательное поле с `nullable` принимает `null`, но не отсутствие.** Поле объявлено `required: true, nullable: true`, документ создают без него, и `create` падает. Так и задумано. `required` требует ключ, а `nullable` разрешает только значение `null`, но не отсутствие. Ошибка называет поле — `Validation failed: "phone": the field is required [required]`. Передайте `null` явно или уберите `required`, если поля может не быть.

**Фильтр по `null` находит лишние документы.** Запрос `{ nickname: null }` вернул и тех, у кого поле пусто, и тех, у кого его нет. Так работает сама MongoDB, как описано выше. Если нужны только настоящие `null`, добавьте условие `$exists: true`.

**`undefined` пришёл из необязательной переменной.** `create({ nickname: maybe })` падает с `undefined is never a value`, потому что `undefined` не значение. Соберите объект без этого ключа — `...(maybe === undefined ? {} : { nickname: maybe })`.
