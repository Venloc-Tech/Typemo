**Виртуального поля** нет в базе, оно вычисляется при чтении. В Typemo их два вида.

- **Геттер** класса собирает значение из полей документа, например полное имя из имени и фамилии.
- **Виртуальная связь** [`@Virtual`](../reference/schemas/virtual.mdx#virtual) подтягивает документы другой модели по обратной ссылке. Например, все посты автора, у которого своего списка постов нет.

Зачем это нужно? Чтобы не хранить то, что можно вычислить. Копия устаревает, а вычисленное значение всегда свежее. Ни тот, ни другой вид не попадает в запись, в фильтры и в результат `.lean()`.

## Вычислить значение из полей [#computed-value]

Геттер без сеттера и есть вычисляемое поле. Декоратор не нужен, класс и так говорит, что это не данные. Тип `Computed<T>` помогает компилятору отличить вычисляемое значение от хранимого и не пустить его в фильтры и запись. Значение приводят через `as Computed<string>`, потому что обычную строку в маркерный тип компилятор сам не превратит.

У загруженного документа вычисляемое поле есть, но в результаты по умолчанию оно не входит. Ни `.lean()`, ни `.plain()`, ни [`$toPlain()`](../reference/documents/document-api.mdx#to-plain) его не содержат, пока вы не попросите `{ virtuals: true }`. Присвоить ему значение нельзя.

<Snippet id="schemas/virtuals/computed-value" twoslash />

Искать по вычисляемому полю нельзя, его нет в базе. Библиотека прямо скажет об этом, а не вернёт пустой результат — `StrictModeError: filter: "label" is not a field of Author [unknown-path]`. Выразите условие через настоящие поля, из которых значение вычисляется.

## Подтянуть документы по обратной связи [#populate-reverse]

Ссылка живёт у поста, это он хранит `author`. Чтобы получить посты автора, не нужно заводить у автора список идентификаторов и следить за ним. Достаточно описать связь. [`@Virtual`](../reference/schemas/virtual.mdx#virtual) называет три вещи.

- Модель — [`ref`](../reference/schemas/virtual.mdx#ref).
- Поле автора, по которому идёт сопоставление, — [`localField`](../reference/schemas/virtual.mdx#local-field), обычно `_id`.
- Поле поста, где лежит значение, — [`foreignField`](../reference/schemas/virtual.mdx#foreign-field).

Само поле ничего не хранит и заполняется, только когда вы просите `populate`.

<Snippet id="schemas/virtuals/populate-reverse" twoslash />

Без `populate` поле равно `undefined`, лишних запросов библиотека не делает. Опция `count: true` подставляет число документов вместо самих документов, а [`justOne`](../reference/schemas/virtual.mdx#just-one) — один документ вместо массива. Флаги в типе `VirtualRef<M, JustOne, Count>` должны совпадать с опциями, и компилятор это проверяет. Сортировку, ограничение и фильтр связи задают [`options`](../reference/schemas/virtual.mdx#options), [`match`](../reference/schemas/virtual.mdx#match) и [`perDocumentLimit`](../reference/schemas/virtual.mdx#per-document-limit).

## Как выбрать [#how-to-choose]

Спросите себя — **вычисляется ли значение из полей этого же документа?**

- **Да** (полное имя, итог по строкам) — геттер с `Computed<T>`.
- **Значение живёт в других документах** (посты автора, число комментариев) — `@Virtual`.
- **По значению нужно искать и сортировать в базе** — виртуальное поле не подойдёт. Храните его настоящим полем и обновляйте при изменениях.

## Когда это не нужно [#when-not-to-use]

Значение, по которому вы фильтруете или строите индекс, должно лежать в базе, а у виртуальных полей путей в базе нет. Для вычислений над всей коллекцией есть конвейер ([Первая агрегация](../aggregation/first-aggregation.mdx)). И помните, что геттер выполняется при каждом обращении. Если расчёт тяжёлый, сохраните результат в поле.

## Если что-то пошло не так [#troubleshooting]

**Виртуальное поле пропало из ответа.** `author.label` есть, а в `$toPlain()` его нет. Вычисляемые значения по умолчанию в сериализацию не входят, иначе их не хватало бы тем, кто читает через `.lean()`. Передайте `{ virtuals: true }`.

**`@Virtual` на поле с другим типом.** Поле объявлено строкой, а не `VirtualRef`, и компилятор остановит с `@Virtual "posts": declare the field as VirtualRef<Model, JustOne, Count>`. Объявите поле типом `VirtualRef<Post>`.

**`@Prop` на геттере.** `@Prop` на методе или геттере даёт `ConfigurationError` при объявлении класса — `G: @Prop on "x", which is a method or an accessor (getters are virtuals and need no decorator)`. Уберите декоратор.

<Callout type="migration">

В Mongoose виртуальные поля описывают через `schema.virtual(...)`, в том числе связи с `localField` и `foreignField`. В Typemo обычный виртуал заменяет геттер класса с типом `Computed<T>`, а связь описывает декоратор `@Virtual` с теми же понятиями — `ref`, `localField`, `foreignField`, `justOne`, `count`. Без `{ virtuals: true }` виртуальные поля не входят ни в `lean()`, ни в `$toPlain()`.
