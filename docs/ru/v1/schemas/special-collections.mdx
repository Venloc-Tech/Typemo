Обычной коллекции достаточно почти всегда, но у MongoDB есть виды коллекций с особыми свойствами: **ограниченная** хранит только последние записи, коллекция **временных рядов** компактно хранит измерения, у любой коллекции может быть **валидатор** — правила, по которым сервер проверяет каждый документ. Typemo описывает их прямо в [`@Schema`](../reference/schemas/schema.mdx#schema): опция объявляет свойство, а сама коллекция создаётся при [`connection.init()`](../reference/connection/connection.mdx#connectioninit) с этими параметрами. Важное следствие: параметры действуют только при создании коллекции, а у уже существующей их этим способом не изменить.

## Что предполагается

Примеры используют клиент из руководства [Подключиться к базе](../connection/connect.mdx). Создание коллекций и работа с уже существующими описаны в руководстве [Создание коллекций](../collections/create.mdx); здесь — что выбрать и что получится.

## Быстрый путь

Ограниченная коллекция журнала на пять записей:

```ts twoslash title="logs/log.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "recent_logs", capped: { size: 4096, max: 5 } }) // [!code highlight]
class Log extends Entity {
  @Prop(() => Number, { required: true }) n!: number;
}

const Logs = client.db().model(Log);
await client.db().init();
for (let n = 1; n <= 7; n++) await Logs.create({ n });
const rows = await Logs.find().sort({ n: 1 }).plain();
console.log(rows.map((row) => row.n));
// → [3, 4, 5, 6, 7]
```

Остальная страница разбирает остальные виды.

## Ограниченная коллекция

[`capped`](../reference/schemas/schema.mdx#capped) делает коллекцию ограниченной: `size` — предельный размер в байтах (обязателен), `max` — предельное число документов. Когда предел достигнут, сервер вытесняет самые старые документы. Так хранят журналы, нужные только за последнее время, и кольцевые буферы событий. Как видно выше, после семи записей осталось пять последних.

## Временные ряды

Коллекция временных рядов хранит измерения датчиков, курсы, метрики. Сервер группирует их в корзины по времени и метаданным, поэтому места нужно меньше, а выборки по времени быстрее. [`timeseries`](../reference/schemas/schema.mdx#timeseries) требует `timeField` — обязательное поле типа `Date` — и принимает `metaField` (что измеряется), `granularity` (`seconds`, `minutes`, `hours`) и `expireAfterSeconds` (автоудаление).

```ts twoslash title="sensors/reading.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({
  collection: "readings",
  timeseries: { timeField: "at", metaField: "sensor", granularity: "minutes" }, // [!code highlight]
})
class Reading extends Entity {
  @Prop(() => Date, { required: true }) at!: Date;
  @Prop(() => String) sensor?: string;
  @Prop(() => Number) value?: number;
}

const Readings = client.db().model(Reading);
await client.db().init();
await Readings.create({ at: new Date("2026-01-01T00:00:00Z"), sensor: "s1", value: 1 });
const rows = await Readings.find({ sensor: "s1" }).plain();
console.log(rows.map((row) => row.value));
// → [1]
```

Ограничения проверяются при описании модели: `timeField` должен быть обязательным (`timeseries: timeField "at" must be required (every measurement has it)`), а коллекция временных рядов не сочетается с `capped` и `clustered` и не допускает уникальных индексов.

## Кластерная коллекция

[`clustered`](../reference/schemas/schema.mdx#clustered) хранит документы в порядке `_id`, а индекс по `_id` совпадает с самой коллекцией. Это экономит место и ускоряет выборки по диапазону `_id`. Объект принимает `name` и `expireAfterSeconds` (для `_id` типа `Date`). С `capped` и `timeseries` она не сочетается: коллекция временных рядов уже кластерная.

## Сортировка строк по умолчанию

[`collation`](../reference/schemas/schema.mdx#collation) задаёт правила сравнения строк для всей коллекции: язык, чувствительность к регистру и акцентам. С `strength: 2` поиск не различает регистр:

```ts twoslash title="accounts/named.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "names", collation: { locale: "en", strength: 2 } }) // [!code highlight]
class Named extends Entity {
  @Prop(() => String) name?: string;
}

const Names = client.db().model(Named);
await client.db().init();
await Names.create({ name: "Anna" });
const found = await Names.find({ name: "anna" }).plain();
console.log(found.length);
// → 1
```

Текстовый индекс и индекс `2d` сортировку не поддерживают, поэтому на такой коллекции их объявляют с `collation: { locale: "simple" }`, иначе `ConfigurationError`.

## Валидатор на сервере

Typemo проверяет данные до записи, но записать в базу могут и другие программы. [`validator`](../reference/schemas/schema.mdx#validator) строит из схемы правила `$jsonSchema` и создаёт их на сервере: коллекция отвергает документы с неверными типами, без обязательных полей, вне `enum` и границ. Значение `true` даёт уровень `strict` и действие `error`; объект уточняет [`validationLevel`](../reference/schemas/schema.mdx#validationlevel) и [`validationAction`](../reference/schemas/schema.mdx#validationaction).

```ts twoslash title="accounts/checked.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "checked", validator: true }) // [!code highlight]
class Checked extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { min: 0 }) age?: number;
}

const Items = client.db().model(Checked);
await client.db().init();
const driver = client.unsafeDriver().db("app").collection("checked");
try {
  await driver.insertOne({ name: 5 });
} catch (error) {
  console.log((error as Error).message);
}
// → Document failed validation
```

Здесь в обход Typemo, через драйвер, записан документ с числом в строковом поле, и сервер его отклонил. Свои функции `validate` и правила ключей Map на сервере выразить нельзя: их проверяет только Typemo. Правила строятся генератором [`JsonSchemaGenerator`](./json-and-standard-schema.mdx).

## Остальные опции

[`changeStreamPreAndPostImages`](../reference/schemas/schema.mdx#changestreampreandpostimages) включает запись состояния документа до и после изменения: она нужна потокам изменений, которые просят `fullDocumentBeforeChange`. [`shardKey`](../reference/schemas/schema.mdx#shardkey) сообщает ключ шардирования, чтобы `$save` находил документ по исходным значениям ключа. [`autoCreate: false`](../reference/schemas/schema.mdx#autocreate) исключает коллекцию из `init()` и `syncAll()`, если коллекцией управляете вы.

Опции [`readConcern`](../reference/schemas/schema.mdx#readconcern) и [`writeConcern`](../reference/schemas/schema.mdx#writeconcern) задают умолчания для операций модели: они уходят на сервер с каждым чтением и записью, а уровень, заданный у самой операции, главнее. Внутри транзакции схемные уровни не отправляются, там действуют настройки транзакции.

## Как выбрать

Задайте себе один вопрос: **что должна гарантировать коллекция?** Только последние записи — `capped`. Измерения во времени — `timeseries`. Чужие программы тоже пишут в неё — `validator`. Поиск без учёта регистра — `collation`. Для остального обычная коллекция подойдёт.

## Когда это не нужно

Не делайте коллекцию ограниченной, если старые документы должны храниться: сервер вытеснит их без предупреждения. Не используйте временные ряды для обычных сущностей с изменяемыми полями. Не включайте валидатор, если схема часто меняется: сервер начнёт отвергать документы, пока вы не обновите коллекцию (как это сделать, описано в руководстве [Создание коллекций](../collections/create.mdx)).

## Частые ошибки

### Опции не применились к существующей коллекции

Вы добавили `capped` или `validator` к коллекции, которая уже есть в базе. `init()` сравнивает параметры и не меняет их молча: он бросает [`SyncError`](../reference/errors/configuration-errors.mdx#syncerror). Свойства, которые MongoDB у существующей коллекции изменить не умеет (сделать обычную коллекцию ограниченной, превратить её во временной ряд или кластерную, сменить коллацию), дают `collection "legacy_logs": exists with options MongoDB cannot change (capped): drop the collection and create it again`. Изменяемые (например, валидатор) — `collection "legacy_checked": exists with other options (validator); run ensureCollection({ update: true }) to change them with collMod`. Создайте новую коллекцию с нужными параметрами или измените существующую по руководству [Создание коллекций](../collections/create.mdx#изменить-параметры-существующей-коллекции).

### Ограничения временных рядов

Уникальный индекс, `capped` и `clustered` вместе с `timeseries` отвергаются: сервер их не поддерживает. Typemo сообщает об этом при описании модели, до обращения к базе.

## Полный пример

```ts twoslash title="sensors/sensors.service.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";

@Schema({
  collection: "readings",
  timeseries: { timeField: "at", metaField: "sensor", granularity: "minutes", expireAfterSeconds: 3600 },
})
class Reading extends Entity {
  @Prop(() => Date, { required: true }) at!: Date;
  @Prop(() => String) sensor?: string;
  @Prop(() => Number) value?: number;
}

@Schema({ collection: "recent_alerts", capped: { size: 8192, max: 100 } })
class Alert extends Entity {
  @Prop(() => String, { required: true }) text!: string;
}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Readings = client.db().model(Reading);
const Alerts = client.db().model(Alert);

// старт: коллекции создаются с нужными параметрами
await client.db().init();

// запись измерения и тревоги
export const record = async (sensor: string, value: number) => {
  await Readings.create({ at: new Date(), sensor, value });
  if (value > 100) await Alerts.create({ text: `${sensor} is too high` });
};
```
