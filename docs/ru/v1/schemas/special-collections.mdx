Почти всегда хватает обычной коллекции. Но у MongoDB есть коллекции с особыми свойствами.

- **Ограниченная** хранит только последние записи.
- Коллекция **временных рядов** компактно хранит измерения.
- **Валидатор** может быть у любой коллекции. Это правила, по которым сервер проверяет каждый документ.

Typemo описывает всё это прямо в [`@Schema`](../reference/schemas/schema.mdx#schema). Опция объявляет свойство, а сама коллекция создаётся с этими параметрами при [`connection.init()`](../reference/connection/connection.mdx#connection.init). Отсюда важное следствие. Параметры действуют только при создании, и у существующей коллекции так их не поменять.

## Что понадобится [#prerequisites]

Клиент из руководства [Подключиться к базе](../connection/connect.mdx). Как создавать коллекции и работать с уже существующими, рассказывает руководство [Создание коллекций](../collections/create.mdx). Здесь речь о том, что выбрать и что получится.

## Ограниченная коллекция [#capped-collection]

[`capped`](../reference/schemas/schema.mdx#capped) делает коллекцию ограниченной. `size` задаёт предельный размер в байтах и обязателен, `max` — предельное число документов. Когда предел достигнут, сервер вытесняет самые старые документы. Так хранят журналы, нужные только за последнее время, и кольцевые буферы событий. В примере выше после семи записей осталось пять последних.

## Временные ряды [#time-series]

Коллекция временных рядов хранит измерения датчиков, курсы, метрики. Сервер раскладывает их по корзинам по времени и метаданным, так что места нужно меньше, а выборки по времени идут быстрее. [`timeseries`](../reference/schemas/schema.mdx#timeseries) требует `timeField` — обязательное поле типа `Date`. Ещё он принимает `metaField` (что измеряется), `granularity` (`seconds`, `minutes`, `hours`) и `expireAfterSeconds` (автоудаление).

<Snippet id="schemas/special-collections/time-series" title="sensors/reading.ts" twoslash />

Ограничения проверяются при описании модели. `timeField` должен быть обязательным (`timeseries: timeField "at" must be required (every measurement has it)`). Коллекция временных рядов не сочетается с `capped` и `clustered` и не допускает уникальных индексов.

## Кластерная коллекция [#clustered-collection]

[`clustered`](../reference/schemas/schema.mdx#clustered) хранит документы в порядке `_id`, и индекс по `_id` совпадает с самой коллекцией. Это экономит место и ускоряет выборки по диапазону `_id`. Объект принимает `name` и `expireAfterSeconds` (для `_id` типа `Date`). С `capped` и `timeseries` кластерная коллекция не сочетается, коллекция временных рядов и так кластерная.

## Сортировка строк по умолчанию [#default-collation]

[`collation`](../reference/schemas/schema.mdx#collation) задаёт правила сравнения строк для всей коллекции — язык, чувствительность к регистру и к акцентам. С `strength: 2` поиск не различает регистр.

<Snippet id="schemas/special-collections/default-collation" title="accounts/named.ts" twoslash />

Текстовый индекс и индекс `2d` сортировку не поддерживают. На такой коллекции их объявляют с `collation: { locale: "simple" }`, иначе будет `ConfigurationError`.

## Валидатор на сервере [#server-validator]

Typemo проверяет данные до записи, но в базу могут писать и другие программы. [`validator`](../reference/schemas/schema.mdx#validator) строит из схемы правила `$jsonSchema` и заводит их на сервере. Коллекция будет отвергать документы с неверными типами, без обязательных полей, вне `enum` и границ. Значение `true` даёт уровень `strict` и действие `error`, а объект уточняет [`validationLevel`](../reference/schemas/schema.mdx#validation-level) и [`validationAction`](../reference/schemas/schema.mdx#validation-action).

<Snippet id="schemas/special-collections/server-validator" title="accounts/checked.ts" twoslash />

Здесь документ с числом в строковом поле записан в обход Typemo, через драйвер, и сервер его отклонил. Ваши функции `validate` и правила ключей Map на сервере не выразить, их проверяет только Typemo. Правила строит генератор [`JsonSchemaGenerator`](./json-and-standard-schema.mdx).

## Остальные опции [#other-options]

Есть ещё три опции коллекции.

- [`changeStreamPreAndPostImages`](../reference/schemas/schema.mdx#change-stream-pre-and-post-images) включает запись состояния документа до и после изменения. Она нужна потокам изменений, которые просят `fullDocumentBeforeChange`.
- [`shardKey`](../reference/schemas/schema.mdx#shard-key) сообщает ключ шардирования, чтобы `$save` находил документ по исходным значениям ключа.
- [`autoCreate: false`](../reference/schemas/schema.mdx#auto-create) исключает коллекцию из `init()` и `syncAll()`, если коллекцией управляете вы сами.

Опции [`readConcern`](../reference/schemas/schema.mdx#read-concern) и [`writeConcern`](../reference/schemas/schema.mdx#write-concern) задают умолчания для операций модели. Они уходят на сервер с каждым чтением и записью, но уровень, заданный у самой операции, главнее. Внутри транзакции уровни схемы не отправляются, там действуют настройки транзакции.

## Как выбрать [#how-to-choose]

Спросите себя — **что должна гарантировать коллекция?**

- **Хранить только последние записи** — `capped`.
- **Хранить измерения во времени** — `timeseries`.
- **Защищаться от чужих программ, которые тоже в неё пишут** — `validator`.
- **Искать без учёта регистра** — `collation`.

Для всего остального подойдёт обычная коллекция.

## Когда это не нужно [#when-not-to-use]

Не делайте коллекцию ограниченной, если старые документы нужно хранить. Сервер вытеснит их без предупреждения. Не берите временные ряды для обычных сущностей с изменяемыми полями. И не включайте валидатор, если схема часто меняется. Сервер начнёт отвергать документы, пока вы не обновите коллекцию (как это сделать, описано в руководстве [Создание коллекций](../collections/create.mdx)).

## Если что-то пошло не так [#troubleshooting]

**Опции не применились к существующей коллекции.** Вы добавили `capped` или `validator` к коллекции, которая уже есть в базе. `init()` сравнивает параметры и молча их не меняет, а бросает [`SyncError`](../reference/errors/configuration-errors.mdx#sync-error).

Есть свойства, которые MongoDB у существующей коллекции поменять не умеет. Сделать обычную коллекцию ограниченной, превратить её во временной ряд или кластерную, сменить коллацию. Для них ошибка такая — `collection "legacy_logs": exists with options MongoDB cannot change (capped): drop the collection and create it again`. Для изменяемых, например валидатора, — `collection "legacy_checked": exists with other options (validator); run ensureCollection({ update: true }) to change them with collMod`. Создайте новую коллекцию с нужными параметрами или измените существующую по руководству [Создание коллекций](../collections/create.mdx#change-collection-options).

**Временные ряды не принимают опцию.** Уникальный индекс, `capped` и `clustered` вместе с `timeseries` отвергаются, сервер их не поддерживает. Typemo скажет об этом при описании модели, ещё до обращения к базе.
