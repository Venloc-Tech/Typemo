Схема описана классом, но иногда она нужна как данные. Сгенерировать документацию по полям, собрать снимок для теста, написать запрос к драйверу с настоящими именами полей, узнать, какие поля скрыты. Для этого у каждой модели есть свойство `schema` — описание схемы [`SchemaInfo`](../reference/schemas/schema-info.mdx), **только для чтения**. Изменить схему нельзя. После сборки модели она заморожена, и все, кто её читает, видят одно и то же.

## Что понадобится

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель пользователя из файла `users/user.ts`. Почта хранится в базе под именем `e`, есть скрытое поле, вложенный адрес и массив тегов.

## Быстрый путь

Имена класса и коллекции лежат прямо в `schema`, а полное описание возвращает [`describe()`](../reference/schemas/schema-info.mdx#describe).

```ts twoslash title="users/user.ts"
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { dbName: "c" }) city?: string;
}
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
  @Prop(() => Address) address?: Address;
  @Prop(() => [String]) tags?: string[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
console.log(Users.schema.name, Users.schema.collection);
// → User users

console.log(Users.schema.toDbPath("address.city"));
// → address.c
```

Ниже посмотрим, для чего это применяют.

## Прочитать пути и их свойства

`describe()` возвращает обычный объект. Его можно печатать, сравнивать со снимком и обходить. В `paths` каждый путь записан так, как в коде (`address.city`, `tags.$` для элемента массива). У него есть вид узла, тип, имя в базе (если оно другое) и флаги.

```ts twoslash title="users/inspect.ts"
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { dbName: "c" }) city?: string;
}
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
  @Prop(() => Address) address?: Address;
  @Prop(() => [String]) tags?: string[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
const description = Users.schema.describe();
console.log(description.paths.email);
// → { kind: "scalar", type: "string", dbPath: "e", flags: "required" }
console.log(Object.keys(description.paths));
// → ["_id", "email", "passwordHash", "address", "address.city", "tags", "tags.$"]
```

Флаги идут строкой через запятую — `required`, `nullable`, `default`, `immutable`, `hidden` и служебные вроде `service:id`. По ним легко собрать список, например, каких скрытых полей не должно быть в документации API.

```ts twoslash title="users/inspect.ts"
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { dbName: "c" }) city?: string;
}
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
  @Prop(() => Address) address?: Address;
  @Prop(() => [String]) tags?: string[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
const hidden = Object.entries(Users.schema.describe().paths)
  .filter(([, path]) => path.flags?.includes("hidden"))
  .map(([name]) => name);
console.log(hidden);
// → ["passwordHash"]
```

Кроме путей, в описании есть `indexes` (ключи и опции), `searchIndexes` (индексы Atlas Search из `@SearchIndex`), `virtuals`, `hooks`, `discriminator` и `discriminators` для иерархий и `ext`.

## Перевести путь в имя из базы

В запросе к драйверу полям нужны имена из базы, а не из кода. У нас `email` хранится как `e`, а `address.city` как `address.c`. [`toDbPath`](../reference/schemas/schema-info.mdx#todbpath) переводит путь на всех уровнях и сохраняет позиции в массиве. Для пути, которого нет в схеме, он вернёт `undefined`, а не бросит ошибку. Так что опечатку ловите проверкой результата.

```ts twoslash title="users/raw-query.ts"
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { dbName: "c" }) city?: string;
}
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
  @Prop(() => Address) address?: Address;
  @Prop(() => [String]) tags?: string[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
export const countByEmail = async (email: string) => {
  const path = Users.schema.toDbPath("email");
  if (path === undefined) throw new Error("no such path");
  return client.unsafeDriver().db("app").collection("users").countDocuments({ [path]: email });
};

console.log(Users.schema.toDbPath("tags.0"), Users.schema.toDbPath("address.nope"));
// → tags.0 undefined
```

## Прочитать опции расширений

Расширения хранят свои настройки прямо в схеме, в `@Schema({ ext })` и `@Prop({ ext })`. [`schema.ext`](../reference/schemas/schema-info.mdx#ext) отдаёт настройки схемы, а [`schema.extOf(путь)`](../reference/schemas/schema-info.mdx#extof) — настройки поля. Для поля без `ext` это пустой объект, для несуществующего пути — `undefined`. Так интеграции узнают, что для поля включён их режим. Как расширения объявляют опции, рассказывает руководство [Свои опции полей и схем](../extensions/custom-options.mdx).

```ts twoslash title="users/inspect.ts"
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { dbName: "c" }) city?: string;
}
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
  @Prop(() => Address) address?: Address;
  @Prop(() => [String]) tags?: string[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
console.log(Users.schema.extOf("email"), Users.schema.extOf("nope"));
// → {} undefined
```

## Как выбрать

Спросите себя — **нужна схема как данные или как типы?**

- **Как типы** — их даёт сам компилятор, `Lean<User>` и `Plain<User>`.
- **Как данные во время работы** — имя в базе, флаг, индекс. Читайте `schema`.
- **Чтобы проверить значения по схеме** — берите [`StandardSchema`](./json-and-standard-schema.mdx), а не разбор `describe()`.

## Когда это не нужно

`schema` только читает. Менять поля, индексы или опции во время работы нельзя. Не разбирайте `describe()` ради проверки данных, для этого есть готовые средства. Формат описания рассчитан на снимки и диагностику, а не на надёжный разбор в бизнес-логике.

## Если что-то пошло не так

**`toDbPath` вернул `undefined`.** Такого пути в схеме нет, скорее всего, опечатка. Сверьте имя с `Object.keys(Users.schema.describe().paths)`.

**Поисковых индексов нет в `indexes`.** `describe().indexes` перечисляет только обычные индексы. Индексы [`@SearchIndex`](../reference/schemas/index-decorators.mdx#searchindex) лежат в отдельном поле `searchIndexes`, там их объявления из схемы, имя и определение. Их состояние на сервере смотрите методами модели из руководства [Поисковые индексы](../collections/search-indexes.mdx).

## Полный пример

```ts twoslash title="users/schema-report.ts"
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";

@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);

// отчёт по схеме: поле, имя в базе, скрыто ли
export const schemaReport = () =>
  Object.entries(Users.schema.describe().paths).map(([name, path]) => ({
    name,
    dbName: path.dbPath ?? name,
    hidden: path.flags?.includes("hidden") ?? false,
  }));
```
