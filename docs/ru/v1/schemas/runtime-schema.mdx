Схема описана классом, но иногда она нужна как данные: сгенерировать документацию по полям, собрать снимок для теста, написать запрос к драйверу с настоящими именами полей, проверить, какие поля скрыты. Для этого у каждой модели есть свойство `schema` — описание схемы **только для чтения**, [`SchemaInfo`](../reference/schemas/schema-info.mdx). Изменить схему нельзя: она заморожена после сборки модели, и это гарантирует, что все, кто её читает, видят одно и то же.

## Что предполагается

Примеры используют клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель пользователя из файла `users/user.ts`: почта хранится в базе под именем `e`, есть скрытое поле, вложенный адрес и массив тегов.

## Быстрый путь

Имя класса и коллекции лежат прямо в `schema`, полное описание — в [`describe()`](../reference/schemas/schema-info.mdx#describe):

```ts twoslash title="users/user.ts"
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { dbName: "c" }) city?: string;
}
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
  @Prop(() => Address) address?: Address;
  @Prop(() => [String]) tags?: string[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
console.log(Users.schema.name, Users.schema.collection);
// → User users

console.log(Users.schema.toDbPath("address.city"));
// → address.c
```

Остальная страница показывает, для чего это применяют.

## Прочитать пути и их свойства

`describe()` возвращает обычный объект, который можно печатать, сравнивать со снимком и обходить. В `paths` каждый путь идёт по коду (`address.city`, `tags.$` для элемента массива) и несёт вид узла, тип, имя в базе (если оно отличается) и флаги:

```ts twoslash title="users/inspect.ts"
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { dbName: "c" }) city?: string;
}
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
  @Prop(() => Address) address?: Address;
  @Prop(() => [String]) tags?: string[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
const description = Users.schema.describe();
console.log(description.paths.email);
// → { kind: "scalar", type: "string", dbPath: "e", flags: "required" }
console.log(Object.keys(description.paths));
// → ["_id", "email", "passwordHash", "address", "address.city", "tags", "tags.$"]
```

Флаги — строка через запятую: `required`, `nullable`, `default`, `immutable`, `hidden` и служебные вида `service:id`. По ним легко собрать список: например, какие поля скрыты и потому не должны попасть в документацию API.

```ts twoslash title="users/inspect.ts"
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { dbName: "c" }) city?: string;
}
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
  @Prop(() => Address) address?: Address;
  @Prop(() => [String]) tags?: string[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
const hidden = Object.entries(Users.schema.describe().paths)
  .filter(([, path]) => path.flags?.includes("hidden"))
  .map(([name]) => name);
console.log(hidden);
// → ["passwordHash"]
```

Кроме путей, описание содержит `indexes` (ключи и опции), `searchIndexes` (индексы Atlas Search, объявленные `@SearchIndex`), `virtuals`, `hooks`, `discriminator` и `discriminators` для иерархий и `ext`.

## Перевести путь в имя из базы

Когда вы пишете запрос к драйверу, полям нужны имена из базы, а не из кода: у нас `email` хранится как `e`, а `address.city` как `address.c`. [`toDbPath`](../reference/schemas/schema-info.mdx#todbpath) делает перевод на всех уровнях и сохраняет позиции массива. Для пути, которого в схеме нет, он возвращает `undefined`, а не бросает ошибку, поэтому опечатку нужно ловить проверкой результата.

```ts twoslash title="users/raw-query.ts"
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { dbName: "c" }) city?: string;
}
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
  @Prop(() => Address) address?: Address;
  @Prop(() => [String]) tags?: string[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
export const countByEmail = async (email: string) => {
  const path = Users.schema.toDbPath("email");
  if (path === undefined) throw new Error("no such path");
  return client.unsafeDriver().db("app").collection("users").countDocuments({ [path]: email });
};

console.log(Users.schema.toDbPath("tags.0"), Users.schema.toDbPath("address.nope"));
// → tags.0 undefined
```

## Прочитать опции расширений

Расширения хранят собственные настройки прямо в схеме: в `@Schema({ ext })` и `@Prop({ ext })`. [`schema.ext`](../reference/schemas/schema-info.mdx#ext) отдаёт настройки схемы, а [`schema.extOf(путь)`](../reference/schemas/schema-info.mdx#extof) — настройки поля: пустой объект для поля без `ext` и `undefined` для несуществующего пути. Так интеграции узнают, что для поля включён их режим. Как расширения объявляют опции, описано в руководстве [Свои опции полей и схем](../extensions/custom-options.mdx).

```ts twoslash title="users/inspect.ts"
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { dbName: "c" }) city?: string;
}
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
  @Prop(() => Address) address?: Address;
  @Prop(() => [String]) tags?: string[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
console.log(Users.schema.extOf("email"), Users.schema.extOf("nope"));
// → {} undefined
```

## Как выбрать

Задайте себе один вопрос: **нужна мне схема как данные или как типы?** Типы даёт сам компилятор: `Lean<User>`, `Plain<User>`. Если нужно во время работы узнать имя в базе, флаг или индекс, читайте `schema`. Для проверки значений по схеме используйте [`StandardSchema`](./json-and-standard-schema.mdx), а не разбор `describe()`.

## Когда это не нужно

`schema` только читает: изменить поля, индексы или опции во время работы нельзя. Не разбирайте `describe()` ради валидации данных: для этого есть готовые средства. Формат описания предназначен для снимков и диагностики, а не для стабильного разбора в бизнес-логике.

## Частые ошибки

### `toDbPath` вернул `undefined`

Пути нет в схеме, скорее всего опечатка. Проверьте имя по `Object.keys(Users.schema.describe().paths)`.

### Поисковые индексы не в `indexes`

`describe().indexes` перечисляет обычные индексы. Индексы [`@SearchIndex`](../reference/schemas/index-decorators.mdx#searchindex) лежат в отдельном поле `searchIndexes`: там их объявления из схемы (имя и определение). Их состояние на сервере смотрите методами модели, описанными в руководстве [Поисковые индексы](../collections/search-indexes.mdx).

## Полный пример

```ts twoslash title="users/schema-report.ts"
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";

@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true }) email!: string;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);

// отчёт по схеме: поле, имя в базе, скрыто ли
export const schemaReport = () =>
  Object.entries(Users.schema.describe().paths).map(([name, path]) => ({
    name,
    dbName: path.dbPath ?? name,
    hidden: path.flags?.includes("hidden") ?? false,
  }));
```
