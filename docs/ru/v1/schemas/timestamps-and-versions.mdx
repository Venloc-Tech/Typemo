Почти любой сущности надо знать, когда её создали, когда последний раз меняли и не поменял ли её кто-то другой, пока вы её редактировали. Тайком Typemo эти поля не добавляет. Вы получаете их, наследуя базовый класс. [`Timestamped`](../reference/schemas/base-classes.mdx#timestamped) добавляет `createdAt` и `updatedAt`, а [`Versioned`](../reference/schemas/base-classes.mdx#versioned) — числовую версию `__v`. Поля видны компилятору, подсказкам редактора и типам результатов, а значения ставит само ядро.

В Mongoose то же самое делают опции `timestamps` и `versionKey`. Разница в том, что здесь это обычные поля класса. Они всегда есть в типе результата, и передавать их при создании не нужно.

## Что понадобится [#prerequisites]

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель поста из файла `posts/post.ts`.

## Быстрый путь [#quick-start]

Оберните базовый класс — `Timestamped(Entity)`. Даты появятся при создании, а `updatedAt` сдвинется при первом же изменении.

```ts twoslash title="posts/post.ts"
import { Entity, Prop, Schema, Timestamped, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Timestamped(Entity) {
  @Prop(() => String, { required: true }) title!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Posts = client.db().model(Post);
// ---cut---
const post = await Posts.create({ title: "Hello" });
console.log(post.createdAt.getTime() === post.updatedAt.getTime());
// → true

post.title = "Hello, world";
await post.$save();
console.log(post.updatedAt.getTime() > post.createdAt.getTime());
// → true
```

Ниже разберём, когда именно меняются метки, и добавим версию.

## Как меняются метки [#how-timestamps-change]

`createdAt` пишется один раз, при создании, и больше не меняется. У поля тип `Immutable`, и обновление, которое пытается его изменить, будет отвергнуто.

`updatedAt` обновляет каждая запись, которая дошла до документа. Это [`$save`](../reference/documents/document-api.mdx#save) с изменениями, [`updateOne`](../reference/writes/writes.mdx#update-one), `updateMany`, `findOneAndUpdate`, замена и upsert. Ставить его самому не нужно. `updatedAt` сдвигается даже от записи, которая по значению ничего не меняет. Например, от `$set` того же заголовка или `$addToSet` значения, которое уже есть в массиве (сервер при этом сообщает `modifiedCount: 1`). Ядро до записи не знает, изменит ли сервер что-нибудь.

```ts twoslash title="posts/posts.service.ts"
import { Entity, Prop, Schema, Timestamped, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts" })
class Post extends Timestamped(Entity) {
  @Prop(() => String, { required: true }) title!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Posts = client.db().model(Post);
// ---cut---
const post = await Posts.create({ title: "a" });
await Posts.updateOne({ _id: post._id }, { $set: { title: "b" } });
const reread = await Posts.findById(post._id).orFail();
console.log(reread.createdAt.getTime() === post.createdAt.getTime(), reread.updatedAt.getTime() >= post.updatedAt.getTime());
// → true true
```

Попытку изменить `createdAt` обновлением остановит [`StrictModeError`](../reference/errors/data-errors.mdx#strict-mode-error) с причиной `immutable` — `$set.createdAt: "createdAt" is immutable; it is written only when the document is created ($setOnInsert on upsert) [immutable]`. В типах такое обновление не скомпилируется. При upsert, когда документ создаёт обновление, обе метки получают одно значение.

Задать метки осознанно можно, типы это разрешают. При создании обе необязательны (`create({ title, createdAt, updatedAt })`), а в обновлении можно записать `updatedAt`. Заданную дату ядро оставит как есть, и присвоенный в документе `updatedAt` `$save` не затрёт. Так переносят старые данные вместе с историей. В обычном коде метки не передавайте, `createdAt` после создания всё равно не изменить.

## Добавить версию [#add-version]

`Versioned(Entity)` добавляет `__v`. Это счётчик, который ядро увеличивает, когда изменение зависит от позиции элементов массива. Иначе два процесса, меняющие один массив по индексу, затёрли бы друг друга. Миксины сочетаются в любом порядке — `Timestamped(Versioned(Entity))`.

```ts twoslash title="posts/post.ts"
import { Entity, Prop, Schema, Timestamped, TypemoClient, Versioned } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "posts" })
class Post extends Timestamped(Versioned(Entity)) { // [!code highlight]
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => [String]) tags!: string[];
}

const Posts = client.db().model(Post);
const post = await Posts.create({ title: "a", tags: [] });
console.log(post.__v);
// → 0

post.tags.push("news");
await post.$save();
console.log(post.__v);
// → 1
```

Изменение обычного поля версию не увеличивает. А замена документа целиком через `replaceOne` сохраняет `createdAt` и текущее значение `__v`.

Метки годятся в ключи постраничного чтения. [`keysetPage`](../reference/query/keyset.mdx#model.keyset-page) сортирует по `createdAt` и `updatedAt` (`sort: [["createdAt", "desc"]]`), потому что эти поля всегда заполнены и не бывают `null`.

## Защититься от одновременных правок [#concurrent-edits]

Чтобы сохранение не затирало чужое изменение, добавьте в схему `optimisticConcurrency: true`. Тогда [`$save`](../reference/documents/document-api.mdx#save) сработает, только если документ в базе не менялся с момента чтения, а иначе бросит [`VersionError`](../reference/errors/query-errors.mdx#version-error). Опции нужен `Versioned`, без него модель не соберётся. Подробно об этом — в руководстве [Версии документа и конфликты](../documents/versions.mdx), а сама опция описана в [`@Schema`](../reference/schemas/schema.mdx#optimistic-concurrency).

## Как выбрать [#how-to-choose]

Спросите себя — **что нужно знать о документе?**

- **Когда он создан и когда менялся** — `Timestamped`.
- **Нужна защита от одновременного редактирования и от гонок по массивам** — `Versioned` с `optimisticConcurrency`.
- **И то и другое** — подмешивайте оба.

Свои поля вроде `publishedAt` так и остаются обычными полями. `Timestamped` отвечает только за создание и изменение записи.

## Когда это не нужно [#when-not-to-use]

Справочникам, которые меняются раз в год, метки времени ни к чему, а каждое лишнее поле — лишний вес. Журналам и событиям, которые только пишутся, `updatedAt` не нужен. Хватит `createdAt`, объявленного обычным полем с `default`. И версия нужна не каждой модели. Если сущность меняет один процесс, конфликтов не будет.

## Если что-то пошло не так [#troubleshooting]

**Обновление `createdAt` не сохраняется.** Поле создаётся один раз. Чтобы записать его вручную, документ придётся создать заново.

**`optimisticConcurrency` в модели без `Versioned`.** Модель не соберётся.

```text
ConfigurationError: optimisticConcurrency needs the version field — extend Versioned(...)
```

Добавьте `Versioned` в цепочку наследования — `class Account extends Versioned(Entity)`.

**Меток нет в ответе.** `createdAt` и `updatedAt` есть в результатах `.plain()` и `.lean()`. Но если выбрать поля через `select({ title: 1 })`, в результате будут только выбранные. Добавьте нужные метки в выбор.

## Полный пример [#full-example]

```ts twoslash title="posts/posts.service.ts"
import { Entity, Prop, Schema, Timestamped, TypemoClient, Versioned } from "@venloc/typemo";

@Schema({ collection: "posts", optimisticConcurrency: true })
class Post extends Timestamped(Versioned(Entity)) {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => [String]) tags!: string[];
}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Posts = client.db().model(Post);

// создание: метки и версия проставляются сами
export const publish = async (title: string) => Posts.create({ title, tags: [] });

// изменение: updatedAt растёт, а при чужой правке $save бросит VersionError
export const rename = async (id: Post["_id"], title: string) => {
  const post = await Posts.findById(id).orFail();
  post.title = title;
  await post.$save();
  return post.updatedAt;
};
```

<Callout type="migration">

В Mongoose метки включаются опцией схемы `timestamps: true`, а версия `__v` есть всегда. В Typemo это наследование. `Timestamped` и `Versioned` подключаются отдельно, поля видны в типах, а проверку версии при сохранении включает опция `optimisticConcurrency`.

</Callout>
