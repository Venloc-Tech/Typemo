Здесь собраны термины из руководств и справочника, у каждого — определение в одну-две фразы. Полное объяснение живёт на странице, куда ведёт ссылка. Глоссарий нужен, чтобы быстро вспомнить слово, а не чтобы учить по нему продукт.

У каждого термина есть стабильный **ключ** — короткое имя латиницей. По нему компонент `Term` показывает определение при наведении. Например, `<Term id="plain">результат plain()</Term>` возьмёт определение термина с ключом `plain`. Ключ указан после определения и не меняется, даже если меняется русское название.

Термины сгруппированы по темам. Если ищете слово по алфавиту, воспользуйтесь поиском по сайту — заголовок каждой записи и есть само слово.

## Данные и виды результата

### Документ

Запись коллекции MongoDB. Если в документации сказано просто «документ», это объект модели, который помнит свои изменения и умеет сохраняться методом `$save`. В Mongoose и англоязычных источниках его называют hydrated document. Ключ: `document`. Подробнее: [Жизненный цикл документа](../documents/lifecycle.mdx).

### Гидратация

Превращение сырой записи из базы в документ модели. Значения приводятся к типам схемы, а массивы, поддокументы и `Map` становятся строго типизированными коллекциями. Ключ: `hydration`. Подробнее: [Жизненный цикл документа](../documents/lifecycle.mdx).

### Результат `.lean()`

Результат чтения, который не превращён в документ. Это обычные объекты, где значения BSON остаются своими типами — `ObjectId`, `bigint`, `Date`. По сути это данные в том виде, в каком их отдал драйвер. Ключ: `lean`. Подробнее: [Чтение данных](../queries/reading-data.mdx).

### Результат `.plain()`

Обычные объекты, готовые для клиента. `ObjectId` и int64 в них заменены строками, а скрытые поля убраны. Ключ: `plain`. Подробнее: [Чтение данных](../queries/reading-data.mdx).

### Проекция

Список полей, которые возвращает запрос, — нужные включаются или лишние исключаются. В Typemo проекцию задаёт метод `select`, и она меняет тип результата. Ключ: `projection`. Подробнее: [Выбор полей и тип результата](../queries/projections.mdx).

### Selected

Тип, который описывает форму ответа после проекции. Он нужен, когда эту форму надо назвать, например чтобы вернуть её из функции. Ключ: `selected`. Подробнее: [Контракты](../reference/query/contracts.mdx#selected).

### Контракт

Зафиксированная форма ответа. При сборке её проверяет компилятор (`.expect`), а во время работы данные из базы можно сверить со схемой (`.parse`). Ключ: `contract`. Подробнее: [Проверка формы ответа](../queries/contracts.mdx).

### Маска

Правило, которое прячет часть значения в ответе клиенту. Например, от почты остаются первая буква и домен. Маски работают только с результатом `.lean()` и `.plain()`. Ключ: `mask`. Подробнее: [Маски ответа](../queries/response-masks.mdx).

### Скрытое поле

Поле с опцией `hidden`. Оно не попадает в ответы и сериализацию, пока вы не попросите его явно. В типах такое поле помечено маркером `Hidden<T>`. Ключ: `hidden`. Подробнее: [Скрытые и чувствительные поля](../schemas/hidden-and-sensitive.mdx).

### Чувствительное поле

Поле с опцией `sensitive`. Его значение маскируется или скрывается везде, где оно могло бы утечь, — в ответах, событиях, аудите и ошибках. Ключ: `sensitive`. Подробнее: [Скрытые и чувствительные поля](../schemas/hidden-and-sensitive.mdx).

### Неизвестные поля

Поля, которые есть у документа в базе, но не описаны в схеме. Typemo не теряет их молча, а сообщает о них ошибкой `UnknownFieldsError`, когда вы работаете с таким документом. Ключ: `unknown-fields`. Подробнее: [Неизвестные поля](../documents/unknown-fields.mdx).

### Типизированные коллекции

Собственные строго типизированные массивы, `Map` и массивы поддокументов, которые есть у документа. Писать в них можно только методами, потому что каждый метод соответствует оператору MongoDB. Ключ: `typed-collections`. Подробнее: [Массивы и Map в документе](../documents/typed-collections.mdx).

### StrictArray

Тип массива в документе. По индексу его можно только читать, а менять — собственными методами вроде `push`, `pull` и `splice`. Каждый такой вызов попадает в журнал изменений и превращается в оператор MongoDB. Запись по индексу (`tags[0] = "x"`) не компилируется, а если обойти это приведением типа, `$save()` бросит `DirectWriteError` с подсказкой, какими методами менять массив. В результатах `.lean()`, `.plain()` и в `$toObject()` те же поля — обычные массивы. Ключ: `strict-array`. Подробнее: [Массивы и Map в документе](../documents/typed-collections.mdx).

### Документ в любом состоянии заполнения

Документ, у которого в поле-ссылке может лежать и идентификатор, и уже заполненный документ. Его тип — `AnyPopulationDoc<T>`. Он нужен функции, которая принимает документ и до `populate`, и после, а сужает его проверка `isPopulated`. Ключ: `any-population-doc`. Подробнее: [Проверки типов при заполнении](../populate/type-checks.mdx).

### Поддокумент

Вложенный объект внутри документа, описанный отдельным классом схемы. У поддокумента есть родитель и путь внутри него. Ключ: `subdocument`. Подробнее: [Поддокументы](../documents/subdocuments.mdx).

### BSON

Двоичный формат, в котором MongoDB хранит данные. Типов в нём больше, чем в JSON, — `ObjectId`, int64, `Decimal128`, `Binary`, `Timestamp`. Поэтому часть значений нельзя отдать клиенту без преобразования. Ключ: `bson`. Подробнее: [Типы данных MongoDB](../concepts/bson-types.mdx).

### ObjectId

Двенадцатибайтовый идентификатор, который MongoDB по умолчанию ставит в поле `_id`. Везде, где Typemo ждёт `ObjectId`, можно передать и его строковую запись. Ключ: `object-id`. Подробнее: [Типы данных MongoDB](../concepts/bson-types.mdx).

### int64

Шестидесятичетырёхбитное целое. В TypeScript ему соответствует `bigint`, потому что обычное число точно хранит целые только до 2⁵³. Ключ: `int64`. Подробнее: [Типы полей](../schemas/field-types.mdx).

### Decimal128

Точное десятичное число MongoDB, подходящее для денег. В отличие от `number`, оно не округляет дроби. Ключ: `decimal128`. Подробнее: [Типы полей](../schemas/field-types.mdx).

## Схемы и модели

### Схема

Описание данных модели — поля, ограничения, индексы и опции коллекции. В Typemo схема — это класс с декоратором `@Schema`. Ключ: `schema`. Подробнее: [Описать модель](../schemas/define-model.mdx).

### Модель

Объект, через который вы читаете и пишете одну коллекцию с помощью `find`, `create`, `updateOne` и остальных методов. Модель берут у подключения, например `connection.model(Account)`. Ключ: `model`. Подробнее: [Описать модель](../schemas/define-model.mdx).

### Поле

Свойство класса схемы с декоратором `@Prop`. Тип поля выводится из класса, а опции вроде `required`, `unique` и `hidden` задают ограничения. Ключ: `field`. Подробнее: [Описать модель](../schemas/define-model.mdx).

### Базовый класс

Класс, от которого наследуется модель, чтобы получить служебные поля. `Entity` даёт `_id`, `Timestamped` добавляет `createdAt` и `updatedAt`, `Versioned` — версию `__v`, а `EntityWithId` — `_id` собственного типа вместо `ObjectId`, например строку, число или UUID. Скрытно Typemo эти поля не добавляет. Ключ: `base-class`. Подробнее: [Базовые классы](../reference/schemas/base-classes.mdx).

### Маркерные типы

Типы-обёртки вроде `Hidden<T>`, `Immutable<T>` и `Ref<M>`, которыми поле сообщает системе типов о своём свойстве. Значение во время работы они не меняют, они меняют то, что разрешит компилятор. Ключ: `marker-types`. Подробнее: [Маркерные типы полей](../reference/schemas/field-markers.mdx).

### Обязательность, `null` и отсутствие

Три разных состояния поля — у него есть значение, значение равно `null` или значения нет. Typemo их различает и не считает `undefined` значением. Ключ: `nullable`. Подробнее: [Обязательность, null и отсутствие](../schemas/required-and-null.mdx).

### Вложенный объект

Объект внутри документа, описанный классом с `@Schema({ nested })`. Собственного `_id` и коллекции у него нет. Ключ: `nested-object`. Подробнее: [Вложенные объекты и поддокументы](../schemas/nested-and-subdocuments.mdx).

### Неизменяемое поле

Поле с опцией `immutable`, которое нельзя менять после создания документа. Ключ: `immutable`. Подробнее: [Неизменяемые поля](../schemas/immutable.mdx).

### Виртуальное поле

Поле, которого нет в базе. Оно либо вычисляется при чтении (геттер), либо подгружает связанные документы (`@Virtual`). Ключ: `virtual`. Подробнее: [Виртуальные поля](../schemas/virtuals.mdx).

### Ссылка

Поле, которое хранит идентификатор документа другой модели. По ссылке можно заполнить связь через populate. Ключ: `reference`. Подробнее: [Ссылки на другие модели](../schemas/references.mdx).

### Дискриминатор

Способ хранить несколько моделей-наследников в одной коллекции. Отдельное поле (`discriminatorKey`) говорит, к какой модели относится документ. Ключ: `discriminator`. Подробнее: [Наследование и дискриминаторы](../schemas/discriminators.mdx).

### Валидация

Проверка значений по правилам схемы — `min`, `max`, `enum` или своему `validate`. Она срабатывает при создании, сохранении и обновлении, а её ошибки собираются в `ValidationError` с путями полей. Ключ: `validation`. Подробнее: [Валидация полей](../schemas/validation.mdx).

### Оптимистичная конкурентность

Защита от потери параллельных правок. Документ хранит версию `__v`, и сохранение с устаревшей версией отклоняется ошибкой `VersionError`. Ключ: `optimistic-concurrency`. Подробнее: [Версии и параллельные изменения](../documents/versions.mdx).

## Подключение

### Peer-зависимость

Пакет, который Typemo не приносит с собой, а ждёт от вас через `peerDependencies`. Это `mongodb` и `bson`. Так значения BSON в вашем коде и в библиотеке — одни и те же классы. Ключ: `peer-dependency`. Подробнее: [Установка и настройка](../getting-started/installation.mdx).

### Клиент

Объект `TypemoClient`, которому принадлежат подключение к MongoDB и пул соединений. Его создают один раз на процесс. Ключ: `client`. Подробнее: [Подключиться к базе](../connection/connect.mdx).

### Подключение

Объект `Connection`, связь клиента с одной базой. У него берут модели (`model`) и на нём запускают синхронизацию индексов (`init`, `syncAll`). Ключ: `connection`. Подробнее: [Подключиться к базе](../connection/connect.mdx).

### Драйвер

Официальный пакет `mongodb`, через который Typemo говорит с сервером. Обратиться к нему в обход Typemo можно через `client.unsafeDriver()`, но политики, маски и хуки тогда не действуют. Ключ: `driver`. Подробнее: [Доступ к драйверу](../connection/driver-access.mdx).

### Реплика-сет

Несколько серверов MongoDB с копией одних и тех же данных. Бывает и реплика-сет из одного узла. Он нужен для транзакций, подписки на изменения и моделей с аудитом. Ключ: `replica-set`. Подробнее: [Подключиться к базе](../connection/connect.mdx).

### Коллекция

Набор документов в базе MongoDB, примерно то же, что таблица в реляционной базе. Ключ: `collection`. Подробнее: [Подключиться к базе](../connection/connect.mdx).

## Чтение и запись

### Строитель запроса

Объект, который возвращают `find`, `findOne` и другие методы. Он собирает запрос цепочкой (`select`, `sort`, `limit`) и идёт в базу только на `await`. Ключ: `query-builder`. Подробнее: [Чтение](../reference/query/reading.mdx).

### Фильтр

Условие поиска. Это объект, где ключи — поля модели, а значения — значение поля или оператор вроде `$in` и `$gt`. Typemo проверяет фильтр и компилятором, и во время работы. Ключ: `filter`. Подробнее: [Фильтры](../queries/filters.mdx).

### Курсор

Объект, который отдаёт документы по одному, по мере чтения из базы. Он нужен, когда выборка не помещается в память. Ключ: `cursor`. Подробнее: [Большие выборки](../queries/large-results.mdx).

### Пагинация по ключу

Способ листать длинные списки без `skip`. Следующую страницу ищут по значениям полей сортировки у последней записи, а сами значения кодируются в подписанный токен. Ключ: `keyset-pagination`. Подробнее: [Пагинация по ключу](../queries/keyset-pagination.mdx).

### План запроса

Описание того, как сервер выполнит запрос — какой индекс возьмёт и сколько документов просмотрит. Его показывает `explain`. Ключ: `query-plan`. Подробнее: [Производительность запросов](../queries/performance.mdx).

### Оператор обновления

Ключ вида `$set`, `$inc` или `$push` в объекте обновления. Он говорит серверу, что сделать с полем, и не заменяет документ целиком. Ключ: `update-operator`. Подробнее: [Операторы обновления](../writes/update-operators.mdx).

### Обновление через конвейер

Обновление, в котором вместо операторов передаётся конвейер стадий. Так новое значение поля можно вычислить из других полей документа. Ключ: `pipeline-update`. Подробнее: [Обновление через конвейер](../writes/pipeline-updates.mdx).

### Пустой фильтр

Фильтр `{}`, которому подходят все документы. В чтении он разрешён, а в записи (`updateOne`, `updateMany`, `deleteOne`, `deleteMany`, `replaceOne`, `findOneAnd*`) запрещён. Чтобы затронуть всё намеренно, пишут `Filters.all()`. Ключ: `empty-filter`. Подробнее: [Пустые фильтры в записи](../writes/empty-filters.mdx).

### Операция уровня базы

Агрегация, которая читает не коллекцию модели, а всю базу, базу `admin` или сессии сервера, например `$currentOp`, `$documents` и `$listSessions`. План для неё строят `Pipeline.database()`, `Pipeline.admin()` и `Pipeline.sessions()`, а выполняют `connection.aggregate` и `client.aggregate`. Модели у такой операции нет, поэтому в событиях `model` равен `null`, а хуки не вызываются. Ключ: `database-level-operation`. Подробнее: [Запросы уровня базы](../aggregation/database-level.mdx).

### Пакетная запись

Несколько разных операций записи, которые метод `bulkWrite` отправляет на сервер одним запросом. Ключ: `bulk-write`. Подробнее: [Пакетная запись](../writes/bulk.mdx).

## Связанные данные и агрегации

### Populate

Заполнение связи. Вместо идентификатора в поле-ссылке появляется сам связанный документ, и тип поля меняется вместе с ним. В тексте документации это называется «заполнить связь», а вся тема — «связанные данные». Ключ: `populate`. Подробнее: [Populate: основы](../populate/basics.mdx).

### Конвейер

Последовательность **стадий** агрегации. Каждая стадия принимает документы от предыдущей и отдаёт следующей. Typemo знает тип результата после каждой стадии. Ключ: `pipeline`. Подробнее: [Первая агрегация](../aggregation/first-aggregation.mdx).

### Стадия

Один шаг конвейера. Например, `$match` отбирает документы, `$group` группирует, а `$lookup` подтягивает документы другой коллекции. Ключ: `stage`. Подробнее: [Стадии](../reference/aggregation/stages.mdx).

### Выражение

Формула внутри стадии, которая вычисляет значение из полей документа, — арифметика, строки, даты, массивы. В Typemo выражения строятся типизированными функциями, а сырой `$expr` запрещён. Ключ: `expression`. Подробнее: [Выражения](../aggregation/expressions.mdx).

### Аккумулятор

Оператор, который сворачивает документы группы в одно значение — сумму, среднее, количество или первое значение. Ключ: `accumulator`. Подробнее: [Группировка и отчёты](../aggregation/grouping.mdx).

### Оконная функция

Вычисление по «окну» соседних документов, например скользящее среднее или накопительная сумма. В отличие от группировки, документы она в одну строку не сворачивает. Ключ: `window-function`. Подробнее: [Оконные функции](../aggregation/windows.mdx).

## Транзакции, хуки и расширения

### Транзакция

Группа операций, которые выполняются целиком или не выполняются вовсе. Typemo запускает транзакцию методом `transaction` и сам повторяет её при временных ошибках. Ключ: `transaction`. Подробнее: [Транзакции](../transactions/transactions.mdx).

### Сессия

Контекст, в котором сервер связывает несколько операций, например в транзакцию. Вручную сессия обычно не нужна, её ведёт `transaction`. Ключ: `session`. Подробнее: [Сессии вручную](../transactions/sessions.mdx).

### Хук

Ваша функция, которую Typemo вызывает до (`@Pre`) или после (`@Post`) операции или события документа. Хук видит контекст операции и может изменить фильтр или обновление либо пропустить операцию. Ключ: `hook`. Подробнее: [Хуки операций](../hooks/operation-hooks.mdx).

### Плагин

Набор хуков и статических методов, который подключается к схеме или сразу ко всем моделям, чтобы не повторять одну и ту же логику. Ключ: `plugin`. Подробнее: [Плагины](../hooks/plugins.mdx).

### Расширение

Способ добавить полю или схеме собственные опции через ключ `ext`. Расширение объявляет тип опции и регистрируется у клиента до первой модели. Ключ: `ext`. Подробнее: [Свои опции полей и схем](../extensions/custom-options.mdx).

## Политики и строгость

### Политика

Правило, которое действует на все операции модели и не отключается в отдельном запросе. Например, тенант, мягкое удаление, строгие пути или аудит. Ключ: `policy`. Подробнее: [Что такое политики](../policies/overview.mdx).

### Тенант

Владелец данных в приложении, где одна база обслуживает многих клиентов. Политика `tenant` подставляет тенанта в каждый запрос, и один клиент не увидит чужих документов. Ключ: `tenant`. Подробнее: [Мультитенантность](../policies/tenants.mdx).

### Мягкое удаление

Удаление, при котором документ остаётся в базе с пометкой, но чтения его больше не возвращают. Включается опцией схемы `softDelete`. Ключ: `soft-delete`. Подробнее: [Мягкое удаление](../policies/soft-delete.mdx).

### Контекст политик

Значения политик для текущего запроса — тенант, автор действия и флаги вроде `includeDeleted`. Их задают через `PolicyContext.run` или `.policy()` у запроса. Ключ: `policy-context`. Подробнее: [Контекст политик](../policies/policy-context.mdx).

### Актор

Тот, кто совершает действие, — пользователь или служба. Актор передаётся в контексте политик и записывается в журнал аудита рядом с изменением. Ключ: `actor`. Подробнее: [Контекст политик](../policies/policy-context.mdx).

### Аудит

Запись о каждом изменении данных в отдельную коллекцию — кто, что и когда изменил. Значения чувствительных полей в аудите маскируются. Ключ: `audit`. Подробнее: [Аудит](../policies/audit.mdx).

### Недоверенный ввод

Значения, которые пришли от клиента приложения. Функция `untrusted()` не даёт подсунуть через них оператор MongoDB в фильтр и превратить условие в другое. Ключ: `untrusted-input`. Подробнее: [Недоверенный ввод](../policies/untrusted-input.mdx).

### Нарушение политики

Ошибка `StrictModeError` с кодом причины, например `empty-filter`, `unknown-path` или `tenant`. Политика отвергла операцию ещё до обращения к базе. Ключ: `policy-violation`. Подробнее: [Нарушения политик](../reference/policies/violations.mdx).

### Строгость

Главный принцип Typemo. Всё, что похоже на ошибку, — неизвестное поле, `undefined` в фильтре, пустой фильтр в записи, неверный тип — становится ошибкой, а не тихим поведением. Ослабить строгость нельзя ни опцией, ни режимом. Ключ: `strictness`. Подробнее: [Строгость](../concepts/strictness.mdx).

## Коллекции и индексы

### Индекс

Структура, которая ускоряет поиск и обеспечивает уникальность. Индексы описываются в схеме и создаются явно, при `init` или `syncAll`, а не при первом запросе. Ключ: `index`. Подробнее: [Синхронизация индексов](../collections/index-sync.mdx).

### Синхронизация индексов

Приведение индексов в базе к тем, что описаны в схеме. `syncIndexes` создаёт недостающие и убирает лишние, а `diffIndexes` только показывает разницу. Ключ: `index-sync`. Подробнее: [Синхронизация индексов](../collections/index-sync.mdx).

### Поисковый индекс

Индекс для полнотекстового и векторного поиска, который строит сам сервер (Atlas Search и векторный поиск). Ключ: `search-index`. Подробнее: [Поисковые индексы](../collections/search-indexes.mdx).

### Представление

Коллекция только для чтения, содержимое которой сервер вычисляет конвейером при каждом обращении. В Typemo её описывает `TypedView`. Ключ: `view`. Подробнее: [Представления](../collections/views.mdx).

### Материализованное представление

Результат конвейера, сохранённый в обычной коллекции. При чтении он не пересчитывается, а обновляется вызовом `refresh`. Ключ: `materialized-view`. Подробнее: [Материализованные представления](../collections/materialized-views.mdx).

## Подписка на изменения и наблюдаемость

### Подписка на изменения

Поток событий (`change stream`), в котором сервер сообщает о вставках, обновлениях, заменах и удалениях в коллекции. Его открывает метод `Model.watch`, и для него нужен реплика-сет. Ключ: `change-stream`. Подробнее: [Подписаться на изменения](../change-streams/watch.mdx).

### Маркер продолжения

Токен, который есть у каждого события подписки. С ним можно продолжить чтение с того же места после разрыва. Ключ: `resume-token`. Подробнее: [Подписаться на изменения](../change-streams/watch.mdx).

### События операций

События, которые Typemo рассылает подписчикам, — начало, конец и ошибка операции, команды драйвера, состояние пула. На них строятся интеграции с мониторингом. Ключ: `instrumentation`. Подробнее: [События операций](../observability/events.mdx).

### Подписчик

Ваша функция, зарегистрированная через `client.instrument` или `Typemo.instrument`. Она получает события операций и передаёт их в мониторинг. Ключ: `subscriber`. Подробнее: [События операций](../observability/events.mdx).

### OpenTelemetry

Отдельный пакет `@venloc/typemo-opentelemetry`, который превращает события операций в спаны и метрики. Ядро Typemo от него не зависит. Ключ: `opentelemetry`. Подробнее: [OpenTelemetry](../observability/opentelemetry.mdx).

### Sentry

Отдельный пакет `@venloc/typemo-sentry`, который добавляет в Sentry breadcrumbs операций и контекст ошибок Typemo. Ядро от него не зависит. Ключ: `sentry`. Подробнее: [Sentry](../observability/sentry.mdx).

## Ошибки и типы

### Ошибка Typemo

Любая ошибка библиотеки — потомок класса `TypemoError`. Ловить их удобно по классу, например `ValidationError` или `DuplicateKeyError`, а исходная причина лежит в поле `cause`. Ключ: `typemo-error`. Подробнее: [Обработка ошибок](../errors/handling.mdx).

### Standard Schema

Общий интерфейс схем валидации. Модель Typemo можно передать туда, где ждут схему zod, valibot или другой библиотеки с его поддержкой. Ключ: `standard-schema`. Подробнее: [JSON Schema и Standard Schema](../schemas/json-and-standard-schema.mdx).

### JSON Schema

Формат описания данных, по которому MongoDB проверяет документы на стороне сервера. Typemo генерирует его из схемы модели. Ключ: `json-schema`. Подробнее: [JSON Schema и Standard Schema](../schemas/json-and-standard-schema.mdx).

### Фабрика тестовых данных

Функция, созданная `defineFactory`. Она один раз задаёт значения документа по умолчанию с порядковым номером, а тест указывает только то, что важно ему. Живёт в `@venloc/typemo/testing`. Ключ: `factory`. Подробнее: [Тестировать приложение](../testing/testing-apps.mdx).

## Декораторы

### Legacy-декораторы

Декораторы в режиме `experimentalDecorators`, на них работает ядро `@venloc/typemo`. Ни `emitDecoratorMetadata`, ни `import "reflect-metadata"` им не нужны, ядро хранит метаданные само. Ключ: `legacy-decorators`. Подробнее: [Установка и настройка](../getting-started/installation.mdx).

### TC39-декораторы

Декораторы из стандарта ECMAScript. Для них есть отдельный пакет `@venloc/typemo-decorators`. Смешивать два вида в одном проекте нельзя. Ключ: `tc39-decorators`. Подробнее: [Использовать TC39-декораторы](../decorators-tc39/tc39.mdx).
