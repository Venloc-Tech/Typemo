Глоссарий собирает термины, которые встречаются в руководствах и справочнике, и даёт каждому определение в одну-две фразы. Полное объяснение живёт на странице, куда ведёт ссылка: глоссарий нужен, чтобы быстро вспомнить слово, а не чтобы выучить по нему продукт.

У каждого термина есть стабильный **ключ** — короткое имя латиницей. По этому ключу компонент `Term` в тексте страниц показывает определение при наведении: запись `<Term id="plain">plain-вид</Term>` берёт определение термина с ключом `plain`. Ключ каждого термина указан после определения. Ключи не меняются, даже если меняется русское название.

Термины сгруппированы по темам. Если вы ищете слово по алфавиту, воспользуйтесь поиском по сайту: заголовок каждой записи — само слово.

## Данные и виды результата

### Документ

Запись коллекции MongoDB. Когда в документации сказано «документ» без уточнения, имеется в виду **гидратированный документ**: объект модели, который помнит свои изменения и умеет сохраняться методом `$save`. Ключ: `document`. Подробнее: [Жизненный цикл документа](../documents/lifecycle.mdx).

### Гидратация

Превращение сырой записи из базы в документ модели: значения приводятся к типам схемы, а массивы, поддокументы и `Map` становятся строго типизированными коллекциями. Ключ: `hydration`. Подробнее: [Жизненный цикл документа](../documents/lifecycle.mdx).

### lean-вид

Результат чтения без превращения в документ: обычные объекты, в которых значения BSON остаются своими типами (`ObjectId`, `bigint`, `Date`). Одна строка такого результата называется **lean-строкой**. Ключ: `lean`. Подробнее: [Чтение данных](../queries/reading-data.mdx).

### plain-вид

Результат, который можно отдать клиенту: обычные объекты, в которых `ObjectId` и int64 заменены строками, а скрытые поля убраны. Одна строка такого результата называется **plain-объектом**. Ключ: `plain`. Подробнее: [Чтение данных](../queries/reading-data.mdx).

### Проекция

Список полей, которые запрос возвращает: включение нужных или исключение лишних. В Typemo проекция задаётся методом `select` и меняет тип результата. Ключ: `projection`. Подробнее: [Выбор полей и тип результата](../queries/projections.mdx).

### Selected

Тип, который описывает форму ответа после проекции. Им пользуются, когда форму ответа нужно назвать: например, чтобы вернуть её из функции. Ключ: `selected`. Подробнее: [Контракты](../reference/query/contracts.mdx#selected).

### Контракт

Зафиксированная форма ответа. Компилятор проверяет её при сборке (`.expect`), а во время работы данные из базы можно сверить со схемой (`.parse`). Ключ: `contract`. Подробнее: [Проверка формы ответа](../queries/contracts.mdx).

### Маска

Правило, которое прячет часть значения в ответе клиенту: например, оставляет от почты первую букву и домен. Маски работают только в lean- и plain-видах. Ключ: `mask`. Подробнее: [Маски ответа](../queries/response-masks.mdx).

### Скрытое поле

Поле с опцией `hidden`: оно не попадает в ответы и сериализацию, пока вы не попросите его явно. В типах такое поле помечено маркером `Hidden<T>`. Ключ: `hidden`. Подробнее: [Скрытые и чувствительные поля](../schemas/hidden-and-sensitive.mdx).

### Чувствительное поле

Поле с опцией `sensitive`: его значение маскируется или скрывается там, где оно может утечь, — в ответах, событиях, аудите и ошибках. Ключ: `sensitive`. Подробнее: [Скрытые и чувствительные поля](../schemas/hidden-and-sensitive.mdx).

### Неизвестные поля

Поля, которые есть в документе в базе, но не описаны в схеме. Typemo не теряет их молча: при работе с таким документом он сообщает об этом ошибкой `UnknownFieldsError`. Ключ: `unknown-fields`. Подробнее: [Неизвестные поля](../documents/unknown-fields.mdx).

### Типизированные коллекции

Собственные строго типизированные массивы, `Map` и массивы поддокументов, которые есть у гидратированного документа. Они запрещают записи «мимо методов», потому что каждый метод соответствует оператору MongoDB. Ключ: `typed-collections`. Подробнее: [Массивы и Map в документе](../documents/typed-collections.mdx).

### StrictArray

Тип массива в гидратированном документе: он только читается по индексу, а менять его можно собственными методами (`push`, `pull`, `splice` и другие), каждый из которых записывается в журнал изменений и превращается в оператор MongoDB. Запись по индексу (`tags[0] = "x"`) не компилируется, а если её обойти приведением типа, `$save()` бросает `DirectWriteError` с подсказкой, какими методами менять массив. В `lean`, `plain` и `$toObject()` те же поля — обычные массивы. Ключ: `strict-array`. Подробнее: [Массивы и Map в документе](../documents/typed-collections.mdx).

### Документ в любом состоянии заполнения

Документ, у которого ссылка может быть как идентификатором, так и уже заполненным документом: тип `AnyPopulationDoc<T>`. Он нужен функции, которая принимает и документ без `populate`, и документ после него; сужает его проверка `isPopulated`. Ключ: `any-population-doc`. Подробнее: [Проверки типов при заполнении](../populate/type-checks.mdx).

### Поддокумент

Вложенный объект внутри документа, описанный отдельным классом схемы. У поддокумента есть родитель и путь в нём. Ключ: `subdocument`. Подробнее: [Поддокументы](../documents/subdocuments.mdx).

### BSON

Двоичный формат, в котором MongoDB хранит данные. Типов в нём больше, чем в JSON (`ObjectId`, int64, `Decimal128`, `Binary`, `Timestamp`), поэтому часть значений нельзя отдать клиенту без преобразования. Ключ: `bson`. Подробнее: [Типы данных MongoDB](../concepts/bson-types.mdx).

### ObjectId

Двенадцатибайтовый идентификатор, который MongoDB по умолчанию ставит в поле `_id`. В Typemo везде, где ждут `ObjectId`, принимается и его строковая запись. Ключ: `object-id`. Подробнее: [Типы данных MongoDB](../concepts/bson-types.mdx).

### int64

Шестидесятичетырёхбитное целое. В TypeScript ему соответствует `bigint`: обычное число точно хранит целые только до 2⁵³. Ключ: `int64`. Подробнее: [Типы полей](../schemas/field-types.mdx).

### Decimal128

Точное десятичное число MongoDB, подходящее для денег: в отличие от `number`, оно не округляет дроби. Ключ: `decimal128`. Подробнее: [Типы полей](../schemas/field-types.mdx).

## Схемы и модели

### Схема

Описание данных модели: поля, ограничения, индексы и опции коллекции. В Typemo схема — это класс с декоратором `@Schema`. Ключ: `schema`. Подробнее: [Описать модель](../schemas/define-model.mdx).

### Модель

Объект, через который вы читаете и пишете одну коллекцию: `find`, `create`, `updateOne` и остальные методы. Модель получают у подключения: `connection.model(Account)`. Ключ: `model`. Подробнее: [Описать модель](../schemas/define-model.mdx).

### Поле

Свойство класса схемы с декоратором `@Prop`. Тип поля выводится из класса, а опции (`required`, `unique`, `hidden` и другие) задают ограничения. Ключ: `field`. Подробнее: [Описать модель](../schemas/define-model.mdx).

### Базовый класс

Класс, от которого наследуется модель, чтобы получить служебные поля: `Entity` даёт `_id`, `Timestamped` добавляет `createdAt` и `updatedAt`, `Versioned` — версию `__v`, а `EntityWithId` — `_id` собственного типа (строка, число, UUID и другие) вместо `ObjectId`. Typemo не добавляет эти поля скрытно. Ключ: `base-class`. Подробнее: [Базовые классы](../reference/schemas/base-classes.mdx).

### Маркерные типы

Типы-обёртки, которыми поле сообщает системе типов своё свойство: `Hidden<T>`, `Immutable<T>`, `Ref<M>` и другие. Они не меняют значение во время работы, а меняют то, что разрешает компилятор. Ключ: `marker-types`. Подробнее: [Маркерные типы полей](../reference/schemas/field-markers.mdx).

### Обязательность, `null` и отсутствие

Три разных состояния поля: у него есть значение, значение равно `null`, значения нет. Typemo различает их и не считает `undefined` значением. Ключ: `nullable`. Подробнее: [Обязательность, null и отсутствие](../schemas/required-and-null.mdx).

### Вложенный объект

Объект внутри документа, который описан классом с `@Schema({ nested })` и не имеет собственного `_id` и коллекции. Ключ: `nested-object`. Подробнее: [Вложенные объекты и поддокументы](../schemas/nested-and-subdocuments.mdx).

### Неизменяемое поле

Поле с опцией `immutable`: после создания документа его нельзя менять. Ключ: `immutable`. Подробнее: [Неизменяемые поля](../schemas/immutable.mdx).

### Виртуальное поле

Поле, которого нет в базе: оно вычисляется при чтении (геттер) или подгружает связанные документы (`@Virtual`). Ключ: `virtual`. Подробнее: [Виртуальные поля](../schemas/virtuals.mdx).

### Ссылка

Поле, которое хранит идентификатор документа другой модели. По ссылке можно заполнить связь (populate). Ключ: `reference`. Подробнее: [Ссылки на другие модели](../schemas/references.mdx).

### Дискриминатор

Способ хранить несколько моделей-наследников в одной коллекции: отдельное поле (`discriminatorKey`) говорит, к какой модели относится документ. Ключ: `discriminator`. Подробнее: [Наследование и дискриминаторы](../schemas/discriminators.mdx).

### Валидация

Проверка значений по правилам схемы (`min`, `max`, `enum`, свой `validate`). Она выполняется при создании, сохранении и обновлении, а её ошибки собраны в `ValidationError` с путями полей. Ключ: `validation`. Подробнее: [Валидация полей](../schemas/validation.mdx).

### Оптимистичная конкурентность

Защита от потери параллельных правок: документ хранит версию `__v`, а сохранение с устаревшей версией отклоняется ошибкой `VersionError`. Ключ: `optimistic-concurrency`. Подробнее: [Версии и параллельные изменения](../documents/versions.mdx).

## Подключение

### Peer-зависимость

Пакет, который Typemo требует от вас (`peerDependencies`), а не приносит с собой: это `mongodb` и `bson`. Так значения BSON в вашем коде и в библиотеке — одни и те же классы. Ключ: `peer-dependency`. Подробнее: [Установка и настройка](../getting-started/installation.mdx).

### Клиент

Объект `TypemoClient`, который владеет подключением к MongoDB и пулом соединений. Его создают один раз на процесс. Ключ: `client`. Подробнее: [Подключиться к базе](../connection/connect.mdx).

### Подключение

Объект `Connection`: связь клиента с одной базой. У него берут модели (`model`), на нём запускают синхронизацию индексов (`init`, `syncAll`). Ключ: `connection`. Подробнее: [Подключиться к базе](../connection/connect.mdx).

### Драйвер

Официальный пакет `mongodb`, через который Typemo говорит с сервером. Обойти Typemo и обратиться к драйверу можно через `client.unsafeDriver()`, но политики, маски и хуки при этом не действуют. Ключ: `driver`. Подробнее: [Доступ к драйверу](../connection/driver-access.mdx).

### Реплика-сет

Группа серверов MongoDB, хранящих одни и те же данные; допустим и реплика-сет из одного узла. Он нужен для транзакций, подписки на изменения и моделей с аудитом. Ключ: `replica-set`. Подробнее: [Подключиться к базе](../connection/connect.mdx).

### Коллекция

Набор документов в базе MongoDB, примерно то же, что таблица в реляционной базе. Ключ: `collection`. Подробнее: [Подключиться к базе](../connection/connect.mdx).

## Чтение и запись

### Строитель запроса

Объект, который возвращают `find`, `findOne` и другие методы: он собирает запрос цепочкой (`select`, `sort`, `limit`) и обращается к базе только на `await`. Ключ: `query-builder`. Подробнее: [Чтение](../reference/query/reading.mdx).

### Фильтр

Условие поиска: объект, где ключи — поля модели, а значения — значение поля или оператор (`$in`, `$gt`). Typemo проверяет фильтр компилятором и во время работы. Ключ: `filter`. Подробнее: [Фильтры](../queries/filters.mdx).

### Курсор

Объект, который отдаёт документы по одному, по мере чтения из базы. Он нужен, когда выборка не помещается в память. Ключ: `cursor`. Подробнее: [Большие выборки](../queries/large-results.mdx).

### Пагинация по ключу

Способ листать длинные списки без `skip`: следующая страница ищется по значению сортировочных полей последней записи, которое кодируется в подписанный токен. Ключ: `keyset-pagination`. Подробнее: [Пагинация по ключу](../queries/keyset-pagination.mdx).

### План запроса

Описание того, как сервер выполнит запрос: какой индекс возьмёт и сколько документов просмотрит. Его показывает `explain`. Ключ: `query-plan`. Подробнее: [Производительность запросов](../queries/performance.mdx).

### Оператор обновления

Ключ вида `$set`, `$inc`, `$push` в объекте обновления: он говорит серверу, что сделать с полем, а не заменяет документ целиком. Ключ: `update-operator`. Подробнее: [Операторы обновления](../writes/update-operators.mdx).

### Обновление через конвейер

Обновление, в котором вместо операторов передаётся конвейер стадий: так новое значение поля можно вычислить из других полей документа. Ключ: `pipeline-update`. Подробнее: [Обновление через конвейер](../writes/pipeline-updates.mdx).

### Пустой фильтр

Фильтр `{}`, которому подходят все документы. В чтении он разрешён, а в записи (`updateOne`, `updateMany`, `deleteOne`, `deleteMany`, `replaceOne`, `findOneAnd*`) запрещён: чтобы затронуть всё намеренно, пишут `Filters.all()`. Ключ: `empty-filter`. Подробнее: [Пустые фильтры в записи](../writes/empty-filters.mdx).

### Операция уровня базы

Агрегация, которая не читает коллекцию модели, а работает со всей базой, с базой `admin` или с сессиями сервера: `$currentOp`, `$documents`, `$listSessions`. Её план строят `Pipeline.database()`, `Pipeline.admin()` и `Pipeline.sessions()`, а выполняют `connection.aggregate` и `client.aggregate`. У такой операции нет модели, поэтому в событиях `model` равен `null`, а хуки не вызываются. Ключ: `database-level-operation`. Подробнее: [Запросы уровня базы](../aggregation/database-level.mdx).

### Пакетная запись

Несколько разных операций записи, отправленных на сервер одним запросом методом `bulkWrite`. Ключ: `bulk-write`. Подробнее: [Пакетная запись](../writes/bulk.mdx).

## Связанные данные и агрегации

### Populate

Заполнение связи: вместо идентификатора в поле-ссылке появляется сам связанный документ, а тип поля меняется вместе с этим. В тексте документации это «заполнить связь», а термин — «связанные данные». Ключ: `populate`. Подробнее: [Populate: основы](../populate/basics.mdx).

### Конвейер

Последовательность **стадий** агрегации: каждая стадия принимает документы предыдущей и отдаёт следующей. Typemo выводит тип результата после каждой стадии. Ключ: `pipeline`. Подробнее: [Первая агрегация](../aggregation/first-aggregation.mdx).

### Стадия

Один шаг конвейера: `$match` отбирает документы, `$group` группирует, `$lookup` соединяет с другой коллекцией. Ключ: `stage`. Подробнее: [Стадии](../reference/aggregation/stages.mdx).

### Выражение

Формула внутри стадии, которая вычисляет значение из полей документа: арифметика, строки, даты, массивы. В Typemo выражения строятся типизированными функциями, а сырой `$expr` запрещён. Ключ: `expression`. Подробнее: [Выражения](../aggregation/expressions.mdx).

### Аккумулятор

Оператор, который сворачивает много документов группы в одно значение: сумма, среднее, число, первое значение. Ключ: `accumulator`. Подробнее: [Группировка и отчёты](../aggregation/grouping.mdx).

### Оконная функция

Вычисление по «окну» соседних документов — например, скользящее среднее или накопительная сумма, — которое не сворачивает документы в одну строку. Ключ: `window-function`. Подробнее: [Оконные функции](../aggregation/windows.mdx).

## Транзакции, хуки и расширения

### Транзакция

Группа операций, которые выполняются целиком или не выполняются вовсе. Typemo запускает транзакцию методом `transaction` и сам повторяет её при временных ошибках. Ключ: `transaction`. Подробнее: [Транзакции](../transactions/transactions.mdx).

### Сессия

Контекст, в котором сервер связывает несколько операций: в частности, транзакцию. Обычно вам не нужна сессия вручную, её ведёт `transaction`. Ключ: `session`. Подробнее: [Сессии вручную](../transactions/sessions.mdx).

### Хук

Ваша функция, которую Typemo вызывает до (`@Pre`) или после (`@Post`) операции или события документа. Хук видит контекст операции и может изменить фильтр, обновление или пропустить операцию. Ключ: `hook`. Подробнее: [Хуки операций](../hooks/operation-hooks.mdx).

### Плагин

Набор хуков и статических методов, который подключается к схеме или ко всем моделям сразу и повторяет одну и ту же логику. Ключ: `plugin`. Подробнее: [Плагины](../hooks/plugins.mdx).

### Расширение

Способ добавить полю или схеме собственные опции через ключ `ext`: расширение объявляет тип опции и регистрируется у клиента до первой модели. Ключ: `ext`. Подробнее: [Свои опции полей и схем](../extensions/custom-options.mdx).

## Политики и строгость

### Политика

Правило, которое действует на все операции модели и которое нельзя отключить в отдельном запросе: тенант, мягкое удаление, строгие пути, аудит. Ключ: `policy`. Подробнее: [Что такое политики](../policies/overview.mdx).

### Тенант

Владелец данных в приложении, где одна база обслуживает многих клиентов. Политика `tenant` подставляет тенанта в каждый запрос, поэтому один клиент не увидит чужие документы. Ключ: `tenant`. Подробнее: [Мультитенантность](../policies/tenants.mdx).

### Мягкое удаление

Удаление, при котором документ остаётся в базе с пометкой, а чтения его больше не возвращают. Включается опцией схемы `softDelete`. Ключ: `soft-delete`. Подробнее: [Мягкое удаление](../policies/soft-delete.mdx).

### Контекст политик

Значения политик для текущего запроса: тенант, автор действия и флаги вроде `includeDeleted`. Его задают через `PolicyContext.run` или `.policy()` у запроса. Ключ: `policy-context`. Подробнее: [Контекст политик](../policies/policy-context.mdx).

### Актор

Тот, кто совершает действие: пользователь или служба. Актор передаётся в контексте политик и записывается в журнал аудита рядом с изменением. Ключ: `actor`. Подробнее: [Контекст политик](../policies/policy-context.mdx).

### Аудит

Запись в отдельную коллекцию о каждом изменении данных: кто, что и когда изменил. Значения чувствительных полей в аудите маскируются. Ключ: `audit`. Подробнее: [Аудит](../policies/audit.mdx).

### Недоверенный ввод

Значения, пришедшие от клиента приложения. Функция `untrusted()` не даёт им подсунуть в фильтр оператор MongoDB и превратить условие в другое. Ключ: `untrusted-input`. Подробнее: [Недоверенный ввод](../policies/untrusted-input.mdx).

### Нарушение политики

Ошибка `StrictModeError` с кодом причины (`empty-filter`, `unknown-path`, `tenant` и другие): операция отвергнута политикой до обращения к базе. Ключ: `policy-violation`. Подробнее: [Нарушения политик](../reference/policies/violations.mdx).

### Строгость

Главный принцип Typemo: всё, что похоже на ошибку — неизвестное поле, `undefined` в фильтре, пустой фильтр в записи, неверный тип, — становится ошибкой, а не тихим поведением. Ослабить строгость нельзя ни опцией, ни режимом. Ключ: `strictness`. Подробнее: [Строгость](../concepts/strictness.mdx).

## Коллекции и индексы

### Индекс

Структура, которая ускоряет поиск и обеспечивает уникальность. Индексы описываются в схеме и создаются явно, при `init` или `syncAll`, а не при первом запросе. Ключ: `index`. Подробнее: [Синхронизация индексов](../collections/index-sync.mdx).

### Синхронизация индексов

Приведение индексов в базе к тем, что описаны в схеме: `syncIndexes` создаёт недостающие и убирает лишние, а `diffIndexes` только показывает разницу. Ключ: `index-sync`. Подробнее: [Синхронизация индексов](../collections/index-sync.mdx).

### Поисковый индекс

Индекс для полнотекстового и векторного поиска, который строит сам сервер (Atlas Search и векторный поиск). Ключ: `search-index`. Подробнее: [Поисковые индексы](../collections/search-indexes.mdx).

### Представление

Коллекция только для чтения, содержимое которой сервер вычисляет конвейером при каждом обращении. В Typemo её описывает `TypedView`. Ключ: `view`. Подробнее: [Представления](../collections/views.mdx).

### Материализованное представление

Результат конвейера, сохранённый в обычной коллекции: он не пересчитывается при чтении и обновляется вызовом `refresh`. Ключ: `materialized-view`. Подробнее: [Материализованные представления](../collections/materialized-views.mdx).

## Подписка на изменения и наблюдаемость

### Подписка на изменения

Поток событий (`change stream`), в котором сервер сообщает о вставках, обновлениях, заменах и удалениях в коллекции. Открывается методом `Model.watch`; нужен реплика-сет. Ключ: `change-stream`. Подробнее: [Подписаться на изменения](../change-streams/watch.mdx).

### Маркер продолжения

Токен, который есть у каждого события подписки: с ним можно возобновить чтение с того же места после разрыва. Ключ: `resume-token`. Подробнее: [Подписаться на изменения](../change-streams/watch.mdx).

### События операций

События, которые Typemo рассылает подписчикам: начало, конец и ошибка операции, команды драйвера, состояние пула. На них строятся интеграции с мониторингом. Ключ: `instrumentation`. Подробнее: [События операций](../observability/events.mdx).

### Подписчик

Ваша функция, которую регистрируют через `client.instrument` или `Typemo.instrument`: она получает события операций и передаёт их в мониторинг. Ключ: `subscriber`. Подробнее: [События операций](../observability/events.mdx).

### OpenTelemetry

Отдельный пакет `@venloc/typemo-opentelemetry`, который превращает события операций в спаны и метрики. Ядро Typemo от него не зависит. Ключ: `opentelemetry`. Подробнее: [OpenTelemetry](../observability/opentelemetry.mdx).

### Sentry

Отдельный пакет `@venloc/typemo-sentry`, который добавляет в Sentry breadcrumbs операций и контекст ошибок Typemo. Ядро от него не зависит. Ключ: `sentry`. Подробнее: [Sentry](../observability/sentry.mdx).

## Ошибки и типы

### Ошибка Typemo

Любая ошибка библиотеки — потомок класса `TypemoError`. Ловить их удобно по классу (`ValidationError`, `DuplicateKeyError`), а исходная причина лежит в поле `cause`. Ключ: `typemo-error`. Подробнее: [Обработка ошибок](../errors/handling.mdx).

### Standard Schema

Общий интерфейс схем валидации: модель Typemo можно передать туда, где ждут схему zod, valibot и других библиотек, которые его поддерживают. Ключ: `standard-schema`. Подробнее: [JSON Schema и Standard Schema](../schemas/json-and-standard-schema.mdx).

### JSON Schema

Формат описания данных, который понимает MongoDB для проверки документов на стороне сервера. Typemo генерирует его из схемы модели. Ключ: `json-schema`. Подробнее: [JSON Schema и Standard Schema](../schemas/json-and-standard-schema.mdx).

### Фабрика тестовых данных

Функция, созданная `defineFactory`, которая один раз задаёт значения документа по умолчанию (с порядковым номером), а тест указывает только то, что для него важно. Живёт в `@venloc/typemo/testing`. Ключ: `factory`. Подробнее: [Тестировать приложение](../testing/testing-apps.mdx).

## Декораторы

### Legacy-декораторы

Декораторы в режиме `experimentalDecorators`. Для них не нужны ни `emitDecoratorMetadata`, ни `import "reflect-metadata"`: ядро хранит метаданные само. На них работает ядро `@venloc/typemo`. Ключ: `legacy-decorators`. Подробнее: [Установка и настройка](../getting-started/installation.mdx).

### TC39-декораторы

Декораторы из стандарта ECMAScript. Для них есть отдельный пакет `@venloc/typemo-decorators`; смешивать два вида в одном проекте нельзя. Ключ: `tc39-decorators`. Подробнее: [Использовать TC39-декораторы](../decorators-tc39/tc39.mdx).
