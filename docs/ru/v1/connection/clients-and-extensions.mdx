Один процесс может держать несколько клиентов: основную базу приложения, отдельный сервер для отчётов, клиент, который создаёт библиотека. Настройки, которые расширяют Typemo (расширения схем, плагины, подписчики на события), можно регистрировать **глобально**, тогда их увидят все клиенты, или **на одном клиенте**. Эта страница объясняет, как выбирать, что общее, а что своё у каждого клиента, и почему порядок регистрации важен.

Если вы впервые работаете с подключением, сначала прочитайте руководство [Подключиться к базе](./connect.mdx).

## Что предполагается

Примеры используют модель счёта и два клиента: `main` для рабочих данных и `reports` для отчётов. Расширение `label` хранит в описании поля подпись для интерфейса. Для Typemo оно только метаданные: расширение никогда не вмешивается в операции и не обходит политики.

```ts twoslash title="accounts/account.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;
}
```

## Быстрый путь

Три способа регистрации, от самого широкого к самому узкому. Расширение схемы для всех клиентов — [`Typemo.use`](../reference/connection/typemo.mdx#typemouse), для одного — [`client.use`](../reference/connection/typemo-client.mdx#clientuse). Подписчик на события всех клиентов — [`Typemo.instrument`](../reference/connection/typemo.mdx#typemoinstrument), одного — [`client.instrument`](../reference/connection/typemo-client.mdx#clientinstrument).

```ts twoslash
import { Typemo, TypemoClient } from "@venloc/typemo";
declare module "@venloc/typemo" {
  interface PropExtensions<V> {
    label?: { readonly text: string };
  }
}
const check = (value: unknown): void => {
  if (typeof value !== "object" || value === null) throw new Error("label: an object is expected");
};
const client = new TypemoClient("mongodb://localhost:27017/app");
// ---cut---
Typemo.use({ name: "label", validateProp: check }); // для всех клиентов
// или
client.use({ name: "label", validateProp: check }); // только для этого клиента
```

Остальная страница разбирает оба уровня на задачах.

## Держать два клиента

Второй клиент нужен, когда данные лежат на другом сервере или когда нужны другие настройки: срок операций, размер пула. Для второй базы **того же** сервера клиент не нужен, достаточно [`client.db`](../reference/connection/typemo-client.mdx#clientdb). Клиентам полезно дать имена через опцию `name`: имя попадает в события и в тексты ошибок, и в журнале видно, какой клиент сработал.

```ts twoslash title="db/clients.ts"
import { TypemoClient } from "@venloc/typemo";

export const main = await TypemoClient.connect("mongodb://localhost:27017/app", { name: "main" });
export const reports = await TypemoClient.connect("mongodb://reports.example.test:27017/reports", {
  name: "reports",
  timeoutMS: 60_000,
});
```

Клиенты полностью независимы: у каждого свой пул, своё состояние и своё закрытие. Закрыв `reports`, вы не затронете `main`.

## Зарегистрировать расширение для всех клиентов

**Расширение** добавляет в описание модели новый ключ внутри `ext` у `@Prop` или `@Schema` и проверяет его значения. Так интеграции хранят свои настройки прямо у поля. Расширение состоит из двух частей: объявление типа для компилятора (`declare module`) и регистрация с проверкой значения.

Регистрируйте глобально то, что должно работать в каждой модели приложения и в библиотеках, которые создают свои клиенты:

```ts twoslash title="extensions/label.ts"
import { Typemo } from "@venloc/typemo";

declare module "@venloc/typemo" {
  interface PropExtensions<V> {
    label?: { readonly text: string };
  }
}

Typemo.use({
  name: "label",
  validateProp: (value) => {
    if (typeof value !== "object" || value === null || typeof (value as { text?: unknown }).text !== "string") {
      throw new Error("label.text must be a string");
    }
  },
});
```

После этого любая модель любого клиента может использовать `ext: { label: { text: "…" } }`. Проверка выполняется при компиляции схемы, то есть при первом [`connection.model`](../reference/connection/connection.mdx#connectionmodel). Если значение неверно, ошибка появится там, а не при первой записи: проверка бросает ошибку, и она становится `cause` у `ConfigurationError`.

Повторное имя запрещено. Если имя занято глобально, его нельзя зарегистрировать и на клиенте, и наоборот:

```text
ConfigurationError: extension "label" is already registered
```

## Зарегистрировать расширение для одного клиента

Если расширение нужно только моделям одного клиента, регистрируйте его на клиенте. Другие клиенты о нём не знают: модель с таким ключом на другом клиенте не скомпилируется. Текст ошибки получен запуском, для модели, у которой `ext: { label: … }` стоит на поле `owner`:

```text
ConfigurationError: Account.owner: ext "label" is not a registered extension; register it before the first model with client.use() (for the models of one client) or Typemo.use() (for every client)
```

Ошибка называет поле и подсказывает исправление. Разграничение полезно, когда библиотека создаёт свой клиент и свои модели: её расширения не попадают в ваше приложение, а ваши не мешают ей.

```ts twoslash title="db/reports-client.ts"
import { TypemoClient } from "@venloc/typemo";
declare module "@venloc/typemo" {
  interface PropExtensions<V> {
    label?: { readonly text: string };
  }
}
// ---cut---
const reports = new TypemoClient("mongodb://localhost:27017/reports", { name: "reports" });
reports.use({
  name: "label",
  validateProp: (value) => {
    if (typeof value !== "object" || value === null) throw new Error("label: an object is expected");
  },
});
```

## Регистрировать до первой модели

Порядок важен. Расширение нельзя зарегистрировать после того, как клиент скомпилировал первую модель: расширение, появившееся позже, не смогло бы проверить уже готовые схемы. Тогда вы получаете ошибку, которая называет модель, вызвавшую закрытие:

```text
ConfigurationError: extension "late": extensions are fixed once a schema is compiled (Account was); call client.use() before the first model
```

Расширения и плагины закрываются по одному правилу: первой **успешной** компиляцией схемы. Реестр клиента (`client.use`) и реестр подключения ([`connection.plugins`](../reference/connection/connection.mdx#connectionplugins)) закрывает первая модель этого клиента или подключения. Глобальные реестры — [`Typemo.use`](../reference/connection/typemo.mdx#typemouse) и [`Typemo.plugin`](../reference/connection/typemo.mdx#typemoplugin) — закрывает первая модель на **любом** клиенте. Причина та же для всех: расширение или плагин, появившиеся позже, не повлияли бы на схемы, которые уже скомпилированы, и приложение работало бы с ними у одних моделей, а у других нет.

Компиляция, которая упала, ничего не закрывает. Если модель не скомпилировалась, потому что ключ `ext` не зарегистрирован, вы можете зарегистрировать его и вызвать `connection.model` снова: запуск показал, что после такой ошибки `Typemo.use`, `Typemo.plugin` и `client.use` ещё принимают регистрацию. Клиент видит и собственные расширения, и глобальные, в том числе зарегистрированные после создания клиента, пока не скомпилирована его первая модель.

Следствие для библиотек: если библиотека создаёт клиент и модели при импорте, ваши глобальные `Typemo.use` и `Typemo.plugin`, вызванные после такого импорта, уже закрыты. Поэтому глобальные регистрации делают раньше любых импортов, которые создают модели. Расширение на клиенте (`client.use`) от этого не страдает: у вашего клиента своя модель ещё не скомпилирована.

```text
ConfigurationError: plugin "late": the global plugins are fixed once a schema is compiled (Account was); register plugins before the first model
```

Поэтому порядок запуска такой: сначала глобальные плагины и расширения, затем клиенты и их расширения, затем модели.

## Подписаться на события всех клиентов или одного

События операций (начало, конец, ошибка) видит подписчик, зарегистрированный глобально, у каждого клиента, или на одном клиенте. Глобальный подписчик нужен интеграциям (метрики, трассировка): он видит все клиенты. Событие содержит имя клиента, базу и операцию, поэтому один подписчик различает клиентов.

```ts twoslash title="observability/log.ts"
import { Typemo } from "@venloc/typemo";

Typemo.instrument({
  handle: (event) => {
    if (event.type === "operation.end") console.log(`${event.connection}/${event.database}: ${event.operation}`);
  },
});
// → "main/app: insertOne"
// → "reports/reports: find"
```

Подписчик клиента ([`client.instrument`](../reference/connection/typemo-client.mdx#clientinstrument)) видит только операции этого клиента. Обе регистрации возвращают подписку с методом `unsubscribe()`. Подробнее об устройстве событий — в руководстве [События операций](../observability/events.mdx).

## Как выбрать уровень

Задайте себе один вопрос: **кому ещё должна быть видна эта настройка, кроме моих моделей?** Если она нужна всему процессу, в том числе библиотекам, которые создают свои клиенты, регистрируйте её глобально. Если нужна одному клиенту, регистрируйте её на клиенте: так чужой код не получит ваше расширение, а ваш не получит чужое. Приложение целиком обычно регистрирует глобально плагины и подписчиков наблюдаемости, а расширения — на тех клиентах, чьи модели их используют. Если в приложении один клиент, разница практически исчезает, и достаточно глобального уровня.

## Когда это не нужно

Если вам нужно хранить свои настройки в описании поля, а не проверять их, обычное расширение не нужно: достаточно [`@Prop`](../reference/schemas/prop.mdx) с его собственными опциями. Если вы хотите изменить поведение операции (фильтр, обновление), расширение для этого не предназначено: оно не участвует в операциях и не обходит политики. Для вмешательства в операцию используются [хуки](../hooks/operation-hooks.mdx).

## Частые ошибки

### Регистрация после первой модели

Расширение или плагин регистрируется в модуле, который импортируется позже моделей. Ошибка `are fixed once a schema is compiled` называет модель, которая закрыла реестр. Перенесите регистрацию выше: в файл, который выполняется до подключения моделей.

### Расширение объявлено для компилятора, но не зарегистрировано

`declare module` даёт ключ только компилятору. Без `Typemo.use` или `client.use` модель компилируется в TypeScript, но падает при первом [`connection.model`](../reference/connection/connection.mdx#connectionmodel) с текстом `ext "label" is not a registered extension`. Нужны обе части.

### Расширение зарегистрировано на одном клиенте, а модель на другом

Тот же текст ошибки у модели, которую вы получили у второго клиента. Зарегистрируйте расширение на втором клиенте или глобально через [`Typemo.use`](../reference/connection/typemo.mdx#typemouse).

## Полный пример

Файл запуска собирает всё в правильном порядке: глобальные плагины и расширения, два клиента, подписчик, модели.

```ts twoslash title="bootstrap.ts"
import { Entity, Prop, Schema, Typemo, TypemoClient } from "@venloc/typemo";

declare module "@venloc/typemo" {
  interface PropExtensions<V> {
    label?: { readonly text: string };
  }
}

@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, ext: { label: { text: "Название" } } })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;
}

// 1. глобальные плагины и расширения: до первой модели любого клиента
Typemo.plugin({ name: "log-compiled", apply: (builder) => console.log("схема", builder.target.name) });
Typemo.use({
  name: "label",
  validateProp: (value) => {
    if (typeof value !== "object" || value === null) throw new Error("label: an object is expected");
  },
});

// 2. подписчик на все клиенты
Typemo.instrument({
  handle: (event) => {
    if (event.type === "operation.end") console.log(`${event.connection}/${event.database}: ${event.operation}`);
  },
});

// 3. клиенты
const main = await TypemoClient.connect("mongodb://localhost:27017/app", { name: "main" });
const reports = await TypemoClient.connect("mongodb://localhost:27017/reports", { name: "reports" });

// 4. модели
const Accounts = main.connection.model(Account);
const ReportAccounts = reports.connection.model(Account);

await Accounts.create({ owner: "alice", title: "Main" });
await ReportAccounts.find();

await Promise.all([main.close(), reports.close()]);
```

<Callout type="migration">

Глобальные плагины в Mongoose подключаются через `mongoose.plugin`. В Typemo это [`Typemo.plugin`](../reference/connection/typemo.mdx#typemoplugin), и он строже: регистрация после компиляции первой схемы — [`ConfigurationError`](../reference/errors/configuration-errors.mdx#configurationerror), а не молчаливое отсутствие плагина у части моделей. Отдельного понятия «расширение схемы» (`Typemo.use`, `client.use`) в Mongoose нет: Typemo различает плагин, который меняет схему, и расширение, которое лишь несёт и проверяет метаданные.

</Callout>
