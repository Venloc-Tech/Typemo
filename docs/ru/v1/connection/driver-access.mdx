Typemo оборачивает не весь драйвер MongoDB. Команды администратора, GridFS и другие возможности драйвера остаются за пределами моделей. Для них у клиента есть доступ к самому `MongoClient` — [`client.unsafeDriver`](../reference/connection/typemo-client.mdx#client.unsafe-driver).

Слово `unsafe` в названии стоит не зря. Всё, что вы делаете через этот объект, идёт мимо защит Typemo. Ниже разберём, когда драйвер действительно нужен, что вы при этом теряете и как без него обойтись.

Если вы ещё не подключились к базе, начните с руководства [Подключиться к базе](./connect.mdx).

## Что понадобится [#prerequisites]

Подключённый клиент из файла `db/client.ts` и модель счёта из `accounts/account.ts`. Модель будет расти по ходу страницы. Сначала в ней два поля, потом появятся скрытый PIN и мягкое удаление.

```ts twoslash title="db/client.ts"
import { TypemoClient } from "@venloc/typemo";

export const client = await TypemoClient.connect("mongodb://localhost:27017/app");
```

## Быстрый путь [#quick-start]

[`client.unsafeDriver`](../reference/connection/typemo-client.mdx#client.unsafe-driver) возвращает драйверный `MongoClient`. Через него можно, например, отправить серверу проверку связи, которой у моделей нет.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
// ---cut---
const pong = await client.unsafeDriver().db("admin").command({ ping: 1 });
console.log(pong.ok);
// → 1
```

Метод каждый раз возвращает один и тот же объект, хранить его в переменной не нужно. Дальше — что вы теряете и как понять, что драйвер вам правда нужен.

## Отправить команду администратора [#admin-command]

Команды сервера вроде `ping`, `buildInfo` или управления пользователями работают на уровне базы и ни к одной модели не относятся. Модели их не выражают, так что здесь драйвер — единственный путь. И потерь почти нет, ведь команда не трогает данные ваших моделей.

```ts twoslash title="db/health.ts"
import { TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
// ---cut---
export const serverVersion = async (): Promise<string> => {
  const info = await client.unsafeDriver().db("admin").command({ buildInfo: 1 });
  return String(info.version);
};
```

Драйвер работает через то же подключение и тот же пул, что и модели. Отдельный клиент для этого не нужен.

## Прочитать коллекцию мимо модели [#read-raw-collection]

Иногда нужно увидеть данные такими, как они лежат в базе, — при отладке, миграции или разборе странного случая. Драйвер вернёт документ без слоя Typemo. Разницу проще показать на примере. Пусть в модели есть скрытое поле `pin`, которое Typemo наружу не отдаёт.

```ts twoslash title="accounts/account.ts"
import { Entity, type Hidden, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => String, { hidden: true })
  pin?: Hidden<string>;
}
```

Через модель скрытое поле в результат `.plain()` не попадёт, а драйвер вернёт документ целиком. Возьмём запись `{ title: "Main", owner: "alice", pin: "1234" }`. У результата модели ключи `_id`, `title` и `owner`, а у документа из драйвера ещё и `pin` со значением `"1234"`. Отличается и идентификатор. В драйвере `_id` — объект `ObjectId`, а в результатах модели это строка.

```ts twoslash title="accounts/inspect.ts"
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
// ---cut---
const Accounts = client.connection.model(Account);
const viaModel = await Accounts.findOne({ owner: "alice" }).plain();
//    ^?
const viaDriver = await client.unsafeDriver().db("app").collection("accounts").findOne({ owner: "alice" });
//    ^?
```

Всё, что бережёт данные, здесь не работает. Скрытые поля, маски `sensitive` и аудит не помогут, и секрет увидит любой код, у которого есть `MongoClient`. Не передавайте его туда, где нужны только данные моделей.

## Что вы теряете [#what-you-lose]

Все проверки Typemo живут внутри операций модели, и драйвер о них ничего не знает. Посмотрим, что будет с коллекцией в четырёх случаях.

**Мягкое удаление перестаёт работать.** Добавим модели опцию `softDelete` и поле `deletedAt`. После `deleteOne` через модель документ помечен удалённым, и модель его больше не видит. А драйвер видит запись как раньше.

```ts twoslash title="accounts/account.ts"
import { Entity, type Hidden, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts", softDelete: true }) // [!code highlight]
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => String, { hidden: true })
  pin?: Hidden<string>;

  @Prop(() => Date, { nullable: true }) // [!code ++]
  deletedAt?: Date | null; // [!code ++]
}
```

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts", softDelete: true })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Date, { nullable: true }) deletedAt?: Date | null;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
const raw = client.unsafeDriver().db("app").collection("accounts");
// ---cut---
await Accounts.deleteOne({ title: "Main" });
console.log(await Accounts.countDocuments(), await raw.countDocuments());
// → 0 1
```

**Проверки данных не срабатывают.** Драйвер запишет документ с числом в поле `title`, и модель по умолчанию прочитает его как есть. Чтение не сверяет каждый документ со схемой. Данные, записанные через модель, уже проверены при записи, а сверка стоила бы времени на каждом чтении. Запись через модель упала бы с ошибкой, но запись мимо неё проверить некому.

Чтобы такой документ не попал в код под чужим типом, включите **строгое чтение**. Это вызов [`.validateReads()`](../reference/query/options.mdx#validate-reads) в запросе или опция клиента [`validateReads`](../reference/connection/typemo-client.mdx#validate-reads).

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
const raw = client.unsafeDriver().db("app").collection("accounts");
// ---cut---
await raw.insertOne({ title: 5, owner: "bob" });

console.log(await Accounts.find({ owner: "bob" }).plain());
// → [{ _id: "…", title: 5, owner: "bob" }]

try {
  await Accounts.find({ owner: "bob" }).validateReads().plain();
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to string failed at path "title" for 5 (number): the stored value does not match the schema of Account (a document read from the database, checked by validateReads) [type]
```

Первое чтение вернуло `title: 5`, хотя у поля тип `string`. Второе сверило документ со схемой и остановилось на `title` с ошибкой [`CastError`](../reference/errors/data-errors.mdx#cast-error).

Если в коллекцию пишут другие программы или скрипты через драйвер, включите в клиенте `validateReads: "development"`. Тогда в разработке и тестах сверяется каждое чтение, а в продакшене (`NODE_ENV=production`) проверка не тратит время. Подробнее в концепции [Строгость](../concepts/strictness.mdx#existing-data).

**Транзакции не подхватывают запись драйвера.** Операции моделей внутри [`client.transaction`](../reference/connection/typemo-client.mdx#client.transaction) присоединяются к ней сами, а вызов драйвера — нет. Транзакция откатилась, а запись `raw.insertOne` из неё осталась — `raw in tx survived rollback: 1`.

Чтобы драйверная операция вошла в транзакцию, передайте ей сессию явно — `raw.insertOne(doc, { session: scope.session })`, где `scope` — аргумент функции транзакции. С сессией после отката документа в коллекции нет, счётчик показывает `0`.

**События и аудит не видят такие вызовы.** Подписчики [`client.instrument`](../reference/connection/typemo-client.mdx#client.instrument) не узнают об операциях драйвера, а модель с аудитом не оставит следа.

## Модель или драйвер [#model-or-driver]

Спросите себя, **касается ли операция данных ваших моделей**.

- **Да** — берите модель, даже если запись выходит длиннее. Политики, проверки, маски и события работают только там.
- **Операция про сервер или про то, чего у моделей нет**, вроде команд администратора, GridFS или сбора статистики, — берите драйвер.
- **Сомневаетесь** — загляните в справочник моделей. Многое, что кажется недоступным, там уже есть, например агрегации ([`Pipeline`](../reference/aggregation/pipeline.mdx)) и потоки изменений ([`Model.watch`](../reference/change-streams/watch.mdx)).

## Когда это не нужно [#when-not-to-use]

Читайте и пишите данные моделей через модель. Мягкое удаление, скрытые поля и аудит работают только там. Если запрос хочется выразить иначе, посмотрите [операторы фильтра](../reference/query/filter-operators.mdx) и [конвейеры агрегации](../aggregation/first-aggregation.mdx). Скорее всего, обходить модель не придётся.

## Если что-то пошло не так [#troubleshooting]

**Скрытое поле утекло в ответ.** Обработчик отдаёт клиенту документ, прочитанный через драйвер, и вместе с ним уходит скрытое поле. Документ получен не через модель, и скрывать поле было некому. Читайте через модель и отдавайте результат `.plain()`. О формах результата рассказано в руководстве [Чтение данных](../queries/reading-data.mdx).

**Удалённый документ снова «появился».** Отчёт на драйвере считает удалённые записи, потому что мягкое удаление мимо модели не работает. Читайте через модель или добавьте в драйверный запрос условие по полю `deletedAt`.

**Запись в транзакции не откатилась.** Откат не затронул драйверную запись. Операциям моделей транзакция передаётся сама, а драйверу её нужно передать явно (`{ session: scope.session }`). Если можете, замените драйверную запись операцией модели.

## Полный пример [#full-example]

Скрипт проверки окружения. Он отправляет команду через драйвер, считает документы через модель и закрывает клиент.

```ts twoslash title="scripts/check-environment.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";

@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;
}

await using client = await TypemoClient.connect("mongodb://localhost:27017/app");

// сервер: команда мимо моделей, через драйвер
const info = await client.unsafeDriver().db("admin").command({ buildInfo: 1 });
console.log("MongoDB", String(info.version));

// данные: только через модель, чтобы действовали политики
const total = await client.connection.model(Account).countDocuments();
console.log("accounts:", total);
```

<Callout type="migration">

В Mongoose драйвер достают через `mongoose.connection.getClient()` или `Model.collection`, и такие обращения тоже обходят схемы, валидацию и хуки. В Typemo обход называется `unsafeDriver`, и это метод, а не свойство. Его видно и в месте вызова, и при поиске по коду. А прямого доступа к коллекции драйвера у моделей Typemo нет вовсе — `Model.collection` не существует.

</Callout>
