Пакеты Typemo приносят с собой **скилы** — инструкции для ИИ-агентов, которые пишут код за вас. Агент, прочитавший скил, знает актуальное API Typemo, его строгие правила и типичные ошибки и не пытается писать «как в Mongoose». Скил подключается один раз на проект, и дальше агент сам открывает его, когда задача касается Typemo.

Скил — это папка с файлом `SKILL.md` и справочными файлами `references/*.md`. В `SKILL.md` описано, когда скил применять, какие правила соблюдать и какой справочный файл открыть под задачу. Агент читает только нужный файл, а не всё сразу, поэтому скил не забивает его контекст. Все примеры кода в скилах компилируются: это проверяется так же, как примеры этой документации.

## Что предполагается

Проект, в который уже установлен `@venloc/typemo` (см. [Установка и настройка](./installation.mdx)), и ИИ-агент, умеющий читать файлы проекта.

## Быстрый путь: Claude Code

Claude Code находит скилы проекта в папке `.claude/skills/`. Сделайте в ней ссылку на скил из установленного пакета:

```bash
mkdir -p .claude/skills
ln -s ../../node_modules/@venloc/typemo/skills/typemo .claude/skills/typemo
```

Ссылка, а не копия, нужна для того, чтобы скил обновлялся вместе с пакетом: после `bun update @venloc/typemo` агент читает инструкции той версии, которая установлена.

Если проект на NestJS, добавьте второй скил:

```bash
ln -s ../../node_modules/@venloc/typemo-nestjs/skills/typemo-nestjs .claude/skills/typemo-nestjs
```

Чтобы скилы были доступны во всех ваших проектах, а не в одном, положите те же ссылки в `~/.claude/skills/`. Тогда путь к пакету нужно указать до проекта, в котором он установлен.

## Какие скилы есть

| Скил | Где лежит | Когда агент его применяет |
| --- | --- | --- |
| `typemo` | `node_modules/@venloc/typemo/skills/typemo` | любой код с `@venloc/typemo`: модели, запросы, запись, документы, populate, агрегации, транзакции, хуки, плагины, политики, ошибки, коллекции, тесты |
| `typemo-nestjs` | `node_modules/@venloc/typemo-nestjs/skills/typemo-nestjs` | приложение на NestJS с `@venloc/typemo-nestjs`: модуль, внедрение моделей, `@Transactional`, тенант из запроса, фильтр ошибок, пайпы, тесты |
| `typemo-contributing` | папка `skills/` репозитория Typemo | работа над самим Typemo: правила, команды проверок, виды тестов, правила документации, карта кода |

Скил `typemo-contributing` в пакеты не входит: он нужен только тем, кто меняет код Typemo, и лежит в [репозитории](https://github.com/Venloc-Tech/Typemo/tree/main/skills/typemo-contributing).

## Что внутри скила `typemo`

`SKILL.md` содержит главные правила, которые агенту нельзя нарушать, таблицу «задача → какой файл открыть» и список самопроверки перед сдачей кода. Справочные файлы разбиты по темам:

| Файл | Тема |
| --- | --- |
| `01-setup.md` | установка, `tsconfig`, клиент, подключение, `connection.init()` |
| `02-models.md` | `@Schema`, `@Prop`, типы полей, массивы, Map, вложенные классы, индексы, дискриминаторы |
| `03-reading.md` | `find`, фильтры, проекции, сортировка, keyset, формы результата |
| `04-writing.md` | создание, обновление, конвейеры обновления, замена, удаление, `bulkWrite` |
| `05-documents.md` | гидратированный документ, отслеживание изменений, коллекции документа, сериализация |
| `06-populate.md` | ссылки, `populate`, `HydratedDocWith`, `isPopulated` |
| `07-aggregation.md` | конвейер, `fn.*`, `$lookup`, `$merge`/`$out`, представления |
| `08-transactions-hooks-plugins.md` | транзакции, хуки, плагины, расширения |
| `09-policies-security.md` | тенант, мягкое удаление, аудит, `untrusted`, маски |
| `10-errors.md` | классы ошибок и как их обрабатывать |
| `11-collections-sync.md` | коллекции, индексы, `init()` и `syncAll()` |
| `12-testing-production.md` | тесты на реальной MongoDB и подготовка к продакшену |
| `13-gotchas.md` | типичные ошибки «плохо → хорошо» с точными текстами |
| `14-not-supported.md` | чего нет по сравнению с Mongoose и что писать вместо этого |

## Другие агенты

Агенты, которые не знают формата скилов, всё равно могут им пользоваться: это обычные Markdown-файлы. Укажите путь в файле инструкций агента — например, в `AGENTS.md` в корне проекта:

```md title="AGENTS.md"
Before writing code that uses Typemo, read node_modules/@venloc/typemo/skills/typemo/SKILL.md
and the reference file it points to for the task. For NestJS code, read
node_modules/@venloc/typemo-nestjs/skills/typemo-nestjs/SKILL.md as well.
```

Для Cursor то же самое пишут в правилах проекта, для других агентов — в их файле инструкций.

## Когда это не нужно

Если вы пишете код сами, без агента, скилы вам не нужны: всё, что в них есть, подробнее описано в этой документации. Скилы — сжатая выжимка для машины, а не замена руководствам.

## Частые ошибки

**Скопировали папку скила вместо ссылки.** После обновления пакета агент продолжает читать старые инструкции и предлагает API, которого уже нет или которое изменилось. Замените копию ссылкой из раздела «Быстрый путь».

**Ссылка ведёт в никуда.** Путь в `ln -s` считается от папки, где лежит ссылка, а не от корня проекта: для `.claude/skills/typemo` это `../../node_modules/...`. Проверить можно командой `ls .claude/skills/typemo/SKILL.md`.
