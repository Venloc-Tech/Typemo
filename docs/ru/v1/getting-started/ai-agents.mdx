Пакеты Typemo приносят с собой **скилы** — инструкции для ИИ-агентов, которые пишут код за вас. Прочитав скил, агент знает актуальное API Typemo, его строгие правила и типичные ошибки и не пытается писать «как в Mongoose». Подключите скил один раз на проект, и дальше агент сам откроет его, когда задача коснётся Typemo.

Скил — это папка с файлом `SKILL.md` и справочными файлами `references/*.md`. В `SKILL.md` написано, когда скил применять, каких правил держаться и какой справочный файл открыть под задачу. Агент читает только нужный файл, а не всё сразу, так что контекст не забивается. Все примеры кода в скилах компилируются, это проверяется так же, как примеры этой документации.

## Что понадобится [#prerequisites]

Проект с установленным `@venloc/typemo` (об этом — [Установка и настройка](./installation.mdx)) и ИИ-агент, который умеет читать файлы проекта.

## Быстрый путь в Claude Code [#quick-start-claude-code]

Claude Code ищет скилы проекта в папке `.claude/skills/`. Сделайте в ней ссылку на скил из установленного пакета.

```bash
mkdir -p .claude/skills
ln -s ../../node_modules/@venloc/typemo/skills/typemo .claude/skills/typemo
```

Делайте ссылку, а не копию — тогда скил обновится вместе с пакетом. После `bun update @venloc/typemo` агент будет читать инструкции установленной версии.

Если проект на NestJS, добавьте второй скил.

```bash
ln -s ../../node_modules/@venloc/typemo-nestjs/skills/typemo-nestjs .claude/skills/typemo-nestjs
```

Чтобы скилы работали во всех ваших проектах, а не в одном, положите те же ссылки в `~/.claude/skills/`. Только путь к пакету тогда указывайте до проекта, где он установлен.

## Какие скилы есть [#skills]

| Скил | Где лежит | Когда агент его применяет |
| --- | --- | --- |
| `typemo` | `node_modules/@venloc/typemo/skills/typemo` | любой код с `@venloc/typemo` — модели, запросы, запись, документы, populate, агрегации, транзакции, хуки, плагины, политики, ошибки, коллекции, тесты |
| `typemo-nestjs` | `node_modules/@venloc/typemo-nestjs/skills/typemo-nestjs` | приложение на NestJS с `@venloc/typemo-nestjs` — модуль, внедрение моделей, `@Transactional`, тенант из запроса, фильтр ошибок, пайпы, тесты |
| `typemo-contributing` | папка `skills/` репозитория Typemo | работа над самим Typemo — правила, команды проверок, виды тестов, правила документации, карта кода |

Скила `typemo-contributing` в пакетах нет. Он нужен только тем, кто меняет код самого Typemo, и лежит в [репозитории](https://github.com/Venloc-Tech/Typemo/tree/main/skills/typemo-contributing).

## Что внутри скила `typemo` [#typemo-skill]

В `SKILL.md` собраны главные правила, которые агенту нарушать нельзя, таблица «задача → какой файл открыть» и список самопроверки перед сдачей кода. Справочные файлы разбиты по темам.

| Файл | Тема |
| --- | --- |
| `01-setup.md` | установка, `tsconfig`, клиент, подключение, `connection.init()` |
| `02-models.md` | `@Schema`, `@Prop`, типы полей, массивы, Map, вложенные классы, индексы, дискриминаторы |
| `03-reading.md` | `find`, фильтры, проекции, сортировка, keyset, формы результата |
| `04-writing.md` | создание, обновление, конвейеры обновления, замена, удаление, `bulkWrite` |
| `05-documents.md` | документ, отслеживание изменений, коллекции документа, сериализация |
| `06-populate.md` | ссылки, `populate`, `HydratedDocWith`, `isPopulated` |
| `07-aggregation.md` | конвейер, `fn.*`, `$lookup`, `$merge`/`$out`, представления |
| `08-transactions-hooks-plugins.md` | транзакции, хуки, плагины, расширения |
| `09-policies-security.md` | тенант, мягкое удаление, аудит, `untrusted`, маски |
| `10-errors.md` | классы ошибок и как их обрабатывать |
| `11-collections-sync.md` | коллекции, индексы, `init()` и `syncAll()` |
| `12-testing-production.md` | тесты на реальной MongoDB и подготовка к продакшену |
| `13-gotchas.md` | типичные ошибки «плохо → хорошо» с точными текстами |
| `14-not-supported.md` | чего нет по сравнению с Mongoose и что писать вместо этого |

## Другие агенты [#other-agents]

Агенты, которые не знают формата скилов, всё равно могут ими пользоваться, ведь это обычные файлы Markdown. Укажите путь в файле инструкций агента, например в `AGENTS.md` в корне проекта.

```md title="AGENTS.md"
Before writing code that uses Typemo, read node_modules/@venloc/typemo/skills/typemo/SKILL.md
and the reference file it points to for the task. For NestJS code, read
node_modules/@venloc/typemo-nestjs/skills/typemo-nestjs/SKILL.md as well.
```

Для Cursor то же самое пишут в правилах проекта, для других агентов — в их файле инструкций.

## Когда это не нужно [#when-not-to-use]

Если вы пишете код сами, без агента, скилы вам ни к чему. Всё, что в них есть, подробнее описано в этой документации. Скил — сжатая выжимка для машины, а не замена руководствам.

## Если что-то пошло не так [#troubleshooting]

**Скопировали папку скила вместо ссылки.** После обновления пакета агент читает старые инструкции и предлагает API, которого уже нет или которое изменилось. Замените копию ссылкой, как в разделе «Быстрый путь».

**Ссылка ведёт в никуда.** Путь в `ln -s` считается от папки, где лежит сама ссылка, а не от корня проекта. Для `.claude/skills/typemo` это `../../node_modules/...`. Проверьте командой `ls .claude/skills/typemo/SKILL.md`.
