Соберём маленький блог. Заведём пользователя, напишем от его имени черновик, опубликуем его и прочитаем пост вместе с автором. Всё это поместится в один скрипт.

Пара слов о Typemo, если вы видите его впервые. Это библиотека для **MongoDB** — базы, где данные лежат не строками в таблицах, а документами в коллекциях. Схема в Typemo — это обычный класс TypeScript с декораторами, и из него же компилятор знает типы всех результатов. Отдельных файлов схем и кодогенерации нет.

## Что понадобится [#prerequisites]

MongoDB на `localhost:27017` и [Bun](https://bun.sh). Если база у вас в другом месте, адрес меняется в одной строке. Другие способы установки описаны в [Установке и настройке](./installation.mdx).

<Steps>
<Step>

### 1. Установите пакеты [#install]

Понадобятся ядро, драйвер MongoDB и `bson` (в нём живут типы вроде `ObjectId`). Драйвер и `bson` ставите вы сами, Typemo их с собой не тащит — так в проекте будет ровно одна копия каждого. Компилятор и типы Bun нужны только при разработке.

```package-install
@venloc/typemo mongodb bson
```

```package-install
-D typescript @types/bun
```

</Step>
<Step>

### 2. Настройте `tsconfig.json` [#configure-tsconfig]

Главная строка здесь — `experimentalDecorators: true`. Без неё Bun включит стандартные декораторы, и Typemo откажется запускаться. Остальное — строгий режим компилятора, который мы советуем.

```json title="tsconfig.json"
{
  "compilerOptions": {
    "target": "ESNext",
    "module": "Preserve",
    "moduleResolution": "bundler",
    "strict": true,
    "exactOptionalPropertyTypes": true,
    "noUncheckedIndexedAccess": true,
    "experimentalDecorators": true,
    "noEmit": true,
    "types": ["bun"]
  },
  "include": ["src"]
}
```

`import "reflect-metadata"` и `emitDecoratorMetadata` не нужны. Подробнее про каждый флаг и про стандартные декораторы рассказано в [Установке и настройке](./installation.mdx).

</Step>
<Step>

### 3. Опишите модели [#define-models]

**Модель** — это класс. [`@Schema`](../reference/schemas/schema.mdx#schema) говорит, в какую коллекцию класть документы, [`@Prop`](../reference/schemas/prop.mdx#prop) описывает поле — сначала тип, потом опции. [`Entity`](../reference/schemas/base-classes.mdx#entity) добавляет `_id`, идентификатор документа.

```ts twoslash title="src/models.ts"
import { Entity, Prop, type Ref, Schema, Types } from "@venloc/typemo";

@Schema({ collection: "users" })
export class User extends Entity {
  @Prop(() => String, { required: true })
  name!: string;

  @Prop(() => String, { required: true, unique: true })
  email!: string;
}

@Schema({ collection: "posts" })
export class Post extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Boolean, { required: true })
  published!: boolean;

  @Prop(() => Types.ObjectId, { ref: () => User, required: true })
  author!: Ref<User>;
}
```

`required` делает поле обязательным, а `unique` не даст завести двух пользователей с одним адресом. В `author` пост хранит только `_id` пользователя, а [`Ref<User>`](../reference/schemas/field-markers.mdx#ref) подсказывает компилятору, что на этом месте может оказаться и сам пользователь, если его подгрузить.

</Step>
<Step>

### 4. Подключитесь и запишите данные [#connect-and-write]

[`TypemoClient.connect`](../reference/connection/typemo-client.mdx#typemo-client.connect) подключается к серверу, а базу берёт из конца адреса — здесь это `blog`. Модели достаёте из [`client.connection`](../reference/connection/typemo-client.mdx#client.connection) через [`connection.model`](../reference/connection/connection.mdx#connection.model).

Индексы Typemo сам не создаёт, для этого есть [`connection.init`](../reference/connection/connection.mdx#connection.init). Не забудьте его вызвать, иначе `unique` у адреса ничего не гарантирует.

Записывает документы [`create`](../reference/writes/writes.mdx#create). В `author` поста можно сразу передать `_id` только что созданного пользователя.

```ts twoslash title="src/main.ts"
// @filename: models.ts
import { Entity, Prop, type Ref, Schema, Types } from "@venloc/typemo";

@Schema({ collection: "users" })
export class User extends Entity {
  @Prop(() => String, { required: true })
  name!: string;

  @Prop(() => String, { required: true, unique: true })
  email!: string;
}

@Schema({ collection: "posts" })
export class Post extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Boolean, { required: true })
  published!: boolean;

  @Prop(() => Types.ObjectId, { ref: () => User, required: true })
  author!: Ref<User>;
}
// @filename: main.ts
// ---cut---
import { TypemoClient } from "@venloc/typemo";
import { Post, User } from "./models.ts";

const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Users = client.connection.model(User);
const Posts = client.connection.model(Post);
await client.connection.init();

const alice = await Users.create({ name: "Alice", email: "alice@example.com" });
console.log(alice.name);
// → "Alice"

const post = await Posts.create({ title: "Hello", published: false, author: alice._id });
console.log(post.title, post.published);
// → "Hello" false
```

`create` возвращает **документ**. Он выглядит как экземпляр вашего класса, помнит свои изменения и умеет сохраняться. Подробно об этом — в разделе [Документы](../documents/index.mdx).

</Step>
<Step>

### 5. Прочитайте и обновите [#read-and-update]

[`find`](../reference/query/reading.mdx#model.find) ищет по условию. [`.plain()`](../reference/query/reading.mdx#plain) отдаёт обычные объекты, которые можно сразу отправить клиенту, и `_id` в них уже строка. [`updateOne`](../reference/writes/writes.mdx#update-one) принимает фильтр и изменение — здесь `$set` публикует пост.

Чтобы вместо `_id` получить самого автора, добавьте [`.populate`](../reference/populate/populate.mdx#populate). Если автора к этому времени удалили, в поле окажется `null`. С `required: true` такой случай становится ошибкой, и `null` пропадает из типа. [`.orFail()`](../reference/query/reading.mdx#or-fail) делает то же для самого поста — не нашёлся, значит ошибка.

```ts twoslash title="src/main.ts"
// @filename: models.ts
import { Entity, Prop, type Ref, Schema, Types } from "@venloc/typemo";

@Schema({ collection: "users" })
export class User extends Entity {
  @Prop(() => String, { required: true })
  name!: string;

  @Prop(() => String, { required: true, unique: true })
  email!: string;
}

@Schema({ collection: "posts" })
export class Post extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Boolean, { required: true })
  published!: boolean;

  @Prop(() => Types.ObjectId, { ref: () => User, required: true })
  author!: Ref<User>;
}
// @filename: main.ts
// ---cut---
import { TypemoClient } from "@venloc/typemo";
import { Post, User } from "./models.ts";

const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Users = client.connection.model(User);
const Posts = client.connection.model(Post);
await client.connection.init();

const alice = await Users.create({ name: "Alice", email: "alice@example.com" });
const post = await Posts.create({ title: "Hello", published: false, author: alice._id });

const drafts = await Posts.find({ published: false }).plain(); // [!code ++]
console.log(drafts); // [!code ++]
// → [{ _id: "…", title: "Hello", published: false, author: "…" }]

const result = await Posts.updateOne({ _id: post._id }, { $set: { published: true } }); // [!code ++]
console.log(result.modifiedCount); // [!code ++]
// → 1

const found = await Posts.findOne({ title: "Hello" }).populate({ path: "author", required: true }).orFail().plain(); // [!code ++]
//    ^?
console.log(found.author.name); // [!code ++]
// → "Alice"

await client.close(); // [!code ++]
```

Посмотрите на тип `found`. У `author` есть `name`, потому что вы вызвали `.populate`. Уберите его, и компилятор скажет, что `author` — строка, а у строки `name` нет.

`client.close()` в конце обязателен, иначе открытый клиент не даст скрипту завершиться.

</Step>
<Step>

### 6. Запустите [#run]

```bash
bun run src/main.ts
```

Bun запускает TypeScript, но типы не проверяет. Проверить их без запуска можно командой `bunx tsc -p .`.

</Step>
</Steps>

## Если что-то пошло не так [#troubleshooting]

**Второй запуск падает с `DuplicateKeyError`.** Скрипт снова создаёт Alice с тем же адресом, а уникальный индекс, который создал [`connection.init`](../reference/connection/connection.mdx#connection.init), не пускает дубль.

```text
DuplicateKeyError: duplicate key on email_1: { email: "alice@example.com" } (code 11000 DuplicateKey)
```

Всё работает как задумано. Для повторного запуска удалите базу `blog` или поменяйте адрес. В настоящем приложении [`DuplicateKeyError`](../reference/errors/server-errors.mdx#duplicate-key-error) ловят и отвечают «адрес уже занят» — пример есть в [Первом приложении](./first-app.mdx#register-user).

**`ConfigurationError` про legacy-декоратор.** Bun не увидел `experimentalDecorators: true`. Проверьте `tsconfig.json` и то, что он лежит в папке, откуда вы запускаете Bun, — Bun берёт конфиг из текущей папки.

```text
ConfigurationError: @Prop from "@venloc/typemo" is a legacy decorator, but it was applied as a TC39 decorator (experimentalDecorators is off). Use "@venloc/typemo-decorators" in a TC39 project; the two packages cannot be mixed
```

Если нужны именно стандартные декораторы, читайте [Использовать TC39-декораторы](../decorators-tc39/tc39.mdx).

**`ConnectionError: no server available`.** MongoDB не запущена или адрес неверный. Ошибка приходит не сразу, потому что драйвер ждёт сервер до 30 секунд.

```text
ConnectionError: no server available: connect ECONNREFUSED ::1:27017, connect ECONNREFUSED 127.0.0.1:27017
```

Как правильно создавать клиент в приложении, рассказано в [Подключиться к базе](../connection/connect.mdx).
