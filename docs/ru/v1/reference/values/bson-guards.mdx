`BsonGuards` отвечает на вопрос «что это за значение?» во время работы: `ObjectId`, `UUID`, дата, карта, обычный объект. `BsonTypeTable` — таблица, в которой у каждого типа MongoDB записано, как он выглядит в документе, в lean, в plain и в JSON; из неё строятся и типы, и формы значений. Обе части нужны, когда вы пишете код над значениями, о типе которых компилятор ничего не знает: разбор данных из внешнего источника, собственный сериализатор, функция, которая принимает `unknown`. В обычной работе с моделями они не нужны: приведение типов и формы делает сам Typemo.

Если вам нужно понять, как выглядит значение в каждой форме, прочитайте [Формы значений](./value-forms.mdx). Эта страница — справочник по классам, которые лежат под ними, и по настройкам BSON, которые Typemo фиксирует у клиента.

Элементы на странице: [`BsonGuards`](#bsonguards), [`BsonTypeTag`](#bsontypetag), [`BsonTypeTable`](#bsontypetable) и [`BsonOptions`](#bsonoptions).

## BsonGuards

`BsonGuards` — набор статических проверок значений, которые сужают тип. Главное свойство проверок: они узнают значения BSON по служебной метке, которую ставит пакет `bson`, а не через `instanceof`. Причина в том, что в одном проекте бывает две копии `bson` (в монорепозитории, во вложенной зависимости), их классы разные, а метки одинаковые: `instanceof` от одной копии не узнает значение из другой, а проверка по метке узнает. Встроенные типы (`Date`, `RegExp`, `Map`) проверяются по строковому тегу `Object.prototype.toString` по той же причине: значение может прийти из другого контекста выполнения.

```ts twoslash
import { ObjectId, UUID } from "mongodb";
import { BsonGuards } from "@venloc/typemo";

const describe = (value: unknown): string => {
  if (BsonGuards.isUuid(value)) return `uuid ${value.toHexString(true)}`;
  if (BsonGuards.isObjectId(value)) return `objectId ${value.toHexString()}`;
  if (BsonGuards.isDate(value)) return "date";
  return "other";
};

console.log(describe(new ObjectId("6abcfeb2f9f532dbc77418c1")), describe(new Date()), describe(1));
// → "objectId 6abcfeb2f9f532dbc77418c1" "date" "other"
console.log(describe(new UUID("0f8fad5b-d9cb-469f-a165-70867728950e")));
// → "uuid 0f8fad5b-d9cb-469f-a165-70867728950e"
```

Обратите внимание на порядок проверок: `UUID` в BSON — это двоичное значение особого вида, поэтому `isBinary` для него тоже возвращает `true`, и более узкую проверку `isUuid` нужно ставить раньше.

<Returns type="boolean">

Каждая проверка возвращает `true`, если значение подходит, и сужает тип в ветке `if`. Проверки не бросают ошибок ни на каком входе, включая `null` и `undefined`.

</Returns>

<Params>
<Param name="value" type="unknown" required>

Любое значение. Все проверки принимают его одним аргументом.

</Param>
</Params>

Различие между двумя последними проверкам легко увидеть на примере: экземпляр вашего класса `Foo` для `isPlainObject` — встроенный документ, а для `isPojo` — нет.

```ts twoslash
import { BsonGuards } from "@venloc/typemo";

class Foo {
  a = 1;
}

console.log(BsonGuards.isPlainObject({ a: 1 }), BsonGuards.isPojo({ a: 1 }));
// → true true
console.log(BsonGuards.isPlainObject(new Foo()), BsonGuards.isPojo(new Foo()));
// → true false
console.log(BsonGuards.isPlainObject(new Map()), BsonGuards.isOpaqueValue(new Map()));
// → false true
```

### Когда не подходит

Чтобы проверить, что значение — экземпляр вашей модели, используйте сам класс и `instanceof`: `BsonGuards` не знает ваших классов. Чтобы проверить структуру входных данных (обязательные поля, формат), используйте схему валидации; проверки на этой странице отвечают только на вопрос о типе значения.

## BsonTypeTag

`BsonTypeTag` — объединение имён BSON-классов, которые узнаёт `tagOf`: `"ObjectId"`, `"Binary"`, `"Long"`, `"Decimal128"`, `"Double"`, `"Int32"`, `"Timestamp"`, `"BSONRegExp"`, `"BSONSymbol"`, `"Code"`, `"DBRef"`, `"MinKey"` и `"MaxKey"`. `UUID` отдельного тега не имеет: это `Binary` подтипа 4.

```ts twoslash
import { ObjectId, UUID } from "mongodb";
import { BsonGuards, type BsonTypeTag } from "@venloc/typemo";

const tag: BsonTypeTag | undefined = BsonGuards.tagOf(new ObjectId());
console.log(tag, BsonGuards.tagOf(new UUID()), BsonGuards.tagOf({}));
// → "ObjectId" "Binary" undefined
```

## BsonTypeTable

`BsonTypeTable` — единственная таблица «тип MongoDB ↔ тип TypeScript» на все четыре формы: документ, lean, JSON и plain. Тип и поведение каждой формы берутся из одной строки: строка не может существовать только на стороне типов или только на стороне рантайма, поэтому тип результата не расходится с данными. Класс даёт и данные таблицы, и функции преобразования между формами.

Что получается на разных значениях, показывают вызовы `kindOf` и преобразований:

```ts twoslash
import { ObjectId, UUID } from "mongodb";
import { BsonTypeTable } from "@venloc/typemo";

console.log(BsonTypeTable.kindOf(4), BsonTypeTable.kindOf(4.5), BsonTypeTable.kindOf(4n), BsonTypeTable.kindOf(new UUID()));
// → "int32" "double" "long" "uuid"

const plain = BsonTypeTable.toPlain({ id: new ObjectId("6abd0031bc77f4bc3599f62f"), big: 5n, nested: [1] });
console.log(plain);
// → { id: "6abd0031bc77f4bc3599f62f", big: "5", nested: [1] }

const json = BsonTypeTable.toJson({ big: 5n, re: /a/i, tags: new Map([["a", 1n]]) });
console.log(json);
// → { big: "5", re: "/a/i", tags: { a: "1" } }
```

Параметр `path` — необязательный путь значения в документе; он попадает в текст ошибки, чтобы было видно, где нашлось неподходящее значение.

### Ошибки

Значение, которого нет в таблице (функция, `undefined`, символ, `Set`, «сырые» обёртки `Long`, `Int32` и `Double`, устаревшие `Code`, `DBRef`, `BSONSymbol`), приводит к [`CastError`](../errors/data-errors.mdx#casterror) с причиной `type`. Это верно на любой глубине и для всех трёх преобразований (`toLean`, `toPlain`, `toJson`): ошибка называет путь к значению, а не молчит там, где функцию можно было бы просто пропустить. Текст получен запуском:

```text
CastError: Cast to a value of the BSON type table failed at path "doc" for a function: this value has no row in BsonTypeTable (undefined, a function, a raw Long/Int32/Double or a legacy type) [type]
```

Функция внутри вложенного объекта, массива или Map получает тот же ответ, а в пути видно, где она лежит:

```text
CastError: Cast to a value of the BSON type table failed at path "doc.a.b" for a function: this value has no row in BsonTypeTable (undefined, a function, a raw Long/Int32/Double or a legacy type) [type]
```

`toJson` кроме того отвергает `NaN` и бесконечности, которых нет в JSON: `CastError: Cast to JSON number failed at path "doc.n" for NaN (number): JSON has no NaN or Infinity [json]`. `toPlain` и `toLean` оставляют `NaN` и `Infinity` числами: в JavaScript это обычные числа, и отвергать их нечем. Поэтому plain-данные с `NaN` в `JSON.stringify` превратятся в `null`, а `$toJSON()` честно откажет; если `NaN` у вас возможен, проверьте его до сериализации.

### Когда не подходит

Если вам нужна форма документа модели, вызывайте методы документа ([`$toPlain`](../documents/document-api.mdx#toplain), [`$toJSON`](../documents/document-api.mdx#tojson)) или `.plain()` у запроса: они знают схему (карты, скрытые поля, связи), а `BsonTypeTable` работает с одним значением без схемы.

## BsonOptions

`BsonOptions` хранит настройки BSON, которые Typemo навязывает драйверу, чтобы данные из базы совпадали с таблицей: `int64` всегда `bigint`, двоичные данные остаются `Binary`, регулярные выражения читаются как родные `RegExp`, `undefined` не молчит. Настройки не отключаются: конфликтующее значение — ошибка, а не выбор. Клиент `TypemoClient` применяет их сам; сюда вы приходите, если создаёте драйверный клиент вручную и хотите передать его в Typemo, или проверяете свои опции.

```ts twoslash
import { BsonOptions } from "@venloc/typemo";

console.log(BsonOptions.REQUIRED);
// → { useBigInt64: true, promoteValues: true, promoteLongs: true, promoteBuffers: false, bsonRegExp: false, ignoreUndefined: false, serializeFunctions: false, raw: false, enableUtf8Validation: true }
console.log(BsonOptions.apply({ appName: "app" }));
// → { appName: "app", useBigInt64: true, promoteValues: true, … }
```

Компилятор тоже следит за конфликтами: тип `CompatibleBsonOptions<T>` разрешает обязательному ключу быть только отсутствующим или равным требуемому значению. Во время работы конфликт даёт [`ConfigurationError`](../errors/configuration-errors.mdx#configurationerror):

```text
ConfigurationError: options: BSON options conflict with Typemo — raw: true (required: false)
```

`verify` требует, чтобы каждая настройка была задана явно, поэтому на опциях, которые вы не заполняли, она перечисляет все ключи: `ConfigurationError: users: BSON options conflict with Typemo — useBigInt64: false (required: true), promoteValues: undefined (required: true), …`. Настройка `fieldsAsRaw` не поддерживается вовсе: сырые поля обходят таблицу типов.

Из-за настройки `bsonRegExp: false` регулярные выражения читаются как родные `RegExp`, а у них нет флагов BSON `x`, `l`, `u`, и BSON-флаг `s` возвращается как JavaScript-флаг `g`; поэтому Typemo записывает у регулярного выражения только флаги `i` и `m`.
