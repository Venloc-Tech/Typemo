`BsonGuards` отвечает на вопрос «что это за значение?» во время работы. `ObjectId`, `UUID`, дата, карта или обычный объект. `BsonTypeTable` — таблица, где у каждого типа MongoDB записано, как он выглядит в документе, в результате `.lean()`, в результате `.plain()` и в JSON. Из неё строятся и типы, и формы значений.

Обе части пригодятся, когда вы пишете код над значениями, о типе которых компилятор ничего не знает. Например, разбираете данные из внешнего источника, пишете свой сериализатор или функцию, которая принимает `unknown`. В обычной работе с моделями они не нужны, приведение типов и формы делает сам Typemo.

Как выглядит значение в каждой форме, смотрите в [Формах значений](./value-forms.mdx). Здесь — классы, которые лежат под ними, и настройки BSON, которые Typemo фиксирует у клиента.

Элементы страницы — [`BsonGuards`](#bson-guards), [`BsonTypeTag`](#bson-type-tag), [`BsonTypeTable`](#bson-type-table) и [`BsonOptions`](#bson-options).

## BsonGuards [#bson-guards]

`BsonGuards` — набор статических проверок, которые сужают тип значения. Главное их свойство в том, что значения BSON они узнают по служебной метке пакета `bson`, а не через `instanceof`. В одном проекте бывает две копии `bson`, например в монорепозитории или во вложенной зависимости. Классы у них разные, а метки одинаковые. `instanceof` от одной копии значение из другой не узнает, а проверка по метке узнает. Встроенные типы (`Date`, `RegExp`, `Map`) проверяются по строковому тегу `Object.prototype.toString` по той же причине, значение может прийти из другого контекста выполнения.

```ts twoslash
import { ObjectId, UUID } from "mongodb";
import { BsonGuards } from "@venloc/typemo";

const describe = (value: unknown): string => {
  if (BsonGuards.isUuid(value)) return `uuid ${value.toHexString(true)}`;
  if (BsonGuards.isObjectId(value)) return `objectId ${value.toHexString()}`;
  if (BsonGuards.isDate(value)) return "date";
  return "other";
};

console.log(describe(new ObjectId("6abcfeb2f9f532dbc77418c1")), describe(new Date()), describe(1));
// → "objectId 6abcfeb2f9f532dbc77418c1" "date" "other"
console.log(describe(new UUID("0f8fad5b-d9cb-469f-a165-70867728950e")));
// → "uuid 0f8fad5b-d9cb-469f-a165-70867728950e"
```

Обратите внимание на порядок проверок. `UUID` в BSON — двоичное значение особого вида, поэтому `isBinary` для него тоже вернёт `true`. Более узкую `isUuid` ставьте раньше.

<Returns type="boolean">

Каждая проверка возвращает `true`, если значение подходит, и сужает тип в ветке `if`. Ни на каком входе проверки не бросают ошибок, `null` и `undefined` тоже.

</Returns>

<Params>
<Param name="value" type="unknown" required>

Любое значение. Все проверки принимают его одним аргументом.

</Param>
</Params>

Разницу между двумя последними проверками видно на примере. Экземпляр вашего класса `Foo` для `isPlainObject` — встроенный документ, а для `isPojo` — нет.

```ts twoslash
import { BsonGuards } from "@venloc/typemo";

class Foo {
  a = 1;
}

console.log(BsonGuards.isPlainObject({ a: 1 }), BsonGuards.isPojo({ a: 1 }));
// → true true
console.log(BsonGuards.isPlainObject(new Foo()), BsonGuards.isPojo(new Foo()));
// → true false
console.log(BsonGuards.isPlainObject(new Map()), BsonGuards.isOpaqueValue(new Map()));
// → false true
```

### Когда не подходит [#bson-guards.when-not-to-use]

Чтобы проверить, что значение — экземпляр вашей модели, берите сам класс и `instanceof`. Ваших классов `BsonGuards` не знает. Структуру входных данных (обязательные поля, формат) проверяйте схемой валидации. Проверки на этой странице отвечают только на вопрос о типе значения.

## BsonTypeTag [#bson-type-tag]

`BsonTypeTag` — объединение имён BSON-классов, которые узнаёт `tagOf`. Это `"ObjectId"`, `"Binary"`, `"Long"`, `"Decimal128"`, `"Double"`, `"Int32"`, `"Timestamp"`, `"BSONRegExp"`, `"BSONSymbol"`, `"Code"`, `"DBRef"`, `"MinKey"` и `"MaxKey"`. Отдельного тега у `UUID` нет, это `Binary` подтипа 4.

```ts twoslash
import { ObjectId, UUID } from "mongodb";
import { BsonGuards, type BsonTypeTag } from "@venloc/typemo";

const tag: BsonTypeTag | undefined = BsonGuards.tagOf(new ObjectId());
console.log(tag, BsonGuards.tagOf(new UUID()), BsonGuards.tagOf({}));
// → "ObjectId" "Binary" undefined
```

## BsonTypeTable [#bson-type-table]

`BsonTypeTable` — единственная таблица «тип MongoDB ↔ тип TypeScript» для всех четырёх форм. Документ, результат `.lean()`, JSON и результат `.plain()` берут тип и поведение из одной строки. Строка не может существовать только на стороне типов или только на стороне рантайма, поэтому тип результата не расходится с данными. Класс даёт и данные таблицы, и функции преобразования между формами.

/>

Что получается на разных значениях, показывают вызовы `kindOf` и преобразований.

```ts twoslash
import { ObjectId, UUID } from "mongodb";
import { BsonTypeTable } from "@venloc/typemo";

console.log(BsonTypeTable.kindOf(4), BsonTypeTable.kindOf(4.5), BsonTypeTable.kindOf(4n), BsonTypeTable.kindOf(new UUID()));
// → "int32" "double" "long" "uuid"

const plain = BsonTypeTable.toPlain({ id: new ObjectId("6abd0031bc77f4bc3599f62f"), big: 5n, nested: [1] });
console.log(plain);
// → { id: "6abd0031bc77f4bc3599f62f", big: "5", nested: [1] }

const json = BsonTypeTable.toJson({ big: 5n, re: /a/i, tags: new Map([["a", 1n]]) });
console.log(json);
// → { big: "5", re: "/a/i", tags: { a: "1" } }
```

Параметр `path` необязательный. Это путь значения в документе, он попадает в текст ошибки и показывает, где нашлось неподходящее значение.

### Ошибки [#errors]

У некоторых значений в таблице нет строки. Это функция, `undefined`, символ, `Set`, «сырые» обёртки `Long`, `Int32` и `Double`, устаревшие `Code`, `DBRef`, `BSONSymbol`. На таком значении все три преобразования (`toLean`, `toPlain`, `toJson`) бросают [`CastError`](../errors/data-errors.mdx#cast-error) с причиной `type`, и на любой глубине. Ошибка называет путь к значению, а не молчит там, где функцию можно было бы просто пропустить. Текст взят из реального запуска.

```text
CastError: Cast to a value of the BSON type table failed at path "doc" for a function: this value has no row in BsonTypeTable (undefined, a function, a raw Long/Int32/Double or a legacy type) [type]
```

Функция внутри вложенного объекта, массива или Map получает тот же ответ, а в пути видно, где она лежит.

```text
CastError: Cast to a value of the BSON type table failed at path "doc.a.b" for a function: this value has no row in BsonTypeTable (undefined, a function, a raw Long/Int32/Double or a legacy type) [type]
```

`toJson` отвергает ещё и `NaN` с бесконечностями, которых в JSON нет — `CastError: Cast to JSON number failed at path "doc.n" for NaN (number): JSON has no NaN or Infinity [json]`. `toPlain` и `toLean` оставляют `NaN` и `Infinity` числами. В JavaScript это обычные числа, отвергать их нечем. Поэтому данные из `.plain()` с `NaN` в `JSON.stringify` превратятся в `null`, а `$toJSON()` честно откажет. Если `NaN` у вас возможен, проверьте его до сериализации.

### Когда не подходит [#bson-type-table.when-not-to-use]

Если нужна форма документа модели, вызывайте методы документа ([`$toPlain`](../documents/document-api.mdx#to-plain), [`$toJSON`](../documents/document-api.mdx#to-json)) или `.plain()` у запроса. Они знают схему — карты, скрытые поля, связи. `BsonTypeTable` работает с одним значением и схемы не знает.

## BsonOptions [#bson-options]

`BsonOptions` хранит настройки BSON, которые Typemo навязывает драйверу, чтобы данные из базы совпадали с таблицей. `int64` всегда `bigint`, двоичные данные остаются `Binary`, регулярные выражения читаются как родные `RegExp`, `undefined` не молчит. Настройки не отключаются. Конфликтующее значение — ошибка, а не выбор. `TypemoClient` применяет их сам. Страница пригодится, если вы создаёте драйверный клиент вручную и хотите передать его в Typemo или проверить свои опции.

```ts twoslash
import { BsonOptions } from "@venloc/typemo";

console.log(BsonOptions.REQUIRED);
// → { useBigInt64: true, promoteValues: true, promoteLongs: true, promoteBuffers: false, bsonRegExp: false, ignoreUndefined: false, serializeFunctions: false, raw: false, enableUtf8Validation: true }
console.log(BsonOptions.apply({ appName: "app" }));
// → { appName: "app", useBigInt64: true, promoteValues: true, … }
```

Компилятор тоже следит за конфликтами. Тип `CompatibleBsonOptions<T>` разрешает обязательному ключу быть только отсутствующим или равным требуемому значению. Во время работы конфликт даёт [`ConfigurationError`](../errors/configuration-errors.mdx#configuration-error).

```text
ConfigurationError: options: BSON options conflict with Typemo — raw: true (required: false)
```

`verify` требует явно заданной каждой настройки. На опциях, которые вы не заполняли, она перечисляет все ключи — `ConfigurationError: users: BSON options conflict with Typemo — useBigInt64: false (required: true), promoteValues: undefined (required: true), …`. Настройка `fieldsAsRaw` не поддерживается вовсе, сырые поля обходят таблицу типов.

При `bsonRegExp: false` регулярные выражения читаются как родные `RegExp`. У них нет флагов BSON `x`, `l`, `u`, а BSON-флаг `s` возвращается как JavaScript-флаг `g`. Поэтому Typemo записывает у регулярного выражения только флаги `i` и `m`.
