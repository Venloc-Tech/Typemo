Результат запроса или метода документа имеет не только данные, но и тип, который выводит компилятор. Эта страница описывает публичные типы, из которых такие результаты собраны. `Lean` отвечает за `.lean()`, `Plain` — за `.plain()` и `$toPlain()`, `ObjectForm` — за `$toObject()`, `PlainJson` — за `$toJSON()`. Для входа есть `CreateInput` и `UpdateInput`. У каждого типа формы есть вариант для одного значения — `LeanOf`, `PlainOf`, `ObjectFormOf`, `JsonOf`.

Если вам нужно только понять, чем формы отличаются, прочитайте [Формы значений](./value-forms.mdx). Там таблица по типам MongoDB. Здесь справочник по типам.

Писать эти типы руками обычно не приходится. Результат запроса выводится сам, а нужный тип можно взять из него (`Awaited<ReturnType<typeof f>>`). Прямая запись нужна, когда вы объявляете параметр или тип возврата своей функции.

Примеры используют модель с полями разных типов (она описана на странице [Формы значений](./value-forms.mdx)) и скрытым полем `secret`.

Типы страницы — [`HydratedDoc`](#hydrated-doc), [`Lean`](#lean), [`Plain`](#plain), [`ObjectForm`](#object-form), [`PlainJson`](#plain-json), [варианты для одного значения](#value-types), [`Int64String`](#int64-string), [`CreateInput` и `UpdateInput`](#create-input-update-input) и [вспомогательные типы](#helper-types).

## HydratedDoc [#hydrated-doc]

`HydratedDoc<T>` — тип документа, который вы получаете после обычного чтения. Это экземпляр модели `T` с типизированными коллекциями (массивы, поддокументы, карты) и методами с префиксом `$` (`$save`, `$set`, `$toPlain`). Скрытых полей в нём нет, как нет их и в ответе обычного чтения.

Документ, сделанный из ваших данных, скрытые поля сохраняет. После `create()`, `insertOne()` и `insertMany()` это [`NewDocument<T>`](#new-document), после `new()` — [`UnsavedDocument<T>`](#unsaved-document). Параметр `HydratedDoc<T>` принимает документ из любого из этих мест.

Только у этой формы есть методы, и только она знает, что изменено. Все остальные формы — данные без методов. Тип `Output<T>` — то же самое под другим именем.

```ts twoslash
import { Binary, Decimal128, UUID } from "mongodb";
import { Entity, Prop, Schema, Spec, TypemoClient, Types, type Hidden, type Vector } from "@venloc/typemo";
@Schema({ collection: "readings" })
class Reading extends Entity {
  @Prop(() => String, { required: true }) label!: string;
  @Prop(() => Types.Double) ratio?: number;
  @Prop(() => Types.Int32) count?: number;
  @Prop(() => BigInt) total?: bigint;
  @Prop(() => Types.Decimal128) price?: Decimal128;
  @Prop(() => Boolean) ok?: boolean;
  @Prop(() => Date) at?: Date;
  @Prop(() => Spec.binary({ subtype: 0 })) blob?: Binary;
  @Prop(() => Types.UUID) uid?: UUID;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) vec?: Vector;
  @Prop(() => RegExp) re?: RegExp;
  @Prop(() => Types.Timestamp) ts?: InstanceType<typeof Types.Timestamp>;
  @Prop(() => Spec.map(BigInt)) scores?: Map<string, bigint>;
  @Prop(() => String, { hidden: true }) secret?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "sensors" });
const Readings = client.db().model(Reading);
// ---cut---
import type { HydratedDoc } from "@venloc/typemo";
const save = async (doc: HydratedDoc<Reading>) => {
  doc.label = "renamed";
  await doc.$save();
};
const doc = await Readings.findOne({ label: "r1" }).orFail();
await save(doc);
```

Документ с полями, которые отличаются от обычного чтения, имеет другой тип — [`HydratedDocWith`](#hydrated-doc-with). Параметру `HydratedDoc<Reading>` он не подойдёт. Функции, которой всё равно, загружена ли связь, нужен [`AnyPopulationDoc<T>`](../populate/populate-types.mdx#any-population-doc). Подробнее в руководстве [Убедиться, что связь загружена](../../populate/type-checks.mdx).

## HydratedDocWith [#hydrated-doc-with]

`HydratedDocWith<T, P>` — документ модели `T`, у которого часть полей отличается от обычного чтения. Второй аргумент `P` перечисляет только эти поля в том виде, в каком они читаются. Остальные поля такие же, как у `HydratedDoc<T>`.

Так редактор показывает три случая. Первый — скрытое поле, запрошенное знаком `+` (`HydratedDocWith<Reading, { secret?: string }>`). Второй — связь, загруженная через populate (`HydratedDocWith<Post, { author: HydratedDoc<User> | null }>`). Третий — поле, суженное условием `.where(…).in(…)`.

Методы такого документа работают с полями из `P`. `$set` загруженного поля принимает идентификатор, `$toPlain()` убирает скрытое поле, пока вы не передали `{ hidden: true }`, а `$depopulate()` возвращает документ к `HydratedDoc<T>`.

Если выбрана часть полей, первым аргументом становится сама проекция класса. `Projected<Reading, "_id" | "label">` задаёт список полей, `Omit<Reading, "blob">` — исключение, `Partial<Reading>` — проекцию, состав которой компилятору неизвестен.

```ts twoslash
import { Binary, Decimal128, UUID } from "mongodb";
import { Entity, Prop, Schema, Spec, TypemoClient, Types, type Hidden, type Vector } from "@venloc/typemo";
@Schema({ collection: "readings" })
class Reading extends Entity {
  @Prop(() => String, { required: true }) label!: string;
  @Prop(() => Types.Double) ratio?: number;
  @Prop(() => Types.Int32) count?: number;
  @Prop(() => BigInt) total?: bigint;
  @Prop(() => Types.Decimal128) price?: Decimal128;
  @Prop(() => Boolean) ok?: boolean;
  @Prop(() => Date) at?: Date;
  @Prop(() => Spec.binary({ subtype: 0 })) blob?: Binary;
  @Prop(() => Types.UUID) uid?: UUID;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) vec?: Vector;
  @Prop(() => RegExp) re?: RegExp;
  @Prop(() => Types.Timestamp) ts?: InstanceType<typeof Types.Timestamp>;
  @Prop(() => Spec.map(BigInt)) scores?: Map<string, bigint>;
  @Prop(() => String, { hidden: true }) secret?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "sensors" });
const Readings = client.db().model(Reading);
// ---cut---
const withSecret = await Readings.findOne({ label: "r1" }).select({ "+secret": true }).orFail();
//    ^?
const labels = await Readings.findOne({ label: "r1" }).select({ label: 1 }).orFail();
//    ^?
declare const fields: Record<string, 0 | 1>;
const dynamic = await Readings.findOne({ label: "r1" }).select(fields).orFail();
//    ^?
```

Тип пишут в сигнатуре так же, как он показан в подсказке. Чаще его выводят из запроса — `Awaited<ReturnType<typeof read>>`.

## NewDocument [#new-document]

`NewDocument<T>` — тип документа, который вы сделали сами и записали. Его возвращают [`create`](../writes/writes.mdx#create), [`insertOne`](../writes/writes.mdx#insert-one) и [`insertMany`](../writes/writes.mdx#insert-many), его же получает хук документа.

В отличие от чтения, по дороге ничего не отброшено. Переданные значения лежат в памяти, поэтому скрытые поля в типе есть. У модели со скрытыми полями подсказка показывает `HydratedDocWith<Reading, { secret?: string }>`, у модели без них — просто `HydratedDoc<Reading>`. `$toObject()` скрытые поля включает, `$toPlain()` и `$toJSON()` — нет, как у любого документа.

Документ этого типа подходит везде, где ждут `HydratedDoc<T>`. Имя пригодится в типе результата вашей функции, которая создаёт документ.

```ts twoslash
import { Binary, Decimal128, UUID } from "mongodb";
import { Entity, Prop, Schema, Spec, TypemoClient, Types, type Hidden, type Vector } from "@venloc/typemo";
@Schema({ collection: "readings" })
class Reading extends Entity {
  @Prop(() => String, { required: true }) label!: string;
  @Prop(() => Types.Double) ratio?: number;
  @Prop(() => Types.Int32) count?: number;
  @Prop(() => BigInt) total?: bigint;
  @Prop(() => Types.Decimal128) price?: Decimal128;
  @Prop(() => Boolean) ok?: boolean;
  @Prop(() => Date) at?: Date;
  @Prop(() => Spec.binary({ subtype: 0 })) blob?: Binary;
  @Prop(() => Types.UUID) uid?: UUID;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) vec?: Vector;
  @Prop(() => RegExp) re?: RegExp;
  @Prop(() => Types.Timestamp) ts?: InstanceType<typeof Types.Timestamp>;
  @Prop(() => Spec.map(BigInt)) scores?: Map<string, bigint>;
  @Prop(() => String, { hidden: true }) secret?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "sensors" });
const Readings = client.db().model(Reading);
// ---cut---
import type { NewDocument } from "@venloc/typemo";
const register = async (label: string, secret: string): Promise<NewDocument<Reading>> =>
  Readings.create({ label, secret });
const created = await register("r1", "s1");
//    ^?
console.log(created.secret);
// → "s1"
```

## UnsavedDocument [#unsaved-document]

`UnsavedDocument<T>` — тип документа из [`Model.new`](../documents/model-document-methods.mdx#model.new), который ещё не сохранён. Он совпадает с [`NewDocument<T>`](#new-document), но без значений первой записи. `createdAt` и `updatedAt` (класс `Timestamped`) и `__v` (класс `Versioned`) появляются только при `$save`, поэтому до него они необязательные. `_id` и значения по умолчанию есть сразу.

`$save()` возвращает тот же документ, но типизированный как сохранённый. Эти поля в нём уже обязательные.

```ts twoslash
import { Binary, Decimal128, UUID } from "mongodb";
import { Entity, Prop, Schema, Spec, Timestamped, TypemoClient, Types, type Hidden, type Vector } from "@venloc/typemo";
@Schema({ collection: "readings" })
class Reading extends Timestamped(Entity) {
  @Prop(() => String, { required: true }) label!: string;
  @Prop(() => Types.Double) ratio?: number;
  @Prop(() => Types.Int32) count?: number;
  @Prop(() => BigInt) total?: bigint;
  @Prop(() => Types.Decimal128) price?: Decimal128;
  @Prop(() => Boolean) ok?: boolean;
  @Prop(() => Date) at?: Date;
  @Prop(() => Spec.binary({ subtype: 0 })) blob?: Binary;
  @Prop(() => Types.UUID) uid?: UUID;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) vec?: Vector;
  @Prop(() => RegExp) re?: RegExp;
  @Prop(() => Types.Timestamp) ts?: InstanceType<typeof Types.Timestamp>;
  @Prop(() => Spec.map(BigInt)) scores?: Map<string, bigint>;
  @Prop(() => String, { hidden: true }) secret?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "sensors" });
const Readings = client.db().model(Reading);
// ---cut---
const fresh = Readings.new({ label: "r1" });
const at = fresh.createdAt;
//    ^?
const saved = await fresh.$save();
const savedAt = saved.createdAt;
//    ^?
```

## Lean [#lean]

`Lean<T>` — форма `.lean()`. В ней только данные, виртуальные поля и методы убраны. Типы значений не меняются — `ObjectId`, `bigint`, `Binary`, а карта становится обычным объектом `{ [key: string]: V }`.

Необязательные поля остаются необязательными, маркеры (`Hidden`, `Ref`, `Immutable`) убираются, `_id` — `ObjectId`. Скрытые поля в результате `.lean()` есть, если запрос их выбрал.

```ts twoslash
import { Binary, Decimal128, UUID } from "mongodb";
import { Entity, Prop, Schema, Spec, TypemoClient, Types, type Hidden, type Vector } from "@venloc/typemo";
@Schema({ collection: "readings" })
class Reading extends Entity {
  @Prop(() => String, { required: true }) label!: string;
  @Prop(() => Types.Double) ratio?: number;
  @Prop(() => Types.Int32) count?: number;
  @Prop(() => BigInt) total?: bigint;
  @Prop(() => Types.Decimal128) price?: Decimal128;
  @Prop(() => Boolean) ok?: boolean;
  @Prop(() => Date) at?: Date;
  @Prop(() => Spec.binary({ subtype: 0 })) blob?: Binary;
  @Prop(() => Types.UUID) uid?: UUID;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) vec?: Vector;
  @Prop(() => RegExp) re?: RegExp;
  @Prop(() => Types.Timestamp) ts?: InstanceType<typeof Types.Timestamp>;
  @Prop(() => Spec.map(BigInt)) scores?: Map<string, bigint>;
  @Prop(() => String, { hidden: true }) secret?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "sensors" });
const Readings = client.db().model(Reading);
// ---cut---
import type { Lean } from "@venloc/typemo";
const row: Lean<Reading> = await Readings.findOne({ label: "r1" }).orFail().lean();
//    ^?
```

`LeanOf<V>` — та же форма для одного значения. `LeanOf<Map<string, number>>` даёт `{ [key: string]: number }`. Этот тип вы увидите в подсказке результата `.lean()`.

## Plain [#plain]

`Plain<T, H>` — форма `.plain()` и `$toPlain()`. Идентификаторы, `bigint`, `Decimal128` и `UUID` в ней строки. `Date` и `RegExp` остаются как есть, `Binary` становится `Uint8Array`, вектор — `number[]`, а карта — `Map` со значениями в той же форме.

Второй параметр `H` решает, оставлять ли скрытые поля. В самом типе по умолчанию `true`, а `$toPlain()` и `.plain()` вычисляют его сами. Скрытые поля выпадают, пока вы не передали `{ hidden: true }`.

```ts twoslash
import { Binary, Decimal128, UUID } from "mongodb";
import { Entity, Prop, Schema, Spec, TypemoClient, Types, type Hidden, type Vector } from "@venloc/typemo";
@Schema({ collection: "readings" })
class Reading extends Entity {
  @Prop(() => String, { required: true }) label!: string;
  @Prop(() => Types.Double) ratio?: number;
  @Prop(() => Types.Int32) count?: number;
  @Prop(() => BigInt) total?: bigint;
  @Prop(() => Types.Decimal128) price?: Decimal128;
  @Prop(() => Boolean) ok?: boolean;
  @Prop(() => Date) at?: Date;
  @Prop(() => Spec.binary({ subtype: 0 })) blob?: Binary;
  @Prop(() => Types.UUID) uid?: UUID;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) vec?: Vector;
  @Prop(() => RegExp) re?: RegExp;
  @Prop(() => Types.Timestamp) ts?: InstanceType<typeof Types.Timestamp>;
  @Prop(() => Spec.map(BigInt)) scores?: Map<string, bigint>;
  @Prop(() => String, { hidden: true }) secret?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "sensors" });
const Readings = client.db().model(Reading);
// ---cut---
import type { Plain } from "@venloc/typemo";
const row: Plain<Reading, false> = await Readings.findOne({ label: "r1" }).orFail().plain();
//    ^?
type WithoutHidden = "secret" extends keyof Plain<Reading, false> ? true : false;
//   ^?
type WithHidden = "secret" extends keyof Plain<Reading, true> ? true : false;
//   ^?
```

`PlainOf<V, H>` — то же для одного значения. `PlainOf<ObjectId>` даёт `string`, `PlainOf<Date[]>` — `Date[]`. Опция `hidden` действует на любой глубине — в поддокументах, массивах, картах и загруженных связях.

`.plain()` не отдаёт скрытые поля, даже если запрос выбрал их через `select`. Их покажут `.plain({ hidden: true })` и `.lean()`.

## ObjectForm [#object-form]

`ObjectForm<T, H>` — форма `$toObject()`. Данные те же, что у `Lean`, но карты остаются `Map`, а BSON-значения — как есть. Скрытые поля здесь включены по умолчанию (`H` равно `true`), потому что `$toObject()` отдаёт данные самому приложению. `ObjectFormOf<V, H>` — вариант для одного значения.

```ts twoslash
import { Binary, Decimal128, UUID } from "mongodb";
import { Entity, Prop, Schema, Spec, TypemoClient, Types, type Hidden, type Vector } from "@venloc/typemo";
@Schema({ collection: "readings" })
class Reading extends Entity {
  @Prop(() => String, { required: true }) label!: string;
  @Prop(() => Types.Double) ratio?: number;
  @Prop(() => Types.Int32) count?: number;
  @Prop(() => BigInt) total?: bigint;
  @Prop(() => Types.Decimal128) price?: Decimal128;
  @Prop(() => Boolean) ok?: boolean;
  @Prop(() => Date) at?: Date;
  @Prop(() => Spec.binary({ subtype: 0 })) blob?: Binary;
  @Prop(() => Types.UUID) uid?: UUID;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) vec?: Vector;
  @Prop(() => RegExp) re?: RegExp;
  @Prop(() => Types.Timestamp) ts?: InstanceType<typeof Types.Timestamp>;
  @Prop(() => Spec.map(BigInt)) scores?: Map<string, bigint>;
  @Prop(() => String, { hidden: true }) secret?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "sensors" });
const Readings = client.db().model(Reading);
// ---cut---
import type { ObjectForm } from "@venloc/typemo";
const row: ObjectForm<Reading, true> = (await Readings.findOne({ label: "r1" }).orFail()).$toObject();
//    ^?
```

## PlainJson [#plain-json]

`PlainJson<T, H>` — форма `$toJSON()`. Её же вызывает `JSON.stringify(doc)`. Все значения в ней такие, что JSON выдерживает их без потерь. `Date` — строка, `int64` — десятичная строка, `Binary` — base64, карта — объект.

`JsonOf<V, H>` — вариант для одного значения. `JsonOf<Date>` даёт `string`, `JsonOf<Map<string, ObjectId>>` — `{ [key: string]: string }`.

```ts twoslash
  @Prop(() => Types.Decimal128) price?: Decimal128;
  @Prop(() => Boolean) ok?: boolean;
  @Prop(() => Date) at?: Date;
  @Prop(() => Spec.binary({ subtype: 0 })) blob?: Binary;
  @Prop(() => Types.UUID) uid?: UUID;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) vec?: Vector;
  @Prop(() => RegExp) re?: RegExp;
  @Prop(() => Types.Timestamp) ts?: InstanceType<typeof Types.Timestamp>;
  @Prop(() => Spec.map(BigInt)) scores?: Map<string, bigint>;
  @Prop(() => String, { hidden: true }) secret?: Hidden<string>;
}

//    ^?
```

## Типы одного значения [#value-types]

`LeanOf<V>`, `PlainOf<V, H>`, `ObjectFormOf<V, H>` и `JsonOf<V, H>` принимают тип поля, а не документа, и возвращают его в нужной форме. Они пригодятся, когда вы пишете код над значением поля. Например, функцию, которая принимает идентификатор из результата `.plain()`.

```ts twoslash
import { Binary, Decimal128, UUID } from "mongodb";
import { Entity, Prop, Schema, Spec, TypemoClient, Types, type Hidden, type Vector } from "@venloc/typemo";
@Schema({ collection: "readings" })
class Reading extends Entity {
  @Prop(() => String, { required: true }) label!: string;
  @Prop(() => Types.Double) ratio?: number;
  @Prop(() => Types.Int32) count?: number;
  @Prop(() => BigInt) total?: bigint;
  @Prop(() => Types.Decimal128) price?: Decimal128;
  @Prop(() => Boolean) ok?: boolean;
  @Prop(() => Date) at?: Date;
  @Prop(() => Spec.binary({ subtype: 0 })) blob?: Binary;
  @Prop(() => Types.UUID) uid?: UUID;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) vec?: Vector;
  @Prop(() => RegExp) re?: RegExp;
  @Prop(() => Types.Timestamp) ts?: InstanceType<typeof Types.Timestamp>;
  @Prop(() => Spec.map(BigInt)) scores?: Map<string, bigint>;
  @Prop(() => String, { hidden: true }) secret?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "sensors" });
const Readings = client.db().model(Reading);
// ---cut---
import type { JsonOf, LeanOf, ObjectFormOf, PlainOf } from "@venloc/typemo";
import type { ObjectId } from "mongodb";
type Scores = Map<string, bigint>;
type L = LeanOf<Scores>;
//   ^?
type O = ObjectFormOf<Scores>;
//   ^?
type P = PlainOf<ObjectId>;
//   ^?
type J = JsonOf<Date>;
//   ^?
```

## Int64String [#int64-string]

`Int64String` — тип `` `${bigint}` ``, то есть десятичная запись целого. `.plain()` и `$toJSON()` отдают `int64` строкой, а методы записи принимают её обратно. Значение из результата `.plain()` можно передать в `create` и `updateOne` без приведений. Формат строки проверяет не компилятор, а Typemo во время работы.

```ts twoslash
import { Binary, Decimal128, UUID } from "mongodb";
import { Entity, Prop, Schema, Spec, TypemoClient, Types, type Hidden, type Vector } from "@venloc/typemo";
@Schema({ collection: "readings" })
class Reading extends Entity {
  @Prop(() => String, { required: true }) label!: string;
  @Prop(() => Types.Double) ratio?: number;
  @Prop(() => Types.Int32) count?: number;
  @Prop(() => BigInt) total?: bigint;
  @Prop(() => Types.Decimal128) price?: Decimal128;
  @Prop(() => Boolean) ok?: boolean;
  @Prop(() => Date) at?: Date;
  @Prop(() => Spec.binary({ subtype: 0 })) blob?: Binary;
  @Prop(() => Types.UUID) uid?: UUID;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) vec?: Vector;
  @Prop(() => RegExp) re?: RegExp;
  @Prop(() => Types.Timestamp) ts?: InstanceType<typeof Types.Timestamp>;
  @Prop(() => Spec.map(BigInt)) scores?: Map<string, bigint>;
  @Prop(() => String, { hidden: true }) secret?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "sensors" });
const Readings = client.db().model(Reading);
// ---cut---
const doc = await Readings.findOne({ label: "r1" }).orFail();
const total = doc.$toPlain().total;
if (total !== undefined) await Readings.updateOne({ label: "r1" }, { $set: { total } });
```

Строка, которая не десятичное целое в диапазоне int64, приводит к `CastError`. Какие записи разрешены, написано на странице [Формы значений](./value-forms.mdx#numbers).

## CreateInput и UpdateInput [#create-input-update-input]

`CreateInput<T>` описывает то, что принимают `create`, `insertOne` и `insertMany`. Обязательные поля обязательны. Необязательны поля с `?`, поля со значением по умолчанию (`Defaulted`), поле тенанта и поля-массивы. Массив без `required` и без `default` при создании становится `[]`. Виртуальных полей во входе нет.

Значения принимаются во входной форме. Вместо `ObjectId` можно передать строку, вместо `bigint` — `Int64String`, вместо `Ref<M>` — идентификатор или сам документ, вместо `Map` — `Map` или объект. `undefined` значением не считается, отсутствующее поле просто не пишите.

`UpdateInput<T>` — поля, которые может присвоить запись. Все они необязательны, `_id` и неизменяемых (`Immutable`) среди них нет. `Replacement<T>` — то, что принимают `replaceOne` и `findOneAndReplace`. Это `CreateInput` без `_id` и без служебных полей `createdAt`, `updatedAt` и `__v`, которые ведёт ядро ([`ServiceKeys`](#helper-types)).

```ts twoslash
import { Binary, Decimal128, UUID } from "mongodb";
import { Entity, Prop, Schema, Spec, TypemoClient, Types, type Hidden, type Vector } from "@venloc/typemo";
@Schema({ collection: "readings" })
class Reading extends Entity {
  @Prop(() => String, { required: true }) label!: string;
  @Prop(() => Types.Double) ratio?: number;
  @Prop(() => Types.Int32) count?: number;
  @Prop(() => BigInt) total?: bigint;
  @Prop(() => Types.Decimal128) price?: Decimal128;
  @Prop(() => Boolean) ok?: boolean;
  @Prop(() => Date) at?: Date;
  @Prop(() => Spec.binary({ subtype: 0 })) blob?: Binary;
  @Prop(() => Types.UUID) uid?: UUID;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) vec?: Vector;
  @Prop(() => RegExp) re?: RegExp;
  @Prop(() => Types.Timestamp) ts?: InstanceType<typeof Types.Timestamp>;
  @Prop(() => Spec.map(BigInt)) scores?: Map<string, bigint>;
  @Prop(() => String, { hidden: true }) secret?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "sensors" });
const Readings = client.db().model(Reading);
// ---cut---
import type { CreateInput, Replacement, UpdateInput } from "@venloc/typemo";
const created: CreateInput<Reading> = { label: "r2", total: "9007199254740993" };
//    ^?
const patch: UpdateInput<Reading> = { count: 3 };
//    ^?
const replacement: Replacement<Reading> = { label: "r3" };
//    ^?
void created;
void patch;
void replacement;
```

`total` принимает строку `"9007199254740993"` вместо `bigint`. В `CreateInput` есть необязательный `_id`, а в `UpdateInput` и `Replacement` его нет, потому что записью идентификатор не изменить. `label` — единственное обязательное поле входа, ведь только оно объявлено с `required: true`. Без него компилятор остановит присваивание.

```ts twoslash
// @errors: 2741
```

Компилятор говорит `TS2741: Property 'label' is missing in type '{ count: number; }' but required in type …` и перечисляет поля входа.

`DocOf` в публичном API есть, но относится к агрегациям. Это тип документа источника конвейера без скрытых полей (`DocOf<typeof User>`), а не общее имя формы документа. Он описан в разделе [агрегаций](../aggregation/index.mdx).

## Когда эти типы не нужны [#when-not-to-use]

Если результат запроса используется там же, где выполнен запрос, называть его тип не нужно — он выводится. Если функции нужно принять результат чужого запроса, выведите тип из запроса (`Awaited<ReturnType<typeof f>>`), а не пишите его вручную. Тогда тип не разойдётся с данными.

Для проверки формы ответа при компиляции и во время работы есть [контракты](../query/contracts.mdx).

## Частые ошибки [#common-mistakes]

### Тип plain не подходит там, где ждут JSON [#plain-not-json]

`Plain<T>` — не JSON. В нём остаются `Date`, `Uint8Array` и `Map`. Для значения, которое пойдёт в `JSON.stringify`, берите `PlainJson<T>` и `$toJSON()`.

### Скрытое поле пропало из типа [#hidden-not-in-type]

`Plain<T>` без второго аргумента включает скрытые поля, а `$toPlain()` их убирает. Не записывайте тип переменной вручную как `Plain<T>`, пусть он выведется из вызова. Тогда компилятор сам учтёт `{ hidden: true }`.
