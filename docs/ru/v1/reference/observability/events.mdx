Пока операция идёт, ядро Typemo сообщает о ней **событиями**. Операция началась, закончилась или упала, выполнился шаг, драйвер отправил команду. Событие — обычный объект с полем `type`. Получатель — **подписчик**, объект с функцией `handle`, которого вы регистрируете через [`client.instrument`](../connection/typemo-client.mdx#client.instrument) или [`Typemo.instrument`](../connection/typemo.mdx#typemo.instrument). На этом работают пакеты [OpenTelemetry](./opentelemetry.mdx) и [Sentry](./sentry.mdx), и так же вы пишете собственный журнал или метрики.

Если вы подключаете наблюдаемость впервые, начните с руководства [События операций](../../observability/events.mdx). Эта страница — справочник. Здесь подписчик, все типы событий и правила, по которым значения фильтров попадают в события.

В примерах модель банковского счёта.

```ts twoslash title="accounts/account.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Number, { required: true })
  balance!: number;

  @Prop(() => String, { sensitive: "mask" })
  iban?: string;
}
```

Значения ниже мы получили на настоящей базе. В коллекции один счёт `{ title: "Main", balance: 100, iban: "DE00" }`.

## InstrumentationSubscriber [#instrumentation-subscriber]

`InstrumentationSubscriber` — то, что вы передаёте в `instrument`. Это объект с обязательной функцией `handle` и настройками, которые говорят ядру, какие события и в каком виде вам нужны. Ядро строит событие, только когда есть кому его получить. Без подписчиков наблюдаемость ничего не стоит, а событие, которое не запросил ни один подписчик (например, шаги, когда `steps: false` у всех), не создаётся вовсе.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";

@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank" });
const Accounts = client.db().model(Account);
// ---cut---
const subscription = client.instrument({
  handle: (event) => {
    if (event.type === "operation.end") {
      console.log(`${event.model ?? event.database}.${event.operation}: ${event.documentCount} шт.`);
    }
  },
});

await Accounts.find({ balance: { $gt: 50 } }).plain();
// → "Account.find: 1 шт."

subscription.unsubscribe();
```

`handle` получает событие из объединения [`InstrumentationEvent`](#instrumentation-event). По полю `type` TypeScript сужает его до нужного типа, поэтому внутри `if` доступны `documentCount` и `durationMS`.

<Returns type="void">

`handle` ничего не возвращает. Исключение из `handle` операцию не ломает. Ядро ловит его и пишет в `console.error` строку вида `[typemo] an instrumentation subscriber threw on "operation.start":` и саму ошибку. Наблюдатель не должен ронять то, за чем наблюдает, но и о своей поломке молчать ему нельзя.

</Returns>

<Params title="Поля подписчика">
<Param name="handle" type="(event: InstrumentationEvent) => void" required>

Получает каждое событие, которое просил подписчик. Исключений бросать не должен и ничего ждать тоже. Он выполняется на пути операции, и медленный `handle` её замедляет.

</Param>
<Param name="sensitive" type="SubscriberSensitive" default={'"mask"'}>

Как значения фильтров, обновлений и ошибок выглядят в событиях этого подписчика. Подробности в разделе [`SubscriberSensitive`](#subscriber-sensitive).

</Param>
<Param name="driverCommands" type="boolean" default="false">

Включает события команд драйвера `driver.command.*`, связанные с отправившей их операцией. Клиент должен быть создан с опцией `monitorCommands: true`, иначе `client.instrument` бросит `ConfigurationError: TypemoClient "default": driver command events need the client option monitorCommands: true`. Опция клиента описана в [опциях клиента](../connection/typemo-client.mdx#client-options).

</Param>
<Param name="poolEvents" type="boolean" default="false">

Включает события пула соединений драйвера `driver.pool`.

</Param>
<Param name="steps" type="boolean" default="true">

Включает вложенные события шагов `operation.step`. Если у каждого подписчика клиента `steps: false`, события шагов не создаются вообще. С `steps: false` операция `find` дала только `operation.start` и `operation.end`.

</Param>
<Param name="includeTenant" type="boolean" default="false">

Кладёт тенанта операции в `OperationInfo.tenant`. По умолчанию его нет, потому что тенант — данные пользователей, а события уходят в чужие системы.

</Param>
<Param name="wrap" type="(operation: OperationInfo, run: () => Promise<void>) => Promise<unknown>">

Функция, внутри которой ядро выполняет операцию. Она нужна интеграциям, которым надо сделать свой контекст активным для всего, что операция запускает, то есть для хуков, вложенных запросов подгрузки связей и команд драйвера. OpenTelemetry так делает спан операции родителем всех вложенных спанов. Ядро вызывает `wrap` только у подписчиков, которые его задали.

Договор такой. Вызовите `run` ровно один раз и верните то, что она вернёт. Результат операции всегда определяет `run`, что бы ни вернула `wrap`. Если `wrap` бросила исключение до вызова `run` или вовсе её не вызвала, это сообщается как ошибка `handle`, а операция всё равно выполняется. Несколько `wrap` вкладываются друг в друга в порядке регистрации. Подписчики клиента идут раньше глобальных, а первый зарегистрированный оказывается снаружи. Для курсора `wrap` охватывает только открытие, до первого запроса пачки.

`wrap`, который пишет в журнал до и после `run`, дал порядок `wrap:in find > operation.start > operation.end > wrap:out`.

</Param>
</Params>

<Callout type="warning">

`handle` не должен менять события и хранить `event.schema`. Это ссылка на схему модели, а не копия, и сериализовать событие целиком (`JSON.stringify(event)`) нельзя.

</Callout>

### Ошибки регистрации [#registration-errors]

`instrument` проверяет подписчика сразу и бросает `ConfigurationError`.

| Что не так | Текст |
|---|---|
| нет функции `handle` | `an instrumentation subscriber is an object { handle(event) }` |
| `sensitive` не из списка | `the sensitive option of an instrumentation subscriber is "mask", "show", "hide" or { mask: (value, { path }) => json }` |
| `wrap` не функция | `an instrumentation subscriber's wrap must be a (operation, run) => Promise callback` |
| `driverCommands: true` без `monitorCommands` | `TypemoClient "default": driver command events need the client option monitorCommands: true` |

Первая, вторая и третья строки одинаковы для `Typemo.instrument`. Четвёртая бывает только у клиента.

### Когда подписчик не подходит [#when-not-to-use]

Подписчик только наблюдает, изменить операцию (добавить условие, отклонить запрос) он не поможет. Для этого есть хуки, [`@Pre`](../hooks/pre-post.mdx#pre) и [`.modify`](../hooks/operation-context.mdx#modify). Для трассировки и Sentry не пишите подписчика с нуля, берите готовые [`@venloc/typemo-opentelemetry`](./opentelemetry.mdx) и [`@venloc/typemo-sentry`](./sentry.mdx).

<FullType>

```ts
interface InstrumentationSubscriber {
  readonly handle: (event: InstrumentationEvent) => void;
  readonly sensitive?: SubscriberSensitive;
  readonly driverCommands?: boolean;
  readonly poolEvents?: boolean;
  readonly steps?: boolean;
  readonly includeTenant?: boolean;
  readonly wrap?: (operation: OperationInfo, run: () => Promise<void>) => Promise<unknown>;
}
```

</FullType>

## SubscriberSensitive [#subscriber-sensitive]

`SubscriberSensitive` — способ показать значения в событиях. Фильтр `{ balance: { $gt: 50 }, title: "Main" }` содержит данные пользователей, а события уходят в системы трассировки, журналы и трекеры ошибок. Поэтому по умолчанию ядро оставляет в событии только **форму** запроса. Ключи и операторы остаются, значения заменяются на `"?"`. Более открытый режим подписчик выбирает явно, и это решение об утечке данных, а не настройка удобства.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";

@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => String, { sensitive: "mask" }) iban?: string;
}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank" });
const Accounts = client.db().model(Account);
// ---cut---
client.instrument({
  sensitive: "show",
  handle: (event) => {
    if (event.type === "operation.start") console.log(JSON.stringify(event.summary.filter));
  },
});

await Accounts.find({ balance: { $gt: 50 }, iban: "DE00", title: "Main" }).plain();
// → {"balance":{"$gt":50},"iban":"?","title":"Main"}
```

У поля `iban` значения остались `"?"`, хотя режим `"show"`. В схеме у поля задан `sensitive: "mask"`, а метка схемы сильнее выбора подписчика. Пометка поля действует во всех подписчиках, и в чужих, которые вы не писали, тоже.

<TypeTable
  type={{
    '"mask"': { description: "По умолчанию. Каждое непомеченное значение становится `\"?\"`, форма запроса остаётся, `{ balance: { $gt: \"?\" }, title: \"?\" }`.", type: "string" },
    '"show"': { description: "Настоящие (уже приведённые к типу) значения непомеченных полей. Только явным выбором, события тогда содержат данные пользователей.", type: "string" },
    '"hide"': { description: "Всё условие непомеченного поля целиком заменяется на `\"[hidden]\"`. Ключ остаётся, операторы не видны. Для `{ balance: { $gt: 50 } }` получится `{ balance: \"[hidden]\" }`.", type: "string" },
    "{ mask }": { description: "Каждое непомеченное значение проходит через вашу функцию `(value, { path }) => json`, где `path` — путь поля в базе (пустая строка вне полей). Исключение из `mask` даёт `\"?\"` и событие `instrumentation.error`.", type: "{ readonly mask: (value: unknown, context: { readonly path: string }) => SensitiveJson }" },
  }}
/>

С тем же фильтром и `sensitive: "hide"` получилось `{"balance":"[hidden]","iban":"?","title":"[hidden]"}`, у `iban` своя метка. С `{ mask: (v, { path }) => path === "title" ? "T" : "?" }` получилось `{"balance":{"$gt":"?"},"title":"T"}`.

Режим действует не только на `summary`, но и на команды драйвера в событиях `driver.command.started`, и на ошибку в `error` и `failure`. `CastError` из `updateOne` с `balance: "abc"` пришёл вызвавшему коду с текстом `Cast to number failed at path "$set.balance" for "abc" (string): expected a number [type]`, а в событии `operation.error` — с `for "?"`. Помеченные `sensitive` и скрытые (`Hidden`) поля не попадают в событие ни в каком режиме. Об этих пометках читайте в руководстве [Скрытые и чувствительные поля](../../schemas/hidden-and-sensitive.mdx).

<FullType>

```ts
type SubscriberSensitive =
  | "mask"
  | "show"
  | "hide"
  | { readonly mask: (value: unknown, context: { readonly path: string }) => SensitiveJson };
```

</FullType>

## Subscription [#subscription]

`Subscription` — то, что возвращает `instrument`, регистрация подписчика. С ней можно перестать получать события, в тестах, при остановке приложения, при смене конфигурации.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank" });
// ---cut---
{
  using subscription = client.instrument({ handle: (event) => console.log(event.type) });
  // события приходят, пока идёт этот блок
}
// здесь подписка уже снята
```

<Params title="Поля">
<Param name="unsubscribe" type="() => void" required>

Снимает регистрацию. После вызова `handle` больше не вызывается. Повторный вызов безопасен.

</Param>
<Param name="[Symbol.dispose]" type="() => void" required>

Делает то же самое, когда подписка выходит из области `using`. Внутри блока `using` `handle` получал события операции, а `find` после блока — уже нет.

</Param>
</Params>

<FullType>

```ts
interface Subscription {
  readonly unsubscribe: () => void;
  readonly [Symbol.dispose]: () => void;
}
```

</FullType>

## InstrumentationEvent [#instrumentation-event]

`InstrumentationEvent` — объединение всех событий. Они различаются по полю `type`, поэтому `switch (event.type)` даёт в каждой ветке точный тип с его полями. Строковые значения `type` собраны в тип `InstrumentationEventType`.

```ts twoslash
import type { InstrumentationEvent } from "@venloc/typemo";
// ---cut---
const describe = (event: InstrumentationEvent): string => {
  switch (event.type) {
    case "operation.start":
      return `${event.operation} начата`;
    case "operation.end":
      return `${event.operation}: ${event.durationMS} мс`;
    case "operation.error":
      return `${event.operation} упала на шаге ${event.failedStep}`;
    default:
      return event.type;
  }
};
```

Порядок событий такой. У операции сначала `operation.start`, затем вложенные `operation.step`, `driver.command.started` и `driver.command.succeeded` (если подписчик их просил) и в конце `operation.end` или `operation.error`. У курсора между началом и концом добавляются `cursor.batch`. У транзакции идут `transaction.start`, события её операций, затем `transaction.commit` или `transaction.abort`, а при повторе между ними `transaction.retry`. События пула `driver.pool` приходят независимо от операций.

## InstrumentationEventType [#instrumentation-event-type]

`InstrumentationEventType` — тип поля `type` у любого события, объединение строк из таблицы выше. Он пригодится, когда вы храните набор интересующих вас типов.

```ts twoslash
import type { InstrumentationEventType } from "@venloc/typemo";
// ---cut---
const interesting = new Set<InstrumentationEventType>(["operation.end", "operation.error"]);
```

## OperationInfo [#operation-info]

`OperationInfo` — общая часть трёх событий операции, их поля наследуют её. В ней всё, что нужно, чтобы понять, какая это операция и где она идёт, то есть имя, модель, коллекция, база, клиент, транзакция, сервер. Поля `operationId` и `parentId` связывают события одной операции и вложенных в неё запросов подгрузки связей. По ним интеграции строят вложенные спаны.

У операции уровня базы ([`connection.aggregate`](../connection/connection.mdx#connection.aggregate), [`client.aggregate`](../connection/typemo-client.mdx#client.aggregate)) модели нет, поэтому три поля могут быть `null` — `model`, `collection` и `schema`. Коллекция `null` и у агрегации всей базы или `admin`. У `Pipeline.sessions()` она равна `"system.sessions"`. Подписчик, который собирает подпись из этих полей, должен проверять `null`, тип его к этому вынудит.

Тот же тип описан со стороны хуков на странице [`OperationInfo` в контексте хука](../hooks/operation-context.mdx#operation-info). Имя операции — [`OperationName`](../hooks/operation-context.mdx#operation-name).

```ts twoslash
import type { OperationInfo } from "@venloc/typemo";
// ---cut---
const label = (info: OperationInfo): string =>
  `${info.connection}/${info.database}.${info.collection ?? "*"} ${info.operation}` +
  (info.populatePath === undefined ? "" : ` (populate ${info.populatePath})`);
// для find по счетам: "default/bank.accounts find"; для агрегации всей базы: "default/bank.* aggregate"
```

## OperationSummary [#operation-summary]

`OperationSummary` — форма входа операции для события `operation.start`. Это фильтр, обновление, конвейер, проекция, сортировка и число документов. Значения в ней заменены по правилам [`SubscriberSensitive`](#subscriber-sensitive), в режиме по умолчанию это `"?"`. Формат заимствован у `db.query.summary` OpenTelemetry. Ключи и операторы остаются, данные нет. По трассе видно, какой был запрос, но не чей.

```ts twoslash
import type { OperationSummary } from "@venloc/typemo";
// ---cut---
const summary: OperationSummary = { filter: { balance: { $gt: "?" } }, sort: { balance: 1 } };
```

Для `Accounts.find({ balance: { $gt: 50 }, iban: "DE00" })` сводка вышла `{"filter":{"balance":{"$gt":"?"},"iban":"?"}}`, а для `Accounts.create(...)` — `{"count":1}`.

## OperationStartEvent [#operation-start-event]

`OperationStartEvent` приходит первым событием операции, ещё до приведения типов, проверки и `pre`-хуков. По нему открывают спан или запоминают время начала. События шагов подготовки (`cast`, `validate`, хуки `@Pre`) доставляются после него. `create` дал порядок `operation.start`, `operation.step` (`cast`), `operation.step` (`validate`), `driver.command.started`. Поэтому `operation.start` есть и у операции, которая упала на приведении или проверке и до драйвера не дошла.

```ts twoslash
import type { OperationStartEvent } from "@venloc/typemo";
// ---cut---
const onStart = (event: OperationStartEvent): void => {
  console.log(event.type, event.operation, JSON.stringify(event.summary.filter));
};
// для find: "operation.start find {"balance":{"$gt":"?"}}"
```

Кроме полей [`OperationInfo`](#operation-info) у него три поля.

<Params title="Поля">
<Param name="type" type={'"operation.start"'} required>

Признак события.

</Param>
<Param name="timestamp" type="number" required>

Когда произошло событие, в миллисекундах с начала эпохи, как `Date.now()`.

</Param>
<Param name="summary" type="OperationSummary" required>

Форма входа операции. Считается при первом чтении и запоминается, так что подписчик, который `summary` не читает, за него не платит. Если функция `mask` подписчика падает при этом чтении, приходит событие [`instrumentation.error`](#instrumentation-error-event).

</Param>
</Params>

`operation.start` приходит и у операции, которая упадёт на приведении типов. `updateOne` с `$set.balance: "abc"` дал `operation.start` и следом `operation.error` с `failedStep: "cast"`, без единой команды драйвера.

## OperationEndEvent [#operation-end-event]

`OperationEndEvent` приходит, когда операция успешно закончилась. У курсора это момент, когда он исчерпан или закрыт, а не открыт. По событию считают длительность и число документов.

```ts twoslash
import type { OperationEndEvent } from "@venloc/typemo";
// ---cut---
const onEnd = (event: OperationEndEvent): void => {
  console.log(`${event.operation}: ${event.durationMS.toFixed(1)} мс, документов: ${event.documentCount}`);
};
// → "find: 2.3 мс, документов: 1"
```

<Params title="Поля">
<Param name="type" type={'"operation.end"'} required>

Признак события.

</Param>
<Param name="timestamp" type="number" required>

Когда произошло событие, в миллисекундах эпохи.

</Param>
<Param name="durationMS" type="number" required>

Сколько длилась операция, в миллисекундах, дробное число.

</Param>
<Param name="documentCount" type="number | undefined" required>

Сколько документов вернуто, записано или затронуто, если это известно, иначе `undefined`. Для `create` одного документа это `1`.

</Param>
</Params>

## OperationErrorEvent [#operation-error-event]

`OperationErrorEvent` приходит вместо `operation.end`, когда операция упала на каком-то шаге. Название шага в `failedStep` показывает, где именно. `cast` — приведение типов, `validate` — проверка, `execute` — вызов драйвера, `postProcess` — шаг после него, например `.orFail()` на пустом результате.

```ts twoslash
import type { OperationErrorEvent } from "@venloc/typemo";
// ---cut---
const onError = (event: OperationErrorEvent): void => {
  const { kind, name, retryable } = event.classification;
  console.error(`${event.operation}: ${name} (${kind}), шаг ${event.failedStep}, повтор ${retryable}`);
};
// → "find: DocumentNotFoundError (not-found), шаг postProcess, повтор false"
```

<Params title="Поля">
<Param name="type" type={'"operation.error"'} required>

Признак события.

</Param>
<Param name="timestamp" type="number" required>

Когда произошло событие, в миллисекундах эпохи.

</Param>
<Param name="durationMS" type="number" required>

Сколько операция работала до ошибки.

</Param>
<Param name="failedStep" type="StepName | undefined" required>

Шаг, на котором операция упала, если он известен. Это имена шагов конвейера операции — `resolveContext`, `validateOptions`, `normalize`, `resolvePaths`, `cast`, `policies`, `defaults`, `validate`, `hooksPre`, `instrumentStart`, `execute`, `postProcess`, `populate`, `audit`, `hooksPost`, `instrumentEnd`.

</Param>
<Param name="error" type="unknown" required>

Ошибка в том виде, в каком её получил вызвавший код. Это ошибка Typemo или ваша собственная ошибка из хука. Она прошла маскировку по `sensitive` подписчика. При `"mask"` значения непомеченных полей в `CastError`, `ValidationError`, `DuplicateKeyError` и `ServerValidationError` заменены на `"?"`, а значения помеченных и скрытых полей в неё не попадают никогда. Вызвавший код получает исходную ошибку с настоящими значениями.

</Param>
<Param name="classification" type="ErrorClassification" required>

Вид сбоя. В `kind` лежит `validation`, `cast`, `not-found`, `duplicate-key`, `timeout`, `connection`, `server` или другой вид. `name` — имя класса ошибки, `code` — код ошибки сервера, `errorLabels` — метки, `retryable` — имеет ли смысл повторить, `transient` — можно ли повторить всю транзакцию. Для `.orFail()` на пустом результате пришло `{ kind: "not-found", name: "DocumentNotFoundError", errorLabels: [], retryable: false, transient: false }`, а для строки `"abc"` в числовом поле — `{ kind: "cast", name: "CastError", … }`.

</Param>
</Params>

## StepEvent [#step-event]

`StepEvent` — завершение вложенного шага операции. Он помогает понять, куда ушло время, в приведение типов, проверку, хуки или подгрузку связей. События шагов идут по одному на шаг, уже после его окончания, и несут длительность.

```ts twoslash
import type { StepEvent } from "@venloc/typemo";
// ---cut---
const onStep = (event: StepEvent): void => {
  console.log(event.operationId, event.step, event.durationMS);
};
```

Для `find` модели с хуками `@Pre` и `@Post` шаги пришли в порядке `cast`, `validate`, `hooksPre`, `populate`, `hooksPost`. У модели без хуков `hooksPre` и `hooksPost` нет, остались `cast`, `validate`, `populate`.

<Params title="Поля">
<Param name="type" type={'"operation.step"'} required>

Признак события.

</Param>
<Param name="operationId" type="number" required>

Операция, к которой относится шаг. Остальных полей [`OperationInfo`](#operation-info) у шага нет, берите их из события `operation.start` по этому номеру.

</Param>
<Param name="step" type="StepName" required>

Имя шага — `cast`, `validate`, `hooksPre`, `hooksPost`, `populate`.

</Param>
<Param name="timestamp" type="number" required>

Когда шаг закончился, в миллисекундах эпохи.

</Param>
<Param name="durationMS" type="number" required>

Сколько шаг длился.

</Param>
</Params>

## CursorBatchEvent [#cursor-batch-event]

`CursorBatchEvent` — очередная пачка документов, которую получил курсор. С ним видно, как долго и порциями какого размера читается большая выгрузка.

```ts twoslash
import type { CursorBatchEvent } from "@venloc/typemo";
// ---cut---
const onBatch = (event: CursorBatchEvent): void => {
  console.log(`пачка ${event.batch}: ${event.size} документов`);
};
// → "пачка 0: 2 документа"
```

<Params title="Поля">
<Param name="type" type={'"cursor.batch"'} required>

Признак события.

</Param>
<Param name="operationId" type="number" required>

Операция, которой принадлежит курсор.

</Param>
<Param name="timestamp" type="number" required>

Когда пачка получена, в миллисекундах эпохи.

</Param>
<Param name="batch" type="number" required>

Номер пачки, первая — `0`.

</Param>
<Param name="size" type="number" required>

Сколько документов в пачке. При двух документах в коллекции пришла одна пачка `{ batch: 0, size: 2 }`.

</Param>
</Params>

О курсорах читайте в [руководстве](../../queries/large-results.mdx).

## TransactionEvent [#transaction-event]

`TransactionEvent` описывает жизнь [`client.transaction`](../connection/typemo-client.mdx#client.transaction) — начало, повтор, фиксацию и откат. Он показывает, какие транзакции повторялись и почему.

```ts twoslash
import type { TransactionEvent } from "@venloc/typemo";
// ---cut---
const onTransaction = (event: TransactionEvent): void => {
  if (event.type === "transaction.abort") console.warn("откат", event.transactionId, event.error);
};
```

Обычная транзакция даёт `transaction.start` и `transaction.commit`. Транзакция, упавшая с ошибкой, даёт `transaction.start` и `transaction.abort`. `abort` пришёл с `error`, исходным `Error("nope")`, и длительностью в миллисекундах. Если драйвер повторяет транзакцию из-за временной ошибки, между ними добавляется `transaction.retry`.

<Params title="Поля">
<Param name="type" type={'"transaction.start" | "transaction.commit" | "transaction.abort" | "transaction.retry"'} required>

Признак события.

</Param>
<Param name="transactionId" type="number" required>

Уникальный в процессе номер транзакции. Тот же номер стоит в `OperationInfo.transactionId` у операций внутри неё.

</Param>
<Param name="timestamp" type="number" required>

Когда произошло событие, в миллисекундах эпохи.

</Param>
<Param name="attempt" type="number" required>

Номер попытки, первая — `1`.

</Param>
<Param name="connection" type="string" required>

Имя клиента.

</Param>
<Param name="durationMS" type="number | undefined" required>

Сколько прошло с `transaction.start`. Есть у `commit` и `abort`.

</Param>
<Param name="error" type="unknown" required>

Ошибка, из-за которой транзакция откатилась или повторяется. Маскируется по правилам [`SubscriberSensitive`](#subscriber-sensitive). У `start` и `commit` это `undefined`.

</Param>
</Params>

О транзакциях читайте в [руководстве](../../transactions/transactions.mdx).

## DriverCommandEvent [#driver-command-event]

`DriverCommandEvent` — команда, которую драйвер отправил серверу. Он нужен, когда одной операции Typemo мало, например чтобы увидеть сервер, выполнивший команду, или отдельное время команды. С операцией событие связано по `operationId`. Подписчик получает такие события только при `driverCommands: true`, а клиент должен быть создан с `monitorCommands: true`.

```ts twoslash
import type { DriverCommandEvent } from "@venloc/typemo";
// ---cut---
const onCommand = (event: DriverCommandEvent): void => {
  if (event.type === "driver.command.succeeded") {
    console.log(`${event.commandName} на ${event.address}: ${event.durationMS} мс`);
  }
};
// → "find на 127.0.0.1:27017: 1 мс"
```

<Params title="Поля">
<Param name="type" type={'"driver.command.started" | "driver.command.succeeded" | "driver.command.failed"'} required>

Начало, успех или сбой команды.

</Param>
<Param name="operationId" type="number | undefined" required>

Операция Typemo, которая отправила команду. `undefined` у команд, которых Typemo не отправлял, то есть служебных команд драйвера и вашего кода, работающего с драйвером напрямую.

</Param>
<Param name="requestId" type="number" required>

Номер запроса в драйвере. Связывает `started` с `succeeded` или `failed`.

</Param>
<Param name="commandName" type="string" required>

Имя команды сервера, например `find`, `insert`, `update`.

</Param>
<Param name="databaseName" type="string" required>

База, к которой обращена команда.

</Param>
<Param name="address" type="string" required>

`хост:порт` сервера, выполнившего команду.

</Param>
<Param name="timestamp" type="number" required>

Когда произошло событие, в миллисекундах эпохи.

</Param>
<Param name="durationMS" type="number | undefined" required>

Длительность команды у `succeeded` и `failed`.

</Param>
<Param name="command" type="unknown" required>

Сама команда, замаскированная так же, как [`OperationSummary`](#operation-summary). Есть только у `started`. Мы получили `{"find":"accounts","filter":{"title":"?"},"lsid":{…},"$db":"bank"}`. Значения фильтра заменены, а служебные поля драйвера (`lsid`, `$clusterTime`) остались.

</Param>
<Param name="failure" type="unknown" required>

Ошибка сервера у `failed`, замаскированная.

</Param>
</Params>

## PoolEvent [#pool-event]

`PoolEvent` — событие пула соединений драйвера (CMAP). Оно нужно для метрик пула, сколько соединений занято и сколько ждут. Подписчик получает его при `poolEvents: true`.

```ts twoslash
import type { PoolEvent } from "@venloc/typemo";
// ---cut---
const onPool = (event: PoolEvent): void => {
  console.log(event.name, event.address);
};
// → "connectionCheckedOut 127.0.0.1:27017"
```

<Params title="Поля">
<Param name="type" type={'"driver.pool"'} required>

Признак события.

</Param>
<Param name="name" type="string" required>

Имя события драйвера — `connectionCheckOutStarted`, `connectionCheckedOut`, `connectionCheckedIn`, `connectionPoolCleared` и другие. Один `find` дал `connectionCheckOutStarted`, `connectionCheckedOut`, `connectionCheckedIn`.

</Param>
<Param name="address" type="string" required>

`хост:порт` сервера, которому принадлежит пул.

</Param>
<Param name="timestamp" type="number" required>

Когда произошло событие, в миллисекундах эпохи.

</Param>
<Param name="event" type="unknown" required>

Объект события драйвера как есть (`time`, `address`, `name` и так далее). Данных пользователей в событиях пула нет.

</Param>
</Params>

## InstrumentationErrorEvent [#instrumentation-error-event]

`InstrumentationErrorEvent` сообщает о сбое самой наблюдаемости, который не остановил операцию. Ваша функция `mask` из [`SubscriberSensitive`](#subscriber-sensitive) бросила исключение при подготовке значения. Значение вместо этого стало `"?"`, а о поломке подписчик узнаёт из события, а не из текста, потерянного в консоли.

```ts twoslash
import type { InstrumentationErrorEvent } from "@venloc/typemo";
// ---cut---
const onFailure = (event: InstrumentationErrorEvent): void => {
  console.warn(`маска для ${event.model}.${event.path} упала: ${String(event.error)}`);
};
```

`mask`, которая бросает на пути `title`, дала событие `{ source: "sensitive-mask", model: "Account", path: "title" }` с ошибкой `the "sensitive" mask of "title" threw`, а `summary.filter` стал `{"title":"?"}`. Ошибка называет путь и значения не содержит никогда.

<Params title="Поля">
<Param name="type" type={'"instrumentation.error"'} required>

Признак события.

</Param>
<Param name="source" type={'"sensitive-mask"'} required>

Откуда сбой. Сейчас единственный источник — функция `mask`.

</Param>
<Param name="timestamp" type="number" required>

Когда произошло событие, в миллисекундах эпохи.

</Param>
<Param name="model" type="string | undefined" required>

Модель операции, чьё событие маскировалось, если она известна.

</Param>
<Param name="path" type="string" required>

Путь значения в базе через точку, пустая строка вне полей.

</Param>
<Param name="error" type="unknown" required>

Ошибка с путём и без значения.

</Param>
</Params>

Если `mask` падает при обработке самого `instrumentation.error`, ядро пишет об этом в `console.error` и новых событий не порождает, так что бесконечного цикла нет. Если к моменту сбоя подписчиков уже не осталось, ядро пишет в `console.error` строку `[typemo] instrumentation: a sensitive mask threw; the value is "?"`.
