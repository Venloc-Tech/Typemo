**Расширение** добавляет в описание модели свой ключ внутри `ext` у `@Prop` и `@Schema`. Typemo проверяет его значения при компиляции схемы. Так библиотеки и ваш код хранят настройки прямо у поля — подпись для интерфейса, правила экспорта, признаки для поиска. Расширение — это только метаданные. Во время операций оно ничего не делает и политики (тенант, мягкое удаление, скрытые поля) не обходит.

Впервые добавляете свой ключ? Начните с руководства [Свои опции полей и схем](../../extensions/custom-options.mdx) и примера [Пример расширения](../../extensions/example.mdx). Регистрация на все клиенты описана в справочнике [`Typemo.use`](../connection/typemo.mdx#typemouse), на один клиент — в [`client.use`](../connection/typemo-client.mdx#clientuse).

Расширение собирается из трёх частей. Тип ключа для компилятора объявляют в `PropExtensions` или `SchemaExtensions`, проверку значения регистрируют через `TypemoExtension`, а читают значения из описания схемы ([`SchemaInfo`](../schemas/schema-info.mdx)). В примерах работает расширение `label`, которое хранит подпись поля для интерфейса.

---

## TypemoExtension

`TypemoExtension<N>` — объект расширения. В нём лежат имя ключа и функции проверки, и благодаря им ошибочное значение находится при компиляции схемы, а не когда его прочитает интеграция. Проверка получает значение как написано и **бросает ошибку**, если оно неверно.

```ts twoslash
import { type TypemoExtension } from "@venloc/typemo";
declare module "@venloc/typemo" {
  interface PropExtensions<V> {
    label?: { readonly text: string; readonly format?: (value: V) => string };
  }
  interface SchemaExtensions {
    label?: { readonly title: string };
  }
}
// ---cut---
export const label: TypemoExtension<"label"> = {
  name: "label",
  validateProp: (value) => {
    if (typeof (value as { text?: unknown }).text !== "string") throw new TypeError("text must be a string");
  },
  validateSchema: (value) => {
    if (typeof (value as { title?: unknown }).title !== "string") throw new TypeError("title must be a string");
  },
};
```

Значение приходит как `unknown`. Компилятор проверяет вызовы на TypeScript, а значения из JavaScript-кода и конфигурации не видит, так что проверка защищается сама. Вторым аргументом она получает описание места объявления — [`ExtensionFieldInfo`](#extensionfieldinfo) или [`ExtensionSchemaInfo`](#extensionschemainfo). По нему можно учесть вид поля или путь. Адрес поля Typemo добавляет в текст ошибки сам, повторять его в своём сообщении не надо.

<Params>
<Param name="name" type="N extends ExtensionName" required>

Имя расширения, то есть ключ под `ext`. Оно должно быть ключом `PropExtensions` или `SchemaExtensions`, уже объявленным в типах. Это непустая строка, которая не начинается с `$`.

</Param>
<Param name="validateProp" type="(value: unknown, field: ExtensionFieldInfo) => void">

Проверяет значение у поля и бросает ошибку, если оно неверно. Без этой функции ключ нельзя указать в `ext` у `@Prop`.

</Param>
<Param name="validateSchema" type="(value: unknown, schema: ExtensionSchemaInfo) => void">

Проверяет значение у схемы и бросает ошибку, если оно неверно. Без этой функции ключ нельзя указать в `ext` у `@Schema`.

</Param>
</Params>

Нужна хотя бы одна из двух функций. Расширение без обеих бесполезно, и регистрация его отвергает.

<FullType>

```ts
interface TypemoExtension<N extends ExtensionName = ExtensionName> {
  readonly name: N;
  readonly validateProp?: (value: unknown, field: ExtensionFieldInfo) => void;
  readonly validateSchema?: (value: unknown, schema: ExtensionSchemaInfo) => void;
}
```

</FullType>

### Что делает Typemo со значением

Перед проверкой Typemo копирует значение в замороженную копию. Ваш вход не меняется, а проверка и читатели не могут испортить сохранённое. Обычные объекты и массивы копируются глубоко, функции и значения BSON остаются как есть. `Object.isFrozen` вернул `true` и для описания поля, и для значения расширения внутри него, а функция `format` осталась вызываемой.

Ошибку, которую бросила проверка, Typemo кладёт в `cause` у `ConfigurationError`, а адрес поля ставит перед её текстом. Вот результат для `ext: { label: { text: "" } }` и проверки, которая бросает `TypeError("text must be a non-empty string")`.

```text
ConfigurationError: Bad.a: ext "label" is invalid: text must be a non-empty string
```

Ключ, у которого для этого места нет проверки, тоже даёт `ConfigurationError`. Так вышло у расширения только с `validateProp`, использованного у схемы.

```text
ConfigurationError: Bad2: extension "label" has no schema options (used on a schema)
```

Ключ, который не зарегистрирован, — вот что вернул клиент без `client.use`.

```text
ConfigurationError: Account: ext "label" is not a registered extension; register it before the first model with client.use() (for the models of one client) or Typemo.use() (for every client)
```

Текст один и для клиента, и для глобальной регистрации. Он называет оба способа, потому что ключ мог быть зарегистрирован любым из них. Если `ext` не объект, Typemo бросает `ConfigurationError` с текстом `Bad3.a: option "ext" is an object { [extension name]: options }`.

### Ошибки регистрации

Имя повторилось, причём неважно, занято оно глобально или на клиенте.

```text
ConfigurationError: extension "label" is already registered
```

У расширения нет ни одной проверки.

```text
ConfigurationError: extension "x": needs validateProp, validateSchema or both
```

Имя пустое или начинается с `$`.

```text
ConfigurationError: an extension is an object { name, validateProp?, validateSchema? } with a name not starting with "$"
```

Регистрация пришла после компиляции первой схемы клиента.

```text
ConfigurationError: extension "late": extensions are fixed once a schema is compiled (Account was); call client.use() before the first model
```

Реестр закрывает **первая успешная компиляция схемы**. Расширение, зарегистрированное позже, не проверило бы уже готовые схемы. Неудачная компиляция реестр не закрывает. После `ConfigurationError` из-за незарегистрированного ключа `client.use` того же клиента ещё принимает расширения, так что зарегистрируйте названное расширение и повторите `model`. Реестр клиента закрывается его первой моделью. Реестр [`Typemo.use`](../connection/typemo.mdx#typemouse) закрывается первой успешно собранной схемой на любом клиенте, и тогда в тексте стоит `call Typemo.use() before the first model`. Планы закрываются так же — плагины, зарегистрированные после первой успешной схемы, дают `ConfigurationError`. Подробнее в руководстве [Несколько клиентов и расширения](../../connection/clients-and-extensions.mdx#регистрировать-до-первой-модели).

### Когда `TypemoExtension` не подходит

Влиять на операции расширение не умеет — у него нет доступа ни к операциям, ни к политикам. Для этого есть [хуки](../../hooks/operation-hooks.mdx), и `modify` проходит все политики. Хотите наблюдать за операциями — подпишитесь на [события](../observability/events.mdx). Нужно изменить схемы многих моделей по одному правилу — напишите [плагин](../hooks/plugins.mdx#schemaplugin).

## PropExtensions

`PropExtensions<V>` — интерфейс опций расширений у поля, то есть `ext` в `@Prop`. В ядре он пустой. Каждое расширение дописывает в него свой ключ через объявление модуля (`declaration merging`), после чего ключ допустим у `@Prop`, а компилятор знает тип его значения. `V` — тип значения поля, поэтому опцию можно им типизировать, например `format?: (value: V) => string`.

```ts twoslash
import { type Defaulted, Entity, Prop, Schema } from "@venloc/typemo";
declare module "@venloc/typemo" {
  interface PropExtensions<V> {
    label?: { readonly text: string; readonly format?: (value: V) => string };
  }
}
// ---cut---
@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => Number, {
    default: 0,
    ext: { label: { text: "Баланс", format: (value) => value.toFixed(2) } },
  })
  balance!: Defaulted<number>;
}
```

Здесь `value` в `format` — число, компилятор вывел его из типа поля.

Параметр в каждом объявлении должен называться `V`, этого требует TypeScript при слиянии интерфейсов с параметрами типа. Ключи уникальны — одно расширение, один ключ.

### Ошибки при компиляции

Компилятор не пропустит ключ, который не объявлен.

```ts twoslash
import { Entity, Prop, Schema } from "@venloc/typemo";
// ---cut---
// @errors: 2322
@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { ext: { nope: { text: "x" } } })
  title?: string;
}
```

Значение неверного типа он тоже не пропустит. Если `label.text` объявлен строкой, число не подойдёт. Во время работы то же самое проверяет `validateProp`.

<FullType>

```ts
interface PropExtensions<V = unknown> {}
```

</FullType>

## SchemaExtensions

`SchemaExtensions` — то же самое для схемы, то есть `ext` в `@Schema`. Ключи добавляются так же, объявлением модуля. Параметра типа у него нет.

```ts twoslash
import { Entity, Schema } from "@venloc/typemo";
declare module "@venloc/typemo" {
  interface SchemaExtensions {
    label?: { readonly title: string };
  }
}
// ---cut---
@Schema({ collection: "accounts", ext: { label: { title: "Счета" } } })
export class Account extends Entity {}
```

Дискриминатор берёт опции схемы своего корня, поэтому `ext` корня действует и на него.

<FullType>

```ts
interface SchemaExtensions {}
```

</FullType>

## ExtensionName

`ExtensionName` — имя расширения, то есть ключ любого из двух интерфейсов, `PropExtensions` или `SchemaExtensions`. Пока ни одно расширение не объявлено, это `never`. После объявления `label` получится `"label"`. Тип нужен для параметра `N` у [`TypemoExtension`](#typemoextension).

<FullType>

```ts
type ExtensionName = (keyof PropExtensions | keyof SchemaExtensions) & string;
```

</FullType>

## ExtensionFieldInfo

`ExtensionFieldInfo` описывает поле, у которого объявлен `ext`. Его получает вторым аргументом `validateProp`. По нему проверка может учесть вид поля или путь, например разрешить ключ только скалярным полям. Адрес `Класс.поле` Typemo добавляет в сообщение об ошибке сам.

<TypeTable
  type={{
    "where": { description: "`Класс.поле` для сообщений, например `Account.balance`.", type: "string" },
    "path": { description: "Путь поля в схеме в кодовых именах (`name.first` для поля вложенного объекта).", type: "string" },
    "dbPath": { description: "Путь поля в базе.", type: "string" },
    "kind": { description: "Вид узла поля — `scalar`, `array`, `map`, `subdocument` и другие.", type: "string" },
  }}
/>

<FullType>

```ts
interface ExtensionFieldInfo {
  readonly where: string;
  readonly path: string;
  readonly dbPath: string;
  readonly kind: string;
}
```

</FullType>

## ExtensionSchemaInfo

`ExtensionSchemaInfo` описывает схему, у которой объявлен `ext`. Его получает вторым аргументом `validateSchema`.

<TypeTable
  type={{
    "name": { description: "Имя класса.", type: "string" },
    "kind": { description: "Документ или вложенный объект.", type: "\"document\" | \"nested\"" },
    "discriminator": { description: "Значение дискриминатора, если схема — дискриминатор (у него те же опции, что у корня), иначе `undefined`.", type: "string | undefined" },
  }}
/>

<FullType>

```ts
interface ExtensionSchemaInfo {
  readonly name: string;
  readonly kind: "document" | "nested";
  readonly discriminator: string | undefined;
}
```

</FullType>

## Чтение значений

Значения расширений читают из описания схемы [`SchemaInfo`](../schemas/schema-info.mdx). Для схемы это `model.schema.ext`, для поля — `model.schema.extOf(path)`. Тот же `SchemaInfo` лежит в поле `schema` событий операций и в [`OperationInfo`](../hooks/operation-context.mdx#operationinfo), так что интеграция читает свои опции прямо по событию.

`extOf` принимает путь в любой позиционной форме (`lines.0.note`). Если такого пути нет, он возвращает `undefined`, а для поля без опций — пустой объект. Метод `describe()` включает `ext` у путей и схемы, но только как данные, и функции в JSON пропадают.

В примере `model.schema.ext` вернул `{ label: { title: "Счета" } }`, а `extOf("title")` — `{ label: { text: "Название" } }`. Для поля без опций `extOf("note")` вернул `{}`, а `extOf("nope")` — `undefined`.
