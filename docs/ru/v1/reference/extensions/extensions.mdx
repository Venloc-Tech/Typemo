**Расширение** добавляет в описание модели свой ключ внутри `ext` у `@Prop` и `@Schema`. Typemo проверяет его значения при компиляции схемы. Так библиотеки и ваш код хранят настройки прямо у поля — подпись для интерфейса, правила экспорта, признаки для поиска. Расширение — это только метаданные. Во время операций оно ничего не делает и политики (тенант, мягкое удаление, скрытые поля) не обходит.

Впервые добавляете свой ключ? Начните с руководства [Свои опции полей и схем](../../extensions/custom-options.mdx) и примера [Пример расширения](../../extensions/example.mdx). Регистрация на все клиенты описана в справочнике [`Typemo.use`](../connection/typemo.mdx#typemo.use), на один клиент — в [`client.use`](../connection/typemo-client.mdx#client.use).

Расширение собирается из трёх частей. Тип ключа для компилятора объявляют в `PropExtensions` или `SchemaExtensions`, проверку значения регистрируют через `TypemoExtension`, а читают значения из описания схемы ([`SchemaInfo`](../schemas/schema-info.mdx)). В примерах работает расширение `label`, которое хранит подпись поля для интерфейса.

## TypemoExtension [#typemo-extension]

`TypemoExtension<N>` — объект расширения. В нём лежат имя ключа и функции проверки, и благодаря им ошибочное значение находится при компиляции схемы, а не когда его прочитает интеграция. Проверка получает значение как написано и **бросает ошибку**, если оно неверно.

<Snippet id="reference/extensions/extensions/typemo-extension" twoslash />

Значение приходит как `unknown`. Компилятор проверяет вызовы на TypeScript, а значения из JavaScript-кода и конфигурации не видит, так что проверка защищается сама. Вторым аргументом она получает описание места объявления — [`ExtensionFieldInfo`](#extension-field-info) или [`ExtensionSchemaInfo`](#extension-schema-info). По нему можно учесть вид поля или путь. Адрес поля Typemo добавляет в текст ошибки сам, повторять его в своём сообщении не надо.

<Params>
<Param name="name" type="N extends ExtensionName" required>

Имя расширения, то есть ключ под `ext`. Оно должно быть ключом `PropExtensions` или `SchemaExtensions`, уже объявленным в типах. Это непустая строка, которая не начинается с `$`.

</Param>
<Param name="validateProp" type="(value: unknown, field: ExtensionFieldInfo) => void">

Проверяет значение у поля и бросает ошибку, если оно неверно. Без этой функции ключ нельзя указать в `ext` у `@Prop`.

</Param>
<Param name="validateSchema" type="(value: unknown, schema: ExtensionSchemaInfo) => void">

Проверяет значение у схемы и бросает ошибку, если оно неверно. Без этой функции ключ нельзя указать в `ext` у `@Schema`.

</Param>
</Params>

Нужна хотя бы одна из двух функций. Расширение без обеих бесполезно, и регистрация его отвергает.

### Что делает Typemo со значением [#value-handling]

Перед проверкой Typemo копирует значение в замороженную копию. Ваш вход не меняется, а проверка и читатели не могут испортить сохранённое. Обычные объекты и массивы копируются глубоко, функции и значения BSON остаются как есть. `Object.isFrozen` вернул `true` и для описания поля, и для значения расширения внутри него, а функция `format` осталась вызываемой.

Ошибку, которую бросила проверка, Typemo кладёт в `cause` у `ConfigurationError`, а адрес поля ставит перед её текстом. Вот результат для `ext: { label: { text: "" } }` и проверки, которая бросает `TypeError("text must be a non-empty string")`.

<Snippet id="reference/extensions/extensions/value-handling" />

Ключ, у которого для этого места нет проверки, тоже даёт `ConfigurationError`. Так вышло у расширения только с `validateProp`, использованного у схемы.

<Snippet id="extensions/custom-options/troubleshooting" />

Ключ, который не зарегистрирован, — вот что вернул клиент без `client.use`.

<Snippet id="extensions/custom-options/per-client-or-global" />

Текст один и для клиента, и для глобальной регистрации. Он называет оба способа, потому что ключ мог быть зарегистрирован любым из них. Если `ext` не объект, Typemo бросает `ConfigurationError` с текстом `Bad3.a: option "ext" is an object { [extension name]: options }`.

### Ошибки регистрации [#registration-errors]

Имя повторилось, причём неважно, занято оно глобально или на клиенте.

<Snippet id="connection/clients-and-extensions/register-global-2" />

У расширения нет ни одной проверки.

<Snippet id="reference/extensions/extensions/registration-errors" />

Имя пустое или начинается с `$`.

<Snippet id="reference/extensions/extensions/registration-errors-2" />

Регистрация пришла после компиляции первой схемы клиента.

<Snippet id="connection/clients-and-extensions/register-before-first-model" />

Реестр закрывает **первая успешная компиляция схемы**. Расширение, зарегистрированное позже, не проверило бы уже готовые схемы. Неудачная компиляция реестр не закрывает. После `ConfigurationError` из-за незарегистрированного ключа `client.use` того же клиента ещё принимает расширения, так что зарегистрируйте названное расширение и повторите `model`. Реестр клиента закрывается его первой моделью. Реестр [`Typemo.use`](../connection/typemo.mdx#typemo.use) закрывается первой успешно собранной схемой на любом клиенте, и тогда в тексте стоит `call Typemo.use() before the first model`. Планы закрываются так же — плагины, зарегистрированные после первой успешной схемы, дают `ConfigurationError`. Подробнее в руководстве [Несколько клиентов и расширения](../../connection/clients-and-extensions.mdx#register-before-first-model).

### Когда `TypemoExtension` не подходит [#when-not-to-use]

Влиять на операции расширение не умеет — у него нет доступа ни к операциям, ни к политикам. Для этого есть [хуки](../../hooks/operation-hooks.mdx), и `modify` проходит все политики. Хотите наблюдать за операциями — подпишитесь на [события](../observability/events.mdx). Нужно изменить схемы многих моделей по одному правилу — напишите [плагин](../hooks/plugins.mdx#schema-plugin).

## PropExtensions [#prop-extensions]

`PropExtensions<V>` — интерфейс опций расширений у поля, то есть `ext` в `@Prop`. В ядре он пустой. Каждое расширение дописывает в него свой ключ через объявление модуля (`declaration merging`), после чего ключ допустим у `@Prop`, а компилятор знает тип его значения. `V` — тип значения поля, поэтому опцию можно им типизировать, например `format?: (value: V) => string`.

<Snippet id="reference/extensions/extensions/prop-extensions" twoslash />

Здесь `value` в `format` — число, компилятор вывел его из типа поля.

Параметр в каждом объявлении должен называться `V`, этого требует TypeScript при слиянии интерфейсов с параметрами типа. Ключи уникальны — одно расширение, один ключ.

### Ошибки при компиляции [#compile-errors]

Компилятор не пропустит ключ, который не объявлен.

<Snippet id="reference/extensions/extensions/compile-errors" twoslash />

Значение неверного типа он тоже не пропустит. Если `label.text` объявлен строкой, число не подойдёт. Во время работы то же самое проверяет `validateProp`.

## SchemaExtensions [#schema-extensions]

`SchemaExtensions` — то же самое для схемы, то есть `ext` в `@Schema`. Ключи добавляются так же, объявлением модуля. Параметра типа у него нет.

<Snippet id="reference/extensions/extensions/schema-extensions" twoslash />

Дискриминатор берёт опции схемы своего корня, поэтому `ext` корня действует и на него.

## ExtensionName [#extension-name]

`ExtensionName` — имя расширения, то есть ключ любого из двух интерфейсов, `PropExtensions` или `SchemaExtensions`. Пока ни одно расширение не объявлено, это `never`. После объявления `label` получится `"label"`. Тип нужен для параметра `N` у [`TypemoExtension`](#typemo-extension).

## ExtensionFieldInfo [#extension-field-info]

`ExtensionFieldInfo` описывает поле, у которого объявлен `ext`. Его получает вторым аргументом `validateProp`. По нему проверка может учесть вид поля или путь, например разрешить ключ только скалярным полям. Адрес `Класс.поле` Typemo добавляет в сообщение об ошибке сам.

## Чтение значений [#reading-values]

Значения расширений читают из описания схемы [`SchemaInfo`](../schemas/schema-info.mdx). Для схемы это `model.schema.ext`, для поля — `model.schema.extOf(path)`. Тот же `SchemaInfo` лежит в поле `schema` событий операций и в [`OperationInfo`](../hooks/operation-context.mdx#operation-info), так что интеграция читает свои опции прямо по событию.

`extOf` принимает путь в любой позиционной форме (`lines.0.note`). Если такого пути нет, он возвращает `undefined`, а для поля без опций — пустой объект. Метод `describe()` включает `ext` у путей и схемы, но только как данные, и функции в JSON пропадают.

В примере `model.schema.ext` вернул `{ label: { title: "Accounts" } }`, а `extOf("title")` — `{ label: { text: "Title" } }`. Для поля без опций `extOf("note")` вернул `{}`, а `extOf("nope")` — `undefined`.
