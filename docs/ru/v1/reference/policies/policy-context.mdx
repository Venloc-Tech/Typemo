**Контекст политик** — набор значений, которые политики модели читают при каждой операции: какому тенанту принадлежат данные, кто действует (для аудита) и должны ли быть видны удалённые документы. Значения не хранятся ни в модели, ни в клиенте: они приходят либо из области, открытой [`PolicyContext.run`](#policycontextrun), либо из [`.policy()`](../query/options.mdx#policy) у одной операции. Если вы только начинаете, сначала прочитайте руководство [Контекст политик](../../policies/policy-context.mdx). Эта страница — справочник.

Контекст читается **в момент построения операции**, а не в момент `await`. Запрос, созданный внутри `run`, помнит значения, даже если вы дождётесь его снаружи. И наоборот: строитель, созданный вне `run`, тенанта не получит, сколько бы раз его ни ждали внутри. Так запрос, сохранённый в переменной модуля, не меняет тенанта вслед за тем запросом HTTP, который случайно его дождался.

Примеры страницы используют модель заказа организации: поле `tenantId` помечено [`@Tenant()`](../schemas/field-markers.mdx#tenant) и типом [`TenantField`](../schemas/field-markers.mdx#tenantfield) и включает политику тенанта ([`tenant`](./schema-options.mdx#опция-tenant)).

```ts twoslash title="orders/order.ts"
import { Entity, Prop, Schema, Tenant, type TenantField } from "@venloc/typemo";

@Schema({ collection: "orders", tenant: true })
export class Order extends Entity {
  @Prop(() => String)
  @Tenant()
  tenantId!: TenantField<string>;

  @Prop(() => String, { required: true })
  number!: string;
}
```

## PolicyContext.run

`run` открывает область, в которой действуют значения контекста, и выполняет в ней функцию. Область сохраняется во всей цепочке асинхронных вызовов внутри функции: после `await`, в колбэках, в таймерах. Это тот же механизм, что хранит данные текущего запроса HTTP в Node и Bun, и поэтому тенанта не нужно передавать параметром в каждую функцию сервиса.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, PolicyContext, Tenant, type TenantField } from "@venloc/typemo";
@Schema({ collection: "orders", tenant: true })
class Order extends Entity {
  @Prop(() => String) @Tenant() tenantId!: TenantField<string>;
  @Prop(() => String, { required: true }) number!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Orders = client.connection.model(Order);
// ---cut---
await PolicyContext.run({ tenant: "acme" }, async () => {
  await Orders.create({ number: "A-1" });
});

const acme = await PolicyContext.run({ tenant: "acme" }, () => Orders.find().plain());
console.log(acme.map((order) => order.number));
// → ["A-1"]
```

Вложенный `run` не заменяет область целиком, а накладывает значения на область снаружи: внутренний `tenant` перекрывает внешний, остальные значения остаются. Если внутренний `run` задаёт `tenant`, унаследованный `allTenants` отменяется, и наоборот: `allTenants: true` отменяет унаследованный `tenant`. Так же ведут себя `includeDeleted` и `onlyDeleted`. Иначе внутренняя область получила бы противоречивый контекст.

```ts twoslash
import { PolicyContext } from "@venloc/typemo";
// ---cut---
const inner = PolicyContext.run({ tenant: "a", actor: "user-1" }, () =>
  PolicyContext.run({ tenant: "b" }, () => PolicyContext.current()),
);
console.log(inner);
// → { tenant: "b", actor: "user-1" }

const all = PolicyContext.run({ tenant: "a" }, () =>
  PolicyContext.run({ allTenants: true }, () => PolicyContext.current()),
);
console.log(all);
// → { allTenants: true }
```

<Returns type="R">

То, что вернула `work`, без изменений: и значение, и `Promise`. `run` сам ничего не ждёт. Если внутри область нужна и после `await`, объявляйте функцию `async` и ждите внутри неё, а не снаружи.

</Returns>

</Param>

### Ошибки

Неверные значения [`run`](#policycontextrun) отвергаются до вызова функции. Форму значений проверяет [`QueryError`](../errors/query-errors.mdx#queryerror), пустой тенант — [`StrictModeError`](./violations.mdx#tenant). Каждый текст получен запуском:

```text
QueryError: PolicyContext.run: unknown policy value "tenat" (known: tenant, allTenants, actor, includeDeleted, onlyDeleted, hardDelete)
QueryError: PolicyContext.run: includeDeleted is `true` or absent
QueryError: PolicyContext.run: tenant and allTenants contradict each other
QueryError: PolicyContext.run: includeDeleted and onlyDeleted contradict each other
QueryError: PolicyContext.run: the policy values are an object ({ tenant, actor, includeDeleted, … })
StrictModeError: PolicyContext.run: the tenant is empty (""); a tenant is a non-empty value, or allTenants: true for cross-tenant work [tenant]
StrictModeError: PolicyContext.run: the tenant is empty (null); a tenant is a non-empty value, or allTenants: true for cross-tenant work [tenant]
```

Опечатка в имени ключа не превращается в тихое отсутствие тенанта: `tenat` называется в ошибке вместе со списком допустимых. `null`, пустая строка и строка из одних пробелов в `tenant` запрещены по той же причине: они выглядели бы как «тенант не нужен», а «не нужен» пишется явно, `allTenants: true`. Без этой проверки ошибка в коде, который достаёт организацию из токена, молча превратилась бы в работу с документами без организации.

## PolicyContext.current

`current` возвращает значения области, в которой вы находитесь. Он нужен там, где значения надо прочитать, а не применить: записать в журнал запроса, передать в задачу очереди, показать в ответе отладки. Вне любого `run` возвращается `undefined`, а не пустой объект: так видно, что области нет вовсе.

```ts twoslash
import { PolicyContext } from "@venloc/typemo";
// ---cut---
console.log(PolicyContext.current());
// → undefined

const inside = PolicyContext.run({ tenant: "a", actor: "u1" }, () => PolicyContext.current());
console.log(inside);
// → { tenant: "a", actor: "u1" }
```

Значения `.policy()` у отдельной операции в `current` не видны: `.policy()` действует на одну операцию и области не создаёт.

<Returns type="Readonly<PolicyValues> | undefined">

Замороженный объект со значениями области (изменить его нельзя) или `undefined` вне `run`.

</Returns>

Принимает ничего.

<FullType>

```ts
static current(): Readonly<PolicyValues> | undefined
```

</FullType>

## PolicyContext.captured

`captured` возвращает значения области в форме, в которой их принимают параметры операций: `{ policy }`. Метод публичен для обёрток и плагинов, которые сами собирают операцию (свой слой запросов, плагин, составляющий операции): операции моделей делают то же самое, когда их строят. Прикладному коду он не нужен: область открывается через [`run`](#policycontextrun). Вне области `policy` — пустой объект.

```ts twoslash
import { PolicyContext } from "@venloc/typemo";
// ---cut---
console.log(PolicyContext.captured());
// → { policy: {} }

const inside = PolicyContext.run({ tenant: "z" }, () => PolicyContext.captured());
console.log(inside);
// → { policy: { tenant: "z" } }
```

<Returns type="{ readonly policy: Readonly<PolicyValues> }">

Объект с одним ключом `policy`. Его можно распаковать в параметры операции.

</Returns>

Принимает ничего.

<FullType>

```ts
static captured(): { readonly policy: Readonly<PolicyValues> }
```

</FullType>

## PolicyContext.merge

`merge` проверяет значения и накладывает их на другие, не меняя ни то, ни другое. Метод публичен для обёрток и плагинов, которые сочетают свои значения политик с значениями области; прикладной код передаёт их операции (`.policy()`, параметр `policy` записи). Так работают [`run`](#policycontextrun) для вложенной области и [`.policy()`](../query/options.mdx#policy) для значений операции поверх области. Правила те же, что у `run`: неизвестный ключ, флаг не `true` и противоречия — [`QueryError`](../errors/query-errors.mdx#queryerror), пустой тенант (`null`, пустая строка) — [`StrictModeError`](./violations.mdx#tenant); в тексте обеих стоит имя вызова из `where`. Значение `undefined` в `extra` пропускается и не стирает значение из `base`.

```ts twoslash
import { PolicyContext } from "@venloc/typemo";
// ---cut---
const merged = PolicyContext.merge({ tenant: "a", actor: "u" }, { allTenants: true }, "myWrapper");
console.log(merged);
// → { actor: "u", allTenants: true }
```

Явный `allTenants` убрал унаследованный `tenant`: результат не противоречит сам себе.

<Returns type="Readonly<PolicyValues>">

Новый замороженный объект. Аргументы не изменяются.

</Returns>

<Params>
<Param name="base" type="Readonly<PolicyValues> | undefined" required>

Значения, на которые накладываются новые. `undefined` означает «ничего».

</Param>
<Param name="extra" type="PolicyValues" required>

Новые значения. Проверяются.

</Param>
<Param name="where" type="string" required>

Название вызова: попадает в начало текста ошибки.

</Param>
</Params>

<FullType>

```ts

```

</FullType>

## PolicyContext.EMPTY

`EMPTY` — замороженный объект без значений, тот же, что подставляется вне области. Сравнивайте с ним, если хотите узнать, пуст ли контекст, вместо того чтобы считать ключи.

```ts twoslash
import { PolicyContext } from "@venloc/typemo";
// ---cut---
console.log(PolicyContext.EMPTY, Object.isFrozen(PolicyContext.EMPTY));
// → {} true
```


## PolicyValues

`PolicyValues` — тип объекта, который принимают [`run`](#policycontextrun), [`merge`](#policycontextmerge) и [`.policy()`](../query/options.mdx#policy). Все ключи необязательны, неизвестный ключ — ошибка. Четыре ключа — флаги: они принимают только `true` или отсутствие, потому что `false` в контексте политик не значит ничего, кроме путаницы («выключить политику» — не то же самое, что «не включать»).

<TypeTable
  type={{
    tenant: { description: "Тенант операции. Значение приводится по типу поля тенанта модели (строка, число, `ObjectId`, …). Нужен каждой операции модели с политикой [`tenant`](./schema-options.mdx#опция-tenant). Непустое значение: `null`, пустая строка и строка из пробелов отвергаются.", type: "unknown" },
    allTenants: { description: "Работа сразу по всем тенантам, например фоновая задача администратора. Политика тенанта не ограничивает операцию. Несовместим с `tenant`.", type: "true" },
    actor: { description: "Кто действует. Записывается в каждую запись [аудита](./schema-options.mdx#опция-audit).", type: "unknown" },
    includeDeleted: { description: "Операция видит и удалённые документы (политика [`softDelete`](./schema-options.mdx#опция-softdelete)). Несовместим с `onlyDeleted`.", type: "true" },
    onlyDeleted: { description: "Операция видит только удалённые документы: так работает [`SoftDelete.restore`](./soft-delete-and-untrusted.mdx#softdeleterestore).", type: "true" },
    hardDelete: { description: "Удаление стирает документы навсегда, а не помечает: так работает [`SoftDelete.purge`](./soft-delete-and-untrusted.mdx#softdeletepurge).", type: "true" },
  }}
/>

`tenant` и `actor` имеют тип `unknown`, потому что тип тенанта задаёт поле модели: для `TenantField<string>` пригодна строка, для `TenantField<ObjectId>` — `ObjectId` или его строка. Значение приводится так же, как значение поля, и неподходящее вызывает [`CastError`](../errors/data-errors.mdx#casterror): например, число для строкового поля — `Cast to string failed at path "tenantId" for 5 (number): expected a string [type]`.

<FullType>

```ts
interface PolicyValues {
  readonly tenant?: unknown;
  readonly allTenants?: true;
  readonly actor?: unknown;
  readonly includeDeleted?: true;
  readonly onlyDeleted?: true;
  readonly hardDelete?: true;
}
```

</FullType>

## Когда не подходит

Контекст политик не заменяет фильтр. Если вы хотите ограничить выборку по обычному полю, например по владельцу счёта, пишите условие в фильтре: политики отвечают за то, что нельзя ослабить ни в одном запросе модели. Для одной операции, которой нужен другой тенант или другой режим удалённых, используйте [`.policy()`](../query/options.mdx#policy): область для этого открывать не нужно. Как контекст используется в задачах — в руководствах [Контекст политик](../../policies/policy-context.mdx) и [Мультитенантность](../../policies/tenants.mdx).
