**Контекст политик** — значения, которые политики модели читают при каждой операции. Какому тенанту принадлежат данные, кто действует (для аудита), нужно ли показывать удалённые документы. Модель и клиент их не хранят. Значения приходят из области, которую открывает [`PolicyContext.run`](#policycontextrun), или из [`.policy()`](../query/options.mdx#policy) у одной операции. Если вы только начинаете, прочитайте сначала руководство [Контекст политик](../../policies/policy-context.mdx).

Контекст читается **в момент построения операции**, а не в момент `await`. Запрос, созданный внутри `run`, помнит значения, даже если вы дождётесь его снаружи. Строитель, созданный вне `run`, тенанта не получит, сколько его ни жди внутри. Поэтому запрос, сохранённый в переменной модуля, не сменит тенанта вслед за HTTP-запросом, который случайно его дождался.

В примерах — модель заказа организации. Поле `tenantId` помечено [`@Tenant()`](../schemas/field-markers.mdx#tenant) и типом [`TenantField`](../schemas/field-markers.mdx#tenantfield), а политика тенанта включена ([`tenant`](./schema-options.mdx#опция-tenant)).

```ts twoslash title="orders/order.ts"
import { Entity, Prop, Schema, Tenant, type TenantField } from "@venloc/typemo";

@Schema({ collection: "orders", tenant: true })
export class Order extends Entity {
  @Prop(() => String)
  @Tenant()
  tenantId!: TenantField<string>;

  @Prop(() => String, { required: true })
  number!: string;
}
```

## PolicyContext.run

`run` открывает область со значениями контекста и выполняет в ней функцию. Область живёт во всей цепочке асинхронных вызовов внутри функции — после `await`, в колбэках, в таймерах. Так же Node и Bun хранят данные текущего HTTP-запроса. Тенанта не нужно передавать параметром в каждую функцию сервиса.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, PolicyContext, Tenant, type TenantField } from "@venloc/typemo";
@Schema({ collection: "orders", tenant: true })
class Order extends Entity {
  @Prop(() => String) @Tenant() tenantId!: TenantField<string>;
  @Prop(() => String, { required: true }) number!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Orders = client.connection.model(Order);
// ---cut---
await PolicyContext.run({ tenant: "acme" }, async () => {
  await Orders.create({ number: "A-1" });
});

const acme = await PolicyContext.run({ tenant: "acme" }, () => Orders.find().plain());
console.log(acme.map((order) => order.number));
// → ["A-1"]
```

Вложенный `run` не заменяет область целиком, а накладывает значения на внешнюю. Внутренний `tenant` перекрывает внешний, остальные значения остаются. Если внутренний `run` задаёт `tenant`, унаследованный `allTenants` отменяется. И наоборот — `allTenants: true` отменяет унаследованный `tenant`. Так же ведут себя `includeDeleted` и `onlyDeleted`, иначе внутри оказался бы противоречивый контекст.

```ts twoslash
import { PolicyContext } from "@venloc/typemo";
// ---cut---
const inner = PolicyContext.run({ tenant: "a", actor: "user-1" }, () =>
  PolicyContext.run({ tenant: "b" }, () => PolicyContext.current()),
);
console.log(inner);
// → { tenant: "b", actor: "user-1" }

const all = PolicyContext.run({ tenant: "a" }, () =>
  PolicyContext.run({ allTenants: true }, () => PolicyContext.current()),
);
console.log(all);
// → { allTenants: true }
```

<Returns type="R">

То, что вернула `work`, без изменений — и значение, и `Promise`. Сам `run` ничего не ждёт. Если область нужна и после `await`, объявите функцию `async` и ждите внутри неё, а не снаружи.

</Returns>

### Ошибки

Неверные значения [`run`](#policycontextrun) отвергает до вызова функции. Форму значений проверяет [`QueryError`](../errors/query-errors.mdx#queryerror), пустой тенант ловит [`StrictModeError`](./violations.mdx#tenant). Все тексты ниже взяты из реального запуска.

```text
QueryError: PolicyContext.run: unknown policy value "tenat" (known: tenant, allTenants, actor, includeDeleted, onlyDeleted, hardDelete)
QueryError: PolicyContext.run: includeDeleted is `true` or absent
QueryError: PolicyContext.run: tenant and allTenants contradict each other
QueryError: PolicyContext.run: includeDeleted and onlyDeleted contradict each other
QueryError: PolicyContext.run: the policy values are an object ({ tenant, actor, includeDeleted, … })
StrictModeError: PolicyContext.run: the tenant is empty (""); a tenant is a non-empty value, or allTenants: true for cross-tenant work [tenant]
StrictModeError: PolicyContext.run: the tenant is empty (null); a tenant is a non-empty value, or allTenants: true for cross-tenant work [tenant]
```

Опечатка в имени ключа не превращается в тихое отсутствие тенанта. Ошибка называет `tenat` и список допустимых ключей. По той же причине `null`, пустая строка и строка из пробелов в `tenant` запрещены. Они выглядели бы как «тенант не нужен», а «не нужен» пишется явно — `allTenants: true`. Без проверки ошибка в коде, который достаёт организацию из токена, молча превратилась бы в работу с документами без организации.

## PolicyContext.current

`current` возвращает значения области, в которой вы находитесь. Он нужен там, где значения надо прочитать, а не применить. Например, записать в журнал запроса, передать в задачу очереди или показать в ответе отладки. Вне любого `run` приходит `undefined`, а не пустой объект, так что отсутствие области видно сразу.

```ts twoslash
import { PolicyContext } from "@venloc/typemo";
// ---cut---
console.log(PolicyContext.current());
// → undefined

const inside = PolicyContext.run({ tenant: "a", actor: "u1" }, () => PolicyContext.current());
console.log(inside);
// → { tenant: "a", actor: "u1" }
```

Значения `.policy()` у отдельной операции в `current` не видны. `.policy()` действует на одну операцию и области не создаёт.

<Returns type="Readonly<PolicyValues> | undefined">

Замороженный объект со значениями области (изменить его нельзя) или `undefined` вне `run`.

</Returns>

Аргументов нет.

<FullType>

```ts
static current(): Readonly<PolicyValues> | undefined
```

</FullType>

## PolicyContext.captured

`captured` отдаёт значения области в форме, которую принимают параметры операций, — `{ policy }`. Метод открыт для обёрток и плагинов, которые сами собирают операцию, например для своего слоя запросов. Операции моделей делают то же самое при построении. Прикладному коду он ни к чему, область открывается через [`run`](#policycontextrun). Вне области `policy` — пустой объект.

```ts twoslash
import { PolicyContext } from "@venloc/typemo";
// ---cut---
console.log(PolicyContext.captured());
// → { policy: {} }

const inside = PolicyContext.run({ tenant: "z" }, () => PolicyContext.captured());
console.log(inside);
// → { policy: { tenant: "z" } }
```

<Returns type="{ readonly policy: Readonly<PolicyValues> }">

Объект с одним ключом `policy`. Его можно распаковать в параметры операции.

</Returns>

Аргументов нет.

<FullType>

```ts
static captured(): { readonly policy: Readonly<PolicyValues> }
```

</FullType>

## PolicyContext.merge

`merge` проверяет значения и накладывает их на другие, не меняя ни то, ни другое. Метод открыт для обёрток и плагинов, которые сочетают свои значения политик со значениями области. Прикладной код передаёт значения операции напрямую (`.policy()`, параметр `policy` записи). Тем же способом [`run`](#policycontextrun) строит вложенную область, а [`.policy()`](../query/options.mdx#policy) накладывает значения операции на область.

Правила те же, что у `run`. Неизвестный ключ, флаг не `true` и противоречия дают [`QueryError`](../errors/query-errors.mdx#queryerror), пустой тенант (`null`, пустая строка) — [`StrictModeError`](./violations.mdx#tenant). В тексте обеих ошибок стоит имя вызова из `where`. Значение `undefined` в `extra` пропускается и не стирает значение из `base`.

```ts twoslash
import { PolicyContext } from "@venloc/typemo";
// ---cut---
const merged = PolicyContext.merge({ tenant: "a", actor: "u" }, { allTenants: true }, "myWrapper");
console.log(merged);
// → { actor: "u", allTenants: true }
```

Явный `allTenants` убрал унаследованный `tenant`, и результат не противоречит сам себе.

<Returns type="Readonly<PolicyValues>">

Новый замороженный объект. Аргументы не меняются.

</Returns>

<Params>
<Param name="base" type="Readonly<PolicyValues> | undefined" required>

Значения, на которые накладываются новые. `undefined` значит «ничего».

</Param>
<Param name="extra" type="PolicyValues" required>

Новые значения. Их `merge` проверяет.

</Param>
<Param name="where" type="string" required>

Название вызова. Оно попадает в начало текста ошибки.

</Param>
</Params>

<FullType>

```ts
static merge(base: Readonly<PolicyValues> | undefined, extra: PolicyValues, where: string): Readonly<PolicyValues>
```

</FullType>

## PolicyContext.EMPTY

`EMPTY` — замороженный объект без значений, тот самый, что подставляется вне области. Сравнивайте с ним, если хотите узнать, пуст ли контекст. Считать ключи не нужно.

```ts twoslash
import { PolicyContext } from "@venloc/typemo";
// ---cut---
console.log(PolicyContext.EMPTY, Object.isFrozen(PolicyContext.EMPTY));
// → {} true
```

<FullType>


## PolicyValues

`PolicyValues` — тип объекта, который принимают [`run`](#policycontextrun), [`merge`](#policycontextmerge) и [`.policy()`](../query/options.mdx#policy). Все ключи необязательны, неизвестный ключ — ошибка. Четыре ключа — флаги, они принимают только `true` или отсутствие. `false` в контексте политик ничего не значит, кроме путаницы, ведь «выключить политику» и «не включать» — разные вещи.

<TypeTable
  type={{
    tenant: { description: "Тенант операции. Значение приводится по типу поля тенанта модели (строка, число, `ObjectId`, …). Нужен каждой операции модели с политикой [`tenant`](./schema-options.mdx#опция-tenant). Значение непустое — `null`, пустая строка и строка из пробелов отвергаются.", type: "unknown" },
    allTenants: { description: "Работа сразу по всем тенантам, например фоновая задача администратора. Политика тенанта операцию не ограничивает. Несовместим с `tenant`.", type: "true" },
    actor: { description: "Кто действует. Записывается в каждую запись [аудита](./schema-options.mdx#опция-audit).", type: "unknown" },
    includeDeleted: { description: "Операция видит и удалённые документы (политика [`softDelete`](./schema-options.mdx#опция-softdelete)). Несовместим с `onlyDeleted`.", type: "true" },
    onlyDeleted: { description: "Операция видит только удалённые документы. Так работает [`SoftDelete.restore`](./soft-delete-and-untrusted.mdx#softdeleterestore).", type: "true" },
    hardDelete: { description: "Удаление стирает документы навсегда, а не помечает. Так работает [`SoftDelete.purge`](./soft-delete-and-untrusted.mdx#softdeletepurge).", type: "true" },
  }}
/>

`tenant` и `actor` имеют тип `unknown`, потому что тип тенанта задаёт поле модели. Для `TenantField<string>` годится строка, для `TenantField<ObjectId>` — `ObjectId` или его строка. Значение приводится так же, как значение поля, а неподходящее вызывает [`CastError`](../errors/data-errors.mdx#casterror). Число для строкового поля даст `Cast to string failed at path "tenantId" for 5 (number): expected a string [type]`.

<FullType>

```ts
interface PolicyValues {
  readonly tenant?: unknown;
  readonly allTenants?: true;
  readonly actor?: unknown;
  readonly includeDeleted?: true;
  readonly onlyDeleted?: true;
  readonly hardDelete?: true;
}
```

</FullType>

## Когда не подходит

Контекст политик не заменяет фильтр. Ограничить выборку по обычному полю, например по владельцу счёта, нужно условием в фильтре. Политики отвечают за то, что нельзя ослабить ни в одном запросе модели. Если одной операции нужен другой тенант или другой режим удалённых, возьмите [`.policy()`](../query/options.mdx#policy), область открывать не придётся. Как контекст работает в задачах, смотрите в руководствах [Контекст политик](../../policies/policy-context.mdx) и [Мультитенантность](../../policies/tenants.mdx).
