На странице четыре элемента. [`SoftDelete.restore`](#softdeleterestore) и [`SoftDelete.purge`](#softdeletepurge) делают то, чего не умеет обычное удаление модели с [мягким удалением](./schema-options.mdx#опция-softdelete). Они возвращают помеченные документы или стирают их навсегда. [`untrusted`](#untrusted) и [`Untrusted.check`](#untrustedcheck) помечают данные из запроса клиента и отказывают, если внутри прячется оператор запроса. Если вы только начинаете, прочитайте руководства [Мягкое удаление](../../policies/soft-delete.mdx) и [Недоверенный ввод](../../policies/untrusted-input.mdx).

Примеры первой половины — блог. У поста есть заголовок и метка удаления.

```ts twoslash title="posts/post.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "posts", softDelete: true })
export class Post extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Date, { nullable: true })
  deletedAt?: Date | null;
}
```

## SoftDelete.restore

`restore` возвращает документы, помеченные удалёнными. Их метка снова становится `null`. Обычные операции модели удалённых документов не видят, поэтому сделать это ими нельзя. `restore` пригодится для кнопки «Отменить удаление», для корзины и для исправления ошибочной очистки.

Это обычная запись модели. Она ленивая, ничего не отправляется до `await`. У неё работают [`.session()`](../query/options.mdx#session) и [`.policy()`](../query/options.mdx#policy), хуки, аудит и политика тенанта. Внутри вызывается `updateMany` с `onlyDeleted`, так что живые документы `restore` не затронет.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, SoftDelete } from "@venloc/typemo";
@Schema({ collection: "posts", softDelete: true })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Date, { nullable: true }) deletedAt?: Date | null;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Posts = client.connection.model(Post);
// ---cut---
await Posts.deleteOne({ title: "Two" });
console.log(await Posts.countDocuments());
// → 2

const result = await SoftDelete.restore(Posts, { title: "Two" });
console.log(result.matchedCount, result.modifiedCount);
// → 1 1
console.log(await Posts.countDocuments());
// → 3
```

<Returns type="WriteBuilder<UpdateResult>">

Строитель записи. После `await` вы получаете результат обновления. `matchedCount` — сколько удалённых документов подошло под фильтр, `modifiedCount` — сколько восстановлено. Если подходящих удалённых документов нет, оба счётчика равны нулю, и ошибки нет.

</Returns>

<Params>
<Param name="model" type="Model<T>" required>

Модель с включённым `softDelete`. Для модели без мягкого удаления Typemo бросает `ConfigurationError: SoftDelete.restore: Plain has no soft delete; declare @Schema({ softDelete })`. Это происходит сразу при вызове, а не при `await`.

</Param>
<Param name="filter" type="Filter<T>" required>

Какие удалённые документы вернуть. Фильтр может назвать любой путь модели. Он обязателен и подчиняется тем же правилам, что фильтр `updateMany`. Пустой фильтр отвергает [`StrictModeError`](./violations.mdx#empty-filter), а «все удалённые» пишется как `Filters.all()` (см. [Пустые фильтры](../../writes/empty-filters.mdx)).

</Param>
</Params>

<FullType>

```ts
static restore<T extends object>(model: Model<T>, filter: Filter<T, true>): WriteBuilder<UpdateResult<IdOf<T>>>
```

</FullType>

## SoftDelete.purge

`purge` стирает мягко удалённые документы навсегда. Он нужен для очистки корзины по сроку давности и для просьбы «удалить мои данные». Обычное удаление модели с политикой документ только помечает.

Живых документов `purge` не трогает никогда, он работает в режиме «только удалённые». Перепутав фильтр, живую запись случайно не стереть. Сначала документ нужно удалить обычным образом.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, SoftDelete } from "@venloc/typemo";
@Schema({ collection: "posts", softDelete: true })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Date, { nullable: true }) deletedAt?: Date | null;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Posts = client.connection.model(Post);
// ---cut---
await Posts.deleteOne({ title: "Three" });
const purged = await SoftDelete.purge(Posts, { title: "Three" });
console.log(purged.deletedCount);
// → 1

const live = await SoftDelete.purge(Posts, { title: "One" });
console.log(live.deletedCount);
// → 0
```

<Returns type="WriteBuilder<DeleteResult>">

Строитель записи. После `await` вы получаете результат удаления, где `deletedCount` — сколько документов стёрто. Живой документ под фильтр не подходит. Счётчик тогда равен нулю, ошибки нет.

</Returns>

<Params>
<Param name="model" type="Model<T>" required>

Модель с включённым `softDelete`. Без него будет `ConfigurationError: SoftDelete.purge: Plain has no soft delete; declare @Schema({ softDelete })`.

</Param>
<Param name="filter" type="Filter<T>" required>

Какие удалённые документы стереть. Правила те же, что у `restore`.

</Param>
</Params>

<FullType>

```ts
static purge<T extends object>(model: Model<T>, filter: Filter<T, true>): WriteBuilder<DeleteResult>
```

</FullType>

Под капотом `purge` — это [`deleteMany`](../writes/writes.mdx#deletemany) с `onlyDeleted: true` и `hardDelete: true`. Те же два флага можно передать через [`.policy()`](../query/options.mdx#policy), но так задумано только для `purge`. Одиночный `deleteOne` с одним `hardDelete: true` сотрёт живой документ навсегда. `hardDelete` отключает лишь превращение удаления в пометку, а видимость определяет `onlyDeleted`.

## untrusted

`untrusted(value, place?)` помечает **данные из запроса клиента**, то есть тело запроса, строку запроса или разобранный JSON. Помечайте их до того, как положите в фильтр, обновление или проекцию. Второй аргумент говорит, куда данные попадут, и меняет только текст ошибки.

Внутри помеченного значения на любой глубине запрещён ключ, который начинается с `$`. Иначе клиент подменил бы значение оператором. Скажем, приложение ищет `find({ name: req.body.name })`, а клиент присылает `{"name": {"$ne": "zzz"}}`. Условие «имя равно» превращается в «имя не равно zzz», и находятся все документы. Ключ с `+` тоже запрещён. В проекции `+путь` добавляет [скрытое поле](../schemas/field-markers.mdx#hidden), и клиент мог бы получить хеш пароля.

```ts twoslash title="users/users.service.ts"
import { Entity, Prop, Schema, TypemoClient, untrusted } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Users = client.connection.model(User);
// ---cut---
export const findByName = async (body: unknown) => {
  return Users.find(untrusted({ name: (body as { name: unknown }).name }) as { name: string }).plain();
};
```

Функция возвращает то же значение, что получила, без изменений. Проверяет она только форму, то есть ключи. Типы, диапазоны и допустимые поля она не смотрит, поэтому `untrusted` — **дополнительная** защита, а не замена проверки ввода. Проверьте данные схемой валидации и постройте фильтр сами из проверенных значений. `untrusted` поймает то, что проверка пропустила.

Запрет срабатывает на любой глубине, включая массивы и `Map`. Ниже ошибка на глубине массива. Текст взят из реального запуска.

```ts twoslash
import { untrusted, StrictModeError } from "@venloc/typemo";
// ---cut---
try {
  untrusted({ a: [{ b: { $gt: 1 } }] });
} catch (error) {
  if (error instanceof StrictModeError) {
    console.log(error.message);
    // → untrusted value: "$gt" at "a.0.b.$gt" — an operator inside data from outside (query selector injection); validate the input and build the filter yourself [sanitize]
    console.log(error.reason, error.path);
    // → "sanitize" "a.0.b.$gt"
  }
}
```

### UntrustedPlace

Тип `UntrustedPlace` — это `"filter" | "update" | "projection"`, то есть место, куда попадут данные. Проверка для всех трёх одна, меняются только слова ошибки. Они объясняют, чем оператор грозит именно в этом месте. Без аргумента подразумевается фильтр. Тексты взяты из реального запуска.

```text
"filter": untrusted value: "$ne" at "title.$ne" — an operator inside data from outside (query selector injection); validate the input and build the filter yourself [sanitize]
"update": untrusted value: "$set" at "$set" — an operator inside data from outside would change what the update does (update operator injection); validate the input and build the update yourself [sanitize]
"projection": untrusted value: "$slice" at "a.$slice" — an operator inside data from outside would turn the projection into a computed expression; validate the input and build the projection yourself [sanitize]
```

Ключ с `+` тоже называется по месту. В проекции он добавил бы скрытое поле, а в фильтре и обновлении это вообще не имя поля.

```text
"projection": untrusted value: "+passwordHash" at "+passwordHash" — a "+path" key inside data from outside would select a Hidden field; validate the input and build the projection yourself [sanitize]
"filter":     untrusted value: "+passwordHash" at "+passwordHash" — a "+path" key inside data from outside is not a field name (in a projection it selects a Hidden field); validate the input and build the filter yourself [sanitize]
```

Если передать место не из этих трёх, Typemo бросает `QueryError`. Такое возможно только без типов — `untrusted(value, place): place must be "filter", "update" or "projection", got string "nope"`.

Для ключа с `+` в проекции, то есть в обычном случае, сообщение выглядит так — `untrusted value: "+passwordHash" at "+passwordHash" — a "+path" key inside data from outside would select a Hidden field; validate the input and build the projection yourself [sanitize]`.

<Returns type="V">

То же значение и тот же тип. Ничего не копируется и не преобразуется.

</Returns>

<Params>
<Param name="value" type="V" required>

Данные из запроса клиента. Проверку не проходят значения, которые по определению устроены как данные, — даты, регулярные выражения, двоичные представления и значения BSON.

</Param>
<Param name="place" type="UntrustedPlace" default='"filter"'>

Куда попадут данные, `"filter"`, `"update"` или `"projection"`. Меняет только текст ошибки.

</Param>
</Params>

<FullType>

```ts
type UntrustedPlace = "filter" | "update" | "projection";

const untrusted: <const V>(value: V, place?: UntrustedPlace) => V
```

</FullType>

### Что untrusted не делает

Он не проверяет значение, которое вы не пометили. Помечать нужно каждое значение, пришедшее из внешнего мира. Он не превращает объект в скаляр и не проверяет, можно ли вообще запрашивать это поле.

Фильтр Typemo допускает операторы полей (`$gt`, `$ne`) как обычное условие. Поэтому без `untrusted` фильтр `{"name":{"$ne":"zzz"}}` из JSON считается корректным и выполняется как «имя не равно zzz». Без `untrusted` его может отвергнуть только приведение типа, если значение не подходит полю. Например, `null` для обязательной строки даёт `CastError: Cast to string failed at path "title.$ne" for null: null is not a value of this path (it is not nullable); an absent field is { $exists: false } [null]`.

## Untrusted.check

`Untrusted.check` делает ту же проверку, что и [`untrusted`](#untrusted), но как явный вызов и без возврата значения. Берите его, когда значение надо проверить, а не пропускать через функцию. Например, чтобы проверить целый объект настроек перед сохранением.

```ts twoslash
import { Untrusted } from "@venloc/typemo";
// ---cut---
Untrusted.check({ d: new Date() });
// → нормально: дата — данные, внутрь не смотрим

try {
  Untrusted.check(new Map([["$x", 1]]));
} catch (error) {
  console.log((error as Error).message);
  // → untrusted value: "$x" at "$x" — an operator inside data from outside (query selector injection); validate the input and build the filter yourself [sanitize]
}
```

<Returns type="void">

Ничего не возвращает. Если внутри найден ключ с `$` или `+`, бросает [`StrictModeError`](./violations.mdx#sanitize) с причиной `sanitize`, а `path` ошибки показывает, где он найден. Если `place` не одно из трёх допустимых значений, бросает [`QueryError`](../errors/query-errors.mdx#queryerror). Циклические ссылки бесконечного обхода не вызывают.

</Returns>

<Params>
<Param name="value" type="unknown" required>

Что проверить.

</Param>
<Param name="place" type="UntrustedPlace" default='"filter"'>

Куда попадёт значение. Выбирает слова ошибки, как у [`untrusted`](#untrusted). Стоит вторым, сразу после значения. Других параметров у метода нет, обход вложенных объектов и защита от циклов работают внутри.

</Param>
</Params>

<FullType>

```ts
static check(value: unknown, place?: UntrustedPlace): void
```

</FullType>

## Когда не подходит

Мягкое удаление не заменяет архив. Помеченные документы остаются в той же коллекции и занимают место, а уникальные индексы без частичного условия продолжают их учитывать (см. [опцию `softDelete`](./schema-options.mdx#опция-softdelete)).

`untrusted` не заменяет проверку ввода. Строгие правила фильтров, включая защиту от неизвестных операторов и `$where`, работают всегда и без него. Подробнее в [Нарушениях политик](./violations.mdx#sanitize).
