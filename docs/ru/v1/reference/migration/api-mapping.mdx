Эта страница — справочник для тех, кто переносит код с Mongoose 9: слева то, что вы пишете сейчас, справа то, что писать в Typemo, а если аналога нет — «нет» и причина. Если вы только выбираете, переходить ли, начните с руководства [Зачем переходить](../../migration/why.mdx); порядок работы — в руководстве [Пошаговая миграция](../../migration/step-by-step.mdx), а все различия в поведении объяснены в [Отличиях в поведении](../../migration/behavior-differences.mdx).

Страница состоит из таблиц: это перечень сопоставлений «имя ↔ имя», объяснения в нём нарочно короткие. Если у сопоставления есть подвох, в третьем столбце сказано, какой, и есть ссылка туда, где он разобран. Строка с пометкой «нет» значит: такого элемента в публичном API Typemo нет, и причина в том, что он существует ради поведения, от которого Typemo отказался. Все факты о Mongoose проверены по исходникам версии 9.10.2, факты о Typemo — по коду и запуском.

Общее для всей страницы: Typemo не создаёт ничего неявно (коллекции и индексы — только по вашей команде), не приводит типы молча и не отбрасывает то, что не понял, а бросает ошибку. Из этого вытекает большая часть строк «нет».

## Схемы

В Mongoose схема — это объект `new Schema({...})`, а модель получается вызовом `mongoose.model`. В Typemo схема — это класс: тип документа, схема для базы и валидатор описываются одним объявлением, и разойтись им не с чем.

| Mongoose | Typemo | Что важно |
|---|---|---|
| `new Schema({ … })` | класс с [`@Schema`](../schemas/schema.mdx#schema), поля с [`@Prop`](../schemas/prop.mdx#prop) | Тип каждого поля явный: `@Prop(() => String)`. Поле без декоратора не попадает в схему |
| `mongoose.model("User", schema)` | [`client.db().model(User)`](../connection/connection.mdx#connectionmodel) | Модель принадлежит подключению; глобальной модели нет |
| `Schema.Types.ObjectId` с `ref` | [`Types.ObjectId`](../schemas/types-and-spec.mdx#types) и опция [`ref`](../schemas/prop.mdx#ref), тип поля [`Ref<User>`](../schemas/field-markers.mdx#ref) | Ссылка в модели — обычный `ObjectId`, а заполненная — документ; тип это различает |
| `Schema.Types.Mixed`, `{}`, `Object`, массив без типа | нет | Поле неизвестной формы — то, что строгость запрещает: нечего проверять и нечем типизировать. Замены — вложенный класс или [`Spec.map`](../schemas/types-and-spec.mdx#specmap). Подробнее в [Чего нет в Typemo](../../migration/missing-features.mdx) |
| `Decimal128`, `Int32`, `Double`, `UUID`, `Buffer` | [`Types.Decimal128`, `Types.Int32`, `Types.Double`, `Types.UUID`, `Types.Binary`](../schemas/types-and-spec.mdx#types) | `Long` объявляется как `BigInt`. `Buffer` из строки или числа не создаётся |
| `Schema.Types.Map` с `of` | [`Spec.map(X)`](../schemas/types-and-spec.mdx#specmap) | Ключи и значения проверяются, `Map` без `of` — ошибка |
| `[String]`, `[subSchema]` | `@Prop(() => [String])`, `@Prop(() => [Line])` | Массив поддокументов — [`SubdocumentArray`](../documents/typed-collections.mdx#subdocumentarray). Пустой массив по умолчанию подставляется, как в Mongoose: `default` не нужен |
| вложенная `new Schema` как поддокумент | класс с [`@Schema({ nested: true })`](../schemas/schema.mdx#nested) | У вложенного объекта нет `_id` и собственных хуков |
| `required`, `default`, `enum`, `min`, `max`, `minLength`, `maxLength`, `match`, `trim`, `lowercase`, `uppercase`, `immutable` | опции [`@Prop`](../schemas/prop.mdx#required) с теми же именами | `required` — явная опция, `null` разрешает только [`nullable`](../schemas/prop.mdx#nullable) |
| `validate` | опция [`validate`](../schemas/prop.mdx#validate) | Контекст проверки — второй аргумент, а не `this` |
| `get`, `set` | опции [`get`](../schemas/prop.mdx#get) и [`set`](../schemas/prop.mdx#set) | `get` работает только через `$get` и `$toObject({ getters: true })`, а не при чтении свойства |
| `select: false` | [`hidden: true`](../schemas/prop.mdx#hidden) и тип [`Hidden<T>`](../schemas/field-markers.mdx#hidden) | Скрытое поле видно компилятору: вернуть его можно только явным `+поле` |
| `alias` | опция [`dbName`](../schemas/prop.mdx#dbname) | Обратное направление: имя свойства — имя в коде, `dbName` — имя в базе |
| `index`, `unique`, `sparse`, `expires`, `text` на поле | одноимённые опции [`@Prop`](../schemas/prop.mdx#index) | `expires` — целое число секунд, строк вроде `"1.5m"` нет |
| `schema.index({ a: 1, b: -1 })` | декоратор [`@Index`](../schemas/index-decorators.mdx#index) | Направления только `1`, `-1`, `"hashed"` |
| `schema.index({ x: "text" })`, Atlas Search | [`text`](../schemas/prop.mdx#text), [`@SearchIndex`](../schemas/index-decorators.mdx#searchindex) | |
| `timestamps: true` | базовый класс [`Timestamped`](../schemas/base-classes.mdx#timestamped) | Поля `createdAt` и `updatedAt` видны в типе |
| `versionKey`, `__v` | базовый класс [`Versioned`](../schemas/base-classes.mdx#versioned) | Без него версии нет вообще |
| автоматический `_id` и виртуал `id` | базовый класс [`Entity`](../schemas/base-classes.mdx#entity); виртуала `id` нет | Модель без `_id` — `ConfigurationError`. Строка вместо `ObjectId` — в plain-виде, где `_id` уже строка |
| `_id: String`, `_id: Number`, `_id: UUID` в схеме | базовый класс [`EntityWithId(() => String)`](../schemas/base-classes.mdx#entitywithid) | Не объявляйте `_id` в классе вручную. Без `default` идентификатор обязателен в `create`; руководство — [Свой тип `_id`](../../schemas/custom-ids.mdx) |
| `_id: false` | нет у модели; у поддокумента — [`nested: true`](../schemas/schema.mdx#nested) | Документ коллекции без `_id` невозможен |
| `collection`, `capped`, `timeseries`, `collation`, `shardKey`, `readConcern`, `writeConcern`, `optimisticConcurrency` | опции [`@Schema`](../schemas/schema.mdx#collection) с теми же именами | `optimisticConcurrency` принимает только список путей, у `{ exclude }` аналога нет |
| `autoIndex`, `autoCreate` | опции [`autoIndex` и `autoCreate`](../schemas/schema.mdx#autocreate) | Действуют только при явном [`connection.init()`](../connection/connection.mdx#connectioninit). Само по себе создание модели ничего не создаёт |
| `strict`, `strictQuery`, `useNestedStrict`, `strictRead` | нет | Строгость абсолютная и не отключается: [`StrictModeError`](../errors/data-errors.mdx#strictmodeerror) и `CastError` вместо тихого поведения |
| `minimize`, `typeKey`, `id`, `bufferCommands`, `bufferTimeoutMS`, `selectPopulatedPaths`, `skipVersioning`, `validateBeforeSave`, `validateModifiedOnly`, `lean` схемы, `pluginTags`, `collectionOptions` | нет | Каждая из них меняет поведение неявно для читателя кода. Пустые объекты не вырезаются, ожидание подключения настраивается в клиенте ([`readyTimeoutMS`](../connection/typemo-client.mdx#опции-клиента)), проверка при сохранении не отключается |
| `toJSON`, `toObject` в схеме | нет; опции передаются при вызове [`$toObject`, `$toPlain`, `$toJSON`](../documents/document-api.mdx#toobject) | Схемные опции меняли форму результата там, где вызывающий этого не видел; опция схемы `@Schema({ toJSON })` — ошибка |
| `Schema#discriminator`, `discriminatorKey` | [`@Discriminator`](../schemas/discriminator.mdx#discriminator), опция [`discriminatorKey`](../schemas/schema.mdx#discriminatorkey) | Значение дискриминатора — литерал; неизвестное значение в базе — `CastError`, а не молчаливая базовая модель. Значение ключа после создания неизменяемо |
| `schema.virtual("posts", { ref, … })` | декоратор [`@Virtual`](../schemas/virtual.mdx#virtual) | Виртуальные свойства без `ref` — вычисляемые поля, см. [`Computed`](../schemas/field-markers.mdx#computed) |
| `schema.methods`, `schema.loadClass` | обычные методы класса | Класс и есть схема, `loadClass` не нужен. Инициализатор у поля с `@Prop` — ошибка |
| `schema.statics`, `schema.query` | нет; для общих статических функций — плагин с [`statics`](../hooks/plugins.mdx#pluginstatics) | Методы запроса-помощники заменяются функциями над строителем |
| `schema.pre`, `schema.post` | [`@Pre`, `@Post`, `@PostError`](../hooks/pre-post.mdx#pre) | Разобрано в таблице [Хуки и плагины](#хуки-и-плагины) |
| `schema.plugin(fn)` | декоратор [`@Plugin`](../hooks/plugins.mdx#plugin) | Плагин — объект, а не функция |
| `schema.set`, `schema.add`, `schema.path`, `schema.clone` | нет | Схема не изменяется после объявления. Описание схемы для чтения — [`describe`](../schemas/schema-info.mdx#describe) |
| `schema.toJSONSchema()` | [`JsonSchemaGenerator.generate`](../schemas/json-and-standard-schema.mdx#jsonschemageneratorgenerate) | Дополнительно есть [`StandardSchema`](../schemas/json-and-standard-schema.mdx#standardschema) |

## Модели и запросы

В Mongoose запрос — объект `Query`, с которым можно делать что угодно до выполнения. В Typemo это [строитель запроса](../query/reading.mdx#как-работает-строитель): такой же цепочечный, но фильтр, проекция и сортировка проверяются типами и в момент построения.

| Mongoose | Typemo | Что важно |
|---|---|---|
| `Model.find`, `findOne` | [`Model.find`](../query/reading.mdx#modelfind), [`Model.findOne`](../query/reading.mdx#modelfindone) | Неизвестное поле в фильтре — ошибка типа и `StrictModeError`, а не пустой результат |
| `Model.findById` | [`Model.findById`](../query/reading.mdx#modelfindbyid) | Принимает строку id; неверная строка — `CastError`. Пустой id — ошибка, а не поиск по `null` |
| `Model.exists` | [`Model.exists`](../query/reading.mdx#modelexists) | |
| `Model.countDocuments`, `estimatedDocumentCount` | [`countDocuments`](../query/reading.mdx#modelcountdocuments), [`estimatedDocumentCount`](../query/reading.mdx#modelestimateddocumentcount) | На дискриминаторе `estimatedDocumentCount` — ошибка: он считает всю коллекцию |
| `Model.distinct` | [`Model.distinct`](../query/reading.mdx#modeldistinct) | |
| `.lean()` | [`.lean()`](../query/reading.mdx#lean) и [`.plain()`](../query/reading.mdx#plain) | `lean` оставляет `ObjectId`, `plain` превращает значения в JSON-формы (`_id` — строка).  |
| `.select("a -b")`, `.select({ a: 1 })` | [`.select({ a: 1 })`](../query/reading.mdx#select) | Только объект. Смесь включения и исключения — ошибка, `+поле` — только для скрытых полей |
| `.sort("-age name")`, `.sort({ age: -1 })` | [`.sort({ age: -1 })`](../query/reading.mdx#sort) или список пар | Строки-DSL нет. Путь дважды — ошибка |
| `.limit`, `.skip` | [`.limit`](../query/reading.mdx#limit), [`.skip`](../query/reading.mdx#skip) | `limit("5")` не приводится; `0` и отрицательные — ошибка (в базе `limit(0)` значит «без предела») |
| `.orFail()` | [`.orFail()`](../query/reading.mdx#orfail) | На `find` бросает [`DocumentNotFoundError`](../errors/query-errors.mdx#documentnotfounderror) при пустом списке |
| `.populate()` | [`.populate()`](../populate/populate.mdx#populate) | См. раздел [Populate](#populate) |
| `.cursor()`, `.eachAsync`, `for await` | [`.cursor()`](../query/reading.mdx#cursor), [`.eachAsync`](../query/cursor.mdx#eachasync) | Ошибка обработчика приходит как [`EachAsyncError`](../query/cursor.mdx#eachasyncerror) |
| `.exec()`, `await query` | [`.exec()`](../query/reading.mdx#exec), `await` | Повторный `await` читателя даёт тот же результат без запроса; в Mongoose он бросает `Query was already executed` |
| `.where("a").gt(1)`, `.equals`, `.in`, `.nin`, `.exists`, `.regex`, `.mod`, `.size`, `.all`, `.elemMatch`, `.or`, `.and`, `.nor` | [`.where`](../query/conditions.mdx#where) и цепочка условий на странице [`conditions`](../query/conditions.mdx) | Значения сверяются с типом поля |
| `.merge(query)` | [`.merge`](../query/conditions.mdx#merge) | Только запрос той же модели |
| `.session()` | [`.session()`](../query/options.mdx#session) | Внутри `transaction` сессия подставляется сама |
| `.hint`, `.collation`, `.comment`, `.batchSize`, `.allowDiskUse` | [`.hint`](../query/options.mdx#hint), [`.collation`](../query/options.mdx#collation), [`.comment`](../query/options.mdx#comment), [`.batchSize`](../query/options.mdx#batchsize), [`.allowDiskUse`](../query/options.mdx#allowdiskuse) | |
| `.maxTimeMS()` | [`.timeoutMS()`](../query/options.mdx#timeoutms) | Единственный способ ограничить время: клиентский тайм-аут драйвера |
| `.read()` | [`.readPreference()`](../query/options.mdx#readpreference) | Внутри транзакции предпочтение чтения, отличное от primary, — ошибка |
| `.explain()` | [`.explain()`](../query/search-and-explain.mdx#explain) | Только для `find` и `findOne` |
| `.setOptions`, `.getFilter`, `.getUpdate`, `.getOptions`, `.projection`, `.cast`, `.transform`, `.tailable`, `.slice`, `.error`, `.j`, `.w`, `.wtimeout`, `.snapshot`, `.$where` | нет | Каждый метод либо читает и меняет внутреннее состояние запроса, либо передаёт драйверу сырые опции, минуя проверки. Вмешаться в операцию можно [хуком](../../hooks/operation-hooks.mdx) |
| `.sanitizeFilter` и опция `sanitizeFilter` | нет | Проверка включена всегда: оператор в значении, пришедшем извне, нужно явно пометить как недоверенный, см. [Отличия в поведении](../../migration/behavior-differences.mdx) |
| `Model.aggregate([{ $match: … }])` | `Model.aggregate((p) => p.match(…))` | Стадии — типизированные методы конвейера, сырых стадий нет. См. руководство [Первая агрегация](../../aggregation/first-aggregation.mdx) и справочник [`Pipeline` и `Model.aggregate`](../aggregation/pipeline.mdx) |
| `Model.watch()` | [`Model.watch`](../change-streams/watch.mdx#modelwatch) | Возвращает асинхронный итератор, а не `EventEmitter` |
| `Model.hydrate`, `Model.castObject`, `Model.validate` | [`Model.hydrate`](../documents/model-document-methods.mdx#modelhydrate), [`Model.castObject`](../documents/model-document-methods.mdx#modelcastobject), [`Model.validate`](../documents/model-document-methods.mdx#modelvalidate) | |
| `new Model({…})` | [`Model.new`](../documents/model-document-methods.mdx#modelnew) | Класс модели не вызывается через `new`: модель — объект подключения |
| `Model.init`, `createCollection`, `createIndexes`, `ensureIndexes`, `syncIndexes`, `cleanIndexes`, `listIndexes` | [`connection.init`](../connection/connection.mdx#connectioninit), [`Model.createCollection`](../collections/collection-manager.mdx#modelcreatecollection), [`createIndexes`](../collections/model-indexes.mdx#modelcreateindexes), [`syncIndexes`](../collections/model-indexes.mdx#modelsyncindexes), [`listIndexes`](../collections/model-indexes.mdx#modellistindexes), [`diffIndexes`](../collections/model-indexes.mdx#modeldiffindexes) | `ensureIndexes` и `cleanIndexes` нет: первый устарел, вторую заменяет `syncIndexes` с `dryRun`. Сбой синхронизации не пропускается: `init()` и `syncAll()` бросают [`SyncError`](../errors/configuration-errors.mdx#syncerror) |
| `Model.startSession()` | [`client.startSession`](../connection/typemo-client.mdx#clientstartsession) | |
| `Model.populate(docs, paths)`, `Model.translateAliases`, `Model.where`, `Model.$where`, `Model.discriminator(…)`, `Model.collection`, `Model.db` | нет | Заполнение уже загруженных документов — [`$populate`](../documents/document-api.mdx#populate) на документе; имена `dbName` переводятся сами; дискриминатор — декоратор; драйвер — [`client.unsafeDriver()`](../connection/typemo-client.mdx#clientunsafedriver) |

## Записи

Главное различие — в умолчаниях: `findOneAndUpdate` возвращает документ **после** изменения, проверки значений включены всегда, а пустая или «не операторная» запись — ошибка.

| Mongoose | Typemo | Что важно |
|---|---|---|
| `Model.create`, `new Model().save()` | [`Model.create`](../writes/writes.mdx#create) | `create([...])` — всегда один упорядоченный `insertMany`. Опции `ordered` у него нет |
| `Model.insertMany` | [`insertMany`](../writes/writes.mdx#insertmany) | Неупорядоченная вставка с невалидными документами завершается [`BulkWriteError`](../errors/server-errors.mdx#bulkwriteerror), а не молчит |
| `Model.updateOne`, `updateMany` | [`updateOne`](../writes/writes.mdx#updateone), [`updateMany`](../writes/writes.mdx#updatemany) | Только операторы: `{ title: "x" }` без `$set` — ошибка |
| `Model.replaceOne` | [`replaceOne`](../writes/writes.mdx#replaceone) | `createdAt` сохраняется, неизменяемое поле обязано быть в замене |
| `findOneAndUpdate`, `findByIdAndUpdate` | [`findOneAndUpdate`](../writes/writes.mdx#findoneandupdate), [`findByIdAndUpdate`](../writes/writes.mdx#findbyidandupdate) | По умолчанию документ **после** изменения. `new: true` и `returnOriginal` нет: `returnDocument: "before"` даёт прежний |
| `findOneAndReplace`, `findOneAndDelete`, `findByIdAndDelete` | [`findOneAndReplace`](../writes/writes.mdx#findoneandreplace), [`findOneAndDelete`](../writes/writes.mdx#findoneanddelete), [`findByIdAndDelete`](../writes/writes.mdx#findbyidanddelete) | |
| `deleteOne`, `deleteMany` | [`deleteOne`](../writes/writes.mdx#deleteone), [`deleteMany`](../writes/writes.mdx#deletemany) | Пустой фильтр — `StrictModeError`; удалить всё сознательно — `Filters.all()` |
| `bulkWrite`, `bulkSave` | [`bulkWrite`](../writes/writes.mdx#bulkwrite), [`bulkSave`](../writes/writes.mdx#bulksave) | Ошибки собираются в `BulkWriteError` с индексами входных элементов. Каждая операция проверяется схемой (в Mongoose — только `insertOne` и `replaceOne`) и запускает хуки одиночного аналога |
| `{ upsert: true }` | [`upsert`](../writes/writes.mdx#upsert) | С `upsert: true` и `"after"` результат никогда не `null` |
| `{ new: true }` / `{ returnDocument }` | [`returnDocument`](../writes/writes.mdx#returndocument) | Только `"before"` и `"after"` |
| `{ runValidators: true }`, `{ context: "query" }` | нет | Проверки включены всегда, для `$set`, `$setOnInsert`, `$min`, `$max`, `$push`, `$addToSet` |
| `{ setDefaultsOnInsert }`, `{ timestamps: false }`, `{ strict }`, `{ overwriteDiscriminatorKey }`, `{ omitUndefined }` | нет | Значения по умолчанию и метки времени ведёт ядро, `strict` не отключается, значение ключа дискриминатора неизменяемо, `undefined` — ошибка, а не пропуск. Опции `timestamps` у записи нет |
| `{ arrayFilters }` | [`arrayFilters`](../writes/writes.mdx#arrayfilters) | Должны точно соответствовать идентификаторам `$[id]`: лишний или недостающий — ошибка до отправки |
| `{ rawResult: true }` | опция `includeResultMetadata`, см. [`findOneAndUpdate`](../writes/writes.mdx#сырой-результат) | |
| `{ session }`, `{ writeConcern }`, `{ ordered }`, `{ maxTimeMS }` | [`.session`](../writes/writes.mdx#строитель-записи), [`.writeConcern`](../writes/writes.mdx#строитель-записи), [`ordered`](../writes/writes.mdx#ordered), `.timeoutMS` | |
| `updateOne(f, [ { $set } ], { updatePipeline: true })` | `updateOne(f, (p) => p.set(…))` | Стадии обновления типизированы: [`UpdatePipelines`](../writes/pipeline-updates.mdx#updatepipelines) |
| `$inc`, `$set`, `$push`, `$pull`, `$addToSet`, `$pop`, `$unset`, `$rename`, `$min`, `$max`, `$mul`, `$currentDate`, `$bit` | [операторы обновления](../writes/update-operators.mdx#set) с теми же именами | Путь под двумя операторами сразу — ошибка |

## Документы

В Mongoose у документа свойства и методы вперемешку с вашими полями (`doc.isNew`, `doc.save()`). В Typemo все служебные члены начинаются с `$`, поэтому поле пользователя с любым именем ничему не мешает.

| Mongoose | Typemo | Что важно |
|---|---|---|
| `doc.save()` | [`doc.$save()`](../documents/document-api.mdx#save) | Пустое сохранение ничего не отправляет. Хук `save` вызывается всегда |
| `doc.set(path, value)`, `doc.get(path)` | [`$set`](../documents/document-api.mdx#set), [`$get`](../documents/document-api.mdx#get) | Значение приводится сразу, ошибка каста бросается, а не откладывается |
| `doc.isNew`, `isModified`, `markModified` | [`$isNew()`](../documents/document-api.mdx#isnew), [`$isModified()`](../documents/document-api.mdx#ismodified), [`$markModified()`](../documents/document-api.mdx#markmodified) | Методы, а не свойства |
| `doc.validate()` | [`$validate`](../documents/document-api.mdx#validate) | |
| `doc.deleteOne()`, `doc.updateOne()` | [`$deleteOne`](../documents/document-api.mdx#deleteone), [`$updateOne`](../documents/document-api.mdx#updateone) | `$deleteOne` не запускает хуки запроса |
| `doc.populate()`, `depopulate`, `populated`, `$assertPopulated` | [`$populate`](../documents/document-api.mdx#populate), [`$depopulate`](../documents/document-api.mdx#depopulate), [`$populated`](../documents/document-api.mdx#populated), [`$assertPopulated`](../documents/document-api.mdx#assertpopulated) | Заполненный массив — представление только для чтения |
| `doc.toObject()`, `doc.toJSON()` | [`$toObject`](../documents/document-api.mdx#toobject), [`$toPlain`](../documents/document-api.mdx#toplain), [`$toJSON`](../documents/document-api.mdx#tojson) | `JSON.stringify(doc)` работает и даёт то же, что `$toJSON()` с настройками по умолчанию |
| `doc.id` | нет | Идентификатор — `_id` типа `ObjectId`; строка — в plain-виде и в `$toJSON()` |
| `doc.$locals`, `doc.$session()` | [`$locals`](../documents/document-api.mdx#locals), [`$session`](../documents/document-api.mdx#session) | |
| `doc.errors`, `doc.invalidate`, `doc.$isValid`, `doc.directModifiedPaths`, `doc.modifiedPaths()`, `doc.$clone`, `doc.overwrite`, `doc.equals`, `doc.collection` | нет; сравнение — [`$is`](../documents/document-api.mdx#is), изменения — [`$getChanges`](../documents/document-api.mdx#getchanges) | Накопленного состояния ошибок нет: проверка либо проходит, либо бросает [`ValidationError`](../errors/data-errors.mdx#validationerror) |
| `MongooseArray`, `.$pop`, `.nonAtomicPush`, `.$shift`, `$atomics` | [`StrictArray`](../documents/typed-collections.mdx#strictarray) и его методы | Запись `arr[i] = x` и `arr.length = 0` не компилируются: нужны `set`, `clear`, `splice`, `replace` |
| `DocumentArray.id()`, `.create()`, `.pull()` | [`SubdocumentArray.id`](../documents/typed-collections.mdx#subdocumentarrayid), [`create`](../documents/typed-collections.mdx#subdocumentarraycreate), [`pull`](../documents/typed-collections.mdx#subdocumentarraypull) | `id` с неверным значением — `CastError`, а не `null` |
| `Map` | [`TypedMap`](../documents/typed-collections.mdx#typedmap) | Ошибка каста значения бросается сразу |
| `subdoc.deleteOne()`, `subdoc.remove()` | нет; удаление — `pull(subdoc)` на массиве | Поддокумент не знает, как удалить себя из родителя, пока не вставлен |
| поле, которого нет в схеме, в поддокументе | [`unknownFieldsOf`](../documents/unknown-fields.mdx#unknownfieldsof), [`UnknownFieldsError`](../documents/unknown-fields.mdx#unknownfieldserror) | Mongoose стёр бы такие поля при перезаписи поддокумента; Typemo отказывает |

| `refPath` | опции [`refPath`](../schemas/prop.mdx#refpath) и [`refModel`](../schemas/prop.mdx#refmodel) | `refPath` — путь внутри самого документа со ссылкой, а не от корня |

| `strictPopulate`, `forceRepopulate`, `populate({ model })`, `options.options` | нет | Неизвестный путь — всегда ошибка; повторный `populate` всегда заменяет предыдущий; модель определяется полем |

| `push(id)` в заполненный массив | нет | Заполненный массив — представление только для чтения; ссылки меняются через сохранённые идентификаторы |

|---|---|---|
| `schema.pre("save", fn)` | [`@Pre("document.save")`](../hooks/pre-post.mdx#pre) на методе класса | События имеют область: `document.save`, `query.find`, `model.insertMany` |

| `next()` в `pre` | нет | В девятой версии Mongoose `next` в `pre` уже убран, хуки — асинхронные функции. В Typemo хук — метод, ошибка — исключение |
| `this` как `Query` в запросных хуках | `this` — типизированный контекст [`OperationHookContext`](../hooks/operation-context.mdx#operationhookcontext) | Значения операции только для чтения; изменение — [`.modify`](../hooks/operation-context.mdx#modify), пропуск — [`.skip`](../hooks/operation-context.mdx#skip) |

| сторонние плагины soft delete, tenant, audit | встроенные политики: [мягкое удаление](../../policies/soft-delete.mdx), [тенанты](../../policies/tenants.mdx), [аудит](../../policies/audit.mdx) | Действуют на всех операциях и путях, включая агрегацию. Поле тенанта помечается [`@Tenant()`](../schemas/field-markers.mdx#tenant) |

## Ошибки

Ошибки Typemo образуют единую иерархию от [`TypemoError`](../errors/hierarchy.mdx#typemoerror), у каждой есть `cause`. Драйверные ошибки не пробрасываются как есть: каждая классифицирована.

| Mongoose | Typemo | Что важно |
|---|---|---|
| `mongoose.Error.ValidationError`, `ValidatorError` | [`ValidationError`](../errors/data-errors.mdx#validationerror) | Поля ошибки описаны в справочнике |
| `mongoose.Error.CastError` | [`CastError`](../errors/data-errors.mdx#casterror) | Есть поле `reason` с причиной: `type`, `format`, `range`, `null`, `unknown-key` |
| `DocumentNotFoundError` | [`DocumentNotFoundError`](../errors/query-errors.mdx#documentnotfounderror) | Фильтр в ошибке не хранится |
| `VersionError` | [`VersionError`](../errors/query-errors.mdx#versionerror) | |
| `StrictModeError`, `StrictPopulateError` | [`StrictModeError`](../errors/data-errors.mdx#strictmodeerror) | Одна ошибка с `reason` вместо набора |
| `MongoServerError` с кодом 11000 | [`DuplicateKeyError`](../errors/server-errors.mdx#duplicatekeyerror) | Остальные серверные коды — [`ServerError`](../errors/server-errors.mdx#servererror) и потомки |
| `MongoBulkWriteError` | [`BulkWriteError`](../errors/server-errors.mdx#bulkwriteerror) | Индексы входных элементов и коды сохраняются |
| `OverwriteModelError` | нет: повторный `model(Post)` на том же подключении возвращает ту же модель | Второй экземпляр модели создать нельзя, поэтому и переопределять нечего |
| `MissingSchemaError` | [`ConfigurationError`](../errors/configuration-errors.mdx#configurationerror) | Класс без `@Schema` или без `_id` не становится моделью |
| `err instanceof mongoose.Error` | `err instanceof TypemoError` | Все ошибки библиотеки — потомки одного класса |
