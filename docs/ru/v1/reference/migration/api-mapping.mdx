Справочник для тех, кто переносит код с Mongoose 9. Слева то, что вы пишете сейчас, справа то, что писать в Typemo. Если аналога нет, там стоит «нет» и причина. Ещё выбираете, переходить ли? Начните с руководства [Зачем переходить](../../migration/why.mdx). Порядок работы описан в [Пошаговой миграции](../../migration/step-by-step.mdx), а все различия в поведении разобраны в [Отличиях в поведении](../../migration/behavior-differences.mdx).

Страница состоит из таблиц «имя ↔ имя», и объяснения в них нарочно короткие. Если у сопоставления есть подвох, он назван в третьем столбце, там же ссылка на разбор. Строка с пометкой «нет» значит, что такого элемента в публичном API Typemo нет. Он существовал ради поведения, от которого Typemo отказался. Факты о Mongoose проверены по исходникам версии 9.10.2, факты о Typemo — по коду и запуском.

Есть и общее для всей страницы. Typemo ничего не создаёт неявно (коллекции и индексы — только по вашей команде), не приводит типы молча и не отбрасывает то, чего не понял, а бросает ошибку. Из этого следует большая часть строк «нет».

## Схемы [#schemas]

В Mongoose схема — объект `new Schema({...})`, а модель получается вызовом `mongoose.model`. В Typemo схема — класс. Тип документа, схема для базы и валидатор описаны одним объявлением, и разойтись им не с чем.

| Mongoose | Typemo | Что важно |
|---|---|---|
| `new Schema({ … })` | класс с [`@Schema`](../schemas/schema.mdx#schema), поля с [`@Prop`](../schemas/prop.mdx#prop) | Тип каждого поля явный, `@Prop(() => String)`. Поле без декоратора в схему не попадает |
| `mongoose.model("User", schema)` | [`client.db().model(User)`](../connection/connection.mdx#connection.model) | Модель принадлежит подключению, глобальной модели нет |
| `Schema.Types.ObjectId` с `ref` | [`Types.ObjectId`](../schemas/types-and-spec.mdx#types) и опция [`ref`](../schemas/prop.mdx#ref), тип поля [`Ref<User>`](../schemas/field-markers.mdx#ref) | Ссылка в модели — обычный `ObjectId`, а заполненная — документ. Тип их различает |
| `Schema.Types.Mixed`, `{}`, `Object`, массив без типа | нет | Поле неизвестной формы строгость запрещает, его нечем проверять и нечем типизировать. Замены — вложенный класс или [`Spec.map`](../schemas/types-and-spec.mdx#spec.map). Подробнее в [Чего нет в Typemo](../../migration/missing-features.mdx) |
| `Decimal128`, `Int32`, `Double`, `UUID`, `Buffer` | [`Types.Decimal128`, `Types.Int32`, `Types.Double`, `Types.UUID`, `Types.Binary`](../schemas/types-and-spec.mdx#types) | `Long` объявляется как `BigInt`. `Buffer` из строки или числа не создаётся |
| `Schema.Types.Map` с `of` | [`Spec.map(X)`](../schemas/types-and-spec.mdx#spec.map) | Ключи и значения проверяются, а `Map` без `of` — ошибка |
| `[String]`, `[subSchema]` | `@Prop(() => [String])`, `@Prop(() => [Line])` | Массив поддокументов — [`SubdocumentArray`](../documents/typed-collections.mdx#subdocument-array). Пустой массив по умолчанию подставляется, как в Mongoose, так что `default` не нужен |
| вложенная `new Schema` как поддокумент | класс с [`@Schema({ nested: true })`](../schemas/schema.mdx#nested) | У вложенного объекта нет `_id` и собственных хуков |
| `required`, `default`, `enum`, `min`, `max`, `minLength`, `maxLength`, `match`, `trim`, `lowercase`, `uppercase`, `immutable` | опции [`@Prop`](../schemas/prop.mdx#required) с теми же именами | `required` — явная опция, `null` разрешает только [`nullable`](../schemas/prop.mdx#nullable) |
| `validate` | опция [`validate`](../schemas/prop.mdx#validate) | Контекст проверки идёт вторым аргументом, а не через `this` |
| `get`, `set` | опции [`get`](../schemas/prop.mdx#get) и [`set`](../schemas/prop.mdx#set) | `get` работает только через `$get` и `$toObject({ getters: true })`, а не при чтении свойства |
| `select: false` | [`hidden: true`](../schemas/prop.mdx#hidden) и тип [`Hidden<T>`](../schemas/field-markers.mdx#hidden) | Скрытое поле видно компилятору. Вернуть его можно только явным `+поле` |
| `alias` | опция [`dbName`](../schemas/prop.mdx#db-name) | Направление обратное. Имя свойства — имя в коде, `dbName` — имя в базе |
| `index`, `unique`, `sparse`, `expires`, `text` на поле | одноимённые опции [`@Prop`](../schemas/prop.mdx#index) | `expires` — целое число секунд, строк вроде `"1.5m"` нет |
| `schema.index({ a: 1, b: -1 })` | декоратор [`@Index`](../schemas/index-decorators.mdx#index) | Направления только `1`, `-1`, `"hashed"` |
| `schema.index({ x: "text" })`, Atlas Search | [`text`](../schemas/prop.mdx#text), [`@SearchIndex`](../schemas/index-decorators.mdx#search-index) | |
| `timestamps: true` | базовый класс [`Timestamped`](../schemas/base-classes.mdx#timestamped) | Поля `createdAt` и `updatedAt` видны в типе |
| `versionKey`, `__v` | базовый класс [`Versioned`](../schemas/base-classes.mdx#versioned) | Без него версии нет вообще |
| автоматический `_id` и виртуал `id` | базовый класс [`Entity`](../schemas/base-classes.mdx#entity), виртуала `id` нет | Модель без `_id` — `ConfigurationError`. Строка вместо `ObjectId` приходит в результате `.plain()`, там `_id` уже строка |
| `_id: String`, `_id: Number`, `_id: UUID` в схеме | базовый класс [`EntityWithId(() => String)`](../schemas/base-classes.mdx#entity-with-id) | Не объявляйте `_id` в классе вручную. Без `default` идентификатор обязателен в `create`. Подробности в руководстве [Свой тип `_id`](../../schemas/custom-ids.mdx) |
| `_id: false` | нет у модели, у поддокумента — [`nested: true`](../schemas/schema.mdx#nested) | Документ коллекции без `_id` невозможен |
| `collection`, `capped`, `timeseries`, `collation`, `shardKey`, `readConcern`, `writeConcern`, `optimisticConcurrency` | опции [`@Schema`](../schemas/schema.mdx#collection) с теми же именами | `optimisticConcurrency` принимает только список путей, у `{ exclude }` аналога нет |
| `autoIndex`, `autoCreate` | опции [`autoIndex` и `autoCreate`](../schemas/schema.mdx#auto-create) | Действуют только при явном [`connection.init()`](../connection/connection.mdx#connection.init). Само создание модели ничего не создаёт |
| `strict`, `strictQuery`, `useNestedStrict`, `strictRead` | нет | Строгость абсолютная и не отключается. Вместо тихого поведения — [`StrictModeError`](../errors/data-errors.mdx#strict-mode-error) и `CastError` |
| `minimize`, `typeKey`, `id`, `bufferCommands`, `bufferTimeoutMS`, `selectPopulatedPaths`, `skipVersioning`, `validateBeforeSave`, `validateModifiedOnly`, `lean` схемы, `pluginTags`, `collectionOptions` | нет | Каждая из них неявно меняет поведение, и читатель кода этого не видит. Пустые объекты не вырезаются, ожидание подключения настраивается в клиенте ([`readyTimeoutMS`](../connection/typemo-client.mdx#client-options)), проверка при сохранении не отключается |
| `toJSON`, `toObject` в схеме | нет, опции передаются при вызове [`$toObject`, `$toPlain`, `$toJSON`](../documents/document-api.mdx#to-object) | Схемные опции меняли форму результата там, где вызывающий этого не видел. Опция схемы `@Schema({ toJSON })` — ошибка |
| `Schema#discriminator`, `discriminatorKey` | [`@Discriminator`](../schemas/discriminator.mdx#discriminator), опция [`discriminatorKey`](../schemas/schema.mdx#discriminator-key) | Значение дискриминатора — литерал. Неизвестное значение в базе даёт `CastError`, а не молчаливую базовую модель. Значение ключа после создания неизменяемо |
| `schema.virtual("posts", { ref, … })` | декоратор [`@Virtual`](../schemas/virtual.mdx#virtual) | Виртуальные свойства без `ref` — вычисляемые поля, см. [`Computed`](../schemas/field-markers.mdx#computed) |
| `schema.methods`, `schema.loadClass` | обычные методы класса | Класс и есть схема, `loadClass` не нужен. Инициализатор у поля с `@Prop` — ошибка |
| `schema.statics`, `schema.query` | нет, для общих статических функций есть плагин с [`statics`](../hooks/plugins.mdx#plugin-statics) | Методы запроса-помощники заменяются функциями над строителем |
| `schema.pre`, `schema.post` | [`@Pre`, `@Post`, `@PostError`](../hooks/pre-post.mdx#pre) | Разобрано в таблице [Хуки и плагины](#hooks-and-plugins) |
| `schema.plugin(fn)` | декоратор [`@Plugin`](../hooks/plugins.mdx#plugin) | Плагин — объект, а не функция |
| `schema.set`, `schema.add`, `schema.path`, `schema.clone` | нет | Схема после объявления не меняется. Описание схемы для чтения — [`describe`](../schemas/schema-info.mdx#describe) |
| `schema.toJSONSchema()` | [`JsonSchemaGenerator.generate`](../schemas/json-and-standard-schema.mdx#json-schema-generator.generate) | Есть и [`StandardSchema`](../schemas/json-and-standard-schema.mdx#standard-schema) |

## Модели и запросы [#models-and-queries]

В Mongoose запрос — объект `Query`, с которым до выполнения можно делать что угодно. В Typemo это [строитель запроса](../query/reading.mdx#how-builder-works). Цепочка такая же, но фильтр, проекция и сортировка проверяются типами и в момент построения.

| Mongoose | Typemo | Что важно |
|---|---|---|
| `Model.find`, `findOne` | [`Model.find`](../query/reading.mdx#model.find), [`Model.findOne`](../query/reading.mdx#model.find-one) | Неизвестное поле в фильтре — ошибка типа и `StrictModeError`, а не пустой результат |
| `Model.findById` | [`Model.findById`](../query/reading.mdx#model.find-by-id) | Принимает строку id, неверная строка даёт `CastError`. Пустой id — ошибка, а не поиск по `null` |
| `Model.exists` | [`Model.exists`](../query/reading.mdx#model.exists) | |
| `Model.countDocuments`, `estimatedDocumentCount` | [`countDocuments`](../query/reading.mdx#model.count-documents), [`estimatedDocumentCount`](../query/reading.mdx#model.estimated-document-count) | На дискриминаторе `estimatedDocumentCount` — ошибка, он считает всю коллекцию |
| `Model.distinct` | [`Model.distinct`](../query/reading.mdx#model.distinct) | |
| `.lean()` | [`.lean()`](../query/reading.mdx#lean) и [`.plain()`](../query/reading.mdx#plain) | `lean` оставляет `ObjectId`, `plain` превращает значения в JSON-формы (`_id` — строка).  |
| `.select("a -b")`, `.select({ a: 1 })` | [`.select({ a: 1 })`](../query/reading.mdx#select) | Только объект. Смесь включения и исключения — ошибка, а `+поле` годится только для скрытых полей |
| `.sort("-age name")`, `.sort({ age: -1 })` | [`.sort({ age: -1 })`](../query/reading.mdx#sort) или список пар | Строки-DSL нет. Путь дважды — ошибка |
| `.limit`, `.skip` | [`.limit`](../query/reading.mdx#limit), [`.skip`](../query/reading.mdx#skip) | `limit("5")` не приводится. `0` и отрицательные значения — ошибка (в базе `limit(0)` значит «без предела») |
| `.orFail()` | [`.orFail()`](../query/reading.mdx#or-fail) | На `find` бросает [`DocumentNotFoundError`](../errors/query-errors.mdx#document-not-found-error) при пустом списке |
| `.populate()` | [`.populate()`](../populate/populate.mdx#populate) | См. раздел [Populate](#populate) |
| `.cursor()`, `.eachAsync`, `for await` | [`.cursor()`](../query/reading.mdx#cursor), [`.eachAsync`](../query/cursor.mdx#each-async) | Ошибка обработчика приходит как [`EachAsyncError`](../query/cursor.mdx#each-async-error) |
| `.exec()`, `await query` | [`.exec()`](../query/reading.mdx#exec), `await` | Повторный `await` читателя даёт тот же результат без запроса. В Mongoose он бросает `Query was already executed` |
| `.where("a").gt(1)`, `.equals`, `.in`, `.nin`, `.exists`, `.regex`, `.mod`, `.size`, `.all`, `.elemMatch`, `.or`, `.and`, `.nor` | [`.where`](../query/conditions.mdx#where) и цепочка условий на странице [`conditions`](../query/conditions.mdx) | Значения сверяются с типом поля |
| `.merge(query)` | [`.merge`](../query/conditions.mdx#merge) | Только запрос той же модели |
| `.session()` | [`.session()`](../query/options.mdx#session) | Внутри `transaction` сессия подставляется сама |
| `.hint`, `.collation`, `.comment`, `.batchSize`, `.allowDiskUse` | [`.hint`](../query/options.mdx#hint), [`.collation`](../query/options.mdx#collation), [`.comment`](../query/options.mdx#comment), [`.batchSize`](../query/options.mdx#batch-size), [`.allowDiskUse`](../query/options.mdx#allow-disk-use) | |
| `.maxTimeMS()` | [`.timeoutMS()`](../query/options.mdx#timeout-ms) | Единственный способ ограничить время — клиентский тайм-аут драйвера |
| `.read()` | [`.readPreference()`](../query/options.mdx#read-preference) | Внутри транзакции предпочтение чтения, отличное от primary, — ошибка |
| `.explain()` | [`.explain()`](../query/search-and-explain.mdx#explain) | Только для `find` и `findOne` |
| `.setOptions`, `.getFilter`, `.getUpdate`, `.getOptions`, `.projection`, `.cast`, `.transform`, `.tailable`, `.slice`, `.error`, `.j`, `.w`, `.wtimeout`, `.snapshot`, `.$where` | нет | Каждый метод либо читает и меняет внутреннее состояние запроса, либо отдаёт драйверу сырые опции в обход проверок. Вмешаться в операцию можно [хуком](../../hooks/operation-hooks.mdx) |
| `.sanitizeFilter` и опция `sanitizeFilter` | нет | Проверка включена всегда. Оператор в значении, пришедшем извне, нужно явно пометить как недоверенный, см. [Отличия в поведении](../../migration/behavior-differences.mdx) |
| `Model.aggregate([{ $match: … }])` | `Model.aggregate((p) => p.match(…))` | Стадии — типизированные методы конвейера, сырых стадий нет. См. руководство [Первая агрегация](../../aggregation/first-aggregation.mdx) и справочник [`Pipeline` и `Model.aggregate`](../aggregation/pipeline.mdx) |
| `Model.watch()` | [`Model.watch`](../change-streams/watch.mdx#model.watch) | Возвращает асинхронный итератор, а не `EventEmitter` |
| `Model.hydrate`, `Model.castObject`, `Model.validate` | [`Model.hydrate`](../documents/model-document-methods.mdx#model.hydrate), [`Model.castObject`](../documents/model-document-methods.mdx#model.cast-object), [`Model.validate`](../documents/model-document-methods.mdx#model.validate) | |
| `new Model({…})` | [`Model.new`](../documents/model-document-methods.mdx#model.new) | Класс модели через `new` не вызывается, модель — объект подключения |
| `Model.init`, `createCollection`, `createIndexes`, `ensureIndexes`, `syncIndexes`, `cleanIndexes`, `listIndexes` | [`connection.init`](../connection/connection.mdx#connection.init), [`Model.createCollection`](../collections/collection-manager.mdx#model.create-collection), [`createIndexes`](../collections/model-indexes.mdx#model.create-indexes), [`syncIndexes`](../collections/model-indexes.mdx#model.sync-indexes), [`listIndexes`](../collections/model-indexes.mdx#model.list-indexes), [`diffIndexes`](../collections/model-indexes.mdx#model.diff-indexes) | `ensureIndexes` и `cleanIndexes` нет. Первый устарел, вторую заменяет `syncIndexes` с `dryRun`. Сбой синхронизации не пропускается, `init()` и `syncAll()` бросают [`SyncError`](../errors/configuration-errors.mdx#sync-error) |
| `Model.startSession()` | [`client.startSession`](../connection/typemo-client.mdx#client.start-session) | |
| `Model.populate(docs, paths)`, `Model.translateAliases`, `Model.where`, `Model.$where`, `Model.discriminator(…)`, `Model.collection`, `Model.db` | нет | Заполнить уже загруженные документы можно через [`$populate`](../documents/document-api.mdx#populate) на документе. Имена `dbName` переводятся сами, дискриминатор — декоратор, драйвер — [`client.unsafeDriver()`](../connection/typemo-client.mdx#client.unsafe-driver) |

## Записи [#writes]

Главное различие в умолчаниях. `findOneAndUpdate` возвращает документ **после** изменения, проверки значений включены всегда, а пустая или «не операторная» запись — ошибка.

| Mongoose | Typemo | Что важно |
|---|---|---|
| `Model.create`, `new Model().save()` | [`Model.create`](../writes/writes.mdx#create) | `create([...])` — всегда один упорядоченный `insertMany`. Опции `ordered` у него нет |
| `Model.insertMany` | [`insertMany`](../writes/writes.mdx#insert-many) | Неупорядоченная вставка с невалидными документами завершается [`BulkWriteError`](../errors/server-errors.mdx#bulk-write-error), а не молчит |
| `Model.updateOne`, `updateMany` | [`updateOne`](../writes/writes.mdx#update-one), [`updateMany`](../writes/writes.mdx#update-many) | Только операторы. `{ title: "x" }` без `$set` — ошибка |
| `Model.replaceOne` | [`replaceOne`](../writes/writes.mdx#replace-one) | `createdAt` сохраняется, неизменяемое поле обязано быть в замене |
| `findOneAndUpdate`, `findByIdAndUpdate` | [`findOneAndUpdate`](../writes/writes.mdx#find-one-and-update), [`findByIdAndUpdate`](../writes/writes.mdx#find-by-id-and-update) | По умолчанию документ **после** изменения. `new: true` и `returnOriginal` нет, прежний документ даёт `returnDocument: "before"` |
| `findOneAndReplace`, `findOneAndDelete`, `findByIdAndDelete` | [`findOneAndReplace`](../writes/writes.mdx#find-one-and-replace), [`findOneAndDelete`](../writes/writes.mdx#find-one-and-delete), [`findByIdAndDelete`](../writes/writes.mdx#find-by-id-and-delete) | |
| `deleteOne`, `deleteMany` | [`deleteOne`](../writes/writes.mdx#delete-one), [`deleteMany`](../writes/writes.mdx#delete-many) | Пустой фильтр — `StrictModeError`. Удалить всё сознательно можно через `Filters.all()` |
| `bulkWrite`, `bulkSave` | [`bulkWrite`](../writes/writes.mdx#bulk-write), [`bulkSave`](../writes/writes.mdx#bulk-save) | Ошибки собираются в `BulkWriteError` с индексами входных элементов. Каждая операция проверяется схемой (в Mongoose — только `insertOne` и `replaceOne`) и запускает хуки одиночного аналога |
| `{ upsert: true }` | [`upsert`](../writes/writes.mdx#upsert) | С `upsert: true` и `"after"` результат никогда не `null` |
| `{ new: true }` / `{ returnDocument }` | [`returnDocument`](../writes/writes.mdx#return-document) | Только `"before"` и `"after"` |
| `{ runValidators: true }`, `{ context: "query" }` | нет | Проверки включены всегда, для `$set`, `$setOnInsert`, `$min`, `$max`, `$push`, `$addToSet` |
| `{ setDefaultsOnInsert }`, `{ timestamps: false }`, `{ strict }`, `{ overwriteDiscriminatorKey }`, `{ omitUndefined }` | нет | Значения по умолчанию и метки времени ведёт ядро, `strict` не отключается, значение ключа дискриминатора неизменяемо, а `undefined` — ошибка, не пропуск. Опции `timestamps` у записи нет |
| `{ arrayFilters }` | [`arrayFilters`](../writes/writes.mdx#array-filters) | Должны точно совпадать с идентификаторами `$[id]`. Лишний или недостающий фильтр — ошибка до отправки |
| `{ rawResult: true }` | опция `includeResultMetadata`, см. [`findOneAndUpdate`](../writes/writes.mdx#raw-result) | |
| `{ session }`, `{ writeConcern }`, `{ ordered }`, `{ maxTimeMS }` | [`.session`](../writes/writes.mdx#builder), [`.writeConcern`](../writes/writes.mdx#builder), [`ordered`](../writes/writes.mdx#ordered), `.timeoutMS` | |
| `updateOne(f, [ { $set } ], { updatePipeline: true })` | `updateOne(f, (p) => p.set(…))` | Стадии обновления типизированы, см. [`UpdatePipelines`](../writes/pipeline-updates.mdx#update-pipelines) |
| `$inc`, `$set`, `$push`, `$pull`, `$addToSet`, `$pop`, `$unset`, `$rename`, `$min`, `$max`, `$mul`, `$currentDate`, `$bit` | [операторы обновления](../writes/update-operators.mdx#set) с теми же именами | Путь под двумя операторами сразу — ошибка |

## Документы [#documents]

В Mongoose свойства и методы документа перемешаны с вашими полями (`doc.isNew`, `doc.save()`). В Typemo все служебные члены начинаются с `$`, поэтому поле пользователя с любым именем ничему не мешает.

| Mongoose | Typemo | Что важно |
|---|---|---|
| `doc.save()` | [`doc.$save()`](../documents/document-api.mdx#save) | Пустое сохранение ничего не отправляет. Хук `save` вызывается всегда |
| `doc.set(path, value)`, `doc.get(path)` | [`$set`](../documents/document-api.mdx#set), [`$get`](../documents/document-api.mdx#get) | Значение приводится сразу, ошибка приведения бросается, а не откладывается |
| `doc.isNew`, `isModified`, `markModified` | [`$isNew()`](../documents/document-api.mdx#is-new), [`$isModified()`](../documents/document-api.mdx#is-modified), [`$markModified()`](../documents/document-api.mdx#mark-modified) | Методы, а не свойства |
| `doc.validate()` | [`$validate`](../documents/document-api.mdx#validate) | |
| `doc.deleteOne()`, `doc.updateOne()` | [`$deleteOne`](../documents/document-api.mdx#delete-one), [`$updateOne`](../documents/document-api.mdx#update-one) | `$deleteOne` не запускает хуки запроса |
| `doc.populate()`, `depopulate`, `populated`, `$assertPopulated` | [`$populate`](../documents/document-api.mdx#populate), [`$depopulate`](../documents/document-api.mdx#depopulate), [`$populated`](../documents/document-api.mdx#populated), [`$assertPopulated`](../documents/document-api.mdx#assert-populated) | Заполненный массив — представление только для чтения |
| `doc.toObject()`, `doc.toJSON()` | [`$toObject`](../documents/document-api.mdx#to-object), [`$toPlain`](../documents/document-api.mdx#to-plain), [`$toJSON`](../documents/document-api.mdx#to-json) | `JSON.stringify(doc)` работает и даёт то же, что `$toJSON()` с настройками по умолчанию |
| `doc.id` | нет | Идентификатор — `_id` типа `ObjectId`. Строка приходит в результате `.plain()` и в `$toJSON()` |
| `doc.$locals`, `doc.$session()` | [`$locals`](../documents/document-api.mdx#locals), [`$session`](../documents/document-api.mdx#session) | |
| `doc.errors`, `doc.invalidate`, `doc.$isValid`, `doc.directModifiedPaths`, `doc.modifiedPaths()`, `doc.$clone`, `doc.overwrite`, `doc.equals`, `doc.collection` | нет, сравнение — [`$is`](../documents/document-api.mdx#is), изменения — [`$getChanges`](../documents/document-api.mdx#get-changes) | Накопленного состояния ошибок нет. Проверка либо проходит, либо бросает [`ValidationError`](../errors/data-errors.mdx#validation-error) |
| `MongooseArray`, `.$pop`, `.nonAtomicPush`, `.$shift`, `$atomics` | [`StrictArray`](../documents/typed-collections.mdx#strict-array) и его методы | Запись `arr[i] = x` и `arr.length = 0` не компилируются. Берите `set`, `clear`, `splice`, `replace` |
| `DocumentArray.id()`, `.create()`, `.pull()` | [`SubdocumentArray.id`](../documents/typed-collections.mdx#subdocument-array.id), [`create`](../documents/typed-collections.mdx#subdocument-array.create), [`pull`](../documents/typed-collections.mdx#subdocument-array.pull) | `id` с неверным значением даёт `CastError`, а не `null` |
| `Map` | [`TypedMap`](../documents/typed-collections.mdx#typed-map) | Ошибка приведения значения бросается сразу |
| `subdoc.deleteOne()`, `subdoc.remove()` | нет, удаление — `pull(subdoc)` на массиве | Пока поддокумент не вставлен, он не знает, как удалить себя из родителя |
| поле, которого нет в схеме, в поддокументе | [`unknownFieldsOf`](../documents/unknown-fields.mdx#unknown-fields-of), [`UnknownFieldsError`](../documents/unknown-fields.mdx#unknown-fields-error) | Mongoose стёр бы такие поля при перезаписи поддокумента, Typemo отказывает |

## Populate [#populate]

| Mongoose | Typemo | Что важно |
|---|---|---|
| `.populate("author")`, `.populate("a b")` | [`.populate("author")`](../populate/populate.mdx#populate), список путей `["a", "b"]` | Строка с пробелами как список путей не поддерживается |
| `.populate({ path, select, match, options, populate })` | [объект опций](../populate/populate.mdx#object-options) — `path`, `select`, `match`, `options` | Вложенные связи задаются точечным путём `author.company`, а не вложенным `populate` |
| `options.limit`, `options.skip` | [`options.limit`, `options.skip`](../populate/populate.mdx#options) | Считаются точно на каждый документ, а не «на весь запрос» |
| `justOne`, `retainNullValues`, `perDocumentLimit`, `transform`, `clone` | [`justOne`](../populate/populate.mdx#just-one), [`retainNullValues`](../populate/populate.mdx#retain-null-values), [`perDocumentLimit`](../populate/populate.mdx#per-document-limit), [`transform`](../populate/populate.mdx#transform), [`clone`](../populate/populate.mdx#clone) | `transform` получает документ из `.lean()` |
| `ref` как функция или имя модели | опция [`ref: () => User`](../schemas/prop.mdx#ref) | Ссылка — только на класс |
| `refPath` | опции [`refPath`](../schemas/prop.mdx#ref-path) и [`refModel`](../schemas/prop.mdx#ref-model) | `refPath` — путь внутри самого документа со ссылкой, а не от корня |
| виртуальное `populate` (`localField`, `foreignField`, `count`, `justOne`) | [`@Virtual`](../schemas/virtual.mdx#virtual), его опции [`count`](../schemas/virtual.mdx#count), [`justOne`](../schemas/virtual.mdx#just-one) | Виртуальная связь — часть типа модели |
| `strictPopulate`, `forceRepopulate`, `populate({ model })`, `options.options` | нет | Неизвестный путь — всегда ошибка. Повторный `populate` всегда заменяет предыдущий, модель определяется полем |
| `Model.populate(docs)` | нет, есть `.populate` на запросе и [`$populate`](../documents/document-api.mdx#populate) на документе | |
| `push(id)` в заполненный массив | нет | Заполненный массив — представление только для чтения. Ссылки меняются через сохранённые идентификаторы |

## Хуки и плагины [#hooks-and-plugins]

| Mongoose | Typemo | Что важно |
|---|---|---|
| `schema.pre("save", fn)` | [`@Pre("document.save")`](../hooks/pre-post.mdx#pre) на методе класса | У событий есть область — `document.save`, `query.find`, `model.insertMany` |
| `schema.post("save", fn)` | [`@Post("document.save")`](../hooks/pre-post.mdx#post) | |
| `schema.post("save", errorFn)` (три аргумента) | [`@PostError`](../hooks/pre-post.mdx#post-error) | На событие — либо `@Post`, либо `@PostError` |
| `next()` в `pre` | нет | В девятой версии Mongoose `next` в `pre` уже убран, хуки — асинхронные функции. В Typemo хук — метод, а ошибка — исключение |
| `this` как `Query` в запросных хуках | `this` — типизированный контекст [`OperationHookContext`](../hooks/operation-context.mdx#operation-hook-context) | Значения операции только для чтения. Изменить их можно через [`.modify`](../hooks/operation-context.mdx#modify), пропустить операцию — через [`.skip`](../hooks/operation-context.mdx#skip) |
| `schema.pre(/^find/)`, регулярные выражения | нет | Список событий явный, см. [`HOOK_EVENTS`](../hooks/pre-post.mdx#hook-events) |
| `pre("save")`, `pre("validate")` порядок | `pre(document.save)`, затем проверка, затем запись | В Mongoose проверка идёт раньше `pre("save")` |
| `schema.plugin(fn, opts)`, `mongoose.plugin(fn)` | [`@Plugin`](../hooks/plugins.mdx#plugin), [`Typemo.plugin`](../connection/typemo.mdx#typemo.plugin), [`SchemaPlugin`](../hooks/plugins.mdx#schema-plugin) | Регистрация закрывается первой успешно скомпилированной моделью |
| сторонние плагины soft delete, tenant, audit | встроенные политики — [мягкое удаление](../../policies/soft-delete.mdx), [тенанты](../../policies/tenants.mdx), [аудит](../../policies/audit.mdx) | Действуют на всех операциях и путях, включая агрегацию. Поле тенанта помечается [`@Tenant()`](../schemas/field-markers.mdx#tenant) |

## Ошибки [#errors]

Ошибки Typemo образуют одну иерархию от [`TypemoError`](../errors/hierarchy.mdx#typemo-error), у каждой есть `cause`. Ошибки драйвера как есть не пробрасываются, каждая классифицирована.

| Mongoose | Typemo | Что важно |
|---|---|---|
| `mongoose.Error.ValidationError`, `ValidatorError` | [`ValidationError`](../errors/data-errors.mdx#validation-error) | Поля ошибки описаны в справочнике |
| `mongoose.Error.CastError` | [`CastError`](../errors/data-errors.mdx#cast-error) | Есть поле `reason` с причиной — `type`, `format`, `range`, `null`, `unknown-key` |
| `DocumentNotFoundError` | [`DocumentNotFoundError`](../errors/query-errors.mdx#document-not-found-error) | Фильтр в ошибке не хранится |
| `VersionError` | [`VersionError`](../errors/query-errors.mdx#version-error) | |
| `StrictModeError`, `StrictPopulateError` | [`StrictModeError`](../errors/data-errors.mdx#strict-mode-error) | Одна ошибка с `reason` вместо набора |
| `MongoServerError` с кодом 11000 | [`DuplicateKeyError`](../errors/server-errors.mdx#duplicate-key-error) | Остальные серверные коды — [`ServerError`](../errors/server-errors.mdx#server-error) и потомки |
| `MongoBulkWriteError` | [`BulkWriteError`](../errors/server-errors.mdx#bulk-write-error) | Индексы входных элементов и коды сохраняются |
| `OverwriteModelError` | нет, повторный `model(Post)` на том же подключении возвращает ту же модель | Второй экземпляр модели создать нельзя, поэтому и переопределять нечего |
| `MissingSchemaError` | [`ConfigurationError`](../errors/configuration-errors.mdx#configuration-error) | Класс без `@Schema` или без `_id` моделью не становится |
| `err instanceof mongoose.Error` | `err instanceof TypemoError` | Все ошибки библиотеки — потомки одного класса |
