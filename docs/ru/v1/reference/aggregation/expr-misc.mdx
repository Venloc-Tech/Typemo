Эта страница описывает **выражения** — операторы, которые внутри конвейера считают новое значение из полей документа, — которые не вошли в другие группы: битовые операции, случайное число, метаданные документа и сходство векторов. Во второй половине страницы собраны **системные переменные** — значения, которые сервер держит сам, например текущее время. В Typemo они лежат в классе `Vars`. Операторы лежат в объекте `fn` и вызываются в колбэке `(f) => …` стадий [`project`](./stages.mdx#project), [`addFields`](./stages.mdx#addfields) и других.

Если вы только начинаете, прочитайте руководство [Выражения](../../aggregation/expressions.mdx). Эта страница — справочник.

Все примеры используют одну модель заказа магазина. У неё есть текстовый индекс по полю `note`: он нужен `fn.meta`.

```ts twoslash title="shop/order.ts"
import { Entity, Index, Prop, Schema } from "@venloc/typemo";

@Index({ note: "text" })
@Schema({ collection: "orders" })
export class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => String)
  note?: string;
}
```

В примерах, кроме отмеченных, стоят стадии `sort` по дате и `limit(2)`, чтобы остались два первых заказа, и `project`. Заказ Alice на 120 оплачен, у него есть скидка 10 и заметка `gift`. Заказ Alice на 80 оплачен, без скидки и без заметки. Строки получены методом [`.plain()`](./pipeline.mdx#plain).

## Битовые операции

Битовые операторы принимают целые числа: `number` (`int32`) или `bigint` (`int64`). Если хотя бы один аргумент `bigint`, результат `bigint`, иначе `number`. Если аргумент может быть `null`, результат тоже может. В plain-виде `int64` приходит строкой. Нужен MongoDB 6.3 и новее (так сказано в описании операторов в коде).

### fn.bitAnd

`fn.bitAnd` считает побитовое «и» двух и более чисел.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Index({ note: "text" })
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => String)
  note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({ _id: 0, total: 1, x: fn.bitAnd(f.total, 12) })),
).plain();
console.log(rows);
// → [
//   { total: 120, x: 8 },
//   { total: 80, x: 0 },
// ]
```

Число 120 в двоичной записи `1111000`, число 12 — `1100`; общие единицы дают 8. С `bigint` результат становится `int64`:

```ts twoslash
// ]
```

## Случайное число

### fn.rand

`fn.rand` возвращает случайное число от 0 (включительно) до 1 (не включая). Принимает ничего, возвращает `number`. Значение вычисляется заново для каждого документа, поэтому в примере проверяется только диапазон:

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Index({ note: "text" })
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => String)
  note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({
      _id: 0,
      total: 1,
      inRange: fn.and(fn.gte(fn.rand(), 0), fn.lt(fn.rand(), 1)),
    })),
).plain();
console.log(rows);
// → [
//   { total: 120, inRange: true },
//   { total: 80, inRange: true },
// ]
```

## Метаданные

### fn.meta

`fn.meta` возвращает служебные данные документа, которые заполняют некоторые стадии. Принимает имя данных, тип результата определяется этим именем. Для текстового поиска это `"textScore"`: показатель релевантности, который заполняет `$text`.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Index({ note: "text" })
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => String)
  note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .match({ $text: { $search: "gift" } })
    .project((f) => ({ _id: 0, customer: 1, score: fn.meta("textScore") })),
).plain();
console.log(rows);
// → [{ customer: "Alice", score: 1.1 }]
```

Показатель есть только в конвейере, где стадия [`match`](./stages.mdx#match) с `$text` стоит первой. Полный список имён — тип `MetaValues`:

## Сходство векторов

**Вектор** — список чисел, например эмбеддинг текста. Три оператора считают, насколько два вектора похожи. Каждый принимает два вектора (массивы чисел или бинарные векторы) либо объект `{ vectors: [a, b], score }`, где `score: true` приводит результат к отрезку от 0 до 1. Если аргумент может быть `null` или отсутствовать, результат `number | null`. Нужен MongoDB 8.3.

### fn.similarityCosine

`fn.similarityCosine` считает косинусное сходство: угол между векторами.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Index({ note: "text" })
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => String)
  note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({ _id: 0, total: 1, s: fn.similarityCosine([1, 0], [1, 1]) })),
).plain();
console.log(rows);
// → [
//   { total: 120, s: 0.7071067811865475 },
//   { total: 80, s: 0.7071067811865475 },
// ]
```

Записанное как объект, с `score: true`, результат приведён к отрезку от 0 до 1:

## Vars

`Vars` — класс со статическими узлами системных переменных MongoDB. Переменная записывается не строкой `"$$NOW"`, а свойством класса: голая строка в позиции выражения превратилась бы в литерал, и сервер вернул бы её как текст. Переменные `$$ROOT` и `$$CURRENT` отдельных узлов не имеют: `$$ROOT` — это сам прокси `f`.

### Vars.NOW

`Vars.NOW` — текущее время. Тип `Date`. Значение одно на весь конвейер: все документы видят один и тот же момент.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Index({ note: "text" })
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => String)
  note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({
      _id: 0,
      total: 1,
      past: fn.lt(f.total, 1000),
      fresh: fn.gt(Vars.NOW, new Date("2026-01-01T00:00:00Z")),
    })),
).plain();
console.log(rows);
// → [
//   { total: 120, past: true, fresh: true },
//   { total: 80, past: true, fresh: true },
// ]
```

### Vars.CLUSTER_TIME

### Vars.REMOVE

`Vars.REMOVE` удаляет поле, которому его присвоили: ключ пропадает из результата, и по описанию в коде — из его типа. Обычно его ставят в одну из веток [`fn.cond`](./expr-logic.mdx#fncond).

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Index({ note: "text" })
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => String)
  note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .set((f) => ({ total: fn.cond(fn.gt(f.total, 100), f.total, Vars.REMOVE) }))
    .project((f) => ({ _id: 0, customer: 1, total: 1 })),
).plain();
console.log(rows);
// → [
//   { customer: "Alice", total: 120 },
//   { customer: "Alice" },
// ]
```

У второго заказа `total` меньше 100, поэтому поле удалено. Для безусловного удаления есть `fn.remove()`; он возвращает `Vars.REMOVE`:

```ts twoslash

//   { total: 80 },
// ]
```

### Vars.USER_ROLES

### Vars.DESCEND

`Vars.DESCEND` нужна стадии [`redact`](./stages.mdx#redact): оставить поля этого уровня и проверить вложенные документы. Тип `RedactVerdict` объединяет три вердикта: `"descend"`, `"prune"` и `"keep"`. Примера с ней нет: см. замечание после `Vars.KEEP`.

### Vars.PRUNE

`Vars.PRUNE` отбрасывает документ или вложенный документ целиком.

### Vars.KEEP

`Vars.KEEP` оставляет этот уровень и всё, что ниже, без проверки.

Стадия `redact` принимает только выражение, которое возвращает один из трёх вердиктов, чаще всего через `fn.cond`. Здесь отменённые заказы отброшены, остальные оставлены:

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Index({ note: "text" })
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => String)
  note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .redact((f) => fn.cond(fn.eq(f.status, "cancelled"), Vars.PRUNE, Vars.KEEP))
    .sort({ placedAt: 1 })
    .project((f) => ({ _id: 0, customer: 1, status: 1 })),
).plain();
console.log(rows);
// → [
//   { customer: "Alice", status: "paid" },
//   { customer: "Alice", status: "paid" },
//   { customer: "Bob", status: "new" },
//   { customer: "Bob", status: "paid" },
//   { customer: "Carol", status: "paid" },
// ]
```

Вердикт `DESCEND` в примерах не показан: его описание взято из кода и не проверялось запуском.

## Когда не подходит

- Нужно выражение на JavaScript: оператора `fn.function` (`$function` сервера) в Typemo нет, его вызов — ошибка компиляции. Соберите выражение из операторов [логики](./expr-logic.mdx), [массивов](./expr-array.mdx) и [строк](./expr-string.mdx); подробности — в разделе [Код на JavaScript](./accumulators.mdx#код-на-javascript).
- Нужна дата или время: смотрите [операторы дат](./expr-date.mdx), `Vars.NOW` даёт только текущий момент.
- Нужно случайно выбрать документы: используйте стадию [`sample`](./stages.mdx#sample), а не `fn.rand` в фильтре.
- Нужен векторный поиск по индексу: стадия [`vectorSearch`](./stages.mdx#vectorsearch), а не сравнение векторов каждого документа.
