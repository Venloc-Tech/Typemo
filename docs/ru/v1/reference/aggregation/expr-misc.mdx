Выражения считают новое значение из полей документа прямо внутри конвейера. Здесь собраны те, что не вошли в другие группы — битовые операции, случайное число, метаданные документа и сходство векторов. Вторая половина страницы про **системные переменные**, то есть значения, которые сервер держит сам, например текущее время. В Typemo они лежат в классе `Vars`. Операторы живут в объекте `fn` и вызываются в колбэке `(f) => …` стадий [`project`](./stages.mdx#project), [`addFields`](./stages.mdx#add-fields) и других.

Если вы только начинаете, сначала прочитайте руководство [Выражения](../../aggregation/expressions.mdx). Эта страница — справочник.

Во всех примерах одна модель заказа магазина. У неё есть текстовый индекс по полю `note`, он нужен для `fn.meta`.

<Snippet id="reference/aggregation/expr-misc/intro" title="shop/order.ts" twoslash />

Если не сказано иное, в примерах стоят `sort` по дате, `limit(2)` и `project`. Они оставляют два первых заказа. Заказ Alice на 120 оплачен, у него есть скидка 10 и заметка `gift`. Заказ Alice на 80 оплачен, без скидки и без заметки. Строки получены методом [`.plain()`](./pipeline.mdx#plain).

## Битовые операции [#bitwise]

Битовые операторы берут целые числа — `number` (`int32`) или `bigint` (`int64`). Если хотя бы один аргумент `bigint`, результат тоже `bigint`, иначе `number`. Если аргумент может быть `null`, результат тоже. В результате `.plain()` `int64` приходит строкой. Нужен MongoDB 6.3 и новее, так сказано в описании операторов в коде.

### fn.bitAnd [#fn.bit-and]

`fn.bitAnd` считает побитовое «и» двух и более чисел.

<Snippet id="reference/aggregation/expr-misc/fn-bit-and" twoslash />

Число 120 в двоичной записи — `1111000`, число 12 — `1100`. Общие единицы дают 8. С `bigint` результат становится `int64`.

<Snippet id="reference/aggregation/expr-misc/fn-bit-and-2" twoslash />

### fn.bitOr [#fn.bit-or]

`fn.bitOr` считает побитовое «или».

<Snippet id="reference/aggregation/expr-misc/fn-bit-or" twoslash />

### fn.bitXor [#fn.bit-xor]

`fn.bitXor` считает побитовое «исключающее или».

<Snippet id="reference/aggregation/expr-misc/fn-bit-xor" twoslash />

### fn.bitNot [#fn.bit-not]

`fn.bitNot` инвертирует все биты одного числа. Для целого `x` результат равен `-x - 1`.

<Snippet id="reference/aggregation/expr-misc/fn-bit-not" twoslash />

## Случайное число [#random]

### fn.rand [#fn.rand]

`fn.rand` возвращает случайное число от 0 (включительно) до 1 (не включая). Аргументов у него нет, результат — `number`. Для каждого документа значение считается заново, поэтому пример проверяет только диапазон.

<Snippet id="reference/aggregation/expr-misc/fn-rand" twoslash />

## Метаданные [#metadata]

### fn.meta [#fn.meta]

`fn.meta` возвращает служебные данные документа, которые заполняют некоторые стадии. Он берёт имя данных, и по этому имени определяется тип результата. Для текстового поиска имя — `"textScore"`, показатель релевантности, который заполняет `$text`.

<Snippet id="reference/aggregation/expr-misc/fn-meta" twoslash />

Показатель есть только в конвейере, где первой стоит стадия [`match`](./stages.mdx#match) с `$text`. Все имена перечислены в типе `MetaValues`.

## Сходство векторов [#vector-similarity]

**Вектор** — список чисел, например эмбеддинг текста. Три оператора считают, насколько два вектора похожи. Каждый берёт два вектора (массивы чисел или бинарные векторы) либо объект `{ vectors: [a, b], score }`. С `score: true` результат приводится к отрезку от 0 до 1. Если аргумент может быть `null` или отсутствовать, результат — `number | null`. Нужен MongoDB 8.3.

### fn.similarityCosine [#fn.similarity-cosine]

`fn.similarityCosine` считает косинусное сходство, то есть угол между векторами.

<Snippet id="reference/aggregation/expr-misc/fn-similarity-cosine" twoslash />

В записи объектом с `score: true` результат приведён к отрезку от 0 до 1.

<Snippet id="reference/aggregation/expr-misc/fn-similarity-cosine-2" twoslash />

### fn.similarityDotProduct [#fn.similarity-dot-product]

`fn.similarityDotProduct` считает скалярное произведение. Для примера это `1·3 + 2·4 = 11`.

<Snippet id="reference/aggregation/expr-misc/fn-similarity-dot-product" twoslash />

### fn.similarityEuclidean [#fn.similarity-euclidean]

`fn.similarityEuclidean` считает евклидово расстояние. Между `[0, 0]` и `[3, 4]` оно равно 5.

<Snippet id="reference/aggregation/expr-misc/fn-similarity-euclidean" twoslash />

## Vars [#vars]

`Vars` — класс со статическими узлами системных переменных MongoDB. Переменную пишут свойством класса, а не строкой `"$$NOW"`. Голая строка в позиции выражения стала бы литералом, и сервер вернул бы её как текст. У `$$ROOT` и `$$CURRENT` отдельных узлов нет. `$$ROOT` — это сам прокси `f`.

### Vars.NOW [#vars.now]

`Vars.NOW` — текущее время, тип `Date`. Значение одно на весь конвейер, все документы видят один и тот же момент.

<Snippet id="reference/aggregation/expr-misc/vars-now" twoslash />

Короткая запись — `fn.now()`. Она возвращает тот же узел.

<Snippet id="reference/aggregation/expr-misc/vars-now-2" twoslash />

### Vars.CLUSTER_TIME [#vars.cluster-time]

`Vars.CLUSTER_TIME` — кластерное время, тип `Timestamp`. Есть только на реплика-сете и шардированном кластере.

<Snippet id="reference/aggregation/expr-misc/vars-cluster-time" twoslash />

### Vars.REMOVE [#vars.remove]

`Vars.REMOVE` удаляет поле, которому его присвоили. Ключ пропадает из результата и, по описанию в коде, из его типа. Обычно `Vars.REMOVE` ставят в одну из веток [`fn.cond`](./expr-logic.mdx#fn.cond).

<Snippet id="reference/aggregation/expr-misc/vars-remove" twoslash />

У второго заказа `total` меньше 100, поэтому поле удалено. Чтобы удалить поле безусловно, есть `fn.remove()`, он возвращает `Vars.REMOVE`.

<Snippet id="reference/aggregation/expr-misc/vars-remove-2" twoslash />

### Vars.USER_ROLES [#vars.user-roles]

`Vars.USER_ROLES` — роли текущего пользователя, массив `UserRole[]`. Каждая роль — объект с полями `_id` (`"<база>.<пользователь>"`), `role` (имя роли) и `db` (база, где роль определена). Тип `UserRole` экспортируется из `@venloc/typemo`. На сервере без аутентификации переменная возвращает пустой массив.

<Snippet id="reference/aggregation/expr-misc/vars-user-roles" twoslash />

### Vars.DESCEND [#vars.descend]

`Vars.DESCEND` нужна стадии [`redact`](./stages.mdx#redact). Она оставляет поля этого уровня и проверяет вложенные документы. Тип `RedactVerdict` объединяет три вердикта — `"descend"`, `"prune"` и `"keep"`. Примера с ней нет, причина названа после `Vars.KEEP`.

### Vars.PRUNE [#vars.prune]

`Vars.PRUNE` отбрасывает документ или вложенный документ целиком.

### Vars.KEEP [#vars.keep]

`Vars.KEEP` оставляет этот уровень и всё ниже него без проверки.

Стадия `redact` принимает только выражение, которое возвращает один из трёх вердиктов, чаще всего через `fn.cond`. В примере отменённые заказы отброшены, остальные оставлены.

<Snippet id="reference/aggregation/expr-misc/vars-keep" twoslash />

Вердикта `DESCEND` в примерах нет. Его описание взято из кода и запуском не проверялось.

## Когда не подходит [#when-not-to-use]

- **Нужно выражение на JavaScript.** Оператора `fn.function` (`$function` сервера) в Typemo нет, его вызов даёт ошибку компиляции. Соберите выражение из операторов [логики](./expr-logic.mdx), [массивов](./expr-array.mdx) и [строк](./expr-string.mdx). Подробности в разделе [Код на JavaScript](./accumulators.mdx#javascript-code).
- **Нужна дата или время.** Смотрите [операторы дат](./expr-date.mdx), `Vars.NOW` даёт только текущий момент.
- **Нужно случайно выбрать документы.** Берите стадию [`sample`](./stages.mdx#sample), а не `fn.rand` в фильтре.
- **Нужен векторный поиск по индексу.** Берите стадию [`vectorSearch`](./stages.mdx#vector-search), а не сравнение векторов в каждом документе.
