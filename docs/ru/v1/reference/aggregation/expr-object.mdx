Выражения считают новое значение из полей документа прямо внутри конвейера. Операторы этой страницы работают с вложенными документами (объектами) и переменными. Ими читают поле по имени, склеивают два документа, добавляют и убирают поле, превращают документ в список пар и вводят временные переменные. Операторы живут в объекте `fn` и вызываются в колбэке `(f) => …` стадий [`project`](./stages.mdx#project), [`addFields`](./stages.mdx#add-fields) и других.

Если вы только начинаете, сначала прочитайте руководство [Выражения](../../aggregation/expressions.mdx). Эта страница — справочник по операторам группы.

Во всех примерах одна модель заказа магазина с вложенным адресом доставки. Город в нём обязателен, индекс нет.

```ts twoslash title="shop/order.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ nested: true })
export class Address {
  @Prop(() => String, { required: true })
  city!: string;

  @Prop(() => String)
  zip?: string;
}

@Schema({ collection: "orders" })
export class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => Address)
  shipTo?: Address;
}
```

В примерах стоят `sort` по дате, `limit(2)` и `project`. Они оставляют два первых заказа. Заказ Alice на 120 едет в Oslo с индексом 0150. Заказ Alice на 80 тоже едет в Oslo, но без индекса. В коллекции есть ещё четыре заказа Bob и Carol. У одного заказа Bob адрес Rome с индексом 00100, у одного заказа Carol адрес Turin. Строки получены методом [`.plain()`](./pipeline.mdx#plain).

Поле `shipTo` необязательное, поэтому в выражениях его тип — документ или отсутствие. Операторы это учитывают. Если документа нет, результат `null` или пропуск, и тип результата это показывает.

## Слияние и чтение [#merge-and-read]

### fn.mergeObjects [#fn.merge-objects]

`fn.mergeObjects` склеивает документы слева направо, как `{ ...a, ...b }`. Поле из правого документа заменяет одноимённое из левого. Оператор берёт один документ или больше, а `null` и пропущенный документ ничего не добавляют.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true })
  city!: string;

  @Prop(() => String)
  zip?: string;
}

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => Address)
  shipTo?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({
      _id: 0,
      total: 1,
      card: fn.mergeObjects(f.shipTo, { country: "NO" }),
    })),
).plain();
console.log(rows);
// → [
//   { total: 120, card: { city: "Oslo", zip: "0150", country: "NO" } },
//   { total: 80, card: { city: "Oslo", country: "NO" } },
// ]
```

У первого заказа в результате город, индекс и добавленная страна. У второго индекса не было, и в результате его тоже нет.

Если правый документ содержит то же поле, он его заменяет. Здесь индекс 0150 первого заказа стал `"1"`, а у второго индекс появился.

С одним аргументом оператор работает ещё и как аккумулятор. В стадии [`group`](./stages.mdx#group) он склеивает документы группы. У заказов Alice адрес Oslo, а у Bob адрес есть только в одном заказе, поэтому остаётся он.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true })
  city!: string;

  @Prop(() => String)
  zip?: string;
}

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => Address)
  shipTo?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .group((f) => ({ _id: f.customer, shipTo: fn.mergeObjects(f.shipTo) }))
    .sort({ _id: 1 }),
).plain();
console.log(rows);
// → [
//   { _id: "Alice", shipTo: { city: "Oslo", zip: "0150" } },
//   { _id: "Bob", shipTo: { city: "Rome", zip: "00100" } },
//   { _id: "Carol", shipTo: { city: "Turin" } },
// ]
```

Остальные аккумуляторы описаны на странице [Аккумуляторы](./accumulators.mdx).

### fn.objectToArray [#fn.object-to-array]

`fn.objectToArray` превращает документ в массив пар `{ k, v }` — ключ и значение. Он выручает, когда имена полей заранее неизвестны и по ним нужно пройти.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true })
  city!: string;

  @Prop(() => String)
  zip?: string;
}

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => Address)
  shipTo?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({ _id: 0, total: 1, pairs: fn.objectToArray(f.shipTo) })),
).plain();
console.log(rows);
// → [
//   { total: 120, pairs: [{ k: "city", v: "Oslo" }, { k: "zip", v: "0150" }] },
//   { total: 80, pairs: [{ k: "city", v: "Oslo" }] },
// ]
```

Для `null` или пропущенного документа результат — `null`.

### fn.getField [#fn.get-field]

`fn.getField` читает поле документа по имени. Он берёт `{ field, input }`, где `field` — строка-константа. Точки и знак `$` в имени считаются его частью, а не путём. Поэтому оператор нужен для полей, чьё имя не записать как путь. Если документа может не быть, в тип результата входит `undefined`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true })
  city!: string;

  @Prop(() => String)
  zip?: string;
}

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => Address)
  shipTo?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({
      _id: 0,
      total: 1,
      city: fn.getField({ field: "city", input: f.shipTo }),
    })),
).plain();
console.log(rows);
//          ^?
// → [
//   { total: 120, city: "Oslo" },
//   { total: 80, city: "Oslo" },
// ]
```

Если поля в документе нет, результат — пропуск. У второго заказа индекса нет, и в строке нет ключа `zip`.

## Изменение документа [#document-change]

Эти операторы возвращают копию документа. Конвейер только считает результат и ничего не пишет в базу.

### fn.setField [#fn.set-field]

`fn.setField` возвращает копию документа, где поле `field` равно `value`. Он берёт `{ field, input, value }`. Существующее поле заменяется, новое добавляется.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true })
  city!: string;

  @Prop(() => String)
  zip?: string;
}

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => Address)
  shipTo?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({
      _id: 0,
      total: 1,
      card: fn.setField({ field: "zip", input: f.shipTo, value: "00000" }),
    })),
).plain();
console.log(rows);
// → [
//   { total: 120, card: { city: "Oslo", zip: "00000" } },
//   { total: 80, card: { city: "Oslo", zip: "00000" } },
// ]
```

## Переменные [#variables]

### fn.let [#fn.let]

`fn.let` вводит переменные для одного выражения. Он берёт `vars` — объект с выражениями — и колбэк `in`, который получает прокси переменных `v`, например `v.tax` или `v.customer.name`. Значение выражения из `in` и есть результат.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true })
  city!: string;

  @Prop(() => String)
  zip?: string;
}

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => Address)
  shipTo?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({
      _id: 0,
      total: 1,
      net: fn.let({
        vars: { tax: fn.multiply(f.total, 0.2) },
        in: (v) => fn.subtract(f.total, v.tax),
      }),
    })),
).plain();
console.log(rows);
// → [
//   { total: 120, net: 96 },
//   { total: 80, net: 64 },
// ]
```

Здесь `tax` — 20 процентов от `f.total`, а результат — `120 − 24 = 96`. В `in` переменную можно брать сколько угодно раз, не пересчитывая её.

Переменные видны только внутри `in`. В колбэке имя переменной — обычное свойство, а не строка с `$$`. Приставку `$$` Typemo добавит сам при отправке.

## Когда не подходит [#when-not-to-use]

- **Нужно достать поле по обычному пути.** Пишите `f.shipTo.city`, без `fn.getField`. Оператор нужен только для имён с точками и знаком `$`.
- **Нужно изменить документ в базе, а не в результате запроса.** Берите [обновления](../writes/writes.mdx).
- **Нужно выбрать поля вложенного документа целиком.** Берите стадию [`project`](./stages.mdx#project) с путём `"shipTo.city": 1`.
