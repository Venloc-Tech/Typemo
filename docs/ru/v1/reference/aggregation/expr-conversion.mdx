Эта страница описывает **выражения** — операторы, которые внутри конвейера считают новое значение из полей документа, — для преобразования значения в другой BSON-тип, проверки типа и вычисления хешей и размеров. Операторы лежат в объекте `fn` и вызываются в колбэке `(f) => …` стадий [`project`](./stages.mdx#project), [`addFields`](./stages.mdx#addfields) и других. Что такое BSON-типы и почему `int64` и `Decimal128` не равны обычному числу JavaScript, объясняет страница [BSON-типы](../../concepts/bson-types.mdx).

Если вы только начинаете, прочитайте руководство [Выражения](../../aggregation/expressions.mdx). Эта страница — справочник по операторам этой группы.

Все примеры используют одну модель заказа магазина. Кроме чисел и даты в ней есть вложенный адрес доставки, он нужен для `fn.bsonSize`.

```ts twoslash title="shop/order.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ nested: true })
export class Address {
  @Prop(() => String, { required: true })
  city!: string;

  @Prop(() => String)
  zip?: string;
}

@Schema({ collection: "orders" })
export class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => Address)
  shipTo?: Address;
}
```

В примерах стоят стадии `sort` по дате и `limit(2)`, чтобы остались два первых заказа, и `project`. Заказ Alice на 120 оплачен, у него есть скидка 10 и адрес доставки Oslo с индексом 0150. Заказ Alice на 80 оплачен, адрес Oslo без индекса. Числа 120 и 80 хранятся в базе как `int`: драйвер записывает целое число JavaScript именно так. Строки получены методом [`.plain()`](./pipeline.mdx#plain).

В таком виде результат отличается от типов в компиляторе. Тип результата оператора соответствует lean-виду BSON-типа (`int64` — это `bigint`, `Decimal128` — это `Decimal128`), а `.plain()` отдаёт `int64` и `Decimal128` строками (тип `${bigint}` для `int64`), которые безопасно отправить клиенту. Ниже это видно на `fn.toLong`.

Оператор преобразования пропускает `null` и отсутствующее поле: результат тогда `null`, и тип результата это учитывает. Если преобразовать нельзя (строка `"abc"` в число), сервер бросает ошибку; чтобы этого не было, используйте [`fn.convert`](#fnconvert) с `onError`.

Операторы, которым нужен сервер новее, помечены. `fn.toUUID` требует MongoDB 8.0, а `fn.toArray`, `fn.toObject`, `fn.subtype`, `fn.hash`, `fn.hexHash`, `fn.createObjectId`, `fn.serializeEJSON` и `fn.deserializeEJSON` — 8.3 (так сказано в описании операторов в коде). Проверялось на MongoDB 9.0.0-rc0.

## Преобразование

### fn.toString_

`fn.toString_` превращает любое значение в строку. Имя с подчёркиванием в конце нужно, потому что `toString` уже занят в каждом объекте JavaScript.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true })
  city!: string;

  @Prop(() => String)
  zip?: string;
}

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => Address)
  shipTo?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({ _id: 0, total: 1, text: fn.toString_(f.total) })),
).plain();
console.log(rows);
// → [
//   { total: 120, text: "120" },
//   { total: 80, text: "80" },
// ]
```

### fn.toDate

`fn.toDate` превращает строку, число (миллисекунды с 1970 года), `ObjectId` или `Timestamp` в дату.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true })
  city!: string;

  @Prop(() => String)
  zip?: string;
}

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => Address)
  shipTo?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({ _id: 0, total: 1, d: fn.toDate("2026-03-01T00:00:00Z") })),
).plain();
console.log(rows);
// → [
//   { total: 120, d: "2026-03-01T00:00:00.000Z" },
//   { total: 80, d: "2026-03-01T00:00:00.000Z" },
// ]
```

Целочисленный литерал в дату не превращается: драйвер отправляет его серверу как `int32`, а сервер не умеет превращать `int32` в дату. Поэтому `fn.toDate(0)` не компилируется: `Argument of type '0' is not assignable to parameter of type '0 & PathError<"fn.toDate: an int32 cannot be converted to a date (the server refuses it); use fn.toLong(n) or a double">'`. Если типы обошли приведением, ошибку даёт сервер: `ServerError: Unsupported conversion from int to date in $convert with no onError value (code 241 ConversionFailure)`. Сначала приведите число к `int64` через [`fn.toLong`](#fntolong): `fn.toDate(fn.toLong(0))` возвращает `"1970-01-01T00:00:00.000Z"`. Поле типа `number` (`fn.toDate(f.total)`) и нецелый литерал (`fn.toDate(86400000.5)`) компилятор пропускает: сервер читает их как `double`.

### fn.convert

`fn.convert` — общее преобразование. Принимает `input`, целевой тип `to` и необязательные `format`, `onError` и `onNull`. Тип результата зависит от `to`, а `onError` и `onNull` добавляются к нему, если вы их задали.

`to` — это имя типа (`"int"`, `"long"`, `"decimal"`, `"date"`, `"objectId"`, `"string"`, `"bool"`, `"double"`, `"binData"`, `"array"`, `"object"`), его номер BSON или объект `{ type: "binData", subtype }`. Формат `format` нужен для перевода между строкой и бинарными данными: `"base64"`, `"base64url"`, `"utf8"`, `"hex"`, `"uuid"`.

## Extended JSON

**Extended JSON** — запись BSON-типов в обычном JSON: дата превращается в объект с ключом `$date`, число `int64` — в `$numberLong`. Так значения безопасно проходят через текст.

### fn.deserializeEJSON

`fn.deserializeEJSON` делает обратное: читает Extended JSON и возвращает BSON-значение. Принимает `{ input, onError }`, тип результата `unknown`. Объект с `$numberLong` нужно передавать через [`fn.literal`](./expr-logic.mdx#fnliteral), иначе сервер прочтёт `$numberLong` как оператор выражения и откажет:

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true })
  city!: string;

  @Prop(() => String)
  zip?: string;
}

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;

  @Prop(() => Address)
  shipTo?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({
      _id: 0,
      total: 1,
      value: fn.typeOf(
        fn.deserializeEJSON({ input: fn.literal({ $numberLong: "5" }) }),
      ),
    })),
).plain();
console.log(rows);
// → [
//   { total: 120, value: "long" },
//   { total: 80, value: "long" },
// ]
```

Тип значения после разбора — `long`.

## Когда не подходит

- Нужно превратить значение при записи в базу, а не в конвейере: задайте тип поля в схеме, приведение выполнит модель.
- Нужно обработать значения разных типов в одном поле: проверьте тип через `fn.typeOf` и выберите ветвь [`fn.switch`](./expr-logic.mdx#fnswitch).
- Нужны арифметика и округление после преобразования: смотрите [арифметические операторы](./expr-arithmetic.mdx).
