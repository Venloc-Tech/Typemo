Выражения считают новое значение из полей документа прямо внутри конвейера. Здесь собраны три группы операторов — сравнение, логика и выбор значения. Выражение пишется в колбэке `(f) => …` стадий [`project`](./stages.mdx#project), [`addFields`](./stages.mdx#addfields), [`group`](./stages.mdx#group) и других. `f` — прокси полей модели, а операторы лежат в объекте `fn`.

Если вы только начинаете, сначала прочитайте руководство [Выражения](../../aggregation/expressions.mdx). Там объяснено, зачем колбэк вместо строк с `$` и почему сырой `$expr` запрещён. Эта страница — справочник по операторам группы.

Во всех примерах одна модель заказа магазина. В ней число, необязательное число, массив чисел, строка со списком допустимых значений и дата.

```ts twoslash title="shop/order.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "orders" })
export class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;
}
```

В примерах две стадии. `sort` по дате и `limit(2)` оставляют два первых заказа, а `project` показывает `total` и вычисленное поле. Заказ Alice на 120 оплачен, у него есть скидка 10 и позиции 20 и 100. Заказ Alice на 80 оплачен, скидки у него нет. Строки получены методом [`.plain()`](./pipeline.mdx#plain).

Typemo сравнивает строже, чем MongoDB. Сервер умеет сравнивать значения разных типов по фиксированному порядку BSON-типов, так что число «меньше» строки, а отсутствующее поле «меньше» любого числа. В запросе, который вы пишете осознанно, это почти всегда ошибка. Поэтому оба аргумента сравнения должны быть одного типа, иначе компилятор откажет с `TS2345: Argument of type '"x"' is not assignable to parameter of type 'Arg<Nullable<number>>'.`

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
// @errors: 2345
Orders.aggregate((p) => p.project((f) => ({ _id: 0, big: fn.gt(f.total, "x") })));
```

Исключение одно — `null`. Его можно поставить с любой стороны, ведь `fn.eq(x, null)` и есть проверка на `null`.

## Логика

### fn.and

`fn.and` возвращает `true`, если все аргументы истинны. Он берёт один аргумент или больше и возвращает `boolean`. `null` считается ложью, так что результат никогда не `null`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({
      _id: 0,
      total: 1,
      big: fn.and(fn.gt(f.total, 100), fn.eq(f.status, "paid")),
    })),
).plain();
console.log(rows);
// → [
//   { total: 120, big: true },
//   { total: 80, big: false },
// ]
```

### fn.or

`fn.or` возвращает `true`, если истинен хотя бы один аргумент. Аргументы и результат те же, что у `fn.and`.

```ts twoslash

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });

// ---cut---

  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({
      _id: 0,
      total: 1,

console.log(rows);
// → [
//   { total: 120, special: true },
//   { total: 80, special: false },
// ]
```

Как оба оператора ведут себя с `null`, показано ниже, после `fn.not`.

### fn.not

`fn.not` меняет `boolean` на противоположный. Он берёт одно значение, которое может быть `null`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({ _id: 0, total: 1, small: fn.not(fn.gt(f.total, 100)) })),
).plain();
console.log(rows);
// → [
//   { total: 120, small: false },
//   { total: 80, small: true },
// ]
```

Все три оператора логики считают `null` ложью. `fn.and(true, null)` даёт `false`, `fn.or(false, null)` тоже `false`, а `fn.not(null)` даёт `true`.

```ts twoslash

  status!: "new" | "paid" | "cancelled";

  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---

  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({
      _id: 0,
      total: 1,
      both: fn.and(true, null),
      either: fn.or(false, null),
      negated: fn.not(null),
    })),
).plain();
console.log(rows);
// → [
//   { total: 120, both: false, either: false, negated: true },
//   { total: 80, both: false, either: false, negated: true },
// ]
```

## Сравнение

Все шесть операторов сравнения берут ровно два аргумента одного типа и возвращают `boolean`. Тип выводится по обоим значениям сразу, поэтому число не сравнить со строкой, а дату с числом.

### fn.eq

`fn.eq` проверяет равенство.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({ _id: 0, total: 1, is120: fn.eq(f.total, 120) })),
).plain();
console.log(rows);
// → [
//   { total: 120, is120: true },
//   { total: 80, is120: false },
// ]
```

Проверка на `null` не находит отсутствующее поле. У второго заказа `discount` не задан, и `fn.eq(f.discount, null)` даёт `false`, потому что пропущенное поле и `null` — разные значения. Чтобы поймать оба случая, возьмите [`fn.ifNull`](#fnifnull) или сравните [`fn.typeOf`](./expr-conversion.mdx#fntypeof) с `"missing"`.

```ts twoslash

  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---

  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({
      _id: 0,
      discount: 1,
      isNull: fn.eq(f.discount, null),
      isTen: fn.eq(f.discount, 10),
    })),
).plain();
console.log(rows);
// → [
//   { discount: 10, isNull: false, isTen: true },
//   { isNull: false, isTen: false },
// ]
```

### fn.cmp

`fn.cmp` сравнивает два значения и возвращает `-1`, `0` или `1`. Тип результата — именно `-1 | 0 | 1`, а не `number`, так что по нему удобно разбирать случаи.

```ts twoslash

  @Prop(() => String, { required: true })
  customer!: string;

  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;
}

const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({ _id: 0, total: 1, vs100: fn.cmp(f.total, 100) })),
).plain();
console.log(rows);
// → [
//   { total: 120, vs100: 1 },
//   { total: 80, vs100: -1 },
// ]
```

Заказ на 120 больше 100, поэтому `1`. Заказ на 80 меньше, поэтому `-1`. Даты сравниваются так же. Заказ Alice от 5 января раньше 10 января (`-1`), а заказ от 12 января позже (`1`).

### fn.isIn

`fn.isIn` проверяет, что значение есть в массиве. Он берёт значение и массив, литерал или поле-массив. На сервере оператор называется `$in`, в `fn` — `isIn`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  status!: "new" | "paid" | "cancelled";
```

## Выбор значения

### fn.cond

`fn.cond` возвращает одно из двух значений. Он берёт три аргумента — условие, значение «да» и значение «нет». Если условие истинно, результат — `then`, иначе `otherwise`. Тип результата — объединение типов обеих ветвей.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({
      _id: 0,
      total: 1,
      size: fn.cond(fn.gt(f.total, 100), "large", "small"),
    })),
).plain();
console.log(rows);
// → [
//   { total: 120, size: "large" },
//   { total: 80, size: "small" },
// ]
```

Это самая короткая запись выбора. Вариантов больше двух — берите [`fn.switch`](#fnswitch).

### fn.switch

`fn.switch` выбирает значение по первому подошедшему условию. Он берёт `branches` — список пар `{ case, then }` — и необязательный `default`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({
      _id: 0,
      total: 1,
      size: fn.switch({
        branches: [
          { case: fn.gte(f.total, 100), then: "large" },
          { case: fn.gte(f.total, 50), then: "medium" },
        ],
        default: "small",
      }),
    })),
).plain();
console.log(rows);
// → [
//   { total: 120, size: "large" },
//   { total: 80, size: "medium" },
// ]
```

Побеждает первое истинное условие, так что порядок ветвей задаёт приоритет. 120 подходит и под «не меньше 100», и под «не меньше 50», но выбирается первая ветвь.

Без `default` Typemo не добавляет `null` к типу результата. Сервер в этом случае не возвращает `null`, а падает, и это видно при выполнении.

```text
ServerError: $switch could not find a matching branch for an input, and no default was specified. (code 40066 Location40066)
```

Если ветви не покрывают все значения, всегда пишите `default`.

### fn.ifNull

`fn.ifNull` возвращает первое значение, которое не `null` и не пропущено. Он берёт значение и запасное того же типа, после них можно добавить ещё запасные.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({ _id: 0, discount: fn.ifNull(f.discount, 0) })),
).plain();
console.log(rows);
//          ^?
// → [
//   { discount: 10 },
//   { discount: 0 },
// ]
```

Тип результата — тип запасного значения (`number`), без `undefined`, ведь и пропуск, и `null` заменены. Для необязательных полей это главный оператор. Он превращает «нет скидки» в `0`, с которым можно считать.

### fn.literal

`fn.literal` передаёт значение серверу как есть, не читая его как путь к полю или оператор. Для строки со знаком доллара он обычно не нужен, потому что Typemo сам оборачивает такую строку в `$literal`. Это видно в результате.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Vars, withWindow } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true, enum: ["new", "paid", "cancelled"] })
  status!: "new" | "paid" | "cancelled";

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [Number])
  prices!: number[];

  @Prop(() => Date, { required: true })
  placedAt!: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p
    .sort({ placedAt: 1 })
    .limit(2)
    .project((f) => ({
      _id: 0,
      total: 1,
      label: fn.concat("$", fn.toString_(f.total)),
    })),
).plain();
console.log(rows);
// → [
//   { total: 120, label: "$120" },
//   { total: 80, label: "$80" },
// ]
```

Здесь `"$"` — просто знак, а не путь `$…`. Чтобы зафиксировать значение явно, оберните его в `fn.literal`.

## Когда не подходит

- **Нужно отфильтровать документы, а не вычислить поле** — берите стадию [`match`](./stages.mdx#match) с обычным фильтром или предикатом-выражением, а не `fn.cond` в `project`.
- **Нужны арифметика и округление** — смотрите [арифметические операторы](./expr-arithmetic.mdx).
- **Нужно сравнить строки без учёта регистра** — берите [`fn.strcasecmp`](./expr-string.mdx#fnstrcasecmp), а не `fn.cmp`.
- **Нужно проверить тип значения** — для этого есть [`fn.typeOf`](./expr-conversion.mdx#fntypeof) и [`fn.isNumber`](./expr-conversion.mdx#fnisnumber).
