Ошибки запросов приходят, когда запрос нельзя построить, когда он ничего не нашёл там, где вы потребовали результат, и когда документ изменили между чтением и записью. Обычно это ситуации вашего приложения, а не сбои базы: запрошенной записи нет, токен страницы пришёл испорченным, два пользователя правили один документ. Для каждой ситуации у библиотеки свой класс, поэтому обработчик отвечает клиенту по классу, а не по тексту.

Если вы только начинаете, сначала прочитайте руководство [Обработка ошибок](../../errors/handling.mdx). Эта страница — справочник. Общее дерево классов — в разделе [Иерархия ошибок](./hierarchy.mdx).

Примеры используют модель счёта с версией документа. Версия нужна для [`VersionError`](#versionerror); остальным ошибкам она не мешает.

```ts twoslash title="accounts/account.ts"
import { Entity, Prop, Schema, Versioned } from "@venloc/typemo";

@Schema({ collection: "accounts", optimisticConcurrency: true })
export class Account extends Versioned(Entity) {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Number, { required: true })
  balance!: number;
}
```

Ошибки из групп соседних страниц: [ошибки данных](./data-errors.mdx), [ошибки сервера](./server-errors.mdx), [ошибки конфигурации и подключения](./configuration-errors.mdx).

## QueryError

`QueryError` бросается, когда запрос или обновление **нельзя построить**: библиотека замечает это, пока собирает план, и на сервер ничего не уходит. Типичные случаи: `undefined` в фильтре (драйвер молча искал бы `null`), пустой `$and`, `$or` или `$nor`, проекция, где смешаны включение и исключение полей, `limit` не больше нуля, пустое обновление, `merge()` с запросом другой модели, обход запроса через `for await`, `batchSize(0)`.

Все эти запросы сервер либо принял бы и сделал не то, что вы имели в виду, либо отверг бы с малопонятным текстом. Ошибка на стороне библиотеки говорит, что именно не так и как исправить. Здесь фильтр собран из значения, которого не оказалось:

```ts twoslash
import { Entity, Prop, QueryError, Schema, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ collection: "accounts", optimisticConcurrency: true })
class Account extends Versioned(Entity) {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
// ---cut---
const filter = JSON.parse("{}");
filter.title = undefined;

try {
  await Accounts.find(filter);
} catch (error) {
  if (error instanceof QueryError) {
    console.log(error.message);
    // → filter: undefined at "title" (use $exists: false / $unset; undefined is never a value)
    console.log(error.path);
    // → "title"
  }
}
```

Тексты остальных случаев, полученные запуском на этой модели:

```text
QueryError: limit must be a positive integer, got 0 (number)
QueryError: limit must be a positive integer, got "3" (string)
QueryError: update: an empty update changes nothing
QueryError: filter: $or must be a non-empty array (at "$or")
QueryError: projection: cannot mix inclusion (title) and exclusion (balance); the server refuses it
QueryError: batchSize must be a positive integer, got 0 (number) (the driver reads 0 as "the server default"; leave batchSize out for the default)
QueryError: find(): a query is not iterable with "for await"; iterate its cursor instead: for await (const doc of Model.find(filter).cursor())
```

Значение в тексте печатается вместе с типом: `"3"` — это строка, а не число, и `limit` её не принимает (значения из адреса страницы приводите к числу сами). Для `limit(0)` и `batchSize(0)` причина в самой базе: она читает ноль как «без ограничения» и «размер по умолчанию», а ноль легко получить из пустого параметра запроса. Запрос не является асинхронным итератором: чтобы пройти по результатам порциями, вызовите у него `.cursor()`, как подсказывает сообщение.

### Поля

<Params title="Поля ошибки">
<Param name="path" type="string | undefined">

Где во вводе проблема (путь через точку), если он известен: `title`, `$or`. Для ошибок вроде `limit` пути нет, и поле равно `undefined`.

</Param>
</Params>

### Когда не подходит

`QueryError` относится к построению запроса. Если фильтр называет поле, которого нет в модели, вы получите [`StrictModeError`](./data-errors.mdx#strictmodeerror), а если значение не приводится к типу поля, [`CastError`](./data-errors.mdx#casterror). Ловите нужные классы явно: общий `catch` по `QueryError` их не поймает.

## DocumentNotFoundError

`DocumentNotFoundError` бросается, когда вы потребовали результат методом [`.orFail()`](../query/reading.mdx#orfail), а ничего не нашлось, либо когда запись, помеченная `orFail`, не задела ни одного документа. Без `.orFail()` чтение вернуло бы `null` (или пустой массив), а обновление сообщило бы `matchedCount: 0`. Ошибка удобна там, где отсутствие документа для вас исключение: «счёт по адресу страницы не найден» превращается в один `catch`, а не в цепочку проверок на `null`.

```ts twoslash
import { DocumentNotFoundError, Entity, Prop, Schema, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ collection: "accounts", optimisticConcurrency: true })
class Account extends Versioned(Entity) {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
// ---cut---
try {
  await Accounts.findOne({ title: "no such account" }).orFail();
} catch (error) {
  if (error instanceof DocumentNotFoundError) {
    console.log(error.message);
    // → Account.findOne: no document matched the filter (orFail)
    console.log(error.operation, error.model);
    // → "findOne" "Account"
  }
}
```

Поле `operation` называет метод, который вы вызвали: `findById` для поиска по идентификатору, `findByIdAndUpdate`, `findOneAndUpdate`, `find`, `replaceOne`, `deleteOne` (запуск на каждом из них). Внутренних имён операций, в которые метод превращается, в тексте нет. Фильтр в ошибку **намеренно не попадает**: он может содержать персональные данные, а Mongoose хранил его в поле `query` и печатал вместе с ошибкой.

### Другие ситуации

Ту же ошибку бросает сохранение документа, который успели удалить. Документ прочитан, потом его удалили (другим процессом или вручную), затем вы изменили поле и вызвали [`$save`](../documents/document-api.mdx#save): запись не нашла документ. Библиотека проверяет это одним чтением, чтобы отличить удаление от конфликта версий ([`VersionError`](#versionerror)). Текст в этом случае: `Account.save: the document is no longer in the collection (deleted since it was read, or out of the scope of the operation's policies); nothing was written`. Вторая причина в скобках: документ остался в базе, но политики операции (тенант, мягкое удаление) его уже не видят. Запуск показал тот же текст и для версионированного документа: вместо `VersionError` приходит `DocumentNotFoundError`, потому что документа нет вовсе.

<Params title="Поля ошибки">
<Param name="operation" type="string">

Метод, который ничего не нашёл: `findOne`, `findById`, `updateOne`, `deleteOne`, `save`.

</Param>
<Param name="model" type="string">

Имя модели.

</Param>
</Params>

### Ответ клиенту

В обработчике запроса эта ошибка почти всегда означает ответ 404 вашего приложения. Класс ответа вы определяете сами; в примерах документации это `__NotFound__`:

```ts twoslash
import { DocumentNotFoundError } from "@venloc/typemo";
declare class __NotFound__ extends Error {}
declare const load: () => Promise<unknown>;
// ---cut---
try {
  await load();
} catch (error) {
  if (error instanceof DocumentNotFoundError) throw new __NotFound__(`${error.model} not found`);
  throw error;
}
```

### Когда не подходит

Если отсутствие документа для вас нормальный исход (проверка, свободно ли имя), не используйте `.orFail()`: получите `null` и проверьте его сами. Если нужно узнать только, есть ли документ, есть [`exists`](../query/reading.mdx#modelexists).

## VersionError

`VersionError` бросается при [`$save`](../documents/document-api.mdx#save) версионированного документа, если после чтения его успел изменить кто-то другой. Это оптимистичная блокировка: вместо того чтобы держать блокировку на время работы пользователя, библиотека сохраняет версию документа (поле `__v`) и в момент записи проверяет, что версия в базе та же. Если версия другая, запись не выполняется, чтобы не затереть чужие правки.

Ошибка возможна у модели, которая наследует `Versioned(...)`. С опцией схемы `optimisticConcurrency: true` условной становится каждая запись, а без неё защищены записи, зависящие от позиций элементов массива. Ниже два экземпляра одного документа: первый сохранён, второй устарел.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, Versioned, VersionError } from "@venloc/typemo";
@Schema({ collection: "accounts", optimisticConcurrency: true })
class Account extends Versioned(Entity) {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
const id = (await Accounts.findOne().orFail())._id;
// ---cut---
const mine = await Accounts.findById(id).orFail();
const theirs = await Accounts.findById(id).orFail();

theirs.balance = 10;
await theirs.$save();

mine.balance = 20;
try {
  await mine.$save();
} catch (error) {
  if (error instanceof VersionError) {
    console.log(error.message);
    // → Account: no document at version 0 (it was changed or deleted since it was read); modified: balance
    console.log(error.model, error.version, error.modifiedPaths);
    // → "Account" 0 ["balance"]
  }
}
```

Что делать с ошибкой, решаете вы: перечитать документ и повторить изменение, показать пользователю конфликт или отказать. Библиотека автоматически ничего не повторяет: она не знает, можно ли применить вашу правку к новым данным.

<Params title="Поля ошибки">
<Param name="model" type="string">

Имя модели.

</Param>
<Param name="version" type="number">

Версия, с которой документ был прочитан.

</Param>
<Param name="modifiedPaths" type="readonly string[]">

Пути, которые изменяла неудавшаяся запись. Массив заморожен.

</Param>
</Params>

### Когда не подходит

Если конфликт для вас не проблема (например, счётчик), не пересохраняйте документ: используйте атомарное обновление [`updateOne`](../writes/writes.mdx#updateone) с `$inc`, которое не читает и не сравнивает версию. Для нескольких связанных записей, которые должны пройти вместе, нужна [транзакция](../transactions/transactions.mdx#transaction).

## KeysetTokenError

`KeysetTokenError` бросается, когда токен следующей страницы, переданный в [`keysetPage`](../query/keyset.mdx#modelkeysetpage), отвергнут. Токен приходит от клиента, значит, ему нельзя доверять: клиент мог испортить его, обрезать, подставить токен от другой сортировки или собрать вручную. Поэтому библиотека проверяет токен до обращения к базе: длину и алфавит, структуру, совпадение ключей с сортировкой, а каждое значение прогоняет через приведение типа поля (объекты и операторы недопустимы). Если настроена подпись токена, то сначала проверяется она.

`KeysetTokenError` — потомок [`QueryError`](#queryerror): поле `path` всегда равно `"after"`, а текст всегда начинается с `keysetPage: invalid cursor —` и называет причину.

```ts twoslash
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ collection: "accounts", optimisticConcurrency: true })
class Account extends Versioned(Entity) {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
// ---cut---
try {
  await Accounts.keysetPage({ sort: [["title", "asc"]], limit: 20, after: "garbage" });
} catch (error) {
  if (error instanceof KeysetTokenError) {
    console.log(error.message);
    // → keysetPage: invalid cursor — it cannot be read
    console.log(error.path);
    // → "after"
  }
}
```

Причины в тексте, полученные запуском: `it cannot be read` (токен не разбирается, при этом в `cause` лежит исходная ошибка разбора), `not base64url` (в токене посторонние символы), `it was made for another sort` (токен от другой сортировки) и `longer than 4096 characters` (слишком длинный). Остальные причины (неверная или отсутствующая подпись, лишние ключи, значение неверного типа) описаны в коде и здесь не воспроизводились.

Ответ клиенту: испорченный токен — это ошибка ввода, то есть 400 вашего приложения, а не 500. Не пытайтесь «починить» токен: начните с первой страницы.

### Когда не подходит

Если страницы нумеруются числом, а не токеном, вам не нужна эта ошибка: используйте `skip` и `limit`, но помните о цене больших смещений. Как выбирать — в руководстве [Пагинация по ключу](../../queries/keyset-pagination.mdx).

## EachAsyncError

`EachAsyncError` бросается по окончании `eachAsync(fn, { continueOnError: true })`, если часть вызовов вашей функции завершилась ошибкой. С этой опцией обход не останавливается на первой ошибке: курсор дочитывается до конца, а ошибки копятся и выдаются одной пачкой, в том порядке, в котором пришли документы. Без `continueOnError` первая ошибка вашей функции просто прерывает обход и приходит как есть: класс `EachAsyncError` при этом не создаётся.

```ts twoslash
import { EachAsyncError, Entity, Prop, Schema, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ collection: "accounts", optimisticConcurrency: true })
class Account extends Versioned(Entity) {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
// ---cut---
try {
  await Accounts.find()
    .cursor()
    .eachAsync(
      (account) => {
        if (account.title === "a" || account.title === "c") throw new Error(`boom ${account.title}`);
      },
      { continueOnError: true },
    );
} catch (error) {
  if (error instanceof EachAsyncError) {
    console.log(error.message);
    // → eachAsync: 2 call(s) of the callback failed (continueOnError)
    console.log(error.errors.map((e) => (e as Error).message));
    // → ["boom a", "boom c"]
    console.log((error.cause as Error).message);
    // → "boom a"
  }
}
```

<Params title="Поля ошибки">
<Param name="errors" type="readonly unknown[]">

Каждая ошибка вашей функции в порядке документов. Массив заморожен. Тип элемента `unknown`: ваша функция может бросить что угодно, и библиотека ничего не оборачивает.

</Param>
</Params>

Первая из ошибок доступна и как стандартный `cause`, чтобы журналы, которые печатают только цепочку `cause`, показали хоть какую-то причину.

### Когда не подходит

Если обход должен остановиться на первой неудаче, не включайте `continueOnError`: ошибка вашей функции придёт как есть. Подробнее об обработке больших выборок — в руководстве [Большие выборки](../../queries/large-results.mdx), а о курсоре — в справочнике [Курсор](../query/cursor.mdx#eachasync).
