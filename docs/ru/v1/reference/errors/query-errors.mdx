Ошибки запросов приходят в трёх случаях. Запрос нельзя построить, запрос ничего не нашёл там, где вы потребовали результат, или документ изменили между чтением и записью. Это ситуации вашего приложения, а не сбои базы. Записи нет, токен страницы испорчен, двое правили один документ. У каждой ситуации свой класс, так что обработчик отвечает клиенту по классу, а не по тексту.

Если вы только начинаете, сначала прочитайте руководство [Обработка ошибок](../../errors/handling.mdx). Общее дерево классов — в разделе [Иерархия ошибок](./hierarchy.mdx).

Примеры используют модель счёта с версией документа. Версия нужна для [`VersionError`](#version-error), остальным ошибкам она не мешает.

```ts twoslash title="accounts/account.ts"
import { Entity, Prop, Schema, Versioned } from "@venloc/typemo";

@Schema({ collection: "accounts", optimisticConcurrency: true })
export class Account extends Versioned(Entity) {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Number, { required: true })
  balance!: number;
}
```

Ошибки из соседних групп описаны на других страницах — [ошибки данных](./data-errors.mdx), [ошибки сервера](./server-errors.mdx), [ошибки конфигурации и подключения](./configuration-errors.mdx).

## QueryError [#query-error]

`QueryError` бросается, когда запрос или обновление **нельзя построить**. Typemo замечает это ещё при сборке плана, и на сервер ничего не уходит. Так бывает с `undefined` в фильтре (драйвер молча искал бы `null`), с пустым `$and`, `$or` или `$nor`, с проекцией, где смешаны включение и исключение полей, с `limit` не больше нуля, с пустым обновлением, с `merge()` запроса другой модели, с обходом запроса через `for await` и с `batchSize(0)`.

Сервер принял бы такие запросы и сделал бы не то, что вы имели в виду, или отверг бы их с малопонятным текстом. Typemo говорит прямо, что не так и как исправить. В примере фильтр собран из значения, которого не оказалось.

```ts twoslash
import { Entity, Prop, QueryError, Schema, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ collection: "accounts", optimisticConcurrency: true })
class Account extends Versioned(Entity) {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
// ---cut---
const filter = JSON.parse("{}");
filter.title = undefined;

try {
  await Accounts.find(filter);
} catch (error) {
  if (error instanceof QueryError) {
    console.log(error.message);
    // → filter: undefined at "title" (use $exists: false / $unset; undefined is never a value)
    console.log(error.path);
    // → "title"
  }
}
```

Вот тексты остальных случаев на той же модели.

```text
QueryError: limit must be a positive integer, got 0 (number)
QueryError: limit must be a positive integer, got "3" (string)
QueryError: update: an empty update changes nothing
QueryError: filter: $or must be a non-empty array (at "$or")
QueryError: projection: cannot mix inclusion (title) and exclusion (balance); the server refuses it
QueryError: batchSize must be a positive integer, got 0 (number) (the driver reads 0 as "the server default"; leave batchSize out for the default)
QueryError: find(): a query is not iterable with "for await"; iterate its cursor instead: for await (const doc of Model.find(filter).cursor())
```

Значение в тексте печатается вместе с типом. `"3"` — это строка, а не число, и `limit` её не принимает, так что значения из адреса страницы приводите к числу сами. С `limit(0)` и `batchSize(0)` дело в самой базе. Она читает ноль как «без ограничения» и «размер по умолчанию», а ноль легко получить из пустого параметра запроса. Сам запрос не асинхронный итератор. Чтобы пройти по результатам порциями, вызовите у него `.cursor()`, как подсказывает сообщение.

### Поля [#fields]

<Params title="Поля ошибки">
<Param name="path" type="string | undefined">

Путь через точку к месту, где во вводе проблема, если он известен. Например `title` или `$or`. У ошибок вроде `limit` пути нет, и поле равно `undefined`.

</Param>
</Params>

### Когда не подходит [#query-error.when-not-to-use]

`QueryError` относится к построению запроса. Если фильтр называет поле, которого нет в модели, вы получите [`StrictModeError`](./data-errors.mdx#strict-mode-error). Если значение не приводится к типу поля, получите [`CastError`](./data-errors.mdx#cast-error). Ловите нужные классы явно, общий `catch` по `QueryError` их не поймает.

## DocumentNotFoundError [#document-not-found-error]

`DocumentNotFoundError` бросается, когда вы потребовали результат методом [`.orFail()`](../query/reading.mdx#or-fail), а ничего не нашлось. Так же она срабатывает, если запись с `orFail` не задела ни одного документа. Без `.orFail()` чтение вернуло бы `null` (или пустой массив), а обновление сообщило бы `matchedCount: 0`. Ошибка удобна там, где отсутствие документа для вас исключение. «Счёт по адресу страницы не найден» превращается в один `catch` вместо цепочки проверок на `null`.

```ts twoslash
import { DocumentNotFoundError, Entity, Prop, Schema, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ collection: "accounts", optimisticConcurrency: true })
class Account extends Versioned(Entity) {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
// ---cut---
try {
  await Accounts.findOne({ title: "no such account" }).orFail();
} catch (error) {
  if (error instanceof DocumentNotFoundError) {
    console.log(error.message);
    // → Account.findOne: no document matched the filter (orFail)
    console.log(error.operation, error.model);
    // → "findOne" "Account"
  }
}
```

Поле `operation` называет метод, который вы вызвали. Это `findById` для поиска по идентификатору, `findByIdAndUpdate`, `findOneAndUpdate`, `find`, `replaceOne` или `deleteOne`, на каждом из них ошибка проверена. Внутренних имён операций в тексте нет. Фильтр в ошибку **намеренно не попадает**. Он может содержать персональные данные, а Mongoose хранил его в поле `query` и печатал вместе с ошибкой.

### Другие ситуации [#other-cases]

Ту же ошибку бросает сохранение документа, который успели удалить. Вы прочитали документ, его удалили другим процессом или вручную, затем вы изменили поле и вызвали [`$save`](../documents/document-api.mdx#save). Запись не нашла документ. Typemo проверяет это одним чтением, чтобы отличить удаление от конфликта версий ([`VersionError`](#version-error)). Текст в этом случае такой — `Account.save: the document is no longer in the collection (deleted since it was read, or out of the scope of the operation's policies); nothing was written`.

Вторая причина в скобках означает, что документ остался в базе, но политики операции (тенант, мягкое удаление) его уже не видят. Для версионированного документа текст тот же. Вместо `VersionError` приходит `DocumentNotFoundError`, потому что документа нет вовсе.

<Params title="Поля ошибки">
<Param name="operation" type="string">

Метод, который ничего не нашёл — `findOne`, `findById`, `updateOne`, `deleteOne` или `save`.

</Param>
<Param name="model" type="string">

Имя модели.

</Param>
</Params>

### Ответ клиенту [#response]

В обработчике запроса эта ошибка почти всегда значит ответ 404 вашего приложения. Класс ответа вы определяете сами, в примерах документации это `__NotFound__`.

```ts twoslash
import { DocumentNotFoundError } from "@venloc/typemo";
declare class __NotFound__ extends Error {}
declare const load: () => Promise<unknown>;
// ---cut---
try {
  await load();
} catch (error) {
  if (error instanceof DocumentNotFoundError) throw new __NotFound__(`${error.model} not found`);
  throw error;
}
```

### Когда не подходит [#document-not-found-error.when-not-to-use]

Если отсутствие документа для вас нормальный исход, например при проверке, свободно ли имя, не используйте `.orFail()`. Вы получите `null` и проверите его сами. А чтобы узнать только, есть ли документ, возьмите [`exists`](../query/reading.mdx#model.exists).

## VersionError [#version-error]

`VersionError` бросается при [`$save`](../documents/document-api.mdx#save) версионированного документа, если после чтения его успел изменить кто-то другой. Это оптимистичная блокировка. Typemo не держит блокировку, пока пользователь работает, а запоминает версию документа (поле `__v`) и в момент записи проверяет, что в базе та же версия. Если версия другая, запись не выполняется, и чужие правки остаются целы.

Ошибка возможна у модели, которая наследует `Versioned(...)`. С опцией схемы `optimisticConcurrency: true` условной становится каждая запись. Без неё защищены записи, которые зависят от позиций элементов массива. В примере два экземпляра одного документа, первый сохранён, второй устарел.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, Versioned, VersionError } from "@venloc/typemo";
@Schema({ collection: "accounts", optimisticConcurrency: true })
class Account extends Versioned(Entity) {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
const id = (await Accounts.findOne().orFail())._id;
// ---cut---
const mine = await Accounts.findById(id).orFail();
const theirs = await Accounts.findById(id).orFail();

theirs.balance = 10;
await theirs.$save();

mine.balance = 20;
try {
  await mine.$save();
} catch (error) {
  if (error instanceof VersionError) {
    console.log(error.message);
    // → Account: no document at version 0 (it was changed or deleted since it was read); modified: balance
    console.log(error.model, error.version, error.modifiedPaths);
    // → "Account" 0 ["balance"]
  }
}
```

Что делать с ошибкой, решаете вы. Можно перечитать документ и повторить изменение, показать пользователю конфликт или отказать. Сам Typemo ничего не повторяет, потому что не знает, можно ли применить вашу правку к новым данным.

<Params title="Поля ошибки">
<Param name="model" type="string">

Имя модели.

</Param>
<Param name="version" type="number">

Версия, с которой документ был прочитан.

</Param>
<Param name="modifiedPaths" type="readonly string[]">

Пути, которые изменяла неудавшаяся запись. Массив заморожен.

</Param>
</Params>

### Когда не подходит [#version-error.when-not-to-use]

Если конфликт для вас не проблема, как у счётчика, не пересохраняйте документ. Возьмите атомарное обновление [`updateOne`](../writes/writes.mdx#update-one) с `$inc`, оно не читает и не сравнивает версию. А когда несколько связанных записей должны пройти вместе, нужна [транзакция](../transactions/transactions.mdx#transaction).

## KeysetTokenError [#keyset-token-error]

`KeysetTokenError` бросается, когда токен следующей страницы, переданный в [`keysetPage`](../query/keyset.mdx#model.keyset-page), отвергнут. Токен приходит от клиента, и доверять ему нельзя. Клиент мог испортить его, обрезать, подставить токен от другой сортировки или собрать вручную.

Поэтому Typemo проверяет токен до обращения к базе. Сначала подпись, если она настроена. Затем длину и алфавит, структуру и совпадение ключей с сортировкой. Каждое значение проходит приведение к типу поля, объекты и операторы недопустимы.

`KeysetTokenError` — потомок [`QueryError`](#query-error). Поле `path` у неё всегда равно `"after"`, а текст всегда начинается с `keysetPage: invalid cursor —` и называет причину.

```ts twoslash
import { Entity, KeysetTokenError, Prop, Schema, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ collection: "accounts", optimisticConcurrency: true })
class Account extends Versioned(Entity) {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
// ---cut---
try {
  await Accounts.keysetPage({ sort: [["title", "asc"]], limit: 20, after: "garbage" });
} catch (error) {
  if (error instanceof KeysetTokenError) {
    console.log(error.message);
    // → keysetPage: invalid cursor — it cannot be read
    console.log(error.path);
    // → "after"
  }
}
```

В тексте встречаются такие причины.

- `it cannot be read` — токен не разбирается, в `cause` лежит исходная ошибка разбора.
- `not base64url` — в токене посторонние символы.
- `it was made for another sort` — токен от другой сортировки.
- `longer than 4096 characters` — токен слишком длинный.

Остальные причины (неверная или отсутствующая подпись, лишние ключи, значение неверного типа) описаны в коде и здесь не воспроизводились.

Испорченный токен — это ошибка ввода, значит, ответ вашего приложения должен быть 400, а не 500. Не пытайтесь «починить» токен, начните с первой страницы.

### Когда не подходит [#keyset-token-error.when-not-to-use]

Если страницы нумеруются числом, а не токеном, эта ошибка вам не нужна. Берите `skip` и `limit`, но помните о цене больших смещений. Как выбирать, описано в руководстве [Пагинация по ключу](../../queries/keyset-pagination.mdx).

## EachAsyncError [#each-async-error]

`EachAsyncError` бросается по окончании `eachAsync(fn, { continueOnError: true })`, если часть вызовов вашей функции завершилась ошибкой. С этой опцией обход не останавливается на первой ошибке. Курсор дочитывается до конца, а ошибки копятся и выдаются одной пачкой в том порядке, в котором пришли документы. Без `continueOnError` первая ошибка вашей функции просто прерывает обход и приходит как есть, и класс `EachAsyncError` не создаётся.

```ts twoslash
import { EachAsyncError, Entity, Prop, Schema, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ collection: "accounts", optimisticConcurrency: true })
class Account extends Versioned(Entity) {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
// ---cut---
try {
  await Accounts.find()
    .cursor()
    .eachAsync(
      (account) => {
        if (account.title === "a" || account.title === "c") throw new Error(`boom ${account.title}`);
      },
      { continueOnError: true },
    );
} catch (error) {
  if (error instanceof EachAsyncError) {
    console.log(error.message);
    // → eachAsync: 2 call(s) of the callback failed (continueOnError)
    console.log(error.errors.map((e) => (e as Error).message));
    // → ["boom a", "boom c"]
    console.log((error.cause as Error).message);
    // → "boom a"
  }
}
```

<Params title="Поля ошибки">
<Param name="errors" type="readonly unknown[]">

Каждая ошибка вашей функции в порядке документов. Массив заморожен. Элемент имеет тип `unknown`, потому что ваша функция может бросить что угодно, а Typemo ничего не оборачивает.

</Param>
</Params>

Первая из ошибок доступна и как стандартный `cause`. Журналы, которые печатают только цепочку `cause`, покажут хотя бы одну причину.

### Когда не подходит [#each-async-error.when-not-to-use]

Если обход должен остановиться на первой неудаче, не включайте `continueOnError`, и ошибка вашей функции придёт как есть. Об обработке больших выборок читайте в руководстве [Большие выборки](../../queries/large-results.mdx), а о курсоре — в справочнике [Курсор](../query/cursor.mdx#each-async).
