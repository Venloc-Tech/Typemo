Здесь описаны обновления, где новое значение поля вычисляется **из других полей того же документа**. Это тип `UpdatePipelineFor`, класс `UpdatePipelines` и шесть стадий, которые такое обновление допускает. Если вы только начинаете, сначала прочитайте руководство [Обновление через конвейер](../../writes/pipeline-updates.mdx).

**Конвейер обновления** — это обновление, записанное не объектом операторов (`$set`, `$inc`), а списком стадий агрегации. Он выручает там, где операторы бессильны. В операторах значение известно заранее, а конвейер берёт его из самого документа. Записать в `note` строку из `owner` и `title` или удвоить баланс выше порога операторами нельзя. Сервер выполняет конвейер одной атомарной командой.

Стадии вы вручную не пишете. [`updateOne`](./writes.mdx#updateone), [`updateMany`](./writes.mdx#updatemany) и [`findOneAndUpdate`](./writes.mdx#findoneandupdate) принимают вместо объекта операторов функцию, которой достаётся строитель конвейера в «режиме обновления». Массив стадий передать нельзя.

```ts twoslash title="accounts/account.ts"
import { type Defaulted, Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true, unique: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => Number, { min: 0, default: 0 })
  balance!: Defaulted<number>;

  @Prop(() => String)
  note?: string;

  @Prop(() => String)
  nickname?: string;

  @Prop(() => Date)
  lastLogin?: Date;
}
```

Во всех примерах исходный документ такой — `title: "Main"`, `owner: "alice"`, `balance: 10`, `nickname: "al"`. Результат в комментарии `// →` — то, что лежит в базе после обновления.

## UpdatePipelines

`UpdatePipelines` — класс со статическим методом `compile`. Он превращает функцию-конвейер в список стадий и следит, чтобы стадия была хотя бы одна. То же самое делают внутри `updateOne` и остальные методы. Вам `compile` нужен, только чтобы посмотреть, какие стадии уйдут на сервер.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const stages = UpdatePipelines.compile<Account>((p) => p.set((f) => ({ balance: fn.add(f.balance, 5) })));
console.log(JSON.stringify(stages));
// → [{"$set":{"balance":{"$add":["$balance",5]}}}]
```

<Returns type="readonly PipelineStage[]">

Список сериализованных стадий. Он не пуст.

</Returns>

<Params>
<Param name="build" type="UpdatePipelineFor<T>" required>

Функция, которая получает строитель и возвращает его после добавления стадий.

</Param>
</Params>

<FullType>

```ts
static compile<T>(build: UpdatePipelineFor<T>): readonly PipelineStage[]
```

</FullType>

### Ошибки

Функция без единой стадии отвергается как ошибка запроса. Пустой конвейер — это ошибка одного вызова, а не настройки приложения.

```text
QueryError: an update pipeline needs at least one stage
```

### Когда не подходит

Если новые значения известны заранее, берите объект операторов — [`$set`](./update-operators.mdx#set), [`$inc`](./update-operators.mdx#inc). Он проще и проверяется целиком до отправки. Что проверяется у конвейера, описано ниже в разделе «Что проверяется».

## UpdatePipelineFor

`UpdatePipelineFor<T>` — тип функции, которую принимают методы обновления. Она получает строитель с типом документа модели и возвращает цепочку стадий. Тип нужен, когда вы выносите конвейер в отдельную функцию.

```ts twoslash title="accounts/pipelines.ts"
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
export const doubleBalance: UpdatePipelineFor<Account> = (p) =>
  p.set((f) => ({ balance: fn.multiply(f.balance, 2) }));

await Accounts.updateMany({ owner: "alice" }, doubleBalance);
```

<FullType>

```ts
type UpdatePipelineFor<T> = (p: PipelineBuilder<PipelineDoc<T>, "update", "empty">) => StagedPipeline;
```

</FullType>

Строитель в режиме `update` знает только шесть стадий — `set`, `addFields`, `unset`, `project`, `replaceWith`, `replaceRoot`. Остальные стадии агрегации (`match`, `group`, `unwind`) в обновлении недопустимы, и типы их не показывают.

Конвейер обновления проходит через сторожа. Константы стадий приводятся к типам и проверяются до отправки. Удаление обязательного поля отвергается. Вычисляемое значение поля с ограничениями (`min`, `max`, `enum`, `minLength`, `maxLength`, `match`, `required`) проверяет сервер, получив то же выражение в условии фильтра. Подробности и ограничения — в разделе [Что проверяется](#что-проверяется) ниже.

## .set

`.set(builder)` записывает вычисленные значения в поля. `builder` получает **прокси полей** `f`. Обращение `f.balance` значит «значение поля `balance` в документе на момент обновления». Значения строятся функциями `fn.*` — `fn.add`, `fn.concat`, `fn.cond` и другими из справочника агрегаций.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
await Accounts.updateOne({ title: "Main" }, (p) => p.set((f) => ({ note: fn.concat(f.owner, "/", f.title) })));
// → note: "alice/Main"
```

<Returns type="PipelineBuilder">

Строитель для следующей стадии. Стадии идут по порядку, и каждая видит результат предыдущей.

</Returns>

<Params>
<Param name="builder" type="(f: FieldProxy<T>) => Record<string, unknown>" required>

Функция, возвращающая объект «путь и выражение». Ключ может быть вложенным через точку. Ключ, которого нет в модели, компилятор отвергает.

</Param>
</Params>

<FullType>

```ts
set<const F extends Record<string, unknown>>(
  builder: (f: FieldProxy<T>) => F & InvalidPathKeys<T, F> & ExprValues<F>,
): PipelineBuilder<ApplyFields<T, F>, M, "staged">
```

</FullType>

### Несколько стадий

Стадии идут по порядку. Во втором `.set` заметка уже такая, какой её сделал первый.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
await Accounts.updateOne({ title: "Main" }, (p) =>
  p
    .set((f) => ({ note: fn.concat(f.owner, "/", f.title) }))
    .set((f) => ({ note: fn.concat(f.note, "!") })),
);
// → note: "alice/Main!"
```

### Ошибки

`arrayFilters` с конвейером недопустимы, потому что в конвейере нет позиционных путей.

```text
QueryError: arrayFilters: not allowed with an update pipeline
QueryError: update: an update pipeline is built with the pipeline builder: updateOne(filter, (p) => p.set({ … })), not passed as an array
```

Второе сообщение приходит, если вместо функции передан массив стадий.

### Что проверяется

Объект операторов проходит приведение типов и валидаторы поля до отправки. У конвейера значения — выражения сервера, и проверка зависит от того, что именно вы записываете.

**Константа** (`balance: -1`, `note: "x"`) приводится к типу поля и проверяется до отправки, как у `$set`. Ошибка — `CastError` или `ValidationError`.

**Вычисляемое значение** поля с ограничениями проверяет сервер. Typemo добавляет в фильтр условие с тем же выражением и теми же ограничениями, поэтому неверный результат не запишется, и это атомарно. В примере баланс ушёл бы ниже нуля, и обновление отвергнуто.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
try {
  await Accounts.updateOne({ title: "Main" }, (p) => p.set((f) => ({ balance: fn.add(f.balance, -50) })));
} catch (error) {
  console.log(error instanceof ValidationError);
  // → true
}
```

```text
ValidationError: Validation failed: "balance": the update pipeline computes -40; the value must be at least 0; nothing was written [min]
```

Условие сервера считает выражение над хранимым документом. Поэтому оно точно, пока выражение не читает поля, изменённые предыдущей стадией. Остальные случаи Typemo отвергает до отправки (`ValidationError`).

- Вычисляемое значение читает поле, изменённое ранее, или `$$ROOT` после изменения.
- Вычисляемое значение стоит после стадии, которая переписывает документ.
- Поле с ограничениями лежит за массивом или `Map`.
- Целый документ вычислен выражением на схеме с обязательными полями.
- `upsert` и [`bulkWrite`](./writes.mdx#bulkwrite) работают с вычисляемым значением такого поля.

```text
ValidationError: Validation failed: "balance": update.1.$set: the computed value of "balance" cannot be checked against its constraints: it reads "balance", which an earlier stage of the pipeline changes; compute both in one stage [min]
```

Сервер не умеет выразить несколько проверок, и они не выполняются. Это ваши функции `validate`, ограничения элементов внутри вычисленного массива, `Map` или вложенного документа и тип вычисленного значения у поля без ограничений. Для `maxLength` и `minLength` сервер считает кодовые точки, а JavaScript — единицы UTF-16. У строк с символами вне основной плоскости длина может расходиться.

### Когда не подходит

Если значение известно заранее, [`$set`](./update-operators.mdx#set) проверит его строже. Чтобы прибавить число, берите [`$inc`](./update-operators.mdx#inc) — он защищает границы `min` и `max`.

## .addFields

`.addFields(builder)` делает то же, что `.set`. В агрегации `$set` — синоним `$addFields`, так что берите то имя, которое вам привычнее.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";

  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });

// ---cut---
await Accounts.updateOne({ title: "Main" }, (p) => p.addFields((f) => ({ note: fn.concat(f.title, "!") })));
```

## .unset

`.unset(path)` удаляет поле или список полей. Для заранее известных полей то же делает оператор [`$unset`](./update-operators.mdx#unset). `.unset` нужен, когда за ним идут другие стадии конвейера.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
await Accounts.updateOne({ title: "Main" }, (p) => p.unset("nickname"));
// → поле nickname удалено, owner остаётся "alice"
```

<Params>
<Param name="fields" type="Path | [Path, ...Path[]]" required>

Путь поля или непустой список путей.

</Param>
</Params>

<FullType>

```ts

  fields: U,

```

</FullType>

### Обязательные поля

```text

```

## .project

`.project(spec)` оставляет в документе только перечисленные поля (`1`) или убирает перечисленные (`0`). `_id` остаётся всегда. Это самая радикальная стадия, потому что всё, что вы не назвали, из документа **исчезает**.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
await Accounts.updateOne({ title: "Main" }, (p) => p.project({ title: 1, owner: 1 }));
// → в документе остались только _id, title и owner
```

<Params>
<Param name="spec" type="{ [path]: 0 | 1 | boolean }" required>

Пути с `1` (оставить) или `0` (убрать). Смешивать их нельзя, кроме `_id`. Вместо объекта можно передать функцию с прокси полей и вычислять значения.

</Param>
</Params>

<FullType>

```ts
project<const P extends { readonly [K in DocPaths<T> | "_id"]?: 0 | 1 | boolean }>(
  spec: P & Exact<P, { readonly [K in DocPaths<T> | "_id"]?: 0 | 1 | boolean }> & MixedProjection<P>,
): PipelineBuilder<ApplyProject<T, P>, M, "staged">
```

</FullType>

### Модели с неизменяемыми полями

Если у модели есть поля с `immutable` или служебное `createdAt` (у `Timestamped`), стадии `.project`, `.replaceWith` и `.replaceRoot` проходят, только когда новый документ переносит **каждое** неизменяемое поле как есть. Допустимы такие варианты.

- Поле, взятое из себя же (`createdAt: f.createdAt`, `"$createdAt"`).
- `"$$ROOT"` целиком.
- `$mergeObjects` с `"$$ROOT"` и объектом полей, среди которых нет неизменяемых.
- Включающий `.project`, который перечисляет эти поля.
- Исключающий `.project`, который их не трогает.

Всё остальное отвергается до отправки, в том числе поле, перенесённое из другого поля, и неизменяемое поле, переписанное константой. В тексте ошибки названы потерянные поля и дана подсказка.

```text
StrictModeError: update.0.$project: $project rewrites the whole document and would change or drop the immutable fields createdAt, owner; carry each unchanged (createdAt: "$createdAt") or use $set/$unset of the other fields [immutable]
```

Ключи объекта в `.replaceWith` и `.replaceRoot` вы пишете именами полей модели. Если у поля задан `dbName`, Typemo сам переведёт их в имена в базе. Зато `$$ROOT` и `$$CURRENT` на модели с такими полями не допускаются — `ConfigurationError: Stamped: $$ROOT/$$CURRENT of a model with dbName fields would give stored names to the rows; list the fields instead`. Перечисляйте поля явно.

### Когда не подходит

Чтобы убрать одно поле, берите [`.unset`](#unset). Чтобы изменить несколько — [`.set`](#set).

## .replaceWith

`.replaceWith(builder)` заменяет весь документ вычисленным. Это замена вроде [`replaceOne`](./writes.mdx#replaceone), только новое содержимое строится из полей старого документа. `_id` остаётся тем же.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
await Accounts.updateOne({ title: "Main" }, (p) =>
  p.replaceWith((f) => ({ title: f.title, owner: "moved", balance: 1 })),
);
// → документ: title: "Main", owner: "moved", balance: 1; остальных полей нет
```

### Ошибки

Для моделей с неизменяемыми полями действуют те же ограничения, что у [`.project`](#project).

### Когда не подходит

Если замена целиком известна заранее, берите [`replaceOne`](./writes.mdx#replaceone) — он проверяет значения.

## .replaceRoot

`.replaceRoot(builder)` делает то же, что `.replaceWith`, — заменяет весь документ вычисленным. Это две записи одной стадии сервера, результат у них одинаковый.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
await Accounts.updateOne({ title: "Main" }, (p) =>
  p.replaceRoot((f) => ({ title: f.title, owner: f.owner })),
);
// → в документе остались только _id, title и owner
```
