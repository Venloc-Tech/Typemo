На этой странице описаны пять типов, которыми Typemo описывает данные, уходящие в базу: `CreateInput`, `UpdateInput`, `Update`, `Replacement` и `WriteValue`. Все они выводятся из класса модели, поэтому меняются вместе с ним. Они нужны, когда вы пишете собственные функции вокруг методов записи и хотите описать аргумент теми же типами, что и сама библиотека.

Если вы только начинаете, сначала прочитайте руководство [Создать документы](../../writes/create.mdx). Эта страница — справочник.

Зачем нужны отдельные типы, а не просто тип модели? Форма данных на входе отличается от формы документа. При создании нельзя требовать поля со значением по умолчанию, при обновлении нельзя разрешать менять `_id` и поля с `immutable`, а на вход принимаются более свободные виды значений: `ObjectId` можно передать строкой, `int64` — десятичной строкой, `Map` — обычным объектом. Один общий тип для всего этого либо запретил бы нужное, либо разрешил бы лишнее.

Все примеры используют одну модель счёта.

```ts twoslash title="accounts/account.ts"
import { type Defaulted, Entity, type Immutable, Prop, Schema } from "@venloc/typemo";

@Schema()
export class Line {
  @Prop(() => String, { required: true })
  sku!: string;

  @Prop(() => Number, { required: true })
  qty!: number;
}

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true, unique: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => Number, { min: 0, default: 0 })
  balance!: Defaulted<number>;

  @Prop(() => [String])
  tags!: string[];

  @Prop(() => String)
  note?: string;

  @Prop(() => String, { immutable: true })
  region?: Immutable<string>;

  @Prop(() => [Line])
  lines!: Line[];
}
```

## CreateInput

`CreateInput<T>` — тип данных нового документа: то, что принимают [`create`](./writes.mdx#create), [`insertOne`](./writes.mdx#insertone), [`insertMany`](./writes.mdx#insertmany) и `Model.new`. Обязательные поля модели обязательны и здесь, а поля с `Defaulted`, необязательные поля (`?:`), массивы и поле тенанта можно не передавать: массив без `required` получит `[]`. Виртуальных полей и методов в типе нет. В подсказке редактора тип раскрыт до полей, так что видно, что именно принимается.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema()
class Line {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => String) alias?: string;
  @Prop(() => Date) lastLogin?: Date;
  @Prop(() => Number) flags?: number;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [Number]) scores!: number[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Spec.map(Number)) counters?: Map<string, number>;
  @Prop(() => String, { immutable: true }) region?: Immutable<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const draft: CreateInput<Account> = { title: "Main", owner: "alice" };
const account = await Accounts.create(draft);
console.log(account.balance);
// → 0
```

Вложенные документы описываются тем же типом: элемент `lines` — это `CreateInput<Line>`, значит, `sku` и `qty` обязательны и там. Значение `undefined` вводом не бывает: поле либо есть, либо отсутствует, потому что драйвер записал бы вместо `undefined` значение `null`.

Вот что показывает подсказка для модели страницы:

```ts twoslash

//   ^?
```

### Какие виды значений принимаются

Значение принимается в нескольких видах, чтобы данные из внешнего мира не приходилось превращать в типы драйвера вручную. `ObjectId` и `UUID` можно передать строкой, `int64` — `bigint` или десятичной строкой (`Int64String`), `Map` — `Map` или обычным объектом, массив — обычным или `readonly`. Формат строки проверяется во время работы.

```text
CastError: Cast to ObjectId failed at path "_id" for "zzz" (string): not a 24-character hex string [format]
```

### Когда не подходит

Для замены документа целиком берите [`Replacement`](#replacement): в нём нет `_id` и служебных полей.

## UpdateInput

`UpdateInput<T>` — набор полей, которые запись **может изменить**: все поля модели необязательные, но без `_id` и без полей с `immutable`. Это тип «патча»: объекта с частью полей, который вы принимаете из формы или запроса и кладёте в [`$set`](./update-operators.mdx#set).

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema()
class Line {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => String) alias?: string;
  @Prop(() => Date) lastLogin?: Date;
  @Prop(() => Number) flags?: number;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [Number]) scores!: number[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Spec.map(Number)) counters?: Map<string, number>;
  @Prop(() => String, { immutable: true }) region?: Immutable<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const rename = async (title: string, patch: UpdateInput<Account>) => {
  await Accounts.updateOne({ title }, { $set: patch });
};
await rename("Main", { owner: "bob", note: "moved" });
```

Патч кладётся в `$set` целиком, без приведения типов и промежуточных переменных. Подсказка показывает его раскрытым:

```ts twoslash
import { type Defaulted, Entity, type Immutable, Prop, Schema, type CreateInput, type Replacement, type UpdateInput } from "@venloc/typemo";
@Schema()

  @Prop(() => Number, { required: true }) qty!: number;

  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String, { immutable: true }) region?: Immutable<string>;
  @Prop(() => [Line]) lines!: Line[];
}

//   ^?
```

Пустой патч (`{}`) компилятор пропустит, а разбор во время работы отвергнет: `QueryError: update: operator "$set" is empty`.

Поле, которое менять нельзя, в типе отсутствует. Компилятор не примет `region` (у него `immutable`) и `_id`:

### Когда не подходит

`UpdateInput` описывает только записываемые поля верхнего уровня. Для остальных операторов (`$inc`, `$push`) и вложенных путей используйте [`Update`](#update).

## Update

`Update<T>` — тип **объекта операторов**: то, что принимают [`updateOne`](./writes.mdx#updateone), [`updateMany`](./writes.mdx#updatemany), [`findOneAndUpdate`](./writes.mdx#findoneandupdate) и [`findByIdAndUpdate`](./writes.mdx#findbyidandupdate). Ключи первого уровня — операторы, а допустимые пути и операнды каждого оператора зависят от модели: `$inc` принимает только числовые поля, `$push` — только массивы, `$unset` — только необязательные поля.

Тип нужен, если обновление собирается в одном месте, а применяется в другом.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema()
class Line {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => String) alias?: string;
  @Prop(() => Date) lastLogin?: Date;
  @Prop(() => Number) flags?: number;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [Number]) scores!: number[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Spec.map(Number)) counters?: Map<string, number>;
  @Prop(() => String, { immutable: true }) region?: Immutable<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const topUp = (amount: number): Update<Account> => ({ $inc: { balance: amount } });

await Accounts.updateOne({ title: "Main" }, topUp(10));
```

Здесь и работает основная защита: оператор не на том поле не скомпилируется.

```ts twoslash

const bad: Update<Account> = { $inc: { title: 1 } };
```

Тип принимает те же операторы, что и разбор во время работы: `$set`, `$setOnInsert`, `$unset`, `$inc`, `$mul`, `$min`, `$max`, `$currentDate`, `$rename`, `$push`, `$addToSet`, `$pull`, `$pullAll`, `$pop`, `$bit`. Их подробное описание — на странице [Операторы обновления](./update-operators.mdx). Пустое обновление и один путь под двумя операторами метод отвергает во время работы (`QueryError`), как описано в [Операторах обновления](./update-operators.mdx).

Второй параметр `Loose` нужен самим методам записи: в ограничении их обобщённого параметра ключи записей `Map` принимают любое значение, а реально переданные ключи проверяет `UpdateCheck`. В своём коде его указывать не нужно.

<FullType>

```ts
type Update<in out T, in out Loose extends boolean = true> = {
  $set?: SetFields<T, false, Loose>;
  $setOnInsert?: SetFields<T, true, Loose>;
  $unset?: { [P in UnsetPaths<T>]?: "" | 1 | true } & LooseEntries<T, Loose>;
  $inc?: { [P in NumericPaths<T>]?: NumericOperand<NonNullable<WriteValue<T, P>>> } & LooseEntries<T, Loose>;
  $mul?: { [P in NumericPaths<T>]?: NumericOperand<NonNullable<WriteValue<T, P>>> } & LooseEntries<T, Loose>;
  $min?: { [P in OrderablePaths<T>]?: CompareOf<NonNullable<WriteValue<T, P>>> } & LooseEntries<T, Loose>;
  $max?: { [P in OrderablePaths<T>]?: CompareOf<NonNullable<WriteValue<T, P>>> } & LooseEntries<T, Loose>;
  $currentDate?: { /* Date: true | { $type: "date" }, Timestamp: { $type: "timestamp" } */ } & LooseEntries<T, Loose>;
  $rename?: { [P in RenamePaths<T>]?: RenameTarget<T, P> };
  $push?: { [P in ArrayPaths<T>]?: PushOperand<ElementAt<T, P>> } & LooseEntries<T, Loose>;
  $addToSet?: { [P in ArrayPaths<T>]?: AddToSetOperand<ElementAt<T, P>> } & LooseEntries<T, Loose>;
  $pull?: { [P in ArrayPaths<T>]?: PullOperand<NonNullable<ElementAt<T, P>>> } & LooseEntries<T, Loose>;
  $pullAll?: { [P in ArrayPaths<T>]?: readonly InputOf<ElementAt<T, P>>[] } & LooseEntries<T, Loose>;
  $pop?: { [P in ArrayPaths<T>]?: 1 | -1 } & LooseEntries<T, Loose>;
  $bit?: { [P in IntegerPaths<T>]?: BitOperand<NonNullable<WriteValue<T, P>>> } & LooseEntries<T, Loose>;
};
```

</FullType>

### Когда не подходит

Для обновления, в котором значение вычисляется из других полей, объект операторов не годится: используйте [конвейер](./pipeline-updates.mdx).

## Replacement

`Replacement<T>` — тип **нового документа** для [`replaceOne`](./writes.mdx#replaceone) и [`findOneAndReplace`](./writes.mdx#findoneandreplace). Это `CreateInput<T>` без `_id` и без служебных полей `createdAt`, `updatedAt` и `__v`: `_id` остаётся прежним, а служебные поля ведёт ядро.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema()
class Line {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => String) alias?: string;
  @Prop(() => Date) lastLogin?: Date;
  @Prop(() => Number) flags?: number;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [Number]) scores!: number[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Spec.map(Number)) counters?: Map<string, number>;
  @Prop(() => String, { immutable: true }) region?: Immutable<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const fresh: Replacement<Account> = { title: "Main", owner: "carol", region: "eu" };
await Accounts.replaceOne({ title: "Main" }, fresh);
```

Поле `region` у этой модели неизменяемое (`immutable`), и замена должна передать его явно, иначе она потеряла бы поле: без него `replaceOne` отвергает замену во время работы (`StrictModeError … without the immutable field "region" would drop it …`), хотя в типе поле необязательное. Подсказка:

## WriteValue

`WriteValue<T, P>` — тип значения по **пути записи** `P`. Он отвечает на вопрос «что лежит по этому пути в обновлении». Путь записи отличается от пути чтения: через массив нужно пройти позиционным знаком, иначе тип будет `never`, как и ответ сервера об ошибке. Тип нужен при построении собственных обёрток над обновлениями.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema()
class Line {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => String) alias?: string;
  @Prop(() => Date) lastLogin?: Date;
  @Prop(() => Number) flags?: number;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [Number]) scores!: number[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Spec.map(Number)) counters?: Map<string, number>;
  @Prop(() => String, { immutable: true }) region?: Immutable<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---

console.log(qty, line.sku);
// → 5 "x"
```

```ts
type WriteValue<T, P extends string> = T extends unknown
  ? P extends `${infer H}.${infer R}`
    ? H extends DataKeys<T>
      ? WriteStep<NonNullable<T[H]>, R>
      : never
    : P extends DataKeys<T>
      ? T[P]
      : never
  : never;
```
