Здесь описаны все операторы, которые принимают [`updateOne`](./writes.mdx#update-one), [`updateMany`](./writes.mdx#update-many), [`findOneAndUpdate`](./writes.mdx#find-one-and-update) и [`findByIdAndUpdate`](./writes.mdx#find-by-id-and-update), и модификаторы `$each`, `$position`, `$slice` и `$sort` оператора `$push`. У каждого указано, к каким полям он применим, какое значение принимает и что делает с документом.

Если вы только начинаете, сначала прочитайте руководство [Операторы обновления](../../writes/update-operators.mdx). Эта страница — справочник.

**Оператор обновления** — это ключ, который начинается с `$` и говорит базе, что сделать с полем. `$inc` прибавляет число, `$push` дописывает элемент в массив. Само обновление — объект, где ключи первого уровня — операторы, а значения — объекты «путь и операнд». База меняет документ на месте и атомарно. Два параллельных `$inc` дадут в сумме оба прибавления, а цепочка «прочитать, прибавить, записать» потеряла бы одно из них.

Typemo проверяет обновление дважды. Компилятор знает поля модели и то, какие операторы к каким полям применимы. Во время работы Typemo приводит значения к типам схемы и запускает валидаторы полей. Обновление отвергается целиком в трёх случаях.

- Оно пусто (`{}` или оператор без путей).
- Один путь меняют два оператора (сервер отвечает ошибкой 40).
- В значении стоит `undefined`. Значением он не бывает, а для удаления поля есть `$unset`.

Все примеры используют одну модель счёта и один исходный документ.

<Snippet id="reference/writes/update-operators/intro" title="accounts/account.ts" twoslash />

Исходный документ, с которого начинается каждый пример, такой — `title: "Main"`, `owner: "alice"`, `balance: 10`, `tags: ["a", "b"]`, `nickname: "al"`, `points: 10n`, `flags: 1`, `scores: [5, 3]`, `lines: [{ sku: "x", qty: 1 }, { sku: "y", qty: 5 }]`, `counters: { logins: 1 }`. Результат в комментарии `// →` — то, что лежит в базе после обновления.

У операндов одно общее правило. `ObjectId` и `UUID` принимают строку, `int64` (`bigint`) принимает десятичную строку, в том числе в `$inc`, `$mul`, `$min` и `$max`. Число вместо строки `"5"` в `$inc` для поля-числа не принимается.

## $set [#set]

`$set` записывает значения в поля. Это самый частый оператор — сменить владельца, записать заметку, обновить вложенное поле. Путь может быть вложенным через точку (`"lines.0.qty"`) и указывать на запись `Map` (`"counters.logins"`).

<Snippet id="reference/writes/update-operators/set" twoslash />

<Params>
<Param name="paths" type="{ [path]: value }">

Пути записи и новые значения. Значение приводится к типу поля и проходит его валидаторы (`min`, `enum`, собственные). Встроенный документ проверяется целиком, вместе с `required` внутри. `null` принимается только для полей, объявленных `nullable`. Путь `_id` менять нельзя.

</Param>
</Params>

### Ошибки [#set.errors]

Неизвестный путь, значение не того типа и нарушение валидатора останавливаются до отправки.

<Snippet id="reference/writes/update-operators/set-errors" />

## $setOnInsert [#set-on-insert]

`$setOnInsert` записывает значения **только тогда, когда `upsert` вставил новый документ**. Если документ уже был, оператор ничего не делает. Он нужен для начальных значений, которые не должны затирать существующие данные — даты создания, стартового баланса, полей с `Immutable`.

Только здесь поле с `Immutable` можно записать. Такое поле пишется при создании документа и дальше не меняется.

Те же пути и значения, что у [`$set`](#set), плюс поля с `Immutable`.

</Param>
</Params>

## $unset [#unset]

`$unset` удаляет поля из документа. Берите его, когда значение должно исчезнуть, а не стать пустым — убрать заметку, очистить прозвище. Значение операнда неважно, подходят `""`, `1` и `true`.

Удалять можно только **необязательные** поля (`?:`). Без обязательного поля документ нарушил бы схему.

<Snippet id="reference/writes/update-operators/unset" twoslash />

<Params>
<Param name="paths" type={'{ [path]: "" | 1 | true }'}>

Пути необязательных полей. Путь обязательного поля и путь элемента массива компилятор не принимает.

</Param>
</Params>

<FullType>

<Snippet id="reference/writes/update-operators/unset-2" />

</FullType>

### Ошибки [#unset.errors]

Если обязательное поле всё же удаляется (типы обойдены), Typemo останавливает обновление.

<Snippet id="reference/writes/update-operators/unset-errors" />

### Когда не подходит [#unset.when-not-to-use]

Чтобы записать `null`, берите [`$set`](#set) на поле с `nullable`. Чтобы убрать элемент из массива — [`$pull`](#pull) или [`$pop`](#pop).

## $inc [#inc]

`$inc` прибавляет число к числовому полю, отрицательное число вычитает. Он нужен для счётчиков и балансов. Операция атомарна, поэтому одновременные прибавления не теряются.

<Snippet id="reference/writes/update-operators/inc" twoslash />

<Params>
<Param name="paths" type="{ [path]: number | bigint | Int64String | Decimal128 }">

Пути числовых полей и числа **того же вида**, что поле. Для `number` это число, для `bigint` (int64) — `bigint` или его десятичная строка, для `Decimal128` — `Decimal128`. Строка вместо числа для поля-числа даёт `CastError`.

</Param>
</Params>

<FullType>

<Snippet id="reference/writes/update-operators/inc-2" />

</FullType>

### Границы `min` и `max` [#min-max-bounds]

Если у поля есть `min` или `max`, результат `$inc` зависит от значения в базе, и заранее его не проверить. Поэтому Typemo делает обновление **условным**. В фильтр добавляется условие, которое сервер проверяет на хранимом значении. Результат вне диапазона не запишется никогда, а вы получите `ValidationError`. В его тексте есть хранимое значение и итог.

<Snippet id="reference/writes/update-operators/min-max-bounds" />

Если документа нет вовсе, ошибки нет, а результат обычный — `matchedCount: 0`. Есть ограничения. С `upsert` такое обновление отвергается, потому что сервер вставил бы новый документ. В `bulkWrite` тоже. Путь через массив (`$`, `$[]`, `$[id]`, индекс) не защищается. В `updateMany` документы вне диапазона находятся до записи, и тогда не записывается ничего.

### Ошибки [#inc.errors]

<Snippet id="reference/writes/update-operators/inc-errors" />

### Когда не подходит [#inc.when-not-to-use]

Чтобы умножить, берите [`$mul`](#mul). Чтобы записать значение — [`$set`](#set). Чтобы поднять значение до порога — [`$max`](#max).

## $min [#min]

`$min` понижает поле до значения, если оно **меньше** текущего. Берите его для «наименьшего из виденных» — самой ранней даты, минимальной цены.

`$currentDate` записывает текущее время **сервера**. Он нужен, когда все записи должны получить время из одного источника, а не с часов разных приложений.

<Snippet id="reference/writes/update-operators/current-date" twoslash />

<Params>
<Param name="paths" type={'{ [path]: true | { $type: "date" } | { $type: "timestamp" } }'}>

Пути полей `Date` (`true` или `{ $type: "date" }`) и `Timestamp` (`{ $type: "timestamp" }`).

</Param>
</Params>

<FullType>

<Snippet id="reference/writes/update-operators/current-date-2" />

</FullType>

### Когда не подходит [#current-date.when-not-to-use]

Если время нужно с часов приложения, запишите его через [`$set`](#set). Для `createdAt` и `updatedAt` есть базовый класс `Timestamped`, он ведёт их сам. `updatedAt` двигается при любой записи, даже если поля не изменились. Скажем, `$addToSet` значения, которое в массиве уже есть, у такой модели даёт `modifiedCount: 1`.

## $push [#push]

`$push` добавляет элемент в **конец массива**. Чтобы добавить сразу несколько элементов, вставить в позицию, отсортировать или обрезать массив, замените элемент объектом с `$each` и модификаторами — [`$each`](#each), [`$position`](#position), [`$slice`](#slice), [`$sort`](#sort).

Оператор применим только к полям-массивам. Дубликаты он не отсекает, для уникальных элементов берите [`$addToSet`](#add-to-set).

<Snippet id="reference/writes/update-operators/push" twoslash />

<Params>
<Param name="paths" type="{ [path]: element | { $each, $position?, $slice?, $sort? } }">

Путь массива и элемент. Элемент приводится к типу элемента массива и проходит его валидаторы. Для массивов поддокументов элемент — объект, он проверяется целиком.

</Param>
</Params>

<FullType>

<Snippet id="reference/writes/update-operators/push-2" />

</FullType>

### Ошибки [#push.errors]

<Snippet id="reference/writes/update-operators/push-errors" />

Последняя ошибка относится к элементу-поддокументу без обязательного поля `qty`. `+0` означает первый из добавляемых элементов.

### Когда не подходит [#push.when-not-to-use]

Для уникальных элементов берите [`$addToSet`](#add-to-set). Чтобы заменить массив целиком — [`$set`](#set).

## $each [#each]

`$each` — модификатор `$push` и `$addToSet`. Он превращает операнд в **список** добавляемых элементов. Берите его, чтобы добавить сразу несколько элементов или использовать остальные модификаторы. В `$addToSet` разрешён только `$each`, без остальных.

<Snippet id="reference/writes/update-operators/each" twoslash />

<Params>
<Param name="$each" type="readonly E[]" required>

Список элементов. Каждый приводится и проверяется как отдельный элемент.

</Param>
</Params>

## $position [#position]

`$position` — модификатор `$push`. Это индекс, с которого вставляются элементы `$each`. Без него они идут в конец.

<Snippet id="reference/writes/update-operators/position" twoslash />

<Params>
<Param name="$position" type="number">

Индекс вставки. Работает только вместе с `$each`.

</Param>
</Params>

## $slice [#slice]

`$slice` — модификатор `$push`. Он обрезает массив **после** добавления. Положительное число оставляет первые N элементов, отрицательное — последние N. Пригодится для ограниченных списков вроде «последние 10 событий».

<Snippet id="reference/writes/update-operators/slice" twoslash />

<Params>
<Param name="$slice" type="number">

Сколько элементов оставить. Положительное число считает с начала, отрицательное с конца, `0` очищает массив.

</Param>
</Params>

---

## $sort [#sort]

`$sort` — модификатор `$push`, он сортирует массив после добавления. Для массива чисел или строк значение — `1` (по возрастанию) или `-1` (по убыванию). Для массива поддокументов это объект с полями элемента, например `{ qty: 1 }`.

Если `$sort` и `$slice` стоят вместе, сначала идёт сортировка, потом обрезка. Так можно держать «наибольшие три».

<Snippet id="reference/writes/update-operators/sort" twoslash />

<Params>
<Param name="$sort" type="1 | -1 | { [field]: 1 | -1 }">

Направление сортировки элементов или полей поддокументов.

</Param>
</Params>

## $pull [#pull]

`$pull` удаляет из массива **все элементы, подходящие под условие**. Для массива чисел или строк условие — значение или оператор (`{ $lt: 4 }`, `{ $in: [...] }`). Для массива поддокументов это фильтр по полям элемента. Целый элемент сравнивают через `$in`, `$nin`, `$eq`, `$ne`.

<Snippet id="reference/writes/update-operators/pull" twoslash />

<Params>
<Param name="paths" type="{ [path]: condition }">

Путь массива и условие для его элементов.

</Param>
</Params>

<FullType>

<Snippet id="reference/writes/update-operators/pull-2" />

</FullType>

### Другие формы [#other-forms]

С простыми значениями `{ $pull: { tags: "a" } }` даёт `tags: ["b"]`, `{ $pull: { scores: { $lt: 4 } } }` даёт `scores: [5]`, а `{ $pull: { tags: { $in: ["a", "b"] } } }` оставляет пустой массив.

### Когда не подходит [#pull.when-not-to-use]

Чтобы убрать первый или последний элемент, берите [`$pop`](#pop). Чтобы убрать конкретные значения списком — [`$pullAll`](#pull-all).

## Позиционные пути [#positional-paths]

Когда поле лежит внутри элемента массива, к пути нужно добавить, **какие** элементы менять. Без этого сервер путь «через массив» не выполняет. Способов четыре. Индекс (`"scores.0"`). Позиционный знак `$` — первый элемент, найденный **фильтром**. Знак `$[]` — все элементы. И `$[имя]` — элементы, выбранные условием `arrayFilters`.

<Snippet id="reference/writes/update-operators/positional-paths" twoslash />

Позиционный знак `$` берёт элемент, который нашёл фильтр по тому же массиву. Поэтому в фильтре нужно условие на этот массив или на путь ниже него (`lines.sku`), на верхнем уровне фильтра или внутри `$and`, `$or`, `$nor`. Без условия сервер отвергнет обновление, как только найдёт документ. Typemo ловит это раньше, до отправки.

<Snippet id="reference/writes/update-operators/positional-paths-2" />

Знакам `$[]` и `$[имя]` условие в фильтре не нужно.

Правила `arrayFilters` описаны в [опции `arrayFilters`](./writes.mdx#array-filters). Каждому `$[имя]` нужен свой фильтр, лишних фильтров быть не должно, а конвейер их не принимает. Компилятор проверяет фильтры по элементу массива. Для `lines.$[l].qty` доступны `l.sku` и `l.qty`.

## Одинаковый путь у двух операторов [#path-conflict]

Один путь нельзя менять двумя операторами. Сервер отвергает такое обновление (код 40), а Typemo замечает это раньше, ещё при разборе.

<Snippet id="reference/writes/update-operators/path-conflict" />

Остальные ошибки разбора обновления.

<Snippet id="reference/writes/update-operators/path-conflict-2" />

Оператор, которого здесь нет, не поддерживается. Принимаются `$set`, `$setOnInsert`, `$unset`, `$inc`, `$mul`, `$min`, `$max`, `$currentDate`, `$rename`, `$push`, `$addToSet`, `$pull`, `$pullAll`, `$pop` и `$bit`.
