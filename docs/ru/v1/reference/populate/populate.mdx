**Populate** подставляет в результат чтения сами связанные документы вместо их идентификаторов. Пост хранит `author` как `ObjectId` пользователя, а после `.populate("author")` в этом поле лежит пользователь. `.populate` — метод строителя запроса. Его вызывают после [`find`](../query/reading.mdx#modelfind), [`findOne`](../query/reading.mdx#modelfindone) и других методов чтения, а запрос уходит в базу на `await`.

Если со связанными данными вы работаете впервые, начните с руководства [Показать связанные данные](../../populate/basics.mdx). Здесь собраны все формы вызова, все опции и все ошибки. Типы результата описаны на странице [Типы populate](./populate-types.mdx), методы документа — в разделе [API документа](../documents/document-api.mdx#populate).

Во всех примерах одна модель блога. Автор лежит в `Post.author`, теги — массивом в `Post.tags`, рецензенты — картой `Post.reviewers`. Комментарии в посте не хранятся. Это **виртуальное поле** `comments`, которое находит их по полю `post` (виртуальные поля описаны в разделе [`@Virtual`](../schemas/virtual.mdx)).

```ts twoslash title="blog/models.ts"
import { Entity, Prop, Schema, Spec, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";

@Schema({ collection: "users" })
export class User extends Entity {
  @Prop(() => String, { required: true })
  name!: string;

  @Prop(() => String)
  email?: string;

  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" })
  posts?: VirtualRef<Post>;
}

@Schema({ collection: "tags" })
export class Tag extends Entity {
  @Prop(() => String, { required: true })
  label!: string;
}

@Schema({ collection: "posts" })
export class Post extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Number, { required: true })
  views!: number;

  @Prop(() => Types.ObjectId, { ref: () => User, required: true })
  author!: Ref<User>;

  @Prop(() => Types.ObjectId, { ref: () => User })
  editor?: Ref<User>;

  @Prop(() => [Types.ObjectId], { ref: () => Tag })
  tags!: Ref<Tag>[];

  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User })
  reviewers?: Map<string, Ref<User>>;

  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" })
  comments?: VirtualRef<Comment>;

  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true })
  commentCount?: VirtualRef<Comment, false, true>;
}

@Schema({ collection: "comments" })
export class Comment extends Entity {
  @Prop(() => String, { required: true })
  text!: string;

  @Prop(() => Types.ObjectId, { ref: () => Post, required: true })
  post!: Ref<Post>;

  @Prop(() => Types.ObjectId, { ref: () => User, required: true })
  author!: Ref<User>;
}
```

В базе два пользователя (Alice с почтой `a@example.com` и Bob), два тега (`db` и `ts`) и три поста.

- «Hello» написала Alice. Теги `db` и `ts`, 10 просмотров.
- «Second» написала Alice. Редактор Bob, тег `ts`, 50 просмотров.
- «Bob's» написал Bob. Тегов нет, 5 просмотров.

Комментариев три. `c1` (автор Bob) и `c2` (автор Alice) относятся к «Hello», `c3` (автор Bob) — к «Second». Идентификаторы в результатах сокращены до `"…"`, потому что база выдаёт их заново при каждой загрузке данных.

Элементы на странице — [`.populate`](#populate) и его [опции](#опции-объекта) [`path`](#path), [`select`](#select), [`match`](#match), [`options`](#options), [`populate`](#опция-populate), [`justOne`](#justone), [`retainNullValues`](#retainnullvalues), [`perDocumentLimit`](#perdocumentlimit), [`required`](#required), [`clone`](#clone) и [`transform`](#transform).

## .populate

`.populate` велит строителю запроса заменить после чтения ссылки в указанных полях документами, на которые они ведут. Он нужен, когда рядом с записью надо показать данные из другой. Пост с именем автора, заказ с товарами, комментарий с постом. Без него связанные документы пришлось бы читать отдельными запросами и склеивать вручную.

Метод принимает строку с путём, список путей и объектов или один объект с опциями. Какую бы форму вы ни выбрали, на стороне базы Typemo документы не соединяет. Для каждого пути он берёт идентификаторы из прочитанных документов, одним запросом находит документы целевой модели и раскладывает их по местам. Это обычные операции целевой модели, так что её политики (мягкое удаление, тенант, скрытые поля) действуют и здесь.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
const post = await Posts.findOne({ title: "Hello" }).populate("author").orFail().plain();
console.log(post.author?.name);
// → "Alice"
```

Знак `?.` нужен не для красоты. Автора могли удалить, и тогда в `author` лежит `null`. Почему так и как это выключить, читайте в разделе [Ссылка без документа](#ссылка-без-документа).

<Returns type="QueryBuilder">

Новый строитель запроса, в типе которого путь помечен как загруженный. Строитель неизменяем, каждый вызов возвращает новый. Содержимое поля зависит от вида результата. У документа это документы модели-цели (массив только для чтения), у [`.lean()`](../query/reading.mdx#lean) и [`.plain()`](../query/reading.mdx#plain) — простые объекты. Если для ссылки документа не нашлось, единичная ссылка станет `null` (тип поля это допускает), а из массива элемент исчезнет. Подробности — в разделе [Ссылка без документа](#ссылка-без-документа).

</Returns>

<Params>
<Param name="path" type="string" required>

Путь поля со ссылкой или виртуального поля. Вложенные поля и поля документов внутри массивов пишутся через точку (`lines.product`), значения карты ссылок — через `$*` (`reviewers.$*`). Путь можно продолжить в связанную модель (`post.author`) — это вложенный populate. Компилятор проверяет путь по сегментам. Подсказывает он пути до трёх сегментов, а проверяет до семи.

</Param>
<Param name="list" type="(string | PopulateObject)[]" required>

Список путей и объектов с опциями вместо одного пути, например `["author", { path: "tags", select: { label: 1 } }]`. Пустой список и повтор одного пути запрещены. Повтор заметит уже компилятор, пустой список — только проверка во время работы.

</Param>
<Param name="spec" type="PopulateObject" required>

Объект с полем `path` и [опциями](#опции-объекта). Путь выводится первым, и остальные опции типизируются по модели-цели этого пути. `select` подсказывает поля целевой модели, `match` — её фильтр.

</Param>
</Params>

### Одна ссылка

Чаще всего передают путь одной ссылки. В документе на её месте оказывается документ модели-цели со всеми методами. Его можно менять и сохранять.

```ts twoslash

@Schema({ collection: "posts" })

  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
```

### Несколько путей списком

Чтобы загрузить несколько путей за один вызов, передайте список. В нём можно смешивать строки и объекты с опциями. Каждый путь — отдельный запрос к его модели-цели.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
const post = await Posts.findOne({ title: "Hello" })
  .populate(["author", { path: "tags", select: { label: 1 } }])
  .orFail()
  .plain();
console.log(post.author?.name, post.tags.map((tag) => tag.label));
// → "Alice" ["db", "ts"]
```

### Путь через точку

Путь можно продолжить в модель, на которую ведёт ссылка. `post.author` значит «загрузи пост комментария и автора этого поста». Это вложенный populate. Typemo находит посты, затем их авторов. То же самое записывается [опцией `populate`](#опция-populate). Путь через точку короче, а опция нужна, когда у вложенного пути свои опции.

```ts twoslash

  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
```

Каждое звено цепочки — единичная ссылка, поэтому `post` и `author` допускают `null`. Путь через точку проходит внутри массивов поддокументов (`lines.product`), вложенных объектов и карт (`reviewers.$*`, `notes.$*.author`). Примеры таких связей есть в руководстве [Сложные связи](../../populate/complex-relations.mdx).

### Повторный вызов заменяет

Опции при повторном populate одного пути не складываются. Последний вызов заменяет предыдущий целиком. Загрузите автора полностью, затем с `select: { name: 1 }`, и в результате будет только имя. Пути, которых второй вызов не касается, остаются как были.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
const post = await Posts.findOne({ title: "Hello" })
  .populate("author")
  .populate({ path: "author", select: { name: 1 } })
  .orFail()
  .plain();
console.log(post.author);
// → { _id: "…", name: "Alice" }
```

Один путь дважды в одном списке — ошибка, потому что победителя пришлось бы угадывать. Компилятор остановит такой список (`"populate error": populate "author": the path is given twice`). Для пути, собранного из данных, то же скажет [`QueryError`](../errors/query-errors.mdx#queryerror) во время работы. Его текст есть в разделе [Ошибки](#ошибки).

### Ссылка без документа

Ссылка может вести на документ, которого нет. Его удалили, скрыло мягкое удаление или отфильтровала опция [`match`](#match). Populate не бросает ошибку (если вы не попросили [`required`](#required)), а смотрит на форму поля.

- Единичная ссылка становится `null`, и тип поля это допускает. У документа это `HydratedDoc<User> | null`, у `.lean()` и `.plain()` — `{ … } | null`.
- Из массива ссылок элемент исчезает, остальные сохраняют порядок (позицию оставит [`retainNullValues`](#retainnullvalues)).
- Значение карты без документа остаётся в карте как `null`, ключ не теряется.
- Поле, которого в документе не было, остаётся без значения.


Здесь `match` отфильтровал тег `db`, и из массива поста «Hello» пропала одна ссылка. У поста «Bob's» тегов не было, поэтому массив пуст.

Тип единичной ссылки после populate всегда содержит `null`, даже при `required: true` в `@Prop`. `required` в схеме требует, чтобы в документе лежал идентификатор. Что документ по нему ещё существует, он не гарантирует. Базе всё равно, удалили ли вы автора после записи поста. Поэтому обращайтесь к полю через `?.` или сузьте его проверкой [`isPresent`](./populate-types.mdx#ispresent). Если пропавшая ссылка для вас ошибка данных, передайте populate [`required: true`](#required). Тогда Typemo бросит ошибку, а `null` уйдёт из типа.

Мягко удалённый документ целевой модели populate тоже не найдёт. Подгрузка идёт как обычное чтение целевой модели и получает то же условие, что любое чтение.

### Скрытые поля целевой модели

Populate читает целевую модель по её правилам, поэтому её скрытые поля (`hidden`) не попадают в загруженные документы в результате `.plain()`. Чтобы получить скрытое поле, добавьте его в [`select`](#select) с префиксом `+`. Для `.plain()` выдачу поля нужно ещё запросить опцией `hidden`.

### Сколько запросов уходит в базу

Один `.populate` с одним путём — один дополнительный запрос к модели-цели, сколько бы документов вы ни прочитали. Идентификаторы всех документов собираются в один `$in`. Запросы к разным целевым моделям идут параллельно, а внутри транзакции — по очереди. Точное число запросов видно в [событиях операций](../observability/events.mdx). Подзапросы populate вложены в родительскую операцию, и у каждого заполнен `populatePath`.

```text
find:Post
find:User@author
find:Tag@tags
find:User@editor
```

Это события для `Posts.find().populate(["author", "tags", "editor"])`. Один запрос постов и по одному на каждый путь. Виртуальное поле с `perDocumentLimit` (или `options.limit`) на нескольких документах превращается в один запрос-агрегацию с `$lookup`. Счётчик (`count: true`) становится агрегацией, которая считает документы на стороне базы и ничего не загружает.

### Где работает populate

Метод работает с `find`, `findOne`, `findById`, с курсором (`cursor`) и с `findOneAndUpdate`. Результат изменения вернётся сразу с загруженными связями. У агрегаций `populate` нет, там связи подтягивает стадия [`$lookup`](../aggregation/stages.mdx#lookup). У загруженного документа есть свои методы — [`$populate`](../documents/document-api.mdx#populate), [`$depopulate`](../documents/document-api.mdx#depopulate) и [`$populated`](../documents/document-api.mdx#populated). О них рассказывает руководство [Populate у документа](../../populate/document-populate.mdx).

### Ошибки

Путь и опции проверяются дважды. Компилятор ловит неверный путь, неизвестную опцию, `select` и `match` с полями, которых нет в модели-цели. Не поймает он только то, что видно лишь во время работы, например путь, собранный из данных.

### Когда не подходит

Если связанные данные нужны для расчёта на стороне базы (сумма по комментариям, группировка по автору), берите агрегацию со стадией [`$lookup`](../aggregation/stages.mdx#lookup). Populate загрузит документы в приложение, и считать пришлось бы уже там. Нужно только количество связанных документов? Заведите виртуальное поле со счётчиком (`count: true`, см. [`@Virtual`](../schemas/virtual.mdx)) и запросите его через populate. Связь нужна один раз у документа, который уже есть на руках? Вызовите на нём [`$populate`](../documents/document-api.mdx#populate).

## Опции объекта

Объект принимает опции ниже. Все, кроме `path`, необязательны. Неизвестное имя опции — ошибка и при компиляции, и во время работы, `QueryError: populate "author": unknown option "foo"`.

### path

Обязательная строка. Это путь поля со ссылкой или виртуального поля, по тем же правилам, что в строковой форме. Путь `title` (обычное поле) и путь до встроенного документа без ссылки — ошибки.

### select

Проекция загружаемых документов. `{ name: 1 }` оставляет только имя, `{ email: 0 }` убирает почту. Включение и исключение не смешиваются, а `_id` можно исключить в любом режиме. Выбор полей в родительском запросе на выбор в populate не влияет, они независимы.

```ts twoslash

  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
```

Дополнительное условие для загружаемых документов. Документ, который ему не подходит, считается ненайденным. Единичная ссылка становится `null`, из массива элемент исчезает. Поэтому тип единичной ссылки с `match` включает `null`.

### options

Объект с ключами `sort`, `limit` и `skip`. Любой другой ключ — `QueryError: populate "tags": unknown option "foo"`. `sort` упорядочивает загруженные документы. `limit` и `skip` действуют **на каждый исходный документ отдельно**. `limit: 2` значит «не больше двух комментариев на пост», а не «два комментария всего».

```ts twoslash
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;

  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
const post = await Posts.findOne({ title: "Hello" })
  .populate({ path: "comments", options: { sort: { text: -1 }, limit: 2 } })
  .orFail()
  .plain();
console.log(post.comments.map((comment) => comment.text));
// → ["c2", "c1"]
```

У одиночной ссылки порядка нет, поэтому `sort`, `limit` и `skip` ей ни к чему. Typemo отвечает ошибкой, а не молча игнорирует опции — `QueryError: populate "author": a single reference holds one document; options sort apply to reference arrays only` (так же для `limit`, `skip` и `perDocumentLimit`). Для массивов ссылок и виртуальных полей опции работают. С `retainNullValues` вместе `sort` не сочетается. Одна опция хранит позиции, другая их меняет.

### Опция populate

Вложенный populate — пути для документов, которые загрузил этот путь. Значение то же, что у `.populate`, то есть строка, объект или список. Путь пишется относительно модели-цели.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";

}
@Schema({ collection: "posts" })

  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;

@Schema({ collection: "comments" })

```

Вложенный populate выполняется на найденных документах, прежде чем они займут свои места. Поэтому [`transform`](#transform) видит документ уже с загруженными вложенными связями. Запись `populate("post.author")` даёт тот же результат, если для `author` не нужны опции.

### justOne

Принудительно один документ (`true`) или список (`false`), как бы ни подсказывал тип поля. У массива ссылок `justOne: true` оставляет первый найденный документ. У единичной ссылки `justOne: false` превращает результат в массив. У виртуального поля это способ получить один документ вместо списка. Для значений карты ссылок опция запрещена (`QueryError: populate "reviewers.$*": justOne does not apply to the values of a Map`), для счётчика тоже.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";

  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
```

Если виртуальное поле объявлено с `justOne: true` в [`@Virtual`](../schemas/virtual.mdx), оно и так вернёт один документ. Повторять опцию не нужно.

### retainNullValues

Для массива ссылок сохраняет позицию каждой ссылки, для которой документа не нашлось. На её месте стоит `null`. Без опции такие элементы исчезают, и индексы результата перестают совпадать с индексами исходного массива. Опция нужна, когда позиция важна, например порядок тегов задал пользователь.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";

class User extends Entity {

  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })

  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })

  @Prop(() => String, { required: true }) text!: string;
```

У виртуальных полей исходных позиций нет, поэтому опция им не подходит. Компилятор отвечает `retainNullValues of "comments": a virtual has no positions to keep`, а во время работы `QueryError` говорит `retainNullValues keeps the positions of a reference array; a virtual has none`. С `sort` опция тоже несовместима — `QueryError: populate "tags": retainNullValues keeps positions, sort reorders: they cannot be combined`.

### perDocumentLimit

Не больше стольки документов на каждый исходный документ. Лимит считается для каждого поста отдельно. Это то же самое, что `options.limit`, и задать можно только одну из двух опций. Обе сразу — ошибка `"options.limit" and "perDocumentLimit" are the same per-document limit; give one`. Для виртуального поля на нескольких документах лимит превращается в один запрос-агрегацию с `$lookup` и `$limit` на владельца. Если владелец один, запрос обычный — `find` с лимитом. В `@Virtual` та же опция задаёт лимит по умолчанию.


### required

Ссылка без документа становится ошибкой, а не `null`. [`DocumentNotFoundError`](../errors/query-errors.mdx#documentnotfounderror) бросается на первой же ссылке, которая ничего не нашла. Из типа результата уходит `| null`, как после [`.orFail()`](../query/reading.mdx#orfail) у запроса. Опция нужна, когда висячая ссылка означает испорченные данные и продолжать нельзя. Это опция самого populate. Одноимённый параметр `required` у `@Prop` тип загруженного поля не меняет. Если поля в документе нет совсем (у поста «Hello» нет `editor`), опция ничего не требует. Ссылки нет, искать нечего.

```text
DocumentNotFoundError: populate "editor": no document for the reference 6abcfa3dd4c0f052aabe53b9 (required: true)
```

### clone

Даёт каждому исходному документу собственную копию загруженного документа. Без неё документ, найденный для нескольких владельцев, — один общий объект. Два поста одного автора получают в `author` один и тот же объект. Изменение через один пост видно через другой, а `$save()` этого документа сохранит всё, что поменяли через любого владельца. `clone: true` разделяет копии за счёт памяти и времени.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
```

### transform

Функция `(doc, id) => value`, которая заменяет каждое загруженное значение своим результатом. `doc` — загруженный документ в виде `.lean()` (или `null`, если документа нет), `id` — исходное значение ссылки. Поле хранит то, что вернула функция, и в типе результата записано именно это. Пригодится, когда клиенту нужна не вся связанная запись, а одно значение.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";

}

  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;

  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];

  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
```

Для массива ссылок функция вызывается на каждом элементе, результат — массив её результатов. Тип `doc` следует за [`select`](#select). Если выбрано только имя, `doc` — `{ _id, name } | null`.

## Ограничения и глубина путей

Компилятор проверяет путь по сегментам и не перебирает все возможные пути. На плотных моделях их десятки тысяч, и компилятор бы не справился. Поэтому подсказки редактора ограничены тремя сегментами, а проверка идёт до семи. Путь в восемь сегментов — ошибка компиляции с текстом `populate path is deeper than the 7-level ceiling`. Во время работы отдельного ограничения глубины нет. Путь, собранный из строки, проверяется по схеме, а не по счётчику.

Ниже полиморфной ссылки (`refPath`, `refModel`) заполнять нечего, потому что цель там не одна модель. Попытка — ошибка, `QueryError: populate "target.author": "target" is a polymorphic reference (refPath/refModel); nothing below it can be populated`. Путь к карте без `$*` тоже ошибка — `QueryError: populate "reviewers": "reviewers" is a Map: its values are "reviewers.$*"`.
