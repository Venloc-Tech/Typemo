После вызова [`.populate`](./populate.mdx#populate) меняется не только результат, но и его тип. Поле `author` из `Ref<User>` становится документом пользователя или `null`, если документ пропал. Виртуальное поле `comments` из служебного маркера становится массивом комментариев. За это отвечают публичные типы этой страницы и две функции для кода, который не знает, загружена ли связь, — [`isPopulated`](#ispopulated) и [`isPresent`](#ispresent). У каждого типа сказано, где вы с ним столкнётесь — в подсказках редактора и сообщениях об ошибках или только в собственных обёртках над результатами populate.

Если связанные данные для вас новы, начните с руководства [Показать связанные данные](../../populate/basics.mdx). О проверке типа в своём коде читайте в руководстве [Убедиться, что связь загружена](../../populate/type-checks.mdx). Здесь справочник по самим типам.

Примеры берут модель блога со страницы [`.populate`](./populate.mdx) — пост со ссылкой на автора, тегами и виртуальным полем комментариев. В базе два пользователя (Alice и Bob), два тега (`db` и `ts`), три поста и три комментария, как и там.

На странице описаны [`PopulatedField`](#populatedfield), [`Depopulated`](#depopulated), [`ApplyPopulate`](#applypopulate), [`isPresent`](#ispresent), [`isPopulated`](#ispopulated), [`AnyPopulationDoc`](#anypopulationdoc), [`PartlyPopulatedDoc`](#partlypopulateddoc), [`AnyPopulationMethods`](#anypopulationmethods), [`PopulatableKeys`](#populatablekeys) и [остальные типы](#остальные-типы) — проверка путей, аргумент `populate`, `transform`.

## PopulatedField

`PopulatedField<Value, Original>` описывает поле, которое уже загружено. `Value` — то, что поле хранит после populate (документ или `null`, массив документов, число, результат `transform`). `Original` — то, что лежало в поле раньше (`Ref<M>`, `Ref<M>[]`, `Map<string, Ref<M>>`, `VirtualRef`). Это тип-маркер. Значения такого типа во время работы нет, он нужен компилятору, чтобы помнить оба состояния поля.

Оба состояния нужны, потому что загрузку можно откатить. [`$depopulate`](../documents/document-api.mdx#depopulate) возвращает на место документов исходные идентификаторы, а [`$set`](../documents/document-api.mdx#set) загруженного поля принимает идентификаторы, не документы. Оба типа берутся из `Original`. Читатель поля видит только `Value`, потому что представление документа сворачивает маркер, и в подсказках `PopulatedField` не встретится.

<Params title="Параметры типа">
<Param name="Value" type="unknown" required>

Что поле хранит после populate. `HydratedDoc<User> | null` для одной ссылки (`null` — документ пропал или не прошёл `match`), `readonly HydratedDoc<Tag>[]` для массива, `ReadonlyMap<string, HydratedDoc<User> | null>` для карты, число для счётчика.

</Param>
<Param name="Original" type="unknown" required>

Что поле хранило до populate. Этот тип возвращает `$depopulate` и принимает `$set`.

</Param>
<Param name="Transformed" type="boolean" default="false">

`true`, когда в поле лежат результаты `transform`, а не документы. Такое значение не нужно превращать через `.plain()` или `.lean()`, оно уже готово.

</Param>
</Params>

<FullType>

```ts
export interface PopulatedField<Value, Original, Transformed extends boolean = false> {
  readonly [POPULATED]: readonly [Value, Original, Transformed];
}
```

</FullType>

Маркер читают вспомогательные типы. [`PopulatedValueOf<V>`](#остальные-типы) даёт `Value` (для не-маркера — сам `V`), [`PopulatedOriginalOf<V>`](#остальные-типы) даёт `Original`, [`IsTransformed<V>`](#остальные-типы) даёт `Transformed`. `AnyPopulatedField` — общий вид любого маркера, им проверяют, загружено ли поле.

Сам документ маркер в подсказке не показывает. Редактор называет класс и загруженные поля, например `HydratedDocWith<Post, { author: HydratedDoc<User> | null }>`. Второй аргумент здесь — `Value` каждого загруженного поля, а `Original` тип берёт из класса. Саму форму описывает справочник [`HydratedDocWith`](../values/form-types.mdx#hydrateddocwith).

## Depopulated

`Depopulated<T, K>` — тип документа после [`$depopulate(key)`](../documents/document-api.mdx#depopulate). Поля под ключом `K` снова имеют исходный тип идентификаторов. Тип заменяет маркеры `PopulatedField` на их `Original` на глубину до четырёх уровней, внутри массивов, карт и вложенных объектов. Остальные поля не меняются.

<Params>
<Param name="T" type="object" required>

Форма документа.

</Param>
<Param name="K" type="PropertyKey" required>

Ключ или объединение ключей, чьи загруженные поля нужно вернуть в исходный вид.

</Param>
</Params>

<FullType>

```ts
export type Depopulated<T, K extends PropertyKey> = { [P in keyof T]: P extends K ? Unboxed<T[P], 4> : T[P] };
```

</FullType>

Самому писать `Depopulated` почти не приходится. По нему `$depopulate` вычисляет, какие поля вернулись к идентификаторам. В подсказке результата его не видно. Поле, вернувшееся к типу из класса, просто уходит из второго аргумента [`HydratedDocWith`](../values/form-types.mdx#hydrateddocwith). Когда загруженных полей не остаётся, документ снова `HydratedDoc<Post>`, а `author` в нём снова `Ref<User>`.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
const post = await Posts.findOne({ title: "Hello" }).orFail();
const untouched = post.$depopulate("author");
//    ^?
const loaded = await post.$populate(["author", "tags"]);
const partly = loaded.$depopulate("author");
//    ^?
const back = partly.author;
//    ^?
```

## ApplyPopulate

`ApplyPopulate<T, Entries, IsLean>` — главный тип. Он превращает тип модели в тип результата после populate. `T` — исходная модель. `Entries` — накопленные записи о загруженных путях, по одной на путь, с проекцией и особенностями формы. `IsLean` говорит, нужны ли обычные объекты или документы. Тип проходит по ключам один раз, поэтому цена растёт с числом путей, а не с их сочетаниями. Записи строитель запроса копит через `ExtractPopulationEntries` и `ReplaceEntries`, так что повторный вызов для того же пути заменяет запись, как и во время работы.

Напрямую `ApplyPopulate` вызывают редко. Его результат вы видите в типе любого запроса с `populate`. Вот как выглядит результат `.lean()` после `.populate("author")`.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
const row = await Posts.findOne({ title: "Hello" }).populate("author").orFail().lean();
//    ^?
```

Загруженная ссылка остаётся необязательной (`editor?` так и остался), а загруженное виртуальное поле после populate есть всегда. С объединениями, то есть встроенными дискриминаторами, тип работает по членам, каждый загружается отдельно.

<FullType>

```ts
export type ApplyPopulate<T, Entries extends PopulationEntry, IsLean extends boolean> = [Entries] extends [never]
  ? T
  : T extends unknown
    ? Simplify<
        Omit<T, PopulatedKeys<T, Entries>> & {
          -readonly [K in keyof T as K extends PopulatedKeys<T, Entries>
            ? IsVirtualRef<T[K]> extends true
              ? never
              : K
            : never]: K extends string ? ApplyField<T, K, Entries, IsLean> : never;
        } & {
          -readonly [K in PopulatedKeys<T, Entries> as IsVirtualRef<T[K]> extends true ? K : never]-?: K extends string
            ? ApplyField<T, K, Entries, IsLean>
            : never;
        }
      >
    : never;
```

</FullType>

Что окажется в поле, зависит от формы пути. Ссылка-массив в документе становится `readonly HydratedDoc<M>[]`, карта — `ReadonlyMap`, а в результате `.lean()` — `M[]` и обычный объект. Единичная ссылка всегда допускает `null`. Документ, на который она вела, могли удалить, а опция [`match`](./populate.mdx#match) могла его отсеять. [`required`](./populate.mdx#required) убирает `| null`, [`transform`](./populate.mdx#transform) заменяет тип значения результатом функции. Эти особенности описывают `PopulateShape` и `PopulationEntry`.

## isPresent

`isPresent(value)` отвечает на вопрос «значение есть?». Она возвращает `true`, если значение не `null` и не `undefined`. Нужна она из-за `null` в загруженной единичной ссылке. После `populate("author")` поле `post.author` — документ или `null`, и без проверки `post.author.name` компилятор не пропустит. `isPresent` — охранник типа. Внутри `if` тип сужается до `NonNullable`, и работает она с любой формой — документом, результатом `.lean()` или `.plain()`, загруженным полем, элементом списка.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
import { isPresent } from "@venloc/typemo";

const post = await Posts.findOne({ title: "Hello" }).populate("author").orFail();
console.log(isPresent(post.author) ? post.author.name : "автор удалён");
// → "Alice"

const authors = [post.author, null].filter(isPresent);
console.log(authors.length);
// → 1
```

<Returns type="boolean">

`true`, если значение не `null` и не `undefined`. Тип результата — `value is NonNullable<T>`, так что в ветке `true` компилятор убирает из типа `null` и `undefined`.

</Returns>

<Params>
<Param name="value" type="T" required>

Проверяемое значение. Поле загруженного документа, элемент списка, результат `findOne` без `orFail`.

</Param>
</Params>

<FullType>

```ts
export const isPresent = <T>(value: T): value is NonNullable<T> => value !== null && value !== undefined;
```

</FullType>

### Список с пустыми элементами

Если список загружен с опцией [`retainNullValues`](./populate.mdx#retainnullvalues), на месте пропавшей ссылки стоит `null`. Передайте `isPresent` прямо в `.filter`. Тип массива сузится вместе с проверкой, и `null` в нём не останется.

### Когда `isPresent` не нужна

Если пропавшая ссылка для вас ошибка данных, не проверяйте `null`. Попросите [`required: true`](./populate.mdx#required), и такая ссылка бросит [`DocumentNotFoundError`](../errors/query-errors.mdx#documentnotfounderror), а в типе результата `null` не будет. Загружена ли связь вообще, `isPresent` не скажет. Для этого есть [`isPopulated`](#ispopulated) и [`$assertPopulated`](../documents/document-api.mdx#assertpopulated).

## isPopulated

`isPopulated(doc, path)` проверяет во время работы, загружена ли связь `path`, и сужает тип документа до [`PartlyPopulatedDoc<T, path>`](#partlypopulateddoc). Поле `path` в нём читается как загруженное. Функция нужна коду, который получает документы в любом состоянии — без populate, с одним путём или с несколькими. Параметр такой функции объявляют типом [`AnyPopulationDoc<T>`](#anypopulationdoc), а `isPopulated` выбирает ветку. Она читает те же записи, что и [`$populated`](../documents/document-api.mdx#populated), и возвращает `true`, пока поле хранит то, что туда положил populate.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) views!: number;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
  @Prop(() => Types.ObjectId, { ref: () => User }) editor?: Ref<User>;
  @Prop(() => [Types.ObjectId], { ref: () => Tag }) tags!: Ref<Tag>[];
  @Prop(() => Spec.map(Types.ObjectId), { ref: () => User }) reviewers?: Map<string, Ref<User>>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post" }) comments?: VirtualRef<Comment>;
  @Virtual({ ref: () => Comment, localField: "_id", foreignField: "post", count: true }) commentCount?: VirtualRef<Comment, false, true>;
}
@Schema({ collection: "comments" })
class Comment extends Entity {
  @Prop(() => String, { required: true }) text!: string;
  @Prop(() => Types.ObjectId, { ref: () => Post, required: true }) post!: Ref<Post>;
  @Prop(() => Types.ObjectId, { ref: () => User, required: true }) author!: Ref<User>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "blog" });
const Users = client.db().model(User);
const Tags = client.db().model(Tag);
const Posts = client.db().model(Post);
const Comments = client.db().model(Comment);
// ---cut---
import { type AnyPopulationDoc, isPopulated } from "@venloc/typemo";

const authorName = (post: AnyPopulationDoc<Post>): string | undefined =>
  isPopulated(post, "author") ? post.author?.name : undefined;

const bare = await Posts.findOne({ title: "Hello" }).orFail();
console.log(authorName(bare));
// → undefined

const loaded = await Posts.findOne({ title: "Hello" }).populate("author").orFail();
console.log(authorName(loaded));
// → "Alice"
```

Одна функция приняла и пост без populate, и пост с загруженным автором. В ветке `true` поле `post.author` имеет тип `AnyPopulationDoc<User> | null`. `null` остался, потому что автора могли удалить. Вне ветки поле читается как `Ref<User> | AnyPopulationDoc<User> | null`, и `post.author.name` не скомпилируется.

<Returns type="boolean">

`true`, если `path` загружен — populate выполнялся, и поле хранит его результат. Тип результата — охранник, в ветке `true` документ сужается до `PartlyPopulatedDoc<T, path>`. Ссылка, для которой документ не нашёлся, тоже считается загруженной. Populate выполнялся, результат — `null`. Поле, которого в документе не было вовсе (у поста «Hello» нет `editor`), не загружено, подставлять было нечего.

</Returns>

<Params>
<Param name="doc" type="D" required>

Документ, объявленный как `AnyPopulationDoc<T>`. Обычный `HydratedDoc<T>` и результат запроса с `populate`, не приведённый к этому типу, не подойдут. Подробности в разделе [Ограничения](#ограничения-ispopulated).

</Param>
<Param name="path" type="PopulatableKeys<T>" required>

Ключ верхнего уровня — ссылка, массив ссылок, карта ссылок или виртуальное поле с populate. Путь через точку не принимается. Вложенную связь проверяйте вторым вызовом на загруженном документе (`isPopulated(post.author, "posts")`). Ключ, который не ссылка, — ошибка компиляции.

</Param>
</Params>

<FullType>

```ts
export const isPopulated = <D extends object, const P extends PopulatableKeys<AnyPopulationOf<D>[0]>>(
  doc: D,
  path: P,
): doc is Extract<PartlyPopulatedDoc<AnyPopulationOf<D>[0], AnyPopulationOf<D>[1] | P>, D> =>
  PopulatedFields.get(doc, path) !== undefined && (doc as Readonly<Record<string, unknown>>)[path] !== undefined;
```

</FullType>

### Все виды связей

Функция различает связи по объявлению в модели. Массив ссылок сужается до `readonly (AnyPopulationDoc<Tag> | null)[]`, где `null` в элементе возможен при `retainNullValues`. Карта даёт `ReadonlyMap<string, AnyPopulationDoc<…> | null>`. Виртуальное поле даёт список документов, один документ или `null` (`justOne`), а для счётчика — число.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, Types, Virtual, type Ref, type VirtualRef } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => String) email?: string;
  @Virtual({ ref: () => Post, localField: "_id", foreignField: "author" }) posts?: VirtualRef<Post>;
}
@Schema({ collection: "tags" })
class Tag extends Entity {
  @Prop(() => String, { required: true }) label!: string;
}
@Schema({ collection: "posts" })
class Post extends Entity {
```

### Ограничения isPopulated

Функция уже, чем может показаться, и у каждого ограничения есть причина.

**Принимается только `AnyPopulationDoc`.** Обычный `HydratedDoc<Post>` говорит компилятору, что ссылки в нём — идентификаторы, спрашивать «загружена ли» не у чего. Документ из `populate`, не приведённый к `AnyPopulationDoc<Post>`, тоже не подходит. Его тип уже описывает загруженные поля. Вызов даст ошибку компиляции, в которой путь не принимается (`parameter of type 'never'`). Обычно хватает объявить параметр функции как `AnyPopulationDoc<Post>`, оба вида документов к нему присваиваются. Если функции нужен именно `HydratedDoc<Post>`, а связь мог загрузить другой код, используйте [`$assertPopulated`](../documents/document-api.mdx#assertpopulated).

**Элементы массива остаются `| null`.** После сужения тип массива ссылок — `readonly (AnyPopulationDoc<Tag> | null)[]`, хотя без `retainNullValues` `null` в нём не бывает. Форма не знает, с какими опциями шёл populate, и не обещает лишнего. Уберите `null` через `.filter(isPresent)`.

**Часть документов не подходит под `AnyPopulationDoc`.** Форма описывает документ целиком, поэтому к ней не присваиваются документы, у которых populate изменил состав или вид значений.

- С `select`, если выборка убирает обязательные поля загруженного документа. `select: { email: 1 }` убирает обязательное `name`, а выборка, которая убирает только необязательные поля, присваивается.
- С `transform` — в поле лежит не документ, а результат вашей функции.
- С `justOne` над массивом ссылок или списком виртуального поля — вместо списка один документ.

Такой документ функция не примет, компилятор выдаст `TS2379`. Если функции нужен именно такой результат, опишите параметр типом результата запроса. Как это сделать, показывает руководство [Убедиться, что связь загружена](../../populate/type-checks.mdx#передать-загруженный-документ-в-другую-функцию).

## AnyPopulationDoc

`AnyPopulationDoc<T>` — тип документа модели `T` в любом состоянии загрузки. К нему присваивается и обычный `HydratedDoc<T>`, и документ с populate по любым путям, вложенные связи тоже. Он нужен функциям, которым всё равно, загружена ли связь, — форматированию поста, проверке, расчёту. Без него пришлось бы описывать сигнатуру для каждого сочетания загруженных путей.

Поля такой формы читаются осторожно. Ссылка — это `Ref<M> | AnyPopulationDoc<M> | null`, то есть идентификатор, документ или пропавший документ. Массив ссылок — массив того же вида по элементам, значения карты тоже. Виртуальное поле читается как свой маркер или как загруженное значение. Все поля только для чтения, а поля с `Hidden` необязательны, потому что чтение без них — тоже документ `T`. Чтобы увидеть ссылку загруженной, сузьте документ через [`isPopulated`](#ispopulated).

Методов у формы немного. Остались те, чей смысл не зависит от загрузки, — [`AnyPopulationMethods`](#anypopulationmethods). Поэтому `post.$populate(...)`, `post.$set(...)` и присваивание поля не скомпилируются. Форма не знает, что лежит в поле, и не может ни принять запись, ни загрузить связь. Для этих действий возьмите конкретный тип документа.

Форма вынесена в собственное имя, а не во второй параметр `HydratedDoc`. Так редактор показывает `AnyPopulationDoc<Post>`, а не раскрытое пересечение типов.

## PartlyPopulatedDoc

`PartlyPopulatedDoc<T, P>` — документ в любом состоянии, у которого ключи `P` известны как загруженные. К этому типу сужает [`isPopulated`](#ispopulated). Ключи из `P` читаются как документы (или `null`) и присутствуют, остальные — как в [`AnyPopulationDoc<T>`](#anypopulationdoc). Значение `PartlyPopulatedDoc` присваивается обратно к `AnyPopulationDoc<T>`, а документ, знающий больше загруженных ключей, присваивается тому, кто знает меньше.

Писать этот тип самому приходится редко. Вы увидите его в подсказке сужённого документа (`PartlyPopulatedDoc<Post, "author">`), а нужен он, когда функция принимает уже проверенный документ.

## AnyPopulationMethods

`AnyPopulationMethods` — методы документа, которые есть у форм [`AnyPopulationDoc<T>`](#anypopulationdoc) и [`PartlyPopulatedDoc<T, P>`](#partlypopulateddoc). Их смысл не зависит от состояния загрузки. Это [`$isNew`](../documents/document-api.mdx#isnew), [`$locals`](../documents/document-api.mdx#locals), [`$isModified`](../documents/document-api.mdx#ismodified), [`$getChanges`](../documents/document-api.mdx#getchanges), [`$validate`](../documents/document-api.mdx#validate), [`$save`](../documents/document-api.mdx#save), [`$deleteOne`](../documents/document-api.mdx#deleteone), [`$toObject`](../documents/document-api.mdx#toobject), [`$toJSON`](../documents/document-api.mdx#tojson), [`$toPlain`](../documents/document-api.mdx#toplain), [`$populated`](../documents/document-api.mdx#populated) и [`$session`](../documents/document-api.mdx#session).

Методов записи и загрузки в списке нет. `$set`, `$get`, `$markModified`, `$populate`, `$depopulate`, `$assertPopulated`, `$is` и `$updateOne` на форме не скомпилируются, их типы зависят от того, какие поля загружены. Методы сериализации возвращают широкий `Record<string, unknown>`. Загруженное поле они сериализуют документом, незагруженное — идентификатором, и форма не знает, какое из двух. `$save` возвращает ту же форму, а загруженное поле сохраняется идентификаторами.

## PopulatableKeys

`PopulatableKeys<T>` — объединение ключей модели `T`, которые можно загрузить через populate. Это ссылки (одна, массив, карта ссылок) и виртуальные поля с populate. Тип задаёт аргумент `path` у [`isPopulated`](#ispopulated). Ключ, которого в объединении нет, не скомпилируется, а редактор предлагает в аргументе именно эти ключи. Для модели блога объединение такое — `"author" | "editor" | "tags" | "reviewers" | "comments" | "commentCount"`. Поля `title` и `views` не ссылки, их в объединении нет.

### Как читать сообщения об ошибках

Ошибка в вызове `populate` приходит от компилятора одним сообщением `TS2345`. У метода одна сигнатура, а причина стоит в типе параметра, в который аргумент не вписался. Например, для `populate("title")` сообщение такое — `Argument of type '"title"' is not assignable to parameter of type 'PopulateObject | "Invalid populate path \"title\": \"title\" is not a reference"'`. Причина — часть после `|`. Для объекта с опциями она приходит в свойстве `"populate error"` (`select of "author": unknown field "nope"`), а для слишком глубокого пути — сообщением `populate path is deeper than the 7-level ceiling`. Их порождают `CheckedPopulatePath`, `PopulateObjectCheck` и `PopulateListCheck`. Все сообщения перечислены в разделе [Ошибки](./populate.mdx#ошибки) страницы `.populate`.

### Когда эти типы не нужны

Обычно явные типы populate не нужны, результат строителя выводится сам. Если тип результата надо назвать, например для возврата из функции, выведите его из вызова — `Awaited<ReturnType<typeof loadPost>>`. Строить тип через `ApplyPopulate` вручную приходится почти только авторам библиотек. Если функции нужен пост в любом состоянии, опишите параметр типом [`AnyPopulationDoc`](#anypopulationdoc). Когда документ объявлен как `HydratedDoc`, а загрузку нужного пути надо проверить, возьмите [`$assertPopulated`](../documents/document-api.mdx#assertpopulated). Он сужает тип без ручных выражений.
