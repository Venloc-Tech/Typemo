Здесь четыре метода модели, которые работают с документами **без запроса к базе**. [`Model.new`](#model.new) создаёт новый документ в памяти. [`Model.hydrate`](#model.hydrate) превращает данные, прочитанные где-то ещё, в документ модели. [`Model.castObject`](#model.cast-object) приводит обычный объект к типам схемы, а [`Model.validate`](#model.validate) приводит его и проверяет. К базе не обращается ни один из них.

Если вы только начинаете, прочитайте сначала руководства [Жизненный цикл документа](../../documents/lifecycle.mdx) и [Валидация документа](../../documents/validation.mdx). Методы самого документа (`$save`, `$set` и другие) описаны в [API документа](./document-api.mdx). Чтение и запись через модель ([`create`](../writes/writes.mdx#create), [`find`](../query/reading.mdx#model.find)) лежат в своих разделах.

Во всех примерах одна модель. В ней есть обязательное поле с асинхронным валидатором, число с границами и значением по умолчанию и поле с перечислением.

## Model.new [#model.new]

`Model.new` создаёт новый документ в памяти. Значения по умолчанию уже подставлены, `_id` выдан, каждое поле приведено к своему типу. В базе документа пока нет, он появится после [`$save`](./document-api.mdx#save). Берите метод, когда собираете документ по частям, хотите проверить его до записи или сохраняете пачкой через [`Model.bulkSave`](../writes/writes.mdx#bulk-save).

Приведение типов идёт сразу. Значение неверного типа или поле, которого нет в модели, дают [`CastError`](../errors/data-errors.mdx#cast-error) на самом вызове `new`. Обязательность и правила вроде `min` и `enum` проверят только [`$validate`](./document-api.mdx#validate) и [`$save`](./document-api.mdx#save). Поэтому документ без обязательного поля в памяти создать можно, а сохранить нельзя.

<Snippet id="reference/documents/model-document-methods/model-new" twoslash />

<Returns type="UnsavedDocument<T>">

Новый несохранённый документ. [`$isNew`](./document-api.mdx#is-new) у него `true`, значения по умолчанию заполнены, `_id` создан, а поле версии `__v` не задано. В типе [`UnsavedDocument<T>`](../values/form-types.mdx#unsaved-document) есть переданные вами поля `Hidden`, а `createdAt`, `updatedAt` и `__v` необязательные — их выставит первый `$save`. После `$save()` документ уже типизирован как сохранённый, и эти поля больше не `undefined`.

</Returns>

<Params>
<Param name="doc" type="CreateInput<T>" required>

Начальные данные. Тип подскажет поля модели. Обязательные поля придётся передать, поля со значением по умолчанию можно пропустить. Значения приводятся к типам полей, а для идентификаторов и int64 подойдут и строки.

</Param>
</Params>

### Ошибки [#model.new.errors]

Значение неверного типа и неизвестный ключ дают `CastError` прямо на вызове. Это случится только в коде без типов, в типизированном коде компилятор остановит вас раньше.

<Snippet id="reference/documents/model-document-methods/model-new-errors" />

Отсутствие обязательного поля вскроется лишь при сохранении.

### Когда не подходит [#model.new.when-not-to-use]

Если документ сразу нужно записать, берите [`create`](../writes/writes.mdx#create). Он создаёт документ, проверяет и вставляет его одной операцией и возвращает сохранённый. Если вы читаете данные из базы, документы вернёт [`find`](../query/reading.mdx#model.find), а `new` для этого не нужен.

## Model.hydrate [#model.hydrate]

`Model.hydrate` оживляет данные, которые прочитали не через Typemo. Он берёт объект **в сохранённой форме**, с именами полей базы, и делает из него документ с типизированными коллекциями и отслеживанием изменений. Метод выручает, когда документ пришёл из кеша, из очереди сообщений, из драйвера или из фикстуры теста, а вам нужны `$`-методы.

Такой документ считается **загруженным**. [`$isNew`](./document-api.mdx#is-new) у него `false`, изменений нет, а любая правка попадёт в обновление при [`$save`](./document-api.mdx#save). Данные не приводятся и заранее не проверяются, метод верит, что перед ним то, что лежит в базе. Хуки `document.init` срабатывают сразу, так что они должны быть синхронными.

<Snippet id="reference/documents/model-document-methods/model-hydrate" twoslash />

<Returns type="HydratedDoc<T>">

Загруженный документ. Массивы, Map и поддокументы в нём — уже типизированные коллекции, у массива значений `constructor.name` равен `StrictArray`. Ключи, которых нет в схеме, в документ не попадают.

</Returns>

<Params>
<Param name="raw" type="Readonly<Record<string, unknown>>" required>

Сохранённый документ. Это обычный объект с именами полей базы (`dbName`, если он задан в `@Prop`), значениями BSON (`ObjectId`, `Date`, `bigint`) и вложенными данными.

</Param>
</Params>

### Ошибки [#model.hydrate.errors]

Если `raw` — не обычный объект, Typemo бросает [`QueryError`](../errors/query-errors.mdx#query-error).

<Snippet id="reference/documents/model-document-methods/model-hydrate-errors" />

Документ, которого нет в базе, `hydrate` создаёт без возражений. Но при сохранении запись не найдётся.

<Snippet id="reference/documents/model-document-methods/model-hydrate-errors-2" />

### Когда не подходит [#model.hydrate.when-not-to-use]

Если данные лежат в базе, читайте их запросом. [`find`](../query/reading.mdx#model.find) сам вернёт документы и учтёт проекции и политики. Если у вас объект, которого в базе ещё нет, берите [`Model.new`](#model.new). Он приведёт и проверит значения, а `hydrate` поверит им на слово.

## Model.castObject [#model.cast-object]

`Model.castObject` приводит обычный объект к типам схемы и возвращает приведённые поля. Он пригодится, когда данные нужно проверить и нормализовать без документа и без записи. Например, ответ внешнего сервиса, строка импорта или значение из настроек.

Метод приводит только то, что вы передали. Значения по умолчанию он не подставляет, обязательность не проверяет, правила `min`, `enum` и асинхронные валидаторы не запускает — для этого есть [`Model.validate`](#model.validate). Приведение в Typemo строгое. Число не примет строку `"3"`, а строка превратится в `ObjectId`, потому что здесь преобразование однозначно.

<Returns type="Partial<DataFields<T>>">

Приведённые поля. Чего не было во входе, того не будет и в результате.

</Returns>

Объект, который нужно привести.

### Ошибки [#model.cast-object.errors]

Первое же поле, которое не приводится, и любой неизвестный ключ дают [`CastError`](../errors/data-errors.mdx#cast-error).

<Snippet id="reference/documents/model-document-methods/model-cast-object-errors" />

Метод останавливается на первой ошибке. Если нужны все проблемы сразу, берите [`Model.validate`](#model.validate).

## Model.validate [#model.validate]

`Model.validate` приводит объект и проверяет его по всем правилам схемы. Это обязательность, границы, перечисления, свои и асинхронные валидаторы. Метод удобен для данных снаружи, например для тела запроса или файла импорта. Вы получаете либо корректное значение, либо полный список проблем. Документ не создаётся, в базу ничего не пишется.

В отличие от [`Model.castObject`](#model.cast-object), `validate` подставляет значения по умолчанию, в том числе `_id`, и возвращает готовое значение. Все проблемы собираются в одну [`ValidationError`](../errors/data-errors.mdx#validation-error). Переданный вами объект не меняется.

<Snippet id="reference/documents/model-document-methods/model-validate" twoslash />

<Returns type="Promise<DataFields<T>>">

Приведённое значение со значениями по умолчанию. Если нашлась хоть одна проблема, вместо него придёт ошибка.

</Returns>

<Param name="input" type="unknown" required>

### Ошибки [#model.validate.errors]

Все найденные проблемы лежат в одной `ValidationError`. Метод дожидается асинхронных валидаторов, а пункты идут в порядке полей схемы, как они объявлены в классе. Какой валидатор закончил раньше, не важно.

<Snippet id="reference/documents/model-document-methods/model-validate-errors" />

Значение, которое не приводится, попадает в тот же список с причиной `cast`, а `CastError` лежит в `cause` пункта. Так `validate` отличается от `castObject`, который бросает `CastError` сам. У каждого поля не больше одного пункта. Если значение не приводится, его ограничения (`min`, `enum`) не проверяются, потому что проверять нечего.

<Snippet id="documents/validation/inspect-cast-error-2" />

Если на входе вообще не объект, ошибка выглядит так.

<Snippet id="reference/documents/model-document-methods/model-validate-errors-2" />

### Когда не подходит [#model.validate.when-not-to-use]

Чтобы проверить уже созданный документ, берите [`$validate`](./document-api.mdx#validate). Если нужно только привести значения без правил, хватит [`Model.castObject`](#model.cast-object).
