Здесь четыре метода модели, которые работают с документами **без запроса к базе**. [`Model.new`](#modelnew) создаёт новый документ в памяти. [`Model.hydrate`](#modelhydrate) превращает данные, прочитанные где-то ещё, в документ модели. [`Model.castObject`](#modelcastobject) приводит обычный объект к типам схемы, а [`Model.validate`](#modelvalidate) приводит его и проверяет. К базе не обращается ни один из них.

Если вы только начинаете, прочитайте сначала руководства [Жизненный цикл документа](../../documents/lifecycle.mdx) и [Валидация документа](../../documents/validation.mdx). Методы самого документа (`$save`, `$set` и другие) описаны в [API документа](./document-api.mdx). Чтение и запись через модель ([`create`](../writes/writes.mdx#create), [`find`](../query/reading.mdx#modelfind)) лежат в своих разделах.

Во всех примерах одна модель. В ней есть обязательное поле с асинхронным валидатором, число с границами и значением по умолчанию и поле с перечислением.

```ts twoslash title="models/product.ts"
import { type Defaulted, Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "products" })
export class Product extends Entity {
  @Prop(() => String, {
    required: true,
    validate: async (value: string) => value !== "bad" || "the name is taken",
  })
  name!: string;

  @Prop(() => Number, { min: 0, max: 10, default: 1 })
  size!: Defaulted<number>;

  @Prop(() => String, { enum: ["a", "b"] })
  kind?: "a" | "b";
}
```

## Model.new

`Model.new` создаёт новый документ в памяти. Значения по умолчанию уже подставлены, `_id` выдан, каждое поле приведено к своему типу. В базе документа пока нет, он появится после [`$save`](./document-api.mdx#save). Берите метод, когда собираете документ по частям, хотите проверить его до записи или сохраняете пачкой через [`Model.bulkSave`](../writes/writes.mdx#bulksave).

Приведение типов идёт сразу. Значение неверного типа или поле, которого нет в модели, дают [`CastError`](../errors/data-errors.mdx#casterror) на самом вызове `new`. Обязательность и правила вроде `min` и `enum` проверят только [`$validate`](./document-api.mdx#validate) и [`$save`](./document-api.mdx#save). Поэтому документ без обязательного поля в памяти создать можно, а сохранить нельзя.

```ts twoslash
import { type Defaulted, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, {
    required: true,
    validate: async (value: string) => value !== "bad" || "the name is taken",
  })
  name!: string;
  @Prop(() => Number, { min: 0, max: 10, default: 1 }) size!: Defaulted<number>;
  @Prop(() => String, { enum: ["a", "b"] }) kind?: "a" | "b";
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Products = client.db().model(Product);
// ---cut---
const product = Products.new({ name: "lamp" });
console.log(product.$isNew(), product.size, product._id.constructor.name);
// → true 1 "ObjectId"

await product.$save();
console.log(product.$isNew());
// → false
```

<Returns type="UnsavedDocument<T>">

Новый несохранённый документ. [`$isNew`](./document-api.mdx#isnew) у него `true`, значения по умолчанию заполнены, `_id` создан, а поле версии `__v` не задано. В типе [`UnsavedDocument<T>`](../values/form-types.mdx#unsaveddocument) есть переданные вами поля `Hidden`, а `createdAt`, `updatedAt` и `__v` необязательные — их выставит первый `$save`. После `$save()` документ уже типизирован как сохранённый, и эти поля больше не `undefined`.

</Returns>

<Params>
<Param name="doc" type="CreateInput<T>" required>

Начальные данные. Тип подскажет поля модели. Обязательные поля придётся передать, поля со значением по умолчанию можно пропустить. Значения приводятся к типам полей, а для идентификаторов и int64 подойдут и строки.

</Param>
</Params>

<FullType>

```ts
new(doc: CreateInput<T>): UnsavedDocument<T>;
```

</FullType>

### Ошибки

Значение неверного типа и неизвестный ключ дают `CastError` прямо на вызове. Это случится только в коде без типов, в типизированном коде компилятор остановит вас раньше.

```text
CastError: Cast to string failed at path "name" for 5 (number): expected a string [type]
CastError: Cast to Product failed at path "nope" for 1 (number): not a field of Product [unknown-key]
```

Отсутствие обязательного поля вскроется лишь при сохранении.

```text
ValidationError: Validation failed: "name": the field is required [required]
```

### Когда не подходит

Если документ сразу нужно записать, берите [`create`](../writes/writes.mdx#create). Он создаёт документ, проверяет и вставляет его одной операцией и возвращает сохранённый. Если вы читаете данные из базы, документы вернёт [`find`](../query/reading.mdx#modelfind), а `new` для этого не нужен.

## Model.hydrate

`Model.hydrate` оживляет данные, которые прочитали не через Typemo. Он берёт объект **в сохранённой форме**, с именами полей базы, и делает из него документ с типизированными коллекциями и отслеживанием изменений. Метод выручает, когда документ пришёл из кеша, из очереди сообщений, из драйвера или из фикстуры теста, а вам нужны `$`-методы.

Такой документ считается **загруженным**. [`$isNew`](./document-api.mdx#isnew) у него `false`, изменений нет, а любая правка попадёт в обновление при [`$save`](./document-api.mdx#save). Данные не приводятся и заранее не проверяются, метод верит, что перед ним то, что лежит в базе. Хуки `document.init` срабатывают сразу, так что они должны быть синхронными.

```ts twoslash
import { ObjectId } from "mongodb";
import { type Defaulted, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { min: 0, max: 10, default: 1 }) size!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Products = client.db().model(Product);
// ---cut---
const product = Products.hydrate({ _id: new ObjectId(), name: "lamp", size: 3, tags: ["home"] });
console.log(product.$isNew(), product.$isModified(), product.tags.constructor.name);
// → false false "StrictArray"

product.name = "desk lamp";
console.log(product.$getChanges());
// → { $set: { name: "desk lamp" } }
```

<Returns type="HydratedDoc<T>">

Загруженный документ. Массивы, Map и поддокументы в нём — уже типизированные коллекции, у массива значений `constructor.name` равен `StrictArray`. Ключи, которых нет в схеме, в документ не попадают.

</Returns>

<Params>
<Param name="raw" type="Readonly<Record<string, unknown>>" required>

Сохранённый документ. Это обычный объект с именами полей базы (`dbName`, если он задан в `@Prop`), значениями BSON (`ObjectId`, `Date`, `bigint`) и вложенными данными.

</Param>
</Params>

<FullType>

```ts
hydrate(raw: Readonly<Record<string, unknown>>): HydratedDoc<T>;
```

</FullType>

### Ошибки

Если `raw` — не обычный объект, Typemo бросает [`QueryError`](../errors/query-errors.mdx#queryerror).

```text
QueryError: hydrate: a stored document (plain object)
```

Документ, которого нет в базе, `hydrate` создаёт без возражений. Но при сохранении запись не найдётся.

```text
DocumentNotFoundError: Product.save: the document is no longer in the collection (deleted since it was read, or out of the scope of the operation's policies); nothing was written
```

### Когда не подходит

Если данные лежат в базе, читайте их запросом. [`find`](../query/reading.mdx#modelfind) сам вернёт документы и учтёт проекции и политики. Если у вас объект, которого в базе ещё нет, берите [`Model.new`](#modelnew). Он приведёт и проверит значения, а `hydrate` поверит им на слово.

## Model.castObject

`Model.castObject` приводит обычный объект к типам схемы и возвращает приведённые поля. Он пригодится, когда данные нужно проверить и нормализовать без документа и без записи. Например, ответ внешнего сервиса, строка импорта или значение из настроек.

Метод приводит только то, что вы передали. Значения по умолчанию он не подставляет, обязательность не проверяет, правила `min`, `enum` и асинхронные валидаторы не запускает — для этого есть [`Model.validate`](#modelvalidate). Приведение в Typemo строгое. Число не примет строку `"3"`, а строка превратится в `ObjectId`, потому что здесь преобразование однозначно.

```ts twoslash
import { type Defaulted, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { min: 0, max: 10, default: 1 }) size!: Defaulted<number>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Products = client.db().model(Product);
// ---cut---
console.log(Products.castObject({ name: "lamp", size: 3 }));
// → { name: "lamp", size: 3 }

console.log(Products.castObject({}));
// → {}
```

<Returns type="Partial<DataFields<T>>">

Приведённые поля. Чего не было во входе, того не будет и в результате.

</Returns>

<Params>
<Param name="input" type="unknown" required>

Объект, который нужно привести.

</Param>
</Params>

<FullType>

```ts
castObject(input: unknown): Partial<DataFields<T>>;
```

</FullType>

### Ошибки

Первое же поле, которое не приводится, и любой неизвестный ключ дают [`CastError`](../errors/data-errors.mdx#casterror).

```text
CastError: Cast to number failed at path "size" for "3" (string): expected a number [type]
CastError: Cast to document failed at path "nope" for 1 (number): not a field of Product [unknown-key]
```

Метод останавливается на первой ошибке. Если нужны все проблемы сразу, берите [`Model.validate`](#modelvalidate).

## Model.validate

`Model.validate` приводит объект и проверяет его по всем правилам схемы. Это обязательность, границы, перечисления, свои и асинхронные валидаторы. Метод удобен для данных снаружи, например для тела запроса или файла импорта. Вы получаете либо корректное значение, либо полный список проблем. Документ не создаётся, в базу ничего не пишется.

В отличие от [`Model.castObject`](#modelcastobject), `validate` подставляет значения по умолчанию, в том числе `_id`, и возвращает готовое значение. Все проблемы собираются в одну [`ValidationError`](../errors/data-errors.mdx#validationerror). Переданный вами объект не меняется.

```ts twoslash
import { type Defaulted, Entity, Prop, Schema, TypemoClient, ValidationError } from "@venloc/typemo";
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, {
    required: true,
    validate: async (value: string) => value !== "bad" || "the name is taken",
  })
  name!: string;
  @Prop(() => Number, { min: 0, max: 10, default: 1 }) size!: Defaulted<number>;
  @Prop(() => String, { enum: ["a", "b"] }) kind?: "a" | "b";
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Products = client.db().model(Product);
// ---cut---
const value = await Products.validate({ name: "lamp" });
console.log(value.name, value.size, value._id.constructor.name);
// → "lamp" 1 "ObjectId"

try {
  await Products.validate({ name: "bad", size: 99, kind: "z" });
} catch (error) {
  if (error instanceof ValidationError) {
    console.log(error.issues.map((issue) => [issue.path.join("."), issue.reason]));
    // → [["name", "validator"], ["size", "max"], ["kind", "enum"]]
  }
}
```

<Returns type="Promise<DataFields<T>>">

Приведённое значение со значениями по умолчанию. Если нашлась хоть одна проблема, вместо него придёт ошибка.

</Returns>

<Params>
<Param name="input" type="unknown" required>

Объект для проверки.

</Param>
</Params>

<FullType>

```ts
validate(input: unknown): Promise<DataFields<T>>;
```

</FullType>

### Ошибки

Все найденные проблемы лежат в одной `ValidationError`. Метод дожидается асинхронных валидаторов, а пункты идут в порядке полей схемы, как они объявлены в классе. Какой валидатор закончил раньше, не важно.

```text
ValidationError: Validation failed: "name": the name is taken [validator]; "size": must be at most 10 [max]; "kind": must be one of "a", "b" [enum]
ValidationError: Validation failed: "name": the field is required [required]
```

Значение, которое не приводится, попадает в тот же список с причиной `cast`, а `CastError` лежит в `cause` пункта. Так `validate` отличается от `castObject`, который бросает `CastError` сам. У каждого поля не больше одного пункта. Если значение не приводится, его ограничения (`min`, `enum`) не проверяются, потому что проверять нечего.

```text
ValidationError: Validation failed: "size": Cast to number failed at path "size" for "4" (string): expected a number [type] [cast]
```

Если на входе вообще не объект, ошибка выглядит так.

```text
ValidationError: Validation failed: "": Cast to Product failed for 5 (number): expected an object [type] [cast]
```

### Когда не подходит

Чтобы проверить уже созданный документ, берите [`$validate`](./document-api.mdx#validate). Если нужно только привести значения без правил, хватит [`Model.castObject`](#modelcastobject).
