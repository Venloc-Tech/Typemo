Здесь всё про **неизвестные поля**. Так называют ключи в сохранённых поддокументах, которых нет в схеме вашего класса. Они появляются, когда данные записала другая версия схемы, старая или новая, или другая программа. Typemo не теряет такие данные молча. [`unknownFieldsOf`](#unknownfieldsof) их показывает, [`UnknownFieldsError`](#unknownfieldserror) отказывает в сохранении, которое их стёрло бы, а [`SaveOptions.dropUnknownFields`](./document-api.mdx#saveoptions) разрешает потерю осознанно.

Если вы только начинаете, прочитайте сначала руководство [Неизвестные поля](../../documents/unknown-fields.mdx). Там объяснено, откуда берутся такие данные и что с ними делать. Эта страница — справочник.

В примерах заказ из [API документа](./document-api.mdx). Версия схемы постарше записала в его базу лишние ключи. У первой строки это `oldPrice`, у адреса `legacyZip`. Лишний ключ в корне документа (`rootExtra`) остаётся нетронутым. Сохранение меняет поля по путям и корень не переписывает, поэтому в список такие ключи не попадают.

```ts twoslash title="models/order.ts"
import { Entity, Prop, Schema, Versioned } from "@venloc/typemo";

@Schema({ nested: true })
export class Address {
  @Prop(() => String, { required: true })
  city!: string;
}

@Schema()
export class Line extends Entity {
  @Prop(() => String, { required: true })
  sku!: string;

  @Prop(() => Number, { required: true, min: 0 })
  qty!: number;
}

@Schema({ collection: "orders" })
export class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => [Line])
  lines!: Line[];

  @Prop(() => Address)
  address?: Address;
}
```

## unknownFieldsOf

`unknownFieldsOf` возвращает список поддокументов, в которых лежат неизвестные схеме ключи. Вызывайте его, когда хотите узнать о таких данных заранее. Например, показать предупреждение, записать метрику или решить, стоит ли мигрировать документ, пока он не упал при сохранении.

Ключи Typemo запоминает **при чтении документа**, без отдельного запроса. Поэтому функция отрабатывает мгновенно, а у документа из [`Model.new`](./model-document-methods.mdx#modelnew) результат пустой. Пути записаны **именами полей класса** от корня документа, например `lines.0`, `address` или `notes.home`. Функция принимает документ целиком, поддокумент или коллекцию. Для поддокумента путь всё равно считается от корня.

```ts twoslash
import { ObjectId } from "mongodb";
import { Entity, Prop, Schema, Spec, TypemoClient, Versioned, isUnknownFieldsError, unknownFieldsOf } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const rawOrders = client.unsafeDriver().db("shop").collection("orders");
const id = new ObjectId();
await rawOrders.insertOne({
  _id: id,
  customer: "legacy",
  lines: [{ _id: new ObjectId(), sku: "A1", qty: 1, oldPrice: 5 }, { _id: new ObjectId(), sku: "B2", qty: 2 }],
  address: { city: "Oslo", legacyZip: "0150" },
  __v: 0,
});
const order = await Orders.findById(id).orFail();
// ---cut---
console.log(unknownFieldsOf(order));
// → [{ path: "lines.0", keys: ["oldPrice"] }, { path: "address", keys: ["legacyZip"] }]

console.log(unknownFieldsOf(order.address!), unknownFieldsOf(order.lines[1]!));
// → [{ path: "address", keys: ["legacyZip"] }] []
```

</Returns>

### Что не попадает в список

Неизвестные ключи **корня** документа в список не входят. Сохранение меняет корень только по полям схемы и остальное не трогает, так что терять там нечего. `lean()` и `.plain()` возвращают строки без гидратации, поэтому ключи не скрывают. В результате `lean()` они видны, а в документе и в `$toObject()` нет.

## UnknownFieldsError

`UnknownFieldsError` — это ошибка сохранения, которое **переписало бы** поддокумент вместе с неизвестными полями и стёрло бы их из базы. По умолчанию Typemo отказывает. Данные другой версии схемы вам не принадлежат, а молчаливая потеря — худшее, что с ними можно сделать. В базу при этом не уходит ничего.

Ошибка возможна, когда сохранение записывает поддокумент заново, а сам он остаётся в документе или может остаться после записи. Это бывает в таких случаях.

- `reverse`, `sort`, `splice`, `clear` или `replace` у массива поддокументов.
- Замена поддокумента через [`$set`](./document-api.mdx#set) или `lines.set(index, …)`.
- `clear()` у Map поддокументов.
- `set` по уже существующему ключу Map.

Правка отдельных полей внутри поддокумента (`order.address.city = …`) неизвестные поля не затрагивает. То же верно для `push`, `unshift`, `addToSet`, `pull`, `pop` и `shift`, если в сохранении только они. Но правка поля внутри элемента вместе с `push` в одном сохранении записывает массив целиком, и тогда ошибка возможна.

Удаление отдельным оператором потерей не считается. `pull`, `pop`, `shift` у массива и `delete(key)` у Map убирают элемент осознанно и без ошибки. А вот `splice`, `clear` и `replace` записывают массив целиком. Неизвестные поля его элементов под угрозой, и сохранение откажет.

```ts twoslash
import { ObjectId } from "mongodb";
import { Entity, Prop, Schema, Spec, TypemoClient, Versioned, isUnknownFieldsError, unknownFieldsOf } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const rawOrders = client.unsafeDriver().db("shop").collection("orders");
const id = new ObjectId();
await rawOrders.insertOne({
  _id: id,
  customer: "legacy",
  lines: [{ _id: new ObjectId(), sku: "A1", qty: 1, oldPrice: 5 }, { _id: new ObjectId(), sku: "B2", qty: 2 }],
  address: { city: "Oslo", legacyZip: "0150" },
  __v: 0,
});
const order = await Orders.findById(id).orFail();
// ---cut---
order.address!.city = "Rome";
order.lines.push({ sku: "C3", qty: 1 });
await order.$save();
console.log(unknownFieldsOf(order).length);
// → 2

order.lines.reverse();
try {
  await order.$save();
} catch (error) {
  if (isUnknownFieldsError(error)) {
    console.log(error.fields);
    // → [{ path: "lines.2", keys: ["oldPrice"] }]
  }
}
```

<Param name="fields" type="readonly UnknownFields[]">

</Param>

Текст ошибки называет пути и ключи и подсказывает выход.

```text
UnknownFieldsError: the save would drop fields the schema does not know from stored data: "lines.1" (oldPrice); migrate the data or the schema, or pass { dropUnknownFields: true } to $save()/bulkSave() to accept the loss
```

### Как поступить

Выходов три. Можно **мигрировать данные** — удалить лишние ключи или перенести их. Можно **дополнить схему**. Если ключ на самом деле нужен, добавьте поле в класс, и он станет известным. И можно **принять потерю** — передайте `{ dropUnknownFields: true }` в [`$save`](./document-api.mdx#save) или [`Model.bulkSave`](../writes/writes.mdx#bulksave). После такого сохранения неизвестные поля пропадают из базы и из экземпляров документа, а `unknownFieldsOf` перестаёт их показывать.

```ts twoslash
import { ObjectId } from "mongodb";
import { Entity, Prop, Schema, Spec, TypemoClient, Versioned, isUnknownFieldsError, unknownFieldsOf } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const rawOrders = client.unsafeDriver().db("shop").collection("orders");
const id = new ObjectId();
await rawOrders.insertOne({
  _id: id,
  customer: "legacy",
  lines: [{ _id: new ObjectId(), sku: "A1", qty: 1, oldPrice: 5 }, { _id: new ObjectId(), sku: "B2", qty: 2 }],
  address: { city: "Oslo", legacyZip: "0150" },
  __v: 0,
});
const order = await Orders.findById(id).orFail();
order.lines.reverse();
// ---cut---
await order.$save({ dropUnknownFields: true });
console.log(unknownFieldsOf(order));
// → [{ path: "address", keys: ["legacyZip"] }]
```

В примере в списке остался адрес. Это сохранение его не переписывало, значит, его ключи по-прежнему в базе.

### Предпросмотр: `$getChanges`

[`$getChanges`](./document-api.mdx#getchanges) не бросает `UnknownFieldsError`. Тот же отказ он кладёт в ключ `$problems`, то есть путь поддокумента и текст ошибки, которую бросил бы `$save`. Остальное обновление возвращается как обычно. До сохранения видно и что запишется, и что откажет.

```text
{ $set: { "lines.0": {…} }, $problems: { "lines.0": "the save would drop fields the schema does not know from stored data: \"lines.0\" (oldPrice); migrate the data or the schema, or pass { dropUnknownFields: true } to $save()/bulkSave() to accept the loss" } }
```

### Ошибки

Сама `UnknownFieldsError` других ошибок не бросает. Это итог проверки перед записью. `bulkSave` применяет то же правило к каждому документу списка.

## isUnknownFieldsError

`isUnknownFieldsError` проверяет тип. Она возвращает `true`, если значение — [`UnknownFieldsError`](#unknownfieldserror), и сужает тип до неё. Функция пригодится в блоке `catch`, где ошибка имеет тип `unknown`. Проверка `error instanceof UnknownFieldsError` даёт тот же результат.

<Returns type="error is UnknownFieldsError">

`true` для `UnknownFieldsError`, `false` для любого другого значения.

</Returns>

<Params>
<Param name="error" type="unknown" required>

Проверяемое значение.

</Param>
</Params>

<FullType>

```ts
const isUnknownFieldsError: (error: unknown) => error is UnknownFieldsError;
```

</FullType>

## UnknownFields

`UnknownFields` описывает один поддокумент с неизвестными ключами. Из таких элементов состоят результат [`unknownFieldsOf`](#unknownfieldsof) и поле `fields` ошибки [`UnknownFieldsError`](#unknownfieldserror).
