На этой странице собраны все `$`-методы **гидратированного документа** — объекта, который вы получаете из `await Model.find()`, `create` и `Model.new`: экземпляр вашего класса, у которого массивы, поддокументы и Map заменены на [типизированные коллекции](./typed-collections.mdx), а рядом с полями лежит набор методов, начинающихся с `$`. Префикс нужен, чтобы имена методов не сталкивались с полями вашей модели: поле `save` у вас может быть, метод `$save` — никогда не займёт его имя.

Если вы только начинаете, сначала прочитайте руководства [Изменить и сохранить](../../documents/change-and-save.mdx) и [Жизненный цикл документа](../../documents/lifecycle.mdx). Эта страница — справочник: к ней возвращаются за деталью.

Все примеры используют один заказ. В нём есть обязательное поле, массив строк, массив поддокументов, вложенный объект, Map и скрытое поле:

```ts twoslash title="models/order.ts"
import { Entity, type Hidden, Prop, Schema, Spec, Versioned } from "@venloc/typemo";

@Schema({ nested: true })
export class Address {
  @Prop(() => String, { required: true })
  city!: string;

  @Prop(() => String)
  street?: string;
}

@Schema()
export class Line extends Entity {
  @Prop(() => String, { required: true })
  sku!: string;

  @Prop(() => Number, { required: true, min: 0 })
  qty!: number;
}

@Schema({ collection: "orders" })
export class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => [String])
  tags!: string[];

  @Prop(() => [Line])
  lines!: Line[];

  @Prop(() => Address)
  address?: Address;

  @Prop(() => Spec.map(Number))
  fees?: Map<string, number>;

  @Prop(() => String, { hidden: true })
  note?: Hidden<string>;
}
```

Заказ Alice, на котором получены результаты, выглядит так: покупатель `alice`, тег `gift`, одна строка `A1` в количестве 2, город `Oslo`, сбор `delivery` на 5. Идентификаторы в результатах сокращены до `"…"`: база выдаёт их заново при каждом запуске.

Методы, у которых на этой странице нет отдельного раздела, — это методы самих коллекций внутри документа (`tags.push`, `lines.create`, `fees.set`) и методы поддокумента. Они описаны в [Типизированных коллекциях](./typed-collections.mdx).

## $save

`$save` записывает документ в базу: новый документ вставляет, загруженный обновляет. Это основной способ сохранить изменения, когда вы работаете с документом как с объектом: прочитали, поменяли поля, вызвали `$save`.

Метод не пересылает документ целиком. Typemo следит за изменениями с момента загрузки или прошлого сохранения ([`$getChanges`](#getchanges) показывает, что именно), собирает из них самое короткое обновление — `$set` изменённых полей, `$push` для добавленных элементов массива, `$unset` для удалённых ключей Map — и отправляет только его. Если менять было нечего, в базу не уходит ничего, а `$save` завершается успешно. Перед записью документ проходит [`$validate`](#validate), запускаются хуки `document.save`, а у документа с полем `__v` (класс `Versioned`) обновление получает проверку версии: подробнее — в руководстве [Версии и параллельные изменения](../../documents/versions.mdx).

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = Orders.new({ customer: "alice", tags: ["gift"], lines: [{ sku: "A1", qty: 2 }] });
await order.$save();
console.log(order.$isNew());
// → false

order.customer = "bob";
order.tags.push("express");
await order.$save();
console.log(order.$isModified(), order.__v);
// → false 1
```

<Returns type="Promise<this>">

Тот же документ, а не копия. После `await` он больше не новый ([`$isNew`](#isnew) возвращает `false`), а отслеживание изменений начинается заново. Если `Versioned` увеличил версию, свежее значение уже лежит в `order.__v`.

</Returns>

<Params>
<Param name="options" type="SaveOptions">

Необязательные настройки записи, описаны ниже в разделе [SaveOptions](#saveoptions): сессия, тайм-аут, разрешение потерять неизвестные поля и контекст политик.

</Param>
</Params>

<FullType>

```ts
$save(options?: SaveOptions): Promise<this>;
```

</FullType>

### Что уйдёт в базу

Форма обновления зависит от того, что вы делали с коллекциями: `push` даёт `$push`, `pull` — `$pullAll`, изменение поля внутри строки — `$set` по пути с индексом. Полную таблицу «метод → оператор» смотрите в справочнике [Типизированные коллекции](./typed-collections.mdx). Проверить итог до записи можно через [`$getChanges`](#getchanges).

### Сохранение внутри транзакции

Если вызов происходит внутри [`client.transaction`](../connection/typemo-client.mdx#clienttransaction), `$save` присоединяется к ней сам: передавать сессию не нужно. Если транзакция откатится, изменения документа в базе тоже откатятся. Документ в памяти при этом сохраняет свои правки, поэтому при повторе транзакции колбэк должен снова читать документ, а не пользоваться загруженным раньше (подробнее — в руководстве [Транзакции](../../transactions/transactions.mdx)).

### Ошибки

Значения, присвоенные обычным присваиванием (`order.customer = 5`), `$save` сначала приводит к типу поля. Если значение не приводится, бросается [`CastError`](../errors/data-errors.mdx#casterror): ограничения этого поля при этом не проверяются, и в базу ничего не уходит.

```text
CastError: Cast to string failed at path "customer" for 5 (number): expected a string [type]
```

После приведения `$save` бросает [`ValidationError`](../errors/data-errors.mdx#validationerror), если документ не проходит проверки (тексты и пути — в разделе [`$validate`](#validate)):

```text
ValidationError: Validation failed: "lines.1.qty": must be at least 0 [min]
```

[`UnknownFieldsError`](../errors/data-errors.mdx#unknownfieldserror) приходит, когда сохранение переписало бы поддокумент вместе с полями, которых нет в схеме (руководство [Неизвестные поля](../../documents/unknown-fields.mdx)). [`DirectWriteError`](../errors/data-errors.mdx#directwriteerror) и [`PartialArrayError`](../errors/data-errors.mdx#partialarrayerror) сообщают о записи мимо методов коллекции и о правке частично загруженного массива. [`VersionError`](../errors/query-errors.mdx#versionerror) означает, что документ изменили после вашего чтения.

Если документ уже удалён через [`$deleteOne`](#deleteone), `$save` отказывается что-либо писать:

```text
QueryError: save: the document of Order was deleted
```

Если же документ удалил кто-то другой, `$save` доходит до базы, не находит запись и бросает [`DocumentNotFoundError`](../errors/query-errors.mdx#documentnotfounderror):

```text
DocumentNotFoundError: Order.save: the document is no longer in the collection (deleted since it was read, or out of the scope of the operation's policies); nothing was written
```

Вторая причина в скобках нужна потому, что запись могла остаться в коллекции, но выйти из области политик модели (другой тенант, мягкое удаление): для `$save` такой документ тоже «не найден».

### Когда не подходит

Если нужно изменить много документов одним запросом или изменить документ, не загружая его, используйте [`updateOne`](../writes/writes.mdx#updateone) и [`updateMany`](../writes/writes.mdx#updatemany). Чтобы сохранить сразу много загруженных документов одной упорядоченной записью, используйте [`Model.bulkSave`](../writes/writes.mdx#bulksave). Если нужно изменить именно этот документ по `_id` через общий конвейер операций и не трогать его копию в памяти, есть [`$updateOne`](#updateone).

## $set

`$set` присваивает значение по пути и сразу приводит его к типу поля. Обычное присваивание `order.customer = "bob"` для скалярных полей тоже работает, но `$set` нужен там, где присваивание недоступно или ненадёжно: для замены целого контейнера (массива, Map, поддокумента), которую тип не даёт записать напрямую, и для пути по вложенным структурам одной строкой.

Путь пишется через точку: `"address.city"` идёт в вложенный объект, `"tags.0"` — к элементу массива по индексу, `"fees.delivery"` — к значению Map по ключу. Позиционных знаков MongoDB (`$`, `$[]`) здесь нет: документ знает свои элементы. Компилятор подсказывает все допустимые пути и проверяет тип значения по пути.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = Orders.new({
  customer: "alice",
  tags: ["gift"],
  lines: [{ sku: "A1", qty: 2 }],
  address: { city: "Oslo" },
  fees: { delivery: 5 },
});

order.$set("address.city", "Paris").$set("tags.0", "express").$set("fees.delivery", 9);
console.log(order.address?.city, [...order.tags], order.fees?.get("delivery"));
// → "Paris" ["express"] 9
```

<Returns type="this">

Тот же документ: вызовы `$set` можно записывать цепочкой, как выше. Значение, уже приведённое к типу поля, лежит в документе сразу, а изменение попадёт в базу при следующем [`$save`](#save).

</Returns>

<Params>
<Param name="path" type="DocumentPaths<T>" required>

Путь к полю: имя поля, путь через точку во вложенные объекты и поддокументы, индекс элемента массива (`tags.0`, `lines.0.qty`) или ключ Map (`fees.delivery`). Пустая строка и путь к служебному полю не принимаются.

</Param>
<Param name="value" type="FieldInput<DocumentValue<T, P>>" required>

Новое значение. Принимается всё, что принимает [`create`](../writes/writes.mdx#create) для этого поля: массив принимает обычный массив, поддокумент — обычный объект, поле `ObjectId` — его строковую запись. `undefined` и `null` для необязательного поля без `nullable` не принимаются.

</Param>
</Params>

<FullType>

```ts
$set<const P extends DocumentPaths<T>>(path: P, value: FieldInput<DocumentValue<T, P>>): this;
```

</FullType>

### Замена контейнера

Массив, Map и поддокумент присваиванием не заменить: `order.tags = ["x"]` не проходит компиляцию, а присваивание в обход типов [`$save`](#save) отклонит с [`DirectWriteError`](../errors/data-errors.mdx#directwriteerror). `$set` — разрешённый путь: он приводит значение и делает новый контейнер отслеживаемым.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const order = Orders.new({ customer: "alice", tags: ["gift"], lines: [] });
// ---cut---
// @errors: 2740
order.tags = ["express"];

order.$set("tags", ["express"]);
console.log(order.tags.length, order.$isModified("tags"));
// → 1 true
```

### Ошибки

Значение, которое не приводится к типу поля, бросает [`CastError`](../errors/data-errors.mdx#casterror) сразу, а не при сохранении:

```text
CastError: Cast to number failed at path "lines.0.qty" for "abc" (string): expected a number [type]
```

Путь, которого нет в схеме, в коде без типов даёт ту же `CastError` с причиной `unknown-key`:

```text
CastError: Cast to Order failed at path "nope" for 1 (number): not a field of Order [unknown-key]
```

Пустой путь — [`QueryError`](../errors/query-errors.mdx#queryerror) `$set: a path`. Поле `_id` у существующего документа неизменяемо, поэтому `$set("_id", …)` бросает [`StrictModeError`](../errors/data-errors.mdx#strictmodeerror):

```text
StrictModeError: $set: "_id" of Order is immutable once the document exists [immutable]
```

### Когда не подходит

Для скалярного поля достаточно присваивания `order.customer = "bob"`: оно короче и так же отслеживается. Чтобы изменить один элемент массива, вызовите [`tags.set(index, value)`](./typed-collections.mdx#strictarrayset), а не `$set("tags.0", …)`, если индекс уже у вас в руках: оба записывают один и тот же оператор.

## $get

`$get` читает значение по пути и применяет функцию `get` поля, если она есть. Он нужен, когда путь известен только во время работы (например, приходит из настроек), и когда вы хотите прочитать значение через геттер поля, а не сырое.

Для существующего пути метод возвращает значение, для отсутствующего значения — `undefined`. Путь, которого нет в схеме, — ошибка, а не молчание: опечатка в имени поля не превратится в «значения нет».

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = Orders.new({
  customer: "alice",
  tags: ["gift"],
  lines: [{ sku: "A1", qty: 2 }],
  address: { city: "Oslo" },
  fees: { delivery: 5 },
});

console.log(order.$get("customer"), order.$get("address.city"), order.$get("lines.0.sku"));
// → "alice" "Oslo" "A1"
console.log(order.$get("fees.delivery"), order.$get("fees.gift"));
// → 5 undefined
```

<Returns type="HydratedField<DocumentValue<T, P>> | undefined">

Значение по пути в его гидратированной форме: для `"tags"` это [`StrictArray`](./typed-collections.mdx#strictarray), для `"address"` — поддокумент, для скаляра — сам скаляр. Если значения по пути нет, возвращается `undefined`.

</Returns>

<Params>
<Param name="path" type="DocumentPaths<T>" required>

Путь к полю в той же записи, что у [`$set`](#set): через точку, с индексами и ключами Map.

</Param>
</Params>

<FullType>

```ts
$get<const P extends DocumentPaths<T>>(path: P): HydratedField<DocumentValue<T, P>> | undefined;
```

</FullType>

### Ошибки

Путь, которого нет в схеме, бросает [`QueryError`](../errors/query-errors.mdx#queryerror) (компилятор остановит вас раньше, если путь записан литералом):

```text
QueryError: $get: "nope" is not a path of Order
```

### Когда не подходит

Если поле известно при написании кода, читайте его свойством: `order.customer`. Свойство не применяет функцию `get`, а `$get` применяет; если у поля есть `get` и вам нужно приведённое значение, используйте `$get` или [`$toObject({ getters: true })`](#toobject).

## $isNew

`$isNew` говорит, вставлен ли документ в базу. Пока документ создан через [`Model.new`](./model-document-methods.mdx#modelnew) и не сохранён, метод возвращает `true`; после первого успешного [`$save`](#save) и у любого документа, прочитанного из базы, — `false`.

От этого зависит, что сделает `$save` (вставку или обновление) и какие проверки применятся: например, у существующего документа нельзя менять `_id` и поля с `immutable`.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = Orders.new({ customer: "alice", tags: [], lines: [] });
console.log(order.$isNew());
// → true

await order.$save();
console.log(order.$isNew());
// → false
```

<Returns type="boolean">

`true`, пока документ не вставлен в базу; `false` после вставки и для прочитанных документов.

</Returns>

Принимает ничего.

<FullType>

```ts
$isNew(): boolean;
```

</FullType>

Документ, удалённый через [`$deleteOne`](#deleteone), новым не становится: он остаётся «удалённым», и его `$save` отклоняется. Подробнее о состояниях — в руководстве [Жизненный цикл документа](../../documents/lifecycle.mdx).

## $isRoot

`$isRoot` отвечает, корневой ли это документ. У документа модели он всегда возвращает `true`, у [поддокумента](./typed-collections.mdx#subdocument) — `false`. Сам по себе ответ очевиден, метод нужен ради типа: это проверка, которая сужает `this` в хуке документа.

Хук документа, объявленный в классе, запускается и на документах модели, и на поддокументах, если класс встроен в другую модель. Поэтому `this` в таком хуке имеет тип `HydratedDoc<T> | Subdocument<T>` ([`HookThis`](../hooks/pre-post.mdx#hookthis)), и методов, которые есть только у корня (`$getChanges`, `$save`, `$populate`), у него нет. После `if (this.$isRoot())` компилятор знает, что это `HydratedDoc<T>`, и они становятся доступны.

```ts twoslash
import { Entity, type HookThis, Pre, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Line extends Entity {

    }
    console.log("поддокумент", this.$fullPath());
  }
}
@Schema({ collection: "orders" })

// ---cut---

// → поддокумент lines.0
```

<Returns type="this is HydratedDoc<T>">

## $isModified

`$isModified` отвечает, менялся ли документ с последней загрузки или последнего сохранения. Он нужен, когда вы хотите сделать что-то только при наличии правок: показать «есть несохранённые изменения», пропустить лишнюю работу, проверить в хуке, тронуто ли конкретное поле.

Без аргумента метод смотрит на весь документ. С путём — только на этот путь и всё, что лежит под ним: `$isModified("lines")` верен, если изменилась любая строка, а `$isModified("lines.0.qty")` — только эта. Вернуть значение поля к прежнему тоже считается: если вы поменяли `customer` на другое значение и вернули исходное, метод даст `false`, потому что Typemo сравнивает значения, а не запоминает факт присваивания.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()

  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({
  customer: "alice",
  tags: ["gift"],
  lines: [{ sku: "A1", qty: 2 }],
});
console.log(order.$isModified());
// → false

order.lines[0]!.qty = 5;
console.log(order.$isModified(), order.$isModified("lines.0.qty"), order.$isModified("customer"));
// → true true false
```

<Returns type="boolean">

`true`, если документ (или указанный путь, или что-то под ним) отличается от состояния при последней загрузке или сохранении. У нового документа, ещё не сохранённого, результат `true`.

</Returns>

## $markModified

`$markModified` заставляет Typemo записать путь при следующем [`$save`](#save), даже если отслеживание изменений его не заметило. Метод нужен редко: обычные присваивания, методы коллекций и `$set` отслеживаются сами. Исключение — значение, которое вы меняете **на месте**, не присваивая заново: например, байты внутри поля `Binary`.

Typemo сравнивает значение с тем, что было при загрузке. Если внутри того же объекта `Binary` поменялся байт, объект остался прежним, и сравнение ничего не находит. Отметка сообщает, что путь надо записать целиком.

В коллекции `files` лежит файл `logo` с тремя байтами данных.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, Types } from "@venloc/typemo";
import type { Binary } from "mongodb";
@Schema({ collection: "files" })
class StoredFile extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Types.Binary) data?: Binary;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Files = client.db().model(StoredFile);
const file = await Files.findOne({ name: "logo" }).orFail();
// ---cut---
file.data!.buffer[0] = 9;
console.log(file.$isModified("data"));
// → false

file.$markModified("data");
console.log(file.$isModified("data"), Object.keys(file.$getChanges()));
// → true ["$set"]
```

<Returns type="this">

Тот же документ. Отметка действует до ближайшего успешного [`$save`](#save).

</Returns>

<Params>
<Param name="path" type="DocumentPaths<T>" required>

Путь, который нужно записать целиком, в записи [`$set`](#set).

</Param>
</Params>

<FullType>

```ts
$markModified(path: DocumentPaths<T>): this;
```

</FullType>

### Ошибки

Путь, которого нет в схеме, — [`QueryError`](../errors/query-errors.mdx#queryerror):

```text
QueryError: $markModified: "nope" is not a path of Order
```

## $getChanges

`$getChanges` показывает обновление, которое отправил бы следующий [`$save`](#save), и ничего при этом не делает: ни в базу, ни в документ. Метод нужен для отладки («почему сохранение медленное?», «что вообще поменялось?»), для тестов и для журналов изменений.

Результат — объект вида «оператор → путь → значение» в **именах полей класса**, а не в именах базы. Для пустого набора изменений возвращается `{}`. Копию результата можно хранить: она заморожена. Метод никогда не бросает ошибку: если `$save` отказал бы, причина лежит в ключе `$problems` (см. [ниже](#проблемные-пути-problems)), а остальное обновление возвращается как обычно.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({
  customer: "alice",
  tags: ["gift"],
  lines: [{ sku: "A1", qty: 2 }],
  address: { city: "Oslo" },
  fees: { delivery: 5 },
});
console.log(order.$getChanges());
// → {}

order.customer = "bob";
order.tags.push("express");
order.lines[0]!.qty = 5;
order.fees?.set("gift", 3);
console.log(order.$getChanges());
// → { $set: { customer: "bob", "lines.0.qty": 5, "fees.gift": 3 }, $push: { tags: { $each: ["express"] } } }
```

<Returns type="DocumentChanges">

Замороженный объект операторов (`$set`, `$push`, `$unset`, `$pull`, …) с путями и значениями. Пустой объект `{}` значит, что `$save` ничего не отправит. У нового документа в `$set` лежат все поля. Если сохранение было бы отклонено, в объекте есть ключ `$problems`: он не оператор, а список «путь → текст ошибки».

</Returns>

Принимает ничего.

<FullType>

```ts
$getChanges(): DocumentChanges;

type DocumentChanges = Readonly<Record<string, Readonly<Record<string, unknown>>>>;
```

</FullType>

### Значения не приводятся заранее

Значения в результате — то, что лежит в документе сейчас. Если вы записали в поле неверный тип в обход компилятора (`(order as any).customer = 5`), `$getChanges` покажет `5` как есть, а приведение и `CastError` случатся при [`$save`](#save) или [`$validate`](#validate).

### Проблемные пути: $problems

`$getChanges` не бросает ошибку и тогда, когда [`$save`](#save) отказал бы. Вместо этого в результате появляется ключ `$problems`: объект «путь → текст ошибки, которую бросит `$save`», а остальная часть обновления возвращается как обычно. Предпросмотр остаётся безопасным для отладки и журналов, а причину будущего отказа видно заранее. Ключ попадает в результат в трёх случаях: контейнер (массив, Map, поддокумент) заменён присваиванием или записан по индексу мимо своих методов ([`DirectWriteError`](../errors/data-errors.mdx#directwriteerror)); сохранение переписало бы сохранённый поддокумент вместе с неизвестными схеме полями ([`UnknownFieldsError`](../errors/data-errors.mdx#unknownfieldserror)); вручную изменён ключ версии `__v` ([`QueryError`](../errors/query-errors.mdx#queryerror)).

```ts twoslash
// @errors: 2740
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: ["gift"], lines: [] });

order.customer = "bob";
order.tags = ["express"];
console.log(order.$getChanges());
// → { $set: { customer: "bob" }, $problems: { tags: "\"tags\" was changed around its methods: the field was replaced by assignment; use $set(\"tags\", value) or the container's methods" } }
```

Правка `customer` попала в `$set`, а замена массива присваиванием записана в `$problems`. `$save` на этом документе бросил бы [`DirectWriteError`](../errors/data-errors.mdx#directwriteerror) с тем же текстом:

```text
DirectWriteError: "tags" was changed around its methods: the field was replaced by assignment; use $set("tags", value) or the container's methods
```

Запись по индексу называет позицию: `"lines" was changed around its methods: position 0 was assigned directly (use set(0, value))`. У изменённого вручную `__v` текст другой: `Order.__v is the version key: the core maintains it; it cannot be changed by hand`. Чтобы сохранение прошло, исправьте указанный путь: вызовите метод коллекции или [`$set`](#set).

## $validate

`$validate` проверяет весь документ по схеме и не пишет в базу. Он нужен, когда вы хотите узнать об ошибках до сохранения: показать пользователю список проблем формы, проверить документ в хуке, убедиться в тесте.

Метод не останавливается на первой ошибке: все найденные проблемы собираются в одну [`ValidationError`](../errors/data-errors.mdx#validationerror), у которой есть список `issues` с путём, причиной и сообщением каждой. Проблемы идут в порядке полей схемы, как они объявлены в классе, а не в порядке правок. Асинхронные валидаторы полей (`validate` в `@Prop`) ждут завершения. Тот же вызов делает [`$save`](#save) перед записью.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, ValidationError, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = Orders.new({ customer: "alice", tags: [], lines: [] });
order.lines.push({ sku: "B2", qty: -1 });

try {
  await order.$validate();
} catch (error) {
  if (error instanceof ValidationError) {
    console.log(error.issues.map((issue) => [issue.path.join("."), issue.reason]));
    // → [["lines.0.qty", "min"]]
  }
}
```

<Returns type="Promise<void>">

Ничего: успешное завершение значит, что документ корректен. Документ метод не меняет.

</Returns>

Принимает ничего.

<FullType>

```ts
$validate(): Promise<void>;
```

</FullType>

### Ошибки

При любой проблеме — `ValidationError` со всеми найденными пунктами:

```text
ValidationError: Validation failed: "lines.0.qty": must be at least 0 [min]
```

Полный список причин (`required`, `min`, `max`, `enum`, `validator` и других) и устройство `issues` — в справочнике [`ValidationError`](../errors/data-errors.mdx#validationerror). Значения, присвоенные обычным присваиванием (`order.customer = 5`), приводятся на этом же вызове. Если значение не приводится, бросается не `ValidationError`, а [`CastError`](../errors/data-errors.mdx#casterror), причём до всякой валидации: ограничения этого поля не проверяются, пока значение не стало значением нужного типа.

```text
CastError: Cast to string failed at path "customer" for 5 (number): expected a string [type]
```

Различие объяснено в руководстве [Валидация документа](../../documents/validation.mdx).

### Когда не подходит

Чтобы проверить обычный объект, из которого документа ещё нет, используйте [`Model.validate`](./model-document-methods.mdx#modelvalidate): он принимает данные и возвращает приведённое значение с заполненными значениями по умолчанию.

## $deleteOne

`$deleteOne` удаляет документ из базы по `_id`. Он нужен, когда документ уже у вас в руках и его надо убрать: удалить заказ, который пользователь только что открыл.

Метод идёт тем же путём, что и [`deleteOne`](../writes/writes.mdx#deleteone) модели: запускаются хуки `document.deleteOne`, применяются политики модели (мягкое удаление, тенант), пишется аудит. После успешного удаления документ помечается удалённым: его [`$save`](#save) и повторный `$deleteOne` отказываются работать.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: [], lines: [] });
const result = await order.$deleteOne();
console.log(result.deletedCount);
// → 1
```

<Returns type="Promise<DeleteResult>">

Результат удаления: `deletedCount` равен 1, если запись удалена, и 0, если её уже не было или документ ещё не вставлялся.

</Returns>

<Params>
<Param name="options" type="SaveOptions">

Сессия, тайм-аут и контекст политик записи, как у [`$save`](#save). Опция `dropUnknownFields` для удаления не имеет значения.

### Ошибки

Повторный вызов на том же объекте — [`QueryError`](../errors/query-errors.mdx#queryerror):


### Когда не подходит

## $updateOne

`$updateOne` обновляет **этот** документ по `_id` документом-обновлением с операторами (`$set`, `$inc`, …), не сохраняя правки, сделанные в памяти. Он нужен, когда надо применить атомарное изменение на стороне базы, например увеличить счётчик, а не прочитать значение, сложить и записать.

Обновление проходит весь конвейер модели: приведение типов, валидаторы, политики, аудит и хуки `document.updateOne` (`this` в хуке — документ; хуки запросов не срабатывают). Документ в памяти при этом **не меняется**: чтобы увидеть результат, прочитайте его заново.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: [], lines: [] });
const result = await order.$updateOne({ $set: { customer: "dave" } });
console.log(result.modifiedCount, order.customer);
// → 1 "alice"

const stored = await Orders.findById(order._id).orFail().plain();
console.log(stored.customer);
// → "dave"
```

Результат обновления: `matchedCount` и `modifiedCount` показывают, нашёлся ли документ и изменился ли он.

</Returns>

<Params>
<Param name="update" type="Update<T, true>" required>

Документ-обновление с операторами. Проверяется компилятором (поля модели, типы значений) и во время работы. Операторы описаны в справочнике [Операторы обновления](../writes/update-operators.mdx).

</Param>
<Param name="options" type="SaveOptions">

Сессия, тайм-аут и политика записи, как у [`$save`](#save).

</Param>
</Params>

<FullType>

```ts

  options?: SaveOptions,

```

</FullType>

### Ошибки

Поле, которого нет в модели, — [`StrictModeError`](../errors/data-errors.mdx#strictmodeerror):

```text

```

Пустое обновление — [`QueryError`](../errors/query-errors.mdx#queryerror) `update: an empty update changes nothing`. Документ, который ещё не сохранён, обновить нельзя:

```text
QueryError: updateOne: the Order document is new; $save() it first
```

### Когда не подходит

Если вы хотите сохранить правки, сделанные в памяти, используйте [`$save`](#save). Если документ не загружен, вызовите [`updateOne`](../writes/writes.mdx#updateone) модели.

## $populate

`$populate` подгружает связанные документы по ссылке и подставляет их вместо идентификаторов. Метод нужен, когда документ уже загружен, а ссылка понадобилась позже. Возвращает **тот же документ**, но с типом, в котором поле уже развёрнуто, поэтому пользоваться нужно возвращённым значением.

Путь и параметры проверяются так же, как у [`.populate`](../populate/populate.mdx#populate) запроса. Принимается и список путей и объектов (`$populate(["author", { path: "tags", select: { label: 1 } }])`): все они загружаются за один вызов, а тип результата показывает каждое загруженное поле. Загруженный путь можно загрузить снова: вызов читает связь заново и заменяет прежнее значение, вместе с его `select` и вложенными путями. Путь ниже уже загруженного поля (`author.posts` после `author`) компилятор не пропускает: вложенную связь передайте опцией `populate` или верните идентификаторы через [`$depopulate`](#depopulate). Подробный разбор с типами и ошибками — в руководстве [Populate у документа](../../populate/document-populate.mdx).

В следующих примерах связанных данных в базе есть покупатель `Ann` и отправление с заголовком `T`, которое ссылается на него в поле `customer`.

```ts twoslash
import { Entity, type Ref, Prop, Schema, TypemoClient, Types } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Schema({ collection: "shipments" })
class Shipment extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Types.ObjectId, { ref: () => Customer }) customer!: Ref<Customer>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Shipments = client.db().model(Shipment);
const shipment = await Shipments.findOne({ title: "T" }).orFail();
// ---cut---
const withCustomer = await shipment.$populate("customer");
console.log(withCustomer.customer?.name);
// → "Ann"
console.log(Object.is(withCustomer, shipment));
// → true
```

<Returns type="Promise<HydratedDocWith<T, { … }>>">

Тот же документ, у которого поле по пути имеет развёрнутый тип (в примере `customer` — документ `Customer` или `null`, если покупателя нет, а не идентификатор).

</Returns>

</Param>
</Params>

## $depopulate

`$depopulate` возвращает на место идентификаторы вместо развёрнутых документов — у всех развёрнутых полей или только у одного. Метод нужен перед сохранением документа с развёрнутой ссылкой и когда надо развернуть то же поле заново с другими параметрами.

Метод меняет документ на месте и возвращает его же с типом, в котором поле снова ссылка; пользоваться нужно возвращённым значением.

```ts twoslash
import { Entity, type Ref, Prop, Schema, TypemoClient, Types } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Schema({ collection: "shipments" })
class Shipment extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Types.ObjectId, { ref: () => Customer }) customer!: Ref<Customer>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Shipments = client.db().model(Shipment);
const shipment = await Shipments.findOne({ title: "T" }).orFail();
const populated = await shipment.$populate("customer");
// ---cut---
const plain = populated.$depopulate("customer");
console.log(Object.is(plain, shipment), populated.$populated("customer"));
// → true undefined
```

</Returns>

<Params>

</Param>

## $populated

`$populated` возвращает идентификаторы, которые стояли на месте развёрнутого поля: копию исходных значений. Метод нужен, чтобы узнать, развёрнуто ли поле, и получить идентификаторы после разворота. Если вам нужно то же самое вместе с сужением типа, есть функция [`isPopulated`](../populate/populate-types.mdx#ispopulated).

Для поля документа возвращается одно значение (для массива ссылок — список), для пути внутри поддокументов — по одному значению на поддокумент. Если путь не развёрнут, метод возвращает `undefined`.

```ts twoslash
import { Entity, type Ref, Prop, Schema, TypemoClient, Types } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Schema({ collection: "shipments" })
class Shipment extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Types.ObjectId, { ref: () => Customer }) customer!: Ref<Customer>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Shipments = client.db().model(Shipment);
const shipment = await Shipments.findOne({ title: "T" }).orFail();
// ---cut---
console.log(shipment.$populated("customer"));
// → undefined

await shipment.$populate("customer");
console.log(shipment.$populated("customer")?.constructor.name);
// → "ObjectId"
```

<Returns type="unknown">

Копия идентификаторов, стоявших на месте развёрнутых значений, или `undefined`, если путь не развёрнут.

</Returns>

</Param>
</Params>

```ts

```

</FullType>

## $assertPopulated

`$assertPopulated` утверждает, что путь развёрнут, и возвращает тот же документ с типом, где поле имеет развёрнутый вид. Метод нужен, когда развёртывание произошло там, где компилятор его не видит (в хуке или в другой функции), а вам дальше нужен развёрнутый тип.

Ничего не загружается: метод только проверяет, что в поле лежат развёрнутые значения. Ссылка, которая при развороте ничего не нашла и стала `null`, считается развёрнутой. Метод принимает тот же список путей и объектов, что и [`$populate`](#populate): `$assertPopulated(["customer", { path: "items", select: { sku: 1 } }])` проверяет каждый элемент списка, а у объекта с вложенным `populate` — и вложенный путь.

```ts twoslash
import { Entity, type Ref, Prop, Schema, TypemoClient, Types } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Schema({ collection: "shipments" })
class Shipment extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Types.ObjectId, { ref: () => Customer }) customer!: Ref<Customer>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Shipments = client.db().model(Shipment);
const shipment = await Shipments.findOne({ title: "T" }).orFail();
await shipment.$populate("customer");
// ---cut---
const ready = shipment.$assertPopulated("customer");
//    ^?
console.log(ready.customer?.name);
// → "Ann"
const both = shipment.$assertPopulated(["customer"]);
console.log(both.customer?.name);
// → "Ann"
```

<Returns type="HydratedDocWith<T, { … }>">

Тот же документ с типом, в котором поля по путям развёрнуты.

</Returns>

Путь строкой, объект с теми параметрами, которые использовал разворот (они определяют форму развёрнутого типа), или список из них.

</Param>
</Params>

<FullType>

## $is

`$is` — проверка типа для иерархии дискриминаторов: сужает документ до класса-наследника. Метод нужен, когда в одной коллекции лежат документы разных видов, а вам надо обратиться к полям конкретного.

`true` возвращается, если документ прочитан как этот класс или как один из его наследников. Для класса вне иерархии метод бросает ошибку, а не возвращает `false`: это почти всегда опечатка. Суженный документ типизирован как чтение класса по умолчанию (скрытые поля не видны): проекция и populate базового документа на суженный тип не переносятся.

</Returns>

</Param>
</Params>

<FullType>

```ts

```

</FullType>

### Ошибки

## $session

`$session` читает или задаёт сессию документа: ту, в которой документ загружен и которую по умолчанию использует [`$save`](#save). Метод нужен, когда документ живёт дольше одной операции и надо явно перенести его в другую сессию или снять с сессии.

Без аргумента метод возвращает сессию драйвера или `undefined`. С аргументом задаёт сессию, а `null` снимает её; в этом случае метод возвращает сам документ. Документ, загруженный внутри [`client.transaction`](../connection/typemo-client.mdx#clienttransaction), получает сессию этой транзакции.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: [], lines: [] });
console.log(order.$session());
// → undefined

await client.transaction(async () => {
  const inside = await Orders.findById(order._id).orFail();
  console.log(inside.$session() === undefined);
  // → false
});
```

<Returns type="ClientSession | undefined | this">

Без аргумента — сессия или `undefined`. С аргументом — этот же документ.

</Returns>

<Param name="session" type="ClientSession | null">

Новая сессия документа; `null` снимает текущую.

</Param>
</Params>


</FullType>

## $locals

`$locals` возвращает объект для данных приложения, привязанных к документу: он не сохраняется и не попадает ни в одну форму документа. Метод нужен, чтобы передать значение между хуками одного документа или пометить документ на время обработки.

Каждый вызов возвращает **один и тот же объект**, поэтому в нём можно накапливать значения.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })

  @Prop(() => String, { required: true }) city!: string;

}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const order = Orders.new({ customer: "alice", tags: [], lines: [] });
// ---cut---
order.$locals().importedFrom = "csv";
console.log(order.$locals() === order.$locals(), order.$locals());
// → true { importedFrom: "csv" }
```

<Returns type="Record<string, unknown>">

## $toObject

`$toObject` отдаёт данные документа как обычные объекты и массивы: без отслеживания изменений и без методов. Метод нужен, когда данные надо передать дальше, не привязывая их к документу: положить в кеш, сравнить, изменить копию.

Значения MongoDB остаются собой: `_id` — `ObjectId`, int64 — `bigint`, `Decimal128` — `Decimal128`, а Map — обычной `Map`. Поэтому результат нельзя отдать в `JSON.stringify` (там `bigint` бросит ошибку) — для клиента есть [`$toPlain`](#toplain) и [`$toJSON`](#tojson). Скрытые поля попадают в `$toObject` по умолчанию, если они были загружены.

```ts twoslash

@Schema({ nested: true })

  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;

@Schema()

  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;

  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
await Orders.create({
  customer: "alice",
  tags: ["gift"],
  lines: [{ sku: "A1", qty: 2 }],
  fees: { delivery: 5 },
  note: "call first",
});
const order = await Orders.findOne({ customer: "alice" }).select({ "+note": true }).orFail();
// ---cut---
const data = order.$toObject();
//    ^?
console.log(data.fees instanceof Map, data.note, data._id.constructor.name);
// → true "call first" "ObjectId"
```

## $toPlain

`$toPlain` отдаёт **plain-форму**: значения MongoDB, которые не переживают JSON, превращены в строки, а родные типы JavaScript остаются. Идентификаторы, int64, `Decimal128` и UUID — строки, `Date`, `RegExp` и `Map` сохраняются, байты становятся `Uint8Array`, вектор — `number[]`. Форма подходит для ответов API и кеша: `JSON.stringify` от неё не встречает `bigint`.

Скрытые поля по умолчанию **не попадают** в результат; чтобы их включить, передайте `{ hidden: true }`. Результат не связан с документом: изменение копии документ не затрагивает.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
await Orders.create({
  customer: "alice",
  tags: ["gift"],
  lines: [{ sku: "A1", qty: 2 }],
  fees: { delivery: 5 },
  note: "call first",
});
const order = await Orders.findOne({ customer: "alice" }).select({ "+note": true }).orFail();
// ---cut---
const plain = order.$toPlain();
//    ^?
console.log(typeof plain._id, "note" in plain, plain.fees instanceof Map);
// → "string" false true

console.log(order.$toPlain({ hidden: true }).note);
// → "call first"
```

## $toJSON

`$toJSON` отдаёт **JSON-форму**: всё, чего нет в JSON, превращено в строки. Отличие от [`$toPlain`](#toplain) — в тех типах, у которых JSON и JavaScript расходятся: `Date` становится ISO-строкой, `RegExp` — строкой `"/src/flags"`, `Map` — обычным объектом, байты — строкой base64.

Именно этот метод вызывает `JSON.stringify(document)`, поэтому документ можно отдавать в `res.json(doc)`-подобные функции напрямую; скрытые поля при этом не попадают в результат.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const order = Orders.new({ customer: "alice", tags: [], lines: [], fees: { delivery: 5 }, note: "call first" });
// ---cut---
const json = order.$toJSON();
//    ^?
console.log(json.fees, "note" in json);
// → { delivery: 5 } false
console.log(JSON.parse(JSON.stringify(order)).fees);
// → { delivery: 5 }
```

</Returns>
