Здесь собраны все `$`-методы документа, который вы получаете из `await Model.find()`, `create` и `Model.new`. Это экземпляр вашего класса, где массивы, поддокументы и Map заменены на [типизированные коллекции](./typed-collections.mdx), а рядом с полями лежат методы с префиксом `$`. Префикс защищает имена. Поле `save` у вашей модели может быть, а метод `$save` его не займёт.

Если вы только начинаете, сначала прочитайте руководства [Изменить и сохранить](../../documents/change-and-save.mdx) и [Жизненный цикл документа](../../documents/lifecycle.mdx). Эта страница — справочник, к ней возвращаются за деталью.

Все примеры строятся на одном заказе. В нём есть обязательное поле, массив строк, массив поддокументов, вложенный объект, Map и скрытое поле.

```ts twoslash title="models/order.ts"
import { Entity, type Hidden, Prop, Schema, Spec, Versioned } from "@venloc/typemo";

@Schema({ nested: true })
export class Address {
  @Prop(() => String, { required: true })
  city!: string;

  @Prop(() => String)
  street?: string;
}

@Schema()
export class Line extends Entity {
  @Prop(() => String, { required: true })
  sku!: string;

  @Prop(() => Number, { required: true, min: 0 })
  qty!: number;
}

@Schema({ collection: "orders" })
export class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => [String])
  tags!: string[];

  @Prop(() => [Line])
  lines!: Line[];

  @Prop(() => Address)
  address?: Address;

  @Prop(() => Spec.map(Number))
  fees?: Map<string, number>;

  @Prop(() => String, { hidden: true })
  note?: Hidden<string>;
}
```

Заказ Alice, на котором получены результаты, такой. Покупатель `alice`, тег `gift`, одна строка `A1` в количестве 2, город `Oslo`, сбор `delivery` на 5. Идентификаторы в результатах сокращены до `"…"`, потому что база выдаёт их заново при каждом запуске.

Методов коллекций внутри документа (`tags.push`, `lines.create`, `fees.set`) и методов поддокумента здесь нет. Их описывают [Типизированные коллекции](./typed-collections.mdx).

## $save [#save]

`$save` записывает документ в базу. Новый он вставляет, загруженный обновляет. Это основной способ сохранить правки, когда вы работаете с документом как с объектом — прочитали, поменяли поля, вызвали `$save`.

Документ целиком метод не пересылает. Typemo следит за изменениями с момента загрузки или прошлого сохранения ([`$getChanges`](#get-changes) показывает, за какими именно) и собирает из них самое короткое обновление. Это `$set` для изменённых полей, `$push` для новых элементов массива, `$unset` для удалённых ключей Map. Если менять нечего, в базу ничего не уходит, а `$save` всё равно завершается успешно.

Перед записью документ проходит [`$validate`](#validate) и запускаются хуки `document.save`. У документа с полем `__v` (класс `Versioned`) обновление ещё и проверяет версию. Подробности — в руководстве [Версии и параллельные изменения](../../documents/versions.mdx).

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = Orders.new({ customer: "alice", tags: ["gift"], lines: [{ sku: "A1", qty: 2 }] });
await order.$save();
console.log(order.$isNew());
// → false

order.customer = "bob";
order.tags.push("express");
await order.$save();
console.log(order.$isModified(), order.__v);
// → false 1
```

<Returns type="Promise<this>">

Тот же документ, а не копия. После `await` он уже не новый ([`$isNew`](#is-new) возвращает `false`), и отслеживание изменений начинается заново. Если `Versioned` поднял версию, свежее значение лежит в `order.__v`.

</Returns>

<Params>
<Param name="options" type="SaveOptions">

Необязательные настройки записи. Разобраны ниже в разделе [SaveOptions](#save-options) — сессия, тайм-аут, разрешение потерять неизвестные поля и контекст политик.

</Param>
</Params>

<FullType>

```ts
$save(options?: SaveOptions): Promise<this>;
```

</FullType>

### Что уйдёт в базу [#what-is-sent]

Форма обновления зависит от того, что вы делали с коллекциями. `push` даёт `$push`, `pull` — `$pullAll`, правка поля внутри строки — `$set` по пути с индексом. Полная таблица «метод — оператор» лежит в справочнике [Типизированные коллекции](./typed-collections.mdx). Итог можно проверить до записи через [`$getChanges`](#get-changes).

### Сохранение внутри транзакции [#save-in-transaction]

Внутри [`client.transaction`](../connection/typemo-client.mdx#client.transaction) `$save` присоединяется к транзакции сам, сессию передавать не нужно. Откатится транзакция — откатятся и изменения документа в базе. Правки в самом документе в памяти останутся, поэтому при повторе колбэк должен снова прочитать документ, а не взять загруженный раньше. Подробнее — в руководстве [Транзакции](../../transactions/transactions.mdx).

### Ошибки [#save.errors]

Значения, присвоенные обычным присваиванием (`order.customer = 5`), `$save` сначала приводит к типу поля. Не приводится значение — бросается [`CastError`](../errors/data-errors.mdx#cast-error). Ограничения поля при этом не проверяются, и в базу ничего не уходит.

```text
CastError: Cast to string failed at path "customer" for 5 (number): expected a string [type]
```

После приведения `$save` бросает [`ValidationError`](../errors/data-errors.mdx#validation-error), если документ не прошёл проверки. Тексты и пути описаны в разделе [`$validate`](#validate).

```text
ValidationError: Validation failed: "lines.1.qty": must be at least 0 [min]
```

[`UnknownFieldsError`](../errors/data-errors.mdx#unknown-fields-error) приходит, когда сохранение переписало бы поддокумент вместе с полями, которых нет в схеме. Это разбирает руководство [Неизвестные поля](../../documents/unknown-fields.mdx). [`DirectWriteError`](../errors/data-errors.mdx#direct-write-error) и [`PartialArrayError`](../errors/data-errors.mdx#partial-array-error) сообщают о записи мимо методов коллекции и о правке частично загруженного массива. [`VersionError`](../errors/query-errors.mdx#version-error) значит, что документ изменили после вашего чтения.

Документ, уже удалённый через [`$deleteOne`](#delete-one), `$save` писать отказывается.

```text
QueryError: save: the document of Order was deleted
```

Если документ удалил кто-то другой, `$save` доходит до базы, не находит запись и бросает [`DocumentNotFoundError`](../errors/query-errors.mdx#document-not-found-error).

```text
DocumentNotFoundError: Order.save: the document is no longer in the collection (deleted since it was read, or out of the scope of the operation's policies); nothing was written
```

Причин в скобках две, потому что запись могла остаться в коллекции, но выйти из области политик модели (другой тенант, мягкое удаление). Для `$save` такой документ тоже «не найден».

### Когда не подходит [#save.when-not-to-use]

Много документов одним запросом или документ без загрузки меняют [`updateOne`](../writes/writes.mdx#update-one) и [`updateMany`](../writes/writes.mdx#update-many). Много загруженных документов одной упорядоченной записью сохраняет [`Model.bulkSave`](../writes/writes.mdx#bulk-save). А чтобы изменить именно этот документ по `_id` через общий конвейер операций и не трогать копию в памяти, есть [`$updateOne`](#update-one).

## $set [#set]

`$set` присваивает значение по пути и сразу приводит его к типу поля. Для скалярных полей хватит и обычного присваивания `order.customer = "bob"`. `$set` нужен там, где присваивание недоступно или ненадёжно — когда меняете целый контейнер (массив, Map, поддокумент), который тип не даёт записать напрямую, и когда хотите дойти до вложенного поля одной строкой.

Путь пишется через точку. `"address.city"` ведёт во вложенный объект, `"tags.0"` — к элементу массива по индексу, `"fees.delivery"` — к значению Map по ключу. Позиционных знаков MongoDB (`$`, `$[]`) нет, документ сам знает свои элементы. Компилятор подскажет допустимые пути и проверит тип значения.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = Orders.new({
  customer: "alice",
  tags: ["gift"],
  lines: [{ sku: "A1", qty: 2 }],
  address: { city: "Oslo" },
  fees: { delivery: 5 },
});

order.$set("address.city", "Paris").$set("tags.0", "express").$set("fees.delivery", 9);
console.log(order.address?.city, [...order.tags], order.fees?.get("delivery"));
// → "Paris" ["express"] 9
```

<Returns type="this">

Тот же документ, поэтому вызовы `$set` можно записывать цепочкой, как выше. Приведённое значение лежит в документе сразу, а в базу изменение попадёт при следующем [`$save`](#save).

</Returns>

<Params>
<Param name="path" type="DocumentPaths<T>" required>

Путь к полю. Это имя поля, путь через точку во вложенные объекты и поддокументы, индекс элемента массива (`tags.0`, `lines.0.qty`) или ключ Map (`fees.delivery`). Пустая строка и путь к служебному полю не принимаются.

</Param>
<Param name="value" type="FieldInput<DocumentValue<T, P>>" required>

Новое значение. Принимается всё, что для этого поля принимает [`create`](../writes/writes.mdx#create). Массив берёт обычный массив, поддокумент — обычный объект, поле `ObjectId` — его строковую запись. `undefined` и `null` для необязательного поля без `nullable` не принимаются.

</Param>
</Params>

<FullType>

```ts
$set<const P extends DocumentPaths<T>>(path: P, value: FieldInput<DocumentValue<T, P>>): this;
```

</FullType>

### Замена контейнера [#replace-container]

Массив, Map и поддокумент присваиванием не заменить. `order.tags = ["x"]` не пройдёт компиляцию, а присваивание в обход типов `$save` отклонит с [`DirectWriteError`](../errors/data-errors.mdx#direct-write-error). `$set` — разрешённый путь. Он приводит значение и делает новый контейнер отслеживаемым.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const order = Orders.new({ customer: "alice", tags: ["gift"], lines: [] });
// ---cut---
// @errors: 2740
order.tags = ["express"];

order.$set("tags", ["express"]);
console.log(order.tags.length, order.$isModified("tags"));
// → 1 true
```

### Ошибки [#set.errors]

Значение, которое не приводится к типу поля, бросает [`CastError`](../errors/data-errors.mdx#cast-error) сразу, а не при сохранении.

```text
CastError: Cast to number failed at path "lines.0.qty" for "abc" (string): expected a number [type]
```

Путь, которого нет в схеме, в коде без типов даёт ту же `CastError` с причиной `unknown-key`.

```text
CastError: Cast to Order failed at path "nope" for 1 (number): not a field of Order [unknown-key]
```

Пустой путь бросает [`QueryError`](../errors/query-errors.mdx#query-error) `$set: a path`. Поле `_id` у существующего документа неизменяемо, поэтому `$set("_id", …)` бросает [`StrictModeError`](../errors/data-errors.mdx#strict-mode-error).

```text
StrictModeError: $set: "_id" of Order is immutable once the document exists [immutable]
```

### Когда не подходит [#set.when-not-to-use]

Для скалярного поля хватит присваивания `order.customer = "bob"` — оно короче и отслеживается так же. Если индекс элемента массива уже у вас в руках, зовите [`tags.set(index, value)`](./typed-collections.mdx#strict-array.set), а не `$set("tags.0", …)`. Оба записывают один и тот же оператор.

## $get [#get]

`$get` читает значение по пути и применяет функцию `get` поля, если она есть. Он выручает, когда путь известен только во время работы (например, пришёл из настроек) и когда нужно значение через геттер поля, а не сырое.

Для существующего пути метод возвращает значение, для пути без значения — `undefined`. Пути, которого нет в схеме, метод не прощает. Опечатка в имени поля не превратится в «значения нет».

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = Orders.new({
  customer: "alice",
  tags: ["gift"],
  lines: [{ sku: "A1", qty: 2 }],
  address: { city: "Oslo" },
  fees: { delivery: 5 },
});

console.log(order.$get("customer"), order.$get("address.city"), order.$get("lines.0.sku"));
// → "alice" "Oslo" "A1"
console.log(order.$get("fees.delivery"), order.$get("fees.gift"));
// → 5 undefined
```

<Returns type="HydratedField<DocumentValue<T, P>> | undefined">

Значение по пути в том виде, как его хранит документ. Для `"tags"` это [`StrictArray`](./typed-collections.mdx#strict-array), для `"address"` — поддокумент, для скаляра — сам скаляр. Если значения нет, возвращается `undefined`.

</Returns>

<Params>
<Param name="path" type="DocumentPaths<T>" required>

Путь к полю в той же записи, что у [`$set`](#set) — через точку, с индексами и ключами Map.

</Param>
</Params>

<FullType>

```ts
$get<const P extends DocumentPaths<T>>(path: P): HydratedField<DocumentValue<T, P>> | undefined;
```

</FullType>

### Ошибки [#get.errors]

Путь, которого нет в схеме, бросает [`QueryError`](../errors/query-errors.mdx#query-error). Если путь записан литералом, компилятор остановит вас раньше.

```text
QueryError: $get: "nope" is not a path of Order
```

### Когда не подходит [#get.when-not-to-use]

Поле, известное при написании кода, читайте свойством — `order.customer`. Свойство функцию `get` не применяет, а `$get` применяет. Если у поля есть `get` и вам нужно приведённое значение, берите `$get` или [`$toObject({ getters: true })`](#to-object).

## $isNew [#is-new]

`$isNew` говорит, вставлен ли документ в базу. Пока документ создан через [`Model.new`](./model-document-methods.mdx#model.new) и не сохранён, метод возвращает `true`. После первого успешного [`$save`](#save) и у любого документа, прочитанного из базы, он возвращает `false`.

От ответа зависит, что сделает `$save` (вставку или обновление) и какие проверки сработают. Например, у существующего документа нельзя менять `_id` и поля с `immutable`.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = Orders.new({ customer: "alice", tags: [], lines: [] });
console.log(order.$isNew());
// → true

await order.$save();
console.log(order.$isNew());
// → false
```

<Returns type="boolean">

`true`, пока документ не вставлен в базу. После вставки и для прочитанных документов — `false`.

</Returns>

Принимает ничего.

<FullType>

```ts
$isNew(): boolean;
```

</FullType>

Удалённый через [`$deleteOne`](#delete-one) документ новым не становится. Он остаётся «удалённым», и его `$save` отклоняется. О состояниях подробнее — в руководстве [Жизненный цикл документа](../../documents/lifecycle.mdx).

## $isRoot [#is-root]

`$isRoot` отвечает, корневой ли это документ. У документа модели он всегда возвращает `true`, у [поддокумента](./typed-collections.mdx#subdocument) — `false`. Сам ответ очевиден, метод нужен ради типа. Это проверка, которая сужает `this` в хуке документа.

Хук документа, объявленный в классе, запускается и на документах модели, и на поддокументах, если класс встроен в другую модель. Поэтому `this` в таком хуке имеет тип `HydratedDoc<T> | Subdocument<T>` ([`HookThis`](../hooks/pre-post.mdx#hook-this)), и методов корня (`$getChanges`, `$save`, `$populate`) у него нет. После `if (this.$isRoot())` компилятор знает, что это `HydratedDoc<T>`, и методы становятся доступны.

```ts twoslash
import { Entity, type HookThis, Pre, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;

  @Pre("document.save")
  report(this: HookThis<"document.save", Line>): void {
    if (this.$isRoot()) {
      console.log("корень", JSON.stringify(this.$getChanges()));
      return;
    }
    console.log("поддокумент", this.$fullPath());
  }
}
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => [Line]) lines!: Line[];
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
await Orders.create({ lines: [{ sku: "A1", qty: 1 }] });
// → поддокумент lines.0
```

<Returns type="this is HydratedDoc<T>">

`true` у корневого документа, `false` у поддокумента.

</Returns>

Принимает ничего.

<FullType>

```ts
$isRoot(): this is DocumentOf<B, P>;
```

</FullType>

## $isModified [#is-modified]

`$isModified` отвечает, менялся ли документ с последней загрузки или последнего сохранения. Он пригодится, когда что-то нужно делать только при наличии правок — показать «есть несохранённые изменения», пропустить лишнюю работу, проверить в хуке, тронуто ли конкретное поле.

Без аргумента метод смотрит на весь документ. С путём он смотрит только на этот путь и всё под ним. `$isModified("lines")` вернёт `true`, если изменилась любая строка, а `$isModified("lines.0.qty")` — только эта. Возврат к прежнему значению тоже учитывается. Поменяли `customer` и вернули исходное — метод даст `false`, потому что Typemo сравнивает значения, а не помнит сам факт присваивания.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({
  customer: "alice",
  tags: ["gift"],
  lines: [{ sku: "A1", qty: 2 }],
});
console.log(order.$isModified());
// → false

order.lines[0]!.qty = 5;
console.log(order.$isModified(), order.$isModified("lines.0.qty"), order.$isModified("customer"));
// → true true false
```

<Returns type="boolean">

`true`, если документ (или указанный путь, или что-то под ним) отличается от состояния при последней загрузке или сохранении. У нового, ещё не сохранённого документа результат `true`.

</Returns>

## $markModified [#mark-modified]

`$markModified` заставляет Typemo записать путь при следующем [`$save`](#save), даже если отслеживание изменений его не заметило. Метод нужен редко, ведь присваивания, методы коллекций и `$set` отслеживаются сами. Исключение — значение, которое вы меняете **на месте**, не присваивая заново. Например, байты внутри поля `Binary`.

Typemo сравнивает значение с тем, что было при загрузке. Если в том же объекте `Binary` поменялся байт, объект остался прежним, и сравнение ничего не находит. Отметка сообщает, что путь надо записать целиком.

В коллекции `files` лежит файл `logo` с тремя байтами данных.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, Types } from "@venloc/typemo";
import type { Binary } from "mongodb";
@Schema({ collection: "files" })
class StoredFile extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Types.Binary) data?: Binary;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Files = client.db().model(StoredFile);
const file = await Files.findOne({ name: "logo" }).orFail();
// ---cut---
file.data!.buffer[0] = 9;
console.log(file.$isModified("data"));
// → false

file.$markModified("data");
console.log(file.$isModified("data"), Object.keys(file.$getChanges()));
// → true ["$set"]
```

<Returns type="this">

Тот же документ. Отметка действует до ближайшего успешного [`$save`](#save).

</Returns>

<Params>
<Param name="path" type="DocumentPaths<T>" required>

Путь, который нужно записать целиком. Записывается так же, как в [`$set`](#set).

</Param>
</Params>

<FullType>

```ts
$markModified(path: DocumentPaths<T>): this;
```

</FullType>

### Ошибки [#mark-modified.errors]

Путь, которого нет в схеме, бросает [`QueryError`](../errors/query-errors.mdx#query-error).

```text
QueryError: $markModified: "nope" is not a path of Order
```

## $getChanges [#get-changes]

`$getChanges` показывает обновление, которое отправил бы следующий [`$save`](#save), и ничего не делает ни с базой, ни с документом. Он помогает при отладке («почему сохранение медленное?», «что вообще поменялось?»), в тестах и в журналах изменений.

Результат — объект вида «оператор, путь, значение» в **именах полей класса**, а не в именах базы. Если изменений нет, вернётся `{}`. Результат заморожен, его копию можно хранить. Метод никогда не бросает ошибку. Если `$save` отказал бы, причина лежит в ключе `$problems` (см. [ниже](#problems)), а остальное обновление возвращается как обычно.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({
  customer: "alice",
  tags: ["gift"],
  lines: [{ sku: "A1", qty: 2 }],
  address: { city: "Oslo" },
  fees: { delivery: 5 },
});
console.log(order.$getChanges());
// → {}

order.customer = "bob";
order.tags.push("express");
order.lines[0]!.qty = 5;
order.fees?.set("gift", 3);
console.log(order.$getChanges());
// → { $set: { customer: "bob", "lines.0.qty": 5, "fees.gift": 3 }, $push: { tags: { $each: ["express"] } } }
```

<Returns type="DocumentChanges">

Замороженный объект с операторами (`$set`, `$push`, `$unset`, `$pull` и другими), путями и значениями. Пустой `{}` значит, что `$save` ничего не отправит. У нового документа в `$set` лежат все поля. Если сохранение отклонили бы, в объекте появится ключ `$problems`. Это не оператор, а список «путь — текст ошибки».

</Returns>

Принимает ничего.

<FullType>

```ts
$getChanges(): DocumentChanges;

type DocumentChanges = Readonly<Record<string, Readonly<Record<string, unknown>>>>;
```

</FullType>

### Значения не приводятся заранее [#no-early-cast]

В результате лежит то, что в документе сейчас. Если вы в обход компилятора записали в поле не тот тип (`(order as any).customer = 5`), `$getChanges` покажет `5` как есть. Приведение и `CastError` случатся позже, при [`$save`](#save) или [`$validate`](#validate).

### Проблемные пути: $problems [#problems]

`$getChanges` не бросает ошибку, даже когда [`$save`](#save) отказал бы. Вместо этого в результате появляется ключ `$problems` — объект «путь — текст ошибки, которую бросит `$save`». Остальное обновление возвращается как обычно. Так предпросмотр остаётся безопасным для отладки и журналов, а причину будущего отказа видно заранее.

Ключ появляется в трёх случаях.

- Контейнер (массив, Map, поддокумент) заменили присваиванием или записали по индексу мимо его методов — [`DirectWriteError`](../errors/data-errors.mdx#direct-write-error).
- Сохранение переписало бы сохранённый поддокумент вместе с неизвестными схеме полями — [`UnknownFieldsError`](../errors/data-errors.mdx#unknown-fields-error).
- Ключ версии `__v` изменили вручную — [`QueryError`](../errors/query-errors.mdx#query-error).

```ts twoslash
// @errors: 2740
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: ["gift"], lines: [] });

order.customer = "bob";
order.tags = ["express"];
console.log(order.$getChanges());
// → { $set: { customer: "bob" }, $problems: { tags: "\"tags\" was changed around its methods: the field was replaced by assignment; use $set(\"tags\", value) or the container's methods" } }
```

Правка `customer` попала в `$set`, а замена массива присваиванием записана в `$problems`. `$save` на таком документе бросил бы [`DirectWriteError`](../errors/data-errors.mdx#direct-write-error) с тем же текстом.

```text
DirectWriteError: "tags" was changed around its methods: the field was replaced by assignment; use $set("tags", value) or the container's methods
```

Запись по индексу называет позицию — `"lines" was changed around its methods: position 0 was assigned directly (use set(0, value))`. У вручную изменённого `__v` текст другой — `Order.__v is the version key: the core maintains it; it cannot be changed by hand`. Чтобы сохранение прошло, исправьте указанный путь. Вызовите метод коллекции или [`$set`](#set).

## $validate [#validate]

`$validate` проверяет весь документ по схеме и ничего не пишет в базу. Он нужен, когда об ошибках надо узнать до сохранения — показать пользователю список проблем формы, проверить документ в хуке, убедиться в тесте.

На первой ошибке метод не останавливается. Все найденные проблемы собираются в одну [`ValidationError`](../errors/data-errors.mdx#validation-error) со списком `issues`, где у каждой есть путь, причина и сообщение. Порядок — как поля объявлены в классе, а не как вы их правили. Асинхронные валидаторы полей (`validate` в `@Prop`) метод дожидается. Тот же вызов делает [`$save`](#save) перед записью.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, ValidationError, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = Orders.new({ customer: "alice", tags: [], lines: [] });
order.lines.push({ sku: "B2", qty: -1 });

try {
  await order.$validate();
} catch (error) {
  if (error instanceof ValidationError) {
    console.log(error.issues.map((issue) => [issue.path.join("."), issue.reason]));
    // → [["lines.0.qty", "min"]]
  }
}
```

<Returns type="Promise<void>">

Ничего. Успешное завершение значит, что документ корректен. Сам документ метод не меняет.

</Returns>

Принимает ничего.

<FullType>

```ts
$validate(): Promise<void>;
```

</FullType>

### Ошибки [#validate.errors]

При любой проблеме приходит `ValidationError` со всеми найденными пунктами.

```text
ValidationError: Validation failed: "lines.0.qty": must be at least 0 [min]
```

Полный список причин (`required`, `min`, `max`, `enum`, `validator` и другие) и устройство `issues` описаны в справочнике [`ValidationError`](../errors/data-errors.mdx#validation-error). Значения, присвоенные обычным присваиванием (`order.customer = 5`), приводятся на этом же вызове. Если значение не приводится, бросается не `ValidationError`, а [`CastError`](../errors/data-errors.mdx#cast-error), и происходит это до любой валидации. Ограничения поля не проверяются, пока значение не стало нужного типа.

```text
CastError: Cast to string failed at path "customer" for 5 (number): expected a string [type]
```

Чем одно отличается от другого, объясняет руководство [Валидация документа](../../documents/validation.mdx).

### Когда не подходит [#validate.when-not-to-use]

Обычный объект, из которого документа ещё нет, проверяйте через [`Model.validate`](./model-document-methods.mdx#model.validate). Он принимает данные и возвращает приведённое значение с заполненными значениями по умолчанию.

## $deleteOne [#delete-one]

`$deleteOne` удаляет документ из базы по `_id`. Он нужен, когда документ уже у вас в руках и его надо убрать — например, заказ, который пользователь только что открыл.

Метод идёт тем же путём, что и [`deleteOne`](../writes/writes.mdx#delete-one) модели. Запускаются хуки `document.deleteOne`, применяются политики модели (мягкое удаление, тенант), пишется аудит. После успешного удаления документ помечается удалённым, и его [`$save`](#save) с повторным `$deleteOne` отказываются работать.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: [], lines: [] });
const result = await order.$deleteOne();
console.log(result.deletedCount);
// → 1
```

<Returns type="Promise<DeleteResult>">

Результат удаления. `deletedCount` равен 1, если запись удалена, и 0, если её уже не было или документ ещё не вставляли.

</Returns>

<Params>
<Param name="options" type="SaveOptions">

Сессия, тайм-аут и контекст политик записи, как у [`$save`](#save). Опция `dropUnknownFields` на удаление не влияет.

</Param>

### Ошибки [#delete-one.errors]

Повторный вызов на том же объекте бросает [`QueryError`](../errors/query-errors.mdx#query-error).

```text

```

Документ, который ещё не сохранён, удалять нечего. Метод возвращает `deletedCount: 0` и ничего не бросает.

### Когда не подходит [#delete-one.when-not-to-use]

Если документ не загружен и известен только `_id`, берите [`deleteOne`](../writes/writes.mdx#delete-one) или [`findByIdAndDelete`](../writes/writes.mdx#find-by-id-and-delete). Читать документ ради удаления не нужно.

## $updateOne [#update-one]

`$updateOne` обновляет **этот** документ по `_id` документом-обновлением с операторами (`$set`, `$inc` и другими) и не сохраняет правки, сделанные в памяти. Он нужен, когда изменение должно быть атомарным и выполниться на стороне базы. Например, увеличить счётчик, а не прочитать значение, сложить и записать.

Обновление проходит весь конвейер модели — приведение типов, валидаторы, политики, аудит и хуки `document.updateOne`. В хуке `this` — документ, хуки запросов не срабатывают. Документ в памяти при этом **не меняется**. Чтобы увидеть результат, прочитайте его заново.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: [], lines: [] });
const result = await order.$updateOne({ $set: { customer: "dave" } });
console.log(result.modifiedCount, order.customer);
// → 1 "alice"

const stored = await Orders.findById(order._id).orFail().plain();
console.log(stored.customer);
// → "dave"
```

<Returns type="Promise<UpdateResult<IdOf<T>>>">

Результат обновления. `matchedCount` и `modifiedCount` показывают, нашёлся ли документ и изменился ли он.

</Returns>

<Params>
<Param name="update" type="Update<T, true>" required>

Документ-обновление с операторами. Его проверяют компилятор (поля модели, типы значений) и сама библиотека во время работы. Операторы описаны в справочнике [Операторы обновления](../writes/update-operators.mdx).

</Param>
<Param name="options" type="SaveOptions">

Сессия, тайм-аут и политика записи, как у [`$save`](#save).

</Param>
</Params>


</FullType>

### Ошибки [#update-one.errors]

Поле, которого нет в модели, бросает [`StrictModeError`](../errors/data-errors.mdx#strict-mode-error).

```text
StrictModeError: $set: "nope" is not a field of Order [unknown-path]
```

Пустое обновление бросает [`QueryError`](../errors/query-errors.mdx#query-error) `update: an empty update changes nothing`. Документ, который ещё не сохранён, обновить нельзя.

```text
QueryError: updateOne: the Order document is new; $save() it first
```

### Когда не подходит [#update-one.when-not-to-use]

Правки, сделанные в памяти, сохраняйте через [`$save`](#save). Если документ не загружен, вызывайте [`updateOne`](../writes/writes.mdx#update-one) модели.

## $populate [#populate]

`$populate` подгружает связанные документы по ссылке и подставляет их вместо идентификаторов. Он нужен, когда документ уже загружен, а ссылка понадобилась позже. Метод возвращает **тот же документ**, но с типом, где поле уже развёрнуто, поэтому работайте с возвращённым значением.

Путь и параметры проверяются так же, как у [`.populate`](../populate/populate.mdx#populate) запроса. Можно передать и список путей и объектов (`$populate(["author", { path: "tags", select: { label: 1 } }])`). Все они загрузятся за один вызов, а тип результата покажет каждое загруженное поле.

Загруженный путь можно загрузить снова. Вызов заново читает связь и заменяет прежнее значение вместе с его `select` и вложенными путями. Путь ниже уже загруженного поля (`author.posts` после `author`) компилятор не пропустит. Вложенную связь передайте опцией `populate` или верните идентификаторы через [`$depopulate`](#depopulate). Подробный разбор с типами и ошибками — в руководстве [Populate у документа](../../populate/document-populate.mdx).

В примерах ниже в базе лежат покупатель `Ann` и отправление с заголовком `T`, которое ссылается на него в поле `customer`.

```ts twoslash
import { Entity, type Ref, Prop, Schema, TypemoClient, Types } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Schema({ collection: "shipments" })
class Shipment extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Types.ObjectId, { ref: () => Customer }) customer!: Ref<Customer>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Shipments = client.db().model(Shipment);
const shipment = await Shipments.findOne({ title: "T" }).orFail();
// ---cut---
const withCustomer = await shipment.$populate("customer");
console.log(withCustomer.customer?.name);
// → "Ann"
console.log(Object.is(withCustomer, shipment));
// → true
```

<Returns type="Promise<HydratedDocWith<T, { … }>>">

Тот же документ, у которого поле по пути получает развёрнутый тип. В примере `customer` — документ `Customer`, а если покупателя нет, то `null`, но не идентификатор.

</Returns>

Путь к ссылке строкой, объект с параметрами (`select`, `match`, вложенный `populate`, `transform` и другие) или список таких путей и объектов. Допустимые параметры те же, что у запроса.

</Param>
</Params>

## $depopulate [#depopulate]

`$depopulate` возвращает на место идентификаторы вместо развёрнутых документов, у всех полей сразу или у одного. Он нужен перед сохранением документа с развёрнутой ссылкой и когда то же поле надо развернуть заново с другими параметрами.

Метод меняет документ на месте и возвращает его же с типом, где поле снова ссылка. Работайте с возвращённым значением.

```ts twoslash
import { Entity, type Ref, Prop, Schema, TypemoClient, Types } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Schema({ collection: "shipments" })
class Shipment extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Types.ObjectId, { ref: () => Customer }) customer!: Ref<Customer>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Shipments = client.db().model(Shipment);
const shipment = await Shipments.findOne({ title: "T" }).orFail();
const populated = await shipment.$populate("customer");
// ---cut---
const plain = populated.$depopulate("customer");
console.log(Object.is(plain, shipment), populated.$populated("customer"));
// → true undefined
```

</Returns>

## $populated [#populated]

`$populated` возвращает копию идентификаторов, которые стояли на месте развёрнутого поля. С его помощью можно узнать, развёрнуто ли поле, и достать идентификаторы после разворота. Если нужно то же самое вместе с сужением типа, есть функция [`isPopulated`](../populate/populate-types.mdx#is-populated).

Для поля документа возвращается одно значение, для массива ссылок — список. Для пути внутри поддокументов приходит по одному значению на поддокумент. Если путь не развёрнут, метод вернёт `undefined`.

```ts twoslash
import { Entity, type Ref, Prop, Schema, TypemoClient, Types } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Schema({ collection: "shipments" })
class Shipment extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Types.ObjectId, { ref: () => Customer }) customer!: Ref<Customer>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Shipments = client.db().model(Shipment);
const shipment = await Shipments.findOne({ title: "T" }).orFail();
// ---cut---
console.log(shipment.$populated("customer"));
// → undefined

await shipment.$populate("customer");
console.log(shipment.$populated("customer")?.constructor.name);
// → "ObjectId"
```

<Returns type="unknown">

</Returns>

</Param>
</Params>

```ts

```

</FullType>

## $assertPopulated [#assert-populated]

`$assertPopulated` утверждает, что путь развёрнут, и возвращает тот же документ с типом, где поле выглядит развёрнутым. Он нужен, когда разворот случился там, где компилятор его не видит (в хуке или в другой функции), а вам дальше нужен развёрнутый тип.

Ничего не загружается, метод только проверяет, что в поле лежат развёрнутые значения. Ссылка, которая при развороте ничего не нашла и стала `null`, считается развёрнутой. Метод принимает тот же список путей и объектов, что и [`$populate`](#populate). `$assertPopulated(["customer", { path: "items", select: { sku: 1 } }])` проверяет каждый элемент списка, а у объекта с вложенным `populate` ещё и вложенный путь.

```ts twoslash
import { Entity, type Ref, Prop, Schema, TypemoClient, Types } from "@venloc/typemo";
@Schema({ collection: "customers" })
class Customer extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Schema({ collection: "shipments" })
class Shipment extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Types.ObjectId, { ref: () => Customer }) customer!: Ref<Customer>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Shipments = client.db().model(Shipment);
const shipment = await Shipments.findOne({ title: "T" }).orFail();
await shipment.$populate("customer");
// ---cut---
const ready = shipment.$assertPopulated("customer");
//    ^?
console.log(ready.customer?.name);
// → "Ann"
const both = shipment.$assertPopulated(["customer"]);
console.log(both.customer?.name);
// → "Ann"
```

<Returns type="HydratedDocWith<T, { … }>">

Тот же документ с типом, где поля по путям развёрнуты.

</Returns>

<Params>
<Param name="path" type="string | { path, select, populate, … } | (string | { path, … })[]" required>

Путь строкой, объект с теми параметрами, с которыми шёл разворот (они определяют форму развёрнутого типа), или список из них.

</Param>
</Params>

<FullType>


### Ошибки [#assert-populated.errors]

Если путь не развёрнут, метод бросает [`QueryError`](../errors/query-errors.mdx#query-error).


## $is [#is]

`$is` проверяет тип в иерархии дискриминаторов и сужает документ до класса-наследника. Он нужен, когда в одной коллекции лежат документы разных видов, а вам надо добраться до полей конкретного.

Метод возвращает `true`, если документ прочитан как этот класс или как один из его наследников. Для класса вне иерархии он бросает ошибку, а не возвращает `false`, потому что это почти всегда опечатка. Суженный документ типизирован как чтение класса по умолчанию, скрытых полей в нём не видно. Проекция и populate базового документа на суженный тип не переносятся.

<Returns type="boolean">

`true`, если документ относится к классу. Тогда TypeScript сужает тип.

</Returns>

<Params>
<Param name="cls" type="abstract new () => object" required>

Класс-дискриминатор или корневой класс иерархии.

</Param>
</Params>

<FullType>

```ts
$is<const C extends abstract new () => object>(cls: C): this is HydratedDoc<InstanceType<C>>;
```

</FullType>

### Ошибки [#is.errors]

Класс вне иерархии документа бросает [`QueryError`](../errors/query-errors.mdx#query-error).

```text
QueryError: $is: Customer is not Order or one of its discriminators (the document is a Order)
```

Наследование и дискриминаторы разбирает руководство [Наследование и дискриминаторы](../../schemas/discriminators.mdx).

## $session [#session]

`$session` читает или задаёт сессию документа — ту, в которой он загружен и которую по умолчанию использует [`$save`](#save). Он нужен, когда документ живёт дольше одной операции и его надо перенести в другую сессию или снять с сессии.

Без аргумента метод возвращает сессию драйвера или `undefined`. С аргументом он задаёт сессию, а `null` её снимает, и тогда метод возвращает сам документ. Документ, загруженный внутри [`client.transaction`](../connection/typemo-client.mdx#client.transaction), получает сессию этой транзакции.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: [], lines: [] });
console.log(order.$session());
// → undefined

await client.transaction(async () => {
  const inside = await Orders.findById(order._id).orFail();
  console.log(inside.$session() === undefined);
  // → false
});
```

<Returns type="ClientSession | undefined | this">

Без аргумента — сессия или `undefined`. С аргументом — этот же документ.

</Returns>

<Params>
<Param name="session" type="ClientSession | null">

Новая сессия документа. `null` снимает текущую.

</Param>
</Params>

<FullType>

```ts

$session(session: ClientSession | null): this;
```

</FullType>

О сессиях подробнее — в руководстве [Сессии вручную](../../transactions/sessions.mdx).

## $locals [#locals]

`$locals` возвращает объект для данных приложения, привязанных к документу. Он не сохраняется и не попадает ни в одну форму документа. Через него удобно передать значение между хуками одного документа или пометить документ на время обработки.

Каждый вызов возвращает **один и тот же объект**, так что в нём можно копить значения.

```ts twoslash

```

## $toObject [#to-object]

`$toObject` отдаёт данные документа обычными объектами и массивами, без отслеживания изменений и без методов. Он нужен, когда данные надо передать дальше и не привязывать к документу — положить в кеш, сравнить, изменить копию.

Типы MongoDB остаются как есть. `_id` — `ObjectId`, int64 — `bigint`, `Decimal128` — `Decimal128`, Map — обычная `Map`. Поэтому результат нельзя отдать в `JSON.stringify`, на `bigint` он бросит ошибку. Для клиента есть [`$toPlain`](#to-plain) и [`$toJSON`](#to-json). Загруженные скрытые поля `$toObject` по умолчанию возвращает.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
await Orders.create({
  customer: "alice",
  tags: ["gift"],
  lines: [{ sku: "A1", qty: 2 }],
  fees: { delivery: 5 },
  note: "call first",
});
const order = await Orders.findOne({ customer: "alice" }).select({ "+note": true }).orFail();
// ---cut---
const data = order.$toObject();
//    ^?
console.log(data.fees instanceof Map, data.note, data._id.constructor.name);
// → true "call first" "ObjectId"
```

## $toPlain [#to-plain]

`$toPlain` отдаёт форму, готовую для клиента. Значения MongoDB, которые не переживают JSON, он превращает в строки, а родные типы JavaScript оставляет. Идентификаторы, int64, `Decimal128` и UUID становятся строками. `Date`, `RegExp` и `Map` сохраняются, байты становятся `Uint8Array`, вектор — `number[]`. Результат годится для ответов API и кеша, потому что `JSON.stringify` не встретит в нём `bigint`.

Скрытые поля в результат по умолчанию **не попадают**. Чтобы их включить, передайте `{ hidden: true }`. Результат не связан с документом, правка копии документ не затронет.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
await Orders.create({
  customer: "alice",
  tags: ["gift"],
  lines: [{ sku: "A1", qty: 2 }],
  fees: { delivery: 5 },
  note: "call first",
});
const order = await Orders.findOne({ customer: "alice" }).select({ "+note": true }).orFail();
// ---cut---
const plain = order.$toPlain();
//    ^?
console.log(typeof plain._id, "note" in plain, plain.fees instanceof Map);
// → "string" false true

console.log(order.$toPlain({ hidden: true }).note);
// → "call first"
```

</Returns>

<Param name="options" type="ToObjectOptions">

## $toJSON [#to-json]

`$toJSON` отдаёт **JSON-форму**, где всё, чего нет в JSON, превращено в строки. От [`$toPlain`](#to-plain) она отличается там, где JSON и JavaScript расходятся. `Date` становится ISO-строкой, `RegExp` — строкой `"/src/flags"`, `Map` — обычным объектом, байты — строкой base64.

Этот метод вызывает `JSON.stringify(document)`, поэтому документ можно отдавать в `res.json(doc)` и подобные функции напрямую. Скрытые поля в результат не попадают.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const order = Orders.new({ customer: "alice", tags: [], lines: [], fees: { delivery: 5 }, note: "call first" });
// ---cut---
const json = order.$toJSON();
//    ^?
console.log(json.fees, "note" in json);
// → { delivery: 5 } false
console.log(JSON.parse(JSON.stringify(order)).fees);
// → { delivery: 5 }
```

</Returns>
