Фильтр — это объект, который говорит базе, какие документы нужны, например `{ price: { $gte: 20 } }`. Ключ — поле модели. Значение — само значение поля или **объект операторов**, то есть ключи с `$`, и каждый задаёт одно условие. Здесь описан каждый оператор, который принимает Typemo. Для каждого сказано, к каким полям он применим, что означает и когда Typemo откажется его выполнять.

Если вы только начинаете, сначала прочитайте руководство [Фильтры](../../queries/filters.mdx). Эта страница — справочник. Методы, которые принимают фильтр, описаны в справочнике [Чтение](./reading.mdx), а цепочки условий вроде `.where("price").gte(20)` — в справочнике [Условия цепочкой](./conditions.mdx).

Во всех примерах одна модель товара. В ней есть обязательные числа, массив строк, необязательная дата, поле, которое может быть `null`, массив вложенных документов, числовое поле для битовых масок и точка на карте.

```ts twoslash title="models/product.ts"
import { Entity, Index, Prop, Schema } from "@venloc/typemo";

@Schema()
export class GeoPoint {
  @Prop(() => String, { required: true, enum: ["Point"] })
  type!: "Point";

  @Prop(() => [Number], { required: true })
  coordinates!: number[];
}

@Schema()
export class Variant {
  @Prop(() => String, { required: true })
  sku!: string;

  @Prop(() => Number, { required: true })
  qty!: number;
}

@Index({ place: "2dsphere" })
@Schema({ collection: "products" })
export class Product extends Entity {
  @Prop(() => String, { required: true })
  name!: string;

  @Prop(() => Number, { required: true })
  price!: number;

  @Prop(() => Number, { required: true })
  stock!: number;

  @Prop(() => [String])
  tags!: string[];

  @Prop(() => Date)
  released?: Date;

  @Prop(() => String, { nullable: true })
  note!: string | null;

  @Prop(() => [Variant])
  variants!: Variant[];

  @Prop(() => Number)
  flags?: number;

  @Prop(() => GeoPoint)
  place?: GeoPoint;
}
```

В коллекции три товара.

- `Keyboard` стоит 50, на складе 10, теги `office` и `usb`, дата выхода 10 января 2025, `note` равен `null`, две вариации (`K-1` в количестве 4 и `K-2` в количестве 0), `flags` равен 5, точка в Париже.
- `Mouse` стоит 20, на складе 0, тег `usb`, дата выхода 1 июня 2025, `note` равен `"sale"`, одна вариация (`M-1`, 7 штук), `flags` равен 2, точка в Берлине.
- `Monitor` стоит 300, на складе 3, тегов нет, даты выхода и точки нет, `note` равен `null`, вариаций нет, `flags` равен 7.

Результаты в комментариях `// →` — имена найденных товаров, отсортированные по алфавиту.

## Как записывается условие [#condition-syntax]

Условие на поле пишется в одной из двух форм. Короткая форма — само значение. `{ price: 50 }` значит «`price` равно 50», то есть то же, что [`$eq`](#eq). Длинная форма — объект операторов, например `{ price: { $gte: 20, $lt: 300 } }`. Несколько операторов в одном объекте работают вместе, как «и».

Компилятор знает тип каждого поля и предлагает только подходящие операторы. У строки есть `$regex`, у числа — `$mod` и битовые операторы, у массива — `$all`, `$size` и `$elemMatch`. Неподходящий оператор не скомпилируется. Во время работы Typemo проверяет то же самое ещё раз, ведь фильтр часто собирается из данных, которых компилятор не видит. Поэтому три вещи он отвергает всегда.

Во-первых, неизвестный оператор. MongoDB ответила бы на него ошибкой сервера или, хуже, поняла бы фильтр иначе, чем вы ждали. Typemo бросает [`StrictModeError`](../errors/data-errors.mdx#strict-mode-error) до отправки запроса.

```text
StrictModeError: "$foo" is not a query operator (at "filter.price.$foo") [sanitize]
```

Во-вторых, оператор там, где ожидается значение. Так выглядит попытка протащить оператор через данные клиента. Клиент присылает в поле пароля не строку, а объект `{ "$gt": "" }`, чтобы условие выполнилось для любого пароля. Typemo такой фильтр отвергает.

```text
StrictModeError: "$foo" inside a value at "filter.name.$gt": an operator where a value is expected (query selector injection) [sanitize]
```

В-третьих, `$where`. Он запускает JavaScript на сервере, и Typemo не поддерживает его вообще. Причин три, и текст ошибки называет их все. Код в запросе выполняется с правами базы, его нельзя проверить по схеме, а данные клиента, попавшие в такую строку, становятся исполняемым кодом. Через `$where` в populate работала уязвимость CVE-2025-23061 в Mongoose.

```text
StrictModeError: "$where" runs JavaScript on the server and is not supported (at "filter.$where"): JavaScript code in a query runs with the rights of the database, cannot be checked against the schema, and turns injected input into executed code (Mongoose CVE-2025-23061, $where in populate); write the condition with query or aggregation operators ($expr) instead [sanitize]
```

Условия, которые обычными операторами не записать, пишите через [`$expr`](#expr). Он принимает типизированные выражения вместо строки с кодом.

## Сравнение [#comparison]

### $eq [#eq]

`$eq` проверяет, что поле равно значению. Короткая запись `{ price: 50 }` делает то же самое. `$eq` пишут, когда хотят показать равенство явно или когда оператор нужен внутри [`$not`](#not) или [`.where`](./conditions.mdx#where).

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn } from "@venloc/typemo";
@Schema()
class GeoPoint {
  @Prop(() => String, { required: true, enum: ["Point"] }) type!: "Point";
  @Prop(() => [Number], { required: true }) coordinates!: number[];
}
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Index({ place: "2dsphere" })
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
  @Prop(() => Number) flags?: number;
  @Prop(() => GeoPoint) place?: GeoPoint;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Products = client.db().model(Product);
// ---cut---
const exact = await Products.find({ price: { $eq: 50 } }).plain();
console.log(exact.map((product) => product.name));
// → ["Keyboard"]
```

Применим к полям любого типа. Для поля-массива значением может быть элемент или весь массив. `{ tags: "usb" }` найдёт товары, у которых среди тегов есть `usb`, а `{ tags: ["usb"] }` — только те, у которых тегов ровно один и это `usb`. `null` можно сравнивать только с полем, которое может быть `null`. Сравнение с обязательным или необязательным полем отвергается, отсутствие поля проверяют через [`$exists`](#exists).

### $ne [#ne]

`$ne` проверяет, что поле не равно значению. Документы, у которых поля нет совсем, тоже подходят, потому что для базы «нет поля» значит «не равно».

```ts twoslash

  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;

  @Prop(() => Date) released?: Date;
```

Применим к полям любого типа, как [`$eq`](#eq).

### $gt, $gte, $lt, $lte [#gt-gte-lt-lte]

`$gt` значит «больше», `$gte` — «больше или равно», `$lt` — «меньше», `$lte` — «меньше или равно». Вместе они задают диапазон, например `{ price: { $gte: 20, $lt: 300 } }`.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn } from "@venloc/typemo";
@Schema()
class GeoPoint {
  @Prop(() => String, { required: true, enum: ["Point"] }) type!: "Point";
  @Prop(() => [Number], { required: true }) coordinates!: number[];
}
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Index({ place: "2dsphere" })
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
  @Prop(() => Number) flags?: number;
  @Prop(() => GeoPoint) place?: GeoPoint;
}

// ---cut---

console.log(range.map((product) => product.name));
// → ["Keyboard", "Mouse"]

const late = await Products.find({ released: { $gt: new Date("2025-03-01") } }).plain();
console.log(late.map((product) => product.name));
// → ["Mouse"]
```

Применимы к значениям, у которых есть порядок. Это числа (`number`, `bigint`), строки, даты, идентификаторы `ObjectId`, `Decimal128`, `Timestamp` и `Binary`. У логического поля порядка нет, и `{ flag: { $gt: 1 } }` не скомпилируется. Документы без поля в результат не попадают.

## Наборы значений [#sets]

### $in [#in]

`$in` проверяет, что поле равно одному из значений списка. Это короткая запись длинного `$or` из нескольких равенств. С его помощью выбирают товары по списку имён или пользователей по списку идентификаторов.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn } from "@venloc/typemo";
@Schema()
class GeoPoint {
  @Prop(() => String, { required: true, enum: ["Point"] }) type!: "Point";
  @Prop(() => [Number], { required: true }) coordinates!: number[];
}
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Index({ place: "2dsphere" })
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
  @Prop(() => Number) flags?: number;
  @Prop(() => GeoPoint) place?: GeoPoint;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Products = client.db().model(Product);
// ---cut---
const picked = await Products.find({ name: { $in: ["Mouse", "Monitor"] } }).sort({ name: 1 }).plain();
console.log(picked.map((product) => product.name));
// → ["Monitor", "Mouse"]

const withTag = await Products.find({ tags: { $in: ["office", "x"] } }).plain();
console.log(withTag.map((product) => product.name));
// → ["Keyboard"]
```

Применим к полям любого типа. Для поля-массива условие выполняется, если в список входит хотя бы один элемент массива. Операнд обязан быть массивом. `{ price: { $in: 5 } }` не скомпилируется, а если такой фильтр пришёл во время работы, Typemo бросает [`CastError`](../errors/data-errors.mdx#cast-error).

```text
CastError: Cast to Array failed at path "price.$in" for 5 (number): $in takes an array [type]
```

`$nin` обратен [`$in`](#in) — поле не равно ни одному значению списка. Документы без этого поля подходят, как и у [`$ne`](#ne).

```ts twoslash
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;

  @Prop(() => Number) flags?: number;
  @Prop(() => GeoPoint) place?: GeoPoint;

```

## Наличие и тип [#existence-and-type]

### $exists [#exists]

`$exists` проверяет, есть ли в документе поле. `{ $exists: true }` — поле есть, `{ $exists: false }` — поля нет. Только так правильно искать документы, у которых поле не задано, сравнение с `undefined` Typemo запрещает.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn } from "@venloc/typemo";
@Schema()
class GeoPoint {
  @Prop(() => String, { required: true, enum: ["Point"] }) type!: "Point";
  @Prop(() => [Number], { required: true }) coordinates!: number[];
}
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Index({ place: "2dsphere" })
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
  @Prop(() => Number) flags?: number;
  @Prop(() => GeoPoint) place?: GeoPoint;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Products = client.db().model(Product);
// ---cut---
const unreleased = await Products.find({ released: { $exists: false } }).plain();
console.log(unreleased.map((product) => product.name));
// → ["Monitor"]
```

Поле со значением `null` существует. `{ note: { $exists: true } }` вернёт все три товара, в том числе те, у которых `note` равен `null`. Чтобы найти именно `null` (и заодно документы без поля), сравните с `null` напрямую.


Сравнение с `null` разрешено только для полей, которые могут быть `null`. Для поля `released` фильтр `{ released: null }` не скомпилируется, а если он пришёл во время работы, Typemo бросает `CastError`.

```text
CastError: Cast to Date failed at path "released" for null: null is not a value of this path (it is not nullable); an absent field is { $exists: false } [null]
```

Применим к полям любого типа.

### $type [#type]

`$type` проверяет BSON-тип значения в базе. Он полезен, когда в одном поле исторически лежали значения разных типов. Принимает алиас типа (`"string"`, `"date"`, `"null"`, `"long"`, `"objectId"` и другие), слово `"number"` для любого числового типа, номер типа или непустой список из них.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn } from "@venloc/typemo";
@Schema()
class GeoPoint {
  @Prop(() => String, { required: true, enum: ["Point"] }) type!: "Point";
  @Prop(() => [Number], { required: true }) coordinates!: number[];
}
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Index({ place: "2dsphere" })
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
  @Prop(() => Number) flags?: number;
  @Prop(() => GeoPoint) place?: GeoPoint;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Products = client.db().model(Product);
// ---cut---
const strings = await Products.find({ note: { $type: "string" } }).plain();
console.log(strings.map((product) => product.name));
// → ["Mouse"]

const stringOrNull = await Products.find({ note: { $type: ["string", "null"] } }).sort({ name: 1 }).plain();
console.log(stringOrNull.map((product) => product.name));
// → ["Keyboard", "Monitor", "Mouse"]
```

Применим к полям любого типа. Неизвестный алиас даёт `CastError` с текстом `Cast to BSON type alias failed at path "name.$type" for "nope" (string): $type takes a BSON type alias or number (or a list of them) [type]`.

## Строки [#strings]

### $regex [#regex]

`$regex` проверяет строку по регулярному выражению. Он принимает строку-шаблон или `RegExp`. Флаги (`i`, `m`, `x`, `s`, `u`) для строки-шаблона задаются в соседнем `$options`, а для `RegExp` пишутся в самом выражении.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn } from "@venloc/typemo";
@Schema()
class GeoPoint {
  @Prop(() => String, { required: true, enum: ["Point"] }) type!: "Point";
  @Prop(() => [Number], { required: true }) coordinates!: number[];
}
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Index({ place: "2dsphere" })
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
  @Prop(() => Number) flags?: number;
  @Prop(() => GeoPoint) place?: GeoPoint;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Products = client.db().model(Product);
// ---cut---
const byPattern = await Products.find({ name: { $regex: "^m", $options: "i" } }).sort({ name: 1 }).plain();
console.log(byPattern.map((product) => product.name));
// → ["Monitor", "Mouse"]

const byRegExp = await Products.find({ name: /^Mo/ }).sort({ name: 1 }).plain();
console.log(byRegExp.map((product) => product.name));
// → ["Monitor", "Mouse"]
```

Применим только к строковым полям, в том числе к строкам в массиве. `{ price: { $regex: "5" } }` не скомпилируется, а во время работы Typemo бросает `StrictModeError`.

```text
StrictModeError: $regex applies to strings only (at "price.$regex") [sanitize]
```

`$options` без `$regex` тоже ошибка.

```text
StrictModeError: $options without $regex (at "name.$options") [sanitize]
```

Не вставляйте в шаблон строку от клиента без экранирования. Специальные символы в ней станут частью выражения.

## Числа и биты [#numbers-and-bits]

### $mod [#mod]

`$mod` проверяет остаток от деления — `{ $mod: [делитель, остаток] }`. С его помощью можно, например, выбрать цены, кратные 100.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn } from "@venloc/typemo";
@Schema()
class GeoPoint {
  @Prop(() => String, { required: true, enum: ["Point"] }) type!: "Point";
  @Prop(() => [Number], { required: true }) coordinates!: number[];
}
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Index({ place: "2dsphere" })
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
  @Prop(() => Number) flags?: number;
  @Prop(() => GeoPoint) place?: GeoPoint;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Products = client.db().model(Product);
// ---cut---
const round = await Products.find({ price: { $mod: [100, 0] } }).plain();
console.log(round.map((product) => product.name));
// → ["Monitor"]
```

Применим к числовым полям (`number`, `bigint`). Делитель и остаток — целые числа, нулевой делитель отвергается.

```text
CastError: Cast to [divisor, remainder] failed at path "price.$mod" for [array of 2]: $mod by 0 [type]
```

### $bitsAllSet, $bitsAnySet, $bitsAllClear, $bitsAnyClear [#bits]

Четыре битовых оператора проверяют отдельные биты целого числа. `$bitsAllSet` требует, чтобы все указанные биты были установлены, `$bitsAnySet` — хотя бы один установлен, `$bitsAllClear` — все сброшены, `$bitsAnyClear` — хотя бы один сброшен. Биты можно задать списком позиций (позиция 0 — младший бит), одним числом-маской или значением `Binary`.

В модели поле `flags` хранит права битами. У `Keyboard` 5 (биты 0 и 2), у `Mouse` 2 (бит 1), у `Monitor` 7 (биты 0, 1 и 2).

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn } from "@venloc/typemo";

}

  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Index({ place: "2dsphere" })
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;

// ---cut---

console.log(bits02.map((product) => product.name));
// → ["Keyboard", "Monitor"]

const anyOf1 = await Products.find({ flags: { $bitsAnySet: 2 } }).sort({ name: 1 }).plain();
```

Применимы к целым числам и к полям `Binary`. Для остальных полей Typemo бросает `StrictModeError`, а для операнда, который не маска, — `CastError`.

```text

CastError: Cast to bitmask failed at path "flags.$bitsAllSet" for "x" (string): $bitsAllSet takes a non-negative integer, a list of bit positions or a Binary [type]
```

## Массивы [#arrays]

Поле-массив принимает всё, что принимает его элемент. `{ tags: "usb" }`, `{ tags: { $in: [...] } }` и `{ tags: { $regex: "^u" } }` проверяют, подходит ли хотя бы один элемент. Собственных операторов для массивов три.

### $all [#all]

`$all` проверяет, что массив содержит все перечисленные значения, в любом порядке и, возможно, вместе с другими.

```ts twoslash

}
@Schema()

  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Index({ place: "2dsphere" })

  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
```

```text
StrictModeError: $all applies to arrays (at "price.$all") [sanitize]
CastError: Cast to Array failed at path "tags.$all" for "x" (string): $all takes an array [type]
```

### $size [#size]

`$size` проверяет длину массива. `{ tags: { $size: 0 } }` находит товары без тегов. Число должно быть целым и не меньше нуля.


Применим только к массивам. Для числового поля `{ price: { $size: 1 } }` не скомпилируется, а во время работы будет ошибка.

```text
StrictModeError: $size applies to arrays (at "price.$size") [sanitize]
```

### $elemMatch [#elem-match]

`$elemMatch` требует, чтобы **один и тот же элемент** массива удовлетворял всем условиям сразу. Без него условия по вложенным полям проверяются независимо и могут выполниться на разных элементах. Это одна из самых частых ловушек.

У `Keyboard` две вариации, `K-1` в количестве 4 и `K-2` в количестве 0. Нужен товар, у которого есть вариация `K-1` с нулевым остатком. Запись без `$elemMatch` находит `Keyboard`, хотя такой вариации нет. `sku` совпал у одного элемента, а `qty` — у другого.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn } from "@venloc/typemo";
@Schema()
class GeoPoint {
  @Prop(() => String, { required: true, enum: ["Point"] }) type!: "Point";
  @Prop(() => [Number], { required: true }) coordinates!: number[];
}
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Index({ place: "2dsphere" })
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
  @Prop(() => Number) flags?: number;
  @Prop(() => GeoPoint) place?: GeoPoint;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Products = client.db().model(Product);
// ---cut---
const wrong = await Products.find({ "variants.sku": "K-1", "variants.qty": 0 }).plain();
console.log(wrong.map((product) => product.name));
// → ["Keyboard"]  (K-1 и qty 0 — это два разных элемента)

const right = await Products.find({ variants: { $elemMatch: { sku: "K-1", qty: 0 } } }).plain();
console.log(right.map((product) => product.name));
// → []

const second = await Products.find({ variants: { $elemMatch: { sku: "K-2", qty: 0 } } }).plain();
console.log(second.map((product) => product.name));
// → ["Keyboard"]
```

Для массива вложенных документов операнд — фильтр этих документов. Для массива скаляров это объект операторов над элементом, например `{ scores: { $elemMatch: { $gte: 8, $lt: 10 } } }`. Применим только к массивам, пустой объект операнда отвергается.

## Логика [#logic]

### $not [#not]

`$not` меняет условие на обратное. Он принимает объект операторов (без вложенного `$not`) или `RegExp`. Обратите внимание, что документы без поля под `$not` подходят, потому что условие к ним не выполнилось.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn } from "@venloc/typemo";
@Schema()
class GeoPoint {
  @Prop(() => String, { required: true, enum: ["Point"] }) type!: "Point";
  @Prop(() => [Number], { required: true }) coordinates!: number[];
}
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Index({ place: "2dsphere" })
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
  @Prop(() => Number) flags?: number;
  @Prop(() => GeoPoint) place?: GeoPoint;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Products = client.db().model(Product);
// ---cut---
const cheap = await Products.find({ price: { $not: { $gt: 30 } } }).plain();
console.log(cheap.map((product) => product.name));
// → ["Mouse"]

const notK = await Products.find({ name: { $not: /^K/ } }).sort({ name: 1 }).plain();
console.log(notK.map((product) => product.name));
// → ["Monitor", "Mouse"]
```

Применим к полям любого типа, а `RegExp` — только к строковым. Если условие можно выразить обратным оператором, берите его, например `$lte` вместо `$not` с `$gt`.

### $and [#and]

`$and` требует, чтобы выполнились все условия списка. Список не может быть пустым. Обычно `$and` не нужен, ведь несколько ключей в одном фильтре и так работают как «и». Он нужен, когда условие на то же поле или тот же оператор надо повторить.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn } from "@venloc/typemo";
@Schema()
class GeoPoint {
  @Prop(() => String, { required: true, enum: ["Point"] }) type!: "Point";
  @Prop(() => [Number], { required: true }) coordinates!: number[];
}
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Index({ place: "2dsphere" })
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
  @Prop(() => Number) flags?: number;
  @Prop(() => GeoPoint) place?: GeoPoint;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });

// ---cut---

  .sort({ name: 1 })

console.log(inStock.map((product) => product.name));
// → ["Keyboard", "Monitor"]
```

`$or` требует, чтобы выполнилось хотя бы одно условие списка.

### $nor [#nor]

`$nor` требует, чтобы не выполнилось ни одно условие списка.


Пустой список у `$and`, `$or` и `$nor` не допускается. Сервер отвергает его у всех трёх, а список условий часто собирается из данных клиента и может оказаться пустым.
```text
QueryError: filter: $or must be a non-empty array (at "$or")
```

Для `$and` и `$nor` текст тот же, с их именем. Если вы вызвали `.and([])`, `.or([])` или `.nor([])` цепочки, он начинается с имени метода (`and:`, `or:`, `nor:`).

## Выражения, схема, выборка [#expressions-schema-sampling]

### $expr [#expr]

`$expr` сравнивает поля документа друг с другом или с вычисленным значением. Он принимает функцию, которая строит выражение через `fn` (те же выражения, что в агрегациях). Компилятор проверяет, что поля существуют и операции подходят их типам. Строкой с кодом, как `$where`, выражение не пишется.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn } from "@venloc/typemo";
@Schema()
class GeoPoint {
  @Prop(() => String, { required: true, enum: ["Point"] }) type!: "Point";
  @Prop(() => [Number], { required: true }) coordinates!: number[];
}
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Index({ place: "2dsphere" })
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
  @Prop(() => Number) flags?: number;
  @Prop(() => GeoPoint) place?: GeoPoint;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Products = client.db().model(Product);
// ---cut---
const pricey = await Products.find({ $expr: (f) => fn.gt(f.price, fn.multiply(f.stock, 10)) })
  .sort({ name: 1 })
  .plain();
console.log(pricey.map((product) => product.name));
// → ["Monitor", "Mouse"]
```

Здесь цена товара сравнивается с десятикратным остатком на складе. Обычными операторами такое условие не записать, потому что оба операнда — поля документа. Подробнее о выражениях в справочнике [Выражения агрегаций](../aggregation/index.mdx).

### $jsonSchema [#json-schema]

`$jsonSchema` оставляет только документы, которые соответствуют JSON-схеме. Он пригодится, чтобы найти документы с нарушенной структурой, например оставшиеся от старой версии модели.

```ts twoslash
  .sort({ name: 1 })
  .plain();
console.log(dated.map((product) => product.name));
// → ["Keyboard", "Mouse"]
```

### $sampleRate [#sample-rate]

`$sampleRate` выбирает случайную долю документов, число от 0 до 1. Он нужен для быстрой оценки на выборке, например при отладке на большой коллекции. Значение 1 выбирает все документы.

### $comment [#comment]

`$comment` прикрепляет к запросу комментарий. Он виден в профилировщике и логах сервера и на результат не влияет. Допустим только на верхнем уровне фильтра, а на уровне поля Typemo его отвергает.

```text
StrictModeError: "$comment" is a top-level operator, not an operator of a field (at "filter.price.$comment") [sanitize]
```

Комментарий ко всему запросу, а не только к фильтру, задаёт метод [`.comment`](./options.mdx#comment).

### $text [#text]

`$text` ищет слова по текстовому индексу. Ему нужен текстовый индекс на коллекции, а без индекса запрос завершается ошибкой сервера `ServerError: text index required for $text query (code 27 IndexNotFound)`. Полный разбор, включая оценку релевантности `textScore`, в справочнике [Поиск и план запроса](./search-and-explain.mdx#text-score).

## Гео-запросы [#geo-queries]

Гео-операторы работают с полями, которые хранят точку или фигуру в формате GeoJSON, и с парами координат `[долгота, широта]`. `$near` и `$nearSphere` требуют на поле индекс `2dsphere`. В модели он объявлен декоратором `@Index({ place: "2dsphere" })`, а создаётся при [синхронизации индексов](../../collections/index-sync.mdx). Координаты — конечные числа, строка вместо числа отвергается `CastError`.

```text
CastError: Cast to GeoJSON failed at path "place.$near.$geometry.coordinates.0" for "1" (string): a geo operand holds numbers, arrays of numbers and GeoJSON objects [type]
```

Фигуры с координатами проще всего строить помощником [`GeoJson`](#geo-json). Он проверяет диапазон и замкнутость кольца раньше, чем запрос уйдёт в базу.

### $near [#near]

`$near` возвращает документы, отсортированные от ближней точки к дальней. Опция `$maxDistance` ограничивает расстояние в метрах, `$minDistance` задаёт нижнюю границу. Результат уже отсортирован по расстоянию, так что `.sort` к нему обычно не добавляют.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, fn } from "@venloc/typemo";
@Schema()
class GeoPoint {
  @Prop(() => String, { required: true, enum: ["Point"] }) type!: "Point";
  @Prop(() => [Number], { required: true }) coordinates!: number[];
}
@Schema()
class Variant {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Index({ place: "2dsphere" })
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number, { required: true }) stock!: number;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Date) released?: Date;
  @Prop(() => String, { nullable: true }) note!: string | null;
  @Prop(() => [Variant]) variants!: Variant[];
  @Prop(() => Number) flags?: number;
  @Prop(() => GeoPoint) place?: GeoPoint;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Products = client.db().model(Product);
// ---cut---
const nearParis = await Products.find({
  place: { $near: { $geometry: { type: "Point", coordinates: [2.3, 48.8] }, $maxDistance: 20_000 } },
}).plain();
console.log(nearParis.map((product) => product.name));
// → ["Keyboard"]
```

Без `$maxDistance` вернутся все документы с точкой, от ближнего к дальнему — `["Keyboard", "Mouse"]`.

### $nearSphere [#near-sphere]

`$nearSphere` делает то же, что [`$near`](#near), но считает расстояния по сфере. Для полей GeoJSON результат совпадает с `$near`, а отличие видно у старых полей с парами координат.

### $geoWithin [#geo-within]

`$geoWithin` оставляет документы, фигура которых целиком лежит внутри заданной области. Индекс не обязателен.

## GeoJson [#geo-json]

`GeoJson` — класс со статическими методами, которые строят значения GeoJSON для гео-операторов. Он умеет строить точку, линию и многоугольник. Нужен он в двух случаях. Первый — фигуру вы собираете не литералом прямо в фильтре, а отдельно, в переменной или функции. Тогда TypeScript выводит `coordinates` как `number[]`, а гео-операторы принимают только точную пару или кольцо нужной длины. Второй — координаты приходят из данных, и их надо проверить до запроса, а не после ответа сервера.

```ts twoslash
import { Entity, GeoJson, Index, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema()
class GeoPoint {
  @Prop(() => String, { required: true, enum: ["Point"] }) type!: "Point";
  @Prop(() => [Number], { required: true }) coordinates!: number[];
}
@Index({ place: "2dsphere" })
@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => GeoPoint) place?: GeoPoint;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Products = client.db().model(Product);
// ---cut---
const paris = GeoJson.point(2.3, 48.8);
//    ^?

const near = await Products.find({ place: { $near: { $geometry: paris, $maxDistance: 20_000 } } }).plain();
console.log(near.map((product) => product.name));
// → ["Keyboard"]
```

Результат подходит везде, где гео-оператор или поле модели ждёт GeoJSON. Это `$near`, `$nearSphere`, `$geoIntersects`, `$geoWithin` (многоугольник) и значение поля при [`create`](../writes/writes.mdx#create). Методы ничего не отправляют в базу и от модели не зависят.

Каждая позиция проверяется так же, как это делает индекс `2dsphere`. Это два числа (третье — необязательная высота), все конечные, долгота от −180 до 180, широта от −90 до 90. Порядок всегда **долгота, затем широта**. Помощник не может угадать, что вы перепутали числа местами, если оба лежат в допустимых пределах.

### GeoJson.polygon [#geo-json.polygon]

Строит многоугольник `{ type: "Polygon", coordinates: [кольца] }`. Первое кольцо — внешняя граница, следующие — дыры внутри неё. Подходит для `$geoWithin`, `$geoIntersects` и значения поля.

```ts twoslash
import { CastError, GeoJson } from "@venloc/typemo";
// ---cut---
const square = GeoJson.polygon([[0, 0], [1, 0], [1, 1], [0, 1], [0, 0]]);
const withHole = GeoJson.polygon(
  [[0, 0], [10, 0], [10, 10], [0, 10], [0, 0]],
  [[1, 1], [2, 1], [2, 2], [1, 1]],
);
console.log(square.coordinates.length, withHole.coordinates.length);
// → 1 2
```

<Returns type="GeoJsonPolygon">

Новый объект многоугольника. Кольца и позиции копируются.

</Returns>

</Param>
</Params>


</FullType>

### Ошибки [#errors]

Недопустимая позиция или кольцо дают [`CastError`](../errors/data-errors.mdx#cast-error). Он бросается сразу при вызове метода, до любого запроса.

```text
CastError: Cast to GeoJSON position failed at path "coordinates" for [array of 2]: the longitude is in [-180, 180] and the latitude in [-90, 90] (longitude first) [range]
CastError: Cast to GeoJSON position failed at path "coordinates" for [array of 2]: a position is [longitude, latitude] (an optional altitude), finite numbers [type]
CastError: Cast to GeoJSON linear ring failed at path "coordinates.0" for [array of 4]: a ring is closed: its last position equals the first [format]
CastError: Cast to GeoJSON linear ring failed at path "coordinates.0" for [array of 3]: a ring has four positions at least [format]
CastError: Cast to GeoJSON line string failed at path "coordinates" for [array of 1]: a line string has two positions at least [format]
```

Первая строка — долгота или широта вне пределов (`GeoJson.point(200, 10)`). Вторая — нечисловая или бесконечная координата (`GeoJson.point(Number.NaN, 1)`). Третья — незамкнутое кольцо, четвёртая — слишком короткое. Пятая — линия меньше чем из двух позиций, то есть `GeoJson.lineString` из кода без типов с одной позицией. Сервер отверг бы такую линию только при записи. В пути ошибки для линии и многоугольника стоит номер позиции или кольца, например `coordinates.1` и `coordinates.0.3`. То же число позиций проверяет и компилятор. `GeoJson.lineString([0, 0])` и многоугольник с тремя позициями в кольце не компилируются, а в коде без типов их останавливает `CastError`.

```ts twoslash
import { CastError, GeoJson } from "@venloc/typemo";
// ---cut---
// @errors: 2555
GeoJson.lineString([0, 0]);
```

`CastError` можно перехватить на границе приложения и ответить клиенту, что координаты неверны.

### Когда `GeoJson` не нужен [#when-not-to-use]

Если фигура записана литералом прямо в фильтре, как в примерах выше, компилятор и так выводит для неё точный тип, и помощник ничего не добавляет. Он нужен, когда фигура живёт отдельно от запроса или когда координаты надо проверить. Обычный объект `{ type: "Point", coordinates: [200, 100] }` Typemo пропустит. Диапазон проверит только сервер при записи документа, и ответ придёт ошибкой `ServerError`.

О гео-запросах с индексами и типами GeoJSON подробнее в руководстве [Гео-запросы](../../queries/geo.mdx).
