**Маска** подменяет значение поля безопасным видом. Адрес `alice@gmail.com` становится `a***@gmail.com`, номер карты — `************4242`. Маска нужна, когда поле надо показать, но не целиком. Сотруднику поддержки важно понять, о какой карте речь, а полный номер ему ни к чему. Если поле не нужно вообще, его не читают — для этого есть [`.select`](./reading.mdx#select) и [`hidden`](../schemas/prop.mdx#hidden). Здесь описан метод [`.mask`](#mask) у запроса и все готовые маски `Mask.*`.

Если вы только начинаете, сначала прочитайте руководство [Маски ответа](../../queries/response-masks.mdx). Эта страница — справочник.

Во всех примерах одна модель клиента. У неё обязательные имя и почта, телефон, который может быть `null`, необязательный возраст, массив карт и словарь заметок.

<Snippet id="queries/response-masks/prerequisites" title="models/customer.ts" twoslash />

В коллекции два клиента. У Alice почта `alice@gmail.com`, телефон `+79161234567`, 30 лет, две карты (`4242 4242 4242 4242` с владельцем `Alice A` и `5555 5555 5555 4444` без владельца) и заметка `vip` со значением `yes`. У Bob почта `bob@example.org`, телефон `null`, 17 лет и нет карт. Результаты в комментариях `// →` сокращены до полей, важных для примера.

## .mask [#mask]

`.mask` применяет маски к результату запроса. Вы передаёте объект «путь → маска». Путь называет поле, вложенные идут через точку, элементы массивов проходятся сами, а значения словаря — через `$*`. Маска — это строка `"mask"` (значение становится `"?"`), функция или готовая маска `Mask.*`.

<Snippet id="reference/query/masks/mask" twoslash />

Маска применяется **последним шагом**, после чтения, подстановки связанных документов и превращения в результат `.lean()` или `.plain()`. Хуки, события и аудит видят настоящие данные, маска касается только того, что получит вызывающий код. Исходные данные она не меняет, результат — копия.

<Returns type="MaskedQuery">

Завершающий запрос, который после `await` даёт результат с масками. Для `find` это массив, для `findOne` — строка или `null`. Тип результата учитывает маски. Поле с `"mask"` получает тип `"?"`, поле с функцией — тип её результата, а если поле может быть `null`, к типу добавляется `"?"`. У `MaskedQuery` есть `exec`, `cursor` (для списков) и `expect`. Других методов строителя нет, запрос фиксируется до маскирования.

</Returns>

<Params>
<Param name="spec" type="объект путь → маска" required>

Ключи — пути строки результата. Компилятор подсказывает их и проверяет, что путь существует, а функция принимает тип значения по этому пути. Значения — `"mask"`, функция `(value) => …` или объект с методом `mask`, какой возвращает любой `Mask.*`. Если значение не маска, будет `QueryError` с текстом `mask: "email" takes "mask" or a mask function`. Пустой путь даёт `QueryError` с текстом `mask: an empty path`, а путь, которого нет в строке результата, — `StrictModeError` (см. раздел [Путь, которого нет в результате](#path-not-in-result)).

Значения `null` и `undefined` по пути маски всегда становятся `"?"`, функция не вызывается. Поэтому функции получают тип значения без `null`.

</Param>
</Params>

### Вложенные значения [#nested-values]

Путь через массив проходит по каждому элементу, так что `cards.number` маскирует номер каждой карты. Значения словаря маскируются через `$*`. Ключ словаря остаётся, маскируется только значение.

<Snippet id="reference/query/masks/nested-values" twoslash />

У второй карты владельца нет, поэтому поля `holder` в результате так и нет. Отсутствующее поле остаётся отсутствующим.

### Своя функция [#custom-function]

Вместо готовой маски подойдёт любая функция. Она получает настоящее значение и возвращает то, что увидит вызывающий код.

<Snippet id="reference/query/masks/custom-function" twoslash />

Если функция бросает ошибку, запрос завершается `QueryError` с текстом `mask: the mask of "email" (model Customer) threw`. Молча вернуть настоящее значение вместо маски было бы утечкой.

### Только для lean и plain [#lean-and-plain-only]

Документ с замаскированным значением можно случайно сохранить, и в базе окажется маска вместо данных. Поэтому `.mask` работает только у [`.lean()`](./reading.mdx#lean) и [`.plain()`](./reading.mdx#plain), а у документа не компилируется. Если вызов пришёл из кода без типов, Typemo бросает `QueryError`.

<Snippet id="reference/query/masks/lean-and-plain-only" />

### Путь, которого нет в результате [#path-not-in-result]

Маска по несуществующему пути ничего бы не замаскировала. Опечатка в `emial` оставила бы настоящую почту в ответе, и утечку никто не заметил бы. Поэтому компилятор отвергает такой путь, а если объект масок собран из данных, которых он не видит, пути проверяет сам Typemo. [`StrictModeError`](../errors/data-errors.mdx#strict-mode-error) вылетает сразу при вызове `.mask`, до любого запроса к базе.

<Snippet id="reference/query/masks/path-not-in-result" twoslash />

<Snippet id="queries/response-masks/troubleshooting-3" />

Так проверяются и вложенные пути (`cards.nope`), и запросы `findOne`. Но маска защищает только результат одного запроса, осторожности она не отменяет. Скрыть поле совсем позволяет [`.select`](./reading.mdx#select).

### Курсор [#cursor]

У `MaskedQuery` есть `.cursor()` для списков. Маска применяется к каждой строке по мере чтения. Для `findOne` курсора нет.

### Когда `.mask` не подходит [#when-not-to-use]

Если поле клиенту не нужно вообще, не читайте его. [`.select`](./reading.mdx#select) с исключением или [`hidden`](../schemas/prop.mdx#hidden) в модели надёжнее маски, потому что значение не покидает базу. Если поле надо замаскировать **везде**, в том числе в логах и ошибках, задайте в модели опцию `sensitive` с теми же `Mask.*`. Она действует и на события, и на тексты ошибок, а `.mask` — только на результат одного запроса.

## Пресеты Mask [#mask-presets]

`Mask` — набор готовых масок. Каждый вызов, например `Mask.email()`, возвращает объект `{ mask }`. Он подходит и для `.mask`, и для опции `sensitive`. У всех масок общие правила.

- Маска типизирована значением, которое принимает. `Mask.email()` на числовом поле не скомпилируется.
- Маска никогда не бросает ошибку из-за данных. `null`, значение не того типа или непригодное значение дают `"?"`, ведь потерять деталь лучше, чем раскрыть значение.
- Ошибку допускают только неверные аргументы фабрики. Она бросает `ConfigurationError` сразу при вызове фабрики, а не при первой строке данных.
- Строки считаются по кодовым точкам, эмодзи и пары суррогатов не режутся пополам.

Отдельной маски «скрыть» нет. Строка `"mask"` в `.mask({ поле: "mask" })` даёт `"?"`.

### Неверные аргументы фабрики [#invalid-factory-arguments]

Фабрика проверяет аргументы сразу и бросает `ConfigurationError`, а не ошибку при первой строке данных.

### Типы масок [#mask-types]

`MaskOf<T>` — тип готовой маски для значений `T`, объект с методом `mask`. `MaskChoice<T>` — ветка `Mask.when`, то есть `"show"`, `"mask"` или `MaskOf<T>`. `MaskFunction<V>` и `MaskValue<V>` — функция маски и значение записи `.mask`. `MaskPaths`, `MaskSpecCheck`, `ApplyMask` и `MaskResult` — типы, по которым компилятор проверяет пути и вычисляет тип результата. Вручную их обычно не пишут.

## SENSITIVE_MASK и SENSITIVE_HIDDEN [#sensitive-mask]

Две константы с текстами, которыми подменяются значения. `SENSITIVE_MASK` равна `"?"` и стоит на месте замаскированного значения. `SENSITIVE_HIDDEN` равна `"[hidden]"` и стоит на месте полностью скрытого значения, вместе со всем условием поля. Они нужны коду, который читает замаскированные данные и должен отличить маску от настоящего значения, например при разборе ошибок и событий.
