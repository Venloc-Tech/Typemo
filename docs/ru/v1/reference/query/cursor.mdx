**Курсор** отдаёт документы запроса по одному, по мере чтения из базы, а не массивом целиком. Его получают из [`.cursor()`](./reading.mdx#cursor) у запроса [`find`](./reading.mdx#modelfind), когда документов так много, что держать их все в памяти неудобно. Это выгрузка в другую систему, миграция данных, ночной отчёт. Здесь описаны все методы курсора и ошибка, которую он бросает при обработке.

Если вы только начинаете, сначала прочитайте руководство [Большие выборки](../../queries/large-results.mdx). Эта страница — справочник.

Во всех примерах одна модель заказа. Сначала в ней два поля, остальные не нужны.

```ts twoslash title="models/order.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "orders" })
export class Order extends Entity {
  @Prop(() => Number, { required: true })
  number!: number;

  @Prop(() => String, { required: true })
  status!: string;
}
```

В коллекции пять заказов с номерами от 1 до 5. Нечётные заказы оплачены (`paid`), чётные новые (`new`). Везде они читаются по возрастанию номера, так что порядок в результатах понятен.

Курсор возвращает те же строки, что вернул бы `await`. Это документы, результат [`.lean()`](./reading.mdx#lean) или результат [`.plain()`](./reading.mdx#plain), смотря по цепочке. [`.skip`](./reading.mdx#skip), [`.limit`](./reading.mdx#limit) и [`.batchSize`](./options.mdx#batchsize) работают и с курсором.

Тип курсора называется [`QueryCursor<T>`](#querycursor), где `T` — тип строки. Его можно назвать в своей сигнатуре, импортировав из пакета. Функции, которая принимает курсор заказов, всё равно, что внутри — документы или результат `.lean()` или `.plain()`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, type QueryCursor } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Orders = client.db().model(Order);
// ---cut---
export const countRows = async (rows: QueryCursor<{ number: number }>): Promise<number> => {
  let total = 0;
  for await (const _row of rows) total += 1;
  return total;
};

const cursor = Orders.find().plain().cursor();
//    ^?
console.log(await countRows(cursor));
// → 5
```

## for await

Чаще всего курсор читают циклом `for await ... of`. Курсор итерируется асинхронно, цикл получает следующий документ, когда закончил с предыдущим. В памяти одновременно живёт только текущая порция.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Orders = client.db().model(Order);
declare const __sendToWarehouse__: (order: { number: number }) => Promise<void>;
// ---cut---
for await (const order of Orders.find().sort({ number: 1 }).plain().cursor()) {
  await __sendToWarehouse__(order);
}
```

Когда документы кончились, цикл завершается и курсор закрывается сам. Он закрывается и при раннем выходе, `break` или ошибка внутри цикла освобождают курсор на сервере. Это важно, ведь незакрытый курсор держит ресурсы сервера. Зато после раннего выхода тот же курсор читать больше нельзя, иначе будет `QueryError`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Orders = client.db().model(Order);
// ---cut---
const cursor = Orders.find().sort({ number: 1 }).plain().cursor();
for await (const order of cursor) {
  if (order.number === 2) break;
}
await cursor.next(); // [!code error]
// QueryError: the cursor is closed (close() or a left for-await); open a new one
```

Так задумано намеренно. Чтение курсора, который вы сами закрыли, значило бы, что код читает не те данные, о которых думает, а молчаливый пустой результат скрыл бы ошибку. Чтобы прочитать данные снова, откройте новый курсор. Курсор, дочитанный до конца, ошибкой не отвечает. Он исчерпан, и `.next` на нём возвращает `null`.

## .next

`.next` возвращает следующий документ или `null`, когда документы закончились. Он пригодится, когда цикл не подходит — вы читаете документы по одному в разных местах кода или забираете только первые несколько.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Orders = client.db().model(Order);
// ---cut---
const cursor = Orders.find().sort({ number: 1 }).plain().cursor();

const first = await cursor.next();
const second = await cursor.next();
console.log(first?.number, second?.number);
// → 1 2
```

<Returns type="Promise<T | null>">

Следующая строка или `null`, если курсор исчерпан. На исчерпанном курсоре `.next` и дальше возвращает `null`, повторный вызов ошибкой не считается. Если курсор закрыли вы сами ([`.close`](#close), выход из `for await`, [`.eachAsync`](#eachasync)), `.next` бросает `QueryError` с текстом `the cursor is closed (close() or a left for-await); open a new one`.

</Returns>

Принимает ничего.

<FullType>

```ts
next(): Promise<T | null>
```

</FullType>

## .toArray

`.toArray` дочитывает курсор до конца и возвращает оставшиеся документы массивом. Он нужен, когда сначала надо снять с курсора несколько документов через [`.next`](#next), а остальное взять целиком. Подойдёт он и тогда, когда курсор достался вам от чужого кода.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Orders = client.db().model(Order);
// ---cut---
const cursor = Orders.find().sort({ number: 1 }).plain().cursor();
await cursor.next();

const rest = await cursor.toArray();
console.log(rest.map((order) => order.number));
// → [2, 3, 4, 5]
```

<Returns type="Promise<T[]>">

Все ещё не прочитанные документы. Курсор при этом исчерпывается и закрывается сам. У курсора, который закрыли вы, `.toArray` бросает `QueryError`, как и [`.next`](#next).

</Returns>

Принимает ничего.

<FullType>

```ts
toArray(): Promise<T[]>
```

</FullType>

### Когда `.toArray` не подходит

`.toArray` собирает всё в память и возвращает то же, что обычный `await`. Если документов много и память дорога, обрабатывайте их по одному в [`for await`](#for-await) или через [`.eachAsync`](#eachasync).

## .map

`.map` превращает документы курсора. Он возвращает **новый** курсор, а его документы получаются вызовом вашей функции над каждой исходной строкой. Так строки можно привести к нужной форме до того, как код начнёт их читать.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Orders = client.db().model(Order);
// ---cut---
const numbers = Orders.find().sort({ number: 1 }).plain().cursor().map((order) => order.number * 10);
console.log(await numbers.toArray());
// → [10, 20, 30, 40, 50]
```

<Returns type="QueryCursor<U>">

Новый курсор с преобразованными документами. Исходный курсор не меняется, но **поток данных у них общий**. Они читают одни и те же документы, и документ, прочитанный через один курсор, другой уже не увидит.

</Returns>

<Params>
<Param name="fn" type="(doc: T) => U" required>

Функция преобразования. Её вызывают на каждой строке, которую читает новый курсор. Результат функции — строка нового курсора, из него выводится `U`.

</Param>
</Params>

<FullType>

```ts
map<U>(fn: (doc: T) => U): QueryCursor<U>
```

</FullType>

### Общий поток с исходным курсором

Драйвер MongoDB изменил бы сам курсор и вернул его же. Здесь `.map` возвращает новый курсор, но читать из обоих сразу не получится. Каждая строка достаётся только одному из них.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Orders = client.db().model(Order);
// ---cut---
const cursor = Orders.find().sort({ number: 1 }).plain().cursor();
const mapped = cursor.map((order) => order.number);

const viaMapped = await mapped.next();
const viaOriginal = await cursor.next();
console.log(viaMapped, viaOriginal?.number);
// → 1 2
```

Если нужны оба вида строк, преобразуйте строку внутри одного цикла и не заводите два курсора.

## .eachAsync

`.eachAsync` вызывает вашу функцию для каждого документа и ждёт её завершения. Так можно обработать все документы курсора без цикла, с настраиваемой параллельностью, порциями и сбором ошибок. В конце курсор закрывается сам, даже если функция бросила ошибку.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Orders = client.db().model(Order);
declare const __sendToWarehouse__: (order: { number: number }) => Promise<void>;
// ---cut---
await Orders.find().sort({ number: 1 }).plain().cursor().eachAsync(async (order, index) => {
  await __sendToWarehouse__(order);
  console.log(index, order.number);
});
// → 0 1
//   1 2
//   2 3
//   3 4
//   4 5
```

<Returns type="Promise<void>">

Промис, который завершается, когда обработаны все документы. К этому моменту курсор закрыт и читать его дальше нельзя, будет `QueryError`, как после выхода из `for await`. Если функция бросила ошибку, промис завершается ошибкой, подробности ниже.

</Returns>

<Params>
<Param name="fn" type="(doc: T, index: number) => unknown" required>

Функция обработки. Она получает документ и его порядковый номер с нуля. Функция может быть асинхронной, `.eachAsync` дождётся её результата. С опцией `batchSize` вместо документа приходит массив документов, а вместо номера документа — номер порции.

</Param>
<Param name="options.parallel" type="number" default="1">

Сколько вызовов `fn` могут выполняться одновременно. Документы по-прежнему читаются по одному, параллельно работает только ваша функция. Значение должно быть положительным целым, иначе будет `QueryError` с текстом `eachAsync: parallel must be a positive integer, got 0 (number)`. Значение печатается вместе с типом. Строка `"2"` даёт `got "2" (string)`, а не молчаливое приведение к числу.

</Param>
<Param name="options.continueOnError" type="boolean" default="false">

Продолжать после ошибки в `fn`. Ошибки копятся и в конце бросаются вместе как [`EachAsyncError`](#eachasyncerror). Без этой опции первая ошибка останавливает обработку и бросается как есть.

</Param>
<Param name="options.batchSize" type="number">

Передавать `fn` порции до `batchSize` документов вместо одного документа. Значение должно быть положительным целым, иначе будет `QueryError` с текстом `eachAsync: batchSize must be a positive integer, got 0 (number)`. Не путайте с [`.batchSize`](./options.mdx#batchsize) запроса. Та опция задаёт размер порции при чтении из сети, а эта — размер порции, которую получает ваша функция.

</Param>
</Params>

<FullType>

```ts
eachAsync(fn: (docs: T[], batchIndex: number) => unknown, options: EachAsyncBatchOptions): Promise<void>
eachAsync(fn: (doc: T, index: number) => unknown, options?: EachAsyncOptions): Promise<void>
```

</FullType>

### Параллельная обработка

По умолчанию `.eachAsync` вызывает `fn` для документов по очереди. Следующий вызов начинается после завершения предыдущего. Если функция ждёт сеть, например отправку в другую систему, это простаивающее время. `parallel` позволяет держать несколько вызовов одновременно.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Orders = client.db().model(Order);
declare const __sendToWarehouse__: (order: { number: number }) => Promise<void>;
// ---cut---
await Orders.find().sort({ number: 1 }).plain().cursor().eachAsync(
  (order) => __sendToWarehouse__(order),
  { parallel: 3 },
);
```

Одновременно выполнялось не более трёх вызовов. Порядок их завершения не гарантирован, заказ 3 может закончиться раньше заказа 2. Если порядок важен, оставьте `parallel` равным единице.

### Порции

Если получателю удобнее принимать пачками, например при вставке в другую базу, `batchSize` собирает документы в массивы.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Orders = client.db().model(Order);
// ---cut---
await Orders.find().sort({ number: 1 }).plain().cursor().eachAsync(
  (orders, batchIndex) => {
    console.log(batchIndex, orders.map((order) => order.number));
  },
  { batchSize: 2 },
);
// → 0 [1, 2]
//   1 [3, 4]
//   2 [5]
```

Последняя порция может быть короче остальных. В примере в ней один заказ.

### Ошибки в обработчике

Без `continueOnError` первая ошибка функции останавливает обработку. Новые документы больше не запускаются, уже запущенные при `parallel` вызовы дожидаются, а сама ошибка бросается без обёртки. К этому моменту курсор закрыт.

С `continueOnError: true` обработка доходит до конца, а ошибки копятся и бросаются вместе как `EachAsyncError`.

```ts twoslash
import { EachAsyncError } from "@venloc/typemo";
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Orders = client.db().model(Order);
// ---cut---
try {
  await Orders.find().sort({ number: 1 }).plain().cursor().eachAsync(
    (order) => {
      if (order.number % 2 === 0) throw new Error(`order ${order.number} rejected`);
    },
    { continueOnError: true },
  );
} catch (error) {
  if (error instanceof EachAsyncError) {
    console.log(error.message);
    // → "eachAsync: 2 call(s) of the callback failed (continueOnError)"
    console.log(error.errors.map(String));
    // → ["Error: order 2 rejected", "Error: order 4 rejected"]
  }
}
```

### Когда `.eachAsync` не подходит

Если чтение надо остановить по условию, например взять документы, пока не встретится определённый, берите [`for await`](#for-await) с `break`. `.eachAsync` читает курсор до конца. Если нужны все документы сразу и в памяти, возьмите [`.toArray`](#toarray) или обычный `await`.

## .close

`.close` закрывает курсор и освобождает ресурсы на сервере. Вручную его вызывают, только если вы не дочитали курсор до конца и не вышли через `for await` или `.eachAsync`. Например, взяли несколько документов через [`.next`](#next) и остановились.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => Number, { required: true }) number!: number;
  @Prop(() => String, { required: true }) status!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Orders = client.db().model(Order);
// ---cut---
const cursor = Orders.find().sort({ number: 1 }).plain().cursor();
const first = await cursor.next();
await cursor.close();
console.log(first?.number);
// → 1
```

<Returns type="Promise<void>">

Промис без значения. Закрытие идемпотентно, повторный `.close` ошибкой не считается. Оно никогда не бросает ошибку, даже если сервер не смог закрыть курсор. После закрытия любое чтение (`.next`, `.toArray`, `for await`) бросает `QueryError` с текстом `the cursor is closed (close() or a left for-await); open a new one`.

</Returns>

Принимает ничего.

<FullType>

```ts
close(): Promise<void>
```

</FullType>

## EachAsyncError

`EachAsyncError` бросает [`.eachAsync`](#eachasync) с `continueOnError: true`, когда хотя бы один вызов функции завершился ошибкой. Она наследует общий класс ошибок Typemo. Все ошибки функции лежат в поле `errors` в порядке документов, а первая из них доступна и как `cause`.

<TypeTable
  type={{
    errors: { description: "Все ошибки, которые бросила функция, в порядке документов. Массив заморожен.", type: "readonly unknown[]" },
    cause: { description: "Первая из ошибок функции.", type: "unknown" },
    message: { description: "Текст `eachAsync: N call(s) of the callback failed (continueOnError)`, где `N` — число ошибок.", type: "string" },
  }}
/>

Без `continueOnError` `EachAsyncError` не бросается, вы получаете первую ошибку функции как есть. Класс описан и в справочнике ошибок — [`EachAsyncError`](../errors/query-errors.mdx#eachasyncerror).

## QueryCursor

`QueryCursor<T>` — тип курсора. Это интерфейс с методами `next`, `toArray`, `map`, `eachAsync` и `close` и с асинхронным обходом. Его возвращает [`.cursor()`](./reading.mdx#cursor), и им удобно описывать параметры функций, которые читают курсор. Функции неважно, какие строки внутри, главное — тип `T`.

За интерфейсом стоит класс `TypedCursor`. Он нужен, когда курсор надо собрать самому, например в тесте, чтобы подменить чтение из базы своими данными. Источник описывает тип `CursorSource<T>` — асинхронно итерируемый объект с необязательным методом `close`.

```ts twoslash
import { type CursorSource, type QueryCursor, TypedCursor } from "@venloc/typemo";
// ---cut---
const source: CursorSource<number> = {
  async *[Symbol.asyncIterator]() {
    yield 1;
    yield 2;
    yield 3;
  },
  close: async () => {},
};

const cursor: QueryCursor<number> = new TypedCursor(source);
const doubled = await cursor.map((n) => n * 2).toArray();
console.log(doubled);
// → [2, 4, 6]
```

Метод `close` источника вызывается один раз, когда курсор закрывается. Ошибок он бросать не должен, потому что закрытие курсора ошибок не бросает, а исключение из `close` проглатывается.

Параметры [`.eachAsync`](#eachasync) описывают два типа. `EachAsyncOptions` (`parallel`, `continueOnError`) подходит, когда функция получает документ. `EachAsyncBatchOptions` добавляет обязательный `batchSize` и подходит, когда она получает порцию. TypeScript сам выбирает нужную форму `fn`, с `batchSize` первым аргументом приходит массив.

<FullType>

```ts
interface CursorSource<T> extends AsyncIterable<T, void, undefined> {
  readonly close?: () => Promise<void>;
}

interface EachAsyncOptions {
  readonly parallel?: number;
  readonly continueOnError?: boolean;
}

interface EachAsyncBatchOptions extends EachAsyncOptions {
  readonly batchSize: number;
}

interface QueryCursor<T> extends AsyncIterable<T, void, undefined> {
  next(): Promise<T | null>;
  toArray(): Promise<T[]>;
  close(): Promise<void>;
  eachAsync(fn: (docs: T[], batchIndex: number) => unknown, options: EachAsyncBatchOptions): Promise<void>;
  eachAsync(fn: (doc: T, index: number) => unknown, options?: EachAsyncOptions): Promise<void>;
  map<U>(fn: (doc: T) => U): QueryCursor<U>;
}
```

</FullType>
