**Контракт** — это описание формы ответа. Вы пишете его сами, а Typemo сверяет с тем, что запрос возвращает на самом деле. Контракт нужен там, где форма ответа — договорённость с другим кодом, например тело ответа API, сообщение в очередь или вход для другого сервиса. Добавите в модель поле или измените запрос, и ответ незаметно не изменится, контракт этого не позволит. Проверка бывает двух видов. При компиляции [`.expect`](#expect) и [`Contract.check`](#contract.check) сравнивают тип результата с вашим описанием и во время работы ничего не стоят. Во время работы [`.parse`](#parse) прогоняет каждую строку через схему проверки данных.

Если вы только начинаете, сначала прочитайте руководство [Проверка формы ответа](../../queries/contracts.mdx). Эта страница — справочник.

Во всех примерах одна модель пользователя. У неё обязательное имя, необязательный возраст и скрытый хеш пароля.

```ts twoslash title="models/user.ts"
import { Entity, type Hidden, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "users" })
export class User extends Entity {
  @Prop(() => String, { required: true })
  name!: string;

  @Prop(() => Number)
  age?: number;

  @Prop(() => String, { hidden: true })
  passwordHash?: Hidden<string>;
}
```

В коллекции два пользователя — Alice (30 лет) и Bob (без возраста).

## .expect [#expect]

`.expect<Shape>()` сверяет строку результата с описанием `Shape` **точно**. Поля, необязательность, `null` и типы значений должны совпасть на любой глубине. Если всё совпало, запрос возвращается как был, а тип результата не меняется. Если нет, вызов не компилируется, и ошибка называет расхождение. Во время работы метод ничего не делает и ничего не стоит.

```ts twoslash
import { Contract, Entity, type Hidden, Prop, Schema, type Selected, type SelectedJson, type SelectedLean, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number) age?: number;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
type UserCard = Selected<User, "name">;

const cards = await Users.find().select({ name: 1 }).plain().expect<UserCard>();
console.log(cards.map((card) => card.name));
// → ["Alice", "Bob"]
```

`Selected<User, "name">` описывает строку результата `.plain()` с полем `name` и `_id`, который есть всегда. Запрос вернул ровно это, так что проверка проходит.

<Returns type="этот же запрос">

Тот же строитель, тип результата не меняется. Метод ничего не выполняет.

</Returns>

<Params>
<Param name="Shape" type="тип-параметр" required>

Ожидаемая строка. Подойдёт любой тип, чаще всего [`Selected`](#selected), [`SelectedLean`](#selected-lean) или [`SelectedJson`](#selected-json).

</Param>
</Params>

<FullType>

```ts
expect<Shape>(
  this: RowsOnly<Form, ExpectRows<ResultDoc<T, S, E, Form, N, X>, Shape>, "expect<Shape>() checks rows: …">,
): QueryBuilder<T, Op, S, E, Form, Found, N, X>
```

</FullType>

### Что показывает ошибка [#error-contents]

Ошибка называет три вида расхождений. `missing` — поле есть в контракте, но нет в результате. `extra` — поле есть в результате, но нет в контракте. `mismatch` — поле есть в обоих, но тип, `null` или необязательность разные. Пути идут через точку, элемент массива записывается как `[]`, а сам результат — как `(root)`.

`extra` всегда считается ошибкой. Присваивание значения с лишним полем TypeScript молча отбросил бы, а контракт нужен как раз затем, чтобы лишнее поле не попало в ответ незамеченным. Допустим, запрос выбрал ещё и `age`, а контракт о нём не знает.

```ts twoslash
import { Contract, Entity, type Hidden, Prop, Schema, type Selected, type SelectedJson, type SelectedLean, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number) age?: number;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
type UserCard = Selected<User, "name">;

// @errors: 2684
await Users.find().select({ name: 1, age: 1 }).plain().expect<UserCard>();
```

### Только для lean и plain [#expect.lean-and-plain-only]

Контракт описывает данные, а документ — это объект с методами. Поэтому `.expect` работает у `.lean()` и `.plain()`, а у документа не компилируется. Для документа сверяйте результат его метода — `Contract.check<Shape>()(doc.$toPlain())`, см. [`Contract.check`](#contract.check).

## .parse [#parse]

`.parse(schema)` проверяет каждую строку **во время работы**. Он защищает от данных, которые в базе не такие, как обещает тип. Их могли записать старая версия приложения, скрипт или драйвер напрямую. Подойдёт любая схема по стандарту Standard Schema (zod, valibot, arktype или своя), то есть объект с полем `"~standard"`. Результатом запроса станет то, что вернула схема, ведь она может не только проверять строки, но и преобразовывать их.

Ниже своя схема на несколько строк. Она требует имя не короче четырёх символов и переводит его в верхний регистр. С библиотекой проверки данных всё выглядит так же, вы передаёте её схему.

```ts twoslash
import { Contract, Entity, type Hidden, Prop, Schema, type Selected, type SelectedJson, type SelectedLean, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number) age?: number;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
const nameRow = {
  "~standard": {
    version: 1 as const,
    vendor: "app",
    validate: (value: unknown) => {
      const row = value as { name?: unknown };
      if (typeof row.name !== "string" || row.name.length < 4) {
        return { issues: [{ message: "name is too short", path: ["name"] }] };
      }
      return { value: { name: row.name.toUpperCase() } };
    },
    types: undefined as unknown as { input: unknown; output: { name: string } },
  },
};

const rows = await Users.find({ name: "Alice" }).plain().parse(nameRow);
//    ^?
console.log(rows);
// → [{ name: "ALICE" }]
```

<Returns type="ParsedQuery">

Запрос, который после `await` даёт результат схемы. Для `find` это массив, для `findOne` — строка или `null`. Если ничего не найдено, `null` остаётся `null` и схемой не проверяется. Запрос завершающий. У него есть `exec`, `cursor` (для списков) и `expect`, других методов строителя нет, потому что запрос фиксируется до разбора.

</Returns>

<Params>
<Param name="schema" type="Standard Schema" required>

Схема стандарта Standard Schema. Асинхронная схема допустима, Typemo дожидается её. Если передан не такой объект, он бросает `QueryError` с текстом `parse: a Standard Schema v1 validator (an object with "~standard": { version: 1, validate })`.

</Param>
</Params>

<FullType>

```ts
parse<Sch extends AnyStandardSchema>(
  this: RowsOnly<Form, unknown, "parse() validates rows: call .lean() or .plain() before .parse(schema)">,
  schema: Sch,
): ParsedQuery<QueryResult<Many<Op>, Found, StandardSchemaOutput<Sch>>, StandardSchemaOutput<Sch>, Many<Op>>
```

</FullType>

### Ошибка проверки [#validation-error]

Если строка не прошла схему, запрос завершается [`ValidationError`](../errors/data-errors.mdx#validation-error). Ошибка одна на весь запрос и содержит замечания по всем строкам, а путь начинается с номера строки. Bob без имени нужной длины стоит вторым, поэтому его путь начинается с `1`.

```ts twoslash
import { Contract, Entity, type Hidden, Prop, Schema, type Selected, type SelectedJson, type SelectedLean, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number) age?: number;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
declare const nameRow: { "~standard": { version: 1; vendor: string; validate: (value: unknown) => { value: { name: string } } | { issues: { message: string; path: string[] }[] }; types: { input: unknown; output: { name: string } } } };
// ---cut---
try {
  await Users.find().sort({ name: 1 }).lean().parse(nameRow);
} catch (error) {
  console.log(String(error));
  // → 'ValidationError: Validation failed: "1.name": row 1: name is too short [schema]'
}
```

### Курсор [#cursor]

У `.parse` для списков есть [`.cursor()`](./cursor.mdx). Строки проверяются по мере чтения, и первая неверная завершает чтение ошибкой `ValidationError` с номером строки в потоке. Курсор при этом закрывается.

### Только для lean и plain [#parse.lean-and-plain-only]

Документ — не «просто данные», поэтому `.parse` работает у `.lean()` и `.plain()`. У документа метод не компилируется, а вызов из кода без типов бросает `QueryError`.

```text
QueryError: parse() validates rows: call .lean() or .plain() before .parse(schema)
```

### Когда `.parse` не подходит [#when-not-to-use]

Если вы доверяете данным в базе и вам нужно лишь зафиксировать форму ответа, проверки во время работы лишние. Берите [`.expect`](#expect), он бесплатен. Схемы полей модели проверяют записываемые данные, а не читаемые. Строки при чтении сам Typemo не проверяет.

## Contract.check [#contract.check]

`Contract.check<Shape>()(value)` сверяет значение с описанием при компиляции. Он возвращает то же значение, но с типом `Shape`. Если тип значения не совпал с `Shape` точно, вызов не компилируется. Это тот же вид проверки, что у [`.expect`](#expect), но для любого значения, а не только для результата запроса. Особенно удобен он для документов — `Contract.check<Shape>()(doc.$toPlain())`.

```ts twoslash
import { Contract, Entity, type Hidden, Prop, Schema, type Selected, type SelectedJson, type SelectedLean, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number) age?: number;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
const alice = await Users.findOne({ name: "Alice" }).orFail();

type AliceJson = SelectedJson<User, "name" | "age">;
const json = Contract.check<AliceJson>()(alice.$toJSON());
//    ^?
console.log(json.name, json.age);
// → "Alice" 30
```

Скобок две намеренно. Первая фиксирует ожидаемый тип, вторая принимает значение, и TypeScript выводит его тип сам.

<Returns type="Shape">

Само переданное значение, без копирования и проверок во время работы.

</Returns>

<FullType>

```ts
class Contract {
  static check<Expected>(): <V>(
    value: V & (ContractCheck<V, Expected> extends true ? unknown : ContractCheck<V, Expected>),
  ) => Expected
}
```

</FullType>

## Selected [#selected]

`Selected<Entity, Fields, Overrides>` описывает строку, которую возвращают [`.plain()`](./reading.mdx#plain) и `$toPlain()`. `_id` включён по умолчанию и в результате `.plain()` это строка. `"-_id"` среди полей его убирает. Поля перечисляются по именам, у необязательных необязательность сохраняется.

```ts twoslash
import { Contract, Entity, type Hidden, Prop, Schema, type Selected, type SelectedJson, type SelectedLean, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number) age?: number;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
type Row = Selected<User, "name" | "age">;
//   ^?

type WithoutId = Selected<User, "name" | "-_id">;
//   ^?
```

Третий параметр, `Overrides`, нужен для полей, форма которых зависит от запроса. Это виртуальные ссылки, которые заполняются через `populate`, и вложенные документы. В нём вы задаёте форму заполненного поля, например `{ author: Selected<User, "name" | "-_id"> }`. Ключ переопределения должен быть одним из выбранных полей.

<FullType>

```ts
type Selected<
  Entity,
  Fields extends SelectedFields<Entity>,
  Overrides extends SelectedOverrides<Fields, Overrides> = Record<never, never>,
> = Simplify<IdPart<…> & Plain<Pick<Entity, …>> & VirtualPart<…> & OverridePart<…> & VirtualWithoutOverride<…>>
```

</FullType>

`SelectedFields` — имена, которые можно выбрать. Это поля данных, виртуальные ссылки (с переопределением), геттер-виртуальные поля и `"-_id"`. `SelectedOverrides` ограничивает параметр `Overrides`. Ключ вне выбранных полей превращается в читаемую ошибку `the override "…" is not one of the selected fields`.

## SelectedLean [#selected-lean]

`SelectedLean<Entity, Fields, Overrides>` описывает то же для результата `.lean()`. Значения в нём такие, как их отдаёт драйвер — `_id` это `ObjectId`, 64-битные числа — `bigint`, поля-`Map` — объекты. Геттер-виртуальных полей у результата `.lean()` нет. Сверяйте с `.lean().expect<…>()`.

```ts twoslash
import { Contract, Entity, type Hidden, Prop, Schema, type Selected, type SelectedJson, type SelectedLean, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number) age?: number;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
type Row = SelectedLean<User, "name" | "-_id">;
//   ^?

const rows = await Users.find().select({ name: 1, _id: 0 }).lean().expect<Row>();
console.log(rows.length);
// → 2
```

<FullType>

```ts
type SelectedLean<
  Entity,
  Fields extends SelectedLeanFields<Entity>,
  Overrides extends SelectedOverrides<Fields, Overrides> = Record<never, never>,
> = Simplify<IdPart<…> & Lean<Pick<Entity, …>> & OverridePart<…> & VirtualWithoutOverride<…>>
```

</FullType>

`SelectedLeanFields` — допустимые имена для контракта `.lean()`. Они те же, что у `SelectedFields`, но без геттер-виртуальных.

## SelectedJson [#selected-json]

`SelectedJson<Entity, Fields, Overrides>` описывает то же для результата `$toJSON()`. Идентификаторы, даты, 64-битные числа и `Decimal128` в нём строки, а `Map` — объект. Берите его для ответов API, которые вы собираете из документа.

```ts twoslash
import { Contract, Entity, type Hidden, Prop, Schema, type Selected, type SelectedJson, type SelectedLean, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number) age?: number;
  @Prop(() => String, { hidden: true }) passwordHash?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Users = client.db().model(User);
// ---cut---
type UserJson = SelectedJson<User, "name" | "age">;
//   ^?
```

<FullType>

```ts
type SelectedJson<
  Entity,
  Fields extends SelectedJsonFields<Entity>,
  Overrides extends SelectedOverrides<Fields, Overrides> = Record<never, never>,
> = Simplify<IdPart<…> & PlainJson<Pick<Entity, …>> & VirtualPart<…> & OverridePart<…> & VirtualWithoutOverride<…>>
```

</FullType>

`SelectedJsonFields` — допустимые имена, те же, что у `SelectedFields`.

## Остальные типы [#other-types]

`ContractCheck<Actual, Expected>` лежит в основе всех проверок. Он даёт `true`, если типы совпали точно, и иначе отчёт вида `{ missing: "email"; extra: "password" }`. `ContractMismatch` — сам отчёт, `ExpectRows` — параметр `this` метода `.expect`, `ContractArgumentError` — читаемая ошибка неверного аргумента контракта. Вручную их обычно не пишут, они видны в подсказках редактора и в текстах ошибок.
