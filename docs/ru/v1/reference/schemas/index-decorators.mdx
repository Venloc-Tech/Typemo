Индекс по одному полю задаёт опция поля — [`index`](./prop.mdx#index), [`unique`](./prop.mdx#unique), [`expires`](./prop.mdx#expires) или [`text`](./prop.mdx#text). Всё остальное описывают декораторы класса. `@Index` отвечает за обычные индексы MongoDB — составные, частичные, с временем жизни, текстовые, wildcard. `@SearchIndex` отвечает за индексы Atlas Search и векторного поиска. Эта страница уточняет их опции и правила проверки.

Руководство с задачами — [Индексы](../../schemas/indexes.mdx). Эта страница — справочник.

В примерах модель заметки с владельцем, датой, почтой, признаком активности, заголовком и текстом. Результаты в `// →` получены на настоящей MongoDB.

## @Index [#index]

`@Index(поля, опции?)` объявляет индекс класса. Первый аргумент — объект `{ путь: направление }`, ключи идут в порядке ключей индекса. Направление — `1` (по возрастанию), `-1` (по убыванию), `"hashed"`, `"text"`, `"2dsphere"` или `"2d"`. Компилятор сверяет пути с классом, в том числе в `partialFilterExpression`, `weights` и `wildcardProjection`. Опечатка не пройдёт компиляцию, и явный тип `<Note>` не нужен. Декоратор повторяемый, каждое применение добавляет ещё один индекс. Одинаковые индексы объединяются. Два индекса с одним именем или ключами и разными опциями дают `ConfigurationError` (`two indexes named or keyed "by_owner" with different definitions`).

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Index({ owner: 1, createdAt: -1 }, { name: "by_owner" }) // [!code highlight]
@Schema()
class Note extends Entity {
  @Prop(() => String) owner?: string;
  @Prop(() => Date) createdAt?: Date;
}
const Notes = client.db().model(Note);
console.log(Notes.schema.describe().indexes);
// → [{ keys: { owner: 1, createdAt: -1 }, options: { name: "by_owner" } }]
```

Опечатка в имени поля останавливает компиляцию, и сообщение называет путь.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
// @errors: 1238
@Index({ ownr: 1 })
@Schema()
class Note extends Entity {
  @Prop(() => String) owner?: string;
}
```

Текст сообщения — `@Index: "ownr" is not a field of the class`. Индексы создаются при [`connection.init()`](../connection/connection.mdx#connection.init) и [`connection.syncAll()`](../connection/connection.mdx#connection.sync-all), если не выключена опция [`autoIndex`](./schema.mdx#auto-index). Сама модель индексы не строит. Созданные индексы совпали с объявленными — сервер показал `by_owner`, `email_active`, `ttl` и остальные с теми же ключами и опциями.

## name [#name]

`name` — имя индекса. Без него сервер выберет имя по ключам, например `owner_1_createdAt_-1`. Своё имя пригодится, если на индекс ссылается подсказка запроса или миграция.

---

## unique [#unique]

`unique: true` не пускает в коллекцию два документа с одинаковым значением ключа. Запись, которая нарушит ограничение, даст [`DuplicateKeyError`](../errors/server-errors.mdx#duplicate-key-error). В отличие от `unique` на поле, `@Index` не проверяет `required`. Для необязательного поля добавьте `partialFilterExpression`, чтобы документы без значения не попали в индекс.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Index({ email: 1 }, { unique: true, partialFilterExpression: { active: true }, name: "email_active" }) // [!code highlight]
@Schema()
class Account extends Entity {
  @Prop(() => String) email?: string;
  @Prop(() => Boolean) active?: boolean;
}
const Accounts = client.db().model(Account);
console.log(Accounts.schema.describe().indexes);
// → [{ keys: { email: 1 }, options: { unique: true, partialFilterExpression: { active: true }, name: "email_active" } }]
```

## sparse [#sparse]

`sparse: true` индексирует только документы, в которых поле есть. С `partialFilterExpression` его сочетать нельзя, будет `ConfigurationError` (`@Index({"a":1}): "sparse" and "partialFilterExpression" cannot be combined (server rule)`). Для новых индексов берите `partialFilterExpression`, он выражает то же и даже больше.

---

## partialFilterExpression [#partial-filter-expression]

`partialFilterExpression` — фильтр, по которому в индекс попадают только подходящие документы. Индекс получается меньше, а уникальность действует только среди этих документов. Сервер принимает не любой фильтр. Допустимы равенство, `$exists: true`, `$gt`, `$gte`, `$lt`, `$lte`, `$type`, `$in` и `$and`/`$or` на верхнем уровне. Тип `PartialFilter` в Typemo описывает именно этот набор. Пути проверяются по классу, и неизвестный путь даёт ошибку компиляции (`@Index: partialFilterExpression "zz" is not a field of the class`) и ошибку сборки (`partialFilterExpression "zz" is not a field of the class`).

---

## expireAfterSeconds [#expire-after-seconds]

`expireAfterSeconds` — время жизни документов в секундах после значения даты. Это индекс TTL, по нему MongoDB сама удаляет старые документы. Индекс должен быть **по одному полю типа `Date`**, иначе будет `ConfigurationError` (`@Index({"a":1}): expireAfterSeconds (TTL) needs a single-field index on a Date field`). Для TTL по одному полю проще опция поля [`expires`](./prop.mdx#expires).

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Index({ lastSeen: 1 }, { expireAfterSeconds: 60, name: "ttl" }) // [!code highlight]
@Schema()
class Session extends Entity {
  @Prop(() => Date) lastSeen?: Date;
}
const Sessions = client.db().model(Session);
console.log(Sessions.schema.describe().indexes);
// → [{ keys: { lastSeen: 1 }, options: { expireAfterSeconds: 60, name: "ttl" } }]
```

## collation [#collation]

`collation` — правила сравнения строк в индексе, то есть язык, регистр и акценты. Индекс без своих правил наследует правила коллекции ([`collation`](./schema.mdx#collation) схемы). Текстовые индексы и `2d` сортировку не поддерживают, поэтому при сортировке коллекции объявляйте их с `collation: { locale: "simple" }`. Иначе будет `ConfigurationError`.

---

## weights [#weights]

`weights` — веса полей **текстового** индекса. Чем больше вес, тем важнее совпадение в этом поле. Ключи — поля класса (`@Index: weights."x" is not a field of the class`). Текстовый индекс в коллекции один. Поля с `text: true` и текстовый `@Index` вместе дают `ConfigurationError`.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Index({ title: "text", body: "text" }, { weights: { title: 5 }, default_language: "english", name: "search" }) // [!code highlight]
@Schema()
class Article extends Entity {
  @Prop(() => String) title?: string;
  @Prop(() => String) body?: string;
}
const Articles = client.db().model(Article);
console.log(Articles.schema.describe().indexes);
// → [{ keys: { title: "text", body: "text" }, options: { weights: { title: 5 }, default_language: "english", name: "search" } }]
```

Сервер построил индекс с весами `title: 5` и `body: 1`. Ключи текстового индекса он хранит в служебной форме (`_fts`, `_ftsx`), а вес по умолчанию записывает сам. Typemo это учитывает. Второй вызов [`connection.init()`](../connection/connection.mdx#connection.init) на такой модели ничего не создаёт и не падает.

### default_language [#default-language]

Язык текстового индекса по умолчанию. Он задаёт правила основ слов и стоп-слова.

### language_override [#language-override]

Поле документа, значение которого переопределяет язык для этого документа.

## wildcardProjection [#wildcard-projection]

`wildcardProjection` задаёт, какие пути включить (`1`) или исключить (`0`) из wildcard-индекса `{ "$**": 1 }`. Ключи — поля класса.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Index({ "$**": 1 }, { wildcardProjection: { title: 1 }, name: "wild" }) // [!code highlight]
@Schema()
class Article extends Entity {
  @Prop(() => String) title?: string;
}
const Articles = client.db().model(Article);
console.log(Articles.schema.describe().indexes);
// → [{ keys: { "$**": 1 }, options: { wildcardProjection: { title: 1 }, name: "wild" } }]
```

---

## hidden [#hidden]

`hidden: true` прячет индекс от планировщика запросов, но не удаляет, и индекс продолжает обновляться. Так проверяют, что будет без индекса, прежде чем его удалить.

---

## @SearchIndex [#search-index]

`@SearchIndex({ name, type?, definition })` объявляет индекс Atlas Search или векторного поиска. Декоратор только записывает описание, а сам индекс создаётся на сервере при синхронизации. Обычный `mongod` таких индексов не поддерживает. [`connection.init()`](../connection/connection.mdx#connection.init) на нём бросает [`SyncError`](../errors/configuration-errors.mdx#sync-error), а в списке сбоев лежит ответ сервера `SearchNotEnabled` (код 31082) — для команд Atlas Search нужна дополнительная настройка. На Atlas это не проверялось.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@SearchIndex({ name: "default", definition: { mappings: { dynamic: true } } }) // [!code highlight]
@Schema()
class Article extends Entity {
  @Prop(() => String) title?: string;
}
```

<Params>
<Param name="options.name" type="string" required>

Имя индекса.

</Param>
<Param name="options.type" type="&quot;search&quot; | &quot;vectorSearch&quot;" default="&quot;search&quot;">

Вид индекса — полнотекстовый или векторный.

</Param>
<Param name="options.definition" type="Record<string, unknown>" required>

Описание индекса в том виде, в каком его ждёт Atlas API. Содержимое Typemo не проверяет.

</Param>
</Params>

В описании схемы ([`describe()`](./schema-info.mdx#describe)) поисковые индексы лежат в отдельном поле `searchIndexes`, а не в `indexes`. Там имя и определение в порядке объявления.

## Когда не подходит [#when-not-to-use]

Индекс по одному полю проще объявить опцией поля ([`index`](./prop.mdx#index), [`unique`](./prop.mdx#unique)). Typemo запрещает уникальность на необязательном поле без `sparse`, и `@Index` с `partialFilterExpression` — правильный способ это обойти. Настройки коллекции целиком живут в [`@Schema`](./schema.mdx#schema).
