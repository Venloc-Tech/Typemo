Схема модели описывает данные один раз, а отдавать её можно в двух форматах. **JSON Schema** — это формат, которым сервер MongoDB проверяет документы. `JsonSchemaGenerator` строит его из схемы. **Standard Schema** — общий интерфейс проверки, который понимают формы, tRPC и другие библиотеки. `StandardSchema` даёт его для моделей и принимает чужой (zod, valibot, arktype), чтобы проверять строки результата. Загляните сюда, если нужно узнать, что попадёт в валидатор и как работает `~standard`.

Руководство с задачами — [JSON Schema и Standard Schema](../../schemas/json-and-standard-schema.mdx). Эта страница — справочник.

Примеры берут модель пользователя с обязательным именем и ролью из двух значений. Результаты в `// →` сняты с реального запуска.

Методы `JsonSchemaGenerator` и `StandardSchema.of` принимают **источник схемы** `SchemaSource`. Это модель, полученная от подключения (`client.db().model(User)`), или её свойство `schema`. Результат в обоих случаях одинаковый. Класс без модели, пустой объект и `null` не подойдут. Сообщение называет, что ожидалось (`JsonSchemaGenerator.generate: a model (connection.model(Entity)) or its schema (model.schema) is expected, got object`).

## JsonSchemaGenerator [#json-schema-generator]

`JsonSchemaGenerator` строит из схемы документ `$jsonSchema`. Это подмножество JSON Schema, которое понимает сервер MongoDB (в нём `bsonType` вместо `type`). Сервер применяет его как валидатор коллекции и отвергает документы, нарушающие схему, **даже если их пишет другая программа**. Проверки Typemo никуда не деваются. Валидатор — второй рубеж, а не замена.

Валидатор создаёт опция [`validator`](./schema.mdx#validator) схемы, и в коллекции оказывается ровно то, что построил генератор. Вот что получит сервер для модели с ограничениями.

```ts twoslash
import { CollectionNaming, Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, StandardSchema, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
}
@Schema({ collection: "users", validator: true }) // [!code highlight]
class User extends Entity {
  @Prop(() => String, { required: true, minLength: 2, maxLength: 10, match: /^[a-z]+$/ }) name!: string;
  @Prop(() => Number, { min: 0, max: 150 }) age?: number;
  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" }) role!: Defaulted<"user" | "admin">;
  @Prop(() => String, { nullable: true }) nickname?: string | null;
  @Prop(() => [String]) tags?: string[];
  @Prop(() => Address) address?: Address;
  @Prop(() => BigInt) big?: bigint;
}
```

Получившийся документ.

```json
{
  "bsonType": "object",
  "properties": {
    "_id": { "bsonType": "objectId" },
    "name": { "bsonType": "string", "minLength": 2, "maxLength": 10, "pattern": "^[a-z]+$" },
    "age": { "bsonType": ["int", "double", "long"], "minimum": 0, "maximum": 150 },
    "role": { "bsonType": "string", "enum": ["user", "admin"] },
    "nickname": { "bsonType": ["string", "null"] },
    "tags": { "bsonType": "array", "items": { "bsonType": "string" } },
    "address": {
      "bsonType": "object",
      "properties": { "city": { "bsonType": "string" } },
      "required": ["city"],
      "additionalProperties": false
    },
    "big": { "bsonType": "long" }
  },
  "required": ["_id", "name"],
  "additionalProperties": false
}
```

Правила построения видны в результате. `bsonType` берётся из типа поля, а `"null"` добавляется только полям с `nullable` (в Mongoose null был допустим у каждого вложенного объекта). `required` собирается из явных `required: true` и `_id`. Строгость абсолютная — `additionalProperties: false` стоит на каждом уровне, и лишнее поле сервер отвергнет. `enum`, `minimum`/`maximum` и `minLength`/`maxLength` переносятся как есть. `pattern` появляется только для регулярного выражения без флагов. У иерархии дискриминаторов документ строится через `oneOf` по корню и каждому наследнику, а вариант выбирает `enum` со значением дискриминатора.

Сервер **не** умеет выражать собственные функции [`validate`](./prop.mdx#validate), границы дат, число измерений вектора и правила ключей Map. Эти проверки делает только Typemo.

### JsonSchemaGenerator.generate [#json-schema-generator.generate]

`generate(source)` возвращает узел `$jsonSchema` (тип `BsonJsonSchema`) для схемы модели. Передайте модель или её `schema`.

<Params>
<Param name="source" type="SchemaSource" required>

Модель (`connection.model(Entity)`) или её `schema`. Что-то другое даёт `ConfigurationError`.

</Param>
</Params>

<Returns type="BsonJsonSchema">

Объект `$jsonSchema` с ключами `bsonType`, `properties`, `required`, `additionalProperties`, `items`, `enum`, `minimum`, `maximum`, `minLength`, `maxLength`, `pattern`, `oneOf` и `description`.

</Returns>

С моделью и с её `schema` результат один и тот же. Класс вместо модели компилятор не пропустит — `JsonSchemaGenerator.generate(User)` даёт ошибку типа.

```ts twoslash
import { Entity, JsonSchemaGenerator, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true, minLength: 2 }) name!: string;
}
const Users = client.db().model(User);
const fromModel = JsonSchemaGenerator.generate(Users); // [!code highlight]
const fromSchema = JsonSchemaGenerator.generate(Users.schema); // [!code highlight]
console.log(JSON.stringify(fromModel) === JSON.stringify(fromSchema), fromModel.required);
// → true ["_id", "name"]
```

### JsonSchemaGenerator.validator [#json-schema-generator.validator]

`validator(source)` возвращает то, что остаётся передать серверу — `{ validator: { $jsonSchema }, validationLevel, validationAction }` (тип `CollectionValidator`). Уровень и действие берутся из опций схемы `validationLevel` и `validationAction`. По умолчанию это `strict` и `error`.

<FullType>

```ts
class JsonSchemaGenerator {
  static generate(source: SchemaSource): BsonJsonSchema;
  static validator(source: SchemaSource): CollectionValidator;
}

type SchemaSource = SchemaInfo | { readonly schema: SchemaInfo };
```

</FullType>

## StandardSchema [#standard-schema]

`StandardSchema` — адаптер между схемой Typemo и интерфейсом Standard Schema v1. Он работает в обе стороны.

**Наружу.** Каждая модель сама служит Standard Schema, а её свойство `~standard` типизировано моделью. Вход — `CreateInput`, выход — `DataFields`. Форма или tRPC-процедура, которая умеет читать Standard Schema, проверит данные приведением типов и валидаторами модели и ничего не узнает о Typemo. Проверка приводит типы строгими каскадами, подставляет значения по умолчанию, запускает `required` и все `validate`. Асинхронные `validate` тоже работают, тогда результат приходит как `Promise`. В ответе будет либо приведённое значение, либо **все** найденные проблемы.

```ts twoslash
import { CollectionNaming, Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, StandardSchema, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true, trim: true, lowercase: true, minLength: 3 })
  name!: string;
  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" })
  role!: Defaulted<"user" | "admin">;
}
const Users = client.db().model(User);
const standard = Users["~standard"];
console.log(standard.version, standard.vendor);
// → 1 typemo
const good = await standard.validate({ name: " Zed " });
console.log(good);
// → { value: { _id: "…", name: "zed", role: "user" } }
const bad = await standard.validate({ name: "a" });
console.log(bad);
// → { issues: [{ message: "must be at least 3 characters long", path: ["name"] }] }
```

Значение `_id` в результате придумывает ядро прямо во время проверки, поэтому в комментарии оно сокращено. Служебные поля, которые ядро заполняет при сохранении (метки времени, версию), проверка не требует. Путь проблемы — список ключей, а индексы массива в нём числа.

**Внутрь.** Запросы `.parse(schema)` у запросов с `.lean()`, агрегаций и курсоров проверяют каждую строку любым Standard Schema (zod, valibot, arktype). Ядро от этих библиотек не зависит. Проблемы собираются в один [`ValidationError`](../errors/data-errors.mdx#validation-error) с причиной `schema`. Чужие схемы внутри `@Prop` не принимаются.

<Returns type="StandardSchemaV1<Input, Output>">

Объект со свойством `~standard`. В нём `version: 1`, `vendor: "typemo"`, метод `validate(value)` и типовое поле `types`.

</Returns>

### StandardSchema.of [#standard-schema.of]

`of(source)` создаёт валидатор Standard Schema для входа документов схемы — тот самый, что лежит в `~standard` модели. Он принимает модель или её `schema`, так что `StandardSchema.of(Users)` и `StandardSchema.of(Users.schema)` дают одинаковый валидатор. Любой другой аргумент вызывает `ConfigurationError` (`StandardSchema.of: a model (connection.model(Entity)) or its schema (model.schema) is expected, got null`).

### StandardSchema.isSchema [#standard-schema.is-schema]

`isSchema(value)` — предикат. Он возвращает `true` для объекта или функции со свойством `~standard`, у которого `version` равен `1`, а `validate` — функция. Тем же предикатом проверяется аргумент `.parse`.

```ts twoslash
import { CollectionNaming, Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, StandardSchema, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true, trim: true, lowercase: true, minLength: 3 })
  name!: string;
  @Prop(() => String, { enum: ["user", "admin"] as const, default: "user" })
  role!: Defaulted<"user" | "admin">;
}
const Users = client.db().model(User);
console.log(StandardSchema.isSchema(Users), StandardSchema.isSchema({}));
// → true false
```

### StandardSchema.require [#standard-schema.require]

`require(schema, where)` возвращает аргумент как Standard Schema или бросает [`QueryError`](../errors/query-errors.mdx#query-error) с текстом `<where>: a Standard Schema v1 validator (an object with "~standard": { version: 1, validate })`.

<Params>
<Param name="schema" type="unknown" required>

Проверяемый аргумент.

</Param>
<Param name="where" type="string" required>

Название вызова для текста ошибки.

</Param>
</Params>

### StandardSchema.validateRows [#standard-schema.validate-rows]

`validateRows(schema, rows, indexed, offset?)` проверяет строки чужой схемой. Он возвращает выходные значения или бросает один `ValidationError` со всеми проблемами всех строк. При `indexed` равном `true` путь проблемы начинается с индекса строки, а текст — со слов `row N:`. Синхронные схемы остаются синхронными, асинхронные ждут все вместе. Если схема бросила исключение, отклонила промис или ответила не объектом, будет `QueryError` (`parse: the Standard Schema (vendor) threw instead of reporting issues`).

<Params>
<Param name="schema" type="AnyStandardSchema" required>

Валидатор, которым проверяются строки.

</Param>
<Param name="rows" type="readonly unknown[]" required>

Строки.

</Param>
<Param name="indexed" type="boolean" required>

Начинать ли пути проблем с индекса строки.

</Param>
<Param name="offset" type="number" default="0">

Индекс первой строки. Он прибавляется к индексам в путях.

</Param>
</Params>

### StandardSchema.issue [#standard-schema.issue]

`issue(issue)` переводит проблему Typemo (`SchemaIssue`) в формат Standard Schema — `{ message, path }`.

### StandardSchema.vendor [#standard-schema.vendor]

`StandardSchema.vendor` — строка `"typemo"`, имя поставщика в `~standard.vendor`.

<FullType>

```ts
class StandardSchema {
  static readonly vendor: "typemo";
  static of<Input = unknown, Output = Record<string, unknown>>(source: SchemaSource): StandardSchemaV1<Input, Output>;
  static issue(issue: SchemaIssue): StandardSchemaIssue;
  static isSchema(value: unknown): value is AnyStandardSchema;
  static require(schema: unknown, where: string): AnyStandardSchema;
  static validateRows(schema: AnyStandardSchema, rows: readonly unknown[], indexed: boolean, offset?: number): unknown[] | Promise<unknown[]>;
}
```

</FullType>

## Типы [#types]

Экспортируются `SchemaSource` (модель или её `schema`, аргумент генератора и `StandardSchema.of`), `StandardSchemaV1`, `AnyStandardSchema`, `StandardSchemaProps`, `StandardSchemaResult` и `StandardSchemaIssue`. Ещё есть `StandardSchemaInput` и `StandardSchemaOutput`, по ним выводятся вход и выход валидатора. Рядом лежат `BsonJsonSchema` и `CollectionValidator`.

## Когда не подходит [#when-not-to-use]

Если валидатор нужен на сервере, не вызывайте генератор вручную. Включите [`validator`](./schema.mdx#validator) в `@Schema`. Генератор пригодится, чтобы посмотреть или проверить в тесте, что уйдёт серверу. Для проверки данных до записи в самом приложении вызывайте `~standard.validate` или методы модели. Простой JSON Schema (draft 2020-12) Typemo не экспортирует, генератор выдаёт только диалект MongoDB.
