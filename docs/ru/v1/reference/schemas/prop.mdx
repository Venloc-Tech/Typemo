`@Prop` объявляет поле модели. Он говорит, какого типа значение лежит в базе и по каким правилам Typemo его принимает, проверяет и отдаёт. Здесь описаны сам декоратор и **все** его опции, каждая в своём разделе. Откройте страницу, когда нужно уточнить, что делает опция, к каким типам она применима и что будет при ошибке.

Первую модель удобнее начать с руководства [Описать модель](../../schemas/define-model.mdx). Оно объясняет, откуда берётся тип поля и как модель связана с коллекцией. Эта страница — справочник.

Примеры берут маленькие модели с одной-двумя опциями. Результаты в комментариях `// →` взяты с настоящей MongoDB. Примеры `hidden`, `ref`, `refPath` и `refModel` читают документы, созданные заранее — пользователя `gina` с хешем `h`, автора `Ann` и бота `R2`.

## @Prop [#prop]

`@Prop(() => Тип, опции)` записывает поле в описание класса. Первый аргумент — **функция, возвращающая рантайм-тип**, например `() => String`, `() => [Address]` или `() => Types.ObjectId`. Тип нужно указать явно на каждом поле. Typemo не читает метаданные `design:type`, потому что они не различают `int32` и `double`, не знают элемент массива и путают `null` с отсутствием. Функция нужна, чтобы класс из конца файла или другого модуля успел появиться к сборке схемы.

Опции и тип поля проверяются дважды. Сначала компилятор сверяет опции с типом, который вы написали в классе. `hidden: true` требует `Hidden<T>`, `default` требует `Defaulted<T>`, `nullable: true` требует `| null` и наоборот. Вторая проверка идёт при сборке модели в [`client.db().model(...)`](../connection/connection.mdx). Она ловит то же самое для кода без типов и правила, которые компилятору не по силам, например `min` больше `max`. Нарушение — [`ConfigurationError`](../errors/configuration-errors.mdx#configuration-error) с именем класса и поля.

<Snippet id="reference/schemas/prop/prop" twoslash />

<Returns type="PropDecorator<S, O>">

Декоратор свойства. Он только записывает поле в описание класса, а схему собирает [`model`](../connection/connection.mdx). На статическом члене, методе или аксессоре он сразу бросает `ConfigurationError`.

</Returns>

<Params>
<Param name="type" type="() => TypeSpec" required>

Функция, возвращающая рантайм-тип поля. Это конструктор (`String`, `Number`, `Boolean`, `Date`, `BigInt`, `RegExp`), класс из [`Types`](./types-and-spec.mdx#types), класс с [`@Schema`](./schema.mdx#schema), массив `[X]` или результат [`Spec`](./types-and-spec.mdx#spec). `Set`, `Map`, `Array` и `Object` не поддерживаются. Вместо них есть `[X]` и `Spec.map(X)`.

</Param>

Опции поля. Какие из них допустимы, зависит от типа (см. таблицу ниже). Опция, которой у типа нет, — ошибка компиляции на ключе, а в коде без типов — `ConfigurationError`.

</Param>

### Какие опции к каким типам применимы [#options-by-type]

Общие опции принимает любое поле. Остальные зависят от типа значения. У массива опции типа элемента относятся к элементам, а `text` и `expires` остаются на самом массиве.

| Тип поля | Общие | Дополнительно |
|---|---|---|
| все типы | `required`, `nullable`, `default`, `immutable`, `hidden`, `sensitive`, `dbName`, `index`, `unique`, `sparse`, `validate`, `get`, `set`, `ext` | — |
| `String` | общие | `enum`, `lowercase`, `uppercase`, `trim`, `match`, `minLength`, `maxLength`, `text`, `ref`, `refPath`, `refModel` |
| `Number`, `Types.Double`, `Types.Int32` | общие | `enum`, `min`, `max`, `ref`, `refPath`, `refModel` |
| `BigInt` | общие | `min`, `max` |
| `Date` | общие | `min`, `max`, `expires` |
| `Types.ObjectId`, `Types.UUID` | общие | `ref`, `refPath`, `refModel` |
| класс с `@Schema` | общие | `excludeIndexes` |
| `Spec.map(X)` из строк, чисел, `ObjectId`, `UUID` | общие | `ref`, `refPath`, `refModel` (относятся к значениям) |
| остальные (`Boolean`, `Types.Decimal128`, `Types.Binary`, `Types.Timestamp`, `Spec.vector`, `RegExp`, `Spec.union`) | общие | — |

Например, `min` — опция чисел и дат. У строки её нет.

<Snippet id="reference/schemas/prop/options-by-type" twoslash />

Компилятор подчёркивает ключ `min` и сообщает, что в типе опций строки такого свойства нет. Без типов то же случится при сборке модели — `Wrong.title: "min" is not an option of this field type`.

## required [#required]

`required: true` требует, чтобы поле было в документе. Без `nullable` оно не может быть и `null`. Вместе с [`nullable: true`](#nullable) ключ обязателен, но `null` допустим. Опция всегда явная. Typemo не выводит её из `?` или `!`, потому что `?` описывает тип в TypeScript, а обязательность — правило для данных. Это два разных решения. Работает на всех типах.

Проверка срабатывает при создании и замене документа, в [`$validate`](../documents/document-api.mdx#validate) и при сохранении.

<Snippet id="reference/schemas/prop/required" twoslash />

Это [`ValidationError`](../errors/data-errors.mdx#validation-error) с причиной `required`. Чем отсутствие поля отличается от `null`, разбирает руководство [Обязательность, `null` и отсутствие](../../schemas/required-and-null.mdx).

---

## nullable [#nullable]

`nullable: true` объявляет `null` допустимым значением поля. Без неё `null` не пройдёт. В MongoDB отсутствие поля и явный `null` — разные состояния, и Typemo не смешивает их молча. Работает на всех типах. Тип поля должен содержать `| null`, компилятор проверяет это в обе стороны.

<Snippet id="reference/schemas/prop/nullable" twoslash />

Если забыть `| null` в типе, компилятор потребует его.

<Snippet id="reference/schemas/prop/nullable-2" twoslash />

Текст ошибки в сообщении — `@Prop "nickname": "nullable" is set, but the field type has no "| null"`. Обратный случай, `| null` в типе без `nullable: true`, даёт `@Prop "nickname": the field type has "| null", add nullable: true`.

Если `null` приходит на поле без `nullable`, приведение типа бросает [`CastError`](../errors/data-errors.mdx#cast-error) — `Cast to string failed at path "role" for null: null is not allowed on a path that is not nullable [null]`.

С [`required: true`](#required) `nullable` даёт пару «ключ обязателен, значение может быть `null`». Документ без ключа не сохранится (`Validation failed: "phone": the field is required [required]`). `null` проходит. `$unset` такого поля запрещён (`Validation failed: "phone": the field is required; $unset would remove it [required]`). Тип поля при этом `T | null` без `?`. Примеры — в руководстве [Обязательность, `null` и отсутствие](../../schemas/required-and-null.mdx).

## default [#default]

`default` задаёт значение, которое подставляется, когда поля нет во входных данных. Принимает значение или функцию без аргументов. Функция вызывается заново для каждого документа, так что `() => new Date()` даёт свежую дату, а массив-литерал копируется. Работает на всех типах. Поле объявляется как `Defaulted<T>`. Этот [маркер](./field-markers.mdx#defaulted) говорит типу, что при создании поле можно не передавать, а при чтении оно всегда есть. Полю-массиву маркер не нужен — массив без значения и без `default` сам становится пустым (`[]`). Поэтому `tags!: string[]` с `default: () => ["new"]` компилируется, а `Defaulted<string[]>` разрешён, но не обязателен.

<Snippet id="reference/schemas/prop/default" twoslash />

Значение по умолчанию проверяется при сборке модели. `default: "x"` на числовом поле даёт `ConfigurationError` — `D1.a: the "default" value is not a value of the field (got "x" (string)): expected a number [type]`. `default: null` разрешён только вместе с `nullable: true`, иначе будет `D2.a: "default: null" on a field that is not nullable`.

Компилятор следит и за парой `default` и `Defaulted<T>`.

<Snippet id="reference/schemas/prop/default-2" twoslash />

Сообщение — `@Prop "score": "default" is set, declare the field as Defaulted<T>`. В обратную сторону, `Defaulted<T>` без `default`, — `the field is Defaulted<T>, but "default" is missing`.

## immutable [#immutable]

`immutable: true` запрещает менять значение после создания документа. Работает на всех типах, поле объявляется как `Immutable<T>`. Опция для того, что не должно меняться никогда, — страна регистрации, идентификатор во внешней системе, дата создания.

Оператор обновления на таком поле останавливает уже компилятор. Неизменяемого поля нет среди допустимых путей `$set`.

<Snippet id="reference/schemas/prop/immutable" twoslash />

Если обновление собрано в коде без типов, то же самое поймает Typemo во время работы.

<Snippet id="reference/schemas/prop/immutable-2" twoslash />

Присваивание в загруженном документе сразу ошибку не бросает, но сохранить такое изменение нельзя. Во всех случаях это [`StrictModeError`](../errors/data-errors.mdx#strict-mode-error) с причиной `immutable`. `$save` после изменения поля бросает ту же ошибку с тем же текстом. При upsert значение поля пишется только через `$setOnInsert`. Замена документа целиком ([`replaceOne`](../writes/writes.mdx#replace-one)) должна нести сохранённое значение поля. Если поля в документе нет, его не передают. Расхождение сравнивает сервер, и замена с ним не запишется. Подробнее — в руководстве [Неизменяемые поля](../../schemas/immutable.mdx).

## hidden [#hidden]

`hidden: true` убирает поле из результатов запросов, пока вы не выберете его явно. Хеш пароля или служебный токен не утекут в ответ по ошибке. Работает на всех типах. Поле объявляется как `Hidden<T>`, и в типе результата его тоже нет. Опция заменяет `select: false` из Mongoose.

<Snippet id="reference/schemas/prop/hidden" twoslash />

Скрытое поле читается, если выбрать его явно. `select({ passwordHash: 1 })` вернёт только его и `_id`, а `select({ "+passwordHash": true })` добавит к обычным полям. Но данные, которые уходят за пределы приложения, скрытое поле не отдают даже после такого выбора. `.plain()` и `$toPlain()` убирают его всегда. Показать его могут только `.plain({ hidden: true })` и `.lean()`.

Компилятор проверяет пару `hidden: true` и `Hidden<T>` — `@Prop "passwordHash": "hidden" is set, declare the field as Hidden<T>` и обратно `the field is Hidden<T>, add hidden: true`. Руководство — [Скрытые и чувствительные поля](../../schemas/hidden-and-sensitive.mdx).

## sensitive [#sensitive]

`sensitive` решает, как значение выглядит **за пределами базы** — в журнале аудита, в событиях наблюдения (а значит, в трассировках) и в текстах ошибок. Работает на всех типах. Значения такие.

- `"show"` — показать настоящее значение
- `"mask"` — показать `?`
- `"hide"` — заменить значение на `[hidden]`, а у условия вроде `$gt` — всё условие. Ключ остаётся, так что видно, что поле было
- `{ mask: (value) => json }` — своя функция маски, типизированная по значению поля

<Snippet id="reference/schemas/prop/sensitive" twoslash />

Отметка на поле сильнее настройки подписчика наблюдения. Функция маски вызывается только для значения объявленного типа. Значение, которое не удалось привести (число в строковом поле), элемент массива и операнд другого типа показываются как `?` без вызова функции. Если функция бросает ошибку при подготовке события или текста ошибки, операция продолжается и показывает `?`. Сбой доходит до подписчиков событием `instrumentation.error`, а без подписчиков — в `console.error`. В журнале аудита такой сбой — [`AuditError`](../errors/configuration-errors.mdx#audit-error). Запись журнала не создаётся, и транзакция откатывается вместе с самой записью. Где маскировка действует, подробно описано в руководстве [Скрытые и чувствительные поля](../../schemas/hidden-and-sensitive.mdx).

## dbName [#db-name]

`dbName` задаёт имя поля в базе, если оно отличается от имени свойства класса. Работает на всех типах. Значение — непустая строка без точки и без `$` в начале. В коде, фильтрах и результатах вы пользуетесь именем свойства. Имя из `dbName` видно только в самой базе.

<Snippet id="reference/schemas/prop/db-name" twoslash />

Через драйвер тот же документ выглядит как `{ e: "a@b.c" }`. Два поля с одним `dbName` или `dbName`, совпадающий с именем другого поля, дают `ConfigurationError` (`fields "a" and "b" are both stored as "x" (dbName conflict)`). У `_id` `dbName` быть не может.

---

## enum [#enum]

`enum` ограничивает значения строки или числа заданным списком. Принимает массив или объект (подойдёт TypeScript `enum`, из него берутся значения). У массива опция применяется к каждому элементу. Поле с объединением литералов (`"user" | "admin"`) обязано иметь `enum` с теми же значениями. И наоборот, поле с `enum` обязано иметь такой тип. Совпадение проверяет компилятор.

<Snippet id="reference/schemas/prop/enum" twoslash />

Компилятор ловит расхождения. Без `enum` у поля с литералами будет `@Prop "role": the field is a literal union, list its members in "enum"`. Если список не совпадает с типом — `"enum" values differ from the field's literal union`. При сборке пустой список даёт `"enum" is empty`, а значение, не подходящее типу поля, — `the enum value 1 is not a value of the field`.

---

## min [#min]

`min` — нижняя граница значения. Работает на `Number`, `Types.Double`, `Types.Int32` (число), `BigInt` (`bigint`) и `Date` (дата). Граница должна быть значением того же типа, что и поле.

<Snippet id="reference/schemas/prop/min" twoslash />

Граница не того типа или `min` больше `max` дают `ConfigurationError` — `"min" is greater than "max"`.

---

## max [#max]

`max` — верхняя граница. Типы и правила те же, что у [`min`](#min).

<Snippet id="reference/schemas/prop/max" twoslash />

---

## minLength [#min-length]

`minLength` — минимальная длина строки, неотрицательное целое. Работает на `String`. Длина считается после `trim` и смены регистра, поэтому пробелы по краям не в счёт.

<Snippet id="reference/schemas/prop/min-length" twoslash />

Нецелое или отрицательное число и `minLength` больше `maxLength` дают `ConfigurationError` (`"minLength"/"maxLength" must be non-negative integers`, `"minLength" is greater than "maxLength"`).

---

## maxLength [#max-length]

`maxLength` — максимальная длина строки. Правила те же, что у [`minLength`](#min-length).

<Snippet id="reference/schemas/prop/max-length" twoslash />

---

## match [#match]

`match` — регулярное выражение, которому должна соответствовать строка. Работает на `String`. Флаги `g` и `y` запрещены. У такого выражения есть состояние (`lastIndex`), и одна проверка давала бы разные ответы на одно значение.

<Snippet id="reference/schemas/prop/match" twoslash />

С флагом `g` модель не соберётся — `"match" with the g or y flag is stateful (lastIndex); remove the flag`.

---

## trim [#trim]

`trim: true` обрезает пробелы по краям строки при присваивании. Работает на `String`. Обрезка идёт раньше `lowercase`, `uppercase`, проверок длины и `match`.

<Snippet id="reference/schemas/prop/trim" twoslash />

---

## lowercase [#lowercase]

`lowercase: true` приводит строку к нижнему регистру при присваивании. Работает на `String`. С `uppercase` не сочетается.

<Snippet id="reference/schemas/prop/lowercase" twoslash />

Обе опции сразу дают `ConfigurationError` — `"lowercase" and "uppercase" together`.

---

## uppercase [#uppercase]

`uppercase: true` приводит строку к верхнему регистру при присваивании. Типы и ограничения те же, что у [`lowercase`](#lowercase). Удобна для кодов страны или валюты.

<Snippet id="reference/schemas/prop/uppercase" twoslash />

---

## validate [#validate]

`validate` — своя проверка значения, функция или список функций. Функция получает значение и контекст. Она возвращает `true`, если всё хорошо, или строку с текстом ошибки, и может быть асинхронной. Работает на всех типах. Запускается после приведения типа и только для значений, не равных `null`, а отсутствие и `null` остаются за [`required`](#required) и [`nullable`](#nullable). Из списка выполняются все проверки, и в ошибке будут все сообщения.

<Snippet id="reference/schemas/prop/validate" twoslash />

Второй аргумент — контекст проверки (см. ниже), по нему проверка узнаёт, где она запущена. Для целого документа это `{ kind: "document", operation, path }`. Для значения, записанного оператором обновления, — `{ kind: "update", operation, operator, path, upsert, filter }`. Проверка работает и при обновлении. `updateOne` со `$set` вызвал ту же функцию с контекстом `update:updateOne`. Не-функция в `validate` даёт `ConfigurationError`.

### Контекст проверки [#check-context]

Контекст — объект одного из двух видов, их различает поле `kind`, `"document"` или `"update"`. Из `@venloc/typemo` экспортируются `DocumentValidationContext`, `UpdateValidationContext`, их объединение `ValidationContext` и тип самой функции `FieldValidator<V>`. Общий валидатор можно вынести в отдельную функцию с точными типами.

<Snippet id="reference/schemas/prop/check-context" twoslash />

---

## get [#get]

`get` — функция, которая преобразует значение при **чтении через `$get`** и при сериализации с параметром `getters: true` (`$toObject`, `$toJSON`, `$toPlain`). Работает на всех типах. Принимает значение и возвращает значение того же типа.

<Snippet id="reference/schemas/prop/get" twoslash />

Обычное чтение свойства (`label.tag`) `get` не вызывает. Он работает только через `$get` и при сериализации с `getters: true`. В результате `lean()` и в значениях, которые уходят в базу, его тоже нет.

---

## set [#set]

`set` — функция, которая преобразует значение при присваивании, **после** приведения типа и встроенных преобразований (`trim`, `lowercase`, `uppercase`). Работает на всех типах. В примере выше `set` перевёл `"abc"` в `"ABC"` уже в `Labels.new`.

---

## index [#index]

`index` создаёт одиночный индекс по полю. Значения — `true` и `1` по возрастанию, `-1` по убыванию, `"hashed"` для хешированного. Работает на всех типах. Составные индексы описывает декоратор [`@Index`](./index-decorators.mdx#index).

<Snippet id="reference/schemas/prop/index" twoslash />

Любое другое значение даёт `ConfigurationError` — `"index" must be true, 1, -1 or "hashed"`. Индекс по `_id` запрещён, сервер и так строит его уникальным.

---

## unique [#unique]

`unique: true` создаёт уникальный индекс. Сервер не даст записать второй документ с тем же значением. Работает на всех типах. Нужно одно из трёх условий — `required: true`, `sparse: true` или частичный `@Index`. Дело в MongoDB. Документы без поля индексируются как `null`, и второй такой документ упал бы с ошибкой дубликата.

<Snippet id="reference/schemas/prop/unique" twoslash />

Без `required` и `sparse` модель не соберётся.

<Snippet id="reference/schemas/prop/unique-2" />

`unique` на поле с `nullable: true` тоже запрещён. Значения `null` конфликтуют даже в разреженном индексе (`"unique" on a nullable field — null values collide even in a sparse index; use a partial @Index`). Нарушение уникальности при записи — [`DuplicateKeyError`](../errors/server-errors.mdx#duplicate-key-error).

---

## sparse [#sparse]

`sparse: true` делает индекс поля разреженным, в него попадают только документы с этим полем. Работает на всех типах, но только вместе с `index` или `unique`. Сама по себе она индекс не создаёт, и `sparse` без них даёт `ConfigurationError` (`"sparse" needs "index" or "unique"`).

<Snippet id="reference/schemas/prop/sparse" twoslash />

---

## expires [#expires]

`expires` — время жизни документа в секундах после значения даты. Работает на `Date` и на массивах дат. Под неё строится TTL-индекс, и MongoDB сама удаляет документ, когда время вышло. Значение — неотрицательное целое число, иначе `ConfigurationError` (`"expires" is a non-negative whole number of seconds`).

<Snippet id="reference/schemas/prop/expires" twoslash />

Сервер проверяет TTL примерно раз в минуту, поэтому документ исчезает не мгновенно.

---

## text [#text]

`text: true` включает поле в текстовый индекс коллекции. Работает на `String` и на массивах строк. В коллекции только один текстовый индекс, поэтому поля с `text: true` сливаются в один. Отдельный текстовый `@Index` рядом с ними даёт `ConfigurationError` (`a collection has at most one text index; "text: true" fields are merged into one, ...`).

<Snippet id="reference/schemas/prop/text" twoslash />

Веса и язык текстового индекса задаются в [`@Index`](./index-decorators.mdx#index) через `weights`, `default_language` и `language_override`. Тогда `text: true` на полях не используется.

---

## excludeIndexes [#exclude-indexes]

`excludeIndexes: true` отключает для этого поля индексы, объявленные внутри класса поддокумента. Работает на поле, тип которого — класс с `@Schema`. Нужна, когда один поддокумент встроен в несколько коллекций и индексы нужны не везде.

<Snippet id="reference/schemas/prop/exclude-indexes" twoslash />

---

## ref [#ref]

`ref` связывает поле со ссылкой на документ другой модели — `ref: () => User`. Работает на `String`, числах, `Types.ObjectId`, `Types.UUID` (тип `_id` целевой модели), на массивах таких значений и на значениях `Spec.map`. Поле объявляется как [`Ref<M>`](./field-markers.mdx#ref), и компилятор сверяет, что модель в `ref` та же, что в типе поля. Нужна функция, а не класс, из-за порядка объявления.

<Snippet id="reference/schemas/prop/ref" twoslash />

Компилятор ругается в трёх случаях. `ref` без `Ref<M>` в типе даёт `@Prop "author": "ref" is set, but the field type is not Ref<Model>`. `Ref<M>` без `ref` даёт `the field is Ref<Model>, add ref: () => Model`. Другая модель даёт `"ref" points to another model than the field's Ref<Model>`. Руководство — [Ссылки на другие модели](../../schemas/references.mdx).

---

## refPath [#ref-path]

`refPath` нужна, когда поле может ссылаться на модели разных классов. Значение — путь к полю **того же документа** (или поддокумента), где лежит имя класса целевой модели, `"User"` или `"Bot"`. Поле объявляется как `Ref<A | B>`, обе модели должны быть зарегистрированы на соединении.

<Snippet id="reference/schemas/prop/ref-path" twoslash />

`ref`, `refPath` и `refModel` взаимоисключающие. Две сразу дают `ConfigurationError` (`"ref", "refPath" and "refModel" are exclusive (one form of reference)`).

---

## refModel [#ref-model]

`refModel` работает как [`refPath`](#ref-path), только модель выбирает ваша функция. Она получает документ (или поддокумент) со ссылкой и идентификатор и возвращает класс модели. Пригодится, когда правило выбора сложнее, чем «имя класса в поле».

<Snippet id="reference/schemas/prop/ref-model" twoslash />

---

## ext [#ext]

`ext` хранит опции зарегистрированных расширений. Это метаданные для интеграций, их проверяет само расширение, а после сборки они замораживаются. Ключ — имя расширения. Опция не может изменить операцию или политику ядра. Расширение читает её через [`SchemaInfo.extOf`](./schema-info.mdx#ext-of). Незарегистрированный ключ — ошибка компиляции на этом ключе.

<Snippet id="reference/schemas/prop/ext" twoslash />

Как объявить расширение и его опции, рассказывает руководство [Свои опции полей и схем](../../extensions/custom-options.mdx).

---

## Ошибки, общие для всех опций [#common-errors]

Тип, которого нет среди поддерживаемых, даёт ошибку компиляции с готовым советом.

<Snippet id="reference/schemas/prop/common-errors" twoslash />

Внутри сообщения — `@Prop "tags": this type is not supported (no Set/Map/Array/Object: use [X], Spec.map(X) or a @Schema class)`. Есть и похожие проверки. `the runtime type () => X does not match the field type` значит, что тип из функции не совпадает с типом поля. Остальные — `a VirtualRef field is declared with @Virtual, not @Prop` и `not a public field (private and protected fields cannot be schema fields)`.

`@Prop` на методе или аксессоре даёт `ConfigurationError` при объявлении класса — `Account: @Prop on "m", which is a method or an accessor (getters are virtuals and need no decorator)`. Значение сразу при объявлении (`a: number = 5`) ловится при сборке модели — `Account: field(s) "a" get a value from an initializer or the constructor; use the "default" option — service fields are filled by Typemo`. `Set` как тип поля в коде без типов — `Account.a: Set is not supported: use an array [X] (with a unique validator if needed)`.

Бывает и наоборот, когда у собственного свойства данных нет `@Prop` (например, `note = "x"` или поле без инициализатора при `useDefineForClassFields: true`). Сборка бросит `ConfigurationError` — `Account: property "note" has no @Prop, so it is not a field of the schema (never stored, cast or loaded); decorate it with @Prop, declare it with "declare", or make it a getter or a method`. Методы, геттеры и неперечисляемые свойства не в счёт.

## Когда не подходит [#when-not-to-use]

`@Prop` описывает поле, которое хранится в базе. Значение, вычисляемое из других полей, — геттер класса с типом [`Computed<T>`](./field-markers.mdx#computed) без декоратора. Ссылка, которая подтягивает документы по обратной связи и ничего не хранит, — [`@Virtual`](./virtual.mdx#virtual). Составной или частичный индекс — [`@Index`](./index-decorators.mdx#index). Настройки всей коллекции — [`@Schema`](./schema.mdx#schema).
