`@Discriminator` объявляет класс **дискриминатором** базового класса. Это наследник, чьи документы лежат в одной коллекции с документами базы и отличаются значением специального поля. Коллекция `shapes` хранит круги и квадраты, у каждого свои поля, а запрос по базовой модели возвращает всех. Эта страница объясняет, как записывается значение, какие проверки делает декоратор и что бывает при ошибках.

Руководство с примерами — [Наследование и дискриминаторы](../../schemas/discriminators.mdx). Эта страница — справочник.

В примерах базовый класс `Shape` (поле `name`) и два наследника, `Circle` (поле `radius`) и `Square` (поле `side`). В коллекции три документа. Круг `c` с радиусом 2 и квадрат `s` со стороной 3 создаёт первый пример, а документ `base` через базовую модель — второй.

## @Discriminator

`@Discriminator("circle")` записывает значение в поле-ключ документа. По умолчанию ключ называется `__t`, а имя меняет опция [`discriminatorKey`](./schema.mdx#discriminatorkey). По этому значению Typemo выбирает класс при чтении, и документ с `__t: "circle"` становится экземпляром `Circle`. Поля наследника — это поля базы и его собственные. Собственный `@Schema` ему не нужен, он берёт опции корня.

Значение передавайте **литералом** и объявляйте ключ в классе с тем же литералом — `declare readonly __t: DiscriminatorValue<"circle">`. Тогда результаты `.lean()` и `.plain()` несут литерал, а объединение наследников сужается по ключу. Без объявления декоратор не скомпилируется.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "shapes" })
class Shape extends Entity {
  @Prop(() => String, { required: true })
  name!: string;
}

@Discriminator("circle") // [!code highlight]
class Circle extends Shape {
  declare readonly __t: DiscriminatorValue<"circle">; // [!code highlight]
  @Prop(() => Number, { required: true })
  radius!: number;
}

@Discriminator("square")
class Square extends Shape {
  declare readonly __t: DiscriminatorValue<"square">;
  @Prop(() => Number, { required: true })
  side!: number;
}
const Shapes = client.db().model(Shape);
const Circles = client.db().model(Circle);
const Squares = client.db().model(Square);
const circle = await Circles.create({ name: "c", radius: 2 });
const square = await Squares.create({ name: "s", side: 3 });
console.log(circle.__t, square.__t);
// → circle square
```

<Params>
<Param name="value" type="string">

Литерал, который записывается в ключ. Без него во время работы взялось бы имя класса, но тип не может его проверить, поэтому вызов без значения не компилируется — `@Discriminator(): pass the value as a literal — @Discriminator("value") with declare readonly __t: DiscriminatorValue<"value"> (the class-name default cannot be checked by the type)`.

</Param>
</Params>

<FullType>

```ts
const Discriminator: <const V extends string = string>(
  value?: V,
) => <C extends EntityClass>(target: C & DiscriminatorCheck<C, V>) => void
```

### Запросы по базовой и по дочерней модели

Модель наследника видит только свои документы, модель базы — все. Документ создаётся классом, имя которого совпадает с его значением.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "shapes" })
class Shape extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Discriminator("circle")
class Circle extends Shape {
  declare readonly __t: DiscriminatorValue<"circle">;
  @Prop(() => Number, { required: true }) radius!: number;
}
const Shapes = client.db().model(Shape);
const Circles = client.db().model(Circle);
await Shapes.create({ name: "base" });
const all = await Shapes.find().sort({ name: 1 }).plain();
console.log(all.map((shape) => shape.name));
// → ["base", "c", "s"]
const circles = await Circles.find().plain();
console.log(circles.map((circle) => circle.name));
// → ["c"]
const loaded = await Shapes.find({ name: "c" });
console.log(loaded[0]?.constructor.name);
// → Circle
```

Документ, созданный через базовую модель, ключа не получает и остаётся базовым `Shape`.

### Поле, которое не принадлежит классу

Поле другого наследника отвергается при приведении.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "shapes" })
class Shape extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Discriminator("circle")
class Circle extends Shape {
  declare readonly __t: DiscriminatorValue<"circle">;
  @Prop(() => Number, { required: true }) radius!: number;
}
const Circles = client.db().model(Circle);
try {
  await Circles.create({ name: "c", side: 2 } as never);
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to Circle failed at path "side" for 2 (number): not a field of Circle [unknown-key]
```

### Значение ключа неизменяемо

Вид документа выбирается один раз, при создании. Ключ объявлен как `DiscriminatorValue<…>`, то есть неизменяемым. Присваивание ему не компилируется, а обновление с ключом отклоняется до отправки в базу. Если обойти типы приведением, присваивание в загруженном документе ошибки не бросит, но первый же `$save()` даст `StrictModeError` с причиной `immutable`.

```ts twoslash
import { Discriminator, Entity, Prop, Schema, TypemoClient, type DiscriminatorValue } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
@Schema({ collection: "shapes" })
class Shape extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Discriminator("circle")
class Circle extends Shape {
  declare readonly __t: DiscriminatorValue<"circle">;
  @Prop(() => Number, { required: true }) radius!: number;
}
const Circles = client.db().model(Circle);
const circle = await Circles.findOne({ name: "c" }).orFail();
// ---cut---
// @errors: 2540
circle.__t = "square";
```

```ts twoslash
import { Discriminator, Entity, Prop, Schema, TypemoClient, type DiscriminatorValue } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
@Schema({ collection: "shapes" })
class Shape extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
@Discriminator("circle")
class Circle extends Shape {
  declare readonly __t: DiscriminatorValue<"circle">;
  @Prop(() => Number, { required: true }) radius!: number;
}
const Circles = client.db().model(Circle);
const circle = await Circles.findOne({ name: "c" }).orFail();
// ---cut---
try {
  await Circles.updateOne({ name: "c" }, { $set: { __t: "square" } } as never);
} catch (error) {
  console.log((error as Error).message);
}
// → $set.__t: "__t" is immutable; it is written only when the document is created ($setOnInsert on upsert) [immutable]
try {
  (circle as { __t: string }).__t = "square";
  await circle.$save();
} catch (error) {
  console.log((error as Error).message);
}
// → $set.__t: "__t" is immutable; it is written only when the document is created ($setOnInsert on upsert) [immutable]
```

С `$unset` ключа то же самое. Чтобы сменить вид, создайте документ нужного вида и удалите прежний.

## Discriminators

`Discriminators<C>` — тип ключа дискриминатора в классе **базы**, которая перечисляет наследников опцией [`discriminators`](./schema.mdx#опция-discriminators). Параметр `C` — объединение классов наследников, например `declare readonly __t?: Discriminators<Circle | Square>`. Ключ необязателен, потому что у документа, созданного через базовую модель, вида нет. Как и `DiscriminatorValue`, тип помечает ключ неизменяемым и заполняемым ядром ([маркерные типы](./field-markers.mdx#discriminators)).

Без списка модель базы возвращает документы, у которых известны только поля базы. `radius` и `side` компилятору неизвестны, и вид приходится сообщать вручную. Со списком результат чтения через модель базы — объединение «база без ключа или любой из наследников». Это верно для документов, результатов `.lean()` и `.plain()`, JSON и курсоров. Проверка ключа сужает объединение, и внутри ветки `shape.__t === "circle"` доступны поля круга.

```ts twoslash
import { Discriminator, Entity, Prop, Schema, TypemoClient, type Discriminators, type DiscriminatorValue } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "shapes", discriminators: () => [Circle, Square] }) // [!code highlight]
class Shape extends Entity {
  declare readonly __t?: Discriminators<Circle | Square>; // [!code highlight]
  @Prop(() => String, { required: true })
  name!: string;
}

@Discriminator("circle")
class Circle extends Shape {
  declare readonly __t: DiscriminatorValue<"circle">;
  @Prop(() => Number, { required: true })
  radius!: number;
}

@Discriminator("square")
class Square extends Shape {
  declare readonly __t: DiscriminatorValue<"square">;
  @Prop(() => Number, { required: true })
  side!: number;
}

const Shapes = client.db().model(Shape);
const shapes = await Shapes.find().sort({ name: 1 }).plain();
const areas = shapes.map((shape) => {
  if (shape.__t === "circle") {
    const radius = shape.radius;
    //    ^?
    return Math.round(Math.PI * radius ** 2);
  }
  if (shape.__t === "square") return shape.side ** 2;
  return 0;
});
console.log(areas);
// → [0, 13, 9]
```

Ветка без проверок получает документ базы. У него нет ни ключа, ни полей наследников, поэтому `base` дал `0`. Круг `c` с радиусом 2 занимает примерно 13 единиц, квадрат `s` со стороной 3 — 9. Документ сужается и проверкой ключа, и проверкой `instanceof`. Запрос к модели наследника по-прежнему возвращает только его тип.

Со своим именем ключа тип объявляют при нём — `discriminatorKey: "kind"` и `declare readonly kind?: Discriminators<Click>`. Список проверяется при сборке схемы, и лишний, пропущенный или повторённый класс даёт `ConfigurationError` ([тексты](./schema.mdx#опция-discriminators)). Объявление без опции `discriminators`, опция без объявления и разные классы в типе и в списке — ошибки компиляции с теми же сообщениями.

<FullType>

```ts
type Discriminators<C extends object> =
  string & DefaultedMarker & ImmutableMarker & DiscriminatorsMarker<C>
```

</FullType>

## Ошибки

Компилятор проверяет объявление ключа. Если в классе нет `declare readonly __t: DiscriminatorValue<"…">`, ошибка называет, что добавить.

```ts twoslash
import { Discriminator, Entity, Schema } from "@venloc/typemo";
// ---cut---
// @errors: 1238
@Schema()
class Shape extends Entity {}

@Discriminator("circle")
class Circle extends Shape {}
```

Текст внутри сообщения — `@Discriminator("circle"): declare the discriminator key with its value in the class — declare readonly __t: DiscriminatorValue<"circle"> (or your discriminatorKey instead of __t)`. Если литерал в классе не тот, что в декораторе, сообщение такое — `@Discriminator: the class declares __t as "d", but the value is "c"`.

Остальное ловит сборка, и это всегда `ConfigurationError`. Повторное значение находится при `model()` **любого** класса иерархии, даже того, которого повтор не касается — `Square: discriminator value "x" is already used by Circle in the hierarchy of Shape`. Другие случаи.

- декоратор на классе без базы бросает ошибку сразу, при объявлении класса — `Orphan: @Discriminator needs a base class (class X extends Base)`
- собственный `@Schema` на наследнике — `Circle: a discriminator uses its root's schema options; remove @Schema (root: Shape)`
- корень иерархии без `@Schema` — `Circle: the root of its discriminator hierarchy (Shape) has no @Schema`
- ключ из `discriminatorKey` не объявлен как строковое поле базы (без `discriminators`) — `Shape: discriminatorKey "kind" is not a declared field (declare it as a string field, or list the discriminators and declare readonly kind?: Discriminators<…>)`
- ключ не строка или `nullable` — `Shape: the discriminator key "kind" must be a non-nullable string field`
- список `discriminators` расходится с иерархией — тексты в [`@Schema`](./schema.mdx#опция-discriminators)

## Когда не подходит

Если типы различаются значением одного поля и полей у них нет, хватит [`enum`](./prop.mdx#enum) на обычном поле. Классы в разных коллекциях наследованием не связывают, это две модели. Значения скалярных типов в одном поле — задача для [`Spec.union`](./types-and-spec.mdx#specunion).
