`@Discriminator` объявляет класс **дискриминатором** базового класса. Это наследник, чьи документы лежат в одной коллекции с документами базы и отличаются значением специального поля. Коллекция `shapes` хранит круги и квадраты, у каждого свои поля, а запрос по базовой модели возвращает всех. Эта страница объясняет, как записывается значение, какие проверки делает декоратор и что бывает при ошибках.

Руководство с примерами — [Наследование и дискриминаторы](../../schemas/discriminators.mdx). Эта страница — справочник.

В примерах базовый класс `Shape` (поле `name`) и два наследника, `Circle` (поле `radius`) и `Square` (поле `side`). В коллекции три документа. Круг `c` с радиусом 2 и квадрат `s` со стороной 3 создаёт первый пример, а документ `base` через базовую модель — второй.

## @Discriminator [#discriminator]

`@Discriminator("circle")` записывает значение в поле-ключ документа. По умолчанию ключ называется `__t`, а имя меняет опция [`discriminatorKey`](./schema.mdx#discriminator-key). По этому значению Typemo выбирает класс при чтении, и документ с `__t: "circle"` становится экземпляром `Circle`. Поля наследника — это поля базы и его собственные. Собственный `@Schema` ему не нужен, он берёт опции корня.

Значение передавайте **литералом** и объявляйте ключ в классе с тем же литералом — `declare readonly __t: DiscriminatorValue<"circle">`. Тогда результаты `.lean()` и `.plain()` несут литерал, а объединение наследников сужается по ключу. Без объявления декоратор не скомпилируется.

<Params>
<Param name="value" type="string">

Литерал, который записывается в ключ. Без него во время работы взялось бы имя класса, но тип не может его проверить, поэтому вызов без значения не компилируется — `@Discriminator(): pass the value as a literal — @Discriminator("value") with declare readonly __t: DiscriminatorValue<"value"> (the class-name default cannot be checked by the type)`.

### Значение ключа неизменяемо [#key-immutable]

Вид документа выбирается один раз, при создании. Ключ объявлен как `DiscriminatorValue<…>`, то есть неизменяемым. Присваивание ему не компилируется, а обновление с ключом отклоняется до отправки в базу. Если обойти типы приведением, присваивание в загруженном документе ошибки не бросит, но первый же `$save()` даст `StrictModeError` с причиной `immutable`.

<Snippet id="reference/schemas/discriminator/key-immutable" twoslash />

<Snippet id="reference/schemas/discriminator/key-immutable-2" twoslash />

С `$unset` ключа то же самое. Чтобы сменить вид, создайте документ нужного вида и удалите прежний.

## Discriminators [#discriminators]

`Discriminators<C>` — тип ключа дискриминатора в классе **базы**, которая перечисляет наследников опцией [`discriminators`](./schema.mdx#discriminators). Параметр `C` — объединение классов наследников, например `declare readonly __t?: Discriminators<Circle | Square>`. Ключ необязателен, потому что у документа, созданного через базовую модель, вида нет. Как и `DiscriminatorValue`, тип помечает ключ неизменяемым и заполняемым ядром ([маркерные типы](./field-markers.mdx#discriminators)).

Без списка модель базы возвращает документы, у которых известны только поля базы. `radius` и `side` компилятору неизвестны, и вид приходится сообщать вручную. Со списком результат чтения через модель базы — объединение «база без ключа или любой из наследников». Это верно для документов, результатов `.lean()` и `.plain()`, JSON и курсоров. Проверка ключа сужает объединение, и внутри ветки `shape.__t === "circle"` доступны поля круга.

<Snippet id="reference/schemas/discriminator/discriminators" twoslash />

Ветка без проверок получает документ базы. У него нет ни ключа, ни полей наследников, поэтому `base` дал `0`. Круг `c` с радиусом 2 занимает примерно 13 единиц, квадрат `s` со стороной 3 — 9. Документ сужается и проверкой ключа, и проверкой `instanceof`. Запрос к модели наследника по-прежнему возвращает только его тип.

Со своим именем ключа тип объявляют при нём — `discriminatorKey: "kind"` и `declare readonly kind?: Discriminators<Click>`. Список проверяется при сборке схемы, и лишний, пропущенный или повторённый класс даёт `ConfigurationError` ([тексты](./schema.mdx#discriminators)). Объявление без опции `discriminators`, опция без объявления и разные классы в типе и в списке — ошибки компиляции с теми же сообщениями.

## Ошибки [#errors]

Компилятор проверяет объявление ключа. Если в классе нет `declare readonly __t: DiscriminatorValue<"…">`, ошибка называет, что добавить.

<Snippet id="reference/schemas/discriminator/errors" twoslash />

Текст внутри сообщения — `@Discriminator("circle"): declare the discriminator key with its value in the class — declare readonly __t: DiscriminatorValue<"circle"> (or your discriminatorKey instead of __t)`. Если литерал в классе не тот, что в декораторе, сообщение такое — `@Discriminator: the class declares __t as "d", but the value is "c"`.

Остальное ловит сборка, и это всегда `ConfigurationError`. Повторное значение находится при `model()` **любого** класса иерархии, даже того, которого повтор не касается — `Square: discriminator value "x" is already used by Circle in the hierarchy of Shape`. Другие случаи.

- декоратор на классе без базы бросает ошибку сразу, при объявлении класса — `Orphan: @Discriminator needs a base class (class X extends Base)`
- собственный `@Schema` на наследнике — `Circle: a discriminator uses its root's schema options; remove @Schema (root: Shape)`
- корень иерархии без `@Schema` — `Circle: the root of its discriminator hierarchy (Shape) has no @Schema`
- ключ из `discriminatorKey` не объявлен как строковое поле базы (без `discriminators`) — `Shape: discriminatorKey "kind" is not a declared field (declare it as a string field, or list the discriminators and declare readonly kind?: Discriminators<…>)`
- ключ не строка или `nullable` — `Shape: the discriminator key "kind" must be a non-nullable string field`
- список `discriminators` расходится с иерархией — тексты в [`@Schema`](./schema.mdx#discriminators)

## Когда не подходит [#when-not-to-use]

Если типы различаются значением одного поля и полей у них нет, хватит [`enum`](./prop.mdx#enum) на обычном поле. Классы в разных коллекциях наследованием не связывают, это две модели. Значения скалярных типов в одном поле — задача для [`Spec.union`](./types-and-spec.mdx#spec.union).
