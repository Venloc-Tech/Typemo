Если в [`@Schema`](./schema.mdx#collection) не указано имя коллекции, Typemo берёт имя класса, приводит к нижнему регистру и ставит во множественное число по английским правилам: `User` становится `users`, `UserProfile` — `userprofiles`. Правила — те же, что были в Mongoose, за исключением исправленных ошибок, поэтому существующие коллекции сохраняют свои имена. Класс `CollectionNaming` собирает эти правила и проверку имён. Сюда приходят, чтобы предсказать имя коллекции или проверить своё.

Руководство с примерами — [Имена коллекций](../../schemas/collection-names.mdx). Эта страница — справочник.

---

## CollectionNaming.default

`default` — функция именования, которая применяется, если `collection` не задана: имя класса в нижнем регистре, затем `pluralize`. Тип функции — `(className: string) => string`. Это поле-функция, а не метод класса: её передают как колбэк, и ей не нужен привязанный `this`.

```ts twoslash
import { CollectionNaming, Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const names = ["User", "UserProfile", "Person", "Category", "Box", "Status", "Data", "Mouse", "Wife"].map(CollectionNaming.default);
console.log(names.join(" "));
// → users userprofiles people categories boxes status data mice wives
```

Из результата видно: неисчисляемые слова (`status`, `data`) не меняются, неправильные множественные формы (`people`, `mice`, `wives`) учтены, многословные имена не разделяются (`userprofiles`, не `user_profiles`).

<Returns type="string">

Имя коллекции для имени класса.

</Returns>

## CollectionNaming.pluralize

`pluralize(слово)` ставит слово во множественное число: принимает слово строчными буквами в единственном числе. Возвращает слово без изменений, если оно неисчисляемо (`sheep`, `news`, `metadata`) или ни одно правило не подошло.

```ts twoslash
import { CollectionNaming, Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
console.log(CollectionNaming.pluralize("wolf"), CollectionNaming.pluralize("sheep"));
// → wolves sheep
```

<Params>
<Param name="word" type="string" required>

Слово в единственном числе, в нижнем регистре.

</Param>
</Params>

Отличия от Mongoose: исправлены слова на `matrix`/`index` (`indexa` больше не превращается в `indicesa`), `data` и `metadata` считаются неисчисляемыми, `criterion` и `phenomenon` получают правильные формы.

## CollectionNaming.check

`check(name, where)` проверяет имя коллекции и возвращает его же. Имя должно быть непустой строкой, не содержать `$` и нулевой символ и не начинаться с `system.`: такие имена зарезервированы сервером. Typemo вызывает проверку для имени из [`collection`](./schema.mdx#collection), и вы можете вызвать её сами.

```ts twoslash
import { CollectionNaming, Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
try {
  CollectionNaming.check("system.users", "User");
} catch (error) {
  console.log((error as Error).message);
}
// → User: "system." collections are reserved
try {
  CollectionNaming.check("a$b", "User");
} catch (error) {
  console.log((error as Error).message);
}
// → User: the collection name "a$b" cannot contain "$" or a null character
```

<Params>
<Param name="name" type="unknown" required>

Проверяемое имя.

</Param>
<Param name="where" type="string" required>

Место для текста ошибки, обычно имя класса.

</Param>
</Params>

Пустая строка и не строка — `ConfigurationError`: `User: the collection name must be a non-empty string`.

## Когда не подходит

Автоматическое имя годится для новых коллекций. Если вы подключаетесь к существующей базе, задайте `collection` явно: тогда переименование класса не сдвинет данные. Имя не должно зависеть от языка, в котором вы привыкли называть классы: правила только английские. Свою функцию именования подставить нельзя: публичной опции для неё нет, поэтому другое правило задаётся явным `collection` в каждом классе.
