`@Virtual` объявляет **виртуальную связь**. Это поле, которое ничего не хранит в базе и заполняется документами другой модели, когда вы просите подтянуть их через `populate`. Обычная ссылка [`Ref`](./field-markers.mdx#ref) лежит у «дочернего» документа и указывает на родителя. Виртуальная связь идёт в обратную сторону. У автора нет списка постов, но `@Virtual` достаёт посты, чьё поле `author` указывает на этого автора.

Значения-геттеры (`get fullName()`), которые вычисляются из полей документа, декоратора не требуют. Для них есть тип [`Computed`](./field-markers.mdx#computed). Руководство с примерами — [Виртуальные поля](../../schemas/virtuals.mdx).

В примерах две модели, пост и автор. У поста есть ссылка на автора, у автора — виртуальная связь с постами. Результаты `// →` получены запуском на настоящей MongoDB. У автора Ann четыре поста (`a1` … `a4`, из них `a3` не опубликован, ранги 1–4), у Bob два (`b1`, `b2`, оба опубликованы).

## @Virtual [#virtual]

`@Virtual({ ref, localField, foreignField, … })` записывает связь в описание класса. Поле объявляется типом [`VirtualRef<M, JustOne, Count>`](./field-markers.mdx#virtual-ref) **без** `@Prop`. Флаги `JustOne` и `Count` должны совпадать с опциями `justOne` и `count`, тогда тип результата после `populate` знает, что придёт — массив, один документ или число.

## ref [#ref]

`ref` — функция, которая возвращает модель, чьи документы подтягиваются, например `ref: () => Post`. Это класс с [`@Schema`](./schema.mdx#schema). Функция нужна из-за порядка объявления классов. Модель обязана совпадать с моделью в типе поля `VirtualRef<Post>`, иначе компилятор скажет `@Virtual "posts": "ref" points to another model than the field's VirtualRef<Model>`. Если функция бросает ошибку или возвращает не схему, сборка даст `ConfigurationError` (`@Virtual "posts": "ref" must return a @Schema class`).

---

## localField [#local-field]

`localField` — путь поля **этого** класса, чьё значение ищется в чужом поле. Обычно это `"_id"`. Компилятор проверяет, что путь есть в классе (`@Virtual "posts": localField "nope" is not a field of this class`). При сборке нарушение даёт `ConfigurationError` (`@Virtual "posts": localField "nope" is not a field of the class`).

---

## foreignField [#foreign-field]

`foreignField` — путь поля **чужой** модели, которое должно совпасть с `localField`. В примере это `author` поста. Неизвестный путь — ошибка компиляции (`@Virtual "posts": foreignField "nope" is not a field of the referenced class`) и ошибка сборки (`@Virtual "posts": foreignField "nope" is not a field of Post`).

---

## justOne [#just-one]

`justOne: true` подтягивает один документ вместо массива, тип поля — `VirtualRef<M, true>`. Опция нужна для связи «один к одному» или когда важен только первый документ выборки, скажем последний пост. Вместе с `options.sort` выбирается лучший.

<Snippet id="reference/schemas/virtual/just-one" twoslash />

Если флаг расходится с типом, компилятор остановит код — `@Virtual "best": the field is VirtualRef<M, true>, add justOne: true` или `"justOne" differs from the field's VirtualRef<M, JustOne>`.

---

## count [#count]

`count: true` подставляет число документов вместо самих документов, тип поля — `VirtualRef<M, false, true>`. Берите её для счётчиков, когда сами документы не нужны.

<Snippet id="reference/schemas/virtual/count" twoslash />

Ошибки согласования — `the field is VirtualRef<M, J, true>, add count: true` и `"count" differs from the field's VirtualRef<M, JustOne, Count>`.

---

## match [#match]

`match` — дополнительный фильтр по документам чужой модели. Ключи — пути чужого класса или операторы верхнего уровня на `$`. Неизвестный путь — ошибка компиляции (`@Virtual "posts": match."x" is not a field of the referenced class`) и сборки (`match."x" is not a field of Post`).

<Snippet id="reference/schemas/virtual/match" twoslash />

## options [#options]

`options` — сортировка и постраничные ограничения запроса подтягивания по умолчанию. Значение — объект с тремя необязательными ключами.

### options.sort [#options.sort]

Ключи сортировки. `1` — по возрастанию, `-1` — по убыванию.

### options.skip [#options.skip]

Сколько подтянутых документов пропустить.

### options.limit [#options.limit]

Сколько документов вернуть, не больше.

<Snippet id="reference/schemas/virtual/options-limit" twoslash />

`sort`, `limit` и `skip` действуют на каждый исходный документ отдельно, а не на весь запрос подтягивания. При нескольких авторах `limit: 2` даёт **каждому** по два поста — у Ann `a4` и `a3`, у Bob `b2` и `b1`. В Mongoose `limit` делился между всеми авторами сразу, здесь такого нет. Ту же границу на автора задаёт и отдельная опция `perDocumentLimit`.

---

## perDocumentLimit [#per-document-limit]

`perDocumentLimit` ограничивает число подтянутых документов для каждого исходного документа. Подтягивание идёт одним запросом `$lookup` с `$limit`. Для выборки «последний пост каждого автора» её сочетают с `options.sort`. В Typemo `options.limit` тоже считается на документ, так что обе опции дают одинаковую границу на автора. `perDocumentLimit` удобна, когда вы переносите описание из Mongoose.

<Snippet id="reference/schemas/virtual/per-document-limit" twoslash />

## Ошибки согласования и сборки [#sync-and-build-errors]

Сборка проверяет и то, чего не видит компилятор. Виртуальное поле с тем же именем, что у поля `@Prop`, даёт `ConfigurationError` (`@Virtual "posts" is also a @Prop field`). Поле без типа `VirtualRef` — ошибка компиляции `@Virtual "posts": declare the field as VirtualRef<Model, JustOne, Count>`.

<Snippet id="reference/schemas/virtual/sync-and-build-errors" twoslash />

## Когда не подходит [#when-not-to-use]

Если значение вычисляется из полей самого документа, нужен геттер с типом [`Computed`](./field-markers.mdx#computed) или [`VirtualValue`](./field-markers.mdx#virtual-value), а не `@Virtual`. Если нужен идентификатор родителя у дочернего документа, берите [`Ref`](./field-markers.mdx#ref) с опцией [`ref`](./prop.mdx#ref) на настоящем поле.
