`SchemaInfo` — схема модели **только для чтения**. Приложение, расширения и интеграции читают её, не лезя во внутренности компилятора схем. Во время работы она подскажет, как называется коллекция модели, какие у неё пути, индексы и виртуальные поля. Ещё она переведёт путь из кода в имя поля базы. `SchemaInfo` лежит в свойстве `schema` любой модели.

Руководство с задачами — [Схема во время работы](../../schemas/runtime-schema.mdx). Эта страница — справочник.

Примеры берут модель пользователя. Поле `email` в базе называется `e`, к нему добавлены вложенный адрес и массив тегов.

```ts twoslash
import { CollectionNaming, Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ nested: true })
class Address {
  @Prop(() => String, { dbName: "c" })
  city?: string;
}

@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true })
  email!: string;
  @Prop(() => Address)
  address?: Address;
  @Prop(() => [String])
  tags?: string[];
}
const Users = client.db().model(User);
const info = Users.schema;
//    ^?
```

`SchemaInfo` — интерфейс. Класс, который его реализует, наружу не экспортируется, и вы работаете только с полями и методами ниже. Менять значения нельзя, потому что после сборки схема заморожена.

## name [#name]

`name` — имя класса модели.

```ts twoslash
import { CollectionNaming, Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "users" })
class User extends Entity {}
const Users = client.db().model(User);
console.log(Users.schema.name, Users.schema.collection);
// → User users
```

---

## collection [#collection]

`collection` — имя коллекции в базе. Оно имеет смысл для корневых документов, у вложенных схем не используется. Как имя строится без явной опции, описано в [`CollectionNaming`](./collection-naming.mdx).

## describe [#describe]

`describe()` возвращает обычный объект `SchemaDescription` — JSON-описание схемы для снимков в тестах и отладки. Пути идут в каноническом коде (`address.city`, `tags.$` для элемента массива). У каждого указаны вид (`kind`), тип (`type`), имя в базе (`dbPath`, если оно отличается) и флаги (`flags`).

```ts twoslash
import { CollectionNaming, Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ nested: true })
class Address {
  @Prop(() => String, { dbName: "c" }) city?: string;
}
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true }) email!: string;
  @Prop(() => Address) address?: Address;
  @Prop(() => [String]) tags?: string[];
}
const Users = client.db().model(User);
const description = Users.schema.describe();
console.log(description.paths.email);
// → { kind: "scalar", type: "string", dbPath: "e", flags: "required" }
console.log(Object.keys(description.paths));
// → ["_id", "email", "address", "address.city", "tags", "tags.$"]
```

В описании есть поля `name`, `kind` (`"document"` или `"nested"`), `collection` и `discriminator` (`{ root, key, value }` у класса-дискриминатора). Дальше идут `discriminators` (значения иерархии), `paths`, `indexes` (ключи и опции) и `searchIndexes`. Последнее — индексы Atlas Search из `@SearchIndex`, имя и определение в порядке объявления, а без них массив пуст. Затем `virtuals` (`populate:posts`, `getter:label`), `hooks` (число хуков по фазам и событиям) и `ext`. Флаги пути записаны строкой через запятую. Это `required`, `nullable`, `default`, `immutable`, `hidden` и служебные вида `service:id`.

Обычный объект описания схемы.

</Returns>

## toDbPath [#to-db-path]

`toDbPath(path)` переводит путь из кода в путь в базе с учётом [`dbName`](./prop.mdx#db-name) на всех уровнях. Позиции массива (`0`, `$`) остаются на месте. Если пути нет в схеме, метод вернёт `undefined` и не бросит ошибку.

```ts twoslash
import { CollectionNaming, Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ nested: true })
class Address {
  @Prop(() => String, { dbName: "c" }) city?: string;
}
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true }) email!: string;
  @Prop(() => Address) address?: Address;
  @Prop(() => [Address]) places?: Address[];
}
const Users = client.db().model(User);
console.log(Users.schema.toDbPath("email"));
// → e
console.log(Users.schema.toDbPath("address.city"));
// → address.c
console.log(Users.schema.toDbPath("places.0.city"));
// → places.0.c
console.log(Users.schema.toDbPath("address.nope"));
// → undefined
```

<Params>
<Param name="path" type="string" required>

Путь из кода. Позиция массива может быть числом, `$`, `$[]` или `$[имя]`.

</Param>
</Params>

## ext [#ext]

`ext` — опции зарегистрированных расширений на уровне схемы, которые заданы в [`@Schema({ ext })`](./schema.mdx#ext). Без расширений это пустой замороженный объект.

## extOf [#ext-of]

`extOf(path)` возвращает опции расширений для поля, заданные в [`@Prop({ ext })`](./prop.mdx#ext). Путь можно писать в любой позиционной форме (`items.3.price`, `items.$.price`). У существующего поля без `ext` метод вернёт пустой объект, а для несуществующего пути — `undefined`.

```ts twoslash
import { CollectionNaming, Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) email!: string;
}
const Users = client.db().model(User);
console.log(Users.schema.extOf("email"), Users.schema.extOf("nope"));
// → {} undefined
```

Как расширения объявляют свои опции, рассказывает руководство [Свои опции полей и схем](../../extensions/custom-options.mdx).

## Связанные типы [#related-types]

Из `@venloc/typemo` экспортируются типы, на которые ссылается описание. Это `SchemaDescription`, `PathDescription`, `DiscriminatorInfo`, `CompiledIndex`, `HookTable`, `VirtualDefinition`, `PathKind` и `ScalarType`. Последние два перечисляют виды узлов пути и скалярные типы. Тип `SchemaSource` значит «модель или её `schema`» (`SchemaInfo | { readonly schema: SchemaInfo }`). Его принимают [`JsonSchemaGenerator`, `StandardSchema.of`](./json-and-standard-schema.mdx) и методы менеджера коллекций, так что `SchemaInfo` можно отдавать им напрямую.

## Когда не подходит [#when-not-to-use]

`SchemaInfo` только читает. Схему во время работы не изменить — она замораживается при сборке модели. Чтобы проверить значение по схеме, берите методы модели (`validate`, `castObject`) или [`~standard`](./json-and-standard-schema.mdx#standard-schema). Для валидатора коллекции есть опция [`validator`](./schema.mdx#validator).
