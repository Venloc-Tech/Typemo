`SchemaInfo` — представление схемы модели **только для чтения**: то, что могут прочитать приложение, расширения и интеграции, не получая доступа к внутренностям компилятора схем. Приходят сюда, когда нужно узнать во время работы, как называется коллекция модели, какие у неё пути, индексы и виртуальные поля, или перевести путь из кода в имя поля базы. Получить `SchemaInfo` можно из свойства `schema` любой модели.

Руководство с задачами — [Схема во время работы](../../schemas/runtime-schema.mdx). Эта страница — справочник.

Примеры используют модель пользователя с полем `email`, которое в базе называется `e`, вложенным адресом и массивом тегов.

```ts twoslash
import { CollectionNaming, Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ nested: true })
class Address {
  @Prop(() => String, { dbName: "c" })
  city?: string;
}

@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true })
  email!: string;
  @Prop(() => Address)
  address?: Address;
  @Prop(() => [String])
  tags?: string[];
}
const Users = client.db().model(User);
const info = Users.schema;
//    ^?
```

`SchemaInfo` — интерфейс. Класс, который его реализует, публично не экспортируется: вы работаете только с полями и методами ниже. Значения нельзя менять: схема заморожена после сборки.

## name

`name` — имя класса модели.

```ts twoslash
import { CollectionNaming, Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "users" })
class User extends Entity {}
const Users = client.db().model(User);
console.log(Users.schema.name, Users.schema.collection);
// → User users
```

---

## collection

`collection` — имя коллекции в базе. Значение осмысленно для корневых документов; у вложенных схем оно не используется. Как формируется имя без явной опции, описано в [`CollectionNaming`](./collection-naming.mdx).

## describe

`describe()` возвращает обычный объект `SchemaDescription`: JSON-описание схемы для снимков в тестах и отладки. Пути идут по каноническому коду (`address.city`, `tags.$` для элемента массива), у каждого указан вид (`kind`), тип (`type`), имя в базе (`dbPath`), если оно отличается, и флаги (`flags`).

```ts twoslash
import { CollectionNaming, Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ nested: true })
class Address {
  @Prop(() => String, { dbName: "c" }) city?: string;
}
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true }) email!: string;
  @Prop(() => Address) address?: Address;
  @Prop(() => [String]) tags?: string[];
}
const Users = client.db().model(User);
const description = Users.schema.describe();
console.log(description.paths.email);
// → { kind: "scalar", type: "string", dbPath: "e", flags: "required" }
console.log(Object.keys(description.paths));
// → ["_id", "email", "address", "address.city", "tags", "tags.$"]
```

Поля описания: `name`, `kind` (`"document"` или `"nested"`), `collection`, `discriminator` (`{ root, key, value }` у класса-дискриминатора), `discriminators` (значения иерархии), `paths`, `indexes` (ключи и опции), `searchIndexes` (индексы Atlas Search из `@SearchIndex`: имя и определение, в порядке объявления; пусто, если их нет), `virtuals` (`populate:posts`, `getter:label`), `hooks` (число хуков по фазам и событиям) и `ext`. Флаги пути — строка через запятую: `required`, `nullable`, `default`, `immutable`, `hidden` и служебные вида `service:id`.

Обычный объект описания схемы.

</Returns>

## toDbPath

`toDbPath(path)` переводит путь из кода в путь в базе с учётом [`dbName`](./prop.mdx#dbname) на всех уровнях. Позиции массива (`0`, `$`) сохраняются. Для пути, которого нет в схеме, возвращает `undefined`, а не бросает ошибку.

```ts twoslash
import { CollectionNaming, Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ nested: true })
class Address {
  @Prop(() => String, { dbName: "c" }) city?: string;
}
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { dbName: "e", required: true }) email!: string;
  @Prop(() => Address) address?: Address;
  @Prop(() => [Address]) places?: Address[];
}
const Users = client.db().model(User);
console.log(Users.schema.toDbPath("email"));
// → e
console.log(Users.schema.toDbPath("address.city"));
// → address.c
console.log(Users.schema.toDbPath("places.0.city"));
// → places.0.c
console.log(Users.schema.toDbPath("address.nope"));
// → undefined
```

<Params>
<Param name="path" type="string" required>

Путь из кода. Позиции массива принимаются как число, `$`, `$[]` или `$[имя]`.

</Param>
</Params>

## ext

`ext` — опции зарегистрированных расширений на уровне схемы, заданные в [`@Schema({ ext })`](./schema.mdx#ext). Без расширений — пустой замороженный объект.

## extOf

`extOf(path)` возвращает опции расширений для поля: заданные в [`@Prop({ ext })`](./prop.mdx#ext). Путь принимается в любой позиционной форме (`items.3.price`, `items.$.price`). Для существующего поля без `ext` возвращает пустой объект, для несуществующего пути — `undefined`.

```ts twoslash
import { CollectionNaming, Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type VirtualValue, type Unbranded, type Int64String, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) email!: string;
}
const Users = client.db().model(User);
console.log(Users.schema.extOf("email"), Users.schema.extOf("nope"));
// → {} undefined
```

Как расширения объявляют свои опции, описано в руководстве [Свои опции полей и схем](../../extensions/custom-options.mdx).

## Связанные типы

Из `@venloc/typemo` экспортируются типы, на которые ссылается описание: `SchemaDescription`, `PathDescription`, `DiscriminatorInfo`, `CompiledIndex`, `HookTable`, `VirtualDefinition`, `PathKind` и `ScalarType`. Последние два перечисляют виды узлов пути и скалярные типы. Тип `SchemaSource` — «модель или её `schema`» (`SchemaInfo | { readonly schema: SchemaInfo }`): его принимают [`JsonSchemaGenerator`, `StandardSchema.of`](./json-and-standard-schema.mdx) и методы менеджера коллекций, поэтому `SchemaInfo` можно передавать им напрямую.

## Когда не подходит

`SchemaInfo` только читает. Изменить схему во время работы нельзя: схема замораживается при сборке модели. Для проверки значения по схеме используйте методы модели (`validate`, `castObject`) или [`~standard`](./json-and-standard-schema.mdx#standardschema), а для валидатора коллекции — опцию [`validator`](./schema.mdx#validator).
