Служебные поля документа — `_id`, `createdAt`, `updatedAt` и версия `__v` — Typemo не добавляет в схему скрытно. Вы получаете их, наследуя базовый класс: `Entity` даёт `_id` типа `ObjectId`, `EntityWithId` — `_id` другого типа (строку, число, `UUID`), `Timestamped` добавляет метки времени, `Versioned` — версию. Так поля видны компилятору, подсказкам редактора и типам результатов, и вам не нужно объявлять их вручную в каждой модели. На этой странице описаны все четыре базовых класса и связанные с ними типы.

Обзор с примерами на задачах — в руководствах [Описать модель](../../schemas/define-model.mdx), [Свой тип `_id`](../../schemas/custom-ids.mdx) и [Метки времени и версии](../../schemas/timestamps-and-versions.mdx). Эта страница — справочник.

Примеры используют модель поста: у неё есть заголовок, а служебные поля приходят от базовых классов. Результаты `// →` получены запуском на настоящей MongoDB.

Базовые классы не имеют конструкторов и инициализаторов: служебные поля заполняет само ядро при создании и сохранении, а не конструктор базы, потому что при `useDefineForClassFields: true` повторное объявление поля в наследнике молча затёрло бы значение, поставленное базой.

## Entity

`Entity` — базовый класс любого документа с идентификатором: даёт поле `_id` типа `ObjectId`. Значение генерируется, если его не передали, и после создания не меняется. Почти каждая модель наследует `Entity` прямо или через `Timestamped` и `Versioned`.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Post extends Entity { // [!code highlight]
  @Prop(() => String, { required: true })
  title!: string;
}
const Posts = client.db().model(Post);
const post = await Posts.create({ title: "Hello" });
console.log(post._id.constructor.name);
// → ObjectId
```

Тип поля `_id` — `Defaulted<Immutable<ObjectId>>`: при создании его передавать не нужно ([`Defaulted`](./field-markers.mdx#defaulted)), а изменить после создания нельзя ([`Immutable`](./field-markers.mdx#immutable)).

Если идентификатором должно быть другое значение (строка, число, `UUID`), наследуйте вместо `Entity` класс [`EntityWithId`](#entitywithid): он даёт то же служебное поле с выбранным вами типом. Модель без `_id` не собирается: `ConfigurationError` (`Slug: a model needs an _id field (extend Entity or declare @Prop _id)`).

`_id` нельзя объявить с `dbName`, с `nullable` и массивом, а также с `index` или `unique`: сервер и так делает его уникальным (`Slug._id: _id is always uniquely indexed by the server; remove index/unique`). Это относится и к `_id`, который вы объявили вручную.

## EntityWithId

`EntityWithId(() => Тип, { default })` — базовый класс документа, у которого `_id` не `ObjectId`: внешний код вроде ISO-кода страны, `UUID`, числовой счётчик или дата. Функция возвращает абстрактный класс с полем `_id` выбранного типа и регистрирует его так же, как [`Entity`](#entity): служебное, неизменяемое поле. Задачи, для которых он нужен: справочники с человекочитаемыми ключами, документы, которым идентификатор выдаёт другая система, идентификаторы, которые нельзя угадать. С `default` идентификатор генерируется, когда его не передали; без `default` он обязателен.

Тип `_id` сквозной. Его читают [`IdOf<T>`](../values/form-types.mdx), [`findById`](../query/reading.mdx#modelfindbyid), ссылки ([`Ref<M, Id>`](./field-markers.mdx#ref)), [`populate`](../populate/populate.mdx#populate), цели [`$out` и `$merge`](../aggregation/stages.mdx#out) и [`keysetPage`](../query/keyset.mdx#modelkeysetpage), поэтому строка в `_id` означает строку везде.

```ts twoslash
import { EntityWithId, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "countries" })
class Country extends EntityWithId(() => String) { // [!code highlight]
  @Prop(() => String, { required: true })
  name!: string;
}
const Countries = client.db().model(Country);
const france = await Countries.create({ _id: "FR", name: "France" });
const found = await Countries.findById("FR").orFail();
console.log(france._id, found.name);
// → FR France
```

Идентификатор с `default` можно не передавать. Миксины [`Timestamped`](#timestamped) и [`Versioned`](#versioned) оборачивают результат так же, как `Entity`: порядок вложения не важен.

```ts twoslash
import { EntityWithId, Prop, Schema, Timestamped, TypemoClient, Types, Versioned } from "@venloc/typemo";
import { UUID } from "mongodb";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "sessions" })
class Session extends Versioned(Timestamped(EntityWithId(() => Types.UUID, { default: () => new UUID() }))) { // [!code highlight]
  @Prop(() => String, { required: true })
  user!: string;
}
const Sessions = client.db().model(Session);
const session = await Sessions.create({ user: "ann" });
console.log(session._id instanceof UUID, session.__v, session.createdAt instanceof Date);
// → true 0 true
```

<Params>
<Param name="type" type="() => IdSpec" required>

Стрелка, которая возвращает тип `_id`, как первый аргумент [`@Prop`](./prop.mdx#prop). Допустимы `String`, `Number`, `BigInt`, `Date`, `Types.UUID`, `Types.ObjectId`, `Types.Int32`, `Types.Double` и `Types.Decimal128`. Другие типы (`Boolean`, массивы, `Spec.*`) компилятор отклоняет. Значение, которое не является функцией, — `ConfigurationError`.

</Param>
<Param name="options.default" type="() => Id">

Функция, которая создаёт идентификатор документа, созданного без него: `() => new UUID()`, `() => crypto.randomUUID()`. С ней `_id` необязателен в `create`, `insertOne` и `insertMany`, без неё — обязателен. Переданный вами `_id` ядро оставляет как есть. Не функция — `ConfigurationError`.

</Param>
</Params>

<Returns type="IdBase<Id, HasDefault>">

Абстрактный класс без аргументов конструктора, у которого есть поле `_id`. Без `default` его тип — `Immutable<Id>`, с `default` — `Defaulted<Immutable<Id>>`: так `create` знает, обязателен ли идентификатор. `Id` выводится из `type`: для `() => String` это `string`, для `() => Types.UUID` — `UUID`, для `() => BigInt` — `bigint`.

</Returns>

<FullType>

```ts
const EntityWithId: EntityWithIdFactory

interface EntityWithIdFactory {
  <const S extends IdSpec>(type: () => S): IdBase<SpecValue<S>, false>;
  <const S extends IdSpec>(
    type: () => S,
    options: { readonly default: () => SpecValue<S> },
  ): IdBase<SpecValue<S>, true>;
}

type IdBase<Id, HasDefault extends boolean> = abstract new () => {
  _id: HasDefault extends true ? Defaulted<Immutable<Id>> : Immutable<Id>;
};

interface EntityIdOptions<Id> {
  readonly default?: () => Id;
}

type IdSpec =
  | StringConstructor | NumberConstructor | BigIntConstructor | DateConstructor
  | typeof UUID | BsonClass<"ObjectId"> | BsonClass<"Int32">
  | BsonClass<"Double"> | BsonClass<"Decimal128">;
```

</FullType>

### Идентификатор обязателен

Без `default` компилятор не даст создать документ без `_id`, а во время работы это `ValidationError`.

```ts twoslash
import { EntityWithId, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
@Schema({ collection: "countries" })
class Country extends EntityWithId(() => String) {
  @Prop(() => String, { required: true })
  name!: string;
}
const Countries = client.db().model(Country);
// ---cut---
try {
  // @errors: 2769
  await Countries.create({ name: "Nowhere" });
} catch (error) {
  console.log((error as Error).message);
}
// → Validation failed: "_id": the field is required [required]
```

Пустая строка для `String` допустима: MongoDB принимает её как идентификатор, поэтому проверяйте такие значения сами, если пустой код для вас ошибка.

### Идентификатор не меняется

Как и у `Entity`, `_id` неизменяем. Обновление, которое его пишет, не компилируется, а во время работы бросает `StrictModeError` с причиной `immutable`. Замена (`replaceOne`) не должна нести `_id` вовсе: документ сохраняет прежний идентификатор, а фильтр выбирает его по `_id`.

```ts twoslash
import { EntityWithId, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
@Schema({ collection: "countries" })
class Country extends EntityWithId(() => String) {
  @Prop(() => String, { required: true })
  name!: string;
}
const Countries = client.db().model(Country);
await Countries.create({ _id: "IT", name: "Italy" });
// ---cut---
try {
  await Countries.updateOne({ _id: "IT" }, { $set: { _id: "XX" } } as never);
} catch (error) {
  console.log((error as Error).message);
}
// → $set._id: "_id" is immutable; it is written only when the document is created ($setOnInsert on upsert) [immutable]
await Countries.replaceOne({ _id: "IT" }, { name: "L'Italia" });
const renamed = await Countries.findById("IT").orFail().lean();
console.log(renamed);
// → { _id: "IT", name: "L'Italia" }
```

Замена с тем же `_id` тоже отклоняется, даже если значение не меняется: `a replacement of Country carries "_id": a replacement keeps the stored _id and cannot change it; leave "_id" out and select the document by _id in the filter [immutable]`.

### Ошибки

Тип, которого нет в `IdSpec`, компилятор отклоняет:

```ts twoslash
import { EntityWithId } from "@venloc/typemo";
// ---cut---
// @errors: 2322
class Flagged extends EntityWithId(() => Boolean) {}
```

Неверный аргумент фабрики — `ConfigurationError` при объявлении класса: `EntityWithId: the spec of the id, as () => String` и ``EntityWithId: `default` is a function that generates the id``. Если передать сам конструктор вместо стрелки (`EntityWithId(String)`), фабрика ошибку не бросает, а схема не соберётся при создании модели: `Country._id: the type thunk returned string, expected a type`. Повторное объявление `_id` другого типа в самом классе — `ConfigurationError` (`Country._id: redeclared with another type (number in Country, string in Identified)`).

## Когда не подходит

Если вам нужен обычный генерируемый идентификатор, наследуйте [`Entity`](#entity): `ObjectId` короче `UUID`, сортируется по времени создания и не требует никакой настройки. `EntityWithId` нужен, когда идентификатор приходит снаружи или должен выглядеть по-другому. Составной `_id`-объект (`{ a, b }`) `EntityWithId` не поддерживает: допустимы только скалярные типы из списка выше.

## Timestamped

`Timestamped(база)` добавляет поля `createdAt` и `updatedAt`. Это функция, которая принимает класс и возвращает расширенный класс: `Timestamped(Entity)`. `createdAt` ставится один раз при создании и не меняется. `updatedAt` обновляется каждой операцией записи, которая дошла до документа: `$save` с изменениями, `updateOne`, `updateMany`, `findOneAndUpdate`, замена и upsert.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Post extends Timestamped(Entity) { // [!code highlight]
  @Prop(() => String)
  title?: string;
}
const Posts = client.db().model(Post);
const post = await Posts.create({ title: "a" });
const created = post.createdAt.getTime();
const updated = post.updatedAt.getTime();
post.title = "b";
await post.$save();
console.log(post.createdAt.getTime() === created, post.updatedAt.getTime() > updated);
// → true true
```

Второй результат показывает, что `updatedAt` вырос, а `createdAt` остался прежним. То же самое происходит при `Posts.updateOne(...)`: `updatedAt` обновился, `createdAt` не изменился.

`updatedAt` двигается **любой** записью, а не только настоящим изменением: ядро до записи не знает, изменит ли что-нибудь сервер. Поэтому `$set` того же значения и `$addToSet` значения, которое уже есть в массиве, тоже обновляют `updatedAt`, и сервер в таких случаях сообщает `modifiedCount: 1`.

Даты можно задать осознанно, и тип это разрешает: при создании необязательны обе (`createdAt?: Date`, `updatedAt?: Date`), а в обновлении можно записать `updatedAt`. Заданную дату ядро оставляет как есть, поэтому так переносят старые данные вместе с историей. `createdAt` после создания записать нельзя: компилятор не пропустит такое обновление, а во время работы это `StrictModeError` с причиной `immutable`.

```ts twoslash
import { Entity, Prop, Schema, Timestamped, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
@Schema()
class Post extends Timestamped(Entity) {
  @Prop(() => String)
  title?: string;
}
const Posts = client.db().model(Post);
// ---cut---
const past = new Date("2001-02-03T04:05:06.000Z");
const imported = await Posts.create({ title: "old", createdAt: past, updatedAt: past }); // [!code highlight]
console.log(imported.createdAt.toISOString(), imported.updatedAt.toISOString());
// → 2001-02-03T04:05:06.000Z 2001-02-03T04:05:06.000Z

await Posts.updateOne({ _id: imported._id }, { $set: { title: "older" } });
const moved = await Posts.findById(imported._id).orFail();
console.log(moved.createdAt.toISOString(), moved.updatedAt.getTime() > past.getTime());
// → 2001-02-03T04:05:06.000Z true
```

Обновление без явного `updatedAt` сдвинуло его вперёд, а `createdAt` остался прежним. Присвоенный в документе `updatedAt` сохраняется как есть: `$save` не затирает заданную вами дату, а `$save` без присваивания двигает её.

<Params>
<Param name="base" type="B extends EntityClass" required>

Класс, который расширяется: `Entity` или результат другого миксина, например `Versioned(Entity)`. Порядок вложения не важен для результата.

</Param>
</Params>

<Returns type="Mixed<B, TimestampFields>">

Абстрактный класс: всё, что есть у `base`, плюс `createdAt: Defaulted<Immutable<Date>>` и `updatedAt: Defaulted<Date>`. Оба поля необязательны при создании (можно передать свою дату), а при чтении они всегда есть.

</Returns>

<FullType>

```ts
const Timestamped: <B extends EntityClass>(base: B) => Mixed<B, TimestampFields>

  createdAt: Defaulted<Immutable<Date>>;
  updatedAt: Defaulted<Date>;
}
```

</FullType>

## Versioned

`Versioned(база)` добавляет числовое поле версии `__v`. Ядро увеличивает версию, когда изменение документа зависит от позиции элементов массива: два процесса, которые одновременно меняют один и тот же массив по индексу, иначе затёрли бы работу друг друга. Вместе с опцией схемы [`optimisticConcurrency`](./schema.mdx#optimisticconcurrency) версия защищает и остальные сохранения.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Doc extends Versioned(Entity) { // [!code highlight]
  @Prop(() => [String])
  tags!: string[];
  @Prop(() => String)
  title?: string;
}
const Docs = client.db().model(Doc);
const doc = await Docs.create({ tags: ["a"] });
console.log(doc.__v);
// → 0
doc.tags.push("b");
await doc.$save();
console.log(doc.__v);
// → 1
doc.title = "x";
await doc.$save();
console.log(doc.__v);
// → 1
```

Версия выросла после изменения массива и осталась прежней после изменения обычного поля: без `optimisticConcurrency` версия защищает только позиционные изменения массивов.

<Params>
<Param name="base" type="B extends EntityClass" required>

Класс, который расширяется: `Entity` или другой миксин.

</Param>
</Params>

<Returns type="Mixed<B, VersionFields>">

Абстрактный класс: всё, что есть у `base`, плюс `__v: Defaulted<number>`.

</Returns>

<FullType>

```ts
const Versioned: <B extends EntityClass>(base: B) => Mixed<B, VersionFields>

interface VersionFields {
  __v: Defaulted<number>;
}
```

</FullType>

Миксины комбинируются: `class User extends Versioned(Timestamped(Entity))` даёт все служебные поля сразу, и подсказки редактора показывают их на сущности.

## Типы

`Mixed<B, F>` — тип результата миксина: абстрактный конструктор экземпляра `InstanceType<B> & F` вместе со статическими членами `B`. Его пишут явным типом, чтобы в публичном API не было `any`. `TimestampFields` и `VersionFields` — интерфейсы полей `Timestamped` и `Versioned`. Для `EntityWithId` экспортируются `IdSpec` (типы, допустимые для `_id`), `EntityIdOptions<Id>` (опции), `IdBase<Id, HasDefault>` (класс, который возвращает фабрика) и `EntityWithIdFactory` (перегрузки самой функции). Все эти типы экспортируются из `@venloc/typemo`.

## Когда не подходит

Метки времени и версию нельзя включить опцией `@Schema`: у декоратора нет `timestamps` и `versionKey`, поля объявляются только через базовые классы. Если нужен другой набор служебных полей или другие имена, объявите поля сами через [`@Prop`](./prop.mdx#prop) (например, `@Prop(() => Date, { default: () => new Date() }) createdAt!: Defaulted<Date>`). Для `_id` другого типа объявлять поле вручную больше незачем: есть [`EntityWithId`](#entitywithid), а `_id`, объявленный вручную через `@Prop`, не получает защиту Typemo от изменения, пока вы не добавите `immutable: true`: до этого его защищает только сервер.
