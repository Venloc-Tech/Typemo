Служебные поля документа — `_id`, `createdAt`, `updatedAt` и версию `__v` — Typemo не добавляет в схему скрытно. Вы получаете их, наследуя базовый класс. `Entity` даёт `_id` типа `ObjectId`, `EntityWithId` — `_id` другого типа (строку, число, `UUID`), `Timestamped` добавляет метки времени, `Versioned` — версию. Поля видны компилятору, подсказкам редактора и типам результатов, и объявлять их в каждой модели вручную не нужно. Ниже описаны все четыре базовых класса и связанные с ними типы.

Обзор с примерами на задачах — в руководствах [Описать модель](../../schemas/define-model.mdx), [Свой тип `_id`](../../schemas/custom-ids.mdx) и [Метки времени и версии](../../schemas/timestamps-and-versions.mdx). Эта страница — справочник.

В примерах модель поста с одним заголовком, а остальные поля приходят от базовых классов. Результаты в `// →` получены на настоящей MongoDB.

У базовых классов нет конструкторов и инициализаторов. Служебные поля заполняет ядро при создании и сохранении. Конструктор базы здесь не годится, потому что при `useDefineForClassFields: true` повторное объявление поля в наследнике молча затёрло бы значение, которое поставила база.

## Entity

`Entity` — базовый класс документа с идентификатором. Он даёт поле `_id` типа `ObjectId`, генерирует значение, если вы его не передали, и не позволяет менять его после создания. Почти каждая модель наследует `Entity` прямо или через `Timestamped` и `Versioned`.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Post extends Entity { // [!code highlight]
  @Prop(() => String, { required: true })
  title!: string;
}
const Posts = client.db().model(Post);
const post = await Posts.create({ title: "Hello" });
console.log(post._id.constructor.name);
// → ObjectId
```

Тип поля `_id` — `Defaulted<Immutable<ObjectId>>`. При создании его можно не передавать ([`Defaulted`](./field-markers.mdx#defaulted)), а после создания нельзя изменить ([`Immutable`](./field-markers.mdx#immutable)).

Нужен другой идентификатор — строка, число, `UUID`? Наследуйте вместо `Entity` класс [`EntityWithId`](#entitywithid). Он даёт то же служебное поле с выбранным вами типом. Модель без `_id` не соберётся и бросит `ConfigurationError` (`Slug: a model needs an _id field (extend Entity or declare @Prop _id)`).

`_id` нельзя объявить с `dbName`, с `nullable` и массивом, а также с `index` или `unique`. Сервер и так делает его уникальным (`Slug._id: _id is always uniquely indexed by the server; remove index/unique`). Это правило касается и `_id`, который вы объявили вручную.

## EntityWithId

`EntityWithId(() => Тип, { default })` — базовый класс документа, у которого `_id` не `ObjectId`. Это может быть внешний код вроде ISO-кода страны, `UUID`, числовой счётчик или дата. Функция возвращает абстрактный класс с полем `_id` выбранного типа и регистрирует его так же, как [`Entity`](#entity), то есть как служебное неизменяемое поле. Пригодится для справочников с человекочитаемыми ключами, для документов, которым идентификатор выдаёт другая система, и для идентификаторов, которые нельзя угадать. С `default` идентификатор генерируется, если вы его не передали. Без `default` он обязателен.

Тип `_id` сквозной. Его читают [`IdOf<T>`](../values/form-types.mdx), [`findById`](../query/reading.mdx#modelfindbyid), ссылки ([`Ref<M, Id>`](./field-markers.mdx#ref)), [`populate`](../populate/populate.mdx#populate), цели [`$out` и `$merge`](../aggregation/stages.mdx#out) и [`keysetPage`](../query/keyset.mdx#modelkeysetpage). Строка в `_id` остаётся строкой везде.

```ts twoslash
import { EntityWithId, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "countries" })
class Country extends EntityWithId(() => String) { // [!code highlight]
  @Prop(() => String, { required: true })
  name!: string;
}
const Countries = client.db().model(Country);
const france = await Countries.create({ _id: "FR", name: "France" });
const found = await Countries.findById("FR").orFail();
console.log(france._id, found.name);
// → FR France
```

Идентификатор с `default` можно не передавать. Миксины [`Timestamped`](#timestamped) и [`Versioned`](#versioned) оборачивают результат так же, как `Entity`, и порядок вложения не важен.

```ts twoslash
import { EntityWithId, Prop, Schema, Timestamped, TypemoClient, Types, Versioned } from "@venloc/typemo";
import { UUID } from "mongodb";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "sessions" })
class Session extends Versioned(Timestamped(EntityWithId(() => Types.UUID, { default: () => new UUID() }))) { // [!code highlight]
  @Prop(() => String, { required: true })
  user!: string;
}
const Sessions = client.db().model(Session);
const session = await Sessions.create({ user: "ann" });
console.log(session._id instanceof UUID, session.__v, session.createdAt instanceof Date);
// → true 0 true
```

<Params>
<Param name="type" type="() => IdSpec" required>

Стрелка, которая возвращает тип `_id`, как первый аргумент [`@Prop`](./prop.mdx#prop). Подходят `String`, `Number`, `BigInt`, `Date`, `Types.UUID`, `Types.ObjectId`, `Types.Int32`, `Types.Double` и `Types.Decimal128`. Другие типы (`Boolean`, массивы, `Spec.*`) компилятор отклоняет. Если вместо функции передать другое значение, будет `ConfigurationError`.

</Param>
<Param name="options.default" type="() => Id">

Функция, которая создаёт идентификатор для документа, созданного без него, например `() => new UUID()` или `() => crypto.randomUUID()`. С ней `_id` необязателен в `create`, `insertOne` и `insertMany`, без неё обязателен. Переданный вами `_id` ядро оставляет как есть. Если `default` не функция, будет `ConfigurationError`.

</Param>
</Params>

<Returns type="IdBase<Id, HasDefault>">

Абстрактный класс без аргументов конструктора, с полем `_id`. Без `default` его тип — `Immutable<Id>`, с `default` — `Defaulted<Immutable<Id>>`, и по этому `create` знает, обязателен ли идентификатор. `Id` выводится из `type`. Для `() => String` это `string`, для `() => Types.UUID` — `UUID`, для `() => BigInt` — `bigint`.

</Returns>

<FullType>

```ts
const EntityWithId: EntityWithIdFactory

interface EntityWithIdFactory {
  <const S extends IdSpec>(type: () => S): IdBase<SpecValue<S>, false>;
  <const S extends IdSpec>(
    type: () => S,
    options: { readonly default: () => SpecValue<S> },
  ): IdBase<SpecValue<S>, true>;
}

type IdBase<Id, HasDefault extends boolean> = abstract new () => {
  _id: HasDefault extends true ? Defaulted<Immutable<Id>> : Immutable<Id>;
};

interface EntityIdOptions<Id> {
  readonly default?: () => Id;
}

type IdSpec =
  | StringConstructor | NumberConstructor | BigIntConstructor | DateConstructor
  | typeof UUID | BsonClass<"ObjectId"> | BsonClass<"Int32">
  | BsonClass<"Double"> | BsonClass<"Decimal128">;
```

</FullType>

### Идентификатор обязателен

Без `default` компилятор не даст создать документ без `_id`, а во время работы вы получите `ValidationError`.

```ts twoslash
import { EntityWithId, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
@Schema({ collection: "countries" })
class Country extends EntityWithId(() => String) {
  @Prop(() => String, { required: true })
  name!: string;
}
const Countries = client.db().model(Country);
// ---cut---
// @errors: 2769
try {
  await Countries.create({ name: "Nowhere" });
} catch (error) {
  console.log((error as Error).message);
}
// → Validation failed: "_id": the field is required [required]
```

Пустая строка для `String` допустима, MongoDB принимает её как идентификатор. Если пустой код для вас ошибка, проверяйте такие значения сами.

### Идентификатор не меняется

Как и у `Entity`, `_id` здесь неизменяем. Обновление, которое его пишет, не компилируется, а во время работы бросает `StrictModeError` с причиной `immutable`. Замена (`replaceOne`) вообще не должна нести `_id`. Документ сохраняет прежний идентификатор, а фильтр выбирает его по `_id`.

```ts twoslash
import { EntityWithId, Prop, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
@Schema({ collection: "countries" })
class Country extends EntityWithId(() => String) {
  @Prop(() => String, { required: true })
  name!: string;
}
const Countries = client.db().model(Country);
await Countries.create({ _id: "IT", name: "Italy" });
// ---cut---
try {
  await Countries.updateOne({ _id: "IT" }, { $set: { _id: "XX" } } as never);
} catch (error) {
  console.log((error as Error).message);
}
// → $set._id: "_id" is immutable; it is written only when the document is created ($setOnInsert on upsert) [immutable]
await Countries.replaceOne({ _id: "IT" }, { name: "L'Italia" });
const renamed = await Countries.findById("IT").orFail().lean();
console.log(renamed);
// → { _id: "IT", name: "L'Italia" }
```

Замену с тем же `_id` тоже отклонят, даже если значение не меняется. Текст ошибки такой — `a replacement of Country carries "_id": a replacement keeps the stored _id and cannot change it; leave "_id" out and select the document by _id in the filter [immutable]`.

### Ошибки

Тип, которого нет в `IdSpec`, компилятор отклоняет.

```ts twoslash
import { EntityWithId } from "@venloc/typemo";
// ---cut---
// @errors: 2322
class Flagged extends EntityWithId(() => Boolean) {}
```

Неверный аргумент фабрики даёт `ConfigurationError` при объявлении класса — `EntityWithId: the spec of the id, as () => String` и ``EntityWithId: `default` is a function that generates the id``. Если передать сам конструктор вместо стрелки (`EntityWithId(String)`), фабрика промолчит, а схема не соберётся при создании модели — `Country._id: the type thunk returned string, expected a type`. Повторное объявление `_id` другого типа в самом классе тоже `ConfigurationError` (`Country._id: redeclared with another type (number in Country, string in Identified)`).

## Когда не подходит

Нужен обычный генерируемый идентификатор — наследуйте [`Entity`](#entity). `ObjectId` короче `UUID`, сортируется по времени создания и не требует настройки. `EntityWithId` берите, когда идентификатор приходит снаружи или должен выглядеть иначе. Составной `_id`-объект (`{ a, b }`) он не поддерживает, допустимы только скалярные типы из списка выше.

## Timestamped

`Timestamped(база)` добавляет поля `createdAt` и `updatedAt`. Это функция, она принимает класс и возвращает расширенный класс — `Timestamped(Entity)`. `createdAt` ставится один раз при создании и не меняется. `updatedAt` обновляется каждой записью, которая дошла до документа. Это `$save` с изменениями, `updateOne`, `updateMany`, `findOneAndUpdate`, замена и upsert.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Post extends Timestamped(Entity) { // [!code highlight]
  @Prop(() => String)
  title?: string;
}
const Posts = client.db().model(Post);
const post = await Posts.create({ title: "a" });
const created = post.createdAt.getTime();
const updated = post.updatedAt.getTime();
post.title = "b";
await post.$save();
console.log(post.createdAt.getTime() === created, post.updatedAt.getTime() > updated);
// → true true
```

Второй результат показывает, что `updatedAt` вырос, а `createdAt` остался прежним. С `Posts.updateOne(...)` будет так же.

`updatedAt` двигается **любой** записью, а не только настоящим изменением. Ядро до записи не знает, изменит ли что-нибудь сервер. Поэтому `$set` того же значения и `$addToSet` значения, которое уже есть в массиве, тоже обновляют `updatedAt`, а сервер в таких случаях сообщает `modifiedCount: 1`.

Даты можно задать сознательно, и тип это разрешает. При создании необязательны обе (`createdAt?: Date`, `updatedAt?: Date`), а в обновлении можно записать `updatedAt`. Заданную дату ядро оставляет как есть, так что вместе с данными переносится их история. `createdAt` после создания записать нельзя. Компилятор не пропустит такое обновление, а во время работы будет `StrictModeError` с причиной `immutable`.

```ts twoslash
import { Entity, Prop, Schema, Timestamped, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
@Schema()
class Post extends Timestamped(Entity) {
  @Prop(() => String)
  title?: string;
}
const Posts = client.db().model(Post);
// ---cut---
const past = new Date("2001-02-03T04:05:06.000Z");
const imported = await Posts.create({ title: "old", createdAt: past, updatedAt: past }); // [!code highlight]
console.log(imported.createdAt.toISOString(), imported.updatedAt.toISOString());
// → 2001-02-03T04:05:06.000Z 2001-02-03T04:05:06.000Z

await Posts.updateOne({ _id: imported._id }, { $set: { title: "older" } });
const moved = await Posts.findById(imported._id).orFail();
console.log(moved.createdAt.toISOString(), moved.updatedAt.getTime() > past.getTime());
// → 2001-02-03T04:05:06.000Z true
```

Обновление без явного `updatedAt` сдвинуло его вперёд, а `createdAt` остался прежним. `updatedAt`, присвоенный в документе, `$save` не затирает. Без присваивания `$save` дату двигает.

<Params>
<Param name="base" type="B extends EntityClass" required>

Класс, который расширяется. Это `Entity` или результат другого миксина, например `Versioned(Entity)`. Порядок вложения на результат не влияет.

</Param>
</Params>

<Returns type="Mixed<B, TimestampFields>">

Абстрактный класс. В нём всё, что есть у `base`, плюс `createdAt: Defaulted<Immutable<Date>>` и `updatedAt: Defaulted<Date>`. При создании оба поля необязательны, можно передать свою дату. При чтении они всегда есть.

</Returns>

<FullType>

```ts
const Timestamped: <B extends EntityClass>(base: B) => Mixed<B, TimestampFields>

interface TimestampFields {
  createdAt: Defaulted<Immutable<Date>>;
  updatedAt: Defaulted<Date>;
}
```

</FullType>

## Versioned

`Versioned(база)` добавляет числовое поле версии `__v`. Ядро увеличивает версию, когда изменение зависит от позиции элементов массива. Без неё два процесса, которые одновременно меняют один массив по индексу, затёрли бы работу друг друга. Вместе с опцией схемы [`optimisticConcurrency`](./schema.mdx#optimisticconcurrency) версия защищает и остальные сохранения.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Doc extends Versioned(Entity) { // [!code highlight]
  @Prop(() => [String])
  tags!: string[];
  @Prop(() => String)
  title?: string;
}
const Docs = client.db().model(Doc);
const doc = await Docs.create({ tags: ["a"] });
console.log(doc.__v);
// → 0
doc.tags.push("b");
await doc.$save();
console.log(doc.__v);
// → 1
doc.title = "x";
await doc.$save();
console.log(doc.__v);
// → 1
```

Версия выросла после изменения массива и осталась прежней после изменения обычного поля. Без `optimisticConcurrency` версия защищает только позиционные изменения массивов.

<Params>
<Param name="base" type="B extends EntityClass" required>

Класс, который расширяется. Это `Entity` или другой миксин.

</Param>
</Params>

<Returns type="Mixed<B, VersionFields>">

Абстрактный класс. В нём всё, что есть у `base`, плюс `__v: Defaulted<number>`.

</Returns>

<FullType>

```ts
const Versioned: <B extends EntityClass>(base: B) => Mixed<B, VersionFields>

interface VersionFields {
  __v: Defaulted<number>;
}
```

</FullType>

Миксины комбинируются. `class User extends Versioned(Timestamped(Entity))` даёт все служебные поля сразу, и подсказки редактора показывают их на сущности.

## Типы

`Mixed<B, F>` — тип результата миксина. Это абстрактный конструктор экземпляра `InstanceType<B> & F` вместе со статическими членами `B`. Его пишут явным типом, чтобы в публичном API не было `any`. `TimestampFields` и `VersionFields` — интерфейсы полей `Timestamped` и `Versioned`. Для `EntityWithId` экспортируются `IdSpec` (типы, допустимые для `_id`), `EntityIdOptions<Id>` (опции), `IdBase<Id, HasDefault>` (класс, который возвращает фабрика) и `EntityWithIdFactory` (перегрузки самой функции). Все эти типы экспортируются из `@venloc/typemo`.

## Когда не подходит

Метки времени и версию нельзя включить опцией `@Schema`. У декоратора нет `timestamps` и `versionKey`, поля объявляются только через базовые классы. Нужен другой набор служебных полей или другие имена — объявите поля сами через [`@Prop`](./prop.mdx#prop), например `@Prop(() => Date, { default: () => new Date() }) createdAt!: Defaulted<Date>`. Для `_id` другого типа вручную объявлять поле незачем, есть [`EntityWithId`](#entitywithid). К тому же `_id`, объявленный вручную через `@Prop`, не получает защиту Typemo от изменения, пока вы не добавите `immutable: true`. До этого его защищает только сервер.
