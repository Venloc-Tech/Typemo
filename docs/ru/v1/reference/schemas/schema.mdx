`@Schema` превращает класс в схему: документ коллекции, поддокумент или вложенный объект. Опции декоратора настраивают коллекцию целиком: как она называется, какого она вида (обычная, ограниченная, временных рядов), какой у неё валидатор, какие политики действуют. На этой странице собраны сам декоратор и **все** его опции, каждая в своём разделе.

Если вы описываете первую модель, сначала прочитайте руководство [Описать модель](../../schemas/define-model.mdx). Особые коллекции разобраны в руководстве [Особые коллекции](../../schemas/special-collections.mdx). Эта страница — справочник.

Опции, которые называют поля класса (`timeseries.timeField`, `discriminatorKey`, поле политики), компилятор сверяет с самим классом: опечатка в имени поля — ошибка на этапе компиляции. Опции, которых у декоратора нет, тоже ошибка компиляции, а в коде без типов — `ConfigurationError` при сборке модели: Typemo не принимает молча `strict`, `strictQuery`, `timestamps`, `versionKey`, `toJSON` и `toObject`.

## @Schema

`@Schema(options?)` записывает опции в описание класса. Без аргумента действуют значения по умолчанию. Класс должен создаваться без аргументов: `new Class()` вызывается при сборке модели для проверок, и конструктор с параметрами — `ConfigurationError`. Класс, который используется как тип поля или как модель, но не помечен `@Schema`, — тоже `ConfigurationError`: `Account: not a schema; decorate the class with @Schema()`.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "accounts" }) // [!code highlight]
class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;
}
const Accounts = client.db().model(Account);
console.log(Accounts.collectionName);
// → accounts
```

<Returns type="(target: C) => void">

Декоратор класса. Во время работы он только записывает опции; схему собирает [`model`](../connection/connection.mdx). Если опции с ошибкой, она найдётся при сборке модели и будет `ConfigurationError` с именем класса.

</Returns>

<Params>
<Param name="options" type="SchemaOptions">

Опции схемы; каждая описана ниже. Тип `SchemaOptions` экспортируется из `@venloc/typemo`.

</Param>
</Params>

  options?: O,

</FullType>

Опечатка в имени опции подсвечивается с подсказкой:

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
// @errors: 2561
@Schema({ colection: "accounts" })
class Account extends Entity {}
```

Компилятор пишет, что `colection` нет в `SchemaOptions`, и предлагает `collection`.

## collection

`collection` — имя коллекции в базе. Без неё Typemo берёт имя класса в нижнем регистре и ставит его во множественное число по английским правилам: `Account` станет `accounts`, `UserProfile` — `userprofiles`. Правила описаны на странице [`CollectionNaming`](./collection-naming.mdx). Если вы работаете с уже существующей коллекцией, указывайте имя явно.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema() // [!code highlight]
class UserProfile extends Entity {}
const Profiles = client.db().model(UserProfile);
console.log(Profiles.collectionName);
// → userprofiles
```

Имя должно быть непустой строкой без `$` и нулевого символа и не должно начинаться с `system.`; иначе `ConfigurationError`: `collection: "system." collections are reserved` или `collection: the collection name "a$b" cannot contain "$" or a null character`.

## nested

`nested: true` объявляет **вложенный объект**: группу полей родителя, у которой не бывает собственного `_id`, хуков, дискриминаторов и опций коллекции. Без опции класс, использованный как тип поля, — **поддокумент**: полноценный участник схемы с хуками. `_id` у поддокумента появляется только тогда, когда класс наследует [`Entity`](./base-classes.mdx#entity) или сам объявляет поле `_id`: обычный `@Schema()` без `Entity` `_id` не получает. Вложенный объект нужен для «адреса» или «имени и фамилии», которые не нужно искать и обновлять по отдельному идентификатору.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ nested: true }) // [!code highlight]
class Name {
  @Prop(() => String, { required: true }) first!: string;
  @Prop(() => String, { required: true }) last!: string;
}
@Schema()
class Person extends Entity {
  @Prop(() => Name, { required: true })
  name!: Name;
}
const People = client.db().model(Person);
console.log(Object.keys(People.schema.describe().paths));
// → ["_id", "name", "name.first", "name.last"]
```

Вложенный объект нельзя использовать как модель: `Name: a nested object (@Schema({ nested: true })) cannot be a model`. Всё, что принадлежит только документам, на нём — `ConfigurationError`, и сообщение перечисляет все нарушения сразу: объявленный `_id` (в том числе унаследованный от `Entity`) — `Name: a nested object (no _id, no own hooks) — it declares _id`, хуки — `it has hooks`, дискриминаторы — `it has discriminators`, а опции `collection`, `discriminatorKey`, `discriminators`, `validator`, `tenant`, `softDelete`, `audit`, `optimisticConcurrency`, `shardKey` и особые коллекции — `option "collection" is for documents`, например `Name: a nested object (no _id, no own hooks) — option "collection" is for documents; option "tenant" is for documents`.

## discriminatorKey

`discriminatorKey` — имя поля, в котором хранится значение дискриминатора: строка, по которой Typemo выбирает класс документа в иерархии. По умолчанию это `__t`, и поле добавляется само. Если вы задаёте своё имя, поле нужно объявить в классе как строку: иначе у базы с наследниками сборка бросает `ConfigurationError` (`Shape: discriminatorKey "kind" is not a declared field (declare it as a string field, or list the discriminators and declare readonly kind?: Discriminators<…>)`). Вторая половина подсказки — про опцию [`discriminators`](#опция-discriminators), при которой ключ объявляется только типом. Как работают дискриминаторы, описано в [`@Discriminator`](./discriminator.mdx#discriminator).

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ discriminatorKey: "kind" }) // [!code highlight]
class Shape extends Entity {
  @Prop(() => String, { required: true })
  kind!: string;
}
```

Ключ, который не является строковым полем класса, компилятор отклоняет: `@Schema: discriminatorKey "kind" is not a string field of the class`. При сборке поле у базы с наследниками должно быть строкой без `nullable`: `Shape: the discriminator key "kind" must be a non-nullable string field`. Опция относится к документам: на вложенном объекте она — `ConfigurationError`.

## Опция discriminators

`discriminators` перечисляет всех наследников базы: `discriminators: () => [Card, Transfer]`. Список нужен типам. Без него тип документа, прочитанного через модель базы, знает только поля базы, а вид приходится сообщать компилятору вручную. Со списком результат чтения через модель базы (гидратированный документ, `lean`, `plain`, JSON и курсор) — объединение «база без ключа или любой из наследников», и проверка ключа сужает его до нужного вида. Список — стрелка, потому что наследники объявляются ниже базы.

Вместе со списком ключ объявляется в классе базы необязательным и типом `Discriminators<…>` ([описание](./discriminator.mdx#discriminators)): документ базы, созданный без вида, по-прежнему разрешён, поэтому у него ключа нет.

```ts twoslash
import { Discriminator, Entity, Prop, Schema, TypemoClient, type Discriminators, type DiscriminatorValue } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "payments", discriminators: () => [Card, Transfer] }) // [!code highlight]
class Payment extends Entity {
  declare readonly __t?: Discriminators<Card | Transfer>; // [!code highlight]
  @Prop(() => Number, { required: true })
  amount!: number;
}

@Discriminator("card")
class Card extends Payment {
  declare readonly __t: DiscriminatorValue<"card">;
  @Prop(() => String, { required: true })
  last4!: string;
}

@Discriminator("transfer")
class Transfer extends Payment {
  declare readonly __t: DiscriminatorValue<"transfer">;
  @Prop(() => String, { required: true })
  iban!: string;
}

const Payments = client.db().model(Payment);
await client.db().model(Card).create({ amount: 30, last4: "4242" });
await client.db().model(Transfer).create({ amount: 500, iban: "PL61" });
await Payments.create({ amount: 5 });
const rows = await Payments.find().sort({ amount: 1 }).plain();
console.log(rows.map((row) => (row.__t === "card" ? `card ${row.last4}` : row.__t === "transfer" ? `transfer ${row.iban}` : `payment ${row.amount}`)));
// → ["payment 5", "card 4242", "transfer PL61"]
```

Ключ `__t` хранится только у документов наследников, у документа базы его нет. Со своим именем ключа объявление меняется вместе с опцией: `discriminatorKey: "kind"` и `declare readonly kind?: Discriminators<Click>`. Поле при этом в классе базы не объявляется декоратором `@Prop`: ключ добавляет сама схема, как и `__t`.

Список проверяется при сборке схемы, с любого класса иерархии, и ошибка называет расхождение. Наследник без записи в списке: `Payment: the "discriminators" list does not match the hierarchy — registered but not listed: Refund`. Лишний класс, который не является `@Discriminator` этой базы: `… — listed but not a @Discriminator class below Payment: Other`. Класс, записанный дважды: `… — a class is listed twice`. Значение, которое не стрелка со списком классов: `Payment: "discriminators" must be a thunk returning a list of classes: () => [Child, …]`. В список входят все наследники, в том числе наследники наследников.

Компилятор сверяет список и объявление ключа: опция без `declare readonly __t?: Discriminators<…>` даёт `@Schema: declare the discriminator key with the listed classes — declare readonly __t?: Discriminators<A | B>`, разные классы в списке и в типе — `@Schema: the classes of __t: Discriminators<…> differ from the "discriminators" list`, а объявление без опции — `@Schema: "__t" is Discriminators<…>, but the schema has no "discriminators" option — add discriminators: () => [A, B]`. Опция относится к документам: на вложенном объекте она — `ConfigurationError`.

## optimisticConcurrency

`optimisticConcurrency` включает **оптимистичную конкурентность**: сохранение документа условно и срабатывает только если документ в базе не менялся с момента чтения, иначе бросается [`VersionError`](../errors/query-errors.mdx#versionerror). Опция требует поля версии, то есть базового класса [`Versioned`](./base-classes.mdx#versioned): без него `ConfigurationError` (`optimisticConcurrency needs the version field — extend Versioned(...)`).

Значения: `true` — каждое `$save`, меняющее документ, проверяет версию и увеличивает её; непустой список путей — только сохранение, затронувшее один из путей (или записавшее целиком массив или поддокумент, который его содержит). Остальные сохранения списка остаются с защитой по умолчанию для позиционных изменений массивов. Пути проверяются по классу: для полей поддокументов пишется `items.price`, для значений Map — `settings.$*`.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ optimisticConcurrency: true }) // [!code highlight]
class Account extends Versioned(Entity) {
  @Prop(() => Number, { default: 0 })
  balance!: Defaulted<number>;
}
const Accounts = client.db().model(Account);
const created = await Accounts.create({});
const first = await Accounts.findOne({ _id: created._id }).orFail();
const second = await Accounts.findOne({ _id: created._id }).orFail();
first.balance = 10;
await first.$save();
second.balance = 20;
try {
  await second.$save();
} catch (error) {
  console.log((error as Error).message);
}
// → Account: no document at version 0 (it was changed or deleted since it was read); modified: balance
```

Второе сохранение не затёрло чужое изменение: оно упало, а `first.__v` стал `1`. Неизвестный путь в списке компилятор отклоняет (`@Schema: optimisticConcurrency names "nope", which is not a path of the class`), а при сборке — `ConfigurationError` с подсказкой про форму путей: `Account: optimisticConcurrency names "nope", which is not a path of the class (subdocument fields as "items.price", a Map's values as "field.$*")`. Пустой список (`Account: optimisticConcurrency is true or a non-empty list of paths`) и повторяющийся путь (`optimisticConcurrency lists a path twice`) тоже запрещены. Опция на поддокументе — ошибка сборки: версионирует корневой документ (`Line: option "optimisticConcurrency" is for the documents of a model — the subdocument at "lines" of Order is versioned by its root (set it on Order)`).

## autoCreate

`autoCreate: false` исключает коллекцию из [`init()`](../connection/connection.mdx#connectioninit) и [`syncAll()`](../connection/connection.mdx#connectionsyncall): они её не создают. По умолчанию `true`. Сама модель ничего на сервере не создаёт, коллекции и индексы создают только эти две операции, поэтому особые коллекции (временных рядов, ограниченные, с валидатором) появляются именно на этом шаге. Отключать опцию стоит, когда коллекцией управляете вы сами: миграция или другой сервис.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "external_events", autoCreate: false }) // [!code highlight]
class ExternalEvent extends Entity {}
const Events = client.db().model(ExternalEvent);
const report = await client.db().init();
console.log(report.created);
// → []
const found = await client.unsafeDriver().db("app").listCollections({ name: "external_events" }).toArray();
console.log(found.length);
// → 0
```

После `init()` отчёт ничего не создал, а коллекции `external_events` на сервере нет: запрос `listCollections` через драйвер вернул пустой список. Опция действует и на явные вызовы: [`Events.createCollection()`](../collections/collection-manager.mdx#modelcreatecollection) при `autoCreate: false` бросает `ConfigurationError` (`ExternalEvent.createCollection: the schema of ExternalEvent says autoCreate: false — Typemo does not create the collection "external_events"; create it where it is owned, or remove autoCreate: false`). Метод [`Events.ensureCollection()`](../collections/collection-manager.mdx#modelensurecollection) создаёт коллекцию несмотря на опцию: вы вызываете его сами и берёте ответственность на себя.

## autoIndex

`autoIndex: false` исключает индексы коллекции из `init()` и `syncAll()`; по умолчанию `true`. Модель сама индексов не строит ни при создании, ни при первой записи. Опция нужна, когда индексы создаёт ваша миграция и приложению не следует делать это при запуске.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "audit_rows", autoIndex: false }) // [!code highlight]
class Row extends Entity {
  @Prop(() => String, { index: true })
  kind?: string;
}
const Rows = client.db().model(Row);
await client.db().init();
const indexes = await client.unsafeDriver().db("app").collection("audit_rows").indexes();
console.log(indexes.map((index) => index.name));
// → ["_id_"]
```

Индекс `kind_1` не построен, остался только обязательный индекс `_id`. Явный вызов [`Rows.createIndexes()`](../collections/model-indexes.mdx#modelcreateindexes) опцию не учитывает и строит индексы схемы: вы просите об этом сами.

## capped

`capped` делает коллекцию **ограниченной**: она хранит не больше заданного размера и вытесняет старые документы новыми. Подходит для журналов, которые нужны только за последнее время. `size` — максимальный размер в байтах (положительное целое, обязательный), `max` — необязательный предел числа документов. Вместе с `clustered` и `timeseries` не используется.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "recent_logs", capped: { size: 4096, max: 5 } }) // [!code highlight]
class Log extends Entity {
  @Prop(() => String) message?: string;
}
const Logs = client.db().model(Log);
await client.db().init();
const [info] = await client.unsafeDriver().db("app").listCollections({ name: "recent_logs" }, { nameOnly: false }).toArray();
console.log(info?.options);
// → { capped: true, size: 4096, max: 5 }
```

Число не положительное — `ConfigurationError` (`capped.size must be a positive integer, got 0`).

## timeseries

`timeseries` делает коллекцию **коллекцией временных рядов**: MongoDB хранит измерения компактно, группируя их в корзины. Опция — объект: `timeField` (обязательный) — поле с временем измерения, остальные — по потребности.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({
  collection: "readings",
  timeseries: { timeField: "at", metaField: "sensor", granularity: "minutes", expireAfterSeconds: 3600 }, // [!code highlight]
})
class Reading extends Entity {
  @Prop(() => Date, { required: true }) at!: Date;
  @Prop(() => String) sensor?: string;
  @Prop(() => Number) value?: number;
}
const Readings = client.db().model(Reading);
await client.db().init();
const [info] = await client.unsafeDriver().db("app").listCollections({ name: "readings" }, { nameOnly: false }).toArray();
console.log(info?.options?.timeseries);
// → { timeField: "at", metaField: "sensor", granularity: "minutes", bucketMaxSpanSeconds: 86400, fixedBucketing: true }
```

Сервер добавил `bucketMaxSpanSeconds` и `fixedBucketing` сам. В коллекции временных рядов нельзя уникальные индексы (`a time series collection cannot have unique indexes`) и нельзя `capped` или `clustered`.

### timeseries.timeField

Имя поля класса с временем измерения. Поле обязано быть `Date`, обязательным (`required: true`) и не `nullable`, иначе `ConfigurationError`: `timeseries: timeField "at" must be required (every measurement has it)`. Компилятор проверяет, что это поле типа `Date`: `@Schema: timeseries.timeField "nope" is not a Date field of the class`.

### timeseries.metaField

Необязательное имя поля с метаданными измерения (датчик, устройство). Не может быть `_id` и совпадать с `timeField`. Компилятор: `@Schema: timeseries.metaField "x" is not a field of the class (and not _id)`.

### timeseries.granularity

Подсказка серверу о частоте измерений: `"seconds"`, `"minutes"` или `"hours"`. Вместе с `bucketMaxSpanSeconds` и `bucketRoundingSeconds` не используется (`timeseries.granularity cannot be combined with bucketMaxSpanSeconds/bucketRoundingSeconds`).

### timeseries.bucketMaxSpanSeconds

Максимальный интервал одной корзины в секундах, положительное целое. Задаётся вместе с `bucketRoundingSeconds` и с тем же значением: сервер требует равенства, и Typemo проверяет это заранее (`timeseries.bucketMaxSpanSeconds and bucketRoundingSeconds must both be set and equal (the server requires it)`).

### timeseries.bucketRoundingSeconds

Округление начала корзины в секундах; правила те же, что у `bucketMaxSpanSeconds`.

### timeseries.expireAfterSeconds

Автоматическое удаление старых измерений через указанное число секунд, неотрицательное целое.

---

## clustered

`clustered` делает коллекцию **кластерной**: документы хранятся в порядке `_id`, а индекс по `_id` совпадает с самой коллекцией. Значение `true` включает опцию с настройками сервера по умолчанию; объект принимает `name` (имя кластерного индекса) и `expireAfterSeconds`. С `capped` и `timeseries` не сочетается: коллекция временных рядов уже кластерная, `ConfigurationError` подскажет: `a time series collection is clustered by itself; remove clustered`.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "clustered_docs", clustered: { name: "by_id" } }) // [!code highlight]
class ClusteredDoc extends Entity {}
const Docs = client.db().model(ClusteredDoc);
await client.db().init();
const [info] = await client.unsafeDriver().db("app").listCollections({ name: "clustered_docs" }, { nameOnly: false }).toArray();
console.log(info?.options);
// → { clusteredIndex: { v: 2, key: { _id: 1 }, name: "by_id", unique: true } }
```

### clustered.name

Имя кластерного индекса; если не задано, имя выберет сервер.

### clustered.expireAfterSeconds

Время жизни документов: удаляются те, чей `_id` (дата) старше указанного. Требует `_id` типа `Date`, иначе `ConfigurationError`: `clustered.expireAfterSeconds needs a Date _id`.

---

## collation

`collation` — правила сравнения строк для коллекции по умолчанию: язык, чувствительность к регистру и акцентам. Значение — объект настроек сортировки драйвера MongoDB. Индексы без собственной сортировки её наследуют.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "names", collation: { locale: "en", strength: 2 } }) // [!code highlight]
class Named extends Entity {
  @Prop(() => String) name?: string;
}
const Names = client.db().model(Named);
await client.db().init();
const [info] = await client.unsafeDriver().db("app").listCollections({ name: "names" }, { nameOnly: false }).toArray();
console.log(info?.options?.collation?.strength);
// → 2
```

Текстовый индекс и индекс `2d` не поддерживают сортировку. Поэтому при коллекции с сортировкой такой индекс нужно объявить с `collation: { locale: "simple" }`, иначе `ConfigurationError`: `a text index cannot have a collation; the collection has a default one, so declare the index with collation: { locale: "simple" }`.

---

## validator

`validator` создаёт на сервере валидатор коллекции `$jsonSchema`, построенный из схемы: сервер отвергает документы, нарушающие типы, обязательные поля, `enum`, границы и длины, даже если их пишет другая программа. `true` включает валидатор с уровнем `strict` и действием `error`; объект уточняет их. Опция применяется при создании коллекции, то есть при `init()` с `autoCreate`.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "checked", validator: { validationLevel: "moderate", validationAction: "warn" } }) // [!code highlight]
class Checked extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
const Items = client.db().model(Checked);
await client.db().init();
const [info] = await client.unsafeDriver().db("app").listCollections({ name: "checked" }, { nameOnly: false }).toArray();
console.log(info?.options);
// → { validator: { $jsonSchema: { bsonType: "object", properties: { _id: { bsonType: "objectId" }, name: { bsonType: "string" } }, required: ["_id", "name"], additionalProperties: false } }, validationLevel: "moderate", validationAction: "warn" }
```

Валидатор строго закрыт: `additionalProperties: false` на каждом уровне. Свои функции `validate`, границы дат и правила ключей Map на сервере выразить нельзя, их проверяет только Typemo. Как строится схема, описано в [`JsonSchemaGenerator`](./json-and-standard-schema.mdx#jsonschemagenerator).

### validationLevel

Какие документы проверяет сервер: `"strict"` — все вставки и обновления, `"moderate"` — только уже валидные документы, `"off"` — никакие. По умолчанию `strict`.

### validationAction

Что делает сервер с нарушением: `"error"` отклоняет запись, `"warn"` только пишет предупреждение в журнал. По умолчанию `error`.

## changeStreamPreAndPostImages

`changeStreamPreAndPostImages: true` включает на коллекции запись состояния документа до и после изменения. Это нужно потокам изменений, которые просят `fullDocumentBeforeChange` или `fullDocument: "required" | "whenAvailable"`.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "watched", changeStreamPreAndPostImages: true }) // [!code highlight]
class Watched extends Entity {}
const Docs = client.db().model(Watched);
await client.db().init();
const [info] = await client.unsafeDriver().db("app").listCollections({ name: "watched" }, { nameOnly: false }).toArray();
console.log(info?.options);
// → { changeStreamPreAndPostImages: { enabled: true } }
```

## shardKey

`shardKey` описывает ключ шардирования коллекции: объект `{ поле: 1 | "hashed" }`. Нужен для одного: `$save` и `bulkSave` фильтруют по **исходным** значениям полей ключа (как они были прочитаны), поэтому документ, у которого поле ключа изменилось, всё равно находится. Поле должно быть полем верхнего уровня (`shardKey names "x", which is not a top-level field`), значение — `1` или `"hashed"` (`shardKey "x" must be 1 or "hashed"`). Сам ключ на сервере вы объявляете командами администратора: Typemo коллекцию не шардирует. Действие на шардированном кластере запуском не проверялось.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "orders", shardKey: { region: 1 } }) // [!code highlight]
class Order extends Entity {
  @Prop(() => String, { required: true }) region!: string;
}
```

## readConcern

`readConcern` объявляет уровень согласованности чтения коллекции по умолчанию: `{ level: "majority" }`. Значение проверяется типом (`ReadConcernLevel` драйвера). Уровень уходит на сервер с каждым чтением модели: `find`, `findOne`, `countDocuments`, `distinct` и `aggregate`. Уровень, заданный у самой операции ([`.readConcern()`](../query/options.mdx#readconcern)), главнее схемного. Внутри транзакции схемный уровень не отправляется: там действуют настройки самой транзакции.

```ts twoslash
import { Entity, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "ledger", readConcern: { level: "majority" } }) // [!code highlight]
class Ledger extends Entity {}
```

## writeConcern

`writeConcern` объявляет гарантию записи коллекции по умолчанию (`w`, `journal`, `wtimeoutMS` в виде настроек драйвера). Правила те же, что у [`readConcern`](#readconcern): гарантия уходит с каждой записью модели (`insert`, `update`, `delete`, `findAndModify`), [`.writeConcern()`](../writes/writes.mdx#writeconcern) у операции главнее, а внутри транзакции схемная гарантия не отправляется.

```ts twoslash
import { Entity, Schema, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ collection: "ledger_writes", writeConcern: { w: "majority" } }) // [!code highlight]
class LedgerWrite extends Entity {}
```

## softDelete

`softDelete` включает политику **мягкого удаления**: удалённый документ остаётся в коллекции с отметкой времени, а обычные запросы его не видят. `true` берёт поле `deletedAt`; объект позволяет выбрать другое имя через [`field`](#field). Поле должно быть `Date | null`: при сборке иначе `ConfigurationError` (`Note: softDelete field "deletedAt" must be a nullable Date field (Date | null)`), а компилятор говорит `@Schema: softDelete field "deletedAt" is not a Date | null field of the class`.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ softDelete: true }) // [!code highlight]
class Note extends Entity {
  @Prop(() => Date, { nullable: true })
  deletedAt!: Date | null;
}
```

Как политика меняет запросы и записи, описано в справочнике [опций политик](../policies/schema-options.mdx) и в разделе о политиках.

## tenant

`tenant` включает политику **мультитенантности**: все запросы модели фильтруются по полю владельца, а запись ставит в него текущего тенанта. `true` берёт поле `tenantId`, объект выбирает имя через [`field`](#field). Поле объявляется парой: декоратор [`@Tenant()`](./field-markers.mdx#tenant) рядом с `@Prop` и тип [`TenantField<T>`](./field-markers.mdx#tenantfield). Тип говорит компилятору, что ядро заполняет поле само: `create` его не требует, а чтение всегда его содержит. Декоратор говорит то же самое времени работы: по нему схема находит, какое поле несёт тенанта.

```ts twoslash
import { Entity, Prop, Schema, Tenant, TypemoClient, type TenantField } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ tenant: true }) // [!code highlight]
class Doc extends Entity {
  @Prop(() => String) @Tenant() // [!code highlight]
  tenantId!: TenantField<string>;

  @Prop(() => String, { required: true })
  title!: string;
}
const Docs = client.db().model(Doc);
const doc = await Docs.create({ title: "Plan" }, { policy: { tenant: "acme" } });
console.log(doc.tenantId);
// → acme
```

Схема без пары не собирается. Ошибки компиляции: поле не объявлено типом `TenantField<T>` — `@Schema: declare the tenant field as tenantId!: TenantField<T> — the core fills it, create() does not require it, reads always have it`; тип без опции — `@Schema: "tenantId" is TenantField<T>, but the schema has no tenant option — add tenant: { field: "tenantId" } or use a plain type`; тип на другом поле — `@Schema: "owner" is TenantField<T>, but the tenant field is "tenantId"`. При сборке те же правила проверяет время работы, и всё — `ConfigurationError`:

- поля нет в классе: `Doc: tenant field "tenantId" is not a field of the class`;
- поле есть, но без `@Tenant()`: `Doc: the tenant field "tenantId" must be marked @Tenant() (declare it @Prop(...) @Tenant() tenantId!: TenantField<T>)`;
- `@Tenant()` есть, а опции `tenant` нет: `Doc: @Tenant() on "tenantId", but the schema has no tenant policy — add tenant: true (or { field }) to @Schema`;
- `@Tenant()` стоит на двух полях: `Doc: @Tenant() marks "tenantId", "other"; only the tenant field "tenantId" may be marked`.

Подробности политики, в том числе как передать тенанта запросу, — в [опциях политик](../policies/schema-options.mdx).

## audit

`audit` включает политику **аудита**: каждая запись модели оставляет запись в журнале. `true` пишет в коллекцию `<коллекция>_audit`; объект позволяет выбрать имя через `collection`. Запись вне транзакции выполняется в собственной транзакции (запись и её след фиксируются вместе), поэтому нужен реплика-сет или шардированный кластер: на одиночном `mongod` такая запись — `ConfigurationError`.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ audit: { collection: "users_history" } }) // [!code highlight]
class Customer extends Entity {}
```

Что попадает в журнал и как поля скрываются, описано в [`sensitive`](./prop.mdx#sensitive) и в руководстве по политикам.

## field

`field` — общая опция объектов `tenant` и `softDelete`: имя поля класса, которое несёт политику. Для `tenant` по умолчанию `tenantId`, для `softDelete` — `deletedAt`. Проверка имени описана в соответствующих разделах.

```ts twoslash
import { Entity, Prop, Schema, Tenant, TypemoClient, type TenantField } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema({ tenant: { field: "orgId" }, softDelete: { field: "removedAt" } }) // [!code highlight]
class Doc extends Entity {
  @Prop(() => String) @Tenant() orgId!: TenantField<string>;
  @Prop(() => Date, { nullable: true }) removedAt!: Date | null;
}
```

## ext

`ext` хранит опции зарегистрированных расширений на уровне схемы: метаданные для интеграций, проверенные расширением и замороженные после сборки. Ключ — имя расширения; незарегистрированный ключ — ошибка компиляции (`@Schema: ext "nope" is not a registered extension (SchemaExtensions)`) и, в коде без типов, `ConfigurationError` при сборке: `Account: ext "nope" is not a registered extension; register it before the first model with client.use() (for the models of one client) or Typemo.use() (for every client)`. Читает опции интеграция через [`SchemaInfo.ext`](./schema-info.mdx#ext). Подробнее — в руководстве [Свои опции полей и схем](../../extensions/custom-options.mdx).

## Ошибки, общие для всех опций

Опций, которых нет в списке, у `@Schema` нет. `toJSON` и `toObject` — частный случай с отдельным текстом: параметры сериализации передаются в каждый вызов `$toJSON()`, `$toObject()` и `$toPlain()`, иначе тип результата не мог бы следовать за настройкой схемы.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type TenantField, type VirtualRef } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
// @errors: 2353
@Schema({ toJSON: {} })
class Account extends Entity {}
```

В коде без типов при сборке модели: `Account: @Schema has no "toJSON" option — pass serialization options to each $toJSON()/$toObject()/$toPlain() call`. Любой другой неизвестный ключ (`strict`, `strictQuery`, `timestamps`, `versionKey`) при сборке даёт `ConfigurationError` со списком допустимых опций: `Account: @Schema has no "strict" option (the options are: collection, nested, ext, discriminatorKey, discriminators, timeseries, capped, collation, clustered, changeStreamPreAndPostImages, validator, autoIndex, autoCreate, readConcern, writeConcern, optimisticConcurrency, shardKey, tenant, softDelete, audit)`. Ошибки, которые называют одну опцию, описаны в её разделе. Остальные проверки сборки:

- у модели нет `_id`: `Account: a model needs an _id field (extend Entity or declare @Prop _id)`. Для `_id` другого типа есть базовый класс [`EntityWithId`](./base-classes.mdx#entitywithid);
- `_id` не бывает с `dbName`, `nullable` и массивом;
- дискриминатор с собственным `@Schema`: `Circle: a discriminator uses its root's schema options; remove @Schema (root: Shape)`;
- у класса есть собственное свойство данных без `@Prop`: `Account: property "note" has no @Prop, so it is not a field of the schema (never stored, cast or loaded); decorate it with @Prop, declare it with "declare", or make it a getter or a method`. Методы, геттеры и неперечисляемые свойства не считаются;
- поле совпадает с методом класса: `Account: field "foo" is also a method of the class`;
- у конструктора есть параметры: `Account: the constructor takes 1 argument(s); an entity is created by Typemo without arguments`.

## Когда не подходит

`@Schema` настраивает коллекцию и политики, но не поля и не индексы по нескольким полям. Поле описывает [`@Prop`](./prop.mdx#prop), составной и частичный индекс — [`@Index`](./index-decorators.mdx#index), значение дискриминатора — [`@Discriminator`](./discriminator.mdx#discriminator). Поля `_id`, `createdAt`, `updatedAt` и `__v` добавляют базовые классы [`Entity`](./base-classes.mdx#entity), [`Timestamped`](./base-classes.mdx#timestamped) и [`Versioned`](./base-classes.mdx#versioned), а не опции схемы.
