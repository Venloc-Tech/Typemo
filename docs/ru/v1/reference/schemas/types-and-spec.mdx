Тип поля в [`@Prop`](./prop.mdx#prop) задаёт функция, которая возвращает **спецификацию**. Это может быть обычный конструктор (`String`, `Number`, `Date`, `BigInt`), класс из `Types` или объект, построенный через `Spec`. Здесь описаны оба набора. `Types` — готовые классы значений BSON, `Spec` — построители составных типов (Map, объединение, бинарные данные, вектор). Страница пригодится, когда нужно выбрать между `Number` и `Types.Int32` или объявить поле-карту.

Руководство по выбору типа с примерами — [Типы полей](../../schemas/field-types.mdx). Эта страница — справочник.

Примеры строятся на одной модели с полями разных типов. Каждое поле появляется в разделе, где о нём речь. Результаты в комментариях `// →` получены на настоящей MongoDB.

---

## Types [#types]

`Types` — пространство имён с классами значений BSON. Через них создают значения и объявляют поля. Это `Types.ObjectId`, `Types.UUID`, `Types.Decimal128`, `Types.Int32`, `Types.Double`, `Types.Timestamp`, `Types.Binary`, а ещё `Types.Long`, `Types.MinKey` и `Types.MaxKey`. Все они — классы драйвера MongoDB, реэкспортированные из одного места. Значение, созданное через `Types.ObjectId`, и значение, прочитанное из базы, принадлежат одному классу, так что `instanceof` не подводит.

Полем становятся не все классы. `Types.Long` не тип поля, для int64 берите `BigInt`. `Types.MinKey` и `Types.MaxKey` не поддерживаются как устаревшие типы BSON. В обоих случаях модель не соберётся и бросит `ConfigurationError` с текстом `Long is not a field type: use BigInt (int64 is a bigint)` или `MinKey is not supported as a field type (legacy BSON types)`.

Три случая стоит показать на деле. `Types.Int32`, в отличие от `Number`, не даст записать дробное число.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Sample extends Entity {
  @Prop(() => Types.Int32) // [!code highlight]
  count?: number;
}
const Samples = client.db().model(Sample);
try {
  await Samples.create({ count: 1.5 });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to Int32 failed at path "count" for 1.5 (number): a fractional number is not an Int32 [integer]
try {
  await Samples.create({ count: 2 ** 40 });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to Int32 failed at path "count" for 1099511627776 (number): out of the Int32 range [-2^31, 2^31 - 1] [range]
```

`BigInt` и `Types.Decimal128` хранят числа, которые не помещаются в точный `number`. В результате `$toPlain()` и в JSON они становятся строками, иначе клиент получил бы число JavaScript с потерей точности.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Sample extends Entity {
  @Prop(() => BigInt) big?: bigint; // [!code highlight]
  @Prop(() => Types.Decimal128) price?: Types.Decimal128; // [!code highlight]
  @Prop(() => Types.UUID) token?: Types.UUID;
  @Prop(() => Types.ObjectId) owner?: Types.ObjectId;
}
const Samples = client.db().model(Sample);
const sample = await Samples.create({
  big: 9007199254740993n,
  price: Types.Decimal128.fromString("1.10"),
  token: "0a1b2c3d-0000-4000-8000-000000000001",
  owner: "6abcfab53690ef6b2db71493",
});
console.log(sample.$toPlain());
// → { _id: "…", big: "9007199254740993", price: "1.10", token: "0a1b2c3d-0000-4000-8000-000000000001", owner: "6abcfab53690ef6b2db71493" }
```

Строку вместо `ObjectId` и `UUID` принимают все методы записи и фильтры. `Decimal128` берёт десятичную строку (`"1.10"`) наравне с `Types.Decimal128.fromString("1.10")`. `BigInt` берёт `bigint` и десятичную строку, в том числе в `$inc`, `$mul`, `$min` и `$max`. Некорректная десятичная запись для `BigInt` даёт `CastError` с текстом `a string must be a decimal integer (no sign +, leading zeros, -0, spaces, exponent or prefix) [format]`. Обычное число для `BigInt` принимается во время работы, только если оно безопасное целое. Иначе будет `CastError` с подсказкой `pass a bigint (5n) or a decimal integer string ("5")`. Для `Decimal128` число принимается через его десятичную запись, но типы такой ввод не пропускают.

Все формы каждого типа (документ, результат `.lean()`, `$toPlain()`, JSON) собраны в разделе [Формы значений](../values/value-forms.mdx).

### Types.Binary [#types.binary]

Двоичные данные подтипа 0. Значение — экземпляр `Types.Binary`, а в результате `$toPlain()` приходит `Uint8Array`. Для другого подтипа возьмите [`Spec.binary`](#spec.binary).

## Spec [#spec]

`Spec` — класс со статическими построителями. Каждый возвращает замороженный объект-спецификацию, который отдаётся в `@Prop(() => Spec.xxx(...))`. Функция вокруг спецификации уже ленивая, поэтому внутри `Spec` отдельные функции не нужны. `@Prop(() => Spec.map(Address))` безопасен при любом порядке объявления классов.

### Spec.map [#spec.map]

`Spec.map(значение, опции?)` описывает поле-словарь. Ключи в нём строки, значения заданного типа. В базе он лежит вложенным документом, в коде это `Map<string, V>`. Берите его, когда ключи заранее неизвестны, например оценки по предметам или настройки по названиям.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Student extends Entity {
  @Prop(() => Spec.map(Number)) // [!code highlight]
  scores?: Map<string, number>;
}
const Students = client.db().model(Student);
const student = await Students.create({ scores: { math: 5 } });
student.scores?.set("art", 4);
console.log([...(student.scores ?? [])]);
// → [["math", 5], ["art", 4]]
```

Ключи проверяются сразу. Пустой ключ, ключ с точкой, ключ со знаком `$` в начале и `__proto__` запрещены. MongoDB прочла бы точку как путь, а `$` как оператор.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Student extends Entity {
  @Prop(() => Spec.map(Number))
  scores?: Map<string, number>;
}
const Students = client.db().model(Student);
try {
  await Students.create({ scores: { "a.b": 1 } });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to Map key failed at path "scores.a.b" for "a.b" (string): a key cannot contain "." (it would be read as a path) [key]
try {
  await Students.create({ scores: { $x: 1 } });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to Map key failed at path "scores.$x" for "$x" (string): a key cannot start with "$" (reserved for operators) [key]
```

Значение `null` в карте запрещено, пока вы не разрешите его явно. `Spec.map(Number, { nullable: true })` даёт `Map<string, number | null>`, а значения хранятся как BSON null. Без флага придёт `Cast to number failed at path "scores.a" for null: null is not allowed on a path that is not nullable [null]`.

<Params>
<Param name="of" type="TypeSpec" required>

Спецификация значений. Подойдёт любой допустимый тип поля, в том числе класс с `@Schema` или массив.

</Param>
<Param name="options.nullable" type="true">

`{ nullable: true }` разрешает `null` в значениях. Типы принимают только `true`. Объект из `Spec.map` хранит опцию так, как её передали, в поле `nullable` (тип `MapSpec` объявляет его как `nullable?: unknown`). Без опции поля нет. Поэтому любое другое значение не пройдёт молча. Это `false`, `"yes"` или `1` из кода без типов, а также копия спецификации вроде `{ ...Spec.map(Number), nullable: false }`. При сборке модели будет `ConfigurationError` `F.x: Spec.map options: "nullable" must be true`, где `F.x` — класс и поле. Чтобы запретить `null`, просто не пишите опцию.

</Param>
</Params>

`$toPlain()` и `$toObject()` оставляют `Map` как есть, а `$toJSON()` превращает его в обычный объект.

### Spec.union [#spec.union]

`Spec.union(A, B, …)` описывает поле, которое может быть одним из нескольких скалярных типов, например `string | number`. Значение проверяется по своему типу, и **ровно один** член должен его принять. Членов не меньше двух. Объединение классов — уже дело дискриминаторов, читайте [`@Discriminator`](./discriminator.mdx#discriminator).

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Setting extends Entity {
  @Prop(() => Spec.union(String, Number)) // [!code highlight]
  value?: string | number;
}
const Settings = client.db().model(Setting);
try {
  await Settings.create({ value: true as never });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to string | number failed at path "value" for true (boolean): no member accepts this value (members: string, number) [union-no-match]
```

Члены, которые принимают одни и те же значения, ломают сборку. `Number` и `Types.Int32` вместе дают `ConfigurationError` (`union members number and int32 accept the same values (exactly one member must claim a value)`). С одним членом ошибка другая — `a union needs at least two members`. Компилятор тоже требует не меньше двух аргументов.

### Spec.binary [#spec.binary]

`Spec.binary({ subtype })` описывает двоичные данные заданного подтипа. Подтип 0 — это `Types.Binary`, 4 — `Types.UUID`, 9 — `Spec.vector`. Остальные, например пользовательские от 128, объявляются этим построителем.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Blob extends Entity {
  @Prop(() => Spec.binary({ subtype: 128 })) // [!code highlight]
  payload?: Types.Binary;
}
const Blobs = client.db().model(Blob);
const blob = await Blobs.create({ payload: new Types.Binary(new Uint8Array([3]), 128) });
console.log(blob.payload?.sub_type);
// → 128
```

### Spec.vector [#spec.vector]

`Spec.vector({ dtype, dimensions? })` описывает **вектор** BSON (двоичные данные подтипа 9) для векторного поиска. `dtype` задаёт тип элемента — `"int8"`, `"float32"` или `"packedBit"`. `dimensions` — точное число элементов, если оно фиксировано. Без него подойдёт любая ненулевая длина. Поле объявляется типом [`Vector`](./field-markers.mdx#vector).

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Embedding extends Entity {
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) // [!code highlight]
  values?: Vector;
}
const Embeddings = client.db().model(Embedding);
const embedding = await Embeddings.create({ values: [1, 2, 3] }); // [!code highlight]
console.log(embedding.$toPlain().values);
// → [1, 2, 3]
try {
  await Embeddings.create({ values: [1, 2] });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to Vector<float32, 3> failed at path "values" for [array of 2]: expected 3 dimensions, got 2 [dimensions]
```

На входе вектор можно передать обычным массивом чисел (`number[]`), типизированным массивом (`Float32Array` для `float32`, `Int8Array` для `int8`) или готовым `Binary` подтипа 9 с тем же типом, например из `Types.Binary.fromFloat32Array`. Типы ввода разрешают `Vector` и `number[]`. Другой типизированный массив во время работы отклоняется, потому что `Float32Array` в `int8` округлил бы значения молча (`Cast to Vector<int8, 2> failed at path "v" for a Float32Array: expected a subtype-9 Binary, a number[] or an Int8Array of int8 [type]`). Вектор и обычный `Binary` — один класс, и различает их маркер [`Vector`](./field-markers.mdx#vector). Формы в результате `$toPlain()` у них разные, `number[]` и байты.

### Spec.isSpecObject [#spec.is-spec-object]

`Spec.isSpecObject(value)` возвращает `true` для объекта, построенного через `Spec.*`. Он нужен инструментам, которые читают результат функции типа в `@Prop`. В обычной модели вы его не вызываете.

## Типы спецификаций [#spec-types]

Экспортируются типы `TypeSpec` (всё, что может вернуть функция в `@Prop`), `ScalarSpec`, `EntityClass`, `MapSpec`, `MapSpecOptions`, `MapSpecBuilder`, `UnionSpec`, `BinarySpec`, `VectorSpec` и `SpecValue`. `SpecValue<S>` вычисляет тип поля по спецификации.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const spec = Spec.map(Number);
type Scores = SpecValue<typeof spec>;
//   ^?
```

## Когда не подходит [#when-not-to-use]

Если ключи известны заранее, `Spec.map` не нужен. Опишите вложенный объект классом с [`@Schema({ nested: true })`](./schema.mdx#nested), и поля будут проверяться по отдельности и появятся в подсказках. Если значения разных классов лежат в одной коллекции, берите [`@Discriminator`](./discriminator.mdx#discriminator), а не `Spec.union`. Для списка значений одного типа хватит `[X]`.
