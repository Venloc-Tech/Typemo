Тип поля в [`@Prop`](./prop.mdx#prop) задаёт функция, которая возвращает **спецификацию**: обычный конструктор (`String`, `Number`, `Date`, `BigInt`), класс из `Types` или объект, построенный через `Spec`. На этой странице описаны оба набора: `Types` — готовые классы значений BSON, `Spec` — построители составных типов (Map, объединение, бинарные данные, вектор). Сюда приходят, когда нужно выбрать между `Number` и `Types.Int32` или узнать, как объявить поле-карту.

Руководство по выбору типа с примерами — [Типы полей](../../schemas/field-types.mdx). Эта страница — справочник.

Примеры используют одну модель с полями разных типов, каждое добавляется в разделе, где о нём говорится. Результаты в комментариях `// →` получены запуском на настоящей MongoDB.

---

## Types

`Types` — пространство имён с классами значений BSON, которые нужны, чтобы создавать значения и объявлять поля: `Types.ObjectId`, `Types.UUID`, `Types.Decimal128`, `Types.Int32`, `Types.Double`, `Types.Timestamp`, `Types.Binary`, а также `Types.Long`, `Types.MinKey`, `Types.MaxKey`. Это классы драйвера MongoDB, реэкспортированные из одного места: значение, созданное через `Types.ObjectId`, и значение, прочитанное из базы, — экземпляры одного и того же класса, поэтому `instanceof` не подводит.

Как поле подходят не все классы: `Types.Long` не тип поля, для int64 используется `BigInt`, а `Types.MinKey` и `Types.MaxKey` не поддерживаются как устаревшие типы BSON. Оба случая — `ConfigurationError` при сборке модели: `Long is not a field type: use BigInt (int64 is a bigint)` и `MinKey is not supported as a field type (legacy BSON types)`.

Разберём три частых случая. `Types.Int32` в отличие от `Number` не позволяет записать дробное число:

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Sample extends Entity {
  @Prop(() => Types.Int32) // [!code highlight]
  count?: number;
}
const Samples = client.db().model(Sample);
try {
  await Samples.create({ count: 1.5 });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to Int32 failed at path "count" for 1.5 (number): a fractional number is not an Int32 [integer]
try {
  await Samples.create({ count: 2 ** 40 });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to Int32 failed at path "count" for 1099511627776 (number): out of the Int32 range [-2^31, 2^31 - 1] [range]
```

Числа, которые не помещаются в точный `number`, хранятся типами `BigInt` и `Types.Decimal128`; в plain-виде и JSON они становятся строками, потому что клиент получит число JavaScript с потерей точности:

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Sample extends Entity {
  @Prop(() => BigInt) big?: bigint; // [!code highlight]
  @Prop(() => Types.Decimal128) price?: Types.Decimal128; // [!code highlight]
  @Prop(() => Types.UUID) token?: Types.UUID;
  @Prop(() => Types.ObjectId) owner?: Types.ObjectId;
}
const Samples = client.db().model(Sample);
const sample = await Samples.create({
  big: 9007199254740993n,
  price: Types.Decimal128.fromString("1.10"),
  token: "0a1b2c3d-0000-4000-8000-000000000001",
  owner: "6abcfab53690ef6b2db71493",
});
console.log(sample.$toPlain());
// → { _id: "…", big: "9007199254740993", price: "1.10", token: "0a1b2c3d-0000-4000-8000-000000000001", owner: "6abcfab53690ef6b2db71493" }
```

Строку вместо `ObjectId` и `UUID` принимают все методы записи и фильтры. `Decimal128` принимает десятичную строку (`"1.10"`) наравне с `Types.Decimal128.fromString("1.10")`, а `BigInt` — `bigint` и десятичную строку, в том числе в `$inc`, `$mul`, `$min` и `$max`. Некорректная десятичная запись для `BigInt` — `CastError`: `a string must be a decimal integer (no sign +, leading zeros, -0, spaces, exponent or prefix) [format]`. Обычное число для `BigInt` во время работы принимается, только если оно безопасное целое: иначе `CastError` с подсказкой `pass a bigint (5n) or a decimal integer string ("5")`, а для `Decimal128` число принимается через его десятичную запись, но типы его не пропускают.

Все формы каждого типа (документ, lean, plain, JSON) собраны в разделе [Формы значений](../values/value-forms.mdx).

### Types.Binary

Двоичные данные подтипа 0. Значение — экземпляр `Types.Binary`; в plain-виде — `Uint8Array`. Для другого подтипа используйте [`Spec.binary`](#specbinary).

## Spec

`Spec` — класс со статическими построителями. Каждый возвращает замороженный объект-спецификацию, который передаётся в `@Prop(() => Spec.xxx(...))`. Функция вокруг спецификации уже ленивая, поэтому внутри `Spec` отдельные функции не нужны: `@Prop(() => Spec.map(Address))` безопасен при любом порядке объявления классов.

### Spec.map

`Spec.map(значение, опции?)` описывает поле-словарь: ключи — строки, значения — заданного типа, в базе он хранится как вложенный документ, в коде — как `Map<string, V>`. Нужен, когда ключи заранее неизвестны: оценки по предметам, настройки по названиям.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Student extends Entity {
  @Prop(() => Spec.map(Number)) // [!code highlight]
  scores?: Map<string, number>;
}
const Students = client.db().model(Student);
const student = await Students.create({ scores: { math: 5 } });
student.scores?.set("art", 4);
console.log([...(student.scores ?? [])]);
// → [["math", 5], ["art", 4]]
```

Ключи проверяются сразу, пустой ключ, ключ с точкой или `$` в начале и `__proto__` запрещены, потому что MongoDB читала бы точку как путь, а `$` как оператор:

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Student extends Entity {
  @Prop(() => Spec.map(Number))
  scores?: Map<string, number>;
}
const Students = client.db().model(Student);
try {
  await Students.create({ scores: { "a.b": 1 } });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to Map key failed at path "scores.a.b" for "a.b" (string): a key cannot contain "." (it would be read as a path) [key]
try {
  await Students.create({ scores: { $x: 1 } });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to Map key failed at path "scores.$x" for "$x" (string): a key cannot start with "$" (reserved for operators) [key]
```

Значение `null` в карте запрещено, если не разрешить его явно: `Spec.map(Number, { nullable: true })` даёт `Map<string, number | null>`, а значения хранятся как BSON null. Без флага: `Cast to number failed at path "scores.a" for null: null is not allowed on a path that is not nullable [null]`.

<Params>
<Param name="of" type="TypeSpec" required>

Спецификация значений: любой допустимый тип поля, в том числе класс с `@Schema` или массив.

</Param>
<Param name="options.nullable" type="true">

`{ nullable: true }` разрешает `null` в значениях. Типы принимают только `true`. Объект, который возвращает `Spec.map`, хранит опцию так, как её передали, в поле `nullable` (тип `MapSpec` объявляет его как `nullable?: unknown`), а без опции поля нет. Поэтому любое другое значение — из кода без типов (`false`, `"yes"`, `1`) или в копии спецификации вроде `{ ...Spec.map(Number), nullable: false }` — не молчит: при сборке модели это `ConfigurationError` `F.x: Spec.map options: "nullable" must be true`, где `F.x` — класс и поле. Чтобы запретить `null`, опцию просто не пишут.

</Param>
</Params>

`$toPlain()` и `$toObject()` оставляют `Map`, `$toJSON()` превращает его в обычный объект.

### Spec.union

`Spec.union(A, B, …)` описывает поле, которое может быть одним из нескольких скалярных типов: `string | number`. Значение проверяется по своему типу, и **ровно один** член должен его принять. Членов не меньше двух. Объединение классов — это уже дискриминаторы, см. [`@Discriminator`](./discriminator.mdx#discriminator).

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Setting extends Entity {
  @Prop(() => Spec.union(String, Number)) // [!code highlight]
  value?: string | number;
}
const Settings = client.db().model(Setting);
try {
  await Settings.create({ value: true as never });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to string | number failed at path "value" for true (boolean): no member accepts this value (members: string, number) [union-no-match]
```

Члены, которые принимают одни и те же значения, — ошибка сборки: `Number` и `Types.Int32` вместе дают `ConfigurationError` (`union members number and int32 accept the same values (exactly one member must claim a value)`); один член — `a union needs at least two members`. Компилятор требует не меньше двух аргументов.

### Spec.binary

`Spec.binary({ subtype })` описывает двоичные данные заданного подтипа. Подтип 0 — это `Types.Binary`, 4 — `Types.UUID`, 9 — `Spec.vector`; остальные, например пользовательские от 128, объявляются этим построителем.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Blob extends Entity {
  @Prop(() => Spec.binary({ subtype: 128 })) // [!code highlight]
  payload?: Types.Binary;
}
const Blobs = client.db().model(Blob);
const blob = await Blobs.create({ payload: new Types.Binary(new Uint8Array([3]), 128) });
console.log(blob.payload?.sub_type);
// → 128
```

### Spec.vector

`Spec.vector({ dtype, dimensions? })` описывает **вектор** BSON (двоичные данные подтипа 9) для векторного поиска. `dtype` — тип элемента: `"int8"`, `"float32"` или `"packedBit"`. `dimensions` — точное число элементов, если оно фиксировано; без него принимается любая ненулевая длина. Поле объявляется типом [`Vector`](./field-markers.mdx#vector).

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
@Schema()
class Embedding extends Entity {
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) // [!code highlight]
  values?: Vector;
}
const Embeddings = client.db().model(Embedding);
const embedding = await Embeddings.create({ values: [1, 2, 3] }); // [!code highlight]
console.log(embedding.$toPlain().values);
// → [1, 2, 3]
try {
  await Embeddings.create({ values: [1, 2] });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to Vector<float32, 3> failed at path "values" for [array of 2]: expected 3 dimensions, got 2 [dimensions]
```

Вход принимает обычный массив чисел (`number[]`), типизированный массив (`Float32Array` для `float32`, `Int8Array` для `int8`) или готовый `Binary` подтипа 9 с тем же типом, например из `Types.Binary.fromFloat32Array`. Типы ввода разрешают `Vector` и `number[]`. Другой типизированный массив во время работы отклоняется: превращение `Float32Array` в `int8` округлило бы значения молча (`Cast to Vector<int8, 2> failed at path "v" for a Float32Array: expected a subtype-9 Binary, a number[] or an Int8Array of int8 [type]`). Вектор и обычный `Binary` — один и тот же класс, и различает их маркер [`Vector`](./field-markers.mdx#vector): их plain-формы разные (`number[]` и байты).

### Spec.isSpecObject

`Spec.isSpecObject(value)` возвращает `true`, если значение — объект, построенный через `Spec.*`. Нужен инструментам, которые читают результат функции типа `@Prop`. В обычной модели вы его не вызываете.

## Типы спецификаций

Экспортируются типы `TypeSpec` (всё, что может вернуть функция `@Prop`), `ScalarSpec`, `EntityClass`, `MapSpec`, `MapSpecOptions`, `MapSpecBuilder`, `UnionSpec`, `BinarySpec`, `VectorSpec` и `SpecValue`. `SpecValue<S>` вычисляет тип поля по спецификации.

```ts twoslash
import { Discriminator, Entity, Index, Prop, Schema, SearchIndex, Spec, Timestamped, TypemoClient, Types, Versioned, Virtual, type Computed, type Defaulted, type DiscriminatorValue, type Hidden, type Immutable, type Ref, type SpecValue, type TenantField, type VirtualRef, type Vector } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const spec = Spec.map(Number);
type Scores = SpecValue<typeof spec>;
//   ^?
```

## Когда не подходит

Если ключи известны заранее, `Spec.map` не нужен: опишите вложенный объект классом с [`@Schema({ nested: true })`](./schema.mdx#nested), тогда поля проверяются по отдельности и видны в подсказках. Если значения разных классов лежат в одной коллекции, используйте [`@Discriminator`](./discriminator.mdx#discriminator), а не `Spec.union`. Для списка значений одного типа хватит `[X]`.
