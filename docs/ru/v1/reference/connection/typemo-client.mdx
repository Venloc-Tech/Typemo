`TypemoClient` держит одно подключение к MongoDB. Он открывает и закрывает его, следит за состоянием, выдаёт [`Connection`](./connection.mdx) для каждой базы и запускает транзакции. Модели привязаны к подключению своего клиента. Глобального клиента в Typemo нет, вы создаёте клиент сами и передаёте туда, где он нужен.

Если вы только начинаете, сначала прочитайте руководство [Подключиться к базе](../../connection/connect.mdx). Эта страница — справочник, к ней возвращаются за деталями.

Внутри клиента живёт один `MongoClient` официального драйвера `mongodb`. Пул соединений, повторные попытки, выбор сервера и переподключение остаются за драйвером. Typemo добавляет состояние, ожидание готовности и свои проверки настроек.

Во всех примерах одна и та же модель счёта.

```ts twoslash title="accounts/account.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;
}
```

Остальное лежит в соседних справочниках. Модели и базы — в [`Connection`](./connection.mdx), глобальные настройки — в [`Typemo`](./typemo.mdx), состояния — в [`ConnectionState`](./connection-state.mdx).

## TypemoClient.connect

`TypemoClient.connect` создаёт клиент и сразу подключает его. Это самый частый старт — одна строка при запуске приложения или скрипта, и клиент готов.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// ---cut---
const client = await TypemoClient.connect("mongodb://localhost:27017/app", { timeoutMS: 30_000 });
console.log(client.state);
// → "connected"
```

<Returns type="Promise<TypemoClient>">

Подключённый клиент. Если подключиться не удалось, промис падает с [`ConnectionError`](../errors/configuration-errors.mdx#connectionerror). Клиент при этом не возвращается, так что закрывать нечего.

</Returns>

<Params>
<Param name="uri" type="string" required>

Строка подключения, `mongodb://` или `mongodb+srv://`. Любая другая, например `localhost:27017` без схемы, даёт `ConfigurationError` ещё до попытки подключиться.

</Param>
<Param name="options" type="TypemoClientOptions" default="{}">

Опции драйвера и собственные опции Typemo. Подробно в разделе [Опции клиента](#опции-клиента).

</Param>
</Params>

<FullType>

```ts
static connect(uri: string, options?: TypemoClientOptions): Promise<TypemoClient>
```

</FullType>

### Когда подключиться не удалось

Если сервер недоступен, драйвер ждёт подходящий сервер `serverSelectionTimeoutMS` (по умолчанию 30 секунд) и сдаётся. Typemo превращает эту ошибку в `ConnectionError` с полем `failure`, по которому видна причина. Ожидание в примере короткое, а нужный порт никто не слушает.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// ---cut---
try {
  await TypemoClient.connect("mongodb://127.0.0.1:1/", { serverSelectionTimeoutMS: 300 });
} catch (error) {
  console.log(String(error));
  // → "ConnectionError: no server available: connect ECONNREFUSED 127.0.0.1:1"
}
```

У `failure` четыре значения. `closed` — клиент уже закрыт. `server-selection` — сервер не нашёлся, как выше. `network` — сбой сети. `authentication` — сервер отверг учётные данные. Первые два проверены на настоящей базе, остальные описаны по коду.

### Когда не подходит

Если клиент нужен заранее, а подключиться можно позже, возьмите [`new TypemoClient`](#new-typemoclient) и вызовите [`client.connect`](#clientconnect) в нужный момент.

## new TypemoClient

Конструктор создаёт клиент и **не** подключает его. Он нужен, когда клиент должен существовать раньше подключения. Например, модули импортируют готовый клиент, а подключается приложение уже при старте.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// ---cut---
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app", name: "main" });
console.log(client.state);
// → "idle"
```

Пока вы не вызвали [`client.connect`](#clientconnect), операции моделей не падают. Они ждут подключения, но не дольше `readyTimeoutMS`. Подробности в разделе [`client.ready`](#clientready).

<Params>
<Param name="uri" type="string" required>

Строка подключения, как у [`TypemoClient.connect`](#typemoclientconnect).

</Param>
<Param name="options" type="TypemoClientOptions" default="{}">

Опции клиента. Typemo копирует и проверяет объект, сам он остаётся нетронутым.

</Param>
</Params>

<FullType>

```ts
constructor(uri: string, options?: TypemoClientOptions)
```

</FullType>

### Ошибки настройки

Все опции проверяет конструктор и бросает `ConfigurationError`, то есть раньше любого обращения к сети.

```text
ConfigurationError: TypemoClient: the first argument is a connection string (mongodb:// or mongodb+srv://)
ConfigurationError: TypemoClient: dbName "other" conflicts with the database "app" of the connection string
ConfigurationError: TypemoClient: socketTimeoutMS is not supported; use timeoutMS (client-side operation timeout)
ConfigurationError: TypemoClient: dbName must be a non-empty string
ConfigurationError: TypemoClient: name must be a non-empty string
ConfigurationError: TypemoClient: timeoutMS must be a non-negative integer, got -1
ConfigurationError: TypemoClient: readyTimeoutMS must be a non-negative integer, got -1
ConfigurationError: TypemoClient: keysetSecret[0] is 3 bytes; an HMAC key needs at least 32
ConfigurationError: TypemoClient: keysetSecret is an empty list
ConfigurationError: TypemoClient: validateReads must be true, false or "development", got "yes"
```

Первая строка — адрес без `mongodb://`. Вторая — `dbName`, не совпавший с базой из строки подключения. Третья — старая опция таймаута. Остальные — пустое или недопустимое значение. Две базы «по умолчанию» отправили бы операции не туда. А три старых таймаута драйвера заменил один, [`timeoutMS`](#опции-клиента), поэтому Typemo не принимает их и подсказывает замену.

## client.connect

`client.connect` подключает клиент, созданный через [`new TypemoClient`](#new-typemoclient). Повторный вызов безопасен. Пока клиент подключается или уже подключён, вы получите тот же результат без нового подключения.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
await client.connect();
await client.connect(); // второй вызов ничего не делает
```

<Returns type="Promise<this>">

Тот же клиент. Если подключиться не удалось, промис падает с `ConnectionError`, а состояние клиента возвращается в `idle`, и `connect` можно вызвать ещё раз.

</Returns>

Закрытый клиент заново не подключить. Создайте новый.

```text
ConnectionError: TypemoClient "default" is closed; create a new client
```

<FullType>

```ts
connect(): Promise<this>
```

</FullType>

## client.db

`client.db` возвращает [`Connection`](./connection.mdx) — одну базу этого клиента вместе с её моделями. По сети вызов ничего не делает, сервер создаст базу при первой записи.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const app = client.db();
const reports = client.db("reports");
console.log(app.name, reports.name);
// → "app" "reports"
console.log(client.db("reports") === reports);
// → true
```

<Returns type="Connection">

Подключение к базе. Для одного имени вы всегда получаете один и тот же объект, поэтому зарегистрированные на нём модели не теряются между вызовами.

</Returns>

<Params>
<Param name="name" type="string" default="client.options.dbName">

Имя базы. Пустую строку Typemo не принимает и бросает `ConfigurationError` с текстом `TypemoClient.db: a database name`. Без аргумента берётся база по умолчанию — `dbName`, база из строки подключения или `test`.

</Param>
</Params>

<FullType>

```ts
db(name?: string): Connection
```

</FullType>

То же самое делает [`connection.useDb`](./connection.mdx#connectionusedb), только от соединения.

## client.connection

`client.connection` — короткая запись для `client.db()`, то есть подключение к базе по умолчанию.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
console.log(client.connection === client.db());
// → true
```

Тип — `Connection`. Модель берите через [`client.connection.model(Account)`](./connection.mdx#connectionmodel) или `client.db().model(Account)`.

## client.aggregate

`client.aggregate` выполняет агрегацию уровня базы, не привязанную к модели. Это выполняющиеся операции (`$currentOp`), литеральные документы (`$documents`), локальные сессии (`$listLocalSessions`) и сессии сервера (`$listSessions`). Метод нужен, когда под рукой есть клиент, но нет ни модели, ни подключения, например в проверке состояния сервера. План строят [`Pipeline.database`](../aggregation/pipeline.mdx#pipelinedatabase), [`Pipeline.admin`](../aggregation/pipeline.mdx#pipelineadmin) и [`Pipeline.sessions`](../aggregation/pipeline.mdx#pipelinesessions).

```ts twoslash
import { Pipeline, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const running = await client.aggregate(Pipeline.admin().currentOp({ idleConnections: false }).plan());
console.log(running.length > 0);
// → true
const rows = await client.aggregate(Pipeline.database().documents([{ n: 1 }]).plan());
console.log(rows);
// → [{ n: 1 }]
```

Метод делает то же, что [`connection.aggregate`](./connection.mdx#connectionaggregate) у подключения к базе по умолчанию. `Pipeline.database()` работает в базе `client.options.dbName`, `Pipeline.admin()` — в `admin`, `Pipeline.sessions()` — в `config.system.sessions`.

Операция идёт через общий конвейер операций. Её события для [`client.instrument`](#clientinstrument) приходят с `model: null` и `collection: null`, а у `Pipeline.sessions` коллекция `"system.sessions"`. В транзакции `client.transaction` она участвует сама, `timeoutMS` и ошибки Typemo работают как у моделей. Хуки не вызываются, потому что у операции нет модели, на которой их можно объявить.

<Returns type="AggregateQuery<R>">

Запрос агрегации, типизированный строками плана. `await` даёт массив строк, `.cursor()` отдаёт их по одной, `.explain()` показывает план сервера.

</Returns>

<Params>
<Param name="plan" type="AggregatePlan<R>" required>

План из `.plan()` строителя `Pipeline.database()`, `Pipeline.admin()` или `Pipeline.sessions()`.

</Param>
<Param name="options" type="ModelAggregateOptions">

`session` (`null` выполняет вне текущей транзакции), `timeoutMS` и `policy`.

</Param>
</Params>

<FullType>

```ts
aggregate<R>(plan: AggregatePlan<R>, options?: ModelAggregateOptions): AggregateQuery<R>
```

</FullType>

Ошибки те же, что у подключения. Если передать не план агрегации, будет `QueryError` (`client.aggregate: an aggregation plan of Pipeline.database(), Pipeline.admin() or Pipeline.sessions()`). План над коллекцией модели даст `ConfigurationError` (`client.aggregate: the plan reads the collection "accounts"; run it with the model's aggregate()`). Сценарии разобраны в руководстве [Запросы уровня базы](../../aggregation/database-level.mdx).

## client.ready

`client.ready` ждёт, пока клиент подключится. Нужен он редко, потому что обычные операции моделей сами дожидаются подключения. Берите его, когда подождать надо явно, например перед запуском HTTP-сервера, а `connect` вы не вызываете сами.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app", readyTimeoutMS: 5_000 });
// ---cut---
await client.ready(1_000);
```

Если клиент уже подключён, метод возвращается сразу. Иначе он ждёт, пока `connect` завершится, но не дольше лимита. По истечении времени вы получите `TimeoutError` с полем `kind: "connection"`. Текст ниже мы получили для клиента, у которого `connect` так и не вызвали.

```text
TimeoutError: TypemoClient "default" is not connected after 50 ms: call connect() (operations issued before connect() wait for it)
```

<Params>
<Param name="timeoutMS" type="number" default="client.options.readyTimeoutMS">

Сколько ждать подключения, в миллисекундах. Ноль — ждать без ограничения.

</Param>
</Params>

Возвращает `Promise<void>`. После `close` метод бросает `ConnectionError` со значением `failure: "closed"`. Если `connect` завершился ошибкой, та же ошибка достанется всем, кто ждёт в `ready`.

<FullType>

```ts
ready(timeoutMS?: number): Promise<void>
```

</FullType>

### Операции до connect

Операция модели, начатая до `connect`, не падает и не встаёт в очередь на повтор. Она просто продолжится, когда клиент подключится. Лимит ожидания — собственный `timeoutMS` операции, а без него `readyTimeoutMS` клиента. Когда лимит вышел, операция падает с тем же `TimeoutError`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
}
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const Accounts = client.connection.model(Account);
const pending = Accounts.countDocuments(); // клиент ещё не подключён
await client.connect();
const total = await pending;
//    ^?
```

## client.state

`client.state` — текущее состояние клиента, одно из `idle`, `connecting`, `connected`, `unavailable` и `closed`. Typemo выводит его из событий драйвера о топологии, поэтому оно одинаково для одиночного сервера, реплика-сета, шардированного кластера и балансировщика. Каждое состояние и переходы описаны на странице [`ConnectionState`](./connection-state.mdx).

Тип — [`ConnectionState`](./connection-state.mdx), свойство только для чтения.

## client.onStateChange

`client.onStateChange` подписывает функцию на смену состояния. Она пригодится для проверок готовности, метрик и журнала — «подключились», «потеряли сервер», «закрыли клиент».

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const stop = client.onStateChange((state) => console.log(state));
await client.connect();
// → "connecting"
// → "connected"
await client.close();
// → "closed"
stop();
```

<Returns type="() => void">

Функция, которая отменяет подписку.

</Returns>

<Params>
<Param name="listener" type="(state: ConnectionState) => void" required>

Получает новое состояние после каждой смены. Повторные события с тем же состоянием до подписчика не доходят. Начальное `idle` ему тоже не присылается, его узнайте через [`client.state`](#clientstate).

</Param>
</Params>

<FullType>

```ts
onStateChange(listener: (state: ConnectionState) => void): () => void
```

</FullType>

## client.close

`client.close` закрывает клиент. Драйвер завершает сессии и закрывает пул соединений. Клиент остаётся в состоянии `closed` навсегда, а все операции падают с `ConnectionError` со значением `failure: "closed"`.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
await client.close();
await client.close(); // повторный вызов ничего не делает
```

Операции, которые в момент закрытия ждали подключения, тоже падают с `ConnectionError` и `failure: "closed"`, но с текстом `TypemoClient "default" was closed`. Операции, начатые после закрытия, получают `TypemoClient "default" is closed; create a new client`. Закрывается весь клиент, а с ним все `Connection`, которые вы получили через [`client.db`](#clientdb).

<Params>
<Param name="force" type="boolean" default="false">

Уходит в `close` драйвера. Закрыть, даже если операции ещё выполняются.

</Param>
</Params>

<FullType>

```ts
close(force?: boolean): Promise<void>
```

</FullType>

## client[Symbol.asyncDispose]

Объявите клиент через `await using`, и он закроется сам в конце блока, даже если внутри бросили ошибку. Метод вызывает [`client.close`](#clientclose) без аргументов.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// ---cut---
let captured: TypemoClient;
{
  await using client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
  captured = client;
}
console.log(captured.state);
// → "closed"
```

<FullType>

```ts
[Symbol.asyncDispose](): Promise<void>
```

</FullType>

## client.name

Имя клиента в событиях наблюдаемости. Оно берётся из опции `name`, по умолчанию `"default"`. Пригодится, когда в приложении несколько клиентов и в журнале надо понять, откуда пришла операция. Тип `string`, только чтение.

## client.options

Опции клиента после проверки. Среди них `client.options.dbName`, `client.options.readyTimeoutMS`, `client.options.name`, `client.options.validateReads` (включено ли [строгое чтение](#validatereads), уже с учётом `"development"`), `client.options.driver` (что ушло в драйвер) и `client.options.keysetSecrets` (ключи подписи токенов, копии в виде байтов). Объект заморожен. Он показывает итог слияния, так что `dbName` из строки подключения виден здесь.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// ---cut---
const fromUri = new TypemoClient("mongodb://localhost:27017/reports");
console.log(fromUri.options.dbName);
// → "reports"
const fallback = new TypemoClient("mongodb://localhost:27017");
console.log(fallback.options.dbName, fallback.options.readyTimeoutMS);
// → "test" 10000
```

## client.supportsTransactions

Умеет ли сервер транзакции. Для реплика-сета, шардированного кластера и балансировщика это `true`, для одиночного `mongod` — `false`. Пока клиент не подключался и топология неизвестна, значение `undefined`. Свойство удобно в проверке готовности, чтобы заметить неверную конфигурацию сервера раньше первой упавшей транзакции.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
console.log(client.supportsTransactions);
// → undefined
await client.connect();
console.log(client.supportsTransactions);
// → true  (на реплика-сете)
```

## client.server

Первый хост из строки подключения, `{ address, port }`, либо `undefined`, если хоста в строке нет. Для реплика-сета это первый указанный адрес, а не обязательно сервер, который обслужил операцию. Значение идёт в атрибуты наблюдаемости.

## client.startSession

`client.startSession` открывает явную сессию драйвера, например чтобы передать её запросу через `.session()`. Обычно она не нужна, потому что [`client.transaction`](#clienttransaction) сама создаёт и закрывает сессию. Как и [`client.ready`](#clientready), метод ждёт готовности клиента.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const session = await client.startSession();
try {
  // операции с .session(session)
} finally {
  await session.endSession();
}
```

Закрывать сессию придётся вам, Typemo этого не делает. О ручных сессиях читайте в руководстве [Сессии вручную](../../transactions/sessions.mdx).

<Params>
<Param name="options" type="ClientSessionOptions">

Параметры сессии драйвера.

</Param>
</Params>

Возвращает `Promise<ClientSession>`. Бросает `ConnectionError`, если клиент закрыт, и `TimeoutError`, если подключение не состоялось вовремя.

## client.transaction

`client.transaction` выполняет функцию в транзакции. Операции моделей внутри функции присоединяются к ней сами, сессию передавать не нужно. При временных сбоях сервера драйвер повторяет функцию целиком, так что она может выполниться не раз. Поэтому побочных эффектов вне базы, вроде писем и платежей, в ней быть не должно. Полное описание ищите в руководстве [Транзакции](../../transactions/transactions.mdx) и в [справочнике транзакций](../transactions/transactions.mdx).

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.connection.model(Account);
// ---cut---
const attempt = await client.transaction(async (scope) => {
  await Accounts.create({ title: "Savings", owner: "alice" });
  return scope.attempt;
});
console.log(attempt);
// → 1
```

Транзакции не вкладываются. Вызов внутри транзакции того же клиента бросает `ConfigurationError`.

```text
ConfigurationError: transaction(): transactions do not nest (already inside a transaction of this client)
```

Для транзакций нужен реплика-сет или шардированный кластер. На одиночном `mongod` (`client.supportsTransactions` равен `false`) вызов бросает `ConfigurationError` раньше, чем выполнится функция и что-то запишется.

```text
ConfigurationError: TypemoClient "default": transaction(): transactions need a replica set or a sharded cluster; this server is a standalone mongod. Run MongoDB as a replica set (a single-member one is enough).
```

Проверить это заранее можно через [`client.supportsTransactions`](#clientsupportstransactions).

<Params>
<Param name="fn" type="(scope: TransactionScope) => Promise<R>" required>

Функция транзакции. Получает `TransactionScope` с сессией и номером попытки (`scope.attempt`, для первого запуска это 1).

</Param>
<Param name="options" type="TransactionOptions" default="{}">

Уровень чтения (`readConcern` — `local`, `majority` или `snapshot`), запись при фиксации (`writeConcern`), общий срок (`timeoutMS`) и предел времени фиксации на сервере (`maxCommitTimeMS`).

</Param>
</Params>

<Returns type="Promise<R>">

Что вернула функция, уже после фиксации. Ошибка вашей функции приходит без изменений (`caught === thrown`), а ошибка сервера или фиксации — в виде ошибки Typemo. Если вышел срок `timeoutMS` транзакции, будет [`TimeoutError`](../errors/server-errors.mdx#timeouterror) с `kind: "transaction"` и заполненным `timeoutMS`.

</Returns>

Повтор функции опасен для документа, загруженного **до** транзакции и изменённого внутри (`doc.balance -= 10`, затем `$save()`). Он изменится дважды, и вместо 90 из 100 у нас получилось 80. Загружайте документы внутри функции или меняйте их атомарной записью (`$inc`). Разбор с примером в руководстве [Транзакции](../../transactions/transactions.mdx#документы-загруженные-снаружи).

Операции внутри транзакции нельзя запускать одновременно через `Promise.all`. Сервер этого не умеет, и Typemo отказывает сам ошибкой, которая называет обе операции, `Account.create: the session is in use by Account.create, which has not finished; …`.

<FullType>

```ts
transaction<R>(fn: TransactionCallback<R>, options?: TransactionOptions): Promise<R>

type TransactionCallback<R> = (scope: TransactionScope) => Promise<R>
```

</FullType>

На уровне соединения то же делает [`connection.transaction`](./connection.mdx#connectiontransaction).

Идёт ли вызов уже внутри транзакции этого клиента, скажет [`client.currentTransaction`](../transactions/transactions.mdx#clientcurrenttransaction). Транзакции не вкладываются, и обёртка, которую зовут и снаружи, и изнутри транзакции, решает по нему, открывать ли свою.

## client.instrument

`client.instrument` подписывает наблюдателя на операции **этого** клиента. Он получает начало и конец операции, шаги, ошибки и события транзакций. На этом работают интеграции OpenTelemetry и Sentry. Пока подписчиков нет, наблюдаемость ничего не стоит.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const subscription = client.instrument({
  handle: (event) => {
    if (event.type === "operation.end") console.log(event.operation, event.durationMS);
  },
});
subscription.unsubscribe();
```

<Params>
<Param name="subscriber" type="InstrumentationSubscriber" required>

Объект с функцией `handle` и необязательными настройками `driverCommands`, `poolEvents`, `steps`, `sensitive`, `includeTenant`, `wrap`. Полный перечень в справочнике [События](../observability/events.mdx).

</Param>
</Params>

<Returns type="Subscription">

Объект с методом `unsubscribe()`. Повторный вызов ничего не делает. Он же работает с `using`, и подписка снимается на выходе из блока.

</Returns>

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
{
  using subscription = client.instrument({ handle: (event) => console.log(event.type) });
  // внутри блока события приходят
}
// здесь подписка уже снята
```

Если подписчик просит события команд драйвера (`driverCommands: true`), а клиент создан без `monitorCommands: true`, вы получите `ConfigurationError`. Молча остаться без событий Typemo не даст.

```text
ConfigurationError: TypemoClient "default": driver command events need the client option monitorCommands: true
```

Подписаться на все клиенты сразу можно через [`Typemo.instrument`](./typemo.mdx#typemoinstrument). О работе с событиями читайте в руководстве [События операций](../../observability/events.mdx).

## client.use

`client.use` регистрирует расширение схемы для моделей **этого** клиента. Имя расширения становится допустимым ключом в `ext` у `@Prop` и `@Schema`, а его проверки разбирают каждое значение при компиляции схемы. Ключ нужно ещё объявить для компилятора через `declare module "@venloc/typemo"`, как в примере ниже. Без объявления имя расширения не пройдёт проверку типов. Если расширение нужно всем клиентам, зарегистрируйте его через [`Typemo.use`](./typemo.mdx#typemouse).

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
declare module "@venloc/typemo" {
  interface PropExtensions<V> {
    label?: { readonly text: string };
  }
}
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
client.use({
  name: "label",
  validateProp: (value) => {
    if (typeof value !== "object" || value === null) throw new Error("label: an object is expected");
  },
});
```

Регистрируйте расширение до первой модели клиента. Позднее расширение не проверило бы уже скомпилированные схемы. Реестр закрывает первая **успешная** компиляция модели этого клиента. Если компиляция упала, например из-за неизвестного ключа в `ext`, реестр остаётся открытым, и нужное расширение ещё можно зарегистрировать.

```text
ConfigurationError: extension "late": extensions are fixed once a schema is compiled (Account was); call client.use() before the first model
ConfigurationError: extension "label" is already registered
```

Первая — регистрация после первой модели. Вторая — повторное имя, занятое на этом клиенте или глобально. Руководство — [Несколько клиентов и расширения](../../connection/clients-and-extensions.mdx). Об устройстве расширений читайте в справочнике [Расширения](../extensions/extensions.mdx).

<Params>
<Param name="extension" type="TypemoExtension" required>

Объект `{ name, validateProp?, validateSchema? }`. Нужна хотя бы одна проверка. Имя не пустое и не начинается с `$`. Проверка получает значение и бросает ошибку, если оно неверно, — эта ошибка станет `cause` у `ConfigurationError`.

</Param>
</Params>

## client.unsafeDriver

`client.unsafeDriver` возвращает настоящий `MongoClient` драйвера. Он нужен для того, что Typemo не оборачивает, — команд администратора, GridFS и возможностей драйвера, которых нет у моделей. Всё, что вы делаете через него, полностью обходит Typemo. Не действуют изоляция тенантов, мягкое удаление, скрытые поля, маски `sensitive`, аудит, хуки и события. Это метод, а не свойство, чтобы обход бросался в глаза в месте вызова.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const pong = await client.unsafeDriver().db("admin").command({ ping: 1 });
console.log(pong.ok);
// → 1
```

Метод при каждом вызове возвращает один и тот же `MongoClient`, а операции моделей им не пользуются. Руководство — [Доступ к драйверу](../../connection/driver-access.mdx).

<FullType>

```ts
unsafeDriver(): MongoClient
```

</FullType>

## Опции клиента

Тип опций — `TypemoClientOptions`. В нём все опции `MongoClientOptions` драйвера, кроме трёх старых таймаутов, и пять собственных опций Typemo. Драйверные опции описаны в документации драйвера `mongodb`, а здесь только те, что Typemo добавляет или ограничивает.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// ---cut---
const client = new TypemoClient("mongodb://localhost:27017", {
  dbName: "app",
  name: "main",
  readyTimeoutMS: 5_000,
  timeoutMS: 30_000,
  maxPoolSize: 20,
});
```

<Params title="Собственные опции Typemo">
<Param name="dbName" type="string" default="база из строки подключения, иначе test">

База по умолчанию для `client.connection` и `client.db()`. Если база указана и в строке подключения, и здесь, а имена различаются, конструктор бросает `ConfigurationError`. Иначе часть кода писала бы не туда.

</Param>
<Param name="name" type="string" default="default">

Имя клиента в событиях и в текстах ошибок. Нужно, когда клиентов несколько.

</Param>
<Param name="readyTimeoutMS" type="number" default="10000">

Сколько операция ждёт подключения, если у неё нет своего `timeoutMS`. Ноль — ждать без ограничения. Отрицательные и дробные значения запрещены.

</Param>
<Param name="keysetSecret" type="string | Uint8Array | (string | Uint8Array)[]">

Ключ подписи токенов постраничного чтения по ключу (`nextCursor`), HMAC-SHA256. Подпись не даёт клиенту подделать или поправить позицию. По умолчанию её нет, потому что токен — это позиция, а не право доступа, и фильтр запроса действует на каждой странице. Ключ не короче 32 байт, строка берётся как UTF-8. Для ротации передайте список. Подписывает первый ключ, проверяются все. С заданным ключом токен без подписи или с чужой подписью отвергается ошибкой `KeysetTokenError`.

</Param>
<Param name="validateReads" type="boolean | &quot;development&quot;" default="false">

Строгое чтение. Каждый прочитанный документ сверяется со схемой, а значение другого типа даёт `CastError`. `true` включает проверку всегда, `"development"` — везде, кроме `NODE_ENV=production`. Подробности в разделе [validateReads](#validatereads).

</Param>
</Params>

<Params title="Драйверные опции, которые Typemo ограничивает">
<Param name="timeoutMS" type="number">

Клиентский срок операции, неотрицательное целое. Заменяет три старых таймаута.

</Param>
<Param name="socketTimeoutMS, waitQueueTimeoutMS, wtimeoutMS" type="number">

Не принимаются ни в опциях, ни в строке подключения (`?waitQueueTimeoutMS=5`). Typemo бросает `ConfigurationError` и подсказывает `timeoutMS`. Один клиентский срок на всю операцию заменяет три таймаута, каждый из которых ограничивал только свой этап.

</Param>
<Param name="BSON-опции (useBigInt64, promoteLongs и другие)" type="—">

Typemo задаёт их сам, потому что вид данных (например, int64 как `bigint`) — часть контракта типов. Повторить значение Typemo можно, изменить нельзя. `useBigInt64: false` даст `ConfigurationError: options: BSON options conflict with Typemo — useBigInt64: false (required: true)`.

</Param>
<Param name="monitorCommands" type="boolean" default="false">

Нужна, если подписчик [`client.instrument`](#clientinstrument) просит события команд драйвера (`driverCommands: true`).

</Param>
</Params>

<FullType label="Полный тип опций">

```ts
type TypemoClientOptions = Omit<MongoClientOptions, "socketTimeoutMS" | "waitQueueTimeoutMS" | "wtimeoutMS"> & TypemoOwnOptions

interface TypemoOwnOptions {
  readonly readyTimeoutMS?: number;
  readonly name?: string;
  readonly dbName?: string;
  readonly keysetSecret?: string | Uint8Array | readonly (string | Uint8Array)[];
  readonly validateReads?: boolean | "development";
}
```

</FullType>

### validateReads

По умолчанию Typemo не сверяет прочитанный документ со схемой. Данные, записанные моделью, уже прошли приведение и проверку, а сверка каждого поля при каждом чтении стоила бы времени. Но в коллекцию пишут и мимо модели — другая программа, скрипт миграции на драйвере, старая версия схемы. Такой документ может принести в `title` число, и код получит его под типом `string`.

Опция `validateReads` включает **строгое чтение**. Перед тем как документ станет результатом, Typemo проверяет тип каждого его поля. Несовпадение — [`CastError`](../errors/data-errors.mdx#casterror) с путём поля.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
}
// ---cut---
const client = await TypemoClient.connect("mongodb://localhost:27017/app", { validateReads: true });
const Accounts = client.connection.model(Account);
await client.unsafeDriver().db("app").collection("accounts").insertOne({ title: 5, owner: "bob" });

try {
  await Accounts.findOne({ owner: "bob" });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to string failed at path "title" for 5 (number): the stored value does not match the schema of Account (a document read from the database, checked by validateReads) [type]
```

Проверка действует на `find`, `findOne`, `findById` и `findOneAnd*` во всех видах результата (документ, `.lean()`, `.plain()`, курсор) и на документы, которые подставляет `populate`. Проверяется то, что есть в документе. Поле, которое проекция не загрузила, не ошибка, а ключ вне схемы не проверяется.

Массивы, `Map`, поддокументы и дискриминаторы сверяются со своими схемами, и путь ошибки содержит индекс или ключ (`lines.1.sku`, `scores.x`). `null` допустим только у поля с `nullable: true`, иначе причина ошибки — `null`. У полей `hidden` и `sensitive` значение в ошибке замаскировано. Строки агрегаций, `distinct` и события потока изменений не проверяются, это не документы модели в её форме.

Значение `"development"` включает проверку, если `process.env.NODE_ENV` не равен `"production"`. Переменную Typemo читает один раз, при создании клиента.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// ---cut---
process.env.NODE_ENV = "production";
console.log(new TypemoClient("mongodb://localhost:27017", { validateReads: "development" }).options.validateReads);
// → false
process.env.NODE_ENV = "development";
console.log(new TypemoClient("mongodb://localhost:27017", { validateReads: "development" }).options.validateReads);
// → true
```

Если `NODE_ENV` не задан, проверка тоже включена. Поэтому в продакшене задайте `NODE_ENV=production` или используйте `false`. Решение клиента можно поменять для одного запроса вызовом [`.validateReads(enabled)`](../query/options.mdx#validatereads) — включить проверку для одного чтения или выключить для тяжёлого отчёта.

Строгое чтение не заменяет проверку при записи. Оно находит уже испорченные данные, но не чинит их. Если ошибки идут из одного источника, исправьте его, а документы в базе — миграцией. Когда в коллекцию пишет только ваша модель, опция не нужна.

## Когда `TypemoClient` не подходит

Если нужна операция, которую Typemo не оборачивает, берите [`client.unsafeDriver`](#clientunsafedriver) и помните, что политики на неё не действуют. Несколько баз одного сервера отдельных клиентов не требуют. Вызовите [`client.db`](#clientdb) с нужным именем, пул соединений у баз общий.
