`TypemoClient` владеет одним подключением к MongoDB: открывает и закрывает его, следит за состоянием, выдаёт [`Connection`](./connection.mdx) для каждой базы и запускает транзакции. Модели привязаны к подключению конкретного клиента, а глобального клиента в Typemo нет: вы создаёте клиент сами и передаёте его туда, где он нужен.

Если вы только начинаете, сначала прочитайте руководство [Подключиться к базе](../../connection/connect.mdx). Эта страница — справочник: к ней возвращаются, когда нужно уточнить деталь.

Под капотом клиент держит один `MongoClient` официального драйвера `mongodb`. Пул соединений, повторные попытки, выбор сервера и переподключение остаются на стороне драйвера, а Typemo добавляет к ним состояние, ожидание готовности и собственные проверки настроек.

Во всех примерах используется одна модель счёта:

```ts twoslash title="accounts/account.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;
}
```

Элементы клиента, которых нет на этой странице, живут в соседних справочниках: модели и базы — в [`Connection`](./connection.mdx), глобальные настройки — в [`Typemo`](./typemo.mdx), состояния — в [`ConnectionState`](./connection-state.mdx).

## TypemoClient.connect

`TypemoClient.connect` создаёт клиент и сразу подключает его. Это самый частый способ начать работу: одна строка при старте приложения или скрипта, после которой клиент готов.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// ---cut---
const client = await TypemoClient.connect("mongodb://localhost:27017/app", { timeoutMS: 30_000 });
console.log(client.state);
// → "connected"
```

<Returns type="Promise<TypemoClient>">

Подключённый клиент. Если подключиться не удалось, промис завершается ошибкой [`ConnectionError`](../errors/configuration-errors.mdx#connectionerror): клиент в этом случае не возвращается, и закрывать нечего.

</Returns>

<Params>
<Param name="uri" type="string" required>

Строка подключения: `mongodb://` или `mongodb+srv://`. Любая другая строка, например `localhost:27017` без схемы, приводит к `ConfigurationError` ещё до попытки подключения.

</Param>
<Param name="options" type="TypemoClientOptions" default="{}">

Опции драйвера и собственные опции Typemo. Подробно — в разделе [Опции клиента](#опции-клиента).

</Param>
</Params>

<FullType>

```ts
static connect(uri: string, options?: TypemoClientOptions): Promise<TypemoClient>
```

</FullType>

### Когда подключиться не удалось

Если сервер недоступен, драйвер ждёт подходящий сервер `serverSelectionTimeoutMS` (по умолчанию 30 секунд) и сдаётся. Typemo превращает эту ошибку в `ConnectionError` с полем `failure`, по которому видно причину. Здесь для скорости задано короткое ожидание, а порт не слушает ничего:

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// ---cut---
try {
  await TypemoClient.connect("mongodb://127.0.0.1:1/", { serverSelectionTimeoutMS: 300 });
} catch (error) {
  console.log(String(error));
  // → "ConnectionError: no server available: connect ECONNREFUSED 127.0.0.1:1"
}
```

Поле `failure` принимает четыре значения: `closed` (клиент уже закрыт), `server-selection` (сервер не нашёлся, как выше), `network` (сбой сети) и `authentication` (сервер отверг учётные данные). Первое и второе проверены запуском на этой странице, остальные взяты из кода.

### Когда не подходит

Если подключение нужно создать заранее, а соединиться позже, используйте [`new TypemoClient`](#new-typemoclient) и вызовите [`client.connect`](#clientconnect) в нужный момент.

## new TypemoClient

Конструктор создаёт клиент и **не** подключает его. Он нужен, когда клиент должен существовать раньше, чем к нему можно обратиться: например, модули импортируют готовый клиент, а само подключение происходит позже, при старте приложения.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// ---cut---
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app", name: "main" });
console.log(client.state);
// → "idle"
```

Пока вы не вызвали [`client.connect`](#clientconnect), операции моделей не падают: они ждут подключения, но не дольше `readyTimeoutMS`. Подробности — в разделе [`client.ready`](#clientready).

<Params>
<Param name="uri" type="string" required>

Строка подключения, как у [`TypemoClient.connect`](#typemoclientconnect).

</Param>
<Param name="options" type="TypemoClientOptions" default="{}">

Опции клиента. Объект не изменяется: Typemo копирует и проверяет его.

</Param>
</Params>

<FullType>

```ts
constructor(uri: string, options?: TypemoClientOptions)
```

</FullType>

### Ошибки настройки

Все проверки опций выполняются в конструкторе и бросают `ConfigurationError`, то есть раньше любого обращения к сети. Тексты ошибок получены запуском:

```text
ConfigurationError: TypemoClient: the first argument is a connection string (mongodb:// or mongodb+srv://)
ConfigurationError: TypemoClient: dbName "other" conflicts with the database "app" of the connection string
ConfigurationError: TypemoClient: socketTimeoutMS is not supported; use timeoutMS (client-side operation timeout)
ConfigurationError: TypemoClient: dbName must be a non-empty string
ConfigurationError: TypemoClient: name must be a non-empty string
ConfigurationError: TypemoClient: timeoutMS must be a non-negative integer, got -1
ConfigurationError: TypemoClient: readyTimeoutMS must be a non-negative integer, got -1
ConfigurationError: TypemoClient: keysetSecret[0] is 3 bytes; an HMAC key needs at least 32
ConfigurationError: TypemoClient: keysetSecret is an empty list
ConfigurationError: TypemoClient: validateReads must be true, false or "development", got "yes"
```

Первая строка — адрес без `mongodb://`. Вторая — `dbName`, который расходится с базой в строке подключения. Третья — старая опция таймаута. Остальные — пустое или недопустимое значение. Причины у ошибок конкретные: две базы «по умолчанию» дали бы операции не в ту базу, а три старых таймаута драйвера заменены одним, [`timeoutMS`](#опции-клиента), поэтому Typemo не принимает их и подсказывает замену.

## client.connect

`client.connect` подключает клиент, созданный через [`new TypemoClient`](#new-typemoclient). Повторный вызов безопасен: пока клиент подключается или уже подключён, вы получаете тот же результат без нового подключения.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
await client.connect();
await client.connect(); // второй вызов ничего не делает
```

<Returns type="Promise<this>">

Этот же клиент. Если подключение не удалось, промис завершается `ConnectionError`, а состояние клиента возвращается в `idle`: вы можете вызвать `connect` ещё раз.

</Returns>

Если клиент уже закрыт, подключиться заново нельзя, нужно создать новый:

```text
ConnectionError: TypemoClient "default" is closed; create a new client
```

<FullType>

```ts
connect(): Promise<this>
```

</FullType>

## client.db

`client.db` возвращает [`Connection`](./connection.mdx): одну базу данных этого клиента, с её моделями. Вызов ничего не делает по сети, база создаётся сервером при первой записи.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const app = client.db();
const reports = client.db("reports");
console.log(app.name, reports.name);
// → "app" "reports"
console.log(client.db("reports") === reports);
// → true
```

<Returns type="Connection">

Подключение к базе. Для одного имени вы всегда получаете один и тот же объект, поэтому модели, зарегистрированные на нём, не теряются между вызовами.

</Returns>

<Params>
<Param name="name" type="string" default="client.options.dbName">

Имя базы. Пустая строка не допускается: `TypemoClient.db: a database name` — `ConfigurationError`. Без аргумента берётся база по умолчанию клиента: `dbName`, база из строки подключения или `test`.

</Param>
</Params>

<FullType>

```ts
db(name?: string): Connection
```

</FullType>

Связанный элемент: [`connection.useDb`](./connection.mdx#connectionusedb) делает то же самое, отталкиваясь от соединения.

## client.connection

`client.connection` — сокращение для `client.db()`: подключение к базе по умолчанию.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
console.log(client.connection === client.db());
// → true
```

Тип: `Connection`. Чтобы получить модель, вызовите [`client.connection.model(Account)`](./connection.mdx#connectionmodel) или `client.db().model(Account)`.

## client.aggregate

`client.aggregate` выполняет агрегацию уровня базы, не привязанную к модели: выполняющиеся операции (`$currentOp`), литеральные документы (`$documents`), локальные сессии (`$listLocalSessions`) или сессии сервера (`$listSessions`). Метод нужен там, где у вас есть клиент, но нет ни модели, ни подключения: например, в проверке состояния сервера. План строят [`Pipeline.database`](../aggregation/pipeline.mdx#pipelinedatabase), [`Pipeline.admin`](../aggregation/pipeline.mdx#pipelineadmin) и [`Pipeline.sessions`](../aggregation/pipeline.mdx#pipelinesessions).

```ts twoslash
import { Pipeline, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const running = await client.aggregate(Pipeline.admin().currentOp({ idleConnections: false }).plan());
console.log(running.length > 0);
// → true
const rows = await client.aggregate(Pipeline.database().documents([{ n: 1 }]).plan());
console.log(rows);
// → [{ n: 1 }]
```

Метод делает то же, что [`connection.aggregate`](./connection.mdx#connectionaggregate), вызванный у подключения к базе по умолчанию: `Pipeline.database()` работает в базе `client.options.dbName`, `Pipeline.admin()` в `admin`, `Pipeline.sessions()` в `config.system.sessions`. Операция проходит через общий конвейер операций: её события для [`client.instrument`](#clientinstrument) приходят с `model: null` и `collection: null` (у `Pipeline.sessions` коллекция `"system.sessions"`), в транзакции `client.transaction` она участвует сама, а `timeoutMS` и ошибки Typemo работают как у моделей. Хуки не вызываются: у операции нет модели, на которой их можно объявить.

<Returns type="AggregateQuery<R>">

Запрос агрегации, типизированный строками плана: `await` даёт массив строк, `.cursor()` отдаёт их по одной, `.explain()` показывает план сервера.

</Returns>

<Params>
<Param name="plan" type="AggregatePlan<R>" required>

План из `.plan()` строителя `Pipeline.database()`, `Pipeline.admin()` или `Pipeline.sessions()`.

</Param>
<Param name="options" type="ModelAggregateOptions">

`session` (`null` выполняет вне текущей транзакции), `timeoutMS` и `policy`.

</Param>
</Params>

<FullType>

```ts
aggregate<R>(plan: AggregatePlan<R>, options?: ModelAggregateOptions): AggregateQuery<R>
```

</FullType>

Ошибки те же, что у подключения: план, который не является планом агрегации, даёт `QueryError` (`client.aggregate: an aggregation plan of Pipeline.database(), Pipeline.admin() or Pipeline.sessions()`), а план над коллекцией модели — `ConfigurationError` (`client.aggregate: the plan reads the collection "accounts"; run it with the model's aggregate()`). Подробности и сценарии — в руководстве [Запросы уровня базы](../../aggregation/database-level.mdx).

## client.ready

`client.ready` ждёт, пока клиент подключится. Он нужен редко: обычные операции моделей сами дожидаются подключения. Метод пригодится, когда вы хотите дождаться подключения явно, например перед запуском HTTP-сервера, и не хотите вызывать `connect` сами.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app", readyTimeoutMS: 5_000 });
// ---cut---
await client.ready(1_000);
```

Если клиент уже подключён, метод возвращается сразу. Если нет, он ждёт, пока `connect` завершится, но не дольше лимита. Когда время вышло, вы получаете `TimeoutError` с полем `kind: "connection"`. Текст получен запуском для клиента, у которого `connect` так и не вызвали:

```text
TimeoutError: TypemoClient "default" is not connected after 50 ms: call connect() (operations issued before connect() wait for it)
```

<Params>
<Param name="timeoutMS" type="number" default="client.options.readyTimeoutMS">

Сколько ждать подключения, в миллисекундах. Ноль означает «ждать без ограничения».

</Param>
</Params>

Возвращает `Promise<void>`. После `close` метод бросает `ConnectionError` со значением `failure: "closed"`. Если `connect` завершился ошибкой, та же ошибка приходит и всем, кто ждёт в `ready`.

<FullType>

```ts
ready(timeoutMS?: number): Promise<void>
```

</FullType>

### Операции до connect

Операция модели, начатая до `connect`, не падает и не встаёт в очередь на повтор: она сама продолжается, когда клиент подключится. Лимит ожидания — собственный `timeoutMS` операции, а если его нет, то `readyTimeoutMS` клиента. По истечении лимита операция завершается тем же `TimeoutError`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
}
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const Accounts = client.connection.model(Account);
const pending = Accounts.countDocuments(); // клиент ещё не подключён
await client.connect();
const total = await pending;
//    ^?
```

## client.state

`client.state` — текущее состояние клиента: `idle`, `connecting`, `connected`, `unavailable` или `closed`. Значение выводится из событий драйвера о топологии, поэтому оно работает одинаково для одиночного сервера, реплика-сета, шардированного кластера и балансировщика. Каждое состояние и переходы между ними описаны на странице [`ConnectionState`](./connection-state.mdx).

Тип: [`ConnectionState`](./connection-state.mdx). Свойство только для чтения.

## client.onStateChange

`client.onStateChange` подписывает функцию на смену состояния. Она нужна для проверок готовности, метрик и журнала: «подключились», «потеряли сервер», «закрыли клиент».

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const stop = client.onStateChange((state) => console.log(state));
await client.connect();
// → "connecting"
// → "connected"
await client.close();
// → "closed"
stop();
```

<Returns type="() => void">

Функция, которая отменяет подписку.

</Returns>

<Params>
<Param name="listener" type="(state: ConnectionState) => void" required>

Вызывается с новым состоянием после каждой смены. Повторные события с тем же состоянием не доходят до подписчика. Начальное состояние `idle` подписчику не присылается: узнайте его через [`client.state`](#clientstate).

</Param>
</Params>

<FullType>

```ts
onStateChange(listener: (state: ConnectionState) => void): () => void
```

</FullType>

## client.close

`client.close` закрывает клиент: драйвер завершает сессии и закрывает пул соединений. После этого клиент навсегда остаётся в состоянии `closed`, а все операции завершаются `ConnectionError` со значением `failure: "closed"`.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
await client.close();
await client.close(); // повторный вызов ничего не делает
```

Операции, которые в момент закрытия ждали подключения, тоже завершаются `ConnectionError` со значением `failure: "closed"`, только с текстом `TypemoClient "default" was closed` (запуск). Операции, начатые после закрытия, получают `TypemoClient "default" is closed; create a new client`. Закрытие относится ко всему клиенту: все `Connection`, полученные через [`client.db`](#clientdb), закрываются вместе с ним.

<Params>
<Param name="force" type="boolean" default="false">

Передаётся в `close` драйвера: закрыть, даже если операции ещё выполняются.

</Param>
</Params>

<FullType>

```ts
close(force?: boolean): Promise<void>
```

</FullType>

## client[Symbol.asyncDispose]

Клиент можно объявить через `await using`: тогда он закроется сам в конце блока, даже если внутри бросили ошибку. Метод вызывает [`client.close`](#clientclose) без аргументов.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// ---cut---
let captured: TypemoClient;
{
  await using client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
  captured = client;
}
console.log(captured.state);
// → "closed"
```

<FullType>

```ts
[Symbol.asyncDispose](): Promise<void>
```

</FullType>

## client.name

Имя клиента в событиях наблюдаемости. Берётся из опции `name`, по умолчанию `"default"`. Оно нужно, когда в приложении несколько клиентов и в журнале нужно различать, откуда пришла операция. Тип `string`, только чтение.

## client.options

Опции клиента после проверки: `client.options.dbName`, `client.options.readyTimeoutMS`, `client.options.name`, `client.options.validateReads` (включено ли [строгое чтение](#validatereads), уже с учётом `"development"`), а также `client.options.driver` (что ушло в драйвер) и `client.options.keysetSecrets` (ключи подписи токенов, копии в виде байтов). Объект заморожен. Он показывает итог слияния: например, `dbName`, взятый из строки подключения, виден здесь.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// ---cut---
const fromUri = new TypemoClient("mongodb://localhost:27017/reports");
console.log(fromUri.options.dbName);
// → "reports"
const fallback = new TypemoClient("mongodb://localhost:27017");
console.log(fallback.options.dbName, fallback.options.readyTimeoutMS);
// → "test" 10000
```

## client.supportsTransactions

Умеет ли сервер транзакции. `true` для реплика-сета, шардированного кластера и балансировщика, `false` для одиночного `mongod`, `undefined`, пока клиент ещё не подключался и топология неизвестна. Свойство пригодится в проверке готовности, чтобы сообщить о неверной конфигурации сервера раньше, чем упадёт первая транзакция.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
console.log(client.supportsTransactions);
// → undefined
await client.connect();
console.log(client.supportsTransactions);
// → true  (на реплика-сете)
```

## client.server

Первый хост из строки подключения: `{ address, port }`, либо `undefined`, если в строке нет хоста. Для реплика-сета это первый указанный адрес, а не обязательно тот сервер, который обслужил операцию. Значение используется в атрибутах наблюдаемости.

## client.startSession

`client.startSession` открывает явную сессию драйвера, например чтобы передать её в запрос через `.session()`. Обычно она не нужна: [`client.transaction`](#clienttransaction) сама создаёт и закрывает сессию. Метод ждёт готовности клиента, как и [`client.ready`](#clientready).

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const session = await client.startSession();
try {
  // операции с .session(session)
} finally {
  await session.endSession();
}
```

Закрыть сессию должны вы: Typemo этого не делает. Подробнее про ручные сессии — в руководстве [Сессии вручную](../../transactions/sessions.mdx).

<Params>
<Param name="options" type="ClientSessionOptions">

Параметры сессии драйвера.

</Param>
</Params>

Возвращает `Promise<ClientSession>`. Ошибки: `ConnectionError`, если клиент закрыт, и `TimeoutError`, если он не подключился вовремя.

## client.transaction

`client.transaction` выполняет функцию в транзакции. Все операции моделей внутри функции присоединяются к ней сами, передавать сессию не нужно. При временных сбоях сервера драйвер повторяет функцию целиком, поэтому она может выполниться больше одного раза, и побочных эффектов вне базы (письма, платежи) в ней быть не должно. Полное описание — в руководстве [Транзакции](../../transactions/transactions.mdx) и в [справочнике транзакций](../transactions/transactions.mdx).

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.connection.model(Account);
// ---cut---
const attempt = await client.transaction(async (scope) => {
  await Accounts.create({ title: "Savings", owner: "alice" });
  return scope.attempt;
});
console.log(attempt);
// → 1
```

Транзакции не вкладываются: вызов внутри транзакции того же клиента бросает `ConfigurationError`:

```text
ConfigurationError: transaction(): transactions do not nest (already inside a transaction of this client)
```

Для транзакций нужен реплика-сет или шардированный кластер. На одиночном `mongod` (`client.supportsTransactions` равен `false`) вызов бросает `ConfigurationError` до того, как выполнится функция и что-нибудь запишется:

```text
ConfigurationError: TypemoClient "default": transaction(): transactions need a replica set or a sharded cluster; this server is a standalone mongod. Run MongoDB as a replica set (a single-member one is enough).
```

Проверить это заранее можно через [`client.supportsTransactions`](#clientsupportstransactions).

<Params>
<Param name="fn" type="(scope: TransactionScope) => Promise<R>" required>

Функция транзакции. Получает `TransactionScope` с сессией и номером попытки (`scope.attempt`, 1 для первого запуска).

</Param>
<Param name="options" type="TransactionOptions" default="{}">

Уровень чтения (`readConcern`: `local`, `majority` или `snapshot`), запись при фиксации (`writeConcern`), общий срок (`timeoutMS`) и предел времени фиксации на сервере (`maxCommitTimeMS`).

</Param>
</Params>

<Returns type="Promise<R>">

То, что вернула функция, после фиксации. Ошибка вашей функции приходит без изменений (`caught === thrown`), а ошибка сервера или фиксации — уже в виде ошибки Typemo. Если вышел срок `timeoutMS` транзакции, это [`TimeoutError`](../errors/server-errors.mdx#timeouterror) с `kind: "transaction"` и заполненным `timeoutMS`.

</Returns>

Функция может выполниться повторно, и документ, загруженный **до** транзакции и изменённый в ней (`doc.balance -= 10`, затем `$save()`), при повторе изменится дважды: в запуске вместо 90 из 100 получилось 80. Загружайте документы внутри функции или меняйте их атомарной записью (`$inc`): разбор с примером — в руководстве [Транзакции](../../transactions/transactions.mdx#документы-загруженные-снаружи). Операции внутри транзакции нельзя запускать одновременно (`Promise.all`): сервер не умеет этого, и библиотека отказывает сама ошибкой, которая называет обе операции: `Account.create: the session is in use by Account.create, which has not finished; …`.

<FullType>

```ts
transaction<R>(fn: TransactionCallback<R>, options?: TransactionOptions): Promise<R>

type TransactionCallback<R> = (scope: TransactionScope) => Promise<R>
```

</FullType>

Аналог на уровне соединения — [`connection.transaction`](./connection.mdx#connectiontransaction).

Узнать, идёт ли вызов уже внутри транзакции этого клиента, можно через [`client.currentTransaction`](../transactions/transactions.mdx#clientcurrenttransaction): транзакции не вкладываются, и обёртка, которую вызывают и снаружи, и изнутри транзакции, решает по нему, открывать ли свою.

## client.instrument

`client.instrument` подписывает наблюдателя на операции **этого** клиента: начало и конец операции, шаги, ошибки, события транзакций. Так работают интеграции OpenTelemetry и Sentry. Пока подписчиков нет, наблюдаемость ничего не стоит.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const subscription = client.instrument({
  handle: (event) => {
    if (event.type === "operation.end") console.log(event.operation, event.durationMS);
  },
});
subscription.unsubscribe();
```

<Params>
<Param name="subscriber" type="InstrumentationSubscriber" required>

Объект с функцией `handle` и необязательными настройками: `driverCommands`, `poolEvents`, `steps`, `sensitive`, `includeTenant`, `wrap`. Полный перечень — в справочнике [События](../observability/events.mdx).

</Param>
</Params>

<Returns type="Subscription">

Объект с методом `unsubscribe()`. Повторный вызов ничего не делает. Он же поддерживает `using`: подписка снимается на выходе из блока.

</Returns>

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
{
  using subscription = client.instrument({ handle: (event) => console.log(event.type) });
  // внутри блока события приходят
}
// здесь подписка уже снята
```

Если подписчик просит события команд драйвера (`driverCommands: true`), а клиент создан без `monitorCommands: true`, вы получаете `ConfigurationError`, а не молчаливое отсутствие событий:

```text
ConfigurationError: TypemoClient "default": driver command events need the client option monitorCommands: true
```

Подписка на все клиенты сразу — [`Typemo.instrument`](./typemo.mdx#typemoinstrument). Подробнее о том, как работать с событиями, — в руководстве [События операций](../../observability/events.mdx).

## client.use

`client.use` регистрирует расширение схемы для моделей **этого** клиента: имя расширения становится допустимым ключом в `ext` у `@Prop` и `@Schema`, а его проверки разбирают каждое значение при компиляции схемы. Ключ, который расширение вводит, нужно ещё и объявить для компилятора через `declare module "@venloc/typemo"`, как показано ниже; без объявления имя расширения не пройдёт проверку типов. Если расширение нужно всем клиентам, зарегистрируйте его через [`Typemo.use`](./typemo.mdx#typemouse).

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
declare module "@venloc/typemo" {
  interface PropExtensions<V> {
    label?: { readonly text: string };
  }
}
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
client.use({
  name: "label",
  validateProp: (value) => {
    if (typeof value !== "object" || value === null) throw new Error("label: an object is expected");
  },
});
```

Регистрировать расширение нужно до первой модели клиента: расширение, появившееся позже, не смогло бы проверить уже скомпилированные схемы. Реестр закрывает первая **успешная** компиляция модели этого клиента; если компиляция упала (например, из-за неизвестного ключа в `ext`), реестр остаётся открытым, и нужное расширение ещё можно зарегистрировать. Обе ошибки получены запуском:

```text
ConfigurationError: extension "late": extensions are fixed once a schema is compiled (Account was); call client.use() before the first model
ConfigurationError: extension "label" is already registered
```

Первая — регистрация после первой модели. Вторая — повторное имя: оно занято на этом клиенте или глобально. Руководство: [Несколько клиентов и расширения](../../connection/clients-and-extensions.mdx). Подробно об устройстве расширений — в справочнике [Расширения](../extensions/extensions.mdx).

<Params>
<Param name="extension" type="TypemoExtension" required>

Объект `{ name, validateProp?, validateSchema? }`. Нужна хотя бы одна проверка. Имя не пустое и не начинается с `$`. Проверка получает значение и бросает ошибку, если оно неверно: ошибка становится `cause` у `ConfigurationError`.

</Param>
</Params>

## client.unsafeDriver

`client.unsafeDriver` возвращает настоящий `MongoClient` драйвера. Он нужен для того, что Typemo не оборачивает: команды администратора, GridFS, драйверные возможности, которых у моделей нет. Всё, что вы делаете через него, обходит Typemo полностью: изоляцию тенантов, мягкое удаление, скрытые поля, маски `sensitive`, аудит, хуки и события. Название — метод, а не свойство, чтобы обход был заметен в месте вызова.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
// ---cut---
const pong = await client.unsafeDriver().db("admin").command({ ping: 1 });
console.log(pong.ok);
// → 1
```

Метод возвращает один и тот же `MongoClient` при каждом вызове, а операции моделей им не пользуются. Руководство: [Доступ к драйверу](../../connection/driver-access.mdx).

<FullType>

```ts
unsafeDriver(): MongoClient
```

</FullType>

## Опции клиента

Тип опций — `TypemoClientOptions`: все опции `MongoClientOptions` драйвера (кроме трёх старых таймаутов) плюс пять собственных опций Typemo. Драйверные опции описаны в документации драйвера `mongodb`; здесь собраны только те, которые добавляет или ограничивает Typemo.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// ---cut---
const client = new TypemoClient("mongodb://localhost:27017", {
  dbName: "app",
  name: "main",
  readyTimeoutMS: 5_000,
  timeoutMS: 30_000,
  maxPoolSize: 20,
});
```

<Params title="Собственные опции Typemo">
<Param name="dbName" type="string" default="база из строки подключения, иначе test">

База по умолчанию для `client.connection` и `client.db()`. Если база указана и в строке подключения, и здесь, и имена различаются, конструктор бросает `ConfigurationError`: два имени «по умолчанию» означали бы, что часть кода пишет не туда.

</Param>
<Param name="name" type="string" default="default">

Имя клиента в событиях и в текстах ошибок. Нужно, когда клиентов несколько.

</Param>
<Param name="readyTimeoutMS" type="number" default="10000">

Сколько операция ждёт подключения, если у неё нет своего `timeoutMS`. Ноль — ждать без ограничения. Отрицательные и дробные значения запрещены.

</Param>
<Param name="keysetSecret" type="string | Uint8Array | (string | Uint8Array)[]">

Ключ подписи токенов постраничного чтения по ключу (`nextCursor`), HMAC-SHA256. Подпись не даёт клиенту подделать или исправить позицию. По умолчанию выключена: токен — это позиция, а не право доступа, потому что фильтр запроса действует на каждой странице. Ключ не короче 32 байт (строка берётся как UTF-8). Список ключей нужен для ротации: подписывает первый, проверяются все. С заданным ключом токен без подписи или с чужой подписью отвергается ошибкой `KeysetTokenError`.

</Param>
<Param name="validateReads" type="boolean | &quot;development&quot;" default="false">

Строгое чтение: каждый прочитанный документ сверяется со схемой, и значение другого типа — `CastError`. `true` — всегда, `"development"` — везде, кроме `NODE_ENV=production`. Подробно — в разделе [validateReads](#validatereads).

</Param>
</Params>

<Params title="Драйверные опции, которые Typemo ограничивает">
<Param name="timeoutMS" type="number">

Клиентский срок операции. Не отрицательное целое. Заменяет три старых таймаута.

</Param>
<Param name="socketTimeoutMS, waitQueueTimeoutMS, wtimeoutMS" type="number">

Не принимаются ни в опциях, ни в строке подключения (`?waitQueueTimeoutMS=5`): `ConfigurationError` с подсказкой использовать `timeoutMS`. Один клиентский срок на всю операцию заменяет три отдельных таймаута, каждый из которых ограничивал только свой этап.

</Param>
<Param name="BSON-опции (useBigInt64, promoteLongs и другие)" type="—">

Typemo задаёт их сам: то, в каком виде вы получаете данные (например, int64 как `bigint`), — часть контракта типов. Повторить значение Typemo можно, изменить нельзя: `useBigInt64: false` даёт `ConfigurationError: options: BSON options conflict with Typemo — useBigInt64: false (required: true)`.

</Param>
<Param name="monitorCommands" type="boolean" default="false">

Нужна, если подписчик [`client.instrument`](#clientinstrument) просит события команд драйвера (`driverCommands: true`).

</Param>
</Params>

<FullType label="Полный тип опций">

```ts
type TypemoClientOptions = Omit<MongoClientOptions, "socketTimeoutMS" | "waitQueueTimeoutMS" | "wtimeoutMS"> & TypemoOwnOptions

interface TypemoOwnOptions {
  readonly readyTimeoutMS?: number;
  readonly name?: string;
  readonly dbName?: string;
  readonly keysetSecret?: string | Uint8Array | readonly (string | Uint8Array)[];
  readonly validateReads?: boolean | "development";
}
```

</FullType>

### validateReads

По умолчанию Typemo не сверяет прочитанный документ со схемой. Данные, которые записала модель, уже прошли приведение и проверку при записи, а сверка каждого поля каждого документа стоила бы времени на каждом чтении. Но в коллекцию пишут и мимо модели: другая программа, скрипт миграции на драйвере, старая версия схемы. Такой документ может принести в поле `title` число, и код получит его под типом `string`. Опция `validateReads` включает **строгое чтение**: перед тем как документ станет результатом, Typemo проверяет тип каждого его поля, и несовпадение — [`CastError`](../errors/data-errors.mdx#casterror) с путём поля.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
}
// ---cut---
const client = await TypemoClient.connect("mongodb://localhost:27017/app", { validateReads: true });
const Accounts = client.connection.model(Account);
await client.unsafeDriver().db("app").collection("accounts").insertOne({ title: 5, owner: "bob" });

try {
  await Accounts.findOne({ owner: "bob" });
} catch (error) {
  console.log((error as Error).message);
}
// → Cast to string failed at path "title" for 5 (number): the stored value does not match the schema of Account (a document read from the database, checked by validateReads) [type]
```

Проверка действует на `find`, `findOne`, `findById` и `findOneAnd*` во всех видах результата (документ, `.lean()`, `.plain()`, курсор) и на документы, которые подставляет `populate`. Проверяется то, что есть в документе: поле, которое проекция не загрузила, не ошибка, и ключ, которого нет в схеме, не проверяется. Массивы, `Map`, поддокументы и дискриминаторы проверяются по своим схемам, путь ошибки содержит индекс или ключ (`lines.1.sku`, `scores.x`). `null` допустим только у поля с `nullable: true`, иначе причина ошибки — `null`. У полей `hidden` и `sensitive` значение в ошибке замаскировано. Строки агрегаций, `distinct` и события потока изменений не проверяются: это не документы модели в её форме.

Значение `"development"` включает проверку, если `process.env.NODE_ENV` не равен `"production"`. Переменная читается один раз, при создании клиента:

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// ---cut---
process.env.NODE_ENV = "production";
console.log(new TypemoClient("mongodb://localhost:27017", { validateReads: "development" }).options.validateReads);
// → false
process.env.NODE_ENV = "development";
console.log(new TypemoClient("mongodb://localhost:27017", { validateReads: "development" }).options.validateReads);
// → true
```

Если `NODE_ENV` не задан, проверка тоже включена: поэтому в продакшене задайте `NODE_ENV=production` или используйте `false`. Отдельный запрос меняет решение клиента вызовом [`.validateReads(enabled)`](../query/options.mdx#validatereads): включает проверку для одного чтения или выключает её для тяжёлого отчёта.

Строгое чтение не заменяет проверку при записи: оно находит уже испорченные данные, но не исправляет их. Если ошибки идут из одного источника, исправьте его, а документы в базе — миграцией. Когда в коллекцию пишет только ваша модель, опция не нужна.

## Когда `TypemoClient` не подходит

Если вам нужна операция, которую Typemo не оборачивает, воспользуйтесь [`client.unsafeDriver`](#clientunsafedriver) и помните, что политики на неё не действуют. Если нужно работать с несколькими базами одного сервера, отдельные клиенты не нужны: достаточно [`client.db`](#clientdb) с нужным именем, пул соединений у них общий.
