`ConnectionState` — тип состояния клиента, строка из пяти значений. Текущее состояние вы читаете через [`client.state`](./typemo-client.mdx#clientstate), а о смене узнаёте через [`client.onStateChange`](./typemo-client.mdx#clientonstatechange). Оно пригодится для проверок готовности («сервер доступен?»), метрик и журнала. Управлять операциями по нему не нужно, потому что операции сами ждут подключения и сами сообщают об ошибках.

Если вы только начинаете, сначала прочитайте руководство [Подключиться к базе](../../connection/connect.mdx). Эта страница — справочник.

Состояние Typemo выводит из публичных событий драйвера о топологии (`topologyDescriptionChanged`). Правило одно для любой топологии — одиночного сервера, реплика-сета, шардированного кластера и балансировщика. Служебные поля драйвера Typemo не читает.

```ts twoslash
import type { ConnectionState } from "@venloc/typemo";
// ---cut---
const states: ConnectionState[] = ["idle", "connecting", "connected", "unavailable", "closed"];
```

## Переходы

Клиент рождается в `idle`. `connect` переводит его в `connecting`, успешное подключение — в `connected`, а `close` в любой момент делает `closed`. С настоящим сервером подписчик получает ровно такую последовательность. Начальное `idle` ему не присылается, только смены.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// ---cut---
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
client.onStateChange((state) => console.log(state));
await client.connect();
// → "connecting"
// → "connected"
await client.close();
// → "closed"
```

Если подключиться не удалось, клиент возвращается в `idle`. Мы указали адрес, на котором никто не слушает. Подписчик увидел `connecting`, затем `idle`, а `connect` завершился `ConnectionError` со значением `failure: "server-selection"`. После этого `connect` можно вызвать ещё раз.

Между `connected` и `unavailable` клиент переключается сам, по событиям драйвера. Он уходит в `unavailable`, когда пропал последний сервер с данными, и возвращается в `connected`, когда сервер появился. На `idle` и `closed` события топологии не влияют — не подключавшийся или уже закрытый клиент остаётся как был.

Отдельного состояния «переподключается» нет, его роль играет `unavailable`. Операции в это время не падают сразу, а ждут выбора сервера в драйвере в пределах `timeoutMS`.

### Когда состояние не нужно

Чтобы дождаться подключения, вызовите [`client.ready`](./typemo-client.mdx#clientready). Он ждёт готовности и падает по таймауту, так что опрашивать `client.state` в цикле не придётся. А чтобы узнать, умеет ли сервер транзакции, возьмите [`client.supportsTransactions`](./typemo-client.mdx#clientsupportstransactions).
