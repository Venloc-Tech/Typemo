`ConnectionState` — тип состояния клиента: строка из пяти возможных значений. Текущее состояние вы читаете через [`client.state`](./typemo-client.mdx#clientstate), а о его смене узнаёте через [`client.onStateChange`](./typemo-client.mdx#clientonstatechange). Состояние нужно для проверок готовности («сервер доступен?»), для метрик и для журнала, а не для управления операциями: операции сами ждут подключения и сами сообщают об ошибках.

Если вы только начинаете, сначала прочитайте руководство [Подключиться к базе](../../connection/connect.mdx). Эта страница — справочник.

Состояние выводится только из публичных событий драйвера о топологии (`topologyDescriptionChanged`), одинаково для всех видов топологии: одиночного сервера, реплика-сета, шардированного кластера и балансировщика. Служебные поля драйвера Typemo не читает.

```ts twoslash
import type { ConnectionState } from "@venloc/typemo";
// ---cut---
const states: ConnectionState[] = ["idle", "connecting", "connected", "unavailable", "closed"];
```

## Переходы

Обычная жизнь клиента выглядит так. Клиент создаётся в `idle`. `connect` переводит его в `connecting`, а успешное подключение — в `connected`. `close` в любой момент делает состояние `closed`. Запуск с настоящим сервером даёт ровно такую последовательность (подписчик получает только смены, начальное `idle` ему не присылается):

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// ---cut---
const client = new TypemoClient("mongodb://localhost:27017", { dbName: "app" });
client.onStateChange((state) => console.log(state));
await client.connect();
// → "connecting"
// → "connected"
await client.close();
// → "closed"
```

Если подключиться не удалось, состояние возвращается в `idle`. Запуск с адресом, на котором ничего не слушает, дал последовательность `connecting`, затем `idle`, а `connect` завершился `ConnectionError` со значением `failure: "server-selection"`. Так вы можете вызвать `connect` ещё раз.

Между `connected` и `unavailable` клиент переходит сам, по событиям драйвера: `unavailable`, когда пропал последний сервер с данными, и обратно в `connected`, когда он появился. Переходы `idle` и `closed` от событий топологии не зависят: клиент, который ещё не подключался или уже закрыт, остаётся в своём состоянии.

Отдельного состояния «переподключается» нет: `unavailable` и есть это состояние. Операции в этот момент не падают сразу, а ждут выбора сервера в драйвере, ограниченного `timeoutMS`.

### Когда состояние не нужно

Чтобы дождаться подключения, используйте [`client.ready`](./typemo-client.mdx#clientready): он ждёт готовности и завершается ошибкой по таймауту. Опрашивать `client.state` в цикле для этого не нужно. Чтобы проверить, что сервер умеет транзакции, используйте [`client.supportsTransactions`](./typemo-client.mdx#clientsupportstransactions).
