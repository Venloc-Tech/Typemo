**Транзакция** собирает несколько записей в одну. Применятся либо все, либо ни одной. Пока транзакция не зафиксирована, другие читатели её изменений не видят, а при ошибке всё откатывается. Typemo запускает транзакцию одним вызовом [`transaction`](#transaction), сам передаёт её сессию каждой операции внутри и повторяет функцию целиком при временных сбоях сервера.

Если вы только начинаете, сначала прочитайте руководство [Транзакции](../../transactions/transactions.mdx). Эта страница — справочник. Ручные сессии описаны в руководстве [Сессии вручную](../../transactions/sessions.mdx).

Транзакции работают только на реплика-сете и шардированном кластере. На одиночном `mongod` `transaction` бросает [`ConfigurationError`](../errors/configuration-errors.mdx#configurationerror) до вызова функции, так что ничего не записывается. Проверить это заранее можно через [`client.supportsTransactions`](../connection/typemo-client.mdx#clientsupportstransactions). Транзакция охватывает все базы и коллекции одного клиента, но дальше него не идёт.

Во всех примерах одна модель счёта.

```ts twoslash title="accounts/account.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true, unique: true })
  title!: string;

  @Prop(() => Number, { required: true, min: 0 })
  balance!: number;
}
```

## transaction

`transaction` выполняет функцию в транзакции и после фиксации возвращает то, что вернула функция. Метод есть у клиента ([`client.transaction`](../connection/typemo-client.mdx#clienttransaction)) и у подключения ([`connection.transaction`](../connection/connection.mdx#connectiontransaction)). Подключение просто передаёт вызов своему клиенту, результат тот же. Он нужен, когда несколько записей должны пройти вместе — перевод между счетами, заказ с позициями, счёт и запись в журнале.

Внутри функции ничего передавать не нужно. Каждая операция моделей (чтение, запись, курсор, агрегация, `populate`, пакетная запись) находит транзакцию сама и работает в её сессии. Забыть сессию в одном из вызовов нельзя, а в Mongoose такая операция молча выполнялась вне транзакции.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => Number, { required: true, min: 0 }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
// ---cut---
const left = await client.transaction(async () => {
  const source = await Accounts.findOne({ title: "Main" }).orFail();
  await Accounts.updateOne({ title: "Main" }, { $inc: { balance: -30 } });
  await Accounts.updateOne({ title: "Savings" }, { $inc: { balance: 30 } });
  return source.balance - 30;
});
console.log(left);
// → 70  (на счёте Main было 100)
```

Если функция бросила ошибку, транзакция откатывается, а до вас ошибка доходит **той же самой**, без обёртки. В примере `caught === thrown` равно `true`. Ошибки самой библиотеки, например нарушение уникальности или ошибка проверки, тоже откатывают транзакцию и приходят как есть.

<Returns type="Promise<R>">

То, что вернула функция, после успешной фиксации. Если упала функция, вы получите её ошибку без изменений. Если упала фиксация, ошибку сервера или драйвера Typemo превратит в [ошибку Typemo](../errors/server-errors.mdx).

</Returns>

<Params>
<Param name="fn" type="TransactionCallback<R>" required>

Асинхронная функция транзакции, она получает [`TransactionScope`](#transactionscope). Она **может выполниться больше одного раза**, потому что при временных сбоях сервера драйвер повторяет её целиком. Не делайте внутри ничего, что нельзя повторить вне базы, — письма, платежи, запросы к внешним сервисам, изменения объектов, созданных снаружи. Подробности в разделе «Повторы».

</Param>
<Param name="options" type="TransactionOptions" default="{}">

Настройки транзакции — уровень чтения, подтверждение записи, общий срок. Подробно они описаны в разделе [`TransactionOptions`](#transactionoptions).

</Param>
</Params>

<FullType>

```ts
transaction<R>(fn: TransactionCallback<R>, options?: TransactionOptions): Promise<R>
```

</FullType>

### Повторы

Сервер помечает некоторые отказы меткой `TransientTransactionError` («временная ошибка транзакции»), например когда две транзакции меняли один документ. Тогда драйвер повторяет функцию с начала, а не продолжает с места сбоя. Typemo не повторяет сам, повтор остаётся за драйвером. Он лишь отдаёт драйверу оригинальную ошибку вместо обёрнутой. Иначе драйвер не увидел бы метку, и повтора не было бы.

Ниже две транзакции одновременно увеличивают баланс одного счёта. Обе стартуют с первой попытки, одна проигрывает конфликт и запускается заново.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => Number, { required: true, min: 0 }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
const sleep = (ms: number) => new Promise((resolve) => setTimeout(resolve, ms));
// ---cut---
const runs: string[] = [];
const bump = (name: string) =>
  client.transaction(async (scope) => {
    runs.push(`${name}${scope.attempt}`);
    await Accounts.updateOne({ title: "Main" }, { $inc: { balance: 1 } });
    await sleep(150);
  });

await Promise.all([bump("A"), bump("B")]);
console.log(runs.slice(0, 2), runs.length > 2);
// → ["A1", "B1"] true
```

Проигравшая транзакция повторяется, пока победитель не зафиксируется. Функции выполнились в сумме 9 раз, баланс вырос ровно на 2. Число попыток зависит от времени и нагрузки, так что полагаться на него нельзя. Важно другое — при правильно написанной функции результат от числа повторов не зависит.

Повторяется не всякий отказ. Нарушение уникальности, ошибка проверки схемы и ошибки вашего кода останавливают транзакцию сразу. Функция с дубликатом выполнилась один раз и завершилась `DuplicateKeyError`.

### Состояние документов при повторе

Документы, которые вы сохраняли в неудавшейся попытке, откатываются в памяти к состоянию до транзакции. Библиотека возвращает им признак «изменён», и повторный `$save` отправляет ту же запись, а не пропускает её. В примере повторная попытка увидела `$isModified()` равным `true`. Так же откатываются признак «новый» и версия документа, но это описано по коду библиотеки и запуском не проверялось. Присваивания, которые сделала ваша функция, библиотека отменить не может. Поля остаются такими, какие вы выставили.

Поэтому изменение документа, загруженного **снаружи** транзакции, при повторе применится дважды. В примере первая попытка терпит временный сбой при фиксации. При остатке 100 функция вычитает 10, сбой, повтор видит 90, вычитает ещё 10 и сохраняет 80, а не 90.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => Number, { required: true, min: 0 }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
// ---cut---
const account = await Accounts.findOne({ title: "Main" }).orFail();

await client.transaction(async () => {
  account.balance = account.balance - 10;
  await account.$save();
});
// при одном временном сбое: в базе 80, а не 90
```

Читайте документ внутри функции или меняйте его атомарной записью. `updateOne` с `$inc` не зависит от того, что лежало в памяти.

### При ошибках

```ts twoslash
import { ConfigurationError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => Number, { required: true, min: 0 }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
// ---cut---
try {
  await client.transaction(async () => {
    await client.transaction(async () => {});
  });
} catch (error) {
  if (error instanceof ConfigurationError) console.log(error.message);
  // → transaction(): transactions do not nest (already inside a transaction of this client)
}
```

Транзакции не вкладываются, у MongoDB вложенных транзакций нет. Вызов `transaction` внутри транзакции того же клиента сразу бросает [`ConfigurationError`](../errors/configuration-errors.mdx#configurationerror) и не присоединяется молча. Остальные ошибки внутри транзакции показаны ниже.

```text
StrictModeError: Account.find: the session is in use by Account.countDocuments, which has not finished; operations on one session must run one after another — await each one; only reads may overlap, and only outside a transaction (MongoDB does not support concurrent operations on a session) [concurrent-session]
StrictModeError: Account.find: readConcern "majority" inside a transaction — the transaction's own settings apply (set them on transaction()) [transaction-option]
StrictModeError: Account.find: timeoutMS 100 (the transaction has timeoutMS 5000) inside a transaction — the transaction's own settings apply (set them on transaction()) [transaction-option]
ConfigurationError: Account.countDocuments: called inside a transaction of another client; its model cannot join that transaction — pass session(null) (or { session: null }) to run it outside explicitly
```

Первая ошибка — одновременные операции. Внутри транзакции нельзя запускать операции параллельно (`Promise.all`), даже чтения. Сервер отвечает на это ошибкой, а драйвер называет такое поведение неопределённым, поэтому библиотека отказывает заранее. Вторая и третья — собственные настройки операции. `readConcern`, `writeConcern`, `readPreference` (кроме `primary`) и `timeoutMS` у отдельной операции внутри транзакции запрещены, их задают на самой транзакции. Четвёртая — модель другого клиента, она к транзакции присоединиться не может. Везде это [`StrictModeError`](../errors/data-errors.mdx#strictmodeerror) с причинами `concurrent-session` и `transaction-option`.

Отдельный случай — сервер без транзакций. На одиночном `mongod` `transaction` сразу бросает `ConfigurationError`, функцию он не вызывает.

```text
ConfigurationError: TypemoClient "default": transaction(): transactions need a replica set or a sharded cluster; this server is a standalone mongod. Run MongoDB as a replica set (a single-member one is enough).
```

`session(null)` (или `{ session: null }`) намеренно запускает операцию вне текущей транзакции. Запись останется, даже если транзакция откатится.

### Когда не подходит

Одна запись в один документ атомарна и без транзакции. Транзакция добавит только накладные расходы и ограничения. Если данные приходят пакетом и частичная запись допустима, возьмите `insertMany` или `bulkWrite` и ловите [`BulkWriteError`](../errors/server-errors.mdx#bulkwriteerror). Чтобы управлять сессией и фиксацией самому, есть [`startSession`](#startsession).

## TransactionOptions

`TransactionOptions` — необязательный объект настроек, второй аргумент [`transaction`](#transaction). Вы задаёте настройки в простой форме, а в объекты драйвера библиотека превращает их сама. Отдельная операция внутри транзакции переопределить их не может и получит [`StrictModeError`](../errors/data-errors.mdx#strictmodeerror) с причиной `transaction-option`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => Number, { required: true, min: 0 }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
// ---cut---
const total = await client.transaction(async () => Accounts.countDocuments(), {
  readConcern: "snapshot",
  writeConcern: { w: "majority" },
  timeoutMS: 5_000,
});
console.log(total);
// → 2
```

<Params title="Поля объекта">
<Param name="readConcern" type={'"local" | "majority" | "snapshot"'}>

Уровень чтения транзакции. `snapshot` показывает всем чтениям один и тот же снимок данных, `majority` — данные, которые подтвердило большинство узлов, `local` — данные узла как есть. Если не задан, действует уровень сервера по умолчанию.

</Param>
<Param name="writeConcern" type="{ w?: number | 'majority'; journal?: boolean }">

Подтверждение записи при фиксации. `w` говорит, сколько узлов должны подтвердить, `journal` — нужна ли запись в журнал. Настройка действует на фиксацию, а не на отдельные операции.

</Param>
<Param name="timeoutMS" type="number">

Срок всей транзакции в миллисекундах, вместе с повторами. Когда срок вышел, вы получаете [`TimeoutError`](../errors/server-errors.mdx#timeouterror) с `kind: "transaction"` и заполненным `timeoutMS`. Транзакция с `timeoutMS: 200`, в которой запрос блокировался на 400 мс, завершилась ошибкой `transaction timed out after 200 ms (timeoutMS)`. Срок отдельной операции (`timeoutMS` запроса) даёт `kind: "operation"`. Внутри такой транзакции отдельной операции со своим `timeoutMS` быть не может.

</Param>
<Param name="maxCommitTimeMS" type="number">

Сколько миллисекунд сервер может тратить на фиксацию. Поле принимается и уходит драйверу, но его действие отдельно не проверялось.

</Param>
</Params>

<FullType>

```ts
interface TransactionOptions {
  readonly readConcern?: "local" | "majority" | "snapshot";
  readonly writeConcern?: { readonly w?: number | "majority"; readonly journal?: boolean };
  readonly timeoutMS?: number;
  readonly maxCommitTimeMS?: number;
}
```

</FullType>

## TransactionCallback

`TransactionCallback<R>` — тип функции, которую принимает [`transaction`](#transaction). Это асинхронная функция, она получает [`TransactionScope`](#transactionscope) и возвращает значение типа `R`. Тип пригодится, когда вы выносите тело транзакции в отдельную функцию или передаёте его параметром.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, type TransactionCallback } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => Number, { required: true, min: 0 }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
// ---cut---
const countAccounts: TransactionCallback<number> = async (scope) => {
  console.log(scope.attempt);
  // → 1
  return Accounts.countDocuments();
};

const count = await client.transaction(countAccounts);
//    ^?
```

Если `scope` не нужен, аргумент можно не принимать. Операции внутри и так находят транзакцию сами.

<FullType>

```ts
type TransactionCallback<R> = (scope: TransactionScope) => Promise<R>
```

</FullType>

## startSession

`startSession` открывает явную сессию драйвера. Она нужна, когда вы сами ведёте транзакцию — запускаете и фиксируете вручную или передаёте сессию запросу через `.session()`. Метод есть у клиента ([`client.startSession`](../connection/typemo-client.mdx#clientstartsession)) и у модели. В остальных случаях берите [`transaction`](#transaction), она сама создаёт и закрывает сессию.

Сессию закрываете вы, вызовом `endSession()`. Библиотека этого не делает, а незакрытая сессия держит ресурсы на сервере, пока не истечёт её срок.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => Number, { required: true, min: 0 }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Accounts = client.connection.model(Account);
// ---cut---
const session = await client.startSession();
try {
  await session.withTransaction(async () => {
    await Accounts.create({ title: "Manual", balance: 1 }, { session });
  });
} finally {
  await session.endSession();
}
```

<Params>
<Param name="options" type="ClientSessionOptions">

Параметры сессии драйвера. Необязательны.

</Param>
</Params>

<Returns type="Promise<ClientSession>">

Сессия драйвера. Сначала метод дожидается готовности клиента, так что вызов до `connect` не падает, а ждёт. Метод бросает [`ConnectionError`](../errors/configuration-errors.mdx#connectionerror), если клиент закрыт, и [`TimeoutError`](../errors/server-errors.mdx#timeouterror), если он не подключился вовремя.

</Returns>

Как передать сессию операциям, что будет при забытой сессии и какие правила действуют для одновременных операций, читайте в руководстве [Сессии вручную](../../transactions/sessions.mdx).

### Когда не подходит

Для обычной транзакции ручная сессия не нужна. [`transaction`](#transaction) делает то же самое, повторяет функцию при временных сбоях и закрывает сессию сама.

## client.currentTransaction

`client.currentTransaction()` отвечает, идёт ли текущий асинхронный вызов внутри транзакции **этого** клиента, и возвращает её [`TransactionScope`](#transactionscope). Метод нужен обёрткам, которым надо решить, открывать транзакцию или работать в уже открытой. Вкладывать транзакции нельзя, и второй [`transaction`](#transaction) внутри первого — ошибка. По этому принципу работает, например, `@Transactional({ join: true })` из пакета для NestJS ([`Transactional`](../integrations/nestjs.mdx#transactional)).

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
// ---cut---
const run = async (work: () => Promise<void>): Promise<void> => {
  if (client.currentTransaction() !== undefined) return work();
  return client.transaction(work);
};

console.log(client.currentTransaction());
// → undefined
await client.transaction(async (scope) => {
  console.log(client.currentTransaction() === scope);
  // → true
  await run(async () => {});
});
```

Вопрос ничего не начинает. Метод не открывает сессию и не отправляет команд. Транзакцию он видит там же, где её видят операции моделей, то есть после `await`, в вызванных функциях и в колбэках внутри функции транзакции.

<Returns type="TransactionScope | undefined">

Транзакция этого клиента, в которой идёт вызов, или `undefined`. `undefined` приходит вне транзакции и **внутри транзакции другого клиента**. Операции этого клиента к ней не присоединятся, так что для него транзакции нет. Чтобы узнать транзакцию любого клиента, вызовите [`TransactionScope.current`](#transactionscopecurrent).

</Returns>

Принимает ничего.

<FullType>

```ts
currentTransaction(): TransactionScope | undefined
```

</FullType>

### Когда не подходит

Чтобы выполнить код в транзакции, вызывайте [`transaction`](#transaction). `currentTransaction` только отвечает на вопрос. Не храните результат дольше функции транзакции, после неё сессия закрыта.

## TransactionScope

`TransactionScope` — объект, который получает функция транзакции. Он описывает текущую транзакцию и её текущую попытку. Обычно он нужен ради двух вещей. Первая — узнать номер попытки (`attempt`). Вторая — передать сессию (`scope.session`) вызову драйвера, который о транзакции Typemo ничего не знает.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => Number, { required: true, min: 0 }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const raw = client.unsafeDriver().db("app").collection("accounts");
// ---cut---
await client
  .transaction(async (scope) => {
    console.log(scope.attempt, scope.timeoutMS, scope.session.inTransaction());
    // → 1 undefined true
    await raw.insertOne({ title: "Raw", balance: 1 }, { session: scope.session });
    throw new Error("abort");
  })
  .catch(() => undefined);

console.log(await raw.countDocuments({ title: "Raw" }));
// → 0
```

Запись драйвера с `session: scope.session` откатилась вместе с транзакцией. Без этого аргумента она осталась бы в базе, потому что вызовы драйвера сами в транзакцию не присоединяются.

### TransactionScope.current

Статический `TransactionScope.current()` возвращает транзакцию текущего асинхронного вызова, **любого** клиента, а вне транзакций — `undefined`. Её `owner` — клиент. Метод нужен, когда надо отличить «вне транзакции» от «внутри транзакции другого клиента». Для своего клиента проще [`client.currentTransaction`](#clientcurrenttransaction). Внутри транзакции второго клиента `client.currentTransaction()` вернул `undefined`, а `TransactionScope.current()?.owner` — второй клиент. Как и `currentTransaction`, метод ничего не начинает.

### enlist

Метод `enlist(participant)` добавляет участника в текущую попытку. Повторный вызов с тем же участником ничего не меняет. Метод нужен только тому, кто хранит в памяти состояние, зависящее от исхода транзакции, и хочет откатывать его при повторе. Участник задаёт три необязательные функции. `onRetry` вызывается, когда попытка не удалась и функция запустится снова, `onAbort` — когда транзакция закончилась неудачей, `onCommit` — когда она зафиксирована. Уведомляются все участники, даже если функция одного бросила ошибку. Первая ошибка вылетает уже после того, как уведомлены остальные.

Обычным приложениям `enlist` не нужен, документы Typemo записываются сами. Он пригодится, если вы пишете собственное хранилище состояния в памяти, которое должно вести себя как документ. Запуском проверено только чтение полей `id`, `attempt`, `timeoutMS`, `session`, `owner` и `participants`. Порядок вызовов участников описан по коду библиотеки.

<FullType>

```ts
class TransactionScope {
  static current(): TransactionScope | undefined;
  readonly id: number;
  readonly session: ClientSession;
  readonly owner: object;
  readonly timeoutMS: number | undefined;
  readonly startedAt: number;
  get attempt(): number;
  get participants(): readonly TransactionParticipant[];
  enlist(participant: TransactionParticipant): void;
}

interface TransactionParticipant {
  readonly onRetry?: () => void | Promise<void>;
  readonly onAbort?: () => void | Promise<void>;
  readonly onCommit?: () => void | Promise<void>;
}
```

</FullType>

### Когда не подходит

Не храните `scope` за пределами функции транзакции, после её окончания сессия закрыта. Не вызывайте `enlist` для вещей вне памяти процесса. Откатить запись во внешний сервис он не умеет.
