**Материализованное представление** — это обычная коллекция, в которую записан результат агрегации. В отличие от [`TypedView`](./typed-view.mdx), который пересчитывается при каждом чтении, `Materialized` считает результат один раз, когда вы вызываете `refresh`, и кладёт его на диск. Чтение после этого такое же быстрое, как у любой коллекции, и на результат можно повесить индексы. Цена — свежесть: результат обновляется только по вашей команде, сам он не меняется.

`Materialized` описывает такую пару «источник → результат» в типах. Целевая коллекция — обычная модель с классом, а строки конвейера сверяются с этим классом при компиляции. Под капотом `refresh` запускает агрегацию над источником и завершает её стадией `$merge` (по умолчанию) или `$out` (режим `replace`): их добавляет сам Typemo, в вашем конвейере их быть не должно.

Если вы впервые работаете с материализованными результатами, сначала прочитайте руководство [Материализованные представления](../../collections/materialized-views.mdx). Эта страница — справочник.

Примеры используют счета. В `accounts` три документа: Main (владелец alice, баланс 120, открыт), Old (alice, 0, закрыт) и Savings (bob, 500, открыт). Результат — итоги по владельцам.

```ts twoslash title="accounts/models.ts"
import { Entity, EntityWithId, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => Number, { required: true })
  balance!: number;

  @Prop(() => Boolean, { required: true })
  closed!: boolean;
}

@Schema({ collection: "owner_totals" })
export class OwnerTotal extends EntityWithId(() => String) {
  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Number, { required: true })
  count!: number;
}
```

Класс результата описан как сущность со своим типом `_id`: [`EntityWithId`](../schemas/base-classes.mdx#entitywithid) с типом `String` делает `_id` строкой (здесь это имя владельца), остальные поля — итоги. Подробнее о таких идентификаторах — в руководстве [Задать свой тип _id](../../schemas/custom-ids.mdx).

## Materialized.define

`define` описывает материализованный результат и **ничего не считает и не записывает**: коллекция результата появится, когда вы вызовете [`refresh`](#materializedrefresh). Вы передаёте подключение, класс результата и определение: модель-источник (`from`), конвейер и способ записи.

Конвейер проверяется на соответствие классу результата: если он не выдаёт поле класса, компилятор указывает на него. Единственное послабление: строка может не содержать `_id`, если его не даёт конвейер, потому что `$merge` и `$out` присваивают вставляемой строке `_id` сами.

```ts twoslash
import { Entity, EntityWithId, fn, Materialized, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => Boolean, { required: true }) closed!: boolean;
}
@Schema({ collection: "owner_totals" })
class OwnerTotal extends EntityWithId(() => String) {
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Number, { required: true }) count!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const connection = client.connection;
// ---cut---
export const ownerTotals = Materialized.define(connection, OwnerTotal, {
  from: Account,
  pipeline: (p) =>
    p.match({ closed: false }).group((f) => ({ _id: f.owner, total: fn.sum(f.balance), count: fn.sum(1) })),
});
console.log(ownerTotals.definition.mode, ownerTotals.definition.on);
// → "merge" ["_id"]
```

<Returns type="Materialized<InstanceType<Target>>">

Объект `Materialized` с полями `model` (обычная [модель](../connection/connection.mdx#connectionmodel) результата), `definition` ([`MaterializedInfo`](#materializedinfo)) и методом [`refresh`](#materializedrefresh). Пока `refresh` не вызван, коллекции результата в базе нет: запуск показал, что после `define` в базе только `accounts`.

</Returns>

<Params>
<Param name="connection" type="Connection" required>

Подключение, которому принадлежат обе модели: и источник, и результат.

</Param>
<Param name="target" type="EntityClass" required>

Класс результата. Его коллекция — целевая. Если под этим именем определено представление ([`TypedView`](./typed-view.mdx)), `define` бросает `ConfigurationError`: `OwnerTotal: a materialized result is a regular collection; "owner_totals" is a view`.

</Param>
<Param name="definition.from" type="EntityClass" required>

Модель-источник: по её данным считается конвейер. Агрегация идёт через операционный конвейер этой модели, как обычная [`aggregate`](./typed-view.mdx#typedviewaggregate): скрытые поля, подстановка `dbName` и условие дискриминатора работают так же.

</Param>
<Param name="definition.pipeline" type="(p) => StagedPipeline" required>

Функция, которая получает строитель и возвращает конвейер вычисления. Стадии `$merge` и `$out` в него не входят: их добавляет `refresh`.

</Param>
<Param name="definition.mode" type='"merge" | "replace"' default='"merge"'>

Как строки попадают в целевую коллекцию. Подробно — в разделе [Режимы записи](#режимы-записи).

</Param>
<Param name="definition.on" type="string | [string, ...string[]]" default='"_id"'>

Поле или поля, по которым `$merge` узнаёт «ту же» строку. Принимаются только поля класса результата (и `_id`). Только для режима `merge`.

</Param>
<Param name="definition.whenMatched" type='"replace" | "keepExisting" | "merge" | "fail"'>

Что делать, если строка с такими значениями `on` уже есть в результате. Только для режима `merge`. Если не указано, действует умолчание сервера.

</Param>
<Param name="definition.whenNotMatched" type='"insert" | "discard" | "fail"'>

Что делать, если такой строки в результате ещё нет. Только для режима `merge`. Если не указано, действует умолчание сервера.

</Param>
</Params>

### Поле `on` не относится к классу

`define` проверяет ключи `$merge` при вызове. Ключ, которого нет среди полей класса результата, — это `ConfigurationError` вида `OwnerTotal: $merge on "…", which is not a field of the class`. Компилятор отклоняет такой ключ ещё раньше, потому что тип `on` — это ключи класса результата.

## Materialized.refresh

`refresh` пересчитывает результат и записывает его: запускает конвейер над источником и завершает его `$merge` или `$out`. Он нужен, когда пришло время обновить итоги: по расписанию, после пакетной загрузки, по кнопке в панели. Автоматически ничего не обновляется.

```ts twoslash
import { Entity, EntityWithId, fn, Materialized, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => Boolean, { required: true }) closed!: boolean;
}
@Schema({ collection: "owner_totals" })
class OwnerTotal extends EntityWithId(() => String) {
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Number, { required: true }) count!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const connection = client.connection;
const ownerTotals = Materialized.define(connection, OwnerTotal, {
  from: Account,
  pipeline: (p) =>
    p.match({ closed: false }).group((f) => ({ _id: f.owner, total: fn.sum(f.balance), count: fn.sum(1) })),
});
// ---cut---
console.log(await ownerTotals.model.find().lean());
// → []

await ownerTotals.refresh();
const totals = await ownerTotals.model.find().sort({ _id: 1 }).lean();
console.log(totals);
// → [{ _id: "alice", total: 120, count: 1 }, { _id: "bob", total: 500, count: 1 }]
```

<Returns type="Promise<void>">

Ничего не возвращает: строки лежат в коллекции результата, читайте их через `materialized.model`. Промис завершается, когда сервер записал все строки.

</Returns>

Опции агрегации над источником: `session`, `timeoutMS`, `policy`. Они передаются в агрегацию модели-источника.

</Param>

### Что `$merge` не делает

В режиме `merge` результат никогда не очищается: `$merge` вставляет новые строки и обновляет совпавшие, а строки, для которых в источнике больше нет данных, остаются. Допустим, счёт Savings закрыли, а счёт Main пополнили до 150. После нового `refresh` итог Main обновился, а bob остался со старым значением, хотя открытых счетов у него уже нет:

```ts twoslash
import { Entity, EntityWithId, fn, Materialized, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => Boolean, { required: true }) closed!: boolean;
}
@Schema({ collection: "owner_totals" })
class OwnerTotal extends EntityWithId(() => String) {
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Number, { required: true }) count!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const connection = client.connection;
const Accounts = connection.model(Account);
const ownerTotals = Materialized.define(connection, OwnerTotal, {
  from: Account,
  pipeline: (p) =>
    p.match({ closed: false }).group((f) => ({ _id: f.owner, total: fn.sum(f.balance), count: fn.sum(1) })),
});
await ownerTotals.refresh();
// ---cut---
await Accounts.updateOne({ title: "Savings" }, { $set: { closed: true } });
await Accounts.updateOne({ title: "Main" }, { $set: { balance: 150 } });
await ownerTotals.refresh();
console.log(await ownerTotals.model.find().sort({ _id: 1 }).lean());
// → [{ _id: "alice", total: 150, count: 1 }, { _id: "bob", total: 500, count: 1 }]
```

Если вам нужно, чтобы результат в точности повторял конвейер, используйте режим `replace`.

### Слияние по полю, которое не `_id`

Если `on` называет поле кроме `_id`, `$merge` нужен уникальный индекс ровно по этим полям в целевой коллекции: иначе сервер не может узнать «ту же» строку однозначно. Typemo проверяет это перед запуском и выдаёт понятную ошибку, а не ответ сервера. Пусть результат — копия остатков по названию счёта, уникальная по `title`:

```ts twoslash title="accounts/models.ts"
import { Entity, Index, Prop, Schema } from "@venloc/typemo";

@Index({ title: 1 }, { unique: true })
@Schema({ collection: "account_balances" })
export class AccountBalance extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Number, { required: true })
  balance!: number;
}
```

Пока индекса в базе нет, `refresh` отказывается работать:

```ts twoslash
import { ConfigurationError, Entity, Index, Materialized, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
@Index({ title: 1 }, { unique: true })
@Schema({ collection: "account_balances" })
class AccountBalance extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const connection = client.connection;
const balances = Materialized.define(connection, AccountBalance, {
  from: Account,
  on: "title",
  pipeline: (p) => p.project({ _id: 0, title: 1, balance: 1 }),
});
// ---cut---
try {
  await balances.refresh();
} catch (error) {
  if (error instanceof ConfigurationError) console.log(error.message);
}
// → AccountBalance: $merge on "title" needs a unique index on exactly these fields in "account_balances";
//   declare it (@Index(..., { unique: true })) and run syncIndexes(), or merge on _id

await balances.model.syncIndexes();
await balances.refresh();
console.log((await balances.model.find().sort({ title: 1 }).plain()).map((row) => [row.title, row.balance]));
// → [["Main", 120], ["Old", 0], ["Savings", 500]]
```

### Совпавшие строки и опция whenMatched

Значения `whenMatched` и `whenNotMatched` передаются стадии `$merge` как есть, поэтому их поведение определяет сервер. Запуском проверено два: `keepExisting` оставляет уже записанную строку (после изменения источника итог не изменился), а `fail` останавливает `refresh` ошибкой `DuplicateKeyError`, как только находит совпавшую строку:

```text
DuplicateKeyError: duplicate key on title_1: { title: "Main" } (code 11000 DuplicateKey)
```

Значения `replace`, `merge`, `insert`, `discard` и `fail` для `whenNotMatched` типизированы, но отдельно на сервере не запускались.

## Режимы записи

**`merge`** (по умолчанию) вставляет новые строки и обновляет совпавшие, не очищая коллекцию. Он подходит для накопительных итогов и инкрементальных обновлений, когда старые строки терять нельзя. Строки сравниваются по `on` (по умолчанию `_id`).

**`replace`** заменяет всю коллекцию результатом конвейера (стадия `$out`). Он подходит, когда результат должен в точности повторять текущий конвейер: исчезнувшие строки пропадают. Параметры `on`, `whenMatched` и `whenNotMatched` в этом режиме не принимаются.

Проверено на тех же данных: после закрытия счёта Savings режим `replace` оставил в результате одну строку, alice, а не две, как `merge`:

```ts twoslash
import { Entity, EntityWithId, fn, Materialized, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => Boolean, { required: true }) closed!: boolean;
}
@Schema({ collection: "owner_totals" })
class OwnerTotal extends EntityWithId(() => String) {
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Number, { required: true }) count!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const connection = client.connection;
// ---cut---
const fresh = Materialized.define(connection, OwnerTotal, {
  from: Account,
  mode: "replace",
  pipeline: (p) =>
    p.match({ closed: false }).group((f) => ({ _id: f.owner, total: fn.sum(f.balance), count: fn.sum(1) })),
});
await fresh.refresh();
console.log(await fresh.model.find().sort({ _id: 1 }).lean());
// → [{ _id: "alice", total: 150, count: 1 }]
```

Одну и ту же целевую коллекцию можно описать несколькими объектами `Materialized`, если их режимы или конвейеры нужны в разных местах: проверки на конфликт определений у `Materialized` нет.

## materialized.model

Обычная модель целевой коллекции: `find`, `aggregate`, `syncIndexes` и всё остальное, что есть у модели. Из неё вы читаете результат и с её помощью строите индексы результата. Так как коллекция обычная, её обрабатывает и [`connection.syncAll`](../connection/connection.mdx#connectionsyncall): индексы результата создаются, а сама коллекция появляется. Синхронизация `syncAll` наполнять результат не будет: строки появляются только после [`refresh`](#materializedrefresh).

Поле только для чтения, тип `Model<T>`.

### MaterializedWrite и MaterializedRowCheck

`MaterializedWrite<Target>` — тип опций записи: `mode`, `on`, `whenMatched`, `whenNotMatched` для режима `merge` и `mode: "replace"` для замены; он разобран в описании [`define`](#materializeddefine). `MaterializedRowCheck<Row, V>` — служебный тип, который сверяет строки конвейера с классом результата: как проверка представления, но допускает строку без `_id`.

---

## Когда не подходит

Если результат нужен всегда свежим и запросов немного, используйте [`TypedView`](./typed-view.mdx): он ничего не хранит и не требует обновления. Если результат не нужно хранить в коллекции, а нужно один раз прочитать, достаточно обычной [агрегации](../aggregation/pipeline.mdx). Автоматического обновления по расписанию в Typemo нет: `refresh` вы вызываете сами, из задачи по расписанию или после изменения данных.

Руководство с реальными задачами — [Материализованные представления](../../collections/materialized-views.mdx).
