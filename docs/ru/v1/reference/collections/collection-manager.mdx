Параметры коллекции — ограниченный размер (`capped`), временные ряды, кластерный индекс, валидатор документов на стороне сервера, правило сортировки строк — описываются в [`@Schema`](../schemas/schema.mdx) и применяются, когда коллекция создаётся. На этой странице описано, как их применить и как сравнить с тем, что уже есть на сервере: методы модели `createCollection` и `ensureCollection`, статический класс `CollectionManager`, на котором они построены, и отчёт `EnsureCollectionReport`.

Если вы впервые настраиваете коллекции, сначала прочитайте руководство [Создание коллекций](../../collections/create.mdx). Эта страница — справочник.

Главная особенность в том, что Typemo не молчит о расхождении. Сама база при повторном `createCollection` с другими параметрами отвечает ошибкой «уже существует», и многие библиотеки эту ошибку глотают, так что изменённый параметр никогда не доходит до сервера. Typemo сравнивает параметры и либо подтверждает совпадение, либо сообщает, что именно отличается.

Примеры используют две модели: счёт с серверным валидатором и журнал проводок ограниченного размера.

```ts twoslash title="accounts/account.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts", validator: true })
export class Account extends Entity {
  @Prop(() => String, { required: true, minLength: 2 })
  title!: string;

  @Prop(() => Number, { min: 0 })
  balance?: number;
}

@Schema({ collection: "ledger", capped: { size: 65_536, max: 100 } })
export class LedgerEntry extends Entity {
  @Prop(() => String, { required: true })
  note!: string;
}
```

Результаты в комментариях получены на пустой базе, если рядом не сказано иное.

## Model.createCollection

`createCollection` создаёт коллекцию модели с параметрами из схемы и возвращает `true`, если создал. Он нужен, когда вы хотите создать коллекцию явно и получить ошибку при расхождении, а не тихо продолжить работу с коллекцией, которая устроена иначе, чем в схеме.

Слово «уже существует» здесь означает одно из двух. Если коллекция есть и её параметры совпадают со схемой, метод возвращает `false`. Если коллекция есть, а параметры другие, метод бросает [`CollectionOptionsError`](../errors/configuration-errors.mdx#collectionoptionserror): изменить существующую коллекцию он не пытается. Для изменения нужен [`ensureCollection`](#modelensurecollection) с опцией `update`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts", validator: true })
class Account extends Entity {
  @Prop(() => String, { required: true, minLength: 2 }) title!: string;
  @Prop(() => Number, { min: 0 }) balance?: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.connection.model(Account);
// ---cut---
console.log(await Accounts.createCollection());
// → true
console.log(await Accounts.createCollection());
// → false
```

<Returns type="Promise<boolean>">

`true`, если коллекция создана этим вызовом; `false`, если она уже существовала с теми же параметрами. Если параметры отличаются, вы получаете не `false`, а [`CollectionOptionsError`](../errors/configuration-errors.mdx#collectionoptionserror) с полем `differences`.

</Returns>

Принимает ничего.

<FullType>

```ts
createCollection(): Promise<boolean>
```

</FullType>

### Коллекция уже есть с другими параметрами

Допустим, счета уже хранятся в коллекции, созданной без валидатора: например, её создала первая запись, ещё до того как в схему добавили `validator`. Метод отказывается молча считать такую коллекцию готовой:

```ts twoslash
import { CollectionOptionsError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts", validator: true })
class Account extends Entity {
  @Prop(() => String, { required: true, minLength: 2 }) title!: string;
  @Prop(() => Number, { min: 0 }) balance?: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.connection.model(Account);
await client.unsafeDriver().db("app").createCollection("accounts");
// ---cut---
try {
  await Accounts.createCollection();
} catch (error) {
  if (error instanceof CollectionOptionsError) {
    console.log(error.collection, error.differences.map((d) => [d.option, d.mutable]));
    // → "accounts" [["validator", true]]
  }
}
```

```text
CollectionOptionsError: collection "accounts": exists with other options (validator); run ensureCollection({ update: true }) to change them with collMod
```

### Схема с `autoCreate: false`

Опция схемы `autoCreate: false` говорит, что коллекцию создаёт кто-то другой: администратор, другой сервис, миграция. Поэтому `createCollection` такой модели не создаёт ничего и бросает [`ConfigurationError`](../errors/configuration-errors.mdx#configurationerror). Если бы он молча создал коллекцию, опция потеряла бы смысл.

```text
ConfigurationError: AuditLog.createCollection: the schema of AuditLog says autoCreate: false — Typemo does not create the collection "audit_logs"; create it where it is owned, or remove autoCreate: false
```

То же правило действует в [`connection.init`](../connection/connection.mdx#connectioninit) и [`connection.syncAll`](../connection/connection.mdx#connectionsyncall): они пропускают шаг параметров коллекции такой модели. Если у схемы нет ни индексов, ни поисковых индексов, ей нечего создавать, и модель пропускается целиком: нет коллекции — нет ошибки, её создаёт владелец. Если индексы есть, а коллекции ещё нет и у схемы есть параметры, задаваемые только при создании, индекс создал бы коллекцию без этих параметров, поэтому `init` и `syncAll` бросают [`SyncError`](../errors/configuration-errors.mdx#syncerror) с той же ошибкой, что у первой записи (см. ниже). Метод [`ensureCollection`](#modelensurecollection) опцию не смотрит: если вы вызвали его сами, коллекция создастся (запуск на MongoDB 9.0 показал `"created"` у модели с `autoCreate: false`).

## Model.ensureCollection

`ensureCollection` делает так, чтобы коллекция существовала с параметрами схемы, и рассказывает, что для этого потребовалось. Если коллекции нет, он её создаёт. Если она есть и совпадает, ничего не делает. Если она есть и отличается только тем, что сервер умеет менять на лету, он меняет это командой `collMod` при `update: true`. Всё остальное — ошибка. Это основной метод для деплоя: он идемпотентен и по результату видно, было ли что-то сделано.

Обратите внимание: по умолчанию `ensureCollection` **ничего не меняет** в существующей коллекции. Параметры уже работающей коллекции не должны меняться случайно, поэтому любое различие без `update: true` — ошибка. Опция `dryRun` показывает, что случилось бы, и ничего не записывает.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "ledger", capped: { size: 65_536, max: 100 } })
class LedgerEntry extends Entity {
  @Prop(() => String, { required: true }) note!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Ledger = client.connection.model(LedgerEntry);
// ---cut---
const first = await Ledger.ensureCollection();
console.log(first.result);
// → "created"
const second = await Ledger.ensureCollection();
console.log(second.result);
// → "unchanged"
```

<Returns type="Promise<EnsureCollectionReport>">

Отчёт [`EnsureCollectionReport`](#ensurecollectionreport): поле `result` (`"created"`, `"unchanged"` или `"updated"`) и список `differences` найденных различий. Для `"created"` и `"unchanged"` список пустой. При `dryRun: true` отчёт описывает то, что было бы сделано.

</Returns>

<Params>
<Param name="options.update" type="boolean" default="false">

Применить командой `collMod` те различия, которые сервер умеет менять на месте (см. [что можно изменить](#что-можно-изменить-на-месте)). Без этой опции любое различие — [`CollectionOptionsError`](../errors/configuration-errors.mdx#collectionoptionserror).

</Param>
<Param name="options.dryRun" type="boolean" default="false">

Только сообщить: `result` и `differences` вернутся, но сервер не изменится. Различие, которое `collMod` изменить не может, всё равно бросает ошибку: такую разницу не исправить ни с `update`, ни без.

</Param>
</Params>

<FullType>

```ts
ensureCollection(options?: EnsureCollectionOptions): Promise<EnsureCollectionReport>
```

</FullType>

### Изменить параметр существующей коллекции

Допустим, журнал проводок был создан с лимитом 1024 байта, а схема теперь требует 65 536. Размер и число документов capped-коллекции сервер менять умеет, поэтому со `update: true` это одна команда:

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "ledger", capped: { size: 65_536, max: 100 } })
class LedgerEntry extends Entity {
  @Prop(() => String, { required: true }) note!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Ledger = client.connection.model(LedgerEntry);
await client.unsafeDriver().db("app").createCollection("ledger", { capped: true, size: 1024, max: 100 });
// ---cut---
const plan = await Ledger.ensureCollection({ dryRun: true });
console.log(plan.result, plan.differences);
// → "updated" [{ option: "size", mutable: true, wanted: 65536, actual: 1024 }]

const done = await Ledger.ensureCollection({ update: true });
console.log(done.result);
// → "updated"
console.log((await Ledger.ensureCollection()).result);
// → "unchanged"
```

Без `update: true` тот же вызов бросил бы ошибку со списком различий:

```text
CollectionOptionsError: collection "ledger": exists with other options (size); run ensureCollection({ update: true }) to change them with collMod
```

### Различие, которое изменить нельзя

Превратить обычную коллекцию в capped сервер не умеет: для этого нужно удалить коллекцию и создать заново. `ensureCollection` не удаляет коллекции сам, поэтому бросает ошибку и с `update`, и без него:

```ts twoslash
import { CollectionOptionsError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "ledger", capped: { size: 65_536, max: 100 } })
class LedgerEntry extends Entity {
  @Prop(() => String, { required: true }) note!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Ledger = client.connection.model(LedgerEntry);
await client.unsafeDriver().db("app").createCollection("ledger");
// ---cut---
try {
  await Ledger.ensureCollection({ update: true });
} catch (error) {
  if (error instanceof CollectionOptionsError) {
    console.log(error.differences.map((d) => [d.option, d.mutable]));
    // → [["capped", false]]
  }
}
```

```text
CollectionOptionsError: collection "ledger": exists with options MongoDB cannot change (capped): drop the collection and create it again
```

### Первая запись в коллекцию, которой ещё нет

Сервер создаёт несуществующую коллекцию при первой записи и всегда обычной: без `capped`, временных рядов, кластерного индекса и правила сортировки. Эти четыре параметра задаются только при создании, поэтому потом исправить их нельзя. Typemo не даёт этого сделать по ошибке: первая вставка, пакетная запись, upsert или сохранение документа модели с такими параметрами, а также `createIndexes`, `syncIndexes` и `connection.init`, проверяют, что коллекция существует. Если её нет, вы получаете [`ConfigurationError`](../errors/configuration-errors.mdx#configurationerror), а в базе ничего не появляется:

```text
ConfigurationError: LedgerEntry.create: the collection "ledger" does not exist, and MongoDB would create it as a plain collection without the options of the schema that can only be given at creation (capped); create it first: await connection.init(), or await LedgerEntry.ensureCollection()
```

Проверка идёт один раз для модели: найденную коллекцию Typemo запоминает, и следующие записи ничего не стоят. Обычное чтение и `updateOne` без `upsert` проверке не подвержены. Для модели с `autoCreate: false` в ту же ошибку добавлено пояснение: коллекцию должен создать её владелец с этими параметрами.

Валидатор и хранение образов документа проверка не охватывает, потому что `collMod` умеет их менять: запись в несуществующую коллекцию со `validator: true` создаст обычную коллекцию без валидатора, а [`ensureCollection`](#modelensurecollection) потом покажет это различие (`validator`, `mutable: true`) и исправит с `update: true`.

### Представление под именем коллекции

Если под именем коллекции лежит представление (view), метод отказывается работать с ним как с коллекцией:

```text
CollectionOptionsError: collection "ledger": exists as a view, not a collection: drop it or use another name
```

Список различий `differences` каждый раз говорит, можно ли исправить различие командой `collMod` (поле `mutable`). Что можно, Typemo знает заранее: список зашит в код сравнения.

## CollectionManager

`CollectionManager` — статический класс, на котором построены `createCollection` и `ensureCollection`. Он нужен там, где у вас есть база драйвера, но нет удобного места для вызова метода модели: служебный скрипт, проверка окружения, свой инструмент деплоя. Методы, которым нужна схема (`optionsOf`, `create`, `ensure`), принимают **модель** или её `schema`: [`SchemaSource`](#schemasource). Остальные три (`info`, `differences`, `collMod`) работают с обычными значениями.

```ts twoslash
import { CollectionManager, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts", validator: true })
class Account extends Entity {
  @Prop(() => String, { required: true, minLength: 2 }) title!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.connection.model(Account);
// ---cut---
const wanted = CollectionManager.optionsOf(Accounts);
console.log(Object.keys(wanted));
// → ["validator", "validationLevel", "validationAction"]
```

### CollectionManager.info

`info` читает с сервера описание одной коллекции: то, что возвращает `listCollections` для этого имени. Он нужен в служебных скриптах, чтобы посмотреть тип и параметры коллекции или представления, не вызывая драйвер вручную. Если коллекции нет, возвращает `undefined`.

```ts twoslash
import { CollectionManager, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const db = client.unsafeDriver().db("app");
await db.createCollection("ledger", { capped: true, size: 1024, max: 100 });
// ---cut---
const info = await CollectionManager.info(db, "ledger");
console.log(info?.name, info?.type, info?.options);
// → "ledger" "collection" { capped: true, size: 1024, max: 100 }

console.log(await CollectionManager.info(db, "missing"));
// → undefined
```

<Returns type="Promise<CollectionInfo | undefined>">

Запись `listCollections`: [`CollectionInfo`](#collectioninfo) с полями `name`, `type` (`"collection"`, `"view"` или `"timeseries"`) и `options` — параметры, с которыми коллекция создана. Если коллекции нет, `undefined`.

</Returns>

<Params>
<Param name="db" type="Db" required>

База драйвера `mongodb`. Её можно получить через [`client.unsafeDriver`](../connection/typemo-client.mdx#clientunsafedriver).

</Param>
<Param name="name" type="string" required>

Имя коллекции.

</Param>
</Params>

<FullType>

```ts
static info(db: Db, name: string): Promise<CollectionInfo | undefined>
```

</FullType>

Ошибка драйвера приходит уже в виде ошибки Typemo (см. [`ServerError`](../errors/server-errors.mdx#servererror)).

### CollectionManager.differences

`differences` сравнивает объявленные параметры коллекции с сохранёнными на сервере и возвращает список различий. Сначала он проверяет **вид** коллекции: представление вместо коллекции или коллекция вместо временного ряда — это сразу [`CollectionOptionsError`](../errors/configuration-errors.mdx#collectionoptionserror), а не список.

Объявленные параметры — это обычный объект в форме, которую принимает `createCollection` драйвера: `{ capped: true, size: 65_536, max: 100 }`. Из схемы такой объект строит [`optionsOf`](#collectionmanageroptionsof-create-и-ensure); в примере он записан руками, чтобы было видно, что сравнивается.

```ts twoslash
import { CollectionManager, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const db = client.unsafeDriver().db("app");
await db.createCollection("ledger", { capped: true, size: 1024, max: 100 });
const info = await CollectionManager.info(db, "ledger");
if (info === undefined) throw new Error("no such collection");
// ---cut---
const found = CollectionManager.differences("ledger", { capped: true, size: 65_536, max: 100 }, info);
console.log(found);
// → [{ option: "size", mutable: true, wanted: 65536, actual: 1024 }]
```

<Returns type="CollectionDifference[]">

Список различий. Пустой, если коллекция совпадает с объявленным.

</Returns>

<Params>
<Param name="name" type="string" required>

Имя коллекции, для текста сообщений.

</Param>
<Param name="wanted" type="Readonly<Record<string, unknown>>" required>

Объявленные параметры.

</Param>
<Param name="info" type="CollectionInfo" required>

Описание с сервера из [`info`](#collectionmanagerinfo).

</Param>
</Params>

<FullType>

```ts
static differences(name: string, wanted: Plain, info: CollectionInfo): CollectionDifference[]
```

</FullType>

### CollectionManager.collMod

`collMod` строит команду `collMod` для сервера, которая применяет изменяемые различия. Метод только строит документ команды и не отправляет его: отправить нужно самому, например через `db.command`. Все переданные различия должны быть изменяемыми.

```ts twoslash
import { CollectionManager } from "@venloc/typemo";
// ---cut---
const command = CollectionManager.collMod(
  "ledger",
  { capped: true, size: 65_536, max: 100 },
  [{ option: "size", mutable: true, wanted: 65_536, actual: 1024 }],
);
console.log(command);
```

### CollectionManager.optionsOf, create и ensure

Эти три метода принимают [`SchemaSource`](#schemasource): модель (`connection.model(Account)`) или её `schema`. Для модели-наследника (дискриминатора) берётся схема корневой модели: коллекция у них общая.

- `optionsOf(source)` строит из схемы параметры для `createCollection` драйвера: `capped`, `size`, `max`, `timeseries`, `clusteredIndex`, `validator` с уровнем и действием, `collation`, `changeStreamPreAndPostImages`. Результат заморожен. Для схемы с `validator: true` это `{ validator: { $jsonSchema: … }, validationLevel: "strict", validationAction: "error" }`;
- `create(db, source)` делает то же, что [`Model.createCollection`](#modelcreatecollection), но не смотрит `autoCreate`: `true` — создана, `false` — уже была с этими параметрами;
- `ensure(db, source, options?)` делает то же, что [`Model.ensureCollection`](#modelensurecollection).

```ts twoslash
import { CollectionManager, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "ledger", capped: { size: 65_536, max: 100 } })
class LedgerEntry extends Entity {
  @Prop(() => String, { required: true }) note!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Ledger = client.connection.model(LedgerEntry);
const db = client.unsafeDriver().db("app");
// ---cut---
console.log(CollectionManager.optionsOf(Ledger));
// → { capped: true, size: 65536, max: 100 }

console.log(await CollectionManager.create(db, Ledger));
// → true
console.log(await CollectionManager.create(db, Ledger.schema));
// → false

console.log(await CollectionManager.ensure(db, Ledger, { dryRun: true }));
// → { result: "unchanged", differences: [] }
```

Если вместо модели передать что-то другое, метод бросает [`ConfigurationError`](../errors/configuration-errors.mdx#configurationerror): объект с похожей формой не подходит, потому что методам нужна настоящая скомпилированная схема.

```text
ConfigurationError: CollectionManager.optionsOf: a model (connection.model(Entity)) or its schema (model.schema) is expected, got object
```

## Когда не подходит

Если нужно привести в порядок все коллекции подключения сразу, используйте [`connection.syncAll`](../connection/connection.mdx#connectionsyncall): он вызывает `ensureCollection` для каждой модели и собирает сбои в отчёт. Индексы этими методами не создаются: для них есть [`syncIndexes`](./model-indexes.mdx#modelsyncindexes). Представления создаёт [`TypedView.ensure`](./typed-view.mdx#typedviewensure), а не `ensureCollection`.

Руководство с реальными задачами — [Создание коллекций](../../collections/create.mdx).
