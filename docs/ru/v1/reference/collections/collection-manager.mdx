Параметры коллекции задаются в [`@Schema`](../schemas/schema.mdx) и применяются при её создании. К ним относятся ограниченный размер (`capped`), временные ряды, кластерный индекс, серверный валидатор документов и правило сортировки строк. Эта страница описывает, как применить параметры и сравнить их с тем, что уже есть на сервере. Здесь методы модели `createCollection` и `ensureCollection`, статический класс `CollectionManager`, на котором они построены, и отчёт `EnsureCollectionReport`.

Если вы впервые настраиваете коллекции, начните с руководства [Создание коллекций](../../collections/create.mdx). Эта страница — справочник.

Typemo не молчит о расхождении. Повторный `createCollection` с другими параметрами сервер отклоняет ошибкой «уже существует», и многие библиотеки эту ошибку глотают. Изменённый параметр тогда просто не доходит до сервера. Typemo сравнивает параметры и либо подтверждает совпадение, либо называет, что именно отличается.

Примеры используют две модели — счёт с серверным валидатором и журнал проводок ограниченного размера.

```ts twoslash title="accounts/account.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts", validator: true })
export class Account extends Entity {
  @Prop(() => String, { required: true, minLength: 2 })
  title!: string;

  @Prop(() => Number, { min: 0 })
  balance?: number;
}

@Schema({ collection: "ledger", capped: { size: 65_536, max: 100 } })
export class LedgerEntry extends Entity {
  @Prop(() => String, { required: true })
  note!: string;
}
```

Результаты в комментариях получены на пустой базе, если рядом не сказано иное.

## Model.createCollection

`createCollection` создаёт коллекцию модели с параметрами из схемы и возвращает `true`, если создал. Берите его, когда коллекцию нужно создать явно и получить ошибку при расхождении, а не работать дальше с коллекцией, устроенной иначе, чем в схеме.

«Уже существует» здесь значит одно из двух. Если коллекция есть и параметры совпадают со схемой, метод возвращает `false`. Если параметры другие, он бросает [`CollectionOptionsError`](../errors/configuration-errors.mdx#collectionoptionserror) и существующую коллекцию не трогает. Чтобы её изменить, вызовите [`ensureCollection`](#modelensurecollection) с опцией `update`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts", validator: true })
class Account extends Entity {
  @Prop(() => String, { required: true, minLength: 2 }) title!: string;
  @Prop(() => Number, { min: 0 }) balance?: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.connection.model(Account);
// ---cut---
console.log(await Accounts.createCollection());
// → true
console.log(await Accounts.createCollection());
// → false
```

<Returns type="Promise<boolean>">

`true`, если этот вызов создал коллекцию, и `false`, если она уже была с теми же параметрами. При других параметрах вернётся не `false`, а [`CollectionOptionsError`](../errors/configuration-errors.mdx#collectionoptionserror) с полем `differences`.

</Returns>

Принимает ничего.

<FullType>

```ts
createCollection(): Promise<boolean>
```

</FullType>

### Коллекция уже есть с другими параметрами

Скажем, счета лежат в коллекции без валидатора. Её могла создать первая запись, пока в схеме ещё не было `validator`. Метод не станет молча считать такую коллекцию готовой.

```ts twoslash
import { CollectionOptionsError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts", validator: true })
class Account extends Entity {
  @Prop(() => String, { required: true, minLength: 2 }) title!: string;
  @Prop(() => Number, { min: 0 }) balance?: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.connection.model(Account);
await client.unsafeDriver().db("app").createCollection("accounts");
// ---cut---
try {
  await Accounts.createCollection();
} catch (error) {
  if (error instanceof CollectionOptionsError) {
    console.log(error.collection, error.differences.map((d) => [d.option, d.mutable]));
    // → "accounts" [["validator", true]]
  }
}
```

```text
CollectionOptionsError: collection "accounts": exists with other options (validator); run ensureCollection({ update: true }) to change them with collMod
```

### Схема с `autoCreate: false`

`autoCreate: false` в схеме говорит, что коллекцию создаёт кто-то другой — администратор, соседний сервис или миграция. Поэтому `createCollection` такой модели ничего не создаёт и бросает [`ConfigurationError`](../errors/configuration-errors.mdx#configurationerror). Иначе опция потеряла бы смысл.

```text
ConfigurationError: AuditLog.createCollection: the schema of AuditLog says autoCreate: false — Typemo does not create the collection "audit_logs"; create it where it is owned, or remove autoCreate: false
```

То же правило действует в [`connection.init`](../connection/connection.mdx#connectioninit) и [`connection.syncAll`](../connection/connection.mdx#connectionsyncall). Они пропускают шаг параметров коллекции у такой модели.

Если у схемы нет ни индексов, ни поисковых индексов, ей нечего создавать. Модель пропускается целиком, и отсутствие коллекции не ошибка, её создаёт владелец. Если индексы есть, коллекции ещё нет, а у схемы есть параметры, которые задаются только при создании, индекс создал бы коллекцию без них. Тогда `init` и `syncAll` бросают [`SyncError`](../errors/configuration-errors.mdx#syncerror) с той же ошибкой, что и у первой записи (она описана ниже).

[`ensureCollection`](#modelensurecollection) эту опцию не смотрит. Если вы вызвали его сами, коллекция создастся. На MongoDB 9.0 у модели с `autoCreate: false` он вернул `"created"`.

## Model.ensureCollection

`ensureCollection` приводит коллекцию к параметрам схемы и сообщает, что для этого понадобилось. Коллекции нет — он её создаёт. Коллекция есть и совпадает — не делает ничего. Отличается только тем, что сервер умеет менять на лету — меняет командой `collMod`, если задано `update: true`. Всё остальное ошибка. Метод идемпотентен, а по результату видно, была ли работа, поэтому он основной для деплоя.

По умолчанию `ensureCollection` **ничего не меняет** в существующей коллекции. Параметры работающей коллекции не должны меняться случайно, и любое различие без `update: true` — ошибка. Опция `dryRun` показывает, что случилось бы, и ничего не записывает.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "ledger", capped: { size: 65_536, max: 100 } })
class LedgerEntry extends Entity {
  @Prop(() => String, { required: true }) note!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Ledger = client.connection.model(LedgerEntry);
// ---cut---
const first = await Ledger.ensureCollection();
console.log(first.result);
// → "created"
const second = await Ledger.ensureCollection();
console.log(second.result);
// → "unchanged"
```

<Returns type="Promise<EnsureCollectionReport>">

Отчёт [`EnsureCollectionReport`](#ensurecollectionreport) с полем `result` (`"created"`, `"unchanged"` или `"updated"`) и списком `differences`. Для `"created"` и `"unchanged"` список пустой. При `dryRun: true` отчёт описывает то, что было бы сделано.

</Returns>

<Params>
<Param name="options.update" type="boolean" default="false">

Применяет командой `collMod` те различия, которые сервер умеет менять на месте (см. [что можно изменить](#что-можно-изменить-на-месте)). Без этой опции любое различие — [`CollectionOptionsError`](../errors/configuration-errors.mdx#collectionoptionserror).

</Param>
<Param name="options.dryRun" type="boolean" default="false">

Только сообщает. `result` и `differences` вернутся, сервер не изменится. Различие, которое `collMod` изменить не может, всё равно бросает ошибку, потому что его не исправить ни с `update`, ни без.

</Param>
</Params>

<FullType>

```ts
ensureCollection(options?: EnsureCollectionOptions): Promise<EnsureCollectionReport>
```

</FullType>

### Изменить параметр существующей коллекции

Скажем, журнал проводок создан с лимитом 1024 байта, а схема требует 65 536. Размер и число документов в capped-коллекции сервер менять умеет, поэтому со `update: true` хватит одной команды.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "ledger", capped: { size: 65_536, max: 100 } })
class LedgerEntry extends Entity {
  @Prop(() => String, { required: true }) note!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Ledger = client.connection.model(LedgerEntry);
await client.unsafeDriver().db("app").createCollection("ledger", { capped: true, size: 1024, max: 100 });
// ---cut---
const plan = await Ledger.ensureCollection({ dryRun: true });
console.log(plan.result, plan.differences);
// → "updated" [{ option: "size", mutable: true, wanted: 65536, actual: 1024 }]

const done = await Ledger.ensureCollection({ update: true });
console.log(done.result);
// → "updated"
console.log((await Ledger.ensureCollection()).result);
// → "unchanged"
```

Без `update: true` тот же вызов бросил бы ошибку со списком различий.

```text
CollectionOptionsError: collection "ledger": exists with other options (size); run ensureCollection({ update: true }) to change them with collMod
```

### Различие, которое изменить нельзя

Превратить обычную коллекцию в capped сервер не умеет, коллекцию нужно удалить и создать заново. `ensureCollection` коллекции сам не удаляет, поэтому бросает ошибку и с `update`, и без него.

```ts twoslash
import { CollectionOptionsError, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "ledger", capped: { size: 65_536, max: 100 } })
class LedgerEntry extends Entity {
  @Prop(() => String, { required: true }) note!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Ledger = client.connection.model(LedgerEntry);
await client.unsafeDriver().db("app").createCollection("ledger");
// ---cut---
try {
  await Ledger.ensureCollection({ update: true });
} catch (error) {
  if (error instanceof CollectionOptionsError) {
    console.log(error.differences.map((d) => [d.option, d.mutable]));
    // → [["capped", false]]
  }
}
```

```text
CollectionOptionsError: collection "ledger": exists with options MongoDB cannot change (capped): drop the collection and create it again
```

### Первая запись в коллекцию, которой ещё нет

Если коллекции нет, сервер создаёт её при первой записи и всегда обычной — без `capped`, временных рядов, кластерного индекса и правила сортировки. Эти четыре параметра задаются только при создании, поэтому потом их не исправить. Typemo не даёт сделать это по ошибке.

Проверку, что коллекция существует, делают первая вставка, пакетная запись, upsert и сохранение документа модели с такими параметрами. То же делают `createIndexes`, `syncIndexes` и `connection.init`. Если коллекции нет, вы получаете [`ConfigurationError`](../errors/configuration-errors.mdx#configurationerror), а в базе ничего не появляется.

```text
ConfigurationError: LedgerEntry.create: the collection "ledger" does not exist, and MongoDB would create it as a plain collection without the options of the schema that can only be given at creation (capped); create it first: await connection.init(), or await LedgerEntry.ensureCollection()
```

Проверка идёт один раз для модели. Найденную коллекцию Typemo запоминает, и следующие записи ничего не стоят. Обычное чтение и `updateOne` без `upsert` проверке не подвержены. Для модели с `autoCreate: false` в ту же ошибку добавлено пояснение — коллекцию должен создать её владелец с этими параметрами.

Валидатор и хранение образов документа проверка не охватывает, потому что `collMod` умеет их менять. Запись в несуществующую коллекцию со `validator: true` создаст обычную коллекцию без валидатора. [`ensureCollection`](#modelensurecollection) потом покажет это различие (`validator`, `mutable: true`) и исправит его с `update: true`.

### Представление под именем коллекции

Если под этим именем лежит представление (view), метод не станет работать с ним как с коллекцией.

```text
CollectionOptionsError: collection "ledger": exists as a view, not a collection: drop it or use another name
```

## CollectionManager

`CollectionManager` — статический класс, на котором построены `createCollection` и `ensureCollection`. Он пригодится там, где у вас есть база драйвера, но нет удобного места для вызова метода модели. Например, в служебном скрипте, проверке окружения или собственном инструменте деплоя.

Методам, которым нужна схема (`optionsOf`, `create`, `ensure`), передают **модель** или её `schema` — [`SchemaSource`](#schemasource). Остальные три (`info`, `differences`, `collMod`) работают с обычными значениями.

```ts twoslash
import { CollectionManager, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "accounts", validator: true })
class Account extends Entity {
  @Prop(() => String, { required: true, minLength: 2 }) title!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.connection.model(Account);
// ---cut---
const wanted = CollectionManager.optionsOf(Accounts);
console.log(Object.keys(wanted));
// → ["validator", "validationLevel", "validationAction"]
```

### CollectionManager.info

`info` читает с сервера описание одной коллекции — то, что `listCollections` возвращает для этого имени. С ним в служебных скриптах можно посмотреть тип и параметры коллекции или представления без ручного вызова драйвера. Если коллекции нет, вернётся `undefined`.

```ts twoslash
import { CollectionManager, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const db = client.unsafeDriver().db("app");
await db.createCollection("ledger", { capped: true, size: 1024, max: 100 });
// ---cut---
const info = await CollectionManager.info(db, "ledger");
console.log(info?.name, info?.type, info?.options);
// → "ledger" "collection" { capped: true, size: 1024, max: 100 }

console.log(await CollectionManager.info(db, "missing"));
// → undefined
```

<Returns type="Promise<CollectionInfo | undefined>">

Запись `listCollections` — [`CollectionInfo`](#collectioninfo) с полями `name`, `type` (`"collection"`, `"view"` или `"timeseries"`) и `options`, то есть параметры, с которыми коллекция создана. Если коллекции нет, `undefined`.

</Returns>

<Params>
<Param name="db" type="Db" required>

База драйвера `mongodb`. Получить её можно через [`client.unsafeDriver`](../connection/typemo-client.mdx#clientunsafedriver).

</Param>
<Param name="name" type="string" required>

Имя коллекции.

</Param>
</Params>

<FullType>

```ts
static info(db: Db, name: string): Promise<CollectionInfo | undefined>
```

</FullType>

Ошибка драйвера приходит как ошибка Typemo (см. [`ServerError`](../errors/server-errors.mdx#servererror)).

### CollectionManager.differences

`differences` сравнивает объявленные параметры коллекции с сохранёнными на сервере и возвращает список различий. Сначала метод проверяет **вид** коллекции. Если вместо коллекции лежит представление или вместо временного ряда обычная коллекция, он сразу бросает [`CollectionOptionsError`](../errors/configuration-errors.mdx#collectionoptionserror), а не возвращает список.

Объявленные параметры — обычный объект в форме, которую принимает `createCollection` драйвера, например `{ capped: true, size: 65_536, max: 100 }`. Из схемы такой объект строит [`optionsOf`](#collectionmanageroptionsof-create-и-ensure). В примере он записан вручную, чтобы было видно, что именно сравнивается.

```ts twoslash
import { CollectionManager, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const db = client.unsafeDriver().db("app");
await db.createCollection("ledger", { capped: true, size: 1024, max: 100 });
const info = await CollectionManager.info(db, "ledger");
if (info === undefined) throw new Error("no such collection");
// ---cut---
const found = CollectionManager.differences("ledger", { capped: true, size: 65_536, max: 100 }, info);
console.log(found);
// → [{ option: "size", mutable: true, wanted: 65536, actual: 1024 }]
```

<Returns type="CollectionDifference[]">

Список различий. Если коллекция совпадает с объявленным, он пустой.

</Returns>

<Params>
<Param name="name" type="string" required>

Имя коллекции, нужно для текста сообщений.

</Param>
<Param name="wanted" type="Readonly<Record<string, unknown>>" required>

Объявленные параметры.

</Param>
<Param name="info" type="CollectionInfo" required>

Описание с сервера из [`info`](#collectionmanagerinfo).

</Param>
</Params>

<FullType>

```ts
static differences(name: string, wanted: Plain, info: CollectionInfo): CollectionDifference[]
```

</FullType>

### CollectionManager.collMod

`collMod` строит для сервера команду `collMod`, которая применяет изменяемые различия. Метод только собирает документ команды и ничего не отправляет. Отправьте его сами, например через `db.command`. Все переданные различия должны быть изменяемыми.

```ts twoslash
import { CollectionManager } from "@venloc/typemo";
// ---cut---
const command = CollectionManager.collMod(
  "ledger",
  { capped: true, size: 65_536, max: 100 },
  [{ option: "size", mutable: true, wanted: 65_536, actual: 1024 }],
);
console.log(command);
// → { collMod: "ledger", cappedSize: 65536 }
```

<Returns type="Document">

Документ команды для `db.command(...)`.

</Returns>

<Params>
<Param name="name" type="string" required>

### CollectionManager.optionsOf, create и ensure

Эти три метода принимают [`SchemaSource`](#schemasource) — модель (`connection.model(Account)`) или её `schema`. Для модели-наследника (дискриминатора) берётся схема корневой модели, потому что коллекция у них общая.

- `optionsOf(source)` строит из схемы параметры для `createCollection` драйвера. Это `capped`, `size`, `max`, `timeseries`, `clusteredIndex`, `validator` с уровнем и действием, `collation` и `changeStreamPreAndPostImages`. Результат заморожен. Для схемы с `validator: true` он выглядит так — `{ validator: { $jsonSchema: … }, validationLevel: "strict", validationAction: "error" }`.
- `create(db, source)` делает то же, что [`Model.createCollection`](#modelcreatecollection), но `autoCreate` не смотрит. `true` значит, что коллекция создана, `false` — что она уже была с этими параметрами.
- `ensure(db, source, options?)` делает то же, что [`Model.ensureCollection`](#modelensurecollection).

```ts twoslash
import { CollectionManager, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "ledger", capped: { size: 65_536, max: 100 } })
class LedgerEntry extends Entity {
  @Prop(() => String, { required: true }) note!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Ledger = client.connection.model(LedgerEntry);
const db = client.unsafeDriver().db("app");
// ---cut---
console.log(CollectionManager.optionsOf(Ledger));
// → { capped: true, size: 65536, max: 100 }

console.log(await CollectionManager.create(db, Ledger));
// → true
console.log(await CollectionManager.create(db, Ledger.schema));
// → false

console.log(await CollectionManager.ensure(db, Ledger, { dryRun: true }));
// → { result: "unchanged", differences: [] }
```

Если вместо модели передать что-то другое, метод бросает [`ConfigurationError`](../errors/configuration-errors.mdx#configurationerror). Объект похожей формы не подойдёт, методам нужна настоящая скомпилированная схема.

```text
ConfigurationError: CollectionManager.optionsOf: a model (connection.model(Entity)) or its schema (model.schema) is expected, got object
```

## Когда не подходит

Чтобы привести в порядок все коллекции подключения сразу, возьмите [`connection.syncAll`](../connection/connection.mdx#connectionsyncall). Он вызывает `ensureCollection` для каждой модели и собирает сбои в отчёт. Индексы эти методы не создают, для них есть [`syncIndexes`](./model-indexes.mdx#modelsyncindexes). Представления создаёт [`TypedView.ensure`](./typed-view.mdx#typedviewensure), а не `ensureCollection`.

Руководство с реальными задачами — [Создание коллекций](../../collections/create.mdx).
