Если готовых пакетов [OpenTelemetry](./opentelemetry.mdx) и [Sentry](./sentry.mdx) мало, адаптер для своей системы (метрики в Prometheus, журнал в файл, внутренний трекер) пишется на тех же [событиях операций](./events.mdx), что и они. Адаптер — это класс, который регистрирует подписчика через `instrument`, сам хранит своё состояние и убирает его при отписке. Ядру от адаптера ничего больше не нужно, а ядро при этом не знает ни про вашу систему, ни про чужую.

## Что предполагается

Вы знаете, как устроены подписчик и события, из руководства [События операций](./events.mdx). Примеры используют модель счёта из него.

## Быстрый путь

Минимальный адаптер принимает цель (клиент или `Typemo`) и возвращает подписку: она снимается вызовом `unsubscribe()` или выходом из области `using`. Ниже он считает операции и ошибки по модели и операции, а среднее время получается из суммы:

```ts twoslash title="monitoring/operation-stats.ts"
import type { InstrumentationSubscriber, Subscription } from "@venloc/typemo";

interface InstrumentTarget {
  readonly instrument: (subscriber: InstrumentationSubscriber) => Subscription;
}

interface Stat {
  count: number;
  errors: number;
  totalMS: number;
}

export class OperationStats {
  readonly #stats = new Map<string, Stat>();

  static instrument(target: InstrumentTarget): { stats: OperationStats; subscription: Subscription } {
    const stats = new OperationStats();
    const subscription = target.instrument({
      steps: false, // шаги не нужны: ядро их не строит
      handle: (event) => {
        if (event.type !== "operation.end" && event.type !== "operation.error") return;
        const key = `${event.model ?? `database ${event.database}`}.${event.operation}`;
        const stat = stats.#stats.get(key) ?? { count: 0, errors: 0, totalMS: 0 };
        stat.count += 1;
        stat.totalMS += event.durationMS;
        if (event.type === "operation.error") stat.errors += 1;
        stats.#stats.set(key, stat);
      },
    });
    return { stats, subscription };
  }

  snapshot(): Record<string, Stat> {
    return Object.fromEntries(this.#stats);
  }
}
```

Ключ собирается из модели и операции. У операции уровня базы (`connection.aggregate`) модели нет: `event.model` равно `null`, поэтому в ключе вместо неё стоит база. Подключение и результат запуска на настоящей базе: одна вставка, три `find` (один из них с `.orFail()` на пустом результате):

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
import type { InstrumentationSubscriber, Subscription } from "@venloc/typemo";

@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
declare const OperationStats: {
  instrument(target: { instrument: (s: InstrumentationSubscriber) => Subscription }): {
    stats: { snapshot(): Record<string, { count: number; errors: number; totalMS: number }> };
    subscription: Subscription;
  };
};
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank" });
const Accounts = client.db().model(Account);
// ---cut---
const { stats, subscription } = OperationStats.instrument(client);

await Accounts.create({ title: "Main", balance: 100 });
await Accounts.find({}).plain();
await Accounts.find({}).plain();
await Accounts.find({ title: "none" }).orFail().catch(() => undefined);

const snapshot = stats.snapshot();
// snapshot["Account.insertOne"].count → 1
// snapshot["Account.find"].count → 3, snapshot["Account.find"].errors → 1

subscription.unsubscribe();
```

Остальная страница разбирает, что учесть, когда адаптер уходит дальше счётчика.

## Выбрать события

Ситуация: адаптеру нужны не все события. Чем меньше он просит, тем меньше работы у ядра: шаги строятся, только если их хочет хоть один подписчик, команды драйвера и события пула включаются флагами `driverCommands` и `poolEvents`. Скажите ядру, что нужно, и обрабатывайте только это:

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank", monitorCommands: true });
// ---cut---
client.instrument({
  steps: false,
  poolEvents: true,
  driverCommands: false,
  handle: (event) => {
    if (event.type === "driver.pool") console.log(event.name, event.address);
  },
});
```

`steps: false` у подписчика означает, что он не получает шаги; если хотя бы один другой подписчик их просил, шаги строятся, но этому не доставляются: запуск с `steps: false` дал только `operation.start` и `operation.end`.

## Хранить состояние операции между событиями

Ситуация: спан или замер открывается на `operation.start`, а закрывается на `operation.end` или `operation.error`. Ключом служит `operationId`: он уникален в процессе, а у вложенных запросов подгрузки связей в `parentId` номер внешней операции.

```ts twoslash title="monitoring/open-operations.ts"
import type { InstrumentationSubscriber } from "@venloc/typemo";

const open = new Map<number, { startedAt: number; parentId: number | undefined }>();

export const timer: InstrumentationSubscriber = {
  handle: (event) => {
    if (event.type === "operation.start") {
      open.set(event.operationId, { startedAt: event.timestamp, parentId: event.parentId });
    } else if (event.type === "operation.end" || event.type === "operation.error") {
      open.delete(event.operationId); // не забудьте: иначе карта растёт
    }
  },
};
```

Событие `operation.start` приходит самым первым, до приведения типов, проверки и `pre`-хуков. Поэтому событие ошибки приходит и у операции, которая не дошла до драйвера (например, упала на приведении типов), и состояние нужно закрывать в обеих ветках. При отписке закройте то, что осталось открытым: адаптер OpenTelemetry для этого при `unsubscribe()` заканчивает все незавершённые спаны.

## Сделать свой контекст активным: `wrap`

Ситуация: система трассировки должна знать, что хук, вложенный запрос или команда драйвера относятся к этой операции. Для этого подписчик задаёт `wrap`: ядро выполняет операцию внутри неё, и вы устанавливаете в это время свой контекст.

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
import { AsyncLocalStorage } from "node:async_hooks";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank" });
// ---cut---
const current = new AsyncLocalStorage<number>();

client.instrument({
  handle: () => {},
  wrap: (operation, run) => current.run(operation.operationId, run),
});
```

Договор: вызвать `run` ровно один раз и вернуть (или дождаться) то, что она вернёт. Результат операции определяется `run`, что бы ни вернула `wrap`. Если `wrap` бросила исключение до `run` или вовсе не вызвала её, это попадёт в `console.error` как ошибка подписчика, а операция всё равно выполнится. Несколько `wrap` вкладываются в порядке регистрации. Для курсора `wrap` охватывает только открытие. Подробнее — в справочнике [`InstrumentationSubscriber`](../reference/observability/events.mdx#instrumentationsubscriber).

## Не менять политики ядра

Адаптер не может изменить операцию или обойти маскировку: он получает событие уже в том виде, который разрешён его `sensitive`, `includeTenant` и пометками схемы. Если вам нужны реальные значения, вы явно выбираете `sensitive: "show"`, и это ваше решение об утечке. Пометки `sensitive` и скрытые поля этот выбор не отменяет.

Если адаптеру не хватает данных или точки расширения, не обходите ядро: сообщите, чего не хватает. Ядро получает общий механизм (событие, опцию, хук), а не особый случай под один продукт.

## Как выбрать

Задайте вопрос: **мне нужно наблюдать или менять?** Наблюдать, то есть считать, журналировать, отправлять, — подписчик. Менять операцию (условие, значения, отказ) — [хук](../hooks/operation-hooks.mdx). Если вы хотите оба, зарегистрируйте и то и другое: они не мешают друг другу.

## Когда это не нужно

Для трассировки и Sentry свои адаптеры не нужны: есть [`@venloc/typemo-opentelemetry`](../reference/observability/opentelemetry.mdx) и [`@venloc/typemo-sentry`](../reference/observability/sentry.mdx). Если хватает журнала запросов в разработке, достаточно десятка строк подписчика из [быстрого пути руководства о событиях](./events.mdx#быстрый-путь).

## Частые ошибки

### Адаптер копит память

Карта открытых операций не очищается, если пропустить `operation.error`. Симптом: рост памяти на приложении с ошибками. Закрывайте состояние в обеих ветках, как в примере выше.

### Тяжёлая работа в `handle`

`handle` выполняется на пути операции: сетевой вызов внутри него замедлит каждый запрос. Копите данные в памяти и отправляйте пачками из таймера.

### Чтение реальных значений без `sensitive: "show"`

В `summary` при умолчании только `"?"`. Если вы получаете `"?"` там, где ждёте значение, это ожидаемо: выберите `sensitive: "show"` осознанно или пометьте свою функцию через `{ mask }`.
