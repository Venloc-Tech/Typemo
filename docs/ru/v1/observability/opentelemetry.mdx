Пакет `@venloc/typemo-opentelemetry` превращает каждую операцию Typemo в **спан**, то есть отрезок трассы с именем, длительностью и атрибутами. Ещё он считает метрики длительности и пула соединений. В трассе запроса сразу видно, какая операция какой модели заняла время и чем закончилась, и ручные обёртки для этого не нужны. Пакет отдельный, ядро про OpenTelemetry ничего не знает.

Если вы впервые работаете с OpenTelemetry, запомните главное. SDK, экспортёр и менеджер контекста выбирает само приложение, а адаптер только создаёт спаны через `@opentelemetry/api`. Подробности API — в [справочнике](../reference/observability/opentelemetry.mdx).

## Что понадобится [#prerequisites]

Настроенный в приложении SDK OpenTelemetry — провайдер трасс, а для метрик ещё и провайдер метрик. Клиент создан как в [быстром старте](../getting-started/quick-start.mdx), а примеры используют модель счёта из банковского приложения. Сборка документации не подключает пакеты OpenTelemetry, поэтому блоки кода здесь не компилируются. Их работа проверена запуском.

## Быстрый путь [#quick-start]

```package-install
@venloc/typemo-opentelemetry @opentelemetry/api
```

```ts title="telemetry.ts"
import { TypemoClient } from "@venloc/typemo";
import { TypemoOpenTelemetry } from "@venloc/typemo-opentelemetry";

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank" });
const subscription = TypemoOpenTelemetry.instrument(client);
```

Теперь каждая операция даёт спан — `Typemo.find (Account)`, `Typemo.insertOne (Account)` и так далее. Ниже разберём задачи по порядку.

## Чтобы спаны вкладывались друг в друга [#nested-spans]

Спаны есть, но ни у одного нет родителя. Так бывает, когда в процессе нет **менеджера контекста** — объекта, который переносит «текущий спан» через `await`. Адаптер делает спан операции активным на время операции. Спаны ваших хуков и подзапросов подгрузки связей вкладываются в него, но только если менеджер зарегистрирован.

```ts title="telemetry.ts"
import { context, trace } from "@opentelemetry/api";
import { AsyncLocalStorageContextManager } from "@opentelemetry/context-async-hooks";
import { BasicTracerProvider, BatchSpanProcessor } from "@opentelemetry/sdk-trace-base";

context.setGlobalContextManager(new AsyncLocalStorageContextManager().enable());
trace.setGlobalTracerProvider(new BasicTracerProvider({ spanProcessors: [new BatchSpanProcessor(exporter)] }));
```

Здесь `exporter` — ваш экспортёр. Этот менеджер на Bun сохранил контекст через `await`, внутри транзакции и при её повторе.

Запрос ленивый. Он берёт активный контекст в момент выполнения, то есть на `await`. Поэтому `context.with(ctx, () => Accounts.find())` без `await` выполнит запрос уже вне `ctx`. Пишите `context.with(ctx, async () => await Accounts.find())`.

## Что вы увидите в трассе [#trace-view]

Вот какие спаны дали `create`, `find`, повторная вставка и транзакция с `stepSpans: true` и `commandSpans: true`.

```ts
// Typemo.transaction                      (INTERNAL, typemo.transaction.attempts: 1)
//   └─ Typemo.updateOne (Account)         (CLIENT, typemo.transaction: true)
//        ├─ Typemo.step cast              (INTERNAL)
//        ├─ Typemo.step validate          (INTERNAL)
//        ├─ update                        (CLIENT, команда драйвера)
//        └─ Typemo.step populate          (INTERNAL)
// Typemo.find (Account)                   (CLIENT, db.query.summary: "find accounts")
// Typemo.find.cursor (Account)            (курсор; событие cursor.batch)
// Typemo.insertOne (Account)              (CLIENT, статус ERROR, error.type: "DuplicateKeyError")
// Typemo.aggregate (database bank)        (CLIENT, connection.aggregate: без модели и коллекции)
```

Конвенция OpenTelemetry советует называть спан вроде `find accounts`, но здесь имя другое — `Typemo.find (Account)`. Так сразу видно, что спан от ODM и какой модели он касается. Коллекция лежит в `db.collection.name`. Полные таблицы атрибутов и метрик — в [справочнике](../reference/observability/opentelemetry.mdx#attributes).

## Найти шаг, на который ушло время [#slow-step]

Спаны шагов по умолчанию выключены, потому что для них ядру приходится строить дополнительные события. Включите `stepSpans`, когда нужно понять, что заняло время внутри операции — приведение типов, проверка, ваши хуки или подгрузка связей.

```ts
TypemoOpenTelemetry.instrument(client, { stepSpans: true });
```

Появятся дочерние спаны `Typemo.step cast`, `Typemo.step validate`, `Typemo.step populate`. Спан шага создаётся, когда шаг уже закончился, а начало ему сдвигают назад на длительность шага.

## Спаны команд драйвера [#command-spans]

Иногда нужно знать, какой сервер выполнил команду и сколько она заняла. Для этого клиент должен быть создан с `monitorCommands: true`, иначе регистрация бросит `ConfigurationError: TypemoClient "default": driver command events need the client option monitorCommands: true`.

```ts
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank", monitorCommands: true });
TypemoOpenTelemetry.instrument(client, { commandSpans: true });
```

Спан команды называется по команде (`find`, `insert`) и вложен в спан операции. Его `server.address` и `server.port` указывают на сервер, который на самом деле выполнил команду, а не просто на первый хост строки подключения. Есть у него и `db.collection.name`.

## Метрики пула соединений [#pool-metrics]

`poolMetrics: true` включает метрики `db.client.connection.count`, `pending_requests`, `wait_time`, `use_time` и другие. Метрика `db.client.operation.duration` считается всегда. Пул, созданный до подписки адаптера, в лимитах не учитывается — его создания адаптер не видел.

## Операции уровня базы [#database-operations]

Бывает, что агрегация идёт над всей базой — через [`connection.aggregate`](../reference/connection/connection.mdx#connection.aggregate) со стадиями вроде `$documents`, `$currentOp` или `$listLocalSessions`. Модели у такой операции нет, поэтому адаптер называет спан по базе, `Typemo.aggregate (database bank)`. Атрибутов `typemo.model` и `db.collection.name` у него нет, пустых значений адаптер не пишет.

Исключение — `Pipeline.sessions()`. Он читает коллекцию `config.system.sessions`, и его спан `Typemo.aggregate (database config)` несёт `db.namespace: "config"` и `db.collection.name: "system.sessions"`. Подробнее — в руководстве [Запросы уровня базы](../aggregation/database-level.mdx).

## Не отдать данные пользователей [#hide-user-data]

Трассы обычно уходят во внешний сервис. Атрибут `db.query.text` содержит форму запроса, и по умолчанию все значения в нём заменены на `"?"` — `{"filter":{"balance":{"$gt":"?"},"iban":"?"}}`. Опция `sensitive` работает так же, как у [подписчика ядра](../reference/observability/events.mdx#subscriber-sensitive), и действует в том числе на исключение, записанное в спан. Поля, помеченные `sensitive` в схеме, остаются замаскированными даже при `"show"`. Тенант попадает в `typemo.tenant` спана операции только с `includeTenant: true`.

```ts
TypemoOpenTelemetry.instrument(client, { sensitive: "mask", includeTenant: false });
```

## Как выбрать [#how-to-choose]

Спросите себя, **что вы хотите увидеть**.

- **Дерево вызовов и время внутри операции** — включите `stepSpans`.
- **Какие команды и на какие серверы ушли** — `commandSpans`.
- **Состояние пула** — `poolMetrics`.
- **Только базовую картину** — оставьте умолчания, они дешевле всего.

## Когда это не нужно [#when-not-to-use]

Если нужны только ошибки в трекере, хватит [Sentry](./sentry.mdx). Для своей системы напишите подписчика, как в [Своей интеграции](./custom-integration.mdx).

Не включайте адаптер вместе с `@opentelemetry/instrumentation-mongodb`. Тот патчит драйвер и создаёт свой спан на каждую команду, и команды окажутся в трассе дважды. Если нужны спаны команд, берите `commandSpans`.

## Если что-то пошло не так [#troubleshooting]

**Два спана на одну операцию.** Адаптер зарегистрирован дважды, например на клиенте и на `Typemo`. Регистрируйте его один раз на каждую цель.

**У спанов нет родителя.** Не зарегистрирован менеджер контекста, как это сделать, показано выше.

**Спаны команд не появляются.** `commandSpans: true` требует у клиента `monitorCommands: true`, без него регистрация падает с `ConfigurationError`. Для команд, которые Typemo не отправлял, спаны не создаются.
