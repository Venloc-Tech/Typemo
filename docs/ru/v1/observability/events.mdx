Каждая операция Typemo сообщает о себе **событиями** — началась, закончилась, упала. Подпишитесь на них функцией, и у вас будут журнал запросов, замеры времени и список ошибок без обёрток вокруг каждого вызова. Пока подписчиков нет, это ничего не стоит. Ядро не строит события, которых никто не ждёт.

Событие — это обычный объект с полем `type`. Подписчик — объект с функцией `handle`, которую вызывает ядро. На тех же событиях построены готовые пакеты [OpenTelemetry](./opentelemetry.mdx) и [Sentry](./sentry.mdx). Если нужна другая система, читайте [Свою интеграцию](./custom-integration.mdx).

## Что понадобится

Клиент из [быстрого старта](../getting-started/quick-start.mdx) и модель банковского счёта. В коллекции `accounts` лежит один счёт `{ title: "Main", balance: 100 }`.

```ts twoslash title="accounts/account.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Number, { required: true })
  balance!: number;
}
```

## Быстрый путь

Подпишитесь на клиент и обработайте нужный тип события. По полю `type` TypeScript сам поймёт, какой формы событие.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";

@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank" });
const Accounts = client.db().model(Account);
// ---cut---
const subscription = client.instrument({
  handle: (event) => {
    if (event.type === "operation.end") {
      console.log(`${event.model}.${event.operation}: ${event.documentCount} шт.`);
    }
  },
});

await Accounts.find({ balance: { $gt: 50 } }).plain();
// → "Account.find: 1 шт."

subscription.unsubscribe();
```

Чтобы слушать все клиенты процесса, вызовите [`Typemo.instrument`](../reference/connection/typemo.mdx#typemoinstrument) вместо `client.instrument`. Ниже разберём типичные задачи.

## Найти медленные операции

Приложение стало отвечать дольше, и непонятно, какой запрос виноват. Событие [`operation.end`](../reference/observability/events.mdx#operationendevent) несёт длительность в миллисекундах, а модель и имя операции есть в общей части всех событий. У операции уровня базы (о ней ниже) модели нет, поэтому в подписи вместо неё подставляется база.

```ts twoslash title="monitoring/slow-operations.ts"
import { TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank" });
// ---cut---
const SLOW_MS = 100;

client.instrument({
  handle: (event) => {
    if (event.type === "operation.end" && event.durationMS > SLOW_MS) {
      console.warn(`медленно: ${event.model ?? event.database}.${event.operation}, ${Math.round(event.durationMS)} мс`);
    }
  },
});
```

`durationMS` — это время от начала операции до конца, вместе с приведением типов, вашими хуками и ожиданием базы. Чтобы понять, куда оно ушло, подпишитесь ещё и на шаги. [`steps`](../reference/observability/events.mdx#instrumentationsubscriber) включены по умолчанию, и событие `operation.step` называет шаг и его длительность. Для `find` модели с хуками `@Pre` и `@Post` шаги пришли в таком порядке — `cast`, `validate`, `hooksPre`, `populate`, `hooksPost`.

## Записать упавшие операции

Хочется знать, какие операции падают и почему, но не оборачивать каждый вызов в `try`. Событие [`operation.error`](../reference/observability/events.mdx#operationerrorevent) приходит вместо `operation.end` и называет шаг, на котором операция упала, и вид сбоя.

```ts twoslash title="monitoring/errors.ts"
import { TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank" });
// ---cut---
client.instrument({
  handle: (event) => {
    if (event.type === "operation.error") {
      const { kind, name, retryable } = event.classification;
      console.error(`${event.operation}: ${name} (${kind}), шаг ${event.failedStep}, повтор: ${retryable}`);
    }
  },
});
```

`find(...).orFail()` на пустом результате вывел `find: DocumentNotFoundError (not-found), шаг postProcess, повтор: false`. Классификация даёт `kind` (`cast`, `validation`, `duplicate-key`, `timeout`, `connection`…), а `retryable` подсказывает, есть ли смысл повторять операцию. Событие приходит, даже если вызывающий код сам ловит ошибку, так что подписчик видит всё, что упало.

Учтите, что это событие не заменяет обработку ошибок. Вызывающий код по-прежнему получает исключение, а подписчик лишь наблюдает. Как обрабатывать ошибки, рассказано в [Обработке ошибок](../errors/handling.mdx).

## Увидеть транзакции и курсоры

Иногда интересна не одна операция, а вся транзакция или выгрузка курсором. Транзакция даёт событие `transaction.start`, потом `transaction.commit` или `transaction.abort`, а между ними при повторе — `transaction.retry`. У операций внутри неё в `transactionId` тот же номер.

```ts twoslash title="monitoring/transactions.ts"
import { TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank" });
// ---cut---
client.instrument({
  handle: (event) => {
    if (event.type === "transaction.retry") console.warn(`повтор транзакции ${event.transactionId}, попытка ${event.attempt}`);
    if (event.type === "transaction.abort") console.error(`откат транзакции ${event.transactionId}`);
  },
});
```

Транзакция, упавшая с ошибкой, дала пару `transaction.start` и `transaction.abort` с исходной ошибкой и длительностью. Курсор шлёт `cursor.batch` на каждую пачку. Для коллекции из двух документов пришла одна пачка `{ batch: 0, size: 2 }`, а за ней `operation.end` с `mode: "cursor"` и `documentCount: 2`.

## Операции уровня базы

Бывает, что агрегация идёт не над коллекцией модели, а над всей базой — через [`connection.aggregate`](../reference/connection/connection.mdx#connectionaggregate) со стадиями вроде `$documents`, `$currentOp` или `$listLocalSessions`. Модели у такой операции нет. В событии `model` равно `null`, `collection` тоже `null` (у `Pipeline.sessions()` это `"system.sessions"`), `schema` — `null`, а база названа в `database`. Если подписчик собирает подпись из `model`, ему придётся учесть `null`, и компилятор это потребует.

```ts twoslash title="monitoring/database-level.ts"
import { Pipeline, TypemoClient } from "@venloc/typemo";
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank" });
// ---cut---
client.instrument({
  handle: (event) => {
    if (event.type === "operation.end") {
      console.log(`${event.model ?? `database ${event.database}`}: ${event.operation}`);
    }
  },
});

await client.connection.aggregate(Pipeline.database().documents([{ n: 1 }]).plan());
// → "database bank: aggregate"
```

В остальном события у такой операции обычные — `operation.start`, шаги, команда драйвера `aggregate` (если вы просили команды) и `operation.end`. Подробнее — в руководстве [Запросы уровня базы](../aggregation/database-level.mdx).

## Видеть команды драйвера и пул соединений

Иногда событий операций мало и нужно знать, на какой сервер ушла команда и сколько соединений занято. Эти события дороже, поэтому по умолчанию они выключены. Включите их в подписчике — `driverCommands` для команд и `poolEvents` для пула. Для команд драйвера клиент должен быть создан с `monitorCommands: true`.

```ts twoslash title="monitoring/driver.ts"
import { TypemoClient } from "@venloc/typemo";
// ---cut---
const client = await TypemoClient.connect("mongodb://localhost:27017", {
  dbName: "bank",
  monitorCommands: true,
});

client.instrument({
  driverCommands: true,
  poolEvents: true,
  handle: (event) => {
    if (event.type === "driver.command.succeeded") {
      console.log(`${event.commandName} на ${event.address}: ${event.durationMS} мс`);
    }
    if (event.type === "driver.pool") console.log(event.name);
  },
});
```

Одна операция `find` дала события `driver.pool` — `connectionCheckOutStarted`, `connectionCheckedOut` и `connectionCheckedIn`. Команда `find` связана с операцией через `operationId`. Если команду отправил не Typemo (рукопожатие драйвера или ваш код с драйвером напрямую), она придёт с `operationId: undefined`.

## Не отдать данные пользователей

События уходят в логи, трассировку, сторонние системы, а в фильтрах лежат имена, адреса почты, номера счетов. Поэтому по умолчанию (`sensitive: "mask"`) ядро оставляет в событии только форму запроса. Ключи и операторы на месте, а значения заменены на `"?"`.

```ts twoslash title="monitoring/masking.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";

@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => String, { sensitive: "mask" }) iban?: string;
}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank" });
const Accounts = client.db().model(Account);
// ---cut---
client.instrument({
  handle: (event) => {
    if (event.type === "operation.start") console.log(JSON.stringify(event.summary.filter));
  },
});

await Accounts.find({ balance: { $gt: 50 }, iban: "DE00" }).plain();
// → {"balance":{"$gt":"?"},"iban":"?"}
```

Если для отладки нужны настоящие значения, выберите `sensitive: "show"`, и `balance` придёт как `{"$gt":50}`. Но `iban` останется `"?"`. Поле помечено `sensitive` в схеме, и подписчик не может эту пометку отменить. Так значения секретных полей не попадут ни в один подписчик, в том числе чужой. Режимы `"hide"` (все непомеченные условия становятся `"[hidden]"`) и `{ mask }` (своя функция) описаны в справочнике [`SubscriberSensitive`](../reference/observability/events.mdx#subscribersensitive). Как помечать поля, рассказано в руководстве [Скрытые и чувствительные поля](../schemas/hidden-and-sensitive.mdx).

Ошибка в событии тоже маскируется. `CastError` для `balance: "abc"` пришёл вызвавшему коду с текстом `Cast to number failed at path "$set.balance" for "abc" (string): expected a number [type]`, а подписчику — с `for "?"`.

## Как выбрать

Спросите себя, **кто должен видеть эти события**.

- **Всё приложение**, включая библиотеки со своими клиентами, — берите [`Typemo.instrument`](../reference/connection/typemo.mdx#typemoinstrument), один вызов при старте процесса.
- **Один клиент**, например отдельная база аналитики, — берите [`client.instrument`](../reference/connection/typemo-client.mdx#clientinstrument). Тогда чужой код в ваш журнал не попадёт.

Подробнее о выборе уровня — в руководстве [Несколько клиентов и расширения](../connection/clients-and-extensions.mdx).

Если подписчик нужен ненадолго, для теста или разовой диагностики, заведите его через `using` — `using subscription = client.instrument(...)`. Подписка снимется на выходе из блока. Внутри блока `handle` получал события, а операция после блока — уже нет.

## Когда это не нужно

Нужны трассы, а не журнал — не пишите подписчика, а подключите [`@venloc/typemo-opentelemetry`](../reference/observability/opentelemetry.mdx). Нужны ошибки в трекере — подключите [`@venloc/typemo-sentry`](../reference/observability/sentry.mdx). А если нужно изменить операцию, добавить условие или отклонить запись, подписчик не поможет, он только наблюдает. Для этого есть [хуки](../hooks/operation-hooks.mdx).

## Если что-то пошло не так

**Регистрация падает, потому что нужны события команд.**

```ts twoslash
import { TypemoClient } from "@venloc/typemo";
// клиент без monitorCommands
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank" });
// ---cut---
client.instrument({ handle: () => {}, driverCommands: true });
// во время работы: ConfigurationError
```

Компилятор такой код пропустит, но клиент без `monitorCommands: true` не может отдавать события команд, и во время работы будет `ConfigurationError: TypemoClient "default": driver command events need the client option monitorCommands: true`. Создайте клиент с `monitorCommands: true`, как описано в [опциях клиента](../reference/connection/typemo-client.mdx#опции-клиента).

**`handle` бросил исключение.** Операцию это не ломает. Ядро ловит исключение и пишет в `console.error` строку `[typemo] an instrumentation subscriber threw on "operation.start":` вместе с ошибкой. Даже с подписчиком, который бросает всегда, `find` вернул документы. Но бросать на каждое событие дорого, поэтому оберните тело `handle` в `try` и не выпускайте из него исключений.

**Событие целиком уходит в `JSON.stringify`.** В каждом событии операции есть `event.schema` — ссылка на описание схемы модели. Она не копируется и не рассчитана на сериализацию. Берите только нужные поля — `event.operation`, `event.model`, `event.durationMS`, `event.summary`.

**Неверный `sensitive`.** `client.instrument({ handle, sensitive: "x" })` бросает `ConfigurationError: the sensitive option of an instrumentation subscriber is "mask", "show", "hide" or { mask: (value, { path }) => json }`. Допустимы только эти четыре формы.

## Полный пример

```ts twoslash title="monitoring/monitoring.ts"
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";

@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank", monitorCommands: true });
const Accounts = client.db().model(Account);
// ---cut---
const SLOW_MS = 100;

const monitoring = client.instrument({
  driverCommands: true,
  handle: (event) => {
    switch (event.type) {
      case "operation.end":
        // медленные операции
        if (event.durationMS > SLOW_MS) console.warn(`медленно: ${event.model ?? event.database}.${event.operation}`);
        break;
      case "operation.error":
        // упавшие операции: шаг и вид сбоя
        console.error(`${event.operation}: ${event.classification.name}, шаг ${event.failedStep}`);
        break;
      case "transaction.retry":
        console.warn(`повтор транзакции ${event.transactionId}`);
        break;
      case "driver.command.failed":
        console.error(`команда ${event.commandName} упала на ${event.address}`);
        break;
    }
  },
});

await Accounts.find({ balance: { $gt: 50 } }).plain();

// при остановке приложения
monitoring.unsubscribe();
```

<Callout type="migration">

В Mongoose за запросами следят через `mongoose.set("debug", …)` и глобальные хуки, и значения запросов попадают в журнал как есть. В Typemo значения по умолчанию заменены на `"?"`, события типизированы по полю `type`, а подписка снимается своим `unsubscribe()`.

</Callout>
