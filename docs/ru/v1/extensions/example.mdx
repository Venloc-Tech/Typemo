Пройдём весь путь расширения на одной задаче. Интерфейсу администратора нужна таблица счетов, и заголовки столбцов с форматом значений хочется задать прямо в модели, а не дублировать в коде интерфейса. Расширение `label` хранит у поля подпись и, если нужно, функцию форматирования. Оно проверяет их при компиляции схемы, а интерфейс читает их из описания схемы.

Общие правила расширений есть в руководстве [Свои опции полей и схем](./custom-options.mdx), все элементы — в справочнике [Расширения](../reference/extensions/extensions.mdx). Здесь только сборка.

## Что понадобится [#prerequisites]

- Клиент, подключённый как в руководстве [Подключиться к базе](../connection/connect.mdx).
- Расширение регистрируется на клиенте, потому что таблицу столбцов строят только его модели.
- В коллекции один счёт — название `Main`, владелец `alice`, баланс `12.5`.

## Шаг 1. Объявить тип и написать проверку [#declare-type]

В файле расширения две части. Объявление модуля добавляет ключ `label` в `ext` у поля и у схемы, а `TypemoExtension` проверяет значения. Адрес поля к ошибке проверки Typemo добавит сам. Так неверная подпись найдётся уже при запуске приложения и будет названа по полю, а не всплывёт пустой таблицей.

<Snippet id="extensions/example/declare-type" title="extensions/label.ts" twoslash />

## Шаг 2. Использовать ключ в модели [#use-in-model]

Модель описывает счёт обычными `@Prop`, а подписи задаёт в `ext`. У баланса есть `format`, и компилятор знает, что `value` — число, ведь тип взят из поля.

<Snippet id="extensions/example/use-in-model" title="accounts/account.ts" twoslash />

У поля `owner` расширения нет, в таблицу оно не попадёт.

## Шаг 3. Прочитать столбцы из схемы [#read-columns]

Функция `columns` обходит пути схемы из `describe()` и берёт опции каждого через `extOf`. Пути без `label` она пропускает. Интерфейс узнаёт заголовки и форматы из модели, и чтобы добавить столбец, достаточно добавить `ext` у поля. Интерфейс править не придётся.

<Snippet id="extensions/example/read-columns" title="admin/columns.ts" twoslash />

`describe()` вернул все пути модели, включая `_id` и `owner`, а `extOf` оставил только те, где есть `label`. Значения `extOf` приходят как `unknown`, ведь компилятор не знает, что ключ `label` объявлен. Поэтому функция сужает тип сама, а форму уже гарантировала проверка `validateProp` при регистрации. Функцию `format` можно достать только через `extOf`. В JSON-описании из `describe()` функции пропадают.

## Как выбрать [#how-to-choose]

Расширение подходит, когда данные нужны **снаружи** ядра, а самому ядру — нет. Читает их ваш код или интеграция. Если значение должно менять запросы, вместо расширения нужен [хук](../hooks/operation-hooks.mdx).

## Когда это не нужно [#when-not-to-use]

Одному приложению с одной моделью хватит обычной таблицы подписей рядом с кодом. Расширение окупается, когда подписи должны жить у поля, а моделей становится всё больше.

## Если что-то пошло не так [#troubleshooting]

**Расширение зарегистрировано после `model`.** `client.use` после первого `connection.model` бросает `ConfigurationError` с текстом `extension "label": extensions are fixed once a schema is compiled (Account was); call client.use() before the first model`. Перенесите регистрацию выше.

**Пустая подпись.** Ошибка придёт при компиляции схемы, а не при отрисовке — `ConfigurationError: Bad.a: ext "label" is invalid: text must be a non-empty string (scalar)`. Адрес `Bad.a` добавил Typemo.
