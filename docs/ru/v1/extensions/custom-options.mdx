У `@Prop` и `@Schema` есть опция `ext` — место для настроек, которых нет в ядре Typemo. Туда библиотеки и ваш код кладут метаданные поля или модели. Например, подпись для интерфейса, правила экспорта или признаки для поиска.

Свой ключ в `ext` заводит расширение. Вы объявляете тип ключа, регистрируете проверку значения и потом читаете значения из описания схемы. Расширение только хранит и проверяет метаданные. Операции оно не меняет и политики не обходит.

Если нужно изменить поведение запросов, расширение не поможет — смотрите [Вмешаться в операцию](../hooks/operation-hooks.mdx). А где вообще регистрируются расширения, рассказано в руководстве [Несколько клиентов и расширения](../connection/clients-and-extensions.mdx).

## Что понадобится [#prerequisites]

Клиент, подключённый как в руководстве [Подключиться к базе](../connection/connect.mdx), `client` здесь — это `TypemoClient`. Во всех примерах одно расширение `label`, подпись поля для интерфейса.

## Быстрый путь [#quick-start]

Расширение делается в три шага. Объявите тип ключа, зарегистрируйте проверку и используйте ключ в `ext`.

```ts twoslash title="extensions/label.ts"
import { Entity, Prop, Schema, Typemo } from "@venloc/typemo";

declare module "@venloc/typemo" {
  interface PropExtensions<V> {
    label?: { readonly text: string };
  }
}

Typemo.use({
  name: "label",
  validateProp: (value) => {
    if (typeof (value as { text?: unknown }).text !== "string") throw new TypeError("text must be a string");
  },
});

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true, ext: { label: { text: "Название" } } })
  title!: string;
}
```

Ниже разберём каждый шаг, ключи схемы и чтение значений.

## Объявить тип ключа [#declare-key-type]

Этот шаг для компилятора. Он должен знать, что в `ext` есть ключ `label` и какое у него значение. В ядре объявлены два пустых интерфейса — `PropExtensions` для полей и `SchemaExtensions` для схем. Вы дописываете в них свой ключ через объявление модуля, а TypeScript сливает такие объявления в один интерфейс.

```ts twoslash
import "@venloc/typemo";
// ---cut---
declare module "@venloc/typemo" {
  interface PropExtensions<V> {
    label?: { readonly text: string; readonly format?: (value: V) => string };
  }
  interface SchemaExtensions {
    label?: { readonly title: string };
  }
}
```

Параметр `V` в `PropExtensions` — это тип значения поля. Через него опция типизируется значением поля, и `format` у числового поля получит число. Параметр в каждом объявлении должен называться именно `V`, этого требует TypeScript. Ключ с неверным типом значения компилятор не пропустит, как и ключ, которого нет вовсе.

```ts twoslash
import { Entity, Prop, Schema } from "@venloc/typemo";
declare module "@venloc/typemo" {
  interface PropExtensions<V> {
    label?: { readonly text: string };
  }
}
// ---cut---
// @errors: 2322
@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { ext: { label: { text: 5 } } })
  title?: string;
}
```

## Зарегистрировать проверку [#register-check]

Тип защищает только код на TypeScript. Значения из JavaScript или из конфигурации компилятор не видит. Поэтому расширение регистрирует функцию проверки — она получает значение как `unknown` и бросает ошибку, если оно неверное. Для регистрации есть [`Typemo.use`](../reference/connection/typemo.mdx#typemo.use) на все клиенты и [`client.use`](../reference/connection/typemo-client.mdx#client.use) на один.

```ts twoslash
import { Typemo, type TypemoExtension } from "@venloc/typemo";
declare module "@venloc/typemo" {
  interface PropExtensions<V> {
    label?: { readonly text: string };
  }
  interface SchemaExtensions {
    label?: { readonly title: string };
  }
}
// ---cut---
export const label: TypemoExtension<"label"> = {
  name: "label",
  validateProp: (value, field) => {
    const text = (value as { text?: unknown }).text;
    if (typeof text !== "string" || text === "") throw new TypeError(`text must be a non-empty string (${field.kind})`);
  },
  validateSchema: (value) => {
    if (typeof (value as { title?: unknown }).title !== "string") throw new TypeError("title must be a string");
  },
};

Typemo.use(label);
```

Ключ можно ставить только там, где есть проверка. `validateProp` разрешает его у полей, `validateSchema` — у схем, и хотя бы одна из них нужна. Вторым аргументом проверка получает описание места, например вид поля или его путь. Для поля это [`ExtensionFieldInfo`](../reference/extensions/extensions.mdx#extension-field-info), для схемы [`ExtensionSchemaInfo`](../reference/extensions/extensions.mdx#extension-schema-info). Адрес поля Typemo сам добавит в сообщение об ошибке.

Проверка срабатывает при компиляции схемы, то есть при первом [`connection.model`](../reference/connection/connection.mdx#connection.model), а не при первой записи. Её ошибка становится `cause` у `ConfigurationError`, а сообщение называет поле. Вот что получится для `ext: { label: { text: "" } }` у поля `Bad.a` с проверкой выше.

```text
ConfigurationError: Bad.a: ext "label" is invalid: text must be a non-empty string (scalar)
```

## Использовать ключ у поля и у схемы [#use-key]

Значение расширения передаётся в опции `ext` у `@Prop` и `@Schema`. У полей ключ работает везде, в том числе у полей вложенных объектов, массивов, поддокументов и Map.

```ts twoslash
import { type Defaulted, Entity, Prop, Schema } from "@venloc/typemo";
declare module "@venloc/typemo" {
  interface PropExtensions<V> {
    label?: { readonly text: string; readonly format?: (value: V) => string };
  }
  interface SchemaExtensions {
    label?: { readonly title: string };
  }
}
// ---cut---
@Schema({ collection: "accounts", ext: { label: { title: "Счета" } } })
export class Account extends Entity {
  @Prop(() => String, { required: true, ext: { label: { text: "Название" } } })
  title!: string;

  @Prop(() => Number, { default: 0, ext: { label: { text: "Баланс", format: (value) => value.toFixed(2) } } }) // [!code ++]
  balance!: Defaulted<number>; // [!code ++]
}
```

Посмотрите на `value` в `format`. Это число, компилятор взял тип из поля. У `title` своя подпись, у схемы своё название. Значения копируются и замораживаются, так что ни проверка, ни читатели их не изменят. Ваш объект в `@Prop` при этом остаётся нетронутым.

## Прочитать значения [#read-values]

Значения лежат в описании схемы [`SchemaInfo`](../reference/schemas/schema-info.mdx). Для схемы это `model.schema.ext`, для поля — `model.schema.extOf(path)`. Тот же `SchemaInfo` приходит в поле `schema` каждого события операции. Поэтому подписчик на события может прочитать опции своего расширения по модели операции.

```ts twoslash
import { type Defaulted, Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
declare module "@venloc/typemo" {
  interface PropExtensions<V> {
    label?: { readonly text: string };
  }
  interface SchemaExtensions {
    label?: { readonly title: string };
  }
}
@Schema({ collection: "accounts", ext: { label: { title: "Счета" } } })
class Account extends Entity {
  @Prop(() => String, { required: true, ext: { label: { text: "Название" } } }) title!: string;
  @Prop(() => String) note?: string;
}
const client = new TypemoClient("mongodb://localhost:27017/app");
client.use({ name: "label", validateProp: () => undefined, validateSchema: () => undefined });
const Accounts = client.db().model(Account);
// ---cut---
console.log(Accounts.schema.ext, Accounts.schema.extOf("title"), Accounts.schema.extOf("note"), Accounts.schema.extOf("nope"));
// → { label: { title: "Счета" } } { label: { text: "Название" } } {} undefined
```

Поле с расширением вернуло своё значение, поле без опций — пустой объект, а несуществующий путь — `undefined`. Тип значений — `Readonly<Record<string, unknown>>`, потому что в `extOf` компилятор тип ключа не знает. Сужайте его сами. Форму гарантирует проверка, которую вы зарегистрировали.

## Расширение для одного клиента или для всех [#per-client-or-global]

`Typemo.use` видят все клиенты, `client.use` — только модели этого клиента. Модель с ключом на клиенте без расширения не скомпилируется. Текст ошибки одинаковый при обоих способах регистрации.

```text
ConfigurationError: Account: ext "label" is not a registered extension; register it before the first model with client.use() (for the models of one client) or Typemo.use() (for every client)
```

Оба вызова нужно сделать до первой модели клиента. Уровни подробно сравниваются в руководстве [Несколько клиентов и расширения](../connection/clients-and-extensions.mdx#register-before-first-model), там же правила закрытия реестра.

## Как выбрать [#how-to-choose]

Спросите себя, **кто должен видеть это расширение**.

- **Ваши модели живут на одном клиенте** — берите `client.use`, и расширение не достанется чужому коду.
- **Модели создаются на нескольких клиентах или ключ нужен библиотекам** — `Typemo.use`.
- **Нужно не хранить настройку, а менять поведение** — расширение не подходит. Берите [хуки](../hooks/operation-hooks.mdx) или [плагин](../hooks/plugins.mdx).

## Когда это не нужно [#when-not-to-use]

Если настройка уже есть среди опций `@Prop`, например `required`, `hidden` или `enum`, расширение не нужно. И если значение должно менять запросы или документы, расширение тоже не поможет. Доступа к операциям и политикам у него нет, это только метаданные. Операции меняйте в хуках через `modify`, такие изменения проходят все политики.

## Если что-то пошло не так [#troubleshooting]

**Тип объявлен, но расширение не зарегистрировано.** `declare module` сообщает о ключе только компилятору. Без `Typemo.use` или `client.use` TypeScript модель пропустит, но при создании она упадёт с `ext "label" is not a registered extension`. Нужны обе части.

**Расширение зарегистрировано после первой модели.**

```text
ConfigurationError: extension "late": extensions are fixed once a schema is compiled (Account was); call client.use() before the first model
```

Первая **успешно** собранная схема клиента закрывает регистрацию. Расширение, которое появилось бы позже, уже не смогло бы проверить готовые схемы. Неудачная компиляция реестр не закрывает, поэтому после ошибки «not a registered extension» достаточно зарегистрировать названное расширение и повторить `model`.

Но не стройте на этом логику, регистрируйте расширения до первого `connection.model`. Глобальный реестр `Typemo.use` закрывается первой успешной схемой на любом клиенте.

**Ключ стоит на схеме, а `validateSchema` нет.**

```text
ConfigurationError: Bad2: extension "label" has no schema options (used on a schema)
```

Ключ разрешён только там, где у расширения есть проверка. Если он нужен у `@Schema`, добавьте `validateSchema`.
