Новые данные записывает [`create`](../reference/writes/writes.mdx#create). Отдайте ему данные, и он вернёт готовый **документ** — объект класса модели, где уже есть `_id` и значения по умолчанию. До отправки в базу Typemo данные проверяет. Он приводит значения к типам схемы, отвергает неизвестные поля и запускает валидаторы, так что неверная запись останавливается в вашем коде и не становится мусором в коллекции. Любой способ создания запускает хуки документа `document.validate` и `document.save`, и правило на сохранение сработает при каждом.

Способов несколько.

- [`create`](../reference/writes/writes.mdx#create) — один документ или упорядоченный список.
- [`insertOne`](../reference/writes/writes.mdx#insertone) — та же запись одного документа.
- [`insertMany`](../reference/writes/writes.mdx#insertmany) — список одним запросом, в том числе без порядка.
- [`Model.new`](../reference/documents/model-document-methods.mdx#modelnew) с [`$save`](../reference/documents/document-api.mdx#save) — когда документ нужно подготовить и поменять до записи.

Если MongoDB для вас в новинку, достаточно знать две вещи. Документ — это запись в **коллекции**, а `_id` — её уникальный идентификатор, который база выдаёт сама.

## Что понадобится

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель счёта. У счёта два обязательных поля и уникальное имя, а индекс `unique` заранее создан вызовом `connection.init()`.

```ts twoslash title="accounts/account.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true, unique: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;
}
```

## Быстрый путь

Один документ создаёт `create`, много — `create` со списком или `insertMany`. Каждый возвращает документы с `_id`.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const one = await Accounts.create({ title: "Main", owner: "alice" });
console.log(one.title, one.balance);
// → "Main" 0

const many = await Accounts.create([
  { title: "Salary", owner: "alice" },
  { title: "Savings", owner: "alice" },
]);
console.log(many.length);
// → 2

const inserted = await Accounts.insertOne({ title: "Cash", owner: "bob" });
console.log(inserted.owner);
// → "bob"
```

Ниже разберём значения по умолчанию, ошибки, списки документов, `Model.new` и то, какой метод когда брать.

## Создать один документ

Пользователь открывает счёт, и его нужно записать и сразу получить `_id`. Вызовите `create` с данными документа. Обязательные поля модели передайте сами, остальное подставит Typemo.

```ts twoslash title="accounts/accounts.service.ts"
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
export const openAccount = async (owner: string, title: string) => {
  const account = await Accounts.create({ owner, title });
  return account._id;
};
```

Typemo проверил данные, добавил `_id` и значения по умолчанию, записал документ и вернул его. Это экземпляр класса `Account`, а не голый объект. Документ помнит, что уже сохранён, поэтому следующие изменения [`$save`](../reference/documents/document-api.mdx#save) отправит как обновление, а не как вставку. Для ответа клиенту, где `_id` нужен в простом виде, у документа есть [`$toPlain()`](../reference/documents/document-api.mdx#toplain).

## Значения по умолчанию и проверки

У поля может быть **значение по умолчанию** и **границы**. Скажем, у счёта появляется баланс. Отрицательным он не бывает, а начинается с нуля. Модель растёт так.

```ts title="accounts/account.ts"
import { type Defaulted, Entity, Prop, Schema } from "@venloc/typemo"; // [!code highlight]

@Schema({ collection: "accounts" })
export class Account extends Entity {
  // …поля выше

  @Prop(() => Number, { min: 0, default: 0 }) // [!code ++]
  balance!: Defaulted<number>; // [!code ++]
}
```

`Defaulted<number>` говорит компилятору, что при создании поле можно не передавать — значение подставит библиотека. Без этой пометки поле было бы обязательным и во входных данных. Массивы — исключение. Поле `tags!: string[]` без `required` и `default` тоже можно не передавать, новый документ получит пустой `[]`, и `Defaulted` тут не нужен.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const account = await Accounts.create({ title: "Zero", owner: "carol" });
console.log(account.balance);
// → 0
```

Если граница нарушена, создание останавливается ещё до базы с ошибкой [`ValidationError`](../reference/errors/data-errors.mdx#validationerror).

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
try {
  await Accounts.create({ title: "Negative", owner: "carol", balance: -1 });
} catch (error) {
  console.log(error instanceof ValidationError);
  // → true
}
```

```text
ValidationError: Validation failed: "balance": must be at least 0 [min]
ValidationError: Validation failed: "title": the field is required [required]
```

Неизвестное поле или значение не того типа дают [`CastError`](../reference/errors/data-errors.mdx#casterror). Того, чего нет в схеме, Typemo не сохраняет. Иначе опечатка в имени поля стала бы лишним полем в базе.

```text
CastError: Cast to Account failed at path "zzz" for 1 (number): not a field of Account [unknown-key]
CastError: Cast to string failed at path "title" for 5 (number): expected a string [type]
```

## Создать много документов

Импорт, начальное заполнение, пакет событий — во всех этих случаях передайте в `create` список. Документы уйдут **одной упорядоченной записью**, в том порядке, в каком вы их дали. Вернётся массив документов в том же порядке.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const created = await Accounts.create([
  { title: "Salary", owner: "alice" },
  { title: "Savings", owner: "alice" },
]);
console.log(created.map((account) => account.title));
// → ["Salary", "Savings"]
```

Порядок здесь не случайность. Если бы документы создавались параллельно, после ошибки нельзя было бы понять, какие из них уже записаны. А так запись идёт по очереди и останавливается на первой ошибке базы.

Список проверяется целиком ещё до отправки. Если хоть один документ не прошёл проверку, не записывается **ничего**.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
try {
  await Accounts.create([
    { title: "C1", owner: "o" },
    { title: "C2", owner: "o", balance: -1 }, // не пройдёт проверку
  ]);
} catch (error) {
  console.log(await Accounts.countDocuments({ title: "C1" }));
  // → 0
}
```

### Неупорядоченная вставка через insertMany

Когда порядок не важен и нужно записать всё, что проходит проверку, берите [`insertMany`](../reference/writes/writes.mdx#insertmany). Значения он проверяет и хуки документа запускает так же, как `create`, но в базу уходит одним запросом. И он умеет **неупорядоченную** вставку. С `ordered: false` записывается всё, что можно, а ошибки собираются и приходят в конце.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
try {
  await Accounts.insertMany(
    [
      { title: "U1", owner: "d" },
      { title: "Main", owner: "d" }, // такой title уже есть
      { title: "U3", owner: "d", balance: -5 }, // не пройдёт проверку
      { title: "U4", owner: "d" },
    ],
    { ordered: false },
  );
} catch (error) {
  if (error instanceof BulkWriteError) {
    console.log(error.writeErrors.map((failure) => [failure.index, failure.error.name]));
    // → [[1, "DuplicateKeyError"], [2, "ValidationError"]]
    console.log(error.result.insertedCount);
    // → 2
  }
}
```

`U1` и `U4` записаны, второй и третий документы — нет. В [`BulkWriteError`](../reference/errors/server-errors.mdx#bulkwriteerror) у каждой неудачи стоит её позиция во входном списке, а `result.insertedCount` говорит, сколько записано. Ошибки проверки Typemo и ошибки сервера лежат в одном списке `writeErrors`. Для вызывающего кода разницы нет — документ не записан.

## Создать документ через new и $save

Бывает, что документ надо сначала подготовить, поменять, проверить и только потом записать. [`Model.new`](../reference/documents/model-document-methods.mdx#modelnew) создаёт документ **в памяти**. Значения приведены к типам, значения по умолчанию подставлены, но в базе его ещё нет. Записывает его [`$save`](../reference/documents/document-api.mdx#save).

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const draft = Accounts.new({ title: "Draft", owner: "erin" });
console.log(draft.$isNew());
// → true

draft.note = "opened by phone";
await draft.$save();
console.log(draft.$isNew());
// → false
```

`new` проверил данные и вернул документ, а `$isNew()` показал, что он ещё не записан. `$save` его вставил. Этот путь нужен, когда между созданием и записью с документом что-то происходит. В остальных случаях `create` короче и делает то же самое.

## Дубликаты

Пусть `title` должен быть уникальным. Уникальность обеспечивает индекс `unique` в базе, а не Typemo. Библиотека видит один документ, а не всю коллекцию, и проверить это сама не может. Поэтому создайте индекс заранее, через [`connection.init()`](../reference/connection/connection.mdx#connectioninit) или [`Model.syncIndexes`](../reference/collections/model-indexes.mdx#modelsyncindexes). Пока индекса нет, базе нечем остановить повтор.

Повтор бросает [`DuplicateKeyError`](../reference/errors/server-errors.mdx#duplicatekeyerror), а не общую ошибку сервера. У ошибки уже разобраны поля `keyPattern` и `keyValue`.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
try {
  await Accounts.create({ title: "Main", owner: "bob" });
} catch (error) {
  console.log(error instanceof DuplicateKeyError);
  // → true
}
```

```text
DuplicateKeyError: duplicate key on title_1: { title: "Main" } (code 11000 DuplicateKey)
```

В сообщении только индекс, значение ключа и код. Полный текст сервера лежит в `serverMessage`, исходная ошибка драйвера — в `cause`. Значение ключа и в сообщении, и в `keyValue` подчиняется [`sensitive`](../schemas/hidden-and-sensitive.mdx).

Если дубликат попался в списке, придёт `BulkWriteError`, а `DuplicateKeyError` будет в `writeErrors[0].error`. Документы перед ним уже записаны, после него — нет.

```text
BulkWriteError: Account.create: 1 write(s) failed (first at index 1: duplicate key on title_1 (code 11000 DuplicateKey))
```

В тексте стоит `Account.create` — метод, который вызвали вы, а не внутренний механизм записи. С `insertMany` там будет `Account.insertMany`.

## Как выбрать

Спросите себя, что вы будете делать с документом после записи.

- **Читать, менять и сохранять дальше** — например, вернёте из сервиса и продолжите работать с ним как с объектом. Берите [`create`](../reference/writes/writes.mdx#create). Он даёт документ, проходит хуки сохранения и пишет список по порядку.
- **Ничего, нужно просто загрузить много данных**, и частичные ошибки вы готовы разбирать. Берите [`insertMany`](../reference/writes/writes.mdx#insertmany) с `ordered: false`. Только так записывается всё, что проходит проверку, ведь `create` со списком всегда упорядочен.
- **Сначала подготовить и поменять** — начинайте с `Model.new`.

## Когда это не нужно

Пишете вперемешку **разные** операции — вставки, изменения, удаления? Вам нужен [`bulkWrite`](../reference/writes/writes.mdx#bulkwrite), об этом в руководстве [Пакетная запись](./bulk.mdx). Если запись надо вставить или обновить в зависимости от того, есть ли она уже, берите [`upsert`](../reference/writes/writes.mdx#upsert), см. [Обновить документы](./update.mdx). А если данные уже в базе и их нужно изменить, `create` ни при чём — используйте [`updateOne`](../reference/writes/writes.mdx#updateone).

## Если что-то пошло не так

**Список создан наполовину.** `create` или `insertMany` бросил `BulkWriteError`, а часть документов в коллекции есть. Список пишется **по очереди**, и всё, что стояло до ошибки, уже сохранено. Если нужно «всё или ничего», выполните запись в транзакции — руководство [Транзакции](../transactions/transactions.mdx). Тогда сбой откатит всё записанное до него.

**Опечатка в имени поля.** Вот так писать нельзя.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
// @errors: 2769
await Accounts.create({ title: "Typo", owner: "o", ownr: "oops" });
```

Компилятор покажет лишнее поле. А если данные пришли снаружи, поле во время работы остановит [`CastError`](../reference/errors/data-errors.mdx#casterror) с текстом `Cast to Account failed at path "ownr" … not a field of Account`. Исправьте имя поля.

## Полный пример

Всё вместе в одном файле — открытие счёта, импорт списка с разбором частичных ошибок и черновик через `new`.

```ts twoslash title="accounts/accounts.service.ts"
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
// Открыть один счёт и вернуть его id
export const openAccount = async (owner: string, title: string) => {
  const account = await Accounts.create({ owner, title });
  return account._id;
};

// Загрузить список счетов и отчитаться, что не записалось
export const importAccounts = async (rows: { owner: string; title: string }[]) => {
  try {
    const created = await Accounts.insertMany(rows, { ordered: false });
    return { saved: created.length, failed: [] as number[] };
  } catch (error) {
    if (error instanceof BulkWriteError) {
      return {
        saved: error.result.insertedCount,
        failed: error.writeErrors.map((failure) => failure.index),
      };
    }
    throw error;
  }
};

// Подготовить черновик и записать позже
export const saveDraft = async (owner: string, title: string, note: string) => {
  const draft = Accounts.new({ owner, title });
  draft.note = note;
  await draft.$save();
  return draft;
};
```

<Callout type="migration">

В Mongoose `Model.create([...])` создавал документы параллельно. В Typemo список уходит одной упорядоченной записью. `Model.new` заменяет `new Model(data)` и сразу приводит все поля, отвергая неизвестные. Значения по умолчанию подставляются при создании, а проверки, которые в Mongoose были опциями, здесь работают всегда.

</Callout>
