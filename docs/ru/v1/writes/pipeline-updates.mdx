Операторы обновления пишут значения, известные заранее. `$set` кладёт «bob», `$inc` прибавляет 5. Но бывает, что новое значение надо посчитать **из других полей того же документа**. Собрать заметку из владельца и названия, удвоить баланс, поставить метку в зависимости от суммы. Для этого обновление пишут **конвейером**. Вместо объекта операторов вы передаёте функцию, которая описывает, как получить новое значение из полей документа. База выполняет её на месте одной атомарной командой, и читать документ, а потом записывать обратно, не нужно.

Если значение известно заранее, конвейер ни к чему — [операторы](./update-operators.mdx) проще, и к ним подходят `$inc`, `$push` и остальные. Что Typemo в конвейере проверяет, а что проверить не может, разобрано ниже, в разделах про проверки и ограничения.

## Что понадобится

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель счёта. В коллекции один счёт — `Main`, владелец `alice`, баланс 10, прозвище `al`. Каждый пример начинает с этих данных.

```ts twoslash title="accounts/account.ts"
import { type Defaulted, Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true, unique: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => Number, { min: 0, default: 0 })
  balance!: Defaulted<number>;

  @Prop(() => String)
  note?: string;

  @Prop(() => String)
  nickname?: string;
}
```

## Быстрый путь

Передайте функцию вместо объекта операторов. Она получает **строитель конвейера** `p`, а `p.set(…)` описывает новые значения через прокси полей `f` и функции `fn`.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
await Accounts.updateOne({ title: "Main" }, (p) => p.set((f) => ({ balance: fn.add(f.balance, 5) })));
// → balance: 15
```

Ниже разберём вычисляемые значения, несколько стадий, условия и ограничения конвейера.

## Записать значение, вычисленное из других полей

В заметку нужно записать «владелец/название». Значение зависит от двух других полей, и оператором `$set` его не записать. Запишите его стадией `set`. Обращение `f.owner` значит «значение поля `owner` в документе в момент обновления».

```ts twoslash title="accounts/accounts.service.ts"
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
export const fillNote = async (title: string) => {
  await Accounts.updateOne({ title }, (p) => p.set((f) => ({ note: fn.concat(f.owner, "/", f.title) })));
};
```

В итоге `note: "alice/Main"`. `fn.concat` — строковая операция базы, а прокси `f` подставил в неё ссылки на поля. Typemo превратил всё это в стадию `{ $set: { note: { $concat: ["$owner", "/", "$title"] } } }` и отправил на сервер. Значение считается там, поэтому оно всегда строится на **актуальных** данных документа, даже если между чтением и записью что-то поменялось.

Функции `fn` — общий набор выражений, они описаны в разделе [агрегации](../aggregation/expressions.mdx). Пока хватит такого. `fn.add`, `fn.multiply` и `fn.concat` считают, `fn.cond` выбирает значение по условию, а `fn.now()` даёт время сервера.

## Условное значение

Поставим метку «rich» или «poor» в зависимости от баланса. Условие проверяет сервер, на значении из документа.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
await Accounts.updateOne(
  { title: "Main" },
  (p) => p.set((f) => ({ note: fn.cond(fn.gt(f.balance, 5), "rich", "poor") })),
);
// → note: "rich"
```

Операторами так не выйдет. `$set` не умеет «если баланс больше 5, записать одно, иначе другое». Без конвейера пришлось бы прочитать документ, решить в коде и записать, а между чтением и записью документ мог измениться.

## Несколько стадий

Конвейер — это цепочка стадий, и каждая видит результат предыдущей. Так вычисление разбивают на шаги. Ниже вторая стадия дописывает восклицательный знак к тому, что записала первая.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
await Accounts.updateOne({ title: "Main" }, (p) =>
  p
    .set((f) => ({ note: fn.concat(f.owner, "/", f.title) }))
    .set((f) => ({ note: fn.concat(f.note, "!") })),
);
// → note: "alice/Main!"
```

Первая стадия записала `alice/Main`, вторая прочитала это значение и добавила знак. Порядок стадий важен, как порядок действий в формуле.

Есть одно ограничение. Если поле с границами (`min`, `max`) считается в нескольких стадиях и поздняя читает результат ранней, Typemo не сможет проверить границу и откажет. Подробнее — в разделе про проверки.

## Удалить поле

Стадия [`unset`](../reference/writes/pipeline-updates.mdx#unset) убирает поле или список полей, обычно вместе с другими стадиями.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
await Accounts.updateOne({ title: "Main" }, (p) => p.unset("nickname"));
// → поле nickname удалено, owner остаётся "alice"
```

## Много документов и получение документа

Конвейер принимают те же методы, что и операторы, — [`updateOne`](../reference/writes/writes.mdx#updateone), [`updateMany`](../reference/writes/writes.mdx#updatemany) и [`findOneAndUpdate`](../reference/writes/writes.mdx#findoneandupdate). Правила фильтра прежние, у `updateMany` он обязателен и не пуст.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const result = await Accounts.updateMany({ owner: "alice" }, (p) =>
  p.set((f) => ({ balance: fn.multiply(f.balance, 2) })),
);
console.log(result.matchedCount);
// → 1

const before = await Accounts.findOneAndUpdate(
  { title: "Main" },
  (p) => p.set((f) => ({ balance: fn.add(f.balance, 1) })),
  { returnDocument: "before" },
).plain();
console.log(before?.balance);
// → 20
```

Второй вызов видит баланс, который удвоил первый, — было 10, стало 20. И возвращает состояние **до** своего изменения.

## Что проверяет конвейер

Конвейер записывает то, что посчитает сервер, поэтому привести значение к типу так же прямо, как у оператора, Typemo не может. Но без проверок конвейер не остаётся. Значения делятся на три случая.

**Константа** в стадии `set` — обычное значение. Typemo приводит её к типу поля и проверяет границы ещё до отправки, как у `$set`. Неверный тип даёт `CastError`, нарушенная граница — `ValidationError`.

```text
CastError: Cast to number failed at path "$set.balance" for "abc" (string): expected a number [type]
ValidationError: Validation failed: "balance": must be at least 0 [min]
```

**Удаление обязательного поля** через `unset` или замену документа без этого поля даёт `ValidationError` до отправки.

```text
ValidationError: Validation failed: "owner": update.0.$unset: the field is required; the pipeline would remove it [required]
```

**Вычисляемое значение** поля с ограничениями — `min`, `max`, `enum`, `minLength`, `maxLength`, `match`, `required` — проверяет сама база. Typemo добавляет к фильтру условие с тем же выражением и теми же ограничениями, и неверный результат не записывается. Всё это атомарно, одной командой. Если условие не пропустило запись, одно дополнительное чтение отличает «документ не найден» от «значение не подошло» и называет посчитанное значение. Вот как защищена граница `min: 0` у `balance`.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
try {
  await Accounts.updateOne({ title: "Main" }, (p) => p.set((f) => ({ balance: fn.add(f.balance, -50) })));
} catch (error) {
  console.log(error instanceof ValidationError);
  // → true
}
```

```text
ValidationError: Validation failed: "balance": the update pipeline computes -40; the value must be at least 0; nothing was written [min]
```

Баланс в базе остался 10, а ошибка называет посчитанное значение, -40. Так же работают [`findOneAndUpdate`](../reference/writes/writes.mdx#findoneandupdate) и `updateMany`. У `updateMany` документы, которые условие не пропустило бы, находятся до записи, и тогда не записывается **ничего**.

## Что конвейер не может проверить

Условие базы считает выражение по хранимому документу. Поэтому оно точно, только пока выражение читает поля, которые не меняла ни одна предыдущая стадия. Всё остальное Typemo отвергает до отправки, а не записывает без проверки.

```text
ValidationError: Validation failed: "balance": update.1.$set: the computed value of "balance" cannot be checked against its constraints: it reads "balance", which an earlier stage of the pipeline changes; compute both in one stage [min]
ValidationError: Validation failed: "balance": the computed value of "balance" cannot be checked against its constraints with upsert (a failed guard would insert a new document) [min]
```

Первая ошибка — значение читает поле, которое поменяла ранняя стадия, или `$$ROOT` после изменения. Выход — посчитать всё в одной стадии. Вторая — вычисляемое значение поля с границами вместе с `upsert`, так же как `$inc` с границей при `upsert`.

По тому же правилу отвергаются ещё несколько случаев.

- Вычисляемое значение после стадии, которая переписывает документ целиком.
- Поле с границами за массивом или `Map`.
- Целый документ, вычисленный выражением.
- Такой конвейер в `bulkWrite`.

Не проверяется то, чего выражение сервера выразить не может. Ваши функции `validate`, ограничения элементов **внутри** вычисленного массива, `Map` или вложенного документа и тип вычисленного значения у поля без ограничений. Для такого поля защищают только типы. Компилятор знает поля модели и типы выражений, так что опечатку в имени поля или выражение не того типа он остановит. Если результат должен уложиться в границы, а выражение читает уже изменённое поле, берите `$inc` — он защищает `min` и `max` на стороне сервера.

Есть и жёсткие правила. `arrayFilters` с конвейером нельзя, потому что позиционных путей в конвейере нет.

```text
QueryError: arrayFilters: not allowed with an update pipeline
```

Массив стадий вместо функции тоже не принимается. Стадии строятся строителем, чтобы их проверяли типы.

```text
QueryError: update: an update pipeline is built with the pipeline builder: updateOne(filter, (p) => p.set({ … })), not passed as an array
```

Функция без стадий — тоже ошибка запроса.

```text
QueryError: an update pipeline needs at least one stage
```

`upsert` с конвейером проверяет обязательные поля нового документа так же, как с операторами. Недостающее поле — `ValidationError` до отправки.

## Заменить документ целиком стадией

Стадии `project`, `replaceWith` и `replaceRoot` переписывают документ целиком. На модели с неизменяемыми полями — с `immutable` или со служебным `createdAt` у `Timestamped` — такая стадия могла бы потерять или изменить поле, которое трогать нельзя. Поэтому Typemo пропускает её, только если новый корень переносит **каждое** неизменяемое поле как есть.

Допустимые формы такие.

- `createdAt: "$createdAt"`, или через прокси полей `owner: f.owner`.
- `$$ROOT` целиком.
- `$mergeObjects` с `$$ROOT` и объектом из других полей.
- У `project` — включающая форма с этими полями или исключающая, которая их не трогает.

Ключи объекта в `replaceWith` пишите именами полей модели. Если у поля задан `dbName`, Typemo сам переведёт их в имена в базе.

Пусть у модели есть неизменяемое поле `owner` и служебное `createdAt`. Замена, которая несёт их с собой, проходит, а остальные поля заменяются.

```ts twoslash
import { Entity, fn, type Immutable, Prop, Schema, Timestamped, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "stamped" })
class Stamped extends Timestamped(Entity) {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true, immutable: true }) owner!: Immutable<string>;
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Stampeds = client.db().model(Stamped);
// ---cut---
await Stampeds.updateOne({ title: "first" }, (p) =>
  p.replaceWith((f) => ({ title: fn.literal("second"), owner: f.owner, createdAt: f.createdAt })),
);
// → документ: title "second", прежние owner и createdAt, поля note больше нет
```

Если новый корень не переносит неизменяемое поле или берёт его из другого поля, обновление отвергается до отправки, и в тексте названы потерянные поля.

```text
StrictModeError: update.0.$replaceWith: $replaceWith rewrites the whole document and would change or drop the immutable fields createdAt, owner; carry each unchanged (createdAt: "$createdAt") or use $set/$unset of the other fields [immutable]
```

У модели с полями под другим именем в базе (`dbName`) в такой стадии нельзя `$$ROOT` и `$$CURRENT` — `ConfigurationError: Stamped: $$ROOT/$$CURRENT of a model with dbName fields would give stored names to the rows; list the fields instead`. Перечисляйте поля явно.

## Как выбрать

Спросите себя, зависит ли новое значение от других полей документа.

- **Не зависит** — берите операторы, `$set` для значения и `$inc` для числа. Они проще, а `$inc` защищает границы без всяких особых условий.
- **Зависит, и считать нужно на месте** — берите конвейер.
- **Зависит только от того же числового поля** — «прибавить», «умножить». Тоже берите оператор. `$inc` и `$mul` атомарны и защищены, конвейер тут ничего не добавит.

## Когда это не нужно

Если значение вы считаете в коде приложения из данных, которые уже есть под рукой, запишите его оператором `$set`. Константа проходит все проверки ещё до отправки. А если значение нужно посчитать и вернуть, не меняя документ, берите [агрегацию](../aggregation/first-aggregation.mdx) — конвейер обновления документы меняет.

## Если что-то пошло не так

**Граница поля не проверена.** Приходит `ValidationError: … cannot be checked against its constraints: it reads "balance", which an earlier stage of the pipeline changes`. Вторая стадия читает поле с границами, которое изменила первая, и база не может проверить границу по хранимому документу. Посчитайте поле в одной стадии, например `fn.multiply(fn.add(f.balance, 1), 2)`, или проведите промежуточный результат через поле без границ.

**Массив стадий.** Например, `Accounts.updateOne(filter, [{ $set: { owner: "q" } }])`. Typemo отвергнет массив с `update: an update pipeline is built with the pipeline builder …`. Передайте функцию `(p) => p.set(…)`.

**Замена корня теряет неизменяемое поле.** Скажем, `p.replaceWith(…)` на модели с `Timestamped`, где новый документ не несёт `createdAt`. Typemo остановит обновление и назовёт потерянные поля.

```text
StrictModeError: update.0.$replaceWith: $replaceWith rewrites the whole document and would change or drop the immutable fields createdAt, owner; carry each unchanged (createdAt: "$createdAt") or use $set/$unset of the other fields [immutable]
```

Перенесите каждое неизменяемое поле как есть, например `createdAt: f.createdAt`, или перечислите изменения через `p.set(…)` и `p.unset(…)`.

## Полный пример

Всё вместе в одном файле — вычисляемая заметка, метка по балансу и удвоение всех балансов владельца.

```ts twoslash title="accounts/accounts.service.ts"
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => Date) lastLogin?: Date;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
// Записать заметку «владелец/название»
export const fillNote = async (title: string) => {
  await Accounts.updateOne({ title }, (p) => p.set((f) => ({ note: fn.concat(f.owner, "/", f.title) })));
};

// Поставить метку по балансу
export const labelAccount = async (title: string) => {
  await Accounts.updateOne(
    { title },
    (p) => p.set((f) => ({ note: fn.cond(fn.gt(f.balance, 5), "rich", "poor") })),
  );
};

// Удвоить балансы владельца
export const doubleBalances = async (owner: string) => {
  return Accounts.updateMany({ owner }, (p) => p.set((f) => ({ balance: fn.multiply(f.balance, 2) })));
};
```
