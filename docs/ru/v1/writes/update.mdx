Чтобы изменить данные, которые уже лежат в базе, вызовите [`updateOne`](../reference/writes/writes.mdx#updateone) или [`updateMany`](../reference/writes/writes.mdx#updatemany) и опишите **что сделать** с полем: прибавить число, записать значение, добавить элемент в массив. Обновление — это не новый документ, а набор операторов, поэтому одновременные изменения не затирают друг друга, а Typemo проверяет каждое значение ещё до отправки.

Если вам нужно получить документ после изменения, есть [`findOneAndUpdate`](../reference/writes/writes.mdx#findoneandupdate) и [`findByIdAndUpdate`](../reference/writes/writes.mdx#findbyidandupdate). Если документа может не быть и его нужно создать, к любому из методов добавляется [`upsert`](../reference/writes/writes.mdx#upsert). Сами операторы (`$set`, `$inc`, `$push` и остальные) разобраны в руководстве [Операторы обновления](./update-operators.mdx).

## Что предполагается

Примеры используют клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель счёта из руководства [Создать документы](./create.mdx). В коллекции лежат счёт `Main` (владелец `alice`, баланс 10, тег `a`), счёт `Second` (`alice`, баланс 5) и счёт `Other` (`bob`). Каждый пример выполняется на этих данных заново.

```ts twoslash title="accounts/account.ts"
import { type Defaulted, Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true, unique: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => Number, { min: 0, default: 0 })
  balance!: Defaulted<number>;
}
```

## Быстрый путь

Три самых частых случая: изменить один документ, изменить много документов, изменить и получить результат. Результат `await` у первых двух — счётчики, у третьего — документ.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const one = await Accounts.updateOne({ title: "Main" }, { $inc: { balance: 10 } });
console.log(one.modifiedCount);
// → 1

const many = await Accounts.updateMany({ owner: "alice" }, { $set: { note: "checked" } });
console.log(many.modifiedCount);
// → 2

const account = await Accounts.findOneAndUpdate({ title: "Main" }, { $inc: { balance: 1 } });
console.log(account?.balance);
// → 21
```

Остальная страница разбирает каждый способ на реальных задачах.

## Изменить один документ

Ситуация: клиент пополнил счёт, и вы знаете, какой именно. Вызовите `updateOne` с фильтром и обновлением. Фильтр выбирает **первый** подходящий документ, обновление говорит, что с ним сделать.

```ts twoslash title="accounts/accounts.service.ts"
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
export const topUp = async (title: string, amount: number) => {
  const result = await Accounts.updateOne({ title }, { $inc: { balance: amount } });
  return result.modifiedCount === 1;
};
```

Что произошло. Метод вернул [`UpdateResult`](../reference/writes/writes.mdx#updateresult): `matchedCount` — сколько документов подошло под фильтр, `modifiedCount` — сколько из них изменилось. Эти два числа различаются, если обновление ничего не поменяло, например записало то же значение.

`updateOne` — это **строитель записи**. Запись уходит в базу на `await`, а не при вызове, и выполняется один раз для каждого объекта. Второй `await` того же объекта — ошибка, потому что он тихо повторил бы запись:

```text
QueryError: updateOne: this operation was already executed; build a new one, or run it again deliberately with exec({ force: true }) (a write runs once per builder)
```

### Если документ не найден

Когда фильтр ничего не нашёл, `updateOne` не бросает ошибку: он возвращает `matchedCount: 0`. Так сделано потому, что «не найдено» — обычный результат, а не сбой. Если для вашей задачи это ошибка, добавьте [`.orFail()`](../reference/writes/writes.mdx#orfail):

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
try {
  await Accounts.updateOne({ title: "Nope" }, { $set: { note: "x" } }).orFail();
} catch (error) {
  console.log(error instanceof DocumentNotFoundError);
  // → true
}
```

```text
DocumentNotFoundError: Account.updateOne: no document matched the filter (orFail)
```

## Изменить много документов

Ситуация: нужно поставить отметку всем счетам владельца. `updateMany` меняет **все** подходящие документы одним запросом.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const result = await Accounts.updateMany({ owner: "alice" }, { $set: { note: "checked" } });
console.log(result.matchedCount, result.modifiedCount);
// → 2 2
```

Фильтр у `updateMany` обязателен и не пуст, как и у `updateOne`: в MongoDB пустой фильтр `{}` подходит любому документу, а фильтр часто собирают из данных. Одна опечатка, и обновление достанется всей коллекции (или произвольному документу у `updateOne`). Поэтому пустой литерал `{}` не компилируется, а пустой объект во время работы Typemo отвергает:

```text
StrictModeError: updateMany with an empty filter would affect every document; pass a filter, or Filters.all() to mean every document on purpose [empty-filter]
```

Как изменить всё намеренно, описано в руководстве [Пустые фильтры в записи](./empty-filters.mdx).

## Изменить и получить документ

Ситуация: вы пополнили счёт и хотите показать клиенту новый баланс. Вместо двух запросов (изменить, прочитать) есть один: [`findOneAndUpdate`](../reference/writes/writes.mdx#findoneandupdate) изменяет документ и возвращает его, причём изменение и чтение выполняются одной командой, так что между ними никто не вклинится.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const account = await Accounts.findOneAndUpdate({ title: "Main" }, { $inc: { balance: 1 } });
console.log(account?.balance);
// → 11
```

По умолчанию возвращается документ **после** изменения. В драйвере MongoDB и в Mongoose по умолчанию возвращается документ до изменения, но почти всегда нужен результат, поэтому здесь наоборот. Чтобы получить состояние до, передайте `returnDocument: "before"` (опция описана в [справочнике](../reference/writes/writes.mdx#returndocument)):

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const before = await Accounts.findOneAndUpdate(
  { title: "Main" },
  { $inc: { balance: 1 } },
  { returnDocument: "before" },
).plain();
console.log(before?.balance);
// → 11
```

Результат — тот же строитель запроса, что у [`find`](../reference/query/reading.mdx#modelfind): к нему добавляют [`.select`](../reference/query/reading.mdx#select), [`.plain`](../reference/query/reading.mdx#plain), [`.lean`](../reference/query/reading.mdx#lean) и [`.orFail`](../reference/query/reading.mdx#orfail). Если ничего не нашлось, результат `null`; с `.orFail()` вместо `null` приходит `DocumentNotFoundError`.

### Документ по идентификатору

Когда `id` пришёл из адреса запроса, не нужно собирать фильтр: [`findByIdAndUpdate`](../reference/writes/writes.mdx#findbyidandupdate) принимает `_id` и как `ObjectId`, и как строку из 24 шестнадцатеричных символов.

```ts twoslash title="accounts/accounts.service.ts"
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
export const renameNote = async (id: string, note: string) => {
  const account = await Accounts.findByIdAndUpdate(id, { $set: { note } }).orFail();
  return account.note;
};
```

Строка неверного формата останавливается ошибкой [`CastError`](../reference/errors/data-errors.mdx#casterror) ещё до базы:

```text
CastError: Cast to ObjectId failed at path "_id" for "zzz" (string): not a 24-character hex string [format]
```

## Создать документ, если его нет

Ситуация: «пополнить счёт, а если такого счёта нет, создать его». Опция `upsert: true` вставляет новый документ, когда фильтр ничего не нашёл. Начальные значения, которые не должны затирать существующие, кладут в `$setOnInsert`: он срабатывает только при вставке.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const result = await Accounts.updateOne(
  { title: "Fresh" },
  { $set: { owner: "ivan" }, $setOnInsert: { balance: 100 } },
  { upsert: true },
);
console.log(result.upsertedCount, result.upsertedId !== null);
// → 1 true
```

Что произошло. Документа `Fresh` не было, поэтому база создала его из равенств в фильтре и операторов обновления, а `upsertedId` содержит его `_id`. Если бы документ был, `upsertedCount` равнялся бы `0`, а `$setOnInsert` ничего бы не сделал.

Обычное обновление проверяет только те поля, которые оно записывает: остальные уже лежат в базе. Но `upsert` может создать документ целиком, поэтому Typemo до отправки проверяет, что вставляемый документ получит **все** обязательные поля: из равенств в фильтре, из `$set`, из `$setOnInsert` или из другого оператора, который пишет это поле. Недостающее поле, например `owner` в `{ $set: { note: "x" } }`, — `ValidationError` до обращения к базе:

```text
ValidationError: Validation failed: "owner": upsert would create a document without the required field "owner"; give it in the filter (an equality), in $set or in $setOnInsert [required]
```

Проверка действует на каждый `upsert`, даже если документ окажется на месте: Typemo не знает заранее, вставит ли сервер новый. Есть и второе ограничение: `$inc` и `$mul` на поле с `min` или `max` вместе с `upsert` не допускаются, потому что условие защиты границы при вставке не сработало бы. Начальное значение такого поля кладут в `$setOnInsert`.

С `findOneAndUpdate` upsert работает так же, а тип результата учитывает его: при `upsert: true` и `returnDocument: "after"` документ есть всегда, поэтому `null` из типа пропадает.

## Что Typemo проверяет при обновлении

Обновление проходит те же проверки, что создание, но применяются они к тому, что оператор записывает. Значение приводится к типу поля, валидаторы поля выполняются, а неизвестные поля отвергаются:

```text
StrictModeError: $set: "nope" is not a field of Account [unknown-path]
CastError: Cast to number failed at path "$set.balance" for "abc" (string): expected a number [type]
ValidationError: Validation failed: "balance": must be at least 0 [min]
```

Особый случай — `$inc` на поле с границей. Итог зависит от значения в базе, поэтому Typemo делает обновление условным: если результат выйдет за границу, запись не происходит, а вы получаете `ValidationError` со значением из базы и итогом.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
try {
  await Accounts.updateOne({ title: "Main" }, { $inc: { balance: -1000 } });
} catch (error) {
  console.log(error instanceof ValidationError);
  // → true
}
```

```text
ValidationError: Validation failed: "balance": $inc -1000 on 10 gives -990, below the minimum 0; nothing was written [min]
```

Пустое обновление тоже ошибка: пустой объект слишком легко получить случайно, и тихое «ничего не менять» скрыло бы ошибку в коде.

```text
QueryError: update: an empty update changes nothing
QueryError: update: operator "$set" is empty
```

## Как выбрать

Задайте себе один вопрос: **нужен ли вам документ после изменения?** Если нет, берите [`updateOne`](../reference/writes/writes.mdx#updateone) или [`updateMany`](../reference/writes/writes.mdx#updatemany): они дешевле, потому что не возвращают документ. Если да, берите [`findOneAndUpdate`](../reference/writes/writes.mdx#findoneandupdate) или, когда известен `_id`, [`findByIdAndUpdate`](../reference/writes/writes.mdx#findbyidandupdate). Второй вопрос — сколько документов вы меняете. Один документ — `updateOne`; много — `updateMany`, но `findOneAndUpdate` всегда меняет один.

## Когда это не нужно

Если вы уже держите документ в памяти и изменили его поля, сохранить его можно через [`$save`](../reference/documents/document-api.mdx#save): он отправит только изменённое, см. [Изменить и сохранить](../documents/change-and-save.mdx). Если нужно заменить документ целиком, а не поменять поля, используйте [`replaceOne`](../reference/writes/writes.mdx#replaceone), см. [Заменить документ](./replace.mdx). Если новое значение вычисляется из других полей документа, нужен [конвейер](./pipeline-updates.mdx).

## Частые ошибки

### Второй await того же обновления падает

Неправильно:

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const query = Accounts.updateOne({ title: "Main" }, { $inc: { balance: 1 } });
await query;
await query;
```

Вторая строка бросает `QueryError: updateOne: this operation was already executed; …`. Запись выполняется один раз для каждого объекта: повтор был бы почти всегда случайным. Правильно построить новое обновление, а если повтор нужен намеренно, вызвать [`query.exec({ force: true })`](../reference/writes/writes.mdx#exec).

### Обновление без операторов

Неправильно: `Accounts.updateOne({ title: "Main" }, { note: "z" })`. Если такое обновление дошло до выполнения (данные пришли извне и типы обойдены), придёт:

```text
QueryError: update: "note" is not an update operator (write { $set: { … } })
```

Правильно: `{ $set: { note: "z" } }`. Без оператора база не поняла бы, что вы хотите сделать: записать поле или заменить документ.

### Один путь под двумя операторами

Неправильно: `{ $inc: { balance: 1 }, $set: { balance: 3 } }`. Сервер отвергает такое обновление, а Typemo находит это раньше:

```text
QueryError: update: "balance" is changed by $inc and $set (server code 40)
```

Оставьте для пути один оператор.

## Полный пример

Файл собирает описанное: пополнение с защитой границы, получение документа по id из адреса и вставка при отсутствии.

```ts twoslash title="accounts/accounts.service.ts"
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
// Пополнить счёт; false, если такого счёта нет или баланс вышел бы за границу
export const topUp = async (title: string, amount: number): Promise<boolean> => {
  try {
    const result = await Accounts.updateOne({ title }, { $inc: { balance: amount } });
    return result.matchedCount === 1;
  } catch (error) {
    if (error instanceof ValidationError) return false;
    throw error;
  }
};

// Сменить заметку и вернуть документ по id из адреса
export const renameNote = async (id: string, note: string) => {
  return Accounts.findByIdAndUpdate(id, { $set: { note } }).plain();
};

// Сменить владельца счёта или открыть его со стартовым балансом
export const reassignOrOpen = async (title: string, owner: string, amount: number) => {
  await Accounts.updateOne(
    { title },
    { $set: { owner }, $setOnInsert: { balance: amount } },
    { upsert: true },
  );
};
```

<Callout type="migration">

В Mongoose `findOneAndUpdate` по умолчанию возвращал документ до изменения (`new: false`), а `updateOne` с пустым обновлением молча ничего не отправлял. Здесь по умолчанию возвращается документ после изменения, а пустое обновление — ошибка. Проверки значений (`runValidators` в Mongoose) работают всегда, а `$inc` защищает границы `min` и `max` на стороне сервера.

</Callout>
