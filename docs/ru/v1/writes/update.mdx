Чтобы поменять данные, которые уже лежат в базе, вызовите [`updateOne`](../reference/writes/writes.mdx#updateone) или [`updateMany`](../reference/writes/writes.mdx#updatemany) и скажите, **что сделать** с полем. Прибавить число, записать значение, добавить элемент в массив. Обновление — это не новый документ, а набор операторов. Поэтому одновременные изменения не затирают друг друга, а Typemo проверяет каждое значение ещё до отправки.

Нужен документ после изменения — есть [`findOneAndUpdate`](../reference/writes/writes.mdx#findoneandupdate) и [`findByIdAndUpdate`](../reference/writes/writes.mdx#findbyidandupdate). Если документа может не оказаться и его тогда надо создать, добавьте к любому из методов [`upsert`](../reference/writes/writes.mdx#upsert). Сами операторы — `$set`, `$inc`, `$push` и остальные — разобраны в руководстве [Операторы обновления](./update-operators.mdx).

## Что понадобится

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель счёта из руководства [Создать документы](./create.mdx). Каждый пример начинает с одних и тех же данных.

- Счёт `Main` — владелец `alice`, баланс 10, тег `a`.
- Счёт `Second` — владелец `alice`, баланс 5.
- Счёт `Other` — владелец `bob`.

```ts twoslash title="accounts/account.ts"
import { type Defaulted, Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true, unique: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => Number, { min: 0, default: 0 })
  balance!: Defaulted<number>;
}
```

## Быстрый путь

Три самых частых случая — изменить один документ, изменить много и изменить с возвратом результата. Первые два после `await` дают счётчики, третий — документ.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const one = await Accounts.updateOne({ title: "Main" }, { $inc: { balance: 10 } });
console.log(one.modifiedCount);
// → 1

const many = await Accounts.updateMany({ owner: "alice" }, { $set: { note: "checked" } });
console.log(many.modifiedCount);
// → 2

const account = await Accounts.findOneAndUpdate({ title: "Main" }, { $inc: { balance: 1 } });
console.log(account?.balance);
// → 21
```

Ниже разберём каждый способ на живых задачах.

## Изменить один документ

Клиент пополнил счёт, и вы знаете, какой именно. Вызовите `updateOne` с фильтром и обновлением. Фильтр выбирает **первый** подходящий документ, обновление говорит, что с ним сделать.

```ts twoslash title="accounts/accounts.service.ts"
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
export const topUp = async (title: string, amount: number) => {
  const result = await Accounts.updateOne({ title }, { $inc: { balance: amount } });
  return result.modifiedCount === 1;
};
```

Метод вернул [`UpdateResult`](../reference/writes/writes.mdx#updateresult). `matchedCount` — сколько документов подошло под фильтр, `modifiedCount` — сколько из них изменилось. Числа расходятся, когда обновление ничего не поменяло, например записало то же самое значение.

`updateOne` — это **строитель записи**. Запись уходит в базу на `await`, а не при вызове, и каждый такой объект выполняется один раз. Второй `await` того же объекта — ошибка, иначе запись тихо повторилась бы.

```text
QueryError: updateOne: this operation was already executed; build a new one, or run it again deliberately with exec({ force: true }) (a write runs once per builder)
```

### Если документ не найден

Если фильтр ничего не нашёл, `updateOne` ошибку не бросает и возвращает `matchedCount: 0`. «Не найдено» — обычный исход, а не сбой. Если для вашей задачи это всё-таки ошибка, добавьте [`.orFail()`](../reference/writes/writes.mdx#orfail).

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
try {
  await Accounts.updateOne({ title: "Nope" }, { $set: { note: "x" } }).orFail();
} catch (error) {
  console.log(error instanceof DocumentNotFoundError);
  // → true
}
```

```text
DocumentNotFoundError: Account.updateOne: no document matched the filter (orFail)
```

## Изменить много документов

Скажем, всем счетам владельца нужно поставить отметку. `updateMany` меняет **все** подходящие документы одним запросом.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const result = await Accounts.updateMany({ owner: "alice" }, { $set: { note: "checked" } });
console.log(result.matchedCount, result.modifiedCount);
// → 2 2
```

Фильтр у `updateMany`, как и у `updateOne`, обязателен и не может быть пустым. В MongoDB пустой фильтр `{}` подходит любому документу, а фильтры часто собирают из данных. Одна опечатка — и обновление достанется всей коллекции или, у `updateOne`, случайному документу. Поэтому литерал `{}` не компилируется, а пустой объект во время работы Typemo отвергает.

```text
StrictModeError: updateMany with an empty filter would affect every document; pass a filter, or Filters.all() to mean every document on purpose [empty-filter]
```

Как изменить всё намеренно, рассказано в руководстве [Пустые фильтры в записи](./empty-filters.mdx).

## Изменить и получить документ

Вы пополнили счёт и хотите показать клиенту новый баланс. Двух запросов, «изменить» и «прочитать», не нужно. [`findOneAndUpdate`](../reference/writes/writes.mdx#findoneandupdate) меняет документ и возвращает его одной командой, и между изменением и чтением никто не вклинится.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const account = await Accounts.findOneAndUpdate({ title: "Main" }, { $inc: { balance: 1 } });
console.log(account?.balance);
// → 11
```

По умолчанию вы получаете документ **после** изменения. Драйвер MongoDB и Mongoose по умолчанию отдают документ до изменения, но почти всегда нужен результат, поэтому здесь наоборот. Нужно состояние до — передайте `returnDocument: "before"`, опция описана в [справочнике](../reference/writes/writes.mdx#returndocument).

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const before = await Accounts.findOneAndUpdate(
  { title: "Main" },
  { $inc: { balance: 1 } },
  { returnDocument: "before" },
).plain();
console.log(before?.balance);
// → 11
```

Вернётся тот же строитель запроса, что у [`find`](../reference/query/reading.mdx#modelfind). К нему можно добавить [`.select`](../reference/query/reading.mdx#select), [`.plain`](../reference/query/reading.mdx#plain), [`.lean`](../reference/query/reading.mdx#lean) и [`.orFail`](../reference/query/reading.mdx#orfail). Если ничего не нашлось, придёт `null`, а с `.orFail()` вместо него — `DocumentNotFoundError`.

### Документ по идентификатору

Когда `id` пришёл из адреса запроса, фильтр собирать не надо. [`findByIdAndUpdate`](../reference/writes/writes.mdx#findbyidandupdate) принимает `_id` и как `ObjectId`, и как строку из 24 шестнадцатеричных символов.

```ts twoslash title="accounts/accounts.service.ts"
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
export const renameNote = async (id: string, note: string) => {
  const account = await Accounts.findByIdAndUpdate(id, { $set: { note } }).orFail();
  return account.note;
};
```

Строку неверного формата ещё до базы остановит [`CastError`](../reference/errors/data-errors.mdx#casterror).

```text
CastError: Cast to ObjectId failed at path "_id" for "zzz" (string): not a 24-character hex string [format]
```

## Создать документ, если его нет

Задача звучит как «пополнить счёт, а если его нет, открыть». Опция `upsert: true` вставляет новый документ, когда фильтр ничего не нашёл. Стартовые значения, которые не должны затирать существующие, кладите в `$setOnInsert` — он срабатывает только при вставке.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const result = await Accounts.updateOne(
  { title: "Fresh" },
  { $set: { owner: "ivan" }, $setOnInsert: { balance: 100 } },
  { upsert: true },
);
console.log(result.upsertedCount, result.upsertedId !== null);
// → 1 true
```

Документа `Fresh` не было, и база собрала его из равенств фильтра и операторов обновления. В `upsertedId` лежит его `_id`. Будь документ на месте, `upsertedCount` был бы `0`, а `$setOnInsert` ничего бы не сделал.

Обычное обновление проверяет только те поля, которые пишет, — остальные уже в базе. Но `upsert` может создать документ целиком. Поэтому до отправки Typemo проверяет, что новый документ получит **все** обязательные поля — из равенств фильтра, из `$set`, из `$setOnInsert` или из другого оператора, который пишет это поле. Если поля не хватает, как `owner` в `{ $set: { note: "x" } }`, придёт `ValidationError`, и до базы дело не дойдёт.

```text
ValidationError: Validation failed: "owner": upsert would create a document without the required field "owner"; give it in the filter (an equality), in $set or in $setOnInsert [required]
```

Проверка работает на каждом `upsert`, даже если документ на месте. Заранее Typemo не знает, будет ли сервер вставлять новый. Есть и второе ограничение. `$inc` и `$mul` по полю с `min` или `max` вместе с `upsert` нельзя, потому что условие, которое защищает границу, при вставке не сработало бы. Стартовое значение такого поля кладите в `$setOnInsert`.

С `findOneAndUpdate` upsert работает так же, и тип результата это учитывает. При `upsert: true` и `returnDocument: "after"` документ есть всегда, и `null` из типа уходит.

## Что Typemo проверяет при обновлении

Обновление проходит те же проверки, что и создание, только для того, что пишет оператор. Значение приводится к типу поля, валидаторы поля выполняются, неизвестные поля отвергаются.

```text
StrictModeError: $set: "nope" is not a field of Account [unknown-path]
CastError: Cast to number failed at path "$set.balance" for "abc" (string): expected a number [type]
ValidationError: Validation failed: "balance": must be at least 0 [min]
```

Отдельный случай — `$inc` по полю с границей. Итог зависит от значения в базе, поэтому Typemo делает обновление условным. Если результат выйдет за границу, ничего не запишется, а вы получите `ValidationError` со значением из базы и итогом.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
try {
  await Accounts.updateOne({ title: "Main" }, { $inc: { balance: -1000 } });
} catch (error) {
  console.log(error instanceof ValidationError);
  // → true
}
```

```text
ValidationError: Validation failed: "balance": $inc -1000 on 10 gives -990, below the minimum 0; nothing was written [min]
```

Пустое обновление — тоже ошибка. Пустой объект слишком легко получить случайно, и тихое «ничего не менять» спрятало бы баг.

```text
QueryError: update: an empty update changes nothing
QueryError: update: operator "$set" is empty
```

## Как выбрать

Спросите себя, нужен ли вам документ после изменения.

- **Не нужен** — [`updateOne`](../reference/writes/writes.mdx#updateone) или [`updateMany`](../reference/writes/writes.mdx#updatemany). Они дешевле, потому что документ не возвращают.
- **Нужен** — [`findOneAndUpdate`](../reference/writes/writes.mdx#findoneandupdate), а если известен `_id`, то [`findByIdAndUpdate`](../reference/writes/writes.mdx#findbyidandupdate).

Дальше посмотрите, сколько документов вы меняете. Один — `updateOne`, много — `updateMany`. `findOneAndUpdate` всегда меняет один.

## Когда это не нужно

Документ уже в памяти и вы поменяли его поля? Сохраните его через [`$save`](../reference/documents/document-api.mdx#save), он отправит только изменённое, см. [Изменить и сохранить](../documents/change-and-save.mdx). Если документ надо заменить целиком, а не поправить поля, берите [`replaceOne`](../reference/writes/writes.mdx#replaceone), см. [Заменить документ](./replace.mdx). А если новое значение считается из других полей документа, нужен [конвейер](./pipeline-updates.mdx).

## Если что-то пошло не так

**Второй `await` того же обновления падает.** Вот так нельзя.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const query = Accounts.updateOne({ title: "Main" }, { $inc: { balance: 1 } });
await query;
await query;
```

Вторая строка бросит `QueryError: updateOne: this operation was already executed; …`. Каждый объект записи выполняется один раз, ведь повтор почти всегда случаен. Постройте новое обновление. А если повтор нужен намеренно, вызовите [`query.exec({ force: true })`](../reference/writes/writes.mdx#exec).

**Обновление без операторов.** Например, `Accounts.updateOne({ title: "Main" }, { note: "z" })`. Если оно всё же дошло до выполнения, потому что данные пришли снаружи в обход типов, придёт такая ошибка.

```text
QueryError: update: "note" is not an update operator (write { $set: { … } })
```

Пишите `{ $set: { note: "z" } }`. Без оператора база не поймёт, чего вы хотите — записать поле или заменить документ.

**Один путь под двумя операторами.** Например, `{ $inc: { balance: 1 }, $set: { balance: 3 } }`. Сервер такое обновление отвергает, а Typemo замечает это раньше.

```text
QueryError: update: "balance" is changed by $inc and $set (server code 40)
```

Оставьте для пути один оператор.

## Полный пример

Всё вместе в одном файле — пополнение с защитой границы, документ по id из адреса и вставка, если документа нет.

```ts twoslash title="accounts/accounts.service.ts"
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
// Пополнить счёт; false, если такого счёта нет или баланс вышел бы за границу
export const topUp = async (title: string, amount: number): Promise<boolean> => {
  try {
    const result = await Accounts.updateOne({ title }, { $inc: { balance: amount } });
    return result.matchedCount === 1;
  } catch (error) {
    if (error instanceof ValidationError) return false;
    throw error;
  }
};

// Сменить заметку и вернуть документ по id из адреса
export const renameNote = async (id: string, note: string) => {
  return Accounts.findByIdAndUpdate(id, { $set: { note } }).plain();
};

// Сменить владельца счёта или открыть его со стартовым балансом
export const reassignOrOpen = async (title: string, owner: string, amount: number) => {
  await Accounts.updateOne(
    { title },
    { $set: { owner }, $setOnInsert: { balance: amount } },
    { upsert: true },
  );
};
```

<Callout type="migration">

В Mongoose `findOneAndUpdate` по умолчанию возвращал документ до изменения (`new: false`), а `updateOne` с пустым обновлением молча ничего не отправлял. Здесь по умолчанию приходит документ после изменения, а пустое обновление — ошибка. Проверки значений, в Mongoose это `runValidators`, работают всегда, а `$inc` защищает границы `min` и `max` на стороне сервера.

</Callout>
