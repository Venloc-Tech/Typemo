Чтобы заменить документ целиком, вызовите [`replaceOne`](../reference/writes/writes.mdx#replace-one). Вы передаёте новое содержимое, и всё, чего в нём нет, из документа исчезает. `_id` остаётся прежним. Замена нужна, когда новое состояние известно полностью. Например, запись пришла из внешней системы, форма сохраняет всё как есть или вы синхронизируетесь с источником и не знаете, какие поля поменялись.

Если нужно поправить пару полей, а остальные сохранить, замена не подойдёт, берите [обновление](./update.mdx). Замена **удаляет** поля, которые вы не передали, а обновление трогает только названные.

## Что понадобится [#prerequisites]

Клиент из руководства [Подключиться к базе](../connection/connect.mdx). Модель счёта наследует `Timestamped(Entity)`. Этот базовый класс добавляет служебные поля `createdAt` и `updatedAt`, и ядро ведёт их само. В коллекции лежит счёт `Main` — владелец `alice`, баланс 10, теги `a` и `b`, прозвище `al`.

```ts twoslash title="accounts/account.ts"
import { type Defaulted, Entity, Prop, Schema, Timestamped } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Timestamped(Entity) {
  @Prop(() => String, { required: true, unique: true })
  title!: string;

  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => Number, { min: 0, default: 0 })
  balance!: Defaulted<number>;

  @Prop(() => String)
  nickname?: string;
}
```

## Быстрый путь [#quick-start]

Заменить без результата — `replaceOne`, заменить и получить документ — `findOneAndReplace`.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema()
class Line {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "accounts" })
class Account extends Timestamped(Entity) {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => String) alias?: string;
  @Prop(() => Date) lastLogin?: Date;
  @Prop(() => Number) flags?: number;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [Number]) scores!: number[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Spec.map(Number)) counters?: Map<string, number>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const result = await Accounts.replaceOne({ title: "Main" }, { title: "Main", owner: "carol" });
console.log(result.modifiedCount);
// → 1

const account = await Accounts.findOneAndReplace({ title: "Main" }, { title: "Main", owner: "frank" }).plain();
console.log(account?.owner);
// → "frank"
```

Ниже разберём, что именно заменяется, как ведут себя служебные поля и когда замена вредит.

## Заменить документ целиком [#replace-document]

Внешняя система прислала свежее состояние счёта. Вы записываете его целиком, а всё устаревшее должно исчезнуть.

```ts twoslash title="accounts/accounts.service.ts"
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema()
class Line {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "accounts" })
class Account extends Timestamped(Entity) {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => String) alias?: string;
  @Prop(() => Date) lastLogin?: Date;
  @Prop(() => Number) flags?: number;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [Number]) scores!: number[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Spec.map(Number)) counters?: Map<string, number>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
export const syncAccount = async (title: string, owner: string) => {
  const result = await Accounts.replaceOne({ title }, { title, owner });
  return result.modifiedCount === 1;
};
```

Теперь в документе `Main` только `title`, `owner` и значения по умолчанию, то есть `balance: 0`. Поля `tags` и `nickname`, которые там были, **пропали**. Замена не дописывает к старому, а пишет новое поверх. Это главное, что нужно помнить. Забудете в замене необязательное поле — оно исчезнет, и ни компилятор, ни база этого не заметят.

В замене нет операторов, только поля документа. `_id` передавать не надо — компилятор его не примет, а идентификатор и так останется прежним. Фильтр у `replaceOne` обязателен и не может быть пустым, иначе замена выбрала бы случайный документ. Поэтому `{}` не компилируется, а пустой объект во время работы даёт `StrictModeError` с причиной `empty-filter`, подробнее в руководстве [Пустые фильтры в записи](./empty-filters.mdx).

Если под фильтр ничего не подошло, метод не бросает ошибку и возвращает `matchedCount: 0`. Нужна ошибка — добавьте [`.orFail()`](../reference/writes/writes.mdx#or-fail).

## Служебные поля [#system-fields]

Служебные поля `createdAt`, `updatedAt` и `__v` ведёт ядро. При замене `createdAt` и `__v` сохраняются, а `updatedAt` получает время замены. Передавать их не нужно, и бояться, что замена сотрёт историю документа, тоже.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema()
class Line {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "accounts" })
class Account extends Timestamped(Entity) {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => String) alias?: string;
  @Prop(() => Date) lastLogin?: Date;
  @Prop(() => Number) flags?: number;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [Number]) scores!: number[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Spec.map(Number)) counters?: Map<string, number>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const before = await Accounts.findOne({ title: "Main" }).orFail();
await Accounts.replaceOne({ title: "Main" }, { title: "Main", owner: "carol" });
const after = await Accounts.findOne({ title: "Main" }).orFail();
console.log(before.createdAt.getTime() === after.createdAt.getTime());
// → true
console.log(before.updatedAt.getTime() === after.updatedAt.getTime());
// → false
```

Если передать служебное поле самому, замена откажется. Эти поля решает ядро, и подменять их не стоит.

```text
StrictModeError: a replacement of Account carries the service field "createdAt": the core keeps createdAt/__v and bumps updatedAt itself; leave it out [immutable]
```

## Заменить и получить документ [#replace-and-return]

Вы заменили документ и хотите отдать его клиенту. [`findOneAndReplace`](../reference/writes/writes.mdx#find-one-and-replace) заменяет и читает одной командой. По умолчанию он вернёт документ **после** замены, а старое состояние даст `returnDocument: "before"`.

```ts twoslash
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema()
class Line {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "accounts" })
class Account extends Timestamped(Entity) {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => String) alias?: string;
  @Prop(() => Date) lastLogin?: Date;
  @Prop(() => Number) flags?: number;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [Number]) scores!: number[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Spec.map(Number)) counters?: Map<string, number>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const previous = await Accounts.findOneAndReplace(
  { title: "Main" },
  { title: "Main", owner: "gina" },
  { returnDocument: "before" },
).plain();
console.log(previous?.owner);
// → "alice"
```

Как и [`findOneAndUpdate`](../reference/writes/writes.mdx#find-one-and-update), метод принимает `upsert`, и если документа нет, замена вставится как новый документ. Фильтр у `findOneAndReplace` тоже обязателен и не может быть пустым. Метод выбирает документ для замены, и пустой фильтр выбрал бы случайный.

```text
StrictModeError: findOneAndReplace with an empty filter would change or remove an arbitrary document; pass a filter, or Filters.all() to mean every document on purpose [empty-filter]
```

## Как выбрать [#how-to-choose]

Спросите себя, что вы знаете о новом состоянии документа.

- **Знаете его целиком, и всё лишнее должно исчезнуть** — берите замену.
- **Знаете только то, что изменилось** — берите [обновление](./update.mdx). Оно не затрёт поля, которые добавил другой код, и спокойно переживает параллельные изменения, ведь операторы вроде `$inc` не теряют чужих прибавлений.

## Когда это не нужно [#when-not-to-use]

Если вы поменяли одно-два поля, замена только усложнит код и рискует затереть остальное. Берите [`updateOne`](../reference/writes/writes.mdx#update-one) с [`$set`](../reference/writes/update-operators.mdx#set). А если документ уже загружен и изменён в памяти, сохраните его через [`$save`](../reference/documents/document-api.mdx#save), он отправит только изменения.

## Если что-то пошло не так [#troubleshooting]

**После замены пропали поля.** В документе нет `nickname`, `tags` и других полей, которых вы не трогали. Замена пишет ровно то, что вы передали. Передайте в неё все поля, которые должны остаться, или возьмите обновление с `$set` только по изменившимся полям.

**Оператор в замене.** Например, `replaceOne({ title: "Main" }, { $set: { owner: "h" } })`. Операторов замена не понимает, и Typemo её остановит.

```text
QueryError: replacement: "$set" — a replacement has no operators
```

Нужен оператор — значит, это обновление, [`updateOne`](../reference/writes/writes.mdx#update-one). Нужна замена — передайте обычные поля.

**Идентификатор в замене.** Передавать `_id` в замене нельзя, даже тот же самый. Компилятор поле `_id` не примет, а если типы обойдены, Typemo отвергнет замену до отправки.

```text
StrictModeError: a replacement of Account carries "_id": a replacement keeps the stored _id and cannot change it; leave "_id" out and select the document by _id in the filter [immutable]
```

Просто не передавайте `_id`, он останется прежним сам. Нужный документ выбирайте по `_id` в фильтре.

### Замена расходится с полем `immutable` [#replace-immutable]

Пусть у другой модели, `Pinned`, есть обязательное поле `region` и необязательное `code`, оба с `immutable`. Замена переписывает документ целиком, поэтому о таких полях она должна сказать то же, что уже хранится. То же значение, если поле в документе есть, и ничего, если его нет. Что хранится, знает только сервер. Поэтому Typemo добавляет это условие в фильтр замены, и сервер сравнивает значения сам, в той же операции. Расхождение не записывается, а Typemo называет поле.

Нельзя передавать в замене другое значение.

```text
StrictModeError: a replacement of Pinned changes the immutable field "region"; the document was not replaced. Carry the stored value [immutable]
```

Нельзя пропускать поле, которое в документе есть, — замена потеряла бы его.

```text
StrictModeError: a replacement of Pinned without the immutable field "code" would drop it from the stored document; the document was not replaced. Include the stored value, or update the other fields with $set [immutable]
```

И нельзя передавать поле, которого в документе нет. Неизменяемое поле получает значение только при создании документа.

```text
StrictModeError: a replacement of Pinned sets the immutable field "code", which the stored document does not have; the document was not replaced. An immutable field gets its value when the document is created [immutable]
```

Передавайте сохранённое значение, а необязательное поле, которого в документе нет, не передавайте вовсе. Такая замена проходит без лишнего обращения к серверу. Если фильтр не нашёл документ, результат обычный — `matchedCount: 0` или `null`. Только в этом случае Typemo один раз читает документ по вашему фильтру, чтобы отличить «документа нет» от «значение другое». Внутри [транзакции](../transactions/transactions.mdx) это чтение идёт в той же сессии.

Замену с `upsert: true` Typemo проверяет чтением до записи. Такое условие в фильтре `upsert` сервер не принимает, а без проверки расхождение обернулось бы вставкой нового документа. Вне транзакции документ, появившийся между чтением и записью, уже не сравнивается, так что от гонок защищайтесь транзакцией.

Так же, чтением до отправки, проверяется `replaceOne` в [`bulkWrite`](../reference/writes/writes.mdx#bulk-write). В неупорядоченном пакете отвергнутая операция попадает в `writeErrors`, а остальные записываются. Упорядоченный пакет при расхождении не отправляется вовсе.

## Полный пример [#full-example]

Всё вместе в одном файле — синхронизация записи из внешнего источника и получение прежнего состояния.

```ts twoslash title="accounts/accounts.service.ts"
import { BulkWriteError, CastError, type CreateInput, type Defaulted, DocumentNotFoundError, DuplicateKeyError, Entity, Filters, fn, type Immutable, Prop, QueryError, type Replacement, Schema, Spec, StrictModeError, Timestamped, TypemoClient, type Update, type UpdateInput, type UpdatePipelineFor, UpdatePipelines, ValidationError, type WriteValue } from "@venloc/typemo";
@Schema()
class Line {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true }) qty!: number;
}
@Schema({ collection: "accounts" })
class Account extends Timestamped(Entity) {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { min: 0, default: 0 }) balance!: Defaulted<number>;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => String) note?: string;
  @Prop(() => String) nickname?: string;
  @Prop(() => String) alias?: string;
  @Prop(() => Date) lastLogin?: Date;
  @Prop(() => Number) flags?: number;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [Number]) scores!: number[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Spec.map(Number)) counters?: Map<string, number>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
// Записать актуальное состояние счёта из внешней системы
export const syncAccount = async (title: string, owner: string): Promise<boolean> => {
  const result = await Accounts.replaceOne({ title }, { title, owner });
  return result.matchedCount === 1;
};

// Заменить счёт и вернуть то, что в нём было
export const archiveAndReplace = async (title: string, owner: string) => {
  return Accounts.findOneAndReplace({ title }, { title, owner }, { returnDocument: "before" }).plain();
};
```
