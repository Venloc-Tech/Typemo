Половина пользы Typemo — в типах. Опечатку в имени поля, неверное значение в фильтре или лишнее поле в ответе останавливает компилятор. Тест типов закрепляет это обещание. Он падает не во время работы, а при проверке `tsc`, если тип модели или запроса изменился не так, как вы ждали.

Такие тесты ничего не запускают и в базу не ходят, их проверяет только компилятор. Поэтому они быстрые и обходятся без тестовой базы. Пишите их для моделей, на которых держится много кода, и для ответов, которые уходят наружу.

## Что понадобится

Модель счёта ниже и запуск `tsc --noEmit` для файлов с тестами. Сервер, в отличие от [тестов приложения](./testing-apps.mdx), не нужен.

```ts twoslash title="accounts/account.ts"
import { Entity, type Hidden, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Number, { required: true })
  balance!: number;

  @Prop(() => String, { hidden: true })
  pin?: Hidden<string>;
}
```

## Быстрый путь

Нужно уметь сказать «тип A равен типу B» так, чтобы несовпадение не компилировалось. Для этого хватит двух строк без всяких библиотек.

```ts twoslash
type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends <T>() => T extends B ? 1 : 2 ? true : false;
const assertType = <_T extends true>(): void => {};
// ---cut---
assertType<Equal<{ a: number }, { a: number }>>(); // компилируется

// @errors: 2344
assertType<Equal<{ a: number }, { a: string }>>();
```

По тому же принципу работают `expectTypeOf` из `bun:test` и `vitest`, `tsd` и похожие. Если они уже есть в проекте, берите их. Ниже — что именно стоит проверять.

## Проверить тип ответа

Скажем, вы отдаёте счета наружу и хотите закрепить форму ответа. Тип берётся из самого запроса, так что проверяйте то, что получит вызывающий код.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";

@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
  @Prop(() => String, { hidden: true }) pin?: Hidden<string>;
}

type Equal<A, B> = (<T>() => T extends A ? 1 : 2) extends <T>() => T extends B ? 1 : 2 ? true : false;
const assertType = <_T extends true>(): void => {};

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank-test" });
const Accounts = client.db().model(Account);
// ---cut---
const rows = await Accounts.find().select({ title: 1, balance: 1 }).plain();
//    ^?

assertType<Equal<(typeof rows)[number]["title"], string>>();
```

Подсказка `^?` показывает выведенный тип прямо в документации. В вашем тесте на её месте будет утверждение. Проверяйте то, что важно именно вам — что `select` сузил ответ, что скрытое поле `pin` не попало в результат `.plain()`, что `.orFail()` убрал `null`. Всё это делается тем же приёмом.

## Проверить, что неверный код не компилируется

Иногда нужно закрепить обратное — что опечатка в поле остаётся ошибкой. Для этого в тестах пишут `// @ts-expect-error`. Компилятор ждёт ошибку на следующей строке и сам падает, если её там нет.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, TypemoClient } from "@venloc/typemo";

@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "bank-test" });
const Accounts = client.db().model(Account);
// ---cut---
// @errors: 2561
Accounts.find({ balanse: { $gt: 5 } });
```

Какая именно ошибка случилась, директива не проверяет, её устроит любая. Поэтому пишите рядом, чего ждёте («опечатка в имени поля»). И не ставьте `@ts-expect-error` над широким выражением, где упасть могла совсем другая часть.

## Как проверять во время сборки

Кладите файлы тестов типов рядом с обычными и включите их в `tsconfig` или в отдельный `tsconfig.types.json`. В `package.json` добавьте `"typecheck": "tsc --noEmit"` и запускайте его в CI вместе с тестами.

Сам раннер типы не проверяет. `bun test` выполняет код и типы пропускает, так что без `tsc` тест типов ничего не проверит.

## Как выбрать

Спросите себя, **какое обещание должно сломать сборку**.

- **Форма ответа, которую вы отдаёте клиентам** — закрепите её через `Equal`.
- **Запрещённый вызов** — `@ts-expect-error`.
- **Просто «работает»** — хватит обычных тестов.

## Когда это не нужно

Не тестируйте типы самого Typemo и очевидные вещи вроде того, что `string` — это `string`. За это отвечает библиотека. Тесты типов нужны для ваших моделей, ваших публичных ответов и ваших обёрток над запросами.

## Если что-то пошло не так

**Тест типов «проходит», но `tsc` его не видит.** Либо файл не входит в `include` вашего `tsconfig`, либо вы запускаете только `bun test`. Типы проверяет отдельный запуск `tsc --noEmit`.

**`@ts-expect-error` больше не нужен.** Компилятор пишет `Unused '@ts-expect-error' directive` — строка перестала быть ошибкой. Значит, тип стал мягче, чем задумано, и обещание нарушено. Разберитесь в причине, а не удаляйте директиву.
