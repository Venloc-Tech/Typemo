Деньги нельзя хранить обычным дробным числом. `0.1 + 0.2` в JavaScript даёт `0.30000000000000004`, и после тысяч операций такие крошки складываются в расхождение в отчёте. В Typemo есть два точных способа.

- **Целое число копеек** в 64-битном поле `int64`. В схеме это `BigInt`.
- Десятичное число `Decimal128` для величин с дробной частью вроде курса.

Соберём на них банковский счёт с пополнением, переводом между счетами и пересчётом по курсу.

Если вы впервые встречаете BSON-типы, начните со страницы [Типы данных MongoDB](../concepts/bson-types.mdx). Там объяснено, почему `int64` и `Decimal128` не помещаются в JSON и как Typemo их отдаёт.

## Что понадобится

Клиент, подключённый по руководству [Подключиться к базе](../connection/connect.mdx), и база `bank`. Для перевода понадобится транзакция, а значит, реплика-сет — несколько серверов MongoDB с копией одних данных, хотя хватит и одного.

## Быстрый путь

Сумма — это целое число копеек в поле `BigInt`, и прибавляется она оператором `$inc`. Переводить рубли в копейки и обратно приложение должно само. Вот как сумма выглядит на разных этапах.

```ts twoslash
import { type Decimal128 } from "mongodb";
import { Entity, Prop, Schema, Types, TypemoClient, type Defaulted } from "@venloc/typemo";
class __BadRequest__ extends Error {}
class Money {
  static parse(text: string): bigint {
    const match = /^(\d+)(?:\.(\d{1,2}))?$/.exec(text);
    if (!match) throw new __BadRequest__(`"${text}" is not an amount like 12.34`);
    return BigInt(match[1] ?? "0") * 100n + BigInt((match[2] ?? "").padEnd(2, "0"));
  }
  static format(minor: bigint): string {
    const negative = minor < 0n;
    const abs = negative ? -minor : minor;
    return `${negative ? "-" : ""}${abs / 100n}.${String(abs % 100n).padStart(2, "0")}`;
  }
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => BigInt, { min: 0n, default: 0n }) balance!: Defaulted<bigint>;
}
@Schema({ collection: "rates" })
class Rate extends Entity {
  @Prop(() => String, { required: true, unique: true }) pair!: string;
  @Prop(() => Types.Decimal128, { required: true }) value!: Decimal128;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Rates = client.db().model(Rate);
// ---cut---
await Accounts.create({ title: "Main", balance: Money.parse("100.00") });
await Accounts.updateOne({ title: "Main" }, { $inc: { balance: Money.parse("12.34") } });

const account = await Accounts.findOne({ title: "Main" }).plain().orFail();
console.log(account.balance, Money.format(BigInt(account.balance)));
// → "11234" "112.34"
```

Ниже разберём каждый шаг — как разобрать сумму из строки, как не уйти в минус, как сделать перевод и когда вместо `int64` нужен `Decimal128`.

## Хранить сумму целым числом копеек

Поле `balance` имеет тип `BigInt`. В MongoDB это `int64`, целое до 9 223 372 036 854 775 807. Обычное число JavaScript хранит целые точно только до 2⁵³, это около девяти квадриллионов. Для копеек хватило бы и этого, но `int64` даёт запас и не позволяет записать дробь. `1.5` вместо копейки станет ошибкой, а не тихим округлением. Опция `min: 0n` запрещает отрицательный баланс.

```ts twoslash title="accounts/account.ts"
import { type Defaulted, Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true, unique: true })
  title!: string;

  @Prop(() => BigInt, { min: 0n, default: 0n })
  balance!: Defaulted<bigint>;
}
```

Число копеек не должно быть `number`. Поле принимает `bigint` или десятичную строку, и дробь отсекается ещё на уровне типов. Если `number` всё же дошёл до записи, скажем из `any` или чужого JSON, дальше всё зависит от значения. Безопасное целое приводится к `int64`, а дробь и целое больше `Number.MAX_SAFE_INTEGER` дают [`CastError`](../reference/errors/data-errors.mdx#casterror) с подсказкой, как записать число правильно. Тексты ошибок — в разделе «Если что-то пошло не так».

Что вернётся в разных видах результата? Документ и `.lean()` отдают `bigint`, а `.plain()` и JSON — десятичную строку (`"10000"`). Число JavaScript теряет точность выше 2⁵³, а `JSON.stringify` не умеет `bigint`. Таблица форм — на странице [Формы значений](../reference/values/value-forms.mdx#числа-double-int32-и-int64).

## Разобрать и показать сумму

Клиент присылает сумму строкой `"12.34"`, и отдаёте вы её тоже строкой. Перевод между строкой и копейками — код вашего приложения, в Typemo его нет. Соберите его в один класс и разбирайте строго. Три знака после запятой — это ошибка клиента, а не повод округлить.

```ts twoslash title="money/money.ts"
class __BadRequest__ extends Error {}
// ---cut---
export class Money {
  static parse(text: string): bigint {
    const match = /^(\d+)(?:\.(\d{1,2}))?$/.exec(text);
    if (!match) throw new __BadRequest__(`"${text}" is not an amount like 12.34`);
    return BigInt(match[1] ?? "0") * 100n + BigInt((match[2] ?? "").padEnd(2, "0"));
  }

  static format(minor: bigint): string {
    const negative = minor < 0n;
    const abs = negative ? -minor : minor;
    return `${negative ? "-" : ""}${abs / 100n}.${String(abs % 100n).padStart(2, "0")}`;
  }
}
```

`Money.parse("12.3")` даёт `1230n`, `Money.parse("7")` — `700n`, а `Money.format(5n)` — `"0.05"`. Строки `"12.345"`, `"-1"`, `"abc"` и `"1e3"` бросают `__BadRequest__` с текстом `"12.345" is not an amount like 12.34`. Отрицательных сумм клиент не присылает, знак задаёт сама операция — пополнение или списание.

## Пополнить и списать

Прибавляйте и вычитайте оператором [`$inc`](../reference/writes/update-operators.mdx#inc). Не читайте баланс, чтобы посчитать в коде и записать обратно. Два одновременных запроса прочитали бы одно и то же число, и одно изменение потерялось бы. `$inc` выполняется в базе целиком, и гонки нет. Значение он принимает как `bigint` или его десятичную строку.

```ts twoslash title="accounts/accounts.service.ts"
import { type Decimal128 } from "mongodb";
import { Entity, Prop, Schema, Types, TypemoClient, type Defaulted } from "@venloc/typemo";
class __BadRequest__ extends Error {}
class Money {
  static parse(text: string): bigint {
    const match = /^(\d+)(?:\.(\d{1,2}))?$/.exec(text);
    if (!match) throw new __BadRequest__(`"${text}" is not an amount like 12.34`);
    return BigInt(match[1] ?? "0") * 100n + BigInt((match[2] ?? "").padEnd(2, "0"));
  }
  static format(minor: bigint): string {
    const negative = minor < 0n;
    const abs = negative ? -minor : minor;
    return `${negative ? "-" : ""}${abs / 100n}.${String(abs % 100n).padStart(2, "0")}`;
  }
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => BigInt, { min: 0n, default: 0n }) balance!: Defaulted<bigint>;
}
@Schema({ collection: "rates" })
class Rate extends Entity {
  @Prop(() => String, { required: true, unique: true }) pair!: string;
  @Prop(() => Types.Decimal128, { required: true }) value!: Decimal128;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Rates = client.db().model(Rate);
// ---cut---
export const deposit = (title: string, amount: string) =>
  Accounts.updateOne({ title }, { $inc: { balance: Money.parse(amount) } }).orFail();

export const withdraw = (title: string, amount: string) =>
  Accounts.updateOne({ title }, { $inc: { balance: -Money.parse(amount) } }).orFail();
```

Граница `min: 0n` защищает от овердрафта прямо в записи. Если списание больше баланса, [`updateOne`](../reference/writes/writes.mdx#updateone) его отклонит, а документ не изменится. Для счёта со 112.34 на балансе списание 1000.00 даст [`ValidationError`](../reference/errors/data-errors.mdx#validationerror) с текстом `Validation failed: "balance": $inc -100000 on 11234 gives -88766, below the minimum 0; nothing was written [min]`.

А `.orFail()` превращает «счёта нет» в [`DocumentNotFoundError`](../reference/errors/query-errors.mdx#documentnotfounderror). Без него `updateOne` вернул бы `matchedCount: 0`, и пополнение несуществующего счёта выглядело бы успешным.

## Перевести деньги между счетами

Перевод — это две записи, и пройти или не пройти они должны вместе. Для этого нужна транзакция. [`client.transaction`](../reference/transactions/transactions.mdx#transaction) выполняет функцию в общей сессии, и любая ошибка откатывает обе записи. Передавать сессию в каждый вызов не нужно, операции моделей находят её сами. Подробнее — в руководстве [Транзакции](../transactions/transactions.mdx).

```ts twoslash title="accounts/accounts.service.ts"
import { type Decimal128 } from "mongodb";
import { Entity, Prop, Schema, Types, TypemoClient, type Defaulted } from "@venloc/typemo";
class __BadRequest__ extends Error {}
class Money {
  static parse(text: string): bigint {
    const match = /^(\d+)(?:\.(\d{1,2}))?$/.exec(text);
    if (!match) throw new __BadRequest__(`"${text}" is not an amount like 12.34`);
    return BigInt(match[1] ?? "0") * 100n + BigInt((match[2] ?? "").padEnd(2, "0"));
  }
  static format(minor: bigint): string {
    const negative = minor < 0n;
    const abs = negative ? -minor : minor;
    return `${negative ? "-" : ""}${abs / 100n}.${String(abs % 100n).padStart(2, "0")}`;
  }
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => BigInt, { min: 0n, default: 0n }) balance!: Defaulted<bigint>;
}
@Schema({ collection: "rates" })
class Rate extends Entity {
  @Prop(() => String, { required: true, unique: true }) pair!: string;
  @Prop(() => Types.Decimal128, { required: true }) value!: Decimal128;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Rates = client.db().model(Rate);
// ---cut---
export const transfer = (from: string, to: string, amount: string) => {
  const minor = Money.parse(amount);
  return client.transaction(async () => {
    await Accounts.updateOne({ title: from }, { $inc: { balance: -minor } }).orFail();
    await Accounts.updateOne({ title: to }, { $inc: { balance: minor } }).orFail();
  });
};
```

На счёте `Main` лежит 100.00, на `Savings` пусто. После `transfer("Main", "Savings", "30.50")` балансы стали `"6950"` и `"3050"` копеек. Две неудачные попытки ничего не меняют.

Функция транзакции может выполниться повторно при временных сбоях сервера. Поэтому не отправляйте внутри неё письма и не вызывайте внешние платёжные системы. Подробнее — в разделе [Повторы](../reference/transactions/transactions.mdx#повторы).

## Отдать сумму клиенту

Клиенту нужна строка `"69.50"`, а не `"6950"`. Читайте через [`.plain()`](../reference/query/reading.mdx#plain). `balance` в нём — десятичная строка копеек, которую `Money.format` превратит в читаемую сумму, а `JSON.stringify` пропустит без ошибок.

```ts twoslash title="accounts/accounts.service.ts"
import { type Decimal128 } from "mongodb";
import { Entity, Prop, Schema, Types, TypemoClient, type Defaulted } from "@venloc/typemo";
class __BadRequest__ extends Error {}
class Money {
  static parse(text: string): bigint {
    const match = /^(\d+)(?:\.(\d{1,2}))?$/.exec(text);
    if (!match) throw new __BadRequest__(`"${text}" is not an amount like 12.34`);
    return BigInt(match[1] ?? "0") * 100n + BigInt((match[2] ?? "").padEnd(2, "0"));
  }
  static format(minor: bigint): string {
    const negative = minor < 0n;
    const abs = negative ? -minor : minor;
    return `${negative ? "-" : ""}${abs / 100n}.${String(abs % 100n).padStart(2, "0")}`;
  }
}
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true, unique: true }) title!: string;
  @Prop(() => BigInt, { min: 0n, default: 0n }) balance!: Defaulted<bigint>;
}
@Schema({ collection: "rates" })
class Rate extends Entity {
  @Prop(() => String, { required: true, unique: true }) pair!: string;
  @Prop(() => Types.Decimal128, { required: true }) value!: Decimal128;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Rates = client.db().model(Rate);
// ---cut---
export const getBalance = async (title: string) => {
  const account = await Accounts.findOne({ title }).plain().orFail();
  return { title: account.title, balance: Money.format(BigInt(account.balance)) };
};
// getBalance("Main") → { title: "Main", balance: "69.50" }
```

Тип `account.balance` здесь не `string`, а `` `${bigint}` ``. Компилятор знает, что это строка с целым числом, и `BigInt(account.balance)` безопасен. Значение выше 2⁵³ проходит без потерь — счёт с `9007199254740993n` копеек вернётся как `"9007199254740993"`.

## Хранить курс в Decimal128

Курс валюты — величина с дробной частью, и округлить её до копейки нельзя. Например, `92.5031` рубля за доллар. Для таких значений подходит `Decimal128`. Это десятичное число до 34 значащих цифр без двоичных погрешностей.

```ts twoslash title="rates/rate.ts"
import { type Decimal128 } from "mongodb";
import { Entity, Prop, Schema, Types } from "@venloc/typemo";

@Schema({ collection: "rates" })
export class Rate extends Entity {
  @Prop(() => String, { required: true, unique: true })
  pair!: string;

  @Prop(() => Types.Decimal128, { required: true })
  value!: Decimal128;
}
```

В [`create`](../reference/writes/writes.mdx#create) значение можно передать строкой — `Rates.create({ pair: "USD/RUB", value: "92.5031" })`. В прочитанном документе лежит настоящий `Decimal128`, и `rateDoc.value.toString()` даёт `"92.5031"`, а `.plain()` отдаёт строку `"92.5031"`. Строку с посторонними символами Typemo не примет и ответит `Cast to Decimal128 failed at path "value" for "abc" (string): not a decimal number string [format]`.

Арифметики у `Decimal128` в JavaScript нет, поэтому пересчитывайте в целых числах. Разберите строку курса на целое и число знаков и умножайте `bigint`.

```ts twoslash title="money/convert.ts"
// ---cut---
export const convert = (minor: bigint, rate: string): bigint => {
  const [whole = "0", fraction = ""] = rate.split(".");
  const scale = 10n ** BigInt(fraction.length);
  const numerator = BigInt(whole + fraction);
  return (minor * numerator * 2n + scale) / (scale * 2n);
};
// convert(10000n, "92.5031") → 925031n (копейки: 100.00 × 92.5031 = 9250.31)
```

Формула делит с округлением до ближайшего целого. Каждый пересчёт даёт целое число копеек, а не дробь, которую пришлось бы куда-то девать.

## Как выбрать

Спросите себя, **есть ли у значения дробная часть, которую нельзя терять**.

- **Нет, это целое в наименьшей единице**, как суммы на счетах, цены в копейках и остатки, — берите `int64` в копейках. Он быстрее считается в базе, работает с `$inc` и не даёт записать дробь.
- **Да**, как у курсов, процентов, тарифов за единицу с четырьмя знаками и всего, что умножается на суммы, — берите `Decimal128`.

Число с плавающей точкой (`Number`) для денег не годится никогда. Оно не может точно хранить даже `0.1`.

## Когда это не нужно

Если вы храните не деньги, а очки, лайки и счётчики, проще обычный `Number` с `$inc`. Если валют много и у каждой своё число знаков после запятой, как у иены без копеек или у динара с тремя знаками, храните рядом в поле код валюты и число знаков. А суммы держите в `int64` в наименьшей единице каждой валюты.

## Если что-то пошло не так

**Сумма записана дробным числом.** Вы храните `balance: number` и пишете `12.34`. Через пару операций `0.1 + 0.2` разойдётся с ожидаемым. Замените поле на `BigInt` в копейках. Если же в поле `BigInt` попытаться записать дробь, Typemo остановит запись.

```text
CastError: Cast to Long failed at path "balance" for 1.5 (number): a fractional number is not an int64; pass a bigint (5n) or a decimal integer string ("5") [integer]
```

В `$inc` текст тот же, только путь называется `$inc.balance`. Целое больше `Number.MAX_SAFE_INTEGER` приходит уже неточным, и Typemo не гадает, какое число вы имели в виду. Ошибка будет такой — `Cast to Long failed at path "balance" for 9007199254740992 (number): beyond Number.MAX_SAFE_INTEGER the number is already imprecise; pass a bigint (5n) or a decimal integer string ("5") [precision]`. Пишите `9007199254740993n` или `"9007199254740993"`.

**Баланс на клиенте превратился в `NaN`.** Клиент получил `"9007199254740993"` и сделал `Number(balance)`, и значение потеряло последнюю цифру. Переводите строку в `BigInt` через `BigInt(account.balance)`, а не в `number`.

**Списание ушло в минус.** Без `min: 0n` в схеме счёт можно увести ниже нуля. Граница защищает даже от двух одновременных списаний, потому что каждый `$inc` проверяется по актуальному балансу.

С `bulkWrite` будьте внимательны — `$inc` на поле с границей он не принимает и отвечает `ValidationError: Validation failed: "balance": $inc on a field with min/max cannot be guarded in bulkWrite (no per-operation match count tells a failed guard from a missing document); use updateOne/updateMany [min]`. Подробнее — в [`bulkWrite`](../reference/writes/writes.mdx#bulkwrite). Используйте `updateOne` в цикле или в транзакции.

## Полный пример

```ts twoslash title="bank/money.ts"
import { type Decimal128 } from "mongodb";
import { type Defaulted, Entity, Prop, Schema, Types, TypemoClient } from "@venloc/typemo";

export class __BadRequest__ extends Error {}

// money/money.ts: strings ⇄ kopecks (your code, not part of Typemo)
export class Money {
  static parse(text: string): bigint {
    const match = /^(\d+)(?:\.(\d{1,2}))?$/.exec(text);
    if (!match) throw new __BadRequest__(`"${text}" is not an amount like 12.34`);
    return BigInt(match[1] ?? "0") * 100n + BigInt((match[2] ?? "").padEnd(2, "0"));
  }

  static format(minor: bigint): string {
    const negative = minor < 0n;
    const abs = negative ? -minor : minor;
    return `${negative ? "-" : ""}${abs / 100n}.${String(abs % 100n).padStart(2, "0")}`;
  }

  // rounds to the nearest kopeck; the rate is a Decimal128 string such as "92.5031"
  static convert(minor: bigint, rate: string): bigint {
    const [whole = "0", fraction = ""] = rate.split(".");
    const scale = 10n ** BigInt(fraction.length);
    return (minor * BigInt(whole + fraction) * 2n + scale) / (scale * 2n);
  }
}

// models
@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true, unique: true })
  title!: string;

  @Prop(() => BigInt, { min: 0n, default: 0n })
  balance!: Defaulted<bigint>;
}

@Schema({ collection: "rates" })
export class Rate extends Entity {
  @Prop(() => String, { required: true, unique: true })
  pair!: string;

  @Prop(() => Types.Decimal128, { required: true })
  value!: Decimal128;
}

export const client = await TypemoClient.connect("mongodb://localhost:27017/bank");
const Accounts = client.db().model(Account);
const Rates = client.db().model(Rate);

// operations
export const deposit = (title: string, amount: string) =>
  Accounts.updateOne({ title }, { $inc: { balance: Money.parse(amount) } }).orFail();

export const withdraw = (title: string, amount: string) =>
  Accounts.updateOne({ title }, { $inc: { balance: -Money.parse(amount) } }).orFail();

export const transfer = (from: string, to: string, amount: string) => {
  const minor = Money.parse(amount);
  return client.transaction(async () => {
    await Accounts.updateOne({ title: from }, { $inc: { balance: -minor } }).orFail();
    await Accounts.updateOne({ title: to }, { $inc: { balance: minor } }).orFail();
  });
};

export const getBalance = async (title: string) => {
  const account = await Accounts.findOne({ title }).plain().orFail();
  return { title: account.title, balance: Money.format(BigInt(account.balance)) };
};

export const convertBalance = async (title: string, pair: string) => {
  const account = await Accounts.findOne({ title }).plain().orFail();
  const rate = await Rates.findOne({ pair }).plain().orFail();
  return Money.format(Money.convert(BigInt(account.balance), rate.value));
};
```

<Callout type="migration">

В Mongoose деньги часто хранили в `Number` или `Decimal128` с приведением через `mongoose.Types.Decimal128.fromString`, а для `int64` подключали плагин. Здесь `BigInt` — обычный тип поля, и строку принимают все методы записи, так что `Decimal128.fromString` вызывать не нужно.
