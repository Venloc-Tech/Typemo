Поиск в справочном центре состоит из двух частей, и устроены они по-разному. **Текстовый поиск** находит статьи, где встречаются слова запроса, и работает на любом сервере MongoDB. **Поиск по смыслу** находит статьи, близкие по значению, даже без общих слов, как «машина» и «автомобиль». Для него каждая статья превращается в вектор, а сервер ищет ближайшие векторы. Такой поиск есть только в Atlas или в его локальной среде.

Соберём поиск, который использует смысл, когда он доступен, и молча остаётся на тексте, когда нет.

<Callout type="warning">

Векторная часть этого рецепта **не запускалась**. Тестовый сервер документации — не Atlas, а на обычном сервере `$vectorSearch` отвечает ошибкой. Проверены текстовый поиск, объявление поискового индекса (код компилируется), ошибка сервера без Atlas и запасной путь на неё. Результатов настоящего векторного поиска на этой странице нет.

</Callout>

## Что понадобится

- Клиент, подключённый по руководству [Подключиться к базе](../connection/connect.mdx), и база `help`.
- Ваша модель эмбеддингов. Эмбеддинг — это вектор чисел, который описывает смысл текста. В примерах его строит функция `__embed__`.
- Руководство [Полнотекстовый и векторный поиск](../queries/text-and-vector-search.mdx), если хотите знать, как устроены оба вида поиска.

## Быстрый путь

Текстовый поиск — это условие [`$text`](../reference/query/filter-operators.mdx#text) плюс [`.textScore`](../reference/query/search-and-explain.mdx#textscore), который добавляет оценку релевантности. Ему нужен текстовый индекс, описанный декоратором [`@Index`](../reference/schemas/index-decorators.mdx).

```ts twoslash
import { Entity, Index, Prop, Schema, SearchIndex, ServerError, Spec, TypemoClient, type Vector } from "@venloc/typemo";
class __BadRequest__ extends Error {}
declare const __embed__: (text: string) => Promise<number[]>;
@Index({ title: "text", body: "text" })
@SearchIndex({
  name: "embedding_index",
  type: "vectorSearch",
  definition: { fields: [{ type: "vector", path: "embedding", numDimensions: 3, similarity: "cosine" }] },
})
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) embedding?: Vector;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/help");
const Articles = client.db().model(Article);
// ---cut---
await Articles.createIndexes();
await Articles.create({ title: "Typed queries", body: "queries in mongodb" });

const found = await Articles.find({ $text: { $search: "typed" } }).textScore().plain();
console.log(found.map((article) => article.title));
// → ["Typed queries"]
```

Дальше превратим это в настоящий поиск — с проверкой ввода, порядком по релевантности, векторным поиском и запасным путём.

## Описать модель и индексы

У статьи есть название, текст и вектор. Текстовый индекс покрывает название и текст. Векторный поисковый индекс задаёт [`@SearchIndex`](../reference/schemas/index-decorators.mdx) — путь к полю с вектором, размерность и способ сравнения. Размерность должна совпадать с вашей моделью эмбеддингов, а здесь для краткости в векторе три числа.

```ts twoslash title="articles/article.ts"
import { Entity, Index, Prop, Schema, SearchIndex, Spec, type Vector } from "@venloc/typemo";

@Index({ title: "text", body: "text" })
@SearchIndex({
  name: "embedding_index",
  type: "vectorSearch",
  definition: {
    fields: [{ type: "vector", path: "embedding", numDimensions: 3, similarity: "cosine" }],
  },
})
@Schema({ collection: "articles" })
export class Article extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => String, { required: true })
  body!: string;

  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 }))
  embedding?: Vector;
}
```

Индексы создаёт синхронизация, а не запись. Обычные индексы создаёт [`createIndexes`](../reference/collections/model-indexes.mdx), поисковые — [`syncSearchIndexes`](../reference/collections/model-indexes.mdx#modelsyncsearchindexes). На обычном `mongod` второй вызов закончится ошибкой. Поэтому в разработке без Atlas его не вызывайте, для текстового поиска хватит `createIndexes`.

## Проверить запрос

Текст запроса приходит от пользователя. Пустая строка в `$text` — не ошибка, а пустой результат. Без проверки страница «ничего не найдено» спрячет то, что поле поиска было пустым. Слишком длинный запрос тоже лучше отсечь, толку от него нет, а стоит он дорого.

```ts twoslash title="articles/search.service.ts"
class __BadRequest__ extends Error {}
// ---cut---
const cleanQuery = (text: string): string => {
  const query = text.trim();
  if (query === "" || query.length > 200) throw new __BadRequest__("the query must have 1 to 200 characters");
  return query;
};
```

`$text` понимает и служебный синтаксис. `-слово` исключает слово, а кавычки ищут фразу. Это можно разрешить пользователю. Запрос `"queries in" -tips` в тестовой коллекции нашёл только «Typed queries». Если такой синтаксис не нужен, уберите из запроса кавычки и минусы перед поиском.

## Искать по словам и упорядочить по релевантности

`$text` сам результат не упорядочивает, порядок задаёт оценка. Опция `{ sort: true }` у [`.textScore`](../reference/query/search-and-explain.mdx#textscore) сортирует строки по убыванию оценки прямо на сервере. Тогда [`.limit`](../reference/query/reading.mdx#limit) после неё оставит лучшие статьи, а не случайные. Подробнее о сортировке по оценке — в руководстве [Полнотекстовый и векторный поиск](../queries/text-and-vector-search.mdx#отсортировать-по-релевантности).

```ts twoslash title="articles/search.service.ts"
import { Entity, Index, Prop, Schema, SearchIndex, ServerError, Spec, TypemoClient, type Vector } from "@venloc/typemo";
class __BadRequest__ extends Error {}
declare const __embed__: (text: string) => Promise<number[]>;
@Index({ title: "text", body: "text" })
@SearchIndex({
  name: "embedding_index",
  type: "vectorSearch",
  definition: { fields: [{ type: "vector", path: "embedding", numDimensions: 3, similarity: "cosine" }] },
})
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) embedding?: Vector;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/help");
const Articles = client.db().model(Article);
const cleanQuery = (text: string): string => text.trim();
// ---cut---
export const searchByWords = (text: string, limit: number) =>
  Articles.find({ $text: { $search: cleanQuery(text) } })
    .textScore("score", { sort: true })
    .limit(limit)
    .select({ title: 1 })
    .plain();
```

Возьмём две статьи. В «Typed queries» текст «queries in mongodb», а в «Mongo tips» слово «typed» встречается трижды. Запрос `typed` даёт им оценки 0.75 и 1.53125 и ставит «Mongo tips» первой, а `searchByWords("typed", 1)` возвращает только её. Сами числа зависят от данных и версии сервера, поэтому сравнивайте их только между собой.

## Искать по смыслу

Векторный поиск — это стадия [`vectorSearch`](../reference/aggregation/stages.mdx#vectorsearch) в конвейере агрегации. Вы называете индекс, поле с векторами, вектор запроса и число кандидатов. `numCandidates` — это сколько ближайших сервер просмотрит, прежде чем выбрать `limit` лучших. Чем больше кандидатов, тем точнее и тем медленнее.

```ts twoslash title="articles/search.service.ts"
import { Entity, Index, Prop, Schema, SearchIndex, ServerError, Spec, TypemoClient, type Vector } from "@venloc/typemo";
class __BadRequest__ extends Error {}
declare const __embed__: (text: string) => Promise<number[]>;
@Index({ title: "text", body: "text" })
@SearchIndex({
  name: "embedding_index",
  type: "vectorSearch",
  definition: { fields: [{ type: "vector", path: "embedding", numDimensions: 3, similarity: "cosine" }] },
})
@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) embedding?: Vector;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/help");
const Articles = client.db().model(Article);
// ---cut---
export const searchBySense = async (text: string, limit: number) => {
  const queryVector = await __embed__(text);
  return Articles.aggregate((pipeline) =>
    pipeline.vectorSearch({ index: "embedding_index", path: "embedding", queryVector, limit, numCandidates: limit * 10 }),
  ).plain();
};
```

Это единственное место, которое на тестовом сервере не запускалось. Код проверен компилятором, а результат поиска — нет.

## Вернуться к тексту, когда смысла нет

На сервере без Atlas векторный запрос заканчивается [`ServerError`](../reference/errors/server-errors.mdx#servererror) с кодом [`ServerErrorCodes.SearchNotEnabled`](../reference/errors/server-errors.mdx#servererrorcodes) — это 31082, а `codeName` равен `SearchNotEnabled`. В сообщении ошибки причина и код — `Using $search and $vectorSearch aggregation stages requires additional configuration. (code 31082 SearchNotEnabled)`. Полный текст сервера с советом подключиться к Atlas лежит в поле `serverMessage`.

В разработке приложение не должно из-за этого падать. Оно ловит именно эту ошибку и отвечает текстовым поиском. Все остальные ошибки пробрасываются дальше, чтобы сбой сети не выглядел как «поиска по смыслу нет».

```ts twoslash title="articles/search.service.ts"
import { ServerError, ServerErrorCodes } from "@venloc/typemo";
const searchBySense = async (text: string, limit: number): Promise<{ title: string }[]> => [];
const searchByWords = async (text: string, limit: number): Promise<{ title: string }[]> => [];
// ---cut---
export const search = async (text: string, limit = 10): Promise<{ title: string }[]> => {
  try {
    return await searchBySense(text, limit);
  } catch (error) {
    if (error instanceof ServerError && error.code === ServerErrorCodes.SearchNotEnabled) return searchByWords(text, limit);
    throw error;
  }
};
```

Запасной путь на тестовом сервере проверен — `search("typed")` вернул те же статьи, что и `searchByWords`.

## Как выбрать

Спросите себя, **ищут ли пользователи словами, которые есть в тексте**.

- **Да**, как с артикулами, названиями и точными терминами, — хватит текстового поиска, векторный только всё усложнит.
- **Формулировки запросов и текстов расходятся**, как с вопросами к справочнику обычным языком, — нужен поиск по смыслу.

Часто выигрывает сочетание. Текст ловит точные слова, смысл — всё остальное. Склеить два списка с учётом оценок — отдельная задача, для неё в конвейере есть стадии объединения результатов, например [`rankFusion`](../reference/aggregation/stages.mdx#rankfusion).

## Когда это не нужно

Если статей десятки, отфильтруйте их обычным поиском подстроки в коде. Если нужны нечёткий поиск, подсветка и фасеты, вам нужна стадия [`search`](../reference/aggregation/stages.mdx#search) из Atlas Search, а не `$text`. А для точных значений векторный поиск текстовый не заменит — артикул `SKU-4471` по смыслу не найти.

## Если что-то пошло не так

**`text index required for $text query`.** Запрос `$text` выполнили раньше, чем появился текстовый индекс. Вызовите `createIndexes()` при старте или синхронизируйте индексы до первого запроса.

**Лучшие статьи не попадают в результат.** Вы поставили [`.limit`](../reference/query/reading.mdx#limit), но не отсортировали по оценке. Без сортировки порядок строк не определён, и сервер отсёк случайные. Сортируйте по оценке на сервере через `.textScore("score", { sort: true })` или `.sort({ score: -1 })`, как в `searchByWords`.

**Без Atlas приложение падает на `ServerError`.** Вы вызываете векторный поиск без запасного пути или запускаете `syncSearchIndexes` при старте на обычном `mongod`. Ловите ошибку с кодом `ServerErrorCodes.SearchNotEnabled` и не объявляйте `@SearchIndex` на моделях, которые работают без Atlas. На них [`connection.init()`](../reference/connection/connection.mdx#connectioninit) тоже бросит [`SyncError`](../reference/errors/configuration-errors.mdx#syncerror) с тем же текстом сервера в причине.

## Полный пример

```ts twoslash title="articles/search.service.ts"
import {
  Entity,
  Index,
  Prop,
  Schema,
  SearchIndex,
  ServerError,
  ServerErrorCodes,
  Spec,
  TypemoClient,
  type Vector,
} from "@venloc/typemo";

export class __BadRequest__ extends Error {}
// your code: turns a text into a vector (an embedding model)
declare const __embed__: (text: string) => Promise<number[]>;

// articles/article.ts
@Index({ title: "text", body: "text" })
@SearchIndex({
  name: "embedding_index",
  type: "vectorSearch",
  definition: { fields: [{ type: "vector", path: "embedding", numDimensions: 3, similarity: "cosine" }] },
})
@Schema({ collection: "articles" })
export class Article extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => String, { required: true })
  body!: string;

  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 }))
  embedding?: Vector;
}

export const client = await TypemoClient.connect("mongodb://localhost:27017/help");
const Articles = client.db().model(Article);

// the query comes from a user
const cleanQuery = (text: string): string => {
  const query = text.trim();
  if (query === "" || query.length > 200) throw new __BadRequest__("the query must have 1 to 200 characters");
  return query;
};

// by words: works on any server; the best matches first, sorted by the server
export const searchByWords = (text: string, limit: number) =>
  Articles.find({ $text: { $search: cleanQuery(text) } })
    .textScore("score", { sort: true })
    .limit(limit)
    .select({ title: 1 })
    .plain();

// by sense: Atlas only (not run on the test server)
export const searchBySense = async (text: string, limit: number) => {
  const queryVector = await __embed__(cleanQuery(text));
  return Articles.aggregate((pipeline) =>
    pipeline.vectorSearch({ index: "embedding_index", path: "embedding", queryVector, limit, numCandidates: limit * 10 }),
  ).plain();
};

// sense first, words when the server cannot search by sense
export const search = async (text: string, limit = 10): Promise<{ title: string }[]> => {
  try {
    return await searchBySense(text, limit);
  } catch (error) {
    if (error instanceof ServerError && error.code === ServerErrorCodes.SearchNotEnabled) return searchByWords(text, limit);
    throw error;
  }
};
```

<Callout type="migration">

В Mongoose `$text` и `$vectorSearch` работали через `find` и `aggregate` без проверки индексов и типов вектора, а ошибка «нет Atlas» приходила общим `MongoServerError`. Здесь вектор объявляется типом `Vector` с размерностью, а ошибка сервера приходит классом `ServerError` с кодом, по которому её легко поймать.

</Callout>
