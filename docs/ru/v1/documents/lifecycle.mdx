Документ в Typemo бывает в одном из четырёх состояний.

- **Новый** — создан в памяти, в базе его ещё нет.
- **Загруженный** — совпадает с тем, что лежит в базе.
- **Изменённый** — в памяти есть правки, которых в базе нет.
- **Удалённый** — запись из базы убрана.

От состояния зависит, что сделает [`$save`](../reference/documents/document-api.mdx#save). Он вставит документ, обновит его, ничего не отправит или откажется работать. Зная состояния, легко понять, почему `$save` нового документа делает вставку, `$save` прочитанного — короткое обновление, а удалённый документ сохранить нельзя. Состояние можно узнать прямо в коде через [`$isNew`](../reference/documents/document-api.mdx#is-new) и [`$isModified`](../reference/documents/document-api.mdx#is-modified).

## Что понадобится [#prerequisites]

Заказ из руководства [Изменить и сохранить документ](./change-and-save.mdx) и подключение из руководства [Подключиться к базе](../connection/connect.mdx).

## Быстрый путь [#quick-start]

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = Orders.new({ customer: "alice", tags: [], lines: [] }); // новый
console.log(order.$isNew(), order.$isModified());
// → true true

await order.$save(); // загруженный
console.log(order.$isNew(), order.$isModified());
// → false false

order.customer = "bob"; // изменённый
console.log(order.$isNew(), order.$isModified());
// → false true

await order.$deleteOne(); // удалённый
```

## Создать новый документ [#create-document]

[`Model.new`](../reference/documents/model-document-methods.mdx#model.new) создаёт документ в памяти. Значения по умолчанию уже подставлены, `_id` выдан, каждое поле приведено к своему типу. В базе документа пока нет.

Типы приводятся сразу, поэтому неверный тип или неизвестный ключ дадут [`CastError`](../reference/errors/data-errors.mdx#cast-error) прямо на вызове `new`. А обязательность и правила проверяются позже, при [`$save`](../reference/documents/document-api.mdx#save) или [`$validate`](../reference/documents/document-api.mdx#validate).

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = Orders.new({ customer: "alice", tags: [], lines: [] });
console.log(order.$isNew(), order.__v, order._id.constructor.name);
// → true undefined "ObjectId"

await order.$save();
console.log(order.__v);
// → 0
```

Поле версии `__v` у нового документа не задано, его выставит вставка. Если сохранённый документ нужен сразу, берите [`create`](../reference/writes/writes.mdx#create) — он делает то же самое одной строкой.

## Прочитать существующий документ [#read-existing-document]

Всё, что вы читаете запросами без [`.lean()`](../reference/query/reading.mdx#lean) и [`.plain()`](../reference/query/reading.mdx#plain), приходит загруженным. `$isNew()` равен `false`, изменений нет. Документ помнит своё исходное состояние и сравнивает себя с ним при каждой проверке изменений.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const created = await Orders.create({ customer: "alice", tags: ["gift"], lines: [] });
// ---cut---
const order = await Orders.findById(created._id).orFail();
console.log(order.$isNew(), order.$isModified());
// → false false
```

## Изменить и сохранить [#change-and-save]

Любое изменение делает документ изменённым, а успешный [`$save`](../reference/documents/document-api.mdx#save) снова делает его загруженным. Если вы вернули значение к прежнему, документ опять не считается изменённым. Typemo сравнивает значения, а не запоминает присваивания. Подробности — в руководстве [Изменить и сохранить документ](./change-and-save.mdx).

## Оживить данные, прочитанные не через Typemo [#hydrate-external]

Данные бывают из кеша, из очереди сообщений или прямо из драйвера. [`Model.hydrate`](../reference/documents/model-document-methods.mdx#model.hydrate) превращает такой объект в загруженный документ с типизированными коллекциями. Метод верит, что данные — ровно то, что лежит в базе. Он их не приводит и не проверяет, а имена полей принимает в том виде, в каком они хранятся в базе.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
import { ObjectId } from "mongodb";
// ---cut---
const order = Orders.hydrate({ _id: new ObjectId(), customer: "alice", tags: ["gift"], lines: [], __v: 0 });
console.log(order.$isNew(), order.$isModified(), order.tags.constructor.name);
// → false false "StrictArray"

order.customer = "bob";
console.log(order.$getChanges());
// → { $set: { customer: "bob" } }
```

Массив тегов здесь — [`StrictArray`](../reference/documents/typed-collections.mdx#strict-array). `constructor.name` называет публичный тип коллекции, так что по имени класса видно, что массив типизированный, а не обычный `Array`. Массив поддокументов называется `SubdocumentArray`, а `Map` — `TypedMap`.

Если документа с таким `_id` в базе нет, `hydrate` всё равно его создаст. Но `$save` записи не найдёт и бросит [`DocumentNotFoundError`](../reference/errors/query-errors.mdx#document-not-found-error).

```text
DocumentNotFoundError: Order.save: the document is no longer in the collection (deleted since it was read, or out of the scope of the operation's policies); nothing was written
```

## Удалить документ [#delete-document]

[`$deleteOne`](../reference/documents/document-api.mdx#delete-one) убирает запись из базы и помечает документ удалённым. Такой документ нельзя ни сохранить, ни удалить второй раз. Это ошибки, а не тихие пустые операции, ведь обычно они значат, что вы работаете с устаревшим объектом.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: [], lines: [] });
await order.$deleteOne();

try {
  order.customer = "bob";
  await order.$save();
} catch (error) {
  console.log(error instanceof Error && error.message);
  // → "save: the document of Order was deleted"
}
```

## Как выбрать [#how-to-choose]

Спросите себя, **откуда у вас данные**.

- **Вы создаёте запись** — [`Model.new`](../reference/documents/model-document-methods.mdx#model.new) и потом `$save` или сразу [`create`](../reference/writes/writes.mdx#create).
- **Читаете из базы** — запрос сам вернёт загруженные документы.
- **Данные пришли откуда-то ещё, а нужны `$`-методы** — [`Model.hydrate`](../reference/documents/model-document-methods.mdx#model.hydrate).
- **Нужен только ответ клиенту** — документ не нужен вовсе, берите [`.plain()`](../reference/query/reading.mdx#plain).

## Когда это не нужно [#when-not-to-use]

Если вы не собираетесь менять и сохранять данные, а только отдаёте их, документ ни к чему, он тяжелее обычного объекта. Читайте через [`.plain()`](../reference/query/reading.mdx#plain) или [`.lean()`](../reference/query/reading.mdx#lean). Для массовых изменений берите [`updateMany`](../reference/writes/writes.mdx#update-many), а не цикл по документам.

## Если что-то пошло не так [#troubleshooting]

**Сохраняется не тот документ, что задумано.** После `Model.hydrate` документ считается существующим. Если вы оживили данные, которых в базе нет, и вызвали `$save`, будет `DocumentNotFoundError`, а не вставка. Для несуществующих данных используйте [`Model.new`](../reference/documents/model-document-methods.mdx#model.new).

**Сохранение после удаления.**

```text
QueryError: save: the document of Order was deleted
```

Создайте новый документ через `Model.new` или прочитайте актуальный.

## Полный пример [#full-example]

```ts twoslash title="orders/orders.service.ts"
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
export const openOrder = async (customer: string) => {
  const order = Orders.new({ customer, tags: [], lines: [] });
  await order.$save();
  return order._id;
};

export const renameCustomer = async (orderId: Order["_id"], customer: string) => {
  const order = await Orders.findById(orderId).orFail();
  order.customer = customer;
  await order.$save();
};

export const cancelOrder = async (orderId: Order["_id"]) => {
  const order = await Orders.findById(orderId).orFail();
  await order.$deleteOne();
};
```

## Если вы пришли из Mongoose [#from-mongoose]

<Callout type="migration">

`new Model(data)` здесь называется `Model.new(data)`, а `doc.isNew` стал методом `doc.$isNew()`. `Model.hydrate` есть и в Mongoose. В Typemo он принимает данные в форме базы, с именами полей базы, и отклоняет всё, что не обычный объект.

</Callout>
