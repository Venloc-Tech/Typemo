Чтобы отдать документ клиенту или положить его в кеш, превратите его в обычные данные. Способов три.

- [`$toPlain()`](../reference/documents/document-api.mdx#toplain) — для ответа API.
- [`$toJSON()`](../reference/documents/document-api.mdx#tojson) — для строгого JSON.
- [`$toObject()`](../reference/documents/document-api.mdx#toobject) — для работы с данными внутри приложения.

Все три возвращают копию, которая с документом уже не связана.

Сам документ отдавать нельзя, и дело не только в служебных методах. В нём лежат значения MongoDB, которых в JSON нет, — идентификаторы `ObjectId`, целые int64 (`bigint`), `Decimal128`, байты. Если отправить их как есть, `bigint` сломает `JSON.stringify`, а `ObjectId` превратится во что-то неожиданное. Три метода решают эту задачу по-разному, и каждый сам выбирает, какие типы превратить в строки, а какие оставить.

## Что понадобится

Подключение из руководства [Подключиться к базе](../connection/connect.mdx) и счёт `Invoice`. У счёта есть покупатель, дата выдачи, баллы в int64, теги, `Map` сборов, скрытая заметка, скидка с функцией `get` и вычисляемое поле `label`.

```ts twoslash title="models/invoice.ts"
import { type Computed, Entity, type Hidden, Prop, Schema, Spec, Versioned } from "@venloc/typemo";

@Schema({ collection: "invoices" })
export class Invoice extends Versioned(Entity) {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => Date)
  issuedAt?: Date;

  @Prop(() => BigInt)
  points?: bigint;

  @Prop(() => [String])
  tags!: string[];

  @Prop(() => Spec.map(Number))
  fees?: Map<string, number>;

  @Prop(() => String, { hidden: true })
  note?: Hidden<string>;

  @Prop(() => Number, { get: (value: number) => Math.round(value) })
  discount?: number;

  get label(): Computed<string> {
    return `${this.customer}#${this.tags.length}` as Computed<string>;
  }
}
```

В базе один счёт.

- Покупатель `alice`, выдан `2026-01-02T03:04:05Z`.
- 9007199254740993 баллов — на единицу больше границы точных чисел JavaScript.
- Тег `gift` и сбор `delivery` на 5.
- Заметка `call first` и скидка 2,6.

## Быстрый путь

```ts twoslash
import { type Computed, Entity, type Hidden, Mask, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ collection: "invoices" })
class Invoice extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => Date) issuedAt?: Date;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
  @Prop(() => Number, { get: (value: number) => Math.round(value) }) discount?: number;
  get label(): Computed<string> {
    return `${this.customer}#${this.tags.length}` as Computed<string>;
  }
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Invoices = client.db().model(Invoice);
const invoice = await Invoices.findOne({ customer: "alice" }).orFail();
// ---cut---
const plain = invoice.$toPlain(); // для ответа API и кеша
const json = invoice.$toJSON(); // строгий JSON
const data = invoice.$toObject(); // данные с типами MongoDB
console.log(typeof plain.points, typeof json.issuedAt, typeof data.points);
// → "string" "string" "bigint"
```

`JSON.stringify(invoice)` сам вызывает [`$toJSON`](../reference/documents/document-api.mdx#tojson), так что документ можно отдать и напрямую. Ниже разберём, чем отличаются формы и как этим пользоваться.

## Отдать данные в ответе API

Для ответа клиенту берите [`$toPlain`](../reference/documents/document-api.mdx#toplain). Идентификаторы, int64, `Decimal128` и UUID становятся строками, а родные типы JavaScript вроде `Date` и `Map` остаются. Такой результат можно смело отдавать в `JSON.stringify`. `bigint` в нём не встретится, а число баллов не потеряет точности.

```ts twoslash
import { type Computed, Entity, type Hidden, Mask, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ collection: "invoices" })
class Invoice extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => Date) issuedAt?: Date;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
  @Prop(() => Number, { get: (value: number) => Math.round(value) }) discount?: number;
  get label(): Computed<string> {
    return `${this.customer}#${this.tags.length}` as Computed<string>;
  }
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Invoices = client.db().model(Invoice);
const invoice = await Invoices.findOne({ customer: "alice" }).orFail();
// ---cut---
const plain = invoice.$toPlain();
//    ^?
console.log(typeof plain._id, plain.points, plain.issuedAt instanceof Date, plain.fees instanceof Map);
// → "string" "9007199254740993" true true
```

Обратите внимание, `points` стал строкой `"9007199254740993"`, а не числом. Число больше 2⁵³ JavaScript хранит неточно, и клиент получил бы другое значение без всякой ошибки. Строка хранит значение точно, и Typemo примет её обратно в `create`, `update` и фильтрах.

Если нужен настоящий JSON, где нет ни `Date`, ни `Map`, берите [`$toJSON`](../reference/documents/document-api.mdx#tojson). Дата станет ISO-строкой, а `Map` — обычным объектом.

```ts twoslash
import { type Computed, Entity, type Hidden, Mask, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ collection: "invoices" })
class Invoice extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => Date) issuedAt?: Date;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
  @Prop(() => Number, { get: (value: number) => Math.round(value) }) discount?: number;
  get label(): Computed<string> {
    return `${this.customer}#${this.tags.length}` as Computed<string>;
  }
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Invoices = client.db().model(Invoice);
const invoice = await Invoices.findOne({ customer: "alice" }).orFail();
// ---cut---
const json = invoice.$toJSON();
//    ^?
console.log(json.issuedAt, json.fees);
// → "2026-01-02T03:04:05.000Z" { delivery: 5 }
```

Какой тип у каждого значения в каждой форме, показывает таблица. Она строится прямо из кода библиотеки.

<ValueForms types={["objectId", "long", "decimal128", "date", "map"]} forms={["hydrated", "object", "plain", "json"]} />

## Работать с данными внутри приложения

[`$toObject`](../reference/documents/document-api.mdx#toobject) возвращает значения MongoDB как есть. `ObjectId` остаётся `ObjectId`, int64 — `bigint`, `Map` — `Map`. Это удобно, когда данные не покидают приложение, например чтобы сравнить их или передать в другую операцию с базой. А вот в `JSON.stringify` такой результат отдавать нельзя.

```text
TypeError: JSON.stringify cannot serialize BigInt.
```

Для этого берите [`$toPlain`](../reference/documents/document-api.mdx#toplain) или [`$toJSON`](../reference/documents/document-api.mdx#tojson).

### Вывести документ в консоль

`console.log` и `util.inspect` показывают документ и поддокумент в читаемом виде. Вы увидите имя класса и данные такими, какими их отдал бы `$toObject`, без служебного содержимого вроде родителя и журнала изменений. Скрытые поля (`hidden`) в этот вывод не попадают, даже если загружены, так что документ можно спокойно печатать в журнал. Всё это работает только при выводе и не замедляет создание, чтение и сохранение.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, type Hidden } from "@venloc/typemo";
@Schema({ collection: "invoices" })
class Invoice extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Invoices = client.db().model(Invoice);
// ---cut---
const invoice = await Invoices.create({ customer: "alice", tags: ["gift"], fees: new Map([["ship", 5]]), note: "secret" });
console.log(invoice);
// → Invoice { _id: new ObjectId("…"), customer: "alice", tags: ["gift"], fees: Map(1) { "ship" => 5 } }
```

Поля `note` в выводе нет, хотя документ его хранит. О скрытых полях подробнее в разделе [Не отдать скрытые поля](#не-отдать-скрытые-поля).

## Не отдать скрытые поля

Поля с `hidden`, как заметка в примере, не должны попадать к клиенту. Поэтому [`$toPlain`](../reference/documents/document-api.mdx#toplain) и [`$toJSON`](../reference/documents/document-api.mdx#tojson) по умолчанию их не включают. [`$toObject`](../reference/documents/document-api.mdx#toobject) включает, он для внутренней работы. К тому же скрытое поле часто не загружено вовсе. По умолчанию запрос его не читает, и в выборку его добавляют явно.

```ts twoslash
import { type Computed, Entity, type Hidden, Mask, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ collection: "invoices" })
class Invoice extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => Date) issuedAt?: Date;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
  @Prop(() => Number, { get: (value: number) => Math.round(value) }) discount?: number;
  get label(): Computed<string> {
    return `${this.customer}#${this.tags.length}` as Computed<string>;
  }
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Invoices = client.db().model(Invoice);
const invoice = await Invoices.findOne({ customer: "alice" }).select({ "+note": true }).orFail();
// ---cut---
console.log("note" in invoice.$toPlain(), "note" in invoice.$toObject());
// → false true

console.log(invoice.$toPlain({ hidden: true }).note);
// → "call first"
```

`hidden` действует на любой глубине — в поддокументах, массивах и `Map` поддокументов.

## Добавить вычисляемые поля и применить get

Вычисляемые поля класса (геттеры `Computed`) попадают в результат, только если попросить через `virtuals: true`. Функции `get` полей применяются только с `getters: true`.

```ts twoslash
import { type Computed, Entity, type Hidden, Mask, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ collection: "invoices" })
class Invoice extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => Date) issuedAt?: Date;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
  @Prop(() => Number, { get: (value: number) => Math.round(value) }) discount?: number;
  get label(): Computed<string> {
    return `${this.customer}#${this.tags.length}` as Computed<string>;
  }
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Invoices = client.db().model(Invoice);
const invoice = await Invoices.findOne({ customer: "alice" }).orFail();
// ---cut---
console.log(invoice.$toPlain({ virtuals: true }).label, "label" in invoice.$toPlain());
// → "alice#1" false

console.log(invoice.$toObject().discount, invoice.$toObject({ getters: true }).discount);
// → 2.6 3
```

## Замаскировать значения

Если нужно отдать часть значения, а не убрать поле целиком, используйте опцию `mask`. Её ключи — пути результата, а значения — `"mask"` (подставится `"?"`) или готовая маска из [`Mask`](../reference/query/masks.mdx#mask). Маска применяется к копии, так что документ и следующий `$save` она не трогает.

```ts twoslash
import { type Computed, Entity, type Hidden, Mask, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ collection: "invoices" })
class Invoice extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => Date) issuedAt?: Date;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
  @Prop(() => Number, { get: (value: number) => Math.round(value) }) discount?: number;
  get label(): Computed<string> {
    return `${this.customer}#${this.tags.length}` as Computed<string>;
  }
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Invoices = client.db().model(Invoice);
const invoice = await Invoices.findOne({ customer: "alice" }).orFail();
// ---cut---
const masked = invoice.$toPlain({ mask: { customer: Mask.initials(), points: "mask" } });
console.log(masked.customer, masked.points, invoice.customer);
// → "a." "?" "alice"
```

Маску с неверным путём отвергнет компилятор. В коде без типов путь, которого нет в результате, тоже не пройдёт. Метод бросит ошибку, а не оставит значение незамаскированным.

## Превратить результат во что-то своё

Опция `transform` принимает функцию, и результат этой функции становится результатом метода. Она применяется после маски.

```ts twoslash
import { type Computed, Entity, type Hidden, Mask, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ collection: "invoices" })
class Invoice extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => Date) issuedAt?: Date;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
  @Prop(() => Number, { get: (value: number) => Math.round(value) }) discount?: number;
  get label(): Computed<string> {
    return `${this.customer}#${this.tags.length}` as Computed<string>;
  }
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Invoices = client.db().model(Invoice);
const invoice = await Invoices.findOne({ customer: "alice" }).orFail();
// ---cut---
const summary = invoice.$toJSON({ transform: (json) => `${json.customer}: ${json.tags.length} tag(s)` });
console.log(summary);
// → "alice: 1 tag(s)"
```

## Как выбрать

Спросите себя, **куда попадут данные после метода**.

- **За пределы приложения** — в ответ API, в очередь сообщений, в кеш — берите `$toPlain` или `$toJSON`. В них нет `bigint`, а скрытые поля выключены. `$toPlain` оставляет даты и `Map`, а `$toJSON` всё делает строго по правилам JSON.
- **Остаются в приложении, и вы будете с ними работать** — сравнивать `ObjectId`, считать в `bigint`, — берите `$toObject`.

## Когда это не нужно

Если документ нужен только для ответа и менять его вы не будете, не загружайте его вовсе. [`.plain()`](../reference/query/reading.mdx#plain) у запроса сразу вернёт обычные объекты, готовые для клиента, без создания документа. А [`.lean()`](../reference/query/reading.mdx#lean) вернёт данные так, как их отдал драйвер. Так быстрее, и скрытые поля даже не читаются из базы.

## Если что-то пошло не так

**`JSON.stringify` падает на больших числах.** Вы отдали в `JSON.stringify` результат `$toObject`, а в нём `bigint`.

```text
TypeError: JSON.stringify cannot serialize BigInt.
```

Используйте [`$toPlain`](../reference/documents/document-api.mdx#toplain) или [`$toJSON`](../reference/documents/document-api.mdx#tojson), либо `JSON.stringify(document)`.

**В ответе нет скрытого поля, а оно нужно.** `$toPlain` и `$toJSON` не включают `hidden`-поля. Если нужна заметка, передайте `{ hidden: true }` и убедитесь, что поле загружено через `select({ "+note": true })`. Незагруженного поля нет ни в одной форме.

**`$toJSON` отказывает на `NaN`.** Сам Typemo не запишет в поле `NaN` или `Infinity` и ответит `CastError: Cast to number failed at path "ratio" for NaN (number): NaN and Infinity are not allowed [finite]`. Но другая программа могла записать их в базу. После чтения они остаются числами в результатах `.lean()` и `.plain()` и в `$toPlain`. JSON таких чисел не знает, поэтому `$toJSON()` и `JSON.stringify(document)` отвечают ошибкой, а не тихим `null`.

```text
CastError: Cast to JSON number failed at path "ratio" for NaN (number): JSON has no NaN or Infinity [json]
```

Само по себе сохранённое `NaN` документ не «изменяет». При сравнении с прочитанным значением `NaN` считается равным `NaN`, поэтому `$isModified()` остаётся `false`, а `$getChanges()` пуст. Подробнее — в [Изменениях и сохранении](./change-and-save.mdx).

Есть и обратная сторона. `JSON.stringify(document.$toPlain())` не откажет, а молча превратит `NaN` в `null`. Если такие данные возможны, проверяйте поле до сериализации или почините данные миграцией.

**Маска отвергнута, потому что такого пути нет.** `mask: { nope: "mask" }` в коде без типов не маскирует ничего. Поэтому метод отвечает ошибкой, а не отдаёт значение как есть — `StrictModeError: mask: "nope" is not a path of Invoice's rows, so it would mask nothing; name a field of the rows [unknown-path]`. В коде с проверкой типов такой путь раньше отклонит компилятор.

## Полный пример

```ts twoslash title="invoices/invoices.service.ts"
import { type Computed, Entity, type Hidden, Mask, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ collection: "invoices" })
class Invoice extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => Date) issuedAt?: Date;
  @Prop(() => BigInt) points?: bigint;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
  @Prop(() => Number, { get: (value: number) => Math.round(value) }) discount?: number;
  get label(): Computed<string> {
    return `${this.customer}#${this.tags.length}` as Computed<string>;
  }
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Invoices = client.db().model(Invoice);
// ---cut---
export const getInvoiceForClient = async (customer: string) => {
  const invoice = await Invoices.findOne({ customer }).orFail();
  return invoice.$toJSON({ virtuals: true, mask: { customer: Mask.initials() } });
};

export const getInvoiceForAdmin = async (customer: string) => {
  const invoice = await Invoices.findOne({ customer }).select({ "+note": true }).orFail();
  return invoice.$toPlain({ hidden: true, virtuals: true });
};
```

## Если вы пришли из Mongoose

<Callout type="migration">

`doc.toObject()` и `doc.toJSON()` здесь называются `$toObject()` и `$toJSON()`. Добавился `$toPlain()` — форма, где значения MongoDB стали строками, а `Date` и `Map` остались. Настроек сериализации на уровне схемы вроде `toJSON: { virtuals: true }` нет, опции передаются при каждом вызове. Скрытые поля по умолчанию исключаются из `$toJSON` и `$toPlain`.

</Callout>
