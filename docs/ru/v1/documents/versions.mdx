Два клиента одновременно прочитали один документ, и оба его сохранили. Победит тот, кто сохранил последним, а правка первого молча пропадёт. Чтобы такого не было, Typemo ведёт в документе **версию** — число в поле `__v` — и сверяет её при сохранении. Если документ изменили после вашего чтения, [`$save`](../reference/documents/document-api.mdx#save) не затрёт чужую правку, а бросит [`VersionError`](../reference/errors/query-errors.mdx#version-error).

Версию включает базовый класс `Versioned`, и режимов у неё два. По умолчанию она защищает изменения **массивов по позиции**. Опция схемы `optimisticConcurrency` защищает **любое** изменение. У документа без `Versioned` версии нет, и защиты тоже.

## Что понадобится [#prerequisites]

Главный пример заказа — он наследует `Versioned`, так что массивы защищены, — и счёт `Ledger` с включённой `optimisticConcurrency`. Основы изменения документа — в руководстве [Изменить и сохранить документ](./change-and-save.mdx).

```ts twoslash title="models/ledger.ts"
import { Entity, Prop, Schema, Versioned } from "@venloc/typemo";

@Schema({ collection: "ledgers", optimisticConcurrency: true })
export class Ledger extends Versioned(Entity) {
  @Prop(() => String, { required: true })
  owner!: string;

  @Prop(() => Number, { required: true })
  balance!: number;
}
```

## Быстрый путь [#quick-start]

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, VersionError, Versioned } from "@venloc/typemo";
@Schema({ collection: "ledgers", optimisticConcurrency: true })
class Ledger extends Versioned(Entity) {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Ledgers = client.db().model(Ledger);
// ---cut---
const created = await Ledgers.create({ owner: "ann", balance: 10 });
const first = await Ledgers.findById(created._id).orFail();
const second = await Ledgers.findById(created._id).orFail();

first.balance = 20;
await first.$save();
console.log(first.__v);
// → 1

second.balance = 30;
await second.$save().catch((error) => console.log(error instanceof VersionError));
// → true
```

Второй клиент не перезаписал баланс молча, а получил ошибку. Ниже разберём, что в ней лежит, как повторить операцию и когда версия работает без `optimisticConcurrency`.

## Поймать конфликт [#catch-conflict]

Ошибка называет модель, версию, которую вы прочитали, и изменённые пути. В базе остаётся то, что записал первый клиент.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, VersionError, Versioned } from "@venloc/typemo";
@Schema({ collection: "ledgers", optimisticConcurrency: true })
class Ledger extends Versioned(Entity) {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Ledgers = client.db().model(Ledger);
const created = await Ledgers.create({ owner: "ann", balance: 10 });
const first = await Ledgers.findById(created._id).orFail();
const second = await Ledgers.findById(created._id).orFail();
first.balance = 20;
await first.$save();
second.balance = 30;
// ---cut---
try {
  await second.$save();
} catch (error) {
  if (error instanceof VersionError) {
    console.log(error.version, error.modifiedPaths);
    // → 0 ["balance"]
  }
}
```

```text
VersionError: Ledger: no document at version 0 (it was changed or deleted since it was read); modified: balance
```

В сообщении сказано «изменён или удалён», потому что по версии одно от другого не отличить. Если документ действительно удалили, Typemo выяснит это одним дополнительным чтением и вместо `VersionError` бросит [`DocumentNotFoundError`](../reference/errors/query-errors.mdx#document-not-found-error).

```text
DocumentNotFoundError: Ledger.save: the document is no longer in the collection (deleted since it was read, or out of the scope of the operation's policies); nothing was written
```

## Повторить операцию [#retry-operation]

На `VersionError` правильно реагировать так — прочитать документ заново, применить изменение к свежему состоянию и сохранить снова. Слепо повторять сохранение старого документа нельзя, в нём по-прежнему устаревшая версия.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, VersionError, Versioned } from "@venloc/typemo";
@Schema({ collection: "ledgers", optimisticConcurrency: true })
class Ledger extends Versioned(Entity) {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Ledgers = client.db().model(Ledger);
// ---cut---
export const deposit = async (ledgerId: Ledger["_id"], amount: number) => {
  for (let attempt = 0; attempt < 3; attempt++) {
    const ledger = await Ledgers.findById(ledgerId).orFail();
    ledger.balance += amount;
    try {
      await ledger.$save();
      return ledger.balance;
    } catch (error) {
      if (!(error instanceof VersionError)) throw error;
    }
  }
  throw new Error("the ledger is busy, try again later");
};
```

Число попыток ограничено. Если конфликты повторяются, лучше сообщить об этом, чем крутиться бесконечно. А счётчики, которые меняют многие клиенты, надёжнее менять атомарным `$inc` через [`updateOne`](../reference/writes/writes.mdx#update-one). Он не конфликтует вовсе.

## Защитить массивы без optimisticConcurrency [#protect-arrays]

У документа с `Versioned`, но без `optimisticConcurrency` защищены только изменения массивов **по позиции**. Операция вроде `tags.1 = "B"` ссылается на индекс. Если другой клиент успел убрать первый элемент, индекс `1` теперь указывает на другой элемент, и правка легла бы не туда. Поэтому Typemo делает такое обновление условным по версии.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
import { VersionError } from "@venloc/typemo";
// ---cut---
const created = await Orders.create({ customer: "alice", tags: ["a", "b", "c"], lines: [] });
const mine = await Orders.findById(created._id).orFail();
const theirs = await Orders.findById(created._id).orFail();

theirs.tags.pull("a");
await theirs.$save(); // версия 0 → 1

mine.tags.set(1, "B"); // я хотел заменить "b", но после чужого удаления это "c"
try {
  await mine.$save();
} catch (error) {
  console.log(error instanceof VersionError && error.modifiedPaths);
  // → ["tags.1"]
}
```

Изменениям, которые от позиций не зависят, версия не нужна. Скалярное поле, `push`, `pull` и `addToSet` дают обновления, которые применяются независимо друг от друга. Так что если один клиент поменял `customer`, а другой добавил тег, конфликта не будет.

## Что делает optimisticConcurrency [#optimistic-concurrency]

С `optimisticConcurrency: true` **каждое** сохранение условно по версии и увеличивает её. Два клиента, поменявшие разные скалярные поля, тоже получат конфликт. Конфликтов станет больше, зато потерянных обновлений не будет совсем.

Вместо `true` можно передать список путей. Тогда так ведёт себя только сохранение, которое затрагивает эти пути, а остальное защищено как у обычного `Versioned`. Описание опции — в справочнике [`@Schema`](../reference/schemas/schema.mdx).

## Как выбрать [#how-to-choose]

Спросите себя, **что случится, если правка одного клиента пропадёт**.

- **Ничего страшного**, это пометка или тег, — хватит `Versioned` по умолчанию.
- **Это деньги, остаток или состояние, которое нельзя терять**, — включайте `optimisticConcurrency` или меняйте значение атомарным оператором.

## Когда это не нужно [#when-not-to-use]

Если документ меняет один клиент, как настройки пользователя или черновик, версия ничего не даёт, и `Versioned` подключать не нужно. Если изменение можно выразить атомарной операцией на стороне базы, вроде [`$inc`](../reference/writes/update-operators.mdx) или `$push`, конфликты и повторы тоже не нужны.

## Если что-то пошло не так [#troubleshooting]

**Документ прочитан без версии.** Вы прочитали документ с проекцией без `__v`, а сохранению нужна версия. Тогда [`$save`](../reference/documents/document-api.mdx#save) откажется работать, ведь молча пропустить проверку значило бы выключить защиту.

```text
QueryError: Order: this save needs the version "__v", but the document was read without it (a projection left it out); select it, or read the document again — the check is never skipped silently
```

Добавьте `__v` в проекцию или прочитайте документ целиком.

**Версию поменяли вручную.** Поле `__v` ведёт ядро. Присвоить ему значение можно только в обход типов, и тогда сохранение откажется работать, а [`$getChanges`](../reference/documents/document-api.mdx#get-changes) покажет причину в `$problems`.

```text
QueryError: Ledger.__v is the version key: the core maintains it; it cannot be changed by hand
```

Не трогайте `__v`. Если нужна защита от конфликтов, включите `optimisticConcurrency`.

**Повтор применяет чужую версию.** Повторять `$save` того же объекта после `VersionError` бесполезно, версия в нём устарела. Прочитайте документ заново, как в функции `deposit` выше.

## Полный пример [#full-example]

```ts twoslash title="ledgers/ledgers.service.ts"
import { Entity, Prop, Schema, TypemoClient, VersionError, Versioned } from "@venloc/typemo";
@Schema({ collection: "ledgers", optimisticConcurrency: true })
class Ledger extends Versioned(Entity) {
  @Prop(() => String, { required: true }) owner!: string;
  @Prop(() => Number, { required: true }) balance!: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Ledgers = client.db().model(Ledger);
// ---cut---
export const withdraw = async (ledgerId: Ledger["_id"], amount: number) => {
  for (let attempt = 0; attempt < 3; attempt++) {
    const ledger = await Ledgers.findById(ledgerId).orFail();
    if (ledger.balance < amount) throw new Error("not enough money");
    ledger.balance -= amount;
    try {
      await ledger.$save();
      return ledger.balance;
    } catch (error) {
      if (!(error instanceof VersionError)) throw error;
    }
  }
  throw new Error("the ledger is busy, try again later");
};
```

## Если вы пришли из Mongoose [#from-mongoose]

<Callout type="migration">

Поле `__v` и `VersionError` есть и в Mongoose, но там проверка версии молча пропускалась, если документ прочитали без `__v`. В Typemo версия появляется только с `Versioned`, а сохранение без нужной версии — ошибка. Пустое сохранение при `optimisticConcurrency` ничего не отправляет и версию не увеличивает.

</Callout>
