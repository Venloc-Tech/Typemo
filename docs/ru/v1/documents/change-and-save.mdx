Изменить документ просто. Загрузите его, поменяйте поля обычным кодом и вызовите [`$save`](../reference/documents/document-api.mdx#save). Typemo сам найдёт, что изменилось, и отправит в базу только это. Собирать обновление вручную и помнить, какие поля вы трогали, не нужно.

Всё дело в том, что документ следит за собой. Документ — это то, что вы получаете из `find`, `create` и `Model.new`. Это экземпляр вашего класса, у которого массивы, `Map` и вложенные объекты заменены на типизированные коллекции с журналом изменений. Сравнивая журнал с исходными значениями, [`$save`](../reference/documents/document-api.mdx#save) строит самое короткое обновление — `$set` для полей, `$push` для новых элементов массива, `$unset` для удалённых ключей `Map`.

## Что понадобится

Заказ с покупателем, тегами, строками, адресом и `Map` сборов. Модель есть в [справочнике](../reference/documents/document-api.mdx), а подключение — в руководстве [Подключиться к базе](../connection/connect.mdx).

```ts twoslash title="models/order.ts"
import { Entity, type Hidden, Prop, Schema, Spec, Versioned } from "@venloc/typemo";

@Schema({ nested: true })
export class Address {
  @Prop(() => String, { required: true })
  city!: string;

  @Prop(() => String)
  street?: string;
}

@Schema()
export class Line extends Entity {
  @Prop(() => String, { required: true })
  sku!: string;

  @Prop(() => Number, { required: true, min: 0 })
  qty!: number;
}

@Schema({ collection: "orders" })
export class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => [String])
  tags!: string[];

  @Prop(() => [Line])
  lines!: Line[];

  @Prop(() => Address)
  address?: Address;

  @Prop(() => Spec.map(Number))
  fees?: Map<string, number>;

  @Prop(() => String, { hidden: true })
  note?: Hidden<string>;
}
```

## Быстрый путь

Поменять документ можно тремя способами, и все они попадут в один `$save`. Присвоить скаляр, вызвать метод коллекции или задать путь через [`$set`](../reference/documents/document-api.mdx#set).

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: ["gift"], lines: [{ sku: "A1", qty: 2 }] });

order.customer = "bob"; // присваивание
order.tags.push("express"); // метод коллекции
order.$set("lines.0.qty", 5); // путь
await order.$save();

console.log(order.$isModified());
// → false
```

Ниже разберём, что уходит в базу, как это увидеть и что делать, если что-то идёт не так.

## Изменить поля и сохранить

Чаще всего нужно поменять несколько полей загруженного документа. Присвойте новые значения и вызовите `$save`. Значение присваивается как есть, а приведение к типу поля и проверки выполняются при сохранении.

Если присвоить значение другого типа, вы узнаете об этом из [`CastError`](../reference/errors/data-errors.mdx#casterror) при `$save` или `$validate`. Нарушение правила поля вроде `min` или `required` даст [`ValidationError`](../reference/errors/data-errors.mdx#validationerror). Хотите ошибку сразу — используйте [`$set`](../reference/documents/document-api.mdx#set). Он приводит значение при вызове и бросает `CastError` на нужной строке.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: ["gift"], lines: [] });
console.log(order.__v);
// → 0

order.customer = "bob";
await order.$save();
console.log(order.customer, order.__v);
// → "bob" 0
```

Версия `__v` не изменилась. Изменение скалярного поля не меняет структуру документа, и Typemo версию не увеличивает. Когда версия меняется и зачем она вообще нужна, рассказано в руководстве [Версии и параллельные изменения](./versions.mdx).

## Изменить массив, Map или вложенный объект

Массивы и `Map` меняют **методами** — `push`, `pull`, `set`, `delete` и другими. Вложенный объект меняют присваиванием его полей. Запись по индексу и в `length` закрыта типами. Из неё не понять, что вы хотели сделать, а из метода понятно. Полный список методов и операторов, в которые они превращаются, — в справочнике [Типизированные коллекции](../reference/documents/typed-collections.mdx).

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({
  customer: "alice",
  tags: ["gift"],
  lines: [{ sku: "A1", qty: 2 }],
  address: { city: "Oslo" },
  fees: { delivery: 5 },
});

order.tags.push("express");
order.lines[0]!.qty = 5;
order.address!.city = "Rome";
order.fees?.set("gift", 3);
await order.$save();
```

Каждое изменение здесь превратилось в свою операцию, а не в перезапись документа. Поэтому два клиента, поменявшие разные теги одного заказа, не затрут друг друга. Что именно уйдёт в базу, покажет [`$getChanges`](../reference/documents/document-api.mdx#getchanges), о нём следующий раздел.

## Посмотреть, что изменилось

Чтобы узнать, что изменилось, без сохранения, спросите сам документ. [`$isModified`](../reference/documents/document-api.mdx#ismodified) ответит «да» или «нет» для документа целиком или для одного пути. [`$getChanges`](../reference/documents/document-api.mdx#getchanges) покажет само обновление — операторы, пути и значения в именах полей вашего класса.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({
  customer: "alice",
  tags: ["gift"],
  lines: [{ sku: "A1", qty: 2 }],
  fees: { delivery: 5 },
});
console.log(order.$isModified());
// → false

order.customer = "bob";
order.tags.push("express");
order.lines[0]!.qty = 5;
order.fees?.set("gift", 3);
console.log(order.$isModified("customer"), order.$isModified("address"));
// → true false
console.log(order.$getChanges());
// → { $set: { customer: "bob", "lines.0.qty": 5, "fees.gift": 3 }, $push: { tags: { $each: ["express"] } } }
```

Typemo сравнивает значения, а не запоминает присваивания. Если вы поменяли `customer` и вернули прежнее значение, документ снова не считается изменённым, и `$save` ничего не отправит.

Так же сравнивается и `NaN`. Если другая программа записала его в поле, оно считается равным самому себе. Прочитанный документ с таким полем не «изменён» — `$isModified()` вернёт `false`, `$getChanges()` вернёт пустой объект, — и `$save` не отправит это `NaN` обратно.

`$getChanges` пригодится в отладке, когда непонятно, почему сохранение такое большое, и в тестах. Он ничего не бросает. Если `$save` откажет, например потому что массив заменили присваиванием, причина окажется в ключе `$problems` результата. Там будут путь и текст ошибки, которую бросило бы сохранение. Так будущий отказ виден заранее, вместе с остальным обновлением.

## Сохранить ничего не изменённый документ

Вызывать `$save` у документа без изменений безопасно. В базу не уйдёт ни одной команды, а метод успешно вернёт тот же документ. Так что проверять `$isModified` перед каждым сохранением не нужно.

Одно исключение, и оно не про базу. Хуки `document.save` вызываются и для документа без изменений. Если хук должен работать только при правках, начните его с проверки `if (!this.$isModified()) return;`.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: [], lines: [] });
const same = await order.$save();
console.log(Object.is(same, order), order.__v);
// → true 0
```

## Сохранить в транзакции

Если несколько записей должны примениться вместе или не примениться вовсе, оберните их в [`client.transaction`](../reference/connection/typemo-client.mdx#clienttransaction). `$save` внутри колбэка сам присоединяется к транзакции, сессию передавать не нужно. При откате изменения из базы исчезают.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: [], lines: [] });

try {
  await client.transaction(async () => {
    const inside = await Orders.findById(order._id).orFail();
    inside.customer = "bob";
    await inside.$save();
    throw new Error("payment failed");
  });
} catch {
  // транзакция откатилась
}

const stored = await Orders.findById(order._id).orFail().plain();
console.log(stored.customer);
// → "alice"
```

Обратите внимание, документ `inside` в памяти сохранил правку `"bob"`, хотя в базе её нет. Поэтому внутри транзакции документы читают заново, как здесь, а не берут загруженные раньше. Колбэк может выполниться несколько раз, и правка заранее загруженного документа применилась бы повторно. Подробнее — в руководстве [Транзакции](../transactions/transactions.mdx).

## Как выбрать

Спросите себя, **есть ли у вас загруженный документ и нужен ли результат ещё и в памяти**.

- **Документ загружен, и вы работаете с ним дальше** — показываете, считаете, отдаёте, — меняйте его и вызывайте [`$save`](../reference/documents/document-api.mdx#save).
- **Документ не загружен, и нужно только изменить запись** — берите [`updateOne`](../reference/writes/writes.mdx#updateone). Это один запрос вместо чтения и записи.
- **Нужно атомарное изменение на стороне базы**, вроде счётчика с `$inc`, а документ уже у вас в руках, — есть [`$updateOne`](../reference/documents/document-api.mdx#updateone). Копию в памяти он не трогает.

## Когда это не нужно

Для массовых изменений, например всех заказов покупателя, документы по одному не загружают. Берите [`updateMany`](../reference/writes/writes.mdx#updatemany). Счётчики, которые меняют многие клиенты сразу, надёжнее менять оператором [`$inc`](../reference/writes/update-operators.mdx) в [`updateOne`](../reference/writes/writes.mdx#updateone), чем «прочитать, прибавить, сохранить». Между чтением и записью другой клиент успеет изменить значение.

## Если что-то пошло не так

**Массив заменён присваиванием.** Присвоить массиву или `Map` новое значение через `=` нельзя.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const order = Orders.new({ customer: "alice", tags: ["gift"], lines: [] });
// ---cut---
// @errors: 2740
order.tags = ["express"];
```

Если обойти это приведением типа, `$save` откажется писать. Typemo не знает, хотели вы заменить содержимое, дополнить его или просто ошиблись. А [`$getChanges`](../reference/documents/document-api.mdx#getchanges) ошибку не бросит, а покажет тот же текст в `$problems`.

```text
DirectWriteError: "tags" was changed around its methods: the field was replaced by assignment; use $set("tags", value) or the container's methods
```

Чтобы заменить содержимое целиком, используйте [`$set("tags", […])`](../reference/documents/document-api.mdx#set) или [`tags.replace([…])`](../reference/documents/typed-collections.mdx#strictarrayreplace). Чтобы дополнить — [`tags.push`](../reference/documents/typed-collections.mdx#strictarraypush).

**Неверное значение обнаружилось только при сохранении.** Обычное присваивание значение сразу не приводит. Если вы присвоили полю неподходящее значение в коде без проверки типов, ошибка появится только при [`$save`](../reference/documents/document-api.mdx#save) или [`$validate`](../reference/documents/document-api.mdx#validate), а не на строке присваивания, как у [`$set`](../reference/documents/document-api.mdx#set). Класс ошибки на любой глубине один — [`CastError`](../reference/errors/data-errors.mdx#casterror), и она случается раньше всякой валидации. Ограничения поля вроде `min` и `enum` не проверяются, проверять пока нечего, и в базу ничего не уходит.

```text
CastError: Cast to string failed at path "customer" for 5 (number): expected a string [type]
CastError: Cast to number failed at path "lines.0.qty" for "abc" (string): expected a number [type]
```

Если значение приходит снаружи, присваивайте его через `$set`, тогда ошибка появится сразу на нужной строке. Или проверьте его заранее через [`Model.validate`](../reference/documents/model-document-methods.mdx#modelvalidate).

**Сохранение не сработало после удаления.** Документ, удалённый через [`$deleteOne`](../reference/documents/document-api.mdx#deleteone), сохранить нельзя. Документ, удалённый другим клиентом, тоже.

```text
QueryError: save: the document of Order was deleted
DocumentNotFoundError: Order.save: the document is no longer in the collection (deleted since it was read, or out of the scope of the operation's policies); nothing was written
```

Первая ошибка значит, что вы сами удалили документ в этой программе. Вторая — что записи в базе уже нет. Создайте документ заново через [`Model.new`](../reference/documents/model-document-methods.mdx#modelnew) или прочитайте актуальный.

## Полный пример

Функция сервиса меняет покупателя заказа, добавляет тег и строку и сохраняет всё одним обращением к базе.

```ts twoslash title="orders/orders.service.ts"
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
export const updateOrder = async (orderId: Order["_id"], customer: string) => {
  const order = await Orders.findById(orderId).orFail();

  order.customer = customer;
  order.tags.addToSet("edited");
  order.lines.push({ sku: "GIFT", qty: 1 });

  if (!order.$isModified()) return order;
  await order.$save();
  return order.$toPlain();
};
```

## Если вы пришли из Mongoose

<Callout type="migration">

В Mongoose изменение массива по индексу или вложенного значения нужно было сопровождать `doc.markModified(path)`, иначе `save()` могло ничего не записать. В Typemo запись по индексу закрыта типами, а методы коллекций отслеживаются сами. `$markModified` нужен только для значений, изменённых на месте, например байтов `Binary`. `doc.save()` здесь называется `$save()`, а `doc.isModified()` — `$isModified()`.

</Callout>
