---
title: Что делать с полями, которых нет в схеме
description: "Как узнать о сохранённых полях, которых не знает схема, не потерять их при сохранении и осознанно принять потерю"
icon: FileWarning
---

Если в базе лежат поддокументы с полями, которых нет в вашей схеме, Typemo не потеряет их молча: [`unknownFieldsOf`](../reference/documents/unknown-fields.mdx#unknownfieldsof) покажет такие поля, а сохранение, которое стёрло бы их, завершится ошибкой [`UnknownFieldsError`](../reference/documents/unknown-fields.mdx#unknownfieldserror). Чтобы принять потерю осознанно, передайте `{ dropUnknownFields: true }` в [`$save`](../reference/documents/document-api.mdx#save).

Такие данные появляются, когда схему меняли, а старые документы остались прежними, когда две версии приложения работают на одной базе или когда в коллекцию пишет другая программа. Молча стереть их значило бы потерять чужие данные при первом же безобидном сохранении, поэтому по умолчанию Typemo отказывает.

## Что предполагается

Примеры используют заказ с покупателем, строками и адресом. В базе лежит заказ, записанный более старой версией схемы: у первой строки есть поле `oldPrice`, у адреса — `legacyZip`. Модель показана в [справочнике](../reference/documents/unknown-fields.mdx).

## Быстрый путь

```ts twoslash
import { ObjectId } from "mongodb";
import { Entity, Prop, Schema, TypemoClient, Versioned, isUnknownFieldsError, unknownFieldsOf } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const rawOrders = client.unsafeDriver().db("shop").collection("orders");
const id = new ObjectId();
await rawOrders.insertOne({
  _id: id,
  customer: "legacy",
  lines: [{ _id: new ObjectId(), sku: "A1", qty: 1, oldPrice: 5 }, { _id: new ObjectId(), sku: "B2", qty: 2 }],
  address: { city: "Oslo", legacyZip: "0150" },
  __v: 0,
});
const order = await Orders.findById(id).orFail();
// ---cut---
console.log(unknownFieldsOf(order));
// → [{ path: "lines.0", keys: ["oldPrice"] }, { path: "address", keys: ["legacyZip"] }]

order.address!.city = "Rome";
await order.$save(); // безопасно: пишется только address.city
```

Остальная страница объясняет, когда сохранение безопасно, когда оно откажется и что делать.

## Увидеть неизвестные поля

[`unknownFieldsOf`](../reference/documents/unknown-fields.mdx#unknownfieldsof) принимает документ, поддокумент или коллекцию и возвращает список путей с ключами. Ключи запоминаются при чтении документа, без дополнительных запросов. Ключи в **корне** документа в список не входят: сохранение их не переписывает, терять там нечего. `lean()` показывает их как есть.

## Менять документ безопасно

Большинство изменений неизвестные поля не затрагивают, потому что пишут точные пути: поле поддокумента, `push`, `pull`, `pop`, `shift`. Поэтому обычная работа с документом продолжается, а данные старой версии остаются в базе нетронутыми. Есть одно исключение: если в одном сохранении сошлись правка поля внутри элемента массива и операция над самим массивом (`push`), Typemo записывает массив целиком, и неизвестные поля его элементов оказываются под угрозой. Поэтому в примере ниже правка полей и `push` сохраняются раздельно.

```ts twoslash
import { ObjectId } from "mongodb";
import { Entity, Prop, Schema, TypemoClient, Versioned, isUnknownFieldsError, unknownFieldsOf } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const rawOrders = client.unsafeDriver().db("shop").collection("orders");
const id = new ObjectId();
await rawOrders.insertOne({
  _id: id,
  customer: "legacy",
  lines: [{ _id: new ObjectId(), sku: "A1", qty: 1, oldPrice: 5 }, { _id: new ObjectId(), sku: "B2", qty: 2 }],
  address: { city: "Oslo", legacyZip: "0150" },
  __v: 0,
});
const order = await Orders.findById(id).orFail();
// ---cut---
order.address!.city = "Rome";
order.lines[0]!.qty = 9;
await order.$save();

order.lines.push({ sku: "C3", qty: 1 });
await order.$save();

const stored = await rawOrders.findOne({ _id: id });
console.log(stored?.address, stored?.lines[0]?.oldPrice);
// → { city: "Rome", legacyZip: "0150" } 5
```

## Понять, почему сохранение отказало

Сохранение отказывает, когда поддокумент с неизвестными полями **записывается заново целиком**: после `reverse`, `sort`, `splice`, `clear` или `replace` массива, при замене поддокумента через [`$set`](../reference/documents/document-api.mdx#set) или `lines.set(index, …)`, при `clear()` у Map поддокументов. Typemo сообщает об этом до обращения к базе, в базу ничего не уходит. Увидеть отказ заранее можно, не сохраняя: [`$getChanges`](../reference/documents/document-api.mdx#getchanges) не бросает ошибку, а записывает её текст в ключ `$problems` по пути поддокумента (`lines.1`).

```ts twoslash
import { ObjectId } from "mongodb";
import { Entity, Prop, Schema, TypemoClient, Versioned, isUnknownFieldsError, unknownFieldsOf } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const rawOrders = client.unsafeDriver().db("shop").collection("orders");
const id = new ObjectId();
await rawOrders.insertOne({
  _id: id,
  customer: "legacy",
  lines: [{ _id: new ObjectId(), sku: "A1", qty: 1, oldPrice: 5 }, { _id: new ObjectId(), sku: "B2", qty: 2 }],
  address: { city: "Oslo", legacyZip: "0150" },
  __v: 0,
});
const order = await Orders.findById(id).orFail();
// ---cut---
order.lines.reverse();

try {
  await order.$save();
} catch (error) {
  if (isUnknownFieldsError(error)) {
    console.log(error.fields);
    // → [{ path: "lines.1", keys: ["oldPrice"] }]
  }
}
```

```text
UnknownFieldsError: the save would drop fields the schema does not know from stored data: "lines.1" (oldPrice); migrate the data or the schema, or pass { dropUnknownFields: true } to $save()/bulkSave() to accept the loss
```

## Выбрать, что делать

Выходов три. **Дополнить схему**: если поле нужно, добавьте его в класс, и оно станет известным. **Мигрировать данные**: убрать или перенести лишние ключи отдельным скриптом. **Принять потерю**: передать `{ dropUnknownFields: true }`.

```ts twoslash
import { ObjectId } from "mongodb";
import { Entity, Prop, Schema, TypemoClient, Versioned, isUnknownFieldsError, unknownFieldsOf } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const rawOrders = client.unsafeDriver().db("shop").collection("orders");
const id = new ObjectId();
await rawOrders.insertOne({
  _id: id,
  customer: "legacy",
  lines: [{ _id: new ObjectId(), sku: "A1", qty: 1, oldPrice: 5 }, { _id: new ObjectId(), sku: "B2", qty: 2 }],
  address: { city: "Oslo", legacyZip: "0150" },
  __v: 0,
});
const order = await Orders.findById(id).orFail();
order.lines.reverse();
// ---cut---
await order.$save({ dropUnknownFields: true });
console.log(unknownFieldsOf(order));
// → [{ path: "address", keys: ["legacyZip"] }]
```

Потерянные поля удаляются и из базы, и из экземпляров документа. Адрес в примере не менялся, поэтому его `legacyZip` остался.

## Как выбрать

Спросите себя: **нужны ли эти поля кому-то, кроме старого кода?** Если да (другая версия приложения, другая программа) — дополните схему или не переписывайте эти поддокументы. Если поля мусор от старой версии — мигрируйте данные один раз, а не принимайте потерю при каждом сохранении.

## Когда это не нужно

Если вы читаете данные только для показа, этот механизм не нужен: [`.plain()`](../reference/query/reading.mdx#plain) и [`.lean()`](../reference/query/reading.mdx#lean) не проверяют неизвестные поля и ничего не сохраняют. Он нужен, когда документ будет изменён и сохранён.

## Частые ошибки

### `dropUnknownFields` включён «на всякий случай»

Если передавать `{ dropUnknownFields: true }` во все сохранения, вы снова получаете молчаливую потерю данных: ту самую, от которой Typemo защищает. Исправление: включайте опцию только для конкретной миграции.

### Ключа нет в `$toObject`, но он в базе

Неизвестные ключи не попадают в гидратированный документ и в `$toObject`, зато видны в `lean()`. Это не потеря: ключ в базе, пока сохранение его не переписало.

## Полный пример

```ts twoslash title="orders/migrate-orders.ts"
import { ObjectId } from "mongodb";
import { Entity, Prop, Schema, TypemoClient, Versioned, isUnknownFieldsError, unknownFieldsOf } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const rawOrders = client.unsafeDriver().db("shop").collection("orders");
const id = new ObjectId();
await rawOrders.insertOne({
  _id: id,
  customer: "legacy",
  lines: [{ _id: new ObjectId(), sku: "A1", qty: 1, oldPrice: 5 }, { _id: new ObjectId(), sku: "B2", qty: 2 }],
  address: { city: "Oslo", legacyZip: "0150" },
  __v: 0,
});
const order = await Orders.findById(id).orFail();
// ---cut---
export const reverseLines = async (orderId: Order["_id"], acceptLoss: boolean) => {
  const doc = await Orders.findById(orderId).orFail();
  doc.lines.reverse();
  try {
    await doc.$save(acceptLoss ? { dropUnknownFields: true } : {});
    return "saved";
  } catch (error) {
    if (isUnknownFieldsError(error)) return `refused: ${error.fields.map((f) => f.path).join(", ")}`;
    throw error;
  }
};
```

## Если вы пришли из Mongoose

<Callout type="migration">

В Mongoose поля, которых нет в схеме, при `strict: true` отбрасываются при чтении и не возвращаются в документе, а замена поддокумента затирала их молча. В Typemo такого режима нет: неизвестные поля запоминаются, а сохранение, которое их потеряло бы, — ошибка.

</Callout>
