Бывает, что в базе лежат поддокументы с полями, которых нет в вашей схеме. Typemo не потеряет их молча. [`unknownFieldsOf`](../reference/documents/unknown-fields.mdx#unknownfieldsof) покажет такие поля, а сохранение, которое стёрло бы их, закончится ошибкой [`UnknownFieldsError`](../reference/documents/unknown-fields.mdx#unknownfieldserror). Если вы готовы с ними расстаться, передайте `{ dropUnknownFields: true }` в [`$save`](../reference/documents/document-api.mdx#save).

Откуда берутся такие данные? Схему поменяли, а старые документы остались прежними. Или две версии приложения работают с одной базой. Или в коллекцию пишет другая программа. Если бы Typemo стирал их молча, чужие данные пропали бы при первом же безобидном сохранении. Поэтому по умолчанию он отказывает.

## Что понадобится

Заказ с покупателем, строками и адресом. Модель есть в [справочнике](../reference/documents/unknown-fields.mdx). В базе лежит заказ, записанный старой версией схемы. У его первой строки есть поле `oldPrice`, а у адреса — `legacyZip`.

## Быстрый путь

```ts twoslash
import { ObjectId } from "mongodb";
import { Entity, Prop, Schema, TypemoClient, Versioned, isUnknownFieldsError, unknownFieldsOf } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const rawOrders = client.unsafeDriver().db("shop").collection("orders");
const id = new ObjectId();
await rawOrders.insertOne({
  _id: id,
  customer: "legacy",
  lines: [{ _id: new ObjectId(), sku: "A1", qty: 1, oldPrice: 5 }, { _id: new ObjectId(), sku: "B2", qty: 2 }],
  address: { city: "Oslo", legacyZip: "0150" },
  __v: 0,
});
const order = await Orders.findById(id).orFail();
// ---cut---
console.log(unknownFieldsOf(order));
// → [{ path: "lines.0", keys: ["oldPrice"] }, { path: "address", keys: ["legacyZip"] }]

order.address!.city = "Rome";
await order.$save(); // безопасно: пишется только address.city
```

Ниже разберём, когда сохранение безопасно, когда оно откажет и что тогда делать.

## Увидеть неизвестные поля

[`unknownFieldsOf`](../reference/documents/unknown-fields.mdx#unknownfieldsof) принимает документ, поддокумент или коллекцию и возвращает список путей с ключами. Ключи запоминаются при чтении документа, лишних запросов нет. Ключи в **корне** документа в список не попадают. Сохранение их не переписывает, и терять там нечего. В `lean()` они видны как есть.

## Менять документ безопасно

Большинство изменений неизвестных полей не касаются, потому что пишут точные пути. Это поле поддокумента, `push`, `pull`, `pop` и `shift`. Так что обычная работа с документом продолжается, а данные старой версии остаются в базе нетронутыми.

Исключение одно. Если в одном сохранении сошлись правка поля внутри элемента массива и операция над самим массивом, например `push`, Typemo запишет массив целиком. Тогда неизвестные поля его элементов окажутся под угрозой. Поэтому в примере ниже правка полей и `push` сохраняются раздельно.

```ts twoslash
import { ObjectId } from "mongodb";
import { Entity, Prop, Schema, TypemoClient, Versioned, isUnknownFieldsError, unknownFieldsOf } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const rawOrders = client.unsafeDriver().db("shop").collection("orders");
const id = new ObjectId();
await rawOrders.insertOne({
  _id: id,
  customer: "legacy",
  lines: [{ _id: new ObjectId(), sku: "A1", qty: 1, oldPrice: 5 }, { _id: new ObjectId(), sku: "B2", qty: 2 }],
  address: { city: "Oslo", legacyZip: "0150" },
  __v: 0,
});
const order = await Orders.findById(id).orFail();
// ---cut---
order.address!.city = "Rome";
order.lines[0]!.qty = 9;
await order.$save();

order.lines.push({ sku: "C3", qty: 1 });
await order.$save();

const stored = await rawOrders.findOne({ _id: id });
console.log(stored?.address, stored?.lines[0]?.oldPrice);
// → { city: "Rome", legacyZip: "0150" } 5
```

## Понять, почему сохранение отказало

Сохранение откажет, если поддокумент с неизвестными полями **записывается заново целиком**. Так бывает в трёх случаях.

- После `reverse`, `sort`, `splice`, `clear` или `replace` у массива.
- При замене поддокумента через [`$set`](../reference/documents/document-api.mdx#set) или `lines.set(index, …)`.
- При `clear()` у `Map` поддокументов.

Typemo скажет об этом ещё до обращения к базе, и в базу ничего не уйдёт. Отказ можно увидеть заранее, ничего не сохраняя. [`$getChanges`](../reference/documents/document-api.mdx#getchanges) ошибку не бросит, а запишет её текст в ключ `$problems` по пути поддокумента (`lines.1`).

```ts twoslash
import { ObjectId } from "mongodb";
import { Entity, Prop, Schema, TypemoClient, Versioned, isUnknownFieldsError, unknownFieldsOf } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const rawOrders = client.unsafeDriver().db("shop").collection("orders");
const id = new ObjectId();
await rawOrders.insertOne({
  _id: id,
  customer: "legacy",
  lines: [{ _id: new ObjectId(), sku: "A1", qty: 1, oldPrice: 5 }, { _id: new ObjectId(), sku: "B2", qty: 2 }],
  address: { city: "Oslo", legacyZip: "0150" },
  __v: 0,
});
const order = await Orders.findById(id).orFail();
// ---cut---
order.lines.reverse();

try {
  await order.$save();
} catch (error) {
  if (isUnknownFieldsError(error)) {
    console.log(error.fields);
    // → [{ path: "lines.1", keys: ["oldPrice"] }]
  }
}
```

```text
UnknownFieldsError: the save would drop fields the schema does not know from stored data: "lines.1" (oldPrice); migrate the data or the schema, or pass { dropUnknownFields: true } to $save()/bulkSave() to accept the loss
```

## Выбрать, что делать

Выхода три.

- **Дополнить схему.** Если поле нужно, добавьте его в класс, и оно станет известным.
- **Перенести данные.** Уберите или переложите лишние ключи отдельным скриптом миграции.
- **Принять потерю.** Передайте `{ dropUnknownFields: true }`.

```ts twoslash
import { ObjectId } from "mongodb";
import { Entity, Prop, Schema, TypemoClient, Versioned, isUnknownFieldsError, unknownFieldsOf } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const rawOrders = client.unsafeDriver().db("shop").collection("orders");
const id = new ObjectId();
await rawOrders.insertOne({
  _id: id,
  customer: "legacy",
  lines: [{ _id: new ObjectId(), sku: "A1", qty: 1, oldPrice: 5 }, { _id: new ObjectId(), sku: "B2", qty: 2 }],
  address: { city: "Oslo", legacyZip: "0150" },
  __v: 0,
});
const order = await Orders.findById(id).orFail();
order.lines.reverse();
// ---cut---
await order.$save({ dropUnknownFields: true });
console.log(unknownFieldsOf(order));
// → [{ path: "address", keys: ["legacyZip"] }]
```

Потерянные поля удаляются и из базы, и из экземпляров документа. Адрес в примере не менялся, поэтому его `legacyZip` остался на месте.

## Как выбрать

Спросите себя, **нужны ли эти поля кому-то, кроме старого кода**.

- **Да, другой версии приложения или другой программе** — дополните схему или не переписывайте эти поддокументы.
- **Нет, это мусор от старой версии** — один раз почистите данные миграцией, а не принимайте потерю при каждом сохранении.

## Когда это не нужно

Если данные читаются только для показа, этот механизм не нужен. [`.plain()`](../reference/query/reading.mdx#plain) и [`.lean()`](../reference/query/reading.mdx#lean) неизвестные поля не проверяют и ничего не сохраняют. Он нужен, когда документ будут менять и сохранять.

## Если что-то пошло не так

**`dropUnknownFields` включён «на всякий случай».** Если передавать `{ dropUnknownFields: true }` в каждое сохранение, вы снова получите молчаливую потерю данных, ту самую, от которой Typemo защищает. Включайте опцию только для конкретной миграции.

**Ключа нет в `$toObject`, хотя в базе он есть.** Неизвестные ключи не попадают ни в документ, ни в `$toObject`, зато видны в `lean()`. Это не потеря. Ключ лежит в базе, пока его не перепишет какое-нибудь сохранение.

## Полный пример

```ts twoslash title="orders/migrate-orders.ts"
import { ObjectId } from "mongodb";
import { Entity, Prop, Schema, TypemoClient, Versioned, isUnknownFieldsError, unknownFieldsOf } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const rawOrders = client.unsafeDriver().db("shop").collection("orders");
const id = new ObjectId();
await rawOrders.insertOne({
  _id: id,
  customer: "legacy",
  lines: [{ _id: new ObjectId(), sku: "A1", qty: 1, oldPrice: 5 }, { _id: new ObjectId(), sku: "B2", qty: 2 }],
  address: { city: "Oslo", legacyZip: "0150" },
  __v: 0,
});
const order = await Orders.findById(id).orFail();
// ---cut---
export const reverseLines = async (orderId: Order["_id"], acceptLoss: boolean) => {
  const doc = await Orders.findById(orderId).orFail();
  doc.lines.reverse();
  try {
    await doc.$save(acceptLoss ? { dropUnknownFields: true } : {});
    return "saved";
  } catch (error) {
    if (isUnknownFieldsError(error)) return `refused: ${error.fields.map((f) => f.path).join(", ")}`;
    throw error;
  }
};
```

## Если вы пришли из Mongoose

<Callout type="migration">

В Mongoose при `strict: true` поля, которых нет в схеме, отбрасываются при чтении и не попадают в документ, а замена поддокумента молча их затирала. В Typemo такого режима нет. Неизвестные поля запоминаются, а сохранение, которое их потеряло бы, — это ошибка.

</Callout>
