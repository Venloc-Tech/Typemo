Чтобы изменить массив или `Map` в загруженном документе, вызовите метод коллекции — `push`, `pull`, `set` или `delete` — и сохраните документ. Typemo превратит вызов в точную операцию MongoDB, например `$push`, `$pullAll` или `$set` одного ключа, и не станет переписывать поле целиком. Запись по индексу и в `length` закрыта типами, потому что из неё не понять, чего вы хотели.

Зачем это нужно? Допустим, два клиента одновременно меняют теги заказа, а вы отправляете массив целиком. Победит тот, кто сохранил последним, и правка другого пропадёт. Операции `$push` и `$pull` говорят, **что** изменить, а не **как теперь выглядит поле**, поэтому друг другу не мешают.

Такие массивы в Typemo называются типизированными коллекциями.

- [`StrictArray`](../reference/documents/typed-collections.mdx#strictarray) — для массивов значений.
- [`SubdocumentArray`](../reference/documents/typed-collections.mdx#subdocumentarray) — для массивов вложенных объектов.
- [`TypedMap`](../reference/documents/typed-collections.mdx#typedmap) — для `Map`.

## Что понадобится

Заказ из руководства [Изменить и сохранить документ](./change-and-save.mdx) с тегами `tags`, строками `lines` и `Map` сборов `fees`. Читать коллекции можно как обычные. Работают `for…of`, `map`, `filter`, спред и `JSON.stringify`, а `map` и `filter` возвращают обычные массивы.

## Быстрый путь

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: ["a", "b", "c"], lines: [], fees: { delivery: 5 } });

order.tags.push("d"); // добавить
order.tags.pull("a"); // убрать по значению
order.tags.set(0, "B"); // заменить элемент по позиции
order.fees?.set("gift", 3); // добавить ключ Map
await order.$save();
```

Ниже разберём каждый случай — какая операция уходит в базу, чего делать нельзя и что делать вместо этого.

## Добавить и убрать элементы

`push` добавляет в конец, `unshift` — в начало, `addToSet` — только то, чего ещё нет, а `pull` убирает по значению. Каждый метод сразу приводит значения к типу элемента, так что ошибка типа появится на строке вызова, а не при сохранении. Возвращают методы то же, что у обычного массива. `push` вернёт новую длину, а `pull` и `addToSet` — убранные или добавленные элементы.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: ["a", "b", "c"], lines: [] });

order.tags.push("d", "e");
console.log(order.$getChanges());
// → { $push: { tags: { $each: ["d", "e"] } } }
await order.$save();

order.tags.pull("a");
console.log(order.$getChanges());
// → { $pullAll: { tags: ["a"] } }
```

Каждый вызов даёт свой оператор. Но если за одно сохранение у **одного и того же массива** накопились разные операции, Typemo не пытается уложить их в одно обновление. Два оператора по одному пути надёжно не объединить, и он записывает массив целиком. Так будет, если вызвать `push` и `pull` подряд до сохранения, и так же после второго `pop`.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: ["a", "b", "c"], lines: [] });

order.tags.push("d", "e");
order.tags.pull("a");
console.log(order.$getChanges());
// → { $set: { tags: ["b", "c", "d", "e"] } }
```

Запись всего массива менее точна. Если между вашим чтением и сохранением другой клиент поправил этот же массив, его правка затрётся. Поэтому там, где возможны параллельные изменения, сохраняйте после каждого вида операции. Или проверяйте через [`$getChanges`](../reference/documents/document-api.mdx#getchanges), какая операция уйдёт.

## Заменить элемент

Чтобы заменить существующий элемент, вызовите `set(index, value)`. Индекс должен существовать, добавить элемент по несуществующему индексу нельзя.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: ["a", "b", "c"], lines: [] });

order.tags.set(1, "B");
console.log(order.$getChanges());
// → { $set: { "tags.1": "B" } }
```

`$set` по индексу привязан к позиции. Если другой клиент успел убрать первый элемент, индекс `1` уже указывает на другой. Поэтому у документов с версией такой `$set` защищён проверкой `__v`, подробнее — в [Версиях и параллельных изменениях](./versions.mdx). Если позиция вам не важна, надёжнее убирать по значению через `pull`.

## Изменить поддокумент в массиве

Элементы массива классов — это поддокументы, и их поля меняют обычным присваиванием. Typemo запишет путь с индексом, вычисленным в момент сохранения.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: [], lines: [{ sku: "A1", qty: 2 }, { sku: "B2", qty: 1 }] });

order.lines[1]!.qty = 9;
console.log(order.$getChanges());
// → { $set: { "lines.1.qty": 9 } }
```

Чтобы добавить элемент, передайте в [`push`](../reference/documents/typed-collections.mdx#strictarraypush) обычный объект, и `_id` создастся сам. Готовый поддокумент, ещё не прикреплённый к массиву, создаёт [`lines.create`](../reference/documents/typed-collections.mdx#subdocumentarraycreate).

## Найти и убрать поддокумент по id

У поддокументов есть `_id`, поэтому искать и убирать их можно по идентификатору, а не по позиции. [`lines.id(id)`](../reference/documents/typed-collections.mdx#subdocumentarrayid) возвращает элемент или `undefined`. [`lines.pull(id)`](../reference/documents/typed-collections.mdx#subdocumentarraypull) убирает его операцией `$pull` по `_id`, и позиции тут ни при чём. Идентификатор можно передать и строкой. Это удобно, когда он приходит из адреса запроса, — не нужно оборачивать его в `ObjectId`.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: [], lines: [{ sku: "A1", qty: 2 }, { sku: "B2", qty: 1 }] });
const lineId = order.lines[0]!._id;

console.log(order.lines.id(lineId)?.sku);
// → "A1"
const removed = order.lines.pull(lineId);
console.log(removed.map((line) => line.sku), Object.keys(order.$getChanges()));
// → ["A1"] ["$pull"]
```

## Работать с Map

`Map` меняют методами `set`, `delete` и `clear`. Ключ проверяется при вызове. Это должна быть непустая строка без точки, не начинающаяся с `$` и не равная `__proto__`. Иначе ключ читался бы как путь или оператор.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: [], lines: [], fees: { delivery: 5, gift: 3 } });

order.fees?.set("insurance", 7);
order.fees?.delete("gift");
console.log(order.$getChanges());
// → { $set: { "fees.insurance": 7 }, $unset: { "fees.gift": "" } }
```

## Получить обычную копию

Чтобы передать содержимое дальше без привязки к документу, используйте [`$toObject`](../reference/documents/typed-collections.mdx#strictarray) коллекции, спред или `map`. Результат — обычный массив, и его изменения документа не касаются.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: ["a", "b"], lines: [] });

const copy = [...order.tags];
copy.push("c");
console.log(order.tags.length, copy.length, Array.isArray(order.tags.$toObject()));
// → 2 3 true
```

## Пустой массив по умолчанию

Поле-массив без `required` и без `default` существует всегда. У нового документа (`create`, `Model.new`) и у документа, прочитанного из базы без этого ключа, это пустой массив, а не `undefined`. Поэтому `order.tags.push("a")` сработает на любом заказе, и следующий `$save` запишет ключ, которого в базе не было.

Пустой массив получают и новые поддокументы, и документы, вставленные через upsert. А `lean()` отдаёт документ таким, каким он хранится, то есть без ключа. У массива с `required: true` значения по умолчанию нет, и без значения `create` откажет.

## Как выбрать

Спросите себя, **что должно остаться от изменений других клиентов**.

- **Чужие изменения массива должны сохраниться** — берите методы с точными операциями. Это `push`, `addToSet`, `pull`, `pop` и запись поля внутри поддокумента.
- **Вы сознательно перезаписываете массив целиком**, например при импорте или синхронизации с внешним источником, — берите [`replace`](../reference/documents/typed-collections.mdx#strictarrayreplace) или `sort`. Они честно записывают весь массив.

`push` и `addToSet` отличаются одним — `addToSet` не добавляет то, что уже есть.

## Когда это не нужно

Если массив нужно поменять у многих документов сразу или у документа, который не хочется загружать, берите операторы обновления [`$push`, `$pull` и `$addToSet`](../reference/writes/update-operators.mdx) в [`updateOne`](../reference/writes/writes.mdx#updateone) и [`updateMany`](../reference/writes/writes.mdx#updatemany). Коллекции нужны там, где документ уже загружен и меняется в коде.

## Если что-то пошло не так

**Запись по индексу не компилируется.** `order.tags[0] = "x"` и `order.tags.length = 0` не проходят проверку типов.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const order = Orders.new({ customer: "alice", tags: ["gift"], lines: [] });
// ---cut---
// @errors: 2542
order.tags[0] = "express";
```

Для замены используйте [`tags.set(0, "express")`](../reference/documents/typed-collections.mdx#strictarrayset), а вместо `length = 0` — [`tags.clear()`](../reference/documents/typed-collections.mdx#strictarrayclear).

**Сохранение отказывается писать «мимо методов».** Если запись в массив или `Map` прошла в обход методов — через приведение к `any`, `Array.prototype.push.call` или `Map.prototype.set.call`, — `$save` бросит [`DirectWriteError`](../reference/errors/data-errors.mdx#directwriteerror) и подскажет нужный метод. [`$getChanges`](../reference/documents/document-api.mdx#getchanges) в этом случае ошибку не бросит, а покажет тот же текст в ключе `$problems`.

```text
DirectWriteError: "tags" was changed around its methods: its length is 4 instead of 3 (use push(), pop(), splice(), clear() or replace())
```

Typemo не пытается угадать, что вы имели в виду, ведь догадка могла бы затереть чужие данные. Замените запись методом коллекции.

**Массив загружен частично.** Если вы прочитали часть массива, скажем через `select({ tags: { $slice: 2 } })`, вы видите не все элементы. Пусть в заказе теги `a`, `b` и `c`. Изменение, которое перезаписало бы то, чего вы не видели, даст [`PartialArrayError`](../reference/errors/data-errors.mdx#partialarrayerror).

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.findOne({}).select({ tags: { $slice: 2 } }).orFail();

order.tags.push("z"); // допустимо: не зависит от позиций
order.tags.splice(0, 1); // PartialArrayError при $save
```

```text
PartialArrayError: "tags" was loaded partially (projection); a $set of the whole array would overwrite the elements that were not loaded
```

Разрешены `push`, `unshift`, `addToSet` и `pull`, они от позиций не зависят. Запрещены `splice`, `sort`, `reverse`, `replace`, `clear`, `set` по индексу, `pop` и `shift`. `$getChanges` и здесь не бросает ошибку, а записывает причину в ключ `$problems`. Прочитайте документ без проекции массива.

## Полный пример

Функции сервиса заказа — добавить строку, убрать строку по id из адреса запроса и задать сбор.

import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";

  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()

  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
export const addLine = async (orderId: Order["_id"], sku: string, qty: number) => {
  const order = await Orders.findById(orderId).orFail();
  order.lines.push({ sku, qty });
  await order.$save();
  return order.lines.length;
};

export const removeLine = async (orderId: Order["_id"], lineId: Order["lines"][number]["_id"]) => {
  const order = await Orders.findById(orderId).orFail();
  const removed = order.lines.pull(lineId);
  await order.$save();
  return removed.length;
};

export const setFee = async (orderId: Order["_id"], name: string, amount: number) => {
  const order = await Orders.findById(orderId).orFail();
  order.$set(`fees.${name}`, amount);
  await order.$save();
};

## Если вы пришли из Mongoose

<Callout type="migration">

В Mongoose массив можно было менять по индексу и присваиванием, но тогда приходилось звать `markModified`. В Typemo запись по индексу и в `length` закрыта, изменения идут методами, а `DocumentArray` называется `SubdocumentArray`. Ошибки типов элементов Typemo бросает сразу, на вызове метода, а не копит в `invalidate`.

</Callout>
