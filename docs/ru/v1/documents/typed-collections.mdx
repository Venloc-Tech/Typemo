Чтобы изменить массив или Map в загруженном документе, вызовите метод коллекции — `push`, `pull`, `set`, `delete` — и сохраните документ: Typemo превратит вызов в точную операцию MongoDB (`$push`, `$pullAll`, `$set` одного ключа) и не перепишет поле целиком. Присваивания по индексу и `length` закрыты типами, потому что они не сообщают, что вы хотели сделать.

Причина проста. Если два клиента одновременно меняют массив тегов заказа, а вы отправляете массив целиком, победит тот, кто сохранил последним, и правка другого пропадёт. Операции `$push` и `$pull` описывают **что** изменить, а не **как теперь выглядит поле**, поэтому не конфликтуют. Такие массивы называются в Typemo типизированными коллекциями: [`StrictArray`](../reference/documents/typed-collections.mdx#strictarray) для массивов значений, [`SubdocumentArray`](../reference/documents/typed-collections.mdx#subdocumentarray) для массивов вложенных объектов и [`TypedMap`](../reference/documents/typed-collections.mdx#typedmap) для Map.

## Что предполагается

Примеры используют заказ из руководства [Изменить и сохранить документ](./change-and-save.mdx): теги `tags`, строки `lines` и Map сборов `fees`. Читать коллекции можно как обычные: `for…of`, `map`, `filter`, спред, `JSON.stringify` работают, а `map` и `filter` возвращают обычные массивы.

## Быстрый путь

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: ["a", "b", "c"], lines: [], fees: { delivery: 5 } });

order.tags.push("d"); // добавить
order.tags.pull("a"); // убрать по значению
order.tags.set(0, "B"); // заменить элемент по позиции
order.fees?.set("gift", 3); // добавить ключ Map
await order.$save();
```

Остальная страница разбирает каждый случай: какая операция уходит в базу, чего нельзя и что делать вместо этого.

## Добавить и убрать элементы

`push` добавляет в конец, `unshift` — в начало, `addToSet` — только то, чего ещё нет, `pull` убирает по значению. Каждый метод приводит значения к типу элемента сразу, поэтому ошибка типа появляется на строке вызова, а не при сохранении. Что вернёт метод, — как у обычного массива: `push` новую длину, `pull` и `addToSet` — убранные или добавленные элементы.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: ["a", "b", "c"], lines: [] });

order.tags.push("d", "e");
console.log(order.$getChanges());
// → { $push: { tags: { $each: ["d", "e"] } } }
await order.$save();

order.tags.pull("a");
console.log(order.$getChanges());
// → { $pullAll: { tags: ["a"] } }
```

Каждый вызов даёт свой оператор. Но если за одно сохранение у **одного и того же массива** сошлись разные операции, Typemo не пытается уложить их в одно обновление: два оператора по одному пути надёжно не объединить. Вместо этого он записывает массив целиком. Так будет, если вызвать `push` и `pull` подряд до сохранения, и так же будет после второго `pop`:

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: ["a", "b", "c"], lines: [] });

order.tags.push("d", "e");
order.tags.pull("a");
console.log(order.$getChanges());
// → { $set: { tags: ["b", "c", "d", "e"] } }
```

Запись всего массива менее точна: правка другого клиента в этом же массиве, сделанная между вашим чтением и сохранением, будет затёрта. Поэтому, если параллельные изменения возможны, сохраняйте после каждого вида операции или используйте [`$getChanges`](../reference/documents/document-api.mdx#getchanges), чтобы проверить, какая операция уйдёт.

## Заменить элемент

Чтобы заменить существующий элемент, вызовите `set(index, value)`. Индекс должен существовать: добавлять элементы по несуществующему индексу нельзя.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: ["a", "b", "c"], lines: [] });

order.tags.set(1, "B");
console.log(order.$getChanges());
// → { $set: { "tags.1": "B" } }
```

Операция `$set` по индексу привязана к позиции: если другой клиент успел убрать первый элемент, индекс `1` теперь указывает на другой элемент. Поэтому у документов с версией такой `$set` защищён проверкой `__v`: см. [Версии и параллельные изменения](./versions.mdx). Если позиция вам не важна, надёжнее убирать по значению через `pull`.

## Изменить поддокумент в массиве

Элементы массива классов — поддокументы, и их поля меняют обычным присваиванием. Typemo запишет путь с индексом, вычисленным в момент сохранения.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: [], lines: [{ sku: "A1", qty: 2 }, { sku: "B2", qty: 1 }] });

order.lines[1]!.qty = 9;
console.log(order.$getChanges());
// → { $set: { "lines.1.qty": 9 } }
```

Чтобы добавить новый элемент, передайте [`push`](../reference/documents/typed-collections.mdx#strictarraypush) обычный объект: поле `_id` создастся само. Готовый поддокумент, ещё не прикреплённый к массиву, делает [`lines.create`](../reference/documents/typed-collections.mdx#subdocumentarraycreate).

## Найти и убрать поддокумент по id

У поддокументов есть `_id`, поэтому найти и убрать элемент можно по идентификатору, а не по позиции. [`lines.id(id)`](../reference/documents/typed-collections.mdx#subdocumentarrayid) возвращает элемент или `undefined`, [`lines.pull(id)`](../reference/documents/typed-collections.mdx#subdocumentarraypull) убирает его операцией `$pull` по `_id`, которая не зависит от позиций. Идентификатор можно передать и строкой: так удобно использовать значение из адреса запроса, не оборачивая его в `ObjectId`.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: [], lines: [{ sku: "A1", qty: 2 }, { sku: "B2", qty: 1 }] });
const lineId = order.lines[0]!._id;

console.log(order.lines.id(lineId)?.sku);
// → "A1"
const removed = order.lines.pull(lineId);
console.log(removed.map((line) => line.sku), Object.keys(order.$getChanges()));
// → ["A1"] ["$pull"]
```

## Работать с Map

Map меняют методами `set`, `delete` и `clear`. Ключ проверяется при вызове: непустая строка, без точки, не начинается с `$` и не `__proto__`, потому что иначе ключ читался бы как путь или оператор.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: [], lines: [], fees: { delivery: 5, gift: 3 } });

order.fees?.set("insurance", 7);
order.fees?.delete("gift");
console.log(order.$getChanges());
// → { $set: { "fees.insurance": 7 }, $unset: { "fees.gift": "" } }
```

## Получить обычную копию

Чтобы передать содержимое дальше, не привязывая его к документу, используйте [`$toObject`](../reference/documents/typed-collections.mdx#strictarray) коллекции, спред или `map`: результат — обычный массив, и его изменение документ не затрагивает.

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.create({ customer: "alice", tags: ["a", "b"], lines: [] });

const copy = [...order.tags];
copy.push("c");
console.log(order.tags.length, copy.length, Array.isArray(order.tags.$toObject()));
// → 2 3 true
```

## Пустой массив по умолчанию

Поле-массив без `required` и без `default` всегда существует: у нового документа (`create`, `Model.new`) и у документа, прочитанного из базы без этого ключа, оно — пустой массив, а не `undefined`. Поэтому `order.tags.push("a")` работает на любом заказе, и следующий `$save` запишет ключ, которого в базе не было. Так же пустой массив получают новые поддокументы и документы, вставленные через upsert. `lean()` отдаёт документ как он хранится, без ключа. У массива с `required: true` умолчания нет: без значения `create` откажет.

## Как выбрать

Задайте себе вопрос: **что должно остаться от изменений других клиентов?** Если чужие изменения массива должны сохраниться, используйте методы, которые дают точные операции: `push`, `addToSet`, `pull`, `pop`, поле внутри поддокумента. Если вы сознательно перезаписываете массив целиком (импорт, синхронизация со внешним источником), используйте [`replace`](../reference/documents/typed-collections.mdx#strictarrayreplace) или `sort`: они честно записывают массив целиком. Разница между `push` и `addToSet` одна: `addToSet` не добавляет то, что уже есть.

## Когда это не нужно

Если вы изменяете массив у многих документов сразу или у документа, который не хотите загружать, используйте операторы обновления [`$push`, `$pull` и `$addToSet`](../reference/writes/update-operators.mdx) в [`updateOne`](../reference/writes/writes.mdx#updateone) и [`updateMany`](../reference/writes/writes.mdx#updatemany). Коллекции нужны там, где документ уже загружен и меняется в коде.

## Частые ошибки

### Запись по индексу не компилируется

`order.tags[0] = "x"` и `order.tags.length = 0` не проходят проверку типов:

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
const order = Orders.new({ customer: "alice", tags: ["gift"], lines: [] });
// ---cut---
// @errors: 2542
order.tags[0] = "express";
```

Исправление: [`tags.set(0, "express")`](../reference/documents/typed-collections.mdx#strictarrayset) для замены и [`tags.clear()`](../reference/documents/typed-collections.mdx#strictarrayclear) вместо `length = 0`.

### Сохранение отказывается писать «мимо методов»

Если запись в массив или Map прошла в обход методов (приведение к `any`, `Array.prototype.push.call`, `Map.prototype.set.call`), `$save` бросает [`DirectWriteError`](../reference/errors/data-errors.mdx#directwriteerror) и подсказывает метод. [`$getChanges`](../reference/documents/document-api.mdx#getchanges) в этом случае не бросает ошибку, а показывает тот же текст в ключе `$problems`:

```text
DirectWriteError: "tags" was changed around its methods: its length is 4 instead of 3 (use push(), pop(), splice(), clear() or replace())
```

Typemo не пытается догадаться, что вы имели в виду, потому что догадка могла бы затереть чужие данные. Исправление: замените запись методом коллекции.

### Массив загружен частично

Если вы прочитали часть массива (`select({ tags: { $slice: 2 } })`), вы видите не все его элементы. Допустим, в заказе теги `a`, `b`, `c`. Изменение, которое перезаписало бы то, чего вы не видели, — [`PartialArrayError`](../reference/errors/data-errors.mdx#partialarrayerror):

```ts twoslash
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
const order = await Orders.findOne({}).select({ tags: { $slice: 2 } }).orFail();

order.tags.push("z"); // допустимо: не зависит от позиций
order.tags.splice(0, 1); // PartialArrayError при $save
```

```text
PartialArrayError: "tags" was loaded partially (projection); a $set of the whole array would overwrite the elements that were not loaded
```

Разрешены `push`, `unshift`, `addToSet` и `pull`: они не зависят от позиций. Запрещены `splice`, `sort`, `reverse`, `replace`, `clear`, `set` по индексу, `pop` и `shift`. `$getChanges` при этом не бросает ошибку, а записывает причину в ключ `$problems`. Исправление: прочитайте документ без проекции массива.

## Полный пример

Функции сервиса заказа: добавить строку, убрать строку по id из адреса запроса и задать сбор.

```ts twoslash title="orders/orders.service.ts"
import { Entity, type Hidden, Prop, Schema, Spec, TypemoClient, Versioned } from "@venloc/typemo";
@Schema({ nested: true })
class Address {
  @Prop(() => String, { required: true }) city!: string;
  @Prop(() => String) street?: string;
}
@Schema()
class Line extends Entity {
  @Prop(() => String, { required: true }) sku!: string;
  @Prop(() => Number, { required: true, min: 0 }) qty!: number;
}
@Schema({ collection: "orders" })
class Order extends Versioned(Entity) {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => [String]) tags!: string[];
  @Prop(() => [Line]) lines!: Line[];
  @Prop(() => Address) address?: Address;
  @Prop(() => Spec.map(Number)) fees?: Map<string, number>;
  @Prop(() => String, { hidden: true }) note?: Hidden<string>;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "shop" });
const Orders = client.db().model(Order);
// ---cut---
export const addLine = async (orderId: Order["_id"], sku: string, qty: number) => {
  const order = await Orders.findById(orderId).orFail();
  order.lines.push({ sku, qty });
  await order.$save();
  return order.lines.length;
};

export const removeLine = async (orderId: Order["_id"], lineId: Order["lines"][number]["_id"]) => {
  const order = await Orders.findById(orderId).orFail();
  const removed = order.lines.pull(lineId);
  await order.$save();
  return removed.length;
};

export const setFee = async (orderId: Order["_id"], name: string, amount: number) => {
  const order = await Orders.findById(orderId).orFail();
  order.$set(`fees.${name}`, amount);
  await order.$save();
};
```

## Если вы пришли из Mongoose

<Callout type="migration">

В Mongoose массив можно было менять по индексу и присвоением, но тогда нужно было звать `markModified`. В Typemo индексы и `length` для записи закрыты, изменения идут методами, а `DocumentArray` называется `SubdocumentArray`. Ошибки типов элементов Typemo бросает сразу, на вызове метода, а не собирает в `invalidate`.

</Callout>
