**Плагин** — это объект с именем и функцией `apply`. При компиляции схемы `apply` добавляет в неё поля, индексы, хуки, виртуальные поля, методы модели и политики. Плагин нужен, когда одно и то же поведение требуется многим моделям — общий хук журнала, мягкое удаление, набор индексов или общие методы. Вы пишете его один раз и подключаете, а не копируете код в каждый класс.

Если нужен один хук на одной модели, плагин ни к чему, хватит метода класса с [`@Pre`](../reference/hooks/pre-post.mdx#pre). А если вы хотите только хранить свои настройки у поля, смотрите [Свои опции полей и схем](../extensions/custom-options.mdx).

## Что понадобится

Модель счёта и клиент из руководства [Подключиться к базе](../connection/connect.mdx). `Accounts` — модель счёта, полученная у клиента уже после подключения плагинов.

## Быстрый путь

Плагин — это объект `{ name, apply }`. К модели его подключает декоратор [`@Plugin`](../reference/hooks/plugins.mdx#plugin), к базе — `connection.plugins.use`, ко всему приложению — [`Typemo.plugin`](../reference/connection/typemo.mdx#typemoplugin).

```ts twoslash title="plugins/read-log.ts"
import { Entity, Plugin, Prop, Schema, type SchemaPlugin } from "@venloc/typemo";

export const readLog: SchemaPlugin = {
  name: "read-log",
  apply: (builder) => {
    builder.addHook("post", "query.find", function () {
      console.log(`прочитан список ${builder.target.name}`);
    });
  },
};

@Plugin(readLog)
@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;
}
```

Теперь `find()` этой модели выводит `прочитан список Account`. Ниже разберём, что плагин умеет добавлять и как выбрать уровень подключения.

## Написать плагин

Функция `apply` получает [`PluginBuilder`](../reference/hooks/plugins.mdx#pluginbuilder) — узкий интерфейс, через который плагин меняет схему. Она вызывается один раз для каждой схемы. Построитель знает, какую модель компилирует (`builder.target`) и какие поля в ней уже есть (`builder.fieldKeys`).

Плагин может добавить поле, индекс, хук, виртуальную связь, статический метод и политику. Хуки плагина вешаются на те же [события](../reference/hooks/pre-post.mdx#hook_events), что и хуки класса, и выполняются после них. Их функция объявляется как `function (this: unknown)`. Построитель не знает, какой `this` у какого события, так что при необходимости приведите его сами.

```ts twoslash
import { type SchemaPlugin } from "@venloc/typemo";
// ---cut---
export const inspect: SchemaPlugin = {
  name: "inspect",
  apply: (builder) => {
    console.log(builder.target.name, builder.fieldKeys);
    // → Account [ "_id", "title" ]
  },
};
```

Подключённый к модели с полями `_id` и `title`, этот плагин выведет `Account [ "_id", "title" ]`.

## Подключить к модели, базе или приложению

Уровней три, и разница между ними в том, каким моделям достанется плагин. Применяются они по порядку — сначала глобальные, потом плагины базы, потом плагины модели.

К одной модели плагин подключается декоратором `@Plugin` над классом. Несколько плагинов применяются сверху вниз.

```ts twoslash
import { Entity, Plugin, Prop, Schema, type SchemaPlugin } from "@venloc/typemo";
const readLog: SchemaPlugin = { name: "read-log", apply: () => {} };
const stamped: SchemaPlugin = { name: "stamped", apply: () => {} };
// ---cut---
@Plugin(readLog)
@Plugin(stamped)
@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;
}
```

Ко всем моделям одной базы плагин подключается через реестр базы, а ко всем моделям приложения — через `Typemo.plugin`. Оба вызова нужно сделать **до первой модели**.

```ts twoslash
import { Typemo, TypemoClient, type SchemaPlugin } from "@venloc/typemo";
const readLog: SchemaPlugin = { name: "read-log", apply: () => {} };
const stamped: SchemaPlugin = { name: "stamped", apply: () => {} };
// ---cut---
Typemo.plugin(readLog); // все клиенты, все модели

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
client.db().plugins.use(stamped); // только модели этой базы
```

Если один и тот же плагин подключён на двух уровнях с одинаковыми настройками, он применяется один раз, там, где встретился впервые. Скажем, плагин базы `conn` и плагин `both` на уровне и базы, и модели дадут порядок `conn`, `both`. Если настройки различаются или два разных плагина названы одинаково, будет `ConfigurationError`. Тексты ошибок — в разделе «Если что-то пошло не так».

## Плагин с настройками

Настройки передаются вторым аргументом и приходят в `apply`. Их тип — первый параметр `SchemaPlugin<O>`. Если настройки обязательны, компилятор потребует их при подключении.

```ts twoslash
import { Entity, Plugin, Prop, Schema, type SchemaPlugin } from "@venloc/typemo";
// ---cut---
export const noted: SchemaPlugin<{ readonly field: string }> = {
  name: "noted",
  apply: (builder, options) => {
    builder.addField(options.field, () => String);
  },
};

@Plugin(noted, { field: "note" })
@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;
}
```

Плагин такого же вида с полем `seenAt` (`addField("seenAt", () => Date)`) сохраняет переданное значение в документе. Но тип модели об этом поле не знает. Плагин добавляет его при компиляции схемы, а компилятор TypeScript видит только объявленный класс. Записать и прочитать такое поле можно с приведением типа. Если поле нужно в типах, объявите его в самом классе.

## Добавить модели методы

Плагин может добавить статические методы, и их получат все модели, к которым он подключён. Методы объявляются в объекте `statics` плагина, и `this` в них — модель. Типизированный доступ к ним даёт [`Model.statics`](../reference/hooks/plugins.mdx#modelstatics). Он возвращает ту же модель, но уже с типами методов плагина.

```ts twoslash
import { Entity, Plugin, Prop, Schema, TypemoClient, type Model, type SchemaPlugin } from "@venloc/typemo";

const statics = {
  async byTitle(this: Model<Account>, title: string): Promise<number> {
    return this.countDocuments({ title });
  },
};

export const tools: SchemaPlugin<undefined, typeof statics> = {
  name: "tools",
  apply: () => {},
  statics,
};

@Plugin(tools)
@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);
// ---cut---
const count = await Accounts.statics(tools).byTitle("Main");
//    ^?
```

После вставки счёта `w` вызов `byTitle("w")` вернёт `1`. Метод привязан к модели, поэтому параметра `this` в его типе нет.

Модель, к которой плагин не подключён, проверяется во время работы. Тип не обещает метода, которого нет.

```text
ConfigurationError: Account: plugin "tools" is not applied to this model's schema
```

Если имя метода совпадает с членом модели, например `find` или `create`, тихо затенить его не выйдет. При создании модели вы получите `ConfigurationError` с текстом `the plugin static "find" would shadow a member of the model`.

## Включить политику

Плагин может включить политику — `tenant`, `softDelete` или `audit` — с теми же опциями, что у [`@Schema`](../reference/schemas/schema.mdx). Так плагин мягкого удаления одной строкой подключается ко всем моделям с полем `deletedAt`.

```ts twoslash
import { Entity, Plugin, Prop, Schema, type SchemaPlugin } from "@venloc/typemo";
// ---cut---
export const softly: SchemaPlugin = {
  name: "softly",
  apply: (builder) => builder.enablePolicy("softDelete", true),
};

@Plugin(softly)
@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Date, { nullable: true })
  deletedAt?: Date | null;
}
```

После `deleteOne({ title: "w" })` `countDocuments()` вернёт 0, а в самой коллекции документ останется. Если политика уже включена в `@Schema` с другими опциями, а плагин включает её иначе, будет `ConfigurationError` вида `declared by @Schema and enabled by plugin "other"`. Подробнее о самой политике — в руководстве [Мягкое удаление](../policies/soft-delete.mdx).

## Как выбрать

Спросите себя, **сколько моделей должны это получить**.

- **Одна модель** — метод класса или `@Plugin` над ней.
- **Все модели одной базы** — реестр базы.
- **Все модели приложения**, включая созданные библиотеками, — `Typemo.plugin`.

Чем шире уровень, тем строже порядок. Глобальные плагины и плагины базы закрываются первой успешно скомпилированной схемой. `@Plugin` привязан к классу, и порядок запуска ему не важен.

## Когда это не нужно

Один хук на одной модели плагином не оформляйте. Менять операции напрямую плагин не может, у него есть только хуки, и они проходят все политики. Чтобы наблюдать за операциями всех моделей, берите [события операций](../observability/events.mdx) — подписчик глобален и ничего не ломает. А если нужны свои опции поля и их проверка, пишите [расширение](../extensions/custom-options.mdx).

## Если что-то пошло не так

**Плагин зарегистрирован слишком поздно.**

```text
ConfigurationError: plugin "late": the global plugins are fixed once a schema is compiled (Account was); register plugins before the first model
```

Реестр закрывается первой **успешно** скомпилированной схемой, иначе плагин достался бы не всем моделям. Реестр базы закрывает первая модель этой базы, а глобальный реестр (`Typemo.plugin`) — первая модель на любом клиенте приложения. Схема, которая не скомпилировалась, реестры не закрывает, и после такой ошибки плагин ещё можно зарегистрировать.

Перенесите регистрацию в самое начало запуска, до создания моделей. Для базы текст тот же, только со словами `the connection plugins`. Расширения закрываются по тому же правилу, подробнее — в руководстве [Несколько клиентов и расширения](../connection/clients-and-extensions.mdx#регистрировать-до-первой-модели).

**Один плагин с разными настройками.**

```text
ConfigurationError: Account: plugin "stamped" is registered twice (connection and model) with different options
```

Один и тот же плагин на двух уровнях с разными настройками неоднозначен. Оставьте одно подключение или сделайте настройки одинаковыми.

**Два плагина с одним именем.**

```text
ConfigurationError: Account: two different plugins are named "both"
```

Имя плагина должно быть уникальным. Переименуйте один из них.

**Плагин без имени.**

```text
ConfigurationError: a plugin is an object { name, apply(builder, options) }
```

## Полный пример

Плагин, который добавляет методы и хук, и модель, которая им пользуется.

```ts twoslash title="plugins/tools.ts"
import { Entity, Plugin, Prop, Schema, TypemoClient, type Model, type SchemaPlugin } from "@venloc/typemo";

const statics = {
  async byTitle(this: Model<Account>, title: string): Promise<number> {
    return this.countDocuments({ title });
  },
};

// Плагин: метод модели и хук чтения.
export const tools: SchemaPlugin<undefined, typeof statics> = {
  name: "tools",
  apply: (builder) => {
    builder.addHook("post", "query.find", function () {
      console.log(`прочитан список ${builder.target.name}`);
    });
  },
  statics,
};

@Plugin(tools)
@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;
}

const client = await TypemoClient.connect("mongodb://localhost:27017", { dbName: "app" });
const Accounts = client.db().model(Account);

await Accounts.create({ title: "Main" });
await Accounts.find(); // → прочитан список Account
console.log(await Accounts.statics(tools).byTitle("Main"));
// → 1
```

<Callout type="migration">

В Mongoose глобальные плагины применяются в момент `model()`, поэтому плагин, зарегистрированный после создания части моделей, на них молча не действует. В Typemo это [`ConfigurationError`](../reference/errors/configuration-errors.mdx#configurationerror). Статические методы там добавляются как `schema.statics.x = …` и без типов. Здесь они типизированы через `statics` плагина и `model.statics(plugin)`, а совпадение имени с методом модели — ошибка, а не тихое затенение.

</Callout>
