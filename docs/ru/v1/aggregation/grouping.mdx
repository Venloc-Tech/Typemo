Отчёт почти всегда отвечает на вопрос «сколько» по группам. Сколько потратил каждый клиент, сколько заказов пришло за месяц, сколько их в каждом диапазоне сумм. В агрегации этим занимается стадия [`group`](../reference/aggregation/stages.mdx#group). Она собирает документы с одинаковым ключом в одну строку и считает значения по группе **аккумуляторами** — функциями, которые сворачивают много значений в одно, вроде `fn.sum`, `fn.avg` или `fn.count`.

Для типовых отчётов есть короткие стадии.

- [`bucket`](../reference/aggregation/stages.mdx#bucket) и [`bucketAuto`](../reference/aggregation/stages.mdx#bucketauto) раскладывают значения по диапазонам.
- [`sortByCount`](../reference/aggregation/stages.mdx#sortbycount) считает повторы.
- [`count`](../reference/aggregation/stages.mdx#count) считает строки.

Компилятор следит, чтобы в группировке остались только аккумуляторы, и выводит тип каждой строки отчёта. Поэтому `spent` ниже — это `number`, а не «что-то из базы».

## Что понадобится

Клиент из руководства [Подключиться к базе](../connection/connect.mdx), запуск агрегации из руководства [Первая агрегация](first-aggregation.mdx) и модель заказа. В коллекции `orders` пять заказов.

- `alice` — 120 и 80, оба оплачены, в январе и феврале.
- `bob` — 50, оплачен в феврале, и 200, отменён в марте.
- `carol` — 30, новый, март.

```ts twoslash title="orders/order.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "orders" })
export class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true })
  status!: string;

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Date, { required: true })
  placedAt!: Date;
}
```

## Быстрый путь

`_id` группировки — то, по чему группируем. Остальные поля — аккумуляторы.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
const query = Orders.aggregate((p) =>
  p
    .group((f) => ({ _id: f.customer, orders: fn.count(), spent: fn.sum(f.total) }))
    .sort({ _id: 1 }),
);
const rows = await query;
//    ^?
// → [{ _id: "alice", orders: 2, spent: 200 }, { _id: "bob", orders: 2, spent: 250 }, { _id: "carol", orders: 1, spent: 30 }]
```

Для диапазонов сумм есть `bucket`, для подсчёта повторов — `sortByCount`. Ниже разберём каждый случай.

## Посчитать по группам

Менеджеру нужна сводка по клиентам — число заказов, сумма, среднее и самый крупный заказ. `_id` — это ключ группы, и без него компилятор стадию не примет. Все остальные поля — аккумуляторы.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
const query = Orders.aggregate((p) =>
  p
    .group((f) => ({
      _id: f.customer,
      orders: fn.count(),
      spent: fn.sum(f.total),
      average: fn.avg(f.total),
      biggest: fn.max(f.total),
    }))
    .sort({ _id: 1 }),
);
const rows = await query;
//    ^?
// → [{ _id: "alice", orders: 2, spent: 200, average: 100, biggest: 120 }, { _id: "bob", orders: 2, spent: 250, average: 125, biggest: 200 }, …]
```

Посмотрите на тип. После `group` в строке только `_id` и ваши аккумуляторы, а `placedAt` и `status` пропали. Все аккумуляторы перечислены в справочнике [Аккумуляторы](../reference/aggregation/accumulators.mdx).

## Сгруппировать по нескольким полям и по дате

Ключ группы может быть составным объектом или вычисленным значением. Составной нужен, когда одного поля мало, например клиент и статус вместе. А чтобы посчитать выручку по месяцам, ключ вычисляют из даты через [`fn.dateToString`](../reference/aggregation/expr-date.mdx#fndatetostring).

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
const query = Orders.aggregate((p) =>
  p
    .group((f) => ({
      _id: fn.dateToString({ date: f.placedAt, format: "%Y-%m" }),
      revenue: fn.sum(f.total),
    }))
    .sort({ _id: 1 }),
);
const rows = await query;
//    ^?
// → [{ _id: "2026-01", revenue: 120 }, { _id: "2026-02", revenue: 130 }, { _id: "2026-03", revenue: 230 }]
```

Для составного ключа напишите `_id: { customer: f.customer, status: f.status }`, и строки будут вида `{ _id: { customer: "bob", status: "paid" }, n: 1 }`. Сортировать по части такого ключа можно через путь — `.sort({ "_id.customer": 1 })`.

## Посчитать всё одной строкой

Когда группа одна на весь набор, ключ — `null`. Так считают итоги вроде общей выручки или числа заказов.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
const totals = await Orders.aggregate((p) =>
  p.group((f) => ({ _id: null, revenue: fn.sum(f.total), orders: fn.count() })),
);
// → [{ _id: null, revenue: 480, orders: 5 }]
```

Если документов нет совсем, группа не создаётся, и вы получите пустой массив, а не строку с нулями. Так ведёт себя сервер, и это стоит учесть, когда показываете итоги.

## Собрать значения в список

Аккумуляторы бывают не только числовые. [`fn.push`](../reference/aggregation/accumulators.mdx#fnpush) собирает значения группы в массив, [`fn.addToSet`](../reference/aggregation/accumulators.mdx#fnaddtoset) — то же без повторов. [`fn.first`](../reference/aggregation/accumulators.mdx#fnfirst) и [`fn.last`](../reference/aggregation/accumulators.mdx#fnlast) берут первое и последнее значение. Но «первое» зависит от порядка документов на входе, поэтому перед ними ставят [`sort`](../reference/aggregation/stages.mdx#sort). Если порядок нужен внутри самой группировки, есть [`fn.top`](../reference/aggregation/accumulators.mdx#fntop) со своим `sortBy`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
const query = Orders.aggregate((p) =>
  p
    .group((f) => ({
      _id: f.customer,
      totals: fn.push(f.total),
      best: fn.top({ output: f.total, sortBy: [[f.total, -1]] }),
    }))
    .sort({ _id: 1 }),
);
const rows = await query;
//    ^?
// → [{ _id: "alice", totals: [120, 80], best: 120 }, { _id: "bob", totals: [50, 200], best: 200 }, …]
```

В `push` элементы идут в том же порядке, что и документы на входе. У `addToSet` порядка нет вовсе, не рассчитывайте на него. Ссылки на поля в `sortBy` берутся из `f`, а не пишутся строками, и путь проверяет компилятор.

## Разложить по диапазонам

Чтобы понять, много ли в магазине крупных заказов, значения раскладывают по **корзинам** — диапазонам с заданными границами. [`bucket`](../reference/aggregation/stages.mdx#bucket) принимает выражение `groupBy` и границы `boundaries`, где нижняя граница включается, а верхняя нет. Можно добавить `default` для тех, кто не попал ни в один диапазон. В `_id` каждой строки — нижняя граница корзины.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
const query = Orders.aggregate((p) =>
  p.bucket({
    groupBy: (f) => f.total,
    boundaries: [0, 50, 100, 500],
    default: "other",
    output: (f) => ({ orders: fn.count(), sum: fn.sum(f.total) }),
  }),
);
const rows = await query;
//    ^?
// → [{ _id: 0, orders: 1, sum: 30 }, { _id: 50, orders: 2, sum: 130 }, { _id: 100, orders: 2, sum: 320 }]
```

Границы идут по возрастанию, и их тип совпадает с типом `groupBy`, так что строки вместо чисел компилятор не примет. Без `default` сервер отвергает документы, которые не попали ни в один диапазон, — `ServerError: $switch could not find a matching branch for an input, and no default was specified. (code 7158303 Location7158303)`. Если значения ничем не ограничены, `default` нужен.

А если границ вы не знаете и хотите просто поделить значения на корзины поровну, берите [`bucketAuto`](../reference/aggregation/stages.mdx#bucketauto). Вы задаёте число корзин, а границы сервер выбирает сам. `_id` тогда — объект `{ min, max }`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
const rows = await Orders.aggregate((p) =>
  p.bucketAuto({ groupBy: (f) => f.total, buckets: 2, output: () => ({ orders: fn.count() }) }),
);
// → [{ _id: { min: 30, max: 120 }, orders: 3 }, { _id: { min: 120, max: 200 }, orders: 2 }]
```

## Подсчитать повторы

Чтобы узнать, какой статус встречается чаще всего, целый `group` с сортировкой не нужен. [`sortByCount`](../reference/aggregation/stages.mdx#sortbycount) делает всё сразу. Группирует по выражению, считает и сортирует по убыванию счётчика. Строка выглядит как `{ _id, count }`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
const rows = await Orders.aggregate((p) => p.sortByCount((f) => f.status));
// → [{ _id: "paid", count: 3 }, { _id: "cancelled", count: 1 }, { _id: "new", count: 1 }]
```

Порядок групп с одинаковым счётчиком, как `cancelled` и `new` здесь, не определён. Если он важен, добавьте [`sort`](../reference/aggregation/stages.mdx#sort) по второму полю. А число строк на входе считает стадия [`count`](../reference/aggregation/stages.mdx#count), которой вы даёте имя поля результата.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
const rows = await Orders.aggregate((p) => p.match({ status: "paid" }).count("paidOrders"));
//    ^?
// → [{ paidOrders: 3 }]
```

Если нужно одно число и больше никаких стадий, проще взять [`countDocuments`](../reference/query/reading.mdx#modelcountdocuments).

## Как выбрать

Спросите себя, какой ключ у результата.

- **Значение поля или вычисление** — клиент, месяц, статус. Нужен `group`.
- **Диапазон значения** — `bucket`, если границы известны, или `bucketAuto`, если нужны равные части.
- **Только число повторов каждого значения** — хватит `sortByCount`.
- **Одно число на весь набор** — `group` с ключом `null`.

## Когда это не нужно

Для одного счётчика по фильтру берите [`countDocuments`](../reference/query/reading.mdx#modelcountdocuments), для уникальных значений поля — [`distinct`](../reference/query/reading.mdx#modeldistinct). Они обходятся без конвейера. А если отчёт нужен постоянно и считается долго, сохраните результат — [материализованное представление или `$out`](output.mdx).

## Если что-то пошло не так

**Вычисление вместо аккумулятора.** В `group` каждое поле, кроме `_id`, должно быть аккумулятором. Обычная функция вроде `fn.add` считает по одному документу и здесь не годится. Компилятор называет причину прямо в ошибке.

```ts twoslash
// @errors: 2741
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
await Orders.aggregate((p) => p.group((f) => ({ _id: f.customer, plusOne: fn.add(f.total, 1) })));
```

Ошибка выглядит так — `Property 'error' is missing in type '{ readonly _id: …; readonly plusOne: Expr<number>; }' but required in type 'PathError<"$group field \"plusOne\" needs an accumulator (fn.sum, fn.avg, fn.push, fn.first, fn.count, ...)">'`. Смотрите в конец. Там имя поля (`plusOne`), стадия и список подходящих аккумуляторов. Оберните значение в аккумулятор, например `fn.sum(fn.add(f.total, 1))`.

То же правило действует для `output` у `bucket` и `bucketAuto`. И наоборот — `fn.push`, `fn.count` и другие чисто аккумуляторные операторы в `project` и `addFields` не скомпилируются.

**Забыт `_id`.** Ключ группы обязателен, даже когда группа одна, — тогда пишут `_id: null`. Без него стадия не скомпилируется с ошибкой `Property '_id' is missing in type '{ readonly spent: DualExpr<number>; }' but required in type '{ readonly _id: unknown; }'`.

```ts twoslash
// @errors: 2741
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
await Orders.aggregate((p) => p.group((f) => ({ spent: fn.sum(f.total) })));
```

**После группировки пропали нужные поля.** После `group` в строке остаются только `_id` и аккумуляторы. Если следующая стадия читает `status`, а вы его не сохранили, компилятор скажет, что такого поля нет. Добавьте его в группировку аккумулятором, например `fn.first(f.status)`, или сделайте частью ключа.

## Полный пример

```ts twoslash title="reports/sales.ts"
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
// 1. Сводка по клиентам оплаченных заказов.
export const spendingByCustomer = () =>
  Orders.aggregate((p) =>
    p
      .match({ status: "paid" })
      .group((f) => ({ _id: f.customer, orders: fn.count(), spent: fn.sum(f.total) }))
      .sort({ spent: "descending" }),
  ).plain();

// 2. Выручка по месяцам.
export const revenueByMonth = () =>
  Orders.aggregate((p) =>
    p
      .group((f) => ({
        _id: fn.dateToString({ date: f.placedAt, format: "%Y-%m" }),
        revenue: fn.sum(f.total),
      }))
      .sort({ _id: 1 }),
  ).plain();

// 3. Распределение заказов по диапазонам сумм.
export const ordersBySize = () =>
  Orders.aggregate((p) =>
    p.bucket({
      groupBy: (f) => f.total,
      boundaries: [0, 50, 100, 500],
      default: "other",
      output: () => ({ orders: fn.count() }),
    }),
  ).plain();
```
