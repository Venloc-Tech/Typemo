**Выражение** — это вычисление над полями документа. Сложить цену и налог, склеить строки, выбрать одно из двух значений. Стадии агрегации принимают выражения там, где нужно посчитать новое значение, — в [`addFields`](../reference/aggregation/stages.mdx#addfields), [`project`](../reference/aggregation/stages.mdx#project), [`match`](../reference/aggregation/stages.mdx#match) и [`group`](../reference/aggregation/stages.mdx#group). Сервер MongoDB записывает выражения строками вроде `"$price"` и объектами с операторами вроде `{ $add: [...] }`. В Typemo вы пишете обычный TypeScript. Поля берёте из параметра `f`, операции — из объекта [`fn`](../reference/aggregation/expr-arithmetic.mdx).

Так вычисления проверяет компилятор. Опечатка в имени поля, сложение числа со строкой, аккумулятор вместо обычного значения — всё это ошибки компиляции, а не пустая строка или `null` в отчёте через час работы.

## Что понадобится

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель товара магазина. Про стадии и запуск агрегации рассказывает [Первая агрегация](first-aggregation.mdx). В коллекции `products` три товара.

- Чайник — цена 40, скидка 5.
- Лампа — цена 25, без скидки.
- Кружка «$5 mug» — цена 8, скидка 1.

```ts twoslash title="products/product.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "products" })
export class Product extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Number, { required: true })
  price!: number;

  @Prop(() => Number)
  discount?: number;

  @Prop(() => [String], { required: true })
  tags!: string[];
}
```

## Быстрый путь

Колбэк стадии получает `f` — описание полей текущей строки — и возвращает объект с новыми значениями. Считают значения функции `fn`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, Vars, type RowOf } from "@venloc/typemo";

@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number) discount?: number;
  @Prop(() => [String], { required: true }) tags!: string[];
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.connection.model(Product);
// ---cut---
const query = Products.aggregate((p) =>
  p.project((f) => ({
    title: 1,
    _id: 0,
    label: fn.concat(f.title, " (", fn.toString_(f.price), ")"),
    tier: fn.cond(fn.gte(f.price, 30), "premium", "basic"),
  })),
);
const rows = await query;
//    ^?
// → [{ title: "Kettle", label: "Kettle (40)", tier: "premium" }, { title: "Lamp", … "basic" }, …]
```

Ниже разберём поля, вложенные и отсутствующие значения, условия, массивы и то, почему вместо сырых строк с `$` вы пишете код.

## Сослаться на поле

`f.price` — это не цена, а **ссылка на поле**. Сервер сам прочитает его в каждом документе. Поэтому сравнить `f.price` с числом через `>` нельзя, для этого есть [`fn.gt`](../reference/aggregation/expr-logic.mdx#fngt). Зато у ссылки есть тип. Редактор подсказывает поля модели, а неизвестное поле не скомпилируется.

```ts twoslash
// @errors: 2551
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, Vars, type RowOf } from "@venloc/typemo";

@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number) discount?: number;
  @Prop(() => [String], { required: true }) tags!: string[];
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.connection.model(Product);
// ---cut---
await Products.aggregate((p) => p.addFields((f) => ({ x: fn.add(f.prise, 1) })));
```

Компилятор предложит ближайшее имя, `price`. Вложенные документы доступны по цепочке, например `f.address.city`. Если родитель необязателен или может быть `null`, каждое поле под ним получает `| undefined`. Сервер прочитает отсутствующее значение как «нет значения», и тип честно об этом говорит.

## Посчитать новое поле

Чтобы добавить к строке вычисленное поле, возьмите `addFields`. Он оставляет все старые поля и добавляет новые, и тип строки растёт на ваши поля.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, Vars, type RowOf } from "@venloc/typemo";

@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number) discount?: number;
  @Prop(() => [String], { required: true }) tags!: string[];
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.connection.model(Product);
// ---cut---
const withTax = Pipeline.from(Product).addFields((f) => ({
  gross: fn.multiply(f.price, 1.2),
}));
type Row = RowOf<typeof withTax>;
//   ^?
```

Операторы называются как в MongoDB, только без `$` — `fn.add`, `fn.concat`, `fn.size`. Два имени отличаются от серверных. [`fn.toString_`](../reference/aggregation/expr-conversion.mdx#fntostring_) — потому что `toString` в JavaScript уже есть у каждого объекта. [`fn.typeOf`](../reference/aggregation/expr-conversion.mdx#fntypeof) — это серверный `$type`. Все операторы по темам собраны в справочнике — [арифметика](../reference/aggregation/expr-arithmetic.mdx), [строки](../reference/aggregation/expr-string.mdx), [даты](../reference/aggregation/expr-date.mdx), [массивы](../reference/aggregation/expr-array.mdx).

## Отсутствующее значение и `null`

У лампы скидки нет, поля `discount` в документе просто нет. Вычтите его из цены, и сервер вернёт не цену, а `null` — любая арифметика с отсутствующим значением даёт `null`. Тип об этом знает. `fn.subtract(f.price, f.discount)` имеет тип `number | null`, и в поле `number` его не присвоить.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, Vars, type RowOf } from "@venloc/typemo";

@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number) discount?: number;
  @Prop(() => [String], { required: true }) tags!: string[];
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.connection.model(Product);
// ---cut---
const query = Products.aggregate((p) =>
  p.project((f) => ({ title: 1, _id: 0, final: fn.subtract(f.price, f.discount) })),
);
const rows = await query;
//    ^?
// → [{ title: "Kettle", final: 35 }, { title: "Lamp", final: null }, { title: "$5 mug", final: 7 }]
```

Чтобы подставить значение вместо отсутствующего, возьмите [`fn.ifNull`](../reference/aggregation/expr-logic.mdx#fnifnull). Первый аргумент — значение, второй — замена. В типе результата `null` уже нет.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, Vars, type RowOf } from "@venloc/typemo";

@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number) discount?: number;
  @Prop(() => [String], { required: true }) tags!: string[];
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.connection.model(Product);
// ---cut---
const query = Products.aggregate((p) =>
  p.project((f) => ({ title: 1, _id: 0, final: fn.subtract(f.price, fn.ifNull(f.discount, 0)) })),
);
const rows = await query;
//    ^?
// → [{ title: "Kettle", final: 35 }, { title: "Lamp", final: 25 }, { title: "$5 mug", final: 7 }]
```

Так работает сервер, и Typemo ничего не прячет. Без вашего решения результат не станет `0`. Что считать нулём, решаете вы.

## Выбрать значение по условию

[`fn.cond`](../reference/aggregation/expr-logic.mdx#fncond) выбирает из двух значений, [`fn.switch`](../reference/aggregation/expr-logic.mdx#fnswitch) — из нескольких. Тип результата — объединение вариантов. В быстром пути выше `tier` получил тип `"premium" | "basic"`, потому что обе ветки — литералы.

Условие в отборе пишется так же. [`match`](../reference/aggregation/stages.mdx#match) принимает либо объект-фильтр, либо функцию, которая возвращает булево выражение. Функция нужна, когда сравниваете два поля одного документа или считаете значение перед сравнением. Обычный фильтр вроде `{ price: { $gt: 20 } }` этого не умеет.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, Vars, type RowOf } from "@venloc/typemo";

@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number) discount?: number;
  @Prop(() => [String], { required: true }) tags!: string[];
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.connection.model(Product);
// ---cut---
const cheap = await Products.aggregate((p) =>
  p.match((f) => fn.lt(fn.subtract(f.price, fn.ifNull(f.discount, 0)), 30)).project({ title: 1, _id: 0 }),
);
// → [{ title: "Lamp" }, { title: "$5 mug" }]
```

## Работать с массивами

Функции над массивами принимают колбэк, а в нём — ссылку на текущий элемент. Она типизирована так же, как `f`, и у `tags` элемент — строка.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, Vars, type RowOf } from "@venloc/typemo";

@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number) discount?: number;
  @Prop(() => [String], { required: true }) tags!: string[];
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.connection.model(Product);
// ---cut---
const query = Products.aggregate((p) =>
  p.project((f) => ({
    title: 1,
    _id: 0,
    kitchen: fn.filter({ input: f.tags, cond: (tag) => fn.eq(tag, "kitchen") }),
    upper: fn.map({ input: f.tags, in: (tag) => fn.toUpper(tag) }),
  })),
);
const rows = await query;
//    ^?
// → [{ title: "Kettle", kitchen: ["kitchen"], upper: ["KITCHEN", "SALE"] }, …]
```

Вложенные колбэки элементы не путают. Внутренний `map` внутри внешнего видит свой элемент, а если нужно, и элемент внешнего. Уникальные имена переменным Typemo даёт сам.

## Строка с `$` — это строка

В MongoDB строка, которая начинается с `$`, — это путь к полю, и `"$price"` читает цену. Захотите записать в результат текст «$5 off», и обычная агрегация прочитает его как поле `5 off`, которого нет. Typemo ошибиться не даст. Строка на месте значения — всегда литерал, а пути пишутся только через `f`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, Vars, type RowOf } from "@venloc/typemo";

@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number) discount?: number;
  @Prop(() => [String], { required: true }) tags!: string[];
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.connection.model(Product);
// ---cut---
const plan = Pipeline.from(Product)
  .project(() => ({ note: "$5 off" }))
  .plan();
console.log(JSON.stringify(plan.pipeline));
// → [{"$project":{"note":{"$literal":"$5 off"}}}]
```

Значение уходит на сервер как `{ $literal: "$5 off" }`, и в результате вы получаете ровно то, что написали. Явный [`fn.literal`](../reference/aggregation/expr-logic.mdx#fnliteral) нужен редко — для значения внутри объекта или массива, которое не должно проходить разбор.

## Убрать поле и получить время

Системные переменные MongoDB собраны в классе [`Vars`](../reference/aggregation/expr-misc.mdx#vars), а для двух самых частых есть короткие вызовы. [`fn.now()`](../reference/aggregation/expr-misc.mdx#vars) даёт текущее время, одно на всю агрегацию. [`fn.remove()`](../reference/aggregation/expr-misc.mdx#vars) удаляет поле, которому его присвоили.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, Vars, type RowOf } from "@venloc/typemo";

@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number) discount?: number;
  @Prop(() => [String], { required: true }) tags!: string[];
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.connection.model(Product);
// ---cut---
const noDiscount = Pipeline.from(Product).addFields(() => ({ discount: fn.remove(), seenAt: fn.now() }));
type Row = RowOf<typeof noDiscount>;
//   ^?
```

Поле `discount` ушло из типа строки, а `seenAt` — дата. Что поле исчезло, записано в типе, а не в комментарии, и в следующей стадии к нему не обратиться.

## Как выбрать

Спросите себя, считается значение для каждого документа или собирается по многим.

- **Для каждого документа отдельно** — цена со скидкой, склеенное имя, метка по условию. Это выражение `fn.*` в `addFields`, `project` или `match`.
- **Много документов сворачиваются в одно значение** — сумма, среднее, число. Это **аккумулятор**, и живёт он только в `group` и похожих стадиях, см. [Группировка и отчёты](grouping.mdx).

## Когда это не нужно

Если нужно просто отобрать документы по значению поля, берите [`find`](../reference/query/reading.mdx#modelfind) с обычным фильтром. Он проще и пользуется индексами. Выражения в `match` оправданы, когда сравниваются два поля одного документа или значение считается на лету. А если документы нужно изменить в базе, а не просто посчитать значение для ответа, смотрите [обновление конвейером](../writes/pipeline-updates.mdx).

## Если что-то пошло не так

**Сырой `$expr` в фильтре.** Привычка из драйвера — записать в `$expr` объект с операторами. Typemo отвергает его сразу, потому что такой объект прошёл бы мимо всех проверок типов. Вместо объекта пишите функцию.

```ts twoslash
// @errors: 2353
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, Vars, type RowOf } from "@venloc/typemo";

@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number) discount?: number;
  @Prop(() => [String], { required: true }) tags!: string[];
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.connection.model(Product);
// ---cut---
await Products.find({ $expr: { $gt: ["$price", 20] } });
```

Если типы обошли приведением, во время работы придёт `QueryError: filter: $expr is a callback (f) => fn.… (a raw $expr object is not typed)`. Запишите условие функцией — `$expr: (f) => fn.gt(f.price, 20)`.

**Цену сравнивают со строкой.** `fn.gt(f.price, "20")` не скомпилируется. Значения разных типов сервер сравнивает по особому порядку, и результат почти никогда не тот, что вы ждёте. Типы аргументов у `fn.*` совпадают с серверными, так что число сравнивайте с числом.

```ts twoslash
// @errors: 2345
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, Vars, type RowOf } from "@venloc/typemo";

@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number) discount?: number;
  @Prop(() => [String], { required: true }) tags!: string[];
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.connection.model(Product);
// ---cut---
await Products.aggregate((p) => p.match((f) => fn.gt(f.price, "20")));
```

## Полный пример

```ts twoslash title="products/products.service.ts"
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, Vars, type RowOf } from "@venloc/typemo";

@Schema({ collection: "products" })
class Product extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true }) price!: number;
  @Prop(() => Number) discount?: number;
  @Prop(() => [String], { required: true }) tags!: string[];
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Products = client.connection.model(Product);
// ---cut---
export const priceList = () =>
  Products.aggregate((p) =>
    p
      .addFields((f) => ({
        final: fn.subtract(f.price, fn.ifNull(f.discount, 0)),
      }))
      .match((f) => fn.gt(f.final, 10))
      .project((f) => ({
        _id: 0,
        title: 1,
        final: 1,
        tier: fn.cond(fn.gte(f.final, 30), "premium", "basic"),
        tags: fn.map({ input: f.tags, in: (tag) => fn.toUpper(tag) }),
      }))
      .sort({ final: "descending" }),
  ).plain();
```
