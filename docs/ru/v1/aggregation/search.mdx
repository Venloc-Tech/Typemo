Обычный текстовый индекс MongoDB ищет по словам, но не умеет нечёткий поиск, подсветку и поиск по смыслу. Для этого у MongoDB Atlas есть **Atlas Search** (стадия `$search`) и **векторный поиск** (стадия `$vectorSearch`): они строятся не в `find`, а в конвейере агрегации, и всегда стоят **первой** стадией. В Typemo это методы [`search`](../reference/aggregation/stages.mdx#search), [`searchMeta`](../reference/aggregation/stages.mdx#searchmeta) и [`vectorSearch`](../reference/aggregation/stages.mdx#vectorsearch); для объединения нескольких поисков есть [`rankFusion`](../reference/aggregation/stages.mdx#rankfusion), [`scoreFusion`](../reference/aggregation/stages.mdx#scorefusion) и [`score`](../reference/aggregation/stages.mdx#score).

<Callout type="warning">

Эта страница описана по коду продукта. Поиск Atlas на тестовом сервере документации не работает: сервер отвечает `ServerError: Using $search and $vectorSearch aggregation stages requires additional configuration. (code 31082 SearchNotEnabled)` (полный текст сервера — в поле `serverMessage` ошибки: «Please connect to Atlas or an AtlasCLI local deployment to enable»). Проверено запуском: все примеры компилируются, а конвейеры собираются в показанные ниже стадии (`plan()`). Результаты поиска на Atlas в этой документации не выполнялись, поэтому комментариев с полученными строками здесь нет.

</Callout>

Поиск по обычным словам и полнотекстовый индекс без Atlas описаны в руководстве [Полнотекстовый и векторный поиск](../queries/text-and-vector-search.mdx). Поисковые индексы объявляются и синхронизируются по руководству [Поисковые индексы](../collections/search-indexes.mdx).

## Что предполагается

Примеры используют клиент из руководства [Подключиться к базе](../connection/connect.mdx) и модель статьи блога. У неё есть поисковый индекс `articles_text` для `$search` и векторный индекс `vec` для поля `embedding` (объявлены по руководству о поисковых индексах).

```ts twoslash title="blog/article.ts"
import { Entity, Prop, Schema, Spec, type Vector } from "@venloc/typemo";

@Schema({ collection: "articles" })
export class Article extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => String, { required: true })
  body!: string;

  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 }))
  embedding?: Vector;
}
```

## Быстрый путь

`search` принимает имя индекса и оператор поиска, например `text`. Оценку релевантности вы получаете через [`fn.meta`](../reference/aggregation/expr-misc.mdx#fnmeta):

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, fn, Pipeline, type Vector } from "@venloc/typemo";

@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) embedding?: Vector;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.connection.model(Article);
// ---cut---
const pipeline = Pipeline.from(Article)
  .search({ index: "articles_text", text: { path: "title", query: "mongo" } })
  .project(() => ({ title: 1, score: fn.meta("searchScore") }));
console.log(JSON.stringify(pipeline.plan().pipeline));
// → [{"$search":{"index":"articles_text","text":{"path":"title","query":"mongo"}}},{"$project":{"title":1,"score":{"$meta":"searchScore"}}}]
```

Остальная страница разбирает операторы, векторный поиск и объединение результатов.

## Найти по словам с условиями

Оператор `text` ищет слова в поле, а `compound` собирает несколько условий: `must` (обязательно), `should` (желательно, повышает оценку), `mustNot` (исключить), `filter` (отбор без влияния на оценку). Поле `path` проверяется по модели: опечатка не скомпилируется.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, fn, Pipeline, type Vector } from "@venloc/typemo";

@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) embedding?: Vector;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.connection.model(Article);
// ---cut---
const pipeline = Pipeline.from(Article).search({
  index: "articles_text",
  compound: {
    must: [{ text: { path: "title", query: "mongo" } }],
    should: [{ phrase: { path: "body", query: "full text" } }],
  },
});
```

Конвейер собирается в `{"$search":{"index":"articles_text","compound":{"must":[{"text":…}],"should":[{"phrase":…}]}}}`. В `search` доступны и другие операторы: `phrase`, `autocomplete`, `equals`, `range`, `regex`, `wildcard`, `near`, `queryString`, `moreLikeThis`, а также `highlight`, `count` и `sort`; полный перечень — в справочнике [Стадии](../reference/aggregation/stages.mdx#search).

Через [`Model.aggregate`](../reference/aggregation/pipeline.mdx#modelaggregate) `search` тоже вызывается первой стадией. Если у модели есть [скрытые поля](../schemas/hidden-and-sensitive.mdx#скрытое-поле-в-агрегации), Typemo убирает их стадией `$unset`, которую ставит сразу после поиска, а не перед ним: сервер принимает `$search`, `$searchMeta` и `$vectorSearch` только первыми. Отправленный конвейер начинается так: `[{ $search: … }, { $unset: ["…"] }, …]`.

```ts twoslash title="blog/articles.service.ts"
import { Entity, Prop, Schema, Spec, TypemoClient, fn, Pipeline, type Vector } from "@venloc/typemo";

@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) embedding?: Vector;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.connection.model(Article);
// ---cut---
export const searchTitles = (query: string) =>
  Articles.aggregate((p) =>
    p
      .search({ index: "articles_text", text: { path: "title", query } })
      .project(() => ({ title: 1, score: fn.meta("searchScore"), _id: 0 }))
      .limit(10),
  ).plain();
```

## Получить метаданные поиска

[`searchMeta`](../reference/aggregation/stages.mdx#searchmeta) возвращает не документы, а сведения о поиске: сколько совпадений всего, как они распределены по фасетам. Оно нужно, чтобы показать «найдено 128 статей» без выгрузки самих статей.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, fn, Pipeline, type Vector } from "@venloc/typemo";

@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) embedding?: Vector;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.connection.model(Article);
// ---cut---
const pipeline = Pipeline.from(Article).searchMeta({
  index: "articles_text",
  text: { path: "title", query: "mongo" },
  count: { type: "total" },
});
console.log(JSON.stringify(pipeline.plan().pipeline));
// → [{"$searchMeta":{"index":"articles_text","text":{"path":"title","query":"mongo"},"count":{"type":"total"}}}]
```

## Искать по смыслу

[`vectorSearch`](../reference/aggregation/stages.mdx#vectorsearch) находит документы, чей вектор ближе всего к вектору запроса. Вектор запроса строит ваш код (модель эмбеддингов); Typemo проверяет, что `path` — поле модели, и принимает массив чисел или бинарный вектор. `limit` — сколько документов вернуть, `numCandidates` — сколько кандидатов рассмотреть (чем больше, тем точнее и медленнее), `exact: true` включает точный, а не приближённый поиск, а `filter` отбирает документы по индексируемым полям до сравнения.

```ts twoslash title="blog/similar.service.ts"
import { Entity, Prop, Schema, Spec, TypemoClient, fn, Pipeline, type Vector } from "@venloc/typemo";

@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) embedding?: Vector;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.connection.model(Article);
// ---cut---
export const similar = (queryVector: number[]) =>
  Articles.aggregate((p) =>
    p
      .vectorSearch({ index: "vec", path: "embedding", queryVector, limit: 5, numCandidates: 50 })
      .project(() => ({ title: 1, score: fn.meta("vectorSearchScore"), _id: 0 })),
  ).plain();
```

## Объединить текстовый и векторный поиск

Текстовый поиск находит точные слова, векторный — похожий смысл; вместе они дают лучший список. [`rankFusion`](../reference/aggregation/stages.mdx#rankfusion) принимает именованные подконвейеры и объединяет их результаты по месту в каждом списке; `weights` задают вес каждого подконвейера. Это тоже первая стадия, и ей нужен MongoDB 8.1 или новее.

```ts twoslash
import { Entity, Prop, Schema, Spec, TypemoClient, fn, Pipeline, type Vector } from "@venloc/typemo";

@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) embedding?: Vector;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.connection.model(Article);
// ---cut---
const pipeline = Pipeline.from(Article)
  .rankFusion({
    input: {
      pipelines: {
        text: (p) => p.search({ text: { path: "body", query: "mongo" } }).limit(10),
        vector: (p) =>
          p.vectorSearch({ index: "vec", path: "embedding", queryVector: [0.1, 0.2, 0.3], limit: 10 }),
      },
    },
    combination: { weights: { text: 2, vector: 1 } },
  })
  .limit(5);
```

Имена в `weights` проверяются по именам подконвейеров: вес несуществующего подконвейера не скомпилируется. [`scoreFusion`](../reference/aggregation/stages.mdx#scorefusion) (MongoDB 8.2+) объединяет по **оценкам**, а не по местам, и требует `normalization` (`"none"`, `"sigmoid"` или `"minMaxScaler"`), чтобы привести оценки разных поисков к одной шкале. [`score`](../reference/aggregation/stages.mdx#score) (MongoDB 8.2+) задаёт оценку документа выражением.

## Как выбрать

Задайте вопрос: что должно совпадать, слова или смысл? Слова, формы слов, фразы и нечёткое совпадение — `search`. Смысл — `vectorSearch`. Нужно и то и другое — `rankFusion` (когда важен порядок в списках) или `scoreFusion` (когда важны сами оценки). Если вам нужен просто поиск по словам без Atlas, хватит текстового индекса в [`find`](../reference/query/reading.mdx#modelfind).

## Когда это не нужно

Если ваш сервер не Atlas, эти стадии не выполнятся: используйте [`$text`](../queries/text-and-vector-search.mdx) с текстовым индексом. Для простого отбора по значению поля берите обычный фильтр в `find`: поиск Atlas оправдан, когда нужна релевантность.

## Частые ошибки

### Поиск не первой стадией

`search`, `searchMeta`, `vectorSearch`, `rankFusion` и `scoreFusion` вызываются только на пустом конвейере, поэтому поставленные после другой стадии они не скомпилируются.

```ts twoslash
// @errors: 2684
import { Entity, Prop, Schema, Spec, TypemoClient, fn, Pipeline, type Vector } from "@venloc/typemo";

@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) embedding?: Vector;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.connection.model(Article);
// ---cut---
Pipeline.from(Article).limit(10).search({ text: { path: "title", query: "mongo" } });
```

Поставьте поиск первым, а `limit` после него.

### `ServerError` на обычном сервере

Стадии работают только в Atlas и локальной среде Atlas CLI. На обычном `mongod` вы получаете `ServerError` с текстом из начала страницы. Это не ошибка кода: запустите приложение на Atlas или уберите поиск из конвейера.

## Полный пример

```ts twoslash title="blog/search.service.ts"
import { Entity, Prop, Schema, Spec, TypemoClient, fn, Pipeline, type Vector } from "@venloc/typemo";

@Schema({ collection: "articles" })
class Article extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => String, { required: true }) body!: string;
  @Prop(() => Spec.vector({ dtype: "float32", dimensions: 3 })) embedding?: Vector;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/blog");
const Articles = client.connection.model(Article);
// ---cut---
// 1. Поиск по словам с оценкой.
export const searchArticles = (query: string) =>
  Articles.aggregate((p) =>
    p
      .search({ index: "articles_text", text: { path: "title", query } })
      .project(() => ({ title: 1, score: fn.meta("searchScore"), _id: 0 }))
      .limit(10),
  ).plain();

// 2. Поиск по смыслу.
export const similarArticles = (queryVector: number[]) =>
  Articles.aggregate((p) =>
    p
      .vectorSearch({ index: "vec", path: "embedding", queryVector, limit: 5 })
      .project(() => ({ title: 1, _id: 0 })),
  ).plain();
```
