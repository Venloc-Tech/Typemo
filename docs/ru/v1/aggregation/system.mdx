Агрегация читает не только документы, но и служебные данные сервера. Сколько в коллекции документов и сколько места она занимает, как часто используется каждый индекс, что выполняется прямо сейчас, какие сессии открыты. Такие стадии называются **служебными**, и у каждой своё место запуска.

- Стадии уровня коллекции — [`collStats`](../reference/aggregation/stages.mdx#collstats), [`indexStats`](../reference/aggregation/stages.mdx#indexstats), [`planCacheStats`](../reference/aggregation/stages.mdx#plancachestats). Их запускают через модель, как обычную агрегацию.
- Стадии базы и сервера — [`currentOp`](../reference/aggregation/stages.mdx#currentop), [`queryStats`](../reference/aggregation/stages.mdx#querystats), [`listLocalSessions`](../reference/aggregation/stages.mdx#listlocalsessions) и другие. Они строятся в отдельных конвейерах [`Pipeline.database`](../reference/aggregation/pipeline.mdx#pipelinedatabase) и [`Pipeline.admin`](../reference/aggregation/pipeline.mdx#pipelineadmin).
- Стадия [`listSessions`](../reference/aggregation/stages.mdx#listsessions) строится в [`Pipeline.sessions`](../reference/aggregation/pipeline.mdx#pipelinesessions).

Планы базы и сервера выполняют [`client.aggregate`](../reference/connection/typemo-client.mdx#clientaggregate) и [`connection.aggregate`](../reference/connection/connection.mdx#connectionaggregate), подробно об этом — в руководстве [Запросы уровня базы](./database-level.mdx).

Поставить стадию не туда не дадут типы. У конвейера коллекции нет `currentOp`, у конвейера базы нет `collStats`, а любая из этих стадий может стоять только первой.

## Что понадобится

Клиент из руководства [Подключиться к базе](../connection/connect.mdx) и запуск агрегации из руководства [Первая агрегация](first-aggregation.mdx). Служебные стадии обычно нужны администратору или скрипту мониторинга, и у пользователя сервера должны быть права на чтение статистики. В коллекции `orders` два документа, а у модели один индекс по `status`.

```ts twoslash title="orders/order.ts"
import { Entity, Index, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "orders" })
@Index({ status: 1 })
export class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true })
  status!: string;
}
```

## Быстрый путь

Для коллекции — через модель, для сервера — план из `Pipeline.admin()` и `client.aggregate`.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, Pipeline } from "@venloc/typemo";

@Schema({ collection: "orders" })
@Index({ status: 1 })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
const stats = await Orders.aggregate((p) => p.collStats({ count: {} }));
console.log(stats.map((row) => row.count));
// → [2]

const plan = Pipeline.admin().currentOp({ idleConnections: false }).limit(1).plan();
const ops = await client.aggregate(plan);
console.log(ops.length);
// → 1
```

Ниже разберём статистику коллекции, индексы, текущие операции и правила запуска.

## Узнать размер и число документов коллекции

`collStats` возвращает статистику коллекции, а нужные разделы вы перечисляете сами.

- `count` — число документов.
- `storageStats` — размер и хранилище, можно с `scale`.
- `latencyStats` — задержки.
- `queryExecStats` — выполнение запросов.

Лишние ключи компилятор отвергнет, а в типе строки будут только запрошенные разделы.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, Pipeline } from "@venloc/typemo";

@Schema({ collection: "orders" })
@Index({ status: 1 })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
const query = Orders.aggregate((p) => p.collStats({ count: {} }));
const rows = await query;
//    ^?
```

Число документов `count` имеет тип `StatNumber`, то есть `number | bigint`. Пока счётчик маленький, сервер пишет его как int32, а когда вырастет — как int64. Поэтому на большой коллекции значение придёт как `bigint`. Сравнивайте через `Number(row.count)` или проверяйте `typeof`. Стадия должна стоять в конвейере первой, а после неё можно ставить обычные стадии вроде `match` и `project`, чтобы выбрать нужное.

## Посмотреть использование индексов

[`indexStats`](../reference/aggregation/stages.mdx#indexstats) возвращает по строке на индекс — имя, ключ и число использований с момента запуска сервера. По ней находят неиспользуемые индексы, которые только замедляют запись.

```ts twoslash
import { Entity, Index, Prop, Schema, TypemoClient, Pipeline } from "@venloc/typemo";

@Schema({ collection: "orders" })
@Index({ status: 1 })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
const query = Orders.aggregate((p) => p.indexStats().project({ name: 1, _id: 0 }).sort({ name: 1 }));
const rows = await query;
//    ^?
// → [{ name: "_id_" }, { name: "status_1" }]
```

Кроме индекса по `status`, есть встроенный `_id_`, он создаётся всегда. [`planCacheStats`](../reference/aggregation/stages.mdx#plancachestats) показывает планы запросов, которые сервер запомнил для коллекции. У свежей коллекции их нет, и результат пуст.

## Посмотреть, что выполняется сейчас

`currentOp` перечисляет операции сервера — запросы, простаивающие соединения и курсоры. Это стадия сервера. Поэтому конвейер начинается с [`Pipeline.admin`](../reference/aggregation/pipeline.mdx#pipelineadmin), а выполняет его [`client.aggregate`](../reference/connection/typemo-client.mdx#clientaggregate). Запрос идёт в базу `admin`, результат типизирован, ошибки приходят как ошибки Typemo, а подписчики событий видят операцию.

```ts twoslash title="ops/current-ops.ts"
import { Entity, Index, Prop, Schema, TypemoClient, Pipeline } from "@venloc/typemo";

@Schema({ collection: "orders" })
@Index({ status: 1 })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
export const currentOps = async () => {
  const plan = Pipeline.admin().currentOp({ idleConnections: false, allUsers: true }).limit(10).plan();
  return client.aggregate(plan);
};
```

Каждая строка описывает одну операцию, среди её полей есть `type`, `host`, `desc` и `active`. Параметры `allUsers`, `idleConnections`, `idleCursors`, `idleSessions`, `localOps` и `backtrace` включают соответствующие сведения.

## Сессии, статистика запросов и каталог

Остальные служебные стадии устроены так же.

- [`listLocalSessions`](../reference/aggregation/stages.mdx#listlocalsessions) показывает сессии текущего узла и строится в конвейере базы или администратора.
- [`listSessions`](../reference/aggregation/stages.mdx#listsessions) читает `config.system.sessions`, то есть то, что сервер уже записал, и строится только в `Pipeline.sessions()`. На только что запущенном сервере она вернёт пустой список.
- [`queryStats`](../reference/aggregation/stages.mdx#querystats), [`querySettings`](../reference/aggregation/stages.mdx#querysettings) и [`listSampledQueries`](../reference/aggregation/stages.mdx#listsampledqueries) требуют базы `admin`.
- [`listClusterCatalog`](../reference/aggregation/stages.mdx#listclustercatalog) требует MongoDB 8.1 или новее.
- [`shardedDataDistribution`](../reference/aggregation/stages.mdx#shardeddatadistribution) — для шардированных кластеров. На обычном сервере она отвечает `ServerError`, что запускается только на маршрутизаторе.

Параметры и типы строк каждой стадии — в справочнике [Стадии](../reference/aggregation/stages.mdx). На тестовом сервере документации `queryStats`, `querySettings` и `listSampledQueries` вернули пустой список, а `listClusterCatalog` — по строке на каждую коллекцию базы.

## Как выбрать

Спросите себя, о чём вы спрашиваете сервер.

- **О конкретной коллекции или её индексах** — стадии уровня коллекции через модель.
- **О состоянии сервера, сессиях, запросах** — `Pipeline.admin()`, `Pipeline.database()` или `Pipeline.sessions()` вместе с `client.aggregate`.

## Когда это не нужно

Если нужно только число документов, берите [`countDocuments`](../reference/query/reading.mdx#modelcountdocuments). Статистику индексов, нужную приложению, а не администратору, лучше держать в системе мониторинга. А проверить, что запрос пользуется индексом, можно в тестах через [`explain`](../reference/aggregation/pipeline.mdx#explain).

## Если что-то пошло не так

**План базы передан модели.** `Model.aggregate` принимает только план своей коллекции. План из `Pipeline.admin()` читает базу, поэтому модель отвергнет его с `ConfigurationError`, и текст подскажет нужный метод.

```text
ConfigurationError: Order.aggregate: the plan reads a database, not this model's collection "orders"; run it with connection.aggregate(plan) or client.aggregate(plan)
```

Выполните такой план через `client.aggregate`, как выше.

**Служебная стадия не первая.** Все служебные стадии стоят только в начале конвейера. После другой стадии такая не скомпилируется.

```ts twoslash
// @errors: 2684
import { Entity, Index, Prop, Schema, TypemoClient, Pipeline } from "@venloc/typemo";

@Schema({ collection: "orders" })
@Index({ status: 1 })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
Orders.aggregate((p) => p.limit(1).indexStats());
```

## Полный пример

```ts twoslash title="ops/monitoring.ts"
import { Entity, Index, Prop, Schema, TypemoClient, Pipeline } from "@venloc/typemo";

@Schema({ collection: "orders" })
@Index({ status: 1 })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
// 1. Размер коллекции.
export const ordersCount = async () => {
  const [row] = await Orders.aggregate((p) => p.collStats({ count: {} }));
  return Number(row?.count ?? 0);
};

// 2. Индексы коллекции.
export const indexNames = () =>
  Orders.aggregate((p) => p.indexStats().project({ name: 1, _id: 0 })).plain();

// 3. Операции сервера.
export const runningOps = () => {
  const plan = Pipeline.admin().currentOp({ idleConnections: false }).limit(10).plan();
  return client.aggregate(plan);
};
```
