Страница заказов в админке показывает сразу три вещи — сколько заказов подошло под фильтр, строки текущей страницы и разбивку по статусам. Можно отправить три запроса, но каждый заново пройдёт по данным. Стадия [`facet`](../reference/aggregation/stages.mdx#facet) справляется за один. Вы описываете несколько **веток**, то есть отдельных конвейеров, а сервер за один проход прогоняет входные строки через все ветки. Вернётся **одна** строка, где под именем каждой ветки лежит массив её результатов.

Тип результата выводится из веток. У каждой ветки свой тип строк, и компилятор знает, что лежит под каждым именем.

## Что понадобится [#prerequisites]

Клиент из руководства [Подключиться к базе](../connection/connect.mdx), запуск агрегации из руководства [Первая агрегация](first-aggregation.mdx) и модель заказа с полями `customer`, `status`, `total`, `placedAt`. В коллекции `orders` пять заказов.

- Два оплаченных заказа `alice`, на 120 и 80.
- Оплаченный заказ `bob` на 50.
- Отменённый заказ `bob` на 200.
- Новый заказ `carol` на 30.

```ts twoslash title="orders/order.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "orders" })
export class Order extends Entity {
  @Prop(() => String, { required: true })
  customer!: string;

  @Prop(() => String, { required: true })
  status!: string;

  @Prop(() => Number, { required: true })
  total!: number;

  @Prop(() => Date, { required: true })
  placedAt!: Date;
}
```

## Быстрый путь [#quick-start]

Каждое поле объекта — имя ветки. Значение — функция, которая получает пустой строитель ветки и добавляет стадии.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
const query = Orders.aggregate((p) =>
  p.facet({
    total: (b) => b.count("n"),
    page: (b) => b.sort({ placedAt: "descending" }).limit(2).project({ customer: 1, total: 1, _id: 0 }),
    byStatus: (b) => b.sortByCount((f) => f.status),
  }),
);
const [report] = await query.plain();
//     ^?
// → { total: [{ n: 5 }], page: [{ customer: "carol", total: 30 }, { customer: "bob", total: 200 }],
//     byStatus: [{ _id: "paid", count: 3 }, …] }
```

Ниже разберём, как устроен результат, что делать с пустым набором и что в ветке запрещено.

## Получить сводку и страницу вместе [#summary-with-page]

`facet` всегда возвращает ровно одну строку, а массивы в ней — результаты веток. Поэтому результат `await` читают так — `const [report] = await …`. Все ветки видят одни и те же входные строки. Всё, что вы отобрали стадиями до `facet`, попадает в каждую ветку.

Обычно сначала идёт общий отбор [`match`](../reference/aggregation/stages.mdx#match), а потом `facet`. Тогда `total` и `page` считаются по одному набору, и число из `total` сходится со строками из `page`.

```ts twoslash title="orders/orders.service.ts"
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
export const orderPage = async (status: string) => {
  const query = Orders.aggregate((p) =>
    p.match({ status }).facet({
      count: (b) => b.count("n"),
      rows: (b) => b.sort({ placedAt: "descending" }).skip(0).limit(20),
    }),
  );
  const [report] = await query.plain();
  return { total: report?.count[0]?.n ?? 0, rows: report?.rows ?? [] };
};
```

Обратите внимание на `report?.count[0]?.n ?? 0`. Если под фильтр ничего не подошло, ветка `count` пуста, ведь стадия `count` строку с нулём не создаёт. Ветка `rows` тогда тоже пуста. Сама строка `facet` при этом есть, так что `report` определён, а вот `[0]` может оказаться пустым. Тип вам об этом напомнит.

## Разбить по группам [#group-by]

В ветку можно поставить любые стадии, кроме запрещённых внутри `facet`. Группировку, корзины, повторный подсчёт. Так строится левая панель фильтров с числом товаров по каждому значению.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
const query = Orders.aggregate((p) =>
  p.facet({
    byStatus: (b) => b.sortByCount((f) => f.status),
    bySize: (b) =>
      b.bucket({ groupBy: (f) => f.total, boundaries: [0, 100, 500], output: () => ({ orders: fn.count() }) }),
  }),
);
const [report] = await query;
//     ^?
```

Ветка `bySize` использует [`bucket`](../reference/aggregation/stages.mdx#bucket), ветка `byStatus` — [`sortByCount`](../reference/aggregation/stages.mdx#sort-by-count). Подробнее о них — в руководстве [Группировка и отчёты](grouping.mdx).

## Что нельзя в ветке [#branch-limits]

Внутри ветки не работают стадии, которые должны стоять первыми или пишут в базу. Это вложенный `facet`, [`out`](../reference/aggregation/stages.mdx#out), [`merge`](../reference/aggregation/stages.mdx#merge) и стадии, допустимые только в начале конвейера. Вызвать `out` у строителя ветки не получится — его тип разрешает вызов только на верхнем уровне конвейера, и ошибку видно при компиляции (`The 'this' context … is not assignable to method's 'this'`).

```ts twoslash
// @errors: 2739 2769
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
await Orders.aggregate((p) => p.facet({ nested: (b) => b.out("archive") }));
```

Ветка без стадий бросает `ConfigurationError` при сборке, потому что пустой конвейер бессмыслен. Если веток нет совсем, тоже будет `ConfigurationError`.

## Как выбрать [#how-to-choose]

Спросите себя, нужны ли вам несколько независимых результатов по одному набору.

- **Да** — `facet` сэкономит проходы по данным.
- **Результат один** — `facet` не нужен.
- **Ветки считаются по разным наборам**, с разными фильтрами до группировки. Несколько отдельных запросов проще и часто быстрее.

## Когда это не нужно [#when-not-to-use]

Для общего числа без строк берите [`countDocuments`](../reference/query/reading.mdx#model.count-documents), а для страниц без сводки — [`find`](../reference/query/reading.mdx#model.find) с [постраничной выдачей](../queries/sorting-and-pages.mdx). И помните, что весь результат `facet` — одна строка, так что ветку `rows` ограничивайте через `limit`.

## Если что-то пошло не так [#troubleshooting]

**Результат читают как массив строк.** `await` возвращает массив из одной строки, а не сами результаты веток. `report.count` у массива не скомпилируется. Возьмите первую строку — `const [report] = await …`.

**Ветка пуста, а код ждёт число.** `count` без совпадений строку с нулём не возвращает. Код `report.count[0].n` упадёт, а с `noUncheckedIndexedAccess` и вовсе не скомпилируется. Пишите `report?.count[0]?.n ?? 0`.

## Полный пример [#full-example]

```ts twoslash title="orders/orders.service.ts"
import { Entity, Prop, Schema, TypemoClient, fn, Pipeline, type RowOf } from "@venloc/typemo";

@Schema({ collection: "orders" })
class Order extends Entity {
  @Prop(() => String, { required: true }) customer!: string;
  @Prop(() => String, { required: true }) status!: string;
  @Prop(() => Number, { required: true }) total!: number;
  @Prop(() => Date, { required: true }) placedAt!: Date;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/shop");
const Orders = client.connection.model(Order);
// ---cut---
export const ordersOverview = async (status: string, page: number) => {
  const query = Orders.aggregate((p) =>
    p.match({ status }).facet({
      count: (b) => b.count("n"),
      rows: (b) =>
        b
          .sort({ placedAt: "descending" })
          .skip((page - 1) * 20)
          .limit(20)
          .project({ customer: 1, total: 1, _id: 0 }),
      bySize: (b) =>
        b.bucket({ groupBy: (f) => f.total, boundaries: [0, 100, 500], default: "other" }),
    }),
  );
  const [report] = await query.plain();
  return {
    total: report?.count[0]?.n ?? 0,
    rows: report?.rows ?? [],
    bySize: report?.bySize ?? [],
  };
};
```
