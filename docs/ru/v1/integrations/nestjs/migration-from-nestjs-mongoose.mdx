`@venloc/typemo-nestjs` устроен так же, как `@nestjs/mongoose`. Корневой `forRoot`, `forFeature` в модулях, `@InjectModel` в сервисах. Отличается то, что стоит за этими именами. Модель регистрируется классом, а не строкой, схема — это сам класс сущности, а тип модели выводится. Ошибки базы и проверку тела запроса пакет берёт на себя. Ниже — таблица соответствия и порядок перехода.

Если вы переводите с Mongoose на Typemo и сами модели, сначала прочитайте [Пошаговую миграцию](../../migration/step-by-step.mdx). Здесь речь только о слое Nest.

## Что понадобится [#prerequisites]

Приложение на NestJS 12 с `@nestjs/mongoose` и сущности, уже описанные классами Typemo (`@Schema`, `@Prop` из `@venloc/typemo`).

## Соответствие API [#api-mapping]

| `@nestjs/mongoose` | `@venloc/typemo-nestjs` | Что изменилось |
|---|---|---|
| `MongooseModule.forRoot(uri, options)` | [`TypemoModule.forRoot(uri, options)`](../../reference/integrations/nestjs.mdx#typemo-module.for-root) | опции клиента Typemo, плюс `sync` для коллекций и индексов |
| `MongooseModule.forRootAsync({ useFactory, useClass, useExisting, inject, imports })` | [`TypemoModule.forRootAsync(...)`](../../reference/integrations/nestjs.mdx#typemo-module.for-root-async) | метод класса опций — `createTypemoOptions`, `uri` в результате |
| `connectionName` | `name` | рядом с фабрикой, в её результате — ошибка компиляции |
| `retryAttempts`, `retryDelay` | те же | число попыток всего, неисправимые ошибки не повторяются |
| `lazyConnection` | тот же | `onClientCreate` вызывается и при нём |
| `connectionFactory(connection, name)` | [`clientFactory(client)`](../../reference/integrations/nestjs.mdx#client-factory) | |
| `connectionErrorFactory(error)` | [`clientErrorFactory(error)`](../../reference/integrations/nestjs.mdx#client-error-factory) | |
| `onConnectionCreate(connection)` | [`onClientCreate(client)`](../../reference/integrations/nestjs.mdx#on-client-create) | один раз на клиента, до первой модели |
| `MongooseModule.forFeature([{ name, schema, collection }], connectionName)` | [`TypemoModule.forFeature([Entity], { client, db })`](../../reference/integrations/nestjs.mdx#typemo-module.for-feature) | по классу, коллекция задаётся на сущности, `db` — другая база клиента |
| `discriminators: [{ name, schema, value }]` | потомок `@Discriminator` в том же списке | |
| `MongooseModule.forFeatureAsync` | нет | плагины — через `@Plugin` или `onClientCreate` |
| `@InjectModel(Cat.name, connectionName)` | [`@InjectModel(Cat, { client, db })`](../../reference/integrations/nestjs.mdx#inject-model) | |
| `@InjectConnection(name)` | [`@InjectConnection({ client, db })`](../../reference/integrations/nestjs.mdx#inject-connection) и [`@InjectClient(name)`](../../reference/integrations/nestjs.mdx#inject-client) | подключение к базе и клиент — разные объекты |
| `getModelToken(Cat.name)` | [`getModelToken(Cat)`](../../reference/integrations/nestjs.mdx#get-model-token) | символ, а не строка |
| `getConnectionToken(name)` | [`getConnectionToken({ client, db })`](../../reference/integrations/nestjs.mdx#get-connection-token), [`getClientToken(name)`](../../reference/integrations/nestjs.mdx#get-client-token) | |
| `ParseObjectIdPipe`, `IsObjectIdPipe` | [`ParseIdPipe.for(Entity)`](../../reference/integrations/nestjs.mdx#parse-id-pipe) | любой тип `_id` |
| `@Schema`, `@Prop`, `SchemaFactory`, `raw` | `@Schema`, `@Prop` из `@venloc/typemo` | схема — сам класс |
| `Model<CatDocument>` | `Model<Cat>` | тип выводится из класса |
| `connection.startSession()` + `session` в каждой операции | [`@Transactional()`](../../reference/integrations/nestjs.mdx#transactional) | сессия неявная |
| — | [`TypemoExceptionFilter`](../../reference/integrations/nestjs.mdx#typemo-exception-filter), [`ValidateBodyPipe`](../../reference/integrations/nestjs.mdx#validate-body-pipe), [`PolicyInterceptor`](../../reference/integrations/nestjs.mdx#policy-interceptor) | новое |

## Перейти по шагам [#step-by-step]

<Steps>
<Step>

### Установите пакет [#install]

```package-install
@venloc/typemo @venloc/typemo-nestjs mongodb
```

`@nestjs/mongoose` и `mongoose` пока оставьте, модули переводятся по одному.

</Step>
<Step>

### Добавьте TypemoModule.forRoot рядом с MongooseModule.forRoot [#add-for-root]

Оба модуля уживаются в одном приложении, их токены не пересекаются. У Typemo это `TypemoClient:default` и модели-символы, а у Mongoose — строки `DatabaseConnection` и `CatModel`. Пока идёт переход, приложение держит два пула соединений к одной базе.

</Step>
<Step>

### Переведите модуль [#migrate-module]

В модуле фичи замените `MongooseModule.forFeature` на `TypemoModule.forFeature([Cat])`, `@InjectModel(Cat.name)` — на `@InjectModel(Cat)` из `@venloc/typemo-nestjs`, а тип `Model<CatDocument>` — на `Model<Cat>` из `@venloc/typemo`. Компилятор покажет каждое место, где сервис пользовался API Mongoose, — `.exec()`, колбэки, `lean<T>()` с ручным типом.

</Step>
<Step>

### Включите фильтр и пайпы [#enable-filter-and-pipes]

`app.useGlobalFilters(new TypemoExceptionFilter())` превращает ошибки моделей Typemo в ответы. DTO, которые повторяли поля сущности, заменяет `ValidateBodyPipe.for(Entity)`, а `ParseObjectIdPipe` — `ParseIdPipe.for(Entity)`.

</Step>
<Step>

### Уберите Mongoose [#remove-mongoose]

Когда последний модуль переведён, удалите `MongooseModule.forRoot` и пакеты `@nestjs/mongoose` и `mongoose`.

</Step>
</Steps>

## Отличия, которые заметит приложение [#visible-differences]

**Модели по классу.** В `@nestjs/mongoose` опечатка в `@InjectModel("Cat")` всплывает только при старте. А модель, уже созданная на подключении под этим именем, молча переиспользуется, даже с другой схемой. Здесь в декоратор передаётся класс. Опечатки быть не может, а два класса с одним именем — это две модели.

**`name` в результате фабрики.** В `@nestjs/mongoose` `connectionName` внутри `useFactory` компилировался, а при старте драйвер отвергал неизвестную опцию, и модуль уходил в повторы. Здесь это ошибка компиляции, а в обход типов — одна понятная ошибка без повторов.

**`lazyConnection`.** С ним `@nestjs/mongoose` не вызывает `onConnectionCreate` и не сообщает о неудачном подключении. Здесь `onClientCreate` вызывается всегда, а неудача пишется в лог.

**Повторы.** В `@nestjs/mongoose` каждая попытка создаёт новое подключение, и `onConnectionCreate` вызывается на каждую. Здесь клиент один, поэтому `onClientCreate` вызывается один раз и расширения регистрируются один раз. Неверный пароль не повторяется.

**Неизвестное поле в теле.** Mongoose в строгом режиме молча его выбрасывает, а запрос без обязательного поля падает с 500. В Typemo неизвестное поле — это ошибка. Без пайпа фильтр ответит 400 с именем поля, а с `ValidateBodyPipe` — 422 сразу со всеми ошибками.

**Ошибки базы.** В `@nestjs/mongoose` фильтра нет, и дубликат ключа доходит до клиента как 500. `TypemoExceptionFilter` отвечает 409 с именами полей.

**Коллекции и индексы.** Mongoose создаёт их при компиляции модели (`autoCreate`, `autoIndex`). Typemo не пишет в базу, пока вы не попросите, — через `sync: "init"` или шаг развёртывания.

## Когда это не нужно [#when-not-to-use]

Если приложение остаётся на Mongoose, этот пакет не нужен, он работает только с моделями Typemo. И переводить слой Nest раньше моделей нельзя, потому что `@InjectModel` из этого пакета внедряет модель Typemo.

## Если что-то пошло не так [#troubleshooting]

**Токен модели не найден после замены импорта.** `@InjectModel` импортирован из `@venloc/typemo-nestjs`, а модуль всё ещё импортирует `MongooseModule.forFeature`. Замените и `forFeature`, у двух пакетов разные токены.

**Класс опций не подходит для useClass.** Метод класса опций называется `createTypemoOptions`, а не `createMongooseOptions`, и возвращает `uri` внутри объекта.
