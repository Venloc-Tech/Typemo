В Typemo транзакцию и контекст политик не передают параметрами. Операция сама находит транзакцию и тенанта текущего асинхронного вызова. В приложении NestJS это значит вот что. Транзакцию объявляют декоратором `@Transactional()` на методе, а тенанта и актора кладёт в контекст перехватчик `PolicyInterceptor`, один раз для всех обработчиков. Если эти механизмы ядра вам ещё незнакомы, сначала прочитайте [Транзакции](../../transactions/index.mdx) и [Контекст политик](../../policies/policy-context.mdx).

## Что понадобится

Приложение из руководства [Подключить Typemo к NestJS](./setup.mdx), работающее на реплика-сете MongoDB. Реплика-сет — это несколько серверов MongoDB с копией одних данных, хватит и одного узла, а вот на отдельном `mongod` транзакции не работают. Модели — счёт и заказ организации, у заказа поле `tenantId` помечено как тенант.

```ts twoslash title="orders/order.ts"
import { Entity, Prop, Schema, Tenant, type TenantField } from "@venloc/typemo";

@Schema({ collection: "orders", tenant: true })
export class Order extends Entity {
  @Prop(() => String)
  @Tenant()
  tenantId!: TenantField<string>;

  @Prop(() => String, { required: true })
  number!: string;
}
```

## Быстрый путь

Транзакция — это декоратор на методе сервиса, а тенант берёт перехватчик на всё приложение.

```ts twoslash title="main.ts"
import { Injectable, Module } from "@nestjs/common";
import { NestFactory } from "@nestjs/core";
import { Entity, type Model, Prop, Schema } from "@venloc/typemo";
import { InjectModel, PolicyInterceptor, Transactional } from "@venloc/typemo-nestjs";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true, min: 0 }) balance!: number;
}
@Module({})
class AppModule {}
// ---cut---
@Injectable()
export class TransfersService {
  constructor(@InjectModel(Account) private readonly accounts: Model<Account>) {}

  @Transactional()
  async transfer(from: Account["_id"], to: Account["_id"], amount: number): Promise<void> {
    await this.accounts.updateOne({ _id: from }, { $inc: { balance: -amount } });
    await this.accounts.updateOne({ _id: to }, { $inc: { balance: amount } });
  }
}

const app = await NestFactory.create(AppModule);
app.useGlobalInterceptors(new PolicyInterceptor({ tenant: (request) => request.headers["x-tenant"] }));
```

Ниже разберём каждую часть на задачах.

## Перевести деньги в транзакции

Перевод меняет два счёта, и половина перевода хуже, чем ничего. [`@Transactional()`](../../reference/integrations/nestjs.mdx#transactional) выполняет метод в транзакции клиента. Каждая операция внутри, в том числе в методах, которые он вызывает, входит в неё сама. Транзакция фиксируется, когда промис метода выполнился, и откатывается, когда он отклонён.

Метод обязан быть асинхронным. Синхронный метод с декоратором не скомпилируется, потому что транзакция асинхронна по своей природе. Ошибка внутри метода доходит до вызвавшего как есть. Метод, который создал счёт и затем бросил ошибку, вернул эту ошибку, и счёта в базе не осталось.

Модели двух баз одного клиента (`forFeature(…, { db })`) попадают в одну транзакцию. Запись в основную базу и в архив с ошибкой в конце откатилась в обеих.

## Пережить повтор

Сервер прервал транзакцию временной ошибкой, например из-за конфликта записи или смены первичного узла. Ядро повторяет транзакцию целиком, то есть **метод выполняется ещё раз**. Когда первая вставка отказала, метод выполнился дважды, а результат зафиксировался один раз.

Поэтому метод должен спокойно переживать повтор. Читайте документы внутри метода и меняйте суммы атомарными операторами вроде `$inc`, как в быстром пути. Если документ загружен **до** вызова и изменён арифметикой внутри (`account.balance -= 10`), при повторе изменение применится дважды. Подробности — в [`client.transaction`](../../reference/connection/typemo-client.mdx#clienttransaction).

## Вызвать транзакционный метод из другого

Метод «записать проводку» вызывают и сам по себе, и из метода «перевести», который уже открыл транзакцию. В MongoDB транзакции не вкладываются, поэтому без опции такой вызов — ошибка ядра. Опция `join: true` в [`@Transactional`](../../reference/integrations/nestjs.mdx#transactional) говорит методу — если транзакция этого клиента уже открыта, выполнись в ней, а если нет, открой свою.

```ts twoslash title="ledger/ledger.service.ts"
import { Injectable } from "@nestjs/common";
import { Entity, type Model, Prop, Schema } from "@venloc/typemo";
import { InjectModel, Transactional } from "@venloc/typemo-nestjs";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true, min: 0 }) balance!: number;
}
// ---cut---
@Injectable()
export class LedgerService {
  constructor(@InjectModel(Account) private readonly accounts: Model<Account>) {}

  @Transactional({ join: true })
  async entry(title: string): Promise<void> {
    await this.accounts.create({ title, balance: 1 });
  }

  @Transactional()
  async pair(title: string): Promise<number> {
    await this.entry(title);
    await this.entry(title);
    return this.accounts.countDocuments({ title });
  }
}
```

Присоединившийся метод сам транзакцию не фиксирует и не откатывает, это делает тот, кто её открыл. Поэтому ошибка внутри `entry` уходит наружу, и откатывается вся транзакция `pair`. С ошибкой во втором `entry` в базе не осталось ни одной записи. При временной ошибке сервера повторяется вся внешняя транзакция, и присоединившийся метод выполняется заново вместе с ней.

Внутри транзакции **другого** клиента `join` не станет молча открывать вторую транзакцию, а бросит ошибку. Запись в другом клиенте не откатилась бы вместе с внешней транзакцией.

```text
ConfigurationError: @Transactional({ join: true }): LedgerService.entry was called inside a transaction of another client; it joins only a transaction of client "default"
```

Опции транзакции (`timeoutMS`, `readConcern`) вместе с `join` не задаются. Они принадлежат внешней транзакции, и компилятор такое не пропустит.

## Транзакция другого клиента

В приложении два клиента, и транзакция нужна во втором. Опция `client` называет его, а остальные опции — это опции транзакции ядра.

```ts twoslash title="billing/billing.service.ts"
import { Injectable } from "@nestjs/common";
import { Transactional } from "@venloc/typemo-nestjs";
// ---cut---
@Injectable()
export class BillingService {
  @Transactional({ client: "billing", timeoutMS: 5000 })
  async charge(): Promise<void> {}
}
```

Неизвестное имя — ошибка при вызове, а не транзакция «где-нибудь».

```text
ConfigurationError: @Transactional(): no TypemoClient named "billing" in this application (TypemoModule.forRoot(uri, { name: "billing" }))
```

## Транзакция на обработчике маршрута

Обработчик сам делает две записи, и выносить их в сервис не хочется. Декоратор можно поставить и на метод контроллера, в любом порядке с `@Post()`, — метаданные маршрута переносятся на обёртку. `POST /accounts/pair`, где обработчик создал счёт и упал перед вторым, вернул 500, и счёта в базе не осталось.

## Тенант из запроса

Приложение обслуживает несколько организаций, и каждый запрос должен видеть только данные своей. [`PolicyInterceptor`](../../reference/integrations/nestjs.mdx#policyinterceptor) выполняет каждый обработчик внутри [`PolicyContext.run`](../../reference/policies/policy-context.mdx#policycontextrun) с тенантом из запроса.

```ts twoslash title="main.ts"
import { Module } from "@nestjs/common";
import { NestFactory } from "@nestjs/core";
import { PolicyInterceptor } from "@venloc/typemo-nestjs";
@Module({})
class AppModule {}
// ---cut---
const app = await NestFactory.create(AppModule);
app.useGlobalInterceptors(
  new PolicyInterceptor({
    tenant: (request) => request.headers["x-tenant"],
    actor: (request) => request.headers["x-user"],
  }),
);
```

Сервисы о тенанте ничего не знают. `Orders.find()` в сервисе сам получает фильтр организации, а `Orders.create` сам ставит `tenantId`. Контекст живёт всю асинхронную цепочку обработчика — и после `await`, и в потоке `Observable`, который возвращает обработчик. Из 20 одновременных запросов двух организаций каждый ответ содержал только заказы своей.

Если тенант лежит не в заголовке, а в пользователе, которого положила аутентификация, объявите свой тип запроса.

```ts twoslash title="main.ts"
import { PolicyInterceptor } from "@venloc/typemo-nestjs";
// ---cut---
interface AuthRequest {
  readonly headers: Readonly<Record<string, string | undefined>>;
  readonly user: { readonly orgId: string; readonly id: string };
}

const interceptor = new PolicyInterceptor<AuthRequest>({
  tenant: (request) => request.user.orgId,
  actor: (request) => request.user.id,
});
```

Резолвер синхронный, потому что контекст открывается до вызова обработчика. Достаньте тенанта раньше, в guard или middleware аутентификации.

## Запрос без тенанта

Заголовка нет. Резолвер вернул `undefined`, тенант не задан, и тенантная модель отвергает операцию ошибкой ядра [`StrictModeError`](../../reference/errors/data-errors.mdx#strictmodeerror) с причиной `tenant`. С [`TypemoExceptionFilter`](./http.mdx) клиент получит такой ответ.

```json
{ "statusCode": 400, "error": "Bad Request", "message": "Not allowed", "reason": "tenant" }
```

Тихо ничего не происходит. Запрос без организации не превращается в запрос по всем организациям. Модели без тенантной политики работают и без тенанта.

## Доступ ко всем тенантам

Административный маршрут должен видеть всех. [`@AllTenants()`](../../reference/integrations/nestjs.mdx#alltenants) на обработчике или контроллере заменяет тенанта запроса на `allTenants: true`.

```ts twoslash title="admin/admin.controller.ts"
import { Controller, Get } from "@nestjs/common";
import { Entity, type Model, Prop, Schema, Tenant, type TenantField } from "@venloc/typemo";
import { AllTenants, InjectModel } from "@venloc/typemo-nestjs";
@Schema({ collection: "orders", tenant: true })
class Order extends Entity {
  @Prop(() => String) @Tenant() tenantId!: TenantField<string>;
  @Prop(() => String, { required: true }) number!: string;
}
// ---cut---
@Controller("admin/orders")
export class AdminOrdersController {
  constructor(@InjectModel(Order) private readonly orders: Model<Order>) {}

  @AllTenants()
  @Get()
  async all() {
    return (await this.orders.find().sort({ number: 1 }).plain()).map((order) => `${order.tenantId}:${order.number}`);
  }
}
```

Заказы `A-1` и `A-2` организации `acme` и `G-1` организации `globex` вернулись как `["acme:A-1", "acme:A-2", "globex:G-1"]`. Доступ ко всем тенантам — явное решение на маршруте, а не следствие пустого заголовка.

## Как выбрать между декоратором и `client.transaction`

Спросите себя, вся ли работа метода должна идти в транзакции.

- **Вся** — берите `@Transactional()`. Граница транзакции видна прямо в объявлении метода.
- **Только часть** — например, сначала прочитать, потом атомарно записать, а письмо отправить уже вне транзакции. Внедрите клиента через [`@InjectClient`](../../reference/integrations/nestjs.mdx#injectclient) и оберните эту часть в [`client.transaction`](../../reference/connection/typemo-client.mdx#clienttransaction).

## Когда это не нужно

Одна операция записи атомарна сама по себе, и транзакция вокруг одного `updateOne` ничего не добавит. Приложению с одной организацией перехватчик политик не нужен. А вне HTTP, в очередях и задачах по расписанию, перехватчик не работает, там открывайте контекст сами через `PolicyContext.run`.

## Если что-то пошло не так

**Transactions do not nest.** Метод с `@Transactional()` вызвал другой метод с `@Transactional()`.

```text
ConfigurationError: transaction(): transactions do not nest (already inside a transaction of this client)
```

В MongoDB вложенных транзакций нет. Пометьте внутренний метод `@Transactional({ join: true })`. Тогда он выполнится во внешней транзакции, а вызванный сам по себе откроет свою (об этом — [Вызвать транзакционный метод из другого](#вызвать-транзакционный-метод-из-другого)).

**Метод отказывается выполняться вне приложения.**

```text
ConfigurationError: @Transactional(): AccountsService.openTwo was called on an object no Nest application with TypemoModule has registered; it works on the providers and controllers of such an application
```

Объект создан через `new` в обход Nest, и приложение не связало его со своим клиентом. Берите сервис из контейнера (`moduleRef.get`), а в модульном тесте добавьте [`provideClientMock`](./testing.mdx).

**PolicyInterceptor works in HTTP handlers only.** Перехватчик подключён к микросервису или шлюзу WebSocket. Там открывайте контекст сами.

## Полный пример

Сервис переводов с транзакцией и контроллер заказов организации. Перехватчик и фильтр подключены в `main.ts`.

```ts twoslash title="main.ts"
import { Body, Controller, Get, Injectable, Module, Post } from "@nestjs/common";
import { NestFactory } from "@nestjs/core";
import { Entity, type Model, Prop, Schema, Tenant, type TenantField } from "@venloc/typemo";
import {
  AllTenants,
  InjectModel,
  PolicyInterceptor,
  Transactional,
  TypemoExceptionFilter,
  TypemoModule,
} from "@venloc/typemo-nestjs";

// модели
@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true, min: 0 }) balance!: number;
}

@Schema({ collection: "orders", tenant: true })
export class Order extends Entity {
  @Prop(() => String) @Tenant() tenantId!: TenantField<string>;
  @Prop(() => String, { required: true }) number!: string;
}

// перевод в транзакции
@Injectable()
export class TransfersService {
  constructor(@InjectModel(Account) private readonly accounts: Model<Account>) {}

  @Transactional()
  async transfer(from: Account["_id"], to: Account["_id"], amount: number): Promise<void> {
    await this.accounts.updateOne({ _id: from }, { $inc: { balance: -amount } });
    await this.accounts.updateOne({ _id: to }, { $inc: { balance: amount } });
  }
}

// заказы организации из запроса
@Controller("orders")
export class OrdersController {
  constructor(@InjectModel(Order) private readonly orders: Model<Order>) {}

  @Post()
  async create(@Body() body: { readonly number: string }) {
    return (await this.orders.create({ number: body.number })).$toPlain();
  }

  @Get()
  async list() {
    return (await this.orders.find().sort({ number: 1 }).plain()).map((order) => order.number);
  }

  @AllTenants()
  @Get("all")
  async all() {
    return (await this.orders.find().plain()).length;
  }
}

@Module({
  imports: [
    TypemoModule.forRoot("mongodb://localhost:27017", { dbName: "bank", sync: "init" }),
    TypemoModule.forFeature([Account, Order]),
  ],
  controllers: [OrdersController],
  providers: [TransfersService],
})
export class AppModule {}

const app = await NestFactory.create(AppModule);
app.useGlobalFilters(new TypemoExceptionFilter());
app.useGlobalInterceptors(
  new PolicyInterceptor({
    tenant: (request) => request.headers["x-tenant"],
    actor: (request) => request.headers["x-user"],
  }),
);
await app.listen(3000);
```

<Callout type="migration" title="Если вы пришли из @nestjs/mongoose">

`connection.transaction(async (session) => …)`, где `session` передаётся в каждую операцию, заменяется на `@Transactional()` без сессии. Операции находят транзакцию сами. Тенанта в Mongoose не было вовсе, и фильтр организации дописывали в каждый запрос руками.

</Callout>
