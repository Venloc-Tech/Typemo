Чтобы работать с Typemo в приложении на NestJS, импортируйте `TypemoModule.forRoot` в корневой модуль, перечислите сущности в `TypemoModule.forFeature` и внедряйте модели в сервисы через `@InjectModel`. Модуль сам создаёт клиента, подключает его при старте приложения и закрывает при остановке, а модель приходит в сервис уже типизированной по классу сущности: фильтры, обновления и результаты проверяет компилятор.

Если вы ещё не писали модели Typemo, сначала пройдите [Быстрый старт](../../getting-started/quick-start.mdx): здесь предполагается, что вы знаете, что такое сущность и модель. Если вы знаете NestJS по `@nestjs/mongoose`, отличия собраны в руководстве [Переход с @nestjs/mongoose](./migration-from-nestjs-mongoose.mdx).

## Что предполагается

Приложение на NestJS 12 с HTTP-адаптером Express и MongoDB, запущенная как реплика-сет (одного узла достаточно): реплика-сет нужен транзакциям. Примеры страницы строятся на счетах банка.

## Быстрый путь

Установите пакеты. `@venloc/typemo-nestjs` не тянет NestJS за собой: Nest, `rxjs` и `reflect-metadata` уже есть в вашем приложении.

```package-install
@venloc/typemo @venloc/typemo-nestjs mongodb
```

Опишите сущность, подключите модуль и внедрите модель:

```ts twoslash title="app.module.ts"
import { Controller, Get, Injectable, Module } from "@nestjs/common";
import { Entity, type Model, Prop, Schema } from "@venloc/typemo";
import { InjectModel, TypemoModule } from "@venloc/typemo-nestjs";

@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;
}

@Injectable()
export class AccountsService {
  constructor(@InjectModel(Account) private readonly accounts: Model<Account>) {}

  list() {
    return this.accounts.find().plain();
  }
}

@Controller("accounts")
export class AccountsController {
  constructor(private readonly service: AccountsService) {}

  @Get()
  list() {
    return this.service.list();
  }
}

@Module({
  imports: [
    TypemoModule.forRoot("mongodb://localhost:27017", { dbName: "bank" }),
    TypemoModule.forFeature([Account]),
  ],
  controllers: [AccountsController],
  providers: [AccountsService],
})
export class AppModule {}
```

Остальная страница разбирает каждую часть на задачах.

## Настроить TypeScript

Ситуация: проект на NestJS уже компилируется, и нужно убедиться, что декораторы Typemo и внедрение Nest работают вместе. И Typemo, и Nest используют legacy-декораторы TypeScript, а Nest ещё читает типы параметров конструктора, которые компилятор записывает в метаданные.

```json title="tsconfig.json"
{
  "compilerOptions": {
    "experimentalDecorators": true,
    "emitDecoratorMetadata": true,
    "strict": true
  }
}
```

`experimentalDecorators` нужен декораторам `@Schema` и `@Prop`. `emitDecoratorMetadata` нужен самому Nest: по метаданным он понимает, что `AccountsController` ждёт `AccountsService`. Модели внедряются по явному токену (`@InjectModel(Account)`), поэтому от метаданных не зависят. Пакет пишет модуль ESM, как и Nest 12.

<Callout type="warning">

Не превращайте импорт класса, который внедряется через конструктор, в `import type`. Метаданные ссылаются на класс как на значение, а после `import type` его в метаданных нет, и Nest не находит провайдер: `Nest can't resolve dependencies of the AccountsController (?)`. Линтеры, которые предлагают `import type` автоматически, в модулях Nest отключают это правило.

</Callout>

## Подключиться к базе

Ситуация: приложению нужен клиент MongoDB на всё время работы. [`TypemoModule.forRoot`](../../reference/integrations/nestjs.mdx#typemomoduleforroot) импортируют один раз, в корневой модуль:

```ts twoslash title="app.module.ts"
import { Module } from "@nestjs/common";
import { TypemoModule } from "@venloc/typemo-nestjs";
// ---cut---
@Module({
  imports: [TypemoModule.forRoot("mongodb://localhost:27017", { dbName: "bank" })],
})
export class AppModule {}
```

При старте модуль создаёт [`TypemoClient`](../../reference/connection/typemo-client.mdx#new-typemoclient) и ждёт подключения: если сервер недоступен, модуль повторяет попытки (по умолчанию 9 раз с паузой 3 секунды) и только потом роняет старт. Приложение, которое стартовало, гарантированно подключено. При `app.close()` модуль закрывает клиента; чтобы это случалось и при остановке процесса сигналом, включите в Nest `app.enableShutdownHooks()`. Модуль клиента глобальный: модели и клиент доступны в любом модуле приложения без повторного импорта `forRoot`.

Вторым аргументом передаются опции клиента ядра (`dbName`, `readyTimeoutMS`, опции драйвера вроде `maxPoolSize`) и опции модуля. Опции из конфигурации, повторы и несколько клиентов разобраны в руководстве [Клиенты, базы и подключение](./connections.mdx).

## Зарегистрировать модели модуля

Ситуация: модулю счетов нужна модель счёта. [`TypemoModule.forFeature`](../../reference/integrations/nestjs.mdx#typemomoduleforfeature) перечисляет сущности, которые модуль использует:

```ts twoslash title="accounts/accounts.module.ts"
import { Module } from "@nestjs/common";
import { Entity, Prop, Schema } from "@venloc/typemo";
import { TypemoModule } from "@venloc/typemo-nestjs";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
}
// ---cut---
@Module({ imports: [TypemoModule.forFeature([Account])] })
export class AccountsModule {}
```

Модель регистрируется **по классу**, а не по строке: в списке стоит сам `Account`, поэтому опечатка в имени невозможна. Модель — объект ядра `connection.model(Account)`: если `Account` перечислен в двух модулях, оба получат один и тот же объект. При регистрации модуль не обращается к базе: коллекции и индексы создаются, только если вы попросите (опция `sync`, руководство [Модели в модулях](./models.mdx)).

## Внедрить модель в сервис

Ситуация: сервису нужно читать и писать счета. [`@InjectModel`](../../reference/integrations/nestjs.mdx#injectmodel) внедряет модель по тому же классу:

```ts twoslash title="accounts/accounts.service.ts"
import { Injectable } from "@nestjs/common";
import { Entity, type Model, Prop, Schema } from "@venloc/typemo";
import { InjectModel } from "@venloc/typemo-nestjs";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Number, { required: true, min: 0 }) balance!: number; // [!code ++]
}
// ---cut---
@Injectable()
export class AccountsService {
  constructor(@InjectModel(Account) private readonly accounts: Model<Account>) {}

  async rich() {
    const rows = await this.accounts.find({ balance: { $gt: 100 } }).select({ title: 1 }).plain();
    //    ^?
    return rows;
  }
}
```

Тип параметра — [`Model<Account>`](../../reference/connection/connection.mdx#connectionmodel) ядра, тот же, что у модели вне Nest: всё, что описано в руководствах по чтению и записи, работает как есть. После `select` и `plain` в типе остались только `_id` (уже строка) и `title`.

Тип параметра вы пишете сами: декоратор параметра не видит его и не может проверить. Пишите `Model<>` той же сущности, что в `@InjectModel`.

## Как выбрать, где перечислять сущности

Задайте себе один вопрос: какой модуль **владеет** данными? Если счетами занимается модуль счетов, перечислите `Account` в его `forFeature`, а другим модулям отдавайте сервис, а не модель: так правила работы со счетами живут в одном месте. Если модели нужны нескольким модулям напрямую (отчёты читают счета), перечислите сущность в `forFeature` каждого — они получат один объект модели, и ничего не задвоится.

## Когда это не нужно

Скрипту миграции или фоновой задаче вне приложения Nest модуль не нужен: создайте [`TypemoClient`](../../reference/connection/typemo-client.mdx#typemoclientconnect) сами, как в [Быстром старте](../../getting-started/quick-start.mdx). Если приложение Nest работает не по HTTP (только GraphQL или микросервисы), модуль и `forFeature` подходят, а фильтр ошибок и перехватчик политик — нет: они работают только в HTTP-контексте.

## Частые ошибки

### Nest can't resolve dependencies of the AccountsService

Модуль сервиса не импортировал `forFeature` с этой сущностью:

```text
Nest can't resolve dependencies of the AccountsService (?). Please make sure that the argument Symbol(TypemoModel:Account#1 (client "default")) at index [0] is available in the AccountsModule module.
```

Токен модели — символ с именем класса и клиента. Добавьте `TypemoModule.forFeature([Account])` в `imports` модуля, где объявлен сервис.

### Nest не находит «TypemoClient:default»

`forFeature` есть, а `forRoot` нет (или у него другое имя клиента):

```text
Nest can't resolve dependencies of the Symbol(TypemoModel:Account#1 (client "default")) (?, TypemoRegistry:default). Please make sure that the argument "TypemoClient:default" at index [0] is available in the TypemoModule module.
```

Импортируйте `TypemoModule.forRoot(...)` в корневой модуль. Если клиент назван (`forRoot(uri, { name: "main" })`), укажите его и в `forFeature([Account], { client: "main" })`.

### Приложение не стартует, пока нет базы

Это поведение по умолчанию: старт ждёт подключения. Для разработки без базы и для быстрого старта контейнера есть `lazyConnection: true` — руководство [Клиенты, базы и подключение](./connections.mdx).

## Полный пример

Приложение счетов: модель, сервис, контроллер, фильтр ошибок. Запуск `POST /accounts` с телом `{ "title": "Main", "balance": 100 }` вернул 201 и созданный счёт, повторный запрос с отрицательным балансом — 422.

```ts twoslash title="main.ts"
import { Body, Controller, Get, Injectable, Module, Post } from "@nestjs/common";
import { NestFactory } from "@nestjs/core";
import { type CreateInput, Entity, type Model, Prop, Schema } from "@venloc/typemo";
import { InjectModel, TypemoExceptionFilter, TypemoModule, ValidateBodyPipe } from "@venloc/typemo-nestjs";

// модель
@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Number, { required: true, min: 0 })
  balance!: number;
}

// сервис: работа с данными
@Injectable()
export class AccountsService {
  constructor(@InjectModel(Account) private readonly accounts: Model<Account>) {}

  async open(body: CreateInput<Account>) {
    return (await this.accounts.create(body)).$toPlain();
  }

  list() {
    return this.accounts.find().sort({ title: 1 }).plain();
  }
}

// контроллер: HTTP
@Controller("accounts")
export class AccountsController {
  constructor(private readonly service: AccountsService) {}

  @Post()
  open(@Body(ValidateBodyPipe.for(Account)) body: CreateInput<Account>) {
    return this.service.open(body);
  }

  @Get()
  list() {
    return this.service.list();
  }
}

// модуль счетов и корневой модуль
@Module({
  imports: [TypemoModule.forFeature([Account])],
  controllers: [AccountsController],
  providers: [AccountsService],
})
export class AccountsModule {}

@Module({ imports: [TypemoModule.forRoot("mongodb://localhost:27017", { dbName: "bank" }), AccountsModule] })
export class AppModule {}

// запуск
const app = await NestFactory.create(AppModule);
app.useGlobalFilters(new TypemoExceptionFilter());
app.enableShutdownHooks();
await app.listen(3000);
```

<Callout type="migration" title="Если вы пришли из @nestjs/mongoose">

`MongooseModule.forRoot` → `TypemoModule.forRoot`, `MongooseModule.forFeature([{ name: Account.name, schema: AccountSchema }])` → `TypemoModule.forFeature([Account])`, `@InjectModel(Account.name)` → `@InjectModel(Account)`. Схема — сам класс сущности, `SchemaFactory` не нужен, а тип модели выводится, а не пишется руками как `Model<AccountDocument>`.

</Callout>
