В приложении NestJS клиента Typemo создаёт модуль. Он берёт опции, подключается с повторами, отдаёт клиента провайдерам и закрывает его при остановке. Здесь разберём, как этим управлять. Как брать строку подключения из конфигурации, ждать ли базу при старте, как настроить клиента до первой модели и как держать в одном приложении несколько клиентов и баз.

## Что понадобится

Приложение из руководства [Подключить Typemo к NestJS](./setup.mdx) с сущностью `Account` и модулем счетов. Для примеров с конфигурацией в приложении есть свой провайдер `Config` с полем `mongoUri`.

## Быстрый путь

Если строка подключения лежит в конфигурации, берите [`forRootAsync`](../../reference/integrations/nestjs.mdx#typemomoduleforrootasync) с фабрикой.

```ts twoslash title="app.module.ts"
import { Injectable, Module } from "@nestjs/common";
import { TypemoModule, type TypemoModuleFactoryOptions } from "@venloc/typemo-nestjs";
@Injectable()
class Config {
  readonly mongoUri = "mongodb://localhost:27017";
}
@Module({ providers: [Config], exports: [Config] })
class ConfigModule {}
// ---cut---
@Module({
  imports: [
    TypemoModule.forRootAsync({
      imports: [ConfigModule],
      inject: [Config],
      useFactory: (config: Config): TypemoModuleFactoryOptions => ({ uri: config.mongoUri, dbName: "bank" }),
    }),
  ],
})
export class AppModule {}
```

Ниже разберём каждый вариант на задачах.

## Опции из конфигурации

Строка подключения и имя базы лежат в конфигурации, которую тоже предоставляет Nest. У `forRootAsync` три источника опций, и выбирается ровно один.

`useFactory` с `inject` — это функция, которая получает провайдеры из `inject` по порядку, как в быстром пути выше. Объявляйте параметры с типами, потому что модуль не знает, что вы перечислили в `inject`.

`useClass` — класс с методом `createTypemoOptions()`. Модуль создаст его сам и внедрит в него зависимости.

```ts twoslash title="database.config.ts"
import { Injectable, Module } from "@nestjs/common";
import { TypemoModule, type TypemoModuleFactoryOptions, type TypemoOptionsFactory } from "@venloc/typemo-nestjs";
@Injectable()
class Config {
  readonly mongoUri = "mongodb://localhost:27017";
}
@Module({ providers: [Config], exports: [Config] })
class ConfigModule {}
// ---cut---
@Injectable()
export class DatabaseConfig implements TypemoOptionsFactory {
  constructor(private readonly config: Config) {}

  createTypemoOptions(): TypemoModuleFactoryOptions {
    return { uri: this.config.mongoUri, dbName: "bank" };
  }
}

const database = TypemoModule.forRootAsync({ imports: [ConfigModule], useClass: DatabaseConfig });
```

`useExisting` — такой же класс, только его уже предоставляет модуль из `imports`. Модуль Typemo возьмёт готовый экземпляр и не станет создавать свой.

Все три варианта возвращают [`TypemoModuleFactoryOptions`](../../reference/integrations/nestjs.mdx#typemomodulefactoryoptions) — `uri`, опции клиента ядра и опции модуля. Единственное, чего в результате быть не может, — это `name` клиента. О нём следующий раздел.

## Назвать клиента

Имя клиента понадобится, если клиентов в приложении больше одного или имя нужно в событиях наблюдаемости. Оно задаётся опцией `name` и входит в токены клиента и моделей. В `forRootAsync` имя стоит **рядом** с фабрикой.

```ts twoslash title="app.module.ts"
import { TypemoModule } from "@venloc/typemo-nestjs";
// ---cut---
const analytics = TypemoModule.forRootAsync({
  name: "analytics",
  useFactory: () => ({ uri: "mongodb://localhost:27017", dbName: "analytics" }),
});
```

Имя нужно Nest ещё при построении графа модулей, до того как фабрика будет вызвана. Поэтому в её результате ему не место, и компилятор это проверяет.

```ts twoslash
import { TypemoModule } from "@venloc/typemo-nestjs";
// ---cut---
// @errors: 2322
TypemoModule.forRootAsync({ useFactory: () => ({ uri: "mongodb://localhost:27017", name: "analytics" }) });
```

Если тип обойдён, старт упадёт сразу, без попыток подключиться.

```text
ConfigurationError: TypemoModule.forRootAsync (useFactory): the result has "name"; name the client next to useFactory: forRootAsync({ name, useFactory })
```

## Повторить подключение

База поднимается одновременно с приложением, например в контейнерах, и первые попытки могут не пройти. [`retryAttempts`](../../reference/integrations/nestjs.mdx#retryattempts) задаёт, сколько всего попыток (по умолчанию 9), а [`retryDelay`](../../reference/integrations/nestjs.mdx#retrydelay) — паузу между ними (3000 мс).

```ts twoslash title="app.module.ts"
import { TypemoModule } from "@venloc/typemo-nestjs";
// ---cut---
const database = TypemoModule.forRoot("mongodb://db:27017", { dbName: "bank", retryAttempts: 5, retryDelay: 1000 });
```

Каждая неудачная попытка пишет строку в лог Nest — имя клиента и вид ошибки. Строку подключения она не пишет, ведь там бывают пароль и адреса.

```text
[TypemoModule] Unable to connect client "default" (ConnectionError: server-selection). Retrying (1)...
```

Повторяются только ошибки, которые повтор может исправить, — нет сервера, проблемы сети. Неверный пароль останавливает попытки сразу, потому что девять попыток с тем же паролем дали бы девять одинаковых отказов. Когда попытки кончились, старт падает с ошибкой последней попытки, а клиент закрывается.

Одна попытка длится до `serverSelectionTimeoutMS` драйвера, по умолчанию это 30 секунд. Так что 9 попыток по умолчанию растягиваются на несколько минут. Если нужен быстрый отказ, уменьшите и то, и другое.

## Стартовать без базы

Бывает, что приложение должно подняться, даже когда база недоступна, — при разработке или когда готовность контейнера проверяется отдельно. [`lazyConnection: true`](../../reference/integrations/nestjs.mdx#lazyconnection) не ждёт подключения.

```ts twoslash title="app.module.ts"
import { TypemoModule } from "@venloc/typemo-nestjs";
// ---cut---
const database = TypemoModule.forRoot("mongodb://localhost:27017", {
  dbName: "bank",
  lazyConnection: true,
  readyTimeoutMS: 2000,
});
```

Клиент подключается в фоне с теми же повторами. Операция, вызванная до подключения, ждёт его не дольше `readyTimeoutMS`, а если подключиться не удалось, получает [`ConnectionError`](../../reference/errors/configuration-errors.mdx#connectionerror). Когда попытки исчерпаны, модуль пишет в лог одну строку.

```text
[TypemoModule] Client "default" could not connect after 1 try (ConnectionError: server-selection); its operations fail until it connects
```

## Настроить клиента до первой модели

Приложению может понадобиться расширение схемы или подписчик наблюдаемости. [`onClientCreate`](../../reference/integrations/nestjs.mdx#onclientcreate) вызывается один раз с новым клиентом — до подключения и до любой модели, в том числе при ленивом подключении.

```ts twoslash title="app.module.ts"
import { TypemoModule } from "@venloc/typemo-nestjs";
declare const auditSubscriber: import("@venloc/typemo").InstrumentationSubscriber;
// ---cut---
const database = TypemoModule.forRoot("mongodb://localhost:27017", {
  dbName: "bank",
  onClientCreate: (client) => {
    client.instrument(auditSubscriber);
  },
});
```

Почему именно здесь? Расширения ([`client.use`](../../reference/connection/typemo-client.mdx#clientuse)) запечатываются, как только скомпилируется первая модель, а модели создают провайдеры `forFeature` сразу после клиента. Позже добавить расширение уже нельзя. Подписчик [`client.instrument`](../../reference/connection/typemo-client.mdx#clientinstrument), подключённый здесь, видит все операции приложения с самой первой. Пакеты [OpenTelemetry](../../observability/opentelemetry.mdx) и [Sentry](../../observability/sentry.mdx) подключаются так же, `TypemoOpenTelemetry.instrument(client)` внутри `onClientCreate`.

[`clientFactory`](../../reference/integrations/nestjs.mdx#clientfactory) получает уже подключённого клиента и возвращает того, которого получат провайдеры. [`clientErrorFactory`](../../reference/integrations/nestjs.mdx#clienterrorfactory) заменяет ошибку, с которой падает старт, например на ошибку вашего приложения с понятным текстом.

## Несколько клиентов

Скажем, аналитика живёт в другом кластере. Каждый `forRoot` со своим `name` — это отдельный клиент. `forFeature`, `@InjectModel` и [`@InjectClient`](../../reference/integrations/nestjs.mdx#injectclient) называют клиента тем же именем.

```ts twoslash title="reports/reports.module.ts"
import { Injectable, Module } from "@nestjs/common";
import { Entity, type Model, Prop, Schema, type TypemoClient } from "@venloc/typemo";
import { InjectClient, InjectModel, TypemoModule } from "@venloc/typemo-nestjs";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
}
// ---cut---
@Injectable()
export class ReportsService {
  constructor(
    @InjectModel(Account) private readonly accounts: Model<Account>,
    @InjectModel(Account, { client: "analytics" }) private readonly copies: Model<Account>,
    @InjectClient("analytics") private readonly analytics: TypemoClient,
  ) {}
}

@Module({
  imports: [TypemoModule.forFeature([Account]), TypemoModule.forFeature([Account], { client: "analytics" })],
  providers: [ReportsService],
})
export class ReportsModule {}
```

Одна сущность на двух клиентах — это два разных токена и две модели. Счёт, записанный через первую модель, вторая не увидела. Два `forRoot` с **одним** именем — ошибка при старте, иначе Nest молча взял бы один из них.

```text
ConfigurationError: TypemoModule.forRoot: two clients named "default" in one application; give each forRoot its own name
```

## Несколько баз одного клиента

Архив лежит в другой базе того же кластера. Отдельный клиент для этого не нужен. `forFeature(…, { db })` регистрирует модели в базе `db` того же клиента и предоставляет её [`Connection`](../../reference/integrations/nestjs.mdx#injectconnection).

```ts twoslash title="archive/archive.module.ts"
import { Injectable, Module } from "@nestjs/common";
import { type Connection, Entity, type Model, Prop, Schema } from "@venloc/typemo";
import { InjectConnection, InjectModel, TypemoModule } from "@venloc/typemo-nestjs";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
}
// ---cut---
@Injectable()
export class ArchiveService {
  constructor(
    @InjectModel(Account, { db: "archive" }) private readonly archived: Model<Account>,
    @InjectConnection({ db: "archive" }) private readonly archive: Connection,
  ) {}
}

@Module({ imports: [TypemoModule.forFeature([Account], { db: "archive" })], providers: [ArchiveService] })
export class ArchiveModule {}
```

Пул соединений общий, и транзакция клиента охватывает обе базы.

## Проверить здоровье

Оркестратору нужен адрес проверки готовности. Своего индикатора у пакета нет, состояние клиента читается напрямую через [`client.state`](../../reference/connection/typemo-client.mdx#clientstate).

```ts twoslash title="health/health.controller.ts"
import { Controller, Get, ServiceUnavailableException } from "@nestjs/common";
import type { TypemoClient } from "@venloc/typemo";
import { InjectClient } from "@venloc/typemo-nestjs";
// ---cut---
@Controller("health")
export class HealthController {
  constructor(@InjectClient() private readonly client: TypemoClient) {}

  @Get()
  check() {
    if (this.client.state !== "connected") throw new ServiceUnavailableException({ database: this.client.state });
    return { database: "connected" };
  }
}
```

Подключённый клиент отвечает 200 `{ "database": "connected" }`, а клиент с `lazyConnection` и недоступной базой — 503.

## Как выбрать, ждать базу или нет

Спросите себя, что должно случиться, если в момент старта базы нет.

- **Без базы приложение бесполезно** и лучше упасть сразу, а оркестратор его перезапустит. Оставьте поведение по умолчанию. Старт ждёт подключения с повторами, и поднявшееся приложение точно подключено.
- **Приложение должно отвечать и без базы** — проверкой готовности, страницей обслуживания — или вы разрабатываете без неё. Включите `lazyConnection`. Тогда каждая операция сама ждёт подключения и сама падает, если его нет.

## Когда это не нужно

Одному клиенту с адресом из переменной окружения `forRootAsync` не нужен, проще написать `forRoot(process.env.MONGO_URI ?? "…")`. Отдельный клиент для другой базы того же кластера тоже не нужен, хватит `forFeature(…, { db })`.

## Если что-то пошло не так

**Старт падает через несколько минут.** По умолчанию девять попыток, и каждая ждёт выбора сервера до 30 секунд. Уменьшите `retryAttempts` и добавьте в строку подключения `serverSelectionTimeoutMS`, например `?serverSelectionTimeoutMS=2000`.

**Расширение не применяется к моделям.** `client.use` вызван после старта, в сервисе или в `onModuleInit`, когда модели уже скомпилированы. Перенесите вызов в `onClientCreate`.

**`forFeature` не находит клиента с именем.** Имя в `forFeature([…], { client })` должно совпадать с `name` у `forRoot`. Без имени клиент называется `"default"`.

## Полный пример

Два клиента и две базы. Основной клиент берёт опции из конфигурации, подключается с повторами и сразу получает подписчика. Клиент аналитики подключается лениво. Архив лежит в другой базе основного клиента, и есть проверка здоровья.

```ts twoslash title="app.module.ts"
import { Controller, Get, Injectable, Module, ServiceUnavailableException } from "@nestjs/common";
import { type Connection, Entity, type Model, Prop, Schema, type TypemoClient } from "@venloc/typemo";
import {
  InjectClient,
  InjectConnection,
  InjectModel,
  TypemoModule,
  type TypemoModuleFactoryOptions,
} from "@venloc/typemo-nestjs";

// конфигурация приложения
@Injectable()
export class Config {
  readonly mongoUri = "mongodb://localhost:27017";
  readonly analyticsUri = "mongodb://analytics:27017";
}
@Module({ providers: [Config], exports: [Config] })
export class ConfigModule {}

// модель
@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;
}

// сервис с моделями трёх мест
@Injectable()
export class ReportsService {
  constructor(
    @InjectModel(Account) private readonly accounts: Model<Account>,
    @InjectModel(Account, { db: "archive" }) private readonly archived: Model<Account>,
    @InjectModel(Account, { client: "analytics" }) private readonly copies: Model<Account>,
    @InjectConnection({ db: "archive" }) private readonly archive: Connection,
  ) {}
}

// проверка здоровья
@Controller("health")
export class HealthController {
  constructor(@InjectClient() private readonly client: TypemoClient) {}

  @Get()
  check() {
    if (this.client.state !== "connected") throw new ServiceUnavailableException({ database: this.client.state });
    return { database: "connected" };
  }
}

@Module({
  imports: [
    TypemoModule.forFeature([Account]),
    TypemoModule.forFeature([Account], { db: "archive" }),
    TypemoModule.forFeature([Account], { client: "analytics" }),
  ],
  controllers: [HealthController],
  providers: [ReportsService],
})
export class ReportsModule {}

// клиенты
@Module({
  imports: [
    TypemoModule.forRootAsync({
      imports: [ConfigModule],
      inject: [Config],
      useFactory: (config: Config): TypemoModuleFactoryOptions => ({
        uri: config.mongoUri,
        dbName: "bank",
        retryAttempts: 5,
        retryDelay: 1000,
      }),
    }),
    TypemoModule.forRootAsync({
      name: "analytics",
      imports: [ConfigModule],
      inject: [Config],
      useFactory: (config: Config): TypemoModuleFactoryOptions => ({
        uri: config.analyticsUri,
        dbName: "analytics",
        lazyConnection: true,
      }),
    }),
    ReportsModule,
  ],
})
export class AppModule {}
```

<Callout type="migration" title="Если вы пришли из @nestjs/mongoose">

`connectionName` → `name`, `connectionFactory` → `clientFactory`, `connectionErrorFactory` → `clientErrorFactory`, `onConnectionCreate` → `onClientCreate`. Отличий три. `onClientCreate` вызывается и при `lazyConnection`, а в `@nestjs/mongoose` — нет. Клиент один на все попытки. А `name` в результате фабрики — ошибка компиляции.

</Callout>
