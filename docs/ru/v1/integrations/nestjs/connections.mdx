Клиент Typemo в приложении NestJS создаёт модуль: он берёт опции, подключается с повторами, отдаёт клиента провайдерам и закрывает его при остановке. Эта страница — о том, как управлять этим путём: брать строку подключения из конфигурации, решать, ждать ли базу при старте, настраивать клиента до первой модели и держать в одном приложении несколько клиентов и баз.

## Что предполагается

Приложение из руководства [Подключить Typemo к NestJS](./setup.mdx): сущность `Account` и модуль счетов. Для примеров с конфигурацией в приложении есть свой провайдер `Config` с полем `mongoUri`.

## Быстрый путь

Строка подключения из конфигурации — [`forRootAsync`](../../reference/integrations/nestjs.mdx#typemomoduleforrootasync) с фабрикой:

```ts twoslash title="app.module.ts"
import { Injectable, Module } from "@nestjs/common";
import { TypemoModule, type TypemoModuleFactoryOptions } from "@venloc/typemo-nestjs";
@Injectable()
class Config {
  readonly mongoUri = "mongodb://localhost:27017";
}
@Module({ providers: [Config], exports: [Config] })
class ConfigModule {}
// ---cut---
@Module({
  imports: [
    TypemoModule.forRootAsync({
      imports: [ConfigModule],
      inject: [Config],
      useFactory: (config: Config): TypemoModuleFactoryOptions => ({ uri: config.mongoUri, dbName: "bank" }),
    }),
  ],
})
export class AppModule {}
```

Остальная страница разбирает каждый вариант на задачах.

## Опции из конфигурации

Ситуация: строка подключения и имя базы лежат в конфигурации, которую тоже предоставляет Nest. У `forRootAsync` три источника опций, и выбирается ровно один.

`useFactory` с `inject` — функция, которая получает провайдеры из `inject` по порядку (быстрый путь выше). Параметры объявляйте с типами: модуль не знает, что вы перечислили в `inject`.

`useClass` — класс с методом `createTypemoOptions()`, который модуль создаст сам и в который внедрит зависимости:

```ts twoslash title="database.config.ts"
import { Injectable, Module } from "@nestjs/common";
import { TypemoModule, type TypemoModuleFactoryOptions, type TypemoOptionsFactory } from "@venloc/typemo-nestjs";
@Injectable()
class Config {
  readonly mongoUri = "mongodb://localhost:27017";
}
@Module({ providers: [Config], exports: [Config] })
class ConfigModule {}
// ---cut---
@Injectable()
export class DatabaseConfig implements TypemoOptionsFactory {
  constructor(private readonly config: Config) {}

  createTypemoOptions(): TypemoModuleFactoryOptions {
    return { uri: this.config.mongoUri, dbName: "bank" };
  }
}

const database = TypemoModule.forRootAsync({ imports: [ConfigModule], useClass: DatabaseConfig });
```

`useExisting` — такой же класс, который уже предоставляет модуль из `imports`: модуль Typemo возьмёт готовый экземпляр, а не создаст свой.

Все три вида возвращают [`TypemoModuleFactoryOptions`](../../reference/integrations/nestjs.mdx#typemomodulefactoryoptions): `uri`, опции клиента ядра и опции модуля. Только `name` клиента в результате быть не может — о нём следующий раздел.

## Назвать клиента

Ситуация: в приложении будет больше одного клиента, или имя нужно в событиях наблюдаемости. Имя задаётся опцией `name` и входит в токены клиента и моделей. В `forRootAsync` имя стоит **рядом** с фабрикой:

```ts twoslash title="app.module.ts"
import { TypemoModule } from "@venloc/typemo-nestjs";
// ---cut---
const analytics = TypemoModule.forRootAsync({
  name: "analytics",
  useFactory: () => ({ uri: "mongodb://localhost:27017", dbName: "analytics" }),
});
```

Имя нужно Nest, когда он строит граф модулей, — ещё до того, как фабрика будет вызвана, поэтому в её результате ему не место. Компилятор это проверяет:

```ts twoslash
import { TypemoModule } from "@venloc/typemo-nestjs";
// ---cut---
// @errors: 2322
TypemoModule.forRootAsync({ useFactory: () => ({ uri: "mongodb://localhost:27017", name: "analytics" }) });
```

Если тип обойдён, старт падает сразу, без попыток подключиться:

```text
ConfigurationError: TypemoModule.forRootAsync (useFactory): the result has "name"; name the client next to useFactory: forRootAsync({ name, useFactory })
```

## Повторить подключение

Ситуация: база поднимается одновременно с приложением (контейнеры), и первые попытки могут не пройти. [`retryAttempts`](../../reference/integrations/nestjs.mdx#retryattempts) — сколько попыток всего (по умолчанию 9), [`retryDelay`](../../reference/integrations/nestjs.mdx#retrydelay) — пауза между ними (3000 мс):

```ts twoslash title="app.module.ts"
import { TypemoModule } from "@venloc/typemo-nestjs";
// ---cut---
const database = TypemoModule.forRoot("mongodb://db:27017", { dbName: "bank", retryAttempts: 5, retryDelay: 1000 });
```

Каждая неудачная попытка пишет строку в лог Nest — имя клиента и вид ошибки, но не строку подключения, в которой бывают пароль и адреса:

```text
[TypemoModule] Unable to connect client "default" (ConnectionError: server-selection). Retrying (1)...
```

Повторяются только ошибки, которые повтор может исправить: нет сервера, сеть. Неверный пароль останавливает попытки сразу: девять попыток с тем же паролем дали бы девять одинаковых отказов. Когда попытки кончились, старт падает с ошибкой последней попытки, а клиент закрывается. Одна попытка длится до `serverSelectionTimeoutMS` драйвера (по умолчанию 30 секунд), поэтому 9 попыток по умолчанию — это несколько минут; для быстрого отказа уменьшите и то и другое.

## Стартовать без базы

Ситуация: приложение должно подняться, даже если база недоступна (разработка, проверка готовности контейнера отдельно). [`lazyConnection: true`](../../reference/integrations/nestjs.mdx#lazyconnection) не ждёт подключения:

```ts twoslash title="app.module.ts"
import { TypemoModule } from "@venloc/typemo-nestjs";
// ---cut---
const database = TypemoModule.forRoot("mongodb://localhost:27017", {
  dbName: "bank",
  lazyConnection: true,
  readyTimeoutMS: 2000,
});
```

Клиент подключается в фоне с теми же повторами. Операция, вызванная до подключения, ждёт его не дольше `readyTimeoutMS`, а если подключиться не удалось, получает [`ConnectionError`](../../reference/errors/configuration-errors.mdx#connectionerror). Когда попытки исчерпаны, модуль пишет в лог одну строку:

```text
[TypemoModule] Client "default" could not connect after 1 try (ConnectionError: server-selection); its operations fail until it connects
```

## Настроить клиента до первой модели

Ситуация: приложению нужно расширение схемы или подписчик наблюдаемости. [`onClientCreate`](../../reference/integrations/nestjs.mdx#onclientcreate) вызывается один раз с новым клиентом — до подключения и до любой модели, в том числе при ленивом подключении:

```ts twoslash title="app.module.ts"
import { TypemoModule } from "@venloc/typemo-nestjs";
declare const auditSubscriber: import("@venloc/typemo").InstrumentationSubscriber;
// ---cut---
const database = TypemoModule.forRoot("mongodb://localhost:27017", {
  dbName: "bank",
  onClientCreate: (client) => {
    client.instrument(auditSubscriber);
  },
});
```

Почему именно здесь: расширения ([`client.use`](../../reference/connection/typemo-client.mdx#clientuse)) запечатываются первой компиляцией модели, а модели создают провайдеры `forFeature` сразу после клиента. Позже добавить расширение уже нельзя. Подписчик [`client.instrument`](../../reference/connection/typemo-client.mdx#clientinstrument), подключённый здесь, видит все операции приложения с первой. Пакеты [OpenTelemetry](../../observability/opentelemetry.mdx) и [Sentry](../../observability/sentry.mdx) подключаются так же: `TypemoOpenTelemetry.instrument(client)` внутри `onClientCreate`.

[`clientFactory`](../../reference/integrations/nestjs.mdx#clientfactory) получает уже подключённого клиента и возвращает того, которого получат провайдеры; [`clientErrorFactory`](../../reference/integrations/nestjs.mdx#clienterrorfactory) заменяет ошибку, с которой падает старт, например на ошибку вашего приложения с понятным текстом.

## Несколько клиентов

Ситуация: аналитика живёт в другом кластере. Каждый `forRoot` с своим `name` — отдельный клиент, а `forFeature`, `@InjectModel` и [`@InjectClient`](../../reference/integrations/nestjs.mdx#injectclient) называют клиента так же:

```ts twoslash title="reports/reports.module.ts"
import { Injectable, Module } from "@nestjs/common";
import { Entity, type Model, Prop, Schema, type TypemoClient } from "@venloc/typemo";
import { InjectClient, InjectModel, TypemoModule } from "@venloc/typemo-nestjs";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
}
// ---cut---
@Injectable()
export class ReportsService {
  constructor(
    @InjectModel(Account) private readonly accounts: Model<Account>,
    @InjectModel(Account, { client: "analytics" }) private readonly copies: Model<Account>,
    @InjectClient("analytics") private readonly analytics: TypemoClient,
  ) {}
}

@Module({
  imports: [TypemoModule.forFeature([Account]), TypemoModule.forFeature([Account], { client: "analytics" })],
  providers: [ReportsService],
})
export class ReportsModule {}
```

Одна сущность на двух клиентах — два разных токена и две модели: запуск записал счёт через первую модель, и вторая его не увидела. Два `forRoot` с **одним** именем — ошибка при старте, иначе Nest молча взял бы один из них:

```text
ConfigurationError: TypemoModule.forRoot: two clients named "default" in one application; give each forRoot its own name
```

## Несколько баз одного клиента

Ситуация: архив лежит в другой базе того же кластера. Отдельный клиент не нужен: `forFeature(…, { db })` регистрирует модели в базе `db` того же клиента и предоставляет её [`Connection`](../../reference/integrations/nestjs.mdx#injectconnection):

```ts twoslash title="archive/archive.module.ts"
import { Injectable, Module } from "@nestjs/common";
import { type Connection, Entity, type Model, Prop, Schema } from "@venloc/typemo";
import { InjectConnection, InjectModel, TypemoModule } from "@venloc/typemo-nestjs";
@Schema({ collection: "accounts" })
class Account extends Entity {
  @Prop(() => String, { required: true }) title!: string;
}
// ---cut---
@Injectable()
export class ArchiveService {
  constructor(
    @InjectModel(Account, { db: "archive" }) private readonly archived: Model<Account>,
    @InjectConnection({ db: "archive" }) private readonly archive: Connection,
  ) {}
}

@Module({ imports: [TypemoModule.forFeature([Account], { db: "archive" })], providers: [ArchiveService] })
export class ArchiveModule {}
```

Пул соединений общий, транзакция клиента охватывает обе базы.

## Проверить здоровье

Ситуация: оркестратору нужен адрес проверки готовности. Своего индикатора у пакета нет: состояние клиента читается напрямую, через [`client.state`](../../reference/connection/typemo-client.mdx#clientstate).

```ts twoslash title="health/health.controller.ts"
import { Controller, Get, ServiceUnavailableException } from "@nestjs/common";
import type { TypemoClient } from "@venloc/typemo";
import { InjectClient } from "@venloc/typemo-nestjs";
// ---cut---
@Controller("health")
export class HealthController {
  constructor(@InjectClient() private readonly client: TypemoClient) {}

  @Get()
  check() {
    if (this.client.state !== "connected") throw new ServiceUnavailableException({ database: this.client.state });
    return { database: "connected" };
  }
}
```

Запуск: у подключённого клиента ответ 200 `{ "database": "connected" }`; у клиента с `lazyConnection` и недоступной базой — 503.

## Как выбрать: ждать базу или нет

Задайте себе вопрос: что должно случиться, если базы нет в момент старта? Если приложение без базы бесполезно и лучше упасть сразу (а оркестратор перезапустит его), оставьте поведение по умолчанию: старт ждёт подключения с повторами, и поднявшееся приложение гарантированно подключено. Если приложение должно отвечать и без базы (проверка готовности, страница обслуживания) или вы разрабатываете без неё, включите `lazyConnection`: тогда каждая операция сама ждёт подключения и сама падает, если его нет.

## Когда это не нужно

Одному клиенту с адресом из переменной окружения `forRootAsync` не нужен: `forRoot(process.env.MONGO_URI ?? "…")` проще. Отдельный клиент для другой базы того же кластера тоже не нужен — хватит `forFeature(…, { db })`.

## Частые ошибки

### Старт падает через несколько минут

Девять попыток по умолчанию, каждая до 30 секунд выбора сервера. Уменьшите `retryAttempts` и добавьте в строку подключения `serverSelectionTimeoutMS`, например `?serverSelectionTimeoutMS=2000`.

### Расширение не применяется к моделям

`client.use` вызван после старта (в сервисе, в `onModuleInit`) — модели уже скомпилированы. Перенесите вызов в `onClientCreate`.

### `forFeature` не находит клиента с именем

Имя в `forFeature([…], { client })` должно совпадать с `name` у `forRoot`. Без имени клиент называется `"default"`.

## Полный пример

Два клиента и две базы: основной клиент из конфигурации с повторами и подписчиком, клиент аналитики с ленивым подключением, архив в другой базе основного клиента и проверка здоровья.

```ts twoslash title="app.module.ts"
import { Controller, Get, Injectable, Module, ServiceUnavailableException } from "@nestjs/common";
import { type Connection, Entity, type Model, Prop, Schema, type TypemoClient } from "@venloc/typemo";
import {
  InjectClient,
  InjectConnection,
  InjectModel,
  TypemoModule,
  type TypemoModuleFactoryOptions,
} from "@venloc/typemo-nestjs";

// конфигурация приложения
@Injectable()
export class Config {
  readonly mongoUri = "mongodb://localhost:27017";
  readonly analyticsUri = "mongodb://analytics:27017";
}
@Module({ providers: [Config], exports: [Config] })
export class ConfigModule {}

// модель
@Schema({ collection: "accounts" })
export class Account extends Entity {
  @Prop(() => String, { required: true })
  title!: string;
}

// сервис с моделями трёх мест
@Injectable()
export class ReportsService {
  constructor(
    @InjectModel(Account) private readonly accounts: Model<Account>,
    @InjectModel(Account, { db: "archive" }) private readonly archived: Model<Account>,
    @InjectModel(Account, { client: "analytics" }) private readonly copies: Model<Account>,
    @InjectConnection({ db: "archive" }) private readonly archive: Connection,
  ) {}
}

// проверка здоровья
@Controller("health")
export class HealthController {
  constructor(@InjectClient() private readonly client: TypemoClient) {}

  @Get()
  check() {
    if (this.client.state !== "connected") throw new ServiceUnavailableException({ database: this.client.state });
    return { database: "connected" };
  }
}

@Module({
  imports: [
    TypemoModule.forFeature([Account]),
    TypemoModule.forFeature([Account], { db: "archive" }),
    TypemoModule.forFeature([Account], { client: "analytics" }),
  ],
  controllers: [HealthController],
  providers: [ReportsService],
})
export class ReportsModule {}

// клиенты
@Module({
  imports: [
    TypemoModule.forRootAsync({
      imports: [ConfigModule],
      inject: [Config],
      useFactory: (config: Config): TypemoModuleFactoryOptions => ({
        uri: config.mongoUri,
        dbName: "bank",
        retryAttempts: 5,
        retryDelay: 1000,
      }),
    }),
    TypemoModule.forRootAsync({
      name: "analytics",
      imports: [ConfigModule],
      inject: [Config],
      useFactory: (config: Config): TypemoModuleFactoryOptions => ({
        uri: config.analyticsUri,
        dbName: "analytics",
        lazyConnection: true,
      }),
    }),
    ReportsModule,
  ],
})
export class AppModule {}
```

<Callout type="migration" title="Если вы пришли из @nestjs/mongoose">

`connectionName` → `name`, `connectionFactory` → `clientFactory`, `connectionErrorFactory` → `clientErrorFactory`, `onConnectionCreate` → `onClientCreate`. Отличия: `onClientCreate` вызывается и при `lazyConnection` (в `@nestjs/mongoose` — нет), клиент один на все попытки, а `name` в результате фабрики — ошибка компиляции.

</Callout>
