icon: Braces

Политикам нужны значения из окружения — чей это тенант, кто действует, показывать ли удалённые. Тянуть их параметром через каждую функцию сервиса не нужно. Откройте область [`PolicyContext.run`](../reference/policies/policy-context.mdx#policy-context.run) один раз там, где эти значения известны, обычно на входе в обработку запроса. Все операции моделей, **построенные** внутри, получат значения сами.

Если особые значения нужны одной операции, для этого есть [`.policy()`](../reference/query/options.mdx#policy).

## Что понадобится [#prerequisites]

Модель заказов организаций с политикой тенанта, как в руководстве [Мультитенантность](./tenants.mdx).

## Быстрый путь [#quick-start]

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, PolicyContext, Tenant, type TenantField } from "@venloc/typemo";
@Schema({ collection: "orders", tenant: true })
class Order extends Entity {
  @Prop(() => String) @Tenant() tenantId!: TenantField<string>;
  @Prop(() => String, { required: true }) number!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Orders = client.connection.model(Order);
// ---cut---
const count = await PolicyContext.run({ tenant: "acme", actor: "user-1" }, async () => {
  await Orders.create({ number: "A-1" });
  return Orders.countDocuments();
});
// → 1
```

## Область в асинхронном коде [#async-scope]

Область сохраняется во всей цепочке вызовов внутри функции — после `await`, в колбэках, после таймера. Даже после паузы `setTimeout` внутри области тенант остался на месте. Поэтому функциям сервиса не нужен тенант в параметрах, они просто вызывают модель.

## Когда область берётся [#when-scope-applies]

Значения фиксируются в момент, когда операцию **строят**, а не когда её ждут. Запрос, построенный внутри `run`, останется запросом своего тенанта, даже если дождаться его снаружи. А запрос, построенный снаружи, тенанта не получит, даже если его дождались внутри. Так запрос, сохранённый в переменной модуля, не подхватит тенанта чужого запроса.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, PolicyContext, Tenant, type TenantField } from "@venloc/typemo";
@Schema({ collection: "orders", tenant: true })
class Order extends Entity {
  @Prop(() => String) @Tenant() tenantId!: TenantField<string>;
  @Prop(() => String, { required: true }) number!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Orders = client.connection.model(Order);
// ---cut---
// построен внутри области, дождались снаружи: тенант acme сохранился
const pending = PolicyContext.run({ tenant: "acme" }, () => Orders.find().plain());
const rows = await pending;
```

## Вложенные области [#nested-scopes]

Внутренний `run` накладывает свои значения поверх внешних. Внутренний `tenant` перекрывает внешний, а `actor` остаётся. `allTenants: true` снимает унаследованный `tenant`, и наоборот. Скажем, `run({ tenant: "a", actor: "u1" }, () => run({ tenant: "b" }, current))` вернёт `{ tenant: "b", actor: "u1" }`. Так фоновая задача внутри запроса может явно перейти на все тенанты и не потерять актора.

## Значения одной операции [#operation-values]

[`.policy()`](../reference/query/options.mdx#policy) накладывается поверх области и действует на одну операцию. `Orders.find().policy({ tenant: "globex" })` прочитает данные `globex`, даже если вызвать его внутри области `acme`. В [`PolicyContext.current()`](../reference/policies/policy-context.mdx#policy-context.current) такие значения не попадают.

## Что контекст проверяет [#context-checks]

Неизвестный ключ, флаг со значением не `true` и противоречия вроде `tenant` вместе с `allTenants` или `includeDeleted` вместе с `onlyDeleted` сразу дают [`QueryError`](../reference/errors/query-errors.mdx#query-error). Опечатку ошибка назовёт по имени — `PolicyContext.run: unknown policy value "tenat" (known: tenant, allTenants, actor, includeDeleted, onlyDeleted, hardDelete)`.

Пустой тенант отвергается как [`StrictModeError`](../reference/policies/violations.mdx#tenant) с причиной `tenant`. Пустым считается пустая строка, строка из одних пробелов и `null`. Текст такой — `PolicyContext.run: the tenant is empty (null); a tenant is a non-empty value, or allTenants: true for cross-tenant work [tenant]`.

## Как выбрать [#how-to-choose]

Спросите себя, **общее ли это значение для всей обработки запроса**.

- **Общее, как тенант и актор запроса**, — открывайте `run`.
- **Особый режим одной операции**, например показать удалённые или прочитать другого тенанта, — берите `.policy()`.

## Когда это не нужно [#when-not-to-use]

Если политик у модели нет, контекст ничего не меняет. И не кладите в него то, что политики не читают. Ключей у контекста шесть, своих добавить нельзя.

Если вы пишете обёртку или плагин, которые сами строят операции, значения области можно взять методами [`PolicyContext.captured`](../reference/policies/policy-context.mdx#policy-context.captured) и [`PolicyContext.merge`](../reference/policies/policy-context.mdx#policy-context.merge). Они публичны как раз для таких случаев, а прикладному коду не нужны.

## Если что-то пошло не так [#troubleshooting]

**`StrictModeError … the operation has no tenant … [tenant]`, хотя вы ждёте запрос внутри `run`.** Область берётся при построении запроса, а этот запрос построили снаружи. Стройте его внутри `run`.

**Область потерялась в очереди или в другом процессе.** `run` живёт в пределах одного процесса. Если работа уходит в очередь, передайте значения `PolicyContext.current()` в сообщении и откройте `run` заново в обработчике.

## Полный пример [#full-example]

```ts twoslash title="http/handler.ts"
import { Entity, Prop, Schema, TypemoClient, PolicyContext, Tenant, type TenantField } from "@venloc/typemo";
@Schema({ collection: "orders", tenant: true })
class Order extends Entity {
  @Prop(() => String) @Tenant() tenantId!: TenantField<string>;
  @Prop(() => String, { required: true }) number!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Orders = client.connection.model(Order);
// ---cut---
declare const __readToken__: (token: string) => { readonly orgId: string; readonly userId: string };

export const handle = (token: string) => {
  const { orgId, userId } = __readToken__(token);
  return PolicyContext.run({ tenant: orgId, actor: userId }, () => Orders.find().plain());
};

// задача очереди: значения передаются явно
export const enqueue = () => PolicyContext.current();
```
