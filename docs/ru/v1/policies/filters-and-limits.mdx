Некоторые значения значат для базы совсем не то, что думает человек.

- Пустой фильтр — это «все документы».
- `limit: 0` — «без ограничения».
- `undefined` драйвер отправит как `null`.
- Пустой `$or` сервер отвергнет, а если его тихо «исправить», поменяется смысл запроса.

Typemo останавливает такие значения ещё до отправки. Эти проверки работают всегда, выключить их нельзя.

## Что понадобится [#prerequisites]

Модель пользователя.

```ts twoslash title="users/user.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "users" })
export class User extends Entity {
  @Prop(() => String, { required: true })
  name!: string;

  @Prop(() => Number)
  age?: number;
}
```

## Быстрый путь [#quick-start]

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, Filters, StrictModeError } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number) age?: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Users = client.connection.model(User);
// ---cut---
try {
  await Users.deleteMany(JSON.parse("{}"));
} catch (error) {
  if (error instanceof StrictModeError) console.log(error.reason);
  // → "empty-filter"
}
await Users.updateMany(Filters.all(), { $set: { age: 1 } });
```

Пустой литерал `{}` в таких вызовах остановит уже компилятор. До базы может дойти только фильтр, который оказался пустым во время работы, например собранный из JSON клиента.

## Пустой фильтр в записи [#empty-filter-in-writes]

`updateOne`, `updateMany`, `deleteOne`, `deleteMany`, `replaceOne` и `findOneAnd*` с пустым фильтром отвергаются до отправки. И `updateOne({})` тоже. Пустой фильтр выбрал бы произвольный документ коллекции, а какой именно, база не обещает. Изменить или удалить «какой-нибудь» документ ничуть не безопаснее, чем все сразу.

Ошибка одна и та же, в том числе внутри `bulkWrite` — `deleteMany with an empty filter would affect every document; pass a filter, or Filters.all() to mean every document on purpose [empty-filter]`. Для форм `One` и `findOneAnd*` текст называет тот же вызов, но звучит иначе, ведь затронут был бы один документ — `deleteOne with an empty filter would change or remove an arbitrary document; …`. Причина `empty-filter` и способ исправить от формы не зависят. В чтении пустой фильтр разрешён, `find({})` вернёт всё.

Литерал `{}` в `updateOne`, `updateMany`, `deleteOne`, `deleteMany` и `replaceOne` не скомпилируется. Компилятор назовёт то же правило ещё до запуска.

```ts twoslash
// @errors: 2769
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
  @Prop(() => Number) age?: number;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Users = client.connection.model(User);
// ---cut---
await Users.updateOne({}, { $set: { age: 1 } });
```

Фильтр с типом `Filter<User>` компилируется, ведь компилятор не знает, пуст ли он. У `findOneAnd*` литерал `{}` тоже компилируется, и ошибка придёт только во время работы. Динамические фильтры вроде `Record<string, unknown>` тоже проверяются только во время работы.

Если «все» — это и есть ваше намерение, напишите [`Filters.all()`](../reference/policies/violations.mdx#filters.all). Это настоящий фильтр `{ _id: { $exists: true } }` без аргумента типа, и намерение видно и в коде, и в журнале команд. Подробнее — в руководстве [Пустые фильтры](../writes/empty-filters.mdx).

## Пустые логические операторы [#empty-logical]

Пустой `$or`, `$and` или `$nor` даёт `QueryError: filter: $or must be a non-empty array (at "$or")`. Для `$nor` и `$and` в тексте будет их имя. Список условий обычно собирается из данных, и пустой список выглядит как «условий нет». Сервер такой оператор отвергает, а если молча его выбросить, запрос найдёт всё. Проверяйте список до сборки.

## undefined вместо значения [#undefined-instead-of-value]

`{ name: undefined }` даёт `QueryError: filter: undefined at "name" (use $exists: false / $unset; undefined is never a value)`, а в обновлении — `update: undefined at "$set.age" …`. Драйвер отправил бы здесь `null`. Просто не передавайте ключ или используйте `$exists: false` и `$unset`.

## Пустое обновление [#empty-update]

Пустое обновление не должно выглядеть как успех. `{}` даёт `QueryError: update: an empty update changes nothing`, а `{ $set: {} }` — `update: operator "$set" is empty`. Конвейер обновления без стадий — тоже `QueryError`, с текстом `an update pipeline needs at least one stage`. Если вместо функции-строителя передать массив, ошибка подскажет, как надо — `update: an update pipeline is built with the pipeline builder: updateOne(filter, (p) => p.set({ … })), not passed as an array`.

## limit и skip [#limit-and-skip]

`limit(0)`, `limit(-1)` и `limit(1.5)` дают `QueryError: limit must be a positive integer, got 0 (number)`. Строка тоже не подойдёт, `limit("3")` вернёт `limit must be a positive integer, got "3" (string)`. Для `skip(-1)` текст такой — `skip must be a non-negative integer, got -1 (number)`. Тип значения печатается рядом, чтобы сразу было видно, что пришла строка, а не число.

В драйвере `0` значит «без ограничения». Ноль легко получить из пустого параметра запроса и случайно выгрузить всю коллекцию. Если ограничение не нужно, просто не вызывайте `limit`. По той же причине отвергается и `batchSize(0)` — драйвер читает ноль как «размер по умолчанию».

## Как выбрать [#how-to-choose]

Спросите себя, **хотите ли вы изменить все документы**. Если да, напишите `Filters.all()`. Если нет, фильтр стал пустым по ошибке, и надо найти, откуда он такой взялся.

## Когда это не нужно [#when-not-to-use]

В чтении пустой фильтр в порядке, `find()` вернёт всё. Ограничение касается только записи.

## Если что-то пошло не так [#troubleshooting]

**`[empty-filter]` в записи, хотя фильтр вы передавали.** Это бывает и в `updateOne` или `deleteOne`. Скорее всего, клиент не прислал условий, а код собрал из них пустой объект. Проверяйте вход и не превращайте отсутствие условий в «все».
