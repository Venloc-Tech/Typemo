Удалённые данные иногда нужны снова. Пользователь передумал, оператор ошибся, юристы просят историю. **Мягкое удаление** делает удаление обратимым. Документ не стирается, а получает в поле метку времени, и остальные операции модели перестают его видеть.

Включите опцию [`softDelete`](../reference/policies/schema-options.mdx#опция-softdelete) в схеме, и дальше `deleteOne` и `deleteMany` работают как обычно. Вернуть документы можно через [`SoftDelete.restore`](../reference/policies/soft-delete-and-untrusted.mdx#softdeleterestore). Если вы впервые слышите о политиках, начните с [обзора](./overview.mdx).

## Что понадобится

Подключённый клиент и блог, где у поста есть заголовок и метка удаления. В коллекции три поста — One, Two и Three.

## Быстрый путь

Добавьте в класс поле `Date | null` и включите политику. Метка `null` значит, что пост жив.

```ts twoslash title="posts/post.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "posts", softDelete: true })
export class Post extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Date, { nullable: true })
  deletedAt?: Date | null;
}
```

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, SoftDelete } from "@venloc/typemo";
@Schema({ collection: "posts", softDelete: true })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Date, { nullable: true }) deletedAt?: Date | null;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Posts = client.connection.model(Post);
// ---cut---
await Posts.deleteOne({ title: "Two" });
console.log(await Posts.countDocuments());
// → 2

await SoftDelete.restore(Posts, { title: "Two" });
console.log(await Posts.countDocuments());
// → 3
```

## Удалить документ

Обычные удаления превращаются в обновление метки, но результат у них остаётся результатом удаления. `deletedCount` — это число помеченных документов. Так ведут себя `deleteOne`, `deleteMany`, `findOneAndDelete`, удаления в `bulkWrite` и `$deleteOne` у документа. `findOneAndDelete` вернёт документ таким, каким он был до пометки.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts", softDelete: true })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Date, { nullable: true }) deletedAt?: Date | null;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Posts = client.connection.model(Post);
// ---cut---
const first = await Posts.deleteOne({ title: "Two" });
console.log(first.deletedCount);
// → 1

const again = await Posts.deleteMany({ title: "Two" });
console.log(again.deletedCount);
// → 0
```

Повторное удаление уже удалённого документа ничего не найдёт. Живых постов с таким заголовком нет, и метка не перезапишется.

## Увидеть удалённые документы

Чтение по умолчанию прячет помеченные документы. Это касается `find`, `findOne`, `countDocuments`, `distinct` и агрегаций. Чтобы увидеть всё или только удалённое, передайте в `.policy()` [`includeDeleted`](../reference/policies/policy-context.mdx#policyvalues) или `onlyDeleted`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts", softDelete: true })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Date, { nullable: true }) deletedAt?: Date | null;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Posts = client.connection.model(Post);
// ---cut---
const live = await Posts.find().sort({ title: 1 }).select({ title: 1 }).plain();
// → ["One", "Three"]

const trash = await Posts.find().policy({ onlyDeleted: true }).plain();
console.log(trash[0]?.title, trash[0]?.deletedAt instanceof Date);
// → "Two" true

const everything = await Posts.find().policy({ includeDeleted: true }).select({ title: 1 }).plain();
// → все три
```

Ваше условие по полю метки не заменяет условие политики, выполниться должны оба. Поэтому `find({ deletedAt: { $ne: null } })` без контекста ничего не найдёт, а вместе с `onlyDeleted` найдёт удалённые за нужный период.

Документы, подтянутые через `$lookup`, `$unionWith`, `$graphLookup` или `populate`, удалёнными не бывают никогда. Политику подтянутой коллекции Typemo берёт из класса, названного в стадии, так что регистрировать его модель не нужно.

## Вернуть и стереть навсегда

[`SoftDelete.restore`](../reference/policies/soft-delete-and-untrusted.mdx#softdeleterestore) снимает метку с подходящих удалённых документов, а [`SoftDelete.purge`](../reference/policies/soft-delete-and-untrusted.mdx#softdeletepurge) стирает удалённые документы насовсем. Обе функции принимают модель и фильтр и возвращают обычную запись модели. Её можно ждать, привязать к сессии и дополнить `.policy()`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, SoftDelete } from "@venloc/typemo";
@Schema({ collection: "posts", softDelete: true })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Date, { nullable: true }) deletedAt?: Date | null;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Posts = client.connection.model(Post);
// ---cut---
await Posts.deleteOne({ title: "Three" });
const purged = await SoftDelete.purge(Posts, { title: "Three" });
console.log(purged.deletedCount);
// → 1

const live = await SoftDelete.purge(Posts, { title: "One" });
console.log(live.deletedCount);
// → 0
```

Обратите внимание, живой пост `One` под `purge` не попал. Функция работает только с удалёнными документами, так что ошибочный фильтр живые данные не сотрёт. Для модели без политики обе функции бросают `ConfigurationError: SoftDelete.purge: Plain has no soft delete; declare @Schema({ softDelete })`.

## Считать быстро

`estimatedDocumentCount` читает метаданные коллекции, а там учтены и удалённые документы. Чтобы число не врало молча, Typemo бросает [`StrictModeError`](../reference/policies/violations.mdx#soft-delete) с текстом `Post.estimatedDocumentCount: the collection's metadata counts soft-deleted documents too; use countDocuments() (or includeDeleted: true to count them all) [soft-delete]`. Для живых документов берите `countDocuments()`, а для общего числа — `.policy({ includeDeleted: true })`.

## Уникальные индексы

Удалённый документ по-прежнему занимает значение в уникальном индексе. Новый пост с тем же уникальным `slug` не запишется, сервер ответит `E11000`. Поэтому при создании модели Typemo подсказывает для каждого уникального индекса, как сделать его частичным по живым документам — `partialFilterExpression: { deletedAt: { $type: "null" } }`. Условие именно `$type: "null"`, потому что вставка всегда пишет `null`, а частичный индекс не умеет выразить «поля нет».

## Как выбрать

Спросите себя, **должен ли этот документ когда-нибудь вернуться**.

- **Да, как заказы, посты или аккаунты** — включайте мягкое удаление.
- **Данные нужно стереть по закону**, например по просьбе «удалите мои данные», — берите `SoftDelete.purge` или отдельную политику хранения. Пометка физически ничего не удаляет.
- **Данные временные и должны чиститься сами** — лучше подойдёт [TTL-индекс](../collections/index-sync.mdx).

## Когда это не нужно

Если удалённые данные не понадобятся никогда, мягкое удаление только тратит место и усложняет уникальные индексы. А если нужен архив со своей жизнью, переносите документы в другую коллекцию явно.

## Если что-то пошло не так

**Удалённый документ «не находится».** После удаления `findOne({ title: "Two" })` возвращает `null`. Это работает политика, данные не потерялись. Посмотреть документ можно через `.policy({ onlyDeleted: true })`.

**Уникальное значение занято удалённым документом.** Создание падает с `DuplicateKeyError`, хотя живого документа с таким значением нет. Сделайте индекс частичным по живым документам. Typemo подсказывает это при создании модели для каждого `unique`-индекса, который «также считает удалённые документы».

**`estimatedDocumentCount` отказывается считать.** Текст ошибки приведён выше. Замените вызов на `countDocuments()`.

## Полный пример

```ts twoslash title="posts/posts.service.ts"
import { Entity, Prop, Schema, TypemoClient, SoftDelete } from "@venloc/typemo";

@Schema({ collection: "posts", softDelete: true })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Date, { nullable: true }) deletedAt?: Date | null;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Posts = client.connection.model(Post);

// удалить: пометка
export const removePost = (title: string) => Posts.deleteOne({ title });

// корзина: только удалённые
export const listTrash = () => Posts.find().policy({ onlyDeleted: true }).plain();

// отменить удаление
export const restorePost = (title: string) => SoftDelete.restore(Posts, { title });

// очистка корзины: навсегда
export const emptyTrash = (title: string) => SoftDelete.purge(Posts, { title });
```

<Callout type="migration">

В Mongoose мягкое удаление делают плагином вроде `mongoose-delete`. Он перехватывает только часть операций, и `lean()`, `aggregate` и `updateMany` часто остаются без защиты. В Typemo политика встроена в конвейер и охватывает все пути, включая агрегации и связанные данные. А восстановление и очистка — отдельные явные функции.

</Callout>
