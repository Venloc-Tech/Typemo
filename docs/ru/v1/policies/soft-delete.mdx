Иногда удалённые данные нужны снова: пользователь передумал, оператор ошибся, юристы просят историю. **Мягкое удаление** делает удаление обратимым: документ не стирается, а получает в поле метку времени, и все остальные операции модели перестают его видеть. Включается опцией [`softDelete`](../reference/policies/schema-options.mdx#опция-softdelete) в схеме, дальше `deleteOne` и `deleteMany` работают как обычно, а вернуть документы можно через [`SoftDelete.restore`](../reference/policies/soft-delete-and-untrusted.mdx#softdeleterestore).

Если вы впервые видите политики, прочитайте [обзор](./overview.mdx).

## Что предполагается

Клиент подключён. Примеры используют блог: у поста есть заголовок и метка удаления. В коллекции три поста: One, Two, Three.

## Быстрый путь

Добавьте в класс поле `Date | null` и включите политику. Метка `null` значит «жив».

```ts twoslash title="posts/post.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "posts", softDelete: true })
export class Post extends Entity {
  @Prop(() => String, { required: true })
  title!: string;

  @Prop(() => Date, { nullable: true })
  deletedAt?: Date | null;
}
```

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, SoftDelete } from "@venloc/typemo";
@Schema({ collection: "posts", softDelete: true })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Date, { nullable: true }) deletedAt?: Date | null;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Posts = client.connection.model(Post);
// ---cut---
await Posts.deleteOne({ title: "Two" });
console.log(await Posts.countDocuments());
// → 2

await SoftDelete.restore(Posts, { title: "Two" });
console.log(await Posts.countDocuments());
// → 3
```

## Удалить документ

Обычные операции удаления превращаются в обновление метки, а результат остаётся результатом удаления: `deletedCount` — число помеченных документов. Это касается `deleteOne`, `deleteMany`, `findOneAndDelete`, удалений в `bulkWrite` и `$deleteOne` документа. `findOneAndDelete` возвращает документ таким, каким он был до пометки.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts", softDelete: true })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Date, { nullable: true }) deletedAt?: Date | null;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Posts = client.connection.model(Post);
// ---cut---
const first = await Posts.deleteOne({ title: "Two" });
console.log(first.deletedCount);
// → 1

const again = await Posts.deleteMany({ title: "Two" });
console.log(again.deletedCount);
// → 0
```

Повторное удаление уже удалённого документа ничего не находит: живых с таким заголовком нет, и метка не перезаписывается.

## Увидеть удалённые документы

Чтение по умолчанию скрывает помеченные документы: `find`, `findOne`, `countDocuments`, `distinct`, агрегации. Чтобы увидеть всё или только удалённое, используйте контекст: [`includeDeleted`](../reference/policies/policy-context.mdx#policyvalues) или `onlyDeleted` в `.policy()`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient } from "@venloc/typemo";
@Schema({ collection: "posts", softDelete: true })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Date, { nullable: true }) deletedAt?: Date | null;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Posts = client.connection.model(Post);
// ---cut---
const live = await Posts.find().sort({ title: 1 }).select({ title: 1 }).plain();
// → ["One", "Three"]

const trash = await Posts.find().policy({ onlyDeleted: true }).plain();
console.log(trash[0]?.title, trash[0]?.deletedAt instanceof Date);
// → "Two" true

const everything = await Posts.find().policy({ includeDeleted: true }).select({ title: 1 }).plain();
// → все три
```

Ваше условие по полю метки не заменяет условие политики: оба должны выполниться. Поэтому `find({ deletedAt: { $ne: null } })` без контекста ничего не найдёт, а вместе с `onlyDeleted` найдёт удалённые нужного периода. Документы, присоединённые через `$lookup`, `$unionWith`, `$graphLookup` или `populate`, удалёнными не бывают никогда. Политику присоединяемой коллекции Typemo берёт из класса, названного в стадии, поэтому создавать его модель на подключении не нужно.

## Вернуть и стереть навсегда

[`SoftDelete.restore`](../reference/policies/soft-delete-and-untrusted.mdx#softdeleterestore) снимает метку с подходящих удалённых документов, [`SoftDelete.purge`](../reference/policies/soft-delete-and-untrusted.mdx#softdeletepurge) стирает удалённые документы совсем. Оба принимают модель и фильтр и возвращают обычную запись модели (её можно ждать, привязать к сессии и `.policy()`).

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, SoftDelete } from "@venloc/typemo";
@Schema({ collection: "posts", softDelete: true })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Date, { nullable: true }) deletedAt?: Date | null;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Posts = client.connection.model(Post);
// ---cut---
await Posts.deleteOne({ title: "Three" });
const purged = await SoftDelete.purge(Posts, { title: "Three" });
console.log(purged.deletedCount);
// → 1

const live = await SoftDelete.purge(Posts, { title: "One" });
console.log(live.deletedCount);
// → 0
```

Живой пост `One` под `purge` не попал: функция работает только с удалёнными документами, и поэтому ошибочный фильтр не сотрёт живые данные. Для модели без политики обе функции бросают `ConfigurationError: SoftDelete.purge: Plain has no soft delete; declare @Schema({ softDelete })`.

## Считать быстро

`estimatedDocumentCount` читает метаданные коллекции и считает удалённые документы тоже. Вместо тихой ошибки в числе Typemo бросает [`StrictModeError`](../reference/policies/violations.mdx#soft-delete): `Post.estimatedDocumentCount: the collection's metadata counts soft-deleted documents too; use countDocuments() (or includeDeleted: true to count them all) [soft-delete]`. Используйте `countDocuments()` для живых или `.policy({ includeDeleted: true })`, если нужно общее число.

## Уникальные индексы

Удалённый документ продолжает занимать значение уникального индекса: новый пост с тем же уникальным `slug` не запишется (`E11000`). Поэтому Typemo при создании модели подсказывает для каждого уникального индекса, как сделать его частичным по живым документам: `partialFilterExpression: { deletedAt: { $type: "null" } }`. Условие именно `$type: "null"`: вставка всегда записывает `null`, а частичный индекс не умеет выражать «поля нет».

## Как выбрать

Спросите себя: **должен ли этот документ вообще когда-нибудь вернуться?** Если да (заказы, посты, аккаунты), включайте мягкое удаление. Если данные нужно стереть по закону (просьба «удалить мои данные»), это `SoftDelete.purge` или отдельная политика хранения: пометка не удаляет данные физически. Для временных данных с автоочисткой лучше [TTL-индекс](../collections/index-sync.mdx).

## Когда это не нужно

Если удалённые данные не нужны никогда, мягкое удаление только расходует место и усложняет уникальные индексы. Если вам нужен архив с отдельной жизнью, перенесите документы в другую коллекцию явно.

## Частые ошибки

### Удалённый документ «не находится»

`findOne({ title: "Two" })` после удаления даёт `null`: это работа политики, а не потеря данных. Посмотрите его через `.policy({ onlyDeleted: true })`.

### Уникальное значение занято удалённым документом

Создание падает с `DuplicateKeyError`, хотя живого документа с таким значением нет. Сделайте индекс частичным по живым документам, как подсказывает Typemo при создании модели (`unique`-индекс, который «также считает удалённые документы»).

### `estimatedDocumentCount` отказывает

Текст приведён выше. Замените вызов на `countDocuments()`.

## Полный пример

```ts twoslash title="posts/posts.service.ts"
import { Entity, Prop, Schema, TypemoClient, SoftDelete } from "@venloc/typemo";

@Schema({ collection: "posts", softDelete: true })
class Post extends Entity {
  @Prop(() => String, { required: true }) title!: string;
  @Prop(() => Date, { nullable: true }) deletedAt?: Date | null;
}

const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Posts = client.connection.model(Post);

// удалить: пометка
export const removePost = (title: string) => Posts.deleteOne({ title });

// корзина: только удалённые
export const listTrash = () => Posts.find().policy({ onlyDeleted: true }).plain();

// отменить удаление
export const restorePost = (title: string) => SoftDelete.restore(Posts, { title });

// очистка корзины: навсегда
export const emptyTrash = (title: string) => SoftDelete.purge(Posts, { title });
```

<Callout type="migration">

В Mongoose мягкое удаление делают плагином (`mongoose-delete` и подобные), который перехватывает часть операций, а `lean()`, `aggregate` и `updateMany` часто остаются без защиты. В Typemo политика встроена в конвейер и охватывает все пути, включая агрегации и связанные данные, а восстановление и очистка — явные функции.

</Callout>
