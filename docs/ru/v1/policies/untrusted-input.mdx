---
title: Принять фильтр из запроса клиента
description: "Клиент не сможет подменить значение оператором запроса или открыть скрытое поле через проекцию"
icon: ShieldAlert
---

Данные для фильтра часто приходят от клиента — из тела запроса или из строки запроса. Клиент может прислать вместо строки объект с оператором и тем самым поменять смысл запроса. Функция [`untrusted`](../reference/policies/soft-delete-and-untrusted.mdx#untrusted) помечает такие данные. Если внутри них на любой глубине найдётся ключ с `$` или `+`, она бросит [`StrictModeError`](../reference/policies/violations.mdx#sanitize) с причиной `sanitize`.

Вторым аргументом, [`UntrustedPlace`](../reference/policies/soft-delete-and-untrusted.mdx#untrustedplace), вы говорите, куда попадут данные — в фильтр, в обновление или в проекцию. Сама проверка от этого не меняется, но текст ошибки объяснит опасность именно для этого места. Это **дополнительная** защита. Основная — проверить ввод схемой и собрать фильтр самому.

<Callout type="warning" title="Фильтр { name: body.name } не защищён сам по себе">

Если поле фильтра берётся из тела запроса как есть, `find({ name: body.name })`, клиент может прислать вместо строки объект с оператором, например `{"name": {"$gt": ""}}`. Для строкового поля `name` условие `{ $gt: "" }` правильное и правильно типизированное. Typemo его выполнит, и вместо одного пользователя запрос вернёт всех. Компилятор этого не заметит, ведь тип `body.name` вы объявили сами. Оберните данные клиента в [`untrusted`](../reference/policies/soft-delete-and-untrusted.mdx#untrusted) или проверьте, что пришла строка. Подробно — в разделе [Оператор вместо значения](#оператор-вместо-значения).

</Callout>

## Что понадобится

Клиент, подключённый по руководству [Подключиться к базе](../connection/connect.mdx), и модель пользователя блога.

```ts twoslash title="users/user.ts"
import { Entity, Prop, Schema } from "@venloc/typemo";

@Schema({ collection: "users" })
export class User extends Entity {
  @Prop(() => String, { required: true })
  name!: string;
}
```

## Быстрый путь

Оберните данные клиента в `untrusted` там, где кладёте их в фильтр.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, untrusted, StrictModeError } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Users = client.connection.model(User);
// ---cut---
const body = JSON.parse('{"name":{"$ne":"zzz"}}') as { name: string };
try {
  await Users.find(untrusted(body)).plain();
} catch (error) {
  if (error instanceof StrictModeError) console.log(error.reason, error.path);
  // → "sanitize" "name.$ne"
}
```

Данные клиента обычно приходят словарём `Record<string, unknown>`. Такой фильтр компилируется без приведения типов, а имена ключей проверяются при запуске, сразу после проверки `untrusted`. Ключ, которого нет в схеме, остановит запрос до обращения к базе.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, untrusted, StrictModeError } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Users = client.connection.model(User);
// ---cut---
const fromQuery: Record<string, unknown> = JSON.parse('{"nope":"x"}');
try {
  await Users.find(untrusted(fromQuery)).plain();
} catch (error) {
  if (error instanceof StrictModeError) console.log(error.message);
  // → filter: "nope" is not a field of User [unknown-path]
}
```

## Оператор вместо значения

Приложение ищет пользователя по имени из тела запроса — `find({ name: body.name })`. Клиент присылает `{"name": {"$gt": ""}}`. Условие «имя равно» превращается в «имя больше пустой строки», и находятся все пользователи. В коллекции их трое — `ann`, `bob` и `cy`.

```ts twoslash title="users/users.service.ts"
import { Entity, Prop, Schema, TypemoClient, untrusted, StrictModeError } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Users = client.connection.model(User);
// ---cut---
const body = JSON.parse('{"name":{"$gt":""}}') as { name: string };

const found = await Users.find({ name: body.name }).plain();
console.log(found.map((user) => user.name));
// → ["ann", "bob", "cy"]
```

Почему Typemo это пропускает? Фильтр разрешает операторы полей как обычное условие, и `{ $gt: "" }` для строкового поля — правильное условие нужного типа. Строгие проверки сверяют путь, оператор и тип операнда, а откуда взялось значение, они не знают. Приведение типов остановило бы только оператор с операндом другого типа.

Компилятор тоже молчит. `JSON.parse` возвращает то, что вы объявили, и тип `string` у `body.name` — ваше обещание, а не проверка. Typemo не отличит условие, написанное программистом, от условия, присланного клиентом. Поэтому данные клиента нужно пометить.

`untrusted` остановит такой ввод до обращения к базе и назовёт путь к оператору.

```ts twoslash title="users/users.service.ts"
import { Entity, Prop, Schema, TypemoClient, untrusted, StrictModeError } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Users = client.connection.model(User);
// ---cut---
const body = JSON.parse('{"name":{"$gt":""}}') as { name: string };

try {
  await Users.find(untrusted({ name: body.name })).plain();
} catch (error) {
  if (error instanceof StrictModeError) console.log(error.message);
}
// → untrusted value: "$gt" at "name.$gt" — an operator inside data from outside (query selector injection); validate the input and build the filter yourself [sanitize]
```

Можно обернуть и одно значение, `{ name: untrusted(body.name) }`. Тогда путь в ошибке начнётся с оператора (`$gt`). Надёжнее всего сначала проверить ввод схемой — `typeof body.name === "string"` или валидатором запроса, — потом собрать фильтр, а `untrusted` оставить страховкой.

Проверка идёт на любую глубину, включая массивы и `Map`. Для `untrusted({ a: [{ b: { $gt: 1 } }] })` путь будет `a.0.b.$gt`. Даты, регулярные выражения и значения BSON считаются данными, внутрь них проверка не заглядывает.

## Не отдать скрытое поле через проекцию

В проекции ключ `+путь` добавляет [скрытое поле](../reference/schemas/field-markers.mdx#hidden). Если клиент сам выбирает поля через `?fields=…`, он может прислать `{"+passwordHash": true}`. Для проекции передайте вторым аргументом `"projection"`. Такая проекция будет отвергнута, и текст назовёт именно эту угрозу — `untrusted value: "+passwordHash" at "+passwordHash" — a "+path" key inside data from outside would select a Hidden field; validate the input and build the projection yourself [sanitize]`.

Ключ с `$` в проекции тоже отвергается, иначе он превратил бы проекцию в вычисляемое выражение. Текст такой — `untrusted value: "$slice" at "a.$slice" — an operator inside data from outside would turn the projection into a computed expression; validate the input and build the projection yourself [sanitize]`.

```ts twoslash
import { Entity, Prop, Schema, TypemoClient, untrusted } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Users = client.connection.model(User);
// ---cut---
export const listFields = async (fields: { name: 1 }) =>
  Users.find().select(untrusted(fields, "projection")).plain();
```

## Данные клиента в обновлении

С обновлением тот же риск. Клиент присылает поля для изменения, а среди них оказывается ключ оператора. Передайте `"update"`, и ошибка скажет, что именно поменяло бы такое значение.

```ts twoslash
import { untrusted, StrictModeError } from "@venloc/typemo";
// ---cut---
const patch = JSON.parse('{"$set":{"role":"admin"}}') as { name?: string };

try {
  untrusted(patch, "update");
} catch (error) {
  if (error instanceof StrictModeError) console.log(error.message);
  // → untrusted value: "$set" at "$set" — an operator inside data from outside would change what the update does (update operator injection); validate the input and build the update yourself [sanitize]
}
```

Ключ `+` в фильтре или обновлении тоже отвергается. Это не имя поля, а синтаксис проекции, и в данных клиента ему делать нечего. Если вместо места передать что-то кроме трёх допустимых значений, а это возможно только без типов, вы получите [`QueryError`](../reference/errors/query-errors.mdx#queryerror) с текстом `untrusted(value, place): place must be "filter", "update" or "projection", got string "nope"`.

## Проверить целый объект отдельно

Если значение нужно проверить, но не пропускать через функцию, вызовите [`Untrusted.check`](../reference/policies/soft-delete-and-untrusted.mdx#untrustedcheck). Проверка та же, только функция ничего не возвращает.

## Что делает Typemo и без untrusted

Строгие проверки фильтра работают всегда. С причиной `sanitize` отвергаются неизвестный оператор, оператор на верхнем уровне, смесь операторов и полей, `$where` и другие вычисления на сервере. Скажем, `filter.$where` даёт такой текст.

`"$where" runs JavaScript on the server and is not supported (at "filter.$where"): JavaScript code in a query runs with the rights of the database, cannot be checked against the schema, and turns injected input into executed code (Mongoose CVE-2025-23061, $where in populate); write the condition with query or aggregation operators ($expr) instead [sanitize]`

Причина в самом тексте. JavaScript в запросе исполняется с правами базы, и подмена значения в нём превращается в выполнение чужого кода. Условие, которое хотелось написать на JavaScript, запишите операторами запроса или агрегации. Полный список — в [Нарушениях политик](../reference/policies/violations.mdx#sanitize).

## Как выбрать

Спросите себя, **пришло ли значение от человека или от другой системы**.

- **Да** — проверьте его схемой валидации, соберите фильтр из проверенных значений и добавьте `untrusted` как страховку.
- **Значение создал ваш код** — `untrusted` не нужен.

## Когда это не нужно

Для значений, которые вы сами собрали из проверенных полей, `untrusted` — лишний проход. Проверку типов и диапазонов он не заменяет и не решает, какие поля клиенту можно запрашивать.

## Если что-то пошло не так

**`untrusted` приняли за проверку ввода.** Он смотрит только на ключи. Строка `"; drop"` или отрицательное число пройдут спокойно. Тип, форму и диапазон проверяйте отдельно.

**Помечено не всё.** Защищено только то, что прошло через функцию. Если `untrusted` обёрнут вокруг `body.name`, а `body.filter` попадает в запрос как есть, оператор пройдёт. Оборачивайте каждый кусок данных клиента.

## Полный пример

```ts twoslash title="users/users.service.ts"
import { Entity, Prop, Schema, TypemoClient, untrusted } from "@venloc/typemo";
@Schema({ collection: "users" })
class User extends Entity {
  @Prop(() => String, { required: true }) name!: string;
}
const client = await TypemoClient.connect("mongodb://localhost:27017/app");
const Users = client.connection.model(User);
// ---cut---
// код читателя: проверка формы ввода
declare const __parseQuery__: (raw: unknown) => { readonly name: string };

export const searchUsers = async (raw: unknown) => {
  const query = __parseQuery__(raw);
  // страховка: даже проверенное значение проходит через untrusted
  return Users.find({ name: untrusted(query.name) }).plain();
};
```

<Callout type="migration">

В Mongoose для этого есть `sanitizeFilter`, и его надо включать. В Typemo строгие проверки фильтра работают всегда, а `untrusted` дополнительно запрещает операторы и `+`-ключи внутри данных клиента.

</Callout>
