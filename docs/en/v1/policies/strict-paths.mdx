---
title: Prevent typos in field names
description: "What happens when a filter, update, projection, or sort names a field the schema doesn't have"
icon: SpellCheck
---

Typemo checks every path in a filter, update, projection, sort, and pipeline against the schema. If there's no such field, the operation never goes to the server, and you get a [`StrictModeError`](../reference/policies/violations.mdx#unknown-path) with the reason `unknown-path`. Otherwise the typo `nmae` would give you a filter that finds nothing, or an update that silently writes nothing.

In typed code the compiler catches such a typo. The runtime check matters where the path comes from data, for example from a client's JSON.

## Where paths are checked [#where-paths-are-checked]

The check works in every part of a query, and the `path` in the error tells you where exactly it tripped.

- A filter: `filter.nope`.
- A condition inside `$or`: `filter.$or.0.nope`.
- An update: `$set.nope`.
- A projection: `projection.nope`.
- A sort: `sort.nope`.

The error text has the same form everywhere: `filter: "nope" is not a field of User [unknown-path]`. First comes the path to the place of the error, printed once, then the name of the unknown field in quotes. Inside `$or` that place is longer: `filter.$or.0: "nope" is not a field of User [unknown-path]`.

A `+path` key in a projection, which adds a hidden field, is checked the same way. An unknown name after the plus gives a `StrictModeError` with the reason `unknown-path` and the path `projection.+nope`. So a typo in `+passwordHash` won't turn into a projection that silently added nothing.

## Unknown fields in document data [#unknown-fields-in-data]

The path check is about queries. Extra fields in a **document you create** are a separate story, described on [Handle fields that aren't in the schema](../documents/unknown-fields.mdx).

## How to choose [#how-to-choose]

You can't relax the check. There's no option that would let an unknown path through. If you really need the field, add it to the schema. If you work with data that has no schema, use [`client.unsafeDriver()`](../reference/connection/typemo-client.mdx#client.unsafe-driver).

## When not to use it [#when-not-to-use]

In typed code the compiler stops a typo earlier. The runtime check matters when the path comes from outside.

## Troubleshooting [#troubleshooting]

**An error on a path built from data.** The path is glued together as a dotted string and contains a field the schema doesn't have. The error shows the whole path in `path`. Check the names against a list of allowed fields before you build the filter.
