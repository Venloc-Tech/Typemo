Let's walk an extension all the way through on one task. The admin UI needs a table of accounts, and you want to set the column headers and value formats right in the model instead of repeating them in the UI code. The `label` extension stores a caption on a field and, if needed, a format function. It checks them when the schema compiles, and the UI reads them from the schema description.

The general rules for extensions are in [Add your own field and schema options](./custom-options.mdx), and every piece is in the [Extensions](../reference/extensions/extensions.mdx) reference. This page only puts it together.

## What you need [#prerequisites]

- A client connected as in [Connect to the database](../connection/connect.mdx).
- The extension is registered on the client, because only its models build the column table.
- The collection holds one account: title `Main`, owner `alice`, balance `12.5`.

## Step 1. Declare the type and write the check [#declare-type]

The extension file has two parts. The module declaration adds the `label` key to the `ext` of fields and schemas, and `TypemoExtension` checks the values. Typemo adds the field's address to a check error itself. So a bad caption shows up as soon as the app starts, named by its field, instead of surfacing as an empty table.

<Snippet id="extensions/example/declare-type" title="extensions/label.ts" twoslash />

## Step 2. Use the key in the model [#use-in-model]

The model describes the account with ordinary `@Prop` fields and sets the captions in `ext`. The balance has a `format`, and the compiler knows `value` is a number, since the type comes from the field.

<Snippet id="extensions/example/use-in-model" title="accounts/account.ts" twoslash />

The `owner` field has no extension, so it won't get into the table.

## Step 3. Read the columns from the schema [#read-columns]

The `columns` function walks the schema paths from `describe()` and takes the options of each one through `extOf`. It skips paths without `label`. The UI learns the headers and formats from the model, and to add a column you only add `ext` to a field. You don't have to touch the UI.

<Snippet id="extensions/example/read-columns" title="admin/columns.ts" twoslash />

`describe()` returned every path of the model, including `_id` and `owner`, and `extOf` kept only the ones with `label`. The values of `extOf` come as `unknown`, since the compiler doesn't know the `label` key is declared. So the function narrows the type itself, and the `validateProp` check at registration has already guaranteed the shape. You can get the `format` function only through `extOf`. Functions disappear from the JSON description that `describe()` returns.

## How to choose [#how-to-choose]

An extension fits when the data is needed **outside** the core and the core itself doesn't need it. Your code or an integration reads it. If the value has to change queries, you need a [hook](../hooks/operation-hooks.mdx) instead of an extension.

## When not to use it [#when-not-to-use]

One app with one model can get by with an ordinary table of captions next to the code. An extension pays off when the captions should live on the field and the number of models keeps growing.

## Troubleshooting [#troubleshooting]

**The extension is registered after `model`.** `client.use` after the first `connection.model` throws a `ConfigurationError` with the text `extension "label": extensions are fixed once a schema is compiled (Account was); call client.use() before the first model`. Move the registration up.

**An empty caption.** The error comes when the schema compiles, not when the table renders: `ConfigurationError: Bad.a: ext "label" is invalid: text must be a non-empty string (scalar)`. Typemo added the `Bad.a` address.
