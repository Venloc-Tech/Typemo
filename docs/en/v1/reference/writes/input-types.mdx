Five types describe the data that goes into the database: `CreateInput`, `UpdateInput`, `Update`, `Replacement`, and `WriteValue`. All of them are inferred from the model class and change with it. Use them when you write your own functions around the write methods and want to type an argument the same way the library does.

If you're just starting out, read the [Create documents](../../writes/create.mdx) guide first. This page is a reference.

The shape of input data differs from the shape of a document. On create, you can't require fields that have a default. On update, you can't allow changes to `_id` or to `immutable` fields. Values are accepted more loosely, though: an `ObjectId` can be passed as a string, an `int64` as a decimal string, a `Map` as a plain object. A single shared type would either forbid something you need or allow something you don't.

All examples use the same account model.

## CreateInput [#create-input]

`CreateInput<T>` describes the data of a new document. It's accepted by [`create`](./writes.mdx#create), [`insertOne`](./writes.mdx#insert-one), [`insertMany`](./writes.mdx#insert-many), and `Model.new`. The required fields of the model are required here too. Fields with `Defaulted`, optional fields (`?:`), arrays, and the tenant field can be left out, and an array without `required` gets `[]`. The type has no virtual fields and no methods. The editor hint expands the type down to the fields, so you can see exactly what is accepted.

<Snippet id="reference/writes/input-types/create-input" twoslash />

Subdocuments are described by the same type. An element of `lines` is a `CreateInput<Line>`, so `sku` and `qty` are required there as well. The input can't hold `undefined`. A field is either present or absent, because the driver would write `null` in place of `undefined`.

### Accepted value forms [#accepted-values]

A value is accepted in several forms, so data from outside doesn't have to be converted into driver types by hand. An `ObjectId` and a `UUID` can be passed as a string, an `int64` as a `bigint` or a decimal string (`Int64String`), a `Map` as a `Map` or a plain object, and an array as a plain or a `readonly` one. The format of a string is checked at runtime.

<Snippet id="reference/writes/input-types/accepted-values" />

### When not to use it [#create-input.when-not-to-use]

To replace a whole document, use [`Replacement`](#replacement). It has no `_id` and no service fields.

## UpdateInput [#update-input]

`UpdateInput<T>` is the set of fields a write **can change**. All the fields of the model are optional in it, but `_id` and the `immutable` fields are missing. It's the type of a "patch": an object with some of the fields that arrives from a form or a request and goes whole into [`$set`](./update-operators.mdx#set).

<Snippet id="reference/writes/input-types/update-input" twoslash />

The patch goes into `$set` with no casts and no intermediate variables. The hint shows it expanded.

<Snippet id="reference/writes/input-types/update-input-2" twoslash />

The compiler lets an empty patch (`{}`) through, and the runtime parser rejects it with `QueryError: update: operator "$set" is empty`.

A field that can't be changed is absent from the type. The compiler accepts neither `region` (it's `immutable`) nor `_id`.

<Snippet id="reference/writes/input-types/update-input-3" twoslash />

<Snippet id="reference/writes/input-types/update-input-4" />

</FullType>

### When not to use it [#update-input.when-not-to-use]

`UpdateInput` describes only writable top-level fields. For other operators (`$inc`, `$push`) and nested paths, use [`Update`](#update).

## Update [#update]

`Update<T>` describes an **operator object**. It's accepted by [`updateOne`](./writes.mdx#update-one), [`updateMany`](./writes.mdx#update-many), [`findOneAndUpdate`](./writes.mdx#find-one-and-update), and [`findByIdAndUpdate`](./writes.mdx#find-by-id-and-update). The first-level keys are operators, and the allowed paths and operands depend on the model. `$inc` accepts only numeric fields, `$push` only arrays, and `$unset` only optional fields.

The type is useful when you build an update in one place and apply it in another.

<Snippet id="reference/writes/input-types/update" twoslash />

This is where the main protection works: an operator on an unsuitable field doesn't compile.

<Snippet id="reference/writes/input-types/update-2" twoslash />

The type accepts the same operators as the runtime parser: `$set`, `$setOnInsert`, `$unset`, `$inc`, `$mul`, `$min`, `$max`, `$currentDate`, `$rename`, `$push`, `$addToSet`, `$pull`, `$pullAll`, `$pop`, and `$bit`. They're described in detail on the [Update operators](./update-operators.mdx) page. An empty update, or one path under two operators, is rejected by the method at runtime with a `QueryError`, as described in [Update operators](./update-operators.mdx).

The second parameter, `Loose`, is for the write methods themselves. In the constraint of their generic parameter, the keys of `Map` entries accept any value, and `UpdateCheck` checks the keys that are actually passed. You don't need to set it in your own code.

</FullType>

### When not to use it [#update.when-not-to-use]

If a value is computed from other fields, an operator object won't do. Use a [pipeline](./pipeline-updates.mdx).

## Replacement [#replacement]

`Replacement<T>` describes the **new document** for [`replaceOne`](./writes.mdx#replace-one) and [`findOneAndReplace`](./writes.mdx#find-one-and-replace). It's `CreateInput<T>` without `_id` and without the service fields `createdAt`, `updatedAt`, and `__v`. The `_id` stays the same, and the core maintains the service fields.

<Snippet id="reference/writes/input-types/replacement" twoslash />

The `region` field of this model is immutable (`immutable`), and a replacement must pass it explicitly, or it would lose the field. Without it, `replaceOne` rejects the replacement at runtime (`StrictModeError … without the immutable field "region" would drop it …`), even though the field is optional in the type. Here is the hint.

## WriteValue [#write-value]

`WriteValue<T, P>` is the type of the value at the **write path** `P`. It answers the question "what sits at this path in an update". A write path isn't the same as a read path. You have to go through an array with a positional operator, or the type is `never`, just like the server's answer is an error. The type is useful in your own wrappers around updates.

<Snippet id="reference/writes/input-types/write-value" twoslash />

A path through an array without a positional operator has no write value.
