Expressions compute a new value from a document's fields right inside the pipeline. This page covers three groups of operators: comparison, logic, and picking a value. You write an expression in the `(f) => …` callback of stages such as [`project`](./stages.mdx#project), [`addFields`](./stages.mdx#add-fields), and [`group`](./stages.mdx#group). `f` is a proxy of the model's fields, and the operators live on the `fn` object.

If you're starting out, read the guide [Calculations in aggregation](../../aggregation/expressions.mdx) first. It explains why a callback replaces strings with `$` and why raw `$expr` is forbidden. This page is a reference for the operators of the group.

All examples use one shop order model. It has a number, an optional number, an array of numbers, a string with a list of allowed values, and a date.

<Snippet id="reference/aggregation/accumulators/intro" title="shop/order.ts" twoslash />

The examples use two stages. `sort` by date and `limit(2)` keep the first two orders, and `project` shows `total` and a computed field. Alice's order for 120 is paid, with a discount of 10 and items 20 and 100. Alice's order for 80 is paid and has no discount. The rows come from the [`.plain()`](./pipeline.mdx#plain) method.

Typemo compares more strictly than MongoDB. The server can compare values of different types by a fixed order of BSON types, so a number is "less" than a string, and a missing field is "less" than any number. In a query you write on purpose, that's almost always a mistake. So both arguments of a comparison must have the same type, or the compiler refuses with `TS2345: Argument of type '"x"' is not assignable to parameter of type 'Arg<Nullable<number>>'.`

<Snippet id="reference/aggregation/expr-logic/intro" twoslash />

There's one exception, `null`. You can put it on either side, because `fn.eq(x, null)` is exactly a check for `null`.

## Logic [#logic]

### fn.and [#fn.and]

`fn.and` returns `true` if all arguments are truthy. It takes one or more arguments and returns `boolean`. `null` counts as false, so the result is never `null`.

<Snippet id="reference/aggregation/expr-logic/fn-and" twoslash />

### fn.or [#fn.or]

`fn.or` returns `true` if at least one argument is truthy. The arguments and the result are the same as for `fn.and`.

<Snippet id="reference/aggregation/expr-logic/fn-or" twoslash />

How both operators behave with `null` is shown below, after `fn.not`.

### fn.not [#fn.not]

`fn.not` flips a `boolean`. It takes one value, which may be `null`.

<Snippet id="reference/aggregation/expr-logic/fn-not" twoslash />

All three logic operators treat `null` as false. `fn.and(true, null)` gives `false`, `fn.or(false, null)` also gives `false`, and `fn.not(null)` gives `true`.

<Snippet id="reference/aggregation/expr-logic/fn-not-2" twoslash />

## Comparison [#comparison]

All six comparison operators take exactly two arguments of the same type and return `boolean`. The type is inferred from both values at once, so you can't compare a number with a string, or a date with a number.

### fn.eq [#fn.eq]

`fn.eq` checks equality.

<Snippet id="reference/aggregation/expr-logic/fn-eq" twoslash />

A check for `null` doesn't find a missing field. In the second order `discount` isn't set, and `fn.eq(f.discount, null)` gives `false`, because a missing field and `null` are different values. To catch both cases, use [`fn.ifNull`](#fn.if-null) or compare [`fn.typeOf`](./expr-conversion.mdx#fn.type-of) with `"missing"`.

<Snippet id="reference/aggregation/expr-logic/fn-eq-2" twoslash />

### fn.ne [#fn.ne]

`fn.ne` checks inequality.

<Snippet id="reference/aggregation/expr-logic/fn-ne" twoslash />

### fn.gt [#fn.gt]

`fn.gt` checks "strictly greater than". Dates are compared with dates.

<Snippet id="reference/aggregation/expr-logic/fn-gt" twoslash />

### fn.gte [#fn.gte]

`fn.gte` checks "greater than or equal to".

<Snippet id="reference/aggregation/expr-logic/fn-gte" twoslash />

### fn.lt [#fn.lt]

`fn.lt` checks "strictly less than".

<Snippet id="reference/aggregation/expr-logic/fn-lt" twoslash />

The operator doesn't warn you about a missing field. The server treats a missing value as less than any number, so in the second order, where `discount` isn't set, `fn.lt(f.discount, 0)` gives `true`.

<Snippet id="reference/aggregation/expr-logic/fn-lt-2" twoslash />

With an optional field, check it separately first or substitute a value through [`fn.ifNull`](#fn.if-null).

### fn.lte [#fn.lte]

`fn.lte` checks "less than or equal to".

<Snippet id="reference/aggregation/expr-logic/fn-lte" twoslash />

### fn.cmp [#fn.cmp]

`fn.cmp` compares two values and returns `-1`, `0`, or `1`. The result type is exactly `-1 | 0 | 1`, not `number`, so it's easy to branch on.

<Snippet id="reference/aggregation/expr-logic/fn-cmp" twoslash />

The order for 120 is greater than 100, so you get `1`. The order for 80 is less, so you get `-1`. Dates compare the same way. Alice's order from January 5 is earlier than January 10 (`-1`), and the order from January 12 is later (`1`).

<Snippet id="reference/aggregation/expr-logic/fn-cmp-2" twoslash />

### fn.isIn [#fn.is-in]

`fn.isIn` checks that a value is in an array. It takes a value and an array, either a literal or an array field. On the server the operator is called `$in`, and in `fn` it's `isIn`.

<Snippet id="reference/aggregation/expr-logic/fn-is-in" twoslash />

The array can be a model field. Then the check is whether the value is in it.

<Snippet id="reference/aggregation/expr-logic/fn-is-in-2" twoslash />

The second order has an item of 80, so `cheap` is `true` for it.

## Pick a value [#choose-value]

### fn.cond [#fn.cond]

`fn.cond` returns one of two values. It takes three arguments: a condition, the "yes" value, and the "no" value. If the condition is true, the result is `then`, otherwise `otherwise`. The result type is the union of the types of both branches.

<Snippet id="reference/aggregation/expr-logic/fn-cond" twoslash />

This is the shortest way to write a choice. For more than two options, use [`fn.switch`](#fn.switch).

### fn.switch [#fn.switch]

`fn.switch` picks a value by the first condition that matches. It takes `branches`, a list of `{ case, then }` pairs, and an optional `default`.

<Snippet id="reference/aggregation/expr-logic/fn-switch" twoslash />

The first true condition wins, so the order of branches sets the priority. 120 matches both "at least 100" and "at least 50", but the first branch is picked.

Without `default`, Typemo doesn't add `null` to the result type. In that case the server doesn't return `null`. It fails, and you see that at run time.

<Snippet id="reference/aggregation/expr-logic/fn-switch-2" />

If the branches don't cover all values, always write a `default`.

### fn.ifNull [#fn.if-null]

`fn.ifNull` returns the first value that isn't `null` and isn't missing. It takes a value and a fallback of the same type, and you can add more fallbacks after them.

<Snippet id="reference/aggregation/expr-logic/fn-if-null" twoslash />

The result type is the fallback's type (`number`), without `undefined`, because both a gap and `null` are replaced. For optional fields this is the main operator. It turns "no discount" into `0`, which you can compute with.

### fn.literal [#fn.literal]

`fn.literal` passes a value to the server as is, without reading it as a field path or an operator. For a string with a dollar sign you usually don't need it, because Typemo wraps such a string in `$literal` itself. You can see that in the result.

<Snippet id="reference/aggregation/expr-logic/fn-literal" twoslash />

Here `"$"` is a plain sign, not a `$…` path. To pin a value explicitly, wrap it in `fn.literal`.

<Snippet id="reference/aggregation/expr-logic/fn-literal-2" twoslash />

## When not to use it [#when-not-to-use]

- **You need to filter documents, not compute a field.** Use the [`match`](./stages.mdx#match) stage with an ordinary filter or an expression predicate, not `fn.cond` in `project`.
- **You need arithmetic and rounding.** See the [arithmetic operators](./expr-arithmetic.mdx).
- **You need to compare strings ignoring case.** Use [`fn.strcasecmp`](./expr-string.mdx#fn.strcasecmp), not `fn.cmp`.
- **You need to check a value's type.** There are [`fn.typeOf`](./expr-conversion.mdx#fn.type-of) and [`fn.isNumber`](./expr-conversion.mdx#fn.is-number) for that.
