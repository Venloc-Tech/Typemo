Expressions compute a new value from a document's fields right inside the pipeline. The operators on this page work with nested documents (objects) and variables. They read a field by name, merge two documents, add and remove a field, turn a document into a list of pairs, and introduce temporary variables. The operators live on the `fn` object and are called in the `(f) => …` callback of stages such as [`project`](./stages.mdx#project) and [`addFields`](./stages.mdx#add-fields).

If you're starting out, read the guide [Calculations in aggregation](../../aggregation/expressions.mdx) first. This page is a reference for the operators of the group.

All examples use one shop order model with a nested shipping address. The city is required, and the postal code isn't.

<Snippet id="reference/aggregation/expr-conversion/intro" title="shop/order.ts" twoslash />

The examples use `sort` by date, `limit(2)`, and `project`. They keep the first two orders. Alice's order for 120 ships to Oslo with postal code 0150. Alice's order for 80 also ships to Oslo, but without a postal code. The collection has four more orders from Bob and Carol. One of Bob's orders has the address Rome with postal code 00100, and one of Carol's has the address Turin. The rows come from the [`.plain()`](./pipeline.mdx#plain) method.

The `shipTo` field is optional, so in expressions its type is a document or nothing. The operators take that into account. If there's no document, the result is `null` or a gap, and the result type shows it.

## Merge and read [#merge-and-read]

### fn.mergeObjects [#fn.merge-objects]

`fn.mergeObjects` merges documents from left to right, like `{ ...a, ...b }`. A field from the right document replaces the same-named field from the left one. The operator takes one or more documents, and `null` and a missing document add nothing.

<Snippet id="reference/aggregation/expr-object/fn-merge-objects" twoslash />

The first order's result has the city, the postal code, and the added country. The second order had no postal code, and the result has none either.

If the right document contains the same field, it replaces it. Here the first order's postal code 0150 became `"1"`, and the second order gained a postal code.

<Snippet id="reference/aggregation/expr-object/fn-merge-objects-2" twoslash />

With one argument, the operator also works as an accumulator. In the [`group`](./stages.mdx#group) stage it merges the group's documents. Alice's orders have the address Oslo, and Bob has an address in only one order, so that one remains.

<Snippet id="reference/aggregation/expr-object/fn-merge-objects-3" twoslash />

The other accumulators are described on the page [Accumulators](./accumulators.mdx).

### fn.objectToArray [#fn.object-to-array]

`fn.objectToArray` turns a document into an array of `{ k, v }` pairs, a key and a value. It helps when you don't know the field names in advance and need to walk through them.

<Snippet id="reference/aggregation/expr-object/fn-object-to-array" twoslash />

For `null` or a missing document, the result is `null`.

### fn.getField [#fn.get-field]

`fn.getField` reads a document's field by name. It takes `{ field, input }`, where `field` is a constant string. Dots and the `$` sign in the name count as part of it, not as a path. That's why you need the operator for fields whose name can't be written as a path. If the document may be missing, the result type includes `undefined`.

<Snippet id="reference/aggregation/expr-object/fn-get-field" twoslash />

If the document has no such field, the result is a gap. The second order has no postal code, and the row has no `zip` key.

<Snippet id="reference/aggregation/expr-object/fn-get-field-2" twoslash />

## Change a document [#document-change]

These operators return a copy of the document. The pipeline only computes a result and writes nothing to the database.

### fn.setField [#fn.set-field]

`fn.setField` returns a copy of the document where the field `field` equals `value`. It takes `{ field, input, value }`. An existing field is replaced, and a new one is added.

<Snippet id="reference/aggregation/expr-object/fn-set-field" twoslash />

### fn.unsetField [#fn.unset-field]

`fn.unsetField` returns a copy of the document without the field `field`. It takes `{ field, input }`.

<Snippet id="reference/aggregation/expr-object/fn-unset-field" twoslash />

## Variables [#variables]

### fn.let [#fn.let]

`fn.let` introduces variables for one expression. It takes `vars`, an object of expressions, and an `in` callback that receives a proxy of the variables `v`, such as `v.tax` or `v.customer.name`. The value of the expression in `in` is the result.

<Snippet id="reference/aggregation/expr-object/fn-let" twoslash />

Here `tax` is 20 percent of `f.total`, and the result is `120 − 24 = 96`. In `in` you can use the variable as many times as you like without recomputing it.

Variables are visible only inside `in`. In the callback, a variable name is an ordinary property, not a string with `$$`. Typemo adds the `$$` prefix itself when it sends the query.

## When not to use it [#when-not-to-use]

- **You need to pick up a field by an ordinary path.** Write `f.shipTo.city`, without `fn.getField`. You need the operator only for names with dots and the `$` sign.
- **You need to change a document in the database, not in a query result.** Use [updates](../writes/writes.mdx).
- **You need to select the fields of a nested document as a whole.** Use the [`project`](./stages.mdx#project) stage with the path `"shipTo.city": 1`.
