This page collects the string operators of the `fn` catalog: case, length, concatenation, substrings, trimming, replacement, and regular expressions. They work inside pipeline stages such as [`project`](./stages.mdx#project) or [`addFields`](./stages.mdx#add-fields), and the server computes them for every row. You write one like this: `(f) => fn.toUpper(f.sku)`.

If you're starting out, read the guide [Calculations in aggregation](../../aggregation/expressions.mdx) first. This page is a reference. Expressions are written only with a callback, and Typemo doesn't accept a raw object with `$expr`.

All examples use the same shop order model.

<Snippet id="reference/aggregation/expr-arithmetic/intro" title="models/order.ts" twoslash />

The collection holds one order. Its `title` is `"  Blue Pen  "` (with spaces on both sides), `sku` is `"PEN-001"`, `price` is 19.99, `quantity` is 3, `delta` is -5, and `ratio` is 0.5. `placedAt` is March 15, 2026, 10:30:45.123 UTC, and `shippedAt` is March 18, 2026, 08:00 UTC. `stamp` is a timestamp with seconds 1700000000 and increment 5. `tags` is `["new", "sale", "pen"]`, `prices` is `[30, 10, 20]`, and `lines` has two rows (`pen`×2 and `ink`×1). The order has no `discount` field. The results in the `// →` comments come from running on this data.

## Case, length, and concatenation [#case-length-concat]

These are the basic operations on a string. The operators treat `null` differently. `toUpper`, `toLower`, and `substr*` turn `null` into an empty string, `concat`, `split`, and `trim*` return `null`, and `strLenCP` and `strLenBytes` fail on `null`, so you can't pass them an optional field.

One query computes all the operators of the group at once.

<Snippet id="reference/aggregation/expr-string/case-length-concat" twoslash />

Each operator is described separately below.

### fn.toUpper [#fn.to-upper]

Converts a string to upper case. `fn.toUpper(s)`.

`fn.toUpper(f.sku)` gives `"PEN-001"`.

### fn.toLower [#fn.to-lower]

Converts a string to lower case. `fn.toLower(s)`.

`fn.toLower(f.sku)` gives `"pen-001"`.

### fn.strLenCP [#fn.str-len-cp]

Counts the length in Unicode code points. `fn.strLenCP(s)`.

`fn.strLenCP(f.sku)` gives `7`.

### fn.strLenBytes [#fn.str-len-bytes]

Counts the length in UTF-8 bytes. `fn.strLenBytes(s)`.

`fn.strLenBytes(f.sku)` gives `7`.

### fn.concat [#fn.concat]

Joins two or more strings. `fn.concat(a, b, …)`.

`fn.concat(f.sku, "/", f.title)` gives `"PEN-001/  Blue Pen  "`.

### fn.split [#fn.split]

Splits a string by a delimiter into an array of strings. `fn.split(s, delimiter)`.

`fn.split(f.sku, "-")` gives `["PEN", "001"]`.

### fn.strcasecmp [#fn.strcasecmp]

Compares strings ignoring case and returns `-1`, `0`, or `1`. `fn.strcasecmp(a, b)`.

`fn.strcasecmp(f.sku, "pen-001")` gives `0`.

## Substrings and search [#substrings]

A substring is defined by a start and a length. The byte variants (`substrBytes`, `indexOfBytes`) count in UTF-8 bytes, so on multibyte characters they answer differently from the code point variants (`substrCP`, `indexOfCP`).

One query computes all the operators of the group at once.

<Snippet id="reference/aggregation/expr-string/substrings" twoslash />

Each operator is described separately below.

### fn.substrCP [#fn.substr-cp]

Takes a substring by code points. `fn.substrCP(s, start, length)`.

`fn.substrCP(f.sku, 0, 3)` gives `"PEN"`.

### fn.substrBytes [#fn.substr-bytes]

Takes a substring by bytes. `fn.substrBytes(s, start, length)`.

`fn.substrBytes(f.sku, 4, 3)` gives `"001"`.

### fn.substr [#fn.substr]

A deprecated name for `substrBytes`. In new code, use [`substrBytes`](#fn.substr-bytes) or [`substrCP`](#fn.substr-cp). `fn.substr(s, start, length)`.

`fn.substr(f.sku, 0, 3)` gives `"PEN"`.

### fn.indexOfCP [#fn.index-of-cp]

Searches for a substring and returns its position in code points, or `-1` if it isn't found. `fn.indexOfCP(s, needle, from?, to?)`.

`fn.indexOfCP(f.sku, "0")` gives `4`.

### fn.indexOfBytes [#fn.index-of-bytes]

Searches for a substring and returns its position in bytes, or `-1` if it isn't found. `fn.indexOfBytes(s, needle, from?, to?)`.

`fn.indexOfBytes(f.sku, "-")` gives `3`.

## Trim and replace [#trim-and-replace]

These operators take an object with an `input` field and other fields. Without `chars`, they trim whitespace characters.

One query computes all the operators of the group at once.

<Snippet id="reference/aggregation/expr-string/trim-and-replace" twoslash />

Each operator is described separately below.

### fn.trim [#fn.trim]

Removes characters from both ends. `fn.trim({ input, chars? })`.

`fn.trim({ input: f.title })` gives `"Blue Pen"`.

### fn.ltrim [#fn.ltrim]

Removes characters at the start. `fn.ltrim({ input, chars? })`.

`fn.ltrim({ input: f.title })` gives `"Blue Pen  "`.

### fn.rtrim [#fn.rtrim]

Removes characters at the end. `fn.rtrim({ input, chars? })`.

`fn.rtrim({ input: f.title })` gives `"  Blue Pen"`.

### fn.replaceOne [#fn.replace-one]

Replaces the first occurrence. `fn.replaceOne({ input, find, replacement })`.

`fn.replaceOne({ input: f.sku, find: "0", replacement: "9" })` gives `"PEN-901"`.

### fn.replaceAll [#fn.replace-all]

Replaces all occurrences. `fn.replaceAll({ input, find, replacement })`.

`fn.replaceAll({ input: f.sku, find: "0", replacement: "9" })` gives `"PEN-991"`.

## Regular expressions [#regex]

Three operators take an object `{ input, regex, options? }`. `regex` is a `RegExp` or a string, and `options` are flags such as `"i"`. The match index is counted in code points.

One query computes all the operators of the group at once.

<Snippet id="reference/aggregation/expr-string/regex" twoslash />

Each operator is described separately below.

### fn.regexMatch [#fn.regex-match]

Checks whether a string matches a pattern. `fn.regexMatch({ input, regex, options? })`.

`fn.regexMatch({ input: f.sku, regex: /^pen/, options: "i" })` gives `true`.

### fn.regexFind [#fn.regex-find]

Finds the first match and returns `{ match, idx, captures }`, or `null` if there's no match. `fn.regexFind({ input, regex, options? })`.

`fn.regexFind({ input: f.sku, regex: /[0-9]+/ })` gives `{match: "001", idx: 4, captures: []}`.

### fn.regexFindAll [#fn.regex-find-all]

Finds all matches in order. `fn.regexFindAll({ input, regex, options? })`.

`fn.regexFindAll({ input: f.sku, regex: "[A-Z]" })` gives `[{match: "P", idx: 0, captures: []}, {match: "E", idx: 1, captures: []}, {match: "N", idx: 2, captures: []}]`.

## Special cases [#special-cases]

Three operators accept `chars`. `fn.trim({ input: f.sku, chars: "PEN-" })` removes any of the listed characters from both ends and gives `"001"`. The characters are a set, not a substring, so the order in `chars` doesn't matter.

You can't compute the length of a missing field. `strLenCP` and `strLenBytes` reject an optional field at compile time.

## When not to use it [#when-not-to-use]

To search for a substring in a [`match`](./stages.mdx#match) filter, the filter's own `$regex` operator is enough. It uses indexes better than `fn.regexMatch`. For full-text search, there's the [`search`](./stages.mdx#search) stage.
