Expressions compute a new value from a document's fields right inside the pipeline. This page collects the ones that don't fit the other groups: bitwise operations, a random number, document metadata, and vector similarity. The second half of the page covers **system variables**, values the server keeps itself, such as the current time. In Typemo they live in the `Vars` class. The operators live on the `fn` object and are called in the `(f) => …` callback of stages such as [`project`](./stages.mdx#project) and [`addFields`](./stages.mdx#add-fields).

If you're starting out, read the guide [Calculations in aggregation](../../aggregation/expressions.mdx) first. This page is a reference.

All examples use one shop order model. It has a text index on the `note` field, which `fn.meta` needs.

<Snippet id="reference/aggregation/expr-misc/intro" title="shop/order.ts" twoslash />

Unless stated otherwise, the examples use `sort` by date, `limit(2)`, and `project`. They keep the first two orders. Alice's order for 120 is paid, with a discount of 10 and the note `gift`. Alice's order for 80 is paid, with no discount and no note. The rows come from the [`.plain()`](./pipeline.mdx#plain) method.

## Bitwise operations [#bitwise]

Bitwise operators take integers, either `number` (`int32`) or `bigint` (`int64`). If at least one argument is a `bigint`, the result is a `bigint` too, otherwise a `number`. If an argument may be `null`, so may the result. In a `.plain()` result, an `int64` arrives as a string. They need MongoDB 6.3 or later, as the operator descriptions in the code say.

### fn.bitAnd [#fn.bit-and]

`fn.bitAnd` computes the bitwise "and" of two or more numbers.

<Snippet id="reference/aggregation/expr-misc/fn-bit-and" twoslash />

The number 120 in binary is `1111000`, and 12 is `1100`. The shared ones give 8. With a `bigint`, the result becomes an `int64`.

<Snippet id="reference/aggregation/expr-misc/fn-bit-and-2" twoslash />

### fn.bitOr [#fn.bit-or]

`fn.bitOr` computes the bitwise "or".

<Snippet id="reference/aggregation/expr-misc/fn-bit-or" twoslash />

### fn.bitXor [#fn.bit-xor]

`fn.bitXor` computes the bitwise "exclusive or".

<Snippet id="reference/aggregation/expr-misc/fn-bit-xor" twoslash />

### fn.bitNot [#fn.bit-not]

`fn.bitNot` inverts all the bits of one number. For an integer `x`, the result is `-x - 1`.

<Snippet id="reference/aggregation/expr-misc/fn-bit-not" twoslash />

## Random number [#random]

### fn.rand [#fn.rand]

`fn.rand` returns a random number from 0 (inclusive) to 1 (exclusive). It takes no arguments, and the result is a `number`. The value is recomputed for every document, so the example checks only the range.

<Snippet id="reference/aggregation/expr-misc/fn-rand" twoslash />

## Metadata [#metadata]

### fn.meta [#fn.meta]

`fn.meta` returns internal document data that some stages fill in. It takes the name of the data, and that name determines the result type. For text search the name is `"textScore"`, the relevance score that `$text` fills in.

<Snippet id="reference/aggregation/expr-misc/fn-meta" twoslash />

The score exists only in a pipeline that starts with a [`match`](./stages.mdx#match) stage with `$text`. All the names are listed in the `MetaValues` type.

## Vector similarity [#vector-similarity]

A **vector** is a list of numbers, for example a text embedding. Three operators compute how similar two vectors are. Each takes two vectors (arrays of numbers or binary vectors) or an object `{ vectors: [a, b], score }`. With `score: true`, the result is mapped to the range from 0 to 1. If an argument may be `null` or missing, the result is `number | null`. They need MongoDB 8.3.

### fn.similarityCosine [#fn.similarity-cosine]

`fn.similarityCosine` computes cosine similarity, that is, the angle between vectors.

<Snippet id="reference/aggregation/expr-misc/fn-similarity-cosine" twoslash />

In the object form with `score: true`, the result is mapped to the range from 0 to 1.

<Snippet id="reference/aggregation/expr-misc/fn-similarity-cosine-2" twoslash />

### fn.similarityDotProduct [#fn.similarity-dot-product]

`fn.similarityDotProduct` computes the dot product. For the example it's `1·3 + 2·4 = 11`.

<Snippet id="reference/aggregation/expr-misc/fn-similarity-dot-product" twoslash />

### fn.similarityEuclidean [#fn.similarity-euclidean]

`fn.similarityEuclidean` computes the Euclidean distance. Between `[0, 0]` and `[3, 4]` it's 5.

<Snippet id="reference/aggregation/expr-misc/fn-similarity-euclidean" twoslash />

## Vars [#vars]

`Vars` is a class with static nodes for the MongoDB system variables. You write a variable as a class property, not as the string `"$$NOW"`. A bare string in an expression position would become a literal, and the server would return it as text. `$$ROOT` and `$$CURRENT` have no separate nodes. `$$ROOT` is the `f` proxy itself.

### Vars.NOW [#vars.now]

`Vars.NOW` is the current time, of type `Date`. There's one value for the whole pipeline, so every document sees the same moment.

<Snippet id="reference/aggregation/expr-misc/vars-now" twoslash />

The short form is `fn.now()`. It returns the same node.

<Snippet id="reference/aggregation/expr-misc/vars-now-2" twoslash />

### Vars.CLUSTER_TIME [#vars.cluster-time]

`Vars.CLUSTER_TIME` is the cluster time, of type `Timestamp`. It exists only on a replica set (several MongoDB servers holding copies of the same data, though a single server is enough) and on a sharded cluster.

<Snippet id="reference/aggregation/expr-misc/vars-cluster-time" twoslash />

### Vars.REMOVE [#vars.remove]

`Vars.REMOVE` removes the field it's assigned to. The key disappears from the result and, according to the description in the code, from its type. You usually put `Vars.REMOVE` in one of the branches of [`fn.cond`](./expr-logic.mdx#fn.cond).

<Snippet id="reference/aggregation/expr-misc/vars-remove" twoslash />

In the second order `total` is below 100, so the field is removed. To remove a field unconditionally, there's `fn.remove()`, which returns `Vars.REMOVE`.

<Snippet id="reference/aggregation/expr-misc/vars-remove-2" twoslash />

### Vars.USER_ROLES [#vars.user-roles]

`Vars.USER_ROLES` holds the current user's roles, an array of `UserRole[]`. Each role is an object with the fields `_id` (`"<database>.<user>"`), `role` (the role name), and `db` (the database where the role is defined). The `UserRole` type is exported from `@venloc/typemo`. On a server without authentication, the variable returns an empty array.

<Snippet id="reference/aggregation/expr-misc/vars-user-roles" twoslash />

### Vars.DESCEND [#vars.descend]

`Vars.DESCEND` is for the [`redact`](./stages.mdx#redact) stage. It keeps the fields of this level and checks the nested documents. The `RedactVerdict` type combines three verdicts: `"descend"`, `"prune"`, and `"keep"`. There's no example for it, and the reason is given after `Vars.KEEP`.

### Vars.PRUNE [#vars.prune]

`Vars.PRUNE` drops the whole document or nested document.

### Vars.KEEP [#vars.keep]

`Vars.KEEP` keeps this level and everything below it without checking.

The `redact` stage accepts only an expression that returns one of the three verdicts, most often through `fn.cond`. In the example, canceled orders are dropped and the rest are kept.

<Snippet id="reference/aggregation/expr-misc/vars-keep" twoslash />

There's no `DESCEND` verdict in the examples. Its description comes from the code and wasn't verified by running.

## When not to use it [#when-not-to-use]

- **You need an expression written in JavaScript.** Typemo has no `fn.function` operator (the server's `$function`), and calling it gives a compile error. Build the expression from the operators for [logic](./expr-logic.mdx), [arrays](./expr-array.mdx), and [strings](./expr-string.mdx). For details, see the section [JavaScript code](./accumulators.mdx#javascript-code).
- **You need a date or time.** See the [date operators](./expr-date.mdx). `Vars.NOW` gives only the current moment.
- **You need to pick documents at random.** Use the [`sample`](./stages.mdx#sample) stage, not `fn.rand` in a filter.
- **You need vector search by index.** Use the [`vectorSearch`](./stages.mdx#vector-search) stage, not a vector comparison in every document.
