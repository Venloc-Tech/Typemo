A **mask** replaces a field's value with a safe form. The address `alice@gmail.com` becomes `a***@gmail.com`, and a card number becomes `************4242`. You need a mask when a field must be shown, but not in full. A support agent needs to tell which card it is, and has no use for the full number. If you don't need the field at all, don't read it. For that there are [`.select`](./reading.mdx#select) and [`hidden`](../schemas/prop.mdx#hidden). This page describes the [`.mask`](#mask) method of a query and all the ready-made `Mask.*` masks.

If you're new to this, read the guide [Response masks](../../queries/response-masks.mdx) first. This page is the reference.

All the examples use one customer model. It has a required name and email, a phone that can be `null`, an optional age, an array of cards, and a dictionary of notes.

<Snippet id="queries/response-masks/prerequisites" title="models/customer.ts" twoslash />

The collection holds two customers. Alice has the email `alice@gmail.com`, the phone `+79161234567`, is 30 years old, has two cards (`4242 4242 4242 4242` with the holder `Alice A` and `5555 5555 5555 4444` without a holder), and a note `vip` with the value `yes`. Bob has the email `bob@example.org`, the phone `null`, is 17, and has no cards. The results in the `// →` comments are cut down to the fields that matter for the example.

## .mask [#mask]

`.mask` applies masks to the query result. You pass a "path → mask" object. The path names a field, nested ones go through a dot, array elements are walked automatically, and dictionary values go through `$*`. A mask is the string `"mask"` (the value becomes `"?"`), a function, or a ready-made `Mask.*` mask.

<Snippet id="reference/query/masks/mask" twoslash />

The mask is applied as the **last step**, after the read, the filling in of related documents, and the conversion to a `.lean()` or `.plain()` result. Hooks, events, and audit see the real data, and the mask touches only what the calling code receives. It doesn't change the source data, and the result is a copy.

<Returns type="MaskedQuery">

A terminal query that gives the result with masks after `await`. For `find` it's an array, for `findOne` a row or `null`. The result type takes the masks into account. A field with `"mask"` gets the type `"?"`, a field with a function gets the type of its result, and if the field can be `null`, `"?"` is added to the type. `MaskedQuery` has `exec`, `cursor` (for lists), and `expect`. There are no other builder methods, because the query is fixed before masking.

</Returns>

<Params>
<Param name="spec" type="object of path to mask" required>

The keys are paths of the result row. The compiler suggests them and checks that the path exists and that the function accepts the type of the value at that path. The values are `"mask"`, a function `(value) => …`, or an object with a `mask` method, like any `Mask.*` returns. If a value isn't a mask, you get a `QueryError` with the text `mask: "email" takes "mask" or a mask function`. An empty path gives a `QueryError` with the text `mask: an empty path`, and a path that isn't in the result row gives a `StrictModeError` (see the section [A path that isn't in the result](#path-not-in-result)).

The values `null` and `undefined` at a masked path always become `"?"`, and the function isn't called. So functions receive the value type without `null`.

</Param>
</Params>

### Nested values [#nested-values]

A path through an array walks every element, so `cards.number` masks the number of each card. Dictionary values are masked through `$*`. The dictionary key stays, and only the value is masked.

<Snippet id="reference/query/masks/nested-values" twoslash />

The second card has no holder, so the result has no `holder` field either. A missing field stays missing.

### A custom function [#custom-function]

Any function works instead of a ready-made mask. It receives the real value and returns what the calling code will see.

<Snippet id="reference/query/masks/custom-function" twoslash />

If the function throws, the query ends with a `QueryError` with the text `mask: the mask of "email" (model Customer) threw`. Quietly returning the real value instead of the mask would be a leak.

### Only for lean and plain [#lean-and-plain-only]

A document with a masked value could be saved by accident, and the database would end up with the mask instead of the data. So `.mask` works only on [`.lean()`](./reading.mdx#lean) and [`.plain()`](./reading.mdx#plain), and doesn't compile on a document. If the call comes from code without types, Typemo throws a `QueryError`.

<Snippet id="reference/query/masks/lean-and-plain-only" />

### A path that isn't in the result [#path-not-in-result]

A mask on a nonexistent path would mask nothing. A typo in `emial` would leave the real email in the response, and nobody would notice the leak. So the compiler rejects such a path, and if the mask object is built from data it can't see, Typemo checks the paths itself. A [`StrictModeError`](../errors/data-errors.mdx#strict-mode-error) is thrown right at the `.mask` call, before any query to the database.

<Snippet id="reference/query/masks/path-not-in-result" twoslash />

<Snippet id="queries/response-masks/troubleshooting-3" />

Nested paths (`cards.nope`) and `findOne` queries are checked the same way. But a mask protects only the result of one query, and it doesn't replace care. To hide a field entirely, use [`.select`](./reading.mdx#select).

### Cursor [#cursor]

`MaskedQuery` has `.cursor()` for lists. The mask is applied to each row as it's read. `findOne` has no cursor.

### When not to use it [#when-not-to-use]

If the client doesn't need the field at all, don't read it. [`.select`](./reading.mdx#select) with an exclusion, or [`hidden`](../schemas/prop.mdx#hidden) in the model, is more reliable than a mask, because the value never leaves the database. If a field must be masked **everywhere**, including logs and errors, set the `sensitive` option in the model with the same `Mask.*`. It also applies to events and error texts, while `.mask` applies only to the result of one query.

## The Mask presets [#mask-presets]

`Mask` is a set of ready-made masks. Each call, for example `Mask.email()`, returns a `{ mask }` object. It fits both `.mask` and the `sensitive` option. All masks share the same rules.

- A mask is typed by the value it accepts. `Mask.email()` won't compile on a numeric field.
- A mask never throws an error because of data. `null`, a value of the wrong type, or an unusable value gives `"?"`, because losing a detail is better than revealing the value.
- Only invalid factory arguments cause an error. It throws a `ConfigurationError` right when the factory is called, not on the first row of data.
- Strings are counted by code points, so emoji and surrogate pairs aren't cut in half.

There is no separate "hide" mask. The string `"mask"` in `.mask({ field: "mask" })` gives `"?"`.

### Invalid factory arguments [#invalid-factory-arguments]

The factory checks its arguments at once and throws a `ConfigurationError`, instead of an error on the first row of data.

<Snippet id="reference/query/masks/invalid-factory-arguments" />

### Mask types [#mask-types]

`MaskOf<T>` is the type of a ready-made mask for values `T`, an object with a `mask` method. `MaskChoice<T>` is a `Mask.when` branch, that is, `"show"`, `"mask"`, or `MaskOf<T>`. `MaskFunction<V>` and `MaskValue<V>` are the mask function and the value of a `.mask` entry. `MaskPaths`, `MaskSpecCheck`, `ApplyMask`, and `MaskResult` are the types the compiler uses to check paths and compute the result type. You usually don't write them by hand.

## SENSITIVE_MASK and SENSITIVE_HIDDEN [#sensitive-mask]

Two constants with the texts that stand in for values. `SENSITIVE_MASK` equals `"?"` and stands in for a masked value. `SENSITIVE_HIDDEN` equals `"[hidden]"` and stands in for a fully hidden value, together with the whole condition of the field. Code that reads masked data needs them to tell a mask from a real value, for example when parsing errors and events.
