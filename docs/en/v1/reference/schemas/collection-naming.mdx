If [`@Schema`](./schema.mdx#collection) has no collection name, Typemo lowercases the class name and pluralizes it by English rules. `User` becomes `users`, and `UserProfile` becomes `userprofiles`. The rules match Mongoose, apart from fixed bugs, so existing collections keep their names. The `CollectionNaming` class holds these rules and the name check. Use it to predict a collection name or to validate your own.

For examples and explanations, see the guide [Collection names](../../schemas/collection-names.mdx). This page is the reference.

---

## CollectionNaming.default [#collection-naming.default]

`default` is the naming function that runs when `collection` isn't set. It lowercases the class name and calls `pluralize`. The function has the type `(className: string) => string`. It's a function field rather than a class method because it gets passed as a callback and doesn't need `this`.

<Snippet id="reference/schemas/collection-naming/collection-naming-default" twoslash />

Uncountable words (`status`, `data`) stay as they are. Irregular forms (`people`, `mice`, `wives`) are handled. Compound names stay joined: `userprofiles`, not `user_profiles`.

<Returns type="string">

The collection name for a class name.

</Returns>

---

## CollectionNaming.pluralize [#collection-naming.pluralize]

`pluralize(word)` takes a singular word in lowercase and returns its plural. An uncountable word (`sheep`, `news`, `metadata`) and a word that matches no rule come back unchanged.

<Snippet id="reference/schemas/collection-naming/collection-naming-pluralize" twoslash />

<Params>
<Param name="word" type="string" required>

A singular word in lowercase.

</Param>
</Params>

A few cases differ from Mongoose. Words ending in `matrix` and `index` now come out right, so `indexa` no longer turns into `indicesa`. `data` and `metadata` are uncountable. `criterion` and `phenomenon` get their correct forms.

---

## CollectionNaming.check [#collection-naming.check]

`check(name, where)` validates a collection name and returns it. The name must be a non-empty string with no `$` and no null character, and it can't start with `system.`, because the server reserves such names. Typemo calls the check itself for the name from [`collection`](./schema.mdx#collection), and you can call it too.

<Snippet id="reference/schemas/collection-naming/collection-naming-check" twoslash />

<Params>
<Param name="name" type="unknown" required>

The name to check.

</Param>
<Param name="where" type="string" required>

What to put in the error text. Usually the class name.

</Param>
</Params>

An empty string or a value that isn't a string throws `ConfigurationError` with the text `User: the collection name must be a non-empty string`.

---

## When not to use it [#when-not-to-use]

The automatic name suits new collections. When you connect to an existing database, set `collection` explicitly, so renaming a class doesn't move your data. The rules are English-only and don't depend on the language of your class names. You can't plug in your own naming function, because there's no public option for it. To get a different rule, set `collection` explicitly in each class.
