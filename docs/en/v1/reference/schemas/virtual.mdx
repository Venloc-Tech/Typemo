`@Virtual` declares a **virtual reference**. It's a field that stores nothing in the database and gets filled with documents of another model when you ask `populate` to pull them in. An ordinary [`Ref`](./field-markers.mdx#ref) lives on the "child" document and points to the parent. A virtual reference goes the other way. An author has no list of posts, but `@Virtual` fetches the posts whose `author` field points to that author.

Getter values (`get fullName()`) that are computed from the document's fields don't need a decorator. For them there's the [`Computed`](./field-markers.mdx#computed) type. For a guide with examples, see [Add computed fields and reverse references](../../schemas/virtuals.mdx).

The examples use two models, a post and an author. The post has a reference to the author, and the author has a virtual reference to posts. The `// →` results come from a run against a real MongoDB. The author Ann has four posts (`a1` … `a4`, with `a3` unpublished, ranks 1–4), and Bob has two (`b1`, `b2`, both published).

---

## @Virtual [#virtual]

`@Virtual({ ref, localField, foreignField, … })` records the reference in the class description. You declare the field with the type [`VirtualRef<M, JustOne, Count>`](./field-markers.mdx#virtual-ref) and **no** `@Prop`. The `JustOne` and `Count` flags must match the `justOne` and `count` options, so that the result type after `populate` knows what arrives: an array, one document, or a number.

## ref [#ref]

`ref` is a function that returns the model whose documents are pulled in, for example `ref: () => Post`. That model is a class with [`@Schema`](./schema.mdx#schema). The function is needed because of the order in which classes are declared. The model must match the model in the field type `VirtualRef<Post>`, or the compiler reports `@Virtual "posts": "ref" points to another model than the field's VirtualRef<Model>`. If the function throws or returns something that isn't a schema, the build fails with `ConfigurationError` (`@Virtual "posts": "ref" must return a @Schema class`).

---

## localField [#local-field]

`localField` is the path of a field in **this** class whose value is looked up in the foreign field. Usually that's `"_id"`. The compiler checks that the path exists in the class (`@Virtual "posts": localField "nope" is not a field of this class`). At build time a violation throws `ConfigurationError` (`@Virtual "posts": localField "nope" is not a field of the class`).

---

## foreignField [#foreign-field]

`foreignField` is the path of a field in the **foreign** model that must equal `localField`. In the example it's the post's `author`. An unknown path is both a compile error (`@Virtual "posts": foreignField "nope" is not a field of the referenced class`) and a build error (`@Virtual "posts": foreignField "nope" is not a field of Post`).

---

## justOne [#just-one]

`justOne: true` pulls in one document instead of an array, and the field type is `VirtualRef<M, true>`. Use it for a one-to-one relation or when only the first document of the selection matters, say the latest post. Together with `options.sort` it picks the best one.

<Snippet id="reference/schemas/virtual/just-one" twoslash />

If the flag disagrees with the type, the compiler stops the code with `@Virtual "best": the field is VirtualRef<M, true>, add justOne: true` or `"justOne" differs from the field's VirtualRef<M, JustOne>`.

---

## count [#count]

`count: true` fills in the number of documents instead of the documents themselves, and the field type is `VirtualRef<M, false, true>`. Use it for counters when you don't need the documents.

<Snippet id="reference/schemas/virtual/count" twoslash />

The mismatch errors are `the field is VirtualRef<M, J, true>, add count: true` and `"count" differs from the field's VirtualRef<M, JustOne, Count>`.

---

## match [#match]

`match` is an extra filter on the foreign model's documents. The keys are paths of the foreign class or top-level operators starting with `$`. An unknown path is a compile error (`@Virtual "posts": match."x" is not a field of the referenced class`) and a build error (`match."x" is not a field of Post`).

<Snippet id="reference/schemas/virtual/match" twoslash />

## options [#options]

`options` sets the default sorting and paging limits of the populate query. The value is an object with three optional keys.

### options.sort [#options.sort]

The sort keys. `1` sorts ascending and `-1` descending.

### options.skip [#options.skip]

How many populated documents to skip.

### options.limit [#options.limit]

The maximum number of documents to return.

<Snippet id="reference/schemas/virtual/options-limit" twoslash />

`sort`, `limit`, and `skip` apply to each source document separately, not to the whole populate query. With several authors, `limit: 2` gives **each** of them two posts: `a4` and `a3` for Ann, `b2` and `b1` for Bob. In Mongoose, `limit` was shared across all authors at once. Typemo doesn't do that. The separate `perDocumentLimit` option sets the same per-author bound.

---

## perDocumentLimit [#per-document-limit]

`perDocumentLimit` caps the number of populated documents for each source document. Populating runs as a single `$lookup` query with `$limit`. For a "latest post of each author" selection, combine it with `options.sort`. In Typemo `options.limit` also counts per document, so both options give the same per-author bound. `perDocumentLimit` helps when you're carrying a definition over from Mongoose.

<Snippet id="reference/schemas/virtual/per-document-limit" twoslash />

## Sync and build errors [#sync-and-build-errors]

The build also checks what the compiler can't see. A virtual field with the same name as a `@Prop` field throws `ConfigurationError` (`@Virtual "posts" is also a @Prop field`). A field without the `VirtualRef` type is a compile error: `@Virtual "posts": declare the field as VirtualRef<Model, JustOne, Count>`.

<Snippet id="reference/schemas/virtual/sync-and-build-errors" twoslash />

## When not to use it [#when-not-to-use]

If the value is computed from the document's own fields, you need a getter with the [`Computed`](./field-markers.mdx#computed) or [`VirtualValue`](./field-markers.mdx#virtual-value) type, not `@Virtual`. If a child document needs the parent's identifier, use [`Ref`](./field-markers.mdx#ref) with the [`ref`](./prop.mdx#ref) option on a real field.
