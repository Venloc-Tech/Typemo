A normal document gets an `_id` of type `ObjectId`, and MongoDB creates it itself. But often the identifier comes from outside: an ISO country code, a product SKU, a session `UUID` from another system, a counter number. For such models, use [`EntityWithId`](../reference/schemas/base-classes.mdx#entity-with-id) instead of [`Entity`](../reference/schemas/base-classes.mdx#entity). It's a base class where you choose the `_id` type. From there the type spreads through your code on its own. `findById` takes a string, a reference to the model stores a string, and `populate` finds the document by a string.

If base classes are new to you, start with [Define a model](./define-model.mdx). It explains what `Entity` is and where a model's `_id` comes from.

## What you need [#prerequisites]

The client from [Connect to the database](../connection/connect.mdx). The examples build a catalog of countries and cities, and each new model appears in the section where it's needed.

## Quick start [#quick-start]

Pass `EntityWithId` an arrow with the `_id` type, as in [`@Prop`](../reference/schemas/prop.mdx#prop). Without `default` the identifier is required. With `default` it's optional and created for you.

<Snippet id="schemas/custom-ids/quick-start" title="countries/country.ts" twoslash />

Below we'll go through each option with real tasks: how to create such documents, how to reference them, how to write aggregation results into them, and how to move over from the old approach.

## A string identifier from the outside world [#string-id]

A country catalog has a natural key, the ISO code. People look countries up by it and reference them by it, so there's no reason to invent a second identifier. Without `default` the identifier is required, so `create` accepts a document only with an `_id`, and `findById` searches by a string. Let's add Italy to France from the quick start.

<Snippet id="schemas/custom-ids/string-id" title="countries/countries.service.ts" twoslash />

The identifier is stored exactly as you passed it. A second `create` with the same `_id` throws a [`DuplicateKeyError`](../reference/errors/server-errors.mdx#duplicate-key-error), because the server doesn't allow two documents with one `_id`. Without an identifier the document isn't created. The compiler stops the call, and in untyped code you get a `ValidationError`.

<Snippet id="schemas/custom-ids/string-id-2" title="countries/countries.service.ts" twoslash />

A value of the wrong type won't pass casting. `Countries.create({ _id: 5, name: "x" })` gives a `CastError` (`Cast to string failed at path "_id" for 5 (number): expected a string [type]`), and `Countries.findById(5)` gives the same `CastError`. An empty string, though, is a perfectly valid identifier, so filter out an empty country code yourself.

## Generate the identifier on create [#generate-id]

Sometimes the identifier doesn't come from outside, but `ObjectId` won't do either. Say a session identifier must not be predictable, or documents get merged from several databases. Then add `default`, a function that creates the value. `_id` becomes optional. One you pass is kept, and a missing one is created by the function.

<Snippet id="schemas/custom-ids/generate-id" title="sessions/session.ts" twoslash />

Notice two things. The [`Timestamped`](../reference/schemas/base-classes.mdx#timestamped) and [`Versioned`](../reference/schemas/base-classes.mdx#versioned) mixins wrap `EntityWithId` the same way they wrap `Entity`, and the order doesn't matter. And a `UUID` in the database is a binary value of subtype 4. `findById` accepts both the `UUID` itself and its hex string. In `.plain()` and `.lean()` results and in JSON, the identifier is a string like `4d86ba33-df2d-49dd-9f01-8191006a98ed` that you can hand to the client.

<Snippet id="schemas/custom-ids/generate-id-2" title="sessions/sessions.service.ts" twoslash />

A string identifier with your own function works the same way: `EntityWithId(() => String, { default: () => crypto.randomUUID() })`.

## A numeric identifier [#numeric-id]

A counter or a number from another system is a number. `Number` is stored as a MongoDB number, `Types.Int32` as a 32-bit integer, and `BigInt` as a 64-bit one.

<Snippet id="schemas/custom-ids/numeric-id" title="counters/counters.service.ts" twoslash />

Cursor-based paged reading ([`keysetPage`](../reference/query/keyset.mdx#model.keyset-page)) adds `_id` to the end of the sort on its own. So rows with the same value come in a predictable order with a numeric identifier too.

<Snippet id="schemas/custom-ids/numeric-id-2" title="counters/counters.service.ts" twoslash />

The sort field `hits` is declared required. A missing value can't be a position in the cursor.

## Reference such a model [#ref-to-model]

A reference field stores the target model's identifier, so its type goes in as the second parameter of [`Ref`](../reference/schemas/field-markers.mdx#ref), for example `Ref<Country, string>`. The first argument of `@Prop` is the type of the field itself, that is, the identifier type. For an array of references to sessions, it's `[Types.UUID]`. France from the quick start is already in the catalog.

<Snippet id="schemas/custom-ids/ref-to-model" title="cities/city.ts" twoslash />

[`populate`](../reference/populate/populate.mdx#populate) finds a document by a string or a `UUID` the same way it does by an `ObjectId`. Instead of an identifier, you can also pass the document itself, and the reference field stores its `_id`: `Cities.create({ name: "Lyon", country: france })`.

## Write an aggregation result into such a collection [#write-aggregation-result]

Aggregation results often go into a separate collection: a summary by country, a daily report. Let's add Lyon and Berlin to Paris from the previous section. After grouping, `_id` becomes a string, the group key. So the target of `$out` or `$merge` must be a model with a string `_id`, and `EntityWithId(() => String)` fits right in. The compiler checks the pipeline's rows against the target's fields, and the string `_id` matches by type.

<Snippet id="schemas/custom-ids/write-aggregation-result" title="cities/totals.ts" twoslash />

The [`merge`](../reference/aggregation/stages.mdx#merge) stage works the same way, except it adds to what's already in the target. If such a target used to be a plain class with `_id!: string`, replace it with `EntityWithId`. The class gets an immutable `_id` and the identifier type in every operation.

## The identifier can't change [#id-immutable]

`_id` on `EntityWithId` is immutable, as it is on `Entity`. An update that writes it won't compile, and in untyped code it throws a [`StrictModeError`](../reference/errors/data-errors.mdx#strict-mode-error) with the reason `immutable`. You can replace a whole document only without an `_id` too.

<Snippet id="schemas/custom-ids/id-immutable" title="countries/countries.service.ts" twoslash />

So you can't fix a wrong country code with an update. Create a document with the correct `_id` and delete the old one.

## How it used to be done [#before]

Before, an identifier of another type was declared by hand in a plain class, with no base class.

<Snippet id="schemas/custom-ids/before" title="countries/country.ts" twoslash />

Such a class still builds, but its `_id` is an ordinary required field, and that has consequences.

- Typemo doesn't protect it from changes. An attempt to write `_id` reaches the server, and the server answers, not the library.
- `Timestamped` and `Versioned` don't pick up the identifier type.
- You can't set a `default`.

Moving over is straightforward. Replace `class Country` with `class Country extends EntityWithId(() => String)` and remove the `_id` declaration. If you keep both, an `_id` declaration with a different type gives a `ConfigurationError` (`Country._id: redeclared with another type (number in Country, string in Identified)`).

## How to choose [#how-to-choose]

Ask yourself: **where does the identifier come from?**

- **Your database creates it, and nobody outside sets it**: keep `Entity`. An `ObjectId` is short, grows over time, and needs no setup.
- **It comes from outside** (a country code, a SKU, a number from another system): use `EntityWithId` without `default`. The database shouldn't make up what belongs to the outside world.
- **You create it, but it must be unpredictable or unique across databases**: `EntityWithId` with `default`, that is, a `UUID` or a string with your own generator.

## When not to use it [#when-not-to-use]

Most models are fine with `Entity`. You don't need your own `_id` type for a "nice" string in an API response. `ObjectId` has `toHexString()`, and [`plain`](../reference/query/reading.mdx#plain) and JSON already return it as a string. You don't need it for a unique field you like to search by either. Add an ordinary field with `unique: true` ([Indexes](./indexes.mdx)) and leave `_id` to the database. `EntityWithId` doesn't support a compound key, that is, an `_id` object made of several fields. Only scalar types are allowed.

## Troubleshooting [#troubleshooting]

**A document isn't created without an identifier.** Without `default` the identifier is required, and `Countries.create({ name: "x" })` won't compile: the compiler says `_id` is missing. At runtime the same call throws `ValidationError: Validation failed: "_id": the field is required [required]`. Pass `_id` or add `default`.

**An identifier of the wrong type.** A number in a model with a string `_id` gives `CastError: Cast to string failed at path "_id" for 5 (number): expected a string [type]`. Convert the value beforehand or change the identifier type.

**The factory got the type itself instead of an arrow.** `EntityWithId(String)` passes the argument check, since `String` is a function too. But building the schema rejects it: `Country._id: the type thunk returned string, expected a type`. Write `EntityWithId(() => String)`.

<Callout type="migration">

In Mongoose you set the `_id` type as a schema field, `_id: String` or `_id: { type: String }`, and its default value with `default`. Typemo has the `EntityWithId` base class for this. The type flows into `IdOf`, `findById`, references, and `populate`, and the library enforces that `_id` is immutable.
