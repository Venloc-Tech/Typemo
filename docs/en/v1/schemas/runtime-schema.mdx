The schema is described by a class, but sometimes you need it as data: to generate field documentation, take a snapshot for a test, write a driver query with the real field names, or find out which fields are hidden. For that every model has a `schema` property, a [`SchemaInfo`](../reference/schemas/schema-info.mdx) description that's **read-only**. You can't change the schema. Once the model is built it's frozen, and everyone who reads it sees the same thing.

## What you need [#prerequisites]

The client from [Connect to the database](../connection/connect.mdx) and the user model from `users/user.ts`. The email is stored in the database under the name `e`, and there's a hidden field, a nested address, and an array of tags.

## Quick start [#quick-start]

The class and collection names sit right on `schema`, and [`describe()`](../reference/schemas/schema-info.mdx#describe) returns the full description.

<Snippet id="schemas/runtime-schema/quick-start" title="users/user.ts" twoslash />

Below we'll look at what this is used for.

## Read paths and their properties [#read-paths]

`describe()` returns a plain object. You can print it, compare it with a snapshot, and walk through it. In `paths` each path is written as in code (`address.city`, `tags.$` for an array element). It has the node kind, the type, the database name (if it's different), and flags.

<Snippet id="schemas/runtime-schema/read-paths" title="users/inspect.ts" twoslash />

The flags come as a comma-separated string: `required`, `nullable`, `default`, `immutable`, `hidden`, and service flags like `service:id`. With them you can build a list of, say, the hidden fields that must not appear in the API docs.

<Snippet id="schemas/runtime-schema/read-paths-2" title="users/inspect.ts" twoslash />

Besides paths, the description has `indexes` (keys and options), `searchIndexes` (Atlas Search indexes from `@SearchIndex`), `virtuals`, `hooks`, `discriminator` and `discriminators` for hierarchies, and `ext`.

## Turn a path into the database name [#to-db-path]

In a driver query, fields need their database names, not their names in code. Here `email` is stored as `e`, and `address.city` as `address.c`. [`toDbPath`](../reference/schemas/schema-info.mdx#to-db-path) translates the path at every level and keeps array positions. For a path that isn't in the schema it returns `undefined` instead of throwing. So catch typos by checking the result.

<Snippet id="schemas/runtime-schema/to-db-path" title="users/raw-query.ts" twoslash />

## Read extension options [#read-extension-options]

Extensions keep their settings right in the schema, in `@Schema({ ext })` and `@Prop({ ext })`. [`schema.ext`](../reference/schemas/schema-info.mdx#ext) returns the schema's settings, and [`schema.extOf(path)`](../reference/schemas/schema-info.mdx#ext-of) returns a field's settings for the given path. For a field without `ext` it's an empty object, and for a path that doesn't exist it's `undefined`. That's how integrations find out that their mode is on for a field. [Add your own field and schema options](../extensions/custom-options.mdx) explains how extensions declare options.

<Snippet id="schemas/runtime-schema/read-extension-options" title="users/inspect.ts" twoslash />

## How to choose [#how-to-choose]

Ask yourself: **do you need the schema as data or as types?**

- **As types**: the compiler gives you those, `Lean<User>` and `Plain<User>`.
- **As data at runtime**: a database name, a flag, an index. Read `schema`.
- **To check values against the schema**: use [`StandardSchema`](./json-and-standard-schema.mdx), not a parse of `describe()`.

## When not to use it [#when-not-to-use]

`schema` is read-only. You can't change fields, indexes, or options at runtime. Don't parse `describe()` to check data, since there are ready-made tools for that. The description format is meant for snapshots and diagnostics, not for reliable parsing in business logic.

## Troubleshooting [#troubleshooting]

**`toDbPath` returned `undefined`.** The schema has no such path, most likely because of a typo. Compare the name with `Object.keys(Users.schema.describe().paths)`.

**Search indexes are missing from `indexes`.** `describe().indexes` lists only regular indexes. [`@SearchIndex`](../reference/schemas/index-decorators.mdx#search-index) indexes are in a separate `searchIndexes` field, which holds their declarations from the schema, the name, and the definition. To see their state on the server, use the model methods from [Define and sync search indexes](../collections/search-indexes.mdx).
