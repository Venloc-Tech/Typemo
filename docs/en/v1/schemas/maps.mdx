A dictionary (**Map**) is for when you don't know the set of keys in advance: a product's price in each currency, grades by subject, settings by name. In a schema you declare it with [`Spec.map`](../reference/schemas/types-and-spec.mdx#spec.map). The keys are always strings, and you choose the value type. In the database the dictionary is an ordinary embedded document (`{ USD: 10, EUR: 9 }`), and in a loaded document it's a `Map<string, V>`.

The main difference from a nested object is that a dictionary's keys are data, not schema field names. So Typemo checks the keys themselves. MongoDB reads a dot in a name as a path and a leading `$` as an operator, and you could never find or update such a key afterwards. The library rejects them right away.

## What you need [#prerequisites]

A model described as in [Define a model](./define-model.mdx). The examples build a product card with prices in several currencies.

## Quick start [#quick-start]

Declare the field with `Spec.map` and pass the value as a plain object.

<Snippet id="schemas/maps/quick-start" title="shop/product.ts" twoslash />

You can pass a `Map` too. In a loaded document the field is a strictly typed map with the `set`, `delete`, and `clear` methods. Below we'll cover keys, values, and queries.

## Allowed keys [#allowed-keys]

A key is a non-empty string with no dot, no leading `$`, and not `__proto__`. Each rule has its reason.

- An empty key can't be written into a path.
- A dot would turn the key into a nested path.
- MongoDB would take a leading `$` for an operator.
- In JavaScript `__proto__` changes the object's prototype and opens the way to property spoofing.

<Snippet id="schemas/maps/allowed-keys" twoslash />

If keys come from users, such as a setting's name, check or normalize them before writing. A key with a dot won't pass anyway, and it's better to find out early than to have `create` return the error to the client.

## Check the values [#validate-values]

Values are cast to the type from `Spec.map`, and the error path includes the key. A `null` value is forbidden until you allow it with the `nullable` option. `Spec.map(Number, { nullable: true })` gives a `Map<string, number | null>`.

<Snippet id="schemas/maps/validate-values" twoslash />

A value can also be a class with a schema. `Spec.map(Line)` stores a dictionary of subdocuments, and all the subdocument's rules (required fields, `min`) apply to each value.

## Query and update by key [#by-key]

A dictionary key works as a path. `"prices.EUR"` in a filter finds products with a price in euros, and in `$set` it changes one value without touching the others. The value type is checked the same way as in the field itself.

<Snippet id="schemas/maps/by-key" twoslash />

## Read the dictionary in different forms [#read-map-forms]

What you get depends on how you read.

- A loaded document gives you a `Map` that checks keys and values.
- [`.plain()`](../reference/query/reading.mdx#plain) and [`$toPlain()`](../reference/documents/document-api.mdx#to-plain) keep the `Map`.
- [`$toJSON()`](../reference/documents/document-api.mdx#to-json) turns it into a plain object, because JSON doesn't know `Map`.
- [`.lean()`](../reference/query/reading.mdx#lean) returns what's in the database, that is, a plain object.

<Snippet id="schemas/maps/read-map-forms" twoslash />

## How to choose [#how-to-choose]

Ask yourself: **do you know all the keys in advance?**

- **Yes** (a city and a street, a first and last name): describe a nested object. Its fields show up in hints and are checked one by one (see [Define nested objects and subdocuments](./nested-and-subdocuments.mdx)).
- **No, the keys come in as data** (currencies, languages, setting names): `Spec.map`.
- **You need a list of pairs where keys can repeat**: an [array](./arrays.mdx) of subdocuments with `key` and `value` fields.

## When not to use it [#when-not-to-use]

You can't index a dictionary's values by key ahead of time, because the set of paths is unknown. If you need fast lookups by value, store the pairs as an array of subdocuments and build an index on their fields. And a JavaScript `Map` doesn't work directly as a field type. `@Prop(() => Map)` isn't supported, which is what `Spec.map` is for.

## Troubleshooting [#troubleshooting]

**A key with a dot in its name.** Data like `{ "v1.2": 5 }` isn't written: `a key cannot contain "."`. MongoDB reads a dot as a path, and you'd never find such a field. Replace the dot in the key with another character.

**A `null` value.** `Spec.map(Number)` doesn't accept `null`: `Cast to number failed at path "prices.a" for null: null is not allowed on a path that is not nullable [null]`. Allow it with the `nullable: true` option, or don't pass the key.
