The history of changes starts here. Typemo wasn't released before the first version, so there's nothing to compare with yet. From now on each version gets its own section: what was added, what changed, and what's incompatible with the previous one. For now the page works as an overview. It shows what the first version consists of and leads to the sections where each area is covered in detail.

The package version in the repository is still `0.0.0`, and the docs are written for the `v1` line. Which server, driver, and runtime versions the first version was tested on is in [Version compatibility](./versions.mdx).

## Version 1 [#version-1]

Typemo is an ODM for MongoDB in TypeScript, written from scratch. Its types are inferred from the implementation, not glued on top of someone else's runtime. It talks to the database through the official `mongodb` driver, and strictness is always on, in full. Where this idea comes from and what follows from it is explained in [What is Typemo](../concepts/what-is-typemo.mdx) and [Strictness](../concepts/strictness.mdx).

### Schemas and models [#schemas-and-models]

A schema is a class with the `@Schema` and `@Prop` decorators, and the types of the model and of query results come from that class. All BSON types are supported, as are required fields and `null` as separate states, default values, and validation. There are nested objects and subdocuments, arrays, `Map`, references, virtual fields, and discriminators. Also hidden, sensitive, and immutable fields, timestamps, and versions. Details are in the [Schemas and models](../schemas/index.mdx) section.

### Reading [#reads]

Both the compiler and Typemo at runtime check filters. A result comes in three forms: a document, the `.lean()` result, and the `.plain()` result, and a projection changes the response type. There's sorting and paging, keyset pagination, a cursor for large results, response shape contracts, masks, full-text, vector, and geo search, and `explain`. Details are in the [Reading](../queries/index.mdx) section.

### Writing [#writes]

Creating, updating with every operator, replacing, deleting, bulk writes, and pipeline updates. Value types are strict. You can pass `ObjectId` and UUID as strings too, and int64 as a decimal string. An empty filter in a write is forbidden. Details are in the [Writing](../writes/index.mdx) section.

### Documents [#documents]

A document tracks its changes and saves only what changed, and a version protects it from losing concurrent edits. Its arrays, subdocuments, and `Map` are its own strictly typed collections. Details are in the [Documents](../documents/index.mdx) section.

### Related data and aggregation [#populate-and-aggregation]

Populate changes the field's type along with its value, and the compiler checks nested and polymorphic forms. The aggregation pipeline knows the result type after every stage. There are expressions, accumulators, window functions, search, and saving the result. Details are in the [Related data](../populate/index.mdx) and [Aggregation](../aggregation/index.mdx) sections.

### Transactions, hooks, and extensions [#transactions-hooks-extensions]

Transactions with automatic retry, and manual sessions. Operation and document hooks, plugins, and extensions with their own field and schema options. Details are in the [Transactions](../transactions/index.mdx), [Hooks and plugins](../hooks/index.mdx), and [Extensions](../extensions/index.mdx) sections.

### Data policies [#data-policies]

These are rules you can't turn off for a single query: multi-tenancy, soft delete, untrusted input, strict paths, result limits, and audit. Details are in the [Data policies](../policies/index.mdx) section.

### Collections and indexes [#collections-and-indexes]

Explicit collection creation and index sync, including search indexes. Special collections, and typed and materialized views. Details are in the [Collections and indexes](../collections/index.mdx) section.

### Change streams [#change-streams]

A typed stream of events for a model and a pipeline that resumes after a disconnect. Details are in the [Change streams](../change-streams/index.mdx) section.

### Errors and observability [#errors-and-observability]

Typemo's own error hierarchy. The original cause is in `cause`, with sensitive data masked. Operation events for monitoring, and separate integration packages for OpenTelemetry and Sentry. Details are in the [Errors](../errors/index.mdx) and [Observability](../observability/index.mdx) sections.

### Testing and decorators [#testing-and-decorators]

Helpers for testing your app in `@venloc/typemo/testing`: data factories and checking index usage. A separate `@venloc/typemo-decorators` package for TC39 decorators. Details are in the [Testing](../testing/index.mdx) and [TC39 decorators](../decorators-tc39/index.mdx) sections.

### Migrating from Mongoose [#migration]

Guides to gradual migration, a list of deliberate behavior differences, a list of what Typemo doesn't have, and an API mapping table. Details are in the [Migrating from Mongoose](../migration/index.mdx) section.
