Typemo is built for the latest versions of everything it relies on and doesn't support older ones. Code needed only for outdated versions wasn't carried over. So there's no long "what works with what" table here. There are the versions Typemo **is tested on**, and an honest list of what wasn't tested.

The versions come from `VERSIONS.md` in the repository (checked on September 26, 2026) and from the packages' `package.json` files. The server, the driver, and `bson` were also confirmed by running them. The test server answered `buildInfo` with version `9.0.0-rc0`, and `node_modules` holds `mongodb` `7.6.0` and `bson` `7.3.3`.

## What's tested [#verified]

For each component, the version the tests run on and what the dependencies declare.

| Component | Tested | In dependencies |
|---|---|---|
| MongoDB | `9.0.0-rc0` (upcoming) and `8.3.11` (stable) | — |
| The `mongodb` driver | `7.6.0` | peer dependency `^7.6.0` |
| `bson` | `7.3.3` | peer dependency `^7.3.3` |
| Bun | `1.4.0` | — |
| TypeScript | `6.0.3` | — |
| `reflect-metadata` | `0.2.2` | a dependency of the core |
| Node.js | `24.14.0`, only a smoke test of the built package | — |

The `@venloc/typemo` package itself is at version `0.0.0` for now, and the `VERSION` constant returns the same. The `@venloc/typemo-decorators`, `@venloc/typemo-opentelemetry`, and `@venloc/typemo-sentry` packages are built in the same repository and depend on the core of the same version.

## The MongoDB server [#mongodb-server]

The tests run on a real server that `mongodb-memory-server` starts. It's always a single-node replica set. A replica set is several MongoDB servers holding copies of the same data, and without one, transactions, change streams, and audit don't work.

By default the **upcoming** branch is used, currently `9.0.0-rc0`. That way Typemo sees server changes before they reach a stable release. The second branch is **stable**, currently `8.3.11`, and the `TYPEMO_MONGO=stable` environment variable turns it on. If the upcoming server doesn't start on a platform, the test harness says so in the console and runs stable. It doesn't swap anything silently.

Here's what that means for you. The behavior in the docs is tested on `8.3` and `9.0` servers. Older servers weren't tested at all, and there's no defined lower bound of compatibility. On versions older than `8.x`, don't count on the examples working the same way. Some features exist only on certain servers, for example search indexes and vector search, and depend on whether you have them turned on. They're covered in [Define and sync search indexes](../collections/search-indexes.mdx) and [Full-text and vector search](../queries/text-and-vector-search.mdx).

Transactions and change streams need a replica set. The [Transactions](../transactions/transactions.mdx) guide shows how to check for one in advance.

## The driver and bson [#driver-and-bson]

Typemo doesn't talk to the server itself. All of the transport is the official `mongodb` driver. The driver and `bson` are declared in the core's `peerDependencies`: `mongodb` `^7.6.0` and `bson` `^7.3.3`. You install them yourself, and they're shared between you and Typemo. So `ObjectId` and the other BSON values from your code are the same classes Typemo uses, not copies from another package.

The tests run on `mongodb` `7.6.0` and `bson` `7.3.3`. Earlier major versions of the driver aren't supported and weren't tested.

[Installation and setup](../getting-started/installation.mdx) explains how to install the packages and pick versions.

## Runtime [#runtime]

The repository, the tests, and the docs examples run on **Bun** `1.4.0`. Both the tests on a real database and the example checks run on it. There are no other environments where Typemo was tested in full.

**On Node.js only a smoke test has been run.** The packages ship built, as `.js` and `.d.ts` files in `dist`. The built package is tested in a separate consumer project. First it's compiled with an ordinary `tsconfig`, then a short script on Node.js `24.14.0` with a real MongoDB creates and reads documents, updates them, populates references, runs an aggregation and a transaction, and catches Typemo errors. That script passes.

All other tests and all docs examples ran on Bun. Of the built-in modules, the core uses only `node:async_hooks` and `node:crypto`, but there's no `engines` field with a version in `package.json`. If you run your app on Node.js, run your own tests on it.

## TypeScript [#typescript]

The compiler version is pinned exactly, `6.0.3` without `^`. By the time of the check, the seventh major version (`7.0.2`) was already out on npm, but Typemo and the docs **weren't tested** on it. Moving to it is a separate decision.

Typemo's types put load on the compiler, so they have a budget. Take a dense test project where users, posts, and comments are linked to each other. On it there must be no more than a million type instantiations, and the check time over an empty project must be no more than half a second. A repository script checks the budget, and growth of more than 15% in a single change counts as a regression.

Of the `tsconfig` settings, the core with legacy decorators needs only `experimentalDecorators`, and the TC39 decorator package doesn't need it. More in [Installation and setup](../getting-started/installation.mdx) and on the [Use TC39 decorators](../decorators-tc39/tc39.mdx) page.

## Integrations [#integrations]

Only the integration packages pull in vendor libraries, and the core has none. `@venloc/typemo-opentelemetry` expects `@opentelemetry/api` at `^1.9.1` and was tested on `1.9.1`. `@venloc/typemo-sentry` expects `@sentry/core` at `^11.1.0` and was tested on `11.1.0`. Details are in the [Observability](../observability/index.mdx) section.

## What isn't tested [#not-verified]

To leave no room for guesses, here's everything untested in one place.

- Node.js beyond the smoke test above, and any other Node.js versions.
- MongoDB servers older than `8.x`.
- Other major versions of the `mongodb` driver and `bson`.
- TypeScript `7` and versions newer than `6.0.3`.
- Other platforms. The tests ran on macOS on Apple Silicon.
- The behavior of the `9.0.0-rc0` server. It's a release candidate, and the server may still change before the stable `9.0`.
