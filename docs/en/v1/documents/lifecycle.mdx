A document in Typemo is in one of four states.

- **New**: created in memory, not in the database yet.
- **Loaded**: matches what's in the database.
- **Modified**: has edits in memory that the database doesn't have.
- **Deleted**: its record has been removed from the database.

The state decides what [`$save`](../reference/documents/document-api.mdx#save) does. It inserts the document, updates it, sends nothing, or refuses to work. Once you know the states, it's easy to see why `$save` on a new document inserts, `$save` on a read document sends a short update, and a deleted document can't be saved. You can check the state right in code with [`$isNew`](../reference/documents/document-api.mdx#is-new) and [`$isModified`](../reference/documents/document-api.mdx#is-modified).

## Create a new document [#create-document]

[`Model.new`](../reference/documents/model-document-methods.mdx#model.new) creates a document in memory. The defaults are already filled in, `_id` is assigned, and every field is cast to its type. The document isn't in the database yet.

Types are cast right away, so a wrong type or an unknown key gives a [`CastError`](../reference/errors/data-errors.mdx#cast-error) on the `new` call itself. Required fields and rules are checked later, on [`$save`](../reference/documents/document-api.mdx#save) or [`$validate`](../reference/documents/document-api.mdx#validate).

<Snippet id="documents/lifecycle/create-document" twoslash />

A new document has no `__v` version field yet. The insert sets it. If you need a saved document right away, use [`create`](../reference/writes/writes.mdx#create). It does the same in one line.

## Read an existing document [#read-existing-document]

Everything you read with queries without [`.lean()`](../reference/query/reading.mdx#lean) and [`.plain()`](../reference/query/reading.mdx#plain) arrives loaded. `$isNew()` is `false`, and there are no changes. The document remembers its original state and compares itself with it on every change check.

<Snippet id="documents/lifecycle/read-existing-document" twoslash />

## Change and save [#change-and-save]

Any change makes a document modified, and a successful [`$save`](../reference/documents/document-api.mdx#save) makes it loaded again. If you set a value back to what it was, the document is no longer modified. Typemo compares values instead of remembering assignments. The details are in [Change and save a document](./change-and-save.mdx).

## Turn data read outside Typemo into a document [#hydrate-external]

Data can come from a cache, a message queue, or straight from the driver. [`Model.hydrate`](../reference/documents/model-document-methods.mdx#model.hydrate) turns such an object into a loaded document with typed collections. The method trusts that the data is exactly what's in the database. It doesn't cast or validate it, and it takes the field names as they're stored in the database.

<Snippet id="documents/lifecycle/hydrate-external" twoslash />

The tags array here is a [`StrictArray`](../reference/documents/typed-collections.mdx#strict-array). `constructor.name` gives the public type of the collection, so the class name shows that the array is typed and not a plain `Array`. An array of subdocuments is called `SubdocumentArray`, and a `Map` is `TypedMap`.

If there's no document with that `_id` in the database, `hydrate` still creates one. But `$save` won't find the record and throws a [`DocumentNotFoundError`](../reference/errors/query-errors.mdx#document-not-found-error).

<Snippet id="documents/lifecycle/hydrate-external-2" />

## Delete a document [#delete-document]

[`$deleteOne`](../reference/documents/document-api.mdx#delete-one) removes the record from the database and marks the document as deleted. Such a document can't be saved or deleted a second time. These are errors, not silent no-ops, because they usually mean you're working with a stale object.

<Snippet id="documents/lifecycle/delete-document" twoslash />

## How to choose [#how-to-choose]

Ask yourself **where your data comes from**.

- **You're creating a record**: [`Model.new`](../reference/documents/model-document-methods.mdx#model.new) and then `$save`, or [`create`](../reference/writes/writes.mdx#create) right away.
- **You're reading from the database**: the query returns loaded documents on its own.
- **The data came from somewhere else, and you need the `$` methods**: [`Model.hydrate`](../reference/documents/model-document-methods.mdx#model.hydrate).
- **You only need a response for the client**: you don't need a document at all. Use [`.plain()`](../reference/query/reading.mdx#plain).

## When not to use it [#when-not-to-use]

If you aren't going to change and save the data, only send it on, you don't need a document. It's heavier than a plain object. Read with [`.plain()`](../reference/query/reading.mdx#plain) or [`.lean()`](../reference/query/reading.mdx#lean). For bulk changes, use [`updateMany`](../reference/writes/writes.mdx#update-many), not a loop over documents.

## Troubleshooting [#troubleshooting]

**The wrong document gets saved.** After `Model.hydrate`, the document counts as existing. If you turned data that isn't in the database into a document and called `$save`, you get a `DocumentNotFoundError`, not an insert. For data that doesn't exist yet, use [`Model.new`](../reference/documents/model-document-methods.mdx#model.new).

**Saving after a delete.**

<Snippet id="documents/lifecycle/troubleshooting" />

Create a new document with `Model.new`, or read the current one.

## Coming from Mongoose [#from-mongoose]

<Callout type="migration">

`new Model(data)` is called `Model.new(data)` here, and `doc.isNew` became the method `doc.$isNew()`. Mongoose has `Model.hydrate` too. In Typemo it takes data in the database's shape, with the database's field names, and rejects anything that isn't a plain object.

</Callout>
