Let's build a tiny blog. We'll create a user, write a draft as that user, publish it, and read the post back together with its author. It all fits in one script.

A quick word about Typemo if this is your first time here. It's a library for **MongoDB**, a database that keeps data as documents in collections rather than rows in tables. A schema in Typemo is an ordinary TypeScript class with decorators, and the compiler learns the type of every result from that same class. There are no separate schema files and no code generation.

## What you need [#prerequisites]

MongoDB on `localhost:27017` and [Bun](https://bun.sh). If your database lives somewhere else, you change the connection string in one line. [Installation and setup](./installation.mdx) covers other ways to install.

<Steps>
<Step>

### 1. Install the packages [#install]

You need the core, the MongoDB driver, and `bson` (it holds types like `ObjectId`). You install the driver and `bson` yourself, because Typemo doesn't bring its own copies. That way your project has exactly one of each. The compiler and the Bun types are only needed during development.

```package-install
@venloc/typemo mongodb bson
```

```package-install
-D typescript @types/bun
```

</Step>
<Step>

### 2. Configure `tsconfig.json` [#configure-tsconfig]

The line that matters here is `experimentalDecorators: true`. Without it, Bun turns on standard decorators and Typemo refuses to start. The rest is the strict compiler setup we recommend.

<Snippet id="getting-started/installation/quick-start" title="tsconfig.json" />

You don't need `import "reflect-metadata"` or `emitDecoratorMetadata`. [Installation and setup](./installation.mdx) goes through every flag and explains the standard decorators.

</Step>
<Step>

### 3. Define the models [#define-models]

A **model** is a class. [`@Schema`](../reference/schemas/schema.mdx#schema) says which collection its documents go to, and [`@Prop`](../reference/schemas/prop.mdx#prop) describes a field, type first, options second. [`Entity`](../reference/schemas/base-classes.mdx#entity) adds `_id`, the document's identifier.

<Snippet id="getting-started/quick-start/define-models" title="src/models.ts" twoslash />

`required` makes a field mandatory, and `unique` won't let you create two users with the same email. A post stores only the user's `_id` in `author`, and [`Ref<User>`](../reference/schemas/field-markers.mdx#ref) tells the compiler that the user itself can end up there once you load it.

</Step>
<Step>

### 4. Connect and write data [#connect-and-write]

[`TypemoClient.connect`](../reference/connection/typemo-client.mdx#typemo-client.connect) connects to the server and takes the database name from the end of the connection string, `blog` in this case. You get models from [`client.connection`](../reference/connection/typemo-client.mdx#client.connection) through [`connection.model`](../reference/connection/connection.mdx#connection.model).

Typemo doesn't create indexes on its own. That's what [`connection.init`](../reference/connection/connection.mdx#connection.init) is for. Don't forget to call it, or `unique` on the email guarantees nothing.

[`create`](../reference/writes/writes.mdx#create) writes documents. You can pass the new user's `_id` straight into the post's `author`.

<Snippet id="getting-started/quick-start/connect-and-write" title="src/main.ts" twoslash />

`create` returns a **document**. It looks like an instance of your class, remembers its changes, and knows how to save itself. The [Documents](../documents/index.mdx) section covers it in detail.

</Step>
<Step>

### 5. Read and update [#read-and-update]

[`find`](../reference/query/reading.mdx#model.find) searches by a condition. [`.plain()`](../reference/query/reading.mdx#plain) returns ordinary objects you can send to a client right away, and `_id` in them is already a string. [`updateOne`](../reference/writes/writes.mdx#update-one) takes a filter and a change. Here `$set` publishes the post.

To get the author itself instead of an `_id`, add [`.populate`](../reference/populate/populate.mdx#populate). If the author was deleted in the meantime, the field holds `null`. With `required: true` that case becomes an error, and `null` drops out of the type. [`.orFail()`](../reference/query/reading.mdx#or-fail) does the same for the post. If it isn't found, you get an error.

<Snippet id="getting-started/quick-start/read-and-update" title="src/main.ts" twoslash />

Look at the type of `found`. Its `author` has a `name` because you called `.populate`. Remove that call, and the compiler will tell you `author` is a string, and a string has no `name`.

Don't skip `client.close()` at the end. An open client keeps the script from exiting.

</Step>
<Step>

### 6. Run it [#run]

<Snippet id="getting-started/first-app/run-app-2" />

Bun runs TypeScript but doesn't check the types. To check them without running anything, use `bunx tsc -p .`.

</Step>
</Steps>

## Troubleshooting [#troubleshooting]

**The second run fails with `DuplicateKeyError`.** The script creates Alice again with the same email, and the unique index that [`connection.init`](../reference/connection/connection.mdx#connection.init) built rejects the duplicate.

<Snippet id="getting-started/quick-start/troubleshooting" />

Everything works as intended. To run the script again, drop the `blog` database or change the email. A real application catches [`DuplicateKeyError`](../reference/errors/server-errors.mdx#duplicate-key-error) and answers "this email is already taken". [Your first app](./first-app.mdx#register-user) shows how.

**`ConfigurationError` about a legacy decorator.** Bun didn't see `experimentalDecorators: true`. Check `tsconfig.json`, and check that it sits in the folder you run Bun from. Bun reads the config from the current folder.

<Snippet id="getting-started/installation/troubleshooting-2" />

If you do want standard decorators, read [Use TC39 decorators](../decorators-tc39/tc39.mdx).

**`ConnectionError: no server available`.** MongoDB isn't running, or the connection string is wrong. The error takes a while to appear because the driver waits up to 30 seconds for a server.

<Snippet id="getting-started/quick-start/troubleshooting-2" />

[Connect to the database](../connection/connect.mdx) shows how to create the client properly in an application.
