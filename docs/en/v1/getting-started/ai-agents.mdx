The Typemo packages ship with **skills**: instructions for AI agents that write code for you. After reading a skill, an agent knows Typemo's current API, its strict rules, and the common mistakes, and doesn't try to write code "the Mongoose way". Hook a skill up once per project, and from then on the agent opens it whenever a task touches Typemo.

A skill is a folder with a `SKILL.md` file and reference files under `references/*.md`. `SKILL.md` says when to use the skill, which rules to follow, and which reference file to open for a given task. The agent reads only the file it needs, not all of them at once, so its context doesn't fill up. Every code example in the skills compiles. It's checked the same way as the examples in these docs.

## What you need [#prerequisites]

A project with `@venloc/typemo` installed (see [Installation and setup](./installation.mdx)) and an AI agent that can read the project's files.

## Quick start in Claude Code [#quick-start-claude-code]

Claude Code looks for project skills in the `.claude/skills/` folder. Create a link there to the skill in the installed package.

<Snippet id="getting-started/ai-agents/quick-start-claude-code" />

Make a link, not a copy. That way the skill updates together with the package. After `bun update @venloc/typemo` the agent reads the instructions of the installed version.

If the project uses NestJS, add the second skill.

<Snippet id="getting-started/ai-agents/quick-start-claude-code-2" />

To make the skills work in all your projects rather than one, put the same links in `~/.claude/skills/`. In that case, point the path at the project where the package is installed.

## Available skills [#skills]

| Skill | Where it lives | When the agent uses it |
| --- | --- | --- |
| `typemo` | `node_modules/@venloc/typemo/skills/typemo` | any code with `@venloc/typemo`: models, queries, writes, documents, populate, aggregation, transactions, hooks, plugins, policies, errors, collections, tests |
| `typemo-nestjs` | `node_modules/@venloc/typemo-nestjs/skills/typemo-nestjs` | a NestJS app with `@venloc/typemo-nestjs`: the module, model injection, `@Transactional`, the tenant from the request, the error filter, pipes, tests |
| `typemo-contributing` | the `skills/` folder of the Typemo repository | work on Typemo itself: rules, check commands, kinds of tests, documentation rules, the code map |

The packages don't include the `typemo-contributing` skill. Only people who change Typemo's own code need it, and it lives in the [repository](https://github.com/Venloc-Tech/Typemo/tree/main/skills/typemo-contributing).

## What's inside the `typemo` skill [#typemo-skill]

`SKILL.md` collects the main rules the agent must not break, a "task → which file to open" table, and a self-check list to run before handing in code. The reference files are split by topic.

| File | Topic |
| --- | --- |
| `01-setup.md` | installation, `tsconfig`, the client, connecting, `connection.init()` |
| `02-models.md` | `@Schema`, `@Prop`, field types, arrays, Map, nested classes, indexes, discriminators |
| `03-reading.md` | `find`, filters, projections, sorting, keyset, result forms |
| `04-writing.md` | creating, updating, pipeline updates, replacing, deleting, `bulkWrite` |
| `05-documents.md` | the document, change tracking, document collections, serialization |
| `06-populate.md` | references, `populate`, `HydratedDocWith`, `isPopulated` |
| `07-aggregation.md` | the pipeline, `fn.*`, `$lookup`, `$merge`/`$out`, views |
| `08-transactions-hooks-plugins.md` | transactions, hooks, plugins, extensions |
| `09-policies-security.md` | tenant, soft delete, audit, `untrusted`, masks |
| `10-errors.md` | error classes and how to handle them |
| `11-collections-sync.md` | collections, indexes, `init()` and `syncAll()` |
| `12-testing-production.md` | tests on a real MongoDB and getting ready for production |
| `13-gotchas.md` | common mistakes, "bad → good", with exact texts |
| `14-not-supported.md` | what's missing compared with Mongoose and what to write instead |

## Other agents [#other-agents]

Agents that don't know the skill format can still use the skills, since they're ordinary Markdown files. Put the path in the agent's instruction file, for example `AGENTS.md` at the project root.

```md title="AGENTS.md"
Before writing code that uses Typemo, read node_modules/@venloc/typemo/skills/typemo/SKILL.md
and the reference file it points to for the task. For NestJS code, read
node_modules/@venloc/typemo-nestjs/skills/typemo-nestjs/SKILL.md as well.
```

For Cursor, write the same thing in the project rules. For other agents, put it in their instruction file.

## When not to use it [#when-not-to-use]

If you write the code yourself, without an agent, you don't need the skills. Everything in them is described in more detail in these docs. A skill is a condensed summary for a machine, not a replacement for the guides.

## Troubleshooting [#troubleshooting]

**You copied the skill folder instead of linking it.** After a package update the agent reads the old instructions and suggests an API that no longer exists or has changed. Replace the copy with a link, as in "Quick start in Claude Code".

**The link points nowhere.** The path in `ln -s` is resolved from the folder that holds the link itself, not from the project root. For `.claude/skills/typemo` that's `../../node_modules/...`. Check it with `ls .claude/skills/typemo/SKILL.md`.
