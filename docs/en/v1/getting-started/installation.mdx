Installing Typemo comes down to three packages, a decorator mode in `tsconfig.json`, and a choice of decorator package. The packages are `@venloc/typemo`, the `mongodb` driver, and `bson`. Decorators come either built into the core (legacy) or from a separate package (TC39). You pick them once for the whole project, because the decorator mode is set by the compiler, not by a single file.

Typemo talks to the database through the official MongoDB driver but doesn't bring its own copy. The driver and `bson` are **peer dependencies**. That way your app has one copy of the driver, and you decide which patch version to use. Typemo targets only the latest versions of MongoDB, the driver, `bson`, Bun, and TypeScript. Older ones aren't supported.

If you want to see a working result right away, start with [Quick start](./quick-start.mdx). It has the same setup without the explanations.

## What you need [#prerequisites]

A Bun project with an empty or existing `package.json` and a running MongoDB server. [Connect to the database](../connection/connect.mdx) shows how to connect to the server from code.

## Quick start [#quick-start]

A new project on legacy decorators needs an install and one file.

```package-install
@venloc/typemo mongodb bson
```

```package-install
-D typescript @types/bun
```

<Snippet id="getting-started/installation/quick-start" title="tsconfig.json" />

That's it. You don't write `import "reflect-metadata"`, you don't need the `emitDecoratorMetadata` and `allowImportingTsExtensions` flags, and you can leave `lib` unset. We'll cover below why each package and each flag is there, which versions are tested, and how to choose decorators.

## Packages [#packages]

The core, the driver, and `bson` are installed together. The TC39 decorator package is an extra, and only if that's the one you chose (see [Choose decorators](#choose-decorators)).

`@venloc/typemo` is the core. It holds models, queries, documents, policies, errors, and the legacy decorators. The package ships already built: `dist` has plain `.js` and `.d.ts` files, not TypeScript sources. So the library doesn't need any special compiler settings. The package has three entry points: `@venloc/typemo` itself, `@venloc/typemo/testing` (test data factories, see [Test your app](../testing/testing-apps.mdx)), and `@venloc/typemo/adapters`.

The core has one regular dependency, `reflect-metadata`, and it installs on its own. The core keeps its schema metadata there. It loads it in a mode that doesn't replace the global `Reflect`, so other libraries with the same dependency aren't affected. You don't need to import it in your app. The compiler doesn't emit field types into metadata, so a field is always declared explicitly: `@Prop(() => String)`.

`mongodb` is the official MongoDB driver. Typemo declares it as a peer dependency at version `^7.6.0`. Result types, errors, and connection options rely on this driver. If you need an operation Typemo doesn't wrap, you can get the `MongoClient` itself from [`client.unsafeDriver`](../reference/connection/typemo-client.mdx#client.unsafe-driver).

`bson` is the package with MongoDB data types like `ObjectId`, `Decimal128`, and `Binary`. It's a peer dependency too, at version `^7.3.3`. The driver depends on `bson` itself, but Typemo and your app have to see the same instance. That's why you install it explicitly, next to the driver.

`typescript` and `@types/bun` are only needed during development. Bun runs TypeScript without checking types, and the `tsc` compiler checks them separately.

Integrations are separate packages, installed only when you need them. They are `@venloc/typemo-opentelemetry` and `@venloc/typemo-sentry` (the [Observability](../observability/index.mdx) section), and for NestJS 12 apps, `@venloc/typemo-nestjs` (the [Connect Typemo to NestJS](../integrations/nestjs/setup.mdx) guide). The core contains none of their code.

## Versions [#versions]

The tested versions were pinned on September 26, 2026. Typemo works only with the latest ones and doesn't support older ones, so this list has no "minimum" versions.

Typemo's tests run on MongoDB 9.0 (the `9.0.0-rc0` pre-release) and on the stable 8.3 branch (`8.3.11`). The driver is `mongodb` 7.6.0, and `bson` is 7.3.3. The code and tests run on Bun 1.4.0. The compiler is TypeScript 6.0.3. Typemo hasn't been tested on the later TypeScript 7.

Transactions, change streams, and audited writes need MongoDB running as a **replica set**. That's several MongoDB servers holding copies of the same data, but for development a single node is enough.

## Choose decorators [#choose-decorators]

Typemo schemas are described with classes and decorators, and TypeScript has two kinds of decorators. **Legacy decorators** are turned on with the `experimentalDecorators` flag. It's the old experimental mode that NestJS, TypeORM, class-validator, and similar libraries run on. **TC39 decorators** are the language standard. They need no flags, and the compiler checks the kind of class member more strictly.

Both packages give you the same set of decorators and the same options, and the resulting schema is identical. The only difference is the import and the compiler setup. The core `@venloc/typemo` works with legacy decorators, and the `@venloc/typemo-decorators` package works with TC39. All options, models, and queries stay in the core.

Ask yourself whether **your project turns on `experimentalDecorators` for other libraries**. If it does, the flag applies to the whole project. The compiler turns every decorator into a legacy one and TC39 decorators won't work, so go with legacy. If it doesn't, go with TC39. It's the standard and needs no flags. You can't mix the two packages in one project, and Typemo reports it with an error (see [Troubleshooting](#troubleshooting)).

Both configurations are tested against the built packages. The project compiles with `tsc -p .`, and running it on Bun against MongoDB gives working models in both modes. Now for why each flag on the list is there and why the others aren't.

`experimentalDecorators` turns on legacy mode, and without it the core refuses to work. Bun reads this flag from the `tsconfig.json` in the folder you run the command from and applies decorators in the mode set there. If the mode is standard, the core throws `ConfigurationError` on the very first field. The text of that error is below.

You don't need `emitDecoratorMetadata`, because Typemo doesn't read `design:type` and keeps its own metadata. If the flag is on for other libraries, nothing breaks, and the result is the same. You don't need to load `reflect-metadata` either.

You don't need `allowImportingTsExtensions`, because the packages ship built and their imports already end in `.js`. There are no restrictions on `lib` and `target` either. A project with `target: "ES2022"` and `lib: ["ES2022"]` compiles with both legacy and TC39 decorators. If you have your own `lib`, you don't have to add `esnext.decorators` to it for Typemo. The configuration above sets `target` to `ESNext`, but the earlier `ES2022` is tested the same way.

`strict`, `exactOptionalPropertyTypes`, and `noUncheckedIndexedAccess` are the recommended strictness. Typemo is tested with it, and all of this documentation is written with it. The project compiles without `exactOptionalPropertyTypes` and `noUncheckedIndexedAccess` too, but you lose some compile-time checks.

You can leave `useDefineForClassFields` unset. With `target: "ESNext"` it's already on. Typemo fills in document fields itself, and the flag's value doesn't affect that. The result is the same with `true` and with `false`.

## How to choose [#how-to-choose]

It all comes down to the question from [Choose decorators](#choose-decorators): does your project need `experimentalDecorators` for anything else?

- **It does**: install only `@venloc/typemo`.
- **It doesn't**: install `@venloc/typemo` and `@venloc/typemo-decorators`.

For more on TC39, including moving a project over from legacy, see the [Use TC39 decorators](../decorators-tc39/tc39.mdx) guide.

## When not to use it [#when-not-to-use]

If all you need is "raw" access to MongoDB without schemas, policies, and result types, the `mongodb` driver is enough. Typemo pays off where the schema is a class and strictness is checked both by the compiler and by code at runtime. Tests against a real database need their own setup, covered in the [Test your app](../testing/testing-apps.mdx) guide.

## Troubleshooting [#troubleshooting]

**`ConfigurationError`: a decorator applied in the other mode.** The decorator package doesn't match the compiler mode. Say the project turns on `experimentalDecorators`, but the decorators are imported from the TC39 package. The error comes at startup, and the compiler reports `TS1238` and `TS1240` ahead of time.

<Snippet id="getting-started/installation/troubleshooting" />

The opposite case, with `experimentalDecorators` off and the decorators taken from the core, gives the same error with a different text. The compiler reports `TS1240`.

<Snippet id="getting-started/installation/troubleshooting-2" />

Make the mode and the package match. Either `experimentalDecorators: true` and imports from `@venloc/typemo`, or no flag and imports from `@venloc/typemo-decorators`. If Bun seems not to see the flag, check which folder you run the command from. Bun reads `tsconfig.json` from exactly that folder.

**`ConnectionError: no server available`.** Nothing answers at that connection string. The error takes a while, because the driver waits up to 30 seconds for a server. Start MongoDB or fix the connection string. The [Connect to the database](../connection/connect.mdx) guide shows how to create the client and handle this error.
